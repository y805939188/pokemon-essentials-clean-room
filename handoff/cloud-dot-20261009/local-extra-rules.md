# 不要求云端继承的本地追加流程

原合同要求真正理解相应材料、首次形成可恢复阅读记录、后续补读新增/受影响内容，以及各自独立质量复审。它不等于以下后来本地形成的流程：

- 一个额外 C-reading 会话重复读全部候选、实际、历史报告、索引、wrapper 和每层嵌套材料，完成后才允许登记。
- 每次读取续接都要求 ROOT 完整逐字读取全部检查点、ACK 身份数组、helper 源码，再发新的续接；把 `reader_all_complete` 作为额外登记前置。
- 为每字段/序列化块/RAW 变体/目录 lookup 建立重复证明或递归恢复旧 proof/source/ACK 树；把字典未匹配、计数、旧 false 标签、未用 UNACCOUNTED 历史变成新增缺口或必须恢复的任务。
- 源生产者/解析器纯度、原程序检查、全连接/universal join、源生命周期或完整序列化证书作为新的行为规格接受门槛。
- 旧辅助脚本假设特定本地目录、线程路由、直接父提交或分支前缀；这些工具假设不额外约束云端接受链。

**2026-10-09 人类明确停止扩大接受前审计，云端不需要继承或完成这些追加规则。** 历史检查点仍保留为可选审计记录，既有真实内容阅读可复用；这不降低原独立 Ultra、实际 SHA/范围绑定、来源和行为正确性、必要新/受影响补读等原要求。

`legacy-reading/` 的 all_complete:false 是被中断额外读者的状态，不代表 B14 的八个实际质量 gates 缺失或失败。云端不能仅因本地证明路径未上传就重建全部历史 corpus 或设置材料阻塞，也不能反向因旧 flag/URI/hash/报告声明就当作自己已读或新质量批准。具体原始行为疑问如确实影响正确性，按原合同有界处理。

原件、未执行草稿、失败与成功后继区别均保留；脱敏副本不是字节相同的原始证明。它们是输入，不是重新派发、自动执行或修改质量状态的授权。
