# 世界绘制与视觉过渡（净化正文；批次 1）

分类：Engine/Overworld Integration。本文件描述 overworld 画面必须满足的可观察规则：地图如何被绘制、角色与物品如何呈现、天气与屏幕效果如何叠加、场景切换时哪些可见状态保持或重建。全部内容为静态证据；一切实际视觉结果、动画时序与宿主输出均未运行验证（见 `../scope-statement.md`）。

## 1. 目的与范围

**目的**：回答「某一帧画面由什么决定、何时刷新」，供后续实现据以构建地图绘制与视觉叠加，而不追踪任何特定渲染器结构。

**范围**：① 地图绘制（图块层、自动图块动画、显示偏移与滚动、邻图拼接、优先级/桥/反射分层）；② 角色与附属呈现（角色图与图块图、图案帧、灌木深度、反射、冲浪基点、动态阴影、日夜着色）；③ 天气与屏幕效果（天气类型与淡入、色调/闪烁/震动、雾与全景、计时器与图片）；④ 场景刷新与视觉过渡（地图切换时可见内容的重建与保持、转场入口）。

**非目标**：不验证实际视觉结果；不规定渲染器/精灵的类层级或渲染管线结构；不重复地图拓扑、地形标签语义、资源缓存机制的主规则（只引用其可见结果）；不含消息/窗口/输入与战斗内画面。

## 2. 领域概念

- **图块层**：地图数据的三层（0/1/2）；画面按屏幕格逐层叠加显示图块。
- **自动图块**：按邻接关系选型的图块（8 个标准位＋可配置的额外自动图块），可按帧动画。
- **显示偏移**：地图显示坐标（子像素单位）决定屏幕滚动；图块网格按整格滚动＋亚格像素偏移。
- **优先级与分层**：图块按优先级决定 Z 序；桥、反射、雾、天气、画面效果各有固定分层。
- **可见状态保持**：跨图时画面连续性依赖显示偏移与邻图拼接；传送后可见内容按新图全部重建呈现。

## 3. 地图绘制（A）

### 3.1 图块呈现网格与屏幕滚动

- 画面按**屏幕格 × 3 个地图数据层**呈现：每个屏幕格的每层各显示一个图块。滚动时画面整格部分按格位移、亚格部分按像素偏移；**新进入画面的区域及时呈现**，移出区域不再显示（本条只约束可见结果，不规定内部对象的分配、复用或挂接方式）。
- **输入单位与量化**：滚动量来自当前图显示偏移——**4 个子像素单位对应 1 像素**（输入比例）。绘制时先把显示偏移换算并**取整到整数像素**（四舍五入），再按整数像素摆放：整格部分按格位移，**格内像素余数取自该整数像素坐标对格宽的取模**——它不是子像素除以 4 后的小数部分，**不呈现小数像素偏移**。例：显示坐标由 0 变为 6 个子像素单位（默认未放大图块），换算中间值为 1.5，取整后绘制偏移为 **2 像素**；量化后的位移差应由前后坐标**分别量化后**比较，不能由「变化量」直接断言小数位移。若实现以标准像素为内部单位，原兼容输入须按同一比例转换并遵循同一量化规则，不得静默改变输入语义。
- **邻图拼接**：遍历全部已加载邻图，各图按自身显示偏移投影到网格并填充图块；未被任何图覆盖的格置空。地图切换时若能取得相对偏移则平移网格保持连续，否则全量重绘。
- **图块来源顺序**：tile_id 小于「自动图块数×48」者为自动图块（含空白 0）；其后依次为额外大自动图块、额外单图块自动图块（配置表，默认空），再其后为图块集普通图块（每行 8 列）；巨型图块集按列重排。
- **图块属性**：地形标签决定**反射**（具反射标记 → Z＝−100）与**桥**（桥图块且玩家在桥上 → Z＝0）；优先级 0 → Z＝0，其余按 **Z＝行号×32＋优先级×32＋33** 抬升。玩家桥状态改变时触发全列 Z 值更新。

### 3.2 自动图块动画

- 帧数＝图宽 ÷ 32（大布局自动图块减半）；帧时长默认 5/20 秒，文件名尾部 `[N]` 标记可改为 N/20 秒；帧推进按系统运行时长对所有同名自动图块同步。
- 自动图块帧变化只更新对应自动图块的可见图案，画面其余内容不变（本条只约束可见结果——任何产生同样画面的绘制方式均满足，不规定「只更新源矩形」等内部更新优化）。

### 3.3 色调与颜色叠加

- 呈现级色调/颜色变化应用到全部图块呈现单元；画面级色调与闪烁色按逻辑显示层叠加（§4.1）。

## 4. 角色与附属呈现（B）

### 4.1 逻辑显示层（遮盖次序）

内容按下列**逻辑显示层**叠加；排序值为兼容排序参数，只描述可见遮盖次序——**不要求对应任何宿主容器、固定数量的视口对象或特定对象分配方式**：

| 逻辑显示层 | 排序值 | 内容 |
| --- | --- | --- |
| 背景层 | −100 | 全景（按显示偏移的一半滚动） |
| 主层 | 0 | 地图、事件、玩家、跟随者、雾（排序值 3000）、天气（相对 +1） |
| 图片/计时器层 | 200 | 图片（1–100 号）、计时器 |
| 闪烁层 | 500 | 闪烁 |

### 4.2 角色呈现

- **图块图角色**（tile_id ≥ 384）：从图块集切取（多格角色按宽高）；锚点底中。
- **图形角色**：按名称取角色图资源，4×4 帧布局——横向 4 帧图案、纵向 4 朝向；名称含 `offset` 时锚点上移；玩家图形被缓存保留。
- **灌木深度**：角色处于深草时按深度做三段渐隐裁剪（图块图与图形角色分别处理）。
- **可见性**：透明标记直接控制；名称含 `regulartone` 的事件免疫日夜着色，其余户外角色按时段着色（§4.4）。
- **位置**：屏幕坐标按角色实时坐标（含移动/跳跃插值）与显示偏移计算；Z 按屏幕高度与角色高度排序。
- **动画**：角色动画标记非 0 时播放对应动画数据并清标记（资源缺失时行为未验证）。
- **更新机会**：事件角色仅在有更新许可时更新，玩家每帧更新。

### 4.3 反射、冲浪基点与动态阴影

- **反射**：玩家与名称含 `reflection`（可带数值参数）的角色有反射呈现——垂直镜像、旋转 180°、上移 2 像素固定偏移；Z＝−50（玩家再 +1）；高度：固定参数或跟随桥状态（桥上抬高）；**静水反射**（高度参数 > 0）：深水色、不透明、不受时段着色影响（日夜着色开启时直接隐藏）；**普通反射**：半透明（3/4×3/4 亮度色）；反射摆动开关开启且地图未标 `still_reflections` 时按正弦摆动。
- **冲浪基点**：玩家专属临时基点图形（上下水时使用，由移动系统置位/清除）。
- **动态阴影**：挂接于来源角色的阴影呈现（角度范围/最大距离/不透明度参数；超出距离不显示）；传送时清理玩家阴影。**阴影的全部创建者与配置来源未穷尽**（具名未验证）。

### 4.4 日夜着色

- `TIME_SHADING` 开启且当前图为户外（`outdoor_map`）时，角色与地图元素按**逐小时色调表**（24 项，小时间按分钟线性插值）着色；否则色调归零。时间来源由时间系统提供。
- 画面级天气色调与日夜色调分别作用于不同逻辑显示层（天气在其叠加层，角色在主层）。

## 5. 天气与屏幕效果（C）

### 5.1 天气

- **天气类型**：注册 9 种——None、Rain、Storm、Snow、Blizzard、Sandstorm、HeavyRain、Sun、Fog；类别归并为 Rain（含 Storm/HeavyRain）/Hail（Snow/Blizzard）/Sandstorm/Sun/Fog/None；各类型登记粒子/叠层图形与色调过程；Rain 类有自动浇水树果的玩法消费（交界，不展开）。
- **设置语义**（天气设置入口：类型、强度、时长三参）：类型经数据注册校验；强度 → **粒子上限＝（强度＋1）×6**（以粒子上限总数 60 为基准的比例）；时长保存为天气淡入标记——**正时长启用固定阶段淡入，时长为 0 时立即切换**（不是实际时长数值）。
- **淡入/切换**：淡入入口只在**类型变化**时被画面整体更新流程调用；入口内**先判「正在淡入则返回」**，再判「类型与上限均无变化则返回」，之后才看时长——**不是任何 0 时长请求都能立即切换**：已有过渡在途时新请求被守卫拒绝，旧目标与当前过渡继续（屏幕保留新请求，后续全局更新按类型比较重新判断；不能写成已立刻生效，也不能写成一定永久丢弃）。通过守卫后：正时长按**固定阶段时序**推进（阶段按帧时增量累积，并受旧天气时间偏移影响——旧类型为 None 时 +2、旧类型无叠层时 +1；结束另须旧粒子不再可见）：旧粒子基础阶段 **1–3**、旧色调 0–2、旧叠层 0–1、新粒子 2–4、新色调 3–5、新叠层 4–5（相对阶段，非传入时长的比例）；时长非正走立即切换分支。None 类型上限归零。
- **同类型强度变化（参考快照行为）**：屏幕记录的类型与上限都会更新，但画面整体更新流程**仅在当前天气对象的类型与屏幕类型不同**时才调用淡入入口——同类型仅改强度时，天气对象不会再次收到新上限，**可见粒子上限不能据源码保证刷新**（天气对象内部的「同类型同上限则返回」分支只有被调用时才有效，不是全局消费者保证）。
- **滚动跟随**：天气显示层偏移跟随地图显示偏移；跨图时按相对偏移平移天气粒子保持连续（无连接偏移则归零重置）。
- **地图天气**：地图元数据的天气字段驱动的设置入口（字段存在性在案；消费者链未穷尽，具名未验证）。

### 5.2 雾与全景

- 雾：地图 fog 字段（名称/色相/缩放/不透明度/混合/色调/滚动速度）驱动叠加层（Z＝3000）；滚动速度按运行时长持续累积；参数变化时帧重置并重设。
- 全景：地图 panorama 字段（名称/色相）驱动背景层（Z＝−100，半速滚动）。

### 5.3 色调、闪烁与震动

- 画面色调变化按游戏时间线性插值到目标色调，作用于主显示层。
- 闪烁颜色的透明度按时长衰减到 0，作用于闪烁显示层（排序值 500）。
- 震动按力度/速度生成周期位移（**最大位移＝力度×2.5 像素**），叠加在主显示层 X 偏移。
- 上述效果由事件命令启动后立即继续执行（事件命令 223/224/225 交界），本文件只登记其可见叠加与计时来源。

### 5.4 图片与计时器

- 图片 1–100 号（战斗内 +50）在图片/计时器显示层显示；显示/移动/旋转/色调/删除由事件命令驱动；旋转按速度持续。
- 计时器呈现按系统计时器状态显示。

## 6. 场景刷新与视觉过渡（D）

- **地图切换时的可见状态**：分三类，不得混为「全部重建、旧内容一概不保留」——
  1. **逐图显示内容**（图块地图、事件等与具体地图绑定的显示）：显式传送时**按新图重建呈现**；同图传送同样重建；边缘切图时画面**保持连续、不重建**（连续性依赖偏移与拼接，§3.1）。
  2. **全局显示内容**（玩家、跟随者、天气、图片、计时器的显示）：传送时**保持不重建**，由各自驱动源继续驱动；天气偏移按相对偏移调整、无连接偏移归零重置（§5.1）。
  3. **独立业务记录**（图片记录、计时状态等）：**不因传送的显示刷新而清除**——显示内容跟随记录；没有事件或其它逻辑另行修改时，既有图片与运行中计时器在传送后继续按记录显示。本条不做「任何传送都保留全部状态」或「清空全部状态」的对称全称保证（记录自身可被事件等修改）。
  以上只约束可见状态与业务状态的去留，不规定某组对象的销毁重建机制。
- **资源使用有效期**：图块集与自动图块位图在仍有使用者时保持有效；最后的使用结束时资源可被释放（本条只约束资源有效性边界，不规定引用计数等内存管理机制）。
- **转场**：事件命令 221 准备过渡（按过渡名取过渡资源）、222 执行；显式传送链中的转场由传送标记触发；实际视觉效果未运行验证。战前的过渡选择、资源条件与固定目标时长见同批《战前过渡》。
- **帧重置**：音乐/雾/全景等变化时做画面帧重置，保证切换帧状态干净（具体宿主语义未运行验证）。
- **刷新请求**：地图需刷新标记置位时，事件页与呈现随更新循环刷新；渲染器刷新标记触发全量重绘。

## 7. 默认行为与配置变体

- **基线默认**：标准 8 自动图块（帧 5/20 秒）；额外自动图块表为空；无天气（None）；雾/全景按地图字段；日夜着色按 `TIME_SHADING` 与户外标记；反射按地形与名称模式。
- **支持但未默认启用**：文件名 `[N]` 自定义自动图块帧时长；额外自动图块配置表；反射摆动开关；地图 `still_reflections`；`regulartone` 事件名免疫着色。
- **配置/数据关联**：`SCREEN_WIDTH/SCREEN_HEIGHT`；地图元数据的 fog/panorama/still_reflections/outdoor_map 字段；`TIME_SHADING` 与逐小时色调表；`EXTRA_AUTOTILES`、`ANIMATE_REFLECTIONS`。
- **未验证组合**：一切实际视觉结果与动画时序；宿主图形/音频输出；动态阴影的全部创建者。

## 8. 边界与失败

- 图块资源缺失：按资源系统边界处理（解析失败按各入口规则），画面表现为缺图（具体输出未验证）。
- 地图切换无连接偏移：网格与天气全量重绘/重置（§3.1、§5.1）。
- 事件呈现在无更新许可时不更新（画面保持上一状态）。
- 反射在日夜着色开启且为静水反射时隐藏（着色冲突的既定处理）。
- 天气类型未注册：按数据身份校验规则报错。
- 视觉时序（帧重置、过渡、淡入）均以静态规则登记，实际帧率/表现未验证。
