# 背包、物品储存与商店界面（数量／目标选择与交易反馈）行为规格（净化正文；批次 14）

分类：user-interface（主）／creature-rpg（接点）；性质：实现独立行为规格。

本稿为净化正文的一部分：按统一交接将批准输入 WP66-C《背包、物品储存与商店界面》转写为独立行为文字，不含源文件路径、行号与脚本入口名（源定位集中登记于 `../../audit/source-traceability.md` 批次 14 条目）。范围 A～E：正常／过滤／PC 存入／出售的入口区别，口袋与选择位置、排序和登记写入，命令菜单及目标／数量选择，PC 存取／丢弃的画面与预检／确认，金钱与 BP 商店已述买卖、失败／回退、统计、库存过滤、覆盖清除和已知显示边界。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。容器规则引用 WP27、使用／消耗引用 WP28、价格与交易顺序引用 WP29、输入与消息引用 WP17；本稿只补四个界面文件的实际用户流程，不重新定义库存或价格公式。宿主／媒体／真实商店事件／插件与 WP66 族其余范围保留。

## 1. 目的、边界与可见流程

本稿描述四个资源类界面的用户流程：背包（正常模式与过滤选择模式）、PC 物品储存（取出／存入／丢弃三画面）、金钱商店（买／卖）与 BP 商店（买）。重点：对象／数量选择、确认、扣除、部分成功、失败反馈与连续操作——**何时只是游标变化，何时已改变资源或登记**。

**非目标**：不定义背包容器语义与预检／部分写入（WP27）；不定义道具使用资格、效果与消耗时机（WP28）；不定义价格来源、覆盖与交易层写入顺序（WP29）；不定义队伍给予画面与摘要（WP66-A）；不定义快捷菜单（WP27）；demo 真实商店库存与接待事件缺失（U01，WP29）。

## 2. 背包：入口与模式（A）

| 模式 | 入口 | 画面差异 | 返回 |
| --- | --- | --- | --- |
| 正常背包 | 暂停菜单「Bag」（WP65 范围，入口登记） | 全口袋；ACTION 排序可用；命令菜单齐全 | 最后选中物品（或 nil）；使用返回 2 时关闭背包转野外 |
| 过滤选择 | 物品选择画面入口（谓词参数）（消费者：仓库持物、摘要给予、树果、化石等，WP27） | 选择态为真；仅匹配谓词的行可见；CLOSE BAG 行恒在末位 | 选中物品标识或 nil |
| PC 存入复用 | PC「Deposit Item」（§5） | **即正常背包画面**（口袋、CLOSE BAG 行、保存游标、ACTION 排序可用） | 选中物品进入存入流程 |
| 出售复用 | 金钱商店出售（§6.3） | 选择态为假的子画面（**无过滤**） | 选中物品进入出售流程 |

**过滤选择的游标处理**（与 WP27 同一事实的 UI 侧）：进入前保存「上次口袋＋各口袋索引」；**带谓词时**先重置各口袋索引为 0，不带谓词时沿用保存值；选择模式的初始口袋＝1（该口袋空／过滤后空则取首个非空口袋）；**返回后无论选中或取消，一律恢复保存的两项游标值**。正常背包则直接读写保存值（§3.1）。

## 3. 背包：导航、游标与排序写入（B）

### 3.1 口袋与索引（游标即持久状态）

- 口袋 1–8（WP27）；左右键切口袋：**正常模式**移到相邻口袋（不跳过空口袋）；**选择模式**跳过「过滤后空」（带谓词）或「空」（不带谓词）的口袋。口袋切换即写上次口袋字段。
- 索引变化即写各口袋上次索引（含 CLOSE BAG 行；写入方只查上限不查下界，WP27）。左右箭头仅在「非选择模式或非空口袋数 >1」时显示。
- 行显示：数量仅当物品「显示数量」且未显示登记图标；登记图标仅重要物品两态（已登记实／可登记空，WP27 三层规则引用）；CLOSE BAG 行无图标、说明文本换为「Close bag.」。

### 3.2 排序（ACTION，**移动即写入**）

- 启动条件（同时满足）：非选择模式、当前口袋成员 >1、游标在物品行（非 CLOSE BAG）、该口袋**未配置自动排序**（当前 TMs&HMs 与 Berries 两口袋自动排序，WP27——这两口袋不可手动排序）。
- 排序中：光标换为交换样式、行名变红；**每次方向键移动立即在容器内搬移该物品**（先从原位置取出、再插入到目标位置——真实写入，不是暂存预览）；游标被钳在物品行内（到 CLOSE BAG 行则弹回末物品行或第 0 行）。
- USE／ACTION：确认落位（写入已发生，仅关排序态）；**BACK：把被拖物品搬回排序起始位置**（其余成员随动还原，净效果＝整次排序未发生）并关排序态。
- 排序不写「上次索引」之外的任何容器外状态；正常背包返回暂停菜单时背包顺序即当前容器顺序。

### 3.3 选择与取消

USE：物品行 → 返回该物品标识；CLOSE BAG 行 → 返回 nil（播关闭音）。BACK：返回 nil（播关闭音）。选择模式两者语义相同；**返回 nil 后调用方才决定无写入**（§4、§5 各自处理）。

## 4. 背包：命令菜单流程（C）

正常背包选中物品后按物品动态生成命令（与 WP27 同一集合）：

| 命令 | 出现条件 | 流程与写入 |
| --- | --- | --- |
| Read | 邮件物品 | 打开读信画面（无容器写入；邮件本体 WP64／WP27） |
| Use（文本可自定义） | 存在背包使用／野外直用／个体使用处理器，或机器且队伍非空 | 使用分流（资格／效果／消耗全部引用 WP28）：内层返回 0 → 留循环；内层返回 1 → 刷新留循环（效果与消耗已发生）；**内层返回 2 → 结束背包画面**——此时只决定了「关闭背包转野外」，野外效果在背包与暂停菜单关闭后才执行（§6.4 三层对照）；飞行目的地特设时直接释放 |
| Give | **队伍至少一个非蛋成员**且物品可携带（非重要物品；非蛋濒死成员仍计入） | 打开队伍给予画面（WP66-A）。**空队、全蛋队或重要物品在正常菜单不生成 Give 命令**；「There is no Pokémon.」／「The X can't be held.」两条提示是防御分支，需要菜单生成后队伍或物品状态再被外部改写才可达——具名额外前提，不计为正常可选结果 |
| Toss | 非重要物品或调试标志 | 数量 >1 先选数量（取消 → 0，跳过）；确认「Is it OK to throw away…」→ **逐个删除（每次删 1，返回值不检查**，WP27 引用）；数量 1 不选数量直接确认 |
| Deselect／Register | 已登记 → Deselect；未登记且登记资格通过 → Register；否则无此项 | 直接登记／取消（领域层规则 WP27） |
| Debug | 调试标志 | 改数量（0..999 数字控件，WP17；多于现数补加、少于补减、到 0 即删光并退出命令）／制作神秘礼物（WP64） |
| Cancel | 恒在 | 无写入 |

「使用」的返回值分三层，不混为一谈（WP28 引用）：**内层使用结果** 0／1／2——个体使用选择循环中，「成功用过一件且背包尚有剩余后取消目标选择」得内层 0（此前效果与扣减不回滚）；**背包出口**——背包入口返回最后选中的物品标识或 nil（正常按 BACK 退出背包返回 nil，不是「整段返回 0」）；**外层野外执行**——背包返回非 nil 时，暂停菜单关闭后才执行野外效果（如自行车的骑乘／下车）。

## 5. PC 物品储存：取出／存入／丢弃（D）

PC「Item Storage」菜单：Withdraw Item／Deposit Item／Toss Item／Exit；储存对象**懒创建**（WP27）；取出／丢弃入口在储存为空时提示「There are no items.」不进入。**三个入口的可见画面不同**：

- **取出／丢弃**：无口袋的储存列表（末行 CANCEL；BACK 或 CANCEL 行 → nil；两个变体仅标题不同）。
- **存入**：**复用正常背包画面**（口袋、CLOSE BAG 行、保存游标读写、§3.2 的 ACTION 排序全部可用）；返回选中物品后进入同一套数量／确认与容器操作流程。因此「在存入画面里排序后取消存入」是实际可达的：没有物品转移，但背包顺序与相关浏览状态保留。

数量控件（共享数量选择控件）：1..上限、上下 ±1 回绕、左右 ±10 钳位、**BACK 返回 0**、USE 返回当前值；确认控件（共享确认控件）：[Yes, No] 默认 Yes，BACK 视为 No。

| 画面 | 数量选择 | 执行与失败 | 连续操作 |
| --- | --- | --- | --- |
| 取出（储存→背包） | 数量 >1 且**非重要物品**才选；重要物品跳过（整叠） | **先预检**背包可加（WP27）：失败 →「There's no more room in the Bag.」；通过 → 储存删除（失败**内部报错**）→ 加入背包（失败**内部报错**）→「Withdrew N X」（重要物品按 1 显示） | 循环直到取消 |
| 存入（背包→储存） | 同上 | 先预检储存可加：失败 →「There's no room to store items.」；通过 → 背包删除（内部报错）→ 储存加入（内部报错）→「Deposited N X」 | 循环直到取消 |
| 丢弃 | 重要物品**直接拒绝**「That's too important to toss out!」（不选数量）；数量 >1 才选 | 确认（默认 Yes；取消 → 跳过）→ 储存删除（内部报错）→「Threw away N X」 | 循环直到取消 |

**配对预检与报错路径**：WP27 已定义「预检纯函数＋执行可部分写入」——**显式配对预检只存在于存／取两个入口**（容量预检）；**丢弃是确认后删除，没有容量预检**（丢弃本身不需要目标空间）。预检失败时容器不动；预检通过后的删除／加入失败属「不应发生」断言，正常界面不可达，按静态反例登记（不修参考）。与接收／拾取／奖品的**直接添加**入口（无配对预检、可部分写入后 false）分列（WP27）。

## 6. 商店：入口、买卖与连续操作（E）

### 6.1 入口包装（事件侧，U01）

- 金钱商店入口（库存, 问候语, 禁售）／BP 商店入口（库存, 问候语）：核心脚本内无正常调用者（真实调用为地图事件，U01；WP29）。
- **库存原地过滤**：进入时从传入的库存列表中移除「重要物品且背包已持有」的条目——**修改的是调用方传入的同一列表**（按引用原地删除，不重建、退出不恢复，WP29 引用）；每次成功购买后再次按同法从同一列表移除。
- 金钱商店命令：买／卖（禁售时无）／退出；默认光标在买；**BACK 等效退出**（取消策略＝退出索引＋1，WP17 引用）；退出显示告别语。BP 商店仅买，进场两条欢迎语、退出两条告别语。
- **两商店退出路径均清除价格覆盖**（覆盖生命周期与共享买槽引用 WP29）。
- 画面层：进入前地图右滚、退出后左滚（呈现，未运行验证）。

### 6.2 购买流程（两商店同构，差异见表）

逐步骤（引用 WP29 的交易层规则；此处固定 UI 顺序与反馈）：

1. 列表选择（末行 CANCEL；BACK → 结束购物循环）。列表行显示单价（金钱 `$ N`／BP `N BP`）与「In Bag: 持有数」窗。
2. **首查资源** < 单价 → 暂停消息（金钱「You don't have enough money.」／BP「You don't have enough BP.」），回到选择（不进数量步）。
3. **重要物品**：确认（单数文案）→ 数量固定 1；**普通物品**：可买上限＝单价 ≤0 时每槽上限 999，否则 `资源 ÷ 单价` 向下取整再钳 999；数量窗逐键刷新总价（左右 ±10 钳位、上下 ±1 回绕、**BACK 返回 0** → 回选择）；确认（数量 >1 复数文案，＝1 单数文案；默认 Yes，BACK 为 No）→ 回选择。
4. **复查资源** < 总价 → 同首查消息（BP 商店文案换「I'm sorry, you don't have enough BP.」），回选择。
5. **逐件放入背包**：全部放入 → 统计（消费累计、件数——两商店共用件数计数）→ 扣资源 → 库存原地再过滤 →「Here you are! Thank you!」＋音效；未全部放入 → **回退已放入件**（移除失败内部报错）→「You have no room in your Bag.」（资源／统计不变）。
6. **赠品（仅金钱商店）**：本次数量 ≥10 且存在纪念球数据：慷慨档开 → 仅球类物品，尝试 `⌊数量÷10⌋` 个、按实际添加数统计与复数显示；关 → 仅普通球、尝试 1 个；添加失败不影响已购（WP29 引用）。
7. 循环直至退出（**连续操作**：每次成功／失败后都回到列表，库存已过滤状态延续）。

**BP 商店差异**：资源为 BP（两处检查文案不同）；无出售、无赠品；统计为 BP 消费累计＋共用件数；**数量窗显示怪癖**（WP29 引用并保留）：场景标志未初始化使数量窗按 `⌊单价÷2⌋` 显示总价（BP 价 1 时显示 0 BP），确认文本与实际扣除仍为全价。

### 6.3 出售流程（仅金钱商店）

1. 出售画面复用**正常背包子画面**（无过滤；§3.2 的 ACTION 排序在出售中同样可用——排序即写背包顺序，与出售互不感知）。
2. 选物品 → **可售判定**（有效售出价 >0 且非重要，WP29）不通过 →「Oh, no. I can't buy X.」回选择；持有数 0 → 跳过（静态边界）。
3. 显示金钱窗；数量 >1 → 数量选择（上限＝持有数；BACK 返回 0 → 隐藏金钱窗回选择）；确认「I can pay ＄N. Would that be OK?」（默认 Yes）。
4. **写入顺序**（WP29 引用）：记录旧金钱 → 加钱（写入方钳上限）→ **统计按实际增量** → **逐个移除（返回值不检查）** →「You turned over the X and got ＄N」＋音效。
5. 拒绝／取消路径不写入；循环直至取消；退出后金钱窗隐藏、告别语、清覆盖。

### 6.4 查看／选择／提交分层汇总

| 动作 | 只改游标／显示 | 已改资源或登记 |
| --- | --- | --- |
| 口袋／索引移动 | — | 写上次口袋／索引（持久游标，WP27） |
| 排序搬移 | — | **立即改容器顺序**；BACK 把被拖物品搬回起始位（净还原） |
| 数量控件 BACK | 返回 0 | 无写入 |
| 确认框 BACK | 视为 No | 无写入 |
| 使用·内层返回 1 | — | 效果与消耗已发生（WP28；再取消不回滚） |
| 使用·内层返回 2 | 决定「关闭背包转野外」 | **此时野外效果尚未执行**；背包返回物品、暂停菜单关闭后才执行（§4 三层；自行车返回 2 时未骑乘） |
| 使用·内层返回 0（用过一件后取消目标选择） | — | 此前一件的效果与扣减保留（内层最后路径为 0）；再按 BACK 退出背包返回 nil |
| 购买全部放入 | — | 统计、扣资源、库存再过滤（赠品另计） |
| 购买部分放入 | — | 回退后无净变化（内部报错路径另列） |
| 出售确认 | — | 加钱（钳制后增量统计）、物品已移除（不检查结果） |
| 退出商店 | — | 价格覆盖清除；库存过滤不恢复 |

## 7. 规则与不变量

1. 背包各入口是**不同画面**：正常背包、过滤选择（游标保存／重置／恢复三段）、PC 存入（复用正常背包、排序可用）、出售复用（选择态为假、排序可用）、PC 取出／丢弃（无口袋储存列表）。
2. 排序、游标、登记切换是**即时写入**，不需要确认；数量／确认控件的 BACK 才是「无写入」路径。
3. **显式配对预检只存在于 PC 存／取两入口**（丢弃为确认后删除、无容量预检）（WP27）；商店购买**逐件放入＋失败回退**（WP29）；出售**先钱后物且移除不检查**——三类写入形状不同，不互套成功保证。
4. 取消不自动等于事务回滚：使用过的道具、已排好的顺序、已登记的切换、已完成的购买在后续取消时全部保留。
5. 失败反馈按入口分列文案（背包满／储存满／不可丢／不可售／资源不足两文案／BP 复查文案），没有统一「失败」消息。
6. 重要物品的界面约束链（WP27 引用）：背包不可丢（默认）、PC 不可丢、不可给予、存取跳过数量选择整叠搬运且按 1 显示、商店禁售、已持有者从商店库存原地删除。
7. 数量控件三处实现同语义（共享助手／商店两处各自实现）：1..上限、±1 回绕、±10 钳位、BACK 返回 0；**返回 0 与「选不到 0」的控件语义一致**——调用方以 0 为取消编码（WP17 对照：另一数字控件族仅调试改数量使用）。

## 8. 边界与失败

- 空容器：背包全空仍有 CLOSE BAG 行；储存为空时取出／丢弃入口被 PC 层消息拦截；出售时背包空 → 只能取消。
- 数量极值：单价 0 → 上限 999、总价 0（统计 ＋0）；持有 1 → 不选数量直接确认；上限 1 的数量控件 USE 只能返回 1、BACK 返回 0。
- 无有效目标：无可用处理器 → 无 Use 命令；**空队／全蛋队／重要物品 → 正常菜单无 Give 命令**（防御提示需菜单生成后外部改写才可达，§4）；全重要物品库存 → 商店列表可能仅剩 CANCEL 行。
- 部分成功：购买部分放入 → 回退（WP29）；WP28 的「按传入数量扣减、不退差」发生在使用路径（引用），不发生在商店。
- 连续操作：买／卖／存／取／丢循环中，前一次的写入（含失败反馈）不影响后一次的选择状态（库存过滤、游标、金钱窗按最新状态刷新）。
- 内部报错路径（静态断言、正常界面不可达）：储存删除／加入失败、购买回退移除失败、出售移除失败（不检查所以无断言）、战斗退回背包满（WP28）。
- 显示怪癖（保留，不修参考）：BP 数量窗半价显示；背包对象不存在时出售退回非子画面路径（出售入口分支，正常游戏背包对象恒在）。
