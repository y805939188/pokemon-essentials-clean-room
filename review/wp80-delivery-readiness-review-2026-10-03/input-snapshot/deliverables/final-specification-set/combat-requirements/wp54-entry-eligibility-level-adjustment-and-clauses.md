本稿为净化正文的一部分：按统一交接将批准输入 WP54《参赛资格、队伍子集、等级调整与杯赛条款》转写为独立行为文字，不含源文件路径、行号、脚本入口名与类层级（源定位集中登记于 `../../audit/source-traceability.md` 批次 13 条目）。范围 A～F：成员/输入队伍/可选子集/最终参赛队伍判断，默认杯赛组合、临时等级和还原接点、战斗条款。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。通过仅限该静态范围，设施完整会话、租借、回放与运行不随之通过。

## 1. 目的、可见流程与状态边界（A）

本稿回答哪些成员/组合可以进入比赛、玩家如何选定参赛顺序、资格与等级调整在哪一步发生、战斗条款在哪个阶段生效。它不设计规则对象/API 或未来继承层级；不能从「杯赛」「子集」名称推断官方赛事规则。

输入是有序个体集合、候选身份/蛋/HP/等级经验/物品/招式/种族形态数据、作者选择的成员与组合条件、人数范围、调整策略、布局与条款，以及配置当前最大队伍 6、最大等级 100。输出是布尔资格、首个拒绝原因、按选择顺序的成员引用列表或取消空结果、建议数量/等级、临时等级/经验/能力值变化与旧经验记录、战斗规则布尔值与具名结果写入。资格查询通常不改个体，但婴儿/可进化与名字查询有缓存，不能称所有判断完全无状态。

可见报名入口先检查有没有可选合法队伍，成员逐个显示可报名/不可报名；选入后显示次序，可取消选入、看摘要、确认或退出。确认再检所选列表整体，不因每个成员标可选就承诺组合合法。战斗包装在开战前另恢复玩家队伍、按调整策略改等级；资格和调整不是同一步。完整设施轮次/报名收费/保存中断/胜场和租借/录像归 WP55/57/58，本稿只闭合真实直接字段和调用顺序；缺 Demo 事件不补造费用奖品。

## 2. 四类资格与数量、组合语义（A/B）

### 2.1 数量与规则组合

原始新规则集默认最少 1、原始最大数 0；原始最大数 <0 时公开最大长度用最大队伍配置（当前 6），否则用该数。设单一人数 n 会把最少和最大都设 max（1，n）；设范围分别对两端至少 1，**不保证最少 ≤ 最大、不自动夹 6**。完整输入队伍范围是最少 max（1，最少参赛数）到 max（6，最大参赛数），最终参赛则按参赛最少/最大。建议人数取最大参赛数。仅用带人数参数的初始化只设最大、**最少仍 1**，不同于后来显式设人数。

成员条件/整队条件按加入顺序全部要求真；重复加入不去重，集合清除只清对应列表；重新设置整套规则、战斗种类、调整策略为覆盖。布局设置会附加单/双战规则并将人数设 3/4；后来再设人数只改人数、不撤双战，故双战 3 名参赛可由工厂默认形成。战斗建立时顺序应用所有附加规则，布局后写覆盖先写，条款重复赋真不叠数值。

**名为「加入子集规则」的入口实际追加到整队条件列表。**因此通过这个普通入口添加总等级/限制物种上限，会对完整待报名输入队伍全部求值；清「子集规则」不会删除它，清整队规则会删除它。保留独立子集列表的消费代码，但本快照公开添加入口没有向其中写入，不能把注释中的意图当当前运行效果。

规则复制只复制原始最大数和三类列表中的规则引用，**最少人数重置 1**，不是完整值复制；参数对象引用共享，战斗种类/等级调整也保留原引用，未建立深层独立快照。复制后建议人数仍原最大，但最终可选最少数可能放宽。

建议等级不是合法性证明：先从 1..最大等级开始，按成员条件遍历取最后一个最小等级、最后一个最大等级；独立子集列表中的最后总等级可覆盖「最大 × 建议人数」。总额足够时返两端较大值，否则总额整除建议人数再与最小取较大。由于普通「子集添加」实际放整队，默认杯赛的总等级未进入此建议算法，建议值可能使随后队伍不合法；真正判断仍是所有限制合取，不只最后条件。异常/非法类型、0 建议人数和矛盾上下限未统一验证。

### 2.2 实际判断入口

判断入口按用户问题分五层（审计名见追溯条目），不按名字许诺等价：

| 判断 | 实际检查和返回 |
| --- | --- |
| 单成员判断 | 空成员假；按顺序成员规则，任一不真即假；没有规则时非空者真，**不会自动排蛋/倒下** |
| 完整输入队伍判断 | 空列表对象或长度小于输入最少/大于输入最大则假；所有成员合法；所有整队规则对整队合法；若独立子集列表非空，枚举「最少参赛数」大小的组合，存在一个满足全部子集规则才真；没有该列表则直接真 |
| 存在完整可报名组判断 | 输入空或不足最少假；枚举**输入最大长度**大小的组合，任一个完整输入判断真才真。组合长度不足时零次枚举 → 假，不自动用较短列表，所以 3 人队伍可能完整输入判断真但本判断假（默认输入最大 6） |
| 是否能选出合法参赛组判断 | 空或不足最少假；先统计单成员合法数，少于最少假；有整队规则时在**原输入（不是过滤后列表）**枚举最少大小组合，逐组调用最终判断，首真即真；没有整队规则时只凭合法数足够返真，不单独消费独立子集列表 |
| 最终已选队伍判断 | 对长度先下限、后上限；逐成员；逐整队条件；逐独立子集条件。每一步失败即返假，并向可选错误集合追加首条人数/成员/规则错误；不是枚举另一个替代组合 |

枚举只产生指定正数 k 的无重复索引组合：k ≤ 0 或输入长度 <k 不产生；长度＝k 产整列；k＝1 每个成员；其它按原索引递增顺序，存在性首个成功就停止。不重排个体、不把相同物种去重成同一条目。空最终数组受人数下限拒；最终判断直接访问列表长度，没有空列表统一守卫。若规则失败却没有错误文案入口、并传入错误集合，可能访问缺失文案而异常（例如通用限制物种数量条件）；布尔查询不自动造文案。

### 2.3 实际选择界面与接收

队伍界面的多选入口先做「是否能选出合法参赛组」判断，不成立直接返回空，不开选择界面；逐成员只按单成员判断标资格。选择加入最多公开人数，按加入顺序编号，移除后顺序压紧；选满且刚加入时焦点移到确认，但不自动提交。确认构造所选引用列表，调用最终判断并显示首个错误；失败继续选。退出/取消返回空，未调用设施队伍提交；看摘要不提交新队伍。

事件便利查询「有无合格成员」忽略可变实参，读当前挑战规则对玩家现有队伍做「是否能选出合法参赛组」判断。报名屏幕入口取得非空列表才传给挑战的队伍提交，返回是否选择了成员。队伍提交保存引用列表；若挑战已进行还立即替换玩家活动队伍，否则留待挑战开始，开始处先保存原队伍引用再替换。这里只定位这次提交，完整恢复原队伍/存档异常窗口交 WP55，不把「选队取消」与「开战中断」统一为回滚。

全脚本范围检索中，「存在完整可报名组/完整输入队伍」两判断只在规则实现内部出现，实际报名界面使用「是否能选出合法参赛组/最终已选队伍」；不能声称所有四入口都已由默认 Demo 接待调用。生成对手入口使用建议等级/人数；候选数 ≤ 建议人数时直接全部构造并返回，不再次最终校验；更多时反复取样直到最终判断通过，无尝试上限。这是规则消费者边界，不在本稿运行或提取完整生成器。

## 3. 成员、队伍与数据约束（C）

| 约束含义（审计名见追溯条目） | 明确参数、顺序与边界 |
| --- | --- |
| 标准资格 | 空/蛋先拒；物种数据普通特性列表含 TRUANT 或 SLOWSTART 即允许，不要求个体当前拥有/有效；否则 DRAGONITE/SALAMENCE/TYRANITAR 允许，WYNAUT/WOBBUFFET 拒；余种族六项总和 ≥600 拒。允许优先于后续禁项；不是传奇标签黑名单，不自带存活门 |
| 非蛋／可战斗 | 非蛋约束仅非空非蛋；可战斗要求个体可战斗（非蛋且 HP 正）。各杯是否装这些规则看组合，不能所有杯默认可战斗 |
| 高度／重量 | 输入米/kg 转参考单位 ×10 后取整，个体当前高度/重量或物种数据值 ≤ 阈值；含等号；不是战斗重量查询受浮石/能力修正后的数值 |
| 基础阶段 | 以物种键缓存第一次查到的基础形态解析，当前物种等于该值才真；没有要求它还能进化。形态共享物种键缓存，不为每形态/配置刷新 |
| 未进化且可继续 | 先同基础阶段，再同物种键缓存当前形态数据是否有有效后续进化记录；真才准。已审物种进化目录过滤继承 WP18/31，此处不跑实际进化条件 |
| 白名单／黑名单物种 | 原物种身份在/不在作者完整列表，复制传入列表；不是依显示名或当前战斗类型；空白名单全拒、空黑名单全准 |
| 限制物种个数 | 非空成员中属于作者指定集合的数量 ≤ 上限；通用可配置，队伍模板上限 4、子集模板上限 2。仍须看被装在哪个实际列表，名字不能越过 §2 子集添加差异 |
| 同种／不同种 | 同种：非空成员的不同物种数恰 1，空集 0 不符；不同种：非空者物种不得重复，空集独立规则真；普通规则集成员层先拒空槽。不同形态但同物种仍重复 |
| 最低／最高／总等级 | 成员等级 ≥min／≤max；总等级忽略空槽求和 ≤ 总额。成员阈值本身不夹合法域；调整策略另夹，两者不混同 |
| 禁止物品／不许持物／心之水滴 | 分别当前物品身份不存在或不在作者禁表；完全无当前物；不持 SOULDEW。与战斗 souldewclause 仅禁旧倍率是不同合同 |
| 不同持物 | 所有非空有物成员的物品身份无重复；多个无物可，按身份不按是否有效/查封状态 |
| 严格小杯附加 | 禁 BERRYJUICE/DEEPSEATOOTH；禁已会 SONICBOOM/DRAGONRAGE；禁 SCYTHER/SNEASEL/MEDITITE/YANMA/TANGELA/MURKROW，余真；只是本附加集合 |
| 负向扩展条款（未见默认使用） | ARCEUS 或四果 MICLEBERRY/CUSTAPBERRY/JABOCABERRY/ROWAPBERRY 任一显式假；其余也没有真返回，末尾条件不满足得到空值，在规则合取中仍被拒。不能把注释意图写成「其它允许」 |
| 昵称约束 | 两两名字完全相同立即假；否则会调用昵称检查入口，但当前模块只有实例定义、未导出对应单例方法，存在缺方法异常路径。单成员/空组没有两两循环可直接真；未证明完整名字检查正常可调用 |

昵称辅助文本另有缓存大小写差异、只在两两循环检查较前成员，最后一成员不单独检查；这不是对外保证能禁止全部其它物种名。规则复制/缓存或作者修改需重新复核；不执行模块验证异常。所有规则缺少数据/个体属性时没有统一兜底，布尔假与异常分别保留。

## 4. 临时等级、经验和还原（D）

### 4.1 策略与范围

无调整策略不写等级、返回空记录；有策略先按**两侧当前列表顺序保存双方每个成员完整经验**，再计算指定侧目标等级，逐成员仅当当前等级不同才赋目标等级并重算能力。等级相同者保留级内经验，不统一归到该级起点。请求等级非法会由个体等级写入口拒绝，已经写过的前面成员没有本层事务还原。

| 调整策略 | 目标及参数 |
| --- | --- |
| 固定级 | 两侧所有成员为 L，L 在创建策略时夹 1..最大等级 |
| 上限级 | 两侧各取 min（当前级，L），L 夹合法域；低于 L 者不提升 |
| 对手固定级 | 仅第二侧固定 L，L 夹合法域 |
| 开放级 | 仅第二侧固定为 max（第一侧所有当前等级，最小参数，1）；最小参数没有预夹，第一侧空时起 1，非法最终值可触发写入口异常 |
| 总等级 | 仅第二侧；min/max 分别夹合法域，先全置 min，不检查最小总和是否已超总额；余预算按队伍次序每轮每成员加 1，到总额或各到 max。同数成员尽量均匀，余数偏前；min>max 时停在 min，不交换上下限 |
| 双侧不同策略 | 第一侧/第二侧各用各自策略的等级计算；空子策略保持该侧当前等级；子策略原「只敌/双侧」标志不决定此组合内的适用侧 |
| 单玩家上限 | 上项组合：第一侧上限 L，第二侧固定 L |
| 等级平衡（未见默认使用） | 两侧每成员 R（113−0.072 × 按物种身份查到的种族总和），保存的最小级参数没有参与计算、无本地上下界夹限，最终写入口仍查合法域 |

只有「双侧同策略」类型才被双侧便利入口执行；双侧不同策略类型虽也影响两边，不通过这个便利门。直接主调整入口支持四种适用范围。裸基础调整的默认计算调用了只有类级定义的空调整入口，若直接实例化基础类型存在缺方法路径；列出的具体策略有自己的实现，不因此一概不可用。

等级写入口把经验设该成长曲线此级最低值并更新等级缓存；重算六能力值读取现有 IV/EV/性格/形态等，不自动重学招式、进化或改变友好。HP 按新总 HP 减旧总 HP 的差加到当前值、至少 1（仅原 HP>0 或总 HP 增加时赋），再夹 0..新总 HP；不保证保留百分比，倒下成员遇总 HP 增加可变正。没有在调整器中保存旧 HP/状态/PP/招式/物品作为统一快照。

还原按两侧**当前位置索引**的旧经验：记录有值且当前经验不同，才写旧经验（使等级缓存失效）并重算能力；没有额外旧等级输入，曲线解级沿 WP30。即使策略原只改敌方，两侧经验记录都可用于还原。队伍若重排/替换，不能凭此索引记录保证身份正确还原；调用者负责维持对应。若经验恰相同，不因 HP 或别的字段变了就强制重算。

### 4.2 真实开战顺序与正常返回

普通设施战斗包装先有调试＋按住取消修饰键的跳过路径，直接返回胜利、清临时录像，跳过治疗/调整/战斗/还原；这是明确测试入口，不在本项目执行。

通常路径：先玩家全队完整治疗 → 保存双方经验并调整等级 → 保存双方当前物品身份 → 创建战斗并顺序施加布局/条款 → 内部战斗标志设假 → 通用战斗准备再应用当前临时战斗规则/环境（其中尺寸可覆盖刚设置布局）→ 战斗 → 正常返回后还原两侧经验/能力 → 两队逐个完整治疗、解除 Mega/原始回归、恢复保存的物品身份。最后只决定 1 返回真，其它决定假；胜/败统计、录像完整逻辑留 WP55/58。

该包装没有用统一确保块覆盖所有异常出口；不能将正常返回还原承诺扩大到抛错/强制中断。玩家治疗发生在保存经验之前，结束又治疗，所以它不保留战前受伤/PP/异常；调整器自身的经验还原也不是「恢复所有战斗字段」。完整挑战的原队伍保存/暂停/结束/地图返回留 WP55，本稿已给实际选队及单场调整边界。

## 5. 杯赛/模式的默认组合（E）

详见[默认杯赛与规则目录附表](wp54-entry-rules-and-cup-data.md)。它区分脚本规则工厂、直接规则集样本和会话模式转换，名称相似不代表相同限制。块注释内的历年赛事样例不执行、不作为当前默认。

工厂 Pika/Poke/Fancy/StrictLittle 不论单双，都最后设置恰 3 名；其「双战」只保留场上布局。Prime/Little/Tower/Palace/Factory 由单/双分别设 3/4；Arena 总单打 3。Prime 不加标准资格；Factory 也不加标准资格，只加最高级/UNOWN 禁项/不同种物。不能补「所有杯都禁蛋/倒下/传奇」。StrictLittle 没有不同持物条款、冻结条款或自爆条款，而用自灭及一击必杀/闪避等，详表。

直接样本 StandardCup/DoubleCup/FancyCup/LittleCup/LightCup 初始化仅最大 3/4、最少 1，不带战斗调整或条款；直接 Little 用基础阶段而不是「基础阶段且可进化」，与工厂 Little 不同。直接 Fancy 没有最低 25 或对手总等级调整。模式转换路径又独立：标准队伍限制最高 100 或 50、对手开放下限 30/60/50，附布局；不自动装工厂 Tower 的心之水滴条款或双方上限调整。

默认会话注册已有规则时不重建；显式设置存下给定规则，名字中的 double/factory/open 解析与规则对象内容并非统一同步。设置后还触发调试条件下内容写入工具入口（完整 WP76），本稿只定位，不调用它；脚本定义存在不证明 Demo 接待必可到达。真实地图事件、参赛费用、奖励及重复报名保存仍未验证。

设置条款只是把相应布尔值放入战斗；战斗建立时才施加，不在队伍资格时过滤相应招式。列表之外的未知规则名没有本有界消费者保证；基础空战斗规则操作不改状态。布局依 WP39，原战斗普通规则仍 WP40/42/43/44。
