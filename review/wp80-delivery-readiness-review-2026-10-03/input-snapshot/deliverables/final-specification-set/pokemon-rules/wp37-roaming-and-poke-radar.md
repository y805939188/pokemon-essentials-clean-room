# 漫游与 Poké Radar（净化正文；批次 6）

分类：Pokémon Rules（主）；Creature-RPG（持久个体状态）、Generic Kernel（随机/保存）、Combat Requirements（战斗交界）、Engine/Overworld Integration（步进/地图接点）、User Interface（调试/道具入口）。本文件固定漫游宝可梦与 Poké Radar 的规则合同——状态有哪些、何时初始化与推进、何时可遇见或被替换、战斗结果如何写回、连锁如何开始/继续/中断、哪些入口取消哪些状态。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的与范围

**目的**：供后续规格判断「某漫游条目何时出现、某草丛摇动意味着什么、某战斗结束后连锁还在不在」，不再各自追踪。

**范围**：① 漫游配置、状态与初始化；② 漫游位置推进与可遇见判定；③ 漫游遭遇替换与跨战斗存续；④ 雷达使用、充能与摇动草丛；⑤ 雷达候选、闪光与连锁延续；⑥ 取消、事件顺序、保存与跨域边界。

**非目标**：不定义普通遭遇算法、战斗终局与结算、捕获接收、逃离许可、创建/覆盖入口通用合同、钓鱼、场地招式（各归已有主规格）；不定义个体生成全部修饰（本文件只登记漫游/雷达特有分支）。

**已通过边界（继承，不重开）**：GR-011（步进、转向、主动请求是不同入口；主动请求包装本身不写遭遇触发标记）、GR-013（参战标记及正常终局合同按已批准字节引用）。本文件不为漫游/雷达补「所有请求统一写标记」的规则。

## 2. 概念与术语

- **漫游条目**：配置数组的一条——`[物种, 等级, 开关编号, 遭遇方式, 战斗 BGM(可选), 专属路线图(可选)]`；**配置存在不等于 demo 中开关已被打开**（开关状态是运行时数据，U01）。
- **漫游状态（持久，全局元数据）**：`roamPokemon[i]`（**空＝未生成/已重置；个体对象＝已有持续个体；true＝已终结**）、`roamPokemonCaught[i]`（终结原因：true＝被捕获、false＝被击败）、`roamPosition[i]`（当前所在地图 ID）、`roamedAlready`（当前地图上已遇到过漫游的标记）、`roamEncounter`（本次待用的漫游选择；战斗中清空）、`pokeradarBattery`（雷达剩余充能步数）。**持久 ≠ 已落盘**——落盘只经保存流程（《保存、启动、新游戏与继续》）。
- **暂态**：`roamer_index_for_encounter`（本次待遇条目下标）、`poke_radar_data`（连锁数据：[物种, 等级, 连锁数, 摇动草列表, 上次捕获标记]）、`force_single_battle`（强制单打标记）——均在临时对象上，不随存档持久。
- **路线图**：键＝地图 ID、值＝可推进到的地图 ID 数组；单条目有专属图时覆盖全局图。默认全局图共 **10 张地图**（键 5、21、28、31、39、41、44、47、66、69），**每图各有其余 9 图作普通邻接**；1/32 额外随机候选仍从全部 10 个键中取、**可能抽中当前图**。
- **惰性初始化**：`roamPosition[i]` 为空时，各消费点（推进、可遇见判定）就地从该条目路线图的键中随机取一个写入——**首次初始化没有独立入口**。
- **雷达连锁（chain）**：`poke_radar_data` 存在即连锁中；**草丛成为闪光（摇动草的稀有度＝2）、生成个体标闪光（生成钩子按格赋值）、连锁继续（概率判定）是三件事**。
- **取消（cancel）**：清空 `poke_radar_data`（临时连锁）的统称；**各取消调用者只清临时连锁，不动电量/统计/最长纪录**——除非另行注明。

## 3. 漫游配置、状态与初始化

### 3.1 条目与路线图配置

- **条目结构**：每个漫游条目为六元配置——物种标识、等级、开关编号（**>0 时开关为 ON 才漫游/可遇见**；≤0 恒启用）、遭遇方式（0＝草地/洞穴步行/冲浪（陆地类＋水）、1＝草地/洞穴步行（陆地类）、2＝冲浪（水）、3＝钓鱼、4＝水基（冲浪＋钓鱼））、战斗 BGM（可选，非空才写下一战 BGM）、专属路线图（可选，覆盖全局图）；全部条目按配置数组的下标索引。
- **默认数据样本**：LATIAS（Lv.30、开关 53、方式 0、「Battle roaming」）、LATIOS（同前）、KYOGRE（Lv.40、开关 54、方式 2、无 BGM、专属 4 图路线（键 2／21／31／69））、ENTEI（Lv.40、开关 55、方式 1）。全局路线图为 **10 张地图的邻接表（每图 9 条普通邻接）**。
- **遭遇方式与当前遭遇类型的映射**：**方式 0**＝陆地类或水、**方式 1**＝仅陆地类、**方式 2**＝**仅水（water，不含钓鱼）**、**方式 3**＝**仅钓鱼（fishing）**、**方式 4**＝水基（water＋fishing）；捕虫大会不属任一。**类型来源分开**：该判定**重新按玩家当前位置查询遭遇类型**（冲浪走 Water 分支、陆地地形走 Land、否则 Cave——**查询可能返回空**），**不读取主动请求保存在临时状态中的类型**（钓竿/击掌/甜香等主动请求把请求类型另存临时字段后触发同一候选钩子，两类来源按入口分列）。**空查询边界**：流程走到方式查询而位置查询为空时，严格类别解析在该处失败——**不能推导普通遭遇安全保留**（不虚构回退）。**方式配置是数据、当前类型是运行时状态**——两者按上表匹配，不按注释推定，也不写成「方式 2 一律禁止钓鱼请求」（冲浪玩家发起主动钓鱼时位置查询得 Water、方式 2 仍可通过）。

### 3.2 状态机与初始化

- **状态三分**：**未生成**（`roamPokemon[i]` 为空——尚无持续个体；重置后也回到此态）、**已有持续个体**（个体对象——首次遭遇时生成并复用）、**已终结**（true——被击败或被捕获后；`roamPokemonCaught[i]` 记录终结原因）。
- **初始化路径**：`roamPokemon`/`roamPokemonCaught` 数组惰性创建；`roamPosition` 惰性创建并按物种存在的条目随机填图，或单条目惰性填图；**不存在「建档式」首次初始化入口**——所有首次写入都是就地惰性完成。
- **重置入口的实际条件**：逐条目检查——**仅当该条目已终结且终结原因为被捕获时，才把该条目恢复为未生成（可再遇）**；**被击败未捕获的条目（终结且原因为非捕获）不动**。**注释与实现不一致**（注释称重置「被击败未被捕获」的漫游，实现门却是「已终结且已捕获」——按实现如实登记，不按注释概括成「全部复活」或「全部清空」）。当前基线**无正常脚本调用者**（调试/事件潜在调用归 U01；不据此断言功能不存在）。
- **辅助入口**：把指定条目位置随机重置为其路线图中的任一图（无正常调用者，单列）。

## 4. 漫游位置推进与可遇见判定

### 4.1 地图进入通知与推进

- **触发条件（换图通知）的真实输入与充分早退条件**：处理器仅在**以下条件全部成立**时才早退（不推进、不清 `roamedAlready`）：地图信息表可载入 **且** 旧地图 ID 为正 **且** 旧条目存在 **且** 旧条目的**原始名称**存在 **且** **旧原始名等于当前解析显示名**（当前名来自地图元数据等解析，两种名字来源分开）。**任一前置缺失（旧 ID 为 0、旧条目缺失、旧名缺失、两侧名字不等）→ 全体推进并清 `roamedAlready`**——无法证明同名时不保持旧状态。配置对照：两张图的解析显示名同为「Route A」，但旧信息表原始名是「Internal A」——比较不相等，**仍推进**（普通对照：旧原始名与新解析名相等才不推进）。**再次遇见限制的写入入口只有三类**（本推进、战后写回、具名调试分支——**三类入口，不按源码写点计数**，具名调试分支内含多个写入处）——**没有按日重置**（经过午夜本身不清该标记）。
- **全体推进**：先惰性初始化位置（§3.2），再逐条目推进。
- **单条推进**：开关关闭（>0 且 OFF）或物种不存在 → 不动；取路线图键集（**键集为空 → 直接返回**）；当前图缺失 → 惰性随机填图；取当前图的邻接表——**当前图不在路线图键中（邻接表为空）→ 直接返回、不推进**；邻接候选全部入列；**1/32 概率额外加入一个全图随机候选（可与邻接候选重复——重复项按入选次数加权）**；从候选中随机选一写入位置。

### 4.2 可遇见判定

- **替换钩子位置**：普通遭遇选择钩子上注册——**在雷达连锁钩子之前执行**（注册次序： overworld 目录先于 items 目录；§8）。每次触发先清 `roamer_index_for_encounter`。
- **前置门（任一不满足 → 保留普通遭遇）**：`roamedAlready`（本图已遇）；伙伴在场；**雷达连锁数据存在**；**75% 概率跳过（即 25% 通过）**。
- **逐条目门**：物种存在；开关启用；**未终结**（条目状态不是终结占位）；位置（惰性初始化）；**位置判定**——在当前地图，或**同名同区域**（该位置的城镇图区域与当前区域相同 **且** 按 ID 解析的图名等于当前图名——两个条件同时成立，缺元数据或区域不一致即排除）；**遭遇方式允许**（§3.1 映射）。全部通过 → 候选 `[条目下标, 物种, 等级, BGM]`。
- **选择与写入**：候选空 → 保留普通遭遇；否则**随机取一候选**：写 `roamEncounter`（本次待用选择）、`roamer_index_for_encounter`、**下一战 BGM**（仅当条目配置了非空 BGM）、**强制单打标记**、并把遭遇的物种/等级替换为该条目。
- **双打抑制**：强制单打标记使双打判定为否——漫游/雷达替换遭遇恒为单打。

## 5. 漫游遭遇替换与跨战斗存续

### 5.1 覆盖开战与持久个体

- **覆盖钩子**：公开开战包装在单一敌方且允许覆盖时触发；**已被其它钩子处理（处理标记非空）→ 不动**；无待用漫游选择 → 不动；否则把处理结果设为漫游战斗的返回。**正常替换链**：步进/主动请求 → 普通候选 → 漫游钩子替换（§4.2）→ 公开包装 → 覆盖钩子 → 漫游战斗。**被其它钩子先处理、提前拒绝、异常未到清理点不与正常返回合并**（处理机制如实登记）。
- **首次生成 vs 复用**：条目尚无持续个体时经生成入口按该条目物种与等级生成野外个体并置漫游生成标记（遭遇规格引用：野外道具、闪光重抽、病毒、性别/性格修饰照常；**漫游生成标记只跳过「同步」性格复制**）；**已有持续个体则复用同一对象**。
- **持续范围**：**同一对象跨战斗复用，按真实战斗/正常终局处理后的持久个体**——不是「全部状态冻结」：终局时**双方场上对象的已激活离场能力效果对该个体同样生效**（战斗结果规格引用：自然回复可清除其异常状态——**再次遇见不保留那份麻痹**；再生力类在战斗结束明确跳过）；**仅玩家侧队伍的形态回调与物品还原不覆盖漫游个体**（已批准的清理边界，本文件不泛化）。**招式 PP 按真实招式回写门同步**（战斗中消耗的 PP 写回持久个体的对应招式；战斗临时替换招式不泛化为全部永久招式变化）；**没有「持有物冻结」保证**（玩家侧物品还原不适用于对方个体，道具层面的变化按实际战斗效果保留）。首次生成后身份（个体编号、闪光）固定复用。
- **战斗规则**：强制单打＋「总是逃跑」规则（逃离规格引用——对手每回合尝试逃跑）。
- **结果写回**（结果编号引用战斗结果规格）：**击败（1）或捕获（4）→ 条目终结**（状态写为终结、终结原因记为「是否捕获」）；**所有结果**都清本次待用选择、**再次遇见限制置真**（`roamedAlready`）、清暂态下标；随后显式触发战斗结束钩子（参数＝物种/等级/结果——**雷达连锁钩子在此消费**，§7）；**返回布尔按行为表述：玩家失败/平局为否，其余正常结果为是**。
- **逃离（3）/玩家失败（2）/平局（5）/中止（0）**：条目**不终结**——**保留的是经真实战斗与对应终局处理后的持久个体**（双方有效离场能力效果对该个体同样生效——自然回复可清其麻痹等状态，**不终结 ≠ 状态不变**）、本图**再次遇见限制置真**（**没有按日重置**）、待用选择清空。战斗结果编号、外层布尔返回、是否实际开战、是否提交终结记录是**四种不同输出**（返回布尔 ≠ 终结记录）。
- **触发次序**：**正常公开链**——漫游战斗直接调核心开战（不经公开包装的战后钩子）→ 自身在结果写回后显式触发一次战斗结束钩子（§8 的限定范围）；**人工直接入口**（直接以物种/等级实参调用）可在清理完成后、构造通知参数处失败（§8.2）；**野生跳战**（无可战斗成员/调试+CTRL）返回胜、条目按终结记录（§8.2）。

## 6. 雷达使用、充能与摇动草丛

### 6.1 许可门与使用

- **许可门的真实顺序**：①**地形**——当前格必须是「陆地野外遭遇＋显示草丛摇动」的地形（否则「不能在这里使用」）；②**普通陆地遭遇表**——当前地图未定义陆地类遭遇（忽略捕虫大会）→ 同消息；③**骑车** →「骑车时不能使用」；④**调试直通**（调试模式且按 CTRL）→ 直接放行；⑤**电量**——剩余充能 >0 →「电池没电了！还需 {N} 步」拒绝。**不能把调试绕过推广到全部前置门**（调试只在④越过⑤，①②③仍在前面拦截）。
- **使用**：统计雷达使用数 +1；**连锁数据惰性初始化（已有连锁数据则保留——再次使用不清连锁）**；上次捕获标记重置为 false；**电量写 50**；执行摇草（§6.2）；返回 true。
- **道具入口分开**：场外使用入口 → 直接执行使用；背包入口 → **预检通过才返回 2**（袋内预检与实际场外执行分开；背包侧不执行摇草）。POKERADAR 为重要道具（口袋 8，内容数据样本）。
- **计步充能**（玩家迈步通知）：**仅当电量 >0 且无连锁数据时**每步 −1（**连锁存在期间不计步充能**——`poke_radar_data` 存在即不递减）；随后**当前格地形失效（非陆地遭遇/不显示摇草）即取消连锁**（§8）。

### 6.2 摇动草丛

- **四环几何**：以玩家为中心的第 i 环（i=0..3，内到外）各随机取 1 格——环为边长 (2i+3) 的正方形边框：上边段（含左上起点）、左右边段、下边段，在第 i 环边框格中**均匀随机抽取**（第 i 环边框共 8×(i+1) 格；独立坐标例：i=0 时共 8 格、边长 3 的正方形边框）。**出图或地形无效（非陆地遭遇/不显示摇草）的格直接跳过**——每环至多 1 格，总数 0～4。
- **稀有度**：每格 25% 为剧烈（1）、否则普通（0）；**连锁存在时**（连锁数 >0）额外判定闪光（2），概率按独立数学定义（设闪光基准常数 c=`SHINY_POKEMON_CHANCE`、链长 L）：**基数 B=⌊65536/c⌋**（首次整数除法**向下取整**）；**分母 D=max（B − 200×min（L, 40）, 200）**；**阈值 T=⌈65536 / D⌉**（转实数**向上取整**）；**概率 P=T/65536**，以 0..65535 均匀整数小于 T 判定——**三个量分列，不是同一等式**（默认 c=16、L=40：B=4096、D=200、T=328、P=328/65536≈0.5%；配置变体 c=100、L=1：B=655、D=455、T=145——漏首次向下取整会错得 144）。**无连锁不执行此判断**；连锁长度只影响闪光摇草概率，不影响环几何。
- **无有效草丛**：四格全无效 →（显示消息为真时）「草丛保持安静……」 → **取消连锁**。
- **表现**：按稀有度播对应摇动动画（普通/剧烈/闪光动画 ID 取自配置，默认 1/5/6——资源规格引用，素材存在性未证）→ 写入摇动草列表（连锁数据中）→ 等待 0.5 秒。

## 7. 雷达候选、闪光与连锁延续

### 7.1 候选选择

- **非连锁开始使用（连锁数＝0）**：雷达专属遭遇查询——**只有剧烈/闪光草（稀有度 >0）才查雷达专属表**：当前地图＋遭遇版本的 PokeRadar 表存在且**通过步概率门**（以 0..99 均匀整数小于该表步概率判定）→ 按权重随机一条、等级在范围内随机；**未命中步概率门、表不存在或表为空 → 回退普通表**：普通遭遇选择（遭遇规格引用：重抽次数＝稀有度+1——普通草 1 次、剧烈 2 次、闪光 3 次，多次取最大值偏向稀有项）。**雷达专属选择与普通重抽不是同一算法，不混用**。**空候选边界**：回退的普通表为空/缺失时返回空候选，**随后读取其物种/等级处失败**——不虚构回退结果。
- **连锁中的遭遇（连锁数 >0，在摇动草上）**：先取该格稀有度 → **继续判定**：连锁继续分按独立数学定义（设环号 r∈{0,1,2,3}、链长 L、上次捕获标记 k∈{0,1}）：**继续分 K = 58 + 10×r + ⌊min（L, 40）/4⌋ + 10×k**（链长修正项为整除下取整）——**闪光草（稀有度＝2）必定继续**；否则以 0..99 均匀整数小于 K 判定（K 可超 100——按实际比较规则，超界即恒真）。继续：遭遇＝连锁数据的物种/等级、强制单打。
- **延续失败的有限改选**：判定失败 → 进入至多 100 次普通表重抽循环，**两道门分开**：**循环提前停止门只看物种**——某次重抽（或初始候选本身）物种与连锁不同即停（初始候选已经异种时 0 次重抽）；**同物种不同等级不停止循环**、继续消耗剩余次数。**循环结束后的最终判等门看物种与等级同时相等**——最终候选与连锁物种等级全同 → **无法断链、继续连锁（强制单打）**；不同 → **断链（取消连锁数据）**。**空候选边界**：普通表为空/缺失时重抽返回空候选，**随后读取其物种/等级处失败**——**不会到达最终判等、强制单打或取消分支**（真实 100 次耗尽与空候选异常分开；零链取候选的回退消费同样在该读取处失败）。**不能把「尝试改选」写成「必定改成不同物种」**。

### 7.2 闪光三件事

1. **草丛成为闪光**：摇草时按 §6.2 概率把该格稀有度标为 2（显示闪光摇动动画）。
2. **生成个体标闪光**：生成钩子——**玩家站在稀有度＝2 的摇动草上**时把生成的个体标为闪光（个体持久属性；发生在生成阶段，遭遇/属性规格引用）。
3. **连锁继续**：稀有度＝2 的摇动草使继续判定**必定通过**（§7.1）——三者分别负责显示、个体属性与连锁走向，不互相推出。

### 7.3 战后更新

- **战斗结束钩子**：连锁数据存在且结果为**击败（1）或捕获（4）** → 连锁数据更新：物种/等级＝本次战斗的物种/等级、**连锁数 +1**、最长连锁统计取大、**上次捕获标记按「本次结果是否为捕获」置真或置假**；随后**静默重摇草丛**（不显示「保持安静」消息——但若重摇无有效草丛仍取消连锁，§6.2）。
- **其它结果（逃离/失败/平局/中止）或无连锁数据** → **取消连锁**（清空临时数据）。
- **刷新草丛与增链的次序**：先更新连锁数据与统计，再重摇——重摇使用更新后的连锁数计算闪光概率（§6.2）。

## 8. 取消、事件顺序、保存与跨域边界

### 8.1 取消调用者全表（各自清理范围）

| # | 取消调用点 | 触发条件 | 显示 | 清理范围 |
| --- | --- | --- | --- | --- |
| 1 | 摇草无有效格 | 主动使用或战后重摇，四格全无效 | **主动使用时有「保持安静」消息；战后重摇静默** | 清临时连锁 |
| 2 | 遭遇类型/骑车/伙伴（雷达钩子） | 当前遭遇类型类别非 land、骑车中、伙伴在场 | 静默 | 同上 |
| 3 | 改选断链 | 继续判定失败且最终改到不同候选 | 静默 | 同上 |
| 4 | 非摇动草丛遭遇 | 遭遇不在任何摇动草格上（含普通遭遇、漫游替换遭遇） | 静默 | 同上 |
| 5 | 战斗结束其它结果 | 结果非击败/捕获，或无连锁数据 | 静默 | 同上 |
| 6 | 计步离开地形 | 当前格非陆地遭遇/不显示摇草 | 静默 | 同上（电量递减判定在其前、按当时状态分别执行） |
| 7 | 地图进入 | 任何换图（注册在漫游推进之后，§8.2） | 静默 | 同上 |
| 8 | **上车** | **尚未骑车、成功上车**——立即取消（不必等下一步或遭遇）；**已骑车再调上车入口 → 早退、不取消** | 静默 | 同上 |

- **全部八个调用点只清临时连锁数据**；电量、使用数、最长连锁统计**不因取消重置**（各自字段的生命周期分列）。`roamedAlready` 只在漫游推进（换图且 §4.1 充分早退条件未全部成立的全体推进——**含旧 ID 0／缺信息分支**，「换名换图」只是其常见情形）、具名调试分支与战斗结束写回三类入口变化，**雷达取消不影响漫游状态**。

### 8.2 事件注册/调用次序

- **同一候选钩子**：漫游替换钩子**先**、雷达连锁钩子**后**（按注册点所在目录与全脚本检索核对）——漫游钩子含「雷达连锁数据存在则跳过」门；雷达钩子对非摇动草遭遇一律取消连锁。两个钩子对同一遭遇的修改按此次序生效；**不把文件名排序直接当成完成的时序证据**。
- **换图钩子**：漫游推进（按 §4.1 的完整充分早退条件判定——未全部成立则全体推进并清 `roamedAlready`，**含旧 ID 0／缺信息分支**）**先于**雷达取消注册——先推进漫游，再清雷达连锁。
- **战斗结束钩子**：**正常公开链的单次合同成立但须限定范围**——公开开战包装在**单敌方、允许覆盖、未被别的覆盖处理且正常抵达通知**时触发一次（雷达连锁路径由此消费）；漫游战斗函数不经该包装、在自身结果写回后显式触发一次。**人工直接入口与异常分支分列**：生成入口接受个体或物种/等级，但**通知参数读取的是原始实参的个体属性**——传物种标识时，核心与漫游清理（清待用选择、置 `roamedAlready`、清暂态下标）可正常完成，**随后在构造通知参数处失败**（无战后通知、无正常布尔返回；**清理前失败与清理后失败分开**，不是泛称的「异常未到清理点」）。**野生跳战对照**：跳战条件成立（玩家无可战斗成员或调试+CTRL）时核心返回 1（胜）——**未实际开战也会把条目标记为终结**（不能自动写成结果 0）。**禁止「每条路径不重复不缺失」的泛化**。
- **强制单打标记**：由漫游/雷达钩子写入，步进与主动请求路径各自在战斗结束后复位（遭遇规格引用）。
- **生成期修改**：雷达闪光赋值在个体创建通知（与遭遇规格的生成修饰同钩，按注册序执行）。

### 8.3 保存与持久边界

- **持久（全局元数据，随存档保存，《保存、启动、新游戏与继续》引用）**：`roamPokemon`（含持续个体对象）、`roamPokemonCaught`、`roamPosition`、`roamedAlready`、`roamEncounter`（虽为「本次待用」但字段在全局元数据上——**战斗中即清空，保存只能存到其当前值**）、`pokeradarBattery`。**普通当前版本载入与版本迁移分开**：标记格式转换属于 **v20 版本门的迁移**（仅对更旧保存版本执行；普通当前版本载入**不执行**该转换）——转换逐项处理：空项跳过、旧整数标记的个体转换格式、已是新格式的跳过；**漫游数组中的终结占位（非个体）在被读取标记处失败**——有界人工迁移反例（版本 19 存档、此前容器均满足前置，漫游项依次为空/旧标记个体/终结占位）：前两项可跳过/转换，到占位时报错，**不能声称全部漫游标记更新成功或已写回**（不是实际旧存档运行结果；不承诺异常事务回滚；《迁移、失败与恢复》合同不重开）。
- **不持久（临时对象）**：`poke_radar_data`（连锁全部内容）、`roamer_index_for_encounter`、`force_single_battle`。**保存并不天然保存全部连锁**——连锁在保存/载入后不存在；**不把内存字段变化写成已经落盘**（没有运行存档恢复，只写静态可证的持久边界）。
- **demo 可达性保留**：漫游开关事件、雷达获取事件、调试工具的实际地图接点与调用链归 U01/demo 规格；没有脚本调用者不等于功能不存在（§3.2 的重置入口同此）。

### 8.4 调试路径（单列，非用户流程）

- **调试漫游画面**（按输入列门、写入和不写入）：
  - **状态显示**：逐条目（ROAMING/CAUGHT/DEFEATED/NOT ROAMING）。
  - **逐条 USE**：**选中条目行即响应（不要求条目已启用）**——状态循环首分支恰好处理关闭的开关：**开关编号 >0 且开关关闭 → 打开该开关（未漫游 → 漫游）**；其后依次为：漫游 → 已击败（终结、原因非捕获）→ 已捕获（原因捕获）→ **仅当开关编号 >0 时**回未漫游（开关置 OFF、清条目与原因）；**开关 ≤0 的条目停在已捕获、再次 USE 无该末分支**。**USE 不写 `roamedAlready`**。
  - **ACTION**：**仅在条目启用且未终结时响应——该外层门同时覆盖普通 ACTION 与 CTRL+ACTION**——先推进一次；**位置仍相同则清位置再推进一次（有限尝试，不保证最终不同于旧图）**；随后清 `roamedAlready`。
  - **CTRL+ACTION**：**同受 ACTION 外层门（条目启用且未终结）——被该门挡住时不切位置**；通过时**只把位置在当前图与空间切换**——**不清 `roamedAlready`**。
  - **USE 与 CTRL+ACTION 的关闭开关对照**：选默认 KYOGRE（开关 54 关闭、其它调试容器合法）——按 **USE**：开关 54 被打开（条目转为漫游）、`roamedAlready` 不变；按 **CTRL+ACTION**：被外层门挡住、不切位置。
  - **全体命令**（「全部漫游换位置」「清空全部漫游位置」）：**仅在条目列表非空的执行分支**分别全体推进/全部位置清空，并清 `roamedAlready`；空列表只蜂鸣。
- **雷达调试直通**：许可门第④门（调试+CTRL 越过电量门）；无雷达状态调试编辑入口（未定位）。

## 10. 边界、失败与未知

- **空路线/缺当前位置**：路线图键集为空 → 单条推进直接返回；当前图不在键中（邻接表空）→ 不推进；无邻接候选时不写位置。
- **无可遇见条目**：开关全关/全终结/位置全不匹配/方式全不允许 → 候选空、保留普通遭遇。
- **换图早退的充分条件**：换图时**仅当 §4.1 的完整充分早退条件全部成立**才不推进且不清 `roamedAlready`；**任一前置缺失或两侧名字不等 → 全体推进并清该标记**——「同名不同 ID」只在上述充分条件意义上不推进，不是无条件承诺（含旧 ID 0／缺信息分支）。可遇见判定另有「同名同区域」通道。
- **首次即终结后**：被击败未捕获的条目在当前基线**没有正常复活路径**（重置入口只覆盖已捕获条目且无正常调用者）。
- **改选两道门与空候选**：循环提前停只看物种（同种异级不停）、最终判等看物种与等级全同；**空候选在读取处失败**（不到达最终判等/继续/取消分支）；雷达专属表步概率门未命中/无表 → 普通表回退（回退亦受空候选边界）。
- **战后重摇无有效草丛**：静默取消连锁；**上车成功立即取消**（已骑车重复上车早退）。
- **覆盖竞争**：覆盖钩子已被处理时漫游不再覆盖；异常未到清理点时 `roamEncounter`/暂态下标的残留按字段生命周期处理（不虚构清理保证）。
- **未证的异常清理**：战斗中异常中断（脚本错误）时暂态字段与强制单打标记的清理未逐项验证；demo 可达性具名保留（U01/demo 规格）。
