# Voltorb Flip（净化正文；批次 8）

分类：Pokémon Rules（本玩法）；输入/标记/退出归 User Interface；代币归 Creature-RPG；普通随机/计时引用 Generic Kernel。5×5 隐藏棋盘中通过行列提示寻找 2/3 倍率格，避开雷（Voltorb，值 0），可中途领取累积得分。全部内容为静态证据；**无运行确认、无抽样或蒙特卡洛证据**（见 `../scope-statement.md`）。

## 1. 目的、分类与输入输出

入口无可选级别或难度实参；每次新会话从等级 1 开始，最高 8。包装要求持有 COINCASE 且代币不等于上限；**零代币允许开始**，没有下注和入场费，盒不消耗。场景直接入口没有相同持物守卫；每次新棋盘先生成/建显示，然后在余额 ≥ 上限时提示并设置退出。余额夹限/类型校验引用玩家规格。输出为代币与 `coins_won` 写入，未定义可供事件兑奖的胜负结果码；级别只在本会话推进，离开后不保存级别。

## 2. 数据、生成与有效性

格值域 0、1、2、3；25 格，5 行 5 列。每一级的有序候选行、雷/二/三/一数量和两类阈值见[候选附表](wp69-voltorb-layouts.md)：一级 5 项，其余各 10 项，总 75 项。重复内容计数但不同限制的行仍独立等权候选。

每次尝试先从该级候选行均匀选 1 项；按其 0/2/3 个数及补足的一格构成多重集合，洗牌分配到行优先的 25 格。再统计行/列雷数。一个倍率格若其行**或**其列没有雷，就称免费倍率格。将这些格分别累计到所在行、所在列，并计总数。

接受条件为：总免费数 < 该行 G，且每行免费数 < F、每列免费数 < F。阈值是严格上界；不是「至多 F/G」。拒绝后重新抽候选行并重新洗牌。最多尝试 1000 次，**1000 次全部不合格时仍返回最后一次棋盘**，没有报失败、降级或再生成；所以免费格阈值不是无条件终局不变量，格值数量仍来自最后候选行。

单次候选行的均匀性不推出最终行均匀；不同候选接受率、重试条件、洗牌宿主行为和最终失败回退都会改变分布。最终棋盘/收益概率未解析，未运行生成器。

## 3. 提示、移动、标记与翻牌

每行及每列显示全部格值之和和雷数；和是加法（雷贡献 0），不是倍率积，也不随揭牌扣掉已知格。显示持久代币、当前可取奖额和等级。新棋盘所有格隐藏、奖额 0、光标左上、标记空、普通模式。

四方向使用单次触发，越边循环到对边；不承诺按住重复移动。ACTION 切换普通/标记模式。标记模式 USE 仅切换当前坐标的一种标记（无 1/2/3 多标记系统），不翻牌、不改得分。检查「未揭格」只守卫标记音效，实际标记增删并未受此条件限制：已揭格也能存标记，可能被牌图遮挡。普通模式翻有标记的格仍可执行，标记不提供保护；已揭格 USE 不重复计分。

普通模式 USE 在未揭格上先播放翻牌，再把该格记为已揭。安全格若当前奖额 0，设为格值；否则只有 2/3 会乘该值，1 维持原值。所有倍率格均已揭开即自动过关，不需翻完 1，也不需标出所有雷。单盘完全收益是 2 的二格数次幂乘 3 的三格数次幂，默认候选的最大固定乘积 3456；这是数据上界，不是期望收益。

## 4. 状态机、结算与上限

| 当前状态 | 条件/输入 | 转移与提交 |
| --- | --- | --- |
| 新会话 | 初始化等级 1 | 生成棋盘 → 构造显示 → 余额上限检查 → 操作 |
| 操作 | 安全格且仍有未揭倍率 | 更新奖额，留本局 |
| 操作 | 揭完所有倍率 | 显示过关/所得 → 加持久代币 → 按实际增量加 `coins_won` → 奖额清 0 → 揭示全盘并等 USE/BACK → 收牌 → 等级+1（最多 8）→ 新棋盘 |
| 操作 | 踩雷 | 记雷已揭 → 爆炸及 0 收益提示 → 揭全盘并等 USE/BACK → 收牌 → 失败级别分支（§5） |
| 操作（任一模式） | BACK，拒绝退出确认 | 回同棋盘，保留分数/已揭/标记 |
| 操作 | BACK，确认退出且奖额 >0 | 先所得提示 → 立即加币和统计 → 奖额清 0 → 揭盘等待与收牌 → 设置退出 |
| 操作 | BACK，确认退出且奖额 0 | 揭盘等待与收牌 → 退出；不写收益 |
| 新棋盘 | 余额 ≥ 上限 | 提示/夹到上限并设退出；不提供继续赚币 |
| 正常退出 | 主循环读到退出标记 | 关闭表现与显示对象 |

得分不是每翻一格立即到账；可见所得提示使用原奖额，实际余额经上限夹限。`coins_won` 只记实际正增量；踩雷失去未领取奖额，不扣此前代币，也不累计 `coins_lost`。与老虎机的会话净额统计不同。

获奖先写余额再记统计，随后还有需要输入的揭盘过程。该过程异常或等待并不撤回已发奖励。场景开始即达到上限时也先生成新盘；主循环一次仍先调用输入处理再检查退出标记，不能声明设退出后绝无额外一帧输入消费（尤其直接调用/胜局触顶路径）。没有自动每日限次或外部日期规则。

## 5. 踩雷与等级异常

等级 1 踩雷：在揭盘和收牌完成后跳过降级分支，奖额归零，重置提示，销毁旧显示并在等级 1 生成新盘；余额和收益统计不变。

**等级 2～8 踩雷存在固定参考失败边界**：计算已揭的正值格数量后，夹限参数次序给出「下界＝当前等级、上界＝1」。下界大于上界，在标准运行库夹限语义下会抛参数错误；全脚本检索未见自定义夹限覆盖。故不能把它写成有效的「按翻开数量降至 1～当前级」。异常发生在雷已揭、爆炸/0 收益提示以及全盘展示和收牌之后，发生在奖额清 0、旧场景销毁与下一盘之前；本次未领分仍留临时变量，持久余额未因踩雷变化。没有本地保证执行的清理或重试。宿主异常呈现未经运行；此处是静态语言语义推导，不是修复建议或正常规则。

## 6. 失败、取消及变体边界

默认候选和正常等级保证有倍率格；直接改数据成无倍率的棋盘可能在任一次 USE 后的过关检查立即触发过关，未提供内容校验。入场无盒拒绝，上限拒绝，余额 0 可玩。普通安全格得分 0→1 后继续揭 1 仍 1，退出可领取 1。标记不改变概率或实际格值。

取消确认按界面规格的 No 处理；揭示整盘的继续步骤 USE 或 BACK 均接受。资源错误、统计状态缺失、倒置夹限等异常不保证关闭对象；已支付的持久增量不会因此回滚。等级变化只支持默认递增和源码中的失败分支，没有对外自选「难度」。
