# 情境、交换、战后成就与事件进化（净化正文；批次 6）

分类：Pokémon Rules（主）、Creature-RPG、Combat Requirements、Engine/Overworld Integration 与 User Interface（触发/提交接点）。本文件补充「谁在何时提供进化条件输入、记录如何累积与清理、由谁调用检查、检查命中后何时真正提交」。全部内容为静态取证与独立固定算术；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的与唯一主规则边界

基础条件族/统一守卫/首目标顺序/成功提交和物品消费主规则继续由**《基础进化》**定义；成长、脚本交换获得、捕获接收、图鉴各归其规格，本文件不建立第二套基础进化公式或提交过程。

三种结果必须分开：①战后承伤门把持久「可进化待触发」标记置真；②检查返回目标或事件触发工具返回命中；③演出未取消并成功提交物种变化。①不改变物种；②可能在可取消演出后仍报告命中；只有③清待触发标记并完成《基础进化》成功序列。

## 2. 情境输入与读取时刻

下表在《基础进化》条件目录上补输入事实，不重新定义全部条件。各条件在其检查被真正调用时读取；不存在统一的「开战时锁定进化情境快照」。详情与默认数据清点见[附表](wp32-context-inputs-and-scenarios.md)。

| 情境 | 实际来源 | 时点/门与边界 |
| --- | --- | --- |
| 日/夜/早/午后/傍晚 | 宿主当前时间 | 日 5≤小时<20，夜其余；早 5–<10、午后 14–<17、傍晚 17–<20。每次谓词缺省读取当前时间；不是战斗背景 time，不依赖 `TIME_SHADING` 或地图是否室外；10–13 只算日 |
| 世界天气 | 当前世界屏幕的天气类型；再由世界 Weather 数据取类别 | 无天气要求类型恰为 None；Sun、Rain/Fog、Hail、Sandstorm 按类别。屏幕不存在则该族不命中；未知类型在取数据处可失败。读取的是已写入的世界天气意图，不等显示淡变结束；不是战斗场地天气/天气剩余回合 |
| 地点编号 | 当前地图 map_id | 不是获得地图、战斗背景或目标传送地图；检查时已经换到哪张图就读哪张。Location 不读坐标/地形；当前地图对象不存在时不补空值保护 |
| 地点旗标 | 当前地图元数据的旗标列表 | Magnetic/MossRock/IceRock 等；不区分大小写；元数据缺失 → 不命中，不要求站在某个岩石格或与某 NPC 交互 |
| 区域 | 当前地图元数据 TownMapPosition 首分量 | 元数据/位置字段缺失不命中；不是图鉴当前观看区域或解锁状态 |
| 黑暗地图 | 当前地图元数据 DarkMap 标志 | 不是当前屏幕亮度、是否已用闪光或战斗夜晚标志 |
| 骑行/冲浪/潜水 | 全局世界元数据对应状态 | 全局元数据不存在则不命中；不由地图名称推定 |
| 队伍有指定物种/恶属性 | **当前全局玩家非蛋队伍** | 可含濒死成员，也可包括被检查者本身；不检查盒子、伙伴拼接战斗队伍或场上类型副本。前一个成员的进化/接收可改变后一个的查询结果 |
| 招式、友好、能力、性别、持物、当前等级/形态 | 正在检查的持久个体 | 读取时的实际值，已完成的战斗成长与终局持物还原在前；不直接用战斗临时招式/属性变化代替 |
| 交换对等方 | 交换画面中的送出旧成员对象 | 收到者的交换检查在收尾读取此对象；§6 的实际 TradeSpecies 关系不得按官方常识改写 |
| 战后成就 | 三份临时队伍索引记录（§3） | 检查当时的索引槽；不是总历史统计或按个人标识查询 |
| 事件编号 | 调用者显式给出的编号；裸检查缺省 0 | 没有编号「已使用」集合；与准备标记/当前物种条目在调用时比较 |

读取会受短路顺序影响：等级不足时不必读取其后的时间/天气；条目按数据顺序遇首个目标就停。常规调用把目标交给演出后，成功阶段不再重跑全部情境条件。等待期间跨时段/地图天气改变，不自动撤销已经选择的目标；持物消费的后置动作仍有其自身「当前还持有/实际目标匹配」检查（《基础进化》）。

地点/时段/天气不会在状态一变化时自动发起进化。它们作为升级类条件，被战后升级检查、等级/经验工具、满级糖果等已有调用者消费。满级糖果无等级增长仍可直接检查此族；这是《基础进化》已审例外，不能要求所有条件必须刚升级。

## 3. 战斗成就记录的建立、写入与清零

### 3.1 三份临时记录与一个持久标记

普通世界野生/训练家核心先通过准入检查，再发开始战斗通知；通知按**此时玩家队伍顺序**建立战前等级 L0、要害次数 K=0、直接承伤 D=0。随后才生成对手/伙伴拼接、创建战斗及开场。蛋的等级也被记下，但战后检查会跳过蛋。无可战斗成员/调试跳过在通知之前返回，不新建三份记录。

这三份记录属于临时状态；下一次开始通知会重建，普通结束通知会在进化检查后置空。持久准备标记 R（ready_to_evolve）属于个体，不因开始记录或一次检查失败自动清除；当本场 D≥49 的特定战后条件执行时可设为真。

### 3.2 要害次数 K 的实际计量域

普通伤害招式的每一有效命中，对各非 unaffected 目标处理要害/克制消息时，若目标本击 critical 为真，K 容器与该使用者队伍槽存在，且使用者为玩家本人所属，就把 K 加 1。没有内部战斗门，也**没有目标必须敌方、非替身或自己当时存活的门**；伙伴使用者不计。画皮/结冻头吸收在这个消息入口最前面返回，故该次不加 K。替身分支只显示替身受伤后继续，因此对替身的要害可计数。多击/多目标是按实际逐击逐目标计量，不是每招至多一次。

本条已由独立首审 CONFIRMED（WP32-N01）：《基础进化》§3.4 的「对对方」摘要过窄，经授权单点同步为本场实际记录次数、目标范围引用本节；旧完整身份留史，不重开旧编号。暴击率公式与判定本身仍引用战斗效果规格；不是本文件自造暴击事件。

### 3.3 直接承伤 D 的实际计量域

普通伤害结算先形成该击实际损失记录 hpLost（致死钳制、撑住等已生效），随后实际扣血/动画/自爆自濒死，再逐非 unaffected 目标进行消息与损失记录。只要 D 容器及目标槽存在、目标属玩家本人，D 加该 hpLost；**没有攻击者必须敌方、非替身、HP 必须真的扣到个体的附加门**。

- 替身被扣的损失也写入 hpLost，因此可累积到 D；个体 HP 可完全不变。
- 混乱自伤单独调用同一损失记录，亦可累积 D；不走要害消息入口，不能据此同时给 K。
- 画皮/结冻头吸收本击 hpLost 为 0；破画皮的附加扣血用普通 HP 减少，不另调用该记录，因此不把那部分计入 D。
- 一般毒、烧伤、天气、入场伤害、反伤/其他仅调用 HP 减少的效果，不因 HP 减少就自动进入此记录。完整招式族以实际是否调用本记录为边界；不把「所有 HP 差」当成 D。
- 同一场内治疗或普通换下不重置 D；只累加、不扣除治疗量。真正濒死处理对玩家本人对应 D 清 0；HP 写 0 还按《HP、状态、招式与持物》清 R。濒死**不清 K**；复活后 D 从 0 重新累积，K 仍保留本场值。

索引存在检查把数值 0 当已初始化有效值，缺失/空槽则不写；不是「只有大于 0 才累计」。直接调用裸战斗且没有世界开始通知时，不补建这些表。特殊模式的通知归各模式主规格，不推定所有战斗都覆盖。

## 4. 从战斗结算到进化的具名时序

| 阶段 | 接收者与状态变化 | 对进化输入的意义 |
| --- | --- | --- |
| T1 战斗中成长 | 击倒/捕获的经验与 EV、等级/学招按成长/战斗结果规格 | 先改变持久等级和招式，战前 L0 仍旧值；普通战斗升级过程不立即跑本文件世界战后扫描 |
| T2 正常战斗终局 | 先图鉴与捕获队列接收；再能力离场、玩家侧一般形态/持物还原 | 新成员可能已入队，旧成员可能已送盒；进化查的是届时队伍和还原后的当前物品 |
| T3 世界外层善后 | 玩家全队清剧毒计数、解除 Mega/Primal；有伙伴则治疗玩家/伙伴；可输且负/平则治疗玩家 | 可能先清 R 或使濒死者恢复；不在此清 L0/K/D；《Mega、Primal 与显式还原》补特殊形态合同 |
| T4 世界结束通知·进化门 | 设置「所有战斗后检查」开，或决定不是 2 负/5 平 | 默认开；关闭时仍包括 0、1、3 逃离、4 捕获，不能写成仅胜利 |
| T5 当前队伍逐成员 | 跳空/蛋；若配置不检查濒死且当前仍濒死则跳；L0 存在且当前等级更高则先查升级族；未得目标再查战后族 | 先升级目标优先；若升级目标已找到，即使其演出随后取消，也不会回头检查该成员战后族 |
| T6 命中或准备 | K 达条目阈值可返回直接进化目标；D≥49 的事件族只置 R=true 并返回假 | 准备不开始演出；无目标可静默；找到目标按《基础进化》可取消演出 |
| T7 清理与后续 | 进化扫描正常返回后，L0/K/D 全部置空；再拾取/采蜜或不可输负/平失败回程 | 取消进化不会保存本场 K/D 供下一场消费；D 转成 R 后 R 可继续保留；失败回程治疗可能再清 R |

默认两配置：`CHECK_EVOLUTION_AFTER_ALL_BATTLES` 随世代 ≥6 为真，`CHECK_EVOLUTION_FOR_FAINTED_POKEMON` 为真。判断濒死使用 T5 时的当前状态，故可输战斗的预先治疗会使成员在该配置关闭时仍满足非濒死门。不可输败局默认先检查进化，再进入失败回程；不凭「已经输了」跳过。

世界显式中止若按战斗结果规格返回决定 0，可继续 T3–T7，但中止跳过正常终局意味着 T2 的捕获接收等不保证发生。准入跳过则无开始/结束通知。回放、设施裸对象或异常未正常返回不自动取得 T3–T7；没有「无论异常都清记录」的兜底保证。

**一次普通扫描不连锁重查同一成员**：每成员至多得到一个目标并起一次演出。后续队员会读取此时已变的队伍；NINCADA 等成功提交可追加个体，普通队伍数组迭代可遇到追加项，但其 L0/K/D 无对应记录，不能继承创建者成就。事件入口另先取可战斗队伍列表，集合语义见 §7。

## 5. 成员移动、捕获替换与成就接收者

| 变化 | 索引与记录 | 后果 |
| --- | --- | --- |
| 普通换人 | 战斗显示顺序变化，个体队伍下标保持 | K/D 随原队伍槽保留；不是换到前台就清零 |
| 场上位置 Shift | 交换场上席位，个体自身队伍下标不改 | 后续记录仍落同一玩家队伍槽 |
| 满队捕获选择旧成员送盒 | 对旧成员离场/解除形态→送盒→队伍删除→将其后的 L0/K/D 及初始持物各左移，末槽置空 | 成就随仍留队的成员移动；被送盒成员不在当前扫描中，临时成就没有写成持久可随盒保存的字段 |
| 新捕获个体填空位或追加 | 接收仅补初始持物记录，不补 L0/K/D | 新成员没有战前等级比较依据或本场成就；不能继承刚移出的旧成员记录 |
| 捕获直接送盒/选择取消后送盒 | 原玩家队伍不变 | 原记录不移位，当前队伍正常扫描；捕获者不参与该次玩家队伍扫描 |
| 捕获替换的选择取消 | 尚未选择要移出的成员前，无该成员的删除/左移 | 此前图鉴等按《捕获判定与接收策略》各自已写；不能把所有操作都视为未发生 |
| 常规结束后手工队伍/储存移动 | 三表已清，R 在个体上保留 | 有存盒治疗时该路径临时保留并恢复 R；一般完整治疗不保留 |

例：起始 [A,B,C]，L0=[10,20,30]、K=[1,3,0]、D=[0,49,5]；捕获 X 替换 A 后，队伍 [B,C,X]，三表分别 [20,30,空]/[3,0,空]/[49,5,空]。检查 B 时用索引 0 命中其自己的成就，X 不用 A 的成就。若 A 原本 D49 但尚未在战后变为 R，则先送盒后不再由本次扫描为 A 建立 R；已从以前战斗得到的 R 是另一事实。

Shadow 战前心量表数组未在上述三表移动代码中处理，Shadow 规格已另列错配观察。不要因为「三表正确左移」就声称所有逐队伍快照都同步。任意外部事件/插件直接重排队伍也没有通用自动同步合同。

## 6. 交换的条件来源、提交与失败

**X01 正常顺序**（获得规格已审获得主流程）：统计交换+1 → 取队伍送出者 → 创建或使用收到个体并改写外来拥有者/昵称/来源、记录首招 → 交换画面在演出前登记收到个体与拥有图鉴 → 交换演出/可选新图鉴页 → 收尾检查收到个体的交换族 → 目标存在则不可取消的进化 → 画面调用结束后才用收到者替换原队伍槽。进化发生时，收到者还没有通过最后一步进入玩家队伍。

**X02 实际条件的接收者**：Trade/男女/日夜检查收到者及收尾时钟；TradeItem 查收到者当时持物。TradeSpecies 的实现比较的是**收到者自己的基础物种是否等于参数**，然后才检查送出旧成员是否持不变之石；不是比较旧成员的物种。收到者自己的不变之石仍由《基础进化》统一守卫阻止全部进化。默认 KARRABLAST 条目参数 SHELMET、SHELMET 条目参数 KARRABLAST，因自身物种不匹配，两条默认交换不会据此进化；交换接收照常。自定义条目若把参数设为自身物种，即使送出的是其它物种，也只受旧成员不变之石门约束。旧成员为空且自身物种分支已命中时，后续持物查询可失败，不补空值保护。

TradeItem 的消耗在成功提交的后置动作，消耗的是收到者仍持有的匹配物品；不消费送出者物品、事件编号或背包。未命中不消耗。正常交换演出/交换进化均没有取消交换出口；之前的「选择要交换哪只」工具可取消，变量写 −1/空名字，由事件调用方决定是否调用实际交换。其拒绝蛋/Shadow/不可交换的门不自动添加到裸交换入口。

**X03 条件图鉴页导致的两处收尾调用**：满足「更常显示新物种条目」＋此前未拥有＋有图鉴＋解锁范围时，交换画面会在图鉴页内调用一次不淡出的收尾；外层交换包装随后仍调用通常收尾。收尾包含交换进化检查，没有「已结束则跳过」的业务标志。脚本的精灵释放工具会清空精灵表，第二次消息窗口因此跳过；但第二次仍直接释放同一显示容器，该宿主重复释放行为未验证。**可静态确认两个检查调用位置，不能保证实际第二次一定抵达检查或二次进化成功。** 若宿主允许继续，第二次按已经变化的收到者重新判断，当前数据普通最终物种通常不再有交换目标；自定义连续交换进化存在重复检查风险。此项具名保留为 WP32-N02，不隐藏在「演出细节」，也不以运行假设修旧稿。

若任一阶段异常，已经写的交换统计、拥有者/图鉴或首次进化状态不回滚，最终队伍替换可能尚未发生。不存在「交换检查命中就表示收到者已在队中」的保证。

## 7. 事件进化与持久准备标记

事件入口有两个层次：

- **全队事件入口**：玩家不存在直接返回；先取得当前可战斗队伍列表（非蛋、未濒死），依序对其中每个对象发起单个体触发。不是扫描盒子；调用中后来追加的成员不在开始列表中。
- **单个体触发**：执行事件检查；无目标返回 false。有目标则启动默认可取消进化并关画面，随后返回 true，**即使玩家取消了演出仍返回 true**。这个返回只报告找到目标并走了演出，不报告物种提交；不另加存活门（只有全队入口选集如此）。

Event 仅比较编号；EventAfterDamageTaken 还要求 R 真。当前默认样本：KUBFU→URSHIFU 编号 1，YAMASK 形态 1→RUNERIGUS 编号 2；具体地点/剧情不在方法里，缺地图事件不能从注释补造石拱门或塔流程。核心检索仅有全队事件入口定义，无正常事件调用实例；保持 U01。

R 的状态机：`未准备 →（战后该条件被执行且 D≥49）→ 已准备 →（成功进化/HP 写 0/一般完整治疗）→ 未准备`。该战后条件未达 49 时不把既有真改假；有不变之石/Shadow/羁绊变身等统一守卫则连设标志步骤也不执行。角色到了目标地点不直接改变 R，只有事件调用判断编号。

事件编号不被消费；取消演出保持物种和 R，可在仍合格时再次用同编号触发，另一个合格成员也可用同编号。成功提交按《基础进化》清 R 与改物种，是**个体**资格改变；不产生全局「编号已用」。取消战后要害进化不同：本场 K 在结束通知仍会清空，下一场不能凭已清 K 自动重试；下一场需重新满足或由合适直接检查提供记录。

## 8. 失败、不变量与保留

判定/待触发/领域提交分层；时间、环境、成员身份与资源的读取点可不同。所有公开说明都受《基础进化》统一守卫；不存在自动更正未知天气/地图或坏队伍索引的保证。

保留：地图事件编号的真实调用、交换接待拒绝条件/奖励、地点可达（U01）；宿主时间/时区/重复释放行为（WP32-N02）、插件及真实队伍并发变化；演出媒体。U01–U10 保留不因本文件静态交付关闭。
