## 1. 目的、范围与非目标

### 1.1 目的

从作者（游戏制作者）视角规定**工程与事件内容的自动转换、整理与外围制作**能力：

- 编译期地图/事件转换（`compile_trainer_events` 及其全部子转换）：训练家注释事件、道具球命名事件、门动画改写、事件名规范化、旧脚本用法替换、文本命令规范化、柜台合并。
- 新地图导入（`import_new_maps`）：Data 目录新地图文件登记进地图信息树。
- 文件名更新器（`FilenameUpdater.rename_files`）：旧图形文件更名与事件引用同步。
- 脚本散文件与归档往返（`scripts_extract.rb`／`scripts_combine.rb`）：Scripts.rxdata ↔ Data/Scripts 目录树。
- 区域地图文本制作（`townmapgen.html`）：town_map.txt 节内容的可视化编辑与文本生成（纯静态阅读结论）。
- 外围宿主工具文档边界（`extendtext.exe`／`extendtext.txt`；`animmaker` 已归 WP74，不重提取）。

### 1.2 范围（A～F）

- **A 入口与触发**：编译生命周期内的调用点与门（WP04 引用）、debug 菜单两项（更名更新、及本包相关入口归属）、命令行两个 Ruby 脚本、浏览器页面、RMXP 外挂程序。

## 2. 概念与术语（实现中立）

- **转换家族**：共享触发与写出方式的一组自动改写。本包六族：新地图导入、训练家注释事件、道具球命名事件、事件改造（门/事件名/通道页/柜台）、旧用法替换、文本规范化。
- **识别谓词**：只判断「长得像什么」的检查（门启发式、通道启发式、柜台启发式、mart/nurse 识别）——命中才改写；识别边界继承 WP61：识别 ≠ 构造模板、不保证不误判。
- **事件简写**：作者在事件名或注释里写的紧凑约定（`item:X`/`hiddenitem:X`、`Battle:`/`Type:` 等注释前缀、注释行内的 `SellItem(道具名,价格)` 括号形式），编译期展开为完整事件命令。
- **地图信息树（mapinfos）**：`Data/MapInfos.rxdata` 中的地图登记集合（编号、名字、顺序）；新地图导入的写入对象。
- **散文件树**：`Data/Scripts/` 目录下的 `.rb` 文件与子目录；与 `Data/Scripts.rxdata`（归档）互为往返。**提取产物按两层编号约定布局**（计数器两级，§12.1）；**作为合并输入的目录层级不设上限**（合并递归无层数上限，§12.2）——两层约定只约束提取侧产物，不是对散文件树本身的全局限制。
- **装载器（loader）**：提取完成后写入 `Data/Scripts.rxdata` 的单节归档（只有一条 Main 记录，内容为一段预置压缩数据）——本包只登记写入形状，不执行、不解包。
- **town_map.txt 节**：区域地图 PBS 数据：`[编号]` 节＋`Name`／`Filename`＋若干 `Point`（字段：X、Y、地点名、地标、飞行图/飞行 X/飞行 Y、开关——Point 模式以 GameData 模式为准，WP04 引用）。
- **已发生写入**：转换/往返对工程文件的实际落盘（地图、地图信息、tileset、系统、公共事件、图形文件、Scripts.rxdata、ScriptsBackup.rxdata）——本包逐族登记，不补原子回滚承诺。

## 3. 入口与触发（A）

### 3.1 编译期转换的调用点（WP04 引用，不重提取）

- `compile_all`（审计名）：不重编译（入参为假）→ 消息并直接返回；否则顺序＝编译 PBS 文件 → 编译动画（WP74 交界）→ **`compile_trainer_events`**（本包主驱动；其入参未被使用，如实登记）→ 翻译收集（WP08 边界）→ 消息保存/载入。主入口 `main` 仅调试模式：缺 PBS 目录则先建目录全量写出并强制重编译；**重编译标志会吸收 `import_new_maps` 的返回值**（有新地图导入即触发重编译）；其后按数据/PBS 文件修改时间判定（`001_Compiler.rb:1015–1070` 定点）。
- debug 菜单 `files_menu` 下「Rename outdated files」（`002_Debug_MenuCommands.rb:1411–1419`）：**先确认**才执行 `FilenameUpdater.rename_files`，完成后提示 Done。

### 3.2 命令行脚本与浏览器/外挂入口

- `scripts_extract.rb`：文件末行调用 `Scripts.dump`（合并入口行被注释）；`scripts_combine.rb`：末行调用 `Scripts.from_folder`（提取入口行被注释）——两文件除入口行外内容相同（各 183 行，同字节数）。运行需要本机 Ruby（README 声明）；本包不执行。
- `townmapgen.html`：浏览器打开的作者工具页；本包只静态阅读 HTML/脚本，不在浏览器运行。
- `extendtext.exe`：RMXP 显示文本/脚本对话框的放大外挂（仅文档陈述，§14）。

## 4. 新地图导入（B；`import_new_maps`）

- **触发**：仅调试模式（非调试返回假）；在 WP04 重编译判定中被调用，返回值并入重编译决定（§3.1）。
- **识别**：扫描 `Data/` 下 `Map*.rxdata` 的数字编号文件；排除已登记在 mapinfos 的编号；**跳过编号 999**（随机地牢图）。
- **转换**：对每个未登记编号新建地图信息——名字 `MAP%03d`（编号三位补零），**顺序从现有最大顺序 +1 起逐个递增**。
- **写出与缓存**：有导入才写 `Data/MapInfos.rxdata` 并清空地图信息运行缓存；消息报告导入数量；无导入不写文件、无消息、返回假。
- **重跑/部分失败**：已登记的不重复导入（幂等）；地图文件本身不被修改（只登记信息）。

## 5. 训练家注释事件转换（C-1；`convert_to_trainer_event`）

### 5.1 触发与识别（R01 修订——收集门与解析支分开）

- 事件有页且首图层命令表 ≥2 条，否则返回 nil（不改事件）。
- **收集门（白名单 13 个前缀）**：逐个注释首行（连续注释行拼为一块）检查——命中 `Battle:`、`Type:`、`Name:`、`BattleID:`、`DoubleBattle:`、`Backdrop:`、`EndSpeech:`、`Outcome:`、`Continue:`、`EndBattle:`、`EndIfSwitch:`、`VanishIfSwitch:`、`RegSpeech:` 之一才收集该注释块（匹配按行首锚定，块内后续行首命中同样入选）；任一入选即进入转换。**`CommonEvent:` 不在白名单内——独立写 `CommonEvent:` 的注释块不被收集、其值被忽略**。
- **解析支（13 条，与白名单不同集）**：`Battle`／`Type`／`Name`／`BattleID`／`DoubleBattle`／`Continue`／`EndIfSwitch`／`VanishIfSwitch`／`Backdrop`／`Outcome`／`EndBattle`／`RegSpeech`／`CommonEvent`——**`EndSpeech` 有收集无解析支**（入选的 `EndSpeech:` 块不产生任何战后台词赋值；战后文本只来自 `EndBattle:`）；**`CommonEvent` 有解析支无收集门**——只在某个已入选注释块的块内行首出现时才被消费，且**每块只取第一个命中支**：块以 `Battle:` 开头时，**Battle 支先命中并把其后整段（含续行）作为战斗文本**——续行行首的 `CommonEvent: 数字` 被吞入战斗文本、公共事件参数仍为默认 0（组合失败）；**真正可达的组合是块以 `EndSpeech:` 开头、末个续行行首为 `CommonEvent: 数字`**——该块靠 EndSpeech 入选、前面无更早命中支，于是进入 CommonEvent 支、该值进入电话登记的公共事件参数（整体转换仍需另有有效 `Battle:` 块）。
- 每个注释块按解析支顺序取**第一个命中支**（一支一块）；未命中任何支的入选块不改变任何字段（保持默认）。
- **必须有至少一条 `Battle:`**，否则返回 nil（此前已收集的其它前缀不产生任何改动）。
- 注释起始于事件第 0 条时，若事件名不含 trainer 字样则改名为 Trainer(3)；若事件名已是 Trainer(N) 形式则保留其 N。
- 转换产生**全新事件对象**替换原事件（同坐标、同 ID；首页图形属性经克隆保留）；**原注释不保留**（保留开关为常量假，如实登记）。

### 5.2 解析（各前缀语义）

- `Battle:` 追加一条战斗文本（可多条＝含再战）；`Type:`/`Name:` 去首尾空白作训练家类型/名字；`BattleID:` 数字（再战系列的起始版本号，默认 0）；`DoubleBattle:`/`Continue:` 值 TRUE/YES（大小写不敏感）为真；`EndIfSwitch:`/`VanishIfSwitch:` 收集开关编号（可多条）；`Backdrop:` 背景名；`Outcome:` 结果变量编号（默认 0）；`EndBattle:` 战后文本（可多条；**一条都没有时默认补一条「...」**）；`RegSpeech:` 登记电话台词；`CommonEvent:`（仅入选块内行首）公共事件编号（电话登记用，默认 0＝不带）。

### 5.3 训练家检查器（TrainerChecker；R02 修订）

- **检查集合按 Battle: 条数分开**（均在本编译驱动内执行，编辑器内不执行）：1 条→只查主战斗（起始版本号）；2 条→**只查主战斗**（第二条文本直接写进再战页、**不查第二个版本**）；≥3 条→查主战斗＋逐个再战（版本号递增）。（运行时首页的系列检查脚本另有运行时合同 `pbTrainerCheck`——调试下确认「新建训练家变体？」，属 WP73-A/WP04 交界，与本编译期检查器是两个入口。）
- **门与「不再问」**：检查器整体先判**调试模式与「不再问」标志——非调试或已置「不再问」时本调用链直接返回**（不产生任何询问或异常）；底层公开缺失入口 `pbMissingTrainer` 的非调试异常是该入口自身合同（WP73-A/WP04 已通过），**不是本编译调用链的结果**。
- 调试且未「不再问」时：**类型不存在**→确认「新建训练家类型？」，是则调训练家类型新建编辑器（WP73-A 交界）；**类型存在但训练家不存在**→经底层缺失入口三回答——是＝调新建入口创建、否＝不创建、**取消＝本次编译不再询问**（检查器置「不再问」标志，后续同类缺失静默跳过）。
- **字符图补设三支（R03 修订）**：事件已有字符图→不经此路径；无字符图且类型存在→查询类型的字符文件名——**解析到名称**→经图像存在性检查，存在才补设；**查询返回空值**（资源路径均无该类型图）→**先与目录拼接即失败**（字符串拼接空值，未保护）——失败发生在存在性检查**之前**，转换无法产出正常新事件（传播边界按编译调用层，WP04 继承；运行形态未验证）。不会「平稳跳过不补图」。

### 5.4 产物页面结构（行为描述；R04 修订）

- **单战斗（1 条 Battle:）→ 2 页**：第 1 页（事件触碰触发）：类型开场、提醒玩家、战斗文本、（双打/背景/结果变量/允许败北按需设置战斗规则）、正常训练家战斗起式条件分支（审计名 `TrainerBattle.start`），分支内置自开关 A；页尾训练家收尾。第 2 页（动作触发、条件自开关 A）：战后文本。
- **多战斗（≥2 条 Battle:）→ 3 页**：第 1 页在单战斗结构基础上**追加一条独立的系列检查脚本命令**（审计名 `pbTrainerCheck`，带战数与版本号——运行时合同见 §5.3）——它是**额外的检查命令，不是战斗起式**；实际战斗仍是随后的正常训练家战斗起式条件分支（先检查、后战斗）。分支内再加「电话可登记？」子分支（登记台词＋Yes/No 选择＋电话登记——带公共事件或版本号的参数变体，公共事件值来自 §5.1 组合路径），自开关 A、B 双置；第 2 页（再战页，条件自开关 B）：开场后按电话变体号分支各战斗文本（首条「不超过」、末条「至少」、中间「等于」），电话起式（审计名 `Phone.battle`）＋胜后重置，自开关 A；第 3 页（结束页，条件自开关 A）：按变体号分支各战后文本（缺省回退到最后一条），并再放一次电话登记子分支（结构同第 1 页）。
- **首页与再战页的背景参数差异（R04 修订）**：首页的背景规则生成**字面字符串参数**（名称按 §15 转义处理后包在引号内）；再战页生成**不带引号的同名文本**——按事件脚本的求值语义它是**待求值内容**：普通背景名（如 forest）在求值环境无同名定义时会失败（经脚本执行的错误展示路径，WP17/WP04 交界；运行形态未验证），默认无背景（未配置 `Backdrop:`）则两页都不生成背景规则。**不能统一预测两页背景配置等效**，也不替参考产物补引号。
- **`EndIfSwitch:N` 页**：每条复制结束页骨架，改条件为开关 N（已有条件 1 则放到条件 2）、清自开关条件、内容为第一条战后文本（无则「...」）。
- **`VanishIfSwitch:N` 页**：同骨架但**无字符图**、无命令（事件在该开关下消失）。

## 6. 道具球命名事件转换（C-2；`convert_to_item_event`）

- **识别**：事件名完整匹配 `item:名字` 或 `hiddenitem:名字`（大小写不敏感；名字为词字符）；**道具必须已注册**，否则返回 nil（不转换）。
- **产物**：2 页新事件（同坐标同 ID；改名为 `Item`／`HiddenItem`）：第 1 页（可见时带「Object ball」字符图）——道具球给予的条件分支＋自开关 A＋否则分支；第 2 页条件自开关 A（空白，表示已拾取）。
- **重跑**：转换后事件名不再匹配前缀（幂等）；不匹配前缀或道具未注册都不改事件。

## 7. 事件改造与修复（C-3）

### 7.1 事件名规范化（`fix_event_name`）

事件名（大小写不敏感、整名匹配）：`tree`→`CutTree`、`rock`→`SmashRock`、`boulder`→`StrengthBoulder`；其它名不改。

### 7.2 门启发式改写（`update_door_event`）

- **外层识别（全部满足才进入后续）**：事件 ≥2 页；末页有开关 1 条件、有字符图、命令 >5 条且首条为条件分支。**外层完全未命中（页数不足、末页无开关条件、无字符图、命令数不足、首条非条件分支）→ 整个事件保持原样**。
- **开关 22 特例（先于结构门执行，R05 修订）**：外层满足后，若末页条件开关恰为 22 但其名字已被改作他用（非 `s:tsOff?("A")`）→ **立即**重新注册该名字到新开关并改用（记为变更；系统开关表可能同时变化）——**此副作用发生在倒数第二页结构检查之前**。

## 9. 文本命令规范化（D-2；Show Text 处理；R11 修订）

按源内实际先后次序执行四个子规则（互不嵌套保证不成立，组合效果见各条）：

1. **格式码规范化**：仅当**行首为反斜杠且码后随空白**才处理——`\B `→`\b`（**空白一并被删除**），`\R `→`\r`，`\PG `→`\pg`，`\POG `→`\pog`，`\G `→`\G`，`\CN `→`\CN`（大小写不敏感匹配、归一为小写或大写形式按源登记）。**裸码无后随空白不改**（`\B` 后无空格 → 不动）；**已小写但码后有空白也会变化**（`\pg x` → `\pgx`，空白被吃掉）。
2. **4 行窗口**：从第 2 行起数，每数到第 4 的续行改为新文本命令首行——9 行文本在**第 5、9 行（一基）**拆分（窗口 4/4/1）。
3. **短首行合并**：首行长度 1–20、**不含 `\n`**、且有续行 → 把第 2 行以 `\n` 并入首行、删除第 2 行、重审本条——**并入后首行已含 `\n`，同一短行规则不再满足**——**只并一次**（第三条行保持为续行，不连锁）。
4. **跨命令断句**：本命令 ≥3 行且下一条也是文本命令，且本命令末行**不含** `.,!?;-"` 结尾字符且**不含反斜杠或 `<`（任何位置）→ 在合并全文中找最后的句读点（优先 `. `/`.\n`/`!`/`?`，找不到退 `, `/`,\n`）；找到则在该点切分：**前半保留为本命令**（多行），**尾段作为新的文本命令（首行＋续行）放到原下一条文本之前**，**原下一条文本被降为续行、内容保留**（不丢弃）；无句读点则不动。
- 每条规则只在实际变化时记变更；命令数/缩进按源行为保持。

## 11. 文件名更新器（E-1；`FilenameUpdater.rename_files`；R17 修订）

- **触发**：debug 菜单 `files_menu`「Rename outdated files」——**先确认**（取消即不执行），执行后提示 Done（§3.1；菜单级确认不是逐文件保护）。
- **阶段 1（图形文件更名）**：`Graphics/Characters/` 下 `berrytree*.png`：跳过已带下划线前缀与四个阶段名（berrytreewet/damp/dry/planted）；其余在 `berrytree` 后插入下划线（`berrytreeX.png`→`berrytree_X.png`）。
- **移动的真实语义（R17 修订——本地复制后删除，不是原子重命名）**：本仓库的 `File.move`＝先 `File.copy`（**读完全部源内容 → 目标已存在则先删除 → 重建并写入目标**）＋**删除源**（`001_Technical/002_RubyUtilities.rb:144–170` 本轮新增证据）。逐点后果：**目标已存在时先被删除**（不比较内容、不再询问）；**重建/写入目标失败**→源尚在，但**原目标可能已丢失或只剩部分内容**；**删除源失败**→可能留下新旧两份。**阶段 1 任一异常都会中止 `rename_files`、阶段 2 引用更新不再执行**（无兜底、无回滚）。目录不存在则阶段 1 返回假（无动作、无警告）。
- **阶段 2（事件引用同步）**：遍历全部地图的每个事件页：字符图名匹配 `berrytree` 后无下划线且非四阶段名 → 同样插入下划线；有改动的地图**立即写回**（`saveMap` 容错），每图一条记录。
- **汇总**：阶段 1 有更名 → 一条更名警告；阶段 2 每图一条记录警告；有任一记录 → 追加「RMXP 数据已被改动，请立即关闭 RMXP」警告；**全无变化 → 无任何警告**（只有完成提示）。
- **重跑**：已更名的文件与引用不再命中（幂等）；阶段 2 不检查目标文件是否存在（如实登记——引用同步不做资源校验）。

## 12. 脚本散文件与归档往返（E-2；`Scripts.dump`／`Scripts.from_folder`）

### 12.1 提取（dump；`scripts_extract.rb` 的活动入口）

- **守卫（R15 修订——数量启发式，不是状态判定）**：读取归档；**节数 <10** 打印「已是散文件状态」提示并返回（不写任何文件）；**节数 ≥10 照常执行**——本方向边界：**9 拒绝、10 放行、11 放行**（与合并方向不同，见 §12.2）。
- **破坏性前置**：创建目标目录后**先清空整个散文件树**（递归删除既有 `.rb` 与全部子目录内容）——README 亦声明「既有散文件会被删除」；无逐项确认。
- **转换**：逐节处理——节名转义为文件名安全形式（9 个实体：`&bs;`＝`\`、`&fs;`＝`/`、`&cn;`＝`:`、`&as;`＝`*`、`&qm;`＝`?`、`&dq;`＝`"`、`&lt;`＝`<`、`&gt;`＝`>`、`&po;`＝`|`）；正文解压并**删除全部 CR**；节名与正文皆空则跳过。
- **目录结构**：`[[ 名 ]]` 节 → 建目录（**两层编号约定**——编号计数器只有两级、按层重置、3 位补零、倒数第二节用 999；**两层约定是提取一侧的布局约定**，见 §12.3 与合并侧的关系）；**等号五连前缀**的节 → 回到主目录；其余节 → `NNN_节名.rb` 写入当前目录（文件编号每目录重置、3 位补零、末节用 999；空名/空节名归一为 `unnamed`）。
- **收尾（写入顺序固定）**：先把原归档**备份**到 `Data/ScriptsBackup.rxdata`，再把 `Data/Scripts.rxdata` **替换为装载器**（单节 Main 记录，内容为预置压缩数据块——本包不执行、不解包，§1.3）。

### 12.2 合并（from_folder；`scripts_combine.rb` 的活动入口）

- **守卫（R15 修订——同一数量启发式、方向相反）**：读取归档；**节数 >10** 打印「已是归档状态」提示并返回；**节数 ≤10 照常执行**——本方向边界：**9 放行、10 放行、11 拒绝**（与提取方向 9 拒绝、10/11 放行相反；两方向的 9/10/11 矩阵分列）。**旧归档只参与进入门**：通过门后**丢弃旧归档列表**、从目录**重新聚合**——合并结果**不包含旧装载器或其它旧节**（如根目录恰一个脚本、无子目录——无论旧档是一节装载器还是其它 ≤10 节输入，**结果只有 1 节**）。**合并产物若仍 ≤10 节**（如上述单脚本产物——1 节），**第二次合并仍通过守卫**——重新聚合并覆盖归档、节 ID 重新随机（**同方向重跑并不必然安全**，如实登记）。
- **聚合**：按目录树**深度优先、字母序**——目录内先收全部 `.rb`（排序后逐个生成节：节名＝文件名去编号前缀与 `.rb` 后缀、按 9 实体反转义、空名归一为 `unnamed`；正文原样压缩；节 ID 为随机数）；再按排序逐个处理子目录：第 0 层每个子目录前先插入一个**等号十八连**的空节，第 1 层先插入空节，再插入 `[[ 子目录名 ]]` 节，然后递归（**递归无层数上限**——三层及更深的散文件树同样被聚合；两层编号约定只约束提取侧布局，§12.1）。
- **写出**：聚合结果**直接覆盖** `Data/Scripts.rxdata`——**不备份**（与提取方向的不对称如实登记）；散文件保留在原地但不再生效（README 声明）。
- **空目录/无 `.rb`**：守卫通过而目录无可聚合内容时，产物为仅含目录结构节的归档（如实登记）。

### 12.3 往返一致性（R16 修订——保留/规范化/丢失矩阵，不再宣称等价）

| 对象 | 提取方向 | 合并方向 | 往返结果 |
| --- | --- | --- | --- |
| 节 ID | 读档使用原 ID | **重新随机** | **不保留**（已知差异） |
| 节标题 | 修剪首尾空白、9 字符→实体转义 | 剥 `NNN_` 前缀与 `.rb` 后缀（**大小写敏感**）、实体反转义 | 修剪归一；**字面实体碰撞**：原标题含字面 `&bs;`（无反斜杠可转义时按字面写入文件名）→ 合并反转义为 `\`（**标题被改变**） |
| 空正文普通节 | **不生成文件**（正文为空的普通节不产生对应 `.rb` 文件） | 无从聚合 | **丢失**（结构节 `[[ ]]`/等号节由目录名重建，普通空节不还原） |
| 空标题/空白标题 | 归一 `unnamed` | 同 | 归一为 `unnamed`（原名不还原） |
| 正文 CR | **全部删除** | 原样写入 | **CR 不还原** |

| 目录层级 | 两层编号约定（提取侧） | **递归无上限** | 三层树可合并成档；再提取的层级/编号**不保证还原** |

- 守卫是数量启发式（§12.1/§12.2）——**不能仅按「已提取/已归档」标签推断同方向重跑安全**。

- **Load into map（R19 修订——开始清空、逐行修改、提示后失败、无回滚）**：开始解析即**先清空点数组**；逐行处理——跳过行首为 `#` 的注释（**行首有空白的注释不匹配此跳过门**——`^\s*$` 空行才按空白跳过）与 `[数字]` 节行；不匹配 `键 = 值` 的行弹出「Bad line syntax in line N」**但不停下或跳过**——紧接着访问失败的匹配结果并**未保护地中断**（弹错后仍失败）。**已发生的部分不会回滚**：坏行之前成功载入的点/名称/图片更新保留在数组中，坏行之后的行与后续生成/取消选择/重绘步骤**到不了**（页面不重绘，数组＝清空后已载入的前缀）。对照：首行即坏→数组空＋失败；中途坏→保留前缀＋失败；全合法→正常完成并重绘。
