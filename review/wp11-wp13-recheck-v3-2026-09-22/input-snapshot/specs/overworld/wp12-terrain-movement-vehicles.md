## 1. 目的、范围与非目标

**目的**：描述地形能力、通行判定、玩家移动与载具状态的行为规则——什么地形允许什么移动、走跑骑行冲浪潜水如何进入/退出/保持、碰撞与移动成功/失败分别发生什么。后续包据此判断"某位置能否进入、某状态何时改变、移动会触发什么"，而不是各自重新追踪运动逻辑。

**范围**（WP12 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP12-A：地形能力与通行判定目录（地形标签能力表、通行判定链）。
2. WP12-B：移动与运动状态（走/跑、跳跃/滑行、强制路线、普通与强制移动入口）。
3. WP12-C：载具与水上运动（骑行、冲浪/潜水、瀑布、上下车/水状态转换）。
4. WP12-D：许可与领域边界（守卫、许可输入、领域交界）。
5. F04-02、F04-03 中属于 WP12 部分的状态更新。

**非目标**：

- 不提取具体徽章、场地招式资格/效果的完整规则（WP24/WP59 等适用包）。
- 不提取事件/NPC/跟随规则（WP13 主规格）、地图拓扑/转移（WP11 主规格）、地图绘制/渲染（WP16）。
- 不把当前通行算法当成未来寻路或碰撞架构模板。
- 不运行游戏或任何参考脚本；不修改 `reference/`。

## 2. 概念与术语

- **地形标签（TerrainTag）**：图块/位置上的一组能力标记（可冲浪、瀑布、冰面、桥、深草、必须步行等），硬编码注册（18 个）。
- **通行判定**：由图块通行位（passages）、优先级、地形能力、事件阻挡、玩家阻挡共同决定的移动许可；**按入口分层**（地图层/角色层/玩家覆写/跟随者严格入口），不能用一个"可通行"布尔概括。
- **运动状态**：玩家当前的移动模式（步行/跑步/骑行/冲浪/潜水/冰滑/瀑布上下），影响速度、外观与移动规则。
- **载具状态**：`$PokemonGlobal` 的 surfing/diving/bicycle 标记（及 ice_sliding、bridge 等辅助状态）。
- **强制路线**：事件/系统接管玩家移动的状态（`move_route_forcing`）；与冰滑/瀑布的 `forced_movement` 标记是**两种不同的接管机制**（4.2）。
- **速度等级**：参考实现的速度数值（1–6）是等级不是像素/秒；每格耗时换算：1 → 1.0 秒、2 → 0.5 秒、3 → 0.25 秒、4 → 0.125 秒、5 → 0.1 秒、6 → 0.05 秒（`Game_Character.move_speed=`，110–123 行）。
- 影响域编号 Dxx 见 module-map；证据状态五档定义见总览第 7 节。

### 3.2 通行判定链（本轮逐行阅读 `004_Game_Map.rb:142–268`、`006_Game_Character.rb:237–303`、`008_Game_Player.rb:238–250`）

**按入口分层，各层规则适用对象不同，不能混用**：

#### 层 1：地图层（`Game_Map.passable?`，142–246 行）

1. 目标须在图内（`valid?`）。
2. **图块事件**：目标位置上有图块 ID > 0、非 through、非忽略通行性的事件 → 按其图块通行位判定（方向位被禁或全向被禁 → 不可通行；**优先级为 0 → 本次地图层判定就此结束并许可**，不再继续该层的玩家/非玩家地形分流——但随后的角色层事件碰撞检查仍照常执行，见层 3）。
3. **分流**：移动者是玩家 → 玩家专用层（层 2）；**其他事件** → 非玩家规则：
   - **水上约束**：移动者当前位于非瀑布水域（can_surf_freely）时，目标须同为非瀑布水域，否则不可通行。
   - **冰面拒绝**：目标地形为冰 → 不可通行。
   - **岩架拒绝**：移动者当前位置即判定位置且目标地形为岩架 → 不可通行。
   - 其余按图块通行位/优先级常规判定。
   - **注意**：水上约束与冰面拒绝位于**非玩家分支**，不是玩家普遍规则（玩家见层 2 与 4.2）。

#### 层 2：玩家专用层（`playerPassable?`，218–246 行；仅地图层分流到玩家时执行）

- 不在桥上（bridge == 0）时忽略桥图块；在桥上（bridge > 0）时按桥图块通行位判定。
- 冲浪中：可冲浪且非瀑布的水域图块 → 许可。
- 骑行中：必须步行（must_walk）**或**必须步行或跑步（must_walk_or_run）地形 → 不可通行（二者都禁骑行）。
- 忽略通行性图块跳过；其余按通行位/优先级常规判定（优先级 0 → 提前许可）。

#### 层 3：角色层（`Game_Character.passable?`，237–257 行；所有移动者共用的外层）

1. **边界检查**：目标须在图内（`map.valid?`）——先于一切其他许可。
2. through → 许可。
3. **地图层双向检查**：源位置按移动方向、目标位置按反方向（10 − d）分别过地图层，任一失败则不可通行（不是只查目标图块方向）。
4. **事件碰撞**：目标位置有非 through 事件时——**非玩家移动者：任何此类事件都阻挡**（不要求具名图形）；**玩家：仅具名图形的事件阻挡**。
5. **玩家阻挡**：目标位置为玩家且移动者具名图形 → 不可通行（玩家不因此被自身阻挡）。

#### 层 4：玩家覆写（`Game_Player.passable?`，238–250 行）

1. **先边界**：目标超出 validLax? 范围 → 不可通行；超出 valid? 但在 lax 内 → 交地图工厂跨图通行判定（`isPassableFromEdge?`，WP11 主规格）。
2. **再调试穿透**：$DEBUG 且按住 Ctrl → 许可（**在边界检查之后**，不意味着任意出界坐标都可走）。
3. 其余走角色层（层 3）。

#### 层 5：跟随者实际入口与严格通行能力的区分

- **跟随者实际移动判定**（`Game_Follower.location_passable?` 与 `move_fancy`/`move_through`，`010_Game_Follower.rb:48–88, 174–213`）：按目标位置的方向位、地形（岩架拒绝、桥按状态、忽略通行性跳过、优先级 0/桥上提前通过）与事件碰撞（**仅具名图形的非 through 事件阻挡**）判定；当前位置不可通行时允许穿透移动。它与玩家路径规则相似但独立，**不等于全向 strict 判定**。
- **严格通行能力**（`passableStrict?` 链，`004_Game_Map.rb:249–268`、`MapFactory.isPassableStrict?`）：图块**任一方向有通行位非零即不可通行**（要求全向可通）。这是一项独立能力；**未在默认跟随流程中检索到对该工厂 strict 入口的调用**（不能由注释推定消费者），其实际调用链待后续包核实。
- 对照例：目标格仅"向下"方向被禁、进入方向许可时，跟随者实际判定可进入；全向 strict 判定则拒绝——二者不能互换。

## 4. WP12-B：移动与运动状态

### 4.1 移动入口与结果（本轮逐行阅读）

| 入口 | 行为 |
| --- | --- |
| 普通移动（`move_generic`，`008_Game_Player.rb:141–177`） | 转身；**先判定能否移动**（can_move_in_direction?）：可移动时——面朝岩架则尝试跳下（jumpForward(2)，成功则跳音+increase_steps；**无论成败都结束本步，落点不许可也不转入碰撞分支**）；瀑布顶且向下则进入下瀑状态（through=true、waterfalls_descended+1）并继续；随后尝试上岸（`pbEndSurf`，见 5.2，成功则结束本步）；否则记录初位、前移、按距离累计距离统计、increase_steps。不可移动时——先尝试事件触碰，否则碰撞（碰撞音、bump_count+1、记录初位、bumping=true） |
| 跳跃（`jump`，`006_Game_Character.rb:767–787`） | 转向主方向；占格全部可过才跳；记录跳点、跳距、跳峰；计步；落点变化才累计距离 |
| 输入处理（`update_command_new`，`008_Game_Player.rb:431–458`） | 强制移动时按当前方向 move_forward；否则按方向键输入：持续同向（≥0.075 秒）则移动，换向则先转身 |
| 步后触发（`update_event_triggering`，同文件 543–554） | 步完成后：跟随者转身 → 远距事件检查 → 同位事件检查 → `pbOnStepTaken`（WP06 计步主规格，引用） |
| 碰撞（`bump_into_object`，同文件 121–128） | 碰撞音（非强制路线时）、bump_count+1、记录初位、bumping=true |

**计步层次**（WP12-R02 修订）：`increase_steps`（`006_Game_Character.rb:397–400`）只做两件事——**重设停止计时（stop_count = 0）并通知离开旧格（on_leave_tile；该通知要求旧位置已记录且位置/地图确有改变）**；它不直接累加全局步数。全局计步在步完成后的 `pbOnStepTaken` 入口（WP06 主规格，引用，本文不另写第二套规则）。**运动开始与完成是两个不同观察点，统计/通知提交在运动开始一侧**：

- **普通步（移动开始）**：通行通过后立即提交——逻辑坐标更新、移动计时开始、距离统计累计（`add_move_distance_to_stats`）、increase_steps（含条件满足的离格通知）。此后画面位移（update_move 插值）尚未完成；动画完成与步后触发（事件检查与全局计步）在后。即"移动方法已返回但画面位移未完成"时，逻辑坐标与距离统计已变、符合条件的离格通知已发生，但本步全局 stepcount 尚未因步完成而累加。
- **跳跃（跳跃开始）**：占格许可检查后提交——逻辑坐标/跳跃计时/跳峰跳距设置、increase_steps；玩家覆写随后在坐标确有变化时累计实际位移距离。落点许可检查失败的跳跃（`jump` 内占格检查未过）直接返回，**不产生成功位移距离，也不触发 increase_steps**。

阶段顺序：移动/跳跃请求 → 通行判定 → **开始（逻辑坐标 + 距离统计 + 条件性离格通知）** → 动画/位移完成 → 步后触发（事件检查与全局计步）。

### 4.2 运动状态机（本轮逐行阅读 `set_movement_type` 与 `can_run?`）

**跑步条件（`can_run?`，52–61 行）**：

- 强制路线中：按当前 move_speed > 3 判定（不看跑鞋/地形）。
- 正常分支前提：非碰撞中、非菜单/战斗/消息/解释器运行、非跳跃。
- 跑鞋例外：`has_running_shoes` 为假时，**冲浪、潜水或骑行中任一**也可跑（潜水是跑鞋例外之一）。
- 地形限制：仅**必须步行**（must_walk）地形禁跑；**必须步行或跑步**（must_walk_or_run，如冰面）**不禁跑**。
- 两者（must_walk 与 must_walk_or_run）**都禁骑行**（层 2）。
- 最终按 runstyle 设置与 BACK 键异或切换。

**状态表**（速度数值为参考速度等级，换算见第 2 节；`set_movement_type` 的速度赋值**多数受"非强制路线"前提限制**（64–99 行），且碰撞中（bumping）最后统一覆盖为 3——下表不是无条件强制值）：

| 状态 | 进入前提 | 速度等级/外观 | 退出/切换 |
| --- | --- | --- | --- |
| 步行（walking） | 默认 | 3 | 默认状态 |
| 跑步（running） | can_run?（见上） | 4；BACK 键按 runstyle 切换 | 条件不满足时回步行 |
| 骑行（cycling） | `$PokemonGlobal.bicycle = true`（`pbMountBike`） | 5（跳 3）、骑行外观与 BGM | `pbDismountBike` 或 `pbCancelVehicles`（目的地不可骑行时） |
| 冲浪（surfing） | `$PokemonGlobal.surfing = true` | 4（跳 3）、冲浪外观、上下浮动动画 | `pbCancelVehicles(cancel_swimming)` 或上岸流程（`pbEndSurf`，5.2） |
| 潜水（diving） | `$PokemonGlobal.diving = true` | 3、潜水外观 | 同上 |
| 冰滑（ice_sliding） | `$PokemonGlobal.ice_sliding` 或当前地形为冰 | 4、步行外观 | 离开冰面 |
| 瀑布下（descending_waterfall） | 瀑布顶向下移动触发 | 2、through=true、冲浪外观 | 离开瀑布地形或调试中断（5.3） |
| 瀑布上（ascending_waterfall） | 攀瀑流程（WP59 交界） | 2、through=true、冲浪外观 | 同上 |
| 停止态（*_stopped） | 菜单中停止或载具更新时 | 保持对应外观、恢复基础速度 | 重新移动时 |

**接管机制区分**：强制路线（`move_route_forcing`）使普通输入不生效、且上述速度赋值被跳过；冰滑/瀑布的自动移动由步后订阅（`on_step_taken` 的 `auto_move_player`，`001_Overworld.rb:158–168`）驱动，是另一种接管路径，二者不能混为一种。

状态保持/清理：跨图转移时 `transfer_player` 调 `pbCancelVehicles`（默认取消载具，可选保留游泳；WP11 引用其调用点）；`pbUpdateVehicle` 按当前标记恢复外观（`008_Game_Player.rb:575–585`）；`pbCancelVehicles` 按目的地决定是否清除骑行标记（5.1）。

## 5. WP12-C：载具与水上运动

### 5.1 骑行（`pbMountBike`/`pbDismountBike`/`pbCancelVehicles`/`pbCanUseBike?`，同文件 587–615 行）

- 上车（`pbMountBike`）：**已骑行时直接返回**（不重复增加 cycle_count）；否则 `bicycle = true`、`cycle_count += 1`、恢复骑行外观与 BGM、音效、取消雷达连锁。
- 下车（`pbDismountBike`）：`bicycle = false`、恢复步行外观、按地图自动播放音乐。
- 载具取消（`pbCancelVehicles(destination, cancel_swimming)`）：`cancel_swimming` 为真才清 surfing/diving；**骑行按目的地图许可决定**——无目的地或目的地 `pbCanUseBike?` 为假时清 bicycle。`pbCanUseBike?` = 地图元数据的 always_bicycle / can_bicycle / outdoor_map 任一允许。**不是"所有跨图都取消载具"**：显式传送默认 `cancel_swimming = true`（WP11 引用调用点），可传 false 保留游泳；边缘切图与显式传送按各自实际调用分开。
- **进入地图的骑行调整（`on_enter_map` 的 force_cycling 消费者，`001_Overworld.rb:268–275`）**：进入 always_bicycle 图 → 自动上车（`pbMountBike`，可增加 cycle_count）；进入不可骑行图（`pbCanUseBike?` 为假）→ 自动下车（`pbDismountBike`）；普通可骑行图保持不变。该通知在**边缘切图与跨图显式传送（setup 内）都会触发**（WP11 引用），同图显式传送没有本次 setup 的 on_enter_map，故不发生此调整。本包只登记该消费者对骑行状态的影响，天气/遭遇等其他订阅者不在此展开。

### 5.2 冲浪与潜水（本轮逐行阅读 `004_Overworld_FieldMoves.rb:715–751`）

- **上水**（开始冲浪）：由互动订阅入口（`on_player_interact` 的 start_surfing）：未冲浪、地图非 always_bicycle、面前为非瀑布可冲浪水域、当前位置按面向可通行 → `pbSurf`；菜单/场地招式入口（UseMove 处理器）殊途同归。**上下岸不是同一个入口**。
- **上水状态提交**（`pbSurf` / `pbStartSurfing`，`004_Overworld_FieldMoves.rb:685–713, 776–785`）：资格与确认通过后——取消载具 → 重置遭遇步数 → **置 surfing** → **surf_count+1** → 刷新载具外观 → 记录面前基点（surf_base_coords）→ **最后才尝试前跳**（jumpForward）。**前跳失败没有这些状态的回滚分支**：冲浪状态、计数与基点在跳跃结果之前已提交；pbSurf 正常确认分支也不以跳跃成功决定其最终返回。资格/确认文案/动画细节归 WP59，本包只登记运动状态交界。
- **下水/上岸**（结束冲浪，`pbEndSurf`）：只处理**结束冲浪**——当前冲浪中、面前地形**非**可冲浪、向陆跳跃成功时才置 `ending_surf` 并结束本步移动；任一条件不满足则返回 false（不影响后续普通移动）。步后订阅（`on_step_taken` 的 surf_jump）清理有**分层守卫**：须为地图场景、玩家事件且存在 surf_base_coords 才清基点；仅当 `ending_surf` 为真时才执行取消载具 → 重置遭遇步数 → 恢复地图 BGM → 清 `ending_surf`。**仅凭 ending_surf 标记不保证任意通知都执行清理**（非玩家通知或基点缺失时不成立）。
- 冲浪：状态标记 `$PokemonGlobal.surfing`；冲浪中按层 2 的水域通行规则移动；外观为冲浪图块并带上下浮动。
- 潜水：状态标记 `$PokemonGlobal.diving`；潜水目标地图由地图元数据的 dive_map_id 指定（WP15/WP59 交界）；潜水外观、速度等级 3。
- 水上遭遇：冲浪/潜水状态下的水域遭遇按遭遇表（WP36 主规格）；`surf_count`/`dive_count` 累计（WP06 统计）。

### 5.3 瀑布（本轮逐行阅读 `004_Overworld_FieldMoves.rb:901–923`、`001_Overworld.rb:158–168`）

- 下瀑：瀑布顶（WaterfallCrest）向下移动触发：`descending_waterfall = true`、`through = true`、`waterfalls_descended += 1`、速度等级 2、冲浪外观（`move_generic`，`008_Game_Player.rb:154–157`）。
- 上瀑：攀瀑流程的资格与效果归 WP59（场地招式领域）；状态标记 `ascending_waterfall`，速度等级 2。
- **瀑布状态清理**（`pbTraverseWaterfall`，步后订阅 `auto_move_player` 调用：当前地形为瀑布/瀑顶或瀑布标记存在时触发）：
  - 下瀑分支（面向下）：**调试 Ctrl 按住，或当前位置既非瀑布也非瀑顶** → 清 `descending_waterfall` 与 through；否则保持/置位下瀑状态（未在下瀑时 waterfalls_descended+1）。
  - 上瀑分支（`ascending_waterfall` 为真）：同样条件下清 `ascending_waterfall` 与 through；否则保持/置位。
  - 冰面分支：当前地形为冰或 `ice_sliding` 时走 `pbSlideOnIce`（滑行），与瀑布分支互斥。

## 8. 边界、失败与未知

- 不可移动时：先尝试事件触碰，否则碰撞（4.1）；碰撞不改变位置（仅音效/计数/标记）。
- 岩架跳下：先过"能否移动"判定才进入岩架分支；**跳跃失败（落点不许可）时本步直接结束，不转入碰撞分支**（无碰撞音/bump 计数）。
- 上岸失败：`pbEndSurf` 任一条件不满足（未冲浪/面前仍可冲浪/跳跃失败）→ 返回 false，不影响后续普通移动判定（5.2）。
- 瀑布/冰面状态中断：调试 Ctrl 或离开瀑布地形时清理对应标记与 through（5.3）；各分支已按静态代码登记，真实地图流程待验证。
- 动画/媒体结果（资源缺口）：跳跃尘、冲浪浮动、载具 BGM 的播放未验证。
- 多格角色的占格判定在各状态下的组合（未逐状态验证）。
