## 1. 目的、范围与非目标

**目的**：说明旧数据转换、保存/载入失败、备份、紧急保存与地图恢复的适用条件和结果——哪些旧存档被转换、按什么顺序、何时写回；失败在哪些分支发生、可能留下什么状态。后续包据此判断"某旧档如何被处理、失败可能损失什么"，而不是各自重新追踪转换与恢复路径。

**范围**（WP10 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP10-A：转换机制（注册、触发条件、排序、备份与写回时机）。
2. WP10-B：已登记转换目录（当前全部转换及其输入/输出）。
3. WP10-C：失败与恢复（损坏/备份/紧急保存/地图恢复）。
4. WP10-D：各阶段副作用与调试/非调试分层。
5. F03-02、F03-04 中属于 WP10 部分的状态更新。

**非目标**：

- 不宣称未经验证的旧格式全兼容；缺旧档样本与宿主行为保持具名待证。
- 不修改或转换真实存档；不为复现失败破坏 reference；不运行游戏或任何参考脚本。
- 不提取各转换涉及对象的领域语义（如树果/寄养/电话的对象结构，归相应领域包）。
- 不重复定义 WP07 的诊断限制（引用）。

## 2. 概念与术语

- **转换（Conversion）**：对存档内容的一次定向修改，含触发条件（低于某版本）、逐值修改与整体修改。
- **触发版本**：转换声明的引擎（essentials）或游戏（game）版本阈值；存档版本**低于**该阈值才执行。
- **备份（.bak）**：执行转换前把原存档整体复制保留的文件；紧急保存前也会先备份。
- **读取时写回**：读取存档后，若发生转换则把结果重新写回存档文件。
- **紧急保存**：脚本超时（Hangup）时尝试的备份 + 保存流程。
- 影响域编号 Dxx 见 module-map；证据状态五档定义见总览第 7 节。

## 3. WP10-A：转换机制

### 3.1 注册与触发（`S/002_Save data/003_SaveData_Conversion.rb`，本轮逐行阅读）

每个转换按以下配置登记（`SaveData.register_conversion(id) { … }`）：

| 配置 | 行为 |
| --- | --- |
| `essentials_version(v)` 或 `game_version(v)` | 触发条件：存档对应版本**低于** v 才执行（`should_run?`）；只能二选一，重复声明报错 |
| `display_title` | 执行时显示的标题（转换在语言选择之前执行，标题**不可本地化**） |
| `to_value(value_id) { … }` | 对指定持久值的修改；要求存档**含有**该值，缺失则抛错 |
| `to_all { … }` | 对整体存档的修改 |

- 触发判断使用**插件版本比较器**（WP05 主规格：逐字符位置比较，1.10 < 1.9）——版本排序与阈值判定都以该实现为准，不套用 SemVer。
- 执行顺序：按触发类型分别收集，版本阈值**从低到高**排序执行（同类型内）。
- 存档版本缺失时的默认：essentials_version 缺省按 "18.1"、game_version 缺省按 "0.0.0" 处理（即极旧存档会触发全部转换）。

### 3.2 备份与写回时机（本轮逐行阅读）

`run_conversions(save_data)`（同文件 195–210 行）：

1. 收集应执行的转换；无则返回 false（不写回）。
2. **先把原存档整体写入 `.bak` 备份**（转换前状态）。
3. 逐个执行转换（控制台输出标题与完成状态；`to_value` 缺值即抛错中断）。
4. 把存档的 essentials_version/game_version 更新为当前版本，返回 true。
5. 随后（WP09 登记的读取路径）：`read_from_file` 在转换返回真时**把转换后的存档重新写回原文件**（`001_SaveData.rb:43–50`）——**读取旧档会改写它**。

### 3.3 副作用分层（WP10-D 的静态事实）

| 阶段 | 可能发生的变化 |
| --- | --- |
| 转换前 | 原存档整体写入 `.bak`（覆盖同名旧备份，无追加/轮换证据） |
| 转换中 | 某转换的 `to_value` 缺值 → 抛错中断，后续转换不执行；已执行的修改保留在内存数据中 |
| 写回后 | 转换后的存档重写原文件（原旧档不再以原样存在，除非 `.bak` 保留）；控制台记录转换标题 |
| 异常处理 | 备份写入/转换执行/写回任一失败的行为未逐分支验证（不默认原子性或日志一定成功） |

## 5. WP10-C：失败与恢复

### 5.1 损坏与备份（启动侧，WP09 已登记，本文细化）

- 存档无效（`SaveData.valid?` 假）：有 `.bak` 时提示"存档损坏，将载入备份"并读备份（`013_UI_Load.rb:228–233`）；无备份时询问是否删除并重新开始（`prompt_save_deletion`，243–262 行；删除经 `SaveData.delete_file`，同时删除 `.bak`，`001_SaveData.rb:63–68`）。
- 备份来源：转换前备份（3.2）与紧急保存前备份（5.2）都可能产生 `.bak`；备份是整体复制，**不保证**它是最新进度（转换前/紧急保存前的状态）。

### 5.2 紧急保存（Hangup 路径，`016_UI/014_UI_Save.rb:1–24`）

- 触发：脚本超时（Hangup）时（调试与非调试路径不同，见 5.3）。
- 行为：提示超时将重启；若有存档，先整体复制到 `.bak`；随后执行正常保存（WP09 路径）；成功提示"已保存，原存档已备份"，失败提示"保存失败"。
- 随后重启（`raise` 传播，见 5.3）。

### 5.3 调试与非调试分层（引用 WP07 主规格）

- 调试模式主流程：`pbCriticalCode` 包装，Hangup 转 `Reset`（重启信号），异常经诊断面处理。
- 非调试主流程：直接调用，Hangup 时**打印异常（若非调试）+ 紧急保存后重抛**（`999_Main/999_Main.rb:43–46`）；普通异常按宿主未知行为处理（WP07 已登记，引用）。
- Reset/SystemExit 的传播仅限具体分支（pbCriticalCode、Compiler.main；插件脚本执行入口经插件诊断/退出路径，WP05/WP07 已登记，引用）。

### 5.4 地图恢复失败（WP09 登记，引用）

- 地图已变化：`setMapChanged` 标记后恢复。
- 地图损坏（`$game_map.events` 为 nil）：抛"地图损坏，游戏无法继续"（`001_StartGame.rb:98–100`）；恢复行为未验证。

## 6. 默认行为与配置变体

- **基线默认**：旧档按版本阈值转换（先备份再写回）；无效档走备份/删除路径；Hangup 走紧急保存。
- **支持但未默认启用**：`run_single_conversions`（对单个对象执行适用转换的入口）；`SKIP_CONTINUE_SCREEN`（调试跳过载入画面，WP02 词典）。
- **配置/数据关联**：`GAME_VERSION`/`Essentials::VERSION` 是转换的触发输入（WP02 词典）；`FLUTES_CHANGE_WILD_ENCOUNTER_LEVELS` 影响笛子转换的方向（WP02 词典）；`MECHANICS_GENERATION` 与数据集组合对转换结果的影响（U02/U03）。
- **未验证组合**：旧档样本的真实转换结果、备份恢复的真实路径、地图损坏分支、完整 Demo 启动（缺失地图/事件材料）。
- 参考快照行为、官方版本预期、未来目标分开标记；本包只记录第一类。

## 7. 边界、失败与未知

- 备份覆盖：同名 `.bak` 被覆盖写入（无轮换）。
- 转换中断：`to_value` 缺值抛错，后续转换不执行；内存中已改数据是否写回取决于写回步骤是否到达（未验证）。
- 写回失败：备份已写入但写回失败时的状态未验证。
- 备份恢复后的二次转换：从 `.bak` 载入后是否再次触发转换（版本已更新与否）未逐分支验证。
- 紧急保存的保存失败路径：提示"保存失败"后的状态未验证。
- 旧档样本与宿主行为（U01/U02 相关）：缺旧档样本，不宣称任意旧档全兼容。
