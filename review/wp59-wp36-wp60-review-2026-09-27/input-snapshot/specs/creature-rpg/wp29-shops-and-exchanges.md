## 1. 目的、范围与非目标

**目的**：定义两个交易入口（金钱商店与 BP 兑换商店）的库存/命令可见性、价格来源与覆盖、数量选择、重要物品与禁售规则、取消与失败、交易前后资源/物品/赠品/统计的**写入顺序与守卫**；供界面审查（WP66-C）、demo 配置（WP77）与统计（WP06）引用。

**范围**（WP29 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP29-A：金钱商店——买/卖两流程、库存预过滤、数量上限、重要物品、成功/部分失败/回退、纪念球赠品。
2. WP29-B：BP 商店——库存、价格、购买流程、与金钱商店的差异。
3. WP29-C：价格来源与覆盖——数据价格/售出价/BP 价、事件价格覆盖命令与算术、覆盖生命周期。
4. WP29-D：资源写入顺序——金钱/BP setter 钳制与交易层判断的差异；统计写入点；失败后状态。

## 2. 概念与术语

- **库存（stock）**：由调用事件传入的物品标识列表（**列表按引用原地使用**）；界面在进入时与每次成功购买后**原地删除**"重要物品且已持有"的条目（不重建、退出不恢复；§3.1/§7.1）。
- **交易层**：商店界面内的判断与写入（价格、数量、资源扣加、物品增删、赠品、统计）。
- **资源域**：玩家金钱/BP 的 setter（钳制到域上限；引用 WP24 §4.1 的资源目录）。
- **价格覆盖**：事件命令对单个物品的买/卖价格覆盖（`$game_temp` 内的会话级映射；§5）。
- **赠品**：金钱商店的纪念球奖励（按数量档位；BP 商店无赠品）。
- **回退**：购买在"物品未全部放入"时的撤销（把已放入的逐个移除；§3.2）。
- **可售判定**：有效售出价 > 0 且非重要物品。

## 3. WP29-A：金钱商店

### 3.1 入口与命令可见性

- 入口包装：接收库存（物品标识列表）、问候语与"是否允许出售"开关；**进入时先原地过滤库存**：重要物品且背包已持有者**从传入列表本身删除**（不重建、不恢复；列表所有权与复用边界见 §7.1）。
- 命令：买 / 卖（禁用出售时无此项）/ 退出；默认光标在第一项（买）；**取消键等效选择"退出"**（以退出索引+1 传入取消策略）。退出后显示告别语；会话结束清除价格覆盖（§5）。
- 买界面：物品列表 + "取消"末项；上方金钱窗、左下说明、持有数量窗。

### 3.2 购买流程（逐步骤，静态核对）

1. 选择物品（末项"取消"或取消键 -> 结束购物循环）。
2. 价 = 交易层价格（§5）；**金钱 < 价** -> "你没有足够的钱。"并回到选择（不进入数量步骤）。
3. **重要物品**：确认"你想要 X 吗？共 $N。可以吗？"；拒绝 -> 返回选择；数量固定 1（不出现数量选择）。
4. **普通物品**：可买上限 = 价格为 0 时取"每槽上限"（当前 999），否则 `金钱 ÷ 价`（向下取整），再钳到每槽上限；数量选择（1–上限；左/右 ±10 钳位、上/下 ±1 环绕、取消返回 0）；数量 0 -> 返回选择；价 ×= 数量；确认文本按单/复数分支。
5. **再次检查**金钱 < 总价 -> 同消息并返回选择。
6. **逐件放入背包**：`添加`一次一件，统计成功件数。
   - **全部放入** -> 统计（商店消费累计 += 总价；商店购买件数 += 数量）-> 金钱 = 金钱 − 总价 -> **库存原地再筛选（重要物品且已持有者从同一列表删除）** -> "给你！谢谢！"音效与消息 -> 纪念球赠品（§3.3）。
   - **未全部放入** -> **回退**：把已放入的逐件移除（移除失败 -> 内部报错）；消息"你的背包没有空间了。"；**金钱不变、统计不变**。
7. 循环直至退出。

### 3.3 纪念球赠品（金钱商店专属）

- 触发条件：本次购买成功且数量 ≥10 且存在"纪念球"物品数据。
- 分支一（"更慷慨的纪念球"配置开）：仅当**购买的是球类物品** -> 尝试添加 `⌊数量÷10⌋` 个纪念球（**逐个添加、放满即停**）；按**实际添加数**计"纪念球获得"统计并显示（数量 >1 用复数）；添加失败（背包满）不报错、不影响已完成的购买。
- 分支二（配置关）：仅当**购买的是普通球** -> 尝试添加 1 个纪念球；成功才计统计与显示。
- 赠品写入在金钱扣减与统计之后、购买消息之后；不参与步骤 6 的回退。

### 3.4 出售流程（逐步骤）

1. 进入：背包作为选择界面（可取消）。
2. 选择物品 -> **可售判定**（售出价 >0 且非重要）不通过 -> "哦不，我不能买 X。"并返回选择。
3. 价 = 交易层售出价（§5）；持有数量 = 背包数量；数量为 0 -> 跳过。
4. 数量 >1 -> 数量选择（上限=持有数量）；取消（0）-> 返回选择。
5. 确认"I can pay $N. Would that be OK?"；拒绝 -> 返回选择。
6. **写入顺序**：记录旧金钱 -> 金钱 = 旧 + 总价 -> **统计"商店收入" += 实际增量**（若被域上限钳制，统计按钳制后增量计）-> 从背包逐件移除（**不检查移除结果**）-> 消息（"你交出了 X，得到了 $N"）与刷新。
- 拒绝/取消路径：不写入金钱、不统计、不移除。

## 4. WP29-B：BP 商店

- 入口包装：接收库存与问候语；**进入时同过滤**（重要物品已持有者移除）；显示欢迎语与说明；退出后显示两条告别语；结束清除价格覆盖。
- 购买流程与金钱商店同构，差异如下：

| 维度 | 金钱商店 | BP 商店 |
| --- | --- | --- |
| 资源与消息 | 金钱；"你没有足够的钱。"（两处检查同一文案） | BP；首查"你没有足够的 BP。"、复查"我抱歉，你没有足够的 BP。" |
| 价格来源 | 数据购买价或覆盖 | 覆盖值（>0 时）或数据 **BP 价（缺省 1）** |
| 数量上限 | `金钱÷价` 钳到每槽上限；价 0 -> 每槽上限 | `BP÷价` 钳到每槽上限；价 0 -> 每槽上限 |
| 重要物品 | 确认后数量固定 1 | 同 |
| 赠品 | 纪念球（§3.3） | **无** |
| 出售 | 有（可禁用） | **无** |
| 统计 | 消费累计 += 总价；件数 += 数量；赠品统计 | BP 消费累计 += 总价；**件数统计与金钱商店共用同一计数** |
| 回退 | 同（移除失败内部报错） | 同 |
| 数量窗显示 | `数量 × 价`（金钱） | `数量 × ⌊价÷2⌋`（BP；**静态怪癖**：场景标志未初始化，导致显示半价总数；确认文本与实扣仍为全价） |

- 成功路径写入顺序：统计（BP 消费 += 总价；件数 += 数量）-> BP = BP − 总价 -> 库存再过滤 -> 消息。
- 失败（未全部放入）路径：回退移除 -> "你的背包没有空间了。"；BP 不变、统计不变。

## 5. WP29-C：价格来源与覆盖

### 5.1 数据价格

- 购买价=物品数据 `Price`；售出价=数据 `SellPrice`，**缺省为购买价的一半（整数除法）**；BP 价=数据 `BPPrice`，**缺省为 1**。
- **价格输入层级（分开记录）**：①编辑器属性上限涉及 `MAX_MONEY`/`MAX_BATTLE_POINTS`（编辑界面输入提示，非运行时校验）；②PBS 文本层对三字段只做**非负整数格式**校验（无上限逻辑；物品专项编译验证亦无价格上限）；③构造读取按原值写入（不钳制）；④玩家钱包/BP 的 setter 才钳到资源上限。**不得把编辑器输入上限写成"全部数据输入的校验上限"**——如 1,000,000 的文本价格不会在上述文本/构造层被自动钳制，正常购买只是资源不足另论。
- 禁售：有效售出价 ≤0 或重要物品。

### 5.2 事件价格覆盖（会话级）

- 命令一（买/卖同时覆盖）：对物品初始化覆盖对 `[-1, -1]`（若不存在）；随后**按条件写入**：`买覆盖 = 参数1` 当参数1 > 0；`卖覆盖 = 参数2 × 2` 当参数2 ≥ 0（0 表示"不能卖"）；否则若参数1 > 0 -> `卖覆盖 = 参数1`。**未满足写入条件时该槽保持原值**——已有覆盖不会被非正参数或参数缺省"清回"数据价。
- 命令二（仅卖）：等价于以"买参数=-1"调用命令一（已有买覆盖保留，仅按条件写卖覆盖）。
- 交易层读取：购买时若买覆盖 > 0 用它，否则用数据购买价；出售时若卖覆盖 ≥ 0 用它（**0 有效且使物品不可售**），否则用数据售出价。
- **旧值保留示例（具名合法调用）**：合法物品 D 已有 买250/卖120 覆盖，再调用 `setPrice(D, -1)`（买参数非正、卖参数缺省）或 `setSellPrice(D, -1)`（卖参数为负）-> 两槽均不写入，仍 250/120。注意**命令二必须带卖参数**（省略是参数数量错误，不是一次成功的无操作调用）。只有**从无覆盖状态**调用才会先形成 `[-1,-1]` 再按数据价回落。
- **BP 商店共用买覆盖槽**：BP 商店价格 = 买覆盖（>0 时）或数据 BP 价——同一映射同时影响金钱商店购买与 BP 兑换。
- 生命周期：会话结束（两个商店的退出路径）清除全部覆盖；未清除前的其它商店入口沿用。

## 6. WP29-D：资源域与写入顺序

### 6.1 setter 钳制 vs 交易层判断（分开记录）

| 维度 | 资源域 setter | 交易层 |
| --- | --- | --- |
| 金钱 | `金钱 = 值` 钳到 `[0, 上限]`（上限 999,999） | 购买两处 `金钱 < 总价` 判断；出售后若超上限被钳制，**统计按实际增量** |
| BP | `BP = 值` 钳到 `[0, 上限]`（上限 9,999） | 购买两处 `BP < 总价` 判断；无出售 |
| 判断来源 | 仅钳制，不提示 | 提示不足消息；数量上限换算使用当前资源 |

- 交易层不对"资源上限"另设提示；数量上限只受"资源÷单价"与每槽上限约束（不把资源域上限当作数量/提示规则）。

### 6.2 写入顺序与守卫（汇总）

| 流程 | 顺序 | 守卫/失败 |
| --- | --- | --- |
| 金钱购买 | 物品全部放入 -> 统计 -> 扣钱 -> 库存再过滤 -> 消息 -> 赠品 | 两处金钱检查；部分放入 -> 回退物品；赠品失败不影响已购 |
| 金钱出售 | 确认 -> 记录旧金钱 -> 加钱 -> 统计（实际增量）-> 物品逐个移除（不检查） | 可售判定；数量 0/取消/拒绝不写入 |
| BP 购买 | 物品全部放入 -> 统计 -> 扣 BP -> 库存再过滤 -> 消息 | 两处 BP 检查；部分放入 -> 回退 |

- **无事务/回滚保证扩展**：仅购买有物品回退；出售的物品移除不检查结果（静态记录，不补写回滚）。
- 统计字段（WP06 目录引用）：商店消费累计、商店收入累计、商店购买件数（两商店共用）、纪念球获得、BP 消费累计。

## 7. 规则与不变量

1. 库存过滤在进入与每次成功购买后**原地执行**（重要物品已持有 -> **从传入列表删除**，成功购买在同一列表继续删除）；**没有自动重建或恢复步骤**：进入时被删的条目即使立即退出也不回来；后来不再持有但复用同一（已过滤）列表仍缺失；只有**新构造且包含该物品的列表**才可能重新进入。重要物品在本入口本就不能出售（禁售判定见 §3.4），"已售出后重现"不成立。
2. 购买的两处资源检查与数量上限换算相互独立；数量上限钳到每槽上限（999）；价 0 时上限为每槽上限。
3. 重要物品数量固定 1 且需明确确认；普通物品数量可为 1 时确认文案用单数。
4. 购买的部分放入必然回退（含内部报错守卫）；**金钱商店与 BP 商店共享同一物品回退形状**（本包独立核对，不套用其它包装结论）。
5. 出售写入顺序为"先钱后物"、且**物品移除不检查结果**；购买为"先物（可回退）后钱"。
6. 资源 setter 只钳制不提示；交易层负责不足提示与数量换算。
7. 价格覆盖：读取按条件（买覆盖需 >0 生效；卖覆盖需 ≥0 生效，0=禁售）；**写入也按条件**（非正买参数与缺省卖参数不写入、旧槽保留，§5.2）；覆盖在会话结束清除；**BP 商店与金钱商店共享买覆盖**。
8. 赠品仅在金钱商店且每次成功购买触发（阈值与球类条件按配置）；按实际添加数统计。
9. 取消/退出路径不写入任何资源、物品与统计。
10. 本包不定义 demo 真实库存与接待事件参数（U01）。

## 8. 边界与失败

- 资源不足：第一处检查即拒绝（不进入数量）；数量确认后到使用前**没有**其它入口会再改资源（当前场景的读取范围与正常未改状态前提；不以此断言所有中途变化不可能，保留复查守卫的意义）。
- 免费/零价：价 0 -> 无金钱检查失败、数量上限=每槽上限、总价 0、成功；统计 +0。
- 价格覆盖边界：**读取按条件**——买覆盖 ≤0 忽略（回落数据价）；卖覆盖 =0 -> 不可售（"我不能买"）；卖覆盖 ≥0 时售出价=参数×2（整数）；**写入按条件**——非正买参数与缺省卖参数**不写入**（已有覆盖原样保留，见 §5.2 旧值保留）。
- 资源上限：金钱/BP 超过上限的写入被 setter 钳制；出售统计按实际增量（例：上限 999,999 时先为 999,950，售 100 -> 实际 +49）。
- 背包/每槽容量：部分放入 -> 回退 + "没有空间"；纪念球添加失败 -> 少给/不给但购买成立；数量上限受每槽上限（999）钳制。
- 数量极值：单价 1 且资源充足 -> 上限被钳到 999；数量选择左/右 ±10 与上/下环绕均为钳位/回绕规则（界面细节 WP66-C 引用）。
- 重要物品与列表状态：已持有 -> 进入时即从传入列表**原地删除**（退出不恢复）；购买成功 -> 在同一列表继续删除；**复用同一（已过滤）列表仍缺失**，只有**新构造且含该物品的列表**才可能再进入；出售重要物品 -> 拒绝（禁售）。
- BP 商店显示怪癖：数量窗显示 `⌊价÷2⌋` 的总数（BP 价 1 时显示 0 BP）；确认与实扣为全价（静态记录，不修参考）。
- 退出：两种商店退出后清除价格覆盖；再次进入需事件重新设置。
- demo 商店库存与接待事件缺失：U01（不补造）。
