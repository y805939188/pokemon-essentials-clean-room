## 1. 目的、范围与非目标

**目的**：定义"从踩步/转向或主动请求到是否开战"的完整普通遭遇链——遭遇数据（地图×版本、类型目录、PBS 文本约束）、类型选择与时段回退、步进触发概率与加速器、多方修正（地图级/首队员道具与特性/驱虫剂/雷达直通）、候选选择与等级决定、生成期修正（持有物/闪光/性别/性格/病毒/钩子）、开战交接与状态清理；供场地能力（WP59）、钓鱼（WP60）、漫游/雷达（WP37）、捕获/战斗（WP38/WP39/WP42）与图鉴（WP62）引用。

**范围**（WP36 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP36-A：遭遇数据——地图×版本键、版本回退、类型目录（25 项/6 类）、PBS 格式与编译器校验、步骤概率缺省来源。
2. WP36-B：触发——步进/转向入口与抑制条件、机会判定（地形/冲浪/洞穴）、类型选择与时段细分回退、触发概率公式与步数宽限/累加器、双打判定。
3. WP36-C：选择与等级——候选偏好过滤（特性）、多次掷取最大、等级区间与取整、等级修正（特性/黑白哨）。
4. WP36-D：生成修正——持有物概率、闪光重掷、性别/性格倾向、病毒、创建钩子与示例修正目录。
5. WP36-E：开战交接——pbEncounter/步进路径的返回、`$game_temp.encounter_type` 生命周期与消费者、清理。
6. F10-01/F10-02 中属于 WP36 部分的状态更新。

**非目标**：

- 不定义漫游个体与雷达连锁状态机（WP37；本包只登记替换点与接口）、Safari/捕虫大会会话（WP53）。
- 不定义战斗启动细节（WP39）、捕获（WP38）、战后结算与再遭遇抑制（WP42）。
- 不重定义队伍/箱子集合口径（WP25）、个体生成字段与派生（WP18–WP21、WP19 引用）。
- 不展开真实 Demo 地图的遭遇编排（U01）；不运行参考选取器/表达式。

## 2. 概念与术语

- **遭遇数据（Encounter）**：以"地图 ID + 版本"为键的一组表；每表含若干**遭遇类型**与各自的**步骤概率**；类型表内为若干**槽位**（权重, 物种, 最低等级, 最高等级）。
- **遭遇类型（EncounterType）**：25 项；每项有**类**（:land/:cave/:water/:fishing/:contest/:none）与**缺省触发概率**（供 PBS 省略概率时使用）。
- **版本（encounter_version）**：玩家全局的遭遇版本号（缺省 0）；查询"地图×当前版本"不存在时回退到该地图的版本 0。
- **步骤概率与累加器**：基础概率来自该地图该类型的 PBS 行；未中时把基础值累加到 `chance_accumulator`，下次步进时折算进概率；驱虫剂活动时该次不累加（且清零）。
- **步数宽限（min steps）**：距上次成功遭遇的步数不足时，额外先做一次"放大掷"；两个阶段都登记。
- **首队员修正**：以队伍第一位（及"第一位可战斗"两种口径）的道具/特性施加修正；具体覆盖目录见 §4.3/§5/§6。
- **双打遭遇**：一次触发可能生成两个个体进入双打（条件见 §4.4）。
- **生成钩子**：生成个体后、开战前触发的 `on_wild_pokemon_created`（以及选择物种时的 `on_wild_species_chosen`）事件钩子，供示例/插件修正。

## 3. WP36-A：遭遇数据与类型目录（静态核对）

### 3.1 数据键与版本回退

- 键 = `地图ID_版本号`；`get(map, version)`：**精确未命中时回退版本 0**；`exists?` 为精确判定。
- `each_of_version(v)`：产出所有版本 v 的表；若某地图无版本 v 的表则产出其版本 0 表（图鉴等消费）。
- 版本号写入时（玩家全局 setter）**重新执行当前地图的遭遇装载**；调试菜单可改（WP73 交界）。

### 3.2 PBS 文本格式（`PBS/encounters.txt`）

```
[地图ID]            或 [地图ID,版本号]   # 段头；同一组合重复出现 → 编译错误
类型名[,概率]                              # 开始一个遭遇类型；概率缺省=该类型缺省触发概率
  权重,物种,最低等级[,最高等级]           # 槽位行（缩进非必需，以"数字+逗号"开头识别）
```

- 槽位行要求：≥3 字段；等级 ≤ 最大等级（100）；最低 ≤ 最高；最高缺省=最低。
- 编译处理：**同物种且同等级区间**的槽位合并（权重相加）；随后按"权重降序、物种名升序"排序。物种/类型/等级格式由编译期校验（未定义类型 → 编译错误）。
- 概率缺省来源：类型目录的 `trigger_chance`；PBS 行提供第二字段则覆盖。

### 3.3 遭遇类型目录（25 项）

| 类 | 类型 id | 缺省触发概率 |
| --- | --- | ---: |
| land | Land、LandDay、LandNight、LandMorning、LandAfternoon、LandEvening | 21 |
| land | PokeRadar | 20 |
| cave | Cave、CaveDay、CaveNight、CaveMorning、CaveAfternoon、CaveEvening | 5 |
| water | Water、WaterDay、WaterNight、WaterMorning、WaterAfternoon、WaterEvening | 2 |
| fishing | OldRod、GoodRod、SuperRod | 无（0） |
| none | RockSmash | 50 |
| none | HeadbuttLow、HeadbuttHigh | 无（0） |
| contest | BugContest | 21 |

- 类语义：land/cave/water 参与"移动触发的机会判定"汇总（has_land/cave/water_encounters?）；fishing 由钓鱼流程直接请求（WP60）；none 类（碎石/摇树）由能力流程请求；contest 供捕虫大会（WP53 前向）。
- **触发概率为 0 或未定义的类型**在步进触发处一律被拒（§4.2 首道门），因此 fishing/Headbutt 等不会被走路触发。

### 3.4 机会判定与类型选择

- **机会判定** `encounter_possible_here?`：冲浪中 → 真；当前脚下地形为冰 → 假；本地图有**洞穴类**遭遇 → 真（洞穴不看单个地格）；有**陆地类**遭遇且脚下地形标记"可野生遭遇" → 真；否则假。
- **类型选择** `encounter_type`（每次触发前计算，时间取当前）：
  1. 冲浪中 → Water 族按时间细分（§3.5）。
  2. 否则：若本地图有陆地遭遇且脚下地形可遇 → 先看捕虫大会（在大会中且有 BugContest 表 → 该类型），否则 Land 族按时间细分；若仍未得 → 若本地图有洞穴遭遇 → Cave 族按时间细分；否则空。
  3. 结果为**空**则本次不触发。
- **时段细分回退**（单类型函数）：先按谓词挑"基础+Morning/Afternoon/Evening"（**昼间且细分类型存在时优先**），否则"基础+Day"（存在才用）；夜间用"基础+Night"；若夜间类型**未定义**则再退回基础类型；全部不存在 → 空。类型必须以该地图已定义为准（无表不选）。

### 3.5 时段输入

- 时段谓词与边界完全引用 WP59 §3.2（morning 5–10、day 5–20、afternoon 14–17、evening 17–20、night 20–5）；昼间与细分重叠时**细分优先**（morning > afternoon > evening 的判定顺序即代码顺序）。

## 4. WP36-B：触发（步进/转向/请求）

### 4.1 入口与抑制

- **步进入口**：迈步计数 +1（含 31 位钳制）→ 触发全部 `on_player_step_taken` 处理器（含 WP59/WP35 的钩子）→ 触发 `on_player_step_taken_can_transfer`（若被处理则终止）→ **若本次步进由事件触发（eventTriggered）或处于菜单中 → 跳过战斗检查**；否则 `pbBattleOnStepTaken(驱虫剂活动)`；随后复位 `$game_temp.encounter_triggered`。
- **转向入口**：玩家原地转向也调用同一检查（非菜单时）——转向可触发遭遇。
- **主动请求入口**（绕过步进机会与概率门，见各族）：碎岩（RockSmash 类型，先查触碰概率）、摇树（HeadbuttLow/High，摇树概率见 WP59 §5.5）、甜味（当前类型直取）、钓鱼（OldRod/GoodRod/SuperRod，WP60 流程）。
- `$game_system.encounter_disabled`：事件命令 136（参数 0=禁用）可整段禁用触发；触发函数首查。

### 4.2 触发概率（算法，按行为描述）

`encounter_triggered?(类型, 驱虫剂活动, 由步进触发)` 依次：

1. 类型不存在 → 抛参数错误；`encounter_disabled` → 假；无玩家 → 假；**DEBUG 且按住 Ctrl** → 假。
2. 该类型无步骤概率或为 0 → 假；该类型无表 → 假。
3. **雷达摇晃草丛直通**：为真（跳过下两步）；否则：
4. 基础概率 = 该类型步骤概率（浮点）；最小步数 = `clamp(8 − 概率/10, 0, 8)`。
5. **修正（按序）**：由步进触发时——概率 += 累加器/200；骑自行车 → 概率 ×0.8。地图级：降遭遇（黑哨旧效果）→ 概率 ÷2、最小步数 ×2；升遭遇（白哨旧效果）→ 概率 ×1.5、最小步数 ÷2（降优先）。首队员道具/特性（**道具优先于特性**）：洁净符/纯净薰香 → ×2/3、×4/3；否则特性——恶臭/白烟/飞毛腿/（若启用扩展）穿透 → ÷2、×2；雪隐（**当前世界天气类别 = 冰雹**）→ ÷2、×2；沙隐（**沙暴**）→ ÷2、×2；虫之预感 → ×1.5、÷2；发光/沙穴/无防守 → ×2、÷2。雪隐/沙隐读取世界天气类别（WP59 §4.1 引用）。
6. **步数宽限与放大掷**（仅由步进触发且 `step_count < 最小步数`）：`step_count += 1`；做一次放大掷——**通过阈值 = 概率×5 ÷（该类型基础步骤概率 + 累加器/200）**（注意分子用修正后概率、分母用基础值+累加器折算）；`rand(100) ≥ 阈值` → **假**（本次结束）；否则**落回下一步再做常规掷**。
7. **常规掷**：`rand(100) < 概率` → 真；否则（仅步进触发）**累加器 += 该类型基础步骤概率**；若驱虫剂活动 → 累加器清零；返回假。

- 静态向量（独立算术）：基础 21、无修正、累加器 0、宽限中——放大掷阈值 = 21×5/21 = 5（5%）；常规掷 21%。基础 5（洞穴）→ 放大 5×5/5=5%；常规 5%。基础 2（水面）→ 放大 2×5/2=5%；常规 2%。最小步数：21→5.9、5→7.5、2→7.8、50（碎石）→3.0。累加器 21 后下一步：概率 += 0.105。
- **由步进触发才累加/宽限**；转向与主动请求按各自入口的调用参数执行（转向调用同以"步进"参数为真——静态记录）。

### 4.3 允许判定 `allow_encounter?(候选, 驱虫剂活动)`

1. 候选为空 → 假；**雷达摇晃草丛直通** → 真（不查驱虫剂）。
2. **驱虫剂**：活动的口径为 `$PokemonGlobal.repel > 0`；目标口径由配置 `REPEL_COUNTS_FAINTED_POKEMON` 二选一——真：首队员（含濒死）；假：首位可战斗成员。若该成员等级 > 候选等级 → **累加器清零**、假。
3. **威吓/锐利目光**：首队员具备且候选等级 ≤ 首队员等级−5 时，50% → 假。
4. 否则真。

### 4.4 双打判定 `have_double_wild_battle?`

- 强制单打标记 → 假；Safari 中 → 假；有伙伴训练家 → **真**；可战斗成员数 ≤1 → 假；脚下地形标记"双打遭遇" → 30% → 真；否则假。

### 4.5 步进入口全程（PBattleOnStepTaken）

1. 可战斗成员数 = 0 → 返回；机会判定（§3.4）为假 → 返回；类型为空或触发（§4.2）为假 → 返回。
2. 写 `$game_temp.encounter_type`；选择候选（§5.1）；触发 `on_wild_species_chosen` 钩子。
3. `allow_encounter?`（§4.3）为真时：需要双打则再选第二候选（并再触发选择钩子）→ `WildBattle.start(候选[,第二候选], can_override: true)`；成功后清 `encounter_type`、置 `$game_temp.encounter_triggered = true`。
4. 无论结果：`$game_temp.force_single_battle = false`。
- 若 `allow_encounter?` 为假（如驱虫剂挡住）：`encounter_type` **保留**（不清理）——静态边界记录（后续流程/其它入口可覆盖）。

## 5. WP36-C：候选选择与等级

### 5.1 当前地图选择 `choose_wild_pokemon(类型, chance_rolls=1)`

1. 类型校验、取表；空表 → 空。
2. **偏好过滤（首队员特性）**：引火→火（需扩展配置+类型存在+50%）、收获→草（同前）、避雷针→电（同前）、磁力→钢（类型存在+50%，**不看扩展配置**）、静电→电（类型存在+50%，**不看扩展配置**）、引水→水（需扩展配置+存在+50%）；命中则**筛出含该属性的槽位**（筛空则不筛，保留原表）。
3. 按权重降序排序；总权重 = Σ权重。
4. **掷取**：做 `chance_rolls` 次 `rand(总权重)`，**取最大 r**（多次掷提升稀有槽命中）；沿排序表用 r 递减定位槽位。
5. **等级**：`rand(最低..最高)`（含端点）；随后首队员特性——毅力/压迫感/斗志 → 50% 取最高等级；地图级黑白哨新效果——降等级：等级 − rand(1..4) 钳制 ≥1；升等级：等级 + rand(1..4) 钳制 ≤最大等级（降优先）。

### 5.2 指定地图选择（捕虫大会其它参赛者）

- `choose_wild_pokemon_for_map(地图, 类型)`：查"地图×当前版本"的静态表（无则空）；单次掷、无偏好/无等级特性/无哨修正；等级 `rand(最低..最高)`。

## 6. WP36-D：个体生成与修正（`pbGenerateWildPokemon(物种, 等级, 漫游?=假)`）

1. 以物种+等级创建个体（WP18–WP21 创建默认与派生引用）。
2. **持有物**：读取物种的野生持有物三档；基础概率 [50, 5, 1]；首队员复眼/超幸运（后者需扩展配置）→ [60, 20, 5]；若三档同物 → 恒取第一档；按掷值落档后从该档**随机采一枚**。
3. **闪光重掷**：次数 = 背包持有闪耀护符 ? +2 : 0；若启用 `HIGHER_SHINY_CHANCES_WITH_NUMBER_BATTLED`——按图鉴"对战次数"分档（<50→0；50–99 概率 15‰ 加 1；100–199 概率 20‰ 加 2；200–299 概率 25‰ 加 3；300–499 概率 30‰ 加 4；≥500 概率 30‰ 加 5）；次数 >0 时循环：已闪光停止，否则清闪光缓存并重掷个体号（与蛋的重掷同构，WP34 引用）。
4. **病毒**：`rand(65536) < 病毒概率` → 给予（毒株随机 1–15，统计 +1；WP61 前向）。
5. **性别/性格倾向（首队员特性）**：迷人身躯且个体非单性别 → 2/3 概率朝向与首队员相反性别；否则同步（非漫游个体；需扩展配置或另掷 50%）→ 性格=首队员性格（**改写已派生缓存**，WP19 引用）。
6. 记录初始形态（形态函数存在时），触发 `on_wild_pokemon_created` 钩子（示例目录见 §6.1）。
7. 返回个体（未入队；开战由调用方发起）。

### 6.1 示例/默认修正钩子（静态目录）

| 钩子 | 条件 | 效果 |
| --- | --- | --- |
| 全闪光开关 | 指定游戏开关开 | 强制闪光 |

## 7. WP36-E：开战交接与状态生命周期

- `$game_temp.encounter_type`：步进入口在开战前写入（供战斗侧判定环境：钓鱼类型检查、音乐/球效果等）；`pbEncounter` 路径在**开战调用返回后**清空，步进路径在开战调用后清空；`allow_encounter?` 拒绝时保留（§4.5）。
- `$game_temp.encounter_triggered`：仅用于当次标记（战斗启动消费者）。
- `$game_temp.force_single_battle`：进入任一开战路径后复位；漫游/雷达设置（WP37 引用）。
- `pbEncounter(类型, only_single=true)`（由钓鱼/摇树/碎石/甜味调用）：写 encounter_type → 选候选 → 物种钩子 → 无候选即返回假；不强制单打且满足双打条件则选第二候选（再触发钩子；任一为空即假）→ `WildBattle.start(..., can_override: true)`；成功后清 encounter_type、复位强制单打、返回真。**甜味以 only_single=false 调用**（可双打），其余为单打默认。
- 战斗启动本身（阵容、规则、环境）归 WP39/WP45/WP53 前向；本包只固定"已发起调用"与上述临时状态。

## 8. 规则与不变量

1. 数据键"地图×版本"、版本查询回退 0、重复定义编译错误；每表类型独立、步骤概率缺省来自类型目录。
2. 步进触发的三道前置门（可战斗成员/机会判定/类型非空）+ 概率门（§4.2）；主动请求入口按各族自己的前置（不经机会判定与概率门）。
3. 类型选择严格"已定义才选"；时段细分优先于 Day/Night 基础，night 未定义回退基础；无表不选。
4. 概率链的修正按固定顺序应用；**清除累加器**只发生在：驱虫剂挡下、驱虫剂活动时未中、雷达直通场景不涉及；累加只在"步进触发且常规掷未中"发生。
5. 闪光/病毒/性别/性格等生成期修正不改候选选择；选择期修正（偏好过滤/哨）不改生成期概率。
6. 双打判定的优先次序：强制单打 > Safari > 伙伴(真) > 成员数(假门) > 地形 30%。
7. encounter_type 生命周期与清理按 §7；拒绝路径保留值。
8. 所有等级取整为整数区间均匀（含端点）；偏好过滤失败不产生空表（保留原表）。

## 9. 边界与失败

- 无表/空表：机会判定与触发均拒绝；主动请求入口回复各自失败消息（WP59/WP60）。
- 禁用：`encounter_disabled` 一律拒绝（含雷达？——§4.2 步 3"雷达直通"位于禁用检查之后，故禁用仍然否决雷达）。
- DEBUG+Ctrl：仅抑制触发（搭配调试穿透移动，WP12 引用）。
- 驱虫剂挡住：`allow_encounter?` 拒绝后**累加器清零**；`encounter_type` 保留（§7）。
- 版本回退：当前版本表缺失时全部查询落到版本 0；版本号变化立即重载当前地图表。
- 宽限段公式在修正后的概率 < 基础时仍成立（分母基础、分子修正）；概率被修到 0 → 阈值 0 → 放大掷必假（`rand(100) ≥ 0` 恒真）。
- 偏好过滤后空表：保留原表（过滤无效，不影响可得性）。
- 等级钳制：哨效果钳制到 1..100（升等级上限=最大等级）；区间取整含端点（单等级行 min=max）。
- 双打第二择空：`pbEncounter` 返回假、不开战（第一候选不消耗）；步进路径不设第二候选空值检查（选空概率只源于表为空，已在更早拒绝）——静态记录。
- 真实地图编排、概率分布抽样验证与开战集成：运行未决（U01/运行范围）。
