## 3. Review Findings

### R01 — 送审版本记录与两个实际附件不一致

优先级：必须先解决版本归属，才能正式登记本轮对某版本的审查结论。  
性质：已确认、可复现。

位置：`review-manifest-2026-09-19.md@319f3bab`，第 10–11 行。

问题：清单中的 overview 与 module-map 的 SHA-256 和字节数不对应本轮收到的附件；Feature Matrix 与计划一致。行数相同不足以证明内容相同。

处理：

1. 在本地对四份实际文件重新计算哈希。
2. 若本地与本轮实测附件一致，保留旧 manifest 作为历史，新增或明确修订版本清单，注明旧条目已被替代；不回写成旧记录从未有误。
3. 若本地与本轮附件不同，先定位送审的是哪个版本；不要仅把 manifest 改成审查方的数字。
4. 本轮意见按此报告的实测哈希应用。修订后记录新的哈希和变更说明。

验收：本地确认送审的四份文件与被审查附件相对应；版本清单准确且历史可追踪。

### R02 — 完成协议应显式区分本包范围、跨包引用、外部 review 和 Feature 聚合

优先级：建议在开始逐包执行前补充最小约定；不需要改变领域或大规模重画依赖图。  
性质：执行语义风险，不是已经发现显式依赖循环。

主要位置：

- `extraction-plan.md@aef0d7ab`，第 17、25、35–36 行。
- 同文件第 75、82 行：WP23 与 WP30 的规则交界。
- 同文件第 100、106–108 行：WP43 与 WP48/WP50。
- `feature-matrix.md@2f4e3e31`，第 7–9、127、131–134 行。
- `extraction-plan.md@aef0d7ab`，第 43、156–159、187 行。

现有优点：计划已区分开始调查和完成依赖，允许登记未就绪引用；矩阵也明确证据状态不等于规格状态。这些应保留。

剩余风险：现有 Specification status 只定义了 Inventoried 与 Provisional，尚未明确详细提取后如何表示草稿、待 review、范围内已审和部分完成。又存在前向规则引用，例如 WP43 需要后续 WP48/WP50 提供具体修正，WP30 引用由后续 WP23 负责的 Shadow 专用处理。机械要求所有引用先终结会互相等待；完全忽略引用则可能把部分规格包装成完整能力。

建议补充：

- 对每包分开记录“自身声明范围”“必须满足的完成依赖”“后续扩展/复核引用”。
- 后续引用记录目标包、相关规则主题、未闭合内容、影响范围和复核触发条件。
- 自身范围可独立成立且达到标准时，可提交该范围的 review；不得宣称尚依赖缺失规则的完整组合已验证。
- 真正影响本包结果正确性的未决依赖，继续标为 Partial/Blocked；不得仅为维持无环而删掉。
- 明确最少的后续规格状态，例如 Drafted、ReviewPending、Reviewed，并始终附范围；提取模型自检不能标成外部审查通过。
- Feature 状态按承接它的相关包/子范围聚合。WP01 完成不自动代表 F18-07 的 WP77 Demo 部分完成。
- 缺失 Demo 不阻塞无关静态范围的提取和审查；静态范围交付与完整 Demo 覆盖结论分别记录。

不强制新增数据库或多个追踪表。在现有计划的维护规则及 Notes 中明确即可。

验收示例：

- WP43 可以清楚说明哪一组基础计算已提取、哪些特性/道具组合仍待后续核对。
- WP01 产物完成后，F18-07 能同时显示“基线范围已提取待审”与“Demo 验证尚待 WP77/材料”，而不是一个笼统完成标记。

### R03 — WP46 的全量效果映射验收语句存在范围歧义

优先级：非 WP01 阻塞项；执行 WP46 前澄清。  
性质：文档范围歧义，不是已经证明招式能力遗漏。

位置：

- `extraction-plan.md@aef0d7ab`，第 103 行。
- `feature-matrix.md@2f4e3e31`，第 87 行。
- 提取计划第 101–105、158、175 行。

问题：WP46 范围是伤害/恢复相关效果族，但完成条件写“PBS 效果标识全部映射到行为族”。可能被理解为 WP46 必须完成全部效果的调查与映射，越过 WP44、WP45 和 WP47 的范围；也可能只指相关子集，执行者理解不一致。

建议表述：

“本包范围内的伤害、恢复及相关招式效果标识均映射到行为规则；其他已发现效果登记其负责工作包，不在本包重复定义。全局映射随各包累积，WP79 审查未归属项。”

或者保留全局初步目录，但明确它仅表示分派/定位，不等于其他规则族已经提取完成。

验收：WP46 不需要提前执行全部战斗规则；全局覆盖责任仍然保留，不能只检查部分 PBS 名称便宣称所有实现分支覆盖。

## 4. 上轮 review 修订的本轮评价

已在实际附件中看到并核对其对应关系：

- 捕获主规格、领域策略与 UI 呈现分开。

- 证据状态不作为功能完成证书。

本次没有依据要求推倒上述修订。任务行的共同完成标准已经允许不适用项说明理由，因此 WP01 无需伪造游戏运行场景来填模板。
