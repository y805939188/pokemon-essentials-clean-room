## 两项残留

### WP74-R01 [P3] 缓存三分已经正确，但边界汇总仍无条件附上组织器拒绝和导出无动画

位置：主稿第411行；§19-1。

已接受：§3.1/§3.2、§7.1、§16、M01/M33及附表已正确区分缓存为空、已缓存空首槽集合、有效缓存；保存不退出时缓存保留/首次重载对象分离也已闭合。仅剩§19-1的跨入口汇总，当前残留降为P3。

残留：§19-1列完三种缓存前提，末尾仍统一写组织器拒绝进入、批量导出报无动画可导出。这两个入口的门不同：组织器拒绝不存在或首槽为空的集合；批量导出仅在载入结果本身不存在时报告无动画，非空对象的零项集合仍进入遍历并正常完成。

静态反例（未运行）：沿用M33的已缓存零项集合C，并分别独立调用两个入口：组织器拒绝；批量导出接收到C，遍历零项，在其余环境操作正常的前提下显示导出完成，而不是无动画可导出。已有有效缓存时，组织器也不会仅因当前文件不存在而拒绝。

最小修订：仅将§19-1末尾改为各入口各自带前提，或明确引用§12/§13.1而不重复无条件结果；在M26/M27或M33补零项集合的两入口对照并同步当前回应/自检。保持已正确的缓存主体、保存与失效语义，不重写它们。

审计定位：B04:39–45；B05:1252–1257；B06:553–560；B06:585–590。

### WP74-R04 [P2] 清空区间的完整守卫漏了当前帧同号槽为空时直接放行

位置：主稿第229行；§8.2、附表D清空行、M14及当前自检中的完整门声明。

已接受：当前存在单元时的锁定/普通图案/最后同图案个体三组对照、目标重置保留字段、清空与滑动的门不同，均已修正。本轮只补同一守卫的空输入分支。

残留：v3把“未锁定且普通图案或同图案个体数大于1”称为完整两条件，并同步到附表与自检；这只覆盖当前帧同号槽存在的情况。来源先判断当前帧/同号槽是否存在，不存在就直接允许清除目标，无需读取图案或计数。当前帧同号槽为空而目标槽存在，是常规跨帧编辑输入。

## 供修订直接使用的边界对照

以下是静态行为摘要，不是参考代码或未来实现结构。

| 载入结果 | 组织器 | 批量导出（其它操作正常） |
| --- | --- | --- |
| 没有集合对象 | 拒绝进入 | 提示无动画可导出 |
| 有集合对象，但0项 | 拒绝进入 | 遍历0项后完成，不报无动画可导出 |
| 有集合对象，首槽空但后槽有有效动画 | 拒绝进入 | 跳过空槽，按既有资格处理后槽 |
| 首槽非空的有效集合 | 可进入 | 按既有资格遍历导出 |

| 当前帧同号槽的守卫输入 | 区间清空对目标槽的决定 |
| --- | --- |
| 当前帧或同号槽不存在 | 直接放行清槽 |
| 当前槽存在且锁定 | 不清槽，重置目标槽（若存在） |
| 当前槽存在、未锁、为最后一个同图案个体 | 不清槽，重置目标槽（若存在） |
| 当前槽存在、未锁、普通图案或同图案个体数大于1 | 放行清槽 |

R04的空槽反例是当前帧有效、仅同号槽为空的常规输入，不依赖非法游标或异常导入。已有“当前帧在区间前部”的顺序效应仍保留：它被清空后，后续帧可读到当前槽为空并由该分支放行。
