## 2. 盒子：入口与模式（A）

### 2.1 PC 菜单入口

精灵中心 PC（`019_UI_PC.rb`）的 `:pc_menu` 菜单经 MenuHandlers 组装；储存系统项的名字按玩家是否见过储存创始人显示「{创始人}'s PC」或「Someone's PC」（创始人名取全局元数据；写入者属事件侧，U01）。打开储存系统后出现四个命令：

| 命令 | PC 层前置（**整队口径，进入前**） | 进入后的模式 |
| --- | --- | --- |
| Organize Boxes（整理盒子） | 无 | 模式 0（整理） |
| Withdraw Pokémon（取出） | 队伍满 → 提示「Your party is full!」，**不进入**，留菜单 | 模式 1（取出） |
| Deposit Pokémon（存入） | 队伍中**非蛋且 HP>0** 的成员数 ≤1 → 提示「Can't deposit the last Pokémon!」，**不进入**，留菜单 | 模式 2（存入） |
| See ya!（离开） | — | 返回 PC 菜单 |

PC 层两个前置与界面内部的逐目标守卫是**不同检查**（WP25 §5 已按入口分列）：整队口径只拦进入，不拦进入后通过蛋／濒死成员使可用数变化的路径。菜单取消（BACK／See ya!）返回 PC 菜单层；`pbShowCommandsWithHelp` 的取消编码引用 WP17 §4（cmdIfCancel=-1 → BACK 返回 -1 → 退出循环）。

### 2.2 屏幕模式与选择模式

`PokemonStorageScreen#pbStartScreen(command)` 在进入时置 `$game_temp.in_storage = true`、退出时置 false（**正常出口**；异常路径不保证，引用 WP17 §7.3 的同类边界）。`in_storage` 的实际消费者：个体当前形态查询在战斗或储存界面期间直接返回存储形态（`014_Pokemon/001_Pokemon.rb:149`），即储存界面期间动态形态处理器不另行触发——跨区域边界，形态规则本体归 WP21。

| command | 模式 | 画面与选择器 | 正常调用者 |
| --- | --- | --- | --- |
| 0 | 整理 | 盒视图＋可下拉队伍面板；盒选择器（`pbSelectBox`）与队伍选择器双层 | PC「整理盒子」；队伍界面 SPECIAL 桥（`005_UI_Party.rb:774–781`，`@can_access_storage` 且 canswitch≠2 时打开，返回后 `pbHardRefresh`——该桥属 WP66-A 范围，此处只登记入口） |
| 1 | 取出 | 仅盒选择器（`pbSelectBox` 直接返回内部选择，不展开队伍面板） | PC「取出」 |
| 2 | 存入 | 队伍面板常驻展开；仅队伍选择器（`pbSelectParty`，depositing=true） | PC「存入」 |
| 3 | 开即关 | `pbStartBox` 后立即 `pbCloseBox`，无输入循环 | **未定位正常调用者**（全 Scripts 检索 `pbStartScreen(3)` 未命中；搜索未命中 ≠ 不存在） |

另有**选择模式** `pbChoosePokemon`（不经 PC 菜单）：**以取出模式（command 1）的画面与选择器进入**——盒选择器直接返回内部选择，**不展开队伍面板**（与取出模式一致，§3.1）。菜单为 Select／Summary／Withdraw／Item／Mark／Cancel（选中的位置盒号为 -1 时 Withdraw 显示为 Store）；选 Select 返回 `[盒号, 格号]`，取消或退出返回 nil。**返回的是位置、不移动任何成员**。唯一定位调用者是净化室编成（`023_UI_PurifyChamber.rb:1273–1277`；其行为归 WP23；该调用链的可达性分歧另列 N01，§12）。选择模式允许在返回前用 Store／Withdraw 实际改动集合——「只选择」与「真正修改集合」在同一菜单内并存，调用者拿到位置时集合可能已被玩家改动。

**选择模式的「队伍」按钮不走正常队伍路径**：选择器对「队伍」按钮返回特殊位置 `[-2, -1]`，选择模式的循环**没有像正常取出循环那样的拦截**（取出模式会拦下该值并提示「Which one will you take?」），直接交给储存寻址。默认基础储存只把盒号 -1 解释为队伍；其它负盒号按「自数组末起」寻址——默认 40 盒配置下 `[-2, -1]` 指向**零基盒 38 的格 29**（`014_Pokemon/001_Pokemon-related/004_PokemonStorage.rb:159–176` 的原址读取）。因此：该格为空 → 直接回选择循环；**该格有成员 X → 出现 Select／Summary／Withdraw／Item／Mark 菜单，Select 返回原始 `[-2, -1]`**。它既不是队伍选择，也不是安全的无操作保证；菜单中 Store 的文本分支存在不证明正常队伍入口可达。该特殊位置的 Withdraw／Store 后续分支未逐条穷尽，不推断本入口及全部后续调用者均安全（具名保留）。

### 2.3 界面分层（按行为职责，不按类名）

本文件的行为按「呈现与动画」「选择与守卫」「提交写入」描述，不按参考侧的类名划分：

- **呈现与动画**（抓取、滑动、马赛克预览、释放缩小淡出、切换音效）只影响画面，未运行验证，不改变数据语义。
- **选择与守卫**：按键循环内的游标、盒切换、菜单组装与拒绝反馈；守卫条件引用 WP25 §4.2／§5。
- **提交写入**按行为分列、**不经过单一提交点**：切盒在盒选择循环内即写 `currentBox`；盒名与墙纸在盒命令流程内写；标记在标记编辑流程内提交；移动／存取／释放／道具在各自操作确认后按 §4.2 的顺序写。下文「何时改了什么」以此为准。

## 3. 盒子：导航状态机（B）

### 3.1 选择状态

`@selection` 语义（整理／取出模式的盒选择器）：

| 值 | 含义 | USE 结果 |
| --- | --- | --- |
| ≥0 | 当前盒网格位置（0..29，6×5） | `[当前盒, 位置]` |
| -1 | 盒名 | `[-4, -1]` → 盒命令菜单 |
| -2 | 队伍 | `[-2, -1]` →（整理）展开队伍面板；（取出）仅提示 |
| -3 | Close Box | `[-3, -1]` → 退出确认 |
| -4／-5 | 盒名处按左／右的**瞬态**：立即切到上一／下一盒（模 40 回绕）并写 `currentBox`，随后游标归位 -1 | 不产生返回 |

方向键转移（`pbChangeSelection`，均为确定值）：网格内上下按 ±6 移动、出顶到 -1；网格行内左右换行回绕；-1 上→-2、下→2；-2 上→25、下→-1、左右→-3；-3 上→28、下→-1、左右→-2。JUMPUP／JUMPDOWN 在任何位置切上一／下一盒（模回绕、滑盒动画、写 `currentBox`）。SPECIAL 跳回盒名（-1）。ACTION **仅整理模式**：切换 quickswap 开／关（光标皮肤切换；无文本提示）。BACK：保存 `@selection` 并返回 nil（进入退出确认流程，§4.4）。队伍面板内的选择器：0..5 为成员、6 为 Close Box；方向键按 2 列网格转移（左右 ±1 回绕、上下 ±2 越界落到 6）；BACK 返回 -1；depositing=true 时选 6 返回 -3。

**盒切换即写**：左右瞬态与 JUMPUP／JUMPDOWN 直接写 `storage.currentBox`——查看层的盒位置是持久状态（WP25 储存对象字段），不是纯画面状态；捕获存储「当前盒优先」也消费它（WP25 §4.1）。

### 3.2 暂持（held）状态

拿起（`pbHold`）后屏幕持有 `@heldpkmn`；此时：BACK 与 Close Box 均先提示「You're holding a Pokémon!」并留在循环（**持物不能退出**）；quickswap 下 USE 直接放／换；菜单模式下 USE 弹含 Shift／Place 的菜单。放下／交换／释放／存入后暂持清空。**拿起即删源**（队伍侧压缩，WP25 §3），所以「拿起→取消任何后续」并不存在：暂持期间唯一的还原路径是手动放回原位或他位。

### 3.3 队伍面板

整理模式下选择 -2 展开队伍面板（下滑动画），在面板内选成员返回 `[-1, 序号]`；BACK 收起面板、游标回到 -2。面板显示与盒网格共用同一套菜单与写入路径（`selected[0] == -1` 区分队伍目标）。

## 4. 盒子：操作菜单与实际写入（C）

### 4.1 各模式菜单分支

| 模式 | 菜单（按实际拼装顺序） | 说明 |
| --- | --- | --- |
| 整理（有目标成员、无暂持） | Move／Summary／Store 或 Withdraw／Item／Mark／Release／（$DEBUG 时 Debug）／Cancel | 队伍目标显示 Store、盒目标显示 Withdraw；quickswap 开时不弹菜单，USE 即拿起 |
| 整理（暂持中） | Shift（目标非空）或 Place（目标空）／Summary／…同上 | Shift=交换、Place=放下 |
| 取出 | Withdraw／Summary／Mark／Release／Cancel | 选队伍位置只提示「Which one will you take?」 |
| 存入 | Store／Summary／Mark／Release／Cancel | 仅队伍成员 |
| 选择模式 | Select／Summary／Withdraw 或 Store／Item／Mark／Cancel | 无 Release；Select 返回位置 |

空位置且未暂持：直接跳回循环（无菜单、无蜂鸣）。取消（BACK 或选 Cancel）不触发任何写入。

### 4.2 写入序（确认前后各改了什么）

下表「守卫」引用 WP25 §4.2／§5 的条件矩阵（含"未持有／目标成员／持有成员可用性"条件），此处固定**界面时序与写入点**：

| 操作 | 守卫失败（无写入） | 确认路径的写入序 |
| --- | --- | --- |
| 取出（盒→队伍） | 队伍满 → 提示，false | 动画 → `pbMove(-1,-1,盒,格)`（队伍末端追加，源格留空）；暂持成员入队走 `pbMoveCaughtToParty` 并清暂持 |
| 存入（队伍→盒） | 最后可用／邮件／不可存放（按 WP25 条件）→ 各自提示 | 选盒循环：BACK 取消 → **无任何写入**；目标盒满 → 提示「The Box is full.」重选；存入治疗开 → 对待存成员治疗（保留进化准备，WP25 §6）→ 移动（`pbMoveCaughtToBox` 或 `pbMove`） |
| 拿起 | 队伍最后可用 → 蜂鸣＋提示 | **立即删源**、置暂持（队伍侧压缩） |
| 放下 | 目标非空 → **报错**（异常路径）；目标为盒：格号 ≥ 盒当前长度 → 提示「Can't place that there.」；邮件／不可存放 → 各自提示 | 目标为盒且存入治疗开 → 治疗 → 写入目标格、清暂持（队伍目标后压缩整理）；**放回队伍空格不查邮件／不可存放** |
| 交换 | 目标为空 → **报错**；持有成员不可存放（目标为盒）→ 蜂鸣＋提示；目标为队伍格的最后可用链 → 蜂鸣＋提示；邮件（目标为盒）→ 提示 | 目标为盒且存入治疗开 → 对持有成员治疗 → 两位置互换；暂持变为原目标成员 |
| 释放 | 蛋／邮件／不可释放 → 各自提示（任何来源）；**未持有**的队伍最后可用 → 蜂鸣＋提示（**不进确认框**） | 确认框 [No, Yes]（默认 No；BACK=No）→ Yes：删除（或清暂持）＋两条告别消息；No／BACK：**无写入** |
| 道具 | 蛋 →「Eggs can't hold items.」；带邮件 → 要求移除 | 有持物：确认「Take the X?」→ `$bag.add` 成功才清持物（**背包满 → 提示且持物保留**，WP27 引用）；无持物：背包选择画面（仅 can_hold? 过滤，WP66-C）→ 选中即写持物并从背包移除；取消 → 无写入 |
| 标记 | 无 | 编辑循环：USE 将当前标记位按变体数循环 +1（**只改编辑副本**）；选 OK → 提交 `pokemon.markings`；Cancel／BACK → 丢弃 |
| 盒命令（盒名处） | — | Jump：选盒（取消 → 无操作）→ 切盒；Wallpaper：列可用墙纸（可用性规则 WP25 §3.4）→ 选择即**写当前盒背景**；Name：文字输入（0..12 字，WP17 §6 引用）→ 长度 >0 才写盒名，空串不覆盖 |

### 4.3 摘要入口

菜单 Summary 打开摘要画面（WP66-A 本体）：暂持成员 → 以单元素列表打开；队伍／盒目标 → 以对应容器列表打开并**把摘要返回的索引回写到本界面游标**（摘要内部切换成员会改变返回位置）。返回后画面刷新，无集合写入（摘要自身的持物／标记改动归 WP66-A）。

### 4.4 退出与确认

| 路径 | 条件 | 结果 |
| --- | --- | --- |
| BACK | 暂持中（仅整理可有暂持） | 提示「You're holding a Pokémon!」，留循环 |
| BACK | 无暂持 | 确认「Continue Box operations?」：Yes → 继续；No／BACK → 退出 |
| Close Box | 暂持中 | 同上提示 |
| Close Box | 无暂持 | 确认「Exit from the Box?」：Yes → 播「PC close」退出；No → 留循环 |

退出后 `$game_temp.in_storage=false`；屏幕层不做任何集合回滚——**已完成的移动／释放／标记／换盒／换墙纸／改名全部保留**。

## 5. 图鉴：入口与区域选择（D）

### 5.1 入口分流

暂停菜单「Pokédex」项的显示条件（WP62 §6）：有图鉴标志 ∧ 可访问列表非空。进入后三分流：

1. `USE_CURRENT_REGION_DEX` 开 → 直接开主列表（区域取当前地图区域，WP62 §5.2）。
2. 可访问恰一个 → 写 `$PokemonGlobal.pokedexDex = 该区域` 并开主列表。
3. 可访问多个 → 先开区域选择菜单。

### 5.2 区域选择菜单

每行＝区域名＋见过数／拥有数／区域长度；两枚标记分别以「见过数 ≥ 长度」「拥有数 ≥ 长度」点亮（数据查询的失败边界——缺／空表成员查询返回 nil 时计数失败——归 WP62 §5.2，UI 不补 nil 保护）。末行为 Exit。选择区域：写 `$PokemonGlobal.pokedexDex` → `pbFadeOutIn` 开主列表 → 主列表退出后**回到本菜单**（可再选）；BACK 或选 Exit → 关闭。

### 5.3 观看状态（持久）

`$PokemonGlobal` 三项（WP62 §2）：`pokedexMode`（排序／搜索模式，默认 0 数值序；**搜索成功后也被改写**，§6.2）、`pokedexDex`（当前观看区域）、`pokedexIndex`（各区域「上次查看的物种索引」数组；**仅非搜索结果态**在主列表游标变化时写入）。主列表打开时按当前区域的保存索引恢复游标。

## 6. 图鉴：主列表与搜索（E）

### 6.1 列表构建与模式

行来源＝当前区域顺序表；该区域无表或空表时回退全国全物种（数据层失败与 UI 回退的区分归 WP62 §5.2）。模式过滤（`pbCanAddForModeList?`）：数值序＝不按见过过滤；首字母序＝仅曾见；最高／最矮／最重／最轻＝仅拥有。行数据（名字、身高、体重、属性、颜色、形状）取「末次形态」的形态数据（WP62 §4）。

数值序修剪：偏移表区域的**首个未见编号 0 行**移除；**末尾连续未见行**裁去；中间未见占位保留（显示「----------」、无图标、不可打开——WP62 §6／§8 W13）。排序：数值序按区域编号；首字母序按名字（同名片按编号）；体型四模式按身高／体重（同值按编号）。

行图标：拥有 → 拥有图标、仅见 → 见过图标、未见 → 无；编号显示＝位置 +1（偏移表区域整体减 1）。确认键**仅在曾见行**播「GUI pokedex open」并打开条目页；未见行 USE 无任何效果（无蜂鸣）。

### 6.2 搜索

ACTION 打开搜索画面。参数 10 元组：排序、名字、属性 ×2、身高下限／上限、体重下限／上限、颜色、形状。**会话参数的初始化在整个图鉴列表场景建立时进行**（以当时的持久模式与全空过滤建立）；同一场景每次进入搜索都**复制上次接受的会话参数**作为编辑草稿，失败搜索不替换会话参数。主画面七项参数＋Reset／Start／Cancel；每个参数进入各自的子画面（`pbDexSearchCommands`），子画面 OK → 写回该参数、Cancel／BACK → **该参数保持原值**（不写回）。**编辑中的参数只是本地副本**；本地草稿、会话已接受参数、当前显示列表与持久排序模式是四个不同的量。

属性子画面的双槽规则（状态转移，非无条件轮流覆盖）：选择**具体属性**——槽 1 为空则写槽 1；槽 1 非空且槽 2 为空则写槽 2；两槽均满则写当前轮转槽并翻转轮转槽；**禁止两槽同属性**（候选值等于另一槽当前值时不写入）。选择**空白**——槽 2 非空则清槽 2，否则清槽 1，随后轮转槽翻转。重新打开子页时按当前两槽值初始化；轮转槽初始取类型命令数对 2 取余（当前 18 类 → 0）。OK 提交两槽、BACK 放弃（不写回）。

Start：**先把持久排序模式（`pokedexMode`）改写为所选排序（在构建与过滤列表之前，无论是否命中）**；再逐参数过滤——名字＝**首字符**在选定字母组字符集合内（仅曾见）；属性＝仅拥有（双属性为同时包含）；身高／体重＝仅拥有、区间闭含（未选端点 0／999、0／9999，表长哨兵另列 §9）；颜色／形状＝仅曾见；最后**一律再剔除未见物种**并按模式排序。**空结果 → 消息「No matching Pokémon were found.」，留在搜索画面**：结果列表与结果态标志不变（原样保留前一次成功结果或普通列表），编辑参数保留可改条件重试，**但持久排序模式已被改写**；随后 Cancel／BACK 退出搜索**不恢复旧模式**。非空：结果态标志置真、本次参数存入场景会话（`@searchParams`，供结果态与条目页返回使用），结果列表从索引 0 打开，列表背景切换为搜索结果样式，底部改显示「Search results＋命中数」。**只有打开参数页后未 Start 就取消，才没有这次模式写入。**

Reset：参数复位为 [0, -1 × 9]（**只改画面参数**，`pokedexMode` 持久值在下次 Start 时才被覆盖）。Cancel／BACK：放弃本次编辑，关闭搜索画面。

### 6.3 搜索结果态的退出

主列表 BACK：搜索结果态 → 关闭结果态：结果态标志清除、**`pokedexMode` 复位 0**、参数复位、重建列表并**按物种找回**原游标位置（找不到则保持）、保存索引；非搜索结果态 → 退出主列表（回区域菜单或暂停菜单）。条目页返回时：搜索结果态 → **重跑同一搜索**刷新结果（命中可能因记录变化而增减），返回索引越界则夹到末位、负则归 0；非搜索态 → 重建列表并保存返回索引。

## 7. 图鉴：条目页与形态浏览（F）

### 7.1 三页与翻页

条目页三页：Info（信息）／Area（栖息地）／Forms（形态）。LEFT／RIGHT 翻页（1..3 内**夹限**：第 1 页再按 LEFT 不动，第 3 页再按 RIGHT 不动）。UP／DOWN 在同一列表内前后移动，**跳过未见物种**（边界处停住；仅搜索／区域列表传入，未见行本就只在数值序出现）。ACTION：各页都先停音效，**仅 Info 页**重播叫声（Area／Forms 页只停不重播）；BACK 退出并返回最后查看的索引。进入时自动播一次叫声（媒体保留）。

Info 页：USE 在「身高／体重」与「Number Battled（击败＋捕获合成计数，WP62 §2）」之间切换显示；信息深度按拥有门（WP62 §6：拥有 → 类别／体型／图鉴文本／足迹／属性图标／拥有图标；仅见 → 占位）。Area 页：USE 无效果；要点生成（遭遇表枚举、隐藏标志、区域匹配、可见点）与其 v>0 枚举缺陷**引用 WP62 §5.3**；无点 → 「Area unknown」空态。Forms 页：USE 在可列形态 >1 时进入形态选择。

### 7.2 可列形态与形态浏览（含查看写入）

可列形态计算：遍历同种各形态——**两道结构性排除先执行**：跳过无名称的非 0 形态（默认形态 0 无名仍可列）；跳过「图鉴展示形态 ≠ 自身形态」的条目。其后是已见门：每项要求对应（性别, 形态）已见，**「显示全部形态」设置开时仅绕过这道已见门，不能绕过上述两道结构排除**。单一性别种按其实性别档、无性别按雄档（WP62 §6）；排序按形态号再性别档；命名缺省补 Male／Female／One Form／Genderless。

**形态选择（`pbChooseForm`）是唯一的「查看即写」路径**：进入选择器（仅可列项 >1 时开放）后，**首次循环即写一次**——初始比较哨兵保证第一轮就触发 `set_last_form_seen(种, 性别档, 形态)` 覆盖「末次形态」（WP62 §3.2／§3.4／§4 引用；该写入三参，闪光按 setter 默认取 false）；当前末次项不在可列项时，初始索引回到首项，首轮写入的即是首项。其后每次上下移动同样写入并刷新展示；BACK 与 USE 都只是退出——**已写入的末次形态不回滚**，即使进入后未移动直接 BACK 也保留首轮写入（取消 ≠ 事务回滚）。主列表行名／图标、条目页初显形态都消费这张表（WP62 §4）。

### 7.3 独立与简略入口

- **摘要「View Pokédex」**（`006_UI_Summary.rb:1218–1225`；摘要本体归 WP66-A）：先**写** `register_last_seen(该个体)`（覆盖「最近见到」，WP62 §3.4），再开**完整三页**条目页（单物种列表，UP／DOWN 无处可去）；返回摘要。编号计算与摘要「Dex No.」行的「首区即停」分叉归 WP62 §6／§8 W25。
- **捕获／获得后的简略条目**（`pbStartSceneBrief`）：仅 Info 页；编号：全国解锁 → 全国序列（偏移减 1）；否则**逐已解锁区域查、查不到继续查下一区域**（与摘要行分叉，WP62 §8 W25）；USE／BACK 关闭。调用方与写入次序归 WP62 §3.1／§3.2。

## 8. 规则与不变量

1. 盒子四种进入方式与选择模式是**不同入口**：PC 整队前置只在进入时；模式内守卫逐目标（WP25）；选择模式返回位置但允许中途实际改集合；选择模式的「队伍」按钮泄漏特殊负位置 `[-2,-1]`（§2.2），不按队伍语义解释、也不当安全无操作。
2. 游标、当前盒、暂持、quickswap 构成界面状态机；`currentBox` 切换即写持久储存对象；暂持期间禁止退出；**拿起即删源**。
3. 每个写入操作分列「守卫失败（无写入）」与「确认写入序」；**取消不自动等于回滚**（§4.2 各行的取消分支均无写入，但已完成的先前操作保留）。
4. 图鉴入口／区域／主列表／搜索／条目的**记录字段、门与计数规则全部归 WP62**；本包只固定：何种按键打开何种画面、参数何时写回、索引与模式何时持久化、形态浏览何时写末次形态。
5. 查看与写入分层：主列表游标移动（非搜索态）写观看索引；**搜索 Start 先写持久 `pokedexMode`（无结果也写、Cancel 不恢复）**，命中才接受结果列表与本次参数；形态选择器进入首轮与每次移动都写末次形态；其余均为纯查看。
6. 空结果、未见行、未见条目均不报错：空结果留搜索画面给消息（持久模式已改写）；未见行不可打开；条目页翻页跳过未见。
7. 两个报错路径（静态）：放下到非空格、交换到空格——异常分层引用 WP07／WP17 §7.3，正常玩法经守卫不可达（目标空格时菜单显示 Place 而非 Shift）。

## 9. 边界与失败

- 盒空／队空：空位置无菜单；队伍面板成员全空时选择器仍可达 Close Box。
- 满盒：存入时提示并可换盒重试，不自动改选；全满兜底（捕获路径）归 WP25／WP38。
- 满队：PC 层拦「取出」入口；整理模式内取出仍逐次检查并提示。
- 蛋／濒死：可存可取；「最后可用」链按可用性口径（WP25 §5），存蛋不被该链拦。
- 暂持跨页：持物可在盒间（切盒保留暂持）与队伍面板间移动；暂持时马赛克预览不更新。
- 搜索体型端点（未选与表长是两个不同哨兵，**不能都当默认端**）：

  | 端 | 未选（-1） | 具体值（0..表长-1） | 表长哨兵（≥表长） |
  | --- | ---: | ---: | ---: |
  | 身高下界 | 0 | 表值 | 999 |
  | 身高上界 | 999 | 表值 | 0 |
  | 体重下界 | 0 | 表值 | 9999 |
  | 体重上界 | 9999 | 表值 | 0 |

  界面可达路径：上界从最小具体值再向左、且下界未选 → 上界进入表长哨兵（0），区间变 [0, 0]，正身高／正体重物种无命中（不是恢复宽泛默认区间）；下界进入表长哨兵（999／9999）时区间收窄到极端。不改变参考的极端范围行为。
- 缺数据：区域无表 → 主列表回退全国序列；条目页 `region<0` 时取当前地图区域、无地图元数据为 0（WP62 §5.3）；未见图鉴文本按占位显示。
- 保存后恢复：观看区域、模式、各区域索引随全局元数据保存（WP62 §2）；重新打开按保存值恢复；搜索参数不持久。
- 模式 3 无正常调用者（检索未命中 ≠ 不存在）。
