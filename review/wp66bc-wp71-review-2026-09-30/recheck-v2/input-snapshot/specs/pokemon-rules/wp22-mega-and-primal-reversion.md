## 1. 目的、范围与用户流程（A）

本包定义两种可逆特殊形态各自的资格、提交与还原。Mega的常见玩家流程为进入选招菜单→切换Mega待执行选择→选择招式／目标→到执行时点变形并使用招式；取消待执行选择不会消费本场次数。Primal在合格个体入场时自动尝试，不要求玩家在选招菜单登记。二者的“变形成功”“本场Mega已用”“个体当前特殊形态”是不同事实。

战斗动作阶段、次数与排序主规则引用WP40§3／5／7，所属训练家映射引用WP39§5，普通换下引用WP41§4。本文补齐个体数据与这些阶段的连接，不另立一套战斗时序。一般进化、其他动态形态、能力效果族、捕获算法不属于本包。Primal Reversion在入场处指**进入原始形态**；本文用“解除Primal”表示恢复普通形态。

## 3. Mega个体规则与内容（A）

**M01 目标选择**：在物种数据遍历顺序中，找同基础物种且“解除Mega后形态”等于个体当前简化形态的条目；其要求的石与当前持物相同，**或**其要求的招式已掌握，即是候选。首个匹配条目决定目标。两个字段同时有值时是替代条件，不是必须同时满足。没有目标用0表示；可Mega要求目标大于0且不同于当前简化形态。默认数据48个目标、46个基础物种，全部解除至0；47石＋1招式型，详[默认资格附表](wp22-transformation-data.md)。SLOWBRO的Mega目标为2，普通形态0可用，地区形态1即使带相同石也不满足默认还原形态条件。

**M02 当前Mega身份**：读取当前形态的数据，只要它有Mega石或Mega招式字段，就算Mega；不要求当前仍持有该石／仍知道该招。解除读取该当前形态的还原形态，非Mega无解除目标。直接执行个体Mega只在目标>0时提交，直接解除只在目标≥0时提交；不负责战斗许可、环、次数、统计、演出或战斗副本同步。

**M03 查询不等于提交**：查找目标与可用性本身不写形态。简化形态优先使用强制形态；当前数据不存在特定形态时可回退基础物种数据（WP18）。形态锁定并不因本包的变形／解除自动清除，故人工锁定可能掩盖存储形态写入；不承诺它与正常路径等价。未知物种导致后续数据解引用失败的通用规则引用WP03／18，不能用“无目标”概括全部坏输入。

**M04 默认与可选配置**：机制世代8；Mega后重算该席位行动顺序默认开启（派生于世代≥7），禁止Mega开关号34的当前游戏值来自存档／事件，不能把脚本声明当实际开关观察。Mega资格本身无“世代必须≥6”门。环目录按物品MegaRing旗标，默认仅MEGARING；MegaStone旗标不是个体目标选择的必要门，目标由物种数据字段绑定。默认数据集与备份集不混合。训练家顶层PBS对本次检索的环／代表性石／宝珠未命中，只能说明没有这批具名数据样本，不能断言Demo中不可获得或无此功能。

## 4. 战斗许可、登记、取消与实际执行（B／C）

### 4.1 分层资格

| 层 | 实际门与结果 |
| --- | --- |
| 战斗个体可Mega | Transform效果为真则否；否则用持久个体M01。没有额外Shadow门 |
| 正常战斗许可 | 禁止开关开→否；个体不可Mega→否；野生席位→否；然后调试Ctrl可直通；否则Sky Drop中→否，无环→否，该所属训练家不是“未用”→否 |
| 正常玩家菜单可达 | 须可显示命令、可进入普通选招菜单；安可／无可用招式走自动选招，特殊模式自动菜单也可截获，故个体可Mega不保证该入口出现按钮 |
| 裸登记／切换 | 只按侧与所属训练家记录席位，不重做许可；登记可覆盖该业主旧席位，切换相同席位则撤销。不是防重复／非法输入校验器 |
| 正常攻击调用者 | 非野生、未濒死、已选择招式且等于所属训练家的登记席位才调用执行；追击打断可在换人阶段提前调用，WP40§5.5 |
| 执行器自身 | 对象与个体存在、当时仍有可用Mega且尚非Mega才继续；不再次核对开关、环、Sky Drop、野生、所属训练家次数或登记。直接调用不具备正常调用者全部门 |

环按**当前战斗业主**归属：玩家侧业主0使用玩家背包；同侧伙伴有自己的物品表与次数，对方每位训练家也分别计次。个体的原拥有者／外来身份不决定环来源。普通一位训练家带多只可Mega个体，共用一次额度；一侧两位训练家不是合计一次。

### 4.2 待执行状态与取消

状态机：`未用 → 席位待执行 → 已用`；待执行→未用可由再次按按钮、取消整份选择、改选Shift或下一命令阶段清理残留实现。已用状态不会被新回合的残留清理复位。撤销只清“正好是该席位”的待执行记录；不能使已用恢复。选招不合法或多目标选择取消，返回选招继续时可保留Mega待执行选择；退出整个战斗菜单触发外层撤销才清除。执行前资格丢失而直接返回，不消费Mega次数，残留登记下一命令阶段再清。正常变形完成后，同一个体换下再换入仍是Mega，但原业主额度仍已用。

### 4.3 提交与能力反馈

执行时先对玩家本人所属者累计Mega统计，再记原战斗特性；若幻觉能力当前有效则触发解除幻觉接点；显示通用“石与环反应”消息或消息号1的特殊意愿消息，随后变形。缺环名时消息有默认名称回退，这不是授予资格。目标形态名称非空优先，缺省为Mega加物种名；消息号1以数据决定，不由物种硬编码。

变形提交到持久个体，再同步战斗形态并完整回读数值／属性／特性，刷新画面，最后标记业主本场已用。GENGAR已经Mega时清意念移物计数。之后执行失去旧特性、获得当前特性的接点并按设置重算该席位行动顺序；具体能力与天气连锁引用WP49，统计不是独立回滚事务。执行期返回失败的早退不走上述写入；中途异常没有补偿保证。

继承WP21§4：形态提交会清特性缓存、调用形态提交处理器、重算能力、登记全局玩家图鉴。这里先提交个体，再以战斗形态写穿个体，**同值也再提交一次**，最后刷新还会重算；不能承诺只调用一次形态处理器或只登记一次。默认Mega／Primal物种没有本包特有的招式重置步骤；不重建战斗招式、不回满PP、不清全部阶级／其他战斗效果。图鉴写入不受三个战斗包装的internalBattle门统一限制（WP62）。

HP变化遵循WP19重算合同：保持已损失HP的差值，并受最低存活HP规则约束，不保证百分比不变或最大HP不变。默认数据有具名例外：METAGROSS,1的HP基础值95，基础形态80；50级、IV／EV均0时最大HP 140→155，当前70→85；解除回140／70。该数据与官方系列预期不作等同，见附表。濒死路径解除只写个体，没有完整刷新战斗副本，二者可在退出时短暂不同。

## 5. Primal独立合同（D）

**P01 条件**：物种处理器返回一个非空形态值，即有Primal形态；默认GROUDON持REDORB、KYOGRE持BLUEORB均返回1，其余无返回。当前Primal身份＝处理器仍有返回且与**存储形态**相等。由此，持物被外部直接移除后，即便存储形态仍为1，也不再被该查询视为Primal。这不同于Mega按当前形态数据判身份。

**P02 执行与时机**：正常开场／换入的入场处理按速度序，在位置治疗、入场伤害及其濒死／经验／裁判之后，检查一般形态，随后尝试Primal。执行器拒绝空对象／无个体／濒死／Transform／无目标／已Primal；不查环、禁止Mega开关、野生身份、所属训练家额度，也不写Mega登记／统计。合格野生个体亦可进入Primal；同侧多个个体可分别变形。

**P03 传播与能力**：持久形态→战斗形态→完整数值／类型／能力回读与场景刷新，同§4.3的重复提交边界。KYOGRE／GROUDON各有前后动画调用，再给Primal消息。该执行器本身不调用Mega的失去／获得能力链，也不主动调用Mega后的排序重算；实际入场消费者紧接持续能力检查与入场能力，故新的能力可以在该处参与天气等效果。不能从“执行器无能力钩子”推导入场没有能力效果，也不能对裸Primal调用补造同一效果。

**P04 解除**：若存在专门解除处理器并有返回，直接提交该返回；否则仅当前Primal身份为真时提交0。当前快照无专门解除处理器登记，只有上述两个进入处理器。缺宝珠→当前身份假→裸解除不回0，是人工改物／坏状态边界；普通物品移动的不可丢失门约束两种宝珠与各自物种（WP47-B／50），不能把正常门与直接状态编辑混同。返回0的自定义进入处理器在接口层也算“非空”，与Mega必须目标>0不同；此处是静态变体合同，非默认数据或插件运行保证。

## 7. 失败、不变量与扩展边界（F）

- 无可用数据、石或招式不匹配、来源形态不匹配均使正常Mega不可登记；执行前再次无法取得目标则不变形。不会选择列表中的第二条来绕过首个匹配条目的返回语义。
- Transform阻止战斗层获得Mega／Primal资格；个体裸接口不检查该战斗效果。Shadow没有额外统一禁止门；两域实际组合由各入口与招式／持物状态决定，不按本批阅读顺序新增优先级。
- 同一玩家业主一次额度在成功执行后不可由换下、濒死、取消或解除返还；裸登记、调试直通并不承诺守住正常次数限制。
- 资格读取与提交不是原子事务，数据处理器／消息异常不自动回滚已记统计或形态；默认数据与自定义处理器坏输入分列。
- AI先尝试换人、道具与特殊自动菜单；没有截获才在许可真时登记Mega，随后选招。差招转换人成功会撤销该登记（WP51）；WP52评分／预测及记录回放Mega标记缺口（WP58）不改变本包真实变形规则。
