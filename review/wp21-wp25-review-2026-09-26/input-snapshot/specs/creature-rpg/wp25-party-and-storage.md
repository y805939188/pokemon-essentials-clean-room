## 1. 目的、范围与非目标

**目的**：定义队伍与盒子的容量、占位、成员移动与限制——哪些操作移动同一对象、哪些路径生成副本；容量/空位/守卫的实际行为；存入/取出与持久状态的保留规则。完成计划中的"生物—队伍—储存"当前检查点的本包部分。

**范围**：

1. WP25-A：容量与占位——队伍/盒子/每盒容量、计数、伪位置（队伍作为盒 -1）、空位查找、地区化储存。
2. WP25-B：领域操作与界面流转——复制/移动/删除、捕获与赠送的容器结果、队伍顺序变更、界面"拿起/放下/交换/存入/取出/释放"。
3. WP25-C：限制与守卫——不可存放/不可释放/邮件/蛋/最后可用成员/满队满盒，区分领域入口与 UI 守卫。
4. WP25-D：持久状态界面的集合侧——存入治疗（配置）、进化准备标记、身份/来源不变。
5. F07-04、F07-05 中属于 WP25 部分的状态更新。

**非目标**：

- 不定义赠送/脚本交换完整接收流程（WP26）、捕获特有强制入队/转送选择（WP38）、寄养会话与繁殖（WP33）、专门 UI 全流程（图鉴/组队界面完整交互 WP66）。
- 不定义个体字段本身（WP18）与治疗语义细节（WP20，引用）；不定义存档布局（WP09/WP10，标记转换引用）。
- 不运行游戏或参考脚本；不设计未来框架的容器 API；"盒数 40 / 每盒 30"是**该内容配置的当前值**，不提升为所有 Creature-RPG 的通用常量。

## 2. 概念与术语

- **队伍**：玩家的有序成员数组（容量 6，配置值）；成员可为蛋/个体。
- **盒子**：储存容器——多盒、每盒 6×5=30 格（有序网格，允许中间空位）；盒有名字与背景（墙纸）编号。
- **伪位置（盒 -1）**：把"队伍"当作一个可寻址容器（与真实盒子同接口），取值/赋值/容量（6）/空位查找统一——但**队伍侧删除会压缩数组**（索引会移动），盒子侧删除留空位。
- **持有流转（界面）**："拿起"= 把成员从容器取出并置于界面持有位（源立即删除）；"放下/交换"= 放入目标（可治疗）或与目标交换。
- **存入治疗**：一项配置——把成员放入盒子时是否先"完整治疗"（并保留"进化准备"标记）。**当前快照默认世代 8 → 该配置为关闭**（开关定义见 §9）。
- **可用（able）**：非蛋且 HP>0（界面守卫口径）。

## 3. WP25-A：容量与占位

### 3.1 容量与计数（`004_PokemonStorage.rb` 全文，本轮逐行阅读）

| 量 | 值/规则 | 备注 |
| --- | --- | --- |
| 队伍容量 | 6（配置） | `party_full?` = 队伍长度达到上限 |
| 盒数 | 40（配置，`NUM_STORAGE_BOXES`） | `maxBoxes` 返回盒数组长度 |
| 每盒容量 | 30（6 宽 × 5 高） | `PokemonBox::BOX_SIZE` |
| 盒计数 | `nitems`（非空数）、`full?`（满）、`empty?`（全空） | 网格长度固定、空位保留 |
| 全储存满 | 所有盒 `full?` | 另有常用组合"队伍满且储存满"（赠送路径使用，WP26 引用） |
| 装置规模有效性 | `maxPokemon(box)`：盒号 ≥ 盒数 → 0；盒 -1 → 6；否则 30 | 供遍历与容量判断 |

### 3.2 伪位置与寻址

- 取值/赋值：`[盒 -1]` 与 `[盒, 索引]` 都支持；队伍作为盒 -1。
- **空位查找** `pbFirstFreePos(box)`：盒 -1 → 队伍长度（≥6 → -1）；盒子 → 从 0 起首个空位，否则 -1。
- 网格遍历（供界面绘制/统计）：按容量上限逐格读取。

### 3.3 地区化储存（`RegionalStorage`）

- 多地区各自一套储存：按**当前地图 → 地区编号**解析并缓存；重解析条件=地图变化；**无地图或无地区元数据时报错**（提示设置地图元数据）。
- 地区储存对象按需创建（首次访问该地区时）。
- 代理方法覆盖盒集合的主要操作与墙纸操作；**静态反例**：其 `pbDelete(盒, 索引)` 代理实现引用了未定义标识（参数名不一致）——该代理路径被调用会失败（按行为登记，不修参考）。
- 消费者：菜单/PC/仓库界面等通过全局储存句柄访问（具体入口归 UI 包）。

### 3.4 墙纸（背景）

- 总目录 = 16 种基础 + 24 种特殊（当前快照计数）；每盒有背景编号。
- **可用性**：基础墙纸恒可用；特殊墙纸需解锁标记（数组按目录序号）；提供解锁/锁定工具（未定位正常游戏内解锁写入者——U 类）。
- 盒显示读取当前可用墙纸清单与当前背景。

## 4. WP25-B：领域操作与界面流转

### 4.1 领域操作（容器方法层）

| 操作 | 输入 | 结果（后置状态） | 失败/边界 |
| --- | --- | --- | --- |
| 复制 `pbCopy(目标盒,目标索引, 源盒,源索引)` | 位置 | 目标处 = **同一对象引用**（不生成新个体）；目标索引 <0 且目标为盒 → 自动找首个空位（找不到 → false）；复制到盒时若"存入治疗"开 → 治疗 + 保留进化准备 | 复制到队伍：满队 → false；复制到盒：源为空 → **报错**；目标为盒且盒号越界：写值失败（越界索引） |
| 移动 `pbMove(...)` | 同上 | = 复制成功 **且** 删除源（源删除在队伍侧会压缩） | 复制失败 → 不删除源 |
| 删除 `pbDelete(盒, 索引)` | 位置 | 该处置空；**队伍侧立即压缩**（其后索引前移） | 空位置：无效果 |
| 捕获入队 `pbMoveCaughtToParty(个体)` | 个体 | 追加到队伍末尾 | 满队 → false；**返回值怪癖**：成功时返回该个体对象（真值），调用者按真值使用（勿依赖布尔） |
| 捕获入盒 `pbMoveCaughtToBox(个体, 盒)` | 个体+盒号 | 写入该盒首个空位；若"存入治疗"开且盒号 ≥0 → 治疗 + 保留进化准备 | 该盒无空位 → false |
| 捕获存储 `pbStoreCaught(个体)` | 个体 | **当前盒优先**首个空位；否则从 0 号盒起扫描所有盒，写入并**把当前盒切换到该盒**；返回盒号 | 全部满 → 返回 -1；**注意：若"存入治疗"开，治疗发生在前，即使随后找不到空位（全满）也已发生**（静态事实） |
| 队伍交换 `pbSwitch(旧, 新)` | 两个队伍索引 | 两个位置的成员互换（同一对象换位；顺序变化） | 相同索引：无效果 |
| 队伍移除 `remove_pokemon_at_index(索引)`（训练家层） | 索引 | 移除该成员 | 前置：移除后仍须有其它可用成员，否则 false（成员守卫在训练家层；见 §5） |
| 清空盒 `clear` | 盒 | 网格清空（存档/新游戏路径引用 WP09） | — |

- **移动即同一对象**：以上操作不创建个体副本（不复制身份/来源/持久状态）；副本语义只出现在明确"复制"语境（WP18 §5.1 的个体克隆与 §5.5 的进化复制路径）。

### 4.2 界面流转（队伍界面 + 仓库界面，静态核对）

**队伍界面**（`005_UI_Party.rb`）：
- 菜单：摘要 / 开关(调试) / **切换**（选择另一成员 → 两成员换位；仅当队伍长度 >1 时可用）/ 邮件（读信/取下）/ 道具（使用/给予/取下/移动 子菜单）。
- 切换 = `pbSwitch` 语义（同一对象换位）。

**仓库界面**（`017_UI_PokemonStorage.rb`）与 **PC 菜单**（`019_UI_PC.rb`）：界面分两层——逻辑与守卫在**屏幕类**（1705–1905 段），动画/呈现镜像在**场景类**（1117–1210 段）；本节只登记逻辑层守卫。

- PC 菜单：整理盒子 / 取出 / 存入 / 离开——**存入前置**（PC 层）：非蛋且 HP>0 的成员 ≤1 → 拒绝并提示"不能存入最后一只"；**取出前置**（PC 层）：队伍满 → 拒绝。
- 界面操作（仓库屏）：
  - **取出**（盒 → 队伍）：从盒取出必须给盒号（对队伍面板调用会报错）；队伍满 → 拒绝；持有位有成员 → 该成员入队，否则把所选成员移入队伍。
  - **存入**（队伍 → 盒）：只能从队伍面板发起（对盒发起会报错）；守卫链：最后可用成员（含持有位场景）→ 拒绝；持有位/目标带邮件 → 提示移除；持有位/目标"不可存放" → 拒绝；随后选择目标盒循环：盒满 → 提示重试/换盒；"存入治疗"开时对**待存成员**先治疗（保留进化准备）；移动。
  - **拿起**：目标为队伍最后可用成员 → 拒绝；否则删除源、置入持有位（源立即为空）。
  - **放下**：目标格必须为空（否则报错）；盒子越界（索引 ≥ 容量）→ 拒绝；邮件/不可存放 → 拒绝；"存入治疗"开且目标为盒 → 治疗；写入；队伍侧压缩。
  - **交换**：目标格必须非空（否则报错）；守卫：向盒交换时"不可存放" → 拒绝；**当目标为队伍一格、且该格是最后可用成员、而持有位成员不可用时** → 拒绝；向盒交换时持有位带邮件 → 拒绝；"存入治疗"开且目标为盒 → 治疗（对持有成员）；交换后持有位 = 原目标成员。
  - **释放**：蛋 → 拒绝；带邮件 → 拒绝；"不可释放" → 拒绝；不足场景守卫：对**队伍面板**释放且其为最后可用成员 → 蜂鸣拒绝（不弹确认）；确认对话框（默认"否"）选"是" → 删除并提示；取消 → 无变化。
- **整理**（PC 菜单第 0 项）即打开仓库界面进行人工移动/交换/排序——**未见自动排序命令**（检索未命中；搜索未命中 ≠ 不存在）。

## 5. WP25-C：限制与守卫（分层）

| 限制 | 领域层（容器/训练家方法） | 界面层（已定位守卫） |
| --- | --- | --- |
| 满队 | 复制到队伍 / 捕获入队返回 false | 取出前置、存入后队伍压缩、PC 取出前置 |
| 盒满 / 全满 | 空位查找返回 -1；存入循环提示 | 存入目标盒循环重选；全满 → 捕获路径返回 -1（球使用限制归 WP38） |
| 最后可用成员 | 训练家层 `remove_pokemon_at_index` 置否（移除后须仍有可用） | 存入/拿起/交换/释放四处（口径：非蛋且 HP>0 计数 ≤1；含持有位对照），PC 存入前置同义 |
| 蛋 | （容器不限制） | 释放拒绝；取出/存入/交换允许（蛋可存盒） |
| 不可存放 | 容器不检查 | 存入/放下/交换到盒时拒绝（个体标记，WP18 §3.3） |
| 不可释放 | 容器不检查 | 释放拒绝 |
| 邮件 | 容器不检查 | 存入（持有位或目标）/放下/交换/释放前要求移除（邮件对象耦合见 WP20 §6.3、流程 WP64） |

- **重要边界**：除容量/空位（领域层确有检查）外，上表守卫**大多在界面/调用者层**——不能概括为"所有集合入口共同的不变量"；同样，界面某处的守卫（如最后可用成员）不保证其它入口（脚本、事件、赠送、寄养）也检查。

## 6. WP25-D：持久状态交界（集合侧）

- **存入治疗**（配置）：开启时在三处实现同一模式——复制入盒、捕获入盒、捕获存储、"放下/存入/交换到盒"（界面）——"先保存进化准备标记 → 完整治疗（HP/异常/PP 及清除该标记）→ 恢复进化准备标记"（完整治疗语义引用 WP20 §3.2）。
  - **默认值**：世代 ≤7 开、世代 8（当前默认）**关**；关闭时存入不做任何治疗。
- **身份/来源**：移动/存入不改变身份、拥有者与来源记录（同一对象）；取出同样。
- **持有物**：集合操作本身不动持有物；捕获流程的持有物登记在战斗侧（WP20 §6.4、WP38 引用）。
- **蛋**：可存入盒（蛋的展示/孵化流程 WP35）；存入治疗对蛋为无效果（WP20 蛋守卫）。
- **图鉴/统计**：集合操作不触图鉴；捕获路径的登记归 WP38。
- **迁移交界**：旧存档标记位掩码在迁移中转换（三处：队伍/寄养槽/盒子，WP21 §5.1 引用；迁移机制 WP10）。

## 7. 规则与不变量

1. 队伍与盒子**共享同一对象寻址**（盒 -1 = 队伍）；队伍侧删除压缩、盒侧删除留空。
2. "移动"= 复制（同引用）成功后删除源；任何集合操作不复制个体身份或状态。
3. 容量是配置/数据值（6 / 40 / 30）；越界读取按容量函数语义（≥盒数 → 0 容量；盒 -1 → 6）。
4. 捕获存储的盒选择顺序：当前盒 → 0 号起扫描；成功时当前盒更新；全满 -1。
5. 存入治疗默认关闭（世代 8）；开启时"治疗+保留进化准备"（三处同模式）。
6. 最后可用成员保护存在于训练家移除方法与界面守卫链；活动口径 = 非蛋且 HP>0。
7. 交换 = 两个位置的成员互换（同对象）；放置要求目标为空；放入盒的守卫按 §5 表分层。
8. 释放不可逆：确认默认"否"；成功即删除（无回收）。
9. 邮件与"不可存放/不可释放"限制在界面层消费个体标记；领域容器不检查这些标记。

## 8. 边界与失败

- **报错路径**（静态）：从盒取出却传队伍位置；存入却传非队伍位置；放下到非空格；复制空成员到盒；地区储存无地图/无地区。
- **返回值怪癖**：捕获入队成功返回个体对象而非 true（调用者应只判真值）；捕获入盒成功返回 true/失败 false；捕获存储返回盒号（含 -1）。
- **索引变化**：队伍删除压缩会让既有索引前移（调用者须按压缩后语义处理；界面的持有/放置流程即按此顺序执行）。
- **存量怪癖**：`pbStoreCaught` 的治疗先于空位查找（全满时也已治疗）；`RegionalStorage#pbDelete` 代理实现对被调用即失败（静态反例，未修参考）。
- **墙纸解锁**：正常游戏内解锁写入者未定位（U 类）。
- **守卫边界**：非界面入口（脚本/事件/赠送/寄养）不继承界面的最后成员/邮件/标记守卫；本包不声称所有入口一致（未穷尽脚本消费者）。
