## 1. 目的、范围与非目标

**目的**：定义玩家与 NPC 训练家的身份、外观、资源与许可，以及伙伴的注册/参与语义——供个体拥有者/外来判定（WP18）、战斗参与（WP39 引用）、集合与获得流程（WP25/WP26）与 UI（图鉴/训练家卡等）引用。

**范围**（WP24 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP24-A：身份、外观与标识——训练家基础字段、玩家扩展、玩家内容（编号/套装/字符集/回家点）、初始命名，及其与 WP18 拥有者的关系。
2. WP24-B：资源与许可——金钱/游戏币/对战点/火山灰的域与写入者；徽章与功能标记的读取消费者。
3. WP24-C：NPC 训练家数据与装载——训练家类型目录、训练家记录（版本）、装载流程、缺失数据反馈与调试新增路径、队伍生成覆盖次序。
4. WP24-D：伙伴——注册/注销、参与资格、战斗内拼接与战后处理、与野外流程的交界。
5. F07-02、F07-03 中属于 WP24 部分的状态更新。

**非目标**：

- 不定义战斗准备/布局的完整规则（WP39）、AI 行为技能（WP51）、服从性判定（WP40 引用本包徽章/等级输入）。
- 不定义收藏集合（WP25）、赠送/交换完整流程（WP26）、图鉴规则（WP62）、神秘礼物完整流程（WP64）。
- 不定义编辑器/调试菜单的完整 UI（WP73）；调试路径仅作对照登记。
- 不重复 WP18（个体/拥有者字段）与 WP02（配置值清单）。
- 不运行游戏或任何参考脚本；不设计未来框架的账号/存档 API。

## 2. 概念与术语

- **训练家（Trainer）**：`{类型, 名字, 标识, 语言, 队伍}` 的基础实体；玩家与 NPC 都是其特化。
- **训练家类型（trainer type）**：内容数据——显示名、性别、基础资金、技能档、标记、三类战斗 BGM（F07-02）。
- **训练家记录（trainer data）**：`{类型, 名字, 版本, 队伍数据…}` 的可装载数据；**版本**用作同一训练家的多套变体（事件传参选择）。
- **玩家内容（player metadata）**：按玩家编号提供训练家类型、各运动状态字符集与"回家点"（失败后去处）。
- **资源**：金钱、游戏币、对战点（BP）、火山灰——各有限值与写入入口。
- **许可标记**：徽章数组与一组功能布尔（图鉴/导航器/跑鞋/盒子连接等）——读取侧决定菜单与移动/道具备选资格；写入侧多为事件（材料缺口）。
- **伙伴（partner）**：注册为"随行训练家"的 NPC 记录 `{类型, 名字, 标识, 队伍}`；参与战斗时作为玩家侧第二训练家。

## 3. WP24-A：身份、外观与标识

### 3.1 训练家基础字段（`001_Trainer.rb` 全文，本轮逐行阅读）

- 字段：类型（规范标识）、名字（可写）、标识（32 位整数，可写）、语言（可写，来源为当前语言设置，WP08）、队伍（数组，可写）。
- **标识双半**：公开号 = 低 16 位；秘密号 = 高 16 位；均可对给定值计算。生成：初始化时 32 位随机。
- **外来标识**：生成"任意其它"32 位随机且不等于自身的标识（供外来拥有者构造，WP18 §6.1 引用）。
- 显示名：类型名 + 名字；类型带"NoName"标记时只显示名字（WP03 数据）。
- 语言：初始化读取当前语言编号（pbGetLanguage；WP08 引用）。
- 派生查询（不穷尽，队伍相关见 §6/§7）：可战斗成员计数、首/末可用成员、是否拥有物种/招式/属性、全队治疗封装等——多数为集合/战斗读取，集合约束主规格在 WP25。

### 3.2 玩家扩展（`004_Player.rb` 全文，本轮逐行阅读）

| 字段 | 域与规则 | 说明 |
| --- | --- | --- |
| `character_ID` | ≥1 的玩家编号；**写入经统一入口**（音量：编号 <1 拒绝；元数据不存在拒绝） | 变更触发地图角色字符集刷新（WP12/16 渲染交界） |
| `outfit` | 套装编号（整数）；写入同样触发字符集刷新 | 与玩家编号共同决定外观（见 §3.3） |
| `badges` | 布尔数组（默认 8 位）；训练家卡读取可跨"地区×8"扩展索引 | 见 §4.2 |
| `money` / `coins` / `battle_points` / `soot` | 整数，setter 钳到各自上限；**非法类型报错**（校验） | 见 §4.1 |
| `pokedex` | 图鉴对象（创建即有；是否"获得"由图鉴标记区分） | 规则归 WP62 |
| 功能标记 | 见 §4.3 表 | 读取侧消费者明确；写入侧多为事件（缺口） |
| `mystery_gifts` | 已下载礼物数据数组 | 流程归 WP64 |
| `trainer_type` | **覆盖**：由玩家元数据的当前编号解析（不是 Trainer 的基础字段） | §3.3 |

- 图鉴便捷查询：`seen?`/`owned?` 直接转发图鉴对象（WP62 引用）。

### 3.3 玩家内容与初始命名（`017_PlayerMetadata.rb`；`001_Utilities.rb:239–287`）

- **玩家元数据**：编号 → 训练家类型 + 9 个字符集键（行走/奔跑/骑行/冲浪/潜水/钓鱼/冲浪钓鱼等，未定义项按链式回退：奔跑缺省用行走、骑行用奔跑、冲浪用骑行、潜水用冲浪、钓鱼用行走、冲浪钓鱼用钓鱼）+ "回家点"（地图与坐标朝向；失败回程消费者归 WP11/WP13 交界）。编号为**数字键**（与其它内容数据的符号键不同）。
- **切换玩家**：`pbChangePlayer(id)`——id <1 拒绝、元数据不存在拒绝；成功写 `character_ID`（触发字符集刷新）。
- **初始命名流程**（`pbTrainerName`，静态核对）：
  1. 若当前玩家编号 <1 → 先切换到编号 1；
  2. 未提供名字时弹出名字输入（长度上限 = 配置值 10）；**取消/空输入** → 生成建议名：取系统用户名第一个词、首字母大写，若超长则去尾部数字再试，仍不行则用系统用户名截断到上限（注：源码留有"随机名字"的不可达分支——按行为记录，不作为设计依据）；
  3. 写入玩家名字与套装编号（outfit 参数）。
- **角色字符集选择**（消费者）：按"潜水/冲浪/骑行 > 行走"的优先级从元数据取字符集；玩家编号/套装变更时刷新（`refresh_charset`，WP12 运动状态处引用）。

### 3.4 与 WP18 拥有者的关系

- 拥有者构造读取训练家的 `标识/名字/性别/语言`：**性别来自训练家类型**（不是训练家字段）；语言来自训练家字段（WP18 §6.1 引用）。
- 外来判定只比较标识与名字（WP18 §6.4 引用）；伙伴注册会把其队伍成员的拥有者重设为该训练家本人（§6.1）。
- 玩家标识的用途（异色判定输入、外来判定）见 WP18/WP19 引用；本包只保证"玩家标识在初始化时生成且可写"。

### 4.2 徽章与许可

- 存储：布尔数组（默认 8 位）；**计数 = 真值个数**。
- 消费者（已定位）：
  - 场地招式许可：配置开关选择口径——**默认按"数量 ≥ 需要数"**；变体为"按具体位"（即第 N 个徽章是否存在）；具体招式需求数值归内容数据（WP12/WP13 交界引用）。
  - 服从性：徽章计数换算可服从的等级上限（战斗包引用；完整判定 WP40）。
  - 训练家卡显示：按"地区×8"扩展索引读取（地区机制消费）。
  - 失败罚金：见 §4.4 的倍数档。
- 写入者：**核心脚本中未定位**（仅调试工具可整批置真；可能由道馆事件写入，U01 保留）。徽章获得时间统计字段的写入声明在事件侧（WP06 统计目录引用）。

### 4.4 战斗内金钱结算（调用玩家 setter 的两个入口）

- **胜利所得**（训练家战）：对每个对手累加"该对手队伍最高等级 × 其训练家类型的基础资金"；"护身金币/快乐时光"各提供 ×2；再加"聚宝功"累积额（同样受两倍加成）；随后写入玩家金钱并记录统计（获得额 >0 时提示）。
- **失败所失**：需要启用金钱结算且"不损失金钱"开关关闭；取玩家队伍最高等级（**不含伙伴队伍**）；倍率按徽章计数（档位：8/16/24/36/48/64/80/100/120，计数超出取最后一档）；损失额不超过当前金钱；写入玩家金钱并记录统计。
- 边界：上限由 setter 钳位（金钱溢出被截断到上限；"实际获得"按写入前后差计——已达上限时显示 0）。

## 5. WP24-C：NPC 训练家数据与装载

### 5.1 数据责任

- **训练家类型**（PBS schema）：显示名、性别（男/女/未知或混合——未知映射 2）、基础资金（显示"金额×最高等级"）、技能档（AI 消费，WP51 引用）、标记（"NoName"等）、三类 BGM（战斗前/中/胜利）。
- **训练家记录**：类型 + 名字 + 版本 + 队伍条目；队伍条目字段（从装载消费面核对）：物种、等级、形态、持有物、招式列表、特性索引/显式特性、性别、异色/超级异色、性格、IV/EV、友好度、昵称、球、Shadow 标记——**个体生成细节与覆盖次序归 WP18 §4.3**（引用）；本包负责数据责任与装载流程。

### 5.2 装载流程（`002_Trainer_LoadAndNew.rb:4–10`）

1. 解析训练家类型：未知 → **报错**。
2. 按（类型, 名字, 版本）查训练家记录：不存在 → 返回空（由调用者处理缺失，§5.3）。
3. 存在 → 转换为可战斗训练家：显示名**可被对战变量替换**（"对手名数组"配置：类型匹配且变量为非 0 字符串 → 用变量值）；标识 = 外来标识；物品列表克隆；胜负台词；队伍逐条按 WP18 的生成覆盖次序构建；收尾重算。

### 5.3 缺失数据反馈与调试新增路径（与正常路径分开）

| 入口 | 非调试行为 | 调试行为 |
| --- | --- | --- |
| 训练家检查（事件调用） | 直接放行（不检查） | 类型缺失 → 提示可新建类型（调试编辑入口）；训练家（版本）缺失 → 提示"新增变体？"并可生成 |
| 缺失训练家（装载失败兜底） | **报错**（含类型/名字/版本信息） | 提示"新增训练家？"；选择"是"→ 交互式新建 |
| 交互式新建 | —（不可达） | 循环录入队伍成员（首个必须录入；物种选择 + 等级范围 1..等级上限、默认 10）；可选**写回**：注册到记录并写回 PBS（训练家类型/训练家两个文件；写回机制归 WP04）、提示已写入 |
| 空闲版本查找 | — | 0..255 内首个未占用的版本号；全部占用 → -1 |

- 调试新增的产物与作者数据同构（写回 PBS 即成为正常数据）；本包只登记行为，不设计未来编辑工具。

## 6. WP24-D：伙伴

### 6.1 注册与注销（`001_Overworld.rb:637–651`）

- **注册**（`pbRegisterPartner(类型, 名字, 版本)`）：
  1. 取消载具（载具清理归 WP12）；
  2. 装载训练家（§5.2；类型未知按报错，记录缺失按空处理——静态可得但完整失败分支未穷尽）；
  3. 触发"训练家装载"事件扩展点（WP05 引用）；
  4. 把其队伍成员的**拥有者设为该训练家本人**（外来判定因此"非外来"）并逐个重算；
  5. 记录为伙伴：`[类型, 名字, 标识, 队伍]`（写入全局伙伴槽）。
- **重复注册** = 替换（再次注册覆盖伙伴槽；旧记录不另行清理——静态语义）。
- **注销**：伙伴槽置空（无其它清理副作用）。

### 6.2 参与资格（战斗侧读取）

- 双打许可：玩家可战斗成员 ≥2，**或**（有伙伴且可战斗成员 ≥1）。
- 三打许可：玩家可战斗成员 ≥3，**或**（有伙伴且可战斗成员 ≥2）。
- 战斗规则可显式禁用伙伴（规则输入"noPartner"）；若战斗规模为单打且未显式指定规模，伙伴**默认不参与**（仅多目标野生战等触发默认参与——按静态条件登记，完整规则归 WP39）。
- 参与时：伙伴作为玩家侧**第二训练家**，其队伍追加在玩家队伍之后并入战斗队伍（起止索引记录）；伙伴道具从其训练家数据读取（克隆）。

### 6.3 战斗内与战后

- 伙伴队伍成员在战斗中按普通成员处理（含形态进入/离开触发，WP21 引用）。
- 战后清理：伙伴在场时——**玩家全队治疗**；伙伴队伍逐成员完整治疗 + 解除 Mega/Primal（WP22 引用）；该清理发生在每次战斗结束后（含未参战情形——按调用位置静态登记）。
- 败北/平局：玩家队伍全队治疗（与伙伴同段流程）。

### 6.4 与野外流程的交界（已定位调用点）

- 漫游宝可梦流程在"伙伴在场"时跳过（具体条件归 WP37 引用）。
- 野生遭遇入口在"伙伴在场"时返回特定结果（细节归 WP36 引用）。
- 宝可雷达使用条件包含"未骑车且无伙伴"（细节归 WP37 引用）。

## 7. 规则与不变量

1. 训练家标识为 32 位；公开/秘密两半；外来标识 != 自身标识。
2. 拥有者构造的性别取自**训练家类型**；语言取自训练家字段；外来判定只用标识+名字（WP18 引用）。
3. 玩家编号/套装写入经统一入口（编号 <1 或元数据缺失拒绝），并触发字符集刷新；字符集按运动状态优先级与链式回退选择。
4. 四类资源 setter：非法类型报错、负值钳到 0、超上限钳到上限；本包不承诺"上限来自何处"以外的规则。
5. 徽章计数 = 布尔真值个数；场地招式许可的口径由配置二选一（默认数量≥需求）；服从性换算引用（WP40）。
6. 训练家装载：类型未知报错、记录缺失返回空、版本由调用者选择；显示名可被对战变量覆盖。
7. 调试新增路径与正常路径分离：写回 PBS 属调试能力；非调试缺失一律报错。
8. 伙伴槽为单槽：注册=替换、注销=置空；注册时会重设其队伍成员拥有者并重算。
9. 伙伴参与资格 = 双打/三打人数规则或伙伴补位；显式规则可禁用。

## 8. 边界与失败

- `money=`/`coins=` 等：非整数报错（不静默）；负值 → 0；超上限 → 上限。
- `pbChangePlayer(<1)` → false；元数据缺失 → false（不改状态）。
- 初始命名：名字输入取消/空 → 建议名流程；系统用户名不可用时的最终回退为"截断的系统用户名"（源码另含不可达的随机名分支——按行为登记）。
- 训练家类型未知：装载/检查/伙伴注册路径**报错**；训练家记录缺失：装载返回空、非调试兜底报错（含参数信息）、调试可新建。
- 版本号超出已有变体：视同缺失（走 §5.3）；空闲版本查找满 256 → -1。
- 伙伴在场时野外/雷达差异见 §6.4（细节引用后续包）。
- 徽章/功能标记写入者缺失（U 类）：不得把"读取消费者存在"当成"许可流程完整"。
