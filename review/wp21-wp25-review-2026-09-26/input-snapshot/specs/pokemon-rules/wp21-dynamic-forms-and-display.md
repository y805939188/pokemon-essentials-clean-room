## 1. 目的、范围与非目标

**目的**：把"同一物种为何、何时、以何种条件改变形态"完整登记，并描述形态提交的直接副作用链；同时登记展示属性（标记、缎带、华丽大赛属性）的读取/变更/边界。后续包（进化、战斗、UI、图鉴）引用本文的形态规则，而不是各自重新追踪处理器注册表。

**范围**（WP21 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP21-A：形态登记机制与**触发性目录**——注册/复制/条件注册语义，按触发族登记当前全部已注册物种及其条件、取值与回退。
2. WP21-B：形态**提交**的副作用链（缓存/能力/招式/登记/创建与战斗内提交），以及锁定形态与时间标记。
3. WP21-C：展示属性——标记（markings）、缎带（ribbons）、华丽大赛属性（contest stats）的读取/变更/边界。
4. F06-07 中属于 WP21 部分的状态更新。

**非目标**：

- 不定义 Mega/Primal 的触发资格与生命周期（WP22；本文只登记其注册接口与调用点归属）、Shadow 的形态相关字段（WP23）。
- 不定义战斗内形态变化的**资格/次数/时机**契约（WP39/WP40/WP42）；不定义形态变化后数值/特性/招式的战斗效果（战斗包）。
- 不定义具体处理器物种的"图鉴/剧情"语义以外的专有 UI（WP66/WP67）；不把"华丽大赛属性字段存在"扩成完整华丽大赛流程（U04 保留）。
- 不定义资源文件组织（WP15/编译层）；不重复 WP18 的字段清单与复制清单。
- 不运行游戏或任何参考脚本；不设计未来框架的回调/API。

## 2. 概念与术语

- **形态处理器注册表**：按物种登记的"触发函数名 → 处理器"映射（`001_FormHandlers.rb`）。触发函数名是参考侧接口名；**处理器行为按物种单独定义**——同名函数不保证行为相同（本包逐族核对）。
- **触发族**：注册表按调用时机划分的函数——创建时（`getFormOnCreation`、`getFormOnEggCreation`）、读取时（`getForm`）、提交时（`onSetForm`）、战斗开始/入场/离场（`getFormOnStartingBattle`、`getFormOnEnteringBattle`、`getFormOnLeavingBattle`、`changePokemonOnStartingBattle`、`changePokemonOnLeavingBattle`）、图像修饰（`alterBitmap`）、Primal 专用（`getPrimalForm`，WP22 接口）。
- **提交（submit）与只读（read）**：只读路径调用处理器**不写入**个体（或把结果与当前值比较后才写）；提交路径经形态设置入口写入并触发副作用链（§4）。处理器返回 **nil 表示"不改变"**；返回数值表示候选形态（是否写入由调用入口决定）。
- **锁定形态（forced_form）**：显式覆盖存储形态；优先于动态处理器结果；由外部写入、由特定流程解除（§3.4）。
- **时间标记（time_form_set）**：为"限时形态"记录设置时刻的整数时间戳；读取时按经过时长决定回退（§3.4）。
- **展示属性**：标记（6 个整数格）、缎带（标识列表）、华丽大赛属性（5 项数值 + 光泽度）——只描述记录与展示，不构成玩法完成度。

## 3. WP21-A：登记机制与触发族目录

### 3.1 注册与查找语义（`001_FormHandlers.rb:4–36`、`005_Event_Handlers.rb:210–290`）

- **注册表**（`MultipleForms`）以物种为键存储"函数名 → 处理器"映射；同一物种重复注册同一函数**覆盖**既有处理器；处理器可为过程（proc）或哈希（多函数一次注册）。
- **双键存储**：按"物种记录的规范标识"与"符号/字符串"两路存键、两路查找（查找顺序：先规范标识、后符号；均无则遍历**条件注册**）。这一双键语义使"符号与记录标识"都能命中同一处理器。
- **复制**（`copy(src, *dests)`）：把已注册物种的处理器映射**原样共享**给其它物种（同一处理器对象；源未注册时静默无操作）。当前注册表有 9 条复制语句，共 27 个物种共享处理器（跨物种的相同行为只写一次）。
- **条件注册**（`registerIf`）：机制存在——按条件过程决定命中的处理器；**当前注册表中的条件注册数为 0**（机制登记为可用但无用例）。
- **查询**：`hasFunction?(pkmn/物种, 函数名)` 返回是否已登记该函数；`getFunction(...)` 返回处理器或 nil；`call(函数名, 个体, 参数...)` 在无注册时返回 nil。
- **注册表规模**（本快照静态计数）：49 条具名注册 + 9 条复制语句（27 物种）＝ 76 个物种带有处理器；函数出现次数：`getForm`×15、`getFormOnCreation`×11、`getFormOnLeavingBattle`×19、`getFormOnStartingBattle`×3、`getFormOnEnteringBattle`×2、`onSetForm`×6、`changePokemonOnStartingBattle`×2、`changePokemonOnLeavingBattle`×2、`getPrimalForm`×2、`getFormOnEggCreation`×1、`alterBitmap`×1（均为注册语句内计数；复制项继承源函数）。

### 3.4 锁定形态与限时形态

- **`forced_form`**：读取优先于处理器结果（`form` 与 `form_simple` 都先取锁定值）；**已定位写入者仅调试工具**；**捕获成功时若物种带读取时处理器会解除锁定**（置空）——正常运行不设置锁定（U 类保留：搜索未命中 ≠ 不存在，插件/事件可能写入）。
- **`time_form_set`**：由两个物种的提交处理器维护（FURFROU 5 天、HOOPA 3 天）；读取处理器在"时间戳缺失或超过窗口"时返回回退形态（0），否则不改变。时间戳在形态 >0 时记录"当前时间"、在形态 0 时清空。窗口以**秒**计（5×86400 / 3×86400），时间来源 WP06。
- 边界：时间戳读取在处理器里做空值保护；系统时间回拨未验证（静态推导不覆盖）。

## 4. WP21-B：形态提交的副作用链

### 4.1 提交入口与顺序（引用 WP18 §3.4 的入口差异表）

| 入口 | 顺序与副作用 |
| --- | --- |
| `form=` | 写入形态 → 清特性缓存 → 调用 `onSetForm`（若有）→ 重算能力（WP19 §4.6）→ 玩家/图鉴存在时登记图鉴（**登记读取性别与普通异色**，WP18 §4.1） |
| `setForm` | 同上，但"写入形态"与"处理器+重算+登记"之间**让出一次**（供提示消息后再执行处理器） |
| `form_simple=` | 仅写入形态 + 重算；**不调用处理器、不清特性缓存、不登记图鉴** |
| 创建复检 | 创建末段（形态为 0 且启用复检）调用 `getFormOnCreation`；有返回值则走 `form=`（含图鉴登记）并（`withMoves` 时）重做招式初始化（WP18 §4.1） |

### 4.2 处理器内的招式改写（与 WP20 状态规则的衔接）

- 六条 `onSetForm` 注册中的四个（ROTOM/KYUREM/NECROZMA/CALYREX）会**改写招式列表**：直接改招标识（保留槽位与 PP 提升计数）、删除（压缩列表）或经"静默学习"接口添加（WP20 §5.1）；战斗中专属招改写（ZACIAN/ZAMAZENTA）在战斗开始/结束时各做一次反向改写。
- 边界（静态）：ROTOM 在"无形态且仅剩一个形招式、替换目标不存在"时**抛错**；CALYREX 保底"至少 1 招"（补固定基础招）；NECROZMA 超形态切换不改招式——这些均为处理器内含的保护分支，不能概括为所有处理器的共同行为。
- 消息：处理器内部可显示消息（忘记/学习提示、音效）；`setForm` 的中断点用于把"形态变化提示"插在处理器之前（先后顺序为：提示 → 处理器消息 → 重算/登记）。

### 4.3 战斗内触发（调用点与参数，登记）

| 时机 | 调用者 | 参数与语义 |
| --- | --- | --- |
| 战斗开始（双方队伍逐成员） | 战斗开始时 | (个体, 是否野生战)；返回值写入形态（提交） |
| 入场（派出参战） | 对战入场流程 | (个体, 是否野生)；同上 |
| 离场（换下/濒死） | 冲刺换下/濒死/捕获 | (个体, 战斗对象, 是否参战过, 是否终战)；终战标志与参战标志由调用者给出 |
| 战斗结束（逐成员含未参战） | 战斗收尾 | 同上，终战=true |
| 捕获成功 | 捕获流程 | 终战=true、参战=true；并**解除锁定形态**（物种带读取时处理器时） |

- 处理器用"终战/参战/濒死"标志决定是否回退形态——**同一处理器在不同时机可能返回不同结果**（如 BURMY 只在终战且参战过时按环境定形态）。
- 形态提交会重算能力（可能改写当前 HP，WP19 §4.6）；战斗内提交的数值修正与战斗刷新时序归战斗包（WP42）。
- Mega/Primal 的同伴调用（离场/濒死路径上的 `makeUnmega`/`makeUnprimal`）不在本包展开（WP22）。

## 5. WP21-C：展示属性

### 5.1 标记（markings）

- **存储**：6 个整数格（每格记录一个"变体号"；缺省视为 0/未选）。图形变体数**由界面资源决定**（资源高度/单格高度），不在数据层固定。
- **编辑（界面层消费者，静态核对）**：摘要界面与仓库界面各有同样的编辑网格——8 个位置（6 格 + 确定/取消）：确定键**循环递增**（模变体数）、动作键在"该格 >0"时**清零**；**确定提交编辑结果、取消放弃编辑**；绘制时把格值钳到"变体数−1"（超范围值显示为最后一格）。
- **兼容转换**：旧存档的位掩码（整数）在存档迁移中转为 6 个 0/1 格（仅当旧值为整数时；三个位置都转换：队伍、寄养槽、仓库；转换条目归 WP10/WP25 交界）。
- **复制/进化交界**：直接复制保留标记数组引用（WP18 §5.1）；进化场景的"复制展示个体"路径会**清空标记**（该路径同时清空昵称、球、持有物与全部缎带并治疗——属特殊复制流程，WP31 引用）。

### 5.2 缎带（ribbons）

- **存储**：标识列表（有序、去重）。
- **变更接口**（WP18 已登记字段，本包补行为细节）：
  - 给予：未知/未登记标识忽略；已拥有不重复添加。
  - 升级：按参数顺序寻找"已拥有的第一个匹配项"，把该项替换为**下一个参数**（下一个未登记/缺失则不改该处、继续尝试其它匹配项）；都不匹配时：首参有效且末参未拥有 → 给予首参并返回之；否则无操作（返回空）。
  - 移除：按标识删除（不存在 → 无效果）；清空全部。
- **展示**：摘要界面按**图标位置**分页显示（每页 12 个、可滚动偏移）——图标位置来自缎带数据（PBS schema：标识/名称/图标位置/描述/标记）；资源文件归 WP15。
- **数据侧**：缎带目录为 PBS 内容（编译往返；WP04 引用）；净化流程会给予固定缎带（WP23 引用）；调试可增减。

### 5.3 华丽大赛属性（contest stats）

- **存储**：5 项数值（帅气/美丽/可爱/聪明/强壮）+ 光泽度；创建为 0；复制按值保留。
- **本快照的行为边界**：核心脚本中**未定位**非调试的写入者或读取者（界面未读取、无制作/比赛流程）；字段存在**不构成**完整华丽大赛流程证据（U04 保留，检索未命中 ≠ 不存在）。
- 与标记/缎带的关系：三者相互独立；进化复制路径不清除华丽大赛属性（与标记/缎带不同）——按该路径实际代码登记。

## 6. 规则与不变量

1. 只有注册表内**有对应函数注册**的物种才会获得该行为；无注册时触发器返回"不改变"（nil），不报错。
2. 读取时处理器**只在入口决定写回时提交**（`form` 读取：结果与当前不同才经 `form=` 写回；战斗中/仓库中直接返回存储值，不触发处理器）。
3. 处理器返回 nil = 不改变；返回数值 = 候选形态（数值本身不做域校验，消费者按各自逻辑使用）。
4. 提交顺序固定：写入 → （特性缓存清理）→ 处理器 → 重算 → 图鉴登记（比较入口差异表）；`form_simple=` 是唯一不触发处理器/登记/特性清理的写入。
5. `onSetForm` 的招式改写只发生在已登记物种；改写保留槽位与 PP 提升计数（直接换招标识时）；删除会压缩列表；保护分支（抛错/保底补招）按物种登记，不是通用规则。
6. 战斗触发由调用者给出（是否野生/参战/终战）标志；同一处理器依赖这些标志决定回退。
7. 锁定形态优先于处理器；捕获会解除读取型物种的锁定。限时形态按"时间戳 + 窗口"回退；时间戳在提交时维护。
8. 标记为 6 个整数格（资源决定变体数）；缎带为去重列表；华丽大赛属性独立存储；三者不因一般形态提交改变（例外：进化复制路径清空标记与缎带——按该路径登记）。
9. 条件注册机制存在但当前无注册；复制共享处理器对象（跨物种同步变更——注册表是全局单例语义）。

## 7. 边界与失败

- 处理器抛错：ROTOM 的无替换招边界（§4.2）；抛错发生在提交过程中（形态已写入、后续重算/登记未必完成）——按静态推导登记，未运行验证中间状态。
- `copy` 时源未注册：静默无操作（不报错、目标无处理器）。
- 形态值不受域校验：处理器返回任意整数都会作为候选写回（不存在的形态号记录照常存储；资源/图鉴显示的后续行为归各自包，"记录存在 ≠ 资源存在"）。
- 标记格值超范围：绘制钳位；编辑循环对超范围旧值会按模运算修正（静态推导）。
- 缎带升级在"匹配到但下一参缺失"时跳过该匹配（不替换）、继续扫描；全部匹配都不适用时按首参给赠（§5.2）。
- 时间窗口以系统时间为准；时钟未设置/回拨的边界未验证。
- 华丽大赛属性无非调试入口（U04）；标记/缎带的完整历史流程依赖事件/Demo（U01）。

## 8. 默认行为与配置变体

- 无处理器物种：形态保持创建/存储值；创建期不调用形态查询。
- 资源变体（标记变体数、缎带图标位置）随图形资源与 PBS 数据而定（WP04/WP15 交界）。
- 季节/昼夜/环境判断依赖配置与时间系统（WP02/WP06 引用）；测试环境的时间差异会改变 DEERLING/ROCKRUFF/LYCANROC/SHAYMIN 的结果。
- 尚未验证组合：同一物种多条触发族并存的组合（如 KYUREM 的入场+离场+提交三层）跨战斗周期的最终形态——静态规则齐全，但组合时序未运行验证。
