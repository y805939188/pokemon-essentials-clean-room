# WP70 · Mining 行为规格

状态：**ReviewPending（具名静态范围，独立并行批次B，尚未外审／待统一合入登记）**。B-v1；D17／F17-06；参考 commit `8c5911e4a4b07b07e832e4bb0d5d8859e88b4a9b`。无游戏、生成器或输入运行证据。

## 1. 目的、分类、输入输出（M-A）

在13×10石壁中选择镐／锤敲击，完全揭露埋藏物并在墙毁、挖完或放弃时尝试领取。User Interface主分类，挖掘和耐久为可选通用玩法，物品身份为当前Pokémon内容，库存接收归Creature-RPG，随机／时间需求引用Generic Kernel。

公开入口无实参，无镐道具、钱、徽章、地图地形或背包空间准入守卫；工具是场景内两种模式，不从背包扣除。输入是固定候选表、随机源、方向／ACTION／USE／BACK及调试条件。输出是逐件入包与反馈，没有明确胜负／已领取物品列表返回合同；不要求外部事件另调用奖品入口才发放。

范围M-A～M-F：初始化／候选、摆放与随机、工具／层厚、揭露与终局、结算／失败。实际矿点事件、重复进入限制、宿主／媒体效果不在已证范围。

## 2. 候选、内容及去重（M-B）

埋藏物为身份、权重、宽高、占用形状；外接矩形定位其素材，形状空洞不属于物品。完整61项有序表（48种身份、权重总2370）及13项铁形状见 [数据附表](wp70-mining-data.md)。相同身份的不同方向／重复形状仍为独立抽样行，不能合并后遗失权重或形状。默认物品在PBS中均存在；REVIVE和MAXREVIVE属口袋2，其余46种口袋1。

去重不是只按候选行：HEARTSCALE可多份；其它同身份不重复；七种化石互斥，整墙最多一种一份：DOMEFOSSIL、HELIXFOSSIL、OLDAMBER、ROOTFOSSIL、SKULLFOSSIL、ARMORFOSSIL、CLAWFOSSIL。十六石板也整组互斥：INSECTPLATE、DREADPLATE、DRACOPLATE、ZAPPLATE、FISTPLATE、FLAMEPLATE、MEADOWPLATE、EARTHPLATE、ICICLEPLATE、TOXICPLATE、MINDPLATE、STONEPLATE、SKYPLATE、SPOOKYPLATE、IRONPLATE、SPLASHPLATE。

## 3. 初始化、摆放与随机次序（M-C）

先抽目标物品数2～4（等权），再逐次从权重累计区间选择候选行。单次抽取概率为行权重/2370；拒绝重复后重新抽取，未对剩余候选先归一化。通过去重的行固定后，反复均匀选一个使其外接矩形在13×10内的左上坐标，直到占用格不与已有物品占用格重叠，才增加一个物品。矩形可交叠，两个形状空洞可以互相嵌合。

**物品外层最多500次尝试，但位置内层无上限**。500次含成功与重复拒绝，达到即结束，故实际物品数可少于所抽2～4（默认合法内容首次会放入一项，极端重复拒绝可只剩1项）。若已经选定的形状在当前布局无可行位置，会停留在内部位置重试，不能靠外层500次退出；没有换形状／回滚／搜索可行位置兜底。未证明默认内容必然触达此不终止状态，登记精确条件而非声称每局会挂起。

然后抽目标铁块数4～6等权；每次等权选13种铁形状之一，再各均匀抽x、y坐标。铁占用不能与物品或已放铁占用相交；失败重新选形状和位置，总尝试最多500次，可能少于目标数；铁没有按身份去重。不会把铁放在物品占用上，但可在其矩形空洞。

最后按行从左到右为130格各抽一次0～99整数，生成覆盖层厚：2占10%、3占15%、4占35%、5占25%、6占15%。不因该格下方是铁／物品而改分布。显示裂纹计数0、光标零基位置58（x6,y4）、初始镐模式，并提示实际埋藏物数量。样本顺序为“物品目标→候选与位置重试→铁目标／形状／位置重试→130次层厚”，不是一次均匀抽最终壁面。最终矿物出现率和完整布局分布保持未决。

## 4. 工具、层厚与操作（M-D）

四方向可按住重复，但到边界停住，不回绕。ACTION在镐／锤之间切换；USE敲击；BACK询问放弃。工具动画期间暂不受理下一个操作或终局检查。镐中心削2、上下左右削1、四角0；锤中心及上下左右削2、四角削1。范围以当前格为中心3×3，越界部分忽略，层厚下限0。

耐久损耗先加：镐1、锤2；无论敲空层、铁或未揭物都计。唯一豁免为调试启用且按住CTRL，只免损耗，不免挖层效果。没有消耗玩家物品或生命。裂纹计数达到49触发坍塌，因此纯镐第49击、纯锤第25击（计50）；混合累计判定。

铁阻挡只看**敲击中心**：若中心下有铁且敲前层厚≤2，则仅中心削2，周围完全不动，给铁命中效果。若中心铁仍埋在3层或更多，按正常3×3处理；周边格有铁不使整个范围受阻。铁本身不被收集或破坏；已揭中心铁继续敲仍耗损并只处理中心。

部分露出物品可见但没有领奖资格。敲后检查全部未登记物品，只要其所有占用格的层厚均0，就进入完全揭露集合；矩形空洞仍盖石不影响成功。一次敲击可完全揭露多件。经过闪光展示后按物品放置顺序将其标为已揭，并把物品身份加入本局待领列表；不是当敲击中心露出一格就立刻发物品。标为已揭者之后不会再次加入待领列表。

## 5. 状态机、终局优先级与结算（M-E）

| 当前状态 | 条件／操作 | 变化与下一状态 |
| --- | --- | --- |
| 初始化 | 摆放和层厚完成 | 提示实际物品数量→自由操作 |
| 操作 | 方向／ACTION | 移动／换工具，库存不变 |
| 操作 | USE | 加损耗→挖层→动画→完整揭露检测／闪光→登记待领 |
| 动画结束 | 损耗≥49 | 先判坍塌，遮住壁面、提示→领取 |
| 动画结束且未坍塌 | 全物品已登记 | 挖完提示→领取 |
| 操作 | BACK且确认放弃 | 立即结束挖掘→领取；未揭物留在壁内 |
| 操作 | BACK但No／取消确认 | 回原场景；层厚／耐久／已揭记录保留 |
| 领取 | 待领列表按顺序逐件 | 各尝试添加1件、分别反馈→正常关闭场景 |

临界一击仍先挖层并登记完全揭露物品，再于动画结束检查坍塌。因此同一击使损耗达49且挖完最后物品时，显示坍塌（其检查优先），但新登记的物品仍参与领取。正常坍塌不会没收已完全揭露者；主动放弃也不没收。尚未完全揭露的物品不发放，部分可见不算。

领取调用背包的直接添加，每件数量1，没有事先全批容量预检。单件成功显示获得；失败显示无空间并继续后续件，没有寄存、退款或稍后重领记录。默认无限口袋＋每槽999使合法单件有一个新槽，不能把同物品某槽满999当成默认拒收；改变口袋为有限容量可逐件部分成功。单件数量1在正常整数槽条件下不会发生“加了半件还返回假”；**部分成功在整批层面**，与WP27的大数量单次部分添加区别。

同种HEARTSCALE分别作为待领项逐件添加；其它正常候选去重。没有在领取结束清空待领列表或打领取完成标记：正常流程仅调用一次；若外部直接重复调用同一场景领取入口，会重复尝试同一列表，不是幂等发奖。来源方法名只作审计，不建议未来接口。

## 6. 前置、异常与提交边界（M-F）

数据要求正权重／合法尺寸／完整0或1占用形状及可解析物品，固定表已经核对；场景未提供通用数据诊断。默认候选均适配13×10，但不保证任意已占布局仍可放。缺媒体可能在生成和建显示阶段失败；没有本地保证清理资源的异常出口。

完全揭露要等闪光结束才登记待领。若闪光中断，没有自动补登记或入包承诺；若领取已发前几件后中断，前几件留在背包，未发的不补。未知物品直接添加返回假后，失败提示又严格读取物品名，可能进一步报错；不把它当成可靠“无空间”正常路径。正常背包不足只损失该未接收件，继续其它项。此活动不增加专属挖矿统计，也不写彩票／代币统计。
