# WP70 · Lottery 行为规格

状态：**ReviewPending（具名静态范围，独立并行批次B，尚未外审／待统一合入登记）**。B-v1；D17／F17-05；参考 commit `8c5911e4a4b07b07e832e4bb0d5d8859e88b4a9b`。仅静态提取，不调用真实时钟、随机数或事件系统。

## 1. 目的、分类与边界

产生日期相关的五位号码，并在玩家队伍／储存个体中寻找拥有者公开号尾数匹配最多者。Pokémon Rules负责公开号和五位比较；集合读取归Creature-RPG，日期／随机输入归Generic Kernel，游戏变量接点归Engine / Overworld Integration。此入口没有可操作的小游戏界面，不设翻牌／投注／中奖演出状态机。

L-A～L-E范围为生成／变量写入、号码转换／匹配、集合顺序／并列、输出／失败、静态场景。NPC接待、何时每日刷新、兑奖奖品／次数、日期锁和领奖标记都没有事件证据；检索成功不等于已经发奖。

## 2. 号码生成、输入与状态变化（L-A）

生成入口接收目标变量号，默认1。读取宿主当前日／月／年，用数学量 d+32m+512y 作为临时全局随机种子，从0～65535均匀整数域取一次，随后无参重新播种，再把号码格式化为至少五位十进制字符串（合法生成域恰五位）写入目标变量。例：抽得7保存为`00007`；不是只返回数字。

同日期、同随机实现条件下生成相同号码；不同日期不保证不同。不是日期一变就自动更新：仅调用入口时写一次；旧变量保留至再次写入，保存生命周期引用既有持久化边界，不另建彩票独立状态。结束的无参重播种**不恢复调用前随机序列**，其它普通随机消费者可能受影响（WP06/U05）。无本地异常保证重播种：抽号前后异常须按阶段判断。

变量写入包装拒绝空号／负号；变量容器只写≤5000的编号，0可用；大于5000不存值，但包装在地图存在时仍请求刷新。即使目标号不合法而不写，播种与取号已经发生；无变量容器时跳过写入，也可请求地图刷新。生成入口没有稳定的“返回开奖号码”合同，调用者应读取指定变量。

## 3. 匹配规则与领域概念（L-B）

检索输入是外部中奖号码、名字变量号、位置变量号、匹配数变量号；后三者默认2／3／4。号码先转整数：数字字符串接受前导零，带数字前缀的字符串按其可解析前缀，非数字字符串按0；没有0～65535或五字符校验。比较只消费最低五个十进制位；负输入和无法转换的对象不属于正常号码域，可能有宿主转换／算术差异或直接失败，不补造输入拒绝UI。

每个个体用**其拥有者标识的低16位公开号**，不是个体随机身份、玩家当前公开号，也不比较拥有者名字／语言。公开号0～65535，以五位看待。自个位向高位连续比较，遇首个不相等立即停止；结果0～5。高位缺位等同0，所以公开号7与号码`00007`匹配5位。

正式数学规则：把公开号和输入整数的第j位记作dⱼ（j=0为个位），匹配数为从j=0起相等的最长前缀长度，上限5。中间不等后更高位的相等不再计入；外部号码112345与公开号12345可匹配5位。

## 4. 检索顺序、过滤与状态机（L-C）

| 阶段 | 范围与顺序 | 最佳记录更新 |
| --- | --- | --- |
| 初始化 | 名字空、位置0、匹配数0 | 尚无胜者 |
| 第一遍 | 玩家队伍实际数组，从首至尾 | 仅严格多于现最佳时更新；位置记1 |
| 第二遍 | 集合遍历从伪盒−1（队伍）开始，再盒0至末盒；每容器按索引升序／实际容量 | 跳空位；严格更优才更新；这里不使用所给盒号，位置一律记2 |
| 全部完成 | 写三结果变量 | 名字→位置→匹配数，随后返回末项匹配数 |

**没有过滤蛋、濒死、外来个体、不可存放标记或重复拥有者**。第一遍没有跳过空元素的保护，队伍含空洞时读取拥有者失败；第二遍跳过空位。第二遍使用的是含蛋的集合遍历，不是非蛋版本。

正常队伍≤容量且扫描期间稳定时，第二遍再次扫描队伍不会更优，因此已经胜出的队伍记录仍是位置1；不要把第二遍叫成“只扫描盒子”。若外部改变集合／读取有副作用，此稳定性前提不成立，第二遍更新即可能把队伍成员标成位置2。并列始终保留最先严格改进者：队伍先于盒子、队伍首项先于后项、低盒号／低格号先于后项；没有全匹配即早停。

按 [WP25](../creature-rpg/wp25-party-and-storage.md)，默认40盒、每盒初始30格；这里循环实际盒数和各盒实际长度，清空后0长盒不扫描。当前盒不享有优先权。若全局储存换为地区代理，遍历当前地区的那一套，并不扫描所有地区；地区解析可能懒建或失败。寄养／伙伴队伍不在默认遍历范围。

## 5. 输出、变量边界与失败（L-D）

正常结果是所选个体的显示名字（昵称存在用昵称，否则物种名，不返回拥有者名字）、位置1或2、匹配数1～5。全部0匹配或所有集合空时：名字空值、位置0、匹配0。变量容器读空值会返回0，因此“名字变量读到0”不等于存了字符串`0`。

三项使用直接变量赋值，**没有生成号码入口的地图刷新请求**。三个变量号可以相同，按名字→位置→匹配数覆盖，最后留下匹配数；没有防冲突校验。大于5000的赋值被容器忽略，0不拒绝；负号直接服从底层索引、可能从末端寻址或越界失败，未走生成包装的负号守卫。错误类型可在写入某项时失败，此前已写项保留。三个赋值不是原子提交。

普通正常返回值是最后匹配数（0～5），不是奖品、成员对象或“已领奖”标记。扫描阶段遇空队员／缺拥有者／储存失败会在三项写入前中止，旧结果变量仍可能残留，不能据其旧值兑奖。没有调用背包添加、金钱写入或彩票领奖统计递增。`lottery_prize_count`仅有声明／初始化和事件侧注释；实际发奖继续U01。
