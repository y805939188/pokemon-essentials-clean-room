## 1. 目的、范围与非目标

**目的**：固定主导航的用户流程合同——标题/载入/选项/暂停/PC/快捷菜单各项**何时可见、按什么条件出现或被拒绝、打开什么、确认与取消分别去哪里、哪些状态在何时写入（界面即时变化／游戏状态变化／持久写入三层分开）**。后续包据此判断"某菜单项何时出现、某取消会回到哪里、某设置在何时生效"，而不是各自重新追踪菜单代码。

**范围**（WP65 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP65-A：标题、启动选择与载入——开场/标题进入和离开，普通与调试启动差异；载入画面各命令的构建与可见条件；无存档/有效存档/无效存档的 UI 分流；删除入口、逐层确认/取消及结束去向；继续面板的展示数据与缺失值边界。
2. WP65-B：保存与退出交接——暂停菜单保存、退出前保存及已定位事件保存入口的可用门、确认次序、成功/拒绝/失败反馈与返回目标；紧急保存的 UI 交界。
3. WP65-C：选项与语言设置——各选项的默认值/合法值域/显示名/可见条件/读取/变更时点/即时预览/结束应用/退出后保留/实际落盘时点；载入画面打开与游戏中打开的差别；语言选择与设置持久化。
4. WP65-D：暂停主导航——菜单入口守卫、显示/隐藏、排序/过滤、游标与返回位置、菜单状态、子屏幕打开与回到父级或地图的差别；12 项注册（含 Safari/捕虫大会专用退出项）逐项条件与消费者。
5. WP65-E：PC 主导航——普通 PC（宝可梦中心 PC）与玩家 PC 的进入、命名、可见项、子菜单、取消与关闭；储存/玩家 PC/净化室/名人堂注册入口的条件及返回；物品储存与信箱导航。
6. WP65-F：野外快捷菜单（F16-02 包含项）——ReadyMenu 的输入触发、两类候选构造、排序、导航、游标保存、确认、失败后继续与取消/关闭。

**非目标**：

- 不定义存档读取/写入/迁移/备份/重建机制（WP09/WP10 主规格，本包只登记 UI 分流与调用点）。
- 不定义图鉴、队伍、背包、地图、电话、储存、商店、邮件、神秘礼物的内容规则（WP62/WP66-A/WP66-C/WP63/WP66-B/WP29/WP64 等主规格；本包只登记菜单入口与返回）。
- 不定义 Safari/捕虫大会会话结算（WP53）、名人堂内容/演出（WP67-B）、净化领域（WP23）、隐藏招式许可与登记规则（WP59/WP27）、道具效果与消耗（WP28）。
- 不运行游戏/UI、不操作真实存档、不播放音频、不调整宿主界面、不编译/转换、不设计未来 UI 架构或把参考类组织当作未来模块。

## 2. 概念与术语

- **注册项（menu registration）**：经统一注册机制登记的菜单条目（键、显示名、排序值、可见条件、效果）；**可见集合 = 按排序值排序后逐项评估可见条件**（排序值缺省时按登记次序）；显示名可为动态计算（如玩家名、储存系统创建者名）。注册数量 ≠ 任一时刻的可见数量（条件逐项判定）。
- **三层状态变化（必须分开）**：**界面即时变化**（窗口皮肤、文字速度预览、音量暂停/恢复等，仅当前画面可观察）；**游戏状态变化**（`$PokemonSystem` 各选项字段、临时标记、菜单游标）；**持久写入**（存档落盘——正常经保存流程（WP09）；例外直写见 §5.4 语言路径与 §4.2 紧急保存备份）。**"离开选项画面"本身不是落盘**。
- **返回语义分层**：**子屏幕取消**（回到打开它的菜单循环、菜单重新显示）与**退出整个流程**（关闭菜单场景回到地图/标题/结束进程）不同义；效果项的布尔返回决定菜单循环是继续还是关闭。
- **游标记忆**：暂停菜单的当前下标（`menu_last_choice`）与快捷菜单的三元游标（招式侧/道具侧/侧别，背包持久字段）在流程结束后保留；**PC 各层游标分开**：宝可梦中心 PC 主循环**每次以默认下标 0 显示**（不把上次选择写回默认位）；玩家 PC 子菜单与储存系统子菜单**在各自循环内**保留当前下标（§7.1/§7.2，R02 修订）。
- **可见条件 vs 执行资格**：菜单项可见只由条件判定；选中后的执行仍可能失败（如保存被拒、道具使用失败、队伍满、空储存），二者不能互相推出。
- 影响域编号 Dxx 见 module-map；证据状态五档定义见总览第 7 节。

## 3. WP65-A：标题、启动选择与载入

### 3.1 开场与标题（`016_UI/001_Non-interactive UI/001_UI_SplashesAndTitleScreen.rb` 全文；`999_Main/999_Main.rb` 全文）

- **启动链**：主入口先载入默认消息（存在核心消息文件时）；调试且非打包且配置开启时先询问是否编译（含完整编译标记）；随后插件管理器加载、编译器主流程、游戏初始化与系统装配，再进入标题入口。**装配期的语言处理**（`001_StartGame.rb:21–34`）：无存档时初始化启动值、有存档时读入启动值；应用画面缩放；**语言配置非空时**——无存档且语言候选 ≥2 则先弹出语言选择，再按 `LANGUAGES[当前索引][1]` 载入消息文件（WP08 引用）。
- **标题入口分流**（`pbCallTitle`）：**调试构建 → 直接进入载入画面**（跳过开场与标题）；普通构建 → 开场序列。
- **开场序列**：逐张播放登记的开场图（默认 2 张），每张约 2 秒或按**确认动作**（USE／C 别名，WP17 引用）提前；放完后进入标题画面：标题背景＋"按任意键"闪烁图（约 40 tick 一个闪烁周期），播放标题 BGM（系统数据登记曲）。
- **标题画面离开**：按**确认动作**（USE／C 别名，WP17 引用）→ 播放一只随机物种的叫声、停顿后淡出（BGM 1 秒淡出）→ 进入载入画面（§3.2）。**隐藏组合键（下＋BACK＋CTRL）→ 进入删除画面**（§3.3）。
- **主循环**：标题入口返回的场景对象持续 `main` 直到为 nil；异常（Hangup 类）→ 紧急保存（§4.2）后原样抛出。

### 3.2 载入画面（`016_UI/013_UI_Load.rb` 全文）

- **存档分流（打开画面前已发生）**：构造载入对象时——存在存档文件则**读取并校验**（WP09 引用）：有效 → 用该数据；无效且存在 `.bak` → 提示"存档损坏，将载入备份"并**递归**改用备份；无效且无备份 → **删除提示流程**（见下）后按无存档 `{}` 继续。不存在存档文件 → 按无存档处理。**更早的读取异常不强行接到备份 UI**（读取层行为归 WP09/WP10，本包不承诺所有异常都到达载入画面）。
- **调试跳过门**：`$DEBUG` 且非打包运行且 `SKIP_CONTINUE_SCREEN` 配置为真（**默认 false**）→ **不显示载入菜单**：无存档 → 直接开新游戏；有存档 → 直接按已读数据载入（WP09 引用）。
- **命令构建与可见条件**（按序追加，每项记录其下标）：
  1. **继续**（Continue）：存档非空才出现；为真时作为首个大面板（展示见下）。
  2. **神秘礼物**：存档非空且玩家 `mystery_gift_unlocked` 为真才出现（WP64 引用）。
  3. **新游戏**：总出现。
  4. **选项**：总出现。
  5. **语言**：`LANGUAGES` 候选数 ≥2 才出现（**默认配置该数组为空——默认不出现**；WP08 引用）。
  6. **调试**：`$DEBUG` 才出现。
  7. **退出游戏**：总出现。
- **继续面板展示数据**（仅继续项的大面板）：徽章数、图鉴已见数、游戏时间（≥1 小时显示"h m"，否则只显示分钟）、玩家名（按性别着色：男蓝/女红/其它默认色）、当前地图名（`\PN` 占位替换为玩家名）、玩家行走图（**图集文件缺失时报错**——"Player character {id}'s walking charset was not found"）与队伍成员图标（按 2 列排布）。非继续项为窄面板、只显示命令名。
- **选择循环**：面板随下标切换选中色并可滚动；**只接受确认键**（返回当前下标；本循环没有取消键分支）。退出游戏以外选项先播决定音。
- **各命令去向**：
  - **继续** → 关闭画面 → 按已读数据载入（WP09）→ 进入游戏。
  - **新游戏** → 关闭画面 → 开新游戏（WP09/WP24 引用）。
  - **神秘礼物** → 淡入淡出执行下载流程（`pbDownloadMysteryGift`，WP64 引用），**随后回到载入菜单循环**（不离开画面）。
  - **选项** → 淡入淡出打开选项画面（**以"载入画面打开"标记**，§5.2），随后回到载入菜单循环。
  - **语言** → 关闭画面 → 语言选择 → 按新索引载入消息文件；**若有继续项（存档非空）：把当前系统选项对象整体写回存档副本并直接序列化落盘存档文件**（审计定位 `Data/Scripts/016_UI/013_UI_Load.rb:338–340`）——**写入的不只语言字段：此前在载入选项画面中已修改的其它选项值也随该对象一并落盘**（R04 修订；直写存档、不经正常保存流程——WP08/WP09 已登记边界，本包引用不另写第二套规则）；无继续项时不写档 → 回到标题入口（普通构建回开场，调试构建回载入画面）。
  - **调试** → 淡入淡出打开调试菜单，随后回到载入菜单循环。
  - **退出游戏** → 关闭菜单音 → 关闭画面 → **场景置 nil（进程结束）**。
  - 其它（不可达分支）→ 蜂鸣。

### 3.3 删除画面（标题隐藏组合键进入）

- **无存档**：提示"No save file was found."→ 结束 → 回标题入口。
- **有存档**：两次"严肃确认"（`pbConfirmMessageSerious`）——第一次"Delete all saved data?"→ 提示删除不可恢复 → 第二次"Delete the saved data anyway?"→ 提示"正在删除，请勿断电"后执行删除；**任一次拒绝即中止删除**（画面结束回标题）。
- **删除结果反馈**：删除成功 → "The saved data was deleted."；删除调用抛出系统错误（`SystemCallError`）→ "All saved data could not be deleted."（部分失败只按该消息区分，不重试）。
- 结束后一律回标题入口。
- **无效存档的删除提示流程**（§3.2 分流的最末端）：先提示存档损坏或不兼容 → 严肃确认"删除存档并重新开始？"——**拒绝：直接 `exit` 结束进程**；**同意：执行删除并重置系统对象（新建 Game_System 与 PokemonSystem），随后按无存档 `{}` 进入载入菜单**。

## 4. WP65-B：保存与退出交接

### 4.1 共享保存流程（`016_UI/014_UI_Save.rb` 全文；暂停保存/退出前保存/事件调用共用）

- **信息窗**：当前地图名、玩家名（按性别着色）、游戏时间（格式同载入面板）、徽章数；**持有图鉴时**追加图鉴"已拥有/已见"（无图鉴不显示该行）。
- **确认次序**：先普通确认"Would you like to save the game?"——**拒绝 → 播放选择音、返回 false**（无副作用）。
- **异存档覆盖警告**：存在存档文件且**本次为新游戏后尚未保存过**（`begun_new_game` 为真）→ 三连警告（WARNING／已存在不同存档／保存将完全失去其冒险内容）→ 严肃确认"确认覆盖？"——**拒绝 → 播放选择音、返回 false**；同意 → 清 `begun_new_game` 标记后继续。
- **执行**：播放选择音 → 调持久层保存（WP09 引用）——**成功**："{玩家名} saved the game."（含音效与停留）→ 返回 true；**失败**："Save failed."→ 返回 false。**取消不自动代表回滚**：确认前/覆盖确认前发生的更改不回滚；保存失败已发生的更改也不在本层回滚（持久层语义归 WP09）。

### 4.2 紧急保存（`014_UI_Save.rb:1–24`；WP10 的 UI 交界，不另造恢复算法）

- 换出当前场景 → 提示"脚本运行过久，游戏将重启"→ **无玩家对象直接返回**；存在存档文件时**先按字节把现存档复制为 `.bak`**；随后调持久层保存——成功：依次提示"已保存"与"之前的存档已备份"；失败："Save failed."。最后恢复原场景。

### 4.3 暂停菜单保存与退出前保存（注册项效果，§6.2 表内引用）

- **暂停保存**：隐藏菜单 → 执行共享保存流程——**返回 true → 关闭暂停菜单场景**（回到地图）；**返回 false（拒绝或失败）→ 刷新并重新显示菜单**（循环继续）。
- **退出前保存**：隐藏菜单 → 普通确认"Are you sure you want to quit the game?"——**拒绝 → 刷新并重新显示菜单**；**同意 → 执行共享保存流程（其返回值不被检查）→ 关闭暂停菜单场景 → 场景置 nil（进程结束）**。**保存被拒绝或失败不阻止退出**——同意退出后无论保存结果如何都结束进程（按行为如实登记）。
- **事件调用**（脚本直接调 `pbSaveScreen`，如地图事件）：只取回布尔值，无暂停菜单的隐藏/重显包装；返回目标由调用者决定（事件材料 U01，未逐点核对）。**事件保存命令**（command_352，`004_Interpreter_Commands.rb:1141–1145`，WP13 命令矩阵引用）：打开同一保存画面但**命令总返回 true 继续事件**——保存画面的布尔结果（含用户拒绝）被忽略，与脚本直接调用取布尔值分列（C02 修订；入口可见门与内部保存规则仍分开）。

## 5. WP65-C：选项与语言设置

### 5.1 选项框架（`016_UI/015_UI_Options.rb` 全文；机制引用 WP05）

- **选项对象三类**（注册时的 `type` 决定）：
  - **枚举（EnumOption）**：有序候选名列表；**左右移动到两端即止（不循环）**——首项再左移保持首项、末项再右移保持末项。
  - **编号（NumberOption）**：整数域 `[最低, 最高]`；**两端循环**——超过最高回最低、低于最低回最高；显示为 "Type 当前/总数"。
  - **滑杆（SliderOption）**：`[最低, 最高, 步长]`；按步长增减、**到端即止（不循环）**。
- **可见集合**：按排序值排序后逐项评估条件（`condition`），符合条件才进入选项窗口；**选项窗口末行固定为"Close"**（总行数 = 可见选项数 + 1）。
- **选中与说明**：下标移动时触发该选项的 `on_select`（若有）并刷新底部说明文本（可为静态文本或动态计算的描述）。
- **即时应用**：每次左右改变值（`value_changed`）**立即调用该选项的 `set` 并传入新值与场景**——**没有"取消后还原"**：BACK 在任何行都只是关闭画面（USE 只在 "Close" 行关闭），已作出的修改保留。
- **结束应用**：关闭画面时**对所有可见选项再逐个 `set` 一次**（确保全部应用，含只读进入未改动的项），随后关闭并刷新地图。

### 5.3 语言设置（WP08 引用为主，本包只登记导航交界）

- **语言不进入选项注册表**：语言选择在**系统装配**（无存档且候选 ≥2 时随启动链弹出，§3.1）与**载入画面"语言"命令**（候选 ≥2 才可见，§3.2）两处出现；游戏中没有选项内的语言项。

## 6. WP65-D：暂停主导航

### 6.1 入口守卫与菜单循环（`016_UI/001_UI_PauseMenu.rb` 全文；`002_Scene_Map.rb:103–111`）

- **入口（请求生产与消费分开，R01 修订）**：**常规地图更新**（`002_Scene_Map.rb:165–229` 的 `update`）在更新循环与标题切换/转场处理后——**消息窗显示中提前返回**（本次不生产也不消费请求）；解释器运行或强制移动中**不产生新输入请求**。其余按动作分派：**USE（确认动作）→ 互动请求**；**ACTION → 暂停菜单请求，但仅在未禁用菜单（`menu_disabled` 为假）且玩家未移动时**（`menu_disabled` 只门 ACTION，不门其它动作）；**SPECIAL → 快捷菜单请求，仅要求玩家未移动**（不经 menu_disabled 门）；F9 → 调试请求（$DEBUG）。**请求消费**（同在常规更新内）：玩家静止时按**暂停菜单 → 调试 → 快捷菜单 → 互动**的优先级依次消费一个请求。**微更新（`miniupdate`，同文件 121–134）不含输入检测与请求分派**——已有快捷请求只经历微更新时**不被消费**（标记保留到常规更新且玩家静止）；阻止新输入的门不能无条件套给已有请求。菜单调用打开时：`in_menu = true`（地图层暂停事件更新等，WP13 引用）、玩家整姿、地图更新一次后打开暂停菜单；**无玩家对象时**（调试下提示"玩家训练家未定义"）直接返回、不开菜单。菜单结束后 `in_menu = false`。
- **命令列表构建**：每次打开时按排序值对注册项排序、逐项评估条件，得到本次可见集合（名称可为动态计算）。**打开时游标取 `menu_last_choice`（上次选择下标）**。
- **选择循环**：BACK 或 ACTION 键 → 返回 −1（播放关闭菜单音、结束场景）；USE → 返回当前下标并**写回 `menu_last_choice`**。执行对应效果项——**效果返回 true → 关闭暂停菜单场景（退出整个菜单）**；**效果返回 false → 回到选择循环**（菜单保持，列表不变）。
- **子屏幕与返回**：效果项打开的子屏幕（图鉴/队伍/背包/Pokégear/地图/训练家卡/选项/调试）**取消或正常返回后回到暂停菜单循环**（菜单重新显示/刷新）；**子屏幕产生特定结果**（选择隐藏招式、选择使用道具、选择飞行目的地）时效果项改为结束菜单并转交结果（见逐项）。

## 8. WP65-F：野外快捷菜单（ReadyMenu；`016_UI/016_UI_ReadyMenu.rb` 全文）

### 8.1 触发与候选构造（`pbUseKeyItem`；`002_Scene_Map.rb:213`）

- **触发**：地图输入触发的快捷调用标记（`ready_menu_calling`）在**常规地图更新中被消费**（与 §6.1 同一合同）：消息窗显示中本次更新提前返回（不消费）；玩家静止时按**暂停菜单 → 调试 → 快捷菜单 → 互动**的优先级依次消费一个请求——轮到快捷请求时清标记、玩家整姿后调用 `pbUseKeyItem`。**微更新（`miniupdate`）不含输入检测与请求分派**——已有快捷请求只经历微更新时**不被消费**、标记保留到满足条件的常规更新（R01 修订）。
- **候选两类**：
  - **隐藏招式侧**：固定 16 个招式标识（CUT、DEFOG、DIG、DIVE、FLASH、FLY、HEADBUTT、ROCKCLIMB、ROCKSMASH、SECRETPOWER、STRENGTH、SURF、SWEETSCENT、TELEPORT、WATERFALL、WHIRLPOOL）——遍历队伍：**非蛋、已学会该招、且通过场地使用资格**（`pbCanUseHiddenMove?`，WP59 引用）的成员各贡献一条 `[招式, 队伍下标]`。
  - **登记道具侧**：背包登记列表（`registered_items`，WP27 引用）中**当前仍持有**的道具（`$bag.has?`）逐条入选。**登记后不再持有的道具不出现**（候选资格 ≠ 执行成功）。
- **两类皆空 → 不开菜单**：仅提示"An item in the Bag can be registered to this key for instant use."。否则：`in_menu = true`、地图更新一次后打开快捷菜单。

### 8.2 显示、导航与游标

- **显示**：两侧按钮列——招式侧靠左（带成员图标）、道具侧靠右（带道具图标与数量：**重要道具不显示数量**；数量 >99 显示 ">99"，否则 "xN"）；两列各按**名称字母序**排列；选中侧按钮高亮并外凸。
- **初始游标**：取背包持久字段 `ready_menu_selection`（三元：招式侧下标、道具侧下标、当前侧别；**默认 [0, 0, 1]**，旧格式存档经迁移填充，WP10 引用）；**下标按当前列表长度夹限**（越界收到末项）；**当前侧别的列表为空时自动换到另一侧**。
- **导航**：LEFT/RIGHT 在两侧间切换（**仅当目标侧列表非空**）；BACK → 播放关闭菜单音、返回 −1（取消）；USE → 返回 `[侧别, 下标]`。**游标在菜单结束后保留在背包字段**（随存档持久，WP09/WP27 引用）。

### 8.3 确认、执行与返回

- **选择招式**：
  - **FLY 特例**：隐藏菜单打开区域地图的飞行选择画面——**确认目的地 → 记录目的地、`in_menu=false`、执行该成员的隐藏招式并关闭整个快捷菜单**；**取消 → 重新显示快捷菜单**（循环继续）。
  - **其它招式**：先确认使用该隐藏招式（`pbConfirmUseHiddenMove`，WP59 引用）——**确认 → `in_menu=false`、执行并关闭整个快捷菜单**；**拒绝 → 重新显示快捷菜单**。
- **选择道具**：隐藏菜单 → 触发该道具的"使用前确认"（`ItemHandlers.triggerConfirmUseInField`，WP28 引用）——**确认通过 → `in_menu=false` 并执行关键道具使用：使用包装返回真 → 关闭整个快捷菜单；包装返回假（无使用处理器，或使用处理器正常返回假）→ `in_menu` 复原、重新显示快捷菜单**；**确认被拒 → 直接重新显示快捷菜单**（`in_menu` 未变）。**返回结果与是否消耗是两条独立事实**（R03 修订）：菜单的关闭/重显只按使用包装的布尔结果——**成功但不被消耗的关键道具（如 COINCASE：显示代币数后使用返回真、数量不变）同样关闭菜单**；消耗移除只在"使用返回真且为消耗品"时发生（WP28 引用），数量不变不等于执行失败。
- **结束**：快捷菜单场景关闭后 `in_menu=false`（由调用处复位）。**候选资格与执行成功分开**：成员资格/持有只是入选条件，执行仍可按领域规则失败（WP59/WP28 引用），失败返回后菜单状态按上表分别处理。

### 8.4 游标持久性与设置边界

- 快捷菜单游标写入背包持久字段（默认 [0,0,1]），随存档保存（WP09 引用）、经旧格式迁移填充（WP10 引用）。**本包不登记该字段的完整写入者目录**（只确认菜单自身读写与迁移点；其它写入者未穷尽，标注未决）。

## 9. 默认行为与配置变体

- **基线默认**：普通构建有开场序列、标题画面与完整载入菜单；选项默认值按 §5.2 表；暂停/PC/快捷菜单条件按 §6.2/§7.1/§8.1；语言命令默认不出现（`LANGUAGES` 默认空）；调试跳过门默认关闭（`SKIP_CONTINUE_SCREEN=false`）。
- **支持但未默认启用**：`SKIP_CONTINUE_SCREEN`（调试构建下跳过载入菜单直进游戏）；`LANGUAGES` 多语言候选（≥2 时出现装配期选择与载入语言命令）；`NEW_CAPTURE_CAN_REPLACE_PARTY_MEMBER`（默认世代 8 真 → Send to Boxes 可见；旧世代配置下该选项不可见）；跑鞋/图鉴/Pokégear/TOWNMAP/储存创建者见面/净化室见面/名人堂记录等**内容驱动可见条件**（各写入者多为事件，材料缺口 U01）。
- **配置/数据关联**：`SPEECH_WINDOWSKINS`（默认 21 项）与 `MENU_WINDOWSKINS`（默认 28 项）的编号域；`SCREEN_SCALE`（默认 1.0 → Screen Size 默认 M）；`SAFARI_STEPS`（Safari 信息行内容，WP53 引用）；`storage_creator` 全局元数据（储存系统命名）；标题 BGM 与系统音效数据（WP15 引用）。
- **未验证组合**：真实资源（标题/背景/图集/音效）的存在与播放结果（U01/E11 保留）；宿主窗口缩放行为（Screen Size 应用后的实际窗口，未验证）；地图事件对 PC/快捷菜单的实际调用点（U01）；异常清理与真实事件可达性（具名保留）。
- 参考快照行为、官方版本预期、未来目标分开标记；本包只记录第一类。

## 10. 边界、失败与未知

- **存档无效分流**：有 `.bak` → 提示后递归用备份；无备份 → 删除提示流程（拒绝则 `exit` 结束进程；同意则删除并重置系统对象后按无存档继续）。更早读取异常不强行接到备份 UI（WP09/WP10 层，本包不承诺全异常可达载入画面）。
- **删除部分失败**：仅按"All saved data could not be deleted."消息区分，不重试、不回滚。
- **保存失败**：返回 false；暂停保存失败/拒绝 → 回菜单；退出前保存的失败/拒绝**不阻止退出**（§4.3，如实登记）。
- **继续面板图集缺失**：玩家行走图文件不存在时报错（具名消息），不静默回退。
- **储存入口门**：队伍满拒取出、最后一只拒存入（§7.1）；PC 物品储存空拒取出/丢弃、信箱空拒开（§7.2）。
- **快捷菜单候选空**：两类皆空只提示、不开菜单（§8.1）；当前侧别为空自动换侧（§8.2）。
- **未证的异常清理**：子屏幕异常退出（如事件中断）时的资源/状态清理未逐项验证；真实事件可达性（菜单各入口的地图事件调用者）具名保留（U01）。
