# WP69 · Voltorb Flip 行为规格

状态：**ReviewPending（具名静态范围，独立并行批次B，尚未外审／待统一合入登记）**。B-v1；D17／F17-04；固定 commit `8c5911e4a4b07b07e832e4bb0d5d8859e88b4a9b`。无运行、抽样或蒙特卡洛证据。

## 1. 目的、分类与输入输出（V-A）

5×5隐藏棋盘中通过行列提示寻找2／3倍率格，避开雷（Voltorb，值0），可中途领取累积得分。Pokémon Rules 为本玩法的分类，输入／标记／退出归 User Interface，代币归 Creature-RPG，普通随机／计时引用 Generic Kernel。

入口无可选级别或难度实参；每次新会话从等级1开始，最高8。包装要求持有COINCASE且代币不等于上限；**零代币允许开始**，没有下注和入场费，盒不消耗。场景直接入口没有相同持物守卫；每次新棋盘先生成／建显示，然后在余额≥上限时提示并设置退出。余额夹限／类型校验引用WP24。输出为代币与coins_won写入，未定义可供事件兑奖的胜负结果码；级别只在本会话推进，离开后不保存级别。

## 2. 数据、生成与有效性（V-B）

格值域0、1、2、3；25格，5行5列。每一级的有序候选行、雷／二／三／一数量和两类阈值见 [候选附表](wp69-voltorb-layouts.md)：一级5项，其余各10项，总75项。重复内容计数但不同限制的行仍独立等权候选。

每次尝试先从该级候选行均匀选1项；按其0／2／3个数及补足的一格构成多重集合，洗牌分配到行优先的25格。再统计行／列雷数。一个倍率格若其行**或**其列没有雷，就称免费倍率格。将这些格分别累计到所在行、所在列，并计总数。

接受条件为：总免费数 < 该行G，且每行免费数 < F、每列免费数 < F。阈值是严格上界；不是“至多F/G”。拒绝后重新抽候选行并重新洗牌。最多尝试1000次，**1000次全部不合格时仍返回最后一次棋盘**，没有报失败、降级或再生成；所以免费格阈值不是无条件终局不变量，格值数量仍来自最后候选行。

单次候选行的均匀性不推出最终行均匀；不同候选接受率、重试条件、洗牌宿主行为和最终失败回退都会改变分布。最终棋盘／收益概率未解析，未运行生成器。

## 3. 提示、移动、标记与翻牌（V-C）

每行及每列显示全部格值之和和雷数；和是加法（雷贡献0），不是倍率积，也不随揭牌扣掉已知格。显示持久代币、当前可取奖额和等级。新棋盘所有格隐藏、奖额0、光标左上、标记空、普通模式。

四方向使用单次触发，越边循环到对边；不承诺按住重复移动。ACTION切换普通／标记模式。标记模式USE仅切换当前坐标的一种标记（无1/2/3多标记系统），不翻牌、不改得分。检查“未揭格”只守卫标记音效，实际标记增删并未受此条件限制：已揭格也能存标记，可能被牌图遮挡。普通模式翻有标记的格仍可执行，标记不提供保护；已揭格USE不重复计分。

普通模式USE在未揭格上先播放翻牌，再把该格记为已揭。安全格若当前奖额0，设为格值；否则只有2／3会乘该值，1维持原值。所有倍率格均已揭开即自动过关，不需翻完1，也不需标出所有雷。单盘完全收益是2的二格数次幂乘3的三格数次幂，默认候选的最大固定乘积3456；这是数据上界，不是期望收益。

## 4. 状态机、结算与上限（V-D）

| 当前状态 | 条件／输入 | 转移与提交 |
| --- | --- | --- |
| 新会话 | 初始化等级1 | 生成棋盘→构造显示→余额上限检查→操作 |
| 操作 | 安全格且仍有未揭倍率 | 更新奖额，留本局 |
| 操作 | 揭完所有倍率 | 显示过关／所得→加持久代币→按实际增量加coins_won→奖额清0→揭示全盘并等USE/BACK→收牌→等级+1（最多8）→新棋盘 |
| 操作 | 踩雷 | 记雷已揭→爆炸及0收益提示→揭全盘并等USE/BACK→收牌→失败级别分支（§5） |
| 操作（任一模式） | BACK，拒绝退出确认 | 回同棋盘，保留分数／已揭／标记 |
| 操作 | BACK，确认退出且奖额>0 | 先所得提示→立即加币和统计→奖额清0→揭盘等待与收牌→设置退出 |
| 操作 | BACK，确认退出且奖额0 | 揭盘等待与收牌→退出；不写收益 |
| 新棋盘 | 余额≥上限 | 提示／夹到上限并设退出；不提供继续赚币 |
| 正常退出 | 主循环读到退出标记 | 关闭表现与显示对象 |

得分不是每翻一格立即到账；可见所得提示使用原奖额，实际余额经上限夹限。coins_won只记实际正增量；踩雷失去未领取奖额，不扣此前代币，也不累计coins_lost。与 Slot Machine 的会话净额统计不同。

获奖先写余额再记统计，随后还有需要输入的揭盘过程。该过程异常或等待并不撤回已发奖励。场景开始即达到上限时也先生成新盘；主循环一次仍先调用输入处理再检查退出标记，不能声明设退出后绝无额外一帧输入消费（尤其直接调用／胜局触顶路径）。没有自动每日限次或外部日期规则。

## 5. 踩雷与等级异常（V-E）

等级1踩雷：在揭盘和收牌完成后跳过降级分支，奖额归零，重置提示，销毁旧显示并在等级1生成新盘；余额和收益统计不变。

**等级2～8踩雷存在固定参考失败边界**：计算已揭的正值格数量后，夹限参数次序给出“下界=当前等级、上界=1”。下界大于上界，在标准运行库夹限语义下会抛参数错误；全脚本检索未见自定义夹限覆盖。故不能把它写成有效的“按翻开数量降至1～当前级”。异常发生在雷已揭、爆炸／0收益提示以及全盘展示和收牌之后，发生在奖额清0、旧场景销毁与下一盘之前；本次未领分仍留临时变量，持久余额未因踩雷变化。没有本地保证执行的清理或重试。宿主异常呈现未经运行；此处是静态语言语义推导，不是修复建议或正常规则。

## 6. 失败、取消及变体边界

默认候选和正常等级保证有倍率格；直接改数据成无倍率的棋盘可能在任一次USE后的过关检查立即触发过关，未提供内容校验。入场无盒拒绝，上限拒绝，余额0可玩。普通安全格得分0→1后继续揭1仍1，退出可领取1。标记不改变概率或实际格值。

取消确认按 [WP17](../ui/wp17-messages-windows-input.md) 的No处理；揭示整盘的继续步骤USE或BACK均接受。资源错误、统计状态缺失、倒置夹限等异常不保证关闭对象；已支付的持久增量不会因此回滚。等级变化只支持默认递增和源码中的失败分支，没有对外自选“难度”。
