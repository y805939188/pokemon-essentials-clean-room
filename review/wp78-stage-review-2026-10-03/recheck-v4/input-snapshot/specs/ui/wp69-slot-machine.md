# WP69 · Slot Machine 行为规格

状态：**ReviewPending（具名静态范围，独立并行批次B，尚未外审／待统一合入登记）**。B-v1；D17／F17-03；参考 commit `8c5911e4a4b07b07e832e4bb0d5d8859e88b4a9b`。静态提取，无游戏运行或随机模拟。

## 1. 目的、分类、概念与入口（S-A）

三转轮活动允许玩家投入1～3代币、依次停止转轮、按有效线获得代币或重玩。User Interface 是主分类，资源持有归 Creature-RPG，时间／随机需求引用 Generic Kernel；转轮规则是可选通用玩法，不是常规战斗规则。

概念分为玩家持久代币、场景信用额、当前下注、待付奖额、三轮的循环位置与旋转／停止状态、重玩标记。本稿 S-A～S-F 覆盖准入、转轮及随机输入、奖项、状态机、支付与失败。

公开入口输入难度，默认1；0为简单、2为困难，其它值未被拒绝且走常速／一次滑移样本。包装入口依次检查：背包无COINCASE→仅提示机器；有盒但代币0→拒绝；代币恰等上限→拒绝；其余进入。盒不消耗。场景直接入口不共享包装的物品守卫，不应把包装条件当底层普遍检查。默认代币上限99999，引用 [WP24](../creature-rpg/wp24-player-trainers-partners.md)。COINCASE为物品数据中的重要物品，使用道具自身只显示余额，不自动开始本活动。

输出是余额／统计写入及界面流程；未定义胜／负结果码，不把包装最终表达式的偶然返回值当奖励合同。没有另外的外部奖品发放入口。

## 2. 转轮、停止与随机次序（S-B）

三轮各22个循环位置，实际有序内容见 [转轮附表](wp69-slot-reels.md)。顶部索引i对应中部i−1、底部i−2，按22循环。初次创建从左至右各均匀选择一次起始索引；之后每次开转从当前位置继续，不重新抽取完整结果。

正常速度640像素/秒；简单难度除以1.5；困难不改变速度。时间按运行时长推进，符号边界判定依赖实际图像高度；槽位显示裁片高48。资源缺失下不能声称实际转动帧率或每秒符号数已验证。

USE请求停止当前仍旋转的最左轮；只有它真正停止后，下次USE才轮到右邻。处于等待停止而仍旋转时重复USE会再次抽样覆盖滑移量，不能描述为三次确认一定停完。每次请求先从12项滑移表抽一个值（0六项、1三项、2两项、3一项）；简单再抽一次取较小，困难再抽一次取较大。重玩仍消费这些样本，之后将滑移强制改0。

| 单次停止请求滑移量 | 0 | 1 | 2 | 3 |
| --- | ---: | ---: | ---: | ---: |
| 默认／其它难度 | 6/12 | 3/12 | 2/12 | 1/12 |
| 简单（两次较小） | 108/144 | 27/144 | 8/144 | 1/144 |
| 困难（两次较大） | 36/144 | 45/144 | 40/144 | 23/144 |
| 重玩强制结果 | 1 | 0 | 0 | 0 |

停止在后续符号边界执行；若边界到来时滑移为0即停止，否则按本次跨过的边界数减少滑移，下一个边界再检。因输入时刻、更新间隔、资源高度和重复停止请求共同作用，不能把表中数值写成独立最终中奖概率或精确多转N格的无条件保证。

## 3. 有效线、奖项与优先级（S-C）

投入1枚只判中心横线；2枚再判顶部、底部横线；3枚再判左上到右下、左下到右上两条对角线。按这个顺序分别判断并累加；下注扩展线数，不把同线奖值再乘下注数。以下均按从左到右三图案：

| 条件 | 每线代币 | 其它结果 |
| --- | ---: | --- |
| 三小磁怪／三大舌贝 | 8 | 普通中奖 |
| 三皮卡丘／三可达鸭 | 15 | 普通中奖 |
| 三个7但颜色混合（红红蓝／红蓝红／蓝红红／蓝蓝红／蓝红蓝／红蓝蓝） | 90 | 级别1大奖表现 |
| 三红7／三蓝7 | 300 | 级别2大奖表现 |
| 三重玩图案 | 0 | 设置下轮重玩 |
| 其余组合且前两格樱桃 | 4 | 第三格不限 |
| 其余组合且仅要求左格樱桃、第二格不是樱桃 | 2 | 第三格不限 |
| 其余 | 0 | 本线未中 |

精确三连条件先判，樱桃是后备分支；不是任意位置一樱桃都中奖。右轮无樱桃，故三樱桃是识别规则容许但默认转轮不生成的输入。多线可同时支付、同时设置重玩；表现等级取各线最高大奖级别，不额外加代币。重玩即使本局只押1枚，也使下轮按3枚激活全部5线。

## 4. 状态机、取消与重玩（S-D）

进入把玩家余额复制为场景信用额，下注0。所有下注和支付先只改场景值。

| 状态 | 输入／条件 | 下一状态／写入 |
| --- | --- | --- |
| 等待投入 | DOWN且下注<3且信用>0 | 下注+1、信用−1，点亮相应线 |
| 等待投入 | 已押3，或下注>0且信用0，或USE且下注>0 | 开转三轮 |
| 等待投入 | 重玩标记 | 下注强制3，不按此赋值扣3枚，自动开转 |
| 等待投入 | BACK且下注0且未先命中开转条件 | 退出会话 |
| 等待投入 | BACK但已下注 | 无取消／退款，仍等待或满足开转条件 |
| 旋转 | USE | 请求停止仍在旋转的最左轮；BACK无出口 |
| 三轮停止 | 结算 | 先清旧重玩标记，按有效线累计新奖额／重玩 |
| 中奖表现 | 等待3秒 | 支付奖额，之后等0.5秒，下注清0 |
| 未中奖且无重玩 | 等待2秒 | 下注清0，回等待投入 |
| 会话外层检查 | 场景信用达到上限 | 提示→退出提交 |

投入分支优先于重玩分支：免费重玩开始前若该帧DOWN有效，仍会先从信用扣1；可持续抢先投入至3再由后续帧开转。不能断言重玩期间绝无额外扣币。无投入时USE不开始；全局余额正常不在每次下注更新。

## 5. 支付时点、统计和参考异常（S-E）

每条线奖值求和写入待付额，计分控件只限制最大值为代币上限。支付逐次从待付减1、给场景信用加1；USE可一次性转移剩余奖额；信用达到上限也会立即清掉剩余奖额，超额不保留。获奖提示／动画不代表已修改玩家持久余额。

支付节拍的名义值为每秒20枚，但参考“上次已支付时点”变量未被正确推进，正常非负运行时下每次支付循环更新都会通过节拍不等检查；实际是每更新最多1枚，或USE／满额一次清算。本稿不将注释中的20枚/秒作为实测保证。

耗尽检查实际读取**玩家持久余额是否0**，不是场景信用。正常以正余额进入且无外部改写时，把场景信用输到0后不会自动触发“Game over”；等待投入时既不能投入也不能无下注开转，但可BACK退出。若仍有重玩则可开转。场景信用满额检查与此不同，确实读取场景值。

会话正常离开时读取玩家旧余额，写入场景信用（经WP24夹限），再仅按此次净差增加coins_won或coins_lost；不是每次中奖／下注分别累计。例如进入100，途中输3又赢8，最终105，仅coins_won+5。若其它更新源在会话期间改全局余额，最终覆盖仍使用场景信用、净差比较使用离场时全局值；未提供隔离／合并保证。

## 6. 前置、失败与异常退出（S-F）

有盒且零代币不能由公开入口进入；余额上限不可继续。相关资源、玩家／背包／统计状态及输入时钟为正常前提。非法难度没有专门校验，除0/2外走默认分支。没有暂停保存本次下注／转轮的合同。

场景异常没有本地保证提交余额与统计的收尾：离场提交前错误会跳过尚未回写的场景账；余额写入与统计更新之间错误可能已写余额但未写统计。外层淡出清理不能代替财务回滚。媒介缺失、宿主时间／输入及外部状态变化保持未决。
