## 1. 目的、范围与非目标

**目的**：把"一个个体或蛋如何进入玩家队伍/盒子"的全部已定位入口与顺序固定下来，并定义脚本交换（以一个指定生物替换队伍成员）的提交语义；供捕获接收（WP38）、礼物（WP64）、寄养/孵化（WP33–WP35）、图鉴（WP62）引用。

**范围**（WP26 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP26-A：获得入口目录与对照——普通/静默、仅入队/可送箱、外来赠送、蛋入口；输入（物种或已有个体）、守卫、写入顺序、消息、返回值与副作用。
2. WP26-B：脚本交换——队伍成员被指定生物替换的完整流程（创建/传参分支、来源与方式写入、图鉴写入、交易进化交界、替换时机）。
3. WP26-C：交界登记——捕获存储、礼物领取、竞赛、净化间、寄养蛋、调试复制等消费者与上述入口的关系。
4. F10-05、F07-06 中属于 WP26 部分的状态更新。

**非目标**：

- 不定义捕获判定与强制入队/转送选择策略（WP38）；不定义球的消耗与战斗合法性（WP38/WP40）。
- 不定义买卖/价格/BP 兑换（WP29）、礼物下载与发放流程细节（WP64）、孵化链（WP35）、寄养会话与遗传细则（WP33/WP34）。
- 不定义进化条件与提交（WP31/WP32；本包只登记"交换后检查进化并对收到个体提交"的交界事实）。
- 不定义图鉴对象的完整规则（WP62；本包只登记调用序列与条件）。
- 不定义队伍/仓库界面长流程（WP66）与训练家资源（WP24）。
- 不运行游戏或参考脚本；不设计未来框架的获得/交换 API。

## 2. 概念与术语

- **获得入口**：把个体或蛋交给玩家的顶层工具。共同维度：**静默/交互**（是否显示消息与命名询问）、**目标策略**（仅入队 / 队伍优先、满队送盒）、**个体来源**（传入物种->新建 / 传入已有个体->直接使用）、**拥有者**（玩家 / 外来）。
- **"盒子全满"（boxes full）**：队伍满 **且** 储存全满（`pbBoxesFull? = party_full? && storage.full?`）——引用 WP25 §3.1/§7。
- **存储管道**：交互获得共用同一管道"消息/图鉴写入 ->（可选命名）-> 存储"；存储前记录最初招式（WP20 §5.2），满队时写入当前盒并可在全盒扫描后切换当前盒（WP25 §4.1）。
- **外来赠送**：拥有者被构造为"外来"的获得入口（来源记录与外来判定引用 WP18 §6.4）。
- **脚本交换**：以传入生物**替换**指定队伍成员的流程；替换发生在演出与（可选）交易进化之后；旧成员不进入盒子（被丢弃）。
- **交换方式标记**：来源记录中的"方式"字段取"交换"值（引用 WP18 §6.3）。
- **命名询问**：受系统选项控制（非 0 时跳过）；文本输入边界引用 WP17（键盘/光标两种场景、空文本与下限）。

## 3. WP26-A：获得入口目录（全文静态核对）

### 3.1 入口对照表

> 输入列"物种/个体"表示两者皆可；"新建"=传入非个体时按参数创建（等级默认见签名）。

| 入口 | 签名默认 | 目标策略 | 守卫（顺序） | 消息/命名 | 返回值 |
| --- | --- | --- | --- | --- | --- |
| 普通赠送 | `pbAddPokemon(pkmn, level=1, see_form=true)` | 队伍优先；满队送盒 | ①空输入 ②盒子全满（双段消息） | 获得消息＋可选命名＋（送盒时）盒消息 | false/true |
| 静默赠送 | `pbAddPokemonSilent(pkmn, level=1, see_form=true)` | 队伍优先；满队送盒 | ①空输入或盒子全满（合并判断，无消息） | 无 | false/true |
| 仅入队 | `pbAddToParty(pkmn, level=1, see_form=true)` | 仅队伍 | ①空输入或满队 | 获得消息＋可选命名 | false/true |
| 仅入队·静默 | `pbAddToPartySilent(pkmn, level=nil, see_form=true)` | 仅队伍 | ①空输入或满队 | 无 | false/true |
| 外来赠送 | `pbAddForeignPokemon(pkmn, level=1, owner_name=nil, nickname=nil, owner_gender=0, see_form=true)` | 仅队伍 | ①空输入或满队 | 获得消息（带/不带赠与人） | false/true |
| 蛋入口 | `pbGenerateEgg(pkmn, text="")`（别名 `pbAddEgg`/`pbGenEgg`） | 仅队伍 | ①空输入或满队 | 无 | false/true |
| 脚本交换 | `pbStartTrade(pokemonIndex, newpoke, nickname, trainerName, trainerGender=0)` | 替换队伍指定成员 | **无统一空输入守卫、无满队/全满守卫**；空/非法新物种走物种查询失败->报错；越界索引无守卫（后续阶段失败） | 交换演出与多段消息 | 成功末尾**返回收到个体**（队伍赋值结果）；失败为报错 |

### 3.2 各入口的写入顺序（静态核对，逐入口）

**普通赠送（`pbAddPokemon`）**——顺序：

1. 空输入 -> `false`。
2. 盒子全满 -> 两段消息（"没有空间/盒子已满"）-> `false`（**不**创建、**不**写图鉴）。
3. 传入非个体时按 `(物种, level)` 新建。
4. 获得消息（"玩家名 获得了 物种名！"，含获得音效与等待标记）。
5. 记忆"此前是否已拥有" -> 图鉴写入：标记已见 -> 标记已拥有 -> 按 `see_form` 登记个体（登记读取性别/普通异色，WP18 §4.1）。
6. 条件图鉴展示：**本物种此前不拥有** 且 `see_form` 且 拥有图鉴且 该物种在图鉴解锁范围内 且 配置开启"更频繁提示新物种" -> 额外消息＋记录"最近见过"＋打开图鉴信息画面。
7. 命名并存储（内部管道，见 §3.3）：**再次**检查盒子全满 -> 图鉴"已见/已拥有"再次写入（重复写）-> 可选命名 -> 存储。
8. 返回 `true`。

**静默赠送（`pbAddPokemonSilent`）**——无任何消息/命名/图鉴展示画面；顺序：空输入或盒子全满 -> `false`；新建（若需要）；图鉴已见->已拥有->按 `see_form` 登记；记录最初招式；满队 -> 写入储存（**忽略返回的盒号、不提示**），否则追加队伍；返回 `true`。

**仅入队（`pbAddToParty`）**——满队或空输入 -> `false`；其余与普通赠送相同的消息/图鉴/条件展示/命名存储管道（**初始有位且交互期间相关容量状态未变时**实际入队；若等待期间队伍变满而盒有位，共用存储可送盒——见 §10.2 条件反例 C）；返回 `true`。

**仅入队·静默（`pbAddToPartySilent`）**——满队或空输入 -> `false`；新建（若需要）；**顺序与其它入口不同**：按 `see_form` 登记个体 -> 标记已拥有（**无显式"已见"写入**）；记录最初招式；追加队伍；返回 `true`（该差异按字面登记；登记接口的完整语义归 WP62）。**注意**：该入口的等级参数默认缺省（空）——传入物种且未显式给出等级时，空值进入创建入口的等级写入比较并失败（静态失败路径，见 §7）。

**外来赠送（`pbAddForeignPokemon`）**——满队或空输入 -> `false`；新建（若需要）；拥有者 <- 外来构造（赠与人名字或空串、性别参数默认 0；WP18 §6.1/§6.2）；**传入昵称非空时**按上限 10 截断后替换；重算能力；获得消息（有赠与人名 -> "从 X 处收到"，否则"收到"）；图鉴写入与条件展示同上；**直接调用存储工具**（不经"命名并存储"管道；**初始有位且交互期间相关容量状态未变时**实际入队，否则共用存储可送盒）；返回 `true`。**外来赠送不询问昵称**；参数昵称为空/nil 时**不写入名称**——已有个体保留原昵称、新建且未命名者回退物种名（WP18 §6.5）。

**蛋入口（`pbGenerateEgg`）**——满队或空输入 -> `false`；传入非个体时按"蛋等级"配置新建；写入：昵称=固定蛋名、孵化步数=物种孵化步数、来源文本=传入文本；重算；追加队伍；返回 `true`。**不写图鉴、不记录最初招式、无命名询问**。

**脚本交换（`pbStartTrade`）**——见 §4。

### 3.3 内部工具语义（交互管道）

- **命名并存储**：先检查盒子全满（双段消息后直接返回，**不**存储、**不**命名）；再写图鉴"已见/已拥有"；再询问命名；再存储。用于**普通赠送/仅入队交互入口与竞赛收尾**（外来赠送不经该管道——它直接调用存储工具，见 §3.2）。
- **命名询问**：系统选项非 0 时整体跳过；否则先确认"是否命名"——**拒绝确认**则不进入输入、不赋值（已有个体保留原昵称；新建者保持无名=显示物种名）；同意 -> 名称输入（最小长度 0、上限 10、初值空）；**输入返回空文本**（键盘 ESC / 空确认；光标场景直接确认）-> 昵称被清除（显示回退物种名，WP18 §6.5）。
- **存储**：再次检查盒子全满（相同双段消息后返回）；记录最初招式；满队 -> 写入储存（返回盒号）并提示"已送往盒子'X'"（盒名为当前写入盒）；否则追加队伍。入盒沿用储存层语义：**"存入治疗"配置开且调用储存接收时的当前盒号非负时先治疗并保留进化准备标记**，然后才寻找位置（引用 WP25 §4.1/§6；默认世代 8 关闭）；**队伍有位直接追加不触发该治疗**。盒子全满时该工具提示后**无值返回**（不存储）——**个体引用仍在调用方手中**，不等于对象被销毁或所有引用失效；有未先检查的调用者（§5 交界）。
- **盒子全满判定**：见 §2；在普通赠送路径中共出现 **3 次**（入口 1 次＋管道 2 次）。各次检查之间隔着获得消息、图鉴展示与命名输入——这些等待期间地图/事件可继续更新（消息等待会驱动场景微型更新，事件与并行公共事件随之更新；见 §11），**因此"后续检查不可达"不成立**：中途状态变化时内层复检可拒绝，而此前图鉴/昵称等写入不回滚、外层仍返回 `true`（条件静态反例见 §10.2）。

## 4. WP26-B：脚本交换（F07-06）

### 4.1 输入与准备（静态核对）

1. 统计"交换次数"计数 **+1**（**在一切校验之前**；统计目录 WP06）。**该入口没有统一的空输入 `false` 守卫**：空/非法新物种走第 3 步的物种查询失败（报错）。
2. 取出队伍 `[pokemonIndex]` 成员（**无索引合法性守卫**；越界得到空值，错误推迟到后续使用点）。
3. 分支（**传入已有个体 vs 物种**）：
   - 传入已有个体：拥有者 <- 外来构造（对方训练家名字/性别）；**不重置招式**（`resetmoves=false`）。
   - 传入物种：物种查询失败 -> **报错**（此时第 1 步已发生）；成功 -> 新建个体，**等级=旧成员等级**；拥有者 <- 外来构造。
4. 昵称 <- 传入昵称（**直接赋值**；空/nil 时按 WP18 §6.5 显示物种名；不截断）。
5. 来源"获得方式" <- 交换值（WP18 §6.3）；物种路径先重置招式（按等级重建，WP20 §5.1）；**记录最初招式**。

### 4.2 演出与提交顺序（静态核对）

1. 交换画面开场（双方个体、训练家名）。
2. 画面内先写图鉴：**无条件**"登记收到个体"调用 + 标记已拥有（**该入口无 `see_form` 参数**；**无显式"已见"写入**；完整语义归 WP62）；随后多段消息与动画（球、叫声、ID/OT 显示）。
3. 条件图鉴展示：收到物种此前不拥有 且 拥有图鉴且 解锁范围内 且 配置开启 -> 额外消息＋"最近见过"＋图鉴画面（同 §3.2 条件模式）。
4. 画面收尾：**交易进化检查**（收到个体，参照旧成员）-> 若有可进化目标：进化场景提交（完整条件/流程归 WP31/WP32）。
5. 演出全部结束后：队伍 `[pokemonIndex]` **被替换**为收到个体；**旧成员被丢弃**（不进入盒子、不提示去向）。

### 4.3 交换的边界语义

- **无取消出口**：交换画面只有演出与确认消息；无"取消交换"分支（输入等待期间除消息推进外无可选动作）。
- **无回滚**：统计、图鉴写入、消息与（可选）进化都发生在队伍替换之前；若流程在替换前中断，队伍保持旧成员而前述副作用已发生。替换本身是最后一步。
- **不要求队伍有空位**：替换不改变队伍长度；无满队/全满守卫。
- **选择器（脚本侧，两层区分）**：另有"选择要交换的队伍成员"工具。**内层选择界面**：按目标物种过滤（只允许该物种）、并强制排除蛋、Shadow 与"不可交换"标记的成员；不符合者标注"不可选"并拒绝选择（提示一句）；**界面层返回所选索引或 -1（取消）**。**脚本包装**（按变量号调用）：把结果写入两个**事件变量**——成功 -> 索引与所选名字；取消 -> -1 与空名字；**包装自身不返回该索引**（不能把包装当"返回所选索引"的接口）。**核心脚本中未定位调用者**——该工具与交换入口的调用者为事件/演示脚本（材料缺失，U01）。

## 6. 规则与不变量

1. 获得入口按目标策略分三类（**"满队失败"均指初始检查**）：**可送盒**（普通/静默赠送：初始满队且盒有位 -> 送盒；盒子全满 -> 失败）；**仅队伍**（仅入队/仅入队·静默/外来赠送/蛋：**初始**满队 -> 失败，不送盒；其中**交互类（仅入队/外来赠送）在初始有位时后续仍走共用存储**——等待期间状态变化可致送盒；**静默仅入队与蛋为直接追加**，不经共用存储）；**替换**（脚本交换：不查容量、替换式提交）。没有入口在初始队伍有空位时立即送盒。
2. "盒子全满"=队伍满且储存全满；其双段消息（"没有空间"＋"盒子已满"）**仅交互类入口显示**（普通赠送及其管道）；静默入口无消息直接 `false`。命中时（就本次检查而言）**不写图鉴、不记录招式、不消耗/创建个体**。
3. 静默入口**完全无消息、无命名、无图鉴展示画面**；交互回调式的图鉴展示（额外消息＋画面）只在满足"首次拥有＋解锁＋配置"时出现。
4. 存储路径统一记录**最初招式**（WP20 §5.2）；蛋入口不记录；**入盒沿用储存层语义**（"存入治疗"配置开且**调用储存接收时的当前盒号**非负时先治疗＋保留进化准备，然后才寻找位置，引用 WP25 §4.1；默认世代 8 关）。
5. 命名询问受系统选项控制；确认"是否命名"被拒绝时不赋值（已有个体保留原昵称）；同意后输入空文本=清除昵称。外来赠送**不询问**：参数昵称非空才按上限截断替换，空/nil 参数不写入（已有个体保留原昵称）。交换把参数昵称直接写入个体。
6. 获得入口的图鉴写入发生在**命名与存储之前**（普通赠送的"已见/已拥有"因此先于昵称；消息中的名字为物种名，送盒消息中的名字为命名后的名字）。
7. 脚本交换是**替换**而非接收：不查满队/全满、**无统一空输入守卫**；旧成员被丢弃；替换提交（队伍数组写入，其值即**成功返回值**＝收到个体）发生在演出、图鉴与进化之后；此前副作用无回滚。
8. 交换的物种路径以**旧成员等级**为基准新建；实例路径不重建（招式重置关闭、等级等按传入个体原样）。
9. 传入非个体时的默认等级：普通/静默/仅入队/外来赠送为 1；仅入队·静默的等级参数默认缺省（传入物种且未显式给出等级 -> 静态失败，见 §7）；蛋为"蛋等级"配置。
10. 空输入返回：除脚本交换外，公开入口对空输入返回 `false`；脚本交换对空/非法新物种报错。失败返回不等于"未发生任何事"——见 §4.3/§7 的各阶段失败。

## 7. 边界与失败

- 空输入：普通/静默/仅入队/仅入队·静默/外来赠送/蛋入口返回 `false`；**脚本交换无该守卫**（空/非法新物种 -> 报错，统计已 +1）。
- 盒子全满·**入口初检**：普通赠送双段消息后 `false`（**未创建、未写图鉴**）；静默赠送**无消息**直接 `false`。
- 盒子全满·**内层复检**（交互期间状态变化后）：内层工具提示后**无值返回**（不是把 `false` 交给外层）——外层普通赠送**仍返回 `true`**，较早的图鉴/昵称等写入不回滚（条件反例见 §10.2）。
- 满队·**初始检查**：仅队伍类（仅入队类/外来赠送/蛋）`false`（即使盒子有位也不送盒）；该失败前无图鉴/招式/命名副作用（守卫在最前）。交互类后续仍走共用存储（可送盒）；静默仅入队与蛋为直接追加。
- 仅入队·静默·缺省等级：传入物种且未显式给等级——空值进入创建入口的等级写入比较并失败（创建中段报错；此前无图鉴/入队副作用）。
- 命名：系统选项非 0 -> 跳过询问（保留现有名字/无名字）；**拒绝"是否命名"确认 -> 保留原名**；同意后输入取消/空 -> 清除昵称。
- 外来赠送昵称：参数空/nil -> 不写入（已有个体保留原昵称；新建未命名者显示物种名）；非空 -> 按上限 10 截断替换。
- 交换·非法/空物种：报错（统计已 +1）；交换·越界索引：无守卫（后续阶段才失败；队伍未被替换）。
- 交换·演出后阶段失败（如进化中断）：图鉴与统计已写、队伍仍为旧成员（替换未执行）。
- 后续容量复检（条件可达）：三次检查之间可因等待（消息/命名输入）期间的地图与事件更新而变化；命中时内层拒绝、此前图鉴/昵称写入不回滚、外层仍返回 `true`；仅入队交互入口初检非满也不保证最终仍直接入队（条件静态反例见 §10.2；事件可达性属 U01/运行未决）。
- 存储工具的拒绝分支：调用者未预先检查盒子全满时（净化间/调试复制等交界），该工具提示后**不存储**而流程继续（按各交界登记）；被拒接收的个体引用仍在调用方手中，不等于对象被销毁或所有引用失效。
- 图鉴条件展示：缺少图鉴、未解锁该物种、非首次拥有或配置关闭 -> 跳过（不影响其余写入）。
