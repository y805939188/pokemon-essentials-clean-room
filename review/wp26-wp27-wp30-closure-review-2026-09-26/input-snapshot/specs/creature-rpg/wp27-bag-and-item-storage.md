## 1. 目的、范围与非目标

**目的**：定义玩家物品的容器语义（口袋组织、槽位/数量、容量与增删替换）、PC 物品储存的存取与丢弃，以及"快捷登记"（登记列表、野外快捷使用与过滤显示）；供道具使用/效果（WP28）、买卖（WP29）、树果（WP60）、邮件（WP20 交界）等引用。

**范围**（WP27 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP27-A：背包容器——口袋、槽位对、数量查询、容量判断、添加/删除/替换/清空与游标状态。
2. WP27-B：PC 物品储存——固定容量、初始化种子、存取/丢弃数量流程与失败。
3. WP27-C：快捷登记——登记/取消、登记图标、快捷菜单的收集/过滤与野外使用入口。
4. WP27-D：交界登记——接收/商店/树果/邮件/队伍与仓库界面的过滤选择、游戏角子、三重三卡助手、存档迁移。
5. F08-01、F08-02 中属于 WP27 部分的状态更新。

**非目标**：

- 不定义物品的用途、效果、消耗与资格（WP28）；不定义买卖/价格/BP 兑换流程（WP29）；不定义球与捕获判定（WP38）、隐藏招式许可（WP59 引用）。
- 不定义持有物在个体上的状态（WP20）与邮件完整流程（WP20 交界）；不定义树果种植规则（WP60）；不定义三重三卡玩法（WP68）。
- 不定义界面动画与全交互细节（WP66）；不运行游戏或参考脚本；不设计未来框架的物品容器 API。

## 2. 概念与术语

- **口袋**：物品按内容数据字段归入的固定槽组。当前快照 8 个口袋（名称固定列表）；内部容器索引 1–8，另有占位索引 0。
- **槽位对**：`[物品标识, 数量]`；一个口袋内**同一标识可占多个槽位**（助手模块按槽位累加/逐槽分配）；槽位内数量上限=配置值（当前 999）。
- **口袋容量**：每口袋的最大槽位数；配置值 `-1` 表示无限（当前全部口袋为无限）。无限时容量判断以"当前长度+1"为上界参与分配计算。
- **自动排序**：按口袋配置，添加成功后按物品目录定义顺序重排该口袋。
- **助手模块**：三种容器（背包口袋、PC 物品储存、三重三卡）共用的增/删/查/预检算法；**预检是纯函数**（不改状态），**执行可部分写入**（见 §3.3）。
- **PC 物品储存**：固定 999 槽、每槽 999 的独立容器；创建时以"初始物品"元数据播种；由 PC 界面懒创建。
- **快捷登记**：把有"野外使用处理器"的物品登记进登记列表（去重）；快捷菜单显示**仍持有**的登记项＋可用隐藏招式；野外按键触发。
- **游标状态**：上次查看的口袋（默认 1）与每口袋上次选中索引（默认 0）；非法口袋号报错。

## 3. WP27-A：背包容器（`008_PokemonBag.rb` 前段全读）

### 3.1 查询与容量

| 操作 | 语义 | 边界 |
| --- | --- | --- |
| 数量 `quantity(item)` | 未知物品 -> 0；否则按物品所在口袋的槽位累加 | 累加可跨多个同标识槽位 |
| 持有 `has?(item, qty=1)`（别名"可删除"） | 数量 ≥ 要求数量（**纯比较**） | 未知物品 -> 0：默认 qty=1 时 false；**qty=0 或负数时比较可为真**（默认/正常值前提；见 §7） |
| 可添加 `can_add?(item, qty=1)` | 未知物品 -> false；否则以"口袋上限（无限=`长度+1`）＋每槽上限"做**纯分配预检** | 预检不修改任何槽位 |
| 游标查询/设置 | 仅接受 1–口袋数；越界**报错**；设置值仅检查上限（≤当前长度），**无下界检查（负值可被保存）**；查询返回 `min(上次索引, 长度)` 原值 | 默认/正常索引下为空时为 0；空口袋＋负索引等非常规输入不保证 0 |

### 3.2 变更

| 操作 | 语义 | 失败/边界 |
| --- | --- | --- |
| `add(item, qty=1)` | 逐槽分配（填满已有同标识槽、再占空槽）；成功后按口袋配置自动排序 | 未知物品 -> false；**空间不足时返回 false 但此前已写入的槽位保留（部分添加）** |
| `add_all` | 先纯预检再添加（全有全无） | 预检失败 -> false 且无写入 |
| `remove(item, qty=1)` | 从**全部**槽位依次扣减，归零槽位删除并压缩数组 | 未知物品 -> false；**数量不足时返回 false 但已扣减部分（部分删除）** |
| `remove_all` | 先预检再删除（全有全无） | 预检失败 -> false 且无删除 |
| `replace_item(old, new)` | **只处理旧物品所在口袋**：把该口袋内所有旧标识槽位的标识改为新标识（原地改标识，不合并、不移动、不校验新物品口袋） | 任一物品未知 -> false；无可替换 -> false |
| `clear` | 清空全部口袋＋重置**每口袋游标**（各为 0） | 上次查看的口袋与登记列表**保留**（reset 与 clear 不等价） |
| `register/unregister/registered?` | 见 §5 | 未知物品：register 无操作、registered? 为 false、unregister 无操作 |

### 3.3 助手模块语义（贪心分配，可部分执行）

- 数量查询：遍历累加同标识槽位。
- 预检（纯函数）：按槽位序模拟分配——空槽可吃满一格（每槽上限），已有同标识未满槽补足到上限；全部分配完成 -> true；槽位耗尽仍不足 -> false。负数量**报错**；数量 0 -> true（无操作）。
- 添加（可部分执行）：与预检相同的分配顺序，但**写入槽位**；若槽位耗尽仍未分配完 -> 返回 false（此前的写入保留）。
- 删除（可部分执行）：按序从同标识槽位扣减、归零即删、最后压缩数组；在扣尽前达到数量 -> true；物品总量不足 -> false（已扣部分保留）。
- 结论：**只有"预检＋执行"成对使用时才获得全有全无语义**；单独调用执行接口可能留下部分结果。**在本包列举的对照入口中，配对预检仅存在于 PC 存取与礼物物品路径**（不推出其它商店/消费者不存在预检）；收到物品/地面拾取/奖品为直接添加（消费者分列见 §7），不能把 helper 机制写成所有入口的保证。

## 4. WP27-B：PC 物品储存与界面流转

### 4.1 PC 物品储存（固定容量容器）

- 常量：999 槽 × 每槽 999（与背包的"无限口袋"不同，为硬上限）。
- 初始化：按元数据"初始物品"逐项添加（仅登记存在的物品）；**创建时机为懒创建**——首次打开 PC 物品界面（取出/丢弃/存入）时若无储存对象则创建。
- 操作：数量/可添加/添加/删除与助手模块同语义（部分执行同）；**物品查询使用严格取用**（未知标识报错，与背包的宽松查询不同）；槽位读取/长度/空判断/清空；另有两个"未被使用"的槽位读取接口（按行为登记）。
- 空态提示：取出与丢弃入口在储存为空时提示"没有物品"。

### 4.2 存取与丢弃（数量与守卫）

| 界面动作 | 数量选择 | 执行顺序与守卫 | 消息/失败 |
| --- | --- | --- | --- |
| 取出（储存 -> 背包） | 数量 >1 且**非重要物品**时选择；取消（0）跳过 | 先预检背包可添加 -> 从储存删除（失败则**内部报错**）-> 加入背包（失败则**内部报错**） | "取出了 N 个 X"；背包无空位 -> "背包没有多余空间" |
| 存入（背包 -> 储存） | 同上 | 先预检储存可添加 -> 从背包删除（失败则内部报错）-> 加入储存（失败则内部报错） | "存入了 N 个 X"；储存无空间 -> "没有存放空间" |
| 丢弃（PC 内） | 数量 >1 时选择 | 重要物品 -> **直接拒绝**（"太重要不能丢"）；确认后从储存删除（失败则内部报错） | "丢掉了 N 个 X" |
| 重要物品的多份边界 | **选择步骤被跳过**（非"数量 1"） | — | 取/存按整叠数量执行；显示数量强制按 1（单数名词） |

- **内部报错**=流程进入"不应发生"分支时的断言式失败（预检已排除）；正常界面不可达，按静态反例登记。
- 背包界面的丢弃另有不同路径：数量 >1 时选择数量、确认后**逐个删除**（每次删除 1 个，返回值不检查）；重要物品在背包界面默认**没有"丢弃"命令**（仅调试可见）。
- PC 总入口：PC 点单（物品储存/邮箱/关闭；或按注册菜单项"玩家的 PC"与"某人的 PC"）；信箱"移至背包"= 确认（信件内容将丢失）后把邮件物品加入背包，成功即从信箱删除，背包满则提示。

### 4.3 界面通用行为（与本包容器相关的部分）

- 背包界面命令按物品动态生成：读信（邮件）、使用（有野外/使用处理器，或机器且有队伍）、给予（队伍非空且可携带；重要物品拒绝；空队伍提示）、丢弃（非重要或调试）、登记/取消登记（见 §5）、调试（仅调试）、取消。
- 使用命令的返回值有三态：0=未使用、1=已使用、2=**关闭背包到野外再使用**（界面据此退出循环）——使用效果本身归 WP28。
- 数量选择控件：上/下 ±1（1 至上限回绕）、左/右 ±10（钳位 1 至上限）、取消返回 0、确认返回当前值。
- **过滤选择**（按谓词的背包选择界面）供多个消费者使用：树果/覆盖物、杏子（球材料）、化石、驱虫喷雾、给个体/仓库持物等选择；进入前先保存"上次口袋＋各口袋索引"——**带过滤谓词时在打开前重置口袋与各口袋索引**（不带则沿用保存值）；**界面返回后（无论有无过滤）一律恢复保存的两项游标值**。

## 5. WP27-C：快捷登记与野外使用

- **登记的三层守卫（分开）**：① **领域直接登记**（容器方法）只校验标识合法并去重——**不检查是否持有、不检查野外处理器**；合法但未持有、无处理器的物品也可登记。② **背包菜单的"登记/取消"命令**：**已登记 -> 提供"取消登记"（不要求处理器）；未登记且资格工具通过（存在野外使用处理器）-> 提供"登记"；其余 -> 无登记类命令**。③ **背包列表的两态登记图标**另包在"**重要物品**"条件内（普通物品不显示登记图标），条件与菜单命令不完全相同。
- **登记/取消语义**：登记为**去重列表**（重复登记不产生重复项）；取消按标识删除（未知物品无操作）。
- **快捷菜单收集**：仅收集**仍在背包中**的登记项（登记后丢弃/用尽则不出现，但登记列表本身不被自动清理）；**收集阶段不再要求存在使用处理器**（直接登记的普通物品持有后即进入收集）；同时收集队伍中可用隐藏招式（许可判定归 WP59）；两类都为空 -> 提示"可在背包登记物品到此键"。
- **触发**：地图上（玩家未移动时）按参考侧"特殊键"（当前输入层映射为 Z；别名/按键层引用 WP17）打开快捷菜单；菜单两列（招式/物品，按名称排序），选择物品后：野外确认 -> **临时退出菜单状态**执行野外使用 -> 成功结束菜单/失败返回菜单。
- 登记的用途限于**野外快捷使用**；消费/效果的消耗规则归 WP28（本包只登记入口与过滤）。
- 存档迁移：旧存档的登记字段改名转换（旧登记列表 -> 登记列表；旧游标 -> 快捷菜单游标）；背包、储存的游标字段同样有旧名转换（WP10 交界）。

## 6. 规则与不变量

1. 槽位对 `[标识, 数量]`；同标识可跨槽；数量累加跨槽；每槽上限 999；口袋上限 `-1` 表示无限（当前全部口袋无限）。
2. **预检纯、执行可部分**：全有全无论必须"预检＋执行"；**在本包列举的接收对照入口中，配对预检仅见于 PC 存取与礼物物品路径**（不推出其它商店/消费者不存在预检）；收到物品/地面拾取/奖品为直接添加（可部分写入后 false）；§7 按消费者分列提示与 false 后状态。
3. 添加成功后的自动排序只对配置为真的口袋（当前：TMs&HMs、Berries）生效，排序基准=物品目录定义顺序。
4. PC 储存固定 999×999，与背包的口袋容量口径不同；PC 储存懒创建并以元数据初始物品播种。
5. 登记三层分开：领域登记只校验标识并去重；菜单为"已登记 -> 取消；未登记且资格通过（野外处理器）-> 登记；其余无登记类命令"；图标另需重要物品条件；快捷收集按"仍持有"过滤（不查处理器）；列表不自动清理。
6. 背包游标状态：口袋域 1–8（越界报错）；设置仅检查上限、无下界；clear 只清物品与各口袋索引（保留上次口袋与登记列表）；过滤选择**仅在带谓词时于打开前重置，返回后一律恢复**。
7. `replace_item` 只在旧物品所在口袋内改标识（不合并/不移动/不校验新口袋）——用于"开关式"钥匙物品替换。
8. 重要物品的界面约束：背包不可丢弃（默认）、PC 不可丢弃、不可给予/携带、存取数量选择跳过（多份整叠搬运并强制按 1 显示）。

## 7. 边界与失败

- 未知标识：默认/正常值前提下 查询 0 / 持有否（qty=1）/ 可添加否 / 添加否；**持有是纯数量比较**——请求数量 0 或负数时可判真（默认/正常前提之外）；PC 储存的严格查询（未知报错）与背包宽松查询不同。
- 负数量：助手模块（预检/添加/删除）**报错**；数量 0：均"成功且无操作"（与 has? 的纯比较语义分开记录）。
- 部分失败：单独调用添加/删除且空间或数量不足 -> 返回 false 但已有部分写入/删除（记录；调用方预检可避免）。
- 无限口袋的容量判断：以"当前长度+1"为上界；接收物品失败来自每槽上限与助手耗尽（静态推导）。
- **消费入口分列（预检与否）**：**在本包列举的对照入口中，PC 取出/存入与礼物物品路径显式配对预检**（预检失败不进入添加；不推出其它商店/消费者不存在预检）；**收到物品（`pbReceiveItem`）、游戏角子奖品（`pbBuyPrize`）、地面拾取（`pbItemBall`）为直接添加**。默认空无限口袋、合法同种物品 1500 的对照：`can_add?` false 且**仍空**；`add` false 且**已存 999**；`add_all` false 且仍空。三个包装消息各异：收到物品=先获得消息、失败无背包满消息；奖品=仅成功消息（失败无消息）；地面拾取=先"发现"文本、失败再补"背包已满"提示。三者均返回 false 而**可能已存 999**。
- 邮件物品进入背包：背包满 -> 提示且**不从信箱删除**（走添加返回值判断；未配对预检）。
- 丢弃数量：背包界面逐个删除（不检查返回值）；PC 丢弃走单次删除并断言成功。
- 游标非常规输入：设置仅检查上限、无下界（负值可保存）；空口袋＋负索引的查询结果按原值返回，不保证 0（默认/正常值前提之外）。

| 添加·执行并写入 | 同上、直接调用 `add` | 执行扫描并写入 999 后返回 false（部分写入；`add_all` 预检可避免） |
| 部分写入反例 | 直接调用添加且分配中空间耗尽 | 返回 false；先前写入保留（预检成对使用可避免） |
| 全有全无 | `add_all` 数量超过可分配 | false 且无写入 |
| 删除·跨槽 | X 占两槽（999+101），删 1000 | 第一槽清零删除、第二槽减 1；返回 true；数组压缩 |
| 删除·不足 | X 共 5，删 10 | false；已删 5（预检 `remove_all` 可避免） |
| 替换钥匙物品 | 旧 A、新 B 同口袋；口袋含 A×2 处 | 两处标识变为 B（不合并）；返回 true |
| 清空 vs 重置 | 上次口袋 4；`clear` 后 | 口袋全空、**各口袋索引为 0**；上次口袋**仍为 4**、登记列表保留（reset 与 clear 不等价） |
| 自动排序 | 第 4 口袋添加后 | 按目录定义序重排 |
| 无限口袋预检 | 口袋长度 0、上限 -1 | 预检只扫描 1 个槽位：新标识 ≤999 可添加、>999 为 false；已有槽位逐槽参与分配 |
| 未知物品 | `quantity/ has?/ can_add?/ add`（默认 qty=1） | 0/false/false/false；**qty=0 或负时 has? 纯比较可为真**（默认前提之外） |
| 负数量 | 助手添加 -1 | 报错 |
| PC 播种 | 首次创建（文本样本含 POTION；默认配置空列表） | 存在的初始物品各 1 个；未知标的跳过 |
