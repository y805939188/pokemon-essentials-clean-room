## 1. 目的、范围与非目标

**目的**：定义种植地块的完整生命周期——植物状态字段与持久化、种植/浇水/成长/成熟/衰败/重植/采摘的调用者与次序、时间/水分/产量算法与配置数据输入、旧/新两套机制差异、与背包（选择/移除/容量）及事件（自身开关）的交界；供事件接待（U01）、图鉴/统计（WP06）与跨包时间边界核对引用。

**范围**（WP60 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP60-B1：植物数据——每地块的状态对象（字段全集）、持久化位置、旧/新机制标记、重置与继承。
2. WP60-B2：生命周期——种植、成长阶段、重植循环、衰败/清零、成熟判定与谓词。
3. WP60-B3：时间与水分——更新时点（**现成精灵链仅推进新机制；旧机制须显式直接调用数据 update**）、跨时长结算、阶段换算、干涸与产量惩罚、旧机制浇水计数与雨天自动浇水。
4. WP60-B4：交互——事件名约定、成长中查问与浇水、空地流程（施肥/种植/退出）、采摘流程与背包/自身开关次序。
5. WP60-B5：产量——两套公式、极值与数据约束。
6. F14-03 中属于本产物部分的状态更新。

**非目标**：

- 不定义物品数据字段全集（`is_berry?`/`is_mulch?` 等标志归 WP27/WP03 引用）、背包容量主规则（WP27）。
- 不定义真实接待/种植事件的编排与奖励（U01）；不定义图形/动画资源表现（运行范围；WP15 引用）。
- 不定义钓鱼（WP60 另一产物）与遭遇系统（WP36）。
- 不运行游戏或参考脚本；不设计未来框架的植物 API。

## 2. 概念与术语

- **植物数据（BerryPlantData）**：一个地块一个对象；**存储在事件变量**（`$PokemonGlobal.eventvars` 中，随存档持久化，WP09 引用）；以"事件变量存在 + `planted?`"表达"有植物"。
- **旧/新机制**：由配置 `NEW_BERRY_PLANTS` 决定（世代 ≥4 为真）；**对象机制标记在创建/重置时读取配置并冻结，也可被直接改写（静态）**；新机制=水分/产量惩罚/覆盖物（Gen 4 风格）；旧机制=每阶段浇水标志与浇水计数（Gen 3 风格）。**领域更新按对象标记分叉**；**UI 的部分分支（花期文案、施肥入口）按当前配置分叉**（§6.2/§6.3）——常规配置不变时二者一致，配置变更下的混用边界即上两节。
- **成长阶段（growth_stage）**：0=空地；1=刚种下；2..4=成长中（幼芽/长高/开花）；≥5=成熟（可采摘且不再成长阶段推进）。成长阶段数与"完全成熟阶段数"分开配置。
- **重植（replant）**：成熟后不采摘而继续经历一个完整生命周期时，植物结出下一轮（阶段回到 2、计数 +1、水分重置），直到达到重植上限后地块清零。
- **覆盖物（mulch）**：新机制下地块可保留一枚覆盖物；影响阶段时长/干燥速率/重植上限/成熟阶段数。
- **浇水壶**：一组固定物品（新机制用于浇水；旧机制同）——任一在背包即可查问浇水。

## 3. WP60-B1：数据与字段（静态核对）

### 3.1 字段全集（按机制）

| 字段 | 机制 | 语义 |
| --- | --- | --- |
| berry_id | 共同 | 所种树果物品 id（空地块为 nil） |
| new_mechanics | 共同 | 创建/重置时冻结的机制标记 |
| time_alive | 共同 | 本生命周期存活秒数 |
| time_last_updated | 共同 | 上次结算的宿主时间戳（秒） |
| growth_stage | 共同 | 0=空、1=种下、2..4=成长、≥5=成熟 |
| replant_count | 共同 | 已重植次数 |
| watered_this_stage / watering_count | 旧 | 本阶段是否浇过 / 总浇水次数 |
| moisture_level / yield_penalty | 新 | 水分（初始 100，可低于 0）/ 产量惩罚计数 |
| mulch_id | 新 | 覆盖物物品 id（`reset(planting=false)` 在校数时清空；种植时保留） |

### 3.2 重置与分叉语义

- **reset(planting=false)**：置机制标记（取自当前配置）、清 berry/mulch（非种植路径）、time=0、阶段=0、重植=0、浇水数=0、**水分=100**、惩罚=0。
- **plant(berry)**：先 reset(planting=true)（**保留已施覆盖物**）→ 记 berry、阶段=1、`time_last_updated=当前时间`。
- **replant()**：time_alive=0、阶段=**2**、重植+1、旧机制浇水标志/计数清零、新机制水分=100、惩罚=0（覆盖物保留）。
- **谓词**：planted?=阶段>0；growing?=0<阶段<5；grown?=阶段≥5；replanted?=重植>0。

### 3.3 数据输入与常量

- **PBS（`berry_plants.txt`）**：每果一段：`HoursPerStage`（**正整数**）、`DryingPerHour`（**非负整数**，0 允许）、`Yield = 第一,第二`（**第一项非负整数、第二项正整数**——`0,5` 是合法格式；缺省 2,5）。**样本**：多数 `3/15/2,5`；LEPPA/ORAN/PERSIM `4/15/2,5`；LUM `12/8/2,5`；SITRUS `8/7/2,5`；FIGY `5/10/1,5`。
- **三层缺省/缺失语义（分开登记，不是查询兜底）**：
  1. **PBS 数值格式**由编译期按"非负整数／正整数"分别校验；
  2. **已登记但缺字段**：在**构造该记录时**补缺省——HoursPerStage=3、DryingPerHour=15、Yield=2,5；构造时**若第二项<第一项则对调**（`5,2` → `2,5`；`0,5` 保持）；
  3. **整条记录缺失**：查询按符号 id 精确命中，**未知 id 报错**（不生成默认记录、不回退）——物品存在但无 BerryPlant 记录时，查询/产量计算同样报未知 id。
- **常量**：重植上限 9；成长阶段数 4；完全成熟阶段数 4；浇水壶列表 =〔SPRAYDUCK、SQUIRTBOTTLE、WAILMERPAIL、SPRINKLOTAD〕。

## 4. WP60-B2：生命周期状态机

```
空地(0) --种植--> 种下(1) --时间--> 2 → 3 → 4 → 成熟(≥5)
                                          ├─采摘--> 空地(reset)
                                          └─继续完整周期--> 重植(阶段=2, 计数+1) ──> … → 成熟
                                                                到达重植上限时，再满一周期 --> 空地(reset)
```

- 种植入口只在地块"未种植"（或已清零）时可用；成熟入场只可采摘；成长中入场只可查问/浇水。
- **重植循环算法（跨时长一次结算）**：反复检查 `time_alive ≥ 本生命周期阶段总长`（见 §5.2）：若重植计数已达上限 → **reset 清零并结束**；否则 replant、扣减时长、继续循环（支持跨多个生命周期/多阶段的离线追赶）。
- 一次结算内可经过多次重植；每次重植后本生命周期时长按"阶段数 −1"计（重植从阶段 2 开始）。

## 5. WP60-B3：时间与水分结算

### 5.1 更新时点

- **领域更新（数据对象自身的 `update`）**：结算入口条件 `planted?`；`time_delta = 当前时间戳 − time_last_updated`；**≤0（时间倒退/同秒）直接返回**。新机制按"加载中每帧"结算（内部对 ≤0 提前返回）；旧机制**可**被显式直接调用按长时间结算（见下）。
- **现成精灵链的实际行为（静态）**：地块精灵只在**构造/每帧**调用更新辅助，且**都没有传"首次"参数**；该参数缺省为假，使数据 `update` **只在"首次或对象机制标记=新"时被调用**——因此**旧机制对象在现成精灵链下不会被推进**（"装图更新"只是注释意图，当前调用未启用）；**新机制对象每帧被推进**。要推进旧机制对象必须**显式直接调用数据 `update`**。二者分开登记，不按注释补造调用。
- 历史注释的"旧机制在装图时更新一次"仅作设计意图记录；行为以本节为准。

### 5.2 跨时长结算（按序）

1. 阶段总长 = `HoursPerStage × 3600` 秒（覆盖物修正见 §5.4）。
2. **重植循环**（§4）：本生命周期阶段数 = 成长阶段数 + 完全成熟阶段数 −（已重植 ? 1 : 0）。
3. 存活时长更新；**成长阶段 = 1 + floor(time_alive ÷ 阶段总长)**；已重植再 +1（从 2 起）。
4. **旧机制**：阶段推进时清除"本阶段浇水"标志；若当前**世界天气类别 = 雨**（WP59 §4.1）→ **自动浇水**一次（计入本阶段一次）。**该路径的现成可达前提 = 显式直接调用数据 `update`**（见 §5.1）。
5. **新机制**：按"跨过的整点（小时）数"逐小时干涸——水分>0 → 水分 − DryingPerHour；水分 ≤0 → 产量惩罚 +1；**水分允许为负**。**若本次结算内发生了重植**，该轮水分以**重植后剩余生命周期的整点数**计（重植点视为重新起算）。
6. 记录 `time_last_updated = 当前时间戳`。

- **静态向量（独立算术）**：HoursPerStage=3、DryingPerHour=15、初始水分 100——**6 小时一次结算 → 阶段 3、水分 10、惩罚 0**（6 个整点各 −15）；**10 小时 → 阶段 4、水分 −5、惩罚 3**（第 7 个整点 10−15 到 −5，其后 3 个整点各 +1）；3 小时 → 水分 55、阶段 2。
- **重植时长向量**：HoursPerStage=3、无覆盖物：首生命周期 8 阶段 ×3h=24h；此后（8−1）×3h=21h；上限 9 → 1+9=10 个生命周期（24h + 9×21h = 213h ≈ 8.9 天）后清零；跨重植结算时，后续水分按剩余小时计。

### 5.3 水分阶段与显示（新机制）

- 水分阶段：水分>50 → 湿（2）；>0 → 潮（1）；≤0 → 干（0）；空地显示为空。地块精灵按阶段显示干/潮/湿三态；植物精灵按成长阶段选图（阶段 1 通用"刚种下"；2..4 与 ≥5 用每果专用图，缺图回退通用球状图；**新机制**阶段推进且在成长区间时播放闪光动画）。
- 阶段/朝向：浇水/查问时事件按阶段转向（制止面向玩家），属表现层（静态记录）。

### 5.4 覆盖物修正（新机制；在结算前套用）

| 覆盖物 | 效果 |
| --- | --- |
| 成长覆盖物（GROWTHMULCH） | 阶段总长 ×0.75（向下取整）；干燥速率 ×1.5（向上取整） |
| 潮湿覆盖物（DAMPMULCH） | 阶段总长 ×1.25（向下取整）；干燥速率 ÷2——**对非负整数干燥值取整数商（向下取整）**（GR-012：干燥 15→7、14→7、1→0；不得写成数学除法 7.5，也不得改为每小时把水分夹到零） |
| 黏黏覆盖物（GOOEYMULCH） | 重植上限 ×1.5（向上取整） |
| 稳定覆盖物（STABLEMULCH） | 完全成熟阶段数 ×1.5（向上取整） |
- 覆盖物在**每次结算**按当前存储值套用；**若在成长中以原始字段改写覆盖物**，下一次结算会**用新参数重新解释累计时间**（阶段总长/干燥速率变化影响本次追赶换算）——**不存在"只影响未来时间"的保证**。正常 UI 施肥只发生在**空地**（§6.3），不提供种植后施肥流程。

## 6. WP60-B4：交互流程（事件侧调用）

### 6.1 入口约定与状态分派

- 地块事件按名称约定（含 `berryplant`）由交互脚本取"自身事件变量"作为植物数据；**变量不存在时创建空对象**（不写入统计）。
- 分派：`grown?` → 采摘；`growing?` → 查问+浇水；否则（空地）→ 空地流程。

### 6.2 成长中查问与浇水

1. 按阶段给查问消息（1：已种下 / 2：发芽 / 3：长大 / 4：开花；旧机制的开花文案按**浇水次数** 0–4 分五档——该分支读**配置**而非对象标记；新机制固定"盛开"）。
2. **浇水查问**：按浇水壶列表顺序，取**背包中存在的第一件**壶（存在即停下）；确认"要浇水吗" → `water`：**同时写两套记录**——新机制水分=100；旧机制若本阶段未浇则置标志并计数 +1（"被哪套规则消费"取决于对象机制标记，"写入"总是发生）；随后音效+两条消息（新："都精神了！" / 旧："植物似乎很高兴。"）。任一壶存在但拒浇 → 不写任何状态。
3. 浇水不改成长阶段/不推进时间。

### 6.3 空地流程（新机制/旧机制；取消语义分阶段）

- **新机制**：若已有覆盖物 → 消息"已施下 X"（不再询问，流程继续到种植询问）；否则三选菜单〔施肥 / 种植树果 / 退出〕：
  - 施肥：打开背包选择屏（过滤覆盖物标志）；**取消选择屏 → 结束（不消耗）**；选中非覆盖物 → "不能施肥"（不写）；选中覆盖物 → **先写 `mulch_id`、先移除背包该覆盖物**，消息"撒上了 X"，随后**继续到种植询问**——**此后拒种或取消选果都不会回滚**：覆盖物已库存 −1、已记录在地块。
  - 种植（菜单项）→ 直接进入种植询问（**跳过额外"要种植吗"确认**）。
  - 退出 → 结束。
- **旧机制**：单确认"要种植树果吗？"；拒 → 结束。
- **种植询问**（菜单项到达或经施肥后）：打开背包选择屏（过滤树果标志）；取消 → 不种；选中 → **统计 berries_planted +1 → `plant(berry)` → 背包移除** → 按机制给对应文案（含元音冠词处理）。
- **取消时点状态表**：①未选覆盖物即取消 → 覆盖物库存不变；②**施肥成功之后**的任何取消/拒种 → **覆盖物库存 −1、地块保留覆盖物、种植统计不增**；③种植选择屏取消 → 不回滚已施覆盖物。
- （不提供种植后施肥流程；"成长中原始改写覆盖物"的边界见 §5.4。）

### 6.4 采摘流程（成熟）

1. 采摘询问（单个/复数文案随数量）。
2. **拒摘 → 返回假，植物保持成熟**。
3. **容量预检**：`背包能否一次加入 qty 个` —— **不能 → "背包满了"、返回假、植物保持**（不部分拾取）。
4. 通过后按序写入：统计 berry_plants_picked +1；**qty ≥ 该果最大产量 → 统计 max_yield_berry_plants +1**；**背包加入 qty**；消息（获得文案 + 口袋提示）；**地块事件自身开关 A 置真**；**工具返回真**。
5. **外层（事件包装）收到真后才 `reset` 植物**；**直接调用 `pbPickBerry` 不重置植物**（只做询问/预检/加入/开关并返回）。
- **次序要点**：预检 → 统计 → 加入 → 消息 → 自身开关 → 工具返回 → 外层 reset；失败分支不清零、不加入。
- **五类状态对照**：施肥后取消（覆盖物已耗、地块保留）；尚未施肥即取消（全不变）；正常包装采摘（A→外层清零）；直接采摘工具（不清植物）；满包拒绝（不加入、不清零）。

## 7. WP60-B5：产量

- **新机制**：`max(最大 × (5 − 惩罚) ÷ 5, 最小)`（整数除）。惩罚由干涸累积（§5.2），**只在水分 ≤0 的小时 +1**。
- **旧机制**：
  - 浇水计数 0 → 最小；
  - 否则 `ret = (最大−最小)×(计数−1) + rand(0..(最大−最小))`；产量 = `ret ÷ 4 + 最小`（整数除）。
- **静态向量**（最大 5、最小 2）：新机制 惩罚 0/2/4/6 → 5/3/2/2（5×1/5=1<2 → 收拢到 2）；旧机制 计数 0/1/2/3/4 → 2 / 2 / 2–3 / 3–4 / 4–5（区间为静态推导范围，实际取随机值）。
- 数据对调：Yield 最大<最小 → 装载时对调（如 `5,2` 等价 `2,5`）。

## 8. 规则与不变量

1. 地块"有无植物"只由事件变量对象的阶段表达；对象随事件变量持久化（WP09）。
2. **对象机制标记在创建/重置时读取配置并冻结，也可被直接改写（静态）**；领域更新一次只用一套水分逻辑（按对象标记），UI 部分分支另按配置（§2/§6.2/§6.3）。
3. 成长阶段推导纯由 time_alive/阶段总长 决定（重植 +1）；不存"上次阶段"；阶段数、成熟阶段数、重植上限来自数据/常量/覆盖物。
4. 时间倒退（time_delta ≤0）不结算、不报错。
5. 水分可负；水分 ≤0 时只累计惩罚，不再消耗水分；惩罚只增不减（重植/清零才归零）。
6. 采摘：先容量预检再写任一状态；成功路径固定次序（§6.4）；失败路径不清植物。
7. 取消/失败消耗按**取消时点**：未进入选择屏的取消不消耗；**施肥成功之后**的取消/拒种已使覆盖物库存 −1（不回滚）；浇水拒绝不写；采摘失败不加入、不清植物。
8. 雨水自动浇水仅旧机制、且按"世界天气类别 = 雨"判定。

## 9. 边界与失败

- 背包满（采摘）：消息后植物保持成熟；覆盖物与惩罚保持；**不加入、不清零**。
- 施肥相关取消（按 §6.3 分阶段）：未选覆盖物即取消 → 不写；选中非覆盖物 → 不写；**施肥成功后取消/拒种 → 覆盖物库存 −1、地块保留**（不回滚）。
- 浇水：所有壶都不在背包时不查问（流程无动作）；拒浇不写。
- **旧机制现成精灵链不推进植物**（§5.1）；要推进须**显式调用数据 update**——"装了图就更新"不是可达保证。
- **采摘工具与外层重置分离**：直接调用工具不重置植物（§6.4）。
- 多阶段离线追赶：一次结算可跨多个阶段与多次重植；到达重植上限后的第一次满周期**清零**（不产生额外一轮）。
- 时间倒退：不结算（下一次前向时间照常累计）。
- 覆盖物极值：重植上限 ×1.5 向上取整（9→14）；成熟阶段 ×1.5 向上取整（4→6）。
- 成长中原始改写覆盖物：下次结算按新参数解释累计时间（§5.4），无"只影响未来"保证。
- 新机制水分长期为零：每个整点 +1 惩罚（产量下限为最小）。
- 阶段 5 以上（含覆盖物加长的成熟区）：仍为"成熟"，采摘行为一致。
- 资源/图形缺图：回退通用图形（§5.3）；真实资源表现运行未决（WP15 引用）。
- 真实接待/种植事件缺失（U01）：本包只固定脚本侧流程。
