## 3. 分层转换合同

前提：唯一合法物种/形态节，方法已登记，TARGET 是有效目标物种，依赖内容/其它字段/此前阶段均正常；无扩展覆写。形态向量指显式给定的进化条目，不是整组属性省略后的基础继承。

| 阶段 | 本范围行为 |
| --- | --- |
| 行预处理 | 去除首个井号及后缀，修剪行首尾空白，再分离属性名和值。`… , 01 #note` 仍成为普通 `01`。引号不保护井号。所有核心 10 边界本身都是合法属性行，尚不在此拒绝 |
| CSV 分词 | 逗号切分，逐值修剪空白；末尾空字段被抑制，内侧空字段保留。`TARGET,M,` 与 `TARGET,M` 的第三位都成为缺值；不是把空串转换为 0。具体引号位置规则沿用 WP04，不替换成标准 CSV 假设 |
| 初次 schema 消费 | 目标与方法各自走文本/枚举规则；参数先保留文本。旧复数第三位为必需文本 `s`，该文本模式本身仍可能返回缺值；R 单数第三位是可选文本 `S`，空/缺变缺值。此处没有整数转换 |
| 方法/条目校验 | R：方法声明有参数且第三位缺值时，当前条目登记前拒绝。V21 无此必需参数门；方法名非法仍在初次方法枚举阶段拒绝，与本问题分开 |
| 基础物种全表终检 | 先解析目标引用，再将所有 Integer 方法的参数文本交给 `u`；这才检查数字格式。V21 基础缺值在此发生缺值接收者异常，而非友好的必需参数诊断；R 此缺值已被前门拦截 |
| 形态全表终检 | Integer 参数仅在它仍是文本时交给 `u`，避免重转基础已继承的整数。V21 显式条目第三位缺值时跳过这一转换，保留缺值并可继续到保存；R 因前置必需参数门而已拒绝。显式非空非法文本在两版本均拒绝 |
| 数值语义 | `u` 接受一个或多个 ASCII 十进制数字并按十进制取整数；允许任意前导零；不接受任何正负号、小数点、指数或尾部字母。这里没有有限位数/数值上界。`01` 不是八进制 1 的特殊入口，`010` 为十进制 10 |

活跃调用路径是 schema 记录求值调用通用值转换，随后进化终检再次调用整数值转换。旁边标为 Unused 的旧 CSV 辅助器不是本结论依据；转换函数前残留注释也不能推翻已核实的活跃调用。只给行为，未输出调用实现。

## 4. 核心边界矩阵（30 项逐项共用，完整展开见 CSV）

| 输入第三位 | CSV/schema 后 | V21 基础复数 | V21 显式形态复数 | R 基础/形态，两种拼写 |
| --- | --- | --- | --- | --- |
| `-1` | 文本 -1 | 全表整数阶段拒绝 | 全表整数阶段拒绝 | 全表整数阶段拒绝 |
| `0` | 文本 0 | 接受→整数0 | 接受→整数0 | 接受→整数0 |
| `1` | 文本 1 | 接受→整数1 | 接受→整数1 | 接受→整数1 |
| `+1` | 文本 +1 | 全表整数阶段拒绝 | 全表整数阶段拒绝 | 全表整数阶段拒绝 |
| `01` | 文本 01 | 接受→整数1 | 接受→整数1 | 接受→整数1 |
| 空尾位（带末逗号） | 缺值 | 全表整数阶段缺值异常 | 接受并保留缺值 | 条目必需参数门拒绝 |
| 缺参数（无第三位） | 缺值 | 同上 | 同上 | 同上 |
| `1.0` | 文本 1.0 | 全表整数阶段拒绝 | 同左 | 同左 |
| `1e2` | 文本 1e2 | 全表整数阶段拒绝 | 同左 | 同左 |
| `1x` | 文本 1x | 全表整数阶段拒绝 | 同左 | 同左 |

补充：`-0` 拒绝；`00`→0；端部空白 ` 01 `→1；`0x10`、`1_000` 拒绝。普通双引号包围 `"1"` 或 `""` 若作为最后参数，会保留引号而在整数阶段拒绝，不能把 `""` 当缺参。尾位仅空白被预处理/分词消尽，仍按缺值。

**内侧空文本与尾缺值不同**：复数 `Evolutions = TARGET,M,,TARGET2,Level,1` 中，第一组第三位是保留的空文本；V21/R 两者（基础/形态）在全表整数阶段拒绝。R 条目必需参数门只判缺值，该空文本不是缺值，因此不在该门拒绝。若写 `TARGET,M, ,TARGET2,Level,1`，第三位经 trim 也为空文本，行为相同。

**错误前缀**：R 条目缺参失败时，当前条目尚未登记；非空坏数值在全表终检失败时，当前表条目可已全部登记，但本表保存未到，不自动回滚。V21 基础尾缺参同属后者。外层启动/直接编译的磁盘清理差别沿用 WP04，未运行、未新增承诺。

## 5. 额外领域约束与运行不命中

下表只回答“是否另设参数域校验”，其它进化守卫、选择顺序和触发时机仍归正式 WP31/WP32。

| 参数用途 | 额外编译域校验 | 编译接受后的具体对照 |
| --- | --- | --- |
| 24 个等级阈值方法（Level 至 Ninjask，CSV 逐项列出） | 不要求 ≥1，不要求 ≤配置等级上限 | 参数0可编译，升级上下文仍受其它条件与统一守卫；设可达等级上限100，参数101可编译但合法等级≤100时阈值不命中 |
| Beauty | 不要求 ≤255，不夹值 | 美丽值255、参数256时只是不命中；参数0不免除升级上下文 |
| BattleDealCriticalHit | 不要求次数≥1、不设上限 | 有成员记录0且参数0时次数比较成立；集合或成员记录缺席时即使参数0也不命中，不得默认成0 |
| Location | 不要求正地图号、不查地图文件或元数据存在性 | 参数0或99999999可以编译；当前地图ID1时均不命中，不是编译错误 |
| Region | 不查 town-map 目录/区域存在性、不要求正值 | 参数0可与当前地图 town-map 位置中的区域0匹配；元数据/位置缺席时不命中 |
| Event | 不查事件目录、不要求编号≥1 | 参数0可编译，事件输入编号0时编号比较成立；输入1不命中 |
| EventAfterDamageTaken | 参数是事件编号，不是伤害或次数阈值 | 参数0可编译；ready为真且事件输入0时可命中。战后直接伤害阈值仍为固定49，不随参数改变；战后检查本身返回否 |

V21 显式形态缺参属于“编译放过无效数据”，不属于有效整数域：等级/美丽/要害计数的有记录大小比较可能在运行时报错；位置/区域的正常整数相等比较仅不匹配；正常整数事件编号也不等于缺值。EventAfterDamageTaken 的战后置 ready 步骤不消费事件参数，因而缺参不代表该步必然失败；随后正常整数事件不会匹配缺值。本项均为有正常上下文时的静态条件推导，不证明整个无效数据工程均可运行，也不制定未来兼容取舍。

## 6. 大整数与 JS 表示域

参考 `u` 的十进制输入检查没有 JS 安全整数或 32/64 位上限；通过后使用 Ruby 整数模型，静态推导如下：

| 文本 | 参考转换结果（精确十进制） | JS Number 安全整数域 |
| --- | --- | --- |
| 9007199254740991 | 9007199254740991 | 域内 |
| 9007199254740992 | 9007199254740992 | 域外，即使该单值可表示也不是安全整数 |
| 9007199254740993 | 9007199254740993 | 域外，相邻整数区分不能靠普通 Number 保证 |
| 18446744073709551616 | 18446744073709551616 | 域外；参考仍无64位上限拒绝 |

依据：[Ruby 3.1 整数模型](https://docs.ruby-lang.org/en/3.1/syntax/literals_rdoc.html#label-Integer+Literals)、[十进制文本转换](https://docs.ruby-lang.org/en/3.1/String.html#method-i-to_i)、[ECMAScript Number.MAX_SAFE_INTEGER](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-number.max_safe_integer)。Ruby 默认文本转换本身可能容忍后缀，但进化管线先做严格数字检查，所以 `1x` 不会到宽松前缀转换。

TypeScript 没有统一的“整数范围”；若实现选择只存 JS 安全整数，则其非负表示域是0…9007199254740991，这是实现政策/表示能力，**不是参考接受域**。这份调查不选定框架表示、不要求引入特定类型、不批准缩窄差异。大整数会否命中取决于运行读入量，不可用“平常达不到”改写编译接受事实。资源耗尽、任意长度文件与任意宿主限制不在本次静态承诺内。
