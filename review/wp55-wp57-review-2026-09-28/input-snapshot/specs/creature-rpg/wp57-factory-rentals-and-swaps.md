# WP57 — Factory 租借与换队

状态：**ReviewPending（A～F：租借候选生成与选择域、初次租借界面与提交、战后交换配对与提交、原队伍隔离与恢复、与WP54／WP55／WP25的交界及有界来源；首稿v1，尚未外审）**。2026-09-28；F13-05，Combat Requirements／Creature-RPG／User Interface。只读基线 `8c5911e4a4b07b07e832e4bb0d5d8859e88b4a9b`，没有运行UI、生成器、模拟器、游戏或存档转换。源码名仅审计定位。

## 1. 目的与流程（A）

本包描述工厂挑战中“临时队伍”的建立与更替：候选池如何按胜场／交换数选择，初次如何从候选中租借，战后如何用上一对手的成员交换，以及这些提交与玩家原队伍、会话状态、容量／所有权规则的关系。它不设计未来对象模型；个体创建数值（等级／个体值／努力值／招式／性格／个人值）主规则由WP55已述的设施个体创建合同，阵容合法性由WP54的工厂规则承担，会话推进与恢复由WP55承担。

可见流程：注册工厂（会话侧创建额外数据、参赛数3）→ 准备租借（生成候选6与对手）→ 租借界面选满3只并确认（提交并**交换数＋1**）→ 逐场对战 → 战后准备交换（记录上一对手队伍、生成新对手与候选）→ 交换界面把1只租借成员与上一对手的1只成员配对（确认成功才**交换数＋1**；取消可回退）→ 循环直至会话结束（队伍恢复由WP55执行）。

## 2. 候选生成（B）

**分组与选择域**（按当前胜场）：组号＝“胜场整除7”与7取较小值（0..7）。选择域表按候选池模板长度881设计，实际按“候选池实际长度/881”等比缩放（起点与终点均取整）：

| 组号 | 普通档区间（模板） | 开放档（最高等级）区间（模板） |
| ---: | --- | --- |
| 0 | 0–173 | 372–491 |
| 1 | 174–272 | 492–610 |
| 2 | 273–371 | 611–729 |
| 3 | 372–491 | 730–849 |
| 4 | 492–610 | 372–881 |
| 5 | 611–729 | 372–881 |
| 6 | 730–849 | 372–881 |
| 7（及更高） | 372–881 | 372–881 |

**个体值两档与阈值**：两组个体值取“个体值表[组号]”与“[组号＋1，7取小]”：表为3、6、9、12、15、21、31、31。每批中前若干只使用较低值、其余使用较高值；阈值按**交换数**取“下限不超过交换数”的**下限最大**一行：0→6、15→5、22→4、29→3、36→2、43→1（即交换越多、越高个体值的成员越多）。

**数量与校验**：调用前先保存规则集的原人数范围。若“排除名单”（对手生成时传入的既有成员串接列表）为空（初次租借）→ 临时把规则集人数设为6并生成6只，按“新队伍自身”校验合法；否则 → 临时把人数设为“原最大值＋排除名单长度”并生成“原最大值”只，按“新队伍＋排除名单”整体校验合法。生成循环：清空→逐只从选择域**含端点**等概率取候选索引、按“本批第n只低于阈值?”分配两档个体值、以给定等级与“无训练家属主”创建；整体合法才结束，否则重来。**无迭代上限**（不合法则无限重试）。结束后把人数范围还原为原值。

**候选对象与身份**：每次生成都是**新的临时个体**（非模板复用）；个体的物种／物品／性格／招式／努力项来自内容表条目，等级＝规则建议等级，训练家属主为空。重复物种／物品在单次尝试内可能被抽到，最终是否接受由规则集整体校验决定（工厂规则含物种与物品不重复等，WP54）。

**对手侧**（交接点）：准备租借时先以“空排除名单”生成玩家候选，再以“玩家候选”为排除名单生成对手候选并**从中随机取3只**组队；准备交换时以“当前租借＋上一对手队伍”为排除名单生成新对手候选，同样取3只。对手训练家名与胜负台词、出场图形等会话包装由WP55。

## 3. 初次租借（C）

界面（租借模式）：标题“RENTAL POKéMON”；列表项为“名称 - 类别 Pokémon”（被选中的条目以红字标记）；帮助文本按已选数提示“选择第一只／第二只／第三只”。交互：

- 逐条浏览；选中菜单＝查看摘要／租借（未选时）或取消选择（已选时）／其它（保留的空命令，无行为）。
- 选满3只后弹出“这三只可以吗？”：确认→以所选3只（对象本身）返回并结束界面；取消→把刚选中的第3只取消选择，继续选择。
- 租借模式**不能退出**（不可取消）：没有取消命令、选择循环不接受返回键退出；界面返回值恒为3只对象列表。

提交（会话侧）：接收所选3只作为当前租借集合，**交换数＋1**（即使在初次选择也计数），随后提交队伍（进行中会立即写玩家队伍）。

## 4. 战后交换（C）

界面（交换模式）：标题“POKéMON SWAP”；首屏为当前租借成员＋“取消”；条目菜单＝摘要／交换／重新选择（重新选择无专属行为，仅回到列表）；第二屏为上一对手成员＋“交换用宝可梦”行＋“取消”：

- 在第二屏选中“交换用宝可梦”行→返回首屏重选；选中“取消”或按返回→询问“退出交换吗？”：确认→结束界面并按“未交换”返回；否认→留在第二屏继续。
- 在第二屏选中具体成员并确认“接受这只宝可梦吗？”→结束界面，并把**首屏所选租借槽位替换为第二屏所选对手成员的对象本身**（引用替换，不复制字段、不改属主、不动等级／经验／招式／持有物），返回“已交换”。

提交（会话侧）：仅“已交换”时**交换数＋1**并提交队伍；取消或退出不计数、不提交（队伍引用未变，界面内未发生替换）。

与对手的关系：交换来源固定为**上一对手的队伍**（上一场对手3只的快照引用）；准备交换时会先保存该快照再生成新对手，避免新对手生成覆盖来源。交换所得的成员来自对手队伍（其创建时以对手为属主，见WP55的设施个体创建）。

## 5. 与其它主规格的交界与不变量（D）

- **原队伍隔离**：租借集合与会话报名引用为同一引用（会话提交后玩家队伍即该集合）；玩家原队伍只在会话开始被快照、在取消／正常结束时恢复（WP55）。本包的任何界面与生成**都不写原队伍快照**，也不复制“全部字段”来模拟临时使用。
- **容量与位置**：临时人数（6／原最大值＋排除长度／3人对手）只用于生成与校验的临时设置，随后还原；正式队伍容量仍按WP25与WP54的报名规则。
- **计数**：交换数只在“租借确认”与“交换成功”两处＋1，且写入只在进行中生效（WP55）；取消、重选、退出均不计数。
- **合法性**：候选与对手都以规则集整体校验（工厂规则：成员限制与组合限制，WP54）；候选不足或无法凑合法组时按WP55所述的重试／报错边界（不伪造终止）。
- **队伍引用**：交换为同对象引用替换；其属主字段仍是创建时的对手（无属主转移代码），与“永久取得”不同层；跨场／暂停／退出后该集合由会话继续持有或恢复。
- **规则集对象副作用**：生成期间临时改写规则集人数并在成功路径还原；若生成中途报错（如空选择域、整体校验永不过、内容表缺失），人数设置可能停留在临时值（部分状态），无异常保护。
