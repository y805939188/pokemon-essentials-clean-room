状态：**ReviewPending（A～F：挑战身份与注册、会话状态机、对手与队伍生成、暂停／继续／取消／结束、原队伍与恢复接点及有界来源；首稿v1，尚未外审）**。2026-09-28；F13-04子范围，Combat Requirements／Creature-RPG／User Interface。只读基线 `8c5911e4a4b07b07e832e4bb0d5d8859e88b4a9b`，没有运行报名、战斗、生成器、事件或解释器。源码名只用于审计定位；不按参考类层级设计未来结构。

## 1. 目的、可见流程与状态边界（A）

本包回答“进入设施挑战后，会话如何推进与收尾”：挑战身份与规则怎样注册、参赛选择何时提交、对手与轮次怎样生成、胜场／交换计数何时写入、暂停／继续／取消／结束各自提交什么、玩家的原队伍何时被替换与恢复。它不设计未来会话对象或API，也不代WP56／57描述两种变体与租借交换的专用规则；单场的等级／经验／物品调整与还原主合同已由WP54闭合，这里只列会话级接点。

输入：挑战标识、轮次数、当前规则集、玩家当前队伍与多个体选择界面结果、设施训练家／宝可梦内容表、当前地图与玩家坐标、消息文本与训练家类型资源。输出：会话进行状态（进行中／暂停）、当前轮与下一对手索引、胜负与交换计数记录、决赛结果、玩家队伍引用替换与恢复、保存请求与地图刷新标记。

可见流程：进入设施（事件侧完成身份与注册）→ 从整队中选择报名／参赛成员（多选界面，可取消）→ 会话开始（立即保存并替换玩家队伍引用）→ 逐场与设施训练家战斗（单场包装治队伍、临调等级并事后还原）→ 每胜递增轮次与胜场、按规则可交换（Factory，见WP57）→ 中途可暂停（保存）与继续（保存）→ 撤销会话会恢复原队伍、正常结束或按胜负回收并保存。接收接待、收费、BP与奖品文本的**实际发放事件**不在本快照脚本内（U01），不因字段或消息存在而假设已发奖。

会话对象是**全局存档的一部分**（懒创建于全局状态），跨保存／加载存续；工作区只描述静态可复核的字段与调用关系，不声称运行序列。

## 2. 会话状态机与写入次序（B）

### 2.1 挑战身份、注册与规则生成

- `set`（事件入口）：接收挑战标识、轮次数与规则对象；登记该标识的类型记录：双打位取自标识中是否包含“double”子串；固定按3只登记；设施类型默认“塔”，标识以“factory”开头者为“工厂”；模式默认“普通”，标识以“open”结尾者记“开放”。随后请求调试用“写杯”记录（仅调试入口条件，WP54已述；不作为正常会话写入）。
- 类型记录按标识惰性创建（缺失即新建），承载历史／当前胜场与交换计数；新记录各计数全为0。
- 规则生成（仅在规则对象缺省时按类型数据重算）：按设施类型选择战斗类型（Palace／Arena／塔式；Arena强制单打）；按模式装配规则集与开放等级调整——开放档下限30、帐篷档下限60、普通档与50级规则；最后附加单打或双打规则。实际登记路径在`set`已持有规则对象，故不重复重算；**帐篷档（60）在`set`路径不可达**（其模式计算只会产出开放档或普通档；脚本内没有其它会以帐篷档登记的调用者），保留为具名不可达分支。
- `register`的工厂分支：登记额外数据（工厂租借／交换状态，规则见WP57）并把参赛数强制为3、设施类型回落为塔式；额外数据在会话数据重置时清除。

### 2.2 会话字段、查询与计数

会话数据字段（来源＝开始／登记／事件推进，读取者＝事件、界面、生成与单场包装）：

| 字段／查询 | 写入者与时机 | 读数与终点 |
| --- | --- | --- |
| 进行中 | 开始置真；取消／正常结束重置 | 事件与生成判断是否可推进 |
| 暂停中 | 暂停置真、继续置假；开始置假 | 事件显示“暂停”与恢复入口 |
| 决定 | 开始清0；单场／裁判／条款写入（WP42） | 结束与计数写入的判据 |
| 胜场 | 开始＝类型记录当前胜场；每胜＋1 | 类型记录回收、生成表输入 |
| 交换数 | 开始＝类型记录当前交换数；Factory选入与成功交换各＋1（WP57） | 类型记录回收、工厂生成输入 |
| 当前轮 | 开始＝1；每胜＋1；回绕决定比赛是否超出 | 与轮次上限比较得“已结束” |
| 轮次上限 | 开始写入（≤0报错） | 生成条数与结束判据 |
| 训练家名单 | 开始生成若干条（去重） | 取“当前轮−1”位置的对手索引 |
| 报名队伍／原队伍 | 选择界面写入报名引用；开始时快照原队伍并在有报名时替换玩家队伍 | 结束／取消恢复原队伍 |
| 开始位置 | 开始时记录地图与坐标 | 暂停／继续在其位置保存；传送回开始点 |
| 额外数据 | 工厂登记时创建 | 生成／交换分支（WP57） |

- “已结束”判据：不在进行中、或决定非0、或当前轮超过轮次上限。
- `data`查询仅在“进行中且当前挑战有效”时返回类型记录的**副本**（显示用）；历史／当前胜场与交换数另有逐挑战读取接口（读活记录，不读副本）。
- 每场胜利的写入只发生在进行中；交换计数的写入只发生在进行中或工厂流程（见WP57）。
- 生成按“当前轮−1”取下一对手；名单长度即轮次数。名单生成按“当前胜场＋已生成条数”逐条抽索引，重复索引**跳过重抽**，直到凑满；若可用不同索引少于轮次数，存在不终止路径（空内容表则先因采样空区间报错）。开始会在这些写入之后请求一次“安全保存”。
- **不变量**：原队伍快照只由开始建立、只由取消或结束恢复；除“进行中的报名／租借提交”外不改玩家队伍引用；未决定的会话不落盘；胜场／交换计数只在进行中（或工厂流程）写入；暂停与进行中互斥（继续即清暂停）。

### 2.3 队伍引用替换与恢复

- 报名：多选界面返回所选个体列表或取消（无返回）。返回非空列表时写入报名引用并返回“已选择”；**返回空列表时仍会写入空报名引用**（引用被替换为空）但整体返回假；取消（无返回）不写入。
- 开始：先快照玩家当前队伍为“原队伍”，若有报名引用则把玩家队伍**替换为该引用**，随后保存。
- 会话进行中（含工厂选入与交换后）再次提交报名／租借集合时，因处于进行中会**立即写玩家队伍**，同时更新报名引用。
- 取消：若存在原队伍快照则恢复，随后整体重置（不保存、不刷新地图）。
- 正常结束：先无条件恢复原队伍；若不在进行中则到此为止；否则按“决定非0”决定是否保存，重置并标记地图刷新，最后按需保存。
- 类型记录回收：结束时若当前挑战有效，把本会话的胜场／交换数写入记录：**未决定**只把“当前”归0（不动最大与上次）；**胜利**把“当前”写为本会话数并更新最大与上次；**失败**把“当前”归0并更新最大与上次。回收在会话数据重置之前进行。

### 2.4 暂停、继续与保存点

- 开始：替换队伍后立即保存（安全保存）。
- 暂停：置暂停真并保存；继续：清暂停并保存。
- 暂停／继续的保存发生在“开始位置”：实现会临时把地图与玩家坐标置为开始点、保存、再恢复原地图与坐标与朝向。
- 正常结束：仅当决定非0时在重置后保存（此时队伍已恢复、会话已清空），并请求地图刷新。
- 取消与未决定的结束路径**不触发保存**；传送回开始点只在当前场景是地图场景时执行（先解除骑乘）。

### 2.5 对手与队伍生成数据

**训练家索引抽取**（按当前胜场在内容表中选择抽取区间；表按内容表模板长度300设计，实际按内容表长度等比例缩放：起点与长度均乘以“实际长度/300”取整后随机）：

| 触发胜场下限 | 区间起点（模板） | 区间长度（模板） |
| ---: | ---: | ---: |
| 0 | 0 | 100 |
| 6 | 80 | 40 |
| 7 | 80 | 40 |
| 13 | 120 | 20 |
| 14 | 100 | 40 |
| 20 | 140 | 20 |
| 21 | 120 | 40 |
| 27 | 160 | 20 |
| 28 | 140 | 40 |
| 34 | 180 | 20 |
| 35 | 160 | 40 |
| 41 | 200 | 20 |
| 42 | 180 | 40 |
| 48 | 220 | 40 |
| 49 | 200 | 100 |

规则：取“触发下限不超过当前胜场”的**下限最大**一行；胜场为负时无行可取，返回0；返回“缩放起点＋随机(0..缩放长度−1)”。若缩放长度为0，随机区间为空（错误路径）。

**对手个体值阶梯**（按对手索引）：索引<100→3；<120→6；<140→9；<160→12；<180→15；<200→18；<220→21；其余31。

**对手组队**：等级取规则集建议等级；训练家名与胜负台词取自消息集（训练家名、设施结束台词胜／负）；宝可梦候选为该训练家名单指向的内容表条目。若名单条数不超过规则建议数，按名单顺序全部生成；否则反复清空并按名单**有放回**随机取条生成至建议数，直到规则集校验通过（**无迭代上限**，也无候选去重；内容表为空或名单指向缺失时先报错）。

**内容表装载**：按挑战标识取“首个非默认且其挑战标识列表包含本挑战”的条目；否则取首个默认条目；都没有则空。训练家数组与宝可梦数组分别返回。

**内容表数据来源与结构**（编译器；生成器属WP76，不在本包执行）：`PBS/battle_facility_lists.txt`节为默认或训练家列表，含训练家文件名、宝可梦文件名、挑战标识列表（默认节无挑战标识）；编译产物每条形如：训练家数组、宝可梦数组、挑战标识、训练家文件名、宝可梦文件名、是否默认。当前快照该PBS含1个默认节与4个杯赛列表节。训练家条目字段：类型、名称、开场白、胜台词、负台词、候选编号列表；宝可梦条目为“物种;物品;性格;努力项列表;招式列表”文本，按此编译为设施个体数据。
**设施个体创建**：按物种、等级、训练家属主（对手有主、租借无主）、性格、全部个体值设为给定值、努力值平均分配到所列努力项（每项=总量/项数）、现有招式按列表补齐（其中“报恩”在“迁怒”存在时替换）、亲密度0、随机32位个人值、并重算能力值。

### 2.6 工厂分支接点（细则见WP57）

登记工厂时创建额外数据并强制3只。会话进行中的工厂流程由事件驱动：准备租借（生成候选、取对手）、选择租借（租借界面返回所选后**交换数＋1**并提交队伍）、准备交换（保存旧对手队伍、生成新对手）、选择交换（仅成功交换时**交换数＋1**并提交队伍；取消不计数）。工厂对决包装改走工厂分支的单场包装；其余会话推进与普通会话相同。

### 2.7 界面、消息与事件接点

- 报名多选界面：以规则集驱动整队多选；界面取消或空结果不写报名；含“可报名／不可报名”显示与顺序选择的主交互在UI／队伍界面已审范围（WP54已述接点）。
- 资格快查：以规则集“存在合法整队”检查玩家当前队伍，供事件侧判断。
- 对手图形：按下一对手的训练家类型取角色图形；缺失或异常回落到“NPC 01”。
- 开场白：不在进行中显示省略；否则取下一位对手的开场白文本。
- 事件侧进行中查询：地图事件可经全局会话查询是否在挑战中（用于门禁／对话）。
- 传送回开始点：仅地图场景执行；设置玩家转移目标为开始位置、面向向上、解除骑乘并执行转移。

## 3. 单场包装与会话的交界（C）

- 单场包装（WP54已闭合的合同，本包只列会话级行为）：战前先治玩家队伍，再记录调整前等级与双方物品，按规则调整双方等级；创建战斗场景与战斗类（塔式＝可记录战斗；Palace／Arena＝对应可记录变体，记录／回放完整合同留WP58）；战斗后还原等级、治疗双方并清除Mega／原始回归、恢复双方物品；仅当决定为胜／负／平时保留战斗记录转储；统计玩家胜／负计数；以“决定是否胜利”为返回。
- 调试跳过路径：调试模式按住Ctrl时跳过战斗，显示跳过与胜利消息、清战斗记录并直接返回真（**不进入任何调整／还原**；仅调试）。
- 会话与单场分工：会话负责轮次、对手、计数、保存与队伍引用；单场负责等级／物品／治疗的瞬时调整与还原。等级调整公式、按索引还原与物品记录由WP54；持物恢复适用性由WP50；终局与裁判由WP42。
- 记录／回放交出点：会话对决的胜／负／平决定会产出战斗记录并写入临时记录，事件可在战后显式持久化为“上次战斗”（记录内容、回放控制与版本边界属WP58，不在本包展开）。

## 4. 失败、取消与异常边界（D）

- 轮次数≤0：开始中途报错；**此时进行中已置真、当前轮已置1、名额未写入**，即存在部分已提交状态，无回滚。
- 空训练家内容表：抽取阶段先因空区间报错；名单指向缺失时生成处报错。
- 名单去重不终止：若可抽取的不同索引少于轮次数（例如内容表过小或区间过窄），名单填充循环无法凑满，无迭代上限与兜底。
- 生成不终止：对手组队在候选集合无法通过规则校验时无限重试（有放回抽取，可能长期不满足）；实现没有次数上限或放弃路径。
- 缩放长度为0：抽取返回空区间的随机调用，属错误路径（模板长度300在内容表过小时产生）。
- 取消早于开始：无原队伍快照时取消只做重置；未进行中的结束会无条件执行“恢复原队伍”（空操作）后返回。
- 保存失败：保存调用没有保护、回滚或重试包装；失败会向上传播，此时队伍替换／暂停标记等已写入。
- 对手信息缺失：名字、台词或图形缺失按各入口的回落（图形回落“NPC 01”；文本缺失处依消息集表现，未补造）。
- 奖励与收费：本快照脚本没有BP／金钱／奖品写入；接收事件缺失时保留U01，不因文本存在推断已发奖。
