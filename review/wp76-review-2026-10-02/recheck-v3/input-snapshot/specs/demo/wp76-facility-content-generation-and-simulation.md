## 1. 目的、范围与非目标

### 1.1 目的

从作者（游戏制作者）视角规定**战斗设施参赛内容的生成、评估与写出**能力：

- 设施挑战设置时联动询问是否生成参赛队伍列表（`BattleChallenge.set` → `pbWriteCup`，调试门）。
- 复用已有列表或触发全新生成（`pbGenerateChallenge`）：候选个体随机构造、合法性筛选、去重与补充、组队迭代、模拟对战评级、分层汇集。
- 训练家池生成与分配（`pbTrainerInfo`）：训练家选择/随机生成、按位置与类型权重分配宝可梦、写回列表数据并反写 PBS。
- 生成侧与正式战斗规则的边界：生成器的筛选/估分是独立近似，不回写为 WP54/WP55/WP51/WP52 的运行合同。

### 1.2 范围（A～F）

- **A 入口与触发**：设施设置调用点、外层调试门、生成/复用询问与确认。
- **B 复用已有列表**：列表选择、挑战 ID 迁移、默认列表特例。
- **C 候选个体生成**：物种/等级/性格/EV/道具/招式的随机构造与拒绝采样、合法性终检。
- **D 队伍组建与迭代**：队伍取样、补充、同类/重复判定、同种上限、更替/退休/删除、分层汇集。
- **E 模拟对战与评级**：真实无视觉战斗与估算分支分流、估分公式、Glicko-2 评级更新、备选 Elo 定义。
- **F 训练家池与写出**：训练家选择/生成、宝可梦分配、列表数据写回与 PBS 反写、编译往返、检查点文件。

### 1.3 非目标

- 不重提取 WP54（参赛资格/等级调整/条款规则——生成器消费的 `ruleset` 合同以其已通过边界为准）、WP55（设施会话）、WP51/WP52-A/B/C（AI 与评估——真实战斗分支只经 `createBattle` 交界调用，其内部不展开）、WP57（工厂租赁——`pbBattleFactoryPokemon` 是另一条生成路径，不属于本包）、WP72（debug 菜单框架）、WP73-A（编辑器反写边界）、WP75（编译驱动与反写管线——本包只引用 `write_trainer_lists` 在其中的位置）；以上以依赖身份引用。
- 不运行生成器/真实对局/Monte Carlo/编译器/游戏/反序列化/参考行为模拟器；不操作工程或存档；不写框架实现或参考行为模型；demo 事件可达性归 WP77。
- 生成结果的对局表现（真实战斗胜负分布、评级收敛的实际数值）未验证——只登记静态可推导规则。

## 2. 概念与术语（实现中立）

- **挑战 ID（challenge id）**：设施挑战的字符串标识（如 `pokecupsingle`）；生成产物（检查点、新列表条目、新 PBS 文件）均以其为名。
- **列表（trainer list）**：`Data/trainer_lists.dat` 中的一条六元条目——训练家表、宝可梦表、挑战 ID 数组、训练家文件名、宝可梦文件名、默认标志；**默认列表**（默认标志为真）是无 ID 命中时的回退。
- **候选个体（candidate）**：`pbRandomPokemonFromRule` 拒绝采样产出的单个宝可梦；**池（party）**：候选的暂存集合——**不足 20 才补充**，是补充目标而非始终成立的容量上限（种子与退休成员回池可令其超过 20，§6.2/§6.4）。
- **队伍（RuledTeam）**：从池中按建议数量取出的可评级小队，携带评分（`rating`＝胜率百分数）、场次（`games`＝当前历史长度）与累计场次（`totalGames`）。
- **真实分支**：1% 概率触发的真实无视觉战斗；**估算分支**：99% 概率的类型效果打分近似。
- **检查点文件**：生成中间产物 `<id>.rxdata`（池）与 `<id>_teams.rxdata`（队伍库），位于游戏根目录（非 `Data/`）——崩溃/中断后可从最近检查点继续的既有设计，如实登记。
- **审计名**：仅作追溯标识的方法/类名（如 `pbRandomPokemonFromRule`、`RuledTeam`、`PlayerRating`）；行为描述不依赖其内部实现结构。

## 3. 入口与触发（A）

### 3.1 设施设置调用点

- `BattleChallenge.set`（审计名；WP55 会话交界；事件侧由设施接待事件触发，demo 可达性归 WP77）：登记挑战后**无条件调用** `pbWriteCup`（审计名）——生成询问是设施设置流程的内嵌步骤，不是独立菜单项（`001_Challenge_BattleChallenge.rb:18–26` 定点）。
- **外层调试门**：`pbWriteCup` 以调试标志为进入条件，**非调试模式下整段不执行直接返回**——正式运行配置下生成/复用询问不可达（`001_ChallengeGenerator_Data.rb:276–277`）。

### 3.2 生成/复用询问（A-2）

- 先读 `Data/trainer_lists.dat`（缺失/异常 → 空表），把各列表显示名（文件名去 `.txt`，默认列表名前加 `*`）组为选项。消息入口的**取消返回值与初始光标是两个独立参数**（`011_Messages.rb:687–705, 721–750` 定点）：第三参数给按取消键时返回的选项位置，第五参数给初始光标位置。
- **无任何列表**：两选项消息「Generate Pokémon teams for this challenge?」（YES／NO）——**初始光标在 YES**；按确认（YES）→进入「新生成」支；按取消 → 映射到 NO 返回。
- **已有列表**：三选项消息同题（NO／YES, USE EXISTING／YES, USE NEW）——**初始光标在 NO**；按取消 → 映射到 NO 返回。
- **新生成支**：再经确认消息「This may take a long time. Are you sure?」（Yes／No——**初始光标在 Yes，按取消映射到 No**）——**取消或选 No 即返回**（不产生任何生成）；确认后创建消息窗口、进入长任务（§4–§8）：进度回调**只在被调用到时**检查距上次刷新是否满 5 秒，满则刷帧；**有文本消息时立即显示并刷新**——不承诺每 5 秒必有文本、也不承诺长计算段内持续刷新。完成后窗口销毁并提示「Team generation complete.」。
- **取消语义**：询问/确认阶段的取消只阻止生成启动；**已启动生成无中途取消路径**（进度回调只刷帧/显示，不查取消），如实登记。

## 4. 复用已有列表（B）

- 选择列表（默认取消值 −1；**取消选择＝不改任何数据**直接返回）。
- 选中后提示该挑战将使用所选列表的宝可梦；随后**把本挑战 ID 从所有非默认列表的挑战数组中移除**（while 循环删除全部出现），再**仅当所选列表非默认**才把 ID 追加进其挑战数组——**选默认列表时 ID 被整体迁出后不再追加**（默认列表经回退支自然覆盖，§8.1 查询顺序）。
- 写回 `Data/trainer_lists.dat`、刷帧、调用 `Compiler.write_trainer_lists` 反写 PBS（§8.4）——复用分支也触发全量列表反写。
- 列表为空时选择步不会出现（§3.2 两选项形态）；**选择默认列表与选择非默认列表的迁移结果不同**，不互相替代。

## 5. 候选个体生成（C；`pbRandomPokemonFromRule` 拒绝采样）

### 5.1 总体结构

外层为**无迭代上限**的拒绝采样循环：逐段构造物种→EV→性格→道具→招式，任一约束不满足即重掷对应段或整体重采；最终以 `rules.ruleset.isPokemonValid?` 为**唯一出口门**（WP54 合同）。**无可满足输入时本循环不终止**（如实登记，§10）。

### 5.2 物种与等级（C-1）

- 等级恒为 `rules.ruleset.suggestedLevel`（WP54）；物种从全部物种键等概抽样，**只收形态 0**。
- 每轮抽 0–19 均匀整数 r，按外层迭代**奇偶交替**两套偏好门（`002:152–170` 定点）：
  - 偶数轮：拒绝 `r<16 且 BST<400`；拒绝 `r<13 且 BST<500`——偏好中高 BST。
  - 奇数轮：拒绝 `BST>400`；拒绝 `r<10 且非宝宝形态`——偏好低 BST/宝宝。
  - 两轮共通：拒绝 `等级 < 该种最低等级`；拒绝 `r<10 且为宝宝形态`；拒绝 `r<7 且仍有进化形`。
- 各项族事实（BST/宝宝种/最低等级/进化形）经**全局缓存**按种 memoize（§9.1）。

### 5.3 EV 与性格（C-2；R04 修订——强调条目可重复）

- EV 初始集合：每个主能力值独立以 50% 概率入选——**此阶段无重复**（先选集合、后续按道具/招式再调整）。
- 性格抽样：中性（无能力修正）或 LAX/GENTLE → 仅 5% 接受；有修正性格：若其**提升项不在 EV 集合**→60% 拒（无提升强调）；若其**降低项在 EV 集合**→90% 拒（有降低强调）——性格与 EV 强调一致性是概率门，不是硬约束。
- **后续调整的重复语义分两类（R04 修订）**：**三种树果门**（§5.4）只在对应强调**不在列表**时才按其 50% 抽样补入一条——**已存在时不追加、也不消费该次抽样，树果不会产生重复条目**；**可能产生重复的是纯物理/纯特殊接受后调整**（§5.6）的 80% 追加——**追加、不去重**，同一能力可出现多条；删除操作则**清除该能力的全部条目**。构造阶段按**含重复条目的总数为分母**均分（§5.7）。

### 5.4 道具（C-3；R07 修订——41 项全表与 13 专属门）

- 候选表为独立输入数据，共 **41 项**（按源表序）：ORANBERRY、SITRUSBERRY、ADAMANTORB、BABIRIBERRY、BLACKSLUDGE、BRIGHTPOWDER、CHESTOBERRY、CHOICEBAND、CHOICESCARF、CHOICESPECS、CHOPLEBERRY、DAMPROCK、DEEPSEATOOTH、EXPERTBELT、FLAMEORB、FOCUSSASH、FOCUSBAND、HEATROCK、LEFTOVERS、LIFEORB、LIGHTBALL、LIGHTCLAY、LUMBERRY、OCCABERRY、PETAYABERRY、SALACBERRY、SCOPELENS、SHEDSHELL、SHELLBELL、SHUCABERRY、LIECHIBERRY、SILKSCARF、THICKCLUB、TOXICORB、WIDELENS、YACHEBERRY、HABANBERRY、SOULDEW、PASSHOBERRY、QUICKCLAW、WHITEHERB。**先以 1/40 直取 LEFTOVERS**，否则表内等概抽。
- **物种限定门共 13 个**：LIGHTBALL→皮卡丘、SHEDSHELL→佛烈托斯/盔甲鸟、SOULDEW→拉帝欧斯/拉帝亚斯、ADAMANTORB→帝牙卢卡、PASSHOBERRY→大钢蛇、BABIRIBERRY→班基拉斯、HABANBERRY→烈咬陆鲨、OCCABERRY→巨金怪、CHOPLEBERRY→月伊布、YACHEBERRY→土台龟/天蝎王/哈克龙、SHUCABERRY→席多蓝恩、DEEPSEATOOTH→珍珠贝、THICKCLUB→卡拉卡拉/嘎啦嘎啦；另有 **FOCUSSASH 为非物种条件门**（BST>450 时 80% 重抽），与 13 门分列。
- 龙之/沙鳞/蒲玲果（LIECHI/SALAC/PETAYA）**只在对应能力（攻击/速度/特攻）不在 EV 列表时**才按 50% 抽样补入一条——**已存在时不追加、不消费该次抽样**（R04：树果门不产生重复；例：前态 [HP、攻击] 选 LIECHIBERRY 后仍为两条，不会变成 [HP、攻击、攻击]；同一前态经纯物理接受后 80% 追加命中才可能出现第三条攻击强调）。
- 等级段替换：**等级 <10**（且 ORANBERRY 已注册）→ 1/40 或当前为 SITRUSBERRY 时换 ORANBERRY；**等级 >20**（且 SITRUSBERRY 已注册）→ 对称替换。
- **无效道具不在抽样阶段统一剔除**：中间表示构造时经存在性尝试查询，无效/不存在的道具转为**空**（`002_Challenge_Data.rb:154–163` 定点）。

### 5.5 招式合法集（C-4；`pbGetLegalMoves2`；R05 修订——首次入集与剪枝自删除）

- 来源三路**按序处理**：**升级招式**（学习等级 ≤ 当前等级，权重 2）→ **机器招式**（教学招式 ∩ 全部机器道具招式，权重 0——机器表全局缓存一次构建）→ **宝宝种蛋招式**（权重 2）。**同一招式已有副本时后续来源不再加权**（去重检查在入集前）；**某来源首次加入恰好产生零副本时**（如机器来源权重 0），该招式未实际入集，**后续来源仍可加入**。
- `addMove` 权重（同一招式可多次入集实现偏置）：默认 base+1；无效果码且威力 ≤40 → base；威力 ≤30 或 GROWL/TAILWHIP/LEER → base；威力 ≥60 或 REFLECT/LIGHTSCREEN/SAFEGUARD/SUBSTITUTE/FAKEOUT → base+2；威力 ≥80 且普通系 → base+3；指定高价值件（PROTECT/DETECT/TOXIC/AERIALACE/WILLOWISP/SPORE/THUNDERWAVE/HYPNOSIS/CONFUSERAY/ENDURE/SWORDSDANCE）→ base+3。**BUBBLE 与 BUBBLEBEAM 永不加入**。
- 剪枝（按集合内两两比较；**比较资料是剪枝前构建的初始快照，删除作用于正在遍历的活集合**——有顺序影响，不是顺序无关的理想优势筛选）：**必中**（命中 0）招式删除同系无效果码且威力不高于它的招式——**无身份排除，满足条件的招式连同自身全部副本一并删除**（固定数据中 AERIALACE、SWIFT 正具备此条件——必中、无效果码、威力 60，`PBS/moves.txt:2990–3000, 5141–5151`）；同效果码双变化招删低命中者；**剧毒**（BadPoisonTarget）删除**中毒**（PoisonTarget）；同效果码同系攻击招的剪枝需**同时**满足（R05 修订——PP 门不是充分条件）：**发起方有伤害**（威力非零）＋**PP 门**（发起方 PP 为 15/10 或与对方相同）＋**强度条件**（威力更高，或同威力而命中更高）→ 删除另一方——**PP 门属于发起方**：满足 PP 但强度不足不剪（负例见 M07-c）；PP 门不满足同样不剪（成对方向相反对照如实登记）。
- 合法集按**等级全局缓存**（等级变化即整体重建，同种缓存命中不重算——Sketch 改写见 §5.6）。

### 5.6 招式选取与一致性（C-5；R06 修订——共享缓存与 Sketch 豁免）

- **Sketch 特例（改写共享缓存）**：合法集首项为 SKETCH 时置 sketch 标志，并把**缓存列表本身**的前四个位置逐个改写为随机招式（等概随机，排除 Struggle 与 ReplaceMoveWithTargetLastMoveUsed 两效果码）——**列表不足四项会被扩展，超过四项的尾部保留**。**相同等级同种的后续采样看到的是改后的缓存**（首项通常不再是 SKETCH，sketch 标志也不再置位）；**切换等级才清空合法集缓存**（`002:193–195, 259–264` 定点；SMEARGLE 全级段仅 SKETCH 的固定数据见 `PBS/pokemon.txt:6191–6204`、`PBS/moves.txt:6395–6403`）。
- 合法集为空 → **整体重采**（外循环继续）；唯一招式数 <4 → 直接采用（不补齐，**不经过本段组合门与 SILKSCARF 门**）；≥4 → 选取循环：
  - 从加权集随机取至满 4 个不同招式；候选有同系更大威力招时 50% 跳过（`hasMorePowerfulMove`）。
  - 组合约束：**蓄力**（STOCKPILE）与**喷出/吞下**（SPITUP/SWALLOW）必须成对——**sketch 标志豁免此配对要求**；**梦话/鼾声**（SLEEPTALK/SNORE）各需**睡觉**（REST）同在，否则仅在（sketch 或合法集本无 REST）时按 20% 放行——**梦话与鼾声各有独立的睡觉例外门**：两者同时出现而无 REST 时，满足例外前提也**需两道门分别通过**。
  - 物理/特殊一致：全队无物理招而 EV 含攻击 → 80% 重掷；无特殊招而 EV 含特攻 → 80% 重掷（物理/特殊/普通系标志**只统计威力非零招式**）。
  - 总威力门（**两门共用同一次十面抽**，不是两个独立随机事件）：该次抽 >6 且总威力 >180 → 拒；同次抽 >8 且总威力 >140 → 拒；总威力 0 → 95% 拒。
  - 接受后调整：纯物理队 → 80% **追加**攻击 EV（可重复，§5.3）、80% 清除特攻 EV 全部条目；纯特殊队对称；**SILKSCARF 在无普通系攻击招时换 LEFTOVERS**（普通系变化招不足以保留）。
- **道具-招式终校**：LIGHTCLAY 无光墙/反射壁 → LEFTOVERS；BLACKSLUDGE 非毒系 → LEFTOVERS；HEATROCK 无大晴天 → LEFTOVERS；DAMPROCK 无求雨 → LEFTOVERS；含 REST → 33% 换 LUMBERRY、再 25% 换 CHESTOBERRY（两段独立可叠加覆盖）。

### 5.7 个体构造（C-6；`PBPokemon.createPokemon`；R04 修订——均分分母含重复条目）

- 中间表示 `PBPokemon`（物种/道具/性格/四招式/EV 条目）→ 实例化：个体值全主能力 31、随机 32 位 personalID、亲密度 0、RETURN 转 FRUSTRATION（存在时）、**EV 均分**——**分母为含重复条目的条目总数**，逐条目对该能力写同一整数值（重复写**不累加**）、重算数值。确定性向量（EV 上限 510）：空条目 → 各能力 0；单条目 → 该能力 510；两条不同 → 各 255；**[HP、攻击、攻击] → 分母 3 → HP 与攻击各 170、合计 340**（不是两能力各 255）。**单条目 510 超过单项上限 252**——生成路径**不自动夹回 252**（该写入与最终规则是否另行拒绝分开，WP54 消费合同）。
- `PBPokemon.fromPokemon`（反向，写表用）：招式位按序取 id（空位 nil）、**EV 收录阈值为 >60**（每主能力独立判定）。

## 6. 队伍组建与迭代（D）

### 6.1 重复判定（D-1；`isBattlePokemonDuplicate`）

- 物种不同 → 必不重复。同种时两判据：
  - **招式判据**：四个招式位**按槽位原序**（含空位占位）逐项相等即重复——源中有一处对两数组求紧凑/排序但**结果未写回**（计算被丢弃），故实际比较是**槽位序敏感**的（如实登记，不补「意图」）。
  - **属性判据**：道具、性格、全部主能力 EV 值逐项相等即重复。
- 判据间为「或」：任一成立即视为重复。

### 6.2 补充与同种上限（D-2；R08 修订——补充目标 ≠ 容量上限）

- **补充**（`pbReplenishBattlePokemon`）：**池不足 20 才反复生成候选**、仅当不与池中任何成员重复才入池——**20 是补充目标而非容量上限**：已有大池不截断，种子填充与退休成员回池均可令其超过 20（§6.4）。候选无限重试，无进度上限登记。
- **去重**（`pbRemoveDuplicates`）：顺序扫描，重复者丢弃；**同种成员超过 10 时删除该种最早成员**（先进先出顶出）——同种上限 10 **仅在显式去重阶段生效**（按重复判据之外的纯物种计数），其它阶段不受此限。

### 6.3 队伍取样（D-3；`RuledTeam` 构造）

- 从池中按 `suggestedNumber`（生成阶段使用**设为 2 的规则副本**——每次取出 2 只，§6.4）**逐个随机抽取并即从池中删除**（池被消耗）；组成后过**该规则副本**的 `ruleset.isValid?` 团队校验，不过则**重新抽取**（无迭代上限；池随每次尝试净消耗——耗尽早于满足时的行为无保护，如实登记）。
- 新队伍：评分对象新建（实际使用变体的初值 1500/350/0.9，§7.4）、历史空、累计已结算场次 0。

### 6.4 生成主流程（D-4；`pbGenerateChallenge`；R08/R09/R10 修订）

- **规则阶段切换（R10）**：开始即把规则**复制副本并把队伍数量设为 2**——**候选、组队与模拟全程使用该副本**；**11 轮结束后恢复原挑战规则**，**分层与训练家分配重新按原规则消费**（最终合法性、建议等级、可组队要求均按原规则；数量 2 不是全流程不变量）。规则副本经构造保留数量与三类规则、最小数量按副本自身语义（WP54 引用，`002_Challenge_Rulesets.rb:13–25, 44–77` 定点）；**建议等级随规则数据而异**——普通杯赛规则下副本与原规则一致，独立自定义规则（如带总等级限制的子集规则）下二者可不同，不套用杯赛必然不变的结论。
- 从检查点读池与队伍库（缺失/异常 → 空）。
- **种子填充**：队伍库 <10 且既有宝可梦表（§8.1 查询）非空 → 逐条按**副本**建议等级、个体值 31 实例化，合法者入池（可使池超过 20，R08；随后 §6.2 去重）。
- **常量**：队伍库**补齐目标 600**（非始终成立的上限，见下）、高分线 65、低分线 40、**迭代 11 轮**。
- 每轮迭代：
  1. **写池检查点**；进度消息「Generating teams (i of 11)」。
  2. 逐队伍扫描（先补充池至 20）：评分 <65 且累计场次 ≥80 → **替换为新队**；成员数 <2 → 替换；**下标 ≥600 → 删除**；累计场次 ≥250 → **退休**（成员回池后替换）；评分 <40 → 替换。五支按序互斥（首命中支生效——各支以更早分支不成立为前提）。**删除后游标仍前进**：被删位置后移入的队伍**本轮被跳过**——例：602 支均不满足前两支替换条件的队伍，下标 600 删除一支后游标越过，本轮可留下 601 支；**不能承诺任何检查点的库长不超过 600**（超额队伍也可能先命中低分/场次替换支而非删除支）。
  3. **写队伍库检查点**；队伍库补至 600（每队建前补充池）。
  4. **写池检查点**；按评分降序排；进度消息「Simulating battles (i of 11)」。
  5. 模拟（§7）：每个发起位置**无条件抽 5 次对手、只用最后一次**（R09）——第 5 次仍为自身则本轮跳过（**前四次抽到的有效对手不被采用**；库长 600 时跳过概率为单次 1/600，不是五连自对的概率）；对局双方**都**记录场次，故每队本轮新增场数不固定；**续战门取全库历史场次的整数平均 <12**（不是每队都达到 12）→ 全员续战；达到 → 全员 `updateRating`（评级结算并清历史，§7.4）后本轮收束；按评分降序、**写队伍库检查点**。
- 11 轮后：池清空；队伍库**升序**遍历，**评分 >65** 的队伍成员全部入池（升序遍历＋条件跳过，不提前终止）；去重；「Writing results」；**恢复原规则**后**分层**（§6.5）；进入训练家池（§8）。

### 6.5 分层（D-5；`pbArrangeByTier`；R10/R18 修订）

- 九层限制器（`withRestr` 构造，`_rule` 入参未用，如实登记）：T0＝BST 0–500 非传说；T1＝BST 380–500 非传说；T2–T5＝BST 400–555 非传说（四层同构）；T6＝BST 580–680 **仅传说**；T7＝BST 500–680 非传说；T8＝BST 580–680 **不限**。
- **传说判定**：无性别且蛋群含「未发现」即传说（`NonlegendaryRestriction` 取反即仅传说；`InverseRestriction` 为通用取反包装）。可入层集合示例（R18）：BST 300 非传说 → 仅 T0；BST 590 非传说 → T7 与 T8；BST 590 传说 → T6 与 T8。
- 定位：逐个候选（先过**原规则**合法门）求其**可入层集合**——**通过原规则但无可入层者被丢弃**；有则可入层时，按其在输入序列的相对位次取 `可入层数 × 位次 ÷ 总数`（整除）映射到可入层之一——输入序列已被评分隐式排序（弱→强），位次越后落层越高。
- 层内按 BST 升序（同 BST 按物种 id 升序）；九层顺次拼接为最终宝可梦表。

## 7. 模拟对战与评级（E）

### 7.1 分流（E-1；`pbRuledBattle`）

- 每场以 **1%（百面抽中 0）走真实分支**，99% 走估算分支；结果三分：队 1 胜（1/0）、队 2 胜（0/1）、平局（-1/-1）记入双方历史。

### 7.2 真实分支（E-2）

- 双方成员**等级归一**为建议等级（不一致才改并重算数值）；构造两名 NPC 训练家（类型取训练家类型表**首项**，名 PLAYER1/PLAYER2），记录原持道具。
- 以 `Battle::DebugSceneNoVisuals` 无视觉场景经 `rule.createBattle` 起战（WP54 交界）；三个标志分别为**调试＝真、玩家方 AI 控制＝真、内部战斗＝假**（R12）——**主命令路径因此交由 AI 选择**（命令阶段对 controlPlayer 侧同样走 AI 默认指令，`009_Battle_CommandPhase.rb:198–230` 定点），**双方策略不靠场景的随机菜单辅助入口决定**；`pbStartBattle` 的返回即胜负（1/2，其它按平局支记）。
- **场景辅助入口合同（仅当被直接调用时；与实际模拟消费路径分开，R12）**：主命令辅助菜单——Bag 1/15 触发；**Call 仅在未选中 Bag 后再以 1/10 触发（整体 (14/15)×(1/10)＝7/75）**；否则 Fight。出招辅助入口以「由调用方 `yield` 门控、至多 50 次」形式随机——**其内部使用的单数招式访问在当前 Battler 定义中无对应接口**（仅有复数招式访问器，`001_Battle_Battler.rb:12` 定点）——**直接调用该辅助入口会抛出访问异常；但此辅助问题不反推 AI 主路径必然失败**（如实分开，不修参考）。目标辅助入口：候选＝对方侧在场者集合，**无候选返回 −1**；换宠辅助入口：候选＝同队可换入位置，**无候选无返回**；道具菜单恒 -1；确认消息恒真、选择消息恒 0；Blitz 按键为 0–29 均匀随机；可选日志（本分支未启用）。
- **战后恢复（R11）**：正常返回后，双方成员逐个接受**完整治疗**（非蛋时：补满 HP、清状态与状态计数、**补满全部招式 PP**、**清进化准备标记**——这是**治疗到目标状态**，不是恢复战前受伤或低 PP 快照；与 WP20 已通过合同一致），再恢复保存的持物。**已归一等级不由此包装恢复**（生成产物本就以建议等级构造，实际为恒等）。**其它字段是否由正式战斗清理由相应合同确定**——不能因本包装没有全字段快照就断言一律不还原；**起战或执行抛错时，恢复段不包住所有异常出口**（不承诺已执行治疗和持物恢复）。

### 7.3 估算分支（E-3；R13 修订）

- 双方评分先**乘 0.15 并取整**（四舍五入）——后续同分裁决使用的也是这两个**取整后**的值：原始评分 50 与 51 都变为 8。
- **打分**（每方）：己方每个招式对每个对方成员算类型效果分（矩阵 **-16/-8/0/4/12/20**：无效/双重抵抗/抵抗/普通/克制/双重克制；威力 0 招式计 0）；**飘浮遇地面招式时跳过类型查询**，最终落入**普通效果 +4**（不按其本身属性弱点计算）；**神奇守护按每一个属性分量分别把非克制分量置为中性后再相乘**（不替换成正式免疫合同，WP44/`Effectiveness` 引用，`003_Type.rb:73–139` 定点）；再按**每个成员分别整数除 10** 加 BST；有持物 **+10**；再加该方缩放评分与**每方独立**的 0–31 均匀随机加项。
- 胜负：分高者胜；**总分相同 → 比较两个取整后的缩放评分**，高者胜；缩放评分也相同 → 结果 5（记平局支）——原始评分不同但缩放值同、总分同 → **平局**。

### 7.4 评级数学（E-4；R09/R14 修订——独立完整定义）

实际使用 `PlayerRating`（Glicko-2 **变体**，初值 R₀=1500、D₀=350、σ₀=0.9）。以下数学按独立变量给出，不调用或移植参考实现：

- **尺度**：归一化 rating₂＝(R−1500)÷173.7178、deviation₂＝D÷173.7178；**波动率 σ 以其原值（0.9）直接参与归一化域运算**（不做尺度换算，如实直述——空历史例：σ=0.9 与归一化偏差平方相加后开方，换回时乘 173.7178）。
- **对局记录**：每条记录保存**记录当时**的对手评级 Rⱼ 与偏差 Dⱼ（快照）；之后逐队结算不回改这些值。结果 sⱼ∈{胜 1、负 0、平 −1}。
- **g/e 因子**：gⱼ＝1÷√(1＋3·(Dⱼ÷173.7178)²÷π²)；eⱼ＝1÷(1＋exp(−gⱼ·(rating₂−(Rⱼ−1500)÷173.7178)))。
- **方差**：v＝1÷Σⱼ(gⱼ²·eⱼ·(1−eⱼ))——**全部记录（含平局）参与**。
- **改进和**：Δ＝Σⱼ(sⱼ≠−1) gⱼ·(sⱼ−eⱼ)——**平局记录不进入改进和**（不等同按 0.5 计分）。
- **波动率更新（R14 修订——按来源实际步进独立定义）**：改进量 **i₀＝Δ·v**（改进和先乘方差，与 Δ 本身分开）；a＝ln σ²；τ＝1.2。以 x 为当前近似做牛顿迭代，每步：d＝(φ²＋v)＋eˣ（φ＝更新前 deviation₂）；i＝i₀÷d；**两项迭代量** h₁＝−(x−a)÷τ² − ½·eˣ·i²、h₂＝−1÷τ² − ½·eˣ·(φ²＋v)÷d² ＋ v·eˣ·(φ²＋v−eˣ)÷d³；**下一近似 x ← x − h₁÷h₂**；**至多 100 次**、步长绝对值 <10⁻⁶ 即停；σ′＝e^(x÷2)。**固定算术核对**：双方 R1500/D350、σ=0.9——g≈0.6690694126、e＝0.5、v≈8.9354749036。**一场平局**：Δ＝0 → i₀＝0 → 初始近似处 h₁＝0、h₂≈−0.6885384548 → **步进为 0、立即保持 σ′＝0.9**。**一场胜局**：Δ≈0.3345347063、i₀≈2.9892264725、i≈0.2165362337 → h₁≈−0.0189896159、h₂≈−0.6885384548 → **步进≈0.0275796011**、下一近似 x₁≈−0.2383006324（一步固定算术，非全程收敛值）。
- **偏差与评级更新（消费新值）**：t＝φ²＋**σ′²**（新波动率）；deviation₂′＝1÷√(1÷t＋1÷v)；rating₂′＝rating₂＋(deviation₂′)²·Δ（新偏差）；换回 R′＝1500＋173.7178·rating₂′、D′＝173.7178·deviation₂′。
- **空历史**：不更新评级/波动率，仅膨胀偏差 deviation₂′＝√(φ²＋σ²)——固定向量：D=350、σ=0.9 → D′≈**383.332855**。
- **展示分数（winChancePercent）按偏差分轨**：D >100 → Smogon 式（对手基准 1500/350：s＝√(100000＋D²＋350²)、g＝10^((1500−R)×0.79÷s)、胜率＝1÷(1+g)×100）；D ≤100 → GLIXARE 式（sqr＝√(15.905694331435×(D²＋221781.21786254))、指数 inner＝(1500−R)×π÷sqr、胜率＝(10000÷(1＋10^inner)＋0.5)÷100）——**展示缓存随评级/偏差变更失效**。
- **结算时序（R09）**：`updateRating` 先以成功结算清历史，**再把刚清空的历史长度并入累计已结算场次**——可见累计场次＝已结算累计＋当前历史长度；结算失败则历史与累计不变（顺序边界如实登记）。
- **备选 Elo**（`PlayerRatingElo`）：**仅定义、生成流程无引用**——初值 1600、K=16、胜率 1÷(1＋10^((R−1600)÷400))；其非空更新**引用了一个从未在作用域中建立的当前对局变量**（循环无块参数）——属**未使用定义的静态缺陷**，如实登记、**不承诺其为可用更新算法**；与活动评级明确分开。

- 既有表非空 → 原样使用（不重排）。

### 8.3 宝可梦分配（F-2；R10/R15 修订——编号与成员列表不对称）

- 先把宝可梦表全员**等级归一**为**原规则**建议等级（就地赋值——直接修改输入对象；**等级赋值只改等级与经验下限、不显式重算数值**（`001_Pokemon.rb:199–205` 定点）——建议等级变化时数值与等级可不一致，如实登记），逐只缓存类型与**按原规则的**合法性。
- 每名训练家：既有宝可梦号 → 统计可用物种集合与**类型计数**（计数 ≥5 才保留：除 4、封顶 10；全 0 → 普通系置 1；无宝可梦号 → 全类型置 1）。
- 抽取（仅当传入宝可梦表）：对每只合法候选算**位次差** `|(候选位次×8÷表长) − (训练家位次×8÷训练家数)|`（截断至 7），查权重表 **[32,12,5,2,1,0,0,0]**；物种可用 → 四十面抽小于权重即入选；不可用 → 权重 × 该候选各类型计数后再判（**每类型独立一次机会——双属性候选同一轮可被加入两次**）。
- **集合不对称（R15）**：首轮结束只对**编号**去重，**成员列表仍可重复**；同种顺序补足**不检查编号已收**（同种支可把已选编号再次加入；仅同型支查重）；最终**仅排序、不再去重**——输出编号可含重复。
- **补足三对象与数量门（R15 修订）**：分清**输入候选总表**、**已选编号列表**（可含重复）、**已选成员列表**（重复规则不同）。**顺序补足入口**：「已选编号数 < 容量（`Settings::MAX_PARTY_SIZE`＝6）**或**清个体规则的规则副本对**当前已选成员列表**判定失败」——满足才进入顺序补足；**顺序退出**需「编号数**达到容量**，**且**原规则对当前已选成员列表判定成功」（例：候选总表 10 项、已选 3 项已能组成原规则的 3 成员队但容量为 6——**仍需补足**，不能因存在合格子队伍即停；合格队在候选总表中但当前已选成员尚不构成时，检查的是当前成员列表）。不足时先按同种/同型顺序补足；仍不足 → **随机补位**：**不再按预先缓存的单体合法性筛选**（可加入不合法候选）。**随机阶段持续条件同时含两个**：「编号数仍小于候选总表长度」**且**「编号数不足容量**或**原规则判定失败」——**达到候选总表长度可在队伍仍不合格时停止**；**不是全候选表存在合法子队伍就能停**。**编号长度限制不是抽样次数上限**——重复抽到已收编号可持续无进展，已有重复编号又可能提前达到长度停止——**不能保证输出六个不同合法候选、也不能保证全部候选均已尝试**。
- 分配结果升序写回各训练家宝可梦号。

### 8.4 写出与反写（F-3；R02/R16 修订）

- 宝可梦表经 `PBPokemon.fromPokemon` 转中间表示（EV 阈值 >60）。
- 更新 `Data/trainer_lists.dat`：**先记录扫描开始时是否存在任意默认列表**（一次性事实），再**更新所有含本挑战 ID 的条目**——**各条目的默认标志都取该先前事实的反值**，遍历途中不重算（R02）：**已有默认且该默认也命中 ID → 该默认被清除**（可能最终没有默认）；**原无默认且多个条目命中 → 多个条目都成默认**；**原有不匹配的多个默认不被清理**。所有匹配条目就地换训练家表/宝可梦表、**保留原文件名**；**仅零匹配才新建条目**（文件名 `<id>_trainers.txt`/`<id>_pkmn.txt`、标志同取先前事实的反值）。**复用路径（§4）不做同样的标志操作**。查询回退顺序（§8.1）在多默认/无默认结果下按首个命中生效。
- **写出顺序与失败残留（R16）**：**先保存 `.dat`，再打开并截断总 PBS**，逐列表交错写总表、训练家表与宝可梦表——**后续失败不自动撤销先前数据或已写文件**；末尾成功消息/窗口销毁也不保证到达。**反写空值不对称**：道具可空（无效/空 → 空字段）；**性格为空或无效时不走同样的空值保护——必需查找直接失败**（`001_GameData.rb:88–114` 定点）。**编译侧边界**：缺总表 → 新建默认引用（battle_tower 两文件）；节内**缺必需文件名键 → 报错**；文件名存在但**所指文件缺失 → 该子表为空**；**宝可梦行缺必要分隔字段 → 解析失败**（不同于未知标识变空）——各阶段失败的可见残留与重跑输入如实登记，引用 WP04/WP75 不代替这些具体消费边界。**旧检查点继续保留，重跑不是事务回滚**。

## 10. 边界、失败与未知汇总

1. **调试门**：`pbWriteCup` 非调试直接返回——正式配置下无任何生成/复用路径。
2. **无终止保护**：候选采样（§5.1）、池补充（§6.2）、队伍取样（§6.3）均无迭代上限；严格规则下可能无进展——不补兜底、不承诺必然生成成功。
3. **取消语义**：仅生成启动前的询问/确认可取消；长任务无中途取消；**保护检查与取消不撤销此前已发生的变化**（检查点已写部分不回滚）。
4. **重复判定的槽位序敏感**（§6.1）与**紧凑/排序结果被丢弃**的实测行为如实登记。
5. **池消耗**：队伍取样从池中删除成员；耗尽早于满足时行为无保护。
6. **真实分支副作用**：等级归一不恢复；正常返回后完整治疗（含 PP）＋持物还原——是治疗到目标状态而非战前快照；异常出口不承诺恢复段已执行（§7.2）。
7. **评级数值边界**：估算分支平分→比较取整后的缩放评分、再同→平局；0–31 每方独立抖动；波动率迭代上限 100 次；胜率两式以偏差 100 分轨；波动率以原尺度参与归一化偏差计算（变体尺度混用，§7.4）。
8. **数据缺口（demo）**：当前快照 `Data/` 仅 `Scripts/`、`Scripts.rxdata`、`messages_core.dat`——**`Data/trainer_lists.dat` 不存在**（R19 修订）：**仅能断言未经准备的该快照在直接执行这些读取且仍缺文件时回退空表**；编译管线把列表数据列为常规产物（`001_Compiler.rb:993–1018` 定点——`compile_trainer_lists` 在 PBS 全量编译序列内），**能从当前已存在的 PBS 生成它**，生成/复用也能写回——**后续读取不一定为空，不能据原始快照断言正常启动必走空表分支**；`PBS/battle_facility_lists.txt` 存在（默认＋4 杯赛节）；**`cup_fancy_trainers.txt` 与 `cup_fancy_pkmn.txt`（非 _single 变体）无任何列表/脚本引用**（未引用文件如实登记）；fancy 杯单双打均引用 `_single` 变体文件。
9. **宿主/环境未知**：长任务实际耗时、真实对局胜负分布、评级收敛表现、生成结果的对局质量均未验证；训练家台词的翻译提取/反写（`MessageTypes` 四组哈希）属 WP08 边界。
10. **回退一致性**：选默认列表时 ID 迁出后不追加（§4）；生成写出时默认标志按**先前事实取反**——可多默认、可无默认，**不是唯一化**（§8.4，R02）——两条路径的默认语义不互相推导。
11. **训练家生成（R01）**：普通抽样循环无成功退出——一般随机生成不保证完成、也非必然卡住（YOUNGSTER 连续快捷命中为可继续特殊路径）；既有非空表绕过（§8.2）。
