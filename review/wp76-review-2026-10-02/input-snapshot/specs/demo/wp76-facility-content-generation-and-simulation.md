## 1. 目的、范围与非目标

### 1.1 目的

从作者（游戏制作者）视角规定**战斗设施参赛内容的生成、评估与写出**能力：

- 设施挑战设置时联动询问是否生成参赛队伍列表（`BattleChallenge.set` → `pbWriteCup`，调试门）。
- 复用已有列表或触发全新生成（`pbGenerateChallenge`）：候选个体随机构造、合法性筛选、去重与补充、组队迭代、模拟对战评级、分层汇集。
- 训练家池生成与分配（`pbTrainerInfo`）：训练家选择/随机生成、按位置与类型权重分配宝可梦、写回列表数据并反写 PBS。
- 生成侧与正式战斗规则的边界：生成器的筛选/估分是独立近似，不回写为 WP54/WP55/WP51/WP52 的运行合同。

### 1.2 范围（A～F）

- **A 入口与触发**：设施设置调用点、外层调试门、生成/复用询问与确认。
- **B 复用已有列表**：列表选择、挑战 ID 迁移、默认列表特例。
- **C 候选个体生成**：物种/等级/性格/EV/道具/招式的随机构造与拒绝采样、合法性终检。
- **D 队伍组建与迭代**：队伍取样、补充、同类/重复判定、同种上限、更替/退休/删除、分层汇集。
- **E 模拟对战与评级**：真实无视觉战斗与估算分支分流、估分公式、Glicko-2 评级更新、备选 Elo 定义。
- **F 训练家池与写出**：训练家选择/生成、宝可梦分配、列表数据写回与 PBS 反写、编译往返、检查点文件。

### 1.3 非目标

- 不重提取 WP54（参赛资格/等级调整/条款规则——生成器消费的 `ruleset` 合同以其已通过边界为准）、WP55（设施会话）、WP51/WP52-A/B/C（AI 与评估——真实战斗分支只经 `createBattle` 交界调用，其内部不展开）、WP57（工厂租赁——`pbBattleFactoryPokemon` 是另一条生成路径，不属于本包）、WP72（debug 菜单框架）、WP73-A（编辑器反写边界）、WP75（编译驱动与反写管线——本包只引用 `write_trainer_lists` 在其中的位置）；以上以依赖身份引用。
- 不运行生成器/真实对局/Monte Carlo/编译器/游戏/反序列化/参考行为模拟器；不操作工程或存档；不写框架实现或参考行为模型；demo 事件可达性归 WP77。
- 生成结果的对局表现（真实战斗胜负分布、评级收敛的实际数值）未验证——只登记静态可推导规则。

## 2. 概念与术语（实现中立）

- **挑战 ID（challenge id）**：设施挑战的字符串标识（如 `pokecupsingle`）；生成产物（检查点、新列表条目、新 PBS 文件）均以其为名。
- **列表（trainer list）**：`Data/trainer_lists.dat` 中的一条六元条目——训练家表、宝可梦表、挑战 ID 数组、训练家文件名、宝可梦文件名、默认标志；**默认列表**（默认标志为真）是无 ID 命中时的回退。
- **候选个体（candidate）**：`pbRandomPokemonFromRule` 拒绝采样产出的单个宝可梦；**池（party）**：候选的暂存集合（上限 20，补充制）。
- **队伍（RuledTeam）**：从池中按建议数量取出的可评级小队，携带评分（`rating`＝胜率百分数）、场次（`games`＝当前历史长度）与累计场次（`totalGames`）。
- **真实分支**：1% 概率触发的真实无视觉战斗；**估算分支**：99% 概率的类型效果打分近似。
- **检查点文件**：生成中间产物 `<id>.rxdata`（池）与 `<id>_teams.rxdata`（队伍库），位于游戏根目录（非 `Data/`）——崩溃/中断后可从最近检查点继续的既有设计，如实登记。
- **审计名**：仅作追溯标识的方法/类名（如 `pbRandomPokemonFromRule`、`RuledTeam`、`PlayerRating`）；行为描述不依赖其内部实现结构。

## 3. 入口与触发（A）

### 3.1 设施设置调用点

- `BattleChallenge.set`（审计名；WP55 会话交界；事件侧由设施接待事件触发，demo 可达性归 WP77）：登记挑战后**无条件调用** `pbWriteCup`（审计名）——生成询问是设施设置流程的内嵌步骤，不是独立菜单项（`001_Challenge_BattleChallenge.rb:18–26` 定点）。
- **外层调试门**：`pbWriteCup` 首行为**非调试模式直接返回**（`return if !$DEBUG`）——正式运行配置下整段生成/复用询问不可达（`001_ChallengeGenerator_Data.rb:276–277`）。

### 3.2 生成/复用询问（A-2）

- 先读 `Data/trainer_lists.dat`（缺失/异常 → 空表），把各列表显示名（文件名去 `.txt`，默认列表名前加 `*`）组为选项。
- **无任何列表**：两选项消息「Generate Pokémon teams for this challenge?」（YES／NO，**默认 NO**——默认下标 2 落到第二项）；YES→进入「新生成」支，NO→返回。
- **已有列表**：三选项消息同题（NO／YES, USE EXISTING／YES, USE NEW，**默认 NO**）。
- **新生成支**：再经确认消息「This may take a long time. Are you sure?」——**取消即返回**（不产生任何生成）；确认后创建消息窗口、进入长任务（§4–§8），期间每 5 秒刷帧并显示进度消息，完成后窗口销毁并提示「Team generation complete.」。
- **取消语义**：询问/确认阶段的取消只阻止生成启动；**已启动生成无中途取消路径**（进度回调只刷帧/显示，不查取消），如实登记。

## 4. 复用已有列表（B）

- 选择列表（默认取消值 −1；**取消选择＝不改任何数据**直接返回）。
- 选中后提示该挑战将使用所选列表的宝可梦；随后**把本挑战 ID 从所有非默认列表的挑战数组中移除**（while 循环删除全部出现），再**仅当所选列表非默认**才把 ID 追加进其挑战数组——**选默认列表时 ID 被整体迁出后不再追加**（默认列表经回退支自然覆盖，§8.1 查询顺序）。
- 写回 `Data/trainer_lists.dat`、刷帧、调用 `Compiler.write_trainer_lists` 反写 PBS（§8.4）——复用分支也触发全量列表反写。
- 列表为空时选择步不会出现（§3.2 两选项形态）；**选择默认列表与选择非默认列表的迁移结果不同**，不互相替代。

## 5. 候选个体生成（C；`pbRandomPokemonFromRule` 拒绝采样）

### 5.1 总体结构

外层为**无迭代上限**的拒绝采样循环：逐段构造物种→EV→性格→道具→招式，任一约束不满足即重掷对应段或整体重采；最终以 `rules.ruleset.isPokemonValid?` 为**唯一出口门**（WP54 合同）。**无可满足输入时本循环不终止**（如实登记，§10）。

### 5.2 物种与等级（C-1）

- 等级恒为 `rules.ruleset.suggestedLevel`（WP54）；物种从全部物种键等概抽样，**只收形态 0**。
- 每轮抽 0–19 均匀整数 r，按外层迭代**奇偶交替**两套偏好门（`002:152–170` 定点）：
  - 偶数轮：拒绝 `r<16 且 BST<400`；拒绝 `r<13 且 BST<500`——偏好中高 BST。
  - 奇数轮：拒绝 `BST>400`；拒绝 `r<10 且非宝宝形态`——偏好低 BST/宝宝。
  - 两轮共通：拒绝 `等级 < 该种最低等级`；拒绝 `r<10 且为宝宝形态`；拒绝 `r<7 且仍有进化形`。
- 各项族事实（BST/宝宝种/最低等级/进化形）经**全局缓存**按种 memoize（§9.1）。

### 5.3 EV 与性格（C-2）

- EV 集合：每个主能力值独立以 50% 概率入选（先选集合、后续按道具/招式再调整）。
- 性格抽样：中性（无能力修正）或 LAX/GENTLE → 仅 5% 接受；有修正性格：若其**提升项不在 EV 集合**→60% 拒（无提升强调）；若其**降低项在 EV 集合**→90% 拒（有降低强调）——性格与 EV 强调一致性是概率门，不是硬约束。

### 5.4 道具（C-3）

- 固定候选表 41 项（浆果/宝珠/头巾/围巾/眼镜/黏泥/光粉/节拍器等，含 12 个物种专属件）；**先以 1/40 直取 LEFTOVERS**，否则表内等概抽。
- 物种专属门：LIGHTBALL 仅皮卡丘、SOULDEW 仅拉帝兄妹、THICKCLUB 仅卡拉/嘎啦、ADAMANTORB 仅帝牙卢卡、各减伤浆果仅指定种（PASSHOBERRY→大钢蛇、BABIRIBERRY→班基拉斯、HABANBERRY→烈咬陆鲨、OCCABERRY→巨金怪、CHOPLEBERRY→月伊布、YACHEBERRY→土台龟/天蝎王/哈克龙、SHUCABERRY→席多蓝恩、DEEPSEATOOTH→珍珠贝、SHEDSHELL→佛烈托斯/盔甲鸟）；FOCUSSASH 在 BST>450 时 80% 重抽。
- 龙之/沙鳞/蒲玲果（LIECHI/SALAC/PETAYA）各有 50% 把对应能力（攻击/速度/特攻）补入 EV 集合。
- 等级段替换：**等级 <10**（且 ORANBERRY 存在）→ 1/40 或当前为 SITRUSBERRY 时换 ORANBERRY；**等级 >20**（且 SITRUSBERRY 存在）→ 对称替换。

### 5.5 招式合法集（C-4；`pbGetLegalMoves2`）

- 来源三路：**升级招式**（学习等级 ≤ 当前等级，权重 2）、**机器招式**（教学招式 ∩ 全部机器道具招式，权重 0——机器表全局缓存一次构建）、**宝宝种蛋招式**（权重 2）。
- `addMove` 权重（同一招式可多次入集实现偏置）：默认 base+1；无效果码且威力 ≤40 → base；威力 ≤30 或 GROWL/TAILWHIP/LEER → base；威力 ≥60 或 REFLECT/LIGHTSCREEN/SAFEGUARD/SUBSTITUTE/FAKEOUT → base+2；威力 ≥80 且普通系 → base+3；指定高价值件（PROTECT/DETECT/TOXIC/AERIALACE/WILLOWISP/SPORE/THUNDERWAVE/HYPNOSIS/CONFUSERAY/ENDURE/SWORDSDANCE）→ base+3。**BUBBLE 与 BUBBLEBEAM 永不加入**。
- 剪枝（按集合内两两比较）：**必中**（命中 0）招式删除同系无效果码且威力不高于它的其它招式；同效果码双变化招删低命中者；**剧毒**（BadPoisonTarget）删除**中毒**（PoisonTarget）；同效果码同系攻击招，PP 为 15/10 或相同且威力更高（或同威力更高命中）者删除另一者。
- 合法集按**等级全局缓存**（等级变化即整体重建，同种缓存命中不重算）。

### 5.6 招式选取与一致性（C-5）

- **Sketch 特例**：合法集首项为 SKETCH 时置 sketch 标志并把全部招式位替换为 `pbRandomMove`（等概随机，排除 Struggle 与 ReplaceMoveWithTargetLastMoveUsed 两效果码）。
- 合法集为空 → **整体重采**（外循环 `next`）；唯一招式数 <4 → 直接采用（不补齐）；≥4 → 选取循环：
  - 从加权集随机取至满 4 个不同招式；候选有同系更大威力招时 50% 跳过（`hasMorePowerfulMove`）。
  - 组合约束：**蓄力**（STOCKPILE）与**喷出/吞下**（SPITUP/SWALLOW）必须成对（单向出现即重掷）；**梦话/鼾声**（SLEEPTALK/SNORE）需**睡觉**（REST）同在，否则仅 20% 放行（且仅在 sketch 或合法集本无 REST 时）。
  - 物理/特殊一致：全队无物理招而 EV 含攻击 → 80% 重掷；无特殊招而 EV 含特攻 → 80% 重掷。
  - 总威力门：十面抽 >6（30%）且总威力 >180 → 拒；十面抽 >8（10%）且总威力 >140 → 拒；总威力 0 → 95% 拒。
  - 接受后调整：纯物理队 → 80% 补攻击 EV、80% 去特攻 EV；纯特殊队对称；SILKSCARF 在无普通系招时换 LEFTOVERS。
- **道具-招式终校**：LIGHTCLAY 无光墙/反射壁 → LEFTOVERS；BLACKSLUDGE 非毒系 → LEFTOVERS；HEATROCK 无大晴天 → LEFTOVERS；DAMPROCK 无求雨 → LEFTOVERS；含 REST → 33% 换 LUMBERRY、再 25% 换 CHESTOBERRY（两段独立可叠加覆盖）。

### 5.7 个体构造（C-6；`PBPokemon.createPokemon`）

- 中间表示 `PBPokemon`（物种/道具/性格/四招式/EV 集合）→ 实例化：个体值全主能力 31、随机 32 位 personalID、亲密度 0、RETURN 转 FRUSTRATION（存在时）、**EV 均分**（每个入选能力 = 上限 ÷ 入选数，整除截断）、重算数值。
- `PBPokemon.fromPokemon`（反向，写表用）：招式位按序取 id（空位 nil）、**EV 收录阈值为 >60**（每主能力独立判定）。

## 6. 队伍组建与迭代（D）

### 6.1 重复判定（D-1；`isBattlePokemonDuplicate`）

- 物种不同 → 必不重复。同种时两判据：
  - **招式判据**：四个招式位**按槽位原序**（含空位占位）逐项相等即重复——源中有一处对两数组求紧凑/排序但**结果未写回**（计算被丢弃），故实际比较是**槽位序敏感**的（如实登记，不补「意图」）。
  - **属性判据**：道具、性格、全部主能力 EV 值逐项相等即重复。
- 判据间为「或」：任一成立即视为重复。

### 6.2 补充与同种上限（D-2）

- **补充**（`pbReplenishBattlePokemon`）：池不足 20 即反复生成候选，**仅当不与池中任何成员重复**才入池——候选无限重试，无进度上限登记。
- **去重**（`pbRemoveDuplicates`）：顺序扫描，重复者丢弃；**同种成员超过 10 时删除该种最早成员**（先进先出顶出）——同种上限 10（按重复判据之外的纯物种计数）。

### 6.3 队伍取样（D-3；`RuledTeam` 构造）

- 从池中按 `suggestedNumber`（生成主流程固定队伍数量为 2——**每次取出 2 只**）**逐个随机抽取并即从池中删除**（池被消耗）；组成后过 `ruleset.isValid?` 团队校验，不过则**重新抽取**（无迭代上限；池随每次尝试净消耗——耗尽早于满足时的行为无保护，如实登记）。
- 新队伍：评分对象新建（Glicko-2 初值 1500/350/0.9）、历史空、累计场次 0。

### 6.4 生成主流程（D-4；`pbGenerateChallenge`）

- 规则副本队伍数量设为 2；从检查点读池与队伍库（缺失/异常 → 空）。
- **种子填充**：队伍库 <10 且既有宝可梦表（§8.1 查询）非空 → 逐条按建议等级、个体值 31 实例化，合法者入池（随后 §6.2 去重）。
- **常量**：队伍库上限 600、高分线 65、低分线 40、**迭代 11 轮**。
- 每轮迭代：
  1. **写池检查点**；进度消息「Generating teams (i of 11)」。
  2. 逐队伍扫描（先补充池至 20）：评分 <65 且累计场次 ≥80 → **替换为新队**；成员数 <2 → 替换；**下标 ≥600 → 删除**；累计场次 ≥250 → **退休**（成员回池后替换）；评分 <40 → 替换。五支按序互斥（首命中支生效）。
  3. **写队伍库检查点**；队伍库补至 600（每队建前补充池）。
  4. **写池检查点**；按评分降序排；进度消息「Simulating battles (i of 11)」。
  5. 模拟（§7）：每队打一场（对手随机，最多重掷 5 次避免自对）；**库均场次 <12 → 全员续战**；≥12 → 全员 `updateRating`（评级结算并清历史，§7.4）后本轮收束；按评分降序、**写队伍库检查点**。
- 11 轮后：池清空；队伍库**升序**遍历，**评分 >65** 的队伍成员全部入池（升序遍历＋条件跳过，不提前终止）；去重；「Writing results」；**分层**（§6.5）；进入训练家池（§8）。

### 6.5 分层（D-5；`pbArrangeByTier`）

- 九层限制器（`withRestr` 构造，`_rule` 入参未用，如实登记）：T0＝BST 0–500 非传说；T1＝BST 380–500 非传说；T2–T5＝BST 400–555 非传说（四层同构）；T6＝BST 580–680 **仅传说**；T7＝BST 500–680 非传说；T8＝BST 580–680 **不限**。
- **传说判定**：无性别且蛋群含「未发现」即传说（`NonlegendaryRestriction` 取反即仅传说；`InverseRestriction` 为通用取反包装）。
- 定位：逐个候选（先过主规则合法门）求其**可入层集合**，按其在输入序列的相对位次取 `可入层数 × 位次 ÷ 总数`（整除）映射到可入层之一——输入序列已被评分隐式排序（弱→强），位次越后落层越高。
- 层内按 BST 升序（同 BST 按物种 id 升序）；九层顺次拼接为最终宝可梦表。

## 7. 模拟对战与评级（E）

### 7.1 分流（E-1；`pbRuledBattle`）

- 每场以 **1%（百面抽中 0）走真实分支**，99% 走估算分支；结果三分：队 1 胜（1/0）、队 2 胜（0/1）、平局（-1/-1）记入双方历史。

### 7.2 真实分支（E-2）

- 双方成员**等级归一**为建议等级（不一致才改并重算数值）；构造两名 NPC 训练家（类型取训练家类型表**首项**，名 PLAYER1/PLAYER2），记录原持道具。
- 以 `Battle::DebugSceneNoVisuals` 无视觉场景经 `rule.createBattle` 起战（WP54 交界）；设 debug、controlPlayer、**internalBattle 关**；`pbStartBattle` 的返回即胜负（1/2，其它按平局支记）。
- **无视觉场景的合同**（`009_Battle_DebugScene.rb` 全文）：命令菜单 1/15 选 Bag、1/10 选 Call、否则 Fight；出招随机（由调用方以 `yield` 门控，至多 50 次）；目标随机；换宠随机；道具菜单恒 -1；确认消息恒真、选择消息恒 0；Blitz 按键为 0–29 均匀随机；可选日志（本分支未启用）。
- **战后恢复**：双方成员**治疗（heal）＋持物还原**——等级归一不在恢复范围（生成产物本就以建议等级构造，实际为恒等）；**HP/状态/道具以外的战斗副作用（如 PP、形态、训练家计数）不回滚**，如实登记；战斗本身的 AI/规则行为属 WP51/WP52 已通过域，不扩展。

### 7.3 估算分支（E-3）

- 双方评分先缩放 `rating × 15 ÷ 100`（四舍五入）。
- **打分**（每方）：己方每个招式对每个对方成员算类型效果分（矩阵 **-16/-8/0/4/12/20**：无效/双重抵抗/抵抗/普通/克制/双重克制；威力 0 招式计 0；飘浮对地面、神奇守护非克制重置为 1——按 `Effectiveness` 合同，WP44 引用）；加 **BST ÷ 10**；有持物 **+10**；再加缩放评分与 0–31 均匀随机加项。
- 胜负：分高者胜；**平分**→评分高者胜，评分同 → 结果 5（记平局支）。

### 7.4 评级数学（E-4；Glicko-2 实际使用）

- 实际使用 `PlayerRating`（Glicko-2）：初值 1500/350/0.9；`update` 按对手偏差算 g/e 因子、方差与改进和，偏差/评级/波动率依次更新，波动率经**至多 100 次牛顿迭代**（收敛阈 1e-6）。
- **胜率百分数（rating 展示值）按偏差分轨**：偏差 >100 → Smogon 式（对手 1500/350 基准，`s=√(100000+dev²+350²)`，`g=10^((1500−rating)×0.79÷s)`，胜率 `1÷(1+g)×100`）；偏差 ≤100 → GLIXARE 式（`sqr=√(15.905694331435×(dev²+221781.21786254))`，胜率 `(10000÷(1+10^inner)+0.5)÷100`）——两式独立数学描述，不作实现推断。
- `updateRating`：先把当前历史场次并入累计场次，再结算并清空历史（历史长度归零）。
- **备选 Elo**（`PlayerRatingElo`）：**仅定义、生成流程无引用**——初值 1600、K=16、胜率 `1÷(1+10^((rating−1600)÷400))`；其更新式按源文登记（`e=1+10^((rating−对手)÷400)`、`stake+=K×(score−e)`——与常见 Elo 期望式形态不同，如实登记、不判正误）。

## 8. 训练家池与写出（F；`pbTrainerInfo`）

### 8.1 列表查询（F-0）

- `pbGetBTTrainers`/`pbGetBTPokemon`：**先找含本挑战 ID 的非默认列表**，找不到**回退第一个默认列表**，皆无 → 空表（`002_Challenge_Data.rb:21–33` 定点）——§4 的 ID 迁移与默认回退按此顺序生效。

### 8.2 训练家来源（F-1）

- 既有表为空 → **生成 200 名随机训练家**：1/30 直取 YOUNGSTER（存在时），否则等概抽**基础奖金 <100** 的训练家类型（无上限重抽）；名字按类型性别经音节名生成器（`getRandomNameEx`，长度上限 12、至多 50 次尝试）；台词固定三句（Here I come!／Yes, I won!／Man, I lost!）；宝可梦号空。**按基础奖金升序**（同额按类型 id 字典序）。
- 既有表非空 → 原样使用（不重排）。

### 8.3 宝可梦分配（F-2）

- 先把宝可梦表全员**等级归一**为建议等级（就地为 pkmn.level 赋值——直接修改输入对象），逐只缓存类型与合法性。

- 抽取（仅当传入宝可梦表）：对每只合法候选算**位次差** `|(候选位次×8÷表长) − (训练家位次×8÷训练家数)|`（截断至 7），查权重表 **[32,12,5,2,1,0,0,0]**；物种可用 → 四十面抽小于权重即入选；不可用 → 权重 × 该候选各类型计数后再判（每类型独立一次机会）。
- **补足**：不满队伍上限（`Settings::MAX_PARTY_SIZE`＝6）或无可注册队 → 先按同种/同型顺序补足；仍不足 → **随机补位**至满且可注册（受表长上界约束，超界即停——严格规则下可能仍不足，如实登记）。

### 8.4 写出与反写（F-3）

- 宝可梦表经 `PBPokemon.fromPokemon` 转中间表示（EV 阈值 >60）。
- 更新 `Data/trainer_lists.dat`：已有**含本挑战 ID** 的列表 → 就地换训练家表/宝可梦表；否则**新建条目**（文件名 `<id>_trainers.txt`/`<id>_pkmn.txt`）。**默认标志唯一化**：扫描时若无任何默认列表，则本次更新的条目（或新条目）置默认；已有默认则新条目非默认。

## 10. 边界、失败与未知汇总

1. **调试门**：`pbWriteCup` 非调试直接返回——正式配置下无任何生成/复用路径。
2. **无终止保护**：候选采样（§5.1）、池补充（§6.2）、队伍取样（§6.3）均无迭代上限；严格规则下可能无进展——不补兜底、不承诺必然生成成功。
3. **取消语义**：仅生成启动前的询问/确认可取消；长任务无中途取消；**保护检查与取消不撤销此前已发生的变化**（检查点已写部分不回滚）。
4. **重复判定的槽位序敏感**（§6.1）与**紧凑/排序结果被丢弃**的实测行为如实登记。
5. **池消耗**：队伍取样从池中删除成员；耗尽早于满足时行为无保护。
6. **真实分支副作用**：等级归一不恢复；heal＋持物以外的战斗状态不回滚（§7.2）。
7. **评级数值边界**：估算分支平分→比评分、评分同→平局；0–31 随机抖动；Glicko-2 波动率迭代上限 100 次；胜率两式以偏差 100 分轨。
8. **数据缺口（demo）**：当前快照 `Data/` 仅 `Scripts/`、`Scripts.rxdata`、`messages_core.dat`——**`Data/trainer_lists.dat` 不存在**（本包全部列表读取落入 rescue 空表路径）；`PBS/battle_facility_lists.txt` 存在（默认＋4 杯赛节）；**`cup_fancy_trainers.txt` 与 `cup_fancy_pkmn.txt`（非 _single 变体）无任何列表/脚本引用**（未引用文件如实登记）；fancy 杯单双打均引用 `_single` 变体文件。
9. **宿主/环境未知**：长任务实际耗时、真实对局胜负分布、评级收敛表现、生成结果的对局质量均未验证；训练家台词的翻译提取/反写（`MessageTypes` 四组哈希）属 WP08 边界。
10. **回退一致性**：选默认列表时 ID 迁出后不追加（§4）；生成写出时默认标志唯一化（§8.4）——两条路径的默认语义不互相推导。
