本合同来自本轮用户授权边界；不是整改启动指令或通过决定。阶段 A 没有派生任务、配置并行作者或开始复审。

## 1. 输入门禁与三个 commit

| 字段 | 含义 | 阶段 A 值 |
| --- | --- | --- |
| REVIEW_BASE_COMMIT | 最终全局 review 实际检查的不可变输入提交；附输入清单及完整文件身份 | 待最终交接，不以当前 main 猜填 |
| REVIEW_REPORT_COMMIT | 最终报告、完整原始 findings、覆盖/等价矩阵和限制说明实际所在的不可变提交 | 待最终交接，不以本准备提交代替 |
| FIX_BASE_COMMIT | 接收最终 review 后，为整改明确选定的实际起点；记录其与前两者的关系、差异及纳入范围 | B 开始前确定，不默认等于 REVIEW_BASE_COMMIT |

三个角色分开记录；即使某些 SHA 恰好相同也须解释，不能混称“基线”。准备基线 `e1e01bb18d824931e54f182dd61af5a9f908ba85` 仅描述 A 的 checkout。最终交接后核对分支实际状态与漂移，不回退、改写或覆盖正在进行的审查材料。

完整保留原 finding ID、原严重度/范围、证据位置、差异、影响及验收条件；不得重编号、缩写到无法溯源或通过合并工作包丢失原 ID。对子项/依赖的派生引用必须指回原 finding。历史报告和冻结快照不改写；新回应、候选、复审和整合记录写入明确的新目录。

## 2. 模型与能力门禁

- 作者：`gpt-6-astra / max / Standard`。只有存在真实“不支持 max”的证据才允许 `xhigh / Standard`，保留错误/能力证据及决定；配置不可读不等于不支持 max。
- 独立复审：`gpt-6-astra / ultra / Standard`，与作者独立；作者自检不替代独立复审。
- 单一公共登记写入者：Astra Max（仅确实不支持时 xhigh）/ Standard；其余作者和 reviewer 只交登记建议，不能并发改中央表。
- 父线程已核验 Ultra 请求被平台接受且 schema 的 default＝Standard；执行端实际配置仍未独立核实。A 本任务的实际配置也未独立核实。**在平台配置证据可用，或用户明确决定如何处理限制之前，B 的模型能力门禁保持未解决。**
- 每个实际任务保存请求参数、可用回执、effective 配置证据或明确缺口；不得把请求成功等同推理实际生效。私人线程/账户/凭证信息不入公开仓库。

## 3. 工作包组织与并发

接收最终 findings 后按**语义依赖与读写冲突**构建有限工作包，不仅按目录划分。每包写明原 finding IDs、输入身份、依赖包、读取集合、唯一可写路径、公共登记需求、验收条件及明确排除项。

- 任意时刻作者与复审合计最多 **3 个并行任务**；公共登记/整合作业若作为作者任务运行，也占用名额。不得把 reviewer 当作额外免费名额。
- 有语义依赖按顺序完成和复审；写写冲突或会改变另一任务读入语义的读写冲突必须串行或重划边界。路径不重叠不代表语义独立。
- 依赖环仅作**有界合批**：列出环内原 IDs、共同不变量、固定输入、有限可写集合和统一验收条件；不能借环扩大为无限整仓修改。有新范围时回报并重新确定边界。
- 公共登记（Feature Matrix、coverage、中央 manifest/TSV、traceability、批准状态等）只能由单一登记写入者在 B 的明确授权范围内串行处理。A 未授权修改这些内容。

## 4. 候选、复审、整合、关闭

1. 作者在隔离工作分支完成有界候选与必要自检，列出原 finding IDs、改动路径、证据、局限及待证项。
2. **冻结候选 commit**：记录完整 SHA、父提交、差异和输入/输出身份。冻结后更改会形成新候选，旧结论不能直接覆盖新字节。
3. 独立 Ultra 对该冻结对象给出限定 `PASS_SCOPED` 或需修订结论。`PASS_SCOPED` 须写明具体 IDs、文件身份、验证范围和不包含的保留项。
4. 通过对象才进入 `integration`。合并/冲突处理、共同登记及与已整合修改的相互影响都要有记录；不自动把源分支的批准搬到变化后的对象。
5. Ultra 对 **integration 实际 commit 的受影响范围**核验；语义冲突/新问题返回有界修订。只有原 finding 的候选通过、成功整合及受影响核验均具备证据，才由单一登记写入者记为 `CLOSED`。
6. 全部工作包完成后进行**最终 Ultra 整合复审**，覆盖完整整合身份、交界、登记链和原 finding 集，不用局部通过数量推导整体通过。

流程约束：`候选冻结 commit → Ultra PASS_SCOPED → integration → Ultra 受影响核验 → CLOSED`。作者“已处理”、文本扫描归零、文件计数或 commit/push 均不是关闭依据。

B 只从 `integration` 交付；main 合入/推送需要用户另行授权。历史审查原件和快照保持。U01–U10、G01–G12、AX 事实、材料/证据缺口和已有静态批准的范围限定全部继承；既不升级未知项，也不因旧头部标签抹去已有批准。
