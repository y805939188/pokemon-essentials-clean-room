## 1. 目的、范围与非目标

**目的**：定义"进化"的基础规则——条件族目录与判定语义、五类检查入口与统一守卫、可行目标的选择顺序、进化提交的完整流程（阻止/取消/提交/展示收尾）、额外个体复制，以及升级与道具（重点）及交换/战后/事件入口的对照；供 WP32（跨域触发）、WP28（道具消耗）、WP38（球数据消费者）、WP62（图鉴）、WP67-B（演出 UI）引用。

**范围**（WP31 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP31-A：条件族目录——全部注册进化方法的标识、参数类型、触发家族、判定输入与语义。
2. WP31-B：检查接口——升级/使用道具/交换/战后/事件五类检查、统一守卫、目标选择顺序与失败。
3. WP31-C：提交过程——演出的准备/取消/成功三路；成功路径的写入顺序（统计→消息→进化后动作→物种变更→重算→标记清除→图鉴→进化时招式→收尾）；保留/变更字段；额外个体复制（队伍容量/球前提）。
4. WP31-D：入口对照——升级与道具入口的阻止/取消/返回/消耗归属；交换/战后/事件入口的已定位交界（完整触发与消费时机登记给 WP32）。
5. F09-03 中属于 WP31 部分的状态更新。

**非目标**：

- 不定义位置/时间/交换/战后成就的**完整触发责任与消费时机**（WP32；本包只给出判定语义与已定位调用点，不把它们未展开的部分当已完成）。
- 不定义进化对形态组合的完整规则（WP21）、能力公式（WP19）、招式状态/PP（WP20）、学习交互主规则（WP30）、图鉴完整语义（WP62）、HP/濒死规则（WP20）。
- 不定义道具的使用资格/数量/消耗流程（WP28）与球/捕获（WP38）；不定义战斗时序（WP42）、队伍/摘要界面交互（WP66）与完整演出规格（WP67-B）。
- 不定义寄养/孵化对进化的影响（WP33–WP35）与事件可达性（U01）。
- 不运行游戏或参考脚本；不设计未来框架的进化 API。

## 2. 概念与术语

- **进化条目**：物种数据中的一行"目标物种 + 方法 + 可选参数"；一个物种可有多行（样本：EEVEE 十条、NINCADA 两条、TYROGUE 三条）。日/夜、天气、位置等情境是否成立由对应条件判定。
- **前身条目**：由其它物种条目推导出的反向条目；**不参与**检查与提交扫描（被统一排除）。
- **方法（注册项）**：以标识注册的判定/动作单元；参数类型可为整数（等级/次数/编号）、物品、招式、属性、物种或字符串。
- **触发家族**：方法可挂接的判定上下文——升级、使用道具、交换、战后、事件；另有只挂"进化后动作"的方法。
- **检查入口**：对"个体 + 家族"执行"守卫→按条目顺序判定→返回首个命中的目标物种（或空）"的接口，共五类（§4）。
- **进化后动作**：提交时、物种变更**之前**执行的单元；用于消耗持有物品或复制额外个体（§5.2/§5.3）。
- **提交**：通过演出把个体物种实际改变的步骤集合。
- **取消**：演出期间按取消键中止；只在允许取消的入口可用（§6）。
- **额外个体（复制）**：提交时按条件在队伍末尾追加一个新个体（当前数据：仅 Shedinja 型）。
- **ready_to_evolve 标记**：个体上的布尔标记；被战后"累积直接伤害"动作置真（§3.4），被提交完成、濒死与治疗后清除。
- **any_level_up 元数据**：方法声明的"需要任意一次升级"属性；**判定过程本身不含等级比较**；该属性参与物种"最小等级"数据推导（§3.7）与文档/数据语义。

## 3. WP31-A：条件族目录（注册表全文静态核对）

> 家族列：**升级**＝升级上下文判定；**道具**＝对个体使用道具时判定；**交换**＝交换上下文判定；**战后**＝战斗结束后判定；**事件**＝按事件编号判定；**后置**＝仅注册进化后动作、不可作为检查目标。参数"无"表示数据行不提供参数。

### 3.1 升级上下文（在升级/换级/战后升级检查中被判定）

| `LevelSnow` | 整数 | 等级 ≥ 参数 且 当前天气类别为"冰雹" |
| `LevelSandstorm` | 整数 | 等级 ≥ 参数 且 当前天气类别为"沙暴" |

| 方法 | 参数 | 判定语义 |

| `Trade` | 无 | 恒成立 |

### 3.4 战后上下文（战斗结束后对每个队伍成员判定）

| 方法 | 参数 | 判定语义 |
| --- | --- | --- |
| `BattleDealCriticalHit` | 整数 | 本场战斗中该成员对对方造成的要害打击次数 ≥ 参数（战斗记录归 WP42/WP32） |
| `EventAfterDamageTaken` | 整数 | 战后动作：该成员本场**承受的直接伤害累计 ≥ 49** 时把 ready_to_evolve 置真，**本次判定返回假**（不在战后直接进化）；随后由事件族的同一方法完成判定（§3.5）。整套记录/清零归 WP32 |

### 3.5 事件上下文（按事件编号判定）

| 方法 | 参数 | 判定语义 |
| --- | --- | --- |
| `Event` | 整数 | 触发编号 = 参数（样本：URSHIFU/编号 1） |
| `EventAfterDamageTaken` | 整数 | 触发编号 = 参数 且 ready_to_evolve 为真（样本：RUNERIGUS/编号 2，形态数据） |

### 3.6 仅进化后动作（不可作为检查目标）

| 方法 | 进化后动作 |
| --- | --- |
| `Shedinja` | 队伍未满且背包有普通球时：复制当前个体（§5.3）；随后消耗 1 个普通球；扫描终止。队伍已满或无球 -> 不复制（返回假，扫描继续） |

- 上表"后置：消耗"各方法统一动作：**仅当** 实际进化目标 = 该条目目标 **且** 个体仍持有参数物品 时，清除该持有；否则不动作（返回假，扫描继续）。
- `Shedinja` 无升级/道具/交换/战后/事件判定过程：**永远不会被选为进化目标**，只作为其它进化完成后的附加动作（数据样本：NINCADA 同时登记 `Ninjask` 与 `Shedinja` 两条目，实际目标恒为 NINJASK，完成后附加复制）。

### 3.7 特殊与无效条目

- `None`：无任何判定与动作；检查时整体排除，永不作目标（数据样本：PERRSERKER、MRRIME、RUNERIGUS 等"由形式/条件另行达成"的条目）。
- **最小等级数据推导**：物种最小等级由前身条目推导——前身有熏香 -> 1；方法无升级判定且非 `Shedinja` -> 等于前身最小等级；否则按 any_level_up：真 -> 前身最小等级+1，假 -> 参数字面值。该推导是数据/展示语义，不影响本包检查接口。
- **进化数据的其它消费者**（登记，不重复其规则）：月球球按"家族是否含使用该石的物品进化"判定（WP38）；物种/家族枚举与蛋招式回退使用家族进化（WP33/WP34）。

判定输入读取的执行时机（位置/时间/天气/状态族）与完整触发责任按 WP32 登记（§10）。

## 4. WP31-B：检查接口与守卫

### 4.1 五类检查入口

| 入口 | 判定家族 | 额外输入 |
| --- | --- | --- |
| 升级检查 | 升级（§3.1） | 无 |
| 使用道具检查 | 道具（§3.2） | 使用的物品标识 |
| 交换检查 | 交换（§3.3） | 对等方个体 |
| 战后检查 | 战后（§3.4） | 队伍席位索引 |
| 事件检查 | 事件（§3.5） | 触发编号（缺省 0） |

### 4.2 统一守卫（全部入口、全部家族）

按顺序在判定前检查，**任一命中即返回空（无进化）**：

1. 蛋 或 Shadow -> 空。
2. 持有"不变之石" -> 空（含使用进化石等道具入口）。
3. 特性为"羁绊变身" -> 空。

### 4.3 目标选择与返回

- 取**当前物种/形态**的进化条目（排除前身条目与 `None`），**按数据顺序**逐条执行对应家族的判定；**首个命中即返回其目标物种**；其后条目不再判定。
- 全部未命中 -> 返回空。
- 返回值为"目标物种标识"或空；**判定不写入个体状态**——唯一例外是战后族的 `EventAfterDamageTaken` 会置 ready_to_evolve 标记（§3.4）。
- 同族多条目互斥/重叠由数据决定（样本：TYROGUE 三选一由攻防关系互斥；WURMPLE 由个体号位互斥；EEVEE 同目标可出现多条不同条件的重复条目，命中顺序按数据）。
- 检查**不接受等级提升要求参数**：`Level*` 的"等级 ≥ 参数"是条件本身；`any_level_up` 族（Happiness/HoldItem/HasMove/Location 等）由**调用上下文**提供升级事件（§6）。

## 5. WP31-C：提交过程（进化演出）

### 5.1 准备与取消

1. 显示确认性文本（"什么？"）并等待；播放当前形态叫声；显示"{名字} 正在进化！"；短暂停顿后进入动画。
2. 动画：旧形态与目标形态两个展示交替缩放（总时长上限约 9 秒）；目标形态在完成前不可见。
3. **取消**（仅当入口允许，§6）：动画期间按取消键 -> 播放取消音效、`evolutions_cancelled` 计数 +1、显示"咦？{名字} 停止了进化！"；**物种不变**、不执行提交；此前已完成的等级/经验/友好/学招/统计等保持。
4. 动画自然结束 -> 进入成功提交（§5.2）。

### 5.2 成功提交（写入顺序，静态核对）

| 步 | 动作 | 备注 |
| --- | --- | --- |
| 1 | `evolution_count` 计数 +1；播放**新物种**叫声（时长按物种叫声数据） | 统计目录 WP06 引用 |
| 2 | 音效与祝贺消息："恭喜！{旧名} 进化成了 {新物种名}！" | 旧名 = 个体当前显示名（含昵称） |
| 3 | **进化后动作扫描**（物种变更之前）：按旧物种条目顺序执行 after-evolution 动作；首个返回真的动作终止扫描 | ① 持有物品消耗族：实际进化目标 = 条目目标 且 仍持有参数物品 -> 清除持有；② `Shedinja` 复制（§5.3） |
| 4 | 记录是否濒死 -> **物种变更**（形态默认化/派生缓存失效/能力重算，引用 WP18 §3.4、WP19 §4.6） | 昵称、来源、拥有者、球、标记/缎带等不在变更范围内 |
| 5 | 若变更前濒死 -> 当前 HP 保持 0（濒死） | 非濒死者当前 HP 按 WP19 写回规则 |
| 6 | 能力重算（显式第二次；让新物种/形态生效） | 引用 WP19 §4.6 |
| 7 | `ready_to_evolve` 置假 | §2 标记语义 |
| 8 | 图鉴：登记个体（新物种）＋标记"已拥有"（引用 WP62）；首次拥有且 拥有图鉴 且 物种在解锁图鉴内 且 **配置开启"更频繁提示新物种"** -> 额外消息＋记录"最近见过"＋打开图鉴信息页 | 与 WP26 §3.2 的条件展示同构（引用） |
| 9 | **进化时招式**：新物种等级学习表中 等级为 0（"进化时学习"）或 等于当前等级的条目，按列表顺序逐个经**通用版学习入口**习得 | 已掌握 -> 静默跳过；满槽 -> 询问遗忘（摘要界面）/放弃；配招引用 WP30 §6.1–6.3、WP20 §5.4 |
| 10 | 收尾：关闭演出画面 | 走图鉴信息页路径且无待学招式时在页内提前关闭；否则学习完成后由调用方关闭 |

### 5.3 额外个体（复制，当前数据仅 Shedinja 型）

- **前提（按顺序）**：队伍未满 -> 否则不复制；背包有普通球 -> 否则不复制。
- **动作**：克隆提交中的个体（此时仍为进化前形态）-> 目标物种设为**条目的目标物种** -> 清除昵称、标记、持有、全部缎带；球重置为普通球 -> 能力重算 -> 完全治疗 -> 追加到队伍末尾 -> 图鉴登记个体＋标记"已拥有"（目标物种）-> 消耗 1 个普通球 -> 扫描终止。
- **边界**：条件在追加之前检查；"复制成功"只表示追加写入完成，**不等于**后续流程（命名/展示等）成功；原个体的进化提交不受复制失败影响（无球/满员时仅跳过复制）。
- 复制体为独立个体（克隆时携带原个体的个体号等完整数据；参考侧是否重设个体号未定位，见 §13）。

| 入口 | 检查调用 | 演出可取消 | 阻止/失败 | 取消后的已发生变更 | 消耗归属 |
| --- | --- | --- | --- | --- | --- |
| 等级设置辅助·升级分支 | 先学习跨越区间的等级招式 -> 再判升级族 | **是** | 守卫或全部未命中 -> 无进化、无消息 | 等级/能力/友好/学招保持 | 调用方道具（若有）按处理器返回值处理，与取消无关 |

- **"同名工具不自动视为同一流程"**：演出入口有三种形态——可取消（多个入口共用）、不可取消（道具/交换）、单成员触发（事件对每个成员独立起一次）。取消语义只在允许的入口存在，且取消**不消耗任何提交内部物品**。
- 道具入口的界面标注（进化石在队伍界面的"可/不可"）由检查结果在打开界面**前**计算；进化后界面刷新并重算标注（WP28 §UI 交界）。

## 7. 规则与不变量

1. **判定与提交分离**：检查入口只读判定并返回首个目标物种；唯一判定副作用是战后族的 ready_to_evolve 置真。提交由演出完成。
2. **统一守卫四条**：蛋/Shadow/不变之石/羁绊变身——全部家族的判定前统一返回空；道具入口对 Shadow 还另有界面前置消息。
3. **目标唯一性与顺序**：每物种条目按数据顺序取首个命中；同族多条目不合并不重试；`None` 与前身条目不参与。
4. **提交顺序固定**：统计→音效/消息→进化后动作（消耗/复制）→物种变更→濒死保持→重算→标记清除→图鉴→进化时招式→收尾。取消只阻止该顺序中"物种变更及之后"的全部步骤。
5. **消耗归属两分**：提交内消耗＝持有物品族与 `TradeItem`（条件=实际进化匹配且仍持有）、复制族普通球；入口层消耗＝进化石/糖果等由道具处理器返回值决定（与取消无关）。两类不重复扣减。
6. **复制与进化相互独立**：复制失败（满员/无球）不改变进化结果；复制体为条目目标物种（当前数据=Shedinja）而原个体照常变为实际目标。
7. **保留清单**：昵称/来源/拥有者/性别/异色/个体值/性格/标记/缎带/生殖字段在提交中不变；未命名个体继续按新物种名显示。
8. 统计：成功与取消分别计数（`evolution_count`/`evolutions_cancelled`）；进化不改变"交换次数"等其它统计。
9. 形态：物种变更后的形态优先级/缓存失效引用 WP18 §3.4（本包不重复）；`ready_to_evolve` 在提交完成、濒死、治疗后清除。
10. 演出可取消性由**入口**决定（§6），不由条件族决定。

## 8. 边界与失败

- 全部条件未命中：无进化、无副作用（§7.1 例外除外）；升级类路径静默，道具类路径显示"没有任何效果"。
- 蛋/Shadow：检查恒空；道具入口对 Shadow 有前置消息；蛋在道具入口被资格守卫拦截（WP28 引用）。
- 不变之石/羁绊变身：恒空——包括对持有不变之石者使用进化石（"没有任何效果"，不消耗）。
- 复制边界：队伍已满 或 背包无普通球 -> 不复制（先查队伍，再查球）；进化照常完成。
- 标记清除的例外：容器流转的"存入治疗"路径会临时保留并恢复 ready_to_evolve 标记（存放治疗；引用 WP25 §4.1/§6）——与"治疗清除标记"的常规路径区分。
- 提交内学招边界：已掌握 -> 静默跳过（不重复学习）；满槽 -> 遗忘/放弃；放弃只影响该招式，**不回滚**已完成的进化。
- 取消只存在于允许的入口且只在动画期间；取消不改变物种、不消耗提交内部物品；对稀有糖果满级分支，取消**不会**阻止糖果消耗（静态推导）。
- 战后含濒死配置：濒死者可参与检查并可进化（提交后 HP 保持 0）。
- 满级稀有糖果路径：无等级变化时"需任意升级"族（Happiness 等）也可被判定命中（判定本身不含等级比较；静态推论）。
- `None` 条目：视为无效（数据样本：PERRSERKER 等），不产生目标。
- 事件编号未命中或被使用过的编号：不产生动作；事件调用者材料缺失（U01）。
- 演出提前关闭路径（图鉴信息页且无待学招）：属展示收尾差异，不改变提交已写入的状态。
