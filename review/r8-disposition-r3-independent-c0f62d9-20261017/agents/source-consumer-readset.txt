## 4. 战斗初始化与布局

### 4.1 初始化

- 拒绝：参与数组 1 为空 →「Party 1 has no Pokémon.」；参与数组 2 为空 →「Party 2 has no Pokémon.」（异常抛出，创建失败）。
- 初始值：侧尺寸 [1,1]；决定 0；回合计 0；可逃/可换 = 真、可败 = 假；开关动画 = 真；经验/金钱收益 = 真；禁用球 = 假；发送盒子默认 1；Mega 登记每训练家 −1；初始持有物记录双方创建时道具；参战标记全假；记录带环标志的物品身份，建立 AI 选择所需的战斗上下文。
- 阵营判定：对方训练家为空 → 野生战斗；否则训练家战斗。单个训练家按一名所有者处理；未提供身份仍保留野生边界，不要求包装为单元素数组。
- 队伍顺序数组初始为自然顺序；战斗内换人只重排顺序数组而不重排参与数组（WP41）。

### 4.2 布局尺寸目录（支持集合）

尺寸字符串 → [玩家侧， 对方侧]：triple/3v3 → [3,3]；3v2 → [3,2]；3v1 → [3,1]；2v3 → [2,3]；double/2v2 → [2,2]；2v1 → [2,1]；1v3 → [1,3]；1v2 → [1,2]；其它/缺省 → [1,1]。

- 上限 = 每侧 3 席；不存在 4 席及以上的已支持布局（源注释明示需要改代码；见未决）。
- 单打判定 = 双侧各 1；单打/双打/三打日志与开场动画类型由尺寸推导。
- 位置编号：席位索引 i 的侧 = i % 2（0 玩家侧、1 对方侧）；同侧席位对为 i 与 i+2……；最大席位索引由较大侧尺寸推导。
- 对面取序（给定全局席位索引，返回对侧席位「最直接对面 → 次之」的完整序；用于目标光标与「最直接对面」）：

| 布局（我方×对方） | 我方席位视角 | 对方席位视角 |
| --- | --- | --- |
| 1v1 | 0 → [1] | 1 → [0] |
| 1v2 | 0 → [3,1] | 1/3 → [0] |
| 1v3 | 0 → [3,5,1] | 1/3/5 → [0] |
| 2v1 | 0/2 → [1] | 1 → [0,2] |
| 2v2 | 0 → [3,1]；2 → [1,3] | 1 → [2,0]；3 → [0,2] |
| 2v3 | 0 → [5,3,1]；2 → [3,1,5] | 1 → [2,0]；3/5 → [0,2] |
| 3v1 | 0/2/4 → [1] | 1 → [2,0,4] |
| 3v2 | 0 → [3,1]；2 → [3,1]；4 → [1,3] | 1 → [2,4,0]；3 → [2,0,4] |
| 3v3 | 0 → [5,3,1]；2 → [3,5,1]；4 → [1,3,5] | 1 → [4,2,0]；3 → [2,0,4]；5 → [0,2,4] |

（3v2 全局席位 1 → [2,4,0] 为具名核对点；全部九种布局均已列出，不再以示例代替全表。）

- 邻近关系（用于邻近限定效果，WP44/45 引用）：双侧均 ≤ 2 → 除自身外任意两席位均邻近；更大布局按「不相邻对」表判定——基础对 {0,4}、{1,5}（覆盖 3v1/1v3）；3v3 追加 {0,1}、{4,5}；3v2 追加 {0,1}、{3,4}；2v3 追加 {0,1}、{2,5}。两名席位命中任一不相邻对 → 非邻近；否则邻近（同一席位除外）。

### 4.3 参与者保真与缩减

1. 硬性拒绝：训练家战斗且任一侧尺寸 > 2，同时双方都多于 1 名训练家 → 报错「Can't have battles larger than 2v2 where both sides have multiple trainers」（理由：多训练家时远位参战者无法互相接近）。
2. 野生侧自动同步：参与者校验按队统计可战斗野生计数；若它与野生侧尺寸不一致，双侧原相等则双侧同改为该计数，否则只改野生侧。此处区别于 §3.1 核心起初按输入对手个数设置默认尺寸的时点。
3. 每训练家必需席位与首个失败：先比较需占位的业主范围与实际建立的可战斗计数范围，再逐业主比较席位需求。计数只在遇到可战斗成员时建立；缺失计数不自动规范化为 0。已有 NPC 对象的非空全濒死队伍可通过构造的非空门，但默认 1v1 中需求范围为 1、计数范围为空，先报 invalid-owner 错误，不到“has no able Pokémon”分支。若某个较早队伍段没有可战斗成员、较后段有，范围中间可为空值；范围长度门通过后，对空计数的数量比较可先失败，不能统一宣称消息分支可达。实际存在的计数项若无席位则有该侧具名错误；可比较的计数不足而必需席位为 1 时，才到“has no able Pokémon”分支。普通生成数据、已有对象与人为不完整段分别看待；不声称默认 PBS 一定提供异常队伍。训练家核心此前已触发开战记录并清创建期规则，失败不承诺回滚。
4. 缩减循环：某训练家可战斗数不足以填其必需席位 → 训练家战斗将两侧中较大者 −1（相等时两侧一起 −1）后重试；野生战斗只改玩家侧（野生侧固定）。缩到 0 → 报错「Couldn't lower either side's size any further, battle isn't possible」。具名场景：① 两侧各一名训练家、原 2v2、玩家仅 1 只可战斗而对方至少 2 只 → 降到 1v1；② 两只可战斗野生、玩家仅 1 只且无伙伴（原 2v2）→ 1v2（野生侧固定、仅玩家侧降）。
5. 第 4 项的不足席位缩减循环只删减、不新增，不会补造额外个体；第 2 项野生同步可另行增加配置人数（BC-16）。配置人数不保证等于随后按原始输入建立的全部席位。

### 4.3.1 已有野生个体的零计数与原序边界

<a id="wild-input-boundaries"></a>

以下均为已有个体对象的有限输入，不声称正常遭遇生成必然提供这些状态。共同前提：固定默认规则、玩家至少一名健康非蛋成员，无伙伴、调试跳过或覆写，无改变输入的钩子；个体及所用数据有效，前序依赖正常返回。玩家本人零可战斗成员属于更早 §3.4 跳过，已有 NPC 异常仍按 §4.3 第 3 项。

**野生侧零可战斗成员**：仅输入一个合法非蛋个体 P，HP0。非空构造门通过，但首段可战斗计数没有建立，不能当作数值0。默认相等 1v1 在野生同步后两侧人数均缺失，玩家侧布局枚举先失败；早于业主席位比较、实际战斗席位建立及战斗场景启动，也早于专门捕获战斗中止的范围。开战记录和创建期规则清空已发生；外层过渡若已正常进入，还可能已写战斗中标志、暂停音频和压入淡出状态。局部没有覆盖该异常的必执行恢复；正常过渡清理、战后善后、输入刷新和结果写回均未到达，远层宿主恢复未知。

显式不等边 2v1 是另一控制：玩家需求可先缩为1，野生人数仍缺失，该缺失侧可被前一需求遍历跳过，后续布局消费者才可能首先失败；不复用默认相等例的首失败结论。单独一个蛋同样不建立可战斗计数；蛋与健康成员混合则可通过人数检查，随后在实际席位初始化拒绝蛋，保留此前前缀。

**正计数、混合原序**：玩家仅一名健康成员；依次输入普通非蛋 [P HP0, Q 健康]，如默认 CATERPIE、SHIELDDUST、无持物、具有有效且可用的 TACKLE/STRINGSHOT，无相关形态或入场干扰。默认初始2v2先按可战斗计数1同步为1v1，参与校验可返回；实际野生席位却按全部原始输入建立为 P席1、Q席3，玩家席0。野生专用入场/已见/参战使用记录先处理两只，AI 包装也可见全部实际席位。正常资源与回调下，场景精灵/数据框初始化可接触席3，而后续按配置人数的野生叫声、数据框出现等遍历只取席1；这只是请求与遍历边界，不保证最终像素或声音。

配置1v1的全量行动序只纳入配置最大席位1以内的现有席0、1；普通存活优先序只有席0，实际存活集合却为席0、3。完整入场效果按该缓存速度序消费时漏掉Q，较早野生入场钩子与其后遍历实际存活者的形态检查仍可见Q。命令阶段按实际席位扫描，跳过昏厥P；在通常前门、技能0及有效招式前提下Q可被AI登记行动，但普通攻击及强制先动/压后消费者仍遍历既有优先序，不因此补入Q。增量重算只更新已有条目，也不插入它。胜负按参与队伍可战斗状态判断，不能由“Q漏行动”推出自动获胜或完整对局结果。

反向对照：交换为 [Q健康, P HP0]，仍1v1但Q在席1，进入行动序；两只都健康且玩家仅一只则1v2，席1、3均在配置范围；显式3v1且玩家三名健康成员时最大席位4也可纳入Q席3。因此不是所有布局均漏Q。启用伙伴可能在更早的伙伴业主无可分配席位处失败，不能套用上述无伙伴全过程。参见 WP40 §6.1 与 WP67-A §3.2/§12；配套目录的 R8-U06-Z/M 向量仅作静态推导。

### 4.4 派出与开场

- 开场消息与派出顺序：对方先、玩家后；对方多名训练家/伙伴按序拼接消息；玩家消息最后。
- 野生开场按对手个数 1/2/3 具名消息；训练家按对方人数具名「挑战」消息。
- 派出对每个席位调用入场形态钩子（§7.2）；野生席位在建立时另外以「wild = true」调用一次入场钩子并登记已见（图鉴「见过」，WP62 前向）。
- 开场后按顺序播放：天气播报（当前战斗天气，WP45 前向）→ 场地播报 → 全员入场特性检查（WP49 前向）→ 进入主循环（命令 → 攻击 → 回合末，WP40/41/42）。

### 4.4.1 多训练家三打的开场显示秩

显示秩初始自然，与完成初始派出后的结果分开；实际参与成员和显示秩也不保证始终是同一长度的全排列。普通训练家核心显式 triple、noPartner，玩家单业主3名可战，对方业主 A/B 各2名可战，合并顺序 A0/A1/B0/B1、段起点0/2：没有命中“双侧都多业主”的拒绝门，需求玩家3、对方A2/B1均满足。A的队伍下标0/1绑定敌席1/3，B的下标2绑定敌席5。

在 B 首次初始派出已绑定之后，开场重排把该成员的秩与“B段起点＋全侧已派出数”的位置交换；此前全侧已派出2名，目的位置4越过原4项记录。审计向量[0,1,2,3]→[0,1,空,3,2]，队伍下标2的显示秩缺项而参与成员仍只有4名。这是合法输入的开场生产边界，不要求未来采用五项数组或复制交换实现，也不等于 GR-013 参战布尔记录错位。

同样2＋2只改双打：初始派出后[0,1,3,2]，没有同一空秩，但不是保持自然顺序；三打而第二业主3名、合并5名：初始派出后[0,1,4,3,2]，目的位置4存在。三打主例后续健康 B0 活换到同业主健康后备 B1、B1 原能力幻觉且无有效中和气体时，替补消息末位查询在新成员绑定前可因该缺秩失败，完整持久/场上副本前缀与对照见 WP41 §4.1.1。没有触发该查询时，不由空秩本身断言开场或任意动作必失败；真实演出、AI选择和未来兼容范围另有边界。

## 9. 边界与失败

- 空参与数组 → 战斗初始化报错（Party 1/2 has no Pokémon）。
- 训练家数据缺失：装载失败先进入「补齐」回调再重试，仍失败才报错；类型/名称/版本号非法各有具名错误。
- 野生等级越界/未知物种/悬挂配对 → 报错（§3.3）；训练家悬挂配对 → 报错。
- 跳过：无成员或调试+Ctrl；训练家且无成员 → 结果 0（未决），否则 1。
- 尺寸不可能：可比较的成员不足路径逐级缩减，到 0 报错；多训练家 > 2 席组合立即拒绝。业主席位/计数比较和已有野生缺失计数可能更早失败，具体首失败及混合原序按 §4.3/§4.3.1，不统一保证到达缩零消息。
- 中止：战斗内中止异常由上层捕获 → 决定置 0 并结束战斗；调试模式回合数 ≥ 100 → 以「按时判定」（可战斗数 → 总 HP）生成结果后中止。
- 对视合并：待战登记后若第二个事件未出现（例如玩家离开），登记保留到下一次任一训练家事件触发（静态记录，不承诺清理）。
- 结果解码按包装分列：野生包装只对 2（负）/5（平）返回假，对 3（逃/弃权）/4（捕获）返回真；训练家包装只对 1（胜）返回真，3/4/5 均为假。野生覆写截断时直接返回钩子值，不经过普通结果归一。
- 未运行确认：开场动画、消息顺序帧、伙伴实际编队、调试跳过均未运行验证。

## 3. 命令阶段

### 3.1 回合的三阶段

命令阶段 → 攻击阶段 → 回合末（本规格只覆盖前两者中与选择/执行合同有关的部分；回合末归 WP42）。

### 3.2 命令阶段流程

1. 复选清空：可出示命令者的选择直接清空，不执行撤销退款；因此此前资格失败已退款但残留物品身份者在此只清身份，见 §4.2.1。不可出示者保留（多回合招式中途等）。
2. 只把「非负的未执行 Mega 登记」复位为 −1（登记值 ≥ 0 → −1；已用的 −2 保留——「每训练家一场一次」的资格不因命令阶段复位而跨回合回退）。
3. 玩家循环（按席位升序，仅玩家拥有席位）：跳过裁定/已登记/不可出示者；每席位进入小循环：
   - 主菜单返回：−1 取消（返回上一席位）、0 战斗、1 背包、2 宝可梦、3 逃跑/取消或 Call、4 Call、−2 调试菜单。
   - 逃跑仅对「本回合第一个被选择的席位」出示；选择后当场尝试（见 §3.3）——返回 −1/1 都停止本回合其余选择（−1 已消耗本行动）、返回 0 则撤销选择继续；对后续席位该格显示「取消」。
   - Call 仅当「暗影类型存在且为训练家战斗」时替代逃跑格（也被目标菜单模式表沿用）。
   - 被抓住（天空摔投）期间除「招式」外均拒绝并提示。
   - 成功登记会跳出小循环、保留选择（供攻击阶段使用）；取消点只在未成功退出的路径：战斗/背包/宝可梦/逃跑菜单返回失败或取消时，走小循环末尾的撤销（物品未用 → 退回；已登记 Mega → 撤销；清空槽位）。返回上一席位（−1）分支只撤销上一席位的选择；更新已选择席位记录后退出小循环，不额外对当前席位调用一次撤销。
   - 选择逃跑即当场尝试（见 §3.3）；调试结局菜单的取消也返回 −1，同样停止本回合其余选择（决定不变）。
   - 战斗结束（决定非 0）→ 立即停止全部选择。
4. AI 循环（同席位扫描，选择权非玩家或玩家侧 AI 控制）：调用 AI 默认命令接口；不读取本规格之外的 AI 评分。
5. 选择登记后的再次进入（同一小循环内重选）：先予撤销；重选覆盖。

### 3.3 各命令的登记语义（分族，不共用一个合同）

- 招式：合法性 → 登记 →（非单打）选择目标并登记目标；Mega 登记在战斗菜单内切换（−2，见本节 Mega 条目）；放弃 →（−1）取消。
- 背包：见 §4.2；登记即从库存扣除（部分物品）；可「占满回合」（投球）。
- 宝可梦：查看/换人入口（可取消）；换人登记的完整资格与执行归 WP41；命令阶段只登记 SwitchOut。
- 逃跑（玩家）：在命令阶段当场尝试（即时调用逃跑判定并消费返回值）：返回 0（不可尝试/被拒前门）→ 撤销选择、继续命令选择；−1（失败，已消耗本行动）或 1（成功，决定置 3）→ 停止本回合其余玩家选择。概率/守卫细则归 WP41，本规格只登记时点与返回消费者。敌侧野生：由对应调用者登记 Run 并返回 −1（无玩家式即时判定）；攻击阶段的「漫游必逃」（总是逃跑规则）是独立执行路径（按决定 3 结束）——不能从存在 Run 枚举推导「所有 Run 同义」。
- Call：登记 Call（无目标）。
- Shift：仅在可 Shift 为真时于战斗菜单内可选（−3）；登记 Shift 且撤销已登记的 Mega；实际位置交换结果归 WP41。
- Mega 登记：战斗菜单内切换（−2）——登记/取消/互换；登记后继续选招；取消整份选择或改选 Shift 会撤销。

## 6. 行动顺序

### 6.1 排序输入

- 参与集合：全量计算只扫描配置布局的最大席位以内的现有席位（空位跳过），不自动纳入所有已建立对象；每席位需要其身份、速度、招式优先级、特性/道具子优先级与最终子优先级、平局序。只规定比较输入及其来源，不规定七项条目或内部存储。
- 招式优先级：招式基础优先级 → 特性改写（先制类，WP48/WP50 提供具体族）；保存该行动的结果供精神场地/快守检查读取。
- 子优先级（仅招式与 Shift 选择计算）：特性族（如 STALL；QUICKDRAW 另有概率触发）与道具族（先制爪/释迦果/迟钝尾/满腹香炉等）分别取子优先级；合并规则：若特性为 0 且道具有值、或特性为负而道具为正 → 采用道具并标记「道具来源」；否则若特性非 0 → 标记「特性来源」；两来源标记供提示消息。
- 平局序：全量计算时为随机洗牌序；每次全量计算重新随机——同一回合内多次调用（非全量）保持既有平局序稳定。
- 已有野生混合输入的配置/实际席位差见 WP39 §4.3.1：默认 [P昏厥,Q健康] 可形成配置1v1、实际存活席0/3，而全量仅纳入席0/1，普通存活序仅席0；命令枚举可见Q不等于它被调度。增量只更新已有条目，不补入Q；反向原序及较大布局分别按该节控制，正常排序按本节其余规则。

### 6.2 排序规则

按序比较：招式优先级（高者先）→ 最终子优先级（高者先）→ 空间（戏法空间）状态：开启时速度低者先、否则速度高者先（比较速度值）→ 平局序。

### 6.3 重算与重排时点

- 全量计算：攻击阶段开始时一次。
- 增量重算（不重全量、可传席位子集）：仅当以下触发且配置开启：速度变化后（物品执行完之后/每次单席位行动之后）——重读速度与「特性改变的招式优先级」，任一变化即重排；戏法空间状态与快照不一致 → 重排（快照在计算时捕获）。
- Mega 进化后：可选按「仅该席位」重算（配置）。
- 仅速度排序变体：供重定向/技能优先级等场合（按速度＋平局序，忽略招式优先级）。
- 已行动者在招式阶段被跳过但仍在序表中。

## 4. 成长调用与持续战斗反馈（B）

### 4.1 触发与接收集合

成长调用的实际位置包括：正常使用招式在结束模式破坏者标志后、动作结束/指令/舞者之前；使用前置失败可能自伤倒下的分支；火药自伤失败分支；捕获成功且开捕获经验时；入场危害倒下时；回合末具名两个成长点；特性/道具触发的替补中也可能嵌套这些路径。成长不等于战斗已经结束。

成长入口先检查野生胜利音乐条件（对方全无可战斗、本方仍有），之后才因非内部战斗或经验开关关而退出。此时不分配 EV/经验，也不清待处理参与者。

正常分配逐场上对方对象扫描：必须有非空参与者记录，且当前濒死或临时捕获标记真。接收者必须当前可战斗且属于玩家本人队伍段；统计有效参战者时还核对所有权。经验全体来源是玩家标志或背包装置；没有经验全体时才收集当前或还原记录持有经验分享道具的合格成员。参与者记录为空仍会在更早处跳过，不能由 Exp All 推导总能分配。有记录但有效参战者为 0，与记录空不是同一情况。

先按玩家队伍段顺序处理参战/分享者：每人先 EV、再经验。然后若经验全体生效，再按段顺序给其余可战斗成员，整体提示只对这一轮的首名，个别经验消息参数另控。该对手本次处理后清参与者记录，避免再次就同一登记分配；无当前合格接收者也可清记录。伙伴只影响战斗参与与胜负，不加入这份玩家本人分配循环。

### 4.2 经验、EV 与场上副本

具体收益和钳制引用 WP30 §4.2/WP19：人数份额分别向下取整后相加，基础份额≤0早退先于训练家倍率/缩放/+1；缩放先整除5，再乘实数等级因子并取整，后续各整数倍率逐项取整。CATERPIE L2基础经验39对L3接收者的限定例给13而非14（G11）；基础份额0仍保留已分配EV，不靠+1产生收益（G12）。当前持有物修正无结果时可回退到当前还原记录的物品，不能当作两个修正必然叠加（完整物品处理器 WP50）。EV 正常分配先写持久个体/所述暗影暂存，不在 EV 子步骤统一刷新能力。普通非 Shadow 分配的非负余量前提及正常模板 HP EV255 的首项反向区间失败沿 WP19 §5.3：该最小失败尚未写此接收者 EV/经验，且未到该对手参与者记录清空；此前已处理接收者及回调前缀不保证回滚。默认非内部设施仍在成长早门返回。

| 路径 | 提交/同步时点 |
| --- | --- |
| 已到最大经验 | EV 已处理；重算持久个体能力后直接返回，没有这一入口的场上副本刷新。不承诺 EV 总会立刻改变当前场上攻防/速度 |
| 算出的经验 ≤ 0 或钳后增量 ≤ 0 | 直接返回；前面的 EV 写入不回滚，未保证调用能力重算或场上刷新 |
| 非暗影且有实际经验 | 先写实际获得经验统计；按下一个等级阈值分段写入持久经验，才调用经验条演出并等待其完成；逐个新等级做能力/HP 重算与场上回读，再显示升级消息/两页能力变化并处理该级所有学习项 |
| 非升级的末段 | 持久个体重算，然后在场者回读并刷新展示，即使本次没升一级；多级路径最后也有该收尾，不省略为只处理最高级 |
| 在场升级 | 友好度「升级」调用仅对当前在场引用；HP/等级/总 HP 回读。非变身时回读五项普通能力；变身中仍读等级/HP，但不覆盖变身五项数值。这里不是完整属性/特性刷新 |
| 后备升级 | 持久经验与能力按路径提交；没有场上对象则无战斗数据框经验条，也无在场升级友好度；仍有升级/学招消息消费 |
| 暗影分支 | 按 WP30 已审写入覆盖：心阶段 ≤ 3 且允许增加时实际增量进暂存经验、统计增加，当前经验不因此升级；心阶段更高不提交该经验；均不走普通逐级/学习循环。完整生命周期 WP23 |

升级的 HP 变化由 WP19 的重算规则给出，本规格不复制公式。数据矛盾导致新等级低于旧等级时明确报错；在此之前已写 EV，但通常尚未提交新的经验总量；不虚构事务回滚。

### 4.3 学招、取消与等待

按每个实际到达的新等级，遍历匹配该等级的全部学习表项。已有招直接跳过；有空槽时先写持久招式，再提示，随后在场列表追加战斗招式并检查招式变化形态。满槽先询问是否遗忘；接受才打开该单个体摘要遗忘选择，呈现4个旧招＋1个新招，返回招式槽或−1；没有先选择队伍成员这一层。取消返回负值后，确认放弃则结束本招学习，拒绝放弃则重新选择；起初拒绝遗忘也只结束本招。

选中槽后先替换持久招式及在场对应槽（生成新招式，PP/总 PP 按新招初始化），再显示忘记/学会消息，最后检查招式变化形态。战斗版不套通用机器教学保留旧 PP 分支，也不从其它学习接口搬来蛋/暗影拒绝或布尔返回语义。此调用者逐项继续处理学习表，不把取消一个招式当终止全部成长。

摘要消费者正常模式拒绝遗忘秘传招式并重新选择，调试可绕过；退回或选到新增招式的取消位置给 −1。实际 UI 等待期间，前面的经验/等级/能力写入已经发生；取消仅不替换该槽，不回滚成长、EV 或统计。无头像/素材的真实等待体验仍属未运行范围。

## 5. 招式/目标候选、分数转选择（D）

先遍历当前槽，真实选择查询拒的槽不入池（含有限 PP 0、安可/其它门）。设置评估招：仿效可换成先前全局招，自然之力先确定环境招、鹦鹉学舌按目标最近普通招可替换；替代只用于评估，最终登记仍原槽。评估会写本次 calcType/模式破坏者等临时数据，并非全程无副作用读取；完成评分将 moldBreaker 清假。预测失败标记开启且整招预计失败 → 保留分 20、目标 −1，不是从池删掉。

目标数据 0（自身/侧/全场等）直接算一份；目标 1 时先预计重定向，再遍历存活可目标者，且目标数据可针对敌方则额外排同侧，所以实际可打盟友的 NearOther 常不把盟友作单目标候选。每个目标是一条独立选择，目标较多会增加该槽条目数。多目标收全部合法目标后合成一分，不逐目标登记多个动作。PROTEAN 幽灵诅咒有目标型修正；每个具体预测和 ScoreMoves 内部由 WP52-A/B/C 承接，不将当前评分合成叫实际模拟。

AI 重定向近似：跳 cannotRedirect、非单一可敌目标、U 有效 PROPELLERTAIL/STALWART；按速度序，对侧存活/非天空摔投/邻近集合，Spotlight 用标记 −50 优先；跟我来分支或「怒粉且 U 受粉末影响」分支可改候选，后者并不带同一强度比较。随后电/水能力吸引找首个有效者（可盟友），若最终预计吸引到同侧，前述敌方候选过滤可能造成该槽无候选。不同于 WP47-A 真实流程，不反向修正实际规则。

野生额外偏好：个人 ID 除当前招式槽数取余得到一个槽，每次加入此槽候选时再加入相同条目一份；稳定但不以技能最优性为准，多目标该槽也逐条重复。没有去重；正常一槽一目标、等权时这个槽机会翻倍。

具体分数以 100 为基准、20 预计失败、60 预计无用；WP52-A 负责目标评分、无效目标过滤、多目标平均/友军反转的共同合成。本规格最终选择只使用每条已取得非负分数。无候选 → 真实自动选择安可或挣扎入口；不是零分就必挣扎。

高技能且有仅换入后备时，最高分 ≤ 60：若近似可攻击则认为差招，否则 25% 认为差招；最高 < 100 × 阈值系数且在场 > 2 轮时 80% 认为差招。随后强迫换人尝试成功则撤 Mega 并结束，失败继续原候选；原有 ConsiderSwitching 反标不一定禁止这条强迫路径，但 §3 首层禁止仍适用。

阈值系数从技能 0 的 0.6 至 ≥ 100 的 0.95，按技能比例平方根递增：基础 0.6，加 0.35 倍的 √（min（技能， 100）/100）。把最高分乘此系数向下取整得截值 q，每条权重 max（原分 − q, 0），最后在总整数权重中按原顺序累计选。技能更高通常排除低分但仍加权；不存在固定贪心最高分。没有候选与候选全部权重 0 不同，后者没有明确保底新选择：对零总量随机输入不当可用分布保证，循环不会因非负零权重命中条目，旧选择可能保持 None；记录为未运行边界。

选中调用真实招式登记，再按非负目标登记。这里未用登记返回真假再次重选；执行时仍可能局势变化。任意非法技能负值、缺数据、候选空随机等异常不保证统一修复；不得把 AI 目录等同合法动作生成的证明。

## 6. 类型与能力改变的偏好（E）

环境变型预测按真实默认环境表与当前类型可改条件；评分只看进攻招：有新类型伤害 +14，每个丢失旧类型有伤害 −14，不评防守改善。纹理 2：最近攻击类型当前已免疫 → 60；当前对它弱/中性/抗性时分别 +15/10/5。镜面属性只登记失败资格，没有特设效果分，保持通用基分。

纹理：失败按真实当代首槽/旧全槽候选；其效果评分登记逐目标族，而正常 User 类别目标数为0，不会通过通常候选消费该目标分。不能把「有注册」误写为当前普通路径一定应用；这也不等于普通候选总分必为100，其它通用修正仍可应用。

<a id="conversion-target-score"></a>

**纹理现存目标评分查询**：当合法 AI 上下文实际直接调用该已登记查询时，从使用者招式的原始类型取候选：世代≥6只看首槽，旧世代看全部槽；排除伪类型及使用者已经拥有的类型。此候选发现不查PP。随后按候选顺序找是否存在对应**计算后类型**的可用伤害招；这里的可用只按PP过滤（有限总PP>0且当前PP0的槽跳过），再查伤害分类和计算类型，不重复禁用、挑衅等完整命令选择资格。首个匹配只加14一次并停止，无匹配保持传入分；不使用目标属性，不套环境变型的失去旧类型扣分。正常合法输入下不写HP、持物、背包或存档，也不插入失败预测或新的默认消费路径；无确认/取消门，依赖异常可能传播，不承诺回滚。

静态对照：传入100，使用者当前NORMAL、当代首槽为有PP的FIRE伤害招、纹理位于后槽，直接查询得114；首槽改为已拥有的NORMAL且后槽仍有FIRE，当代保持100、旧代可得114。首槽FIRE但有限PP0且没有其它可用FIRE伤害招，候选仍被发现而最终保持100；多个类型合格也只加一次14。普通原始User/0目标路径不进入这项贡献，不能据此改接线。燃尽只预测必须有火类型，无单独失去火系评分。

改 T 纯超能/纯水，遍历 T 的每个敌方成员全部伤害槽（不按 PP 过滤），以新单类型对每招相性：弱点 +10、免疫 −10；添加幽灵/草另在抗性 −5。这里不是比较完整旧类型与新类型差值。真实添加/替换及数据缺失资格沿 WP47-A 与对应真实前门。

基础能力评级完整 −2..10 默认表在附表，未知 0；中等起才应用该族的 20 条直接登记与 5 个复制目标（展开共 25 个身份，完整清单见附表）。评级假定能力本身可拥有，不自动验证其当前有效，具体招评分另做有效性门。

胃液：T 能力不活跃 → 60；评级 > 0 加至少 15（每点 5），< 0 减至少 15，友方符号反向。核心惩罚存在替身、不可失、能力不活跃或 U 更快时保持，否则按相同抑制评级；粗速度并非真实「目标已经行动」的完整条件。实际能力失去/获得后置和共享状态修改仍 WP47-B/48/49。

## 3. 物种内容与个体信息分层

### 3.1 物种记录的查找身份

1. 每条物种记录有 id（基形态为物种符号本身；形态 N>0 为「物种_N」）、species（基身份）、form（编号）。
2. 按形态查找的回退：请求「物种+形态 f」时，若形态记录不存在，回退到基形态记录；基记录也不存在则整体未命中。调用入口按 WP03 的查找语义分层（报错入口 / 返回空入口 / 存在性判定）。
3. 枚举「全部物种」只遍历基形态记录（form 0）；物种计数同样只计基形态。
4. 形态记录在编译时从基记录继承未定义字段：标量字段直接拷贝；集合类字段（属性/基础能力/EV 产出/教学/蛋招式/特性/隐藏特性/蛋组/后代/标记）克隆；等级招式表与进化表为空时整表继承；三项野生持有物仅在全部为空时整组继承。运行时按「形态记录已含继承值」使用。

物种 egg_groups 的固定 15 个作者身份由 [WP03 §6.2](../generic-kernel/wp03-content-identity-and-schema.md#62-蛋群的固定作者身份目录)唯一给出；基础与形态显式成员按该域严格校验，省略默认与形态克隆仍按本节及 §3.2。

物种Shape/Color/Habitat采用[WP03固定目录](../generic-kernel/wp03-content-identity-and-schema.md#61-物种描述字段的固定身份目录)的14/10/10个精确身份、定义次序和14个参考体型图标位置；显示名再本地化。HeadArms/Gray/WatersEdge接受，未知身份枚举拒绝；基础省略仍Head/Red/None。Habitat不代替Area遭遇/地图查询。

前身关系在编译时按首次发现选择，形态对应关系优先再回基础关系，见[WP31 §3.8](../pokemon-rules/wp31-basic-evolution.md#38-作者前向列表合并与反向前身选择)。物种的最低等级与繁殖回溯消费已选前身；其它合法前向路径不被删除。既有形态继承、默认与个体生成次序保持。

### 3.4 物种/形态变更对个体的影响

**物种变更**（入口身份 species=；输入：物种/形态/记录标识；前置：记录存在，按 WP03）：

1. 解析目标记录；若目标记录的基身份与当前相同，无效果直接返回（边界：不能用此入口把个体切到同物种的另一形态）。
2. 设为基身份；形态目标：目标记录存在默认形态标记（DefaultForm_N）则取 N；否则若目标记录自身形态号 >0 则取该形态号；两者都没有则保留当前形态。
3. 清除 forced_form；若新物种为单性别/无性别，则清除性别缓存（下次读取时重派）；等级缓存清除（按当前经验、新成长曲线重派）；特性缓存清除（索引保留，特性按新物种重新解析）；重算能力。
4. 不改变：经验、招式、来源记录、拥有者、昵称、友好度等。

**形态变更**（三个入口的副作用差异，均登记为不变量）：

| 入口身份 | 形态处理器 | 特性缓存 | 能力重算 | 图鉴登记 | 中断点 |
| --- | --- | --- | --- | --- | --- |
| form= | 调用 | 清除 | 是 | 是（有玩家时；登记读取性别与普通异色——这两个缓存会因此被填充） | 无 |
| setForm | 调用 | 清除 | 是 | 是（有玩家时；登记读取性别与普通异色） | 形态已设、处理器未调用前让出一次（供提示消息） |
| form_simple= | 不调用 | 不清除 | 是 | 不登记 | 无 |

读取语义：

- form 读取：若 forced_form 有值优先返回；战斗中或仓库中直接返回存储形态（不触发处理器）；否则调用动态处理器，若结果不同则以 form= 写回。
- form_simple 读取：直接返回 forced_form 或存储形态（无处理器）。物种内容记录的读取（如基础能力数据）使用 form_simple。
- 按个体取正面／背面精灵或图标则先读取普通 form，继承其强制值、战斗／仓库守卫及动态提交合同，再以所得形态选资源（WP15 §4.1、WP21 §3.4/§4）。摘要的个体精灵／图标也消费此入口，前置界面构造须正常。低层按显式物种／形态取图仅消费已求值的数值参数；若调用者先读个体形态取得参数，整条调用链仍可能提交形态。WP35 §5.2 与 EG-13/20 已描述孵化演出的这一交界，保持其原范围。

边界：物种设置为未知标识按 WP03 查找失败处理（报错）；形态处理器结果与存储形态相同则不写回（不触发 form= 的副作用链）。

## 4. 战斗经验与 EV 分配

### 4.1 资格与收集

- 前置：内部战斗 且 战内「经验开关」为真；否则整体不分配（外部战斗模式按各自流程，登记为交界）。
- 遍历每个已倒下或被捕获且有过参与记录的对方个体；参与计数 = 参与列表内「仍在队、未濒死、战斗席位归属一致」的成员数——该归属是战斗内的席位/训练家分队索引（同一方持有者），不是个体原拥有者字段；原拥有者仅用于 §4.2 的「外来」倍率与队伍读取（WP18 引用）。
- 共享列表：仅当未启用全队时收集——未濒死且「当前持有点名物品或战斗开始时持有该物品」的队员。
- 有参与/共享/全队任一（且计数 > 0）时，对每名参与或共享成员：先 EV 后经验（经验消息对 Shadow 抑制）；再对全队模式下其余未濒死成员补一次 EV＋经验（补发经验消息被抑制，仅显示一次「其他宝可梦也获得了经验」）。
- 每个对方个体处理完后清空其参与列表。

### 4.2 经验计算（按实现顺序）

1. 已达最大经验：只重算能力（让新 EV 生效）后返回。
2. 基础量 a = 对方等级 × 对方基础经验。
3. 基础分配（所有人数除法在本步各自向下取整，受均分开关影响）：
   - 有共享列表且本人参与／共享：有效参与数0时，每名共享者得⌊a／共享数⌋（均分开）或a（关）；有效参与数>0且均分开时，参与资格取得⌊a／(2×参与数)⌋，共享资格取得⌊a／(2×共享数)⌋，兼任者相加两个已经截断的份额，不能先合成实数再取整。均分关时，参与者得a，否则共享者得⌊a／2⌋，兼任只取a。
   - 仅参与、无共享：均分开取⌊a／参与数⌋，关取a。
   - 仅全队、未参与：⌊a／2⌋。
   - **基础分配结果≤0立即返回**，早于训练家加成、缩放和资格+1；没有经验消息／写入／累计经验统计。调用者此前已经分配的EV仍保留，不回滚。外层仍要求该对方有非空参与记录；有效参与数0可以由其记录中成员已濒死等产生。
4. 训练家战加成：开关开启时 ×1.5（向下取整）。
5. 缩放：开时先把本步入口整数经验整除5取⌊经验/5⌋，再乘实数因子((2×对方等级+10)/(本人等级+对方等级+10))^2.5，再向下取整，参与者／共享者随后+1；关时整数经验整除7取⌊经验/7⌋，无+1。÷5前的截断不能推迟到因子乘完之后。
6. 外来加成：判据 = 拥有者 ID ≠ 玩家 ID，或（拥有者语言非 0 且 ≠ 玩家语言）；倍率二选一——语言非 0 且不同 → ×1.7；否则若 ID 不同 → ×1.5；语言为 0（未知）不产生语言加成；均为向下取整（不是先 1.5 再 1.7）。
7. 经验护符：检查背包（而非个体持有）→ ×3/2（向下取整）。
8. 持有效果修正：向「当前持有物」查询修正值，返回负值（无物品/无相应处理器）时才回退战斗开始时持有物（有效但无处理器的物品同样走回退）；修正接口归 WP50。
9. 亲密度加成（效果开且内部战斗且亲密度≥4且未Mega）：取⌊此前整数经验×6/5⌋，并置加成消息标志。每项倍率使用上一项已截断结果；经验护符⌊×3/2⌋，默认幸运蛋修正亦⌊×3/2⌋，顺序仍为护符→持物→亲密度，不合并倍率。
10. 经验钳制加法得终值；实际增量 ≤ 0 → 结束（无消息、无写入）。
11. 消息：「获得 N 点经验」或加成版；然后升级循环（§4.3）。
12. Shadow 例外（追到实际写入者，逐字登记）：先按最大经验钳制得到实际增量；心阶段 ≤ 3 → 写入经 Shadow 的「经验赋值」覆盖——暂存经验 += 实际增量、当前经验保持不变，统计同样按实际增量累加，随后返回（不走升级循环）；心阶段 > 3 → 该分支不增加任何经验、不累加统计。完整 Shadow 生命周期（解禁/净化/折算）归 WP23 前向。

### 4.3 升级循环（多级；逐级推进）

- 计算新等级（经验 → 等级）；若新等级小于当前等级 → 报错（不应发生）。
- 统计「累计获得经验」。
- 逐级循环：按等级边界写经验并播经验条动画；到达终点（多级已走完）→ 重算能力、刷新，结束。
- 每升一级：等级 +1 →（若该成员当前在场上）友好度 +「升级」增量 → 重算能力 →「升到了 Lv.N！」消息与升一级演出（前后六项数值）→ 学习该等级的招式（逐个经战斗版学习入口）。
- 备注：友好度「升级」变化只发生在当前在场上的成员（未上场者是经验到手但无该变化）；招式学习消息与形态复检（招式集变化后）见 §6。

### 4.4 EV 分配

- 来源 = 对方物种的 EV 产出表（内容数据）；先按持有效果修正接口——「当前持有物」查询返回否（无此处理器）时回退「战斗开始时持有物」（WP50）。
- 病毒（阶段 ≥ 1，含已治愈）：产出全部 ×2。
- Shadow 且心阶段 ≤ 3 且存在「暂存 EV」：增量写入暂存 EV，上限同时计入已暂存值（单项上限与总量上限均含暂存）——暂存/恢复细则归 WP23。
- 其他：逐项写入 clamp（0, 单项上限 − 已有点数） 且再 clamp（0, 总量上限 − 已有点数合计）；单项上限 252、总量上限 510（域归 WP19）。
- 普通分配要求两个剩余额度上界非负；已有越额存量不自动修复。WP19 §5.3 的模板 HP EV255 对照在第一项夹限即失败，早于本接收者 EV/经验写入；默认设施的非内部成长门及此前写入前缀沿该节，不扩张到 Shadow/道具。
- 本函数不触发能力重算；重算发生在升级循环/已达上限分支。

## 5. 兼容性、周期与取蛋

### 5.1 兼容性判定（返回 0–3）

按顺序（任一命中即 0）：

1. 占用槽数 ≠ 2 → 0。
2. 任一个体为 Shadow → 0。
3. 任一个体蛋组含 Undiscovered → 0。
4. 双方都非 Ditto 蛋组 且 蛋组交集为空 → 0。
5. 性别不兼容 → 0。性别兼容规则（任一项成立即兼容）：一雌一雄（任意槽序）；一方 Ditto 蛋组、另一方非 Ditto（任意性别/无性别；Ditto + Ditto 不兼容；无性别 + 无性别不兼容）。
6. 否则等级 = 1 +（同物种 ? 1 : 0）+（拥有者编号不同 ? 1 : 0），得 1–3。

- 拥有者比较用拥有者编号（WP24 引用）；与「拥有者名字/语言」无关（静态核对）。
- 等级值只反映上述三项，不读取遗传/道具（Everstone 等不影响兼容等级）。
- Ditto 的性别例外只在两个槽均占用、双方非 Shadow 且蛋组均不含 Undiscovered 后适用。默认 DITTO＋PICHU（普通非蛋、非 Shadow、任意有效拥有者 ID）兼容等级为 0，周期产蛋概率也为 0；DITTO＋通过先行门的可繁殖非 Ditto 才按物种与拥有者计算等级。该限制不增加到 §5.3 的直接生成/领取工具。

### 5.2 256 步周期与产蛋概率

- 每次「玩家迈步」事件：周期计数 +1；达到 256 时归零，并执行：
  1. 蛋生成检定（仅当 无已有蛋标记 且 占用槽数 = 2）：兼容等级 = c；基础概率 = [0, 20, 50, 70][c]；若背包持有圆形护符 → [0, 40, 80, 88][c]；0–99 抽样 < 概率 → 置「已有蛋标记」= 真（不生成实体、不占用队伍）。
  2. 蛋招共享检定（配置开启时；50% 概率）：见 §5.4。
- 概率是每个 256 步周期一次、单次掷值；兼容等级 0 → 概率 0（不会置标记）。
- 已有蛋标记置真后：后续周期不再做蛋生成检定（仍做蛋招共享与经验）；计数照常累计与清零。
- 复位时机：寄存、取回、领取蛋后复位（标记与计数同时归零）；调试入口可独立改写（WP73 交界）。

### 5.3 领取蛋

1. 由两个占用槽生成蛋——实际守卫仅「占用槽数 = 2」（生成入口在槽数 ≠ 2 时返回空 → 报错「无法生成蛋」）；生成入口不重查已有蛋标记与兼容性（两者仅在周期置标记层已确认；事件接待实际守卫仍待 U01，不据缺失材料肯定；不再泛化为「其它生成前置不满足」）。生成细节与遗传归 WP34。
2. 队伍已满 → 报错「队伍没有位置放蛋」。此时生成已发生：随机取值已消费、若病毒检定命中则感染统计已写入；失败不重置计数/已有蛋标记（可整理队伍后再领）——重试会重新生成一枚新蛋（不是复用已生成的那枚）。
3. 追加蛋到队伍末尾；复位蛋计数（标记与计数归零）。
- 次序要点：生成（含上述副作用）→ 容量检查 → 入队 → 复位；失败发生在入队前（未入队），但生成副作用已发生——静态记录。

### 5.4 蛋招共享（同物种互相教学；静态）

- 条件：占用 = 2、两槽物种相同、配置「同位寄存可共享蛋招」开启、且该周期共享检定命中（50%）。
- 两个方向分别计算（供方 → 学员）：学员有招式空位时，按供方当前招式槽顺序枚举供方招式，保留同时满足「在学员可接受蛋招表（带前身回溯的蛋招表，引用 WP18）中、供方已掌握、学员尚未掌握」的项；每方向取首项：
  - 仅一方有候选 → 该方向学员学会其首项（静默学习，WP20 引用）。
  - 双方各有候选 → 随机选一个方向，该方向学员学会其首项（另一方本周期不学）——不是随机挑任意候选招式。
  - 学员满槽的方向无候选；供方未掌握的接受表项不教学；均无候选 → 无动作。
- 接受表归属：用学员的表（不同形态可不同）；供方立场只决定「教什么、按供方槽序」。
- 蛋招表取值：共享教学使用带前身回溯的蛋招表（引用 WP18；与 WP34 生成直接读原始蛋招表的入口不同，勿混用）。本规格只登记共享入口与选取次序。

### 5.5 寄养经验与静默学招

- 配置「走步加经验」开启（默认世代 ≤ 6 开）时：每一步给每个占用槽 +1 经验（不产生消息、不触发友好/进化检查）。
- 经验达到新等级时：按新等级重算能力，并静默学习恰好在该等级的等级招式（learn_move：槽满时按该接口规则顶掉第一招，WP20 引用）；无升级消息、无友好变化、无进化检查（与战斗/升级辅助入口的差异登记）。
- 已达最大经验 → 不再增加（检查发生在加值前）。
- 配置关闭（默认世代 ≥ 7/8）时：无走步经验；在无其它等级写入、且无此前累积等级差的常规前提下等级差为 0、取回报价为 100——报价本身仍按「当前等级 − 寄存时等级」计算，不由该开关强制归零（该个体被其它途径改级时报价随之变化）。

## 3. 地图身份与连接关系

### 3.1 地图身份与加载

- 地图以整数 ID 标识；建立时读取对应数据文件，装入图块集、雾/背景配置，触发地图建立通知，并创建该图的事件与公共事件实例。
- 地图容器持有已加载地图与当前图索引；按索引取当前图：**索引 nil/负数归 0**；索引不命中但首图存在时**回退首图**并输出提示；全部为空才抛错。
- 地图有效范围：0 ≤ x < 宽、0 ≤ y < 高；宽松范围各向外扩 10 格（用于互动判断）。

#### 3.1.1 驻留复用与临时查询建立（GR3-M03-002）

按图ID查询先查已加载集合：命中则复用同一实例，不发新的建立通知；未命中则先实际建立地图。普通加载在建立成功后才加入集合；地形、目标通行及部分连接坐标查询采用“不加入集合”方式，**不加入只限制驻留，不省略读取、建立或通知**。建立通知在地图数据/图块集等前置初始化之后、运行时事件实例创建之前发出。

当前图A查询未驻留图B，不必先排队正式传送，也不因这次查询切换当前图或移动玩家。若B的地牢标记为真，建立通知可生成B、消费待播种子、重播全局随机，玩家摆放成功还写玩家传送暂存坐标（WP14 §3.1.1）；不据此置传送请求标记。不在集合的临时B不因查询成功而自动驻留；两次之间仍不驻留时，重复查询可再次实际建立及生成，不能假设纯读、一次性缓存或相同布局。合法连接跨缘预检查也可沿此链；一次预检查可能有多次按ID临时取图，不规定每次预检查恰好只生成一次。

已驻留B、没有另行重建时的查询/边缘切换复用实例，才适用“不重生成”。非地牢B仍经建立通知，但该地牢消费者不生成、不消费种子也不写摆放暂存；其他订阅者的作用须分别判断。失败前缀与原单次生成限制见WP14；通知按已接受WP05的顺序与首次异常停止合同传播，无原子回滚保证。随附默认地图元数据文本的 [051] 明确配置 `Dungeon=true`，该字段由元数据模式识别为地牢标记；[050] 未提供该属性。只有相应编译、登记和装载成功，建立通知的地牢消费者才按登记值判断生成资格。真实 Map051 资源、图块集/区域/事件绑定、实际编译装载、进入/连接查询链及 Demo 可达性仍为 `MISSING_MATERIAL`；案例 `NOT_EXECUTED`。

源追溯：固定R `8c5911e4a4b07b07e832e4bb0d5d8859e88b4a9b`，`Data/Scripts/004_Game classes/005_Game_MapFactory.rb` 54–92、157–169、203–206、307–309（blob `0657b0f2d3a35e68fe8d1add1b855a167c3f7575`）；`004_Game_Map.rb` 45–74（`3fda78303080bf7be450d110ecaf9df834bec691`）；地牢通知与随机/暂存证据见WP14 §3.1.1。案例 GR3-DQ01–GR3-DQ09。

### 3.2 连接配置与坐标/偏移规则

- 连接来自编译产物（作者文本经编译生命周期）；原始配置每条为 [A图ID, A端描述, A坐标, B图ID, B端描述, B坐标]；加载时两端各自换算为一个二维锚点：
  - 端描述为 N 或 S：锚点 x＝配置坐标值，锚点 y＝边值（N→0，S→图高）。
  - 端描述为 E 或 W：锚点 x＝边值（E→图宽，W→0），锚点 y＝配置坐标值。
  - 端描述为显式坐标（非方向字母）：两个数值直接作为锚点 (x, y)。
  - 边值规则：N/W→0，E→图宽，S→图高。两端图尺寸为 0 的连接被忽略。
- 连接按两端分别索引（双向可查）。
- **跨图坐标换算**：A→B 方向时，目标坐标＝(B锚点 − A锚点)＋当前坐标，即 xB＝B锚点x − A锚点x＋xA、yB＝B锚点y − A锚点y＋yA。逐条连接检查，**第一个使目标落在 B 图有效范围内的连接生效**；都不满足则不转移。B→A 方向使用同一锚点对反向相减。
- **相对位置换算**：同图直接差值；有连接则按锚点偏移差值；无连接为 [0, 0]。
- **邻图显示偏移**：邻图显示坐标＝(锚点差 × 128 子像素)＋当前图显示坐标；显示范围采用6格缓冲；修剪的分支与当前图适用域见 §5.2.1。

#### 3.2.1 连接文本的编译接受与运行消费

作者端点配对按第一端分支校验（WP04 §4.5）：方向N/S/E/W要求第二端对应S/N/W/E；整数第一端不执行该方向配对。因此1,0,0,2,W,0可编译保留，1,E,0,2,W,0正常通过，反向混合1,W,0,2,0,0拒绝。实际运行仍逐端按上节换算；编译接受不保证混合记录的跨图、资源读取或写出成功，缺地图警告不等于统一拒绝。

## 5. 地图生命周期

### 5.1 进入/离开与更新顺序

### 5.2 邻图加载与卸载

- 加载：进入当前图范围或邻图范围内时按连接与显示偏移加载。
- 卸载：玩家移动中不执行；无连接分支与有连接分支的适用对象不同，见 §5.2.1。
- **实例复用与重建**：加载复用已存在实例；重建清空集合并重新构造——卸载后再加载会**重新构造事件实例**。事件实例的临时状态（消去标记、启动标记、临时自开关表）在实例初始化时重置；页条件读取的（持久）自开关存于全局表（键为 [图ID, 事件ID, 字母]），**不随实例重建丢失**。即：临时自开关随实例重建丢失，持久自开关保留。
- 邻图的事件/更新按各自地图实例进行（事件规则归事件规格）。

<a id="r8-range-pruning"></a>
#### 5.2.1 范围修剪与当前图引用

玩家无普通移动/碰撞计时，才进入本次生命周期修剪。当前图没有连接时，驻留集合只有一项便直接返回；否则只删除身份不同于当前图的项并重设选图索引，不继续作显示范围过滤。当前图有连接时，先删除与它不相连的驻留图，再摆放邻图，最后对**全部驻留图（包括当前图）**作显示范围过滤；集合长度改变才重设索引。因此，“当前图”身份本身不使它豁免最后的范围门。

范围门按各图显示偏移判断：横向偏移 ≥（图宽＋6）×128、纵向偏移 ≥（图高＋6）×128，或横向偏移 ≤−（画面宽＋6×32）×4、纵向偏移 ≤−（画面高＋6×32）×4，任一成立便在范围外；等于边界也排除。当前图被删除时，全局当前图引用并不由这次删除同步清空或替换。容器选图与全局引用须分别观察：集合为空时选图索引为−1，紧接的容器取图先将负索引归0，再报无地图错误；集合非空时仍按 §3.1 的首图回退规则取图。

有限对照为两张合法人工图 A/B，均20×20，A东侧(20,0)连接B西侧(0,0)，画面512×384，两图均不贴边；A当前、两图驻留，玩家在A(5,5)且无普通移动计时，初始显示偏移 A=(0,0)、B=(−2560,0)。无通知/建立异常、插件、传送、额外显示改写或中间生命周期时，**显式速度0**向右即刻滚屏100格，偏移成为12800/10240；只执行一次生命周期，两者均达到右侧排除门3328，集合为空而全局仍指原A。滚屏及该次生命周期本身可以正常返回，错误发生在随后的容器取图。独立复位后仅右移26格，A=3328被删、B=768保留，容器可回退B，而全局仍为原A；小偏移仍保留A。

玩家普通移动中会跳过修剪；开启贴边时同夹具A横向偏移被钳到512，不能套100格空集合结果。无连接分支也不能套此结果。第二次生命周期可能补建地图，产生全局旧A与新驻留A实例不同的情况；默认/非零滚屏速度含微更新循环，不能沿上述单次链推定其终态、普通保存UI的抢先时机或永久空集合。相机输入与贴边规则见 [WP16](wp16-world-rendering-and-visual-transitions.md)，向量 R8-RP01–R8-RP08 均为未运行静态推导。

<a id="r8-neighbor-placement"></a>
#### 5.2.2 邻图摆放失败后的后继能力

邻图摆放正常完成后，后续显示变化仍可再次请求摆放。若**已经进入摆放阶段**，在邻图获取、建立通知或偏移写入处发生首次异常，异常传播而正常收尾未到，则同一地图容器的后续摆放可保持受抑制：即使移除单次失败原因，下一请求也直接返回，不再枚举连接、加载或调整邻图。观察这个后继状态，必须明确由外层捕获该异常并继续；默认调用链并未承诺吞异常或安全恢复。

同一容器重新建立合法地图、或仅清除地图帮助缓存，均不独立恢复这项摆放能力。新建容器的初始状态不受该旧实例的抑制，但新建、建立通知及后续操作仍须各自正常完成；这不是无条件恢复保证。已成功加入的地图与已完成偏移写入不因后继异常回滚；某次地图建立尚未成功返回时，该失败地图不因这次获取而加入集合。进入摆放前的失败、以及正常收尾之后的失败须按各自前缀判断，不套用本例；本单元没有取消接口。通知的首次异常传播沿用 [WP05](../generic-kernel/wp05-events-extensions-plugins.md)，同实例读档重建仍受 §6 的入口条件约束。此处固定可观察后继能力，不规定未来实现的私有标记或容器布局，也不推定永久软锁、可见画面或真实保存恢复结果。

### 5.3 地点提示的进入门与生命周期

地图/显示集合变化通知须有场景与显示集合、地图确已改变且目标元数据 `announce_location` 为真才创建地点提示。已有前一地图历史时，`NO_SIGNPOSTS` 按相邻两个元素组成地图对、双向抑制；尾部孤立元素不组成地图对。前图解析名称与当前名称相同也抑制。没有前图历史时跳过这两项历史抑制。只刷新同一地图的显示集合不创建。

提示按单调时间依次进入 0.4 秒、停留 1.6 秒、退出 0.4 秒。创建时存在 `fly_destination` 则延迟；只要飞行目的地仍存在，更新直接返回，连消息显示/地图改变导致的销毁检查也尚未执行。目的地清空后的首次更新重置计时，再检查消息显示或当前地图身份不同并销毁；没有这些门才开始完整时线。常规消息/换图直接销毁，不在原提示上换文字。实际字体、像素与素材属于世界显示规格，未运行确认。

### 5.3.1 地图名称的材料、展开与生命周期

有效地图名先用元数据原名作为本地化哈希键，按当前语言game→core查找；缺命中返回原名。空译是命中，不再转core；地图消费者看到空值/空串才回退基本地图名，无元数据也走基本名。空原名、缺元数据、空译文是不同进入条件。大写`\PN`在所选可变文本中以全局玩家名直接展开；没有玩家时该查询不展开。普通名字Alice/Bob且无替换元字符/再次引入占位、查找替换正常是以下成功合同前提。

| 实际选中材料 | 展开后的保留与重复读取 | 恢复含占位材料的必要操作 |
| --- | --- | --- |
| 非空当前game译文，或game未中后的非空core译文 | 所选译文值保留已展开名字；独立原名不改 | 成功重载含模板的相应语言材料；语言重载不恢复独立原名/基本名 |
| 两语言层缺命中的非空元数据原名 | 登记原名保留已展开值，后续查找键也随原名变化 | 重新载入/登记含模板的元数据；仅语言重载不足 |
| 名称结果空/空串或缺元数据后的有效基本名缓存 | 基本名称缓存保留已展开值 | 清该缓存并成功读回未改材料；仅语言或元数据重载不保证恢复 |

重复读取同一材料且无重载、编辑、新键命中或其它写入时，已消耗占位不会随玩家改名自动重建。两层MAP_NAMES域均为空可确定原名主例两次缺命中；若只排除原模板键，原名展开后形成的新键可能命中新译文，结果须按新命中重新判定。上述各独立材料例排除已有别名；已有共享文本引用会使一次变化被多个持有者看到，编译缺名回填可能与基本名共享，不能保证原名变化绝不影响另一入口。

无大写占位内容不变；无玩家且不走继续预览时保留占位。通用消息显示先复制输入再处理控制字符，不因此改共享原文，不能把所有PN显示/本地化查询都归此写入。继续面板先查名，再以存档训练家名展开剩余占位且早于选择（WP65§3.2）；全局Alice、存档Bob时先行Alice占优。

查询和预览只改变内存，普通玩家存档不自动保存内容登记。后续显式确认该地图元数据保存，原名已变、没有另改、文件步骤正常时，内容档案和PBS可携带已展开原名（[世界编辑器§4](../demo-dx/wp73-b-world-editors.md)的保存次序与共享嵌套取消规则保持）。已展开后的UI失败不自动撤回；前置查找类型/结构失败、不可变文本或任意替换元字符名字不套成功主例。地点提示同名抑制、电话/漫游/地点展示消费当前命名服务值，并不重新构造模板；不据静态合同保证Demo事故或未来必须复用共享文本结构。

## 6. 地图恢复与存档交界

- 地图容器是持久值（存档目录），随存档保存/恢复；新游戏按起始图 ID 与坐标建立。
- 存档中地图的持久状态（已加载地图与玩家位置）按存档目录登记；跨图后地图状态保留/重建按 §4 规则。

§5.2.1 空集合形成后，若在任何失败取图或额外生命周期之前**另行分叉直接保存**，地图容器的存档值只经过类型门，不因集合为空自动拒绝。其余存档值、文件写入、序列化及帧重置均正常时，直接保存可以成功；这不证明实际文件已写成。若该空集合随后原样读回、没有转换或外部改写，正常读档在重建判断前先从容器取图，因而可在此失败，尚未进入缺图恢复。未跳过继续菜单时，继续面板也在选择命令之前先从保存容器取图，可更早失败，不能保证到达备份/缺图UI。若先取图已抛错，保存并未到达，除非另有明确捕获继续。保存机制与导航分别归 [WP09](../generic-kernel/wp09-save-startup-continue.md) 和 [WP65](../user-interface/wp65-title-load-options-pause-and-pc.md)；本条只接合有限消费者顺序，不保证普通UI必在补图前保存，也不构成真实存档往返验证。

### 6.1 正常读档的实例与记录（GR3-M03-004）

读档门沿已批准WP09（blob `d9a256cbc1054cc3ad190f83231bfdfa564ac4a2`）：系统标记不一致或安全保存为真才重建，两者都不成立才复用已加载实例并发送地图变更/进入通知。两正常分支的必要前提为有效存档/地图、各通知及更新返回、无插件或额外写入。

| 分支 | 离开 / 进入 | 局部记录与事件实例 |
| --- | --- | --- |
| 一致且非安全保存，未重建 | 只发送进入；无本次离开 | 进入首个消费者在可选记录新治疗点之后清局部消去/移动记录及地图局部效果；已加载地图事件实例可仍保留消去、位置、朝向或through状态，不能据清记录宣称实例也重置 |
| 实际重建（包含目标ID等于旧ID） | 旧ID非零时先离开，再建立/摆放邻图、进入；旧ID0不发离开 | 新建地图初始身份为0，离开门比较旧图与这个初始身份，故同ID实际重建也会离开；事件实例按新页数据初始化，进入仍清局部记录，不保证旧移动记录再次恢复 |

通过进入通知及地图事件集合的空值损坏守卫后，恢复遭遇/载具，随后自动音乐 → 地图更新 → **局部记录恢复辅助** → 新地图场景。集合存在但空数组/空集合不等于空值损坏（WP09）。无进入后追加记录时，两分支到辅助处的消去与移动记录均为空，辅助不会凭已清旧条目再次消去/移动。记录曾作为持久单元保存，不等于读档消费它时仍存在。

同图显式传送的不重建/不发进入条款只属§4那个入口；不得套到读档同ID实际重建或“只标记地图变更”恢复。同ID进入仍执行清记录消费者，天气消费者的“同图不处理”也不能抑制该清记录行为。

### 6.2 记录内容、条件恢复及失败前缀

局部消去记录以(记录图ID,事件ID)为键、值为真；移动记录以同样身份记录位置(x,y)、方向及through快照。有效整数ID且当前事件存在才追加移动记录；同键后写覆盖此前快照，记录与实例状态分别观察。清空还将力量已使用、黑/白笛遭遇率与等级效果四个局部标志归假。普通实例消去不登记；记录式脚本辅助有当前事件存在门；主事件命令116则以正事件ID为门，缺实例仍可登记(当前图ID,事件ID)→真，局部记录对象缺失时跳过登记。116推进一项并停止本次解释器更新，见 [WP13 §3.3 三入口表](wp13-map-events-npc-followers.md)及命令矩阵116行（GR4-M03-003）；本节的进入清表与条件恢复合同保持。

以下是“记录仍存在”的直接辅助输入，或进入清空之后有明确新写入的条件合同，**不是默认读档保留旧记录的承诺**：

| 字段 / 条件 | 辅助规则 |
| --- | --- |
| 消去 | 仅记录图等于当前图且标记真时消去同ID事件；缺事件安全跳过，异图不消去 |
| 位置与方向 | 仅同图且移动记录存在时处理；同图缺事件跳过整条。先落位，再按2/4/6/8转向下/左/右/上；其他方向不请求转向，落位仍发生 |
| through | 真值写入在上述地图匹配门之外；异图记录也会尝试给当前图同事件ID写through真。假值不写，**不会清当前已有真值** |
| 异图＋through真＋当前缺事件 | 未经过同图缺事件跳过门，through写入尝试失败；后续记录不再到达。已处理条目的消去/位置/转向/through前缀不自动回滚 |

具体反例：A≠B，A记录事件7为(8,8,下,true)，B事件7初始(2,2,右,false)：恢复后B仍(2,2,右)，through为真；把记录through改假，B原假保持假、原真也保持真。B缺事件7且记录真时失败；改为同图记录且缺事件则整条跳过。正常同图有效事件可落位并转向，through假仍不清旧真。记录坐标经过角色落位的取模/通知门，不保证任意越界输入原样落地。

进入通知失败时沿批准WP05“已执行前缀保留、后续未到”的合同：例如清空完成后后继消费者抛错，记录仍已清，地图更新/恢复辅助未到；若在清空前失败，则不能断言记录已清。地图更新失败则恢复辅助未到。辅助中后项缺事件失败不回滚已处理前项；没有统一异常恢复或重新尝试保证。具体宿主报错呈现未证。

异图through门差异是固定参考异常事实；未来是否保留是 `USER_DECISION`，不要求修改参考或预定新架构。实际存档样本、地图、页切换与额外动态消费者 `MISSING_MATERIAL`；正常/异常案例均 `NOT_EXECUTED`。

## 4. 移动与运动状态

### 4.1 移动入口与结果

| 入口 | 行为 |
| --- | --- |
| 普通移动 | 转身（**保留本次遭遇标记**）；**遭遇标记门（先于一切通行判断）**：本次所作转向若触发遭遇且开战调用正常返回（遭遇系统置标记），标记为真时**跳过本步全部移动分支**——不走通行判定、不前移、不触碰、不碰撞；方法末尾清标记。标记未置时才先判定能否移动：可移动时——面朝岩架则尝试跳下（成功则跳音＋计步；**无论成败都结束本步，落点不许可也不转入碰撞分支**）；瀑布顶且向下则进入下瀑状态（through＝真、下瀑计数＋1）并继续；随后尝试上岸（成功则结束本步）；否则再次同向转身后**经同一标记的第二次检查**才记录初位、前移、按距离累计距离统计、计步。不可移动时——先尝试事件触碰，否则创建零位移碰撞计时（非强制路线才请求碰撞音、碰撞计数＋1、记录初位、碰撞标记）。**仅通行许可不是同次必然位移的充分条件** |
| 跳跃 | 非零直接偏移先转主方向、占格全部许可后记录跳点/计时/峰距并一般计步；玩家坐标确变才按两轴绝对位移和累计距离。直接(0,0)不转向、不查占格，仍启动原地跳跃和一般计步，名义距离1、跳峰为每格高度×3/8，坐标不变不增距离。前/后跳包装距离0直接false、不创建跳跃 |
| 输入处理 | 自动强制移动优先按当前方向前移；正常输入须解释器/消息/迷你更新/菜单门均未阻塞。**上一帧已移动**，或「正方向输入与上次相同且距上次输入改变 ≥0.075 秒」，任一满足即按当前方向尝试移动；否则改变方向时只转身。故上一帧移动后的换向可立即移动，不受 0.075 秒首转等待。输入改变后记录新方向和单调时刻；方向 0 不调用移动 |
| 步后触发 | 步完成后：跟随者转身 → 远距事件检查 → 同位事件检查 → 步进入口（全局计步主规格，引用） |
| 碰撞创建 | 普通四向受阻且事件触碰未成功时：非强制路线才请求碰撞音；碰撞计数＋1、记录初位并启动零位移碰撞计时。位置/距离不变，不由本次创建发离格通知；此时不增加全局步数 |
| 碰撞正常完成 | 计时获得合格更新并到达终点时清运动/碰撞状态，仍发一般迈步通知；若消费者正常返回、玩家已无运动/跳跃且自动移动门放行，再进入步后触发。该后继不以坐标变化为门；强制路线/解释器分流及玩家消费者仍按计步规格各自守卫 |

**计步层次**：角色的计步函数只做两件事——**重设停止计时并通知离开旧格（该通知要求旧位置已记录且位置/地图确有改变）**；它不直接累加全局步数。全局计步在步完成后的步进入口（计步主规格）。**运动开始与完成是两个不同观察点；位移距离与条件性离格通知在开始一侧提交，全局计步另在完成后的合格玩家入口处理**：

- **普通步（移动开始）**：遭遇标记未置且通行通过后立即提交——逻辑坐标更新、移动计时开始、距离统计累计、计步（含条件满足的离格通知）。**遭遇标记为真的本步没有「开始」**：坐标/距离不变、无离格通知、无运动开始。此后画面位移（插值）尚未完成；动画完成与步后触发（事件检查与全局计步）在后。即「移动方法已返回但画面位移未完成」时，逻辑坐标与距离统计已变、符合条件的离格通知已发生，但本步全局步数尚未因步完成而累加。
- **跳跃（跳跃开始）**：非零偏移通过占格许可（直接零偏移不检查）后提交——逻辑坐标/跳跃计时/跳峰跳距设置、计步；玩家覆写随后在坐标确有变化时累计实际位移距离。实际检查了落点许可且失败的非零跳跃直接返回，**不产生成功位移距离，也不触发计步**。

**零位移碰撞的完成来源**：普通四向受阻且触碰未成功才创建上述计时；创建不调用一般计步/离格处理，不把碰撞计数等同于全局步数。正常完成先发一般迈步通知，再按玩家步后门进入[WP61 §3.1](../pokemon-rules/wp61-field-passive-effects-and-blackout.md)。一般消费者可启动冰滑/瀑布等新运动、转移或失败，玩家链也可被强制路线/解释器门分流；不能仅凭碰撞已创建承诺玩家周期最终推进。无这些干扰且正常返回时，碰撞完成虽始终零位移/零新增距离，仍可增加全局步数、友好周期并递减非冰面 Repel。默认野外毒伤关闭，空寄养仍可推进自身周期；这些例示不是全部状态变化清单。

阶段顺序（按入口分列）：**普通移动**请求 → 转向（所作转向保留本次遭遇标记）→ **遭遇标记门（为真则跳过本次全部移动分支，方法末尾清标记）** → 通行判定 → **开始（逻辑坐标＋距离统计＋条件性离格通知）** → 动画/位移完成 → 步后触发（事件检查与全局计步）。**直接跳跃**请求**不经过普通移动入口、没有该标记门**：非零偏移按主方向转向（转向自身规则与副作用照旧）→ 落点占格许可检查；直接零偏移跳过这两步 → **开始（逻辑坐标＋跳跃计时/跳峰跳距＋计步；玩家覆写按实际位移累计距离）** → 动画/位移完成 → 步后触发。经普通移动分支进入的岩架跳跃仍处外层普通移动门之内，与直接跳跃入口不是同一回事。

岩架成功分支请求**沿当前朝向跳两格**；首格可通行还须满足跳跃落点占格许可。它不是一格跳跃。移动速度等级 1/2/3/4/5/6 的一格名义插值时长分别为 1/0.5/0.25/0.125/0.1/0.05 秒；这些时长不把实际更新机会固定为帧数。

### 4.2 运动状态机

**跑步条件**：

- 强制路线中：按当前速度等级 > 3 判定（不看跑鞋/地形）。
- 正常分支前提：非碰撞中、非菜单/战斗/消息/解释器运行、非跳跃。
- 跑鞋例外：无跑鞋时，**冲浪、潜水或骑行中任一**也可跑（潜水是跑鞋例外之一）。
- 地形限制：仅**必须步行**地形禁跑；**必须步行或跑步**（如冰面）**不禁跑**。
- 两者（必须步行与必须步行或跑步）**都禁骑行**（层 2）。
- 最终按跑法设置与 BACK 键异或切换。

**状态表**（速度数值为速度等级；状态切换的速度赋值**多数受「非强制路线」前提限制**，且碰撞中最后统一覆盖为 3——下表不是无条件强制值）：

| 状态 | 进入前提 | 速度等级/外观 | 退出/切换 |
| --- | --- | --- | --- |
| 步行 | 默认 | 3 | 默认状态 |
| 跑步 | 跑步条件（见上） | 4；BACK 键按跑法切换 | 条件不满足时回步行 |
| 骑行 | 骑行标记置位（上车） | 5（跳 3）、骑行外观与 BGM | 下车或载具取消（目的地不可骑行时） |
| 冲浪 | 冲浪标记置位 | 4（跳 3）、冲浪外观、上下浮动动画 | 载具取消或上岸流程 |
| 潜水 | 潜水标记置位 | 3、潜水外观 | 同上 |
| 冰滑 | 冰滑标记或当前地形为冰 | 4、步行外观 | 调试 Ctrl、离冰或面向不可移动时结束（见下文） |
| 瀑布下 | 瀑布顶向下移动触发 | 2、through＝真、冲浪外观 | 离开瀑布地形或调试中断 |
| 瀑布上 | 攀瀑流程（场地招式交界） | 2、through＝真、冲浪外观 | 同上 |
| 停止态 | 菜单中停止或载具更新时 | 保持对应外观、恢复基础速度 | 重新移动时 |

**接管机制区分**：强制路线使普通输入不生效、且上述速度赋值被跳过；冰滑/瀑布的自动移动由步后订阅驱动，是另一种接管路径，二者不能混为一种。

冰滑步后保持条件为：非「调试且 Ctrl」、当前仍为冰且面向可移动；全满足才保持冰滑并停止步行动画。任一失败即清冰滑、恢复步行动画，**没有清 through 的写入**；仍在冰上但前方阻挡也归还普通控制。瀑布清理另见 §5.3。

状态保持/清理：显式载具取消入口默认取消游泳，但正常事件 201 的两个场景消费者显式传假而保留（WP11 §4）；边缘切图没有此取消调用。载具更新按当前标记恢复外观；骑行取消按目的地决定（§5.1）。

### 4.3 对角与多格角色、NPC 移动选择

角色锚点是占格的**底行左格** (x,y)，宽 w、高 h 占据列 x…x+w−1、行 y−h+1…y。直线移动检查相应前缘的每格。向下对角须先向下，再在下降一格后的整侧缘横移；向上对角须先横移，再从已横移一格后的顶缘向上。两阶段每格均须许可，不能用「任一 L 形路径可走」代替此固定顺序。

四对角入口在通行检查前直接调整方向，方向固定则保持：左下使原右→左、原上→下；右下使原左→右、原上→下；左上使原右→左、原下→上；右上使原左→右、原下→上；其它原方向不变。调整不发普通转向通知。任一固定分段失败则无位移、无距离累计、无四向碰撞计数/触碰尝试，但已调整方向可保留。许可全部通过才一次提交两轴各一格、运动初位/计时及一般计步（停止计时归零、条件性离格）。

玩家四对角入口不调用普通四向移动的距离累计、岩架/上岸或碰撞处理；步行/骑行/冲浪/潜水/冰滑距离都不会由这次对角提交增加。运动完成仍经一般步完成和玩家步后链，按其各自守卫处理，不能从“不增距离”推出全局步数必不变。普通四向成功距离＋1、非零直接跳跃按两轴绝对位移和增加；直接零偏移跳跃坐标不变距离不增。三种入口不可互相替代。

随机移动在四个正方向等概率选择，移动前不转向，通行成功后仍转向（方向固定时按既有守卫）。接近/远离玩家以双方**占格中心**差计算轴距离：绝对差较大轴优先，相等时各半选轴；优先移动未进入运动状态才尝试另一个非零轴，重合时不移动。不是路径求解或绕障保证。普通自主随机策略六等分中四份随机方向、一份前进、一份不动并重置停止计时。自主接近策略在中心曼哈顿距离 ≥20 时随机方向；距离 <20 时六份中四份接近、一份随机、一份前进。事件是否获得这次自主更新仍受 WP13 更新资格/锁定/启动/运动与频率门控制。

**范围随机移动（GR4-M03-001）**：这是普通四向随机之外的方向筛选能力。对普通地图事件，原始锚点 (x₀,y₀) 取自该事件实例建立时的地图事件位置；当前逻辑位置 (x,y) 可因移动、跳跃或落位改变，落位不重定原始锚点。事件重建的新实例重新取地图事件位置；不将当前位置作为每次调用的新中心。横、纵范围分别输入 r、s，省略时各为 −1；以下针对有效数值范围，非整数及非法输入未穷尽。

| 轴 / 输入 | 允许成为候选的方向 |
| --- | --- |
| 横 r < 0 | 左、右均允许，不设原始位置边界 |
| 横 r = 0 | 左、右均禁用 |
| 横 r > 0 | 左仅当 x > x₀−r；右仅当 x < x₀+r |
| 纵 s < 0 | 下、上均允许，不设原始位置边界 |
| 纵 s = 0 | 下、上均禁用 |
| 纵 s > 0 | 下仅当 y < y₀+s；上仅当 y > y₀−s |

固定参考按**左、右、下、上**顺序保留满足条件的候选，然后在非空候选中只作一次均匀索引抽取，每个候选概率为 1/候选数。无候选时直接返回，不抽随机数也不尝试移动。候选筛选不预查碰撞；抽中后只尝试该方向的普通单格移动，受阻不重抽、不改试其它方向。不预转向、通行成功后转向及方向固定守卫沿本节既有随机移动合同；运动/触碰沿相应角色入口。该候选序用于解释固定参考抽样索引，不规定未来容器结构或跨语言随机序列。

纵向单轴能力（兼容字面 `move_random_UD`）把横范围禁用为 0，仅应用给定纵范围；横向单轴能力（`move_random_LR`）反之；单轴范围省略时为 −1。正范围规则是**方向过滤，不是越界钳回**：原始 (5,5)、落位后当前 (10,5)、横 2 纵 0 时仅尝试左至 (9,5)，不会瞬移回边界 (7,5)。普通四向随机仍用四方向，不套此范围表。路线 45 的字面前缀调度另沿 [WP13 路线 §1](wp13-move-route-matrix.md)，正常求值后推进/让出不以本次位移成功为门。

地图场景末端分为**新按键登记**与**已有调用消费**。本段的“静止”只表示**没有普通移动/碰撞计时**；跳跃计时独立，仍在跳跃不额外阻止这些末端门。角色新方向/路线命令的移动与跳跃门仍按各自规则判断，不能合并到这里。消息窗口仍显示时，在两阶段之前返回，不登记也不消费。新登记另须主地图解释器未运行，且冰滑、下瀑、上瀑三个自动移动标记均为假；这里不读角色的强制路线标记。强制路线阻止角色普通方向更新（§4.1），不能据此推定末端按键也被阻止：静止角色的路线 15 WAIT 尚未到期、上述末端门均放行且菜单启用时，ACTION 仍可登记菜单并在本次末端消费（路线矩阵 §1；MV72–74）。

新登记按 **USE → ACTION → SPECIAL → F9** 检测链选择第一个检测成立的分支：前三键用本次触发，F9 用按住检测。USE 登记互动，不另要求静止；ACTION 须菜单启用且静止才登记菜单与提示音标记；SPECIAL 须静止才登记快捷；F9 须调试开启，但**不要求静止或新的按下沿**，移动中也能登记调试调用。较早分支虽检测成立、却因其内部资格不符而未登记时，不继续检测后面的键，例如移动中的 ACTION 触发会挡住本次按住 F9 的登记（MV68–71、MV77）。

通过消息公共门后，已有调用仅在静止时按 **菜单 → 调试 → 快捷 → 互动** 消费第一项，不重新检查新登记的解释器/冰滑/上下瀑布门；未消费标记继续保留。移动中排队的调试调用可在后来静止、F9 已松开且没有其他调用时消费，调试标记在请求调试菜单之前清除。消息仍显示则连已有调用也保留（MV75–76）。迷你更新不进入这段末端分发。方向更新、新登记与消费的门分别判断；本段只规定调用请求，不证明宿主菜单或插件呈现结果。

本节末端门只约束该末端的新登记/已有调用消费。系统更新更早独立检查SPECIAL过场跳过，主解释器运行且当前事件注释严格为 `Cut Scene` 时按“写持久A→结束→请求重启”处理（WP13 §4.3；GR3-M03-003）；正常/迷你更新都可到达，迷你仍不进入末端。不能给过场跳过附加末端的“解释器未运行”门，或把同一轮SPECIAL宣称为独占消费。正常轮跳过后是否又登记/消费快捷须按本节实际消息/运动/先检测分支/优先级门判断，案例 GR3-CS11–GR3-CS13（`NOT_EXECUTED`）。

合法玩家直接作(0,0)跳跃，可建立活动跳跃而不建立普通移动计时。旧格记录一致、默认跳速3、没有方向输入/传送/额外写入，下一合格普通更新的时间差0.01秒（且≤0.25秒）、跳跃分数仍小于1时，在上述新登记门放行条件下，ACTION可登记菜单及提示音并消费菜单请求；独立复位的SPECIAL可登记并消费快捷。仅改普通移动计时存在，则ACTION/SPECIAL不登记、已有调用不消费，F9仍可登记。已有调试请求在无普通移动计时且消息不显示时，即使主解释器或冰滑/上下瀑门阻止新登记，也可按原优先级消费；消息显示则保留请求。

菜单调用先清菜单请求并置“菜单中”，然后整姿、更新地图、请求暂停菜单。只断言实际到达的请求与写入前缀；后继失败不保证清“菜单中”、恢复游戏或完整UI。菜单/快捷的后续正常取消沿各自合同，不新增取消跳跃动作，也不由该入口推定跳跃会清除、暂停或恢复。零跳与普通移动、已有请求/消息早退的对照见 R8-JT01–R8-JT06，均 `NOT_EXECUTED`。

## 2. 分派与回退规则

- 到达命令列表末尾 → 结束处理（清除列表与跟随者覆盖；主解释器且事件 ID 有效时解锁事件）。
- 命令代码在分派表中 → 调用对应命令实现。
- 命令代码不在分派表中 → 返回 true，跳过并继续下一条（索引＋1）。
- **续行消费**：401（文本续行）由 101 在命令体内消费；655（脚本续行）及相邻 355 由 355 合并执行。「未单独分派」不等于无作用——这两类代码是上游命令的数据延续，正常流程中不会直接到达默认分派分支。
- 脚本命令（355）的异常：SystemExit/Reset 原样抛出，其他异常按事件错误处理。
- 命令返回 false 时解释器本轮停止；返回 true 时外层索引＋1。

通常角色0/指定编号查当前图，私有变量与缺省脚本自开关查绑定图；111自开关、123、主解释器结束解锁查当前图。207/209的显式跟随覆盖例外见[WP13§4.1](wp13-map-events-npc-followers.md)。

### 3.2 连续选项、取消与一次性改写

扫描同缩进组的 402/403/404 边界后，若紧接另一 102，则把其选项追加到当前逻辑组，合并后组的开始项、调整后组分支编号。后组分支号增加此前选项数，身份仍对应合并前原选项。合并可继续到下一同缩进组，不能跨其他命令或缩进随意合并。

取消类型 0 不覆盖已有设置；后组取消类型 1–4 加此前选项数，类型 5 转换为合并后总选项数＋1。这一步只形成显示调用的取消参数，**尚未确定最终原分支**。显示侧接受取消时将正的一基取消参数减 1，得到零基原始返回值；普通确认则返回所选可见位置。两种返回都随后查本次「可见位置 → 原分支」映射：有条目就用其原分支号，没有条目才保留原始返回值。因此隐藏选项后，取消也可能转入另一原选项，不能按合并的取消参数直接宣布进入指定后组选项。后组类型 5 合并所得的 403 对应「总选项数」结果，该值超出可见映射时保留；独立组的默认取消分支索引仍为 4，不能按其实际选项数推定。禁止取消、指定参数取消与独立取消分支应分列，不保证每次取消都到 403。

改名/隐藏输入按**合并后的原选项序号、一基**指定，应用于本次选项后清空。被隐藏项不改变 402 原分支身份：例如 A/B/C 合并后隐藏 A，首个可见 B 的显示索引 0 映射到原分支 1。改名后按显示文本作翻译；下一独立组选项不继承本次改名/隐藏。消息合入选项同样使用这条管线。选项窗口的键输入与绘制归 [WP17 消息、窗口与输入](../user-interface/wp17-messages-windows-input.md)，不以本节宣称该领域已完成整改。

组合反例：首组 A、取消 0，紧接同缩进后组 B/C/D、取消 1，各 402/404 及分支体合法；合并原分支为 A=0、B=1、C=2、D=3，取消参数为 2。按原一基 1 隐藏 A 后，可见映射为 [1,2,3]；BACK 返回原始值 1，再经映射得到原分支 2，**进入 C 而非 B**。无隐藏的同输入以身份映射进入 B；有隐藏但正常确认首个可见 B，原始值 0 映射 1，也进入 B。101 合入同组选项后，取消返回同样先作映射；下一独立组不继承本次隐藏。组合、无隐藏、正常确认、101 合入及取消分支回退见 IM36–IM41，均为未运行静态向量。

**解释器绑定身份与当前图目标**：命令列表启动时保留绑定图和事件编号。当前图不同但仍相连时保留编号；失联时只清编号0，列表继续。通常角色选择−1指玩家，0指当前图同该编号事件，指定编号也查当前图；并不查询绑定图的角色实例。私有变量与缺省脚本自开关使用绑定图键；111自开关子型、123及有效主解释器结束解锁使用当前图键。具体命令的编号有效门与缺对象门仍各自生效。

<a id="r8-common-event-identity"></a>
**117 子公共事件的身份生产**：有效公共事件调用建立深度加1的子解释器，携带父解释器**当时的事件编号**，但子解释器绑定的是**建立时的当前地图**；调用不改变父解释器的原绑定图。子事件先运行至正常结束，父事件再继续；私有变量与缺省脚本自开关等消费者分别使用父/子自己的绑定图键。父绑定A/7、当前图B，A/B仍相连且驻留、A并行事件获得更新、无等待/传送/额外写入时，子先写私有值“child”、父随后写“parent”，结果为[B,7]=child、[A,7]=parent。同图时两次都写[A,7]，后写父值覆盖子值；失联更新先把父编号清0而保留绑定A，随后子[B,0]、父[A,0]。这些是有限键选择推导，不证明默认Demo或实体存档往返。

缺公共事件记录则不建立子解释器，父按正常控制推进；深度101触发既有提示退出门。建立或脚本后继首次异常只保留已完成写入，不承诺外层恢复；117无取消接口。其它直接公共事件助手的event0与返回差异仍按本节独立入口判断，不能套117的编号携带。成对向量见 R8-CE01–R8-CE05，矩阵117行同步同一合同。

跟随互动锁定跟随实例，以其列表、编号与图身份启动主解释器，但普通“本事件”角色查询不自动改指跟随实例。207/209在有显式跟随覆盖时可选择具名跟随实例，属于特定命令例外。正常结束解锁只向当前图同编号的有效事件请求，不自动解锁原跟随实例；不能由此推永久软锁或所有跟随移动失效。

**脚本开关的消费判据**：地图页条件与公共并行启停在refresh时把`s:`表达式按真值使用（仅false/nil为非真）；111开关子型将表达式结果与目标布尔值作严格相等比较，保存的是比较后的true/false。故`s:1`对ON/OFF都不满足，`s:nil`对ON/OFF也都不满足且走Else。111脚本子型保存表达式原值：1进Then、false进Else、nil两支都跳。公共自动运行启动直接读普通开关槽，不对名称脚本求值；普通槽OFF时`s:1`也不会启动它。true/false的正常二值比较保持。公共并行没有“每次update无条件重求表达式”的承诺。

**脚本直接公共事件与钓鱼**：非战斗解释器内直接调用的公共事件助手在事件存在并正常执行完后为空返回；缺记录也为空返回，没有全局助手的负ID拒绝门，负数依实际数组索引取记录。正常鱼竿物品回调使用全局助手，非负存在事件完成返回true。这个返回差异使解释器脚本直接钓鱼可先完成开始/结束公共事件，再执行对应内置段；开始先置fishing，结束正常表现及随附消息后仍共同清理。入口表见[钓鱼§6](wp60-fishing.md)，不把所有“由事件触发物品”都归为脚本直接调用。

### 4.2 结束与恢复（三种终止状态分列）

- **命令结束**：命令列表执行完（索引到末尾）→ 清除列表、结束跟随覆盖；主解释器且编号>0、当前图同编号事件存在时，解锁该当前图事件（绑定身份与跟随例外见§4.1）。
- **显式退出**：退出事件处理命令 → 同样进入结束处理。
- **地图失联**：仅事件 ID 归 0（§4.1），**已有命令列表继续有效**——失联后合法的全局命令（如开关赋值）仍可执行；事件的解锁/锁定上下文已失去。
- 脚本命令异常：按类别处理（SystemExit/Reset 原样抛出，其他进入事件错误处理路径）。
- 公共事件并行处理按开关状态刷新。

### 4.3 具名过场跳过、结束与重新启动（GR3-M03-003）

`SPECIAL` 本次触发在**系统更新**中独立检查，正常地图更新与迷你更新都会到达；正常系统更新早于地图末端快捷登记，迷你更新没有该末端分发。跳过门要求主地图解释器正在运行、可按解释器事件ID从当前地图取得事件，以及该事件当前命令列表含代码108或408的注释项，其完整文本**严格等于 `Cut Scene`**。大小写不同、尾空格、前后附文、拼接多个注释才得到该词或把同文本放入非注释命令均不匹配。

注释入口返回“匹配后的最多一项参数”的数组；跳过消费者只检测结果存在，**空数组也通过**，与未匹配/无列表/列表不是数组/解释器未运行/事件不存在返回的空值分开。不要求下一项是特定代码或含非空参数；合法注释在列表末端时仍可能匹配。主解释器运行判定是命令列表非空值，不以数组内容多寡替代；启动动作另有列表长度门。

### 3.5 种子来源与消费点

- **三级来源**：参数集固定种子 → 全局待播种子字段 → 系统新种子，取第一个非空。
- **消费规则**：确定种子后先**无条件清空待播种子字段**，再重播全局随机序列（无论种子来自哪级，对后续所有随机消费者有副作用）。下述空节点/密度失败到达时，该字段已消费；大网格奇数参数的构造失败发生在此之前。
- **消费点**（按生成顺序）：迷宫起点抽取、方向重洗、额外连接抽取、房间抽取、房间尺寸/中心、通道偏移、装饰密度判定与坐标、图块随机选取（含变体）、事件/玩家摆放的房间与坐标抽取、失败重试时的再次抽取。
- **重绘不重新播种**：同一轮生成内，布局/墙体失败后的重绘继续消费当前随机序列（§4.4）。
- **不保证**：相同 seed 在不同实现/版本/参数组合下产生相同地图（U05）；本文件只记录输入来源与消费顺序，不写跨实现一致不变量。

## 3. 资源身份与路径解析

### 3.1 解析层规则

- **图像解析**：输入路径去图像扩展名后，在各搜索路径下依次尝试 .png、.gif（.jpg/.jpeg/.bmp 停用）；全部未命中返回 **nil**（另一入口则回退返回原输入）。
- **音频存在性**：广义存在性检查六后缀.wav/.ogg/.mp3/.midi/.mid/.wma及字面路径；专门SE解析固定Audio/SE前缀，只追加.wav/.ogg/.mp3/.wma四后缀及检查字面路径。
- **搜索路径**：绝对路径直接使用；相对路径沿宿主搜索路径（当前实现仅当前目录）；加密包经数据层加载检查（文件层规格引用）。存档目录按宿主系统数据目录（存档规格引用）。
- **数据文件存在性**：有加密包时以首字节读取为准，否则规范化路径后查文件系统。
- **失败归一**：资源解析层失败返回 nil（不抛异常）；文件字节读取层的失败归一（nil/空结果）按文件层规格（引用，不重复）。

### 3.2 与内容身份的衔接

- 资源文件名以内容的**符号 ID 字符串**为基名（如物种 ID、训练家类型 ID、道具 ID）；内容身份的查找/回退规则归内容身份规格，本文件只登记「身份 → 文件名」的映射与降格。

指定 UI 图像在进入资源访问前，可先按 [WP08 §5.1.1](../generic-kernel/wp08-localization.md#511-指定-ui-图像身份的语言选择) 由当前语言选择资源身份：缺译交原身份 A，非空命中 A→B 则交 B。控制帮助键图、图形战斗菜单按钮、训练家卡、翻牌小游戏及 [Slot Machine 七个图像角色](../user-interface/wp69-slot-machine.md#22-图像身份与当前语言)的指定资源有此接点；各消费者的独立固定资源仍按 WP08 表划分。资源解析／缓存／动画包装仍按本文件各自入口处理 B；译后资源未命中或加载失败不带通用原身份重试，空译的后续消费也不等于语言缺译回退。身份选择不认证媒体存在、加载成功或像素结果。

### 3.3 默认窗口皮肤的选择与显式设置

消息与菜单分别保存各自的逻辑皮肤选择。仅在尚未取得默认结果时，按下表依次解析候选，首个命中即停止；后继候选不参与。选项索引有效、配置与资源解析正常且无插件为前提；没有玩家选项对象时，第一步取相应配置列表的首项。

| 次序 | 逻辑资源候选 | 继续条件 |
| --- | --- | --- |
| 1 | `Graphics/Windowskins/` 下玩家消息／菜单选项对应的配置名 | 解析未命中 |
| 2 | `Graphics/Windowskins/` 下系统登记的窗口皮肤名 | 登记名不存在／为空，或解析未命中 |
| 3 | `Graphics/System/Window` | 解析未命中 |
| 4 | `Graphics/Windowskins/001-Blue01` | 解析未命中则最终为空逻辑皮肤 |

得到的命中路径或空结果均成为后续读取的既定结果；空结果不等于尚未求默认。**显式设置消息／菜单逻辑皮肤**只解析传入的完整逻辑资源位置一次，失败保存空结果；即使备用素材存在，后续读取也不重新走上表。WP65 的 Speech/Menu Frame 选项先写选项值，再走此显式设置并把结果交给预览窗口。

## 5. 缓存与位图访问

- **缓存键**：相同路径与色相的有效访问可共享位图内容；已释放结果不能继续当有效命中。
- **使用有效期**：资源在仍有使用者时保持有效，复制内容与原图隔离；不规定具体内存管理机制。
- **空文件名**：返回 32×32 空白位图（不读盘）。
- **图块切取**：图块访问由资源、图块身份、色相与所需尺寸确定切片内容；相同有效内容可以复用，不规定缓存容器或键的表示。
- **缓存清空**：场景切换时由宿主缓存层整体清理（地图拓扑规格显示层重建处的清空调用点，引用）；本文件不规定淘汰策略。
- **失败边界**：分入口按下表区分解析 nil、缓存空白及动画/内嵌图像异常；损坏媒体与宿主输出未证。


### 5.1 位图访问的分入口失败

| 直接缓存访问，非空文件名 | 未有有效缓存结果且宿主对缺文件抛普通加载错误时，本入口没有捕获，异常传播；不能推空白结果。已有有效缓存命中不发生这次加载。 |

### 5.2 前缀横条动画的切帧和时相

文件名以合法数字前缀`[N]`或`[N,d]`开始才走此规则，N为正整数；负号、空白等不匹配形式不自动按此数字语法处理。正常资源成功加载且宽W能被N整除时，从左向右分N个等宽帧，每帧W/N×H。缺省d或d=0用5；每帧名义d/20秒。加载可先失败，不能据尺寸校验推加载已经成功；非正N和成功加载后的不整除尺寸仍按§5.1报错。

创建时建立t0，未更新初帧0；N>1、正常单调运行钟下更新的帧号为floor((t−t0)/(d/20)) mod N，允许跳帧。不是首次更新起钟或全局绝对相位。静止化从任何当前帧回到第0帧，此后不轮换。复制内容隔离按§5，复制时相不要求新起点。GIF自动播放由宿主提供，不套此公式；专用图标及箭头全局相位沿WP17 §6.5。

合法128×32资源、创建t0=.375：`[4]`和`[4,0]`每帧32×32、周期1秒，未更新为0，t=.625与1.625均为1；误用全局相位在.625会为2。`[4,2]`每帧.1秒，t=.48为1；从帧1静止化后保持0。成功加载的127宽/4帧不整除而失败，资源未加载成功时不能先承诺此尺寸异常。

| 角色 | 作者内容的枚举引用源与规则参数（成长曲线、进化方式、能力值、地形、天气、目标、环境等） | 游戏实际内容（物种、招式、道具、地图、训练家等） |
| 可否含行为 | **可以**（如成长曲线的经验公式、进化方式的判定），不只是枚举 | 字段语义按类归领域规格 |
| 修改方式 | 改脚本（开发者） | 改 PBS（作者/编辑器） |

维度澄清：Type、Move、Item 是**作者数据**（经 PBS 编译），同时也充当其他内容的枚举引用源；「是枚举引用源」不等于「是固定规则」。判断「某行为由什么决定」时，含行为的固定规则（成长公式、进化判定）与纯枚举目录必须分别对待。

**Nature 的固定身份前提**：参考快照的性格目录有 25 个身份，派生性格按个人标识对 25 取余后选取目录顺序中的身份；该顺序与每个身份的能力修正属于固定规则，不能由作者 PBS 自由重排或只保留显示名。例如顺序 1 的 LONELY 为攻击 +10、防御 −10；顺序 2 的 BRAVE 为攻击 +10、速度 −10（顺序从 0 开始）。完整 25 身份顺序、20 项双能力修正与 5 项中性映射，以及能力取整、薄荷等消费者合同由 WP19 负责；本档案登记该必需依赖，不以通用 schema 的身份校验替代这些领域规则。

## 3. 通知机制

### 3.1 事件订阅原语

| 原语 | 行为 |
| --- | --- |
| 回调列表（无序名） | 支持替换全部回调、添加（**已存在则不重复添加**）、移除、清空；触发时在各项正常返回的前提下依次调用全部回调（异常边界见 §3.3）：**仅当回调声明的参数个数大于 2 且与触发参数个数相等时传完整参数**；否则恒传（发送者, 其余参数数组）——两参数回调收到的是后者，不是「个数匹配即完整传参」；另有恒传完整参数的触发入口 |
| 命名回调表 | 按键登记/移除回调；**同键再登记则替换**；触发时在各项正常返回的前提下依次调用全部回调（完整参数；异常边界见 §3.3） |
| 身份处理器表 | 登记时**先**校验处理器形态（非过程/哈希/块则抛出参数错误），**再**按身份登记（空身份被忽略）；**同键再登记则替换**；查找未中返回空；支持把处理器复制到其他身份；触发时返回处理器的返回值（无处理器为空） |
| 符号处理器表（内容用） | 注册侧**没有「仅符号身份」的校验**：接受任意真值键；查找时非符号且可换算身份的对象取其身份，其余值按原样匹配；条件回退登记（精确未中时按登记顺序尝试条件处理器）；触发时把**按上述规则归一化后的键**作为首参传入（**类型不保证为符号**——字符串键登记并触发时首参仍为该字符串） |
| 内容专用表 | 物种/特性/道具/招式四类内容的效果各有独立处理器表（空特化，行为同上；效果族归战斗领域规格） |

#### 3.1.1 内容条件处理器的单项移除与清空

精确登记与条件组是两种状态。条件组G对X为真且效果C正常时，单项移除只删除所给键的精确登记；移除G这个同名键不注销条件组G，随后X仍命中C。X有精确效果D时优先D；移除精确X后回落到仍存在的C。整体清空同时删除全部精确登记与条件组，此后X不再命中。

以上假定触发期间不动态增删登记且无覆写。它与命名事件表的按键删除不同；既有处理器复制使用已经解析到的效果、不因后来条件改变而重解析的合同保持。

### 3.2 命名事件注册表

- 按「事件名＋回调键」注册（同键替换）；可按键移除/清空；按事件名触发时依序调用回调，全部调用以各项正常返回为前提（§3.3）；事件未定义时不报错、无效果。
- 文档化事件集（当前快照）：地图设置/进入/离开、每帧更新、玩家转向/迈步/可转移迈步/互动、训练家载入、野生物种选择/个体创建/战斗呼叫/战斗开始/战斗结束/野生战斗结束。
- 静态统计：注册点与触发点的全部文本命中均在文档化事件集内，未发现临时新事件名（统计口径见审计）。注意形似属性（如进化数据的「交换时回调」字段）不是本注册表的事件。
- 典型约定：迈步效果按命名键订阅（如亲密增长）；「可转移迈步」事件的消费者通过共享数组约定「已发生转移则跳过」。

### 3.3 通知异常、中断与部分状态

回调列表的两种参数入口、命名回调表及命名事件触发均没有逐回调的错误隔离或事务撤回。限定已确定的 A→B→C 顺序，无更早失败、入口未被扩展补捕获且不在触发期间增删订阅：全正常时三项依序完成；A 将可见状态由 0 写为 1 后正常返回、B 抛错时，C 不执行，状态保持 1，异常传向触发调用者，该调用者本次尚未到达的后续步骤也被中断。若首项抛错，没有先前回调副作用，但触发前的写入仍可保留；若末项抛错，所有前项已完成。失败项抛错前自身已经完成的写入也不自动撤回。

普通玩家迈步在无强制路线、无地图解释器运行且前序操作正常时，先写步计数 `(旧值 + 1) mod 2³¹`，随后触发玩家步通知，再触发可转移步通知。因此首个通知中的 B 失败时，已写步数与 A 的效果保留；本次不进入第二个通知或后面的遭遇检查，不能当作未迈步。若第二个通知失败，先前第一个通知已经发生。强制路线/解释器入口的早退计数规则仍按计步规格，不外推普通步前提。

调试主流程的外层诊断可在更外层处理传播的异常，它不保证回到本次通知继续 C，也不保证恢复已写状态；宿主最终提示/退出/恢复效果仍未运行。触发时动态增删订阅的宿主细节未穷尽。本合同不规定未来事件总线、异常类型或框架组织。

## 4. 语言配置与选择

- **作者配置**：`LANGUAGES` 声明候选语言列表（每条＝显示名＋文件名片段，对应 `Data/messages_<片段>_core/game.dat`）；默认为空（不提供候选）。
- **游戏语言选择机会**：启动流程在候选 ≥2 且已读存档数据为空时提供语言选择；载入界面在候选 ≥2 时显示语言菜单。调试菜单的翻译提取入口选择的是作者导出目标语言，不写玩家语言选项，也不切换当前游戏消息集（§6.2）；该入口不能计为已核实的游戏语言切换机会。不由此断言任意外部/插件语言入口不存在。
- **主动加载 vs 延迟加载**：主启动直接调用语言消息载入**立即加载**，不是首次查找才加载；翻译服务构造另支持延迟加载（首次查找时），两条路径分开。
- **持久化与直写**：选择保存在玩家系统选项（语言字段）；**载入菜单已有存档时切换语言会把选项写入该存档数据并直接写回存档文件**——这是**直接写档**，不经过正常保存路径（《保存、启动、新游戏与继续》引用）。无存档时切换不写档。
- **交界**：语言属于**设置**（玩家选项），不属于游戏进度；设置与进度的保存/重置边界归《保存、启动、新游戏与继续》，本文件引用。

### 5.1 查找链（当前语言 game → 当前语言 core，不再查默认语料）

| 入口形态 | 查找链 | 未中结果 |
| --- | --- | --- |
| 数组域查找 | 当前语言 game[域][索引] → 当前语言 core[域][索引] | 空字符串 |
| 哈希域查找 | 当前语言 game[域][键] → 当前语言 core[域][键] | **返回原文**（键为空/缺失时也返回原文；**不自动取默认语料**） |
| 地图事件文本查找 | 当前语言 game[图][键] → game[0][键]（共享桶） → 当前语言 core[图][键] → core[0][键] | 返回原文 |

用途分层：默认 core/game 用于**收集与导出**（作者工作流）；当前语言 core/game 由另一入口载入，用于**运行查找**。语言 game 覆盖语言 core 的同名译文（先查 game）。

#### 5.1.1 指定 UI 图像身份的语言选择

当前语言材料也可把指定 UI 图像的原始身份 A 映射为另一身份 B；这些字符串仍属于 SCRIPT_TEXTS，不新增文本域。查找先于图像创建／加载：语言 game 优先于语言 core；两层均缺译时交付原身份 A；命中非空译文 B 时交付 B，即使 A 本身可用也不改回 A。说明标签的文本查找与图像身份查找分别进行。

| 指定消费者 | 语言材料选择的范围 | 独立固定资源 |
| --- | --- | --- |
| 控制帮助 | 七个键图身份 | 控制帮助背景 |
| 图形模式下的战斗命令／招式菜单 | 命令与招式光标图、类型图、Mega 与换位按钮图 | 对应菜单背景 |
| 训练家卡 | 卡片及女性卡片图身份；女性分支另有资源存在性门 | 背景与徽章图 |
| 翻牌小游戏 | 背景和备忘图的基名；查找后仍在该消费者的图像目录下加载 | 其它图块、光标等资源 |

此规则只覆盖指定的查找调用者，不把所有 UI 图像都设为可翻译。空译仍是命中，随后怎样处理空身份、不可解析身份或加载异常由 [WP15](../engine-overworld/wp15-resource-matching-and-audio.md) 的实际资源入口决定；没有“译后资源失败就重试原图”的通用保证。查找本身不新增语言选择提示或存档写入，场景可能已建立视口／部分图像，不据后续失败保证整体清理或回滚。资源存在、合适尺寸、加载成功及实际像素仍须分别验证。

### 5.2 空译与异常边界

| 情形 | 行为 |
| --- | --- |
| 缺键/缺失 | 按 §5.1 回退链处理（数组域空串、哈希/地图回原文） |
| **空字符串命中** | 空字符串是**有效命中**（真值判断），**直接返回空串，不触发回退**——空译不会被原文/核心译文替补 |
| 文件载入失败 | 载入入口的异常捕获把语言/核心消息置空，效果同回退；**加载器仅检验外层为数组**，内层形态不符仍可能在查找处出错 |
| 查找结构异常 | 数据形态异常（如内层非预期类型）按常规异常传播，不被查找入口捕获 |
| 格式化异常 | 脚本翻译入口的异常捕获**只包住查找部分**；后续格式化在捕获之外，**格式化错误向外传播** |
| 地图翻译入口的格式化 | 地图翻译入口**没有**同样的查找捕获——其格式化/查找错误**均不被该入口捕获**（不能套用脚本入口的捕获保证） |

**地图名的查找值消费**：哈希查找返回所选译文值或原输入，不给每个消费者独立模板副本。地图命名服务会直接展开所选材料中的大写`\PN`，材料保留、改变后的查找键、别名及恢复规则集中于[WP11§5.3.1](../engine-overworld/wp11-map-topology-transfer.md)；空译在语言层不转core，地图消费者随后可转基本名。继续预览另按WP65，通用消息复制输入的控制处理不能套为地图名状态规则。当前替换参数与其捕获/格式化边界仍按下节。

### 5.3 占位参数

脚本翻译入口在取回文本后按参数次序替换 `{1}`、`{2}` 等占位；常规参数如Q直接插入，但**不承诺任意参数逐字保留**。格式化翻译入口支持 `{1:d}` 形式的格式占位（按格式化规则求值）；地图翻译入口为地图事件文本的对应入口（先按地图回退链取文本，再替换占位）。查找失败时脚本翻译入口回原文（见 §5.2 捕获范围）。

正常主入口已定义、无插件覆写，当前语言各层均无命中时，在进入任何消息窗口**之前**观察返回字符串：

| 入口与原文 | 参数的真实字符 | 返回字符串 |
| --- | --- | --- |
| 普通脚本，X{1}Y | Q | XQY |
| 普通脚本，X{1}Y | U+005C后接U+0026（反斜线与&） | X{1}Y，恢复被匹配的占位文本 |
| 普通脚本，X{1}Y | U+005C后接U+0031（反斜线与数字1） | XY |
| 地图5普通入口，X{1}Y | U+005C后接U+0026／U+0031，各例独立 | 分别X{1}Y／XY，同样解释替换参数 |
| 脚本／地图格式化字符串入口，X{1:s}Y | U+005C后接U+0026 | X后接这两个参数字符再接Y，保留反斜线与& |

反斜线与数字1是两个字符，**不是U+0001**；这些结果属于本地化插入阶段，与 [WP17](../user-interface/wp17-messages-windows-input.md) 后续显示控制/暂停转换分开。第四审查的Ruby 2.6.10隔离原函数回执支持所列脚本结果及地图反斜线&结果；地图反斜线1与地图格式化对照另由同样的源路径静态推导。本次未重跑，新增向量为DERIVED_VECTOR、NOT_EXECUTED_THIS_UPDATE；随附宿主及窗口呈现未执行，更多转义/嵌套组合未穷尽。未来是否采用任意参数字面插入须另作兼容决策。

### 4.1 启动阶段表

| 阶段 | 行为 |
| --- | --- |
| 上游准备 | 核心消息加载 → 插件 → 编译检查 → 游戏初始化 → **系统设置**（读取并加载启动值，错误可能在此中断，不到达备份界面，《迁移、失败与恢复》引用） → 标题场景 |
| 启动读取 | 先检查默认主档：存在则读取并作必要的旧格式适配，不存在则取得空表；成功取得数据后，**按数据是否为空**分流：空表以新游戏值初始化启动值，非空数据加载启动读取值（game_system、pokemon_system、essentials_version、game_version、stats）。现存可读旧序列也可适配为空表（《迁移、失败与恢复》§3.3）；读取/适配异常不视为空表 |
| 标题/载入界面 | **普通无存档路径仍构建菜单**（已读数据非空时首项「继续」，另有新游戏、选项、语言（候选 ≥2）、调试（调试模式）、退出）；**仅当调试模式＋无打包归档＋`SKIP_CONTINUE_SCREEN` 三者同时成立时**，才跳过菜单：已读存档数据为空 → 新游戏；已读数据有效且非空 → 继续载入。三门只决定是否跳菜单，不决定清空进度；不能永久等同文件存在性与已读数据是否非空（旧序列转空表边界见《迁移、失败与恢复》§3.3） |
| 新游戏 | 加载新游戏值（有新游戏值且未加载或要求重置的值取新游戏值）→ 设游戏时间锚点 → 会话数加 1 → 建地图容器与玩家位置 → 进入地图场景 |
| 继续（读档） | 加载全部未加载值 → 设游戏时间锚点 → 会话数加 1 → 恢复地图 → 进入地图场景 |
| 地图恢复 | **magic_number 不一致或 safesave 为真时重新设置地图**（缺地图时：调试给选图入口（取消则退出，选择后设图与坐标），非调试抛「地图未找到，无法继续」）；**两者都不成立才按地图变更恢复**；此后当前地图的事件集合缺失（空值）时抛「地图损坏，游戏无法继续」。集合存在但零条目不触发该损坏守卫；通过该守卫不等于后续恢复/完整启动成功（与缺图是不同错误） |

世界恢复投影（GR3-M03-004；静态，NOT_EXECUTED）：两正常地图恢复分支均发送进入通知；默认首消费者先清地图局部消去/移动记录，随后地图更新与条件恢复辅助（WP11 §6.1–6.2）。无新记录时辅助见空表；复用的已加载实例状态与记录清空分开。实际同ID重建旧ID非零仍离开，非重建只进入。 进入/地图更新异常时后续未到；清空/先前加载前缀不自动回滚。缺图调试选择/取消与nil事件集合/空集合守卫保持。 通知失败前缀见 WP05 §3.3；条件异图穿透辅助不代表默认读档仍有旧记录。

#### 4.1.1 调试主流程异常后的脚本收尾

DEBUG真、普通异常在主流程关键段中发生且诊断正常完成时，失败点之前的可见状态保持；之后的场景动作与本次场景重入未到。关键段给失败标记0，主入口仍给自己的完成值1，顶层脚本循环结束，具体规则见[诊断关键段](wp07-diagnostics-files-http.md#511-关键段完成标记与调试主入口)。Reset/SystemExit、Hangup紧急保存与诊断失败各走该合同的不同分支；不由脚本循环结束推宿主窗口/进程已退出。

### 4.2 设置与进度的区分

- **设置（pokemon_system）**：玩家选项（语言、文本速度、选项配置）——启动读取，**新游戏时也读取保留**（不属于进度，不随新游戏重置）。
- **进度（其余各值）**：玩家、背包、储存、开关/变量、地图、统计等——按上表的新游戏值/重置规则处理；**game_system 是启动已加载、非强制重置的值，与 pokemon_system 一样可能保留**（不能把所有非选项对象统一为「新游戏重置的进度」）；stats 启动读取但**新游戏强制重置**（重建后会话数又加 1，完成时为 1，《时间、随机、计步与统计》对齐）。
- **版本（essentials_version、game_version）**：随存档保存的引擎/游戏版本，启动读取，供版本兼容判断（迁移归《迁移、失败与恢复》）；启动加载的状态与保存时读取当前常量是两种形态，分别记录。
- 语言属于设置（《本地化》引用）：新游戏不重置语言选择；具体选项集合的语义归选项界面规格。

## 5. 保存路径与写入边界

### 5.1 保存成功路径与前后状态

| 阶段 | 内存状态变化 | 磁盘状态 |
| --- | --- | --- |
| 保存前 | 设 safesave 标志；save_count 加 1；magic_number 设为系统数据的 magic_number；写入最近保存时刻（当前游戏时间，可能经游戏时间锚点刷新，《时间、随机、计步与统计》对齐） | 未触及 |
| 取值/校验 | 汇编保存数据：全部持久值的保存取值并校验（类型约束不符抛**持久值类型错误**——**不在 IO/系统调用错误捕获集合内，save_count 不回退**） | 未触及（此阶段尚未打开文件） |
| 打开/序列化 | 以覆盖模式打开后序列化写入 | 打开即截断旧文件（覆盖模式） |
| 成功后 | 帧计时重置 | 新存档文件 |
| IO/系统调用错误分支 | **仅回退 save_count（减 1）** 并返回失败——safesave、magic_number、最近保存时刻、锚点等**均不回退** | 文件状态未验证（可能部分写入/截断） |

路径选择：默认保存路径为宿主数据目录下的 `Game.rxdata`（该目录存在时），否则当前目录 `Game.rxdata`；也可传入自定义路径（调用方决定，与默认路径是两种写入目标）。

### 5.2 其他写档路径（各自责任，不暗示都经过正常保存）

- **语言菜单直写**：已有存档时切换语言把选项写入存档数据并直接写回（《本地化》引用）。
- **转换读取写回**：读取存档后若发生转换则把结果重新写回（《迁移、失败与恢复》引用）。
- **删除存档**：先删除默认主档，再删除存在的单个相邻 `.bak`；各失败前缀、剩余文件与下次主档存在门见[迁移、失败与恢复 §5.1.1](wp10-migration-failure-recovery.md#511-有序删除与下次载入门)。

### 5.3 无存档/损坏/备份（启动侧事实）

- 无存档：存档数据为空表；普通路径仍显示菜单（§4.1）。
- 存档无效（有效性校验为假）：有 `.bak` 备份时提示「存档损坏，将载入备份」并读备份；无备份时询问是否删除存档并重新开始。完整失败/恢复规则归《迁移、失败与恢复》。

## 3. 转换机制

### 3.1 注册与触发

每个转换按以下配置登记：

| 配置 | 行为 |
| --- | --- |
| 引擎版本阈值或游戏版本阈值 | 触发条件：存档对应版本**低于**阈值才执行；只能二选一，重复声明报错 |
| 显示标题 | 执行时显示的标题（转换在语言选择之前执行，标题**不可本地化**） |
| 逐值修改（指定持久值） | 对指定持久值的修改；要求存档**含有**该值，缺失则抛错 |
| 整体修改 | 对整体存档的修改 |

### 3.2 触发判定与执行顺序

- 触发判断使用**版本比较器**（《通知、扩展与插件》：逐字符位置比较）。以输入 "19" 与阈值 "20" 为例：**第一位 1 与 2 比较，结果为 −1，判定低于阈值，应触发**（不是「19 > 20 不触发」）。其他可复核输入输出：20/20 → 0（不低于，不触发）；1.10/1.9 → −1（1.10 < 1.9，触发较低阈值一侧按实现判定）；存档缺省版本按引擎 "18.1"、游戏 "0.0.0" 处理（低于当前 20/21 阈值，触发对应转换）。
- **执行顺序**：**引擎族先于游戏族**；各族内按比较器把阈值**从低到高**排序执行；**同阈值按登记顺序**。筛选出「应运行的列表」不等于所有转换都成功（执行可能中断，见 §3.4）。
- **版本判断、转换族先后、同阈值登记顺序、候选列表与成功执行是不同层次**，不能混为同一关系。

### 3.3 旧格式入口与边界

| 存档形态 | 处理路径 |
| --- | --- |
| 旧序列（v19 之前，数组形式） | 按各持久值的旧格式转换入口组装为表结构。**当前 17 个默认登记均无旧格式转换入口配置**——在固定默认登记、无动态插件补充且旧对象可成功读取的前提下，该数组→表结构路径得到**空表**，之后跳过转换执行。**不能统一为「凡无版本信息的极旧档都会执行全部 14 项」**。登记接口存在不等于已有实际适配 |
| 空表 | 无键可读；按后续校验/加载规则处理 |
| 非空但缺版本标记的表 | 按缺省版本（18.1 / 0.0.0）处理（§3.2），触发对应转换 |
| 显式版本表 | 按存档版本与阈值比较（§3.2） |

### 3.4 备份与写回时机

转换执行流程：

1. 收集应执行的转换；无则返回「未执行」（不写转换备份、不写回）。
2. **先把内存中的存档数据序列化到默认保存路径旁的 `.bak`**（转换前快照；**不是原文件逐字节复制**；覆盖同名旧备份，无追加/轮换证据）。
3. 逐个执行转换（控制台输出标题与完成状态；逐值修改缺值即抛错中断）。
4. 把存档的引擎版本/游戏版本更新为当前版本，返回「已执行」。
5. 随后（《保存、启动、新游戏与继续》登记的读取路径）：读取入口在转换返回「已执行」时**把转换后的存档重新写回读取时使用的路径**——**读取旧档会改写它**。

**备份与写回目标按读取路径区分**：

| 读取路径 | 转换备份位置 | 写回位置 |
| --- | --- | --- |
| 默认保存路径 | 默认路径旁 `.bak` | 默认路径 |
| 默认 `.bak` | 默认路径旁 `.bak`（**与读取来源同一文件**） | 默认 `.bak`（**同一文件**） |
| 自定义路径 | 默认路径旁 `.bak`（**不随自定义路径变化**） | 自定义路径 |

紧急保存的备份是另一操作：把原存档文件**逐块复制**到 `.bak`，与转换备份（内存数据快照）不同，不能混为「原档总能逐字节保留在旁边」。

### 3.5 副作用分层

| 阶段 | 可能发生的变化 |
| --- | --- |
| 转换前 | 内存数据快照写入 `.bak`（覆盖同名旧备份） |
| 转换中 | 某转换的逐值修改缺值 → 抛错中断，后续转换不执行；已执行的修改保留在内存数据中 |
| 写回后 | 转换后的存档重写读取路径对应文件（原旧档不再以原样存在，除非 `.bak` 保留）；控制台记录转换标题 |
| 异常处理 | 备份写入/转换执行/写回任一失败的行为未逐分支验证（不默认原子性或日志一定成功） |

## 5. 失败与恢复

### 5.1 启动值读取到界面校验/递归备份的完整链

| 分支 | 行为 |
| --- | --- |
| 早期启动值错误 | 系统设置在载入界面之前直接读取并加载启动值（含转换）；**错误可能在此就中断，不能保证所有坏档都到达备份界面** |
| 读取/转换抛错 | 读取入口或转换本身抛异常——**与「返回无效数据」是不同分支**，不进入备份/删除逻辑 |
| 返回无效数据 | 有效性校验为假时才进入：有 `.bak` 时提示「存档损坏，将载入备份」并读备份；**备份是递归调用「路径＋.bak」（可能继续 `.bak.bak`）**；无备份时询问是否删除并重新开始 |
| 备份仍无效 | 递归到 `.bak.bak`（同上），继续同样判断 |
| 拒绝删除 | **调用退出，产生退出信号并退出当前游戏执行**（外层关键段包装对退出信号原样传播，《诊断、文件与 HTTP》引用）——不删除、也不返回菜单继续 |
| 删除失败 | UI 捕获删除序列的系统调用错误（SystemCallError）并请求失败提示，已完成的删除不回滚；各步骤留下的文件状态见 §5.1.1 |

### 5.1.1 有序删除与下次载入门

删除目标是默认主档 P 和单个相邻备份 P.bak：先删除 P，成功后才检查 P.bak 是否存在，存在才删除它。第一次删除失败时不到第二次；第二次失败不恢复已删除的 P。无效数据的递归备份**读取**仍按 §5.1，不使删除扩展到 P.bak.bak。

下表限定标题删除入口已由有效、当前格式/版本的主档到达，两文件初始均为普通文件（无备份对照除外），无并发/插件改写，确认、提示与标题操作正常。失败例明确给定相应删除抛 SystemCallError 且该次未删文件；不据任意错误推定同一磁盘状态。

| 确认与删除结果 | 剩余文件 | UI 请求与后继 |
| --- | --- | --- |
| 任一次确认拒绝 | P、P.bak 均在 | 不尝试删除；结束删除画面并回标题 |
| 两次确认通过，两次删除均成功 | P、P.bak 均无 | 请求删除成功提示，随后回标题 |
| 两次确认通过，删除 P 失败且未删 P | P、P.bak 均在 | 不尝试删除备份；请求删除失败提示，随后回标题；下次主档存在门仍为真 |
| 两次确认通过，P 删除成功，P.bak 删除失败且未删备份 | P 无、P.bak 在 | 请求删除失败提示，随后回标题；不重试、不回滚；下次主档存在门为假 |
| 两次确认通过，P 删除成功且相邻备份不存在 | P、P.bak 均无 | 不尝试删除备份；请求删除成功提示，随后回标题 |

返回标题后的下一次载入对象先只检查默认主档 P。P 不存在时取得空数据，不扫描孤立 P.bak，普通载入菜单没有继续项；P 存在时才进入读取/校验与必要的备份链。回标题不等同于重新执行全新进程的系统装配。

无效存档删除提示是另一调用者：拒绝产生退出信号；同意后执行同一删除序列，即使删除的系统调用错误已被处理，仍新建游戏系统与系统选项对象并返回空数据。提示自身失败或不属于该捕获范围的异常可阻止标题返回、对象重置或后续菜单，不能从正常收尾推成兜底保证。以上只描述固定参考的条件化行为；真实文件失败未执行，未来删除原子性政策仍须另作兼容决定。

### 5.2 紧急保存（脚本超时路径）

- 触发：脚本超时到达主流程分支时（两种模式均可能调用；调试与非调试差异见 §5.3）。
- 行为序列：保存旧场景并把场景置空、提示超时将重启；**无玩家时直接返回（不恢复旧场景）**；有玩家时：**无旧存档也可尝试新建保存**（不需要「已有存档」作为保存前提）；有旧存档时先逐块复制到 `.bak`（**备份复制失败可以阻止后面的保存**）；随后执行正常保存（《保存、启动、新游戏与继续》路径）；成功提示「已保存」（**「旧档已备份」仅在实际存在旧档时成立**），失败提示「保存失败」。
- **场景的恢复只在正常走到底时执行**（不是兜底保证）——提前返回（无玩家）或异常时场景不恢复。

### 5.3 调试与非调试分层（引用《诊断、文件与 HTTP》）

- 两种模式的主流程超时分支**均调用紧急保存**（§5.2）；**仅非调试先打印异常**；**调试时该分支重抛后才由外层关键段包装转成重启信号**。
- 前提是超时**到达此处**——编译/插件内部另行处理的超时不覆盖（《PBS 生命周期》《通知、扩展与插件》引用）。
- 重启/退出信号的传播仅限具体分支（关键段包装、编译主流程；插件脚本执行入口经插件诊断/退出路径，《通知、扩展与插件》《诊断、文件与 HTTP》已登记，引用）。
- 只描述异常信号传播，不声称宿主已经完成重启。

### 5.4 地图恢复失败（《保存、启动、新游戏与继续》登记，本节细化）

- 重新设置缺地图（文件缺失类错误）：**调试给选图入口**（取消则退出，选择后设图与坐标），**非调试抛「地图未找到，游戏无法继续」**——静态分支可读，不能仅归为「待 demo 材料」；场景实际显示/地图可达可待证。
- 地图损坏（当前地图的事件集合缺失/空值）：抛「地图损坏，游戏无法继续」；存在但零条目的集合不触发该损坏守卫。限定已到达校验点且先前地图操作成功，不把通过守卫当作完整启动成功。**与缺图是不同错误**，分开记录。

## 5. 六项能力与培养参数

### 5.1 数据分层与来源

| 输入 | 来源 | 责任 |
| --- | --- | --- |
| 基础能力值（六项） | 物种/形态记录 | 数据归个体/物种规格；计算使用归本文件 |
| 个体值（IV，六项） | 创建随机 0–31；后续按入口覆盖 | 本文件 |
| 个体值上限标记 | 默认空；外部设置 | 本文件（生效方式）；启用入口见 §8 未决 |
| 努力值（EV，六项） | 创建为 0；后续按入口增加/减少 | 本文件（域与上限）；分配流程见前向引用 |
| 等级 | 由经验换算（或显式设置） | 本文件接口；流程归成长规格 |
| 性格修正 | 由性格/计算用覆盖决定 | 本文件 |
| 禁用开关 | 配置（默认假） | 本文件（视为 0 的变体） |

### 5.2 个体值（IV）

- **域**：每项 0–31（上限常量 31）；创建时逐项均匀随机（0 至 31 含端点）。
- **存储**：六项键值的映射；**数据层本身不钳位**（任意写入原样存储）；已定位写入者均把值限制在域内（野生重掷、传说满个体、训练家数据、调试/编辑器范围）。存储应包含全部六项（计算入口不为缺失项兜底；缺失项进入算术会失败）。
- **有效值**：上限标记为真 → 31；否则存储值；「禁用 IV/EV」配置 → 0。
- **上限标记（Hyper 类）**：键值映射，默认空；语义＝「该项按 31 计算」；**仅**影响能力计算，不改写存储值、不影响展示中的原始 IV 排序/描述（展示入口按各自读取）。
- **特殊分支（生成侧，完整流程归遭遇规格）**：猎场/捕虫大会内野生个体最多重掷 4 次全项 IV 直至出现一项满值；传说/神话/究极异兽标记物种在世代 ≥6 配置下随机选 3 项设为满值；两者都触发重算。
- **未决**：正常游戏内设置「上限标记」的启用入口在核心脚本中未定位（检索未见写入者；接口存在但入口不明，见 §8）。

**原始 IV 的个性描述消费合同**：摘要以存储的六项 IV 选择描述，不读上限标记替代值、计算用性格或能力大小。并列最高时，以固定环序 **HP → 攻击 → 防御 → 速度 → 特攻 → 特防**，从个体编号 mod 6 的位置开始环扫，选首先遇到的最高项；相等的后续项不替换它。选中项的原始 IV mod 5 决定下表列。它与能力公式中 HP／攻击／防御／特攻／特防／速度的列序不同，不能借登记序号替代。性格文字／个性是否显示的 Shadow 阶段门及画面布局仍归 WP66A；此处提供数据合同供该消费者核对。

| 最高原始 IV 项 | 余数 0 的含义 | 余数 1 的含义 | 余数 2 的含义 | 余数 3 的含义 | 余数 4 的含义 |
| --- | --- | --- | --- | --- | --- |
| HP | 爱吃 | 常打盹 | 容易睡着 | 常把东西弄散 | 爱休息 |
| 攻击 | 自豪于力量 | 爱大闹 | 有点急脾气 | 爱争斗 | 脾气急 |
| 防御 | 体格结实 | 耐打 | 坚持不懈 | 耐力好 | 毅力好 |
| 速度 | 爱跑 | 对声音警觉 | 莽撞而傻气 | 有点滑稽 | 逃得快 |
| 特攻 | 好奇心强 | 爱恶作剧 | 很精明 | 常陷入思考 | 很挑剔 |
| 特防 | 意志坚定 | 有点自负 | 很不服输 | 讨厌输 | 有点固执 |

表中为 30 项独立语义释义，实际文案经本地化，不承诺逐字输出。六项原始 IV 均 31 时，个体编号 mod 6 = 3 选速度、余数 1（对声音警觉）；mod 6 = 4 选特攻、余数 1（爱恶作剧）。

### 5.3 努力值（EV）

- **域与上限**：从各项及总量均在额度内的输入出发，普通培养/增量入口按各自额度门维持单项 `0–252`、六项合计 `0–510`，**不是所有正常写入者的全称保证**——已批准的设施/工厂模板创建是正常入口例外：按「EV 总额 ÷ 努力项数」整数分配（2 项各 255、3 项各 170），不使用单项 252 常量夹限（GR-016；设施规格已按同一白名单批准范围记录该行为）。
- **存储**：六项键值的映射；创建为 0；数据层本身不钳位，增量入口各自检查剩余额度。普通非 Shadow 战斗分配按 HP、攻击、防御、特攻、特防、速度逐项处理：先把该项产出夹至 [0, 252 − 该项现值]，再把所得增量夹至 [0, 510 − 当前合计]，随后写入并更新合计。两上界均非负时，可写成 min（非负产出, 单项余量, 总余量）；这不是对已有越额存量的安全归零或自动规范化保证，道具/调试仍按各自入口规则；**Shadow 暂存分支**先计入「已暂存 EV」并入总量、单项剩余按「252 − 当前值 − 已暂存值」夹限（归 Shadow 规格）；**设施/工厂模板创建不经该夹限模式**（直接按总量整数分配写入）。
- **计算使用**：`⌊EV / 4⌋` 进入能力公式（取整发生在这里；不足 4 点不产生增量）。
- **已定位写入者目录**（规则细节归各入口规格，本文件只登记上限模式与消费者；增量额度规则仅在相应前提成立时适用，模板创建与存量越额边界分别列明）：
  - 战斗击败获取（病毒「已感染或已治愈」阶段使本次获取翻倍；另有持有物侧的获得修正入口；Shadow 成长暂存写入「暂存 EV」而非当前 EV）；
  - 培养道具（维生素类单次 +10；**默认配置（世代 8）不受 100/项限制**、仅守单项 252/总 510；「100/项封顶」是设置关闭（较早世代配置）的变体；工具函数形参默认不等于道具入口的默认实参；羽毛类小幅；EV 降低树果下调）；
  - 训练家数据（未给定 EV 时按等级推导：`min（⌊等级×3/2⌋, 85）`）；
  - **设施/工厂模板创建（正常入口例外，GR-016）**：逐项整数分配写入——对非空、由**互不重复的有效努力项**构成的模板，设总额为 E、项数为 n，每个指定项得 `⌊E/n⌋`（默认 E=510：2 项各 255、3 项各 170、4 项各 127）；新个体这些项合计 `n × ⌊E/n⌋`（仅当 n 整除 E 时等于 E），其余项仍为 0，**未分配余数不自动补到任一项**（无「合计恒为 E」保证；此公式不无条件推广到重复项配置，重复项目录未展开）；**不用单项 252 夹限**；默认数据即含双努力项模板（具名样本见审计）。调试。「禁用 IV/EV」配置下存储仍存在、仅计算视为 0（不能借配置把存储规范化）。
- **边界**：EV 修改后由写入者调用重算（§5.6）；EV 数值本身不影响经验/等级。

具名反向对照：固定默认设施模板第 5 行 **CATERPIE／FOCUSBAND／QUIRKY／HP,ATK／TACKLE,STRINGSHOT**，合法 L50、六项 IV31、默认 E510，普通设施/工厂创建正常返回后 HP 与攻击 EV 各 **255**，其余 0、总量 510；重算保留存储值，两个计算项均取 ⌊255/4⌋=63。培养道具仍受 252/510 额度门；不能将 WP28 的培养门写成所有正常写入入口的保证。生成器对含重复 EV 条目的规则另归 WP76，未由此二项样本扩张。

<a id="ev-increment-domain"></a>

**普通战斗分配的越额存量边界**：把上述正常模板产物交给可单独调用的普通非 Shadow EV 分配入口，或显式满足内部战斗、允许成长及合法接收者/对手参与记录等门后进入同一分配，HP 首先被处理。HP EV255 使单项上界为 252−255=−3，区间下界 0 大于上界，夹限即失败；尚未执行总量夹限和第一项 EV 写入。对手 HP 产出为 1 或为 0 都如此，零产出没有提前跳过该检查。最小例排除物品、病毒修正及其它回调副作用，因此此接收者的 EV、经验和成长统计在此失败点不变；原模板255仍保留。经正常成长调用时，此接收者后续经验授予及该对手参与者记录清空未到达；此前生产过程、已处理的其它接收者或回调写入不承诺回滚。

对照：全项 EV0、HP 产出1，写 HP EV1；HP/攻击各252、合计504时同样产出被夹成0且可正常完成。默认组织化设施战斗的内部战斗标志为假，普通成长在更早处返回，不会因持有模板255自动进入这个失败。上述边界不扩张为默认设施故障、所有培养道具、Shadow 暂存或净化的同一失败合同。

### 5.6 特殊物种与分支

| 分支 | 行为 | 归属 |
| --- | --- | --- |
| 基础 HP = 1 的物种 | HP 上限恒 1 | 本文件公式特例 |
| 传说/神话/究极异兽 | 3 项满 IV（世代配置） | 遭遇规格（生成） |
| 猎场/捕虫大会野生 | IV 全项重掷 ≤4 次至出现满值 | 遭遇规格 |
| 训练家队伍 | 未给定 IV/EV 的按等级推导；可显式覆盖 | 训练家规格 |
| 计算用性格（「薄荷」） | 表现与计算分离 | 本文件；道具流程归道具规格 |
| 禁用 IV/EV 配置 | 计算视为 0 | 本文件变体 |
| Shadow 的 EV/经验暂存 | 不进入当前 EV/经验（暂存字段） | Shadow 规格 |

## 3. 亲本归一与角色

### 3.1 槽序交换规则

传入两槽个体后，**当且仅当**满足以下任一条件时交换两方：①「母」为雄性；②「父」为雌性；③「母」为无性别。交换后不重复检查（单次交换）。

| 槽序示例 | 交换 | 归一后（母 / 父） |
| --- | --- | --- |
| ♀ / ♂ | 否 | ♀ / ♂ |
| ♂ / ♀ | 是 | ♀ / ♂ |
| ♂ / 百变怪 | 是（母为雄性） | 百变怪 / ♂ |
| 百变怪 / ♀ | 是（母为无性别） | ♀ / 百变怪 |
| 百变怪 / ♂ | 是（母为无性别） | ♂ / 百变怪 |
| ♂ / ♂ 或 ♀ / ♀（不兼容对） | 至多一次交换 | 不保证归一；常规门控在寄养周期层已确认、事件接待仍待 U01（见下注） |

> 表的边界记录：**单次交换不复查**，「母/父」只是后续通道的角色名，**不保证最终生物性别**——例如 百变怪/♂ 交换后「母」仍为雄性；百变怪/♀ 也发生交换（两种槽序归一后同为 ♀/百变怪，不是「不交换」）。共同等级招式要求**双方（含百变怪）都掌握**；机器与两路蛋招的性别门控后果见 §9。**生成/领取领域工具自身不重查兼容性**（寄养规格）；「不兼容对」的豁免在寄养的**周期置标记层已确认**；**事件接待实际守卫仍待 U01**，静态边界记录。

### 3.2 物种亲本与招式提供方

- 「母方百变怪」＝「母」方蛋组含百变怪；「父方百变怪」同理。
- **物种亲本**＝母方百变怪 ? 父 : 母（百变怪不提供物种；无百变怪时由母提供）。
- **招式提供方**（归一补正）：招式「父方」＝父方百变怪 ? 母 : 父、招式「母方」＝父方百变怪 ? 父 : 母；即「父为百变怪」时，招式通道的「父方」落到母方对象上、而「母方」落到百变怪上（其后果见 §9 边界）。
- **特性通道的非百变怪方**＝母方百变怪 ? 父 : 母。

### 3.3 族内标志

对**母**与**父**分别计算「该亲本是否与蛋的后代物种同族」（家族集合或后代列表包含关系）；两个布尔标志用于：形态继承（§5）、球的候选（§8.1）、Volt Tackle 的持球前提（§6.1）。

族集合的有序展开从已选前身回溯到族根；每层目标按物种定义位置排序，先展开当前分支的全部后代，再展开下一分支，根在前且重复身份保首见。None关系也可连接族集合，但不成为可执行进化条件。有效无环族A→C、A→B、B→D，定义序A/B/C/D，族块为A/B/D/C；按族填充地区图鉴消费此有序结果，编号与外层保存门见WP62及内容编辑器。该顺序不改变蛋的后代列表等概率采样、熏香门或招式通道。

## 3. WP65-A：标题、启动选择与载入

### 3.1 开场与标题

- **启动链**：主入口先载入默认消息（存在核心消息文件时）；调试且非打包且配置开启时先询问是否编译（含完整编译标记）；随后插件管理器加载、编译器主流程、游戏初始化与系统装配，再进入标题入口。**装配期的语言处理**：先检查默认主档，存在则读取并作必要的旧格式适配，不存在则取得空表；成功取得数据后，空表初始化启动值，非空数据读入启动值（WP09 §4.1；现存可读旧序列也可适配为空表，WP10 §3.3）。随后应用画面缩放；**语言配置非空时**——已读数据为空且语言候选 ≥2 才先弹出语言选择，再按当前索引的消息文件载入（WP08 引用）。读取/适配异常不作成功空表处理；之后的载入有效性与备份/删除分流见 §3.2。
- **标题入口分流**：**调试构建 → 直接进入载入画面**（跳过开场与标题）；普通构建 → 开场序列。
- **开场序列**：逐张播放登记的开场图（默认2张）；每张先0.4秒淡入，再停留最多2秒，最后0.4秒淡出，无输入目标总2.8秒。USE提前仅在停留检查窗口生效，淡入/淡出不检查这一跳过键。放完后标题背景与确认提示进入闪烁（目标40个1/20秒单位一周），播放登记标题BGM；真实素材/宿主时序未运行。
- **标题画面离开**：USE请求随机物种叫声后，等待1秒，再两幅标题图0.4秒淡出，同时请求BGM按1秒淡出，随后进载入画面。等待/淡出前清除标题更新与确认回调；不保证叫声全长播放或听感。下＋BACK＋CTRL进入删除画面也经过此离开过程。
- **主循环**：标题入口返回的场景对象持续主循环直到为 nil；中止类异常 → 紧急保存（§4.2）后原样抛出。

### 3.2 载入画面

- **存档分流（打开画面前已发生）**：构造载入对象时——存在存档文件则**读取并校验**（WP09 引用）：有效 → 用该数据；无效且存在 `.bak` → 提示「存档损坏，将载入备份」并**递归**改用备份；无效且无备份 → **删除提示流程**（见下）后按无存档继续。不存在存档文件 → 按无存档处理。**更早的读取异常不强行接到备份 UI**（读取层行为归 WP09/WP10，本稿不承诺所有异常都到达载入画面）。
- **调试跳过门**：调试标志、非打包运行、`SKIP_CONTINUE_SCREEN`（默认false）＝true 三门同时成立才不显示载入菜单；此后按**已读数据是否为空**分流：空 → 新游戏，合法非空 → 继续。至少一门假则仍显示菜单。文件存在本身不等于数据非空，旧序列转空数据的迁移边界仍归 WP10/MG03；共享 SV02 的已接受限定保持。
- **命令构建与可见条件**（按序追加，每项记录其下标）：
  1. **继续**（Continue）：存档非空才出现；为真时作为首个大面板（展示见下）。
  2. **神秘礼物**：存档非空且玩家神秘礼物解锁标记为真才出现（WP64 引用）。
  3. **新游戏**：总出现。
  4. **选项**：总出现。
  5. **语言**：`LANGUAGES` 候选数 ≥2 才出现（**默认配置该数组为空——默认不出现**；WP08 引用）。
  6. **调试**：调试标志才出现。
  7. **退出游戏**：总出现。
- **继续面板展示数据**（仅继续项的大面板）：徽章数、图鉴已见数、游戏时间（≥1 小时显示"h m"，否则只显示分钟）、玩家名（按性别着色：男蓝/女红/其它默认色）、当前地图名（先查询地图命名服务，再以存档训练家名展开剩余大写`\PN`，共享材料规则见下）、玩家行走图（**图集文件缺失时报错**——"Player character {id}'s walking charset was not found"）与队伍成员图标（按 2 列排布）。非继续项为窄面板、只显示命令名。 行走预览按合法4×4图集首行四格，0.5秒一周，按绝对运行时间取帧；玩家/NPC命名（键盘输入和屏幕光标两模式）同为4×4图集首行四格、0.5秒一周；只有盒名预览使用单行四格、0.4秒一周。各入口按运行时钟相位，资源失败由消费者另列。
- **选择循环**：面板随下标切换选中色并可滚动；**只接受确认键**（返回当前下标；本循环没有取消键分支）。退出游戏以外选项先播决定音。
- **各命令去向**：
  - **继续** → 关闭画面 → 按已读数据载入（WP09）→ 进入游戏。
  - **新游戏** → 关闭画面 → 开新游戏（WP09/WP24 引用）。
  - **神秘礼物** → 淡入淡出执行下载流程（WP64 引用），**随后回到载入菜单循环**（不离开画面）。

## 6. WP65-D：暂停主导航

### 6.1 入口守卫与菜单循环

- **入口（请求生产与消费分开，R01 修订）**：本节“玩家未移动／静止”仅表示**没有普通移动／碰撞计时**；跳跃计时独立，仍在跳跃不额外阻止这些末端登记与消费门（[WP12 地图末端门](../engine-overworld/wp12-terrain-movement-vehicles.md#r8-terminal-motion)）。**常规地图更新**在更新循环与标题切换/转场处理后——**消息窗显示中提前返回**（本次不生产也不消费请求）；解释器运行或强制移动中**不产生新输入请求**。其余按动作分派：**USE（确认动作）→ 互动请求**；**ACTION → 暂停菜单请求，但仅在未禁用菜单（菜单禁用标记为假）且玩家未移动时**（菜单禁用标记只门 ACTION，不门其它动作）；**SPECIAL → 快捷菜单请求，仅要求玩家未移动**（不经菜单禁用门）；F9 → 调试请求（调试标志）。**请求消费**（同在常规更新内）：玩家静止时按**暂停菜单 → 调试 → 快捷菜单 → 互动**的优先级依次消费一个请求。**微更新不含输入检测与请求分派**——已有快捷请求只经历微更新时**不被消费**（标记保留到常规更新且玩家静止）；阻止新输入的门不能无条件套给已有请求。菜单调用打开时：菜单中标记置真（地图层暂停事件更新等，WP13 引用）、玩家整姿、地图更新一次后打开暂停菜单；**无玩家对象时**（调试下提示「玩家训练家未定义」）直接返回、不开菜单。菜单结束后菜单中标记置假。

- **子屏幕与返回**：效果项打开的子屏幕（图鉴/队伍/背包/Pokégear/地图/训练家卡/选项/调试）**取消或正常返回后回到暂停菜单循环**（菜单重新显示/刷新）；**子屏幕产生特定结果**（选择隐藏招式、选择使用道具、选择飞行目的地）时效果项改为结束菜单并转交结果（见逐项）。

## 8. WP65-F：野外快捷菜单（ReadyMenu）

### 8.1 触发与候选构造

- **触发**：地图输入触发的快捷调用标记在**常规地图更新中被消费**（与 §6.1 同一合同：“静止”沿用没有普通移动／碰撞计时的定义，活动跳跃不额外阻止消费）：消息窗显示中本次更新提前返回（不消费）；玩家静止时按**暂停菜单 → 调试 → 快捷菜单 → 互动**的优先级依次消费一个请求——轮到快捷请求时清标记、玩家整姿后调用快捷菜单入口。**微更新不含输入检测与请求分派**——已有快捷请求只经历微更新时**不被消费**、标记保留到满足条件的常规更新（R01 修订）。
- **候选两类**：
  - **隐藏招式侧**：固定 16 个招式标识（CUT、DEFOG、DIG、DIVE、FLASH、FLY、HEADBUTT、ROCKCLIMB、ROCKSMASH、SECRETPOWER、STRENGTH、SURF、SWEETSCENT、TELEPORT、WATERFALL、WHIRLPOOL）——遍历队伍：**非蛋、已学会该招、且通过场地使用资格**（WP59 引用）的成员各贡献一条 `[招式, 队伍下标]`。
  - **登记道具侧**：背包登记列表（WP27 引用）中**当前仍持有**的道具逐条入选。**登记后不再持有的道具不出现**（候选资格 ≠ 执行成功）。
- **两类皆空 → 不开菜单**：仅提示「An item in the Bag can be registered to this key for instant use.」。否则：菜单中标记置真、地图更新一次后打开快捷菜单。

### 8.2 显示、导航与游标

- **显示**：两侧按钮列——招式侧靠左（带成员图标）、道具侧靠右（带道具图标与数量：**重要道具不显示数量**；数量 >99 显示「>99」，否则「xN」）；两列各按**名称字母序**排列；选中侧按钮高亮并外凸。
- **初始游标**：取背包持久字段快捷菜单游标（三元：招式侧下标、道具侧下标、当前侧别；**默认 [0, 0, 1]**，旧格式存档经迁移填充，WP10 引用）；**下标按当前列表长度夹限**（越界收到末项）；**当前侧别的列表为空时自动换到另一侧**。
- **导航**：LEFT/RIGHT 在两侧间切换（**仅当目标侧列表非空**）；BACK → 播放关闭菜单音、返回 −1（取消）；USE → 返回 `[侧别, 下标]`。**游标在菜单结束后保留在背包字段**（随存档持久，WP09/WP27 引用）。

### 8.3 确认、执行与返回

- **选择招式**：
  - **FLY 特例**：隐藏菜单打开区域地图的飞行选择画面——**确认目的地 → 记录目的地、菜单中标记置假、执行该成员的隐藏招式并关闭整个快捷菜单**；**取消 → 重新显示快捷菜单**（循环继续）。
  - **其它招式**：先确认使用该隐藏招式（WP59 引用）——**确认 → 菜单中标记置假、执行并关闭整个快捷菜单**；**拒绝 → 重新显示快捷菜单**。
- **选择道具**：隐藏菜单 → 触发该道具的「使用前确认」（WP28 引用）——**确认通过 → 菜单中标记置假并执行关键道具使用：使用包装返回真 → 关闭整个快捷菜单；包装返回假（无使用处理器，或使用处理器正常返回假）→ 菜单中标记复原、重新显示快捷菜单**；**确认被拒 → 直接重新显示快捷菜单**（菜单中标记未变）。**返回结果与是否消耗是两条独立事实**（R03 修订）：菜单的关闭/重显只按使用包装的布尔结果——**成功但不被消耗的关键道具（如 COINCASE：显示代币数后使用返回真、数量不变）同样关闭菜单**；消耗移除只在「使用返回真且为消耗品」时发生（WP28 引用），数量不变不等于执行失败。
- **结束**：快捷菜单场景关闭后菜单中标记置假（由调用处复位）。**候选资格与执行成功分开**：成员资格/持有只是入选条件，执行仍可按领域规则失败（WP59/WP28 引用），失败返回后菜单状态按上表分别处理。

### 8.4 游标持久性与设置边界

- 快捷菜单游标写入背包持久字段（默认 [0,0,1]），随存档保存（WP09 引用）、经旧格式迁移填充（WP10 引用）。**本稿不登记该字段的完整写入者目录**（只确认菜单自身读写与迁移点；其它写入者未穷尽，标注未决）。

## 3. α：战斗入口、命令导航与阶段切换

### 3.1 战斗创建与配置注入

- **场景创建**：场景创建入口新建场景对象；战斗对象以场景、双方队伍、双方训练家构造（任一方队伍为空则抛参数错误）。默认 1v1、可逃跑、不可免败、可换人、Switch 风格、显示动画、有经验/金钱、捕获送盒为「不询问」。

- **配置注入发生在场景显示之前**；战斗规则表是一次性消耗品（用后清除，WP12 引用），本稿只登记注入点与取值来源。

### 3.2 战斗开始与开场序列

- **开始链**：参与者校验（人数不足降席位，最低 1v1，无法降则抛错）→ 双方出战成员开战处理（WP39 引用）→ 场景开战（建视口与各窗口/精灵图，主命令/招式下标按位置数初始化为 0）→ **开场动画**（阻塞至完成）→ 开场消息与派出 → 天气/场地通告 → 入场特性链（WP39/WP40 引用）→ 回合主循环。
- **开场消息**：野生战按对方数「Oh! A wild {1} appeared!」（1/2/3 只各有一句，暂停消息）；训练家战「You are challenged by {1}!」（1/2/3 人各一句，暂停消息）。**派出消息按侧、对方先**：对方/同伴「{1} sent out {2}!」，玩家最后「Go! {1}!」（按派出数 1/2/3 只组句；brief 消息）；随后实际派出（§9.3）。
- **窗口互斥**：消息/命令/招式/目标四类窗口任一时刻只显示一类；命令/招式/目标窗口各自承载 §3.3/§4/§4.3 的输入。
- **开场动画分两种**：训练家战——两侧队伍排列动画异步启动后立即返回（排列动画与后续消息并行）；野生战——数据框出现＋野怪恢复正常色调与叫声**阻塞**至完成，随后闪光公共动画（仅动画开关为真且个体为闪光；`SUPER_SHINY` 配置下另有超级闪光变体）。
- **天气/场地通告**：天气/场地数据有动画名时先播公共动画，再显示对应消息（普通消息）；Shadow Sky 亦在此分支。

### 3.2.1 背景、消息条与两侧平台的资源选择

以已注入的背景身份B、可选平台身份T和时间值为输入；有效字符串、正常解析且无外部覆写为前提。time=1对应`eve`，2对应`night`，其它值不加时段后缀。下表为`Graphics/Battlebacks/`下的逻辑命名，文件解析沿WP15，不规定未来路径组织。

| 部件 | 有时段s时 | 无时段时 |
| --- | --- | --- |
| 背景 | 解析`B_s_bg`命中就用它，否则请求`B_bg` | 请求`B_bg` |
| 消息条 | 独立解析`B_s_message`，命中就用它，否则请求`B_message` | 请求`B_message` |
| 平台前缀 | 初始P为有T时`B_T`、无T时B；`P_s_base0`可解析则改P为`P_s`。此后P的base0仍不可解析且有T，才切至T，并在`T_s_base0`可解析时改为`T_s` | 初始P同左；P的base0不可解析且有T才改P为T |
| 平台两侧 | 最后分别请求`P_base0`和`P_base1` | 同左 |

组合基础`B_T_base0`已命中时，即使`T_night_base0`也存在，仍用组合基础前缀。base1不独立挑时段或回退；其缺失不重选base0。有T而组合全部未命中时没有额外的`B_base0`回退。独立T基础仍缺时也保留T命名请求。背景/消息可分别选时段与基础，平台则两侧共用由base0确定的前缀。

候选生成、扩展名解析与最终加载是三个阶段。全部候选缺失不等于全部入口同一种异常：普通非前缀动画包装对普通加载错误用空白位图，场景局部建图还捕获普通错误；前缀条带、直接缓存及其它更早异常沿WP15分入口合同。只据命名不能保证像素、透明度、全空结果或整段场景失败。

已有野生个体异常输入的开场边界见 WP39 §4.3.1：默认零可战斗野生输入在场景启动前的布局枚举先失败；正计数混合原序可建立配置范围之外的实际席位，精灵/数据框初始化、按配置人数的野生演出与按实际席位的命令遍历并不相同。正常资源/回调是后续请求可达前提，不据构造对象存在保证最终显示或行动。

### 3.3 主命令菜单

- **菜单构建**：每项动作 4 个命令，2×2 排布——Fight／Bag／Pokémon／第 4 项按条件：**暗影训练家战**（SHADOW 类型存在且为训练家战）→「Call」；否则**首行动**（本轮第一个可选位置）→「Run」；否则 →「Cancel」。**可见门按实际条件核对，不按注释推定**：逃跑只在首行动出现，但能否逃跑成功仍由领域判定（§3.4）。
- **返回值合同**：−1＝取消（回退上一位置）、0＝Fight、1＝Bag、2＝Pokémon、3＝Run、4＝Call（暗影战把 3 转为 4；非首行动把 3 转为 −1）；−2＝调试菜单（F9 且调试标志）。
- **游标**：初始下标取该位置的主命令记忆；确认时写回。方向键按 2×2 网格移动（左右 ±1、上下 ±2，到边即止），移动播光标音；确认播决定音；**BACK 仅在「取消模式」（mode 1，即非首行动）有效**——播取消音并返回 −1；首行动模式 BACK 无效（菜单不退出）。
- **模式表**（菜单显示模式）：0＝普通含 Run、1＝普通含 Cancel、2＝普通含 Call、3＝Safari、4＝捕虫大会；模式决定按钮图形与 BACK 语义（仅模式 1 可 BACK）。
- **命令提示**：「What will\n{1} do?」（{1}＝当前位置成员名）；暗影/特殊模式替换提示文本（§10）。

### 3.4 命令分派与回退

- **命令阶段总控**：阶段开始清消息窗；可显示命令的位置直接清本轮选择而不退款（包括此前执行资格失败已退款但仍残留物品身份者，§5.3.1；**不可显示的位置保留既有选择**——如多回合招式继续）；重置各侧 Mega 登记槽。先玩家循环、后 AI 循环；战斗决定非 0（战斗已结束）立即停止。
- **不可输入情形**：位置不存在/昏厥/使用多回合招式中（可显示命令查询为假）→ 跳过；控制玩家或非玩家所有 → AI 代选（WP40/WP52 引用）；**Sky Drop 状态**：除 Fight 外的主命令被拒（普通消息后重显菜单）。
- **Fight** → 招式流程（§4；返回 true 才离开命令循环，false 回主菜单重显）。**Bag** → 物品流程（§5；返回 true 离开，若所登记物品消耗全部行动——精灵球——则整个命令选择结束）。**Pokémon** → 队伍流程（§6；有效换人登记后离开）。**Run** → 逃跑流程（见下；**无论成败都结束本轮行动选择**：成功决定＝3、失败本位置行动耗尽——逃跑入口返回非 0 即命令选择结束；返回 0 表示根本未构成逃跑尝试，回主菜单）。**Call** → 登记呼唤（§4.2 注；返回 true 离开）。**−2 调试** → 打开调试菜单，关闭后刷新全部显示并做形态检查（WP13/WP20 引用），随后重回主菜单。
- **逃跑流程**：训练家战——内部战斗「No! There's no running from a Trainer battle!」（暂停消息）后返回 0；非内部战斗确认「Would you like to forfeit the match and quit now?」——同意 → 逃跑音＋「{1} forfeited the match!」＋决定＝3，拒绝 → 返回 0。规则禁止逃跑（canRun 假）→「You can't escape!」（暂停）返回 0。随后按序：幽灵属性（`MORE_TYPE_EFFECTS` 配置，默认世代 8 真）→ 必定逃脱；保证逃脱特性（显示特性提示条后）→ 必定逃脱；保证逃脱道具 → 必定逃脱；被束缚 →「You can't escape!」返回 0；对方束缚特性/道具 → 防止逃脱消息返回 0。通过则**逃跑计算**（WP41 引用：未提速比较，逃跑指令计数每次尝试＋1 且仅命令逃跑时递增）——成功 → 逃跑音＋「You got away safely!」（暂停）＋决定＝3；失败 →「You couldn't get away!」（暂停）返回 −1（行动耗尽）。调试下按 CTRL 选逃跑时先弹结局选择菜单（视为胜/负/平/逃跑/捕获/取消，调试）。
- **回退（−1）**：仅当本轮已有完成位置时可回退——弹出当前位置、回到上一位置并**撤销其选择**（若选择为使用物品则**物品退回背包**、Mega 登记撤销、选择清空）；回退后从该位置重新选。**选择物品后又回退＝登记时的扣减被撤回**（§5.3）。
- **行动耗尽**：逃跑（无论成败）、精灵球（消耗全部行动）、决定非 0 都会提前结束整个命令选择；其余完成位置逐一选完为止。

### 3.5 阶段次序与行动提交

- **攻击阶段固定次序**：优先级变动消息（特性/道具「先制」提示，WP40 引用）→ **呼唤**（按优先序）→ **换人**（含追击拦截——对方已选追击类招式且合法时先执行追击，WP41 引用；随后收回消息、Pursuit 检查、收回替换）→ **物品**（按优先序执行 §5.3 的四类使用）→ **Mega 进化**（已登记且选择招式的位置，按优先序）→ **招式**（先显示蓄力消息，再按「强制先动 → 常规优先级 → Quash」分组处理）。
- **回末阶段**（与本稿相关的观察点）：经验结算（§7）→ 形态检查 → **回合末替补**（§6.3）→ 自动远距移位 → 特性持续检查。自动移位承接 WP42 §5.4 的收集/执行合同，交换结果承接 WP41：按调整前分布先侧0、后侧1收齐候选，再执行；端点须存在、同属主，已有近邻对可停止后续收集而保留已收候选。计划多于一项时排除双席侧候选，不排除三席侧；第一项执行后不因新近邻关系撤销后项。只承诺实际到达该阶段的移动消息与最终位置，先前终局早退不承诺移动。此自动过程与手动 Shift 的行动代价分开。
- **终局与清理**：胜利——训练家战播胜利 BGM＋「You defeated {1}!」（暂停）＋逐个对手滑入显示败北台词（缺省为「...」）；野生战胜利 BGM（捕获结局且无捕获经验配置时也在此触发）。失败/平局——「You have no more Pokémon that can fight!」等暂停消息、输钱（规则与开关门）、不可免败时「You blacked out!」；设施败北显示对手胜利台词。**两条胜利路径都会置战斗结束标记：此后暂停消息不再自动关闭**（§9.1）。清理：场景战斗结束（关中断标志、空窗、BGM 1 秒淡出、全部精灵淡出并销毁）→ 按届时仍保留的物品消费身份撤销选择并尝试退款（包括从未执行及执行资格失败已退款者，§5.3.1；成功效果正常返回已清身份者不再退物）→ 特性退场触发 → 逐成员离场复位与初始道具恢复（WP39/WP42 引用）。
- **中止例外**：非交互战斗场景置可中止时，BACK 触发战斗中止异常——主开始链捕获后决定＝0 并走战斗结束清理（不弹消息）。

### 3.6 自动控制与调试替身边界

- 控制玩家为真时玩家侧所有位置由 AI 代选（菜单完全不出现）；调试战斗（战斗挑战生成）强制换人由 AI 默认值代选。回放战斗的命令阶段循环被覆写为按记录回放（§10）。
- **无视觉调试辅助入口**：没有玩家视觉/输入等待；确认恒 true、命令列表恒0、遗忘恒选第1招。主命令先以1/15选 Bag，未选 Bag 才以1/10选 Call（总体7/75），其余 Fight。**直接调用出招辅助，在标准战斗者具有非空招式列表、无插件补入缺失读取操作时，首候选读取即失败，早于随机抽样和调用者合法性校验；不会返回随机合法招式**。目标辅助只从对方存活位置采样，不按招式目标类别，空集返回−1；换人辅助从同队非在场位置抽取、交调用者验证，至多50次尝试，无候选则无返回。设施真实模拟设置玩家 AI 控制，主命令由 AI 默认指令选择，旁路该出招辅助；不能据局部辅助失败判断整个模拟成功或失败。这些直接入口结果不作为玩家 UI 或真实 Demo 证据（WP76 §7.2）。

## 12. 边界、失败与未知

已有野生对象的零可战斗计数与混合原序分别沿 WP39 §4.3.1；计数缺失不规范化为0，也不保证总能缩减到专用错误。布局异常可早于专门战斗中止捕获，前序记录/过渡写入及后续未到达善后分列；宿主远层恢复未知。

- **无目标投球的直接触达边界**：指定位置昏厥且无存活队友时，改取队友得到空对象、后续状态查询先失败——不会到达投掷消息与无目标提示；不承诺自动退球/回滚/进程退出（§8.1，R07）。
- **队伍为空侧**：构造时即抛参数错误（任一方队伍空）；可比较的成员不足路径逐次降席位，降至 0 抛错；缺失计数及原序边界不统一归此分支（WP39 §4.3.1）。
- **背包为空/过滤后无项**：列表为空，只能取消（§5.1）；**物品登记后背包已扣**——回退/无效/战斗结束三条退回路径（§5.3）。
- **无合格替补**：昏厥位置无合格成员时不触发替补（§6.3）；Arena 自动替补到队伍尽头为止（§10）。
- **共享详情初绘边界**：WP66-A现行合同中，零已知招式的普通MOVES页可画四空位，但进入详情、直接遗忘或事件选招会在BACK循环前访问空首招字段失败；非空合法详情才有取消返回。空重学候选另在首绘严格ID校验失败。战斗教学不足4招直接加入，不经这些失败入口；本稿满槽遗忘已满足有旧招前提。
- **遗忘画面反复取消**：取消 → 放弃确认 → 拒绝放弃 → 回遗忘画面，可无限循环（§7.2）；HM 不可遗忘（调试豁免）。
- **动画缺失**：动画数据库/招式映射/类型默认/Tackle 四级全部落空 → 静默无动画（§9.4）；公共动画名不存在 → 不播放。
- **消息与动画开关**：动画开关为假时消息、HP/经验条、派出/收回/倒下动画仍播放（§9.3）；暂停消息在战斗结束标记后不自动关闭（§9.1）。
- **回放降级**：回放中暂停消息转为普通消息（仍有显示与计时，非零等待——R05）；常规命令不打开菜单、自动招式的目标窗口为例外（§10，R10）；调试替身的固定/随机返回不是玩家行为（§3.6）。
- **未证的异常清理**：子画面异常退出（如事件中断）时的画面状态未逐项验证；真实事件可达性（各战斗入口的地图事件调用者）归 WP39/WP77；宿主输入物理映射未运行验证（U01）。

## 2. 转轮、停止与随机次序（S-B）

三轮各 22 个循环位置，实际有序内容见 [转轮附表](wp69-slot-reels.md)。顶部索引 i 对应中部 i−1、底部 i−2，按 22 循环。初次创建从左至右各均匀选择一次起始索引；之后每次开转从当前位置继续，不重新抽取完整结果。

正常速度 640 像素/秒；简单难度除以 1.5；困难不改变速度。时间按运行时长推进，符号边界判定依赖实际图像高度；槽位显示裁片高 48。资源缺失下不能声称实际转动帧率或每秒符号数已验证。

USE 请求停止当前仍旋转的最左轮；只有它真正停止后，下次 USE 才轮到右邻。处于等待停止而仍旋转时重复 USE 会再次抽样覆盖滑移量，不能描述为三次确认一定停完。每次请求先从 12 项滑移表抽一个值（0 六项、1 三项、2 两项、3 一项）；简单再抽一次取较小，困难再抽一次取较大。重玩仍消费这些样本，之后将滑移强制改 0。

| 单次停止请求滑移量 | 0 | 1 | 2 | 3 |
| --- | ---: | ---: | ---: | ---: |
| 默认／其它难度 | 6/12 | 3/12 | 2/12 | 1/12 |
| 简单（两次较小） | 108/144 | 27/144 | 8/144 | 1/144 |
| 困难（两次较大） | 36/144 | 45/144 | 40/144 | 23/144 |
| 重玩强制结果 | 1 | 0 | 0 | 0 |

停止在后续符号边界执行；若边界到来时滑移为 0 即停止，否则按本次跨过的边界数减少滑移，下一个边界再检。因输入时刻、更新间隔、资源高度和重复停止请求共同作用，不能把表中数值写成独立最终中奖概率或精确多转 N 格的无条件保证。

### 2.1 时间区间、顶部提交与停止顺序

以有效位图高H>0、开转前顶部i、恒定速度v、非负单调经过时间t及合法本局状态为前提。令q=floor(vt/H)。第一次正常更新必处理边界（此前视为区间−1），后续仅q不同于上次更新区间才处理；无新边界即使已有零滑停止请求也继续转。

| 边界到达时状态 | 本次操作 |
| --- | --- |
| 待停、滑移0 | 先停止，保留上次已提交顶部；不提交本次q算出的新顶部 |
| 待停、滑移s>0 | 按自上次更新跨过的区间数Δq减至max(s−Δq,0)，本次仍转；减成0后另一个新边界才停 |
| 本次仍旋转 | 提交顶部(i+1+q) mod22；中/底符号取其两个循环前驱 |

首次仍转且q0才为i+1；首次迟到q2为i+3。零滑冻结依赖最后已提交值及期间全部更新时间，不能只由停请求时刻给唯一终值。主循环先更新转轮，再处理本輪USE，重复USE只向仍转最左轮重抽。支付消费最终三符号，原概率/重玩/支付限制保持。

条件资源H48、i0、v640，各时间为开转后秒数，两序列独立且除所列时间无额外更新：A在.01更新为顶部1、仍转；随后请求零滑，.02仍q0，顶部1/待停；.20的q2先停，顶部仍1，图案[2,3,5]。B另重置，.01先到1，再直接给合法待停滑移2；.20跨2区间减滑至0而仍转、顶部3/[6,7,2]；.25到q3才停、仍顶部3。B的滑移2不是no-slipping返回结果。无停请求对照.01到1、.20到3且仍转；首次只在.20更新也到3，不默认先经过顶部1。这些是限定静态向量，真实媒体、像素、输入及支付执行另未证。

### 2.2 图像身份与当前语言

下列七个图像角色按 [WP08 §5.1.1](../generic-kernel/wp08-localization.md#511-指定-ui-图像身份的语言选择) 的 SCRIPT_TEXTS 哈希域选择身份：每次到达相应图像请求时，先查当前语言 game，再查当前语言 core；两层均缺译交原身份 A，非空命中 B 就交 B，即使 A 仍可用。同键 game 优先于 core；不因进入活动另选语言或写存档。

| 图像角色 | 查找时点 |
| --- | --- |
| 转轮符号图 | 初始化三个转轮时，各自查找 |
| 中奖提示 | 有奖额或重玩时，中奖表现循环中的每次请求 |
| 大奖提示 | 中奖表现循环中，大奖级别大于 0 时的每次请求 |
| 未中提示 | 无奖额且无重玩时，未中表现循环中的每次请求 |
| 投入提示 | 场景初始化，以及等待投入表现循环中的每次请求 |
| 停止提示 | 进入旋转处理分支时 |
| 按键提示 | 等待投入表现循环中，已有下注时的每次请求 |

背景、转轮遮罩、按钮、线、灯和数字图保持固定身份。所选转轮符号图的实际高度仍参与 §2.1 的时间分区，显示仍用既定符号裁片与 [22 位置附表](wp69-slot-reels.md)；替换图像须满足所需布局，不能推定任意尺寸 B 与 A 等价。

限定静态对照：有效当前语言已成功加载、正常准入及前序构造正常、A/B/C 均为普通非前缀且可加载的同高度同布局位图。两层缺转轮图键时，三个转轮各请求 A；仅 game 有 A→B 时各请求 B；game 缺键而 core 有 A→C 时各请求 C；两层都有时取 game 的 B。即使语言材料给背景另一个映射，背景仍请求其固定身份。观察点是交付图像入口的身份；这些向量未执行，不认证默认配置已启用语言、媒体实际存在或像素结果。

## 5. 支付时点、统计和参考异常（S-E）

每条线奖值求和写入待付额，计分控件只限制最大值为代币上限。支付逐次从待付减 1、给场景信用加 1；USE 可一次性转移剩余奖额；信用达到上限也会立即清掉剩余奖额，超额不保留。获奖提示／动画不代表已修改玩家持久余额。

支付节拍的名义值为每秒 20 枚，但参考「上次已支付时点」变量未被正确推进，正常非负运行时下每次支付循环更新都会通过节拍不等检查；实际是每更新最多 1 枚，或 USE／满额一次清算。本稿不将注释中的 20 枚/秒作为实测保证。

耗尽检查实际读取**玩家持久余额是否 0**，不是场景信用。正常以正余额进入且无外部改写时，把场景信用输到 0 后不会自动触发「Game over」；等待投入时既不能投入也不能无下注开转，但可 BACK 退出。若仍有重玩则可开转。场景信用满额检查与此不同，确实读取场景值。

会话正常离开时读取玩家旧余额，写入场景信用（经 WP24 夹限），再仅按此次净差增加 coins_won 或 coins_lost；不是每次中奖／下注分别累计。例如进入 100，途中输 3 又赢 8，最终 105，仅 coins_won＋5。若其它更新源在会话期间改全局余额，最终覆盖仍使用场景信用、净差比较使用离场时全局值；未提供隔离／合并保证。

## 6. 前置、失败与异常退出（S-F）

有盒且零代币不能由公开入口进入；余额上限不可继续。相关资源、玩家／背包／统计状态及输入时钟为正常前提。非法难度没有专门校验，除 0/2 外走默认分支。没有暂停保存本次下注／转轮的合同。

场景异常没有本地保证提交余额与统计的收尾：离场提交前错误会跳过尚未回写的场景账；余额写入与统计更新之间错误可能已写余额但未写统计。外层淡出清理不能代替财务回滚。媒介缺失、宿主时间／输入及外部状态变化保持未决。

### 6.1 图像选择、加载失败与已完成前缀

§2.2 的空译是有效命中，不回退 core 或 A。六种提示图的空身份会清除旧图，不进入动画位图加载；后续对图像的操作仍可能失败。转轮符号图直接消费空身份时，在文件名求值阶段失败，早于普通加载捕获，两条路径不能合并为空白成功。

非空译后身份仍交 [WP15 §5.1](../engine-overworld/wp15-resource-matching-and-audio.md#51-位图访问的分入口失败) 的原入口：普通非前缀身份的缓存加载若抛该包装捕获的普通错误，则尝试 32×32 空白；空白创建及后继操作仍可失败。帧前缀资源走独立加载和切帧校验，不具有同一捕获保证。均不重试原身份 A。

包装入口的三种拒绝均在图像初始化前；合法进入后的未下注 BACK 仍走 §5 的正常离场提交。初始化中，转轮的对象／状态建立及起始随机抽样先于符号图请求；后续图像失败不回滚已完成的对象、场景状态或随机消耗，也没有本地保证整体清理。中奖图请求前已经评估奖额／重玩、赋待付显示并可能请求音效；失败不撤销这些前缀。财务尾尚未到达时不因此提交玩家币额或统计，已到达的余额／统计前缀仍按本节原规则保留。
