## 1. 目的、范围与非目标

**目的**：描述地图事件（事件页选择、条件、触发方式、启动/等待/结束、公共事件、并行/自动运行）和 NPC/跟随（NPC 移动/互动、训练家感知、跟随者生命周期与转移限制）的行为规则，以及解释器命令的兼容范围——哪些命令有实现、哪些有差异、哪些是空操作、哪些未处理。后续包据此判断"某事件何时启动、命令会产生什么效果、跟随者如何行动"，而不是各自重新追踪事件系统。

**范围**（WP13 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP13-A：事件页与触发（页选择、条件、触发方式、启动/结束）。
2. WP13-B：解释器运行（更新循环、等待/恢复、公共事件、并行/自动运行、深度限制）。
3. WP13-C：解释器命令兼容矩阵（见附表 [wp13-interpreter-command-matrix](wp13-interpreter-command-matrix.md)）与移动路线命令矩阵（见附表 [wp13-move-route-matrix](wp13-move-route-matrix.md)）。
4. WP13-D：NPC、训练家感知与跟随（NPC 移动/互动、感知、跟随者生命周期与转移限制）。
5. F04-04、F04-05 中属于 WP13 部分的状态更新。

**非目标**：

- 不复制具体 Demo 事件的收费、奖励、剧情结果（缺失材料，U01/U08）。
- 不把方法存在当实现、把 return 值当业务成功、把搜索未中当不存在；不执行脚本命令、不移植 Ruby 解释器。
- 不承诺标准 RMXP 命令全兼容（以附表的实际分派/实现为准）。
- 不提取战斗内事件/命令的行为（归战斗包）。
- 不运行游戏或任何参考脚本；不修改 `reference/`。

## 2. 概念与术语

- **事件页（page）**：事件的一组条件与内容；按从后向前顺序选择第一个条件全部满足的页。
- **触发方式（trigger）**：事件启动条件（0=动作键、1=玩家接触、2=事件接触、3=自动运行、4=并行处理）。
- **启动（starting）**：事件被标记为待运行；由触发检查或自动运行触发。
- **公共事件（common event）**：全局事件，trigger 1=自动运行（主解释器执行）、trigger 2=并行处理（自有解释器）。
- **解释器（interpreter）**：逐条执行事件命令的循环；支持等待（消息/移动/计时）、子解释器（公共事件调用）与深度限制（100）。
- **命令兼容**：命令在分派中的状态（有实现/空操作（command_dummy）/标记/未分派回退）。
- **over_trigger?**：事件的"可越格触发"判定——**不是 through 的别名**：具名图形且非 through → false；名称含 hiddenitem → false；否则按占格是否可通行判定（无图形、非 through 的事件也可能为真）。
- **跟随者（follower）**：由 FollowerData 描述、以 Game_Follower 实例随行的事件角色；部分场地/道具入口禁止带跟随者（6.2）。
- 影响域编号 Dxx 见 module-map；证据状态五档定义见总览第 7 节。

## 3. WP13-A：事件页与触发

### 3.1 事件页选择（`004_Game classes/007_Game_Event.rb:197–258`，本轮逐行阅读）

- 页按**从后向前**遍历：第一个条件全部满足的页成为当前页——开关 1/2 为 ON、变量 ≥ 指定值、自开关为 ON（`switchIsOn?` 支持开关名为 `s:` 前缀的脚本条件）。
- 无满足页（new_page 为 nil）：事件不可见、可穿透、无触发与命令列表。
- 页内容决定图形/移动类型/速度/频率/路线/方向/穿透/触发/命令列表；触发为 4（并行处理）时创建自有解释器。
- 自开关与临时自开关（`tsOn?/tsOff?/setTempSwitchOn/Off`）影响页与冷却判定（`cooledDown?/cooledDownDays?`：过期且临时自开关 A 为 OFF 时通过，否则标记刷新）。临时自开关随事件实例重建丢失；页条件自开关在全局表（WP11 引用）。

### 3.2 触发与启动（本轮逐行阅读；WP13-R04 修订：按调用者分入口）

| 入口 | 调用者与守卫 | 行为 |
| --- | --- | --- |
| 动作键（trigger 0） | 玩家按互动键；主解释器未运行 | 同位检查（`check_event_trigger_here`：事件在同位、非跳跃、**over_trigger? 为真**才启动）与面前检查（`check_event_trigger_there`：事件在面前格、非跳跃、**over_trigger? 为假**才启动；面前格为柜台时再延伸一格）（`008_Game_Player.rb:332–389`） |
| 玩家接触（trigger 1） | 两条玩家路径：(a) **玩家移动失败**时 `move_generic` 调**玩家侧** `check_event_trigger_touch(dir)`（`008_Game_Player.rb:172, 389–409`）：候选 trigger [1,2]、事件在移动目标格、非跳跃、over_trigger? 为假；sight/trainer 事件另做可达检查、counter 事件另做面向范围检查；(b) **玩家步完成**时 `update_event_triggering` 调同位 `check_event_trigger_here([1,2])`（同文件 332–344, 543–552：移动/跳跃/强制移动中不检查）：事件须同位、非跳跃、**over_trigger? 为真** | 满足则启动 |
| 事件接触（trigger 2） | 两条路径：(a) **NPC 自身移动失败**时经 `006_Game_Character.rb:553–564` 调**事件侧** `check_event_trigger_touch`（`007_Game_Event.rb:142–157`：**trigger == 2**、主解释器未运行、按方向的坐标对齐、非跳跃、over_trigger? 为假）；(b) 事件自身更新时 `check_event_trigger_auto`（同文件 186–195：与玩家同位、非跳跃、**over_trigger? 为真**） | 满足则启动 |
| 感知（名称模式，trigger 2 前提） | NPC **转向后**（`check_event_trigger_after_turning`）与**移动完成后**（`check_event_trigger_after_moving`）两入口（同文件 160–183） | 共同守卫：主解释器未运行、非 starting、**trigger == 2**、非跳跃、over_trigger? 为假。名含 `sight(N)`/`trainer(N)` → **可达检查**（`pbEventCanReachPlayer?`：面向范围内且沿途每格可移动，`001_Overworld.rb:340–389`，两入口都有）；名含 `counter(N)` → **面向范围检查**（`pbEventFacesPlayer?`，只看朝向与距离），**仅存在于移动完成后的入口**——仅转向不触发 counter |
| 自动运行（trigger 3） | `check_event_trigger_auto` | 每更新机会即启动 |
| 并行处理（trigger 4） | 页选择时创建自有解释器（`refresh`），`update` 驱动 | 每更新机会由自有解释器执行 |

**更新机会前提**（WP13-R04 修订）："每帧执行"以实际更新调用为前提——`should_update?`（同文件 260–271）对**自动/并行、强制路线、moveto 发生、名称含 update** 的事件提前许可，其余按屏幕范围（约 2 格缓冲）判定；菜单打开时 `Game_Map.update`（`004_Game_Map.rb:461–465`）**不更新地图事件但仍更新公共事件**。因此"屏幕外事件不更新"不成立（并行/自动等例外），"菜单中一切暂停"也不成立（公共事件仍更新）。

启动后：非自动/非并行事件被锁定并清除启动标记；自动运行公共事件（trigger 1 + 开关 ON）由主解释器启动（`setup_starting_event`，`003_Interpreter.rb:54–78`）。

## 4. WP13-B：解释器运行

### 4.1 更新循环与等待/恢复（`003_Interpreter.rb:84–136`，本轮逐行阅读）

| 阶段 | 行为 |
| --- | --- |
| 冻结防护 | 每 100 次循环刷新画面一次 |
| 地图失联 | 当前图与解释器地图不同且无连接 → **仅把 event_id 置 0**（WP13-R03 修订：不清命令列表、index 或子解释器；执行循环按等待/执行继续推进）。失联只失去"本事件"上下文，不等于结束执行 |
| 子解释器 | 先更新子解释器（公共事件调用），结束才回到父解释器 |
| 消息等待 | 消息显示中不执行命令 |
| 移动等待 | **仅当该解释器已置路线等待标记（由 210 设置）时**，才检查玩家、当前地图事件及跟随者的强制路线：任一处于强制移动路线则不执行命令；全部结束后清除等待。209 只设强制路线、**不设置该等待标记**——未执行 210 时，进行中的路线不阻塞本解释器 |
| 上岸等待 | 玩家上岸流程中（ending_surf）不执行命令 |
| 计时等待 | wait_count 计时（System.uptime）未到不执行命令 |
| 菜单调用 | 暂停菜单将打开时不执行命令 |
| 无命令时 | 主解释器尝试启动下一个待启动事件（公共事件 → 地图事件 → 自动运行公共事件） |
| 深度限制 | 公共事件调用深度 > 100 时提示并退出 |
| 指令推进 | 命令返回 false → 本轮停止；返回 true → @index += 1。注意 105 在命令体内已 @index += 1 且返回 true（一次推进两条）；命令的启动效果与等待不能混谈（附表控制结果列） |

### 4.2 结束与恢复（WP13-R03 修订：三种终止状态分列）

- **命令结束**：命令列表执行完（index 到末尾）→ `command_end`（`004_Interpreter_Commands.rb:128–135`）：**清除命令列表**、结束跟随者覆盖；主解释器且事件 ID 有效时解锁该事件。
- **显式退出**：115（退出事件处理）→ 同样进入 command_end。
- **地图失联**：仅 event_id 归 0（4.1），**已有命令列表继续有效**——失联后合法的全局命令（如开关赋值）仍可执行；事件的解锁/锁定上下文已失去。
- 脚本命令异常：`execute_script` 的异常按类别处理（SystemExit/Reset 原样抛出，其他进入事件错误处理路径，`003_Interpreter.rb:138–146` 及后续；WP07 引用）。
- 公共事件并行处理按开关状态刷新（`Game_CommonEvent.refresh`，`009_Game_CommonEvent.rb:40–47`）。

- **空操作 28 个**：126（增减物品）、127、128、129、133（战斗结束 ME）、301（战斗处理）、302（商店）、311、312、313、315、316、317、318、319、320、321、322、331–340。事件作者调用这些命令**无可见效果**（含 126 不改变背包、301 不启动战斗、311 不改变 HP）。
- **标记 2 个**：112（循环开始）、118（标签）。
- **续行不是无效数据**：401 由 101 消费、655 及相邻 355 由 355 合并；"未单独分派"仅限直接到达默认分支的代码。

- **未分派回退**：不在分派表中的任意命令代码 → 返回 true（跳过并继续，无效果）；不承诺标准 RMXP 命令全兼容（以附表为准）。

## 6. WP13-D：NPC、训练家感知与跟随

### 6.1 NPC 移动与互动

- NPC（事件角色）按页的移动类型/速度/频率/路线移动（`007_Game_Event.rb` 的移动与更新规则，同文件 274–301 行）；更新机会按 3.2 的 `should_update?` 规则（非"屏幕外一律不更新"）。
- 训练家感知：按 3.2 感知入口（trigger 2 前提、可达/面向两种检查、跳跃与 over_trigger 守卫）；不是"进入视野即启动"。
- 训练家事件由战斗入口调用（`001_Overworld_BattleStarting.rb`，WP39 交界）；战斗后 NPC 的状态（再启动/再战）归 WP63/WP24。

### 6.2 跟随者生命周期与转移限制（WP13-R05 修订：当前事件跟随机制的行为范围）

- **加入**：`FollowerFactory.add_follower(event, name, common_event_id)`（`011_Game_FollowerFactory.rb:89–103`）——**去重守卫**：同一原始图 + 事件 ID 已存在则直接返回；否则登记 FollowerData（原始地图/事件/名称、当前地图/坐标/朝向、外观克隆；名称与可选公共事件覆盖）。
- **移除**：`remove_follower_by_event`（当前图匹配 + 原始图/事件匹配）、`remove_follower_by_name`、`remove_all_followers`（同文件 106–136）。
- **实例化**：Game_Follower 按 FollowerData 创建（`010_Game_Follower.rb:1–40`）；可穿透跟随（`move_through` 临时穿透）。
- **移动/更新**：玩家移动后跟随者依次移动（`move_followers`，工厂 165–189）：**领队链为玩家 → 前一跟随者**；每个跟随者 `follow_leader`（`010_Game_Follower.rb:134–167`）——**强制路线中跳过跟随**；相连地图时目标为领队身后格（岩架时取跳上来的一格）；不相连地图时目标为领队位置；跨图时按相对坐标向量换图定位；`instant` 或不相连时即时 moveto，否则按 `fancy_moveto` 的**条件位移**（同文件 48–110）：
  - **同轴相差一格** → 走一步（目标为玩家位置、或目标按进入方向许可、或当前位置不可通行时穿透走）。
  - **同轴相差两格** → 按中间/落点/起点许可决策：中间格许可 → 走两步（不启动跳跃）；中间格不许、落点许可、起点许可 → 尝试两格跳跃；中间格不许、落点许可、起点不许 → 穿透走两步；中间与落点均不许 → 不前进。中间格许可而第二步受阻时，不能保证两次行走尝试到达目标。
  - **其他非重合目标** → 直接定位（moveto）：未命中同轴一格/两格分支时，只要目标与当前位置不同即直接定位——**既包括非同轴目标（即使只相差 (1,1)），也包括同轴相距三格及以上**；同轴超过两格不是逐格追赶或停留。
  - 位置判定按 WP12 层 5 的跟随者实际入口（方向位/地形/具名图形事件；引用，不另写第二套通行规则）。
  移动后把坐标/地图/朝向写回 FollowerData 持久层。转向（`turn_followers`）、逐帧更新（`followers.update`：同步领队速度、按 visible? 设透明、冰滑时整姿停动画；玩家移动中且跟随者未动时设置/清除启动标记驱动其更新）。
- **显式传送**：`map_transfer_followers`（工厂 242–257 区间）：跟随者放到玩家位置、朝向一致、opacity 255、写回持久层并设 `invisible_after_transfer`；玩家开始移动时清该标记并转向玩家（同文件 update）；`visible?` = 可见标记且非转移后隐藏。
- **互动**：USE 键且非菜单/战斗/强制路线/消息/解释器时，面前格上的跟随者（非跳跃）触发 `FollowerData#interact`（38–44：需事件有命令列表且登记了公共事件 ID → 刷新、锁定并以该事件列表启动主解释器）。
- **转移限制**：`can_map_transfer_with_follower?` 与 `can_ride_vehicle_with_follower?` 仅在跟随者数为 0 时为真（`008_Game_Player.rb:42–48`）——**但守卫只在调用它们的场地/道具入口生效**（`004_Overworld_FieldMoves.rb`、`013_Items` 等调用点）；普通显式 `Scene_Map.transfer_player` **没有此守卫**，反而会调用 `map_transfer_followers` 携带跟随者。不能由函数名推出"有跟随者就无法地图传送"。
- **持久化**：跟随者数据在 `$PokemonGlobal.followers` 中持久保存（WP09 登记）；`dependentEvents` 为弃用旧格式（WP10 转换）。
- 跟随机制是事件级跟随（事件角色随行），**不自动等同于完整"跟随宝可梦"系统**（其完整规则归后续适用包；不得无证扩张，但本节机制是当前可读源码的直接提取）。

## 7. 默认行为与配置变体

- **基线默认**：事件页按从后向前选择；触发按 3.2 分入口启动；解释器按 4.1 更新循环执行；命令按第 5 节兼容矩阵；跟随者按 6.2 生命周期与限制。
- **支持但未默认启用**：开关名为 `s:` 前缀的脚本条件开关；调试穿透（$DEBUG+Ctrl，WP12 引用）；`SKIP_CONTINUE_SCREEN`（WP02 词典）。
- **配置/数据关联**：`GRASS_ANIMATION_ID` 等动画 ID（WP02 词典）；`SHINY_WILD_POKEMON_SWITCH`、`FATEFUL_ENCOUNTER_SWITCH` 等开关（WP02 词典）；公共事件与开关/变量的配置（作者内容）。

## 8. 边界、失败与未知

- 无满足页：事件不可见/可穿透/无触发（3.1）。
- 解释器失联：地图不同且无连接 → event_id 归 0，**命令列表继续**（4.1/4.2）。
- 深度超限：公共事件调用 > 100 层 → 提示并退出（4.1）。
- 脚本异常：SystemExit/Reset 原样抛出；其他异常按事件错误处理（4.2）。
- 空操作命令：28 个 command_dummy 命令被跳过且无效果（第 5 节）；调用方（事件作者）若依赖这些命令将无可见效果——兼容性限制如实登记。
- 缺失地图/事件材料：具体 NPC 对话、事件页、任务流程、商店库存、奖励和可达性无法确认（U01/U08）。
