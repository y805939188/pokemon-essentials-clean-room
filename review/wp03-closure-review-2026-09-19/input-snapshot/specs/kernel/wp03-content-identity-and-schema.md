## 1. 目的、范围与非目标

**目的**：建立跨域统一的内容引用概念——各类内容（物种、招式、道具、地图等）以什么身份被注册、查找、枚举和引用；未知或重复身份如何处理；固定规则与作者数据如何区分；每类内容的字段组由哪个后续工作包负责。后续领域包引用本文的概念，不再各自发明"内容如何标识"的解释。

**范围**（WP03 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP03-A：内容身份模型（默认规则与按类的例外、查找语义、完整类清单）。
2. WP03-B：注册、查找与缺失值处理（加载、默认值、缺失文件、查询副作用）。
3. WP03-C：schema 与作者内容校验（字段约束结构、编译期错误）。
4. WP03-D：固定规则与作者数据的区分。
5. WP03-E：字段责任目录（字段组 → 主要负责包 → 必要引用）。
6. F01-02、F02-01 中属于 WP03 部分的状态更新。

**非目标**：

- 不提取各类内容的字段语义全集（归 WP03-E 指派的领域包，如物种字段归 WP18–WP21）。
- 不展开完整编译生命周期、写回与失败分支（WP04）；不描述编辑器行为（WP73）。
- 不设计未来框架的 ID 类型、注册 API 或类层级（F01-02 明确"不预设未来 ID 类型"）。
- 不提取资源文件命名与回退规则（物种图像/声音归 WP15）。
- 不修改 `reference/`，不运行游戏或编译器。

## 2. 概念与术语

- **内容身份**：一个内容条目在注册表中的唯一键。默认形式有三类：符号身份、整数身份、符号+整数双身份；若按类覆写，则存在复合身份（见第 3.2 节）。
- **复合身份**：由多个要素合成的身份，如（训练家类型, 姓名, 版本）三元组、（地图, 版本）、（物种, 形态）。
- **注册表**：每类内容一个内存数据表，启动时从编译产物载入；提供存在性检查、查找、枚举。
- **schema**：作者数据类声明的字段约束——PBS 属性名到字段、类型模式与枚举引用的映射（部分类走专用解析，无自身 schema，见第 5.1 节）。
- **固定规则数据（hardcoded）**：在脚本中直接注册、不经 PBS 编译的内容（成长曲线、进化方式、能力值、地形等），可作作者内容的枚举引用源。
- **作者数据（PBS data）**：由作者在文本中定义、经编译产物载入的内容；其中 Type、Move、Item 等**也是**常用的枚举引用源——"是引用源"与"是固定规则"是两个不同维度。
- **必选/可选数据文件**：缺失时是否触发调试模式下的重编译判定（可选仅一例）。
- 影响域编号 Dxx 见 module-map；证据状态五档定义见总览第 7 节。

## 3. WP03-A：内容身份模型

### 3.1 默认规则：三类身份与查找语义（有明确适用范围）

多数内容类共用同一注册表模式（`S/010_Data/001_GameData.rb`），按身份形式分三类。**以下只是未被覆写时的默认契约，不能据此推出每个数据类都如此**（例外见 3.2）：

| 身份类 | 键形式 | 接受的查找输入 | 未知身份行为 | 枚举顺序 |
| --- | --- | --- | --- | --- |
| 符号身份 | 符号 | 符号 / 条目实例 / 字符串（转符号后匹配） | `get` 抛出"Unknown ID"异常；`try_get` 返回 nil；`exists?` 返回 false（nil 输入亦为 false） | 定义顺序；另有按原始名称字段（非翻译后显示名）字母序的枚举 |
| 整数身份 | 整数 | 条目实例 / 整数 | 同上（字符串/符号不可用于查找） | 数值顺序 |
| 双身份（符号+整数） | 同一条目同时以符号和整数为键 | 符号 / 条目实例 / 字符串 / 整数 | 同上 | 按整数序号顺序 |

默认契约的补充限定（本轮核实）：

- 容错仅覆盖 **nil 与类型合法的未知身份**；错误输入类型（如对道具宽容查询传入整数）触发参数验证错误（`S/001_Technical/001_Debugging/004_Validation.rb:12–29`），不是返回 nil/false。
- `get`/`try_get` 对同类实例直接返回该实例，**不能据此推出该实例已登记**。
- 双身份"两键一条目"以注册时无键冲突为前提；冲突边界未逐类验证。
- 相等判定：与符号/字符串按符号身份比较，与整数按整数序号比较，与同类实例按身份比较。
- 反向读取 `get_property_for_PBS` 按 schema 取字段值，false 与空数组归一化为 nil。

### 3.2 按类例外（WP03-R01 修订：默认方法被覆写的实际契约）

| 类/操作 | 实际契约（本轮逐处源码核实） |
| --- | --- |
| Trainer | 身份为（训练家类型, 姓名, 版本）三元组，版本默认 0；`exists?/get/try_get` 均接受该三元参数；`get` 对未知组合抛出"Unknown trainer"。队伍成员另有子字段约束（sub_schema）。`015_Trainer.rb:56–84` |

| Metadata | 无参 `get` 直接返回全局 0 号记录。`016_Metadata.rb:55–57` |
| PlayerMetadata | `get(player_id)` 先按编号查找，**未知编号回退 1 号记录**（默认编号也为 1）。`017_PlayerMetadata.rb:45–49` |
| TerrainTag | `try_get` 对 nil 输入与未知键均**回退 None 地形**。`011_TerrainTag.rb:31–36` |
| DungeonTileset | `try_get` 对未知键**回退首条图块配置**。`019_DungeonTileset.rb:38–42` |
| DungeonParameters | `try_get(area, version)` 先按（区域, 版本）合成符号、回退基础区域；仍缺时**新建默认参数实例返回（不登记）**。`020_DungeonParameters.rb:58–65` |
| SpeciesMetrics | `get_species_form` 对缺失指标可能**创建并登记**记录：基础指标缺失先登记基础默认，形态指标缺失再以基础值克隆登记。**查询有副作用**；物种本身未定义则抛错。`010_SpeciesMetrics.rb:32–56` |
| Species（形态） | `get_species_form` 以"物种_形态号"合成符号查找，形态缺失回退基础物种符号，仍缺返回 nil；nil 输入直接返回 nil。`008_Species.rb:154–163` |

### 3.3 完整内容类清单（本轮逐一核对声明，WP03-C01 口径）

**作者数据类（PBS 编译，含 DATA_FILENAME，共 19 个唯一类）**：符号身份 14 类——Type、Ability、Move、Item、BerryPlant、Species、SpeciesMetrics、ShadowPokemon、Ribbon、Encounter、TrainerType、Trainer、DungeonParameters、PhoneMessage；整数身份 5 类——TownMap、Metadata、PlayerMetadata、MapMetadata、DungeonTileset。`002_PBS data/` 共 21 个 Ruby 文件，其中 `001_MiscPBSData.rb`（非类产物加载）与 `009_Species_files.rb`（Species 资源解析扩展）不新增数据类。

**固定规则数据类（脚本内注册，无 DATA_FILENAME，load/save 为空操作，共 17 类）**：符号身份 15 类——GrowthRate、GenderRatio、EggGroup、BodyShape、BodyColor、Habitat、Evolution、Stat、Nature、Status、EncounterType、Environment、BattleWeather、BattleTerrain、Target；双身份 2 类——TerrainTag、Weather。

**合计 36 个唯一 GameData 类。** PBS 基名：18 个声明类（PlayerMetadata 无基名，由 metadata.txt 玩家节编译），经 Species 双基名（pokemon + pokemon_forms）展开为 19 项，再合并 3 个非类基名（battle_facility_lists、map_connections、regional_dexes），共 22 个基名。

**非 GameData 注册表的编译产物与资源**（`001_MiscPBSData.rb:27–63`）：regional_dexes（.dat）、map_connections（.dat）、trainer_lists（.dat）、战斗动画（PkmnAnimations.rxdata，存在性检查后加载）、move2anim（.dat，宿主读取返回 nil/false 时回退空表；文件缺失或宿主读取失败的行为未验证）、MapInfos（.rxdata）。它们的来源与加载方式各不相同，**不能统称为 PBS 作者数据编译产物**（WP03-R04 修订）。

**来源标记**：PBS 来源条目携带 `pbs_file_suffix`（其来源文件相对基名的后缀）；该标记只适用于 PBS 编译条目，固定规则条目与查询时新建的默认记录不追溯到输入文件（WP03-C01 修订）。

## 4. WP03-B：注册、查找与缺失值处理

### 4.1 注册与加载

- 注册：条目按身份键写入本类数据表（双身份同时写两个键）。固定规则类在脚本加载时逐条注册（如 GrowthRate 的 6 条注册调用）。
- 加载：启动时统一从 `Data/*.dat` 载入全部作者数据（`GameData.load_all`，仅处理声明 DATA_FILENAME 的类）；加载本身是宿主提供的序列化读取，失败行为未验证。
- 启动顺序（本轮核实 `999_Main/999_Main.rb:25–41`）：核心消息 → 插件 → **编译检查** → 游戏初始化 → 标题场景。编译检查仅在调试模式执行（见 4.2）。

### 4.2 缺失数据文件（WP03-R04 修订：补上触发前提）

| 情形 | 行为 | 前提与证据 |
| --- | --- | --- |
| 必选数据文件缺失 | **仅在调试模式**的编译检查中判定必须重编译；非调试模式该检查直接返回，不存在普通运行自动修复 | `001_Compiler.rb:1039–1040`（`return if !$DEBUG`）、1051–1075 行；必选清单含 GameData 各类与 map_connections、regional_dexes、trainer_lists 三个非类文件（仅此三个） |
| 可选数据文件缺失（仅 ShadowPokemon，`OPTIONAL = true`） | 该条件本身不触发重编译判定；加载时先检查文件存在，不存在则**本次不读取** | `011_ShadowPokemon.rb:14、28–30`；`001_Compiler.rb:1063–1075` |
| 可选类的 PBS 输入全部缺失 | 通用编译在清空数据表**之前**直接返回 | `002_Compiler_CompilePBS.rb:4–8` |

重要限定（WP03-R04）：可选缺席**不等于**"数据为空"——缺失加载分支只跳过读取，**不会清空已有表**；"数据为空"只在"初始为空表且无其他登记"的前提下成立。可选数据缺席后 Shadow 消费者的行为未逐点核实（U06，归 WP23）。

### 4.3 字段缺失值（默认值）

条目构造时对缺失字段赋类级默认值，例如：物种未命名显示名 → "Unnamed"、类型 → [:NORMAL]、捕获率 → 255、亲密度 → 70；道具卖价 → 买价的一半、BP 价 → 1；招式类型 → :NONE、命中 → 100、PP → 5；地图元数据标志 → 空表。默认值是**当前快照的类级声明**，不是 Pokémon 通用规则；完整字段语义归领域包。

### 4.4 查询副作用（WP03-R01 增补）

SpeciesMetrics 的指标查询可能创建并登记新记录（见 3.2），因此"查询后注册表内容"与"查询前"可能不同；DungeonParameters 的缺失查询返回未登记的默认实例，不改变注册表。设计测试时不能把查询都当作只读。

## 5. WP03-C：schema 与作者内容校验

### 5.1 schema 结构（WP03-R03 修订）

作者数据类的字段约束为 PBS 属性名 → [目标字段, 类型模式, 枚举引用]。多数类为常量表；Species 为方法（基础物种与形态属性集不同）；**并非每个作者类都有自身 schema**：Encounter 走专用逐行解析（`002_Compiler_CompilePBS.rb:658–767`），Trainer 除主 schema 外还有队伍成员子约束（sub_schema）。

观察到的类型模式（本轮核对 `001_Compiler.rb:384–435` 的求值行为；解析细节归 WP04）：

| 模式 | 含义（行为层） |
| --- | --- |
| `m` | 符号值，名称字符约束（字母/数字/下划线、不以数字开头）；用于节名，也用于 Type 的相克引用（`003_Type.rb:18–27`，Weaknesses/Resistances/Immunities 为 `*m`） |
| `s` / `q` | 文本 / 非格式化文本（如图鉴描述） |
| `i` | 有符号整数 |
| `u` | 非负整数（允许 0） |
| `v` | **严格大于 0** 的整数（显式拒绝 0） |
| `x` / `f` / `b` / `n` | 十六进制 / 浮点 / 布尔 / 名称（同 m 的字符约束） |
| `e` | 单个枚举值：引用固定规则类或作者数据类（如 :Type、:Move、:Item、:Weather），或内联枚举表（道具 FieldUse 名值映射、招式 Category 字符串数组） |
| `y` | 枚举或整数 |
| `*` 前缀 | 列表（如 `*e`、`*s`、`*m`） |
| `^` | 可重复属性（同一属性多行累加，如 Evolution） |
| 复合 | 固定长度元组（如 `vvvvvv` 六项能力、`vuu` 坐标） |

### 5.2 编译期身份与引用校验（WP03-R02/R03 修订：按入口分别表述）

**重复处理按入口分开，不能统一成一种失败规则**：

| 入口 | 重复身份行为 | 证据 |
| --- | --- | --- |
| 直接注册（`register`，含固定规则注册与专用编译的注册调用） | **不检查已存在身份**：同键后项替换前项 | `001_GameData.rb:13–15, 83–85, 158–160` |
| 通用 PBS 编译（`compile_PBS_file_generic`） | 注册前检查：**重复节名报"Section name 'X' is used twice."** 并报告位置 | `002_Compiler_CompilePBS.rb:54–60` |
| 训练家专用编译（`compile_trainers`） | 每节完成即直接注册，校验与终检无同身份拒绝：**两个合法同身份训练家节由后项覆盖** | `002_Compiler_CompilePBS.rb:791–861, 864–869` |
| 训练家队伍成员招式 | 重复招式**静默去重**（非错误检查） | 同文件 885–886 行 |
| 地区图鉴物种 | 重复物种**拒绝**："Dex list number {1} has species {2} listed twice." | 同文件 618–625 行 |
| 遭遇条目（槽） | 同一遭遇方式中**物种与等级范围相同**的槽**合并并累加权重**（权重求和），随后按权重降序排列；不是简单去重 | 同文件 695–708、743–757 行 |
| 遭遇节身份 | 同（地图, 版本）节重复定义**拒绝**："Encounters for map 'X' are defined twice."——与槽合并不是同一层级 | 同文件 712–716 行 |

**引用校验**：

| 校验 | 行为与真实入口 | 证据 |
| --- | --- | --- |
| 未定义枚举值（如道具 Move 引用未定义招式） | 通用枚举求值路径拒绝："Undefined value {1} in {2}." 并报告位置。错误入口是 `get_csv_record` → `cast_csv_value` → `checkEnumField`，**不是**特定类型的专用报错函数 | `001_Compiler.rb:438–459`；`006_Item.rb:42` |
| 必需参数缺失 | 编译错误（如进化方式需要参数而未给） | `002_Compiler_CompilePBS.rb:313–319` |
| 校验时机 | 条目级校验（编译该节时）+ 全量终检（全部读入后） | 同文件 283–286、859 行附近 |

**已撤回的说法**（WP03-R03）："枚举在写入 PBS 时可自动补写新常量"缺乏证据——写回路径 `pbWriteCsvRecord` 是值到文本的转换，对枚举只查找已有名称或返回值/错误（`001_Compiler.rb:742–842`；`019_Utilities/001_Utilities.rb:137–153`），不创建新常量。

## 6. WP03-D：固定规则与作者数据的区分

| 维度 | 固定规则数据 | 作者数据 |
| --- | --- | --- |
| 定义位置 | 脚本内注册（17 类） | PBS 文本编译（19 类）+ 非类产物与独立资源（见 3.3） |
| 加载 | 无 .dat；load/save 为空操作 | 从 `Data/*.dat` 载入 |
| 角色 | 作者内容的枚举引用源与规则参数（成长曲线、进化方式、能力值、地形、天气、目标、环境等） | 游戏实际内容（物种、招式、道具、地图、训练家等） |
| 可否含行为 | **可以**（如 GrowthRate 的经验公式、Evolution 的方式判定），不只是枚举 | 字段语义按类归领域包 |
| 修改方式 | 改脚本（开发者） | 改 PBS（作者/编辑器） |

维度澄清（WP03-R03）：Type、Move、Item 是**作者数据**（含 DATA_FILENAME、经 PBS 编译），同时也充当其他内容的枚举引用源；"是枚举引用源"不等于"是固定规则"。判断"某行为由什么决定"时，含行为的固定规则（成长公式、进化判定）与纯枚举目录必须分别对待。
