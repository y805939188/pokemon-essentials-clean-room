## 1. 目的、范围与非目标

**目的**：固定战斗交互的用户流程合同——玩家看见什么、何时可选择/取消/等待、返回哪一层、选择如何进入领域判定，以及显示/动画与状态提交的先后关系。后续包据此判断"某命令何时出现、某取消回到哪里、某画面在何时提交状态"，而不是各自重新追踪战斗场景代码。

**范围**（WP67-A 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP67-A-α（战斗入口、命令导航与阶段切换）：战斗创建的配置注入；开场序列；主命令菜单的构建、游标记忆、确认/取消/回退；自动控制与不可输入情形；命令选择、登记、撤销与开始行动的时间点（引用 WP40）。
2. WP67-A-β（招式与目标选择）：招式列表、PP/类型/可用性反馈、Mega 等附加选择的 UI 接点；目标选择的显示时机、初选目标、导航与高亮、目标不合法/不存在、取消后回哪一层。
3. WP67-A-γ（战斗物品交互）：与野外背包不同的入口、过滤/可见物品、物品目标与招式选择、取消/拒绝/重试/接受、游标保存恢复与战斗画面隐藏/重显。
4. WP67-A-δ（队伍选择与替补/接收模式）：主动换人、强制替补、捕获后送盒/查看等实际调用模式；可取消权限的传入者、成员可选或被拒、显示队伍到实际下标的映射、取消与有效选择的消费者。
5. WP67-A-ε（成长、学招、替换与放弃）：经验条、升级数值、招式学习提示与摘要选择的等待/返回；已有招、空槽、满槽、拒绝遗忘、取消选择、放弃/返回重选各分支；状态写入与显示等待的观察点。
6. WP67-A-ζ（捕获接收与结果反馈）：抛球、失败/成功反馈、图鉴条目和命名接点、满队选择与收尾画面的入口返回。
7. WP67-A-η（消息、画面状态与动画时序）：各消息类型的输入、自动等待与返回区别；数据框、HP/经验条、特性提示、派出/收回/倒下、胜败/结束和捕获动画的可观察阶段；动画开关真/假的行为差异与缺动画数据的路径。

**非目标**：

- 不定义动作资格、目标容量、战斗登记与消费、换人限制、捕获公式与球效果、经验/EV 计算、终局结算（WP40/WP41/WP38/WP42 等主规格；本包只登记 UI 交界与调用点）。
- 不定义深层进化/孵化/交易/净化/名人堂演出（WP67-B 前向）；本包只登记与战斗结束的交接点。
- 不定义 Safari/捕虫大会会话规则（WP53 前向）；本包只核对已存在的 UI 覆写与命令/返回差异。
- 不定义 Palace/Arena 规则与回放机制（WP56/WP58 已通过规格引用）；不定义动画作者格式与编辑器（WP74 前向）。
- 不运行战斗/UI/回放/AI、不操作真实存档、不播放音频、不调整宿主界面、不编译/转换、不设计未来 UI 架构或把参考类组织当作未来模块。

## 2. 概念与术语

- **场景（Battle::Scene）**：战斗的呈现层——窗口（消息/命令/招式/目标四类，互斥显示）、数据框、精灵图、队列动画的持有者；**只负责显示与输入采集，选择是否被接受由战斗对象（Battle）判定**。
- **战斗对象（Battle）**：领域调用者——场景菜单以 yield/返回值把选择交给它，它验证后登记为本轮选择（choices）；**UI 提供选择 ≠ 调用者接受选择；调用者接受 ≠ 效果已执行**（执行在攻击阶段按优先级发生）。
- **本轮选择（choice）**：每个场上位置一条——类型（招式/换人/物品/逃跑/呼唤/移位）＋参数；命令阶段可登记、撤销（撤销时物品退回背包、Mega 登记撤销），攻击阶段按优先级消费。
- **首行动（firstAction）**：一轮中玩家为其第一个可选位置选动作时主菜单第 4 项为"逃跑"；之后的位置为"取消"（回退上一位置的选择）。逃跑类动作（含精灵球）消耗全部行动。
- **显示队伍（display party）**：队伍画面展示的顺序（按战斗内队伍次序重排），与实际队伍下标经 partyPos 映射；显示下标不能直接当实际下标。
- **三类取消权限**：队伍画面的 canCancel 由调用者传入（命令菜单换人为 true、强制替补为 false、捕获换入视 sendToBoxes 而定）；**不能把同一个队伍画面概括成统一取消合同**。
- **游标记忆**：主命令下标（`lastCmd`）与招式下标（`lastMove`）按场上位置记忆、派出新成员时复位；战斗背包的口袋与各口袋下标在战斗内单独保存并在退出时恢复野外值。
- **阻塞/非阻塞动画**：硬编码动画（派出/收回/倒下/HP 条/经验条/投球）大多阻塞流程直到完成；招式/公共动画经 `pbAnimationCore` 阻塞；球爆开公共动画为非阻塞（入队播放）。
- **动画开关（showAnims）**："Battle Effects"选项（或 battleAnims 规则）为假时，**招式动画与公共动画不播放**；消息、HP/经验条动画、派出/收回/倒下动画、数据框动画**仍然播放**（不经过该开关）。
- **调试替身（DebugSceneNoVisuals）**：无视觉替身场景，用于战斗挑战生成——固定/随机返回，**不是玩家 UI 行为**，只作对照。
- 影响域编号 Dxx 见 module-map；证据状态五档定义见总览第 7 节。

## 3. WP67-A-α：战斗入口、命令导航与阶段切换

### 3.1 战斗创建与配置注入（`012_Overworld/002_Battle triggering/001_Overworld_BattleStarting.rb:204–269`；`011_Battle/001_Battle/001_Battle.rb:98–174`）

- **场景创建**：`create_battle_scene` 新建场景对象（默认 `Battle::Scene.new`）；战斗对象以场景、双方队伍、双方训练家构造（任一方队伍为空则抛参数错误）。默认 1v1、可逃跑、不可免败、可换人、Switch 风格、显示动画、有经验/金钱、捕获送盒为"不询问"。
- **规则注入（prepare_battle）**：战斗规则表（`$game_temp.battle_rules`，WP12/WP39 引用）逐项覆盖默认——战斗规模（single/double/triple/NvM 字符串→两侧席位数，setBattleMode）、canLose（败不黑屏）、canRun（可逃跑）、canSwitch（可手动换人）、expGain、moneyGain、disablePokeBalls（禁止投球）、switchStyle（对手替补时是否提议换人）、battleAnims（动画开关）、defaultTerrain/defaultWeather/environment、roamerFlees（总是逃跑）。
- **选项注入**：`sendToBoxes` = 选项"Send to Boxes"（仅配置 `NEW_CAPTURE_CAN_REPLACE_PARTY_MEMBER` 为真时，默认世代 8 真；规则 forceCatchIntoParty 强制为 2=必须入队）；`switchStyle` = 选项"Battle Style"为 Switch（规则可覆盖）；`showAnims` = 选项"Battle Effects"为 On（规则可覆盖）。
- **配置注入发生在场景显示之前**；战斗规则表是一次性消耗品（用后清除，WP12 引用），本包只登记注入点与取值来源。

### 3.2 战斗开始与开场序列（`001_Battle/002_Battle_StartAndEnd.rb:170–317`；`004_Scene/001_Battle_Scene.rb`、`002_Scene_Initialize.rb`）

- **开始链**：参与者校验（人数不足降席位，最低 1v1，无法降则抛错）→ 双方出战成员 onStartingBattle（WP39 引用）→ 场景 `pbStartBattle`（建视口与各窗口/精灵图，`lastCmd`/`lastMove` 按位置数初始化为 0）→ **开场动画**（阻塞至完成）→ 开场消息与派出 → 天气/场地通告 → 入场特性链（WP39/WP40 引用）→ 回合主循环。
- **开场消息**：野生战按对方数"Oh! A wild {1} appeared!"（1/2/3 只各有一句，暂停消息）；训练家战"You are challenged by {1}!"（1/2/3 人各一句，暂停消息）。**派出消息按侧、对方先**：对方/同伴"{1} sent out {2}!"，玩家最后"Go! {1}!"（按派出数 1/2/3 只组句；brief 消息）；随后实际派出（§9.3）。
- **窗口互斥**：消息/命令/招式/目标四类窗口任一时刻只显示一类（`pbShowWindow`）；命令/招式/目标窗口各自承载 §3.3/§4/§4.3 的输入。
- **开场动画分两种**：训练家战——两侧队伍排列（lineup）动画异步启动后立即返回（排列动画与后续消息并行）；野生战——数据框出现＋野怪恢复正常色调与叫声（Intro2）**阻塞**至完成，随后闪光公共动画（仅动画开关为真且个体为闪光；SUPER_SHINY 配置下另有超级闪光变体）。
- **天气/场地通告**：天气/场地数据有动画名时先播公共动画，再显示对应消息（"The sunlight is strong."等，普通消息）；Shadow Sky 亦在此分支。

### 3.3 主命令菜单（`004_Scene/003_Scene_ChooseCommands.rb:6–63`；`005_Battle_Scene_Menus.rb:97–193`）

- **菜单构建**：每项动作 4 个命令，2×2 排布——Fight／Bag／Pokémon／第 4 项按条件：**暗影训练家战**（SHADOW 类型存在且为训练家战）→ "Call"；否则**首行动**（本轮第一个可选位置）→ "Run"；否则 → "Cancel"。**可见门按实际条件核对，不按注释推定**：逃跑只在首行动出现，但能否逃跑成功仍由领域判定（§3.4）。
- **返回值合同**：−1=取消（回退上一位置）、0=Fight、1=Bag、2=Pokémon、3=Run、4=Call（暗影战把 3 转为 4；非首行动把 3 转为 −1）；−2=调试菜单（F9 且 $DEBUG）。
- **游标**：初始下标取该位置的 `lastCmd`；确认时写回。方向键按 2×2 网格移动（左右 ±1、上下 ±2，到边即止），移动播光标音；确认播决定音；**BACK 仅在"取消模式"（mode 1，即非首行动）有效**——播取消音并返回 −1；首行动模式 BACK 无效（菜单不退出）。
- **模式表**（菜单显示模式）：0=普通含 Run、1=普通含 Cancel、2=普通含 Call、3=Safari、4=捕虫大会；模式决定按钮图形与 BACK 语义（仅模式 1 可 BACK）。
- **命令提示**："What will\n{1} do?"（{1}=当前位置成员名）；暗影/特殊模式替换提示文本（§10）。

### 3.4 命令分派与回退（`001_Battle/009_Battle_CommandPhase.rb` 全文；`007_Battle_ActionRunning.rb` 全文）

- **命令阶段总控**：阶段开始清消息窗；可显示命令的位置重置本轮选择（**不可显示的位置保留既有选择**——如多回合招式继续）；重置各侧 Mega 登记槽。先玩家循环、后 AI 循环；`decision != 0`（战斗已结束）立即停止。
- **不可输入情形**：位置不存在/昏厥/使用多回合招式中（`pbCanShowCommands?` 假）→ 跳过；`controlPlayer` 或非玩家所有 → AI 代选（WP40/WP52 引用）；**Sky Drop 状态**：除 Fight 外的主命令被拒（"Sky Drop won't let {1} go!"普通消息后重显菜单）。
- **Fight** → 招式流程（§4；返回 true 才离开命令循环，false 回主菜单重显）。**Bag** → 物品流程（§5；返回 true 离开，若所登记物品消耗全部行动——精灵球——则整个命令选择结束 commandsEnd）。**Pokémon** → 队伍流程（§6；有效换人登记后离开）。**Run** → 逃跑流程（见下；**无论成败都结束本轮行动选择**：成功 decision=3、失败本位置行动耗尽——`pbRun` 返回非 0 即 commandsEnd；返回 0 表示根本未构成逃跑尝试，回主菜单）。**Call** → 登记呼唤（§4.2 注；返回 true 离开）。**−2 调试** → 打开调试菜单，关闭后刷新全部显示并做形态检查（WP13/WP20 引用），随后重回主菜单。
- **逃跑流程（pbRun）**：训练家战——内部战斗"No! There's no running from a Trainer battle!"（暂停消息）后返回 0；非内部战斗确认"Would you like to forfeit the match and quit now?"——同意→逃跑音＋"{1} forfeited the match!"＋decision=3，拒绝→返回 0。规则禁止逃跑（canRun 假）→"You can't escape!"（暂停）返回 0。随后按序：幽灵属性（MORE_TYPE_EFFECTS 配置，默认世代 8 真）→ 必定逃脱；保证逃脱特性（显示特性提示条后）→ 必定逃脱；保证逃脱道具 → 必定逃脱（"{1} fled using its {2}!"）；被束缚 →"You can't escape!"返回 0；对方束缚特性/道具 →"{1} prevents escape with {2}!"返回 0。通过则**逃跑计算**（WP41 引用：未提速比较，逃跑指令计数每次尝试 +1 且仅命令逃跑时递增）——成功→逃跑音＋"You got away safely!"（暂停）＋decision=3；失败→"You couldn't get away!"（暂停）返回 −1（行动耗尽）。调试下按 CTRL 选逃跑时先弹结局选择菜单（视为胜/负/平/逃跑/捕获/取消，$DEBUG）。
- **回退（−1）**：仅当本轮已有完成位置时可回退——弹出当前位置、回到上一位置并**撤销其选择**（`pbCancelChoice`：若选择为使用物品则**物品退回背包**、Mega 登记撤销、选择清空）；回退后从该位置重新选。**选择物品后又回退 = 登记时的扣减被撤回**（§5.3）。
- **行动耗尽**：逃跑（无论成败）、精灵球（消耗全部行动）、`decision != 0` 都会提前结束整个命令选择；其余完成位置逐一选完为止。

### 3.5 阶段次序与行动提交（`001_Battle/010_Battle_AttackPhase.rb` 全文；`011_Battle_EndOfRoundPhase.rb:695–711`）

- **攻击阶段固定次序**：优先级变动消息（特性/道具"先制"提示，WP40 引用）→ **呼唤**（按优先序）→ **换人**（含追击拦截——对方已选追击类招式且合法时先执行追击，WP41 引用；随后收回消息、Pursuit 检查、RecallAndReplace）→ **物品**（按优先序执行 §5.3 的四类使用）→ **Mega 进化**（已登记且选择招式的位置，按优先序）→ **招式**（先显示蓄力消息，再按"强制先动→常规优先级→Quash"分组处理）。
- **回末阶段**：经验结算→形态检查→回末替补（§6.3）→实际到达阶段23时按已接受WP42 §5.4的调整前候选计划执行远距移动，交换结果沿WP41 §6→持续能力检查。移动消息依计划成功项顺序；3v3单业主且仅0/1活的正常后续状态可两侧依序移到2/3，不在首移后重判近邻而停止。双席多候选排除、端点/同业主与终局早退全部沿该接口，不与手动Shift的行动代价合并。
- **终局与清理**（`002_Battle_StartAndEnd.rb:405–512`）：胜利——训练家战播胜利 BGM（`pbTrainerBattleSuccess`）＋"You defeated {1}!"（暂停）＋逐个对手滑入显示败北台词（缺省为"..."）；野生战胜利 BGM（`pbWildBattleSuccess`，捕获结局且无捕获经验配置时也在此触发）。失败/平局——"You have no more Pokémon that can fight!"等暂停消息、输钱（规则与开关门）、`!canLose` 时"You blacked out!"；设施败北显示对手胜利台词。**两条胜利路径都会置 `@battleEnd`：此后暂停消息不再自动关闭**（§9.1）。清理：场景 `pbEndBattle`（关中断标志、空窗、BGM 1 秒淡出、全部精灵淡出并销毁）→ 撤销所有未执行选择（**未用物品退回背包**）→ 特性退场触发 → 逐成员离场复位与初始道具恢复（WP39/WP42 引用）。

## 4. WP67-A-β：招式与目标选择

### 4.1 招式菜单（`004_Scene/003_Scene_ChooseCommands.rb:68–133`；`005_Battle_Scene_Menus.rb:198–437`；`001_Battle/009_Battle_CommandPhase.rb:42–88`；`004_Battle_ActionAttacksPriority.rb:5–79`）

- **游标**：初始下标取 `lastMove`（该位置记忆），若该下标无招式则回 0；退出时写回 `lastMove`。方向键按 2×2 移动，**只在目标槽有招式时移动**（左右 ±1、上下 ±2），移动播光标音。

- **Shift（SPECIAL 键）**：仅当 `pbCanShift?` 真（三重战、非中位、目标位同属一个训练家；双打及以下恒假）显示 Shift 按钮——触发后**撤销 Mega 登记**、登记移位（`:Shift`），返回 true（WP41 引用）。

### 4.3 目标选择（`004_Scene/003_Scene_ChooseCommands.rb:327–439`；`005_Battle_Scene_Menus.rb:444–551`；`001_Battle/001_Battle.rb:505–568`；`010_Data/001_Hardcoded data/017_Target.rb`）

- **导航与高亮**：**仅 num_targets==1 采用可移动单选模式**——左右键在同侧内 ±2 跳到下一个非 nil 位置（到侧边界止）、上/下键跨侧跳到对位次序表中首个非 nil 位置；**其余（0 或 2+）采用不可移动的整体高亮模式**——所有有文本的位置同时高亮、方向键不移动（R03 修订）。选中位置的成员精灵与数据框高亮（选择态 2=闪烁/摆动）。按钮排布按该侧训练家视角从左到右（两侧递增方向相反），席位 >2 时用窄按钮。

### 5.3 登记、扣减与执行（`001_Battle/006_Battle_ActionUseItem.rb` 全文；`013_Items/003_Item_BattleEffects.rb:4–64`；`001_Battle/010_Battle_AttackPhase.rb:69–90`）

- **登记即扣减**：校验全部通过 → `pbRegisterItem` 写入本轮选择（类型、物品、目标成员/位置、招式下标）并**立即从背包删除该物品**（仅"用后即耗"数据为真的物品；玩家侧从 $bag 移除、AI 侧从训练家道具列表移除——WP27 引用）。**登记后三种撤回路径**：命令阶段回退上一位置（§3.4）；攻击阶段执行时判定无效果（"But it had no effect!"，场上目标失效时"But it's not where this item can be used!"）→ **退回背包**；战斗结束清理未执行选择 → 退回背包。**使用成功与物品消耗是两条独立事实**：执行成功则选择中的物品位清空（不再退回）；消耗与否按物品数据（WP28）。
- **执行时点**：攻击阶段物品子阶段（§3.5），按优先序逐位置执行——类型 1/2 → 用于成员（可再经 CanUseInBattle 复核）；3 → 用于场上位置；4 → 投球流程（§8.1）；5 → 直接使用。执行消息后领域效果生效（WP28）；精灵球消耗全部行动的合同见 §3.4。
- **与野外使用语义的分界**：战斗背包不套用 WP66-C 的野外返回/取消语义——未选物品退出才回主菜单、Use/Cancel 子菜单取消回物品列表、成员/目标子画面取消回背包（R01 修订）、登记即扣减、执行在攻击阶段；野外"使用成功才消耗"的判断在战斗侧改为"登记先扣、无效退回"。

## 6. WP67-A-δ：队伍选择与替补/接收模式

### 6.1 队伍画面的战斗调用模式（`004_Scene/003_Scene_ChooseCommands.rb:141–191`；`016_UI/005_UI_Party.rb:746–800, 908–1034`）

- **画面进入**：战斗画面淡出隐藏 → 以**显示队伍**（`pbPlayerDisplayParty`：按战斗内队伍次序重排的视图，WP39 引用）打开共享队伍画面；提示语按模式——模式 0 "Choose a Pokémon."（主菜单换人）、模式 1 "Send which Pokémon to Boxes?"（捕获满队换入，§8.3）、模式 2 仅看摘要（捕获满队"Check party"，§8.3）。
- **成员选择循环**：选择成员 → 命令列表——**"Switch In"仅模式 0 且该成员 able 且（战斗允许换人 canSwitch 或本画面不可取消）时出现**；"Send to Boxes"仅模式 1；"Summary"总出现（进入摘要画面，返回后回成员循环，WP66-A 引用）；"Cancel"总出现。**取消分两层（R02 修订）**：**成员命令子菜单的 Cancel/BACK 只回成员列表**（不退出整屏，与 canCancel 无关）；**成员列表层的取消（BACK/未选成员退出）才服从 canCancel**——为假 → 重显成员选择（不可退出整屏）；为真 → 结束画面、战斗画面淡入。**场景画面自身只报告"未取得有效选择"**；−1 是战斗包装在未取得选择时的结果值，不是场景方法对所有路径保证的直接返回。
- **有效选择的提交**：Switch In / Send to Boxes 时，把显示下标经 partyPos 映射回实际队伍下标（映射不到则忽略继续循环），yield 给战斗侧：模式 0 → §6.3 的校验链；模式 1 → §8.3 的换入流程。yield 返回假 → 回成员循环；真 → 结束画面。

### 6.2 成员拒绝与消息（`001_Battle/005_Battle_ActionSwitching.rb:5–105`）

- **换入拒绝（pbCanSwitchIn?，消息经队伍画面显示）**：蛋 →"An Egg can't battle!"；非本训练家所有 →"You can't switch {1}'s Pokémon with one of yours!"；昏厥 →"{1} has no energy left to battle!"；已在场上 →"{1} is already in battle!"。**可达性分层（R02 修订；v3 更正调用路径）**：普通换人画面里蛋/昏厥成员**根本不出现 Switch In 命令**（只能看摘要或取消）——蛋/昏厥两条消息不沿该 UI 路径触达；流程中替补等包装入口接收的是**当前场上位置**、玩家路径仍打开同一队伍画面，**不存在绕过画面的直接传候选调用**。**防御性校验以入口级对照表述**：直接向换入资格校验给出合法存在的蛋／昏厥／他人队伍下标——**有消息承接画面（partyScene）时给对应提示、无承接时仅拒绝**。显示队伍按当前训练家的队伍范围构造（§6.1/WP39 引用），正常未损坏的映射下普通画面**不列出他人队伍成员**——"非本训练家所有"消息同样不沿列表选择触达；**普通 UI 可达的拒绝只保留有证据的"已在场""同回合已选"与换出束缚类**。
- **同一回合冲突**：同侧另一位置本轮已选择换入同一成员 →"{1} has already been selected."。
- **换出拒绝（pbCanSwitchOut?）**：被束缚 →"{1} can't be switched out!"；对方束缚特性/道具 →"{1}'s {2} prevents switching!"；必定可换出的特性/道具/幽灵属性（MORE_TYPE_EFFECTS）例外（WP41 引用）。
- **登记**：全部通过且需要登记时 `pbRegisterSwitch` 写入本轮选择（`:SwitchOut`＋队伍下标）；**校验消息只在队伍画面上下文显示**（非画面路径静默拒绝）。

### 6.3 主动换人与强制替补（`001_Battle/009_Battle_CommandPhase.rb:140–148`；`005_Battle_ActionSwitching.rb:107–226`）

- **主菜单换人（主动）**：`pbPartyMenu` → `pbPartyScreen(idxBattler, checkLaxOnly=false, canCancel=true, shouldRegister=true)`——**可取消**；完整校验链（§6.2）＋登记。`@debug` 战斗直接由 AI 代选（不开画面）。

Will you switch your Pokémon?"（确认消息）——同意 → `pbSwitchInBetween(0, false, true)`（可取消；**进入选人后仍可因换出束缚被拒**——提议门不查束缚、校验在选人提交时）；取消则不换；随后收回消息＋替换；双打等其余情形不提议。玩家位置（训练家战）：直接 `pbGetReplacementPokemonIndex`（owner 选择，checkLaxOnly=true，**默认不可取消**——必须选出合格替补，无合格成员时该位置不替补）。**野生战玩家昏厥**：先确认"Use next Pokémon?"——同意 → 同上选替补；**拒绝 → 当场逃跑判定**（pbRun duringBattle=true——**保留规则禁逃（canRun 假仍报"You can't escape!"），但跳过幽灵属性/保证逃脱特性道具/束缚整组检查，也不递增命令逃跑计数**——R11 修订；成功 decision=3；失败（返回 ≤0）则同样必须选替补）。

- **Arena 例外**：换入恒拒（"​{1} can't be switched out!"），昏厥自动按队伍顺序替补（§10）。

### 7.2 学招分支（`001_Battle/003_Battle_ExpAndMoveLearning.rb:229–271`；`016_UI/006_UI_Summary.rb:1355–1366`）

- **已会**：跳过（无消息）。**空槽**（招式数 < MAX_MOVES）：直接学会——**先写持久招式**（个体招式表追加），再显示"{1} learned {2}!"普通消息＋"Pkmn move learnt"音；**消息返回后才追加在场成员的战斗招式表**并做形态检查（R14 修订：持久个体与当前战斗状态是两次分开的提交，WP20 引用）。
- **满槽**：暂停消息"{1} wants to learn {2}, but it already knows {3} moves."→ 确认"Should {1} forget a move to learn {2}?"——**拒绝** →"{1} did not learn {2}."（结束）；**同意** → 打开**遗忘画面**（共享摘要画面的遗忘模式，淡出淡入；WP66-A 引用）：
  - **选中旧招**（0–3）：执行替换——**持久招式与在场战斗招式两份都在 Ta-da 消息之前写好**（R14 修订）——"1, 2, and... ... ... Ta-da!"暂停消息＋"Battle ball drop"音 →"{1} forgot how to use {2}. And..."暂停 →"{1} learned {2}!"＋学会音；随后做形态检查。PP 按新招重置（WP20 引用）。
  - **取消（−1）**→ 确认"Give up on learning {1}?"——**同意放弃** →"{1} did not learn {2}."（结束）；**拒绝放弃** → **回到遗忘画面重选**（可反复）。
  - **HM 限制**：选中隐藏招式时"HM moves can't be forgotten now."并重选（$DEBUG 豁免）。
- **观察点**：空槽分支——消息显示时持久招式已增、战斗招式表未追加，消息返回后才同步（R14 修订）；满槽替换——两份招式均在 Ta-da 消息前写好；遗忘画面的取消不产生任何写入（招式表不变）；升级与学招全部完成后才进入下一个事件（§7.1 的逐级链）。

## 8. WP67-A-ζ：捕获接收与结果反馈

### 8.1 抛球流程与反馈（`011_Battle/007_Other battle code/005_Battle_CatchAndStoreMixin.rb:112–201`；`004_Scene/004_Scene_PlayAnimations.rb:331–384`）

- **目标解析**：对方位置 → 直接对位；指定位置昏厥则改取其存活队友。**改取后无存活队友的直接触达边界**（R07 修订）：得到空对象，后续状态查询先失败——**不会到达投掷消息与无目标提示**（"threw a ball"＋"But there was no target..." 分支在本版不可达）；不承诺自动退球、回滚或整个进程必定退出。**三种前提分开**：普通菜单路径由目标窗口与数量门保护（§5.2/§5.3）；直接调用投球入口不经菜单保护；已登记扣减的前提是此前完成登记（§5.3）——仅直接调用投球本身不等于发生背包扣减。目标昏厥但有存活队友 → 改取队友后继续正常投掷流程（对照）。
- **训练家战阻挡**：非 Snag 球或目标非暗影 → **挡球动画**（`pbThrowAndDeflect`，阻塞）＋"The Trainer blocked your Poké Ball! Don't be a thief!"（结束）。
- **投掷与结果**：投掷消息（brief）→ 摇动数计算（WP38 公式与前置，本包不展开；$DEBUG+CTRL 必捕）→ **捕获动画**（`pbThrow`，阻塞；含投掷、吸入、摇动、成功收合/爆出各阶段）→ 按摇动数反馈：0–3 各有一句逃脱消息（普通消息）＋球效果 onFailCatch（WP38 引用）；**4=捕获**：brief"Gotcha! {1} was caught!" → **成功旋律**（`pbThrowSuccess`——仅野生战：捕获 ME＋3.5 秒等待后停止；训练家战无此音乐）→ 从对方队伍移除 → 捕获经验（配置开启时，§7）→ 成员复位 → 对方全灭则结局（训练家战=胜、野生战=捕获）→ Snag 球改写拥有者 → onCatch 球效果 → 登记球种、解除 Mega/原始、暗影招式更新、记录初招、形态复位 → 离场处理 → **收球隐藏**（数据框消失＋球淡出）→ 加入待接收列表（`@caughtPokemon`，**暂不入队/入盒**——接收在战斗结束后统一进行）。
- **多个画面不是统一提交点**：投掷动画、结果消息、成功旋律、经验结算、收球隐藏是同一流程内的有序阶段；任一后续流程（经验/升级/学招）都按 §7 的次序插入，捕获个体的**入队/入盒提交**以 §8.3 为准。

### 8.2 图鉴登记与命名（`005_Battle_CatchAndStoreMixin.rb:5–13, 88–107`）

- **接收总流程（战斗结束清理段）**：逐个待接收个体——登记捕获/见过（图鉴记录，WP62 引用）→ **此前尚未拥有该物种时写入拥有记录**；**新增消息与条目画面要求三个条件同时成立**（v3 显式）：**此前尚未拥有该物种**＋**持有图鉴**＋**该物种在已解锁图鉴内**——满足才显示"{1}'s data was added to the Pokédex."暂停消息＋登记最后见过＋**图鉴条目画面**（淡出淡入打开条目，WP66-B 引用）；**已拥有该物种（即使持图鉴且已解锁）不再显示新增消息/条目**，未持图鉴或未解锁同样不显示，拥有记录按"此前未拥有"写入——随后继续命名与存放（R06 修订；三条件不与已有记录合并）→ 暗影个体另登记暗影捕获（WP23 引用）→ 存放流程（§8.3）。
- **命名接点**：非暗影个体且选项"Give Nicknames"为 Give → 确认"Would you like to give a nickname to {1}?"（确认框初始选中 Yes，§9.1）——选 Yes → **命名画面**（`pbNameEntry` → 共享文字输入，模式=宝可梦名、长度上限 MAX_NAME_SIZE、带个体预览；WP17/WP66-A 引用），输入结果写入个体名；选 No 或选项为 Don't give → 直接跳过。
- **次序合同**：图鉴处理在命名之前、命名在存放去向选择**之前**（§8.3 的命令列表与摘要以命名后的名字显示）。

### 8.3 存放与满队选择（`005_Battle_CatchAndStoreMixin.rb:5–85`；`011_Battle/001_Battle/001_Battle.rb:71, 142`）

- **常规存放**：队伍未满或（满队且 sendToBoxes=1 不询问）→ 直接存放：入队成功（存放返回 <0）→"{1} has been added to your party."（暂停）；入盒 →"{1} has been sent to Box \"{2}\"!"（暂停，带盒名）。入队时同步战斗初始道具记录（WP42 引用）。
- **满队且（询问 sendToBoxes=0 或必须入队 sendToBoxes=2）**：命令列表循环——"Add to your party"／"Send to a Box"（**sendToBoxes=2 时移除**）／"See {1}'s summary"／"Check party"；**初始选中第 0 项（"Add to your party"）**（R04 修订：初始游标不是取消项）；**BACK 返回标记值 99**——sendToBoxes=2 时 99 继续循环（不可取消）；否则 99=送往盒子（结束循环走常规存放）。**初始游标、BACK 返回标记、调用者解释是三件事**（R04 修订）。
  - **Add to your party**：普通消息"Choose a Pokémon in your party to send to your Boxes."→ 队伍画面模式 1（§6.1；canCancel = sendToBoxes≠2）——**取消 → 回命令列表**；选定成员 → 该成员离场处理（毒状态计数复位、解除 Mega/原始）→ 送盒（"{1} has been sent to Box \"{2}\"."暂停）→ 从队伍移除并重排战斗记忆数据（初始道具/战前等级/会心/承伤，WP42 引用）→ 新个体随后按常规入队。
  - **Send to a Box**：结束循环 → 常规存放（入盒消息）。
  - **See {1}'s summary**：淡出打开该个体摘要（WP66-A 引用）→ 回命令列表。**Check party**：队伍画面模式 2（仅看摘要）→ 回命令列表。
- **配置来源**：sendToBoxes 由选项注入（§3.1；0=询问、1=不询问、2=必须入队）；规则 forceCatchIntoParty 强制为 2。选项不存在时（配置为假）按 1 不询问。
- **多个体**：逐个独立走 §8.2–§8.3——**每个体均按图鉴处理 → 命名 → 存放完整完成后才处理下一个**（不颠倒、不按"全部图鉴/全部命名"分批，R06 修订）；任一画面取消只影响当前个体的当前环节（命令列表循环），不回滚已完成环节。

## 9. WP67-A-η：消息、画面状态与动画时序

### 9.1 消息类型（`004_Scene/001_Battle_Scene.rb:164–308`）

- **普通消息（pbDisplayMessage）**：逐字显示；全部显示后 1 秒自动关闭。BACK/USE：逐字中→快进（停顿处播决定音）；已全显→立即关闭。block 在文本全显时触发（用于同步音效）。**brief 变体**：全显后不关闭、不等待——驻留显示（后续流程并行），下一条消息到来前补 1 秒驻留（`pbWaitMessage`）；部分动画把 brief 标记直接清除（不等这 1 秒）。
- **暂停消息（pbDisplayPausedMessage）**：带续行箭头；全显后 3 秒自动关闭，**战斗结束标记（`@battleEnd`，胜负 BGM 设置后置位）除外——不自动关闭、必须输入**。BACK/USE：逐字中快进、已全显则播决定音关闭。
- **确认消息（pbDisplayConfirmMessage）**：Yes/No 命令列表——**初始选中第 0 项 Yes**（R04 修订：每次命令框初始下标为 0）；文本全显后不移动直接 USE = 确认 Yes；**BACK 返回 No**（默认值 1 是取消返回值，不是初始游标）。
- **命令列表（pbShowCommands）**：消息窗＋命令窗；**初始下标为 0**（R04 修订）；USE 返回下标；**BACK 仅当默认值 ≥0 时返回默认值**（默认 −1=不可取消）。消息逐字中时 BACK/USE 先快进。
- **abortable 场景（非交互战斗/回放）**：消息文字自动快进（逐字立即跳完），**但普通消息全显后仍有 1 秒计时、brief 驻留等待仍存在、普通暂停消息在非战末仍有 3 秒自动关闭计时**（R05 修订）；**命令列表不因 abortable 自动选项/返回**。BACK 经场景输入处理触发战斗中止（§3.5 的 abort 路径——decision=0＋pbEndBattle），与普通取消返回分开。

### 9.2 数据框、HP/经验条与状态图标（`004_Scene/006_Battle_Scene_Objects.rb` 全文）

- **数据框**：单席位用标准框、多席位用窄框；**仅玩家侧单席位显示 HP 数字与经验条**。内容：名字、等级、性别（♂蓝/♀红）、状态图标（剧毒用独立图标）、闪光图标、Mega/原始图标、**已拥有图标（仅对方）**。位置按席位布局表（1/2/3 席位各自的偏移）。
- **HP 条**：任何变化播放**固定 1.0 秒**的补间（与变化量无关）；颜色绿 >1/2、黄 ≤1/2、红 ≤1/4；动画期间该框阻塞流程（`pbHPChanged`/`pbHitAndHPLossAnimation`——后者多目标同时播放并全部等待）。恢复/伤害公共动画仅当调用方要求且动画开关为真时附加播放。
- **经验条**：从空到满 1.75 秒按比例（含"Pkmn exp gain"音）；满槽 0.2 秒闪白＋"Pkmn exp full"音；**无经验条显示的框不播放但仍走同一等待链**（动画立即完成）。经验条动画阻塞（§7.1）。
- **选择态**：数据框/成员精灵的 selected=1（选命令中，上下摆动 0.6 秒周期）、2（被选为目标，数据框摆动＋精灵 0.3 秒周期闪烁）；目标选择结束全部复位。
- **特性提示条**：仅 `USE_ABILITY_SPLASH`（世代 ≥5）——按侧各一条，显示"{1}'s"＋特性名；触发时播出现动画（新特性触发前若已有提示条先消隐）；领域侧包装另有 1 秒可选延迟（`pbShowAbilitySplash(delay)`）。

### 9.3 派出、收回、倒下与胜负动画（`004_Scene/004_Scene_PlayAnimations.rb` 全文；`007_Battle_Scene_BaseAnimation.rb:4–63`；`008_Battle_Scene_Animations.rb` 定点）

- **硬编码动画基类**：由若干 PictureEx 进程组成，全部进程结束才算完成（`animDone?`）；场景流程**逐帧驱动并阻塞等待**（少数入队异步，见下）；临时精灵在结束后销毁。
- **派出（pbSendOutBattlers）**：等待已有排列动画结束 → 清 brief 标记 → 训练家淡出（对方 TrainerFade/己方 PlayerFade；开局版含扔球动作）与各个体的球动画**在同一更新循环中共同推进**（R08 修订：非逐只全串行）——**每只数据框只等待自己的球动画完成**（多个体出现可错峰）；**全部数据框完成且排列动画结束后才离开该等待段**。Illusion 个体以伪装显示（WP20）；闪光公共动画收尾（动画开关为真时）。
- **收回（pbRecall）**：清 brief → 收球动画 → 数据框消失（均阻塞）。**倒下（pbFaintBattler）**：叫声＋下落＋数据框消失（阻塞）。
- **伤害（pbDamageAnimation/pbHitAndHPLossAnimation）**：单目标/多目标闪烁＋HP 条，全部完成才返回。
- **投球（pbThrow）**：清 brief → 投掷/吸入/摇动/收合或爆出（阻塞；同时等待排列动画队列空）；**挡球（pbThrowAndDeflect）**阻塞；**收球隐藏（pbHideCaptureBall）**数据框消失＋球 1 秒淡出并行；**成功旋律（pbThrowSuccess）**仅野生战、3.5 秒等待后停 ME。
- **开场/天气/场地**：开场动画阻塞（训练家战排列除外，§3.2）；天气/场地以公共动画播放（动画开关为真时）。
- **Mega/原始**：公共动画 MegaEvolution → 形态写入与精灵图/数据框刷新 → MegaEvolution2 → 完成消息（§3.5 时点；原始回归在入场时，WP39 引用）。

### 9.4 招式/公共动画的查找、等待与缺失路径（`004_Scene/004_Scene_PlayAnimations.rb:386–579`；`007_Other battle code/007_BattleAnimationPlayer.rb:670–844`；`010_Data/002_PBS data/001_MiscPBSData.rb:39–53`）

- **查找链（pbFindMoveAnimation）**：招式动画表（move2anim.dat）精确命中——对方侧优先 OppMove 版本（不翻转播放），无则共用版本；未命中 → 按招式类型/分类查**类型默认表**（六格：单目标物理/特殊、自身变化、多目标物理/特殊、非自身变化；回退链：本格 → 单目标格 → 自身变化格）；再无 → Tackle 的动画；**全部失败返回 nil——静默不播放**（无回退消息）。
- **播放（pbAnimation/pbCommonAnimation）**：动画开关为假 → 领域侧包装直接跳过（§3.5 注）；无动画 ID 或**动画数据库缺失**（PkmnAnimations.rxdata 不存在 → 加载为 nil）→ 直接返回。播放时隐藏全部影子、按用户/目标实际位置做焦点变换（单点/用户/目标/两点连线），`PBAnimationPlayerX` 按 **20 帧/秒**推进、到达末帧结束（可循环者循环），**`pbAnimationCore` 阻塞至完成**并恢复精灵位置；用户/目标图版可用双方实际立绘（pattern −1/−2）。公共动画按"Common:名字"首个匹配播放一次。
- **球爆开公共动画（pbBallBurstCommonAnimation）**：**非阻塞**——播放器入队、随场景帧更新推进（爆出粒子在后续消息期间继续）。
- **失败边界**：动画数据缺失/招式无映射/数据库文件缺失都静默无动画（流程不等）；资源（图形/音频）存在性未验证（U01 类保留）；不转录逐帧坐标/轨迹/作者格式（WP74 前向）。

## 12. 边界、失败与未知

- **无目标投球的直接触达边界**：指定位置昏厥且无存活队友时，改取队友得到空对象、后续状态查询先失败——不会到达投掷消息与无目标提示；不承诺自动退球/回滚/进程退出（§8.1，R07）。
- **队伍为空侧**：构造时即抛参数错误（任一方队伍空）；参与者校验失败逐次降席位，降至 0 抛错（§3.2）。
- **背包为空/过滤后无项**：列表为空，只能取消（§5.1）；**物品登记后背包已扣**——回退/无效/战斗结束三条退回路径（§5.3）。
- **无合格替补**：昏厥位置无合格成员时不触发替补（§6.3）；Arena 自动替补到队伍尽头为止（§10）。
- **遗忘画面反复取消**：取消→放弃确认→拒绝放弃→回遗忘画面，可无限循环（§7.2）；HM 不可遗忘（调试豁免）。
- **动画缺失**：动画数据库/招式映射/类型默认/Tackle 四级全部落空 → 静默无动画（§9.4）；公共动画名不存在 → 不播放。
- **消息与动画开关**：动画开关为假时消息、HP/经验条、派出/收回/倒下动画仍播放（§9.3）；暂停消息在 `@battleEnd` 后不自动关闭（§9.1）。
- **回放降级**：回放中暂停消息转为普通消息（仍有显示与计时，非零等待——R05）；常规命令不打开菜单、自动招式的目标窗口为例外（§10，R10）；调试替身的固定/随机返回不是玩家行为（§3.6）。
- **未证的异常清理**：子画面异常退出（如事件中断）时的画面状态未逐项验证；真实事件可达性（各战斗入口的地图事件调用者）归 WP39/WP77；宿主输入物理映射未运行验证（U01）。
