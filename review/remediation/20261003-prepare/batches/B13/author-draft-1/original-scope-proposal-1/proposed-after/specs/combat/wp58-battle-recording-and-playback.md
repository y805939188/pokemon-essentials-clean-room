## 1. 目的、可见流程与状态边界（A）

本包回答“一场设施战斗如何被记录、记录了什么、何时成为可保存的‘上次战斗’、回放按什么规则重演，以及哪些内容不在记录内”。它不定义战斗规则本体（WP39–52）、设施会话（WP55／56）或存档系统（WP09）；不承诺跨版本／跨实现重放等价（同种子或同记录数组都不构成保证）。

可见流程（设施单场）：按挑战规则创建**可记录**战斗对象（战斗类型号决定记录的类型字段：0塔式／1Palace／2Arena）→ 战斗开始写入初始条件 → 每命令阶段追加一轮槽位，行动登记／随机／换人询问按发生时点追加 → 战斗结束时导出字节串；单场包装只在**胜／负／平**时把它放入临时字段，否则清空 → 由事件入口把临时记录提升为全局“上次战斗”（随存档保存）→ 回放入口反序列化并按类型分派重演；调试可用数字选择一个 `Battles/Battle###.dat` 文件回放。

入口现状：记录提升与回放入口在脚本内**没有调用者**（由地图事件驱动；事件缺失即U01）；调试回放入口独立于正常流程。回放不写回任何记录。

## 2. 记录生命周期与持久化（B）

两个记录存放处：

| 存放处 | 属性 | 写入／清空时机 |
| --- | --- | --- |
| 临时记录 | 游戏临时状态字段（不随存档） | 单场包装结束时：**先清空**；仅当决定∈{1胜、2负、5平}时写入导出字节串。调试按住Ctrl跳过战斗同样先清空后返回“胜利” |
| 全局“上次战斗” | 全局元数据字段（随存档保存；默认空） | 仅由提升入口写入：把临时记录移入全局并把临时置空。不提升则临时记录不持久 |

生命周期状态：`未开始 → 记录中（战斗对象内，不对外可见）→ 已导出（临时字段，通常仅存活到下一次战斗或被提升）→ 已提升（全局字段，跨存档保存）`。回放不改变任何记录；回放结束即退出。

各终局对临时记录的处理（单场包装，2026-09-29静态）：

| 决定 | 含义（WP42） | 临时记录 | 备注 |
| --- | --- | --- | --- |
| 1／2／5 | 胜／负／平 | 写入导出字节串 | 平局同样保留 |
| 3 | 逃离／弃权 | 清空 | 包装随即使玩家可弃权（设施训练家战） |
| 4 | 捕获终结 | 清空 | 本接入为训练家战，不可达 |
| 0 | 未决／中止 | 清空 | 含调试跳过（先给“SKIPPING BATTLE…”等提示） |

导出字节串是运行时序列化的不透明数据（**无显式格式版本号**）；其内部分量按§3以语义列出。记录的对象图包含队伍成员快照与物品对象等运行时对象，兼容性依赖实现内部结构（未决保留）。

## 3. 初始条件字段与记录结构（C）

记录五元组：`[战斗类型号, 初始条件属性包, 轮次表, 随机序列, 换人序列]`。

初始条件属性包（于战斗开始、在正常开始流程之前写入；复制语义**按字段分列**：名字与徽章表作clone、双方队伍／起始索引表／物品表／规则标志作序列化字节快照、NPC台词及天气等其余字段直接赋值——不统一承诺深复制；训练家与队伍因此被**去引用**）：

| 键 | 记录内容 | 备注 |
| --- | --- | --- |
| internalBattle | 内部战斗标志 | 本接入恒假：设施战物品菜单被拒、对训练家可由确认弃权 |
| player | 玩家侧训练家快照数组，每项＝[类型, 名字, 编号, 徽章表副本] | 空则记空 |
| opponent | 对手侧训练家快照数组，每项＝[类型, 名字, 编号, 败台词, 胜台词] | 缺失台词以“...”占位 |
| party1／party2 | 双方队伍成员快照（含个体数据） | 去引用副本，回放只动副本 |
| party1starts／party2starts | 双方起始索引表 | 本接入未另行设置，保持初始化默认[0]（普通遭遇路径才由战斗触发流程写入，对照见来源） |
| weather／weatherDuration | 场地天气与剩余时长 | 取自战斗场地现值 |
| canRun | 可逃走许可 | 布尔 |
| switchStyle | 换人风格（系统设置现值） | 布尔 |
| showAnims | 招式动画开关现值 | 布尔 |
| items | 对手侧训练家物品表快照 | 本接入未另行设置，通常记空（普通遭遇路径才写入，对照见来源）；玩家伙伴物品表（ally）**未记录** |
| backdrop／backdropBase | 背景标识与基值 | 初始默认空／空值 |
| time／environment | 战斗时段数值与环境类别 | 初始默认0／无 |
| rules | 战斗规则标志快照 | 条款等（WP54前向） |

**布局与未保存的运行选项（具名）**：18键中**没有双方场上人数**。普通战斗初始化默认1v1；布局设置入口只改场上人数；设施的双打规则直接调用该入口，**不把布局写入所录rules字典**，回放入口也不再施加该规则工厂。因此**同一实现内也会丢布局**：双打记录回放为默认1v1，后续非空2号／3号席指令将访问不存在的战斗者（失败形态见§5.4／§6.3）。其它不由记录恢复、保持回放初始化默认的具名运行选项：双方队伍顺序表（按队伍长度重新初始化）、可换人／可认输／控制玩家／经验与金钱开关、禁用球开关、捕获送盒方向、Mega登记状态等——18键不等于完整战斗状态。

轮次表：每个命令阶段一项；每项**先建4个空席**（按战斗者索引；单打只用前两席）；更大布局下按索引赋值可把该项扩展到4席以上，但回放一律按4席循环消费（§6.3），超出席位的记录不会被回放读取。槽位形式见§4。

随机序列与换人序列：顺序数组，只追加（见§5）。两者无长度上限、无逐项类型校验。

**不记录项（具名）**：Mega进化登记——**原录制战斗的Mega能力未被取消**：命令菜单的Mega开关、Mega登记与攻击阶段的Mega执行照常运行，但记录不保存该标记；回放不重建Mega登记，已登记的Mega不能据记录重现（不能写成“录制时也不会登记”）；换位与呼叫命令——**实际行动照常登记**（选择被写入实际行动数组），只是没有记录钩子：该席此前为空时仍为空席，但同轮已有成功登记（如FIGHT）后撤销、再改选换位／呼叫时，旧记录不被清除、残留在该轮（见§4取消语义）；玩家伙伴物品表；AI内部状态与评分（回放时不重建AI决策，改由命令槽直接驱动）；背包与货币的真实扣减；随机种子；场景缓冲与演出状态；记录提升入口之外的一切持久化。另：记录战斗把“收服存储”覆盖为**空操作**（收服在设施不可达；完整接收链归WP38／WP62）。

## 4. 命令登记内容与时点（D）

登记以“命令阶段”为节拍：每命令阶段开始时**追加新一轮**（4个空席），进行中的每次成功登记**覆盖**该席当前内容（无追加式历史）。

| 命令 | 写入槽位 | 触发时点与失败／取消 |
| --- | --- | --- |
| 使用招式（正常） | [0, 招式索引] | 资格校验通过才写；校验失败不写。若随后选定目标，目标写入第3位 |
| 使用招式（自动） | [0, -1] | 安可／无可选招等自动入口；该入口**在自动逻辑返回后整体赋值**，先前经自动逻辑内部写入的目标位会被丢弃（具名边界） |
| 使用招式（Palace自动） | [0, 招式索引] 或 [0, -2] | Palace按性格概率与类别自动选招：有该类招式→索引；无该类招式→**-2**——以挣扎对象为载体的“无力”哨兵：登记时挣扎对象被放入选择，但执行成功检查按-2**提前失败**（提示“无力使用力量”），不等同实际使用普通挣扎攻击；回放经普通招式登记把-2原样传回，同样提前失败（§5.3／§6.3）。该登记语义不做招式资格复检 |
| 物品 | [1, 物品对象, 目标索引, 招式索引] | 登记入口同时从背包扣减（若最终未使用由既有路径回还）；设施接入物品菜单被拒，本槽通常不可达 |
| 换人 | [2, 队伍索引] | 资格校验通过才写；失败不写 |
| 逃跑 | [3, 当时的决定值] | 逃跑尝试入口返回后写入：失败记0；成功记3（该记录随后因决定3被清，不保留）；调试改判时记入所设值。失败逃跑同样终止本轮的其余选招（语义照旧，不属记录） |
| 目标补充 | 既有席位的第3位 | 选靶取消不写；**若无先行走招登记**，写入会产生不完整槽（形如[空,空,目标]），回放不对此分派（具名边界） |

槽位只有上表所列命令族形态（招／物品／换人／逃跑，含自动-1与Palace-2两个哨兵）；未选择、强制动作（多回合招等）的席位保持空。换位、呼叫有实际行动登记但无记录钩子：席位此前为空时选它们仍为空席；同轮已有成功登记后撤销改选时，旧记录残留（不保证“均为空席”）。**取消与返回不触发记录清空**——回退重选只会被后续登记覆盖；未被覆盖的旧内容在该轮保留。

时点对照：登记动作发生在命令菜单流程中（玩家侧与AI侧共用同一组登记入口；AI的选招／换人／物品最终也走登记入口）。记录模块不覆盖“撤销／返回”类入口。

## 5. 随机与换人序列、调用域（E）

### 5.1 记录随机入口

普通战斗中，战斗对象的随机入口本身就是全局随机；可记录战斗把它包装为“先取真实随机、再把结果追加入序列”。回放端按序列**依序取用、不重新随机**（WP06§5.3）。

经该入口、**进入记录序列**的域（有界清点：`011_Battle/`内共74处调用行，其中3处在Safari战斗类——该类自定义随机入口、不在本记录机制内；其余**71处分布于20个文件**）：

| 域（代表） | 处数（非定义行） | 说明 |
| --- | --- | --- |
| 攻击合并时的平手顺序 | 1 | 同优先级行动排序的洗牌随机（对回放结果关键） |
| 招式执行（命中、追加效果、状态时长、多段命中、使用计算、招式候选取一） | 43 | UseMoveSuccessChecks 9、MoveEffects_BattlerOther 9、ChangeMoveEffect 5、MoveAttributes 5、MultiHit 3、UsageCalculations 3、Move_Usage 2、Battler_Statuses 2、Battler_UseMove 2、BaseEffects 1、BattlerStats 1、SwitchingActing 1 |
| 随机目标与随机补位 | 3 | 随机选靶2处、随机补位索引1处 |
| 能力／道具触发与选择、回合末 | 21 | AbilityEffects 16、ItemEffects 2、EndOfRoundPhase 2、AbilityAndItem 1 |
| 收服摇晃与接收（机制涵盖） | 3 | 收服在设施不可达；完整捕获归WP38 |
（合计71处。）

**不进入记录序列**的随机：AI随机入口＝全局随机（AI评分噪声、AI选招权重、AI换人与物品倾向、Palace自动选招与Pinch换人概率、逃跑成功率的随机判定）；命令阶段内的“类别判定”分支走全局随机（同一判定的执行期分支才走记录入口）；场景动画与调试场景的随机仅呈现；战斗结束后世界侧检查（如队伍接触传播判定，且其门槛为“内部战斗”标志，本接入为假）不入记录。

### 5.2 换人序列

换人询问返回队伍索引或取消−1，返回即按发生时点追加同一换人序列。回合末对手／玩家补位与攻击阶段属主选择式替补均可达：训练家Teleport、U-turn/Flip Turn/Volt Switch、PartingShot（按实际换出者）、BatonPass、EjectButton/EjectPack、EmergencyExit/WimpOut，在各自phase／owner／健康非蛋后备／存活／失败／追打门通过后经pbGetReplacementPokemonIndex非随机分支到pbSwitchInBetween，回放同一时点消费。命令仍为原出招，替补当轮无行动。Roar/Whirlwind/DragonTail/CircleThrow与RedCard走随机分支，只有随机记录、不写询问序列。内部战斗门所限定的对手补位后换人风格确认在设施不可达（W16保持）。Arena正常顺序补位不询问，候选换入资格恒假使攻击阶段自换不到询问。

### 5.3 模式差异

| 方面 | 塔式／普通可记录 | Palace | Arena |
| --- | --- | --- | --- |
| 命令登记 | 通用登记入口（校验≠记录；失败不写） | Palace登记语义：自动选招结果入槽，含-2挣扎哨兵；不做资格复检 | 通用登记入口 |
| 随机使用 | 执行期机制随机入序列；AI与评估期随机不入 | 自动选招与Pinch换人用全局随机（**不入序列**）；结果以槽位快照 | 该类战斗文件内无随机调用（评判与提交为确定性状态机，WP56已述） |
| 回放登记 | 通用 | -2经普通招式登记原样传回、执行检查按“无力”提前失败（不映射为可用的普通挣扎），其余同通用 | 通用；开场初始化，正常补位保留心技／首发HP基线／计数／开始标记，至少3后第3/4/5轮可连续裁判（WP56） |

### 5.4 消费、不足与保证边界

回放按序取用随机与换人条目；**数组越界无保护**，且失败阶段按数组分列：轮次表缺轮次或缺席对象时，先在下标读取或长度调用处失败（空值没有这些方法）；随机／换人序列越界才表现为取到空值后索引继续递增、偏差从越界点起扩散（空值在下游使用处另行失败；不夸大具体下游表现）。随机数量、次序或调用域在不同实现／版本间变化都会改变结果；记录内无格式版本号；因此**不承诺跨版本、跨实现或“同种子”等价**（U05保留；WP06边界不扩大）。

## 6. 回放：恢复、分派、重放、中止与清理（F）

### 6.1 入口与分派

回放入口：给定字节串→为空直接返回（无操作）→建立战斗场景（**标记可中止**）→反序列化五元组→按类型号分派三类回放战斗（0／1／2）→按重建的对手信息取训练家战背景音乐→在战斗动画包裹内运行战斗主体。**未知类型号**会使分派结果为空，随后启动调用将报错（静态具名缺陷；未运行验证）。调试回放：数字选择0–500（取消不播放），读取 `Battles/Battle%03d.dat` 数据文件（二进制读取）后走同一入口；该目录不随仓库提供（U01）。

### 6.2 恢复的内容与方式

重建：双方队伍由记录字节串反序列化为副本；训练家对象按快照重建（玩家侧含徽章、对手含胜负台词；均为新对象，不引用实时对象）；随后逐项回填初始条件（§3全部键——**不含布局**，布局后果见§3）。**副本不构成全局隔离**，分三层：

- **副本字段**：队伍成员与训练家属性在副本上改动，不写回原队伍／原训练家对象（但不据此宣称所有副本字段都与全局无关，见下）。
- **仍读取的实时依赖**：回放命令循环按槽再登记；物品登记入口对使用后消耗的物品按侧归属扣减（空物品／非消耗品先被跳过）——属玩家侧时扣**实时背包**，背包无该物即在扣减处报错（§6.3）；是否属玩家侧按侧／属主索引判断，不比较是否为原玩家对象。
- **可写入的全局状态**：回放正常结束走普通终局（§6.4），离场处理可对副本个体调用形态提交；形态提交入口**直接登记全局玩家图鉴，没有内部战斗门槛**（接收者与门详见WP62对应条目）。具名反例：BURMY——**传入参战标志实际为真**（按写入/读取口径：BURMY 位于队伍下标 0 且首发席位 0；**仅"实际参战过"不足以代替该标志**——下标 1 仅换入席位 0 时记录位 0 虽真、按其队伍下标读取却为假，形态保持 0，GR-013／WP41 §4.1／WP42 §6）、战斗结束、旧形态0、环境为Cave时离场形态变为1，回放中的副本变形仍写实时玩家图鉴。该例不扩大为"所有实际参战过的后备都会在回放变形"。

设施正常菜单禁止用物只是输入来源限制，不构成回放入口的隔离保护或记录校验。

### 6.3 重放循环

命令阶段仅由记录驱动：每阶段递增轮次索引；**固定对4席**逐一（记录中超出4席的内容不被读取）——空席跳过；其余先清空该席选择再按槽分派：使用招式（-1→自动入口；其余含-2→普通招式登记，-2随后在执行成功检查按“无力”提前失败）；有目标位则补目标；物品按槽直调物品登记——该入口对**使用后消耗的物品（如POTION）**同时扣背包（空物品／非消耗品先被跳过）：属玩家侧时扣**实时背包**，背包无该物即报错（给定记录含合法玩家侧消耗品BAG槽时此分支实际可达）；换人按槽再登记；逃跑槽直接把记录的决定值写入。回放按1v1重建时，**需要读取战斗者的指令分支**（如FIGHT的招式登记）在非空2号／3号席访问不存在的战斗者对象；RUN槽只写决定值、不读取战斗者（首次失败点随指令族而异，不概括每种非空指令都在登记时失败；未运行验证）。**AI侧命令循环不执行**（双方命令都已含在槽内；无现场AI决策）。记录数组不足或格式不符按5.4处理。

### 6.4 呈现与中止

回放场景的消息等待自动前进、暂停式显示降为普通显示，命令循环由记录驱动、通常无命令交互；但不作“任何回放都无交互”的普遍保证：-1自动入口在**非单打、安可且属玩家侧**时仍调用选靶流程（消息开关只控制提示，不取消选靶调用）；标准回放因布局丢失回到1v1（§3）使该分支通常不可达——那是布局缺陷的后果，不是交互保证。半途按取消键触发中止（战斗中止异常→外层捕获→决定置0并结束场景，**不执行正常战斗终局**；注意正常结束时另有普通终局路径——场景结束、退未用物品、离场能力、形态回调与持有物还原记录——回放正常结束会经过它，但设施包装的还原／统计／记录产出不在此路径）。中止或结束都不产出记录、不改实时队伍。

### 6.5 回放不做的设施善后

等级调整还原、双方治疗、Mega／原始回归清除、物品恢复、胜负统计与临时记录产出均为单场包装职责（WP55已述），回放入口**不调用**它们。
