## 1. 目的、边界与可见流程

队伍界面与摘要界面是玩家浏览队伍成员、执行成员级操作（换位、持物、邮件、秘传招、查看摘要、重排招式、标记）以及供其它系统借用「选择一名成员／选择一招」的两层 UI。玩家可见入口：暂停菜单「Pokémon」项；背包对物品选 Give 后的队伍给予画面；PC 邮箱对邮件选 Give 后的队伍给予画面；净化遗迹石、融合类物品、PP 类物品、事件脚本（选择成员／选择招式）与战斗设施多选入场的借用调用；Move Relearner（重学）入口。每个入口的**模式**决定可用操作集合：完整主菜单模式、纯选择模式（注解 ABLE／NOT ABLE 或无注解）、给予模式、多选模式。

本包只描述两界面本身的用户流程、选择合同与其直接触发的写入；写入的领域规则（可否持有、可否学习、可否使用）一律引用主规格。

## 3. 队伍界面：面板、导航与选择合同（B）

### 3.1 面板布局与显示合同

- 固定 6 个面板位（MAX_PARTY_SIZE=6）＋取消按钮；多选模式改为 CONFIRM＋CANCEL 两按钮。空槽为空白面板（不可选中态）。初始选中面板 0。
- 面板按 2 列网格排布：偶数索引左列、奇数索引右列，每行两块、逐行向下；首槽（索引 0）为圆角面板，其余为矩形面板。
- 面板皮肤四态：正常、濒死（fainted 皮肤）、换位来源（preselected 皮肤）、换位中选中（switching 皮肤）；选中与非选中各有对应图。
- 显示内容：宝贝球图标、成员图标、持物图标、名字、等级（蛋不显示）、性别符号（蛋与无性别不显示）、HP 数值与 HP 条（蛋不显示；有注解文本时 HP 区域被注解替代）、状态图标（濒死＝状态图末位；异常＝该异常图标位；Pokérus 感染期＝状态图后追加位）、闪光图标（蛋不显示）、注解文本（如 ABLE／NOT ABLE／位次）。
- HP 条：宽 96 像素基准，按 hp/totalhp 比例、不足 1 像素取 1、四舍五入到最近偶数像素；三档色区按阈值 >1/2、≤1/2、≤1/4 取自资源图不同行（与摘要 HP 条同规则）。

### 3.2 导航（方向键，均为确定结果）

游标索引 0..5 为面板、6 为取消（多选时 6＝CONFIRM、7＝CANCEL）。方向键按网格语义移动并跳过空槽：

- LEFT／RIGHT：索引减一／加一（水平语义）；越过空槽时继续同向直到非空；LEFT 越过 0 或 RIGHT 越过末位时回绕到取消按钮／面板 0（队伍为空时 RIGHT 回到取消位）。
- UP／DOWN：索引减二／加二（同列换行）；在取消按钮行与面板区之间按最近面板转换；空槽跳过；UP 从面板 0／1 到取消位、DOWN 从末行到取消位，越界回绕。

（确切转移函数为静态映射；上表为行为化概括，逐项可推导复核。）

### 3.3 选择与返回合同

| 输入 | 条件 | 结果 |
| --- | --- | --- |
| USE | 游标在面板 | 返回该成员索引（选择音） |
| USE | 游标在取消按钮 | 返回 -1（换位置子状态为决定音，否则关菜单音） |
| BACK | 任意 | 返回 -1（非换位置子状态播关菜单音） |
| ACTION | 主循环（canswitch=1）且游标在面板 | 返回 `[1, 索引]`＝快捷换位请求 |
| ACTION | 快捷换位的目标选择（canswitch=2） | 返回 -1（该子状态下 ACTION 等同于取消） |
| ACTION | 菜单 Switch 发起的目标选择（canswitch=0） | 无效果（不取消、不请求换位） |
| SPECIAL | Box Link 桥可用且 canswitch≠2 | 打开盒子界面（WP66-B）；canswitch=2 的快捷换位目标选择中不可用。**菜单 Switch 的目标选择（canswitch=0）仍可用本桥**。返回后整屏重建：注解按面板索引恢复（不按成员身份重分配）；选中位仅在其索引仍小于剩余队伍长度时保留，超出时夹到末位，无有效旧选择时落到取消位 |

**换位置两段流程**：发起（菜单 Switch 或 ACTION 快捷）→ 提示「Move to where?」、来源面板 preselected、进入目标选择 → 选定目标且与来源不同才执行交换：交换队伍数组两项引用（播放换位动画），随后清除全部 preselected／switching 并刷新。目标等于来源或取消（-1）则不交换。**两种发起的输入权限不同**：ACTION 快捷的目标选择为 canswitch=2（ACTION 取消、SPECIAL 禁用）；菜单 Switch 的目标选择为 canswitch=0（ACTION 无效果、SPECIAL 桥仍可用）。**「无写入」仅指换位动作本身**——未完成第二段时队伍数组不发生交换；但菜单 Switch 的目标选择中可经 SPECIAL 进入盒子界面，期间在盒子侧已完成的状态修改（如切换当前盒、存入／取出成员等 WP66-B 合同下的真实写入）**不会随取消换位回滚**（WP66A-R03 查明：例如把当前盒 0 切到 1 再退出并 BACK 取消，队伍未交换而当前盒 1 保留）。快捷换位禁用 SPECIAL，其「第二段前无其它写入」成立。 **盒侧收缩队伍后旧源索引不重绑**：队伍[A,B]先选B源1，普通Switch中经SPECIAL存B入盒，返回[A]游标0后USE，先交换旧源1与目标0，队伍变[空,A]，随后换位结束对空面板赋成员失败；B仍在盒、部分队伍写入不回滚。ACTION快捷换位禁SPECIAL，不套此链。

## 4. 队伍界面：命令菜单与成员操作（C）

### 4.1 菜单构建（可扩展注册表）

主菜单由注册表 `:party_menu` 生成：按各注册项 order 升序、逐项求 condition（满足才出现），名字可为静态文本或动态求值；末尾追加「Cancel」。场地招命令插入到固定位置：非调试插到第 1 项之后、调试模式插到第 2 项之后，并以蓝色（colorKey=1）显示。默认注册项（order）：Summary 10、Debug 20（仅 $DEBUG）、Switch 30（队伍>1）、Mail 40（非蛋且持有邮件）、Item 50（非蛋且无邮件）。**持邮件成员显示 Mail 而非 Item；蛋两者皆无。**场地招插入条件：已知招中有秘传招处理器或 MILKDRINK／SOFTBOILED；蛋不插入。

物品子菜单由 `:party_menu_item` 生成（默认：Use 10、Give 20、Take 30（持有物品时）、Move 40（持有物品且非邮件）），末尾追加 Cancel。

### 4.2 菜单命令效果

| 命令 | 条件 | 效果与写入 |
| --- | --- | --- |
| Summary | 总出现 | 打开该成员摘要（§5）；关闭后刷新队伍面板 |
| Debug | $DEBUG | 打开调试成员界面（调试功能，不计正常范围） |
| Switch | 队伍>1 | 进入 §3.3 换位置两段流程 |
| 场地招（蓝色） | 已知秘传招且有处理器 | 先经可用性检查（WP59 规则，可显示拒绝消息）；通过后请求确认；**FLY 特例**：确认后先打开地图飞行目标画面（WP63 前向）——选定目的地则写入飞行目的地并整体返回 `[成员, FLY]`，取消则重组队伍界面留在主循环；其它秘传招确认后直接整体返回 `[成员, 招]`，由调用方在界面外执行 |
| 场地招（奶招） | MILKDRINK／SOFTBOILED | 用量 `amt = max(floor(totalhp/5), 1)`；自身 hp ≤ amt 时拒绝（「Not enough HP...」）。进入目标选择循环：不能对自己使用、目标是蛋拒绝、目标濒死或满血拒绝；合法目标：来源 hp −= amt，对目标执行 HP 恢复写入（WP28）并显示恢复量。循环在取消或来源 hp ≤ amt 时结束；期间每次合法使用后刷新 |
| Mail → Read | 成员持邮件 | 打开邮件阅读画面（§4.5） |
| Mail → Take | 成员持邮件 | 取回写入（§4.4 取回分支） |
| Item → Use | 子菜单总出现 | 打开内嵌背包选择画面（过滤见 §4.3），选定后对成员执行使用写入（§4.4 使用分支） |
| Item → Give | 子菜单总出现 | 打开内嵌背包选择画面（过滤 `can_hold?`），选定后执行给予写入（§4.4 给予分支） |
| Item → Take | 持有物品 | 取回写入（§4.4 取回分支） |
| Item → Move | 持有物品且非邮件 | 持物换位循环（§4.4 移位分支） |

### 4.3 内嵌背包选择画面（WP66-C 画面借用）

- **给予过滤**：仅 `can_hold?` 的物品可选（WP27 规则）。
- **使用过滤**：须为有「对成员使用」处理器或是机器；Hyper 有效成员额外只放行香类（is_scent?，WP23）；机器额外排除成员已会该招与成员不兼容该招（WP30 规则）。
- 两画面都在队伍界面上层淡入淡出打开，取消返回 nil（不写任何东西）。
- 注解维护：进化石类使用入口（WP28）先按成员逐个预演资格并给出 ABLE／NOT ABLE 注解打开队伍画面；使用后由调用方重算注解（ableProc 再评估）或清空注解并整屏重建面板。注解仅为显示，选择时不强制（选择合同见 §3.3）。

### 4.4 持物／邮件的真实写入（WP27／WP28 规则引用，此处登记触发点与顺序）

| 分支 | 门与顺序 | 写入与失败 |
| --- | --- | --- |
| 给予 | 蛋拒绝；成员已有邮件须先成功取回邮件；已有持物时询问是否交换两件 | 成功：背包减一 → 成员持物改写；交换时旧物回背包；邮件物品须先完成写信（自由文本至多 250 字；写作途中可确认放弃）才改写持物。背包满无法回收旧物时失败并保持原状（含防御性异常分支）。**交换给予邮件的放弃顺序（WP66A-R01 查明）**：确认交换后**先**背包减新邮件、**再**旧物入背包、**然后**进入写信；写作放弃时新邮件回背包（无法回包为防御异常），但**已入包的旧物不回撤、成员仍持原物、给予返回 false**——背包旧物计数净 +1，不是全有全无事务。成员原持邮件时先走取回链（可能已把原邮件存入信箱），后续给予或写作再被取消/失败时，**先前的信箱入库与成员清空同样不回滚**。成功后刷新该面板 |
| 取回 | 未持物提示；背包满拒绝 | 非邮件：物品入背包、成员持物清空。邮件：先询问「存到 PC？」——邮箱未满（容量 10）则邮件入邮箱、清空成员邮件与持物；邮箱满提示失败；选择不存则再确认「消息将丢失」——物品入背包、成员邮件与持物都清空 |
| 使用（机器） | Shadow 拒绝、不兼容拒绝；先播放开启消息再请求确认 | 确认后走 §7.1 学习流程；学会且物品为消耗型才从背包扣除（默认机器非消耗，WP28） |
| 使用（其它） | 数量上限处理器与库存取小；>1 时弹出数量选择 | 触发使用处理器（WP28）；返回真且消耗型才按量扣除；用完最后一份有提示；结束后清注解并整屏重建 |
| 移位 | 目标蛋拒绝；目标无持物直接移入；目标持邮件须先取邮件；目标有持物先告知再询问是否交换 | 来源与目标持物字段互换或单向移动；成功后显示双方结果消息；取消或未移动时选中回到来源面板 |

**给予画面（背包 Give 入口）**：打开给予模式 → 选定成员即执行上述给予分支 → 刷新该面板并关屏，返回是否成功。**邮件给予画面（PC 邮箱入口）**：成员已有持物或已有邮件 → 「持物中不能持邮件」；蛋 → 「蛋不能持邮件」；否则邮件对象写入成员、成员持物设为该邮件物品、邮箱删除该封，显示「Mail was transferred from the Mailbox.」。

### 4.5 邮件阅读画面

显示邮件卡片图（按邮件物品决定）、正文与发件人（按背景明暗自动选择文字配色）；图鉴邮件（is_icon_mail?）附带快照成员图标：写信时记录的至多三组 [物种, 性别, 闪光, 形态, Shadow, 蛋] 快照，次序为**持有者之后第二名成员（存在时）、之后第一名成员（存在时）、持有者本人**（WP66A-C02 纠正后的次序；阅读画面按 poke1／poke2／poke3 依次绘制）。USE 或 BACK 关闭；无任何写入。邮件数据模型与邮箱归属引用 WP64。

### 4.6 借用选择器与多选入场

- **资格选择**：资格处理器**只在打开画面时对每位成员求值一次并缓存**（WP66A-R07 查明：连续选择同一不合格成员不会再次调用处理器）；注解显示 ABLE／NOT ABLE；选择不合格且未允许时提示并留在选择循环。交易资格选择同样按打开时快照工作；进化石注解是另一条**显式刷新**路径（使用后由调用方重算，§4.3）。事件助手族：选择任意成员、选择非蛋成员、选择非蛋且 hp>0 成员、选择可交易成员、按指定物种选择可交易成员；结果写入事件变量（索引与名字，未选为 -1 与空串）。**交易助手分四种前提**（WP66A-R02）：默认助手不给资格处理器时走普通成员选择，**不叠加**拒蛋／拒 Shadow／拒 cannot_trade（这些成员可被返回并写名）；给处理器时在其结果上叠加三项拒绝；显式允许不合格时可接受 NOT ABLE 选择；按物种助手因提供处理器而走过滤路径。
- **多选入场**：打开前先校验规则集存在有效队伍（WP66A-R08：按规则的**最少**人数计，合格数不足即不打开），无则直接返回 nil 不开画面。打开后每位成员注解初始为 NOT ENTERED（合格）或 BANNED（不合格）；对合格成员可 Entry（按选择先后分配位次注解 FIRST、SECOND…，达到规则人数后再 Entry 提示上限）、No Entry 撤销回 NOT ENTERED；每次操作后重排实际位次；达到规则人数且本轮有新增时自动把游标移到 CONFIRM。CONFIRM 提交按位次排列的成员数组给规则集校验，失败显示第一条错误并继续；BACK／CANCEL 返回 nil。

## 6. 摘要界面：交互、选项与标记写入（E）

### 6.1 招式选择（MOVES 页 USE）

进入招式选择：游标在已有招式间循环（数量不足 4 时夹到末招）；随时显示所选招式的类别、威力（0 显示 ---、变量威力显示 ???）、命中（0 显示 ---）与描述。**USE 开始换位**：来源招出现预选光标；再 USE 另一招则**直接交换成员 moves 数组两项**（立即写入，含 PP 与提升计数随招式对象移动）并重绘；BACK 或 USE 第 5 槽位（学习模式的额外槽，纯查看选择中实际不可达）取消换位。**Shadow 成员禁止招式换位**（USE 不进入换位态）。BACK（无换位态）退出选择。

### 6.3 标记画面（选项菜单 Mark）

六槽标记编辑（3 列 × 2 行）＋ OK＋Cancel：USE 将该槽标记循环到下一变体（变体总数由标记图形资源决定，代码按位取模；显示按槽值与变体上限取小）；ACTION 将非空槽清零；BACK 或 Cancel 放弃编辑；OK 提交。**只有编辑结果与原标记不同才写入成员 markings** 并返回「已变更」（调用方据此刷新）；取消不写。编辑画面打开时总是基于当前标记的副本工作。

## 7. 学习／替换与重学流程（F）

### 7.1 教学流程（pbLearnMove 合同）

1. 目标为蛋且非调试 → 消息拒绝，false；目标为 Shadow → 消息拒绝，false。

4. 满 4 招：先提示想学，再询问「忘记一招来学习？」；拒绝则「未学习」false。同意则进入 §6.5 遗忘画面选招：
   - 选定：记录旧招名与旧 PP，**以新招式对象整体替换该槽**（PP 重置满、提升计数 0）；仅当机械教学且配置「机械保留旧 PP」（默认关，世代 5 专属）时，新 PP 改为 min(旧 PP, 新上限)。播放遗忘与学会消息；机械教学追加友好度「machine」变化（WP30）。true。

### 7.2 机器使用入口（两条路径分开，WP66A-R06）

- **背包使用机器**（WP28 的 UseFromBag 机器处理器）：先播放「开启机器」消息并确认「要教这只招吗」，**然后**打开带注解的成员选择（注解逐成员求值：蛋＝NOT ABLE、已会＝LEARNED、兼容＝ABLE、否则 NOT ABLE）；**选定后才逐项检查**——蛋拒绝、Shadow 拒绝、不兼容拒绝（均留在选择循环），通过才按 §7.1 学习。取消（BACK）直接退出、**不消耗**机器；**学会才**累计机器教学统计（moves_taught_by_item）、TR 额外记录最初招式（add_first_move），随后消耗型机器才扣除（默认 TR 一次性、TM 非消耗，WP28）。

## 8. 规则与不变量

- 选择合同以返回值分层：成员索引 ≥0、-1 取消、`[1, 索引]` 快捷换位、`[成员, 招]` 秘传招提交、成员数组（多选入场）或 nil；调用方据此行动，界面自身除 §4／§6 具名写入外不产生副作用。
- 换位置（队伍）与招式／缎带换位的**动作写入**都是两次选择后才发生；取消即无动作写入。限定：**菜单 Switch 目标选择中经 SPECIAL 进入盒子后已提交的盒子侧修改不回滚**（WP66A-R03；快捷换位禁用 SPECIAL，无此例外）。
- 给予／取回／使用先过领域门再写入；具名门失败保持原状并给消息（背包满、邮箱满、蛋、Shadow、不兼容、HM 遗忘限制）。**例外（WP66A-R01）**：邮件／持物给予链不是事务——取消写信或后续失败时，已完成的变化（旧物入包、原邮件入信箱、成员清空）不回滚，实际余额按 §4.4 与 §9 的真实顺序记录。
- 摘要的一切显示都是只读派生，除 §6 具名写入（招式换位、缎带换位、标记、选项菜单的给予／取回）外不改成员状态。
- 注解仅显示，不构成资格保证；资格处理器**在打开画面时求值一次并缓存**（WP66A-R07），选择时读取缓存结果，仅在显式刷新路径（如进化石使用后）重算。
- 蛋的交互子集：可被选中、可看摘要（单页）、可标记；不能持物、不能学招、不能邮件、无菜单物品／邮件命令、不能作为奶招目标。

## 9. 边界与失败

- 空队伍：暂停菜单项不出现（条件队伍成员数 >0）；借用选择器在空队伍上 RIGHT 回绕到取消位；给予画面／背包使用在空队伍由调用方先拦（WP28/WP66-C 登记）。
- 全蛋队伍：蛋可被选择与标记；物品／邮件命令不生成；学习拒绝。
- 单人队伍：Switch 命令不生成（条件队伍 >1）；快捷换位 ACTION 仍可按合同返回请求（其目标选择禁用 SPECIAL，第二段前无其它写入）。
- 背包满取回、邮箱满存邮件、交换两件时旧物无法回背包：均失败且原状保持（后者为防御性异常，正常流程不可达，具名保留）。
- **邮件给予链的部分提交（WP66A-R01）**：(a) 交换给予邮件后写作放弃——新邮件回背包、**已入包的旧物不回撤**（背包旧物净 +1）、成员仍持原物、给予 false；(b) 先取原邮件入信箱成功后再取消后续给予／写作——信箱入库与成员清空不回滚。两条都不是全有全无事务。
- 多选入场：合格数不足规则最少人数时不开画面返回 nil（WP66A-R08：固定 3 人时 2 合格 1 不合格即此前置失败）；提交校验失败显示首条错误并留在画面。
- 重学候选为空：若进入该画面，首绘严格ID校验失败，尚未进入选择循环；没有取消返回或学习写入。至少一合法候选的BACK才进入正常放弃确认。
- 秘传招可用性检查带消息（WP59）；确认失败留在主循环。**FLY 取消（WP66A-R05）**：领域数据未提交（不写飞行目的地），但调用方重组队伍界面时未携带本次存储访问许可、选中位重置为面板 0——本次 Box Link 桥失效（提示消失、SPECIAL 无效），退出整个队伍界面重开才重新按三条件计算。
- 从盒子返回（Box Link 桥）：注解按面板索引恢复；选中位超出剩余队伍长度时夹到末位，无有效旧选择落到取消位（WP66A-R09）。
- 奶招循环中来源 HP 降到阈值以下即自动结束循环；期间任何目标拒绝都只是消息，不写状态。
