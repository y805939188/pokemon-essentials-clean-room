## 1. 目的、范围与非目标

**目的**：固定调试情境与控制的规则合同——**调试能力从哪些入口可达、各自可见性门是什么、每个命令读什么输入、写什么状态、给什么反馈、失败与取消走哪条路、即时效果与持久归属如何分层**。后续包据此判断"某个调试动作实际改变了什么"，而不是各自重新追踪七份调试菜单文件。调试实现是作者行为要求的参考，不作为未来框架的交互设计模板。

**范围**（WP72 自身声明范围）：

1. WP72-A：调试入口、菜单可见性与交互——地图热键、暂停菜单命令、载入界面受限菜单、队伍/存储个体调试、构造测试战斗时的个体调试、战斗命令热键、战斗内成员/队伍入口；菜单框架的层级/返回/根取消/默认选中与刷新/命令返回值关闭语义；`always_show` 三态、上下文用途过滤与可用处理器筛选。
2. WP72-B：世界情境与会话状态控制——地图传送、开关/变量编辑、地图刷新、场地效果、寄养调试、漫游编辑、Safari/捕虫计数、遭遇版本、训练家重置、Exp All、战斗日志开关、片尾跳过、Shadow/净化室访问各入口。
3. WP72-C：玩家、队伍、存储与背包操控——货币/徽章/图鉴与地区图鉴/跑步鞋/Pokégear/电话联系人/Box Link/角色/外观/名字/ID；治疗、添加个体、填/清盒子、示例队伍、蛋快速孵化、打开存储；加道具、填充/清空背包。
4. WP72-D：个体诊断与编辑（非战斗）——HP/异常/治疗/濒死/Pokérus、等级/经验/EV/IV/个人 ID、友好/华丽六维、招式/PP/初始招式、物品/特性/性格/性别/物种/形态、闪光/球/缎带/昵称/所有权、丢弃许可、蛋、Shadow 与心量表、Mystery Gift、复制与删除。
5. WP72-E：测试战斗及战斗内观察/编辑——普通/高级野生与训练家测试的构造与校验；战斗内双方在场者、速度顺序、队伍、训练家资源、Mega 配额、天气/场地/环境/时间/背景；场/阵营/席位/成员四层效果观察与编辑；成员 HP/状态/能力值/类型/招式/物品/特性/性格/性别/形态/物种/Shadow 的双层（原个体 vs 战斗当前）编辑。
6. WP72-F：日志、持久性与后续工具边界——观察与修改分列；运行标志与调试标志共同门；临时战斗态/运行中持久对象/显式文件写出/编译输出分层；通往 WP73-A/B、WP74、WP75、WP76、WP64、WP77 的工具入口登记与归属。

**非目标**：

- 不提取编辑器主体（WP73-A/B 主责）、动画编辑/组织/导入/导出（WP74）、文件更名/编译/文本抽取/工程与事件转换（WP75）、设施生成/模拟（WP76）、demo 事件编排（WP77/U01）。WP72 只完整登记通往这些工具的**入口、条件、即时副作用和归属**，不宣布工具内部已完成。
- 不重提取已通过规则：正常遭遇/捕获/结算（WP36/WP42/WP38）、战斗上下文（WP39/WP40）、AI 评分（WP51）、个体底层规则（WP18～WP23/WP25～WP35）、净化室合同（WP23）、漫游（WP37）、Safari/捕虫（WP53）、时间/场地（WP59）、野外被动与回程（WP61）、Mystery Gift 领域（WP64）。
- 不运行参考实现/游戏/UI/测试战斗/随机模型/编译器/导入导出/保存转换，不操作真实存档，不访问网络，不设计未来 API 或把参考类组织当作未来模块。

## 2. 概念与术语

- **调试标志（`$DEBUG`）与运行标志（`$INTERNAL`）分层**：`$DEBUG` 由宿主环境给定（RPG Maker 测试运行语义；WP01/WP07 引用），是全部调试入口的总门；`$INTERNAL` 是**运行中可切换的内部标志**——当前基线唯一的写入者是调试菜单的战斗日志开关（§8.1），读取者是日志模块（与 `$DEBUG` 共同门）与异常打印长度选择（`001_Technical/001_Debugging/003_Errors.rb`）。**两者独立**：入口可见性只看 `$DEBUG`；日志输出要求两者同真。
- **菜单注册与可用筛选（MenuHandlers，WP05 事件分发引用）**：命令以菜单名＋选项 ID 注册为哈希（名称/父级/描述/条件/效果等键）；**可用筛选**按 `order` 键（缺省按注册序号）排序、逐个执行 `condition` 条件（无条件的调试主菜单注册项不设 condition——`$DEBUG` 门在**入口调用侧**，不在注册项上）；名称可为取值 Proc 或静态文本。**`always_show` 三态**：未设置（nil）／显式真／显式假——**受限模式只排除显式假**（未设置与显式真都保留），§3.2。
- **命令菜单列表（CommandMenuList 框架）**：层级菜单——每个命令记录父级；`list` 给出当前层命令名；`hasSubMenu?` 判定是否可下钻；`getParent` 返回父层 ID 及当前层在父层中的下标（用于返回时恢复光标）；描述缺省回落"<No description available>"。**返回父级**（BACK 且存在父级：取消音效＋切回父层＋光标恢复到该层在父级中的位置）与**根取消**（BACK 且无父级：整体退出）分开；**效果返回值关闭语义**——个体调试菜单中效果返回真即退出整个调试菜单（复制/删除用此关闭）；地图调试菜单中 `:warp` 特殊——效果返回真才关菜单（先清理自身窗口/视口再转移，§4.1）。
- **原个体与战斗当前两层（R07 修订）**：战斗内编辑同时面对**原个体对象**（pkmn——队伍/盒子中的持久数据）与**战斗当前状态**（battler——在场派生层）。**写入器写穿**：在场对象的 **HP、状态、状态计数、道具、等级、形态**的写入器会**同步写回原个体**（状态写入器还重置相关计数并刷新场景——WP40 引用）；**战斗特性、能力阶段、能力值、类型、效果、Mega 配额等是战斗层**（不写回原个体）。各命令**按名选择写哪一层**（§7.4 逐项）；不存在"改了原个体就自动同步战斗层"或反向的通用保证；退出战斗调试后由战斗命令阶段执行一串**刷新回调**（§7.6），仅这些具名回调，不虚构全面重同步。**持久性推论**：写穿层的改动落在持久对象上（战后保留——WP39 生命周期引用）；战斗层改动随战斗结束消散。
- **用途过滤（`usage`）**：战斗个体调试菜单的命令带 `:pokemon`／`:battler`／`:both` 用途——有 battler 时排除 `:pokemon`，无 battler 时排除 `:battler`（在场成员与不在场队伍个体看到的命令集不同，§7.4）。
- **构造测试 ≠ 沙盒**：测试战斗走正常生成/战斗/捕获/结算入口（WP36/WP39/WP42 引用）——其真实副作用（图鉴登记、经验、拾取、传播、统计等）按正常规则成立；调试侧只负责候选构造与规则实参（`canLose`、遭遇类型清空、人数布局）。
- **观察与修改分列**：仅展示（速度顺序、成员/队伍信息、效果当前值、寄养/漫游状态行）与写入（数值/开关/对象编辑）分开登记；观察行的"当前值"是读取时刻快照，不承诺实时刷新（各界面按自身 refresh 时机）。
- **持久归属分层**：**临时战斗态**（battler 层与战斗设置——**按字段分层（R07 v3）：写穿层字段（HP/状态/状态计数/道具/等级/形态）落在持久个体上、按其后续正常生命周期演化（WP39/WP42 引用）；仅战斗层字段（战斗特性/能力阶段/能力值/类型/效果/Mega 配额等）随战斗结束消散——不声称所有在场编辑都消散**）；**运行中持久对象**（`$PokemonGlobal`/`$player`/`$bag`/`$PokemonStorage`/`$game_switches`/`$game_variables`/`$game_map`/`$game_temp` 上的改动——随存档保存的部分按 WP09 归属，其中 `$game_temp` 为运行临时）；**显式文件写出**（动画导入导出、修复图块写地图文件、PBS 生成、编译、日志追加——各自的立即落盘语义按条登记）。**调试改变值 ≠ 正常事件调用 ≠ 会话重新初始化**；菜单效果完成后**不自动落盘存档**（保存由正常保存入口负责，WP09/WP10）。
- **已通过边界（必须继承，不重开）**：WP61（野外被动与回程——含 Pokérus 调试三动作合同与净化室惰性取用）、WP53（Safari/捕虫，当前字节 `75fc4db7`）、WP37（漫游，当前字节 `d032f5b7`）、WP23（Shadow/净化）、WP36/WP39/WP42/WP38（遭遇/战斗上下文/终局/捕获副作用）、WP24～WP28（玩家/存储/背包）、WP30（友好数值）、WP33/WP34/WP35（寄养/育种/孵化）、WP59（时间/场地）、WP64（Mystery Gift）、WP65（载入/暂停 UI 框架）、WP67-A/B、GR-001～016、WP23-N01。

### 3.2 可见性三态与菜单交互（`001_Debug_Menus.rb:4–146`）

- **完整 vs 受限**：`pbDebugMenu` 的 `show_all` 形参——为假时**只排除 `always_show` 显式假**的条目；未设置（基线中 PBS 编辑器、其它编辑器、文件选项等菜单节点）与显式真（基线中无）都保留。**基线显式假的条目**：Field options…、Battle options…、Pokémon options…、Item options…、Player options… 五个顶层分组节点（其子项随父级不可达而整体不可见——可见性沿父级链，不是逐条打标）。
- **个体调试菜单的构造测试模式**：`settingUpBattle` 为真时同样**只排除 `always_show` 显式假**——基线显式假的个体条目：**Set egg、Mystery Gift、Duplicate、Delete**（构造测试时这四项不出现；§6）。
- **交互合同（按菜单家族区分，R02 修订）**：USE——有子菜单则下钻（决定音效、光标归零）；无子菜单则调用效果；BACK——有父级返回父级（取消音效、光标恢复到当前层在父级中的下标）；无父级退出。**描述求值时机**：命令清单（含描述 Proc 的求值）在**进入菜单时收集一次**——**下钻/返回父层只切换当前层与窗口命令名，不重新运行描述过程**（R02 v3 对照：进入一次菜单后往返层级，动态描述依赖值变化不触发重新求值）；光标移动只用已存文本刷新描述行，**不随光标移动重新求值**。**退出清理按家族分开**：地图调试菜单根退出带关菜单音效＋**淡出**＋释放窗口/视口；战斗调试菜单根退出为关菜单音效＋释放（**不走相同淡出链**）；特殊传送（`:warp`）的整体关闭属于地图菜单（§4.1）。开关/变量页是**独立子屏幕**（§4.2——BACK 关闭子屏幕回到菜单，不算菜单内层级）。
- **命令返回值何时关闭菜单（R02 v3）**：**地图调试菜单**——普通效果返回值被忽略（菜单继续）；**仅 `:warp`**（**仅存在于地图菜单**）的效果返回真时整体返回（其效果内部先完成自身窗口/视口清理与转移准备，§4.1）；**战斗调试菜单——普通效果返回值均被忽略，无特殊传送分支**。**个体调试菜单**——效果返回真即退出（基线中 Duplicate/Delete 返回真：编辑完成后整单关闭并回到底层界面）；取消在顶层且无父级时退出。

### 4.2 开关与变量（`:switches`/`:variables` → `pbDebugVariables` 以实参 0/1 调用；`003:44–227`）

- **开关页（mode 0）**：列出名表条目。USE 只翻转当前 ID 的原始开关并请求地图刷新，随后页面刷新重新求值，不编辑表达式文字。独立常量表达式的结果可保持不变；表达式若读取被翻转的同一原始开关，则显示可随之改变。合法表达式前提下，ID 1 原始值 false，名称为 ASCII `s:` 后接以非字母开头的同 ID 读取表达式，USE 后原始值 true、显示 OFF→ON；独立常量真则翻转前后均 ON。前缀必须为小写 ASCII s 与 U+003A 冒号；全角 `s：` 不识别为表达式，常量真且原始值 false 时按普通开关显示 OFF。求值异常回落空值、显示 [-]，真/假显示 ON/OFF；既有求值资格门保留。
- **变量页（mode 1）**：名表逐项显示，LEFT/RIGHT 对数值±1（空先归0、夹±99,999,999）；USE 数值最多8位并允许负号、字符串最多250字符，其它类型无编辑。ACTION 按有序互斥分支处理：0→空字符串；空字符串→0；其它数值→0；其它字符串→空字符串；其它类型保持原值。每次请求地图刷新并刷新页面。连续两次 ACTION 从 0 得到空字符串再回 0；从 7 得 0，再按一次才得空字符串；从非空文字得空字符串，再按一次才得 0。USE 根据随后值的类型进入数值或文本输入，不能把 0→空串解释成同类型归零。
- **开关/变量上限**：包装类读写均限 **ID ≤ 5000**（读越界得 false/0，写越界忽略——`002_Game_Switches.rb`、`003_Game_Variables.rb` 全文）。

## 10. 边界、失败与未知

- **取消约定（R03 修订）**：数值输入的取消返回值分两类——**显式设置取消值的入口**（BACK 返回该值：0/−1/当前值，调用方按约定处理）；**未设置取消值的入口**（**BACK 返回钳制后的默认值——与按 USE 接受默认值不可区分，调用方随后若无条件写入，状态仍可能改变**）。三个可达对照：①非战斗睡眠计数（默认 3、无独立取消值——**选 0 才取消；按 BACK 返回默认 3，仍赋予睡眠 3 回合**，§6.1）；②寄养"其它值"（以原计数为默认值、无独立取消值——**BACK 返回原计数后仍按 256−输入换算写入：计数 5 时 BACK 使计数变 251**，§4.4）；③所有权"设外来 ID"（以公开 ID 为默认值——**BACK 返回公开 ID 后仍执行完整 ID 合成：低半区 12、高半区 99 时 BACK 使两半区均 12**，§6.5）。普通独立选择取消不提交其目标；寄养与遗迹石仍按§4写入事件变量并请求刷新；传送取消 → 返回假菜单继续；测试战斗 BACK → 放弃集合（**已发生的生成/加载副作用不回退**，§7.1）。**不承诺任何确认对话框的默认选择**（除文中具名）；**不作全局"取消不写"保证**——以各入口逐项注明为准。
- **容量与拒绝**：队伍/存储全满（添加个体/复制/领取蛋/取出）；盒子满（复制入盒）；口袋容量 0/满（填充背包跳过）；物种数 > 存储容量（填盒部分完成＋附注）；满四招（Teach 提示）；最大等级（Set Exp 提示）；单形态（设形态提示＋重置确认）；单性别（设性别提示）；非 Shadow（心量表提示）；战斗层最大 HP 1（Set HP 拒绝）。**均按实际消息登记，不补事务撤销**。
- **直接调用的有界前提**：各公开函数（`pbDebugMenu`/`pbPokemonDebug`/`pbBattleDebug` 等）可被脚本直接调用——**此时不走入口侧 `$DEBUG` 门**；其行为合同不变（菜单框架与效果逻辑相同），但**可达性结论只对 §3.1 入口成立**。
- **不写盘承诺**：除 §8.2 具名文件写出外，调试编辑**不触发自动保存**；`$game_temp` 改动不持久。
- **异常路径**：动画**导出**整体 rescue → "The export failed."式消息；动画**导入**只有逐项解码局部回落（无整体兜底，R14）；效果编辑器遇未知值类型 → 抛异常（防御）；求值型开关显示异常 → 回落 nil（"[-]")。**不虚构其它异常兜底**。
- **未知/未证**：宿主 `$DEBUG`/`$INTERNAL` 的实际环境与注入时机（WP01/WP07）；无视觉场景模拟内部（WP76）；各编辑器/工具内部（WP73-A/B、WP74、WP75）；demo 事件链与真实调试使用编排（WP77/U01）；随机源实际序列；批量填盒/填包的实际运行耗时。
