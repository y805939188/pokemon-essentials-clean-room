## 3. WP08 修订项

### WP08-R01 [P1] 混淆默认消息、当前语言的 game/core 层及实际内容键

**位置**：WP08:36–39、50、59、68–72、98、106、131。

**证据**：`S/001_Technical/003_Intl_Messages.rb:492–545` 有四组不同材料：默认 core/game 用于收集和导出；当前所选语言的 core/game 由另一入口载入。查找 589–631 行先查**当前语言的 game**，再查**当前语言的 core**，不在两者未中时再查默认数组。地图顺序为“当前语言 game 的目标地图→game 的 0 桶→当前语言 core 的目标地图→core 的 0 桶”。

主启动 `S/003_Game processing/001_StartGame.rb:31–33` 直接调用 load_message_files，实际立即载入；延迟加载是 Translation 构造参数支持的另一条路径，不能把默认游戏启动写为首次查找才加载。

物种名、招式名也不是当前基线中的数组索引例子：`S/021_Compiler/002_Compiler_CompilePBS.rb:228,377` 用 setMessagesAsHash；`S/010_Data/002_PBS data/008_Species.rb:225`、`005_Move.rb:67` 按 real_name 文本查哈希。保留“通用数组查找接口存在”，但不要由域编号推定域内身份形态。

**影响**：缺译、游戏覆盖核心译文、默认语料和真实内容消费者的预期都会错误。

**最小修订/验收**：区分四组消息的用途及主动/延迟载入；以同一键在语言 game/core 中均存在、仅 core 存在、两者均缺但默认语料存在为向量。第三种哈希查找回原文，不自动取默认语料。补四层地图优先级和物种/招式哈希键的真实消费者证据。

### WP10-R02 [P1] 转换备份不是原文件逐字节复制，路径也不随读取路径变化

**位置**：WP10:37、64、73、106、135–138；WP09:118 引用。

**证据**：`003_SaveData_Conversion.rb:195–209` 将**传入的内存 Hash**序列化到固定 `SaveData::FILE_PATH + '.bak'`。`001_SaveData.rb:43–48` 则把成功转换后的结果写回参数 file_path。转换备份与紧急保存中逐块复制原文件是不同操作。

从自定义路径读档时，备份仍在固定保存路径旁；从固定 `.bak` 读档并发生转换时，转换前备份与后续写回还可能指向同一个 `.bak`。不能一概承诺原旧档在旁边以原字节保留，或备份载入后一定修复主文件。

**最小修订/验收**：分别列内存对象快照和原文件字节备份，注明源路径/目的路径、覆盖时机及失败中断。以读取路径等于默认、等于默认 `.bak`、与默认不同三种情形作静态路径表；无转换时不写转换备份，有转换并全部成功才到参数路径写回。真实磁盘写入失败结果继续未验证。
