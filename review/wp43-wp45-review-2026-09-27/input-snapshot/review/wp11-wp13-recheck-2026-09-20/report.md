## 3. WP11-R02 [P2，剩余范围] 缺图可能在 setup 前失败

**被审位置**：WP11 `ac090bc1`：72、120、148。第 120 行及缺图场景把失败描述为 setup 已清空地图集合；第 72 行虽然列出音乐处理，却未区分该阶段也会读取目标地图。

**本轮源码证据**：`S/003_Game processing/002_Scene_Map.rb:56–60,72–81`。只要已有 BGM 或 BGS，autofade 就先读取目标地图文件。它在清桥、清阴影和工厂 setup 之前调用。无 BGM/BGS 时跳过该读取，才可能到达 `S/004_Game classes/005_Game_MapFactory.rb:17–26` 的重建阶段。显式传送没有 Game.load_map 的缺图恢复这一修正仍成立。

**影响**：同一缺图输入，在两种音频状态下留下的地图集合、桥及通知状态不同。现有失败预期会把未发生的清空/重建当成既成事实。旧报告强调 setup 先清集合也需以“已到达 setup”为前提；本轮明确收紧这一点。

**最小修订**：仅按实际失败点区分副作用；保留已正确的四入口和生命周期，不重做地图包。同步失败条目和测试场景。

**静态验收**（其余先行调用正常、无自定义回调改变流程）：

1. 非空旧地图集合、桥高度 2、已有 BGM 或 BGS、目标文件缺失：传送标记和载具处理已经发生；在 autofade 读取失败，尚未清桥/阴影或 setup，旧地图集合仍在，尚无本次 setup 的 leave/enter 通知。
2. 同样缺图但 BGM/BGS 均为空：跳过 autofade 读取，经过清桥/阴影后到达 setup；若失败发生在目标图读取，则旧集合已被替换并已有相应前置副作用。不是“失败一定无变化”，也不是“失败一定已清地图”。
