## 1. 目的、范围与非目标

**目的**：固定野外被动效果与失败回程的规则合同——**哪些入口计步、计什么、按什么次序产生什么效果、病毒如何随日期推进、失能后按什么顺序回到哪里**。后续包据此判断"某一步会发生什么、某次回城先做了什么"，而不是各自重新追踪两份主域文件。

**范围**（WP61 自身声明范围）：

1. WP61-A：触发、计数与效果次序——普通玩家迈步、强制路线/事件解释器移动、原地转向、主动遭遇请求及地图帧更新的入口差别；全局步数的累计/边界；步进与帧通知的消费者注册/调用次序及 handled 门。
2. WP61-B：行走友好度——步数累计、周期门、参与成员集合、逐个随机门、计数重置、空/全不合资格队伍、正值修正与封顶消费（数值只引用 WP30）。
3. WP61-C：野外中毒与全队失能——默认设置与更代/配置变体；计数周期、已处理门、成员资格、免疫特性、音效/闪烁次数、HP 损失、临界 HP 清状态或濒死、友好度更新、全队可战数量检查和回程交接；逐成员处理内发生治疗/转移之后的剩余循环。
4. WP61-D：Pokérus 状态与日期推进——菌株、未感染/感染期/已治愈、剩余期限；赋予/重设期限/降低期限/治愈/重复赋予的许可和统计；每帧日期比较的门与更新时间；各来源（野外生成/育种/战斗终局传播/每日自然变化/调试修改/治疗点解释查询）的分列。
5. WP61-E：治疗点、治疗与失败回程——最近中心记录、地图元数据更新的场地回程目的地、洞穴逃脱点、角色/全局家地点的写入/消费/优先级/清空；恢复入口（个体/队伍/事件"全部恢复"）的实际覆盖；野外全队失能、普通战斗败/平且不可败、可败剧情战斗、事件 Game Over、捕虫大会特殊回程的分流；统计/治疗/消息/载具/跟随者清理/开关/转移参数/场景门/刷新/逃脱点清空的真实顺序。
6. WP61-F：集成、持久、开发者入口与证据边界——步数/友好计数、病毒时间、三类地点、统计和开关的持久归属与初始化；普通当前版本载入与版本转换分开；调试直接修改按非默认路径标注；PBS/编译器模板与实际运行可达分开。

**非目标**：

- 不定义普通遭遇算法（候选层/触发率/Repel 门/双打，WP36 主规格）、友好度数值与影响全集（WP30）、战斗终局/钱款/资源结算（WP42）、场地招式与道具合同全集（WP59/WP28）、寄养/育种/孵化合同（WP33/34/35）、Shadow/净化合同（WP23）、漫游/雷达合同（WP37）、Safari/捕虫合同（WP53）。
- 不展开地图事件编排/治疗点解释/费用话术——只能按实际可读证据登记（U01/WP77）；脚本提供入口不等于默认事件确实调用。
- 不运行游戏/战斗/UI、不操作真实存档、不播放音频、不执行编译器或反序列化、不设计未来 API 或把参考类组织当作未来模块。

## 2. 概念与术语

- **步进入口四分**：**普通玩家迈步**（玩家完成一步→`pbOnStepTaken`）；**强制路线/事件解释器移动**（玩家处于强制路线或地图解释器运行中完成移动——**只发 `:on_step_taken` 通知，不计全局步数、不发玩家步进钩子、不判定遭遇**）；**原地转向**（`:on_player_change_direction`——可判定遭遇但不计步）；**地图帧更新**（`:on_frame_update`——每帧一次，含微更新路径，WP53 已证暂停命令循环链）。**GR-011（已关闭）**的入口差别保持：步进、转向、主动请求是不同入口，主动请求包装本身不写遭遇触发标记。
- **全局步数（`stepcount`，持久于全局元数据）**：仅在普通玩家迈步时 +1（31 位回绕）；**计数初始化**：首次迈步前惰性为 0。各消费者读自己关心的周期（友好周期 128、毒伤周期 4）；**不因消费者重置全局步数**（友好度用的是独立计数 `happinessSteps`，§4）。
- **handled 门（`on_player_step_taken_can_transfer`）**：handled 是单槽数组——**任一消费者触发转移后置真，后续消费者与当步遭遇判定不再执行**（中毒全队失能、Safari 计步回起点）。
- **三类目的地状态（互相独立、不是同一份状态）**：**最近中心记录**（`pokecenterMapId/X/Y/Direction`——由接待/中心事件写入，编译模板证明其构造能力，U01）；**场地回程目的地**（`healingSpot`——进入带回程目的地元数据的地图时**覆盖写入**，由 Teleport 消费、**使用后不清空**）；**洞穴逃脱点**（`escapePoint`——洞穴入口写入、洞穴出口/逃脱类入口/失败回程**使用后清空**）；**角色/全局家地点**（角色元数据 `home` 与全局元数据 `home`——静态数据，Teleport 与失败回程的回退）。
- **Pokérus 编码（个体字段，独立数学）**：单整数字段——**菌株 S = 高 4 位（⌊字段/16⌋），剩余期限 T = 低 4 位（字段 mod 16）**；**阶段**：字段=0 → 未感染；T>0 → 感染期（1）；T=0 且 S>0 → 已治愈（2）。**期限由菌株决定：T = 1 + (S mod 4)**（1–4 天）。
- **持久 ≠ 已落盘**：全局元数据随存档保存（WP09）；`stepcount`、`happinessSteps`、`pokerusTime`、三类地点、统计、开关的持久归属见 §9；运行时刻值（帧计时器、倒计时）与落盘分开。
- **已通过边界（必须继承，不重开）**：GR-011／GR-013（已关闭）；WP37（漫游/雷达，当前字节 `d032f5b7`）；WP53（Safari/捕虫，当前字节 `75fc4db7`——捕虫分流按当前合同引用，不重新推断其计数/治疗/判奖）；WP42（终局、败/平、钱款与资源合同）；WP36（普通遭遇与 Repel 门）；WP30（友好度数值）；WP59（时间/场地与回程工具）；WP23（Shadow/净化）。

## 3. WP61-A：触发、计数与效果次序

### 3.1 步进入口与全局计数（`001_Overworld.rb:172–218`；`004_Game classes/008_Game_Player.rb:183, 552`；`004_Game classes/006_Game_Character.rb:983`）

- **普通玩家迈步（`pbOnStepTaken` 正常分支，按序）**：①全局步数初始化（首次为 0）并 +1（31 位回绕）；②读 Repel 激活态（计数 >0——WP36 门输入）；③触发 `:on_player_step_taken`；④触发 `:on_player_step_taken_can_transfer`（handled 数组）；⑤**handled 为真 → 本步结束（不再判定遭遇）**；⑥事件未触发且不在菜单 → 判定遭遇（`pbBattleOnStepTaken`——无可战成员/无遭遇可能/无类型/触发判定未过即返回；通过后选择遭遇、触发 `:on_wild_species_chosen`、允许门、双打门、公开开战（可覆盖）；最后写遭遇类型清空、遭遇触发标记、强制单打复位——WP36 主责）。
- **强制路线/事件解释器移动（`pbOnStepTaken` 早退分支）**：玩家处于强制路线或地图解释器运行中完成移动——**只触发 `:on_step_taken`（携带玩家）并返回**——**不计全局步数、不发 `:on_player_step_taken`/`:on_player_step_taken_can_transfer`、不判定遭遇**。地形效果钩子（煤烟拾取/草丛摇动/瀑布冰面自动移动）在此分支照常收到通知。
- **原地转向（`:on_player_change_direction`）**：可判定遭遇（同一 `pbBattleOnStepTaken`——WP36），**不计步**；转向清理与步进清理不同（GR-011 已关闭合同，继承）。
- **任意事件完成一步（`Game_Character` 步进点）**：触发 `:on_step_taken`（携带该事件）——煤烟（仅当事件是玩家且持有煤烟袋时计数与拾取）、草丛摇动动画（地图场景内的占用格）、瀑布/冰面自动移动（仅玩家）。
- **帧更新（`:on_frame_update`）**：每帧一次（含暂停微更新链——WP53 已证部分，不重开）。

### 3.2 消费者注册/调用次序（WP05 事件分发引用；按目录加载序）

- **`:on_frame_update`**：Pokérus 日期检查（`012/001`）→ 低电量警告（`012/001`）→ 延迟 BGM（`012/001`）→ 捕虫倒计时（`018/002`，WP53 主责）。
- **`:on_step_taken`（任意事件）**：煤烟拾取 → 草丛摇动 → 瀑布/冰面自动移动（均 `012/001`）。
- **`:on_player_step_taken`**：行走友好度（`012/001`）→ 寄养步进处理（`012/007`，WP33 主责）→ Repel 计数（`013/002`，本包 §3.3）→ 雷达电量（`013/005`，WP37 主责）→ 孵化步数（`016/003`，WP35 主责）。

- **`:on_enter_map`**：新图设置（回程目的地覆盖写入、`$PokemonMap` 清空、遭遇表重建、已访问记录，`012/001`）→ 天气（`012/001`，WP59 主责）→ 足迹（`012/001`）→ 强制骑行（`012/001`）→ 漫游推进（`012/005`，WP37）→ 雷达取消（`013/005`，WP37）→ Safari 清空（`018/001`，WP53）→ 捕虫清理（`018/002`，WP53）。

### 3.3 Repel 计数的步进侧事实（`013_Items/002_Item_Effects.rb:123–166`；WP28/WP36 引用）

- **写入**：Repel 道具（WP28 主责）——已激活时拒绝（效果仍在）、否则播放音效、统计 +1、按档位写入步数（100/200/250）。

## 4. WP61-B：行走友好度

### 4.1 步数累计与周期门（`001_Overworld.rb:70–80`）

- **独立计数（`happinessSteps`，持久于全局元数据）**：普通迈步时初始化（首次为 0）并 +1；**未达 128 即返回**；**到 128** → 对**全体可战成员**（非空、非蛋、未濒死——`able_party`）**逐个以 1/2 概率**（0..1 均匀整数为 0 才生效）执行一次"步行"友好变化（`changeHappiness("walking")`——**数值、获得地/豪华球/安抚铃修正与封顶只引用 WP30**，本包不复制一套数学）；随后**计数重置为 0**。
- **空/全不合资格队伍**：队伍无可战成员（全蛋/全濒死/空）→ 循环无对象，**计数仍重置为 0**（周期正常消耗）；有事件触发不等于自动进行进化检查（进化检查归战斗/升级入口，WP42/WP31 引用；实际调用未证的部分不补成保证）。
- **资格与限制（逐项）**：**蛋**（非 `able_party` 成员——不参与）；**濒死**（同上——不参与）；**Shadow**（`changeHappiness` 覆写：**Shadow 个体且心灵阶段 ≥4 时不产生友好变化**——WP23 主责，本包引用）；**正值修正与封顶消费**（获得地一致 +1、豪华球 +1、安抚铃 ×1.5 取整、软顶配置开启时封顶到 179 以下——**默认软顶关闭**（`AFFECTION_EFFECTS` 为假 → `APPLY_HAPPINESS_SOFT_CAP` 为假——配置值），WP30/WP02 引用）。

### 4.2 与步行相关的其它友好写入口（边界引用）

- **濒死（"faint"）**：野外中毒濒死时写入（§5）；**负值修正不受正值加成**——数值引用 WP30。
- **未知方法**：未登记的方法名在变化入口报错（防御性边界，WP30 引用）。

## 5. WP61-C：野外中毒与全队失能

### 5.1 默认设置与配置变体（`001_Settings.rb:97–102`）

- **默认（机制世代 8）**：`POISON_IN_FIELD` 为**假**（世代 ≤4 才为真）——**默认不发生野外毒伤**（钩子第二门直接跳过）；`POISON_FAINT_IN_FIELD` 为**假**（世代 ≤3 才为真）——即使开启野外毒伤，**默认 HP 到 1 即清毒、不在野外濒死**。
- **配置变体（两个独立开关组合）**：野外毒伤开关（≤4 世代语义）× 野外濒死开关（≤3 世代语义）——四种组合按两个配置分别登记（不把"更代"当作单一开关）。

### 5.2 步进毒伤处理（`001_Overworld.rb:83–113`；逐项真实顺序）

**门（按序）**：①handled 已为真 → 不动；②**野外毒伤开关为假 → 不动**；③**全局步数不是 4 的倍数 → 不动**（每 4 步一次）。

**逐成员处理（对全体可战成员，按队伍顺序）**：

1. **资格**：成员**未中毒 → 跳过**；**免疫特性（IMMUNITY）→ 跳过**（不损 HP、不清毒、不反馈）。
2. **音效/闪烁**：本批次**只在第一次实际处理时各发生一次**（毒步音效＋红色闪烁——**不是每个中毒成员各一次**）。
3. **HP 损失**：`HP > 1` 或野外濒死开关为真 → HP −1（开关为假且 HP=1 时不扣）。
4. **临界 HP**：**HP=1 且野外濒死开关为假 → 清状态为无异常＋"扛住了毒"消息**——本次不再继续处理该成员（**不发生濒死、不写友好**）；**HP=0（仅开关为真可达）→ "faint" 友好变化＋清状态为无异常＋"…fainted…"消息**。
5. **全队检查（每个成员处理完后立即做）**：**可战成员数归零 → handled 置真并调用全队失能交接（§5.3）**。**交接不终止当前成员循环**——**handled 已置真且回程已启动之后，剩余成员仍按同一循环继续被处理**（HP 损失/清毒/濒死消息照常发生；不能假定设置 handled 便自动终止当前循环）。

### 5.3 全队失能交接（`001_Overworld.rb:107–123`；区分单个成员濒死与全队失能）

- **直接检查入口（`pbCheckAllFainted`）**：**可战成员数归零才执行**——两条消息（"没有能战斗的宝可梦！"＋"眼前一黑！"）、BGM/BGS 淡出、**淡出块中调用失败回程**（§7.2 的 `pbStartOver`）。**单个成员濒死 ≠ 全队失能**——只剩一个可战成员倒下时才进入本交接。
- **有界前提**：本入口是公开函数——**直接检查入口的调用者**（中毒循环、以及任何脚本入口）按同一门执行；**异常/空队伍**（无可战成员）直接调用时同样进入消息＋淡出＋回程（有界前提：可战成员数为零即成立，不附加队伍非空校验）。

## 6. WP61-D：Pokérus 状态与日期推进

### 6.1 领域状态与编码（`014_Pokemon/001_Pokemon.rb:786–832`；独立数学）

- **编码**：单整数字段——**菌株 S = ⌊字段/16⌋（高位），剩余期限 T = 字段 mod 16（低 4 位）**；**阶段判定**：字段为 0 → **未感染**；T > 0 → **感染期（阶段 1）**；T = 0 且 S > 0 → **已治愈（阶段 2）**。**期限由菌株决定：T = 1 + (S mod 4)**（1–4 天）。
- **赋予（`givePokerus`）**：**已治愈（阶段 2）→ 拒绝（不能再感染）**；**感染期（阶段 1）重复赋予不拒绝**——重新抽取并**统计再次 +1**（重复赋予的许可与统计分列）；菌株实参 ≤0 或 ≥16 → **1..15 均匀随机**；期限按菌株计算（1–4 天）后写入。
- **重设期限（`resetPokerusTime`）**：字段为 0 → 不动；否则**按当前菌株重算期限并写回（保留菌株）**——**对已治愈个体同样生效**：T 被重设为 1+(S mod 4) ≥ 1，**阶段随之回到感染期**（"重设期限"不是"保持已治愈"）。
- **降低期限（`lowerPokerusCount`）**：**仅感染期生效**——字段 −1；**T 减到 0 → 阶段变为已治愈（2）**。
- **治愈（`curePokerus`）**：**清除期限部分（T 置 0、保留菌株）→ 阶段变为已治愈（2）**。**个体治疗（`heal`）不触碰病毒字段**——HP/状态/PP 恢复与 Pokérus 无关联（§7.3）。

### 6.2 每帧日期比较（`001_Overworld.rb:5–16`；时间戳首次写入来源单列）

- **门（按序）**：①玩家不存在或**队伍（非蛋成员集合）中没有感染期成员 → 不动**；②**上次时间（`pokerusTime`）为空 → 不动**（**默认值存在不等于有正常初始化调用**——仅脚本检索未见初始化写入者，首次推进依赖外部写入，demo 事件未知归 U01；不臆造每日必然推进）；③**上次时间的年/月/日与当前墙钟（`Time.now`）任一不同 → 推进**。
- **推进（一次）**：对**队伍全体非蛋成员**逐个 `lowerPokerusCount`（感染期才减；**不参与集合**：蛋被集合排除；**濒死成员在集合内**（非蛋即入列）；**箱内/寄养成员不在集合内**——其期限不随本入口推进）；随后**上次时间 = 当前墙钟**（**更新时点 = 推进之后立即写入**）。
- **日期边界**：**日期相同 → 不推进**；**跨一天 → 推进一次**；**跨多天 → 仍只推进一次**（推进后立即把上次时间写为当前——**不补跳过的天数**）；**时钟回拨**（上次日期在未来）同样满足"不同"——**也推进一次并写回当前**（比较只看年/月/日是否不同，不区分方向）。

### 6.3 各来源分列（不合并）

- **野外生成**：生成时以 **3/65536** 概率赋予（`Settings::POKERUS_CHANCE` 默认 3——**初次感染概率继承 WP36/WP34，不能把传播合并进步行规则**）。
- **育种**：继承 WP34 主责（本包不重提取）。
- **战斗终局传播**：正常终局时**对每个感染期（阶段 1）成员，其队伍相邻非感染成员各以 1/3 概率被赋予**（WP42 已批准的邻位传播合同，继承；**捕获接收先后继承 WP42**——本包不重排次序）。
- **每日自然变化**：§6.2 的帧日期比较（本包主责）。
- **调试修改**：`007_Debug_PokemonCommands.rb:113–140`——直接显示/修改菌株与期限、调用赋予、清零（**按非默认路径标注**，不混入默认用户流程）。
- **治疗点解释查询（`pbPokerus?`）**：中心解释门——**已见过开关（SEEN_POKERUS_SWITCH）为真 → 不解释**；**队伍任一成员感染期 → 应解释**。**当前基线无脚本调用者**（仅脚本检索——实际解说事件编排归 U01；默认值存在不等于有正常调用）。

### 7.2 失败回程主流程（`003_Overworld_MapTransitionAnims.rb:80–138`；按真实顺序）

**分流（入口）**：野外全队失能（§5.3 淡出块）、普通战斗败/平且**不可败**（`:on_end_battle`——败/平且 `canLose` 为假 → 恢复音乐后调用，WP42 引用）、**可败剧情战斗**（`canLose` 为真 → **不进入本流程**，WP42 主责）、**事件 Game Over**（解释器命令——BGM/BGS 淡出＋淡出块中以 gameover 实参为真调用——**消息措辞与正常回程不同**）、**捕虫大会**（**最先检查**——`pbInBugContest?` 为真 → 捕虫特殊回程并返回，**不执行本流程任何后续步骤**；按当前 WP53 合同引用，不重新推断其计数/治疗/判奖）。

**捕虫分流之后的真实顺序**：

1. **统计**：`blacked_out_count` +1（**捕虫分流不执行本步**；家路径同样计数）。
2. **治疗**：**立即对全队执行全体治疗**（`heal_party`——HP/状态/PP 全恢复；**先于目的地解析**）。
3. **中心存在（ID 存在且 ≥0）→ 中心路径**：消息（gameover 与正常两种措辞）→ **取消载具** → **跟随者清理**（移除全部跟随者并注销伙伴，失败兜底不阻断）→ **`STARTING_OVER_SWITCH` 置真** → 转移参数取中心记录 → 下车 → **仅当地图场景时转移** → **请求地图刷新**。
4. **无中心 → 家回退**：取角色家，缺失取全局家——**家存在但家图资源缺失** →（调试模式消息提示）**再次全体治疗并返回**（不发生转移、开关不写入）；**家存在且图资源存在** → 消息（gameover 与正常两种措辞）→ 取消载具 → 跟随者清理 → 开关置真 → 转移参数取家 → 下车 → **仅当地图场景时转移** → 刷新；**无有效家** → **再次全体治疗并返回**（不发生转移、开关不写入）。
5. **末尾**：**无条件清空逃脱点**（所有路径——包括转移未发生的分支）。

**非目标与不承诺**：WP42 已处理的钱款与战后资源合同继续引用——**回程入口不另加默认扣款或整档重置**；**禁止概括为每次必定换图或事务回滚**——转移未发生的分支（非地图场景、家图缺失、无家）只发生统计/治疗/（调试消息）/逃脱点清空。

### 7.3 恢复入口的实际覆盖（`014_Pokemon/001_Pokemon.rb:274–306`；`015_Trainers and player/001_Trainer.rb:163–165`；`003_Game processing/004_Interpreter_Commands.rb:1099–1108`；`014_Pokemon/001_Pokemon-related/004_PokemonStorage.rb:388`）

- **个体治疗（`heal`）**：**蛋 → 不动**；否则 HP 全恢复、异常清除（状态与计数）、PP 全恢复（可指定单一招式）、待进化标记清除——**不触碰 Pokérus 字段、不写持有物/友好/形态**（Shadow/形态覆写归 WP23/WP21 引用）。
- **队伍治疗（`heal_party`）**：对**队伍全体成员**（含蛋——蛋在个体治疗处自然不动）逐个个体治疗。
- **事件"全部恢复"（解释器命令，实参为 0 时）**：**存储治疗配置为真（HEAL_STORED_POKEMON，默认世代 ≤7 → 默认世代 8 为假）→ 仅队伍治疗**；**为假（默认）→ 遍历队伍与箱内全体**（`pbEachPokemon`）逐个个体治疗。**"全部恢复"的名字不承诺超过个体治疗的字段覆盖**（同 §7.3 个体边界）。
- **盒子相关设置**：存储治疗配置仅影响上一条；盒内个体的其它治疗入口未定位（不臆造）。

## 10. 边界、失败与未知

- **计数边界**：全局步数 31 位回绕；友好周期计数在无可战成员时仍被重置（周期正常消耗）；毒伤按全局步数模 4（初始化后第 4 步首次满足）。
- **逐成员处理的剩余循环**：全队失能交接（handled 置真＋回程启动）**不终止**中毒成员循环——剩余成员继续被扣 HP/清毒/濒死（§5.2 ⑤）；**不能假定设置 handled 便自动终止当前循环**。
- **日期边界**：`pokerusTime` 为空 → 不推进（初始化写入者未定位，U01）；跨多天与时钟回拨都只推进一次并写回当前（§6.2）；**不臆造每日必然推进**。
- **回程分支**：非地图场景 → 不转移（统计/治疗/开关前的步骤已执行；开关写入与转移参数已设置但转移不发生——**刷新闻仍请求**）；家图缺失/无家 → 再次治疗后返回（开关不写入）；**逃脱点在所有路径末尾清空**；捕虫分流最先返回（统计/治疗均不执行）。
- **恢复边界**：蛋在个体/队伍治疗中自然不动；"全部恢复"的覆盖不超过个体治疗边界（不触碰 Pokérus、持有物、形态——Shadow/形态归 WP23/WP21）。
- **未知/未证**：中心记录与解释事件的实际编排（U01/WP77）；离线时间语义；素材存在与播放（U01/E11）；宿主随机源序列；地图事件运行可达性（模板 ≠ 默认运行）。
