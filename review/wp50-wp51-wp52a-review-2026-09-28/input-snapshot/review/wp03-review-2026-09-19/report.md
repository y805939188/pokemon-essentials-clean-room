### WP03-R02 [P2] 注册重复、编译重复和内容去重没有分开

**位置**：77、118、121、188、200 行。

**证据**：`001_GameData.rb:13–15,83–85,158–160` 的直接注册不检查已存在身份；合法同键后项替换前项。通用 PBS 编译器在注册前检查重复（`002_Compiler_CompilePBS.rb:54–60`），但训练家走专用编译路径：791–861 行在完成每节后直接注册，864–948 行的校验和终检没有同身份拒绝；因此两个其余内容均合法、身份相同的训练家节由后项覆盖，而不是统一的“used twice”错误。

**影响**：不同入口的替换、去重与拒绝会被合并成一种失败规则，直接改变作者内容结果。

**最小修订**：按直接注册、通用 PBS 编译、已确认的专用编译入口分别表述；改正重复招式例证的对象与结果。未覆盖的专用细节可指向 WP04，但不能留下全局错误承诺。双身份注册若要维持“两键一条目”表述，应明确正常无冲突前提或记录冲突边界。

### WP03-R03 [P2] schema 类型含义、引用分类和错误取证有事实错误

**位置**：40–41、99–121、130–134、201 行。

- `v` 是严格大于 0 的整数；`u` 允许 0；`i` 接受有符号整数。`m` 是有名称字符约束的符号值，不专指节名，也用于 Type 的相克引用。证据：`001_Compiler.rb:384–435`、`003_Type.rb:18–27`。
- Type、Move、Item 都是 PBS 作者数据，不能在 `e` 示例或固定规则示例中列作 hardcoded。是否作为枚举引用源与是否硬编码是两个不同维度。定义及文件声明分别见 `003_Type.rb:14–30`、`005_Move.rb:18–38`、`006_Item.rb:21–46`；P/types.txt 亦有实际内容。
- “每个作者数据类声明 schema”不成立：Encounter 走专用解析，`013_Encounter.rb` 没有自身 SCHEMA，编译路径见 `002_Compiler_CompilePBS.rb:658–767`。Trainer 还区分顶层及成员子字段约束；不能只凭所有类继承同名入口就当作全部具有同一种 schema。
- 道具 Move 字段使用通用枚举验证：`006_Item.rb:42` → 通用编译 → `get_csv_record` → `cast_csv_value` → `checkEnumField`。未知值走 `001_Compiler.rb:449–459`，不是 201 行写的 parseMove 专用错误文本。867–941 行不能作为所有枚举引用的统一证据。
- “枚举在写入 PBS 时也可自动补写新常量”没有所引路径支持。已读反写逻辑 `001_Compiler.rb:742–842` 是值到文本的转换，所调用的 `getConstantName` 等也只查找已有名称或返回值/错误（`S/019_Utilities/001_Utilities.rb:137–153`）。

**影响**：合法输入范围、引用来源和诊断预期错误；还引入了未证的自动生成能力。

**最小修订**：只纠正本包已列出的模式/结构和引用路径，区分固定规则枚举、作者内容引用及内联枚举；删除或补证自动新增常量说法。完整格式解析仍归 WP04。`^` 可重复属性及 Evolution 示例经核对有对应声明，本轮不要求改动这一正确部分。
