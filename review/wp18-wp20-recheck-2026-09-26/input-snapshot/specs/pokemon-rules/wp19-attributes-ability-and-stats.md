## 1. 目的、范围与非目标

**目的**：定义个体属性与能力数值的确定性规则——哪些值是固定配置、哪些是覆盖、哪些由随机身份派生、哪些由公式计算；数值域、上限、取整位置、重算触发与写回。后续包（成长、战斗计算、繁殖、图鉴、UI 展示）据此引用，不再各自追踪个体类。

**范围**（WP19 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP19-A：属性派生——类型、性别、异色（含超级异色）、特性选择、Nature（含计算用覆盖）。
2. WP19-B：六项能力与培养参数——等级↔经验接口、个体值（IV）/上限覆盖、努力值（EV）、能力计算公式、重算触发与当前 HP 写回、特殊物种/分支与配置变体。
3. F06-03、F06-04 中属于 WP19 部分的状态更新。

**非目标**：

- 不定义成长曲线目录与经验获取/等级成长流程（WP30）；本文只登记等级↔经验的换算接口及曲线标识来源。
- 不定义学习/替换、友好度变更（WP30）、进化（WP31）、繁殖遗传（WP34）。
- 不定义战斗内临时修正（能力阶级、变身、场地、特性触发效果；WP43/WP44/WP48 等），不定义捕获率/图鉴/展示排序。
- 不定义动态形态处理器（WP21）；不定义 Mega/Primal（WP22）、Shadow 的 EV/经验暂存（WP23）。
- 不复制参考实现的公式源码或方法结构；公式以数学表达重写。
- 不运行游戏或任何参考脚本；向量数值为自有算术核对。

## 2. 概念与术语与数值分层

- **属性（attribute）**：类型、性别、异色、特性、Nature 等"标识性差异"。
- **能力（stat）**：六项主能力——HP、物攻、物防、特攻、特防、速度；由基础值、个体值、努力值、等级、Nature 修正共同决定。另有战斗专用项（命中率/闪避率，只用于战斗，归战斗包）。
- **数值分层**（本包的统一分类口径）：

| 层 | 含义 | 本包实例 |
| --- | --- | --- |
| 固定/配置 | 来自物种内容或配置常量 | 基础能力值、性别比例、成长曲线标识、等级上限、异色判定阈值 |
| 覆盖 | 显式设置的替代值 | 计算用 Nature（"薄荷"覆盖）、个体值上限标记（Hyper 标记）、"禁用 IV/EV 计算"配置（视为 0） |
| 派生 | 由身份/其它字段确定性或按规则计算 | 性别、异色、特性索引、Nature、等级（由经验）、六项能力 |
| 随机条件 | 创建时随机生成或按概率重试 | personal ID、六项个体值初值、野生异色重试、传说满个体、猎场重掷 |

- **有效个体值**：计算能力时使用的个体值 = 上限标记为真时取上限值 31，否则取存储值（"禁用 IV/EV"配置下两者都按 0）。
- **计算用 Nature**：显式覆盖存在时替代表现 Nature 参与计算（展示仍可用原 Nature）。
- **重算（recalculate）**：按当前输入重算六项能力与当前 HP 调整；见 §4.6。

## 3. WP19-A：属性派生

### 3.1 类型（`001_Pokemon.rb:312–334`）

- 个体的类型列表来自其物种/形态记录（形态记录在编译时继承或覆盖类型，见 WP18 §3.1），读取返回副本（修改返回值不影响个体）。
- 兼容读取：第一位类型直接取列表首项；第二位类型在列表只有一项时回落为首项（兼容入口带弃用提示，计划移除）。
- `hasType?`：给定类型标识（符号/字符串/记录）先按 WP03 语义解析为规范标识，再做"任一匹配"判定；未知标识按解析失败处理。
- 边界：内容约定常见 1–2 项，但数据/读取层**不设两项硬上限**——编译只做去重/去空、不截断；读取返回完整列表副本；成员判定覆盖整个列表；兼容的第一/第二类型读取只取前两项（单类型时第二项回落首项）。战斗中的临时类型改变不写回本字段（战斗包边界，WP43/WP44）。

### 3.2 性别（`001_Pokemon.rb:340–383` + `002_GenderRatio.rb` 全文）

- 值域：`0` 男 / `1` 女 / `2` 无性别。
- **单性别/无性别物种**（比例记录没有女性概率）：固定映射——"仅男性"系 → 0；"仅女性"系 → 1；"无性别"系 → 2。
- **比例物种**：读取存储值；未缓存时派生——
  1. 取 `personal ID` 的低 8 位（值域 0–255）；
  2. **低 8 位 < 女性概率** → 女（1）；否则男（0）。
- 女性概率配置表（比例标识 → 概率）：`1/8 → 32`；`25% → 64`；`50% → 128`；`75% → 192`；`7/8 → 224`。
- 设置入口：仅在物种非单性别时生效；`0/1` 直接设置，`nil` 清除缓存（下次读取重派）；其它值忽略（无效果、不报错）。便捷"设为男/女"以 `0/1` 调用同一入口。
- 单性别物种上调用设置入口：直接无效果（不报错）。
- 已定位消费者（不穷尽）：野生生成的首位特性修正（迷人之躯，WP36）、训练家数据指定性别（WP24）、展示与部分判定（UI/图鉴等）。

### 3.3 异色与超级异色（`001_Pokemon.rb:389–418`）

- **判定**（首次读取时计算并缓存）：
  1. `a = personal ID ⊕ 拥有者 id`（32 位异或；拥有者 id 取完整 32 位）；
  2. `b = a 的低 16 位`；`c = a 的高 16 位`；
  3. `d = b ⊕ c`；
  4. **异色** ⇔ `d < 阈值`；阈值 = 16（机制世代 ≥6，默认世代 8）或 8（更早世代）。即概率 16/65536 ≈ 1/4096（或 8/65536）。
  5. **超级异色** ⇔ `d == 0`（同公式的**另一次独立计算**；与普通异色各自首次求值、各自缓存——普通异色查询不写超级缓存，反之亦然）。
- 设置入口：可直接写异色真假（写入后不自动重算）；"超级异色=真"会强制异色为真；"超级异色=假"**不清除**异色标记；此后普通异色缓存仍可被单独覆盖或清除——两缓存可并存任意组合（"`d == 0` ⇒ `d < 阈值`"是数学蕴含，**不是**缓存状态的不变量）。
- 缓存失效：判定结果缓存于个体；`personal ID` 或拥有者的改变**不自动**使缓存失效——需要重派时必须显式清除对应缓存再改输入；**两个缓存分别清除、互不影响**（野生异色重试流程即"先清普通异色缓存、再重掷 personal ID、再读取"两步，WP36）。
- 已定位消费者：野生生成重试与开关强制（WP36）、训练家数据指定（WP24）、战斗开场特效（仅超级异色参与特殊闪光分支，时机归战斗表现包）、调试显示。
- 边界：拥有者占位 id 为 0 时仍按公式参与（异色与拥有者绑定，交接个体展示既有判定值）。

### 3.4 特性选择（`001_Pokemon.rb:424–490`）

- **索引（ability index）**：0/1 为自然槽位；≥2 为隐藏槽位（第 n 个隐藏特性 = 索引 n+2）。未缓存时按 `personal ID` 最低位派生：偶数 → 0，奇数 → 1。
- **解析顺序**（读取时；结果缓存）：
  1. 已有显式/缓存值 → 直接使用；
  2. 索引 ≥2：取"隐藏特性[索引−2]"；该槽位为空 → **索引回落**为 `personal ID` 最低位（0/1），继续第 3 步；
  3. 取"自然特性[索引]"；为空 → 取"自然特性[0]"；
  4. 两者均无（物种未定义特性）→ 结果为空。
- 设置入口：`ability=` 接受已存在的特性标识或 nil（nil 清除缓存、恢复派生）；未知标识忽略（无效果）。**不校验**该特性是否属于当前物种/形态（可形成覆盖值）。
- `ability_index=` 接受任意整数（不校验范围）：负索引按容器语义取末项、≥2 且隐藏槽缺失时按第 2 步回落（静态推导）；设置时清除已解析特性缓存（索引即新写入值，保留待下次解析）。
- 派生读取：`hasAbility?(nil)` = 当前解析结果非空；`hasAbility?(X)` = 当前解析结果与 X 是否同一特性（比较语义接受符号/字符串/记录，引用 WP03）；`hasHiddenAbility?` = 索引 ≥2（**注意**：隐藏槽缺失回落自然特性时，该判定仍为真，与解析结果可能不一致——按行为记录）。
- 候选列表：返回"已定义的自然槽（0/1）+ 已定义的隐藏槽（2+）"的 [特性, 索引] 对，跳过空槽。
- 物种/形态变更的缓存清理：物种设置清除特性缓存（索引保留）；`form=`/`setForm` 清除缓存；`form_simple=` **不清除**（WP18 §3.4）。
- 特性效果（战斗触发、野外效果等）归相应包（WP48/WP36）；本包只定义"选到哪个特性"。
- 已定位消费者：野生生成首位特性判定（迷人之躯/同步/复眼等，WP36）、战斗特性触发（WP48）、展示。

### 3.5 Nature（`001_Pokemon.rb:496–545` + `009_Nature.rb` 全文）

- **派生**：未缓存时 `索引 = personal ID % 25`，取登记顺序第索引项（登记顺序：`HARDY, LONELY, BRAVE, ADAMANT, NAUGHTY, BOLD, DOCILE, RELAXED, IMPISH, LAX, TIMID, HASTY, SERIOUS, JOLLY, NAIVE, MODEST, MILD, QUIET, BASHFUL, RASH, CALM, GENTLE, SASSY, CAREFUL, QUIRKY`），缓存结果。
- **修正表**：25 种里 5 种无修正（HARDY/DOCILE/SERIOUS/BASHFUL/QUIRKY——顺序中的 0/6/12/18/24），其余各为"一项 +10%、一项 −10%"；修正以百分数直接参与能力公式（§4.5）。
- 设置入口：`nature=` 接受已登记 Nature 或 nil；未知忽略。**若已设置计算用覆盖 Nature，则不触发重算**；否则设置后重算能力。
- **计算用覆盖（"薄荷"）**：`nature_for_stats=` 接受已登记 Nature 或 nil（nil 清除覆盖），设置后**总是**重算能力。计算用 Nature 读取 = 覆盖存在则覆盖，否则表现 Nature。
- 边界：`hasNature?(nil)` 直接检查缓存值——只有尚未经过任何求值的个体才可能为假；**普通创建返回前 Nature 已被能力重算求值缓存**（WP18 §4.1），故新建个体的 `hasNature?` 通常已为真（缓存语义）；Nature 对 HP 无修正。

## 4. WP19-B：六项能力与培养参数

### 4.1 数据分层与来源

| 输入 | 来源 | 责任 |
| --- | --- | --- |
| 基础能力值（六项） | 物种/形态记录 | WP18（数据）、本包（计算使用） |
| 个体值（IV，六项） | 创建随机 0–31；后续按入口覆盖 | 本包 |
| 个体值上限标记 | 默认空；外部设置 | 本包（生效方式）；启用入口见 §7 未决 |
| 努力值（EV，六项） | 创建为 0；后续按入口增加/减少 | 本包（域与上限）；分配流程见前向引用 |
| 等级 | 由经验换算（或显式设置） | 本包接口、WP30 流程 |
| Nature 修正 | 由 Nature/计算用覆盖决定 | 本包 |
| 禁用开关 | 配置（默认假） | 本包（视为 0 的变体） |

### 4.2 等级与经验接口（`001_Pokemon.rb:190–238`）

- **等级读取**：缓存为空时按"成长曲线"由当前经验换算（换算为纯函数：给定经验 → 等级）；结果缓存。经验一旦写入即清除等级缓存。
- **换算函数**（接口语义，曲线目录归 WP30）：给定等级 n → 该等级最小经验 `minExp(n)`；给定经验 e → 最大档位 `L` 使 `minExp(L) ≤ e < minExp(L+1)`；`e ≥ minExp(满级)` → 满级。等级与经验界：`minExp(1) = 0`。
- **等级设置**：域 `[1, 等级上限]`（上限 = 配置值，默认 100）；越界**报错**（提示含等级号）；成功时同时把经验写为该等级的最小经验并缓存等级。
- **经验设置**：直接写入并清除等级缓存（无钳制——副作用与钳制由调用者负责，如"经验累加"入口会把结果限制在 `[0, 满级经验]`，WP30）。
- **经验进度（展示用）**：满级 → 0.0；否则 `(当前经验 − minExp(L)) / (minExp(L+1) − minExp(L))`（浮点）。
- **边界（按行为记录，两入口分列）**：等级换算对非法等级（空/≤0）**返回一个错误对象**（调用方把它当数值使用才会失败）；经验换算对非法经验（空/负）**不返回错误对象**——其诊断文本引用了未定义的标识（该方法内可供读取的局部值只有参数本身），在文本求值阶段即发生名称解析错误。两者均为参考快照现状反例：记录行为、不修参考代码、不把反例当作未来实现必须保留的设计。
- 消费者示例：升级流程逐级应用经验并按档推进（WP30/WP42）；能力重算在等级/经验变化后由调用者触发（§4.6）。

### 4.3 个体值（IV）（`001_Pokemon.rb:1073–1090` 及创建段）

- **域**：每项 0–31（上限常量 31）；创建时逐项均匀随机（0 至 31 含端点）。
- **存储**：六项键值的映射；**类本身不钳位**（任意写入原样存储）；已定位写入者均把值限制在域内（野生重掷、传说满个体、训练家数据、调试/编辑器范围）。存储应包含全部六项（计算入口不为缺失项兜底；缺失项进入算术会失败）。
- **有效值**：上限标记为真 → 31；否则存储值；"禁用 IV/EV"配置 → 0。
- **上限标记（Hyper 类）**：键值映射，默认空；语义 = "该项按 31 计算"；**仅**影响能力计算（`calcIV`），不改写存储值、不影响展示中的原始 IV 排序/描述（展示入口按各自读取）。
- **特殊分支（生成侧，完整流程归 WP36）**：猎场/捕虫大会内野生个体最多重掷 4 次全项 IV 直至出现一项满值；传说/神话/究极异兽标记物种在世代 ≥6 配置下随机选 3 项设为满值；两者都触发重算。
- **未决**：正常游戏内设置"上限标记"的启用入口在核心脚本中未定位（检索未见写入者；接口存在但入口不明，见 §7）。

### 4.4 努力值（EV）（`001_Pokemon.rb:91–93` 常量与全仓写入者核对）

- **域与上限**（不变量）：单项 `0–252`；六项合计 `0–510`。
- **存储**：六项键值的映射；创建为 0；类本身不钳位，上限由各写入入口的"按剩余空间夹限"模式保证——通用模式：`单次增量 → min(增量, 252 − 该项现值, 510 − 当前合计)`（战斗获取/道具/调试等入口一致）；**Shadow 暂存分支**先计入"已暂存 EV"并入总量、单项剩余按 `252 − 当前值 − 已暂存值` 夹限（WP23）。
- **计算使用**：`⌊EV / 4⌋` 进入能力公式（取整发生在这里；不足 4 点不产生增量）。
- **已定位写入者目录**（规则细节归各入口包，本包只登记上限模式与消费者）：
  - 战斗击败获取（Pokérus"已感染或已治愈"阶段使本次获取翻倍；另有持有物侧的获得修正入口；Shadow 成长暂存写入"暂存 EV"而非当前 EV——WP23/WP43）；
  - 培养道具（维生素类单次 +10；**默认配置（世代 8）不受 100/项限制**、仅守单项 252/总 510；"100/项封顶"是设置关闭（较早世代配置）的变体；工具函数形参默认 false 不等于道具入口的默认实参；羽毛类小幅；EV 降低树果下调——WP28）；
  - 训练家数据（未给定 EV 时按等级推导：`min(⌊等级×3/2⌋, 85)`，WP24）；
  - 设施/调试（WP54/WP73）；"禁用 IV/EV"配置下存储仍存在、仅计算视为 0。
- **边界**：EV 修改后由写入者调用重算（§4.6）；EV 数值本身不影响经验/等级。

### 4.5 能力计算公式（`001_Pokemon.rb:1086–1127`）

**输入**：基础值 B（物种）、有效个体值 IV、努力值 EV、等级 L、Nature 修正 N、HP 特例与配置开关。所有除法为"整除下取整"（⌊·⌋），不存在四舍五入。

**HP 上限**：

```
若 B = 1（特例物种）：HP上限 = 1（与 IV/EV/L/配置无关）
否则：HP上限 = ⌊ ((2B + IV + ⌊EV/4⌋) · L) / 100 ⌋ + L + 10
```

**其它五项能力**（含 Nature 修正；N ∈ {90, 100, 110}）：

```
内层 = ⌊ ((2B + IV + ⌊EV/4⌋) · L) / 100 ⌋
能力 = ⌊ ((内层 + 5) · N) / 100 ⌋
```

**Nature 修正 N**：以 100 为基准，对该 Nature 的每项变化累加（+10 → 110，−10 → 90；无变化 → 100）。例：性格"+物攻/−特攻"作用于物攻时 N=110、作用于特攻时 N=90、其余 100。

**变体**："禁用 IV/EV"配置 → 公式中的 IV 与 EV 都取 0（存储值保留，其它用途如展示/隐藏力量类判定仍读原值——后者归相应包）；"有效个体值"与"计算用 Nature"见 §2。

**取整位置**（不变量）：① 先 `⌊EV/4⌋`；② 乘等级后整除 100 取整一次；③ 加 5 后乘 Nature 修正再整除 100 取整一次。任何一步的取整顺序变化都可能改变结果（不可交换）。

**HP 特例**：基础 HP 为 1 的物种（经典特例"脱壳忍者"）恒为 1。

### 4.6 重算触发与当前 HP 写回（`001_Pokemon.rb:1099–1127`）

**重算动作**（单一入口，行为固定）：

1. 取当前基础值/等级/有效 IV/EV/计算用 Nature；计算六项。
2. 上限替代：新 HP 上限覆盖旧值；物攻/物防/特攻/特防/速度全部覆盖为计算值。
3. **当前 HP 调整**（与 WP20 的持久 HP 衔接，唯一写回点）：
   - 若当前 HP > 0：`新HP = max(当前HP + (新上限 − 旧上限), 1)`；
   - 若当前 HP = 0：**仅当**上限增加时 `新HP = 新上限 − 旧上限`（>0）；否则保持 0；
   - 最终值再按持久 HP 的赋值规则钳到 `[0, 新上限]`（WP20 §3.1）。
   - 推论（静态）：已濒死个体在上限增加的重算中会被"复活"为增量值；上限不变或减少时保持濒死；存活个体的最小值为 1（不会因上限减少而被打成 0）。
4. 不改变输入值本身：经验值、招式与 PP、异常与计数、友好度、来源/拥有者、个体数值输入（IV/EV/Nature 存储）、个体标记。注意**缓存填充**不属于"修改输入"但会随读取发生：重算读取等级（缓存为空时按经验重派并写入）与计算用 Nature（无覆盖时求值并缓存表现 Nature）。

## 5. 规则与不变量

1. 六项能力的唯一计算入口为 §4.5 公式；HP 特例（B=1）与配置变体是仅有的两处替换。
2. 取整顺序固定（§4.5），结果对同一输入确定；无浮点参与。
3. 属性（性别/异色/特性索引/Nature）由 `personal ID`（异色另加拥有者 id）派生；派生结果缓存，缓存不因输入变化自动失效（§3.3/3.4/3.5 的缓存规则为不变量）；**普通异色与超级异色是两个独立缓存**（§3.3）。
4. 性别的显式设置只接受 0/1/nil；单性别物种不可设；特性/Nature 的显式设置只接受已登记标识或 nil，未知忽略。
5. IV 域 0–31、EV 单项 ≤252 且合计 ≤510；存储层不钳位、由写入者保证（§4.3/4.4）。
6. 上限标记只改变计算用量（31），不改存储；计算用 Nature 只改变计算，不改表现 Nature。
7. 重算写回当前 HP 的规则唯一（§4.6.3）；重算不改变其它字段的**值**（但读取会填充等级/Nature 等缓存，§4.6.4）。
8. 等级域 `[1, 上限]`，设置越界报错；经验换算不在写入时钳制。
9. 能力计算使用形态记录（`form_simple`）的基础值/属性；动态形态的取值时机由 WP21 定义。

## 6. 边界与失败

- 等级设置越界：报错（含等级号），状态不变。
- 经验换算非法输入（空/负）：**不返回错误对象**，在诊断文本求值阶段发生名称解析错误；等级换算非法输入（空/≤0）返回错误对象（§4.2，均为参考快照反例，不作未来要求）。
- 性别设置：单性别物种无效果；越域值（如 2、负数、字符串）忽略；无报错。
- 特性/Nature 设置为未知标识：忽略、不报错；特性设置不做物种归属校验（覆盖）。
- 特性索引显式设为任意整数：不校验（负值按容器语义取末项、≥2 缺隐藏槽时回落，§3.4）。
- IV/EV 存储缺项或超出域（绕过写入者直接写入）：计算入口不兜底，缺项进入算术会失败；超域值按原值参与公式（行为静态推导，正常入口不产生该状态）。
- `hasNature?(nil)` 的缓存先后语义；`hasHiddenAbility?` 与解析结果可能不一致（§3.4）。
- 超级异色置假不清除普通异色；普通异色缓存可被直接覆盖或清除，两缓存互不同步、可并存任意组合（§3.3）。
- "禁用 IV/EV"配置下，依赖 IV/EV 的非计算用途（展示/特定判定）仍读原值——各消费者的读取口径不在本包声称统一。
