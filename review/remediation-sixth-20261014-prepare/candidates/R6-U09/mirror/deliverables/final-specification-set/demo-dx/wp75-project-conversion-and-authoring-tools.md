## 2. 概念与术语（实现中立）

- **转换家族**：共享触发与写出方式的一组自动改写。本稿六族：新地图导入、训练家注释事件、道具球命名事件、事件改造（门/事件名/通道页/柜台）、旧用法替换、文本规范化。
- **识别谓词**：只判断「长得像什么」的检查（门启发式、通道启发式、柜台启发式、mart/nurse 识别）——命中才改写；识别边界继承 WP61：识别 ≠ 构造模板、不保证不误判。
- **事件简写**：作者在事件名或注释里写的紧凑约定（`item:X`/`hiddenitem:X` 名字、`Battle:`/`Type:` 等注释前缀、注释行内的 `SellItem(POTION,200)`（POTION和200代表合法道具名与非负价格） 括号形式），编译期展开为完整事件命令。四个前缀的冒号是ASCII U+003A。道具球的 `item:`/`hiddenitem:` 前缀及训练家注释的 `Battle:`/`Type:` 收集/解析前缀大小写不敏感；道具/训练家登记身份与有效页面、有效Battle等其它门仍独立。只把冒号换成U+FF1A的 `item：POTION`、`hiddenitem：POTION`、`Battle：文本`、`Type：类型` 是不匹配负例，不能代替ASCII语法。
- **地图信息树（mapinfos）**：`Data/MapInfos.rxdata` 中的地图登记集合（编号、名字、顺序）；新地图导入的写入对象。
- **散文件树**：`Data/Scripts/` 目录下的 rb 脚本文件与子目录；与 `Data/Scripts.rxdata`（归档）互为往返。**提取产物按两层编号约定布局**（计数器两级，§12.1）；**作为合并输入的目录层级不设上限**（合并递归无层数上限，§12.2）——两层约定只约束提取侧产物，不是对散文件树本身的全局限制。
- **装载器（loader）**：提取完成后写入 `Data/Scripts.rxdata` 的单节归档（只有一条 Main 记录，内容为一段预置压缩数据）；其可读文本的加载行为见 §12.4，不执行脚本。
- **town_map.txt 节**：区域地图 PBS 数据：`[编号]` 节＋`Name`／`Filename`＋若干 `Point`（字段：X、Y、地点名、地标、飞行图/飞行 X/飞行 Y、开关——Point 模式以 GameData 模式为准，WP04 引用）。
- **已发生写入**：转换/往返对工程文件的实际落盘（地图、地图信息、tileset、系统、公共事件、图形文件、Scripts.rxdata、ScriptsBackup.rxdata）——本稿逐族登记，不补原子回滚承诺。

## 3. 入口与触发（A）

### 3.1 编译期转换的调用点（WP04 引用，不重提取）

- 全量内容阶段：不重编译（入参为假）→ 消息并直接返回；否则顺序＝编译 PBS 文件 → 编译动画（WP74 交界）→ **训练家事件编译驱动**（本稿主驱动；其入参未被使用，如实登记）→ 翻译收集（WP08 边界）→ 消息保存/载入。启动检查入口仅调试模式：缺 PBS 目录则先建目录全量写出并强制重编译；**重编译标志会吸收新地图导入的返回值**（有新地图导入即触发重编译）；其后按数据/PBS 文件修改时间判定。
- debug 菜单文件选项下「Rename outdated files」：**先确认**才执行文件名更新，完成后提示 Done。

运行中调试菜单 Compile data 先创建消息窗，直接强制进入上述内容阶段，正常返回后才显示完成并释放窗口。该入口仍发现 PBS 并作固定路径兼容改写，但没有启动检查的缺 PBS 建目录/全量反写、新地图导入、新鲜度检查、数据清单预删除或局部异常诊断/删除/转换（[WP04 §3.3](../generic-kernel/wp04-pbs-lifecycle.md#33-运行中直接全量编译)）。事件驱动只遍历地图信息中已登记的地图，新文件未登记时不由本入口自动导入。

完整兼容工程、PBS 与旧档案可用、此前阶段正常时，词法合法的 Status/Power40 在招式条目校验失败：类型/特性等更早档案可已更新，坏招式未登记，当前招式表可有新前缀且旧 moves.dat 仍在；直接入口不做启动清单清理、没有整体回滚，后继阶段/完成消息/消息窗释放不保证到达。相同失败的启动检查只有诊断正常返回才继续尝试清单删除。全合法直接流程可正常完成，不把缺少宿主数据的当前 Demo 当这个成功对照。

编译成功也不统一刷新已预载的区域图鉴、动画集合/关联或连接缓存；区域表从旧 A 编译出磁盘 B 后，当前查询仍 A，随后区域 PBS 反写采用 A 而磁盘仍 B。缓存尚未建立、地区图鉴编辑器 Yes 的显式失效、新临时会话数据与独立连接清理分别按 [WP04 §5.5–§5.6](../generic-kernel/wp04-pbs-lifecycle.md#56-磁盘产物与同会话缓存)；新临时会话数据不保证清连接缓存。宿主文件缓存重载的请求不等于这些对象刷新。

### 3.2 命令行脚本与浏览器/外挂入口

- `scripts_extract.rb`：文件末行调用提取入口；`scripts_combine.rb`：末行调用合并入口——两文件除入口行外内容相同（各 183 行，同字节数）。运行需要本机 Ruby（README 声明）；本稿不执行。
- `townmapgen.html`：浏览器打开的作者工具页；本稿只静态阅读 HTML/脚本，不在浏览器运行。
- `extendtext.exe`：RMXP 显示文本/脚本对话框的放大外挂（仅文档陈述，§14）。

### 3.3 脚本往返方向的同一归档对照（B20-C024）

提取是归档→散文件：当前归档节数<10拒绝，≥10继续；合并是散文件→归档：当前归档节数>10拒绝，≤10继续。静态11节归档正常对照：extract通过数量门 → 创建/清空散文件树 → 逐节写出目录和脚本文件 → 备份原归档 → 写单节装载器；编号是文件/目录布局，没有独立索引文件。同一11节输入给combine则拒绝，不开始目录聚合或写归档。10节分别允许两入口，9节提取拒绝而合并可继续；允许不保证后续文件访问成功。失败对照：清树成功后首个非空脚本文件打开失败，旧树已被清空，备份尚未到，已有备份保持原值（原先无备份则仍无），原归档未改、无装载器。其它阶段的部分写入边界见 §12.1，无原子回滚保证。本轮未运行脚本或 Ruby；装载器的安全静态解码与执行分开（§12.4）。

## 4. 新地图导入（B）

- **触发**：仅调试模式（非调试返回假）；在 WP04 启动检查的重编译判定中被调用（运行中直接内容阶段不调用），返回值并入重编译决定（§3.1）。
- **识别**：扫描 `Data/` 下 `Map*.rxdata` 的数字编号文件；排除已登记在 mapinfos 的编号；**跳过编号 999**（随机地牢图）。
- **转换**：对每个未登记编号新建地图信息——名字 `MAP%03d`（编号三位补零），**顺序从现有最大顺序＋1 起逐个递增**。
- **写出与缓存**：有导入才写 `Data/MapInfos.rxdata` 并清空地图信息运行缓存；消息报告导入数量；无导入不写文件、无消息、返回假。
- **重跑/部分失败**：已登记的不重复导入（幂等）；地图文件本身不被修改（只登记信息）。

## 5. 训练家注释事件转换（C-1）

### 5.1 触发与识别（R01 修订——收集门与解析支分开）

- 事件有页且首图层命令表 ≥2 条，否则返回 nil（不改事件）。
- **收集门（白名单 13 个前缀）**：逐个注释首行（连续注释行拼为一块）检查——命中 `Battle:`、`Type:`、`Name:`、`BattleID:`、`DoubleBattle:`、`Backdrop:`、`EndSpeech:`、`Outcome:`、`Continue:`、`EndBattle:`、`EndIfSwitch:`、`VanishIfSwitch:`、`RegSpeech:` 之一才收集该注释块（匹配按行首锚定，块内后续行首命中同样入选）；任一入选即进入转换。**`CommonEvent:` 不在白名单内——独立写 `CommonEvent:` 的注释块不被收集、其值被忽略**。
- **解析支（13 条，与白名单不同集）**：`Battle`／`Type`／`Name`／`BattleID`／`DoubleBattle`／`Continue`／`EndIfSwitch`／`VanishIfSwitch`／`Backdrop`／`Outcome`／`EndBattle`／`RegSpeech`／`CommonEvent`——**`EndSpeech` 有收集无解析支**（入选的 `EndSpeech:` 块不产生任何战后台词赋值；战后文本只来自 `EndBattle:`）；**`CommonEvent` 有解析支无收集门**——只在某个已入选注释块的块内行首出现时才被消费，且**每块只取第一个命中支**：块以 `Battle:` 开头时，**Battle 支先命中并把其后整段（含续行）作为战斗文本**——续行行首的 `CommonEvent: 数字` 被吞入战斗文本、公共事件参数仍为默认 0（组合失败）；**真正可达的组合是块以 `EndSpeech:` 开头、末个续行行首为 `CommonEvent: 数字`**——该块靠 EndSpeech 入选、前面无更早命中支，于是进入 CommonEvent 支、该值进入电话登记的公共事件参数（整体转换仍需另有有效 `Battle:` 块）。
- 每个注释块按解析支顺序取**第一个命中支**（一支一块）；未命中任何支的入选块不改变任何字段（保持默认）。
- **必须有至少一条 `Battle:`**，否则返回 nil（此前已收集的其它前缀不产生任何改动）。
- 注释起始于事件第 0 条时，若事件名不含 trainer 字样则改名为 `Trainer(3)`；若事件名已是 `Trainer(N)` 形式则保留其 N。
- 转换产生**全新事件对象**替换原事件（同坐标、同 ID；首页图形属性经克隆保留）；**原注释不保留**（保留开关为常量假，如实登记）。

### 5.2 解析（各前缀语义）

- `Battle:` 追加一条战斗文本（可多条＝含再战）；`Type:`/`Name:` 去首尾空白作训练家类型/名字；`BattleID:` 数字（再战系列的起始版本号，默认 0）；`DoubleBattle:`/`Continue:` 值 TRUE/YES（大小写不敏感）为真；`EndIfSwitch:`/`VanishIfSwitch:` 收集开关编号（可多条）；`Backdrop:` 背景名；`Outcome:` 结果变量编号（默认 0）；`EndBattle:` 战后文本（可多条；**一条都没有时默认补一条「...」**）；`RegSpeech:` 登记电话台词；`CommonEvent:`（仅入选块内行首）公共事件编号（电话登记用，默认 0＝不带）。


两个布尔族 `DoubleBattle:` 与 `Continue:` 在每个事件开始各自为假；已收集块按顺序、每块一个解析支消费，值去端部空白且大小写归一后只有 TRUE/YES 将相应标志置真。NO/FALSE/其它值不写假，后来的假值不撤销先前真值。首页与再战页均消费最终标志，分别生成双打与可败规则；下一事件重新以假开始。此累计启用只约束这两个族：类型/名字/版本等标量保持后命中值，战斗文本/战后文本/开关列表仍各自追加。

| 同族独立块的顺序 | DoubleBattle 最终值／两页双打规则 | Continue 最终值／两页可败规则 |
| --- | --- | --- |
| YES→NO（或 TRUE→FALSE） | 真／生成 | 真／生成 |
| NO→YES（或 FALSE→TRUE） | 真／生成 | 真／生成 |
| 仅 NO/FALSE | 假／不生成 | 假／不生成 |
| 前一事件真；下一事件无真块 | 下一事件假／不生成 | 下一事件假／不生成 |

这些对照须通过 §5.1 收集门且各块实际进入对应支，另有合法 Battle、类型/名称及资源依赖；一块被较早解析支吞入时不能以其内部布尔文字推导启用。缺有效 Battle 或前序检查失败仍按既有失败条件，不保证生成正常两页。

### 5.3 训练家检查器（R02 修订）

- **检查集合按 Battle: 条数分开**（均在本编译驱动内执行，编辑器内不执行）：1 条 → 只查主战斗（起始版本号）；2 条 →**只查主战斗**（第二条文本直接写进再战页、**不查第二个版本**）；≥3 条 → 查主战斗＋逐个再战（版本号递增）。（运行时首页的系列检查脚本另有运行时合同（调试下确认「新建训练家变体？」，属 WP73-A/WP04 交界），与本编译期检查器是两个入口。）
- **门与「不再问」**：检查器整体先判**调试模式与「不再问」标志——非调试或已置「不再问」时本调用链直接返回**（不产生任何询问或异常）；底层公开缺失入口的非调试异常是该入口自身合同（WP73-A/WP04 已通过），**不是本编译调用链的结果**。
- 调试且未「不再问」时：**类型不存在** → 确认「新建训练家类型？」，是则调训练家类型新建编辑器（WP73-A 交界）；**类型存在但训练家不存在** → 经底层缺失入口三回答——是＝调新建入口创建、否＝不创建、**取消＝本次编译不再询问**（检查器置「不再问」标志，后续同类缺失静默跳过）。
- **字符图补设三支（R03 修订）**：事件已有字符图 → 不经此路径；无字符图且类型存在 → 查询类型的字符文件名——**解析到名称** → 经图像存在性检查，存在才补设；**查询返回空值**（资源路径均无该类型图）→**先与目录拼接即失败**（字符串拼接空值，未保护）——失败发生在存在性检查**之前**，转换无法产出正常新事件（传播边界按编译调用层，WP04 继承；运行形态未验证）。不会「平稳跳过不补图」。

### 5.4 产物页面结构（行为描述；R04 修订）

- **单战斗（1 条 Battle:）→ 2 页**：第 1 页（事件触碰触发）：类型开场、提醒玩家、战斗文本、（双打/背景/结果变量/允许败北按需设置战斗规则）、正常训练家战斗起式条件分支，分支内置自开关 A；页尾训练家收尾。第 2 页（动作触发、条件自开关 A）：战后文本。
- **多战斗（≥2 条 Battle:）→ 3 页**：第 1 页在单战斗结构基础上**追加一条独立的系列检查脚本命令**（带战数与版本号——运行时合同见 §5.3）——它是**额外的检查命令，不是战斗起式**；实际战斗仍是随后的正常训练家战斗起式条件分支（先检查、后战斗）。分支内再加「电话可登记？」子分支（登记台词＋Yes/No 选择＋电话登记——带公共事件或版本号的参数变体，公共事件值来自 §5.1 组合路径），自开关 A、B 双置；第 2 页（再战页，条件自开关 B）：开场后按电话变体号分支各战斗文本（首条「不超过」、末条「至少」、中间「等于」），电话再战起式＋胜后重置，自开关 A；第 3 页（结束页，条件自开关 A）：按变体号分支各战后文本（缺省回退到最后一条），并再放一次电话登记子分支（结构同第 1 页）。
- **首页与再战页的背景参数差异（R04 修订）**：首页的背景规则生成**字面字符串参数**（名称经转义处理后包在引号内）；再战页生成**不带引号的同名文本**——按事件脚本的求值语义它是**待求值内容**：普通背景名（如 forest）在求值环境无同名定义时会失败（经脚本执行的错误展示路径，WP17/WP04 交界；运行形态未验证），默认无背景（未配置 `Backdrop:`）则两页都不生成背景规则。**不能统一预测两页背景配置等效**，也不替参考产物补引号。
- **`EndIfSwitch: N` 页**：每条复制结束页骨架，改条件为开关 N（已有条件 1 则放到条件 2）、清自开关条件、内容为第一条战后文本（无则「...」）。
- **`VanishIfSwitch: N` 页**：同骨架，仅清字符文件名、命令表改为终止条；图块ID及其它图形/移动属性继承，全部继承条件仍有效（见 §5.5），不能保证任何原图形输入都完全不可见。

### 5.5 原首页面条件与页面选择（B20-C030）

生成首页从原首页保留条件集合、图形与移动/动画设置，替换命令表并把触发改为事件触碰（2）；结束页从该首页继承，再改动作触发（0）、自开关A。多战斗的再战页继承结束页、改自开关B。因此原开关1、开关2、变量阈值都保留在这些页；原自开关条件在首页保留，在结束/再战页被A/B覆盖。移动类型/路线、速度、频率、行走/踏步动画、方向固定、穿透、置顶等原有页面属性未在本转换另行复原为默认值。

EndIf与Vanish额外页从结束页继承并清自开关条件：原开关1启用时把N放在开关2并覆盖原开关2；原开关1未启用时启用开关1=N，原开关2（含启用和值）保留。变量条件继续保留。EndIf替换为第一条战后文本，Vanish清字符文件名并保留终止命令；其余图形/移动/动画属性继承，不能推断所有视觉属性都清空。

事件消费者从末页向首页搜索，第一个满足全部启用条件的页生效；开关1、开关2、变量下限、自开关是合取，A/B成立不会绕过变量和其它开关。静态夹具：原两开关7/8都启用、变量5≥10、自开关C；当前变量5=0且A/B/C均真时，生成首页、再战页、结束页都不能凭自开关生效。变量5=10且7/8真时结束A页优先于再战B页。EndIf9页保留7、覆盖8为9、保留变量、清自开关；将原开关1禁用时则9放开关1、原开关2=8仍保留。Vanish同条件门；关闭9或降低变量值不会让该消失页无条件生效。该规则只描述生成产物和静态消费者，不证明Demo事件链。

## 7. 事件改造与修复（C-3）

### 7.1 事件名规范化

事件名（大小写不敏感、整名匹配）：`tree`→`CutTree`、`rock`→`SmashRock`、`boulder`→`StrengthBoulder`；其它名不改。

### 7.2 门启发式改写

- **外层识别（全部满足才进入后续）**：事件 ≥2 页；末页有开关 1 条件、有字符图、命令 >5 条且首条为条件分支。**外层完全未命中（页数不足、末页无开关条件、无字符图、命令数不足、首条非条件分支）→ 整个事件保持原样**。
- **开关 22 特例（先于结构门执行，R05 修订）**：外层满足后，若末页条件开关恰为 22 但其名字已被改作他用（非 `s:tsOff?("A")` 形式）→ **立即**重新注册该名字到新开关并改用（记为变更；系统开关表可能同时变化）——**此副作用发生在倒数第二页结构检查之前**。
- **改写条件**：末页条件开关的名字为 `s:tsOff?("A")` 形式，且**倒数第二页**恰有 1 条玩家转移命令且不含透明标志命令。
- **三条路径（R05 修订）**：(a) 外层未命中 → 原样；(b) 外层命中＋开关 22 被改名＋**结构门不通过**（如倒数第二页有 2 条转移）→**两页不重写，但开关重注册及系统开关表变化已发生并随驱动保存**——无「无操作式保证」；(c) 外层命中＋（如有需要已重注册）＋结构门通过 → 两页重写。
- **改写（两页都重写，仅路径 c）**：倒数第二页与末页分别按以下顺序生成。路线均非重复、可跳过并带结束；标明“等路线”的位置另生成等待移动完成命令，不由路线包装的等待参数代替。

### 7.2a 门转换对跟随系统的调用合同（B20-C051）

§7.2路径c的门事件改写是真实静态消费者：入门路线在透明开后调用跟随者入门；重写末页在透明开后隐藏跟随者，玩家出门后调用归位。受路径a/b的结构门和先行副作用约束，不把普通自动跟随冒充这些显式门操作。完整输入/输出及状态以已接受 [WP13 §6.3](../engine-overworld/wp13-map-events-npc-followers.md#63-门入口的跟随操作族) 为同一合同：

入门在分派任何路线前快照玩家及全部跟随者位置，按玩家→前一跟随者的快照向量取一步，横轴非零优先，否则纵轴，向累计路线前端加入；每个跟随者执行其累计路线后不透明0。玩家(5,3)、F1(5,4)、F2(5,5)使F1上一步、F2上两步，随后各隐藏。隐藏入口只改实例不透明0，不改坐标/持久可见标记；归位入口把各实例放到玩家位置、不透明255、写持久x/y并置转移后隐藏标志；玩家开始移动清该标志，最终可见性仍受持久可见标记与该标志共同控制。

门系统路线为非重复、可跳过，包装穿透ON→请求命令→穿透OFF→结束，结束时强制OFF而非恢复先前through。路线包装的等待参数未被消费，调用本身不等待；生成门事件另有等待移动路线命令才产生等待。位置快照、异步路线、透明开关和跟随者可见标志为不同状态，不由不透明255推出本帧可见。没有跟随者时这族不产生跟随位移；多轴相差时横轴优先，区别于普通跟随的传送/寻路条件。本链只有静态源/规格依据，Demo门事件及运行观察为0。

### 7.2b 独立玩家转移规范化

仅有一条玩家转移加终止，或一条玩家转移、一条音效加终止的页面，进入本规范化路径。替换原命令序列为：音效 `Exit Door`（音量80、音调100）→ RGB(−255,−255,−255) 色调6单位 → 等待8单位 → 玩家转移（保留原目的地取得方式、目的地图/坐标/朝向，fade 强制为无）→ RGB(0,0,0) 色调6单位 → 终止。原额外音效被替换，不额外保留或叠加。与 §7.2 门路径的音效请求、原转移参数保留和结构门分开；不满足该独立结构门时不产生这份配方。已有开关重注册前缀、跟随穿透结束OFF与非事务写出合同保持。

### 7.3 通道页补设

- **识别**：事件恰 1 页、无字符图、命令 ≤12 条、含玩家转移命令；事件所在格可通行，但**左、右、左上、右上四格均不可通行**（向下格的检查在源中被注释停用，如实登记）。
- **产物**：追加一个自动运行页（条件＝注册名为 `s:tsOff?("A")` 形式的开关）：「在事件上？」分支＋透明关＋等待＋透明开＋向下移动＋临时自开关置位。
- 当前版本**没有调用者**（其唯一调用点在停用注释块内，§8.4）——登记为定义存在、当前不可达。

### 7.4 柜台合并

- **NPC 侧识别（商店/护士谓词）**：单页、移动类型固定、无任何开关/变量/自开关条件；且满足三者之一：命令 ≤1 条（空事件）；或简单商店（≤12 条命令、有字符图、首条为商店脚本起头）；或中心护士（>8 条命令、有字符图、首条为中心设置脚本起头）。
- **候选排除门（R12 修订）**：邻接候选先过空事件谓词——空/纯装饰候选（单页、固定移动、无条件、命令 ≤1 条）**直接跳过**（不检查柜台、不删除）。
- **柜台侧识别（柜台谓词）**：下列二选一——(a) 位于柜台标志格（**此支先于一切空间检查**，见下方边界条款）；(b) 在「有图事件与玩家可站位置之间」：NPC 事件有字符图、候选事件无字符图且为动作触发、NPC 格可通行、候选格不可通行、候选格另一侧（远离 NPC 方向）可通行。
- **邻接查询的真实边界（R13 修订）**：位置查询只拒绝负坐标、**不拒绝横坐标达到地图宽度**——其位置键（y×宽＋x）与下一行首格重合：宽 4 的地图上查询 (4,0) 可能取到 (0,1) 的事件。命中走 (a) 支（已在柜台格）时**不做空间核对**——所谓「四邻」扫描在最右列可能处理**几何上并不相邻**的事件（如实登记该检索缺口，不推荐为未来存储设计）。
- **多命中与共享（R12 修订）**：邻接按**上、下、左、右**固定顺序处理；每个命中都是**替换**（NPC 的页面被换成该候选的页面数组）而非累加——多候选命中时**最后处理的候选决定页面**，全部命中候选都列入删除（删除在本图全部事件处理完之后统一进行，因此同一候选可被多个 NPC 先后接收）；接收方保存的是**同一页数组对象**——后接收者套用视觉属性（图形/动画）会**改变先接收者已得页面的显示**（共享效果，如实登记）。
- **写出**：有合并才随 §10 落盘；tileset 通行表修改随 tileset/系统一同保存。

按表中六族顺序寻找具有完整旧调用形态的一行（允许调用行外围空白），括号内部至少一个字符，调用名大小写准确。边界为行首/行尾，不是整个脚本字段的绝对首尾：字段前后有独立普通行仍可命中，结果按捕获参数重组后替换整个字段，周围独立行不保留。括号内捕获不跨 LF；调用外围空白可跨换行。同一行紧贴无关前缀/后缀、错误大小写或空括号不满足该门；若字段另有合法调用行，须按六族顺序消费该行，不能用一行负例排除全字段。参数用 §15.4 切分；**没有固定参数数量验证**，匹配不保证核心参数齐备。下表的可选尾段不构成固定元数要求。旧调用名称只用于工程输入兼容识别。

- **转换与空分支检查的先后（R07 修订）**：空分支补退出仅检查训练家新起式；野外三族即使因规则插入而被重访，也不由此补退出。处理到旧形条件分支时，本循环步先**捕获**分支脚本（旧文本），随后旧形转换改写之；**本次循环步的空分支检查读取的是捕获的旧文本**——刚转换的分支在本步不按新文本检查。但两条路径要分开：转换**未插入命令**时分支原位不动、游标越过——本轮不再访问该分支，空分支退出结构**留到下一轮编译**；转换**插入了规则/注释命令**时原分支**后移**、游标在同一轮内会**再次访问**到它（此时已是新文本）——空分支检查**本轮即触发并补退出结构**。据此：**无需插入命令的旧训练家起式输入**（缺省台词/版本、无双打、无可败、结果默认）且分支为空——第一轮只改起式、第二轮才补退出；**有插入命令的旧训练家起式输入**（如仅把允许败北改为启用）且分支为空——**同一轮即完成起式转换与空分支补退出**。本驱动**不保证一次编译即达不变状态**——按家族与输入区分重跑结果（§10 不持跨家族自然幂等保证）。

### 8.3 金钱比较与售货简写改写（R09／R10 修订）

- **售货注释（R09 修订——括号形式、非冒号前缀）**：只检查**注释首行**命令（不拼接续行、不当脚本执行）；行内（**非整行锚定**——前后可有其它文本）含**大小写敏感**的 `SellItem` ＋括号形式 `SellItem(POTION,200)`（POTION和200代表合法道具名与非负价格）（关键字后任意空白、括号内道具名与**非负数字**价格、逗号分隔）才识别；冒号形（`SellItem:POTION,200`）、小写形式、负价格均不命中。命中且**道具已注册**才改写（未注册不改写）。
- **改写产物（保留已正确合同）**：免费（价格 0）→ 可放分支：给道具＋文案，否则包满文案；收费 → 金钱条件分支：钱够且可放 → 扣款＋给＋文案，否则按钱不足/包满分别文案。
- **金钱比较改写（R10 修订——目标为「至多/至少」）**：条件分支脚本恰为「玩家金钱 比较符 整数」四形之一 → 改写为**金币型条件**（消费者比较为**大于等于／小于等于**，见 §15.6）：`< N` → **至多 N−1**（99 通过、100 不通过）；`<= N` → **至多 N**；`> N` → **至少 N+1**；`>= N` → **至少 N**。边界按消费者实际比较（含等号），不是严格小于/严格大于。
- **道具球谓词改写**：条件分支脚本含旧道具球谓词（可带 Kernel. 前缀——审计名见追溯）且**不在页面第 0 条** → 替换为接收道具入口（第 0 条不动——那里通常是给予本体）。

### 8.6 转换文本与移动路线脚本的交界（B20-C007）

35条文本转换不增加新的路线分派保证。消费者为已接受 [WP13移动路线矩阵 §1/§2](../engine-overworld/wp13-move-route-matrix.md)：脚本先求值；仅在整个求值正常返回后，检查原脚本文本的任一行行首是否大小写准确地具有 `move_random_range`、`move_random_UD`、`move_random_LR` 三种前缀之一。至少一行命中时索引加1并结束当前帧；没有任何一行命中时索引加1、同帧继续；求值异常发生在判定与推进之前，即使另一行有前缀也不推进。匹配行的前导空白、接收者前缀或大小写变体使该行不命中，但其它行仍可能命中；前缀后接更长文字仍可匹配，前提仍是整个求值正常返回。前缀不是精确函数签名或语法分析条件，不为任意带前缀字符串承诺执行成功。

## 9. 文本命令规范化（D-2；Show Text 处理；R11 修订）

按源内实际先后次序执行四个子规则（组合删除范围见 §9.1，不承诺全内容保留）：

1. **格式码规范化**：仅当**行首为反斜杠且码后随空白**才处理——`\B `→`\b`（**空白一并被删除**），`\R `→`\r`，`\PG `→`\pg`，`\POG `→`\pog`，`\G `→`\G`，`\CN `→`\CN`（大小写不敏感匹配、归一为小写或大写形式按源登记）。**裸码无后随空白不改**（`\B` 后无空格 → 不动）；**已小写但码后有空白也会变化**（`\pg x` → `\pgx`，空白被吃掉）。
2. **4 行窗口**：从第 2 行起数，每数到第 4 的续行改为新文本命令首行——9 行文本在**第 5、9 行（一基）**拆分（窗口 4/4/1）。
3. **短首行合并**：首行长度 1–20、**不含 `\n`**、且有续行 → 把第 2 行以 `\n` 并入首行、删除第 2 行、重审本条——**并入后首行已含 `\n`，同一短行规则不再满足**——**只并一次**（第三条行保持为续行，不连锁）。
4. **跨命令断句**：本命令 ≥3 行且下一条也是文本命令，且本命令末行**不含** `.,!?;-"` 结尾字符且**不含反斜杠或 `<`（任何位置）→ 在合并全文中找最后的句读点（优先 `. `/`.\n`/`!`/`?`，找不到退 `, `/`,\n`）；找到则在该点切分：**前半保留为本命令**（多行），**尾段作为新的文本命令（首行＋续行）放到原下一条文本之前**，**原下一条文本被降为续行、内容保留**（不丢弃）；无句读点则不动。
- 每条规则只在实际变化时记变更；命令数/缩进按源行为保持。

### 9.1 分页与断句的组合删除范围（B20-C027）

四行分页先把原第5、第9行的命令类型改成新文本首行，但本轮已统计的行数仍为9。紧随其后的断句规则只拼接到遇见的首个新首行，即原1–4行，却按旧计数删除原1–9行；因此分页与断句组合时会丢失原5–9行，不能从孤立规则推导所有文本都保留。

精确静态夹具：同缩进的9行消息，第一行是长于20字符的 `A sufficiently long opening sentence. Tail`，其余依次 `L2`..`L9`，各续行无反斜杠、`<`与末尾句读；之后紧接独立首行 `Following message.`、最后终止命令。短首行合并门不命中；分页改原5/9类型；断句由末行L9无句读且后有独立文本而启动。实际合并串仅为第一行、L2、L3、L4（以实际换行连接），在第一行句点切分，保留前句和尾段Tail/L2/L3/L4、删除原1–9，原5–9消失；紧接的 `Following message.` 内容保留，第一次断句产物中被降为续行接尾段。游标接着处理新尾段：Tail、L2、L3、L4、Following共5条，分页把Following重新升为首行；短首行规则将Tail与L2合为含字面`\n`的一个首行，再次访问不重复合并，尾段没有可切句读，不再断句。整轮最终命令顺序为：首行 `A sufficiently long opening sentence.`、首行 `Tail\nL2`、续行 `L3`、续行 `L4`、首行 `Following message.`、终止命令。原5–9依然丢失；不得把暂时降续行当整轮最终类型。既定同缩进不改变。

反向对照：保持9行而把原末行改成以句点结尾，断句门不启动，分页4/4/1保留全内容；或移除后续文本命令，亦不启动断句。原CV-M15安全9行窗口案例和CV-M17三行断句案例仍各自有效，不能把本组合损失推广为它们也丢文。本条为静态推导，未执行转换器、事件解释器或行为向量。

- **移动的真实语义（R17 修订——本地复制后删除，不是原子重命名）**：本仓库的文件移动＝先复制（**读完全部源内容 → 目标已存在则先删除 → 重建并写入目标**）＋**删除源**。逐点后果：**目标已存在时先被删除**（不比较内容、不再询问）；**重建/写入目标失败** → 源尚在，但**原目标可能已丢失或只剩部分内容**；**删除源失败** → 可能留下新旧两份。**阶段 1 任一异常都会中止整个更新、阶段 2 引用更新不再执行**（无兜底、无回滚）。目录不存在则阶段 1 返回假（无动作、无警告）。
- **阶段 2（事件引用同步）**：遍历全部地图的每个事件页：字符图名匹配 `berrytree` 后无下划线且非四阶段名 → 同样插入下划线；有改动的地图**立即写回**（地图保存容错），每图一条记录。
- **汇总**：阶段 1 有更名 → 一条更名警告；阶段 2 每图一条记录警告；有任一记录 → 追加「RMXP 数据已被改动，请立即关闭 RMXP」警告；**全无变化 → 无任何警告**（只有完成提示）。
- **重跑**：已更名的文件与引用不再命中（幂等）；阶段 2 不检查目标文件是否存在（如实登记——引用同步不做资源校验）。

## 12. 脚本散文件与归档往返（E-2）

### 12.1 提取（归档 → 散文件）

- **守卫（R15 修订——数量启发式，不是状态判定）**：读取归档；**节数 <10** 打印「已是散文件状态」提示并返回（不写任何文件）；**节数 ≥10 照常执行**——本方向边界：**9 拒绝、10 放行、11 放行**（与合并方向不同，见 §12.2）。
- **破坏性前置**：创建目标目录后**先清空整个散文件树**（递归删除既有 rb 脚本文件与全部子目录内容）——README 亦声明「既有散文件会被删除」；无逐项确认。
- **转换**：逐节处理——节名转义为文件名安全形式（9 个实体：`&bs;`＝`\`、`&fs;`＝`/`、`&cn;`＝`:`、`&as;`＝`*`、`&qm;`＝`?`、`&dq;`＝`"`、`&lt;`＝`<`、`&gt;`＝`>`、`&po;`＝`|`）；正文解压并**删除全部 CR**；节名与正文皆空则跳过。
- **目录结构**：`[[ 名 ]]` 节 → 建目录（**两层编号约定**——编号计数器只有两级、按层重置、3 位补零、倒数第二节用 999；**两层约定是提取一侧的布局约定**，见 §12.3 与合并侧的关系）；**等号五连前缀**的节 → 回到主目录；其余节 → `NNN_节名` 加 rb 脚本后缀写入当前目录（文件编号每目录重置、3 位补零、末节用 999；空名/空节名归一为 `unnamed`）。
- **收尾（写入顺序固定）**：先把原归档**备份**到 `Data/ScriptsBackup.rxdata`，再把 `Data/Scripts.rxdata` **替换为装载器**（单节 Main 记录，内容为预置压缩数据块；固定归档可读文本的行为见 §12.4，不执行，§1）。
- **分阶段失败边界（B20-C024）**：完整顺序为数量门 → 创建/清空散文件树 → 逐节目录/脚本文件写出 → 备份 → 装载器；编号仅规定目录和文件名布局，没有另写独立索引文件。清树失败时可能已经删除一部分旧内容，后续阶段未到；清树成功后，若首个非空脚本的输出文件打开失败（尚未创建该文件），旧树已清空，备份阶段尚未到，原有备份仍是原值（原先没有则仍没有），原归档未改且未写装载器。后续目录/脚本写出失败保留此前已产生的前缀；备份写入失败可已截断或部分写入备份，装载器阶段未到；装载器写入失败时备份已写成，而原归档可能已截断或部分写入。各阶段没有全局回滚承诺，不把正常收尾当作异常时必达。

### 12.2 合并（散文件 → 归档）

- **守卫（R15 修订——同一数量启发式、方向相反）**：读取归档；**节数 >10** 打印「已是归档状态」提示并返回；**节数 ≤10 照常执行**——本方向边界：**9 放行、10 放行、11 拒绝**（与提取方向 9 拒绝、10/11 放行相反；两方向的 9/10/11 矩阵分列）。**旧归档只参与进入门**：通过门后**丢弃旧归档列表**、从目录**重新聚合**——合并结果**不包含旧装载器或其它旧节**（如根目录恰一个脚本、无子目录——无论旧档是一节装载器还是其它 ≤10 节输入，**结果只有 1 节**）。**合并产物若仍 ≤10 节**（如上述单脚本产物——1 节），**第二次合并仍通过守卫**——重新聚合并覆盖归档、节 ID 重新随机（**同方向重跑并不必然安全**，如实登记）。
- **聚合**：按目录树**深度优先、字母序**——目录内先收全部 rb 脚本文件（排序后逐个生成节：节名＝文件名去编号前缀与 rb 脚本后缀、按 9 实体反转义、空名归一为 `unnamed`；正文原样压缩；节 ID 为随机数）；再按排序逐个处理子目录：第 0 层每个子目录前先插入一个**等号十八连**的空节，第 1 层先插入空节，再插入 `[[ 子目录名 ]]` 节，然后递归（**递归无层数上限**——三层及更深的散文件树同样被聚合；两层编号约定只约束提取侧布局，§12.1）。

### 12.4 单节装载器的散文件发现与异常分层

入口读取 `Data/Scripts` 散文件树，前提为未加密工程及兼容、可访问的文件系统。每进入一个目录先枚举项目，将文件与子目录分开；本层后缀为 `.rb` 的文件（后缀大小写不敏感）按名称排序并全部先加载，然后对子目录按名称排序、逐个递归。点开头目录不进入；点开头的普通 `.rb` 文件仍入选。递归没有显式深度上限；空目录没有脚本内容动作。它不以文件/目录混合排序代替这一顺序。

每个文件先打开并读完，再进入该文件的脚本求值保护。求值的诊断标识取文件基名。阶段及失败合同为：

| 阶段／异常 | 结果与已发生状态 |
| --- | --- |
| 文件打开或读取失败 | 发生在局部求值保护之前；不由下列局部脚本错误或长消息日志分支接收，不承诺同一日志或窗口结果。目录枚举失败亦不被这层保护吸收。 |
| 脚本错误族（如语法、加载错误） | 替换为该族共同的脚本错误类别，保留原消息；不走普通错误的长度判断，不保留原具体子类的保证。 |
| 普通默认捕获类别的求值错误 | 尝试把回溯中的旧脚本编号展开为编号/标题，并把回溯附入消息；是否实际改写同一消息对象受运行时影响，不能无条件承诺成功。 |
| 到达长度判断且实际消息长度为 899 | 重新抛出原错误，不因这一长度写 `traceback.log`。 |
| 到达长度判断且实际消息长度 ≥900，日志写成功 | 覆盖 `traceback.log`，再抛固定说明 `Traceback is too big. Output in traceback.log`；长度门针对到达此处的实际消息，不能只按原始短消息判断。 |
| 消息改写或日志打开/写入失败 | 不补成功保证；失败可阻断后续固定说明，日志可能未写成或只部分写成。其它不属默认捕获类别的异常不由此统一处理。 |

发生未恢复异常时，不继续该顺序中未到的文件或目录；之前已经加载的定义、当前失败脚本已产生的前缀副作用不作整体回滚。加载成功、错误上抛和游戏后续启动是不同观察量。本合同限固定可读文本，不承诺任意归档格式兼容、完整工程或原生宿主成功。

## 16. 边界、失败与未知汇总

1. 调试门：新地图导入仅调试模式；启动检查仅调试模式，默认 Compile data 菜单由调试入口门保护；共享内容阶段自身不再检查调试标志，直接调用不套默认菜单可达结论；菜单更名需确认。
2. 无变化路径：导入 0 张、转换 0 命中、更名 0 文件——都不写文件、各有既定消息或静默返回；往返守卫是**数量启发式**（提取 <10 拒绝、合并 >10 拒绝、**恰 10 两边放行**、合并产物 ≤10 节可再次合并覆盖，§12.1/§12.2）。
3. 识别不误判不保证：门/通道/柜台/mart/护士均为启发式（WP61 识别边界继承）；`SellItem` 只认**注释首行内大小写敏感的括号形式**（`SellItem(POTION,200)`（ASCII括号/逗号；合法名/非负价格），非锚定、冒号形/小写/负价不命中）且道具已注册才改写；道具球名需道具已注册。
4. 文本级替换的边界：**35 对**＋2 正则非语法分析（旧式变量读取**后随**赋值/比较运算符不动——运算符跟在读取之后才受保护（读取位于比较符左侧），读取为右操作数仍替换）；可逃/可败判定是文本包含；逗号切分器不处理转义引号。
5. 破坏性写入如实登记：提取前清空整个散文件树（原归档有备份）；合并直接覆盖归档不备份；更名＝**本地复制后删除**（目标先删再写——目标可能先丢或部分、源删除失败留两份、阶段 1 异常阻断阶段 2）；地图写回容错吞异常（保存失败不报告）；编译驱动无整体兜底（异常中止、已写不回滚）；**一次编译不保证达不变状态**（旧训练家起式空分支二轮才补、治疗残留与单命令持续插入、门路径 b 副作用，§8.2/§8.4/§7.2）。
6. 停用/不可达：玩家转移处理的大停用块、通道补设的唯一调用点、事件 ID 工具的无效实现、装载器脚本（可静态解码读取但不执行，§12.4）、townmapgen 的引号处理停用代码。
7. 训练家检查副作用：类型不存在可触发编辑器新建（编译期、调试下）；缺训练家三回答（建/不建/不再问）——「不再问」只影响本次编译进程；**2 条 Battle: 时第二个版本不被检查**（≥3 才逐个查再战）；**非调试或已「不再问」时本调用链直接返回**（底层缺失入口的非调试异常是该入口自身合同，不经本路径产生）。
8. **demo 素材可得性与缺口（静态身份；运行未验证）**：`Data/` 仅含 `Scripts/`、`Scripts.rxdata`、`messages_core.dat`——无 `Map*.rxdata`/`MapInfos.rxdata`/`System.rxdata`/`Tilesets.rxdata`/`CommonEvents.rxdata`（地图数据访问层无法构造，全部地图类转换在 demo 不可运行）；`Graphics/` 整体缺失（berrytree、Town Map 目录及默认区域底图 `Graphics/UI/Town Map/mapRegion0.png` 均无）。根目录 `knownpoint.bmp`／`selpoint.bmp` 均可读、受 Git 跟踪，BMP 头部为 8×8，精确身份见 §13.3；二者不属于 `Graphics/` 缺项。demo 地图/事件内容可达性归 WP77，底图补交、浏览器/宿主兼容性和全部实际运行表现保持未知。
9. 宿主/环境相关未知：两个 Ruby 脚本的实际运行环境（README 要求本机 Ruby）；extendtext 的实际效果；townmapgen 在不同浏览器的行为；开关注册槽满返回 1 的后续影响。
