# 生物身份、物种记录、来源与拥有者行为规格（净化正文；批次 9a）

分类：creature-rpg（个体身份/来源/拥有者；物种内容分层）＋ Pokémon Rules（Pokémon 特定字段）；性质：实现独立行为合同。

本规格为净化正文：按统一交接将批准输入 WP18《生物个体、物种内容、来源与拥有者》转写为独立行为文字，不含源文件路径、类名、行号与证据 URL（参考与已读集中登记于 `../../audit/source-traceability.md` 批次 9a 条目）。文中保留的字段名、入口身份名与配置键均为数据标识，不构成未来实现的数据结构或接口模板。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

---

## 1. 目的、范围与非目标

### 1.1 目的

确立生物收集 RPG 的基础词汇与不变量——物种/形态内容提供什么字段、个体自身携带什么信息、个体如何被生成与复制、来源与拥有者如何记录与变更。后续规格（属性、成长、队伍、获得流程等）据此引用，而不各自重新定义。

### 1.2 范围

1. 物种内容与个体信息的分层；物种记录的查找身份与字段责任；物种/形态变更对个体的可见影响。
2. 个体生成：创建入口、初始化清单、随机派生输入、生成上下文变体。
3. 个体复制：深/浅复制清单、身份保持与后续影响。
4. 来源与拥有者：拥有者结构、拥有者变更入口、来源记录字段、外来判定、命名。

### 1.3 非目标

- 不规定动态形态处理器的触发与优先级（另见 WP21 净化正文）；不规定 Mega/Primal（WP22）与 Shadow 字段语义（WP23）。
- 不规定队伍/盒子集合操作（WP25）、赠送/交换完整接收流程（WP26）、捕获判定与接收策略（WP38）、繁殖与孵化流程（WP33–WP35）。
- 不规定属性派生与能力数值（WP19）、HP/异常/招式/PP/持有物状态规则（WP20）、成长/学习/友好变更规则（WP30）。
- 不把参考侧字段名与类结构当作未来实现的数据模型；物种记录以「字段责任」描述。

## 2. 概念与术语

| 术语 | 定义 |
| --- | --- |
| 物种 | 内容数据记录的基身份标识；形态记录以「物种 + 形态号」区分（形态 N>0 的键为「物种_N」），基形态为 0。个体持有的物种标识始终是基身份。 |
| 形态 | 同一物种下的变体编号（整数，基形态 0）。个体存储三处相关值：forced_form（显式锁定）、time_form_set（设置时刻，WP21 使用）、当前 form。 |
| 个体 | 一个生物的运行时实体；本规格指其持久字段——身份、来源、拥有者及各类状态。 |
| personalID | 32 位整数个体标识，创建时随机；同时是多项派生属性（性别/异色/特性索引/性格）的输入（派生规则见 WP19）。 |
| 拥有者（Owner） | 结构化记录 id / name / gender / language 四项；与「当前操作者」（如战斗控制）不同。 |
| 外来 | 给定训练家与个体拥有者不一致的判定结果（比较 id 与名字，见 §7.4）。 |
| 获得来源（obtain） | 个体被获得的方式与地点时间记录：方式编号、地图、文本、等级、孵化信息、时间戳。 |
| 蛋 | 以 steps_to_hatch > 0 表示的个体状态；蛋拥有独立的孵化/来源规则（WP35）。 |
| 复制 | 生成一个与来源个体共享身份数值的副本；区别于「新建个体」（重新随机 personalID/IV）。 |

## 3. 物种内容与个体信息分层

### 3.1 物种记录的查找身份

1. 每条物种记录有 id（基形态为物种符号本身；形态 N>0 为「物种_N」）、species（基身份）、form（编号）。
2. 按形态查找的回退：请求「物种+形态 f」时，若形态记录不存在，回退到基形态记录；基记录也不存在则整体未命中。调用入口按 WP03 的查找语义分层（报错入口 / 返回空入口 / 存在性判定）。
3. 枚举「全部物种」只遍历基形态记录（form 0）；物种计数同样只计基形态。
4. 形态记录在编译时从基记录继承未定义字段：标量字段直接拷贝；集合类字段（属性/基础能力/EV 产出/教学/蛋招式/特性/隐藏特性/蛋组/后代/标记）克隆；等级招式表与进化表为空时整表继承；三项野生持有物仅在全部为空时整组继承。运行时按「形态记录已含继承值」使用。

物种Shape/Color/Habitat采用[WP03固定目录](../generic-kernel/wp03-content-identity-and-schema.md#61-物种描述字段的固定身份目录)的14/10/10个精确身份、定义次序和14个参考体型图标位置；显示名再本地化。HeadArms/Gray/WatersEdge接受，未知身份枚举拒绝；基础省略仍Head/Red/None。Habitat不代替Area遭遇/地图查询。

前身关系在编译时按首次发现选择，形态对应关系优先再回基础关系，见[WP31 §3.8](../pokemon-rules/wp31-basic-evolution.md#38-作者前向列表合并与反向前身选择)。物种的最低等级与繁殖回溯消费已选前身；其它合法前向路径不被删除。既有形态继承、默认与个体生成次序保持。

### 3.4 物种/形态变更对个体的影响

**物种变更**（入口身份 species=；输入：物种/形态/记录标识；前置：记录存在，按 WP03）：

1. 解析目标记录；若目标记录的基身份与当前相同，无效果直接返回（边界：不能用此入口把个体切到同物种的另一形态）。
2. 设为基身份；形态目标：目标记录存在默认形态标记（DefaultForm_N）则取 N；否则若目标记录自身形态号 >0 则取该形态号；两者都没有则保留当前形态。
3. 清除 forced_form；若新物种为单性别/无性别，则清除性别缓存（下次读取时重派）；等级缓存清除（按当前经验、新成长曲线重派）；特性缓存清除（索引保留，特性按新物种重新解析）；重算能力。
4. 不改变：经验、招式、来源记录、拥有者、昵称、友好度等。

**形态变更**（三个入口的副作用差异，均登记为不变量）：

| 入口身份 | 形态处理器 | 特性缓存 | 能力重算 | 图鉴登记 | 中断点 |
| --- | --- | --- | --- | --- | --- |
| form= | 调用 | 清除 | 是 | 是（有玩家时；登记读取性别与普通异色——这两个缓存会因此被填充） | 无 |
| setForm | 调用 | 清除 | 是 | 是（有玩家时；登记读取性别与普通异色） | 形态已设、处理器未调用前让出一次（供提示消息） |
| form_simple= | 不调用 | 不清除 | 是 | 不登记 | 无 |

读取语义：

- form 读取：若 forced_form 有值优先返回；战斗中或仓库中直接返回存储形态（不触发处理器）；否则调用动态处理器，若结果不同则以 form= 写回。
- form_simple 读取：直接返回 forced_form 或存储形态（无处理器）。物种内容记录的读取（如基础能力数据）使用 form_simple。
- 按个体取正面／背面精灵或图标则先读取普通 form，继承其强制值、战斗／仓库守卫及动态提交合同，再以所得形态选资源（WP15 §4.1、WP21 §3.4/§4）。摘要的个体精灵／图标也消费此入口，前置界面构造须正常。低层按显式物种／形态取图仅消费已求值的数值参数；若调用者先读个体形态取得参数，整条调用链仍可能提交形态。WP35 §5.2 与 EG-13/20 已描述孵化演出的这一交界，保持其原范围。

边界：物种设置为未知标识按 WP03 查找失败处理（报错）；形态处理器结果与存储形态相同则不写回（不触发 form= 的副作用链）。

## 4. 个体生成

### 4.1 创建入口与参数

入口：创建（物种， 等级， 拥有者 = 玩家， 是否带默认招式 = 真， 是否创建后复检形态 = 真）。

- 输入：物种（符号/字符串/记录）、等级、拥有者（Owner 记录 / 玩家 / NPC 训练家 / 其它）、withMoves、recheckForm。
- 前置：物种记录存在（按 WP03）；等级在允许区间（越界按 WP19 等级设置规则报错）。
- 输出：新的个体实体，其中：
  - 身份：species = 基身份；form = 目标记录的基形态（默认形态优先）；forced_form / time_form_set = 空；personalID = 32 位随机。
  - 等级/经验：由等级设置写入（经验 = 该等级的最小经验；等级缓存已写入）。
  - 蛋标记：steps_to_hatch = 0（非蛋）。
  - 异常：状态 = 无、计数 = 0（经「治疗异常」路径写入）。
  - 性别/异色/特性索引/特性/计算用性格覆盖：初始化赋空；基础能力重算不读取这些缓存。**返回时的最终缓存状态取决于此后的读取路径**——创建形态复检经形态设置触发图鉴登记时，登记会读取性别与普通异色（返回前已缓存）；关闭复检且无其它读取副作用时可保持未缓存（首次读取时按 WP19 派生）。
  - 性格：**返回时已被求值并缓存**——创建末尾的能力重算需要读取计算用性格；不能把初始化赋空当作最终输出。
  - 持有物/邮件：无。
  - 招式：withMoves 为真时按「等级可达学习表」初始化（规则归 WP20）；first_moves = 空。
  - 缎带/标记/华丽大赛/病毒：空/0。
  - 昵称：无（显示物种名）。
  - 友好度：直接采用物种记录值，创建入口不另夹到 0–255。合法基础物种 PBS 的 Happiness 为非负整数，省略为70；独立作者值256可登记并在成功创建后保留256。编辑器的0–255限制及后续受控变化是不同入口（WP30 §7.1）。
  - 球：默认普通球。
  - 个体值：六项各自 0–31 均匀随机；上限覆盖表为空；努力值六项均为 0。
  - 拥有者：Owner 记录按原样使用；玩家/NPC 训练家记录转换为 Owner（§6.1）；其它输入回退为空 Owner（id = 0、名字空、性别 2、语言 2）。
  - 来源：方式 = 0（遇到）；若命运相遇开关当前为开则方式 = 4；地图 = 当前地图 id（无地图时 0）；来源文本 = 空；来源等级 = 创建等级；hatched_map = 0；timeReceived = 当前时间（写入时取整为整数秒）；孵化时间戳 = 空；fused = 空。
  - 生命：初始 1/1，随即因能力重算调整为满。
  - 能力：创建末尾重算一次。
- 创建后形态检查：recheckForm 为真且当前形态为 0 时，调用「创建时形态」处理器（WP21）；若返回形态值，以提交型入口写入（返回 0 也提交，含 §3.4 的副作用链，图鉴登记会读取性别/普通异色），并仅当 withMoves 为真时重做一次招式初始化（等级可达学习表按新形态）；withMoves 为假时复检不产生招式重置。

### 4.2 随机与派生输入

**基础初始化**抽取 personalID（32 位）与六项个体值；**完整创建不保证只有这两类随机来源**：形态为 0 且复检开启时，创建处理器还可抽样，例如 UNOWN 从 0–27 取形态，PUMPKABOO/GOURGEIST 按 5%/15%/45%/35% 取 3/2/1/0。复检关闭则不调用该处理器；非零初始形态也不进入此创建复检。

性别、异色、特性索引、特性由 personalID（异色还叠加拥有者 id）按需派生、首次读取后缓存；**性格为例外：创建返回前已被能力重算求值并缓存**——普通创建返回后性格已确定，之后更改 personalID 不会重派该缓存。处理器的额外形态抽样不据此重派性格；登记对性别/普通异色的缓存影响仍按 §4.1。等级/能力为确定性换算（WP19）。

### 4.3 生成上下文变体

| 上下文 | 生成要点 | 责任规格 |

### 4.3.1 普通 NPC 成员的确定性覆盖

前提是普通训练家记录装载正常返回、数据身份有效且无后续装载钩子/插件覆写。先普通创建（不自动带招式）。条目给定形态（含 0）时采用简单存储形态写入：该次写入不调用形态处理器、不登记图鉴、不清特性缓存，仍重算能力。随后设置持有物；显式招式列表存在且非空时，按给定顺序逐个静默学习，否则按当前等级可达学习表重建默认招式。招式通用细节引用 [WP20 §5.1](wp20-hp-status-moves-helditem.md)。下表的省略值仍覆盖创建结果，不能把普通个体按 personalID 的派生当作最终 NPC 缺省。

| 字段 | 省略时 | 显式内容及顺序 |
| --- | --- | --- |
| 特性索引 | 写 0，清特性缓存 | 给定索引先写；随后设置显式 Ability，省略 Ability 则清显式/解析缓存；槽 0 不阻止合法显式特性覆盖 |
| 性别 | 男性训练家类型尝试设男，其余类型尝试设女 | 显式 Male/Female 优先；沿 WP19 单性别/无性别守卫，不能改固定性别。训练家类型自身的 Unknown=2 保持 |
| 普通异色 / 超级异色 | 依次写 false / false | 先普通，再超级；超级 true 会把普通置 true；随后 Shadow=true 的制作阶段再把普通置 false，不清超级标记 |
| Nature | 以当前完整物种登记键序列中基物种的零基位置 iS，加训练家类型登记键序列的零基位置 iT，取 (iS+iT) mod N，选 Nature 登记序对应身份；固定 N=25 | 显式 Nature 使用给定身份；设 Nature 沿 WP19 的重算规则。位置不是全国编号，不先过滤物种表为基础形态；身份映射用 WP19 表 N |

之后处理可选友好、昵称、Shadow（含上述普通异色覆盖）、球，最后重算。字段设置有先后，失败不保证撤销已创建成员或已完成覆盖；后续装载事件允许另行覆写，表中不承诺钩子之后的最终值。

固定内容 COOLCOUPLE/Alice & Bob 未给两个成员的 Gender；该类型 Unknown=2，不为男性，正常装载后的比例物种 TURTWIG、CHIMCHAR 均为女。男性类型缺 Gender 或显式 Male 的比例物种为男；无性别物种忽略尝试设女。缺 AbilityIndex 且无显式 Ability 的合法双自然特性物种，即使 personalID 为奇数也写槽 0。SuperShiny=true、非 Shadow 时两异色都真，随后 Shadow=true 则普通假/超级真。人工登记位置夹具 iS=0、iT=1、N=25 的 Nature 是 LONELY；不把该夹具当成随附 NPC 的实际 Nature。以上为静态推导，未执行随机创建或装载。

## 5. 个体复制

### 5.1 复制语义

复制产生一个同身份数值的副本，与「新建个体」（新 personalID、新个体值）相对。

- 深复制（副本拥有独立子对象）：iv、ivMaxed、ev（逐项复制）；moves（每个招式对象独立复制，招标识/当前 PP/PP 提升计数随副本，之后两端各自演化）；first_moves；owner（新的 Owner 对象、相同四项值）；ribbons。
- 浅复制（按值复制或共享引用）：所有数值字段（species/form/等级/经验/HP/异常/计数/来源记录/昵称/球/友好度/personalID 等）按当前值复制；未单独重建的容器/对象为共享引用——markings 数组、fused 指向的个体对象、mail 对象等（副本上的改动经共享对象可影响原个体，反之亦然）。
- 身份含义：副本与原个体 personalID、拥有者相同，由它们派生的属性（异色/性别/特性索引/性格）在缓存未重置时完全一致；已缓存的派生值随复制保留，即使之后 personalID 变化也不会自动重派（§5.2 边界）。

### 5.2 边界与不变量

1. 复制不触发任何「重新生成」：个体值、招式 PP、来源记录与当前 HP/异常均为复制时刻的原值。
2. 复制后修改一方的可派生输入（如 personalID、物种）不会自动使另一方的已缓存派生值失效；两侧缓存各自独立（深复制部分）或共享引用（浅复制部分）。
3. 复制不发出通知、不做图鉴登记（与 form= 的副作用链不同）。

## 6. 拥有者模型

### 6.1 拥有者结构（GR-009 更正后表述）

- 四字段：id（整数）、name（字符串）、gender（0 男 / 1 女 / 2 未知）、language（语言编号）。
- 取值由构造路径决定，并非一律读取宿主：
  - 直接构造：采用传入整数。
  - 由训练家构造（入口身份 new_from_trainer）：复制训练家**现有**字段值（训练家的默认初始化来源才是宿主语言映射，见 WP24 净化正文 §3；字段被改写后复制改写值，不重新读取宿主）。
  - 外来构造（入口身份 new_foreign）：省略 language 时默认 2。
  - 四类写入入口采用显式值。
- 与 WP08 界面语言选择索引分开、不随 UI 切换自动回改。
- 构造与四类写入入口均做类型校验（校验失败报错）。
- 外来构造的 id 取「任意其它」（随机 32 位且不等于玩家 id；由玩家侧生成），默认名字空串、性别 2、语言 2。
- public_id = id 的低 16 位（id 与 0xFFFF 按位与）；训练家侧另有「公开/秘密」两半（WP24）。
- 显示例：id 0x12345678 的公开号为 0x5678（22136）。

## 7. 来源记录

### 7.1 方式编号与字段

- 方式编号（域 {0, 1, 2, 4}）：0 = 遇到；1 = 蛋来源（含孵化）；2 = 交换；4 = 命运相遇。显示映射：[0] 在 Lv.N 遇到 / [1] 收到蛋 / [2] 在 Lv.N 交换 / [3] 空行 / [4] 在 Lv.N 命运相遇。
- 地图与文本：obtain_map = 地图编号；obtain_text 非空时优先于地图名显示（「来自 {文本}」）。
- 时间：timeReceived = 获得时刻（整数秒）；timeEggHatched 仅在方式 = 1 时可读取，否则读取返回空（写入不影响其它方式的读取）。
- 孵化记录：方式 = 1 时展示孵化时间与 hatched_map（孵化地图）。
- 球：默认普通球；捕获成功写为实际球标识；持有该球的个体在友好度奖励等处被读取（WP30 引用）。
- 已定位写入者：孵化（方式 1 + 孵化地图 + 孵化时间）；交换（方式 2）；神秘礼物（方式 4 + 获得时间 + 地图）；装蛋工具（来源文本）；调试（方式 0/1、孵化地图清零）。创建默认见 §4.1。

### 7.2 外来判定

- 判定输入：拥有者与一个训练家（默认玩家）。**当且仅当 id 与名字同时相等**则为非外来；任一不同即为外来。性别与语言不参与判定。
- 边界例：id 相同、名字不同（如改名后）→ 外来；id 不同、名字相同 → 外来；id 与名字都相同、性别/语言不同 → 非外来。
- 已定位消费者：战斗服从性判定（外来 + 高等级按配置参与不服从；完整规则归 WP40）；调试显示。其它消费者按后续规格核对，不声称穷尽。

### 7.3 命名与展示属性

- name 读取：有昵称返回昵称，否则返回物种名（本地化，WP08）。
- name 写入规则：值为空、nil、或与物种名相等时，昵称被清除（恢复显示物种名）；不截断（长度约束由入口负责，昵称上限 10）。
- 已定位入口的长度处理：外来赠送入口按上限截断传入昵称；命名场景的名称输入上限按 WP17 的文字输入边界与上限 10 交互。命名提示可被系统选项跳过（「是否询问昵称」选项非 0 时跳过，WP02 配置索引）。
- 物种尺寸：height / weight 读取自当前有效物种／形态记录（单位 0.1 m / 0.1 kg）；另有以原始 IV/PID 计算个体毫米尺寸的可得辅助，独立合同见 §7.4，不替代这两个字段。
- 蛋的展示：蛋个体昵称通常为 Egg（装蛋工具写入；孵化时昵称被重置为空，显示物种名）。

### 7.4 个体尺寸辅助：毫米数学合同

这是可得的 Pokémon Rules / Demo-DX 计算能力，与 §7.3 的物种高度读取和展示分开。输入为当前有效物种／形态记录的整数高度 H（单位 0.1m）、合法 32 位个人编号 P、六项原始 IV；输出为整数毫米。它不抽随机、不写个体状态，不读取 EV、等级、Nature、能力计算用的性格覆盖或强化 IV 标记。固定脚本只定位到此辅助定义，未定位普通静态调用者；地图／Demo／插件／动态调用未知，不据此宣称默认钓鱼或其它玩家流程已启用，也不强制未来保留同名接口。

**组合输入。** 六项原始 IV 各取除以 16 的余数（0…15）。定义两个无符号字节特征：先将攻击余数与防御余数按位异或，乘 HP 余数，再与 P 的最低字节按位异或，得到 B；另将特攻余数与特防余数按位异或，乘速度余数，再与 P 的次低字节按位异或，得到 C。按位异或按整数二进制位定义，乘积不在异或前截断。B、C 均在 0…255；尺寸索引 s=256B+C，在 0…65535。P 的高 16 位不参与此辅助。

**整数阶段。** 由下表选偏移基数 A、除数 D 和索引基准 T，先得到整数比例 q=A+⌊(s−T)/D⌋，再输出毫米 M=⌊q×H/10⌋。这两个整数阶段不可合并为最后一次取整；也不能直接把 H 当作毫米。各区间均含两端，穷尽合法索引。

| s 闭区间 | A | D | T | q 两端 |
| --- | --- | --- | --- | --- |
| 0…9 | 290 | 1 | 0 | 290…299 |
| 10…109 | 300 | 1 | 10 | 300…399 |
| 110…309 | 400 | 2 | 110 | 400…499 |
| 310…709 | 500 | 4 | 310 | 500…599 |
| 710…2709 | 600 | 20 | 710 | 600…699 |
| 2710…7709 | 700 | 50 | 2710 | 700…799 |
| 7710…17709 | 800 | 100 | 7710 | 800…899 |
| 17710…32709 | 900 | 150 | 17710 | 900…999 |
| 32710…47709 | 1000 | 150 | 32710 | 1000…1099 |
| 47710…57709 | 1100 | 100 | 47710 | 1100…1199 |
| 57710…62709 | 1200 | 50 | 57710 | 1200…1299 |
| 62710…64709 | 1300 | 20 | 62710 | 1300…1399 |
| 64710…65209 | 1400 | 5 | 64710 | 1400…1499 |
| 65210…65409 | 1500 | 2 | 65210 | 1500…1599 |
| 65410…65535（默认段） | 1700 | 1 | 65510 | 1600…1725 |

默认段的 T=65510，起点却为 65410；负的 s−T 在这里也是合法输入，不能自行补成不存在的 1600／1650 分段或把这一段移到 65510 才开始。H=7、原始 IV 均 0 时：P=0→B=0、C=0、s=0、q=290→203mm；P=2304→B=0、C=9、s=9、q=299→209mm；P=2560→C=10、s=10、q=300→210mm。任意 s 可用零 IV 与 P=256×(s mod 256)+⌊s/256⌋ 的合法夹具覆盖；全部分段两端见 U03-SZ-B01…U03-SZ-B15。

失败／范围限定：本段只保证有效个体、合法原始 IV/PID 和有效整数高度输入的静态数学；缺失物种记录、非法字段与外部调用故障未建立新恢复／回滚合同。未知用途及未来产品范围保持待定，事实表先补齐。U03-SZ01…U03-SZ05 与全部边界均为 NOT_EXECUTED 静态设计，未调用参考辅助或运行独立行为模拟。

## 8. 规则与不变量

1. 任何个体恒有：基身份物种、至少一项形态存储值、拥有者记录（可能为全零占位）、personalID、可由经验换算的等级。
2. 来源方式域 {0, 1, 2, 4}；孵化时间戳只在方式 = 1 时可读。
3. 拥有者变更不追溯清理已有派生缓存；外来判定只用 id 与名字。
4. 物种变更的形态选择优先级：目标默认形态标记 > 目标记录形态号 > 保持原形态；同基身份目标为无效果。
5. 形态三入口的副作用差异（§3.4 表）为不变量；form_simple= 不触发处理器、不登记图鉴、不清特性缓存。
6. 副本与新建的区分：副本保持身份数值（personalID/拥有者/个体值），新建全部重新随机（personalID/个体值）。
7. 昵称与物种名等价即视为无昵称；未命名个体按物种名显示。
8. 创建时的默认来源方式受命运相遇开关影响（开 → 4，否则 0）；开关状态在创建时刻读取一次（之后开关变化不回改已有个体——按写入路径静态可得；事件脚本运行时行为未验证）。

## 9. 边界与失败

- 未知物种标识：按 WP03 查找语义报错或空（入口不同）；创建路径按报错处理。
- 等级越界：创建/设置等级时按 WP19 报错；本规格不重复定义范围值。
- 拥有者写入入口收到非 Owner 值：校验报错；拥有者构造器字段类型不符：报错。
- species= 指向同基物种的形态标识：无效果（不能借此改形态）。
- **动态形态读取**的处理器返回与当前相同的值：不写回、无副作用链。**显式提交形态与创建复检提交**没有同值短路，仍执行提交副作用（WP21）。
- 复制共享引用清单（§5.1）之外不得扩展声称；共享对象的后续互相影响未穷尽逐项验证。
- cannot_store / cannot_release / cannot_trade：仅定位到调试写入与仓库/队伍 UI 读取；正常流程写入者未定位（可能由事件脚本/插件设置，属未决类，搜索未命中不等于不存在）。
- 昵称展示的极端输入（超长字符串直接赋给写入入口）不被清除、按值保留——与入口截断行为不同源。
