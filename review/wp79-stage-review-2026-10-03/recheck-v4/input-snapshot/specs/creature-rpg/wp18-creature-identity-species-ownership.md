## 1. 目的、范围与非目标

**目的**：确立 Creature RPG 的基础词汇与不变量——"物种/形态内容提供什么字段、个体自身携带什么信息、个体如何被生成与复制、来源与拥有者如何记录与变更"。后续包（属性、成长、队伍、获得流程等）据此引用，而不是各自重新追踪个体类或物种 schema。

**范围**（WP18 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP18-A：物种内容与个体信息的分层；物种记录的查找身份与字段责任；物种/形态变更对个体的可见影响。
2. WP18-B：个体生成（创建入口、初始化清单、随机派生指针、生成上下文变体）。
3. WP18-C：个体复制（深/浅复制清单、身份保持与后续影响）。
4. WP18-D：来源与拥有者（拥有者结构、拥有者变更入口、来源记录字段、外来判定、命名）。
5. F06-01、F06-02、F07-01 中属于 WP18 部分的状态更新。

**非目标**：

- 不提取动态形态处理器（`getForm`/`onSetForm`/`getFormOnCreation` 等）的触发与优先级（WP21）；不提取 Mega/Primal（WP22）、Shadow 字段语义（WP23）。
- 不提取队伍/盒子集合操作（WP25）、赠送/交换完整接收流程（WP26）、捕获判定与接收策略（WP38）、繁殖与孵化流程（WP33–WP35）。
- 不提取属性派生与能力数值（WP19）、HP/异常/招式/PP/持有物状态规则（WP20）、成长/学习/友好变更规则（WP30）。
- 不复制参考实现的类层次或字段表设计；物种 schema 以"字段责任"描述，不作为未来数据结构模板。
- 不运行游戏或任何参考脚本；不修改 `reference/`。

## 2. 概念与术语

- **物种（species）**：内容数据记录的基身份标识；形态记录以"物种 + 形态号"区分（`物种_N` 键，N>0），基形态为 0。个体持有的 `species` 始终是基身份。
- **形态（form）**：同一物种下的变体编号（整数，基形态 0）。个体存储三处相关值：`forced_form`（显式锁定）、`time_form_set`（设置时刻，WP21 使用）、当前 `form`。
- **个体（individual）**：一个生物的运行时实体；本文指其**持久字段**——身份、来源、拥有者、以及各类状态（其余状态分别归 WP19/WP20 等）。
- **personal ID**：32 位整数个体标识，创建时随机；它同时是多项派生属性（性别/异色/特性索引/Nature）的输入（派生规则见 WP19，本文只登记"派生依赖 personal ID 与拥有者"这一事实）。
- **拥有者（Owner）**：结构化记录 `id/name/gender/language` 四项；与"当前操作者"（如战斗控制）不同（控制归属归战斗包）。
- **外来（foreign）**：给定训练家与个体拥有者不一致的判定结果（比较 id 与名字，见 6.4）。
- **获得来源（obtain）**：个体被获得的方式与地点时间记录（方式编号、地图、文本、等级、孵化信息、时间戳）。
- **蛋（egg）**：以 `steps_to_hatch > 0` 表示的个体状态；蛋拥有独立的孵化/来源规则（WP35）。
- **复制（clone）**：生成一个与来源个体共享身份数值的副本；区别于"新建个体"（重新随机 personal ID/IV）。

## 3. WP18-A：物种内容与个体信息分层

### 3.1 物种记录的查找身份（`S/010_Data/002_PBS data/008_Species.rb` 全文，本轮逐行阅读）

- 每条物种记录有 `id`（基形态为物种符号本身；形态 N>0 为 `物种_N`）、`species`（基身份）、`form`（编号）。
- **按形态查找的回退**：请求"物种+形态 f"时，若形态记录不存在，回退到基形态记录；基记录也不存在则整体未命中（nil）。调用入口按 WP03 的查找语义分层（`get` 报错 / `try_get` 返回 nil / `exists?` 判定）。
- 枚举"全部物种"只遍历基形态记录（form 0）；物种计数同样只计基形态。
- 形态记录在**编译时**从基记录继承未定义字段：标量字段直接拷贝；集合类字段（属性/基础能力/EV 产出/教学/蛋招式/特性/隐藏特性/蛋组/后代/标记）克隆；等级招式表与进化表为空时整表继承；三项野生持有物仅在全部为空时整组继承（规则归 WP04/编译层；运行时按"形态记录已含继承值"使用）。

### 3.4 物种/形态变更对个体的影响（`001_Pokemon.rb:123–184`）

**物种变更 `species=`**（输入：物种/形态/记录标识；前置：记录存在，WP03）：

1. 解析目标记录；若目标记录的**基身份**与当前相同 → 无效果直接返回（**边界**：不能用此入口把个体切到同物种的另一形态）。
2. 设为基身份；形态目标：目标记录存在"默认形态"标记（`DefaultForm_N`）→ 取 N；否则若目标记录自身形态号 >0 → 取该形态号；两者都没有则保留当前形态。
3. 清除 `forced_form`；若新物种为单性别/无性别，则清除性别缓存（下次读取时重派）；等级缓存清除（按当前经验、新成长曲线重派）；特性缓存清除（**索引保留**，特性按新物种重新解析）；重算能力。
4. 不改变：经验、招式、来源记录、拥有者、昵称、友好度等。

**形态变更**（三个入口的差异，均登记为不变量）：

| 入口 | 形态处理器（onSetForm） | 特性缓存 | 能力重算 | 图鉴登记 | 中断点 |
| --- | --- | --- | --- | --- | --- |
| `form=` | 调用 | 清除 | 是 | 是（有玩家时；登记读取性别与普通异色——这两个缓存会因此被填充） | 无 |
| `setForm` | 调用 | 清除 | 是 | 是（有玩家时；登记读取性别与普通异色） | 形态已设、处理器未调用前让出一次（供提示消息） |
| `form_simple=` | **不调用** | **不清除** | 是 | **不登记** | 无 |

- **读取语义**：`form` 读取——若 `forced_form` 有值优先返回；战斗中或仓库中直接返回存储形态（不触发处理器）；否则调用动态处理器，若结果不同则以 `form=` 写回。`form_simple` 读取——直接返回 `forced_form` 或存储形态（无处理器）。物种内容的读取（如能力/图像）使用 `form_simple`。

**边界**：物种设置为未知标识按 WP03 查找失败处理（报错）；形态处理器结果与存储形态相同则不写回（不触发 `form=` 的副作用链）。

## 4. WP18-B：个体生成

### 4.1 创建入口与参数（`001_Pokemon.rb:1159–1226`）

**入口**：`new(species, level, owner = 玩家, withMoves = true, recheckForm = true)`。

- **输入**：物种（符号/字符串/记录）、等级、拥有者（Owner 记录 / 玩家 / NPC 训练家 / 其它）、是否带默认招式、是否创建后检查形态。
- **前置**：物种记录存在（按 WP03）；等级在允许区间（1–最大等级；越界按等级设置规则报错，见 WP19 §4.2）。
- **输出**：新的个体实体，其中：
  - 身份：`species`=基身份；`form`=目标记录的基形态（默认形态优先）；`forced_form`/`time_form_set`=空；`personalID`=32 位随机。
  - 等级/经验：由等级设置写入（经验=该等级的最小经验；等级缓存已写入，见 WP19 §4.2）。
  - 蛋标记：`steps_to_hatch`=0（非蛋）。
  - 异常：状态=无、计数=0（经"治疗异常"路径写入）。
  - 性别/异色/特性索引/特性/计算用 Nature 覆盖：**初始化赋空**；基础能力重算不读取这些缓存。**返回时的最终缓存状态取决于此后的读取路径**——如创建形态复检经形态设置触发图鉴登记，登记会读取性别与普通异色（→返回前已缓存）；关闭复检且无其它读取副作用时则可保持未缓存（首次读取时按 WP19 派生）。
  - Nature：**返回时已被求值并缓存**——创建末尾的能力重算需要读取"计算用 Nature"（无覆盖时求值表现 Nature）；不能把初始化赋空当作最终输出（WP19 §3.5/§4.6）。
  - 持有物/邮件：无。
  - 招式：`withMoves` 为真时按"等级可达学习表"初始化（规则归 WP20 §5.1）；`first_moves`=空。
  - 缎带/标记/华丽大赛/ Pokérus：空/0。
  - 昵称：无（显示物种名）。
  - 友好度：=物种记录值。
  - 球：默认普通球。
  - 个体值：六项各自 0–31 均匀随机；上限覆盖哈希为空；努力值六项均为 0。
  - 拥有者：Owner 记录按原样使用；玩家/NPC 训练家记录转换为 Owner（4.4/6.1）；其它输入回退为空 Owner（id=0、 名字空、性别 2、语言 2）。
  - 来源：方式=0（遇到）；若"命运相遇开关"当前为开 → 方式=4；地图=当前地图 id（无地图时 0）；来源文本=空；来源等级=创建等级；`hatched_map`=0；`timeReceived`=当前时间（秒）；未孵化时间戳=空；`fused`=空。
  - 生命：初始 1/1，随即因能力重算调整为满（公式与写回见 WP19 §4.5/§4.6）。
  - 能力：创建末尾重算一次。
- **创建后形态检查**：`recheckForm` 为真且当前形态为 0 时，调用"创建时形态"处理器（WP21）；若返回形态值 → 以 `form=` 写入（含 §3.4 的副作用链，图鉴登记会读取性别/普通异色），并**仅当 `withMoves` 为真时**重做一次招式初始化（等级可达学习表按新形态）；`withMoves` 为假时复检不产生招式重置。

### 4.2 随机与派生输入（详见 WP19）

创建时只有两类随机来源：`personalID`（32 位）与六项个体值。其余属性（性别、异色、特性索引、特性）由 `personalID`（异色还叠加拥有者 id）**按需派生**、首次读取后缓存；**Nature 为例外：创建返回前已被能力重算求值并缓存**——普通创建（含禁用形态复检、或处理器无额外副作用的情形）返回后 `hasNature?` 已为真，之后更改 `personalID` 不会重派该缓存。等级/能力为确定性换算（WP19 §3.2–3.5）。

## 5. WP18-C：个体复制

### 5.1 复制语义（`001_Pokemon.rb:1135–1151`）

复制产生一个**同身份数值**的副本，与"新建个体"（新 personalID、新个体值）相对：

**深复制（副本拥有独立子对象）**：`iv`、`ivMaxed`、`ev`（逐项复制）；`moves`（每个招式对象独立复制，招标识/当前 PP/PP 提升计数随副本，之后两端各自演化）；`first_moves`；`owner`（新的 Owner 对象、相同四项值）；`ribbons`。

**浅复制（按值复制或共享引用）**：所有数值字段（species/form/等级/经验/HP/异常/计数/来源记录/昵称/球/友好度/`personalID` 等）按当前值复制；**未单独重建的容器/对象为共享引用**——`markings` 数组、`fused` 指向的个体对象、`mail` 对象等（副本上的改动经共享对象可影响原个体，反之亦然）。

**身份含义**：副本与原个体 personalID、拥有者相同 → 由它们派生的属性（异色/性别/特性索引/Nature）在缓存未重置时完全一致；异色/性别/特性/Nature 的**已缓存值**也随复制保留，即使之后 personalID 变化也不会自动重派（5.2 边界）。

### 5.2 边界与不变量

- 复制不触发任何"重新生成"：个体值、招式 PP、来源记录与当前 HP/异常均为复制时刻的原值。
- 复制后修改一方的可派生输入（如 personalID、物种）不会自动使另一方的已缓存派生值失效；两侧缓存各自独立（深复制部分）或共享引用（浅复制部分，如 markings）。
- 复制不发出通知、不做图鉴登记（与 `form=` 的副作用链不同）。

## 6. WP18-D：来源与拥有者

### 6.1 拥有者结构（`005_Pokemon_Owner.rb` 全文，本轮逐行阅读）

- 四字段：`id`（整数）、`name`（字符串）、`gender`（0 男/1 女/2 未知）、`language`（语言编号）。**取值由构造路径决定，并非一律读取宿主**：直接构造采用传入整数；`new_from_trainer` 复制训练家**现有**字段值（训练家的默认初始化来源才是宿主语言映射，见 WP24 §3.1；字段被改写后复制改写值，不重新读取宿主）；`new_foreign` 省略 language 时默认 2；四类 setter 采用显式值。与 WP08 界面语言选择索引分开、不随 UI 切换自动回改（WP24 §3.1）。构造与四类 setter 均做类型校验（校验失败报错）。
- 从训练家构造：读取训练家的 `id/name/gender/language`（训练家自身字段归 WP24）。
- **外来构造**：id 取"任意其它"（随机 32 位且不等于玩家 id；由玩家侧生成），默认名字空串、性别 2、语言 2。
- `public_id` = id 低 16 位（`id & 0xFFFF`）；训练家侧另有"公开/秘密"两半（WP24）。
- 显示例：id `0x12345678` → 公开号 `0x5678`（22136）。

### 6.2 拥有者变更入口与效果

- 设置入口仅接受 Owner 记录（否则校验报错）；设置本身不重算、不登记、不清理派生缓存（**边界**：已缓存的异色不因换主人改变；尚未读取的派生在之后按新主人计算）。
- 已定位变更入口：

| 交换（`005_UI_Trading.rb:223,230,233`） | 拥有者=外来（对方名字/性别） | 方式=2；新建个体路径先重置招式（完整流程 WP26） |

### 6.3 来源记录字段

- **方式编号**（域 `{0,1,2,4}`）：0=遇到；1=蛋来源（含孵化）；2=交换；4=命运相遇。显示映射（`006_UI_Summary.rb:566–572`）：[0] "在 Lv.N 遇到 / [1] 收到蛋 / [2] 在 Lv.N 交换 / [3] 空行 / [4] 在 Lv.N 命运相遇"。
- **地图与文本**：`obtain_map`=地图编号；`obtain_text` 非空时优先于地图名显示（"来自 {文本}"）。
- **时间**：`timeReceived`=获得时刻（秒精度，写入时取整为整数秒）；`timeEggHatched` 仅在方式=1 时可读取，否则读取返回空（写入不影响其它方式的读取）。
- **孵化记录**：方式=1 时展示孵化时间与 `hatched_map`（孵化地图）。
- **球**：默认普通球；捕获成功写为实际球标识；持有该球的个体在友好度奖励等处被读取（WP30 引用）。
- 已定位写入者：孵化（方式 1+孵化地图+孵化时间）；交换（方式 2）；神秘礼物（方式 4+获得时间+地图）；装蛋工具（来源文本）；调试（方式 0/1、孵化地图清零）。创建默认见 4.1。

### 6.4 外来判定（`001_Pokemon.rb:847–849`）

- 判定输入：拥有者与一个训练家（默认玩家）。**当且仅当 id 与名字同时相等** → 非外来；任一不同 → 外来。性别与语言**不参与**判定。
- 边界例：id 相同、名字不同（如改名后）→ 外来；id 不同、名字相同 → 外来；id 与名字都相同、性别/语言不同 → 非外来。
- 已定位消费者：战斗服从性判定（战斗包引用，`009_Battler_UseMoveSuccessChecks.rb:117`——外来+高等级按配置参与不服从；完整规则归 WP40）；调试显示。其它消费者（繁殖、彩票等）按后续包核对，不在本包声称穷尽。

### 6.5 命名与展示属性

- `name` 读取：有昵称返回昵称，否则返回物种名（本地化，WP08）。
- `name` 写入规则：值为空、nil、或**与物种名相等**时，昵称被清除（恢复显示物种名）；不截断（长度约束由入口负责，昵称上限 10）。
- 已定位入口的长度处理：外来赠送入口按上限截断传入昵称；命名场景的名称输入上限按 WP17 的文字输入边界与上限 10 交互（引用）。命名提示可被系统选项跳过（"是否询问昵称"选项非 0 时跳过，WP02 配置索引）。
- 尺寸：`height`/`weight` 读取自物种记录（单位 0.1 m / 0.1 kg）。
- 蛋的展示：蛋个体昵称通常为"Egg"（装蛋工具写入；孵化时昵称被重置为空 → 显示物种名）。

## 7. 规则与不变量

1. 任何个体恒有：基身份物种、至少一项形态存储值、拥有者记录（可能为全零占位）、personalID、可由经验换算的等级。
2. 来源方式域 `{0,1,2,4}`；孵化时间戳只在方式=1 时可读。
3. 拥有者变更不追溯清理已有派生缓存；外来判定只用 id 与名字。
4. 物种变更的形态选择优先级：目标默认形态标记 > 目标记录形态号 > 保持原形态；同基身份目标为无效果。
5. 形态三入口的副作用差异（3.4 表）为不变量；`form_simple=` 不触发处理器/不登记图鉴/不清特性缓存。
6. 副本与新建的区分：副本保持 identity 数值（personalID/拥有者/个体值），新建全部重新随机（personalID/个体值）。
7. 昵称与物种名等价即视为无昵称；未命名个体按物种名显示。
8. 创建时的默认来源方式受"命运相遇开关"影响（开 → 4，否则 0）；开关状态在**创建时刻**读取一次（之后开关变化不回改已有个体——按写入路径静态可得；事件脚本运行时行为未验证）。

## 8. 边界与失败

- 未知物种标识：按 WP03 查找语义报错或空（入口不同）；创建路径按报错处理。
- 等级越界：创建/设置等级时按 WP19 §4.2 报错；本包不重复定义范围值。
- 拥有者 setter 收到非 Owner 值：校验报错；拥有者构造器字段类型不符：报错。
- `species=` 指向同基物种的形态标识：无效果（不能借此改形态）。
- 形态处理器返回与当前相同的值：不写回、无副作用链。
- 复制共享引用清单（§5.1）之外不得扩展声称；共享对象的后续互相影响未穷尽逐项验证（标记数组、融合个体、邮件以外未逐字段核对）。
- `cannot_store`/`cannot_release`/`cannot_trade`：核心脚本中仅定位到调试写入与仓库/队伍 UI 读取；**正常流程写入者未定位**（可能由事件脚本/插件设置，属 U 类，搜索未命中不等于不存在）。
- 昵称展示的极端输入（超长字符串直接赋给 setter）不被清除、按值保留——与入口截断行为不同源。
