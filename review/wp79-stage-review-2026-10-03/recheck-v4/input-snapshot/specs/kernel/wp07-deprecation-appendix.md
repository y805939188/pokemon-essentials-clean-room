## 1. 目的与可见行为

弃用机制让游戏与插件作者平滑迁移：被标记弃用的方法仍可被调用（**兼容不阻断**），但每次使用都会向**调试控制台**发出一条弃用警告（含替代方法指引）。两类入口：**直接告警**（`Deprecation.warn_method`）与**弃用别名**（`deprecated_method_alias`——创建「调用时先告警、再按原方法执行」的别名）。

**非目标**：不复刻 Ruby 元编程/类结构（`Module#define_method` 的实现机制只作行为描述）；不定义调试控制台的宿主呈现（WP07 诊断面已述控制台输出集合，本附页只说明告警文本进入该集合）；不提取全部弃用方法清单（别名在代码各处的登记点枚举归来源索引）。

## 2. 领域概念

- **弃用警告**：一条发往调试控制台的文本（`Console.echo_warn`），含被弃用方法名、可选的移除版本、可选的替代方法（§3）。
- **弃用别名**：与被弃用方法**同名异名**的入口——调用时先发出弃用警告，再以相同参数调用原方法并返回其结果（**不阻断调用、不改变返回值**）（§4）。
- **校验**：别名创建的参数类型与目标方法存在性检查（WP03 参数验证引用——`004_Validation.rb:12–29`）。

## 3. 直接告警（`Deprecation.warn_method`，10–19 行）

| 输入 | 行为 |
| --- | --- |
| `method_name`（必需，被弃用方法名） | 组成首行文本「Usage of deprecated method "{1}" or its alias.」 |
| `removal_version`（可选，移除版本） | 非 nil 时追加一行「The method is slated to be removed in Essentials {1}.」 |
| `alternative`（可选，替代方法） | 非 nil 时追加一行「Use "{1}" instead.」 |

- 组成文本经本地化（`_INTL`，WP08 引用）后调用 `Console.echo_warn` 发往调试控制台（WP07 诊断面引用）。
- **首行（方法名）必有**；**移除版本与替代建议两个部分分别可选**——不给时对应行不存在（不推断为必给）。

## 4. 弃用别名（`deprecated_method_alias`，32–51 行）

- **参数校验**（`004_Validation.rb:12–29` 引用）：`name` 与 `aliased_method` 必须为 Symbol；`removal_in` 为 nil 或 String；`class_method` 为 true/false——**类型不符时触发参数验证错误（非返回 nil/false）**。
- **目标方法存在性**：目标（`class_method` 为真时取类的类、否则取模块/类自身）未定义 `aliased_method` 时，**抛出 `ArgumentError`（"`类名` does not have method `方法名` defined"）**——不是静默忽略。
- **别名行为**：定义 `name` 方法——被调用时：(1) 组装别名显示名（类名＋分隔符＋方法名；分隔符：`class_method` 为真用 `.`、否则用 `#`）；(2) 以别名显示名发出 `Deprecation.warn_method`（传 `removal_in` 与被别名方法显示名）；(3) **按位置参数与关键字参数调用原方法并返回其结果**——**仅显式转发位置/关键字参数，未显式转发块回调**；**目标自身失败等边界按原方法合同，不被「透明兼容」抹掉**。
- **效果**：旧名调用继续工作（兼容），但每次使用产生一条弃用警告——**兼容不阻断调用、不改变返回值（限实际参数通道与正常返回）**；不产生静默失败。

## 6. 边界与不变量

- **兼容边界**：弃用告警**不阻断调用**（别名照常执行原方法——限实际参数通道与正常返回；未显式转发块回调，目标自身失败等边界不被抹掉）；告警只进调试控制台（宿主呈现未验证）。
- **失败边界**：别名创建时的类型校验失败（参数验证错误）与目标方法缺失（`ArgumentError`）是两个不同阶段；使用阶段的告警不影响返回。
- **不变量**：`warn_method` **首行（方法名）必有、移除版本与替代建议两部分分别可选**；别名先告警后执行原方法；分隔符按 `class_method` 真假二选一。
