## 1. 目的、边界与可见流程（A）

Shadow不是异常状态枚举中的一项。它有独立标志、心量表、Hyper有效状态、暂存经验／EV和招式记录。量表从满向0推进；0仍是Shadow，表示可进入某些净化入口，不是已解除。净化成功后恢复招式与部分暂存经验、恢复受额度约束的EV、获得缎带，并可触发升级／学习／进化及命名。

玩家可见入口包含训练家暗影出场提示、捕获后的暗影个体、摘要心量表与阶段消息、呼唤、香类道具、遗迹石选择和净化室。抢夺许可／所有者改写／捕获接收**只引用WP38**；图鉴暗影拥有**只引用WP62**。本包不新增捕获公式，也不把Shadow招式的全部效果重新提取一遍；相关战斗效果由WP43–49主规格负责。

默认与可选内容必须分开：核心脚本始终含Shadow扩展，顶层训练家数据有WEEPINBELL与ELECTABUZZ的Shadow标志样本；顶层PBS没有Shadow专用类型／招式／四件道具／shadow_pokemon表。备份目录含131个Shadow配置节、18招、4物品、1类型，是**可选原始样本**，不是当前默认已编译／启用数据。实际运行数据缺失，不声称当前游戏已可达。完整数据与阶段／性格表见[附表](wp23-shadow-data-and-vectors.md)。

**S01 建立**：没有“已是Shadow则不重做”的守卫。重新建立会把Hyper清除、S／V重置、G改为M、步数归0、重新收集Shadow招式；若能收集到Shadow招式，保存**此刻已知招式**作为原招式，再按当前阶段换招。重复建立会丢弃旧暂存和旧恢复目标，不能当无副作用的幂等操作。原持物／所有者／异常／物种不由该入口统一改写。训练家装载在指定Nature、IV／EV等之后调用建立，再清普通异色并重算（WP24／19）；与直接建立本身分开。

**S02 裸标志与成功净化不同**：直接清Shadow标志只使查询不再认作Shadow，不自动返还成长或恢复招式。调用招式刷新时若已经非Shadow，才恢复记录并清招式记录；暂存经验／EV仍需净化提交处理。净化不统一改物种／形态、治疗HP／异常／PP、改所有者或清暗影拥有图鉴记录。

**S03 复制的有限隔离**：普通个体复制规则引用WP18。此扩展另复制招式标识记录的列表，但没有新建暂存EV容器，复制个体与原个体可共享同一暂存EV表；改副本该表的一项会影响原表。净化将副本的暂存EV引用置空不等于清空原表。此为本包新观察，不把“所有Shadow字段深复制”写成保证。

## 3. 心量表、阶段与下降入口（B）

合规M>0时：`H = ceil(5 × min(G,M) / M)`；非Shadow为0。默认M=4000：G=0为阶段0，1–800为1，801–1600为2，1601–2400为3，2401–3200为4，3201–4000为5。高于M的直接写值计算阶段时钳到M；正式调整入口将结果钳到0..M，且非Shadow不调整。原始量表写入口没有上述钳制，负值还会使Shadow查询为假，不能以正式调整保证所有坏输入。

下降量按**储存的Nature身份**查25行数据，不用Nature训练覆盖值；没有表项时战斗／行走／香基础100、呼唤300。香乘数分别1／2／3；其它入口的乘数参数不放大下降量。未知方法对Shadow报错，对非Shadow在前置门直接返回。数据见附表。

| 入口 | 实际接收者／门 | 写入与后续 |
| --- | --- | --- |
| 建立／重新建立 | 给定个体，无非Shadow守卫 | G=M，H通常5，招式立即刷新 |
| 派入战斗 | 初始化后的新个体是Shadow；只对**玩家本人所属席位**减量表 | 按“battle”下降；若SHADOW类型存在，战斗副本先设为该单类型；不在此刷新Shadow招式 |
| 呼唤 | 当前场上Shadow且有效Hyper，WP40的Call执行 | 先清Hyper，再按“call”下降；非Hyper Shadow无效果；不在该点刷新招式／净化 |
| 行走256步 | 玩家可战斗队伍成员，G非0；不等于所有队伍／盒子成员 | 步数到256→按“walking”下降；变到0则准备提示＋换招，跨非0阶段则换招；再计数归0。普通个体G0跳过；濒死／蛋不累计 |
| 香 | §7分入口许可后 | 先友好度“vitamin”，再按“scent”下降；量表改变则准备检查／换招。友好度变化发生在下降前的阶段门下 |
| 净化室每步 | 中心存在且G>0，无HP／蛋／256步门 | 下降本组流量，达到净化室资格则通知；**不调用阶段换招**，G已0的后续步跳过，不重复提示 |
| 战后通知 | 按战前量表快照的索引查看当前玩家队伍 | 战前值非空且非0、当前G0才调用准备检查；它先换招再提示，不完成净化 |

“准备检查”只要求仍是Shadow，会刷新招式；G0时每次调用都可显示已可净化，不使用一般purifiable的LUGIA排除门。战后心量表数组只在开始时按队伍索引保存；捕获换出成员时WP38会移动等级／要害／直接伤害数组，**未移动这份心量表数组**。因此满队替换后通知判断可能配到另一成员的战前G。本包单列该观察，不能沿用其他数组的移动保证；真实接收与成员移动主规则不改。

## 4. 招式保存、切换与恢复（B）

**S04 建立招式记录**：从可选Shadow内容中按给定顺序只取存在的招式，至多4项；没有有效项时，仅在SHADOWRUSH实际存在才使用它作为后备。最终仍为空则不保存原招、不改变当前招式。默认顶层无该招与Shadow内容的条件下，建立仍可把个体设为Shadow，但其原招式原样保留。

记录前4槽是Shadow招，后4槽保存建立时的原招标识。Shadow状态下候选＝所有已记录Shadow招＋原招的一个后缀片段：若有k个Shadow招，先跳过原招前k槽，再按H允许恢复最多 `[H0:3,H1:3,H2:2,H3:1,H4:1,H5:0]` 项。不把原招前k槽在阶段0自动全恢复；解除Shadow并刷新才恢复全部原招。

**S05 实际替换**：保留当前列表中仍在候选集合内的招式对象及相对顺序（PP／提升计数保留）；删除其余；再按候选次序补入还未掌握的有效招式，满4槽停止。补入的是新招式对象，PP初始满、提升计数0。不是每次按候选重排，也不统一回满现有PP。直接补招不走“Shadow不能教学”的通用交互门。

非Shadow刷新时，记录长度超过4才从原招区域构成候选并恢复，之后把记录置空；非空但没有原招区域的异常／空原招建立情况不会强制删除现存Shadow招。空列表在入口直接返回，甚至不改为空引用。捕获成功会刷新Shadow招并记录首招；战斗中香改变持久招式不会由该香处理器自动重建场上招式副本（WP20各写入层不能混同）。

## 5. Hyper与战斗状态（C）

**H01 进入**：常规招式流程后段，在成长与设施记账之后、结束行动的持续能力检查之前尝试；若选择已被清空（如被替换）则不尝试。执行器要求未濒死、Shadow、当前非有效Hyper、玩家本人所属。对正整数G，从0..G−1取战斗随机r；当 `r ≤ floor(M/4)` 时写Hyper真并提示。概率为 `min(G, floor(M/4)+1)/G`，不是严格小于门。默认G=M=4000为1001/4000；G≤1001时必命中。G0没有进入前置排除。**普通默认Battle、M4000、G0且其余门均通过**时，数值0随机入口返回[0,1)浮点（已审WP55§2.5与RubyUtilities数值转交合同）；任一结果都≤1000，因此本次**写Hyper存储标志为真并请求进入Hyper提示**。有效查询仍因G0为假；同前提再次调用仍能重新写入／提示，不能把“有效假”写成“未发生写入”。G0不套上述正整数概率；自定义小M、改写随机服务／插件或回放记录不套本默认结论。未执行随机接口。

普通Call菜单还要求SHADOW类型已注册且为训练家战；默认顶层缺该类型时不能仅因个体Shadow就宣称菜单有呼唤。

**H02 服从与反伤**：非有效Hyper／没有招式／招式数据类型为SHADOW则服从此门；其它招式用普通全局随机100取值<20才服从。它嵌在WP40服从链中，非内部战斗或非玩家本人会在外层提前返回；不是独立的所有战斗20%规则。回合末WP42阶段8：有效Hyper且登记招式行动者受到总HP除24的整数商伤害，普通扣血入口对存活者至少扣1、最多当前HP，然后处理濒死；不另查魔法防守。阶段18才对仍存活有效Hyper用战斗随机10%清标志，否则提示仍处Hyper；平静本身不减量表。

**H03 退出／保留**：HP赋值到0先走WP20清理并清Hyper；呼唤、香、成功净化明确清标志。普通完整治疗只恢复HP／状态／PP及进化准备，不专门清Hyper、Shadow或量表；因此存活Hyper全治疗后仍可Hyper。G降到0只令查询假，不必改存储标志，随后人工回升G可再次暴露旧标志。

初始化战斗席位前还有**旧对象**清Hyper步骤：旧队伍下标>0且旧对象此刻有效Hyper才清，随后载入新个体；不是对新入场者统一清除，也不是对下标0无条件清。普通换下先把旧战斗副本HP置0，之后初始化读有效Hyper为假，所以不能据此承诺正常换下清Hyper。索引0、濒死副本和直接初始化分别有不同门；不补造“离场一定平静”。

**H04 与形态／能力**：暗影入场将副本类型设SHADOW只在该类型存在时执行，持久个体类型不改；之后Mega／Primal完整刷新会回读个体类型，不再次自动加暗影覆盖。本包与批内WP22仅说明真实调用先后，没有新增互斥条件。Shadow招式的效果克制按WP43实际检查目标Shadow标志，不以此副本类型替代；能力阶段链引用WP49。

## 6. 成长限制、暂存与成功净化（D）

### 6.1 Shadow期间

经验主规则WP30§4、战斗时机WP42§4保持：实际收益先按**当前经验**到上限的余量钳制；心阶段≤3且实际收益>0时增加暂存S与统计，当前经验不变，不走战斗升级／学习。阶段4／5不入经验与统计。S不会计入这次最大经验余量；多次收益可使暂存总量超过最终可恢复余量。

经验裸赋值对Shadow把“请求值−当前经验”加入S，既不直接写当前经验，也无阶段／上下限保护；负差额能减少S，未正确建立S时可能在加法失败。不能把战斗阶段门当作所有赋值入口的规则。

EV主规则WP30§4.4：Shadow且阶段≤3且暂存表存在才入V，单项与总量额度都同时计入当前EV与V；**阶段4／5或V缺失落入普通EV写入分支**，不是完全禁止EV。普通分支不额外计入残留暂存；净化恢复时再按当前额度限制。EV分配本身不统一重算能力。

友好度的通用变化入口在Shadow且阶段≥4时完全返回（正负变化均拦），≤3走WP30原规则；直接写友好度不共享此门。经验糖果、通用教学／重学、普通进化等具体拒绝门引用WP30／31；Shadow不等于“所有低层成长入口都禁用”。摘要心量表替代普通成长展示，Nature文字及能力色彩在阶段≤3才显示；数据仍存在并可参与计算。

### 6.2 净化提交、调用者失败与副作用顺序

统一净化提交自身只要求Shadow且G**恰为0**；无LUGIA、非蛋、HP、场景可达或资源检查，外围入口各自设门（§7）。下表是提交顺序，**能否越过等级工具的窗口取决于实际调用者**，不能合并为一条必然成功流程：

| 阶段 | 已写状态／调用 | 取消／失败边界 |
| --- | --- | --- |
| 1 | 净化统计+1；Shadow=false、Hyper=false；授予NATIONAL缎带 | 之后消息／UI失败不回滚。重复再调用因已非Shadow早退；缎带去重引用WP21 |
| 2 | 显示心灵打开；保存当时招式标识对照；刷新原招；按新旧同位置差异提示恢复招式；重记首招 | 提示按位置差异，不等于每条都是新掌握；S05不重新教学所有原招 |

3. **直接调用的下游合同**：调用方不经选择器、直接提供**有效队伍位置** `[-1, 序号]` 时（脚本／调试等入口），放置读取该队伍成员、成功后从队伍删除并压紧——**此链没有"保留最后可战斗队员"门**：该守卫只存在于 WP25 §5 的特定 UI 入口（PC 存入前置、仓库屏存入／拿起／释放守卫等），不在净化室放置、也不在容器删除本身。此合同成立，但**不得作为正常选择 UI 的可达示例**；也不能用它证明正常 UI 能取得队伍位置。

### 8.2 亲和、节奏与每步流量

对有序外圈n只（0..4），按环顺序考察每只对下一只（含最后到第一）。若任一攻击属性对任一防御属性是超有效，即此有向边有利；**NORMAL→NORMAL额外视为有利**。不使用复合属性倍率乘积，所以“一对有利、另一对抵抗／免疫”仍可算有利；使用持久个体类型，不用暗影战斗副本的SHADOW强制类型。

令E为有利外圈边数，C为中心对当前朝向成员有利时1、否则0（无可朝向成员为0）：

- 节奏 `T = n(n+1)/2 + E`，不要求中心存在；n0为0，最大T=14。
- 中心存在时每步流量 `F = E + C + floor(n/2)`；中心不存在为0。普通显示亲和是有利2、不利1、无对象0；该显示值不能直接当流量。
- 没有跨组“更多最佳圆圈”的额外流量奖励；源注释提到但实际流量未消费别组。其它8组只参与LUGIA净化门。
- 1只外圈也形成自身到自身的环；纯NORMAL单只该边有利，而常见单纯同类型未必有利。4只纯NORMAL外圈T14；中心也含NORMAL时F7，中心不占优势时F6。

每次世界迈步通知在队伍256步处理后更新9组；中心G>0才扣F并钳到0。无外圈F0，不推进；正G到0且资格通过才提示准备好。已0不因后续步重复提示；编成改变使原本G0合格，需进入／结束编辑的检查来发现，不把步进提示视为唯一入口。室内推进不更新招式、不恢复成长、不改变HP／Hyper存储标志，也不重置队伍用256步计数。

### 8.3 资格、净化与接收

普通组：中心存在、G0且至少1外圈；忽略外圈的查询仅用于“需要至少一只普通成员”的消息。LUGIA另要求**全部9组节奏恰为14**，不要求别组有中心；也不把LUGIA的G自动清0。完成所有圆圈而G仍正时，只能继续流量推进。

领取先快照合格组列表，按组号逐一：选定并打开该组→净化演出接点（实际只刷新）→统一净化调用（§6）。**跨级恢复在该调用内的首个能力变化窗口先失败**，不进入存放／清中心或后续组询问，中心仍保留已部分修改的对象。只有该调用正常返回的路径（如有效S0同等级恢复）才继续：通用存放→无条件清中心→若还有下一组合格，询问是否切换；拒绝则关闭并停止，后面组仍保留。开始时存在任一合格组会直接进入该流程，不先询问第一只；可到达的命名等取消按§6处理。

**确实到达通用存放后**，队伍有位则入队，否则存盒；成功路径再次记录届时招式为首招。默认净化室跨级路径未到该段，不承诺其已学招或已被存放。双满时通用存放只提示并返回，随后调用者仍清中心；此前已完成的Shadow清除／缎带／成长及可到达的命名不回滚。这是O03的到达前提，与§6.2更早的跨级失败、以及§8.1取出时“盒满而队伍有位”分开。
