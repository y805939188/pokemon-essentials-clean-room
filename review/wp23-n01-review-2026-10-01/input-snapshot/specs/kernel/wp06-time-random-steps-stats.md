## 1. 目的、范围与非目标

**目的**：定义横切计量边界——哪些系统由现实时间、运行时长、帧/更新周期还是步数推动；随机输入在哪些入口、以什么形式（普通随机/显式种子/记录序列）进入系统；统计字段如何产生、累加、重置和保存。后续包据此判断"某规则由什么输入驱动、能否重现"，而不是各自重新追踪时钟与随机。

**范围**（WP06 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP06-A：时间与计时来源（现实时间、运行时长、游戏时间、帧/更新周期）及消费者推进方式。
2. WP06-B：计步与统计（计步机制、统计字段族、更新点、持久化）。
3. WP06-C：随机入口与种子（普通随机、显式种子、记录/回放）。
4. WP06-D：保存/恢复交界与可重现性。
5. F01-05、F03-05 中属于 WP06 部分的状态更新。

**非目标**：

- 不提取领域规则：地牢算法（WP14）、繁殖/遭遇概率（WP33–WP37）、设施回放（WP58）、世界天气与树果（WP59–WP61）、步数效果全集（WP61）、电话业务全集（WP63）。
- 不提取保存生命周期与迁移细则（WP09/WP10 主规格，本文只登记交界）。
- 不宣称存在统一、可注入、全局可重放的随机服务；不保证相同 seed 跨语言/随机数实现产生相同结果。
- 不运行游戏或任何参考脚本；不修改 `reference/`。

## 2. 概念与术语

- **现实时间**：宿主提供的真实时钟（`Time.now`），驱动昼夜、日历、树果、电话、彩票等。
- **运行时长**：进程已运行秒数（`System.uptime`），驱动帧计时、等待、切换、部分比赛计时。
- **游戏时间**：累计游玩秒数（`$stats.play_time`），在锚点存在时惰性累加，持久化保存。
- **帧增量**：逐帧推进的更新与 `on_frame_update` 事件及其 delta 扣减。
- **普通随机**：标准库随机调用（rand/sample/shuffle 等，无显式种子）；取值范围可由调用参数静态确定的以参数为准，跨系统/跨实现重放不可证。
- **显式种子**：指定输入决定随机序列的种子（地牢生成、彩票日期种子）。
- **记录/回放**：战斗记录保存随机数序列，回放按序列取用而非重新随机。
- 影响域编号 Dxx 见 module-map；证据状态五档定义见总览第 7 节。

### 3.3 现实时间规则族（`003_Overworld_Time.rb`，本轮逐行阅读）

- 时段判定：`isDay?`（5–20 时）、`isNight?`（20–5 时）、`isMorning?`（5–10 时）、`isAfternoon?`（14–17 时）、`isEvening?`（17–20 时）——**边界时刻** 5/10/14/17/20 时。
- 日历：星期（可写入游戏变量）、月份（名称/缩写）、季节 `(month - 1) % 4`、月相（天文公式，UTC）、星座与配对。

## 4. WP06-B：计步与统计

### 4.1 通用计步入口（WP06-R03 修订）

`pbOnStepTaken`（`012_Overworld/001_Overworld.rb:172–187`，本轮逐行阅读）：

1. **守卫**：强制路线或解释器运行中时，只触发 `on_step_taken` 并直接返回（**不累计 stepcount**）。
2. 否则：`$PokemonGlobal.stepcount`（无则初始化为 0）+1，并按 31 位掩码截断（`&= 0x7FFFFFFF`）。
3. 依次触发 `on_player_step_taken`、`on_player_step_taken_can_transfer`（共享 handled 数组，任一消费者标记已转移则返回，不再触发战斗检查）。
4. 未被事件触发且非菜单中：进入迈步战斗检查（`pbBattleOnStepTaken`，遭遇归 WP36）。

距离统计（`004_Game classes/008_Game_Player.rb:123–136`）：`distance_walked` / `distance_cycled` / `distance_surfed`（含潜水）按实际移动距离累加；碰撞累加 `bump_count`。迈步效果族（亲密、病毒、蛋等）归 WP61 主规格。

### 4.2 统计字段清单（WP06-R03 修订）

`GameStats`（存于 `$stats`，`012_Game_Stats.rb`）共 **74 个声明字段**（不含 Game_Temp 锚点与派生 getter）。构造**并非"全 0"**：`gym_leader_attempts = [0] * 50`（数组）、`times_to_get_badges = []`（空数组），其余多为数值 0。

**全部 74 个字段的目录（字段/组/单位形态/初始化/更新规则类别与定位/持久化/证据等级/后续责任）见附表 [wp06-stats-directory](wp06-stats-directory.md)**，声明集合与目录成员集合机械对照一致、无漏项。要点：

- **有明确脚本写入入口（静态确认）**：旅行 8、场地动作 10、道具活动 9、宝可梦 11、战斗 10、货币中的 8（money_spent/earned_at_marts、mart_items_bought、premier_balls_earned、coins_won/lost、battle_points_spent、soot_collected）、特殊中的 6（time_to_enter_hall_of_fame、times_to_get_badges、safari_pokemon_caught、most_captures_per_safari_game、bug_contest_count、bug_contest_wins）、游戏时间 3。其中 Safari/BugContest 四个字段与两个时间赋值方法的写入机制存在且可读，**写入机制静态确认，Demo 可达/调用者未证**——不标 U01。
- **写入依赖缺失 NPC/地图事件（待验证 U01，仅 8 个字段）**：poke_center_count、revived_fossil_count、lottery_prize_count、drinks_bought、drinks_won、gym_leader_attempts、elite_four_attempts、hall_of_fame_entry_count（代码注释声明更新方式但当前快照无事件可读；不对同组其他字段连带标待证）。
- **来源待查（不标 U01、不虚构）**：battle_points_won——当前未定位到更新入口，"可能位于缺失设施发奖事件"为推断/待证，归 WP55/WP77 核实，不由搜索未命中证明一定来自该事件。
- 派生值：`distance_moved`（三者之和）、`caught_pokemon_count`（按图鉴现算，非计数器）、`save_count`（来自 `$game_system`）。
- 保存/恢复生命周期与迁移归 WP09/WP10；覆盖审查归 WP79；统计重置与存档边界是横切项。

## 5. WP06-C：随机入口与种子

### 5.1 随机入口/消费者族目录（WP06-R03 修订）

- `rand(` 形式：`rand(` 文本出现 242 次（正则 `\brand\(`，其中 2 处为整行注释；匹配行 230 行；宽松 `rand\(` 为 232 行/244 次，含 srand 子串）——**文本命中不是随机入口全集，也不等于调用可达**（BATCH-C02 口径）。
- `sample` / `shuffle` 形式：文本命中 53 处，例如寄养遗传多处 `.sample`（`007_Overworld_DayCare.rb:58, 150, 204, 210, 211, 232`）、地牢生成 `.sample`/`.shuffle`（`008_Overworld_RandomDungeons.rb:168, 177`）。
- 取值范围可由调用参数静态确定（如 `rand(20...40) * 60` 为 20–39 分钟区间）；**跨系统/跨实现重放不可证**（相同 seed 在不同语言与随机数实现中不保证相同结果，交接纪律）。
- 显式种子仅 **3 处**：
  1. **地牢生成**（`008_Overworld_RandomDungeons.rb:429–431`）：种子优先级 = 参数种子 > `$PokemonGlobal.dungeon_rng_seed`（待播种子）> `Random.new_seed`；随后 `Random.srand(seed)` 重播全局随机序列。
  2. **彩票**（`017_Minigames/005_Minigame_Lottery.rb:5–11`）：`srand(day + (month << 5) + (year << 9))`——**号码按日期确定**；取号后 `srand`（无参）重播种。
  3. 无其他 `srand` 使用点。

### 5.2 地牢待播种子的清空（WP06-R02 修订）

`008_Overworld_RandomDungeons.rb:428–434`（本轮逐行阅读）：选定种子后**无条件**把 `$PokemonGlobal.dungeon_rng_seed` 置 nil，随后 `Random.srand`；尺寸检查导致的提前返回发生在这些步骤**之后**。因此：

| 参数种子 A | 待播种子 B | 使用 | B 的状态 |
| --- | --- | --- | --- |
| 有 | 有 | A | **仍被清空**（不是"留到下一次"） |
| 无 | 有 | B | 被清空 |
| 无 | 无 | 新生成种子 | 无 |

生成失败/提前返回不撤回先前的清空与播种。本条只闭合随机输入状态，地牢布局算法归 WP14。

### 5.3 记录/回放（`011_Battle/008_Other battle types/005_RecordedBattle.rb`，本轮核实）

- 战斗记录内容：战斗类型、属性（双方训练家信息、两队与首发序列化、天气与持续、可逃跑/换人风格/动画显示、物品、背景、时间、环境、规则）、回合命令序列、**随机数序列**、换人记录。
- 回放：按记录索引顺序取用随机数（`@randomnums[@randomindex]` 递增），**不重新随机**——确定性重放依赖记录序列完整；覆盖哪些动作/布局、遗漏随机调用或版本变化的影响归 WP58 主规格。
- 可重现性限定：普通随机、显式种子、记录序列是三类不同机制；**跨系统一致性未验证（U05 保持开放）**。

## 6. WP06-D：保存/恢复交界与可重现性

- `$stats` 与 `$PokemonGlobal`（含 `encounter_version`、`dungeon_rng_seed`、`happinessSteps`）均为持久状态，经保存值注册保存（WP09 主规格，引用）。
- `encounter_version`（`012_Overworld/002_Overworld_Metadata.rb:41, 96, 114–117`）：持久全局遭遇版本选择（默认 0），影响遭遇表查询（WP03 身份例外、WP36 主规格）。
- 读档后：现实时间系统按宿主时钟继续（各消费者按 3.2 的规则处理）；运行时长从新进程重新起算；游戏时间从存档值继续累加（载入重新设锚点）。
- 种子消费与恢复的边界：地牢待播种子保存后随存档恢复，下一次地牢生成被选中即被清空（5.2）——保存/恢复时的种子状态一致性归 WP14/WP09 联查（U05）。

## 7. 默认行为与配置变体

- **基线默认**：现实时间驱动日历/昼夜；运行时长驱动帧计时；游戏时间锚点机制；普通随机无统一入口；显式种子仅地牢与彩票。
- **支持但未默认启用**：`TIME_SHADING`（默认 true，可关）；`dungeon_rng_seed` 待播种子（作者可预设）；`$full_compile` 等编译触发（WP04）。
- **配置/数据关联**：`NEW_BERRY_PLANTS`（树果机制变体，WP02 词典）；时段/季节判定的内容组合（遭遇时段条目、形态时间条件）归领域包。
- **未验证组合**：跨系统随机一致性（U05）、录像重放的范围与版本边界（WP58）、离线时长对各系统的组合影响（WP60/WP61/WP63）。
- 参考快照行为、官方版本预期、未来目标分开标记；本包只记录第一类。
