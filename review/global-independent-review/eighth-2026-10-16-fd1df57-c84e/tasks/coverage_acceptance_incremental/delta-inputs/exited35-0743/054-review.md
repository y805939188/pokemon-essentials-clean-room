## GR8-WORLD-001

建议保留必修事实，P3。错误不是“所有异常会继续游戏”或“正常重建本身失败”，而是规格没有表达：一次已进入的邻图摆放中断以后，同一世界上下文即使继续运行并消除原失败条件，后继邻图摆放仍可不再执行；普通同实例重新建立地图和帮助缓存清理不提供这项恢复能力。

主证据 S01（MapFactory）7–27、114–140：进入摆放后的抑制状态只在正常末尾解除，异常没有收尾；同实例 setup 不重置它。S02（Map）45–74、322–341：取图可在通知阶段失败，显示坐标写入可引出摆放。S18 42–65 / S19 66–90 的完整通知入口没有局部异常隔离。S06 11–23 的清数据只清帮助缓存及其他具名缓存，没有清此后继状态。S04 76–104 的恢复重建沿用原地图上下文，不构成该状态的独立修复。

普通对照：当前 A、合法连接、需要取得并摆放 B，各通知/资源正常。摆放完成，后继显示变化仍可重新摆放。最小失败向量可使用合法作者通知入口：A 已正常驻留、B 尚未驻留但尺寸/连接和摆放请求有效；第一次建立 B 的通知明确抛一次普通异常。外层作者调用明确捕获该异常并继续，随后撤掉单次失败条件。B 的本次建立没有成功返回，因此没有因该次普通加载加入集合；第二次同实例摆放请求在开始即返回，不再尝试 B。该条件向量没有执行，也不声称默认 Demo 注册了这个失败回调。

独立反驳尝试：

- “异常会自动收尾”：完整 S01 没有异常收尾，只有正常末尾解除；全 R 的 `@fixup`/`setMapsInRange` 检索没有发现另外的清理入口。
- “同实例 setup 重新开始，应能恢复”：setup 虽清集合并建新当前图，仍没有清该残留状态；进入通知及地图建立可能成功，并不等于邻图摆放已恢复。
- “pbClearData 清缓存即可恢复”：S06 清帮助缓存与地图容器后继状态不同，不能替代；重新构造一个正常世界上下文才重新具备正常初始能力，且其资源/通知仍须成功。
- “默认解释器吞异常并继续”：S12 138–180 捕获脚本错误后重新抛出诊断错误；S03/S04 没有给摆放异常提供统一同实例恢复继续。F05 §3.3 和 F03 §4.1.1 也明确外层诊断不保证继续本次场景。因此外层捕获并继续是必列前提；未捕获时后继观察未到。
- “WP05 已有前缀保留，所以无缺项”：它支持已写前缀不回滚，但没有告诉实施者后继摆放能力仍被抑制、同实例重建也不恢复；这项可观察后继差异不能只靠通用异常传播条款表达。

正常末尾之后发生的失败不留下本例状态；进入摆放以前失败也不能套用此例。该摆放单元没有用户取消接口，不新增取消 API。已完成的加入/偏移/通知前缀不回滚，但具体哪些前缀完成必须按失败位置决定，不能统一声称“图已加入”。失败后保存残留状态只是有明确外层继续、合法保存并无额外改写时的条件链；本裁决不以此证明真实存档或主流程继续。

最小修订为在 WP11 §5.2/§8 补上述后继能力事实与恢复边界，用领域状态表达。同步同一共享测试目录，加入正常、进入前失败、摆放内失败＋捕获继续、同实例再次摆放/重建/清缓存、新上下文六组对照。维持 GR3-DQ 的临时查询副作用、GR3-MR 的读档记录清空/复用、首有效连接、范围单位、音乐失败分期和所有正确转移通知顺序。该事实不重开或改写旧 GR3-M03-002/004 的关闭范围。

## GR8-WORLD-002

建议保留必修事实，P3。该路径完全不要求异常：有连接时最后范围扫描包括当前图，可正常返回一个空的驻留集合，而全局当前地图引用仍指向旧地图。F01 §5.1/§5.2 的部分措辞可按全体地图理解，且 §3.1/§8 已正确列空容器取图报错；但概念、偏移说明和 MP13 持续把范围卸载写为邻图行为，没有清楚连接当前图被删这一生产路径。F02 §3.1.1 已正确说明相机可引出邻图范围处理；它没有补齐当前图豁免不存在的事实。

最小向量精确采用冻结 v1：合法人工 A/B 各 20×20 格，512×384 屏幕，两图 SnapEdges 假，连接 A 的东端锚点 (20,0) 对 B 的西端 (0,0)。当前 A，玩家在 A(5,5)，静止、无移动路线/传送/额外写入；初始 A 显示 (0,0)、B (−2560,0)，两图均驻留，摆放未受 001 的残留状态影响。调用 `pbScrollMap(6,100,0)`，明确速度 0，再给一次范围生命周期，随后立即观察，不给第二次生命周期。

S02 497–518 的速度 0 包装一次把格距换为 128 子像素/格，不运行 miniupdate 循环；S02 322–341 仅在 SnapEdges 真时钳边。故 A 横显示为 12800，B 为 12800−20×128＝10240。S01 361–375 的连通过滤保留 A/B，摆放不把显示移回，最后范围扫描对两图都使用 S01 475–493 的右侧排除门 `(20+6)×128＝3328`。两图均 ≥3328，被移除，索引更新为 −1；全局当前引用没有被这次过滤改写。随后直接取容器当前图会把负索引归 0 再报空图错误（S01 30–39）。这些都是手工静态推导，未执行参考或独立模型。

独立反驳尝试：

- “相机会钳回边界”：SnapEdges 缺失/假没有该门，S05 89–117 也没有将未给字段默认成真；本向量显式为假。真值对照中 A 上界为 (20−16)×128＝512，当前 A 留在范围内，不能沿用空集合结果。
- “玩家更新会自动居中”：S10 254–266 的居中属于落位；416–546 的跟随只在玩家实际移动且没有在途手动卷动时写偏移。静止且无额外写入的本向量没有自动回中。S01 94–112 的换当前图也先要求玩家位置在当前图外；(5,5) 有效，不能用换图救回。
- “连通过滤保证当前图驻留”：它在有连接分支可以保当前图通过前一门，但最后范围门没有当前图排除条件。无连接分支确实只删非当前并提前返回，须作为独立正常对照。
- “同一滚屏包装会继续加载”：仅非零速度走 S02 510–516 的循环；速度 0 没有。S13 18–20 还有场景及淡出门，不能泛化任意脚本包装都获得更新。默认速度 4 若中途删旧当前图，后继可能补建同 ID 新实例，不能声称它必然正常返回该空表。
- “下一次生命周期会重新补回，故反例不存在”：第二次机会确实可从全局当前 ID 沿连接补建 A/B；这不撤销第一次正常返回的空集合观察，而且新驻留 A 与全局旧 A 可分离。该限制排除了永久空表、永久卡死或固定可见黑屏的结论。
- “保存层会拒绝空集合或先重建”：S08 63–67 + S09 30–53/279–284 只校验容器类型并整体取值；S04 110–126 不取其当前图。若直接在该精确观察点保存，其他值合法可序列化且文件步骤正常、保存前无新生命周期，空集合可以随容器保存。不能把这写成保存必失败。
- “读档的缺图恢复能处理它”：S14 310 在构建继续面板之前先取保存容器的当前图，尚未用户选择；即使跳过菜单，S04 77 也在 magic/safesave 和缺文件恢复之前先取当前图。类检查成功不验证内部驻留非空。该条件消费者链支持后继失败可能性，但真实文件 I/O、反序列化、UI 画面未观察。普通保存 UI 的确认/消息可能给额外更新，故没有证明它必然抢在补载前保存。保存分支须从空集合刚形成、任何失败取图之前分叉；若先取图而抛错，保存尚未到达，除非另有明确捕获继续。读回条件还排除其间转换或外部内容改写。

额外边界推导：仅右移26格时A显示3328恰好被删，B显示768仍保留；负索引归0后容器取图可返回B，而全局仍旧A，因此“当前图被删”也不等于“集合必空”。右移100格向量才同时删除两图。

正常对照取 0 或小偏移，A 留在范围内；moving 真则整个生命周期提前返回；SnapEdges 真和无连接分支分别对照。该单元没有取消接口；前置失败或换图时按真实前缀另判，不能套全部正常返回的向量。当前图已被过滤与全局仍指旧图必须分列；直接容器取图失败、下轮补建、保存快照、继续预览是不同时间点。

最小修订只以 WP11 为 primary，明确范围门适用当前图与空驻留生产路径，并在原共享目录补成对静态向量。WP16 的正确卷动数学/速度分支/SnapEdges 门、WP09 的整体值保存/类型校验、WP65 的预览先取图只作一致性接收；不重复新增 mandatory 根因。保留六格精确不等号、移动暂停、无连接分支、首图回退与全空错误、正常复用/重建、GR3-CAM/MP/GR3-MR 旧范围。002 不依赖001成立，两项仅共享写文件，不能因同属 W13 合并根因。
