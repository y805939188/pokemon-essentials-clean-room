## 数据意义与前提

`reception-ledger.json` 每行以稳定 ID 精确引用下列域语义、固定视图完整字面值、原物理双行、身份索引行和实际读片。共同语义不掩盖值：14 个小批次实际呈现了每一个完整 JSON 字面值，随后才登记阅读；并已机械独立证实本范围每对两个原始字段与该字面值严格相等。机械解析和哈希本身不计阅读。未读 A/B/C 的其它记录，也未把父的跳号记录纳入信用。

共同前提：固定 R/B8；定义未被插件覆写；有效预期数据结构；需要当前语言时其文件已成功加载；前序 PBS/宿主操作正常、无并发改写。原字段是导出文本中的编码形式，不等于逆转义后的运行键。分节过滤／修剪先发生，继而对两字段逆转义，只有键再规范化。键规范化按行首／行尾连续空白处理并折叠剩余至少两个连续空白；单个内部 LF 可保留。译文值不套此键算法。占位替换、窗口控制和最终显示是后续不同层。

四份原文件四行头均为两行翻译说明、分隔注释、对应域节头；均有 UTF-8 BOM，当前原字节是 LF（无 CRLF），末行有 LF。导出器写 CRLF 是其行为，不能反写为当前语料的字节身份。原文件第一保留内容均机械核为非纯数字，因此这些原节按哈希解释；D 在 SCRIPT_TEXTS 从 282 起片不改变这一点。`Rn` 是记录号，原物理行为 `2*n+3`／`2*n+4`，不是数值消息 ID。原五处不等对的全局断言未扩为本任务信用；本任务独立核定的结论为自身不等对 0。
