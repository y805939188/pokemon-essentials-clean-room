### 6.3 编译（作者导入）

- 把 `Text_<语言>/` 下全部 .txt 编译为 `Data/messages_<语言>.dat`。
- **分节读取先于节名/形态/行数求值**：先跳过空白行及**原行列首**为井号 U+0023 的注释行，再识别节头；保留的内容行修剪首尾空白。列首井号行会被删除，前置一个 ASCII 空格的井号行则先被保留、再修剪为井号起首内容；内容行内的井号不会按 PBS 的规则删后缀。后续判断使用这批过滤/修剪后的内容，空节直接跳过。特殊字符逆转义发生在分节之后，不能把转义控制字符等同于原始空白行。
- **节名识别先于内容形态**：对非空节，先作整数前缀解释；结果非零就取为编号，不要求整个名称为纯数字。因此 `1tail` 与 `1` 都归编号 1。结果为零才依次尝试文本域常量名、大小写不敏感的 `Map`＋纯数字地图编号；最终编号仍为负则报非法节名。数字节名 `0` 既不在非零分支接受、也不命中后两类，因此拒绝；常量 `EVENT_TEXTS` 可以归编号 0，不能把目录中的域 0–30 误作数字节头的严格接受范围。`SPECIES_NAMES` 归编号 1；负编号拒绝。本规则仅描述当前静态输入合同，不改写成理想严格数字校验。
- **形态判别**：节名识别成功后，**数组／哈希形态不按域固定，而由该节首条内容是否纯数字决定**：首条内容匹配纯数字 → 按数组解释，随后要求内容行数为 3 的倍数（索引/原文/译文三元组），**Map 节一旦被识别为数组立即拒绝**（「不能是有序列表」；早于行数检查）；首条内容非纯数字 → 按哈希解释，随后要求行数为偶数（键/译文二元组）；行数不符、索引非数字均报错（显式异常）。**由此，哈希导出（键/译文两行）中首键为纯数字的节在导入时被改判为数组**——例如明确位于非地图 `SCRIPT_TEXTS` 节的首键 `123`／译文两行，因 2 不是 3 的倍数而被拒绝，即使它是导出端可合法产生的哈希条目。节头中的 `0` 与内容中的索引 `0` 是不同判定，后者可在三行数组中接受。
- **先打开并截断输出，再扫描/解析输入**（以覆盖模式打开输出文件）：输入目录或内容失败时**旧产物可能已被截断**；收尾关闭文件不等于恢复旧文件。
- **真实菜单路径**：从 `Text_*_*` 目录中选择，片段含 core/game 后缀（如 `english_core`），再生成对应 `Data/messages_<片段>.dat`——目录、语言名与输出文件名不是同一个参数。

### 6.3.1 运行空译与作者文本表达边界

运行查找的空字符串仍是有效命中（§5.2）；作者文本导出/导入却不保证无损表示该集合。限定成功的导出及可读导入、非地图 SCRIPT_TEXTS 节、单条非空非数字键 K、有效非空原文且默认语料存在：

| 已有译文／对照 | 导出、预处理及导入结果（NOT_EXECUTED） |
| --- | --- |
| 有效空字符串 | 导出键 K 与空译行；分节删除空行后只剩 1 条内容，判哈希再因奇数拒绝 |
| 首字符为 U+0023 的非空译文 `#Word` | 译文不受井号转义保护，导入视为列首注释删除；同样只剩 1 条，奇数拒绝 |
| 译文为一个 ASCII 空格后接 `#Word` | 原行并非列首井号，保留后修剪，得到 `#Word`；2 条内容构成哈希并登记此值，是上一行的相邻反例 |
| 译文 ` Word `，端部各一个 ASCII 空格 | 保留内容后修剪为 Word，值改变；导出没有普通端部空格保护 |
| 译文端部为制表符、中间 Word | 导出为 `<<t>>Word<<t>>`，预处理保留转义标记，逆转义恢复两端制表符；不能概括为所有空白均丢失 |

若空译或列首井号失败经完整编译入口发生，且旧产物存在、输出已成功按覆盖模式打开，则拒绝时旧输出**已经截断**，关闭文件不恢复它。单文件解析不打开输出，不自行产生该副作用。仍保留数字首键改变数组形态、Map 数组在行数检查前拒绝的规则；这些判断均发生在分节预处理之后。以上决定向量只覆盖单条非地图哈希节，不推断全量语料受影响数量；实际异常提示、文件系统失败和往返运行未验证。空译/井号等历史异常的未来兼容政策待决定，不阻塞本轮事实补全。

### 6.3.2 同域重复键与重复节

同域输入归并是作者导入合同，与§5.1当前语言game/core的运行查找优先级分开。分节过滤、逆转义、节名识别与形态门仍按§6.3。对单一可读文件、合法非地图域24、所有保留内容非空且形态合法的输入：

- **节内**先形成规范键，同一规范键后出现的译文替换先值；相同键重复、连续空白归一导致的碰撞均取后值。数组节同一索引重复也取后值。
- **节间**按文件中的出现顺序，把后一个同域同形态节逐项合入已积累域；同键/索引覆盖，先前独有键/索引保留。数组后节未提供的稀疏位置不会删除先值。完整入口将排序后的文件依次送入同一累计集合；以下单文件例不依赖跨文件排序。

| 有序输入（均为合法24号节） | 导入结果 |
| --- | --- |
| 一个哈希节K→First、K→Last | K=Last；不拒绝重复，不取先值 |
| 一个哈希节A双ASCII空格B→First、A单空格B→Last | 规范键A B仅有Last |
| 先节K→First、L→Other，后节K→Last、M→New | K=Last、L=Other、M=New；不是整节替换 |
| 先数组节索引0→First、2→Keep，后数组节仅0→Last；每条含合法索引/原文/译文三行 | 0=Last、2=Keep，索引1仍缺席 |
| 先数组节仅0→First，后哈希节非数字键K→Last | Ruby 2.6隔离回执为TypeError，早节已积累的0=First保留；不保证所有混合形态安全合并 |

同域**同形态**的成功规则不能升级为所有混合形态兼容，也不能把上述失败外推为全部混合都失败。第四审查已有单文件隔离原函数回执，本次静态向量未执行；未执行完整菜单、跨文件导入、二进制写回或全部混合组合，未证明默认18份语料含重复。失败前的累计内存不等于成功产物；经完整入口且输出覆盖打开成功时，§6.3的**先截断旧输出**边界仍成立，单文件解析不自行截断输出。Map数组拒绝仍早于行数检查。未来兼容选择待决定。

### 6.4 写回与失败副作用

| 步骤 | 可能的副作用 |
| --- | --- |
| 收集 | 超时后部分收集（§6.1）；其他异常按调用路径传播 |
| 提取覆盖 | 确认后删除递归列举文件（不限 .txt）再重写；目标/子目录保留，操作异常可留下部分删除；稀疏桶合并检查还可能不重建事件域文件（§6.2.1；非原子） |
| 编译 | 先截断输出再解析：非法输入时旧 .dat 可能已被截断；收尾关闭不恢复 |
| 语言切换直写 | 已有存档时把选项写入存档数据并直接写回（§4；无存档不写） |

## 7. 默认行为与配置变体

- **基线默认**：`LANGUAGES` 为空（无候选语言）；默认消息随启动加载；无候选时无语言菜单/选择；查找按 §5.1/§5.2 入口分层（不是统一「回退到原文」）。
- **支持但未默认启用**：多语言候选（启动选择＋载入菜单＋按片段加载＋载入菜单直写）；地图文本按地图分桶与共享桶；作者提取/编译工作流；翻译服务的延迟加载构造。
- **配置/数据关联**：语言文件名片段与数据文件的对应关系（`messages_<片段>_core/game.dat`）；地图文本的地图编号依赖（缺失地图数据时地图事件文本可达性，U01）。
- **未验证组合**：多语言切换的运行效果、缺译/空译在各消费者的显示、提取/编译的真实往返、地图事件文本在缺失地图下的行为。
- 参考快照行为、官方版本预期、未来目标分开标记；本文件只记录第一类。

## 8. 边界、失败与未知

- 消息文件缺失与查找结果：按 §5.1/§5.2 入口分层处理，**不是**「整体回退到原文」——默认材料是否存在不决定当前已载入语言的命中结果；当前语言两层均未中时，数组入口返回空字符串，哈希/地图文本入口返回输入原文。文件加载异常、嵌套形态异常与格式化异常仍沿 §5.2 的分层。
- 空译：直接显示空串（有效命中）；各消费者的空串显示效果归界面领域规格。
- 占位参数缺失：未提供对应参数时占位原样保留（推导，未运行）；已提供参数中的反斜线组合按§5.3，不保证字面插入；格式化入口/地图入口的格式化错误向外传播（§5.2）。
- 编译输入非法（非法节名、行数不符、索引非数字）：显式异常（作者可见错误，具体呈现归诊断面）；旧 .dat 可能已被截断（§6.4）。
- 提取覆盖：拒绝替换请求时不写；确认后旧文件被删除再重写（非原子）。
- 地图事件文本在缺失地图数据下的可达性（U01）。
