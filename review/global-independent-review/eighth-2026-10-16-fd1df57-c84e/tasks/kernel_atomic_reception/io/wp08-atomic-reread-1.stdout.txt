# 本地化（净化正文；批次 4）

分类：Generic Kernel（文本域与语言机制）。本文件描述文本如何分域、选择语言、提取/编译/载入、查找/替换和回退，以及作者翻译材料的输入输出。除明确列出的第四审查限定历史隔离回执外，正文与向量为静态证据；**本次无新增行为执行，宿主/Demo未执行**（见 `../scope-statement.md`；历史回执仅支持其注明的输入、版本与观察点）。

## 1. 目的与范围

**目的**：回答「某段文本来自哪个域、缺译时显示什么、翻译何时生效」，供后续规格引用，而不追踪任何特定消息系统的实现。

**范围**：① 文本域与身份（文本域目录、存储形态、键归一化、真实消费者）；② 语言配置与选择（配置、选择机会、主动与延迟载入、持久化）；③ 消息查找与回退（查找链、空译与异常边界、占位参数与格式化）；④ 作者翻译工作流（文本收集、提取、编译、写回与失败副作用）；⑤ 当前语言对指定 UI 图像身份的选择。

**非目标**：不复制文本语料（不输出任何具体翻译文本）；不提取字体、窗口绘制与各界面页面的文本呈现（归界面领域规格）；不提取核心消息的二进制格式细节（加载器行为未验证）。

## 2. 概念与术语

- **文本域**：按内容类别划分的文本集合，每个域一个整数身份。
- **默认消息**：随工程编译保存的基础文本（`Data/messages_core.dat`、`Data/messages_game.dat`）——用于**收集与导出**（作者工作流），不是运行查找的回退层。
- **语言消息**：当前所选语言的翻译文本（`Data/messages_<片段>_core/game.dat`）——运行查找的两层来源（先 game 后 core）。
- **数组域 / 哈希域**：按整数索引存储的域与按文本键存储的域；**域内身份形态按域而定**（如物种名/招式名为哈希键），不能由域编号推断。
- **回退**：查找未中时逐层下降的策略；空字符串是有效命中，**不触发**回退。

## 3. 文本域与身份

### 3.1 文本域目录

共 **31 个文本域，编号 0–30 连续**（注释只说编号没有特定语义顺序，不是编号不连续）：EVENT_TEXTS(0)（公共事件与地图事件文本）、SPECIES_NAMES(1)、SPECIES_CATEGORIES(2)、POKEDEX_ENTRIES(3)、SPECIES_FORM_NAMES(4)、MOVE_NAMES(5)、MOVE_DESCRIPTIONS(6)、ITEM_NAMES(7)、ITEM_NAME_PLURALS(8)、ITEM_DESCRIPTIONS(9)、ABILITY_NAMES(10)、ABILITY_DESCRIPTIONS(11)、TYPE_NAMES(12)、TRAINER_TYPE_NAMES(13)、TRAINER_NAMES(14)、FRONTIER_INTRO_SPEECHES(15)、FRONTIER_END_SPEECHES_WIN(16)、FRONTIER_END_SPEECHES_LOSE(17)、REGION_NAMES(18)、REGION_LOCATION_NAMES(19)、REGION_LOCATION_DESCRIPTIONS(20)、MAP_NAMES(21)、PHONE_MESSAGES(22)、TRAINER_SPEECHES_LOSE(23)、SCRIPT_TEXTS(24)、RIBBON_NAMES(25)、RIBBON_DESCRIPTIONS(26)、STORAGE_CREATOR_NAME(27)、ITEM_PORTION_NAMES(28)、ITEM_PORTION_NAME_PLURALS(29)、POKEMON_NICKNAMES(30)。

### 3.2 存储形态与真实消费者

- **数组域**：按整数索引存储（按键号查找）。
- **哈希域**：按文本规范键存储。对逆转义后的键，先去掉从每行开始处起始的连续空白段，再去掉在每行结束处结束的连续空白段；这些空白段可跨相邻空行。最后将剩余长度至少2的连续空白段折叠为一个ASCII空格。单个内部LF可以保留，不能等价改写为整串trim后把所有空白压成空格，亦不能只split/trim每行再统一join。原文值/译文值不按此键算法转换。
- **物种名/招式名是哈希域**（不是数组索引例子）：编译以哈希形态写入，消费者按真实名称文本查哈希。通用数组查找接口存在，但**不能由域编号推定域内身份形态**。
- **地图事件文本**：EVENT_TEXTS 按地图编号分桶，另有 **0 号共享桶**（公共事件文本与跨地图共用文本）；同一文本在不同地图中按各自地图桶分别登记，不预设统一字符串键。

同一有效当前语言哈希分别有A+LF+B→T和A空格B→U，无占位参数、无覆写、观察窗口处理之前：查询A+LF+LF+B或A+单LF+B均取T；A+两个ASCII空格+B取U。已有译文值含双LF时，查找原样交出双LF，不因键规范化而折叠。导入行修剪在逆转义之前、键处理在之后；碰撞后值覆盖与后续窗口换行各按自己的合同，不据这些有限输入穷尽Unicode/CRLF组合。

## 4. 语言配置与选择

- **作者配置**：`LANGUAGES` 声明候选语言列表（每条＝显示名＋文件名片段，对应 `Data/messages_<片段>_core/game.dat`）；默认为空（不提供候选）。
- **游戏语言选择机会**：启动流程在候选 ≥2 且已读存档数据为空时提供语言选择；载入界面在候选 ≥2 时显示语言菜单。调试菜单的翻译提取入口选择的是作者导出目标语言，不写玩家语言选项，也不切换当前游戏消息集（§6.2）；该入口不能计为已核实的游戏语言切换机会。不由此断言任意外部/插件语言入口不存在。
- **主动加载 vs 延迟加载**：主启动直接调用语言消息载入**立即加载**，不是首次查找才加载；翻译服务构造另支持延迟加载（首次查找时），两条路径分开。
- **持久化与直写**：选择保存在玩家系统选项（语言字段）；**载入菜单已有存档时切换语言会把选项写入该存档数据并直接写回存档文件**——这是**直接写档**，不经过正常保存路径（《保存、启动、新游戏与继续》引用）。无存档时切换不写档。
- **交界**：语言属于**设置**（玩家选项），不属于游戏进度；设置与进度的保存/重置边界归《保存、启动、新游戏与继续》，本文件引用。

## 5. 消息查找与回退

### 5.1 查找链（当前语言 game → 当前语言 core，不再查默认语料）

| 入口形态 | 查找链 | 未中结果 |
| --- | --- | --- |
| 数组域查找 | 当前语言 game[域][索引] → 当前语言 core[域][索引] | 空字符串 |
| 哈希域查找 | 当前语言 game[域][键] → 当前语言 core[域][键] | **返回原文**（键为空/缺失时也返回原文；**不自动取默认语料**） |
| 地图事件文本查找 | 当前语言 game[图][键] → game[0][键]（共享桶） → 当前语言 core[图][键] → core[0][键] | 返回原文 |

用途分层：默认 core/game 用于**收集与导出**（作者工作流）；当前语言 core/game 由另一入口载入，用于**运行查找**。语言 game 覆盖语言 core 的同名译文（先查 game）。

#### 5.1.1 指定 UI 图像身份的语言选择

当前语言材料也可把指定 UI 图像的原始身份 A 映射为另一身份 B；这些字符串仍属于 SCRIPT_TEXTS，不新增文本域。查找先于图像创建／加载：语言 game 优先于语言 core；两层均缺译时交付原身份 A；命中非空译文 B 时交付 B，即使 A 本身可用也不改回 A。说明标签的文本查找与图像身份查找分别进行。

| 指定消费者 | 语言材料选择的范围 | 独立固定资源 |
| --- | --- | --- |
| 控制帮助 | 七个键图身份 | 控制帮助背景 |
| 图形模式下的战斗命令／招式菜单 | 命令与招式光标图、类型图、Mega 与换位按钮图 | 对应菜单背景 |
| 训练家卡 | 卡片及女性卡片图身份；女性分支另有资源存在性门 | 背景与徽章图 |
| 翻牌小游戏 | 背景和备忘图的基名；查找后仍在该消费者的图像目录下加载 | 其它图块、光标等资源 |

此规则只覆盖指定的查找调用者，不把所有 UI 图像都设为可翻译。空译仍是命中，随后怎样处理空身份、不可解析身份或加载异常由 [WP15](../engine-overworld/wp15-resource-matching-and-audio.md) 的实际资源入口决定；没有“译后资源失败就重试原图”的通用保证。查找本身不新增语言选择提示或存档写入，场景可能已建立视口／部分图像，不据后续失败保证整体清理或回滚。资源存在、合适尺寸、加载成功及实际像素仍须分别验证。

### 5.2 空译与异常边界

| 情形 | 行为 |
| --- | --- |
| 缺键/缺失 | 按 §5.1 回退链处理（数组域空串、哈希/地图回原文） |
| **空字符串命中** | 空字符串是**有效命中**（真值判断），**直接返回空串，不触发回退**——空译不会被原文/核心译文替补 |
| 文件载入失败 | 载入入口的异常捕获把语言/核心消息置空，效果同回退；**加载器仅检验外层为数组**，内层形态不符仍可能在查找处出错 |
| 查找结构异常 | 数据形态异常（如内层非预期类型）按常规异常传播，不被查找入口捕获 |
| 格式化异常 | 脚本翻译入口的异常捕获**只包住查找部分**；后续格式化在捕获之外，**格式化错误向外传播** |
| 地图翻译入口的格式化 | 地图翻译入口**没有**同样的查找捕获——其格式化/查找错误**均不被该入口捕获**（不能套用脚本入口的捕获保证） |

**地图名的查找值消费**：哈希查找返回所选译文值或原输入，不给每个消费者独立模板副本。地图命名服务会直接展开所选材料中的大写`\PN`，材料保留、改变后的查找键、别名及恢复规则集中于[WP11§5.3.1](../engine-overworld/wp11-map-topology-transfer.md)；空译在语言层不转core，地图消费者随后可转基本名。继续预览另按WP65，通用消息复制输入的控制处理不能套为地图名状态规则。当前替换参数与其捕获/格式化边界仍按下节。

### 5.3 占位参数

脚本翻译入口在取回文本后按参数次序替换 `{1}`、`{2}` 等占位；常规参数如Q直接插入，但**不承诺任意参数逐字保留**。格式化翻译入口支持 `{1:d}` 形式的格式占位（按格式化规则求值）；地图翻译入口为地图事件文本的对应入口（先按地图回退链取文本，再替换占位）。查找失败时脚本翻译入口回原文（见 §5.2 捕获范围）。

正常主入口已定义、无插件覆写，当前语言各层均无命中时，在进入任何消息窗口**之前**观察返回字符串：

| 入口与原文 | 参数的真实字符 | 返回字符串 |
| --- | --- | --- |
| 普通脚本，X{1}Y | Q | XQY |
| 普通脚本，X{1}Y | U+005C后接U+0026（反斜线与&） | X{1}Y，恢复被匹配的占位文本 |
| 普通脚本，X{1}Y | U+005C后接U+0031（反斜线与数字1） | XY |
| 地图5普通入口，X{1}Y | U+005C后接U+0026／U+0031，各例独立 | 分别X{1}Y／XY，同样解释替换参数 |
| 脚本／地图格式化字符串入口，X{1:s}Y | U+005C后接U+0026 | X后接这两个参数字符再接Y，保留反斜线与& |

反斜线与数字1是两个字符，**不是U+0001**；这些结果属于本地化插入阶段，与 [WP17](../user-interface/wp17-messages-windows-input.md) 后续显示控制/暂停转换分开。第四审查的Ruby 2.6.10隔离原函数回执支持所列脚本结果及地图反斜线&结果；地图反斜线1与地图格式化对照另由同样的源路径静态推导。本次未重跑，新增向量为DERIVED_VECTOR、NOT_EXECUTED_THIS_UPDATE；随附宿主及窗口呈现未执行，更多转义/嵌套组合未穷尽。未来是否采用任意参数字面插入须另作兼容决策。

## 6. 作者翻译工作流

### 6.1 文本收集（编译流程末段）

- 普通脚本先扫描已加载脚本归档的全部节；归档恰一节才额外扫描Data/Scripts递归列举返回的所有文件，不承诺只扫.rb，也不因目录存在就无条件扫描。插件归档存在且可读时随后扫描其中脚本，再处理公共事件和有效地图事件。普通脚本识别旧输入标记_INTL/_ISPRINTF后、左括号后的双引号首字符串片段；事件脚本识别_I的对应双引号片段。单引号不由该识别器收集，注释里的匹配文本仍可成为候选，不证明运行可达。这些名称是参考作者输入词汇，不要求未来提供同名API。
- 普通脚本片段按回车、换行、控制字符1、转义引号、双反斜线的次序解码；事件脚本只解码转义引号与双反斜线，字面反斜线n不按普通脚本路径变LF。显示文本续行在非空旧文本后以一个空格接合。非续行命令触发提交时，非句点/感叹号/问号字符后的连续空白另作规整；列表确以显示文本结束时的末尾提交不做该步。普通A双ASCII空格B在前路成为A单空格B，末路保留双空格；后续规范键可相同但登记原文值不同，不将此有限例扩为所有句读组合。
- 脚本文本入 SCRIPT_TEXTS 哈希域；公共事件文本入 EVENT_TEXTS 的 0 号共享桶；地图事件文本按地图编号入各自桶（仅非空时登记）。
- **超时捕获后返回，已收集内容可能只是部分**——进入收集函数不保证完整收集；其他未捕获错误按实际调用路径传播。
- 这是编译流程（《PBS 生命周期》）末段调用，随后保存默认消息。

**收集键与运行输入的换行边界**：普通脚本的源拼写解码不保证得到与运行查找输入相同的字符序列。一个片段在 A/B 间的源拼写为两个 U+005C 后接 U+006E 时，按上述收集次序可得到 A＋U+005C/U+000A＋B；对应的普通运行输入却为 A＋U+005C/U+006E＋B。键规范化不会把字母 n 转成 LF。在有效当前语言两层只给收集键译文 Q、运行键均缺译且无覆写时，运行查找返回原输入，不选 Q；随后消息显示层才把反斜线 n 处理为换行，不能凭相同换行外观认定查找已命中。无此转义差异且实际运行键命中 Q 的普通消息仍选 Q。此区别只限定上述输入，不推成全部转义文本或整个语料的翻译失效；是否在未来实现中保留该异常另作兼容决定。

物品成功接收／拾取／奖品和树果成功采摘的口袋提示到达此查找前，库存写入已发生；缺译是正常回退，不自行抛错或撤销该写入。作者导出取消、确认覆盖后先删后写及完整导入先截断输出仍按 §6.2–§6.4 的独立边界。

#### 6.1.1 默认哈希材料的替换与追加

候选在保存默认消息前，以**默认core同域规范键集合**过滤：core存在该键即跳过，不比较原文值，也不借用当前语言材料。替换式收集重建目标game域；追加式保留旧game域再写合格新候选。跳过不是删除：旧game同键及未再收集的独有键仍可保留。地图m仅对默认core的同m桶过滤，不借用运行查找的共享桶0。缺值候选跳过；哈希空串候选可形成键，但导出跳空原文值。

| 默认输入（彼此独立） | 更新后默认game |
| --- | --- |
| core仅键A；旧game键Z；替换收集A/B | 只有B |
| 同输入但追加 | 保留Z，加入B |
| core键A；旧game有A→Old和Z；追加A/B | A→Old、Z仍在，加入B |
| 同输入但替换 | 只有B |
| core仅桶0有A、桶4无A，收集地图4的A | game[4]可加入A |

普通招式名称/描述终检是替换调用者；形态文本与普通脚本文本收集是追加调用者；公共事件桶0及非空地图桶是替换调用者。新K只有在来源门成立、不被core排除且无规范键碰撞时才成为相应默认域最终值。数组低层收集并不由这些哈希调用证明，不扩大成全部数组作者入口。超时部分收集、随后保存及其它异常前缀保持。

### 6.2 提取（作者导出）

- 调试提取入口从作者候选选导出目标语言，再选 core/game；选游戏文本时还可选择地图文本分文件方式。选择 B 后在 core/game 问题取消，在到达导出器之前返回：当前游戏语言 A 和当前消息集不变，不创建、删除或重写导出文件。成功导出时 B 决定目标文件夹和作者导出使用的译文材料，仍不写玩家语言或切换游戏消息集；与 §4 真正的启动/载入切换及载入菜单直写分开。
- 从默认消息导出到 `Text_<语言>_core/` 或 `Text_<语言>_game/` 文件夹。
- **输出格式分形态**：**数组条目为索引/原文/译文三行**；**哈希条目为键/译文两行**——「每条两行」不覆盖所有形态。
- **覆盖与跳过**：目标文件夹已有文件时询问是否全部替换；拒绝则中止（不写）；确认则**删除目录递归列举返回的全部文件**（不只 .txt）后重写，目标目录及已存在的子目录本身保留，不调用删除整棵目录树的入口。默认消息文件缺失时提示未找到并返回（不写）。文件操作异常可传播，先删后写不保证原子性。
- 导出编码有条件：原文/译文含真实CR、LF、TAB、U+0001，或某行起始字符为左/右方括号时才进入编码；进入后将全部CR/LF/TAB/U+0001及全部左右方括号分别写为<<r>>/<<n>>/<<t>>/<<1>>/<<[>>/<<]>>。仅一个ASCII空格后接[Q]且无控制字符不触发括号保护。导入先分节再按既定转义表逆转义，不能在分节前先解码。

输出条目由所选默认core/game中的非空原文条目决定，译文取作者选定目标语言材料；目标语言独有X而默认域无X时不会新增X输出。外层检查范围可包含语言材料更长的域号，不等于根本不遍历语言独有域，也不保证损坏/缺失地图域安全跳过。此条不改变游戏当前语言或先删后写、稀疏桶条件。

合格非地图SCRIPT_TEXTS单条非空非数字键K，导出/读取正常且无先行错误：译文[Q]被编码，单文件导入恢复[Q]；译文一个ASCII空格+[Q]且无控制字符不编码，分节读取在修剪/逆转义前把它识别为新节头，交付旧节时只剩K一行，**先因旧哈希节奇数拒绝**，尚未求新Q节是否合法。同负例另含真实TAB时编码门成立，括号一并保护，不再发生同一节头反例，但不承诺ASCII首空格无损。经完整编译且旧输出存在、覆盖打开成功时，拒绝前旧输出已截断，关闭不恢复；单文件解析不打开输出，二者副作用分列。

### 6.2.1 地图导出的稀疏桶边界

合并和逐地图模式不仅改变文件分组。限定默认 game 消息有效、事件域按地图编号分桶、目标可写且相关宿主调用正常：合并模式先从桶 0 向后检查是否有文本，**遇到第一个缺席桶就停止这次检查**，存在但零条目的桶不会使检查停止。若停止前未见非空桶，则跳过整个 EVENT_TEXTS 文件；若此前已见非空桶，随后的实际写出仍跳过空/缺桶并继续遍历较晚编号，不能概括为只导出连续地图。

| 桶前提与选择 | 静态输出（NOT_EXECUTED） |
| --- | --- |
| 桶 0 存在但空，桶 1 缺席，桶 5 有一条非空哈希文本；没有更早非空桶；合并模式 | 在桶 1 停止检查，整个 EVENT_TEXTS 文件不生成，桶 5 文本被省略 |
| 同一集合；逐地图模式，另给 MapInfos 可读 | 空/缺桶被跳过后继续，可生成 Map005 文本文件（名称可附地图名） |
| 同一合并集合，但给桶 0 或桶 1 一条非空文本 | 已在缺席桶前见到非空内容，生成 EVENT_TEXTS 文件，后续写出仍可包含桶 5 |

§6.2 的确认覆盖删除发生在这些检查之前；确认并成功删除旧文件后，合并模式可不重建旧事件域文件，其他文本域仍按各自前提导出。取消/默认文件缺失/宿主文件失败保持原边界。此为固定参考的异常事实；未来是否保留须另作兼容决策。随附编译消息未反序列化，实际默认数据是否满足此稀疏前提未知；没有真实地图夹具或宿主执行证据。
