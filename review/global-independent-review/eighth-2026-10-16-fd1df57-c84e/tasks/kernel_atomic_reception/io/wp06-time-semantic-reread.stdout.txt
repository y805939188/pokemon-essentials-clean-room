# 时间、随机、计步与统计（净化正文；批次 4）

分类：Generic Kernel（横切计量）。本文件定义横切计量边界——哪些系统由现实时间、运行时长、帧/更新周期还是步数推动；随机输入在哪些入口、以什么形式（普通随机/显式种子/记录序列）进入系统；统计字段如何产生、累加、重置和保存。除明确列出的第四审查限定历史隔离回执外，正文与向量为静态证据；**本次无新增行为执行，宿主/Demo未执行**（见 `../scope-statement.md`；历史回执仅支持其注明的输入、版本与观察点）。

## 1. 目的与范围

**目的**：回答「某规则由什么输入驱动、能否重现」，供后续规格引用，而不追踪任何特定时钟或随机实现。

**范围**：① 时间与计时来源（现实时间、运行时长、游戏时间、帧/更新周期）及消费者推进方式；② 计步与统计（计步机制、统计字段族、更新点、持久化）；③ 随机入口与种子（普通随机、显式种子、记录/回放）；④ 保存/恢复交界与可重现性。

**非目标**：不提取领域规则（地牢算法、繁殖/遭遇概率、设施回放、世界天气与树果、步数效果全集、电话业务全集，各归相应领域规格）；不提取保存生命周期与迁移细则（归《保存、启动、新游戏与继续》《迁移、失败与恢复》，本文件只登记交界）；不宣称存在统一、可注入、全局可重放的随机服务；不保证相同种子跨语言/随机数实现产生相同结果。

## 2. 概念与术语

- **现实时间**：宿主提供的真实时钟，驱动昼夜、日历、树果、电话、彩票等。
- **运行时长**：进程已运行秒数，驱动帧计时、等待、切换、部分比赛计时。
- **游戏时间**：累计游玩秒数（统计记录的 play_time 字段），在锚点存在时惰性累加，持久化保存。
- **帧增量**：逐帧推进的更新与每帧更新事件及其增量扣减。
- **普通随机**：标准库随机调用（无显式种子）；取值范围可由调用参数静态确定的以参数为准，跨系统/跨实现重放不可证。
- **显式种子**：指定输入决定随机序列的种子（地牢生成、彩票日期种子）。
- **记录/回放**：战斗记录保存随机数序列，回放按序列取用而非重新随机。

#### 3.1.1 派生游戏时间查询

两项可调用查询都先按§3.1取得当前累计秒数T，因而锚点存在时会累加给定运行时长差并推进临时锚点；它们不是无副作用地读取缓存。每会话时间为T/S，S为给定正整数会话数：正整数T保留整数除法商，浮点T保留连续商。距最近保存时间为T−L，不夹到0。

无锚点T=5.0、S=2、L=7，独立查询得到2.5与−2.0秒，T/L不变；独立整数T=5/S=2得到2，浮点5.0/2得到2.5。有锚点T=9.0、锚点10、给定现在13、S=2，平均查询把T改12.0、锚点改13并返回6.0；同初值、L=5的独立距保存查询返回7.0并同样推进T/锚点。

S=0没有本地保护，除零或非有限表现按数值类型与原生运行时保留未知，不能统一返回0。未定位普通默认消费者，限定为可调用统计能力，不声称有新玩家页面；会话默认1、新游戏/读档累加与保存先写时刻及失败不回退保持。

### 3.3 现实时间规则族

- 时段判定：昼（5–20 时）、夜（20–5 时）、清晨（5–10 时）、午后（14–17 时）、傍晚（17–20 时）——**边界时刻** 5/10/14/17/20 时。
- 日历：星期（可写入游戏变量）、月份（名称/缩写）、季节按「（月份 − 1）除以 4 取余」、月相（天文公式，UTC；完整公式见《资源匹配》/世界表现规格的引用边界）、星座与配对。
- 日夜调色：按小时色调表逐分钟插值；`TIME_SHADING` 开启且为室外地图时应用；缓存重算门按 §3.2 的运行时长判断。断言 18:30 的半小时插值须把观察点限定为无重算记录或距上次重算 ≥30 秒；缓存未到期的读取仍返回上一色调（完整色调表及地图呈现归相应领域规格）。

### 3.4 游戏变量墙钟计时

作者脚本可把墙钟计时记录写入可写的非负整数游戏变量槽；以下以槽 1 为例，游戏变量对象存在且没有覆写。记录包含设置时 Unix 墙钟秒数 t 与持续量 D。秒数设置的默认持续量为 86400 秒，输入 s<0 时取 0，即 D=max(s,0)。天数设置默认 d=0，负天数先取 0，保存的持续量为：

**D=(t mod 86400)+86400×max(d,0)−t**。

这是固定参考的实际数学规则，不能改述为下一午夜或通常日历倒计时。两个设置入口写完记录后，地图存在时请求立即刷新；游戏变量对象不存在、槽号未提供或为负时，设置不写入，查询返回 false。

查询有效记录时，只有 **D>0 且当前墙钟−t>D** 才返回 true，并保留记录、不请求刷新。未到期、恰到期、D≤0 或槽中不是计时记录时返回 false，把该槽写为数值 0，并在地图存在时请求刷新。因此提前查询会销毁等待中的记录，不能当作无副作用的到期探测。畸形记录不在此有界合同内。

| 独立输入／观察点 | 返回与槽状态 | 刷新请求总数（包含设置） |
| --- | --- | --- |
| t=1000，s=100；首次查询1099 | false，槽为0 | 2 |
| 同设置；首次查询1100 | false，槽为0（严格大于门） | 2 |
| 同设置；首次查询1101 | true，保留t=1000、D=100 | 1 |
| 同设置；1050查询后再在1101查询 | 两次均false，槽为0，计时已消失 | 3 |
| t=1000，s=0或−5；随后查询 | D=0，false，槽为0 | 2 |
| t=1728000100，d=1；随后查询 | 保存D=−1727913600，false并清0 | 2 |
| 同t，天数省略／d=0／d=−1 | 三者D=−1728000000，查询false并清0 | 各2 |

表中各子例独立复位（只有提前再迟查例连续），刷新正常返回且不回写该槽。第四审查的 Ruby 2.6.10 隔离回执仅记录时钟输入和地图刷新替身调用次数，未执行事件页刷新；本次表格为 DERIVED_VECTOR，**NOT_EXECUTED_THIS_UPDATE**。游戏变量整体持久化按 [WP09](wp09-save-startup-continue.md) 保存/恢复，但真实存档往返未执行。该能力区别于 [WP13事件私有冷却](../engine-overworld/wp13-map-events-npc-followers.md) 的事件记录/自开关及 [命令124](../engine-overworld/wp13-interpreter-command-matrix.md) 的累计游戏时间计时器；墙钟来源交界见 [WP59](../engine-overworld/wp59-world-time-weather-field-moves.md)。固定脚本搜索未定位默认调用或覆写，不据此声称能力不存在或默认Demo使用。查询清零与天数异常的未来兼容政策待决定。

## 4. 计步与统计

### 4.1 通用计步入口

迈步处理（逐行核实）：

1. **守卫**：强制路线或解释器运行中时，只触发「迈步」通知并直接返回（**不累计步数计数器**）。
2. 否则：全局元数据的步数计数器（缺失则初始化为 0）加 1，并在非负整数范围按 2³¹ 回绕，即新值为（旧值＋1）除以 2³¹ 的非负余数。旧值 2147483646 → 2147483647，旧值 2147483647 → 0；不是在最大值饱和保留。
3. 依次触发「玩家迈步」「玩家迈步（可转移）」两个通知（后者经共享数组，任一消费者标记已转移则返回，不再触发战斗检查）。
4. 未被事件触发且非菜单中：进入迈步战斗检查（遭遇规则归遭遇领域规格）。

第 2 步写入先于通知、已转移返回及事件/菜单门。上界向量须排除通知订阅者再次改写计数；强制路线/解释器的第 1 步提前分流仍不计数，不能用后面的战斗门替代它。

距离统计按入口：普通四向成功按位移累计步行/骑行/冲浪（含潜水）距离，非零直接跳跃按两轴绝对位移和累计；玩家四对角入口不写这些距离或冰滑距离，直接零偏移跳跃也不增距离。对角失败可能已调方向，但不调用四向碰撞/触碰；一般离格与步完成通知仍按WP12§4.1/4.3、全局步数按本节守卫，不能从距离未增推步数必不变。

## 5. 随机入口与种子

### 5.1 随机入口/消费者族目录

- 标准随机调用形式的文本命中数百处（口径与数字见审计）——**文本命中不是随机入口全集，也不等于调用可达**。
- 集合抽样/乱序形式：文本命中数十处，例如寄养遗传多处抽样、地牢生成抽样/乱序。
- 取值范围可由调用参数静态确定（如「20–39 的均匀抽样 × 60」为 20–39 分钟区间）；**跨系统/跨实现重放不可证**（相同种子在不同语言与随机数实现中不保证相同结果）。
- 显式种子仅 **3 处**：
  1. **地牢生成**：种子优先级＝参数种子 > 待播种子（全局元数据的 dungeon_rng_seed 字段）> 新生成种子；随后按选定种子重播全局随机序列。
  2. **彩票**：按「日＋月×2⁵＋年×2⁹」播种——**号码按日期确定**；取号后无参重播种。
  3. 无其他显式播种使用点。

#### 5.1.1 普通随机作者参数分派

在给定底层整数随机源可按正上界产生合法偏移的前提下：

| 首参/次参 | 实际请求与正常输出域 |
| --- | --- |
| 两个有限有序整数a≤b | 请求宽度b−a+1，再加a，闭区间[a,b]；5/7配偏移0/1/2返回5/6/7，5/5只能5 |
| 整数区间首参 | 用该区间实际最小/最大成员决定闭整数域，忽略次参；5...8与5..7均为5/6/7 |
| 数值首参、非数值次参 | 委托原单上界抽样；正整数5为0..4 |
| 空首参 | 委托次参；空/7与原单上界7请求相同 |
| 其它类型首参（如文本“5”） | 无参抽样请求，忽略次参，不把文本解析为5；文本“5”/1不因此强制返回0 |

区间首参即使给次参仍取自身域。电话20...40保持20–39、钓鱼5..10保持5–10；两数值分支没有固定核心默认调用证明，不称为全游戏统一入口。浮点、反向/空/无界/非数值区间及错误类型的原生接受/异常不补造统一拒绝。此为给定偏移的静态向量，不保证跨语言随机序列或统计分布；显式种子、录像与跨次有状态选择仍分别按原合同。

### 5.2 地牢待播种子的清空

选定种子后**无条件**把待播种子置空，随后按种子重播；尺寸检查导致的提前返回发生在这些步骤**之后**。因此：

| 参数种子 A | 待播种子 B | 使用 | B 的状态 |
| --- | --- | --- | --- |
| 有 | 有 | A | **仍被清空**（不是「留到下一次」） |
| 无 | 有 | B | 被清空 |
| 无 | 无 | 新生成种子 | 无 |

生成失败/提前返回不撤回先前的清空与播种。本条只闭合随机输入状态，地牢布局算法归《随机地牢》。

### 5.3 记录/回放

- 战斗记录内容：战斗类型、属性（双方训练家信息、两队与首发序列化、天气与持续、可逃跑/换人风格/动画显示、物品、背景、时间、环境、规则）、回合命令序列、**随机数序列**、换人记录。
- 回放：按记录索引顺序取用随机数，**不重新随机**——确定性重放依赖记录序列完整；覆盖哪些动作/布局、遗漏随机调用或版本变化的影响归设施回放领域规格。
- 可重现性限定：普通随机、显式种子、记录序列是三类不同机制；**跨系统一致性未验证（U05 保持开放）**。

### 5.4 有状态的偏向未出现值选择

另有作者/插件可直接调用的整数选择能力，输入限定为正整数规模 n，候选为0至n−1。每轮保留已出现和未出现的身份：首抽从全部候选均匀选择并记为已出现；未出现者仍有剩余且已出现者非空时，有 **1/7** 的分支从已出现者均匀再次选择，重复不改变已见/未见状态；其余 **6/7** 从未出现者均匀选择并移为已出现。全部出现后，**下一次请求先重开一轮**，清除本轮已见身份，首抽不经过重复门。

| 条件 | 推导结果／状态 |
| --- | --- |
| n=2，首抽0后，已见仅0、未见仅1 | 下一次P(0)=1/7、P(1)=6/7；返回0仍留下未见1；重复门未命中则返回1，随后本轮耗尽 |
| 同一条件的其它选择机制 | 无放回的P(0)=0；独立均匀抽样的P(0)=1/2；单条0,0序列只能排除无放回，不能证明与独立均匀抽样的分布差异 |
| n=2，一轮0/1均已出现，下一次请求 | 新轮候选重新为0/1，首抽各1/2，无旧值重复门 |
| n=1 | 每次只能返回0，每次耗尽后于下次重开 |

重复可以延迟本轮耗尽，故不保证每n次请求覆盖全集，也不是无放回洗牌。条件概率是依普通整数均匀随机前提的静态数学推导（DERIVED_VECTOR，NOT_EXECUTED_THIS_UPDATE），没有统计运行或跨语言序列一致性证明。固定脚本搜索只有能力定义，未定位默认消费者/覆写；不能称为系统统一默认随机服务。零/负规模、真实插件使用及原生随机分布未证。本条只描述行为与跨次状态，不规定未来类、容器或API。

## 6. 保存/恢复交界与可重现性

- 统计记录与全局元数据（含遭遇版本、地牢待播种子、亲密步数）均为持久状态，经保存值注册保存（《保存、启动、新游戏与继续》引用）。
- 遭遇版本：持久全局遭遇版本选择（默认 0），影响遭遇表查询（《内容身份、注册与 schema》身份例外、遭遇领域规格）。
- 读档后：现实时间系统按宿主时钟继续（各消费者按 §3.2 的规则处理）；运行时长从新进程重新起算；游戏时间从存档值继续累加（载入重新设锚点）。
- 种子消费与恢复的边界：地牢待播种子保存后随存档恢复，下一次地牢生成被选中即被清空（§5.2）——保存/恢复时的种子状态一致性归《随机地牢》与《保存、启动、新游戏与继续》联查（U05）。

## 7. 默认行为与配置变体

- **基线默认**：现实时间驱动日历/昼夜；运行时长驱动帧计时；游戏时间锚点机制；普通随机无统一入口；显式种子仅地牢与彩票。
- **支持但未默认启用**：`TIME_SHADING`（默认开，可关）；地牢待播种子（作者可预设）；全量编译标志等编译触发（《PBS 生命周期》）。
- **配置/数据关联**：`NEW_BERRY_PLANTS`（树果机制变体）；时段/季节判定的内容组合（遭遇时段条目、形态时间条件）归领域规格。
- **未验证组合**：跨系统随机一致性（U05）、录像重放的范围与版本边界、离线时长对各系统的组合影响。
- 参考快照行为、官方版本预期、未来目标分开标记；本文件只记录第一类。
