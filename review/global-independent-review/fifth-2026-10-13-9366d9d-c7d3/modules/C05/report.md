## GR5-M05-001：已有自清条款不足以接收 PC Give 失败

最强反证是 WP20 §6.3 与 HP-24：两者已正确描述持物不匹配时邮件读取会自清。WP64 §3.3、WP66-A §4.4 又已明确部分给予操作并非事务。但这些既有条款仍与 WP64 第 56 行、WP66-A 第 22/107 行及 MG-12 的明确成功输出矛盾；并没有写出本入口的失败时点和剩余状态。WP64 §8 的相关不变量实际在第 124 行，应补进 M05 原定位。

直接读取链为 PC 信箱入口 → 邮件给予画面 → 个体持物/邮件读写 → 邮件建构与信箱转入。默认 GRASSMAIL 是合法邮件；邮件写入不会同步持物。接收者原持物为空时，成功提示返回后临时挂入原邮件，下一次邮件读取将其清空，再访问空结果的物品身份而失败（静态判定为 NoMethodError）。持物赋值、信箱删除和正常关屏均尚未到达。

最小初态为一名空手非蛋 P 与信箱一封合法 M。这个初态可以由正常背包给予 GRASSMAIL、完成写信，再在容量条件满足时 Take→存 PC 得到，无需损坏数据或人工失配。失败点上 P 无持物、无邮件，信箱仍保存同一 M 及原内容。

| 对照 | 结果 |
| --- | --- |
| PC Give 选择空手非蛋 P | 提示 → 临时挂信 → 自清 → 失败；M 留信箱 |
| PC Give 取消选人 | 不发生转交 |
| 目标已有正常持物/匹配邮件，或为蛋 | 先行拒绝，不到该失败点 |
| 背包新邮件给予空手非蛋并完成写作 | 正常扣物、设持物，邮件保留；没有中间失配读取 |

原 WP64-C02 只纠正“转移既有对象而非重建”的身份语义；它不能证明 Give 能走完。旧 WP66A-R01/MG-07–08 的交换取消与先取后给取消属于别的执行链。修订应保留这些正确事实，改正成功承诺及 MG-12，并单列未来兼容选择。不声称信箱丢信、进程崩溃或存档损坏。

## GR5-M05-002：实际整理入口可以存走主体，删除失败被忽略

本项重点质疑了五处可能使反例不成立的条件，均直接读到必要 caller、门、数据和后续处理：

1. **正常入口与许可**：暂停菜单把玩家队伍交给完整主队伍界面；当前会话保存 Box Link 许可。Item→Use 临时打开背包后继续使用原场景。融合第二选择没有切为禁 SPECIAL 的快捷换位模式。
2. **实际队伍访问**：SPECIAL 打开整理模式 0；它正常展开队伍面板，允许选择 K 并 Store。这不同于净化室选择模式的特殊负位置问题。PBS 的 Box Link 物品及无禁用旗地图样本存在，但本审查不声称已验证 Demo 发放链。
3. **先存主体能过门**：初态 [K,R] 两者可战斗。存 K 时尚有 R，K 无邮件且可存、盒有空位，最后成员保护不阻止这次存放。
4. **同一主体仍被写入**：默认基础储存移动同一 K 后删除其队伍位置并原地压缩；不是克隆。融合会话保留的 K 正是盒中的 K，重建面板没有把该参数重绑到 R。
5. **实际 false 后续**：先写 K 的形态及对 R 的融合关联，再尝试删除 R。此时 party=[R]，删除因没有其它可战斗成员返回 false；调用方忽略它，继续刷新/提示与形态后段，随后替换工具并返回效果真。

最小限定输入采用 KYUREM0 K 与 RESHIRAM0 R，均普通存活非蛋非 Shadow；K 未融合、无强制形态、无邮件且可存；默认基础储存、世代 8、正常数据和后续处理。可用默认 L5 招式避免形态后段额外交互。背包 DNASPLICERS×1、已用版0，盒0格0空；当前主队伍会话的许可仍为真。进入第二选择后把 K 存入盒0，退出选 R，最终：

- party 仅有 R；
- 盒0格0仍为同一 K，形态1，融合伙伴是 party 中同一 R；
- 可用工具0、已用工具1，效果返回真。

这是同一成员从两处可达，不是复制了一个新 R，也不是全队清空。形态/融合关联**早于**删除失败写入；不能把所有提交都说成发生在 false 之后。

| 独立对照 | 应保留的结果 |
| --- | --- |
| 不进入盒子，直接选 R | R 正常移出，K 在队伍中融合，工具已用 |
| 存 K 后取消第二选择 | 不新增融合或工具替换；K 留盒、party=[R] |
| Box Link 禁用、或当前许可因先前 FLY 取消而丢失 | 这条 SPECIAL 存 K 链不可达 |
| 从普通 Bag→Use 新建选择画面进入 | 没有本主队伍会话的盒子许可，不能套主例 |
| 初态另有保持可用的 A，存 K 后再选 R | 删除 R 成功；K 仍在盒中融合 R，party=[A] |

C125 的有效控制与完整附表只接收菜单 Switch 的旧索引、孔位及空面板失败；U05-MV 只接收未缩队的旧持物重复。它们均未接收本次“盒中主体＋融合关联＋删除 false＋工具替换”的输出。WP25 的删除保护本身正确，应保留。
