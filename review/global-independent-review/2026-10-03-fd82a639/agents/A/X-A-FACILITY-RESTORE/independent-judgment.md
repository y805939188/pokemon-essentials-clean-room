## 场景 1：报名、取消、开始与非法轮次

前提：新会话已设置合法字符串挑战标识，所有全局状态有效；当前原队伍集合 P=[A,B,C]，之前报名集合 R=[A,B]，P 与 R 为不同集合但 A/B 为同一成员引用。新报名 UI 正常取消且返回空值；不把直接传空数组当 UI 常规结果。

取消新报名后 R 保留，玩家仍 P，未请求保存。随后以轮次 1、合法内容表与正常结束的抽样开始：先置进行中真、暂停假、决定 0、复制历史当前胜场／交换数、当前轮 1、训练家名单；成功生成后保存开始位置、原队伍引用=P，再将玩家队伍=R，最后请求安全保存。不是保存成功以后才替换队伍。保存假也不回滚这些写入。取消会话恢复集合 P 并重置，不做成员字段快照恢复、不保存。

成对非法向量：同样的新会话但轮次 0。进行中真、暂停假、决定 0、当前轮 1、名单空已写；此时轮次数尚未写（新对象为空）、开始位置和原队伍快照仍空，玩家仍 P，报名 R 保留，未请求保存。外层当前挑战标识也已写。若不是新对象，不可断言旧轮次数一定空，因为重置不清该字段。非法开始后取消只重置而保留玩家 P；调用结束则无条件把玩家写为原队伍字段空值，这一边界 WP55 已述。

证据：Challenge_BattleChallenge 79–93、200–229、270–318；Challenge_Data 38–49；UI_Party 1051–1138。原 WP55 38–63、120–126、174–198；净化 WP55 40–65、123–129；WS W09–W17、W28–W34。

## 场景 2：正常单场返回并非完整快照还原

前提：普通单打、无调试跳过、无额外临时规则／插件改队、双方各两只非蛋非暗影 CATERPIE，IV/EV 全 0、无极限训练、无特殊形态，只有 TACKLE 且 PP=1/35；原 HP 均 10。四只各持合法物品 I1/I2/I3/I4，普通内容可正常创建、动画与战斗正常返回。明确使用双侧固定 50 调整规则，不宣称为某默认杯；不加不同种限制。玩家 A 经验125123/等级50/总HP105，B 经验216007/等级60/总HP124；对手 C 经验125321/等级50/总HP105，D 经验216111/等级60/总HP124。

顺序与中间结果：玩家先全治，A/B HP105/124、PP35；保存双方完整经验；同级 A/C 跳过等级写入，经验仍125123/125321；B/D 改50级起点125000并重算。B 的 HP 为105；对手 C 未经战前全治仍HP10，D 从HP10按总HP差−19得到至少1，所以HP1。双方物品在上述调整返回之后才取快照。

正常返回后按当前列表位置恢复四个原经验值，等级分别50/60/50/60；两侧逐个完整治疗，HP分别105/124/105/124、PP35、状态清除；恢复四个保存的持物身份。原先的HP10和PP1不恢复。默认此战内部战斗标志假，经验奖励入口直接退出；不会用正常打怪经验覆盖本例。若引入具名 Mega／原始回归对象，包装还会清这些形态，不把它们当成原始形态快照复原；其余形态回调依各自条件，不能推导“所有形态都恢复初态”。

记录快照是在调整及玩家治疗后、真正开战前形成；导出发生在正常的设施恢复之后，但导出的初始双方队伍早已是独立序列化快照，不能把回放初值混为设施返回值。本轮仅检查该交界，未进行 WP58 全包主审。

## 场景 3：部分调整失败与战斗内未捕获异常

完全具名的作者配置边界：最大等级100；两侧使用组合策略，己侧固定50、敌侧开放下限101。玩家两成员初级45／40，对手两成员40／40；全部合法普通成员、未跳过、已有受伤／缺PP，其余设置正常。目标数组先算出玩家50/50、敌方101/101。玩家战前先治，玩家两只等级/经验均改到50级起点；到敌方第一只时等级写入拒101并抛异常。敌方第二只尚未访问。外层尚未取得调整返回记录、尚未记录物品、尚未创建战斗；没有局部回滚，玩家已改等级及治疗保留，对手经验未改。本向量用现有具体策略组合，无需虚构返回数组；不是默认杯自然输入。

另一个条件向量：合法固定50调整完成、物品已记录、进入战斗后，在引发任何正常终局收尾前发生未捕获异常。异常向外传播，设施还原、双方治疗、物品重置与临时记录清空／导出语句均不会到达；此前治疗／等级／战斗已写状态保留。若异常是在终局内部的更晚时点，必须按实际已经执行的行细分，不能说任何终局层都必未执行。场景待机与战斗动画也无统一确保清理：其异常后的重建精灵／退场／in_battle清假未到达。全局主循环或宿主之后怎样处理不属本静态局部承诺。

证据：LevelAdjustment 47–78、132–147、212–228；Pokemon 199–204；ChallengeRules 61–68；Challenge_Battles 50–96；BattleIntroAnim 51–57、59–151；Settings 131。原 WP54 73、81、83、99，净化 76、83、85、101，QC Q30 已述无事务保证。

## 场景 4：暂停／继续的状态、位置、保存结果

前提：已进行会话、决定0，开始位置 S=(地图1,2,3)，当前位置 C=(地图9,8,7,朝向6)；已有安全完整存档 D0，所有必需全局对象有效，无额外保存回调副作用。

暂停先置暂停真，进行中仍真；临时位置改S且朝向8，然后发保存请求。成功返回时磁盘新内容包括暂停真与S位置，内存位置恢复C。保存因 IO/SystemCallError 返回假时暂停真仍保留、内存位置仍恢复C；磁盘状态取决于故障点：打开前失败可仍为D0，打开截断后失败可能不完整，不能把假当已成功持久化或保证D0完整。继续先清暂停，再做同样保存，成功时持久化暂停假；返回假仍保留内存暂停假，位置恢复C。设施助手最终恢复朝向，不向上原样传递 Game.save 的真假。

具体未捕获异常：在完成位置替换后，保存数据验证遇到错误类型的背包值（其余预置数据有效），在真正打开文件之前抛出 InvalidValueError。暂停／继续对应标志已写，进行中仍真；位置留在S/朝向8，文件D0不因该次调用改写。该失败点在文件打开前，区别于上段的写文件 IO 失败。保存自己的安全标志、计数/时间等早期写入也不构成全局回滚；未运行该向量。

证据：Challenge_BattleChallenge 258–267、306–318；StartGame 111–124；SaveData 57–60；SaveData_Value 48–51、109–111、279–282；Game_SaveValues 69–95。原 WP55 57–63、126、181、197–198 与净化 59–65、129、WS W17/W33/W34 均正确保留主要区别。没有据一次请求声明真实磁盘提交。

## 场景 5：租借、战后交换与索引还原

初始租借在 UI 中不能整体取消；第三只确认否认会撤该第三次选择、继续选择。确认三只时返回新的集合但成员仍来自候选对象；会话只在进行中时交换数+1，随后提交租借集合。活动会话中玩家队伍与报名引用都被提交到 R。正常租借对象为新创建，区别于原队伍 P；退出会话恢复 P 的集合引用。

战后交换准备先保存上一对手队伍的引用 O，再生成新对手；正常单场恢复已在进入交换 UI 以前完成。选槽i并接受O[j]是引用替换R[i]=O[j]，不转属主、不拷贝字段。首屏或第二屏确认退出时UI不改槽、返回假、交换计数不加；会话仍无条件提交R。若活动会话当前队伍P2与R不同，可观察到取消后当前队伍变R；同引用下值不变不等于没有提交。选择“重选”则回首屏。原队伍字段未在这些UI或生成路径重写。

位置还原条件向量（直接边界，非正常UI自然重排）：旧玩家列表[A,B]，A旧经验125123、B旧经验216007，合法固定50调整后，在设施恢复之前由外部改列表为[B,A]。恢复按槽位使 B 得125123、A 得216007；持物快照也按新槽位给回，出现同样身份错配。普通战斗换人仅交换战斗排序表，未改成员集合；租借交换 UI 发生在单场返回以后，不能拿它证明本场恢复期间会自然重排。没有声称存在普通租借操作可在这个窗口触发错配。

证据：Challenge_BattleChallenge 373–427；ChooseFoes 88–164；BattleSwap 168–245；LevelAdjustment 34–44；Challenge_Battles 70–82；Battle初始化125–128、查询303–312；ActionSwitching 274–284。原 WP57 38–63、F09–F15 与净化 65–93、FC09–15、原 WP54 91/197 与净化93/QC Q28 相符。
