136	### 5.2 最初招式记录（GR-008 更正后表述）
137	
138	- 整表记录（入口身份 record_first_moves）：先清空，再把当前全部招标识依序复制入记录——**不做去重**：当前列表中的重复标识与顺序原样进入记录（当前列表可经 §5.4 招标识赋值等合法入口形成同标识两槽，PP 钳制规则不变）。
139	- 逐项入口：加入（未知 → 无效果；记录已含同标识 → 不再追加——但只阻止追加本身，不清除记录中已有的重复）／删除（未知 → 无效果；按标识删除全部同标识项）／清空。
140	- 已定位记录调用点（获得/转化时刻）：存入盒子/队伍前（赠送工具路径）；静默送出/送出到队伍（另一组赠送工具）；孵化完成；交换接收；捕获成功；神秘礼物；净化补记；调试（对照）。含义：记录「获得时刻的招式集」，供可重学功能使用。
141	- 逐项追加调用差异：**背包直接使用 TR** 经教学选择成功后，把所学招式追加到首招记录（已有则不重复），随后按道具属性消费；**队伍 Item → Use** 直接对已选成员教学成功并消费，但没有该记录追加。通用学习本身不自动补记；确认取消、拒绝或未学会均不追加。TM/HM/TR 按实际数据字段区分，例如具名 TM57 的字段为 TR、教学招为 CHARGEBEAM，不能仅凭名称把它当作非消耗 TM。教学统计与外层资源顺序归 WP28/WP30/WP66A。
142	- 消费方：招式重学界面——把记录作为候选来源之一（受配置开关控制「是否可教更多招式」）；以及可重学判定（§5.3）。
143	- 边界：记录与当前招式相互独立（之后学习/遗忘不自动同步记录；记录为空 ≠ 无候选）。

145	### 5.3 重学与兼容接口
146	
147	- 可重学判定（入口身份 can_relearn_move?）：蛋或 Shadow → 否；否则：存在「等级 ≤ 当前等级、且当前未掌握」的等级学习表条目 → 是；或存在「记录中而当前未掌握」的招标识 → 是；否则否。
148	- 重学界面候选：先取等级 ≤ 当前等级且未掌握的等级招；「可教更多招式」开启时，再把记录中未掌握、未在等级候选中的招放在等级候选之前，最后去重。**不会直接追加物种整个蛋招表**；孵化时曾记录的蛋招或背包 TR 追加项只是通过首招记录进入。界面开关关闭时不追加记录，而个体的可重学判定仍按上条检查记录，两入口不能合并。
149	- 兼容判定（入口身份 compatible_with_move?）：未知招式为否；否则命中以下之一即为是——教学表（TM/教学）、等级学习表、蛋招式表（本物种蛋招式表为空时回退到前进化物种的蛋招式表）。
150	- 学习/替换的交互主规则（何时问、放弃、满槽处理）归 WP30；本规格只定义上述判定函数的行为。

152	### 5.4 招式对象与 PP 规则
153	
154	- 总 PP（派生）：总PP = 基础PP + ⌊（基础PP × 提升计数）/ 5⌋（每 1 次提升 +20%，整除下取整）。向量与极端值见 WP19。
155	- 当前 PP 赋值：钳到 [0, 总PP]。
156	- 招标识赋值：改为新招式后，当前 PP 钳到「新招式的总 PP」（提升计数保留）。
157	- 提升计数赋值：写入任意整数（不钳位）；该调用随后即把当前 PP 按新总 PP 钳制。
158	  - 边界（静态）：提升计数过负（如 −6、基础 PP 20）→ 总 PP 变为 −4，写入提升计数的调用本身在钳制当前 PP 时失败（钳位区间反转：下界 0 > 上界 −4）；失败时提升计数已写入（−6）、当前 PP 保留原值；此后再做任何 PP 赋值仍会失败。正常入口不产生负计数。
159	- PP 恢复入口：完整治疗/回复 PP（§3.2）；道具层单项恢复（校验「槽位存在且招标识有效」与「总 PP > 0」，否则返回 0 不生效；回复量按总 PP 截断）；战斗内恢复道具在满足「同招标识且未变身」时同步战斗侧副本（WP42）。
160	- PP 消耗（战斗层）：战斗内经专门同步入口消耗——读包装对象、写其 PP，并在「原招式关联存在 + 标识相同 + 未处于变身」时写回持久对象的当前 PP（§5.5）；直接给包装对象写 PP 字段不触发该写回；多回合招式进行中不重复扣减、负 PP 的特殊调用不扣减、总 PP ≤ 0 视为无限（机制归 WP42，本规格登记边界事实）。
161	
162	### 5.5 持久/战斗临时边界（招式与 PP，登记）
163	
164	- 战斗开始时以持久招式列表逐项包装为战斗招式对象（各自持有独立 PP 数值与对原对象的关联；包装对象的 PP 只是一个独立字段）。
165	- 战斗中 PP 的三层区分：① 直接给包装对象写 PP 字段 → 只改战斗侧数值；② 经专门同步入口的设置/扣减 → 写包装对象，并在「原招式关联存在 + 标识相同 + 非变身」时写回持久对象的 PP；③ 变身/模仿等替换或复制出来的招式（无关联或标识不同）→ 永不写持久侧，战斗结束不保留。
166	- 战斗中升级学到新招式：持久列表更新后同步到战斗侧对应槽（战斗层流程，WP42）。
167	- 战斗结束：持久侧无需整体回写（同步入口已在过程中写回所需数值）；捕获的个体会被补记最初招式（§5.2）。
168	- 蛋的招式内容主要由孵化流程驱动（WP35）；学习/遗忘接口本身不含蛋守卫（守卫在各消费者/流程层）。

172	## 6. 持有物状态
173	
174	### 6.1 读取
175	
176	- 持有物记录读取：按标识解析（未知 → 空）；另有原始标识读取（未经解析）。
177	- 「是否持有」：无参 → 当前是否持有任意物；带参 → 当前持有物与给定项是否同一（比较语义接受符号/字符串/记录，WP03）；未持有时返回否。
178	- 物种「野生持有物池」读取：常见/少见/稀有三级池（各为列表）；生成侧按概率选取（WP36）。
179	
180	### 6.2 变更与清除
181	
182	- 设置规则：值非空且不是已登记道具 → 静默无效果（无提示）；空值 → 清除持有物；其余 → 写入规范标识。
183	- 入口差异（按行为登记）：个体字段入口（本节的设置规则）对未登记标识**静默忽略**；战斗侧对象的持有物入口对同一未知标识会解析为空并经由写穿**清空**个体持有物（§6.4 路径）——两个入口的失败结果不同，不能合并描述。
184	- 本规格不提供「取出/交给」的交互流程（队伍界面、道具使用、战斗效果均归各自规格）；本规格定义的是字段层行为与约束。
185	
186	### 6.3 约束（本规格可证）
187	
188	- 邮件耦合：邮件记录读取时若「邮件缺失或邮件对应道具与当前持有物不一致」→ 自动清除邮件；邮件写入只接受邮件对象或空值（其它报错）；邮件建立时若已有邮件 → 报错（邮件流程归 WP64）。含义：更换/清除持有物可隐式使邮件失效。
189	- 持有物与「所在球」是两个独立字段（球标识由捕获写入，WP18/WP38）。
190	- 进化消耗（特定进化条件持有物的清除，WP31）、战斗内效果（偷取/打落/消费等，WP42/WP50）与战斗还原记录（§6.4）分别经各自入口；不要概括为「所有入口遵守同一校验」——战斗侧入口对未知标识的行为与个体字段入口不同（§6.2 入口差异）。
191	
192	### 6.4 战斗内变更与可更新的还原记录（登记）
193	
194	- 战斗内持有物的战斗侧写入写穿到持久个体（战斗层对象写入时同时写个体；未知道具在其中解析为空并清空，见 §6.2 入口差异）。
195	- 战斗开始时以各成员当时的持有物初始化一份还原记录；该记录可在战斗中更新：当道具被永久移除（正常消耗/失去，且当前值与记录相同）时记录同步清除；副作用明确的「永久取得」（如对野生目标的夺取）可把记录更新为取得项；暂时移除（如打落）保留原记录。
196	- 正常战斗终局按玩家侧参与集合及届时同索引还原记录写回持有物；无伙伴实际参战且参与集合与当前玩家队伍同步时，以下逐成员对照成立。伙伴实际参战而满队接收移出旧成员时，身份与记录可错配，完整映射沿 WP38/WP42。
197	  - 正常消耗且未再获得 → 记录与当前均空，战后仍为空（不返还）；
198	  - 暂时打落且记录未改 → 当前空、战后还原原持有物；
199	  - 记录被更新过的合法路径（永久取/失）→ 战后按更新后的记录值。
200	- 捕获个体：若加入队伍，则在加入时把当前持有物登记进记录（战后按登记值，保留捕获时持有物）；若直接送箱，则不在队伍还原循环内（保持当前值）。
201	- 满队捕获转送旧成员至盒子：先按当前持物送盒，再从玩家当前队伍删除并左移玩家记录；无伙伴实际参战且参与集合同步时，该旧成员退出正常终局还原。伙伴实际参战的旧合并参与集合仍可保留其共享身份，终局按已移位记录写回，故盒中旧成员和留队成员都可能被写错物品。仅登记伙伴而未参与不构成此反例；完整限定输入及反向对照沿 WP38/WP42 的 CP20–22、E14／CX40–42，不以普通永久消耗冒充暂时打落前提。
202	- 各效果族对还原记录的更新点由 WP50 完整定义；本规格只定义「记录可更新 + 结束读取记录」的交界，不展开效果族。

206	## 7. 规则与不变量
207	
208	1. HP ∈ [0, 上限]；HP = 0 ⇒（非蛋个体）状态 = 无、计数 = 0（蛋保留既有异常/计数——清理入口带蛋守卫）；进化准备 = 假（不分蛋与否，恒执行）；Shadow 扩展清 Hyper 标志（叠加恒执行）。
209	2. 蛋对治疗/异常设置/重学/进化相关入口一律「无效果」；蛋的 HP 仍受重算写回。
210	3. 异常状态设置只对可用个体生效；未知值报错、非法类型报错；设置不改计数。
211	4. 关联计数只对睡眠/中毒有语义；中毒计数在战斗收尾归 0。
212	5. 四槽是初始化与常规学习界面的限制；整表存储可为零项或超过四项。静默新增超出时只移除首项一次；初始化重取最近 ≤4 招；列表顺序是状态的一部分（静默学习已会招式移到末尾）。
213	6. 每招式的「总 PP」由基础 PP 与提升计数派生（§5.4 公式）；正常合法状态下当前 PP ∈ [0, 总 PP]（成功赋值的结果）；极端负计数的失败路径下旧 PP 可留在区间外（§5.4 边界）；提升计数自身无域校验。
214	7. 最初招式记录与当前招式相互独立；记录 = 某时刻招标识的副本。「不重复」只限定到逐项添加入口：整表记录清空后逐项复制当时全部标识，保留重复与顺序；逐项添加只阻止对已含标识的再追加，不清除已有重复（GR-008）。
215	8. 持久/临时边界：HP/异常/计数/持有物写穿；招式 PP 仅经专门同步入口写穿（直接字段赋值与替换/复制招式只在战斗侧）；战斗结束对队伍成员按届时的还原记录写回持有物。
216	9. 持有物字段设置只接受已登记项或空值（未知项静默忽略）；战斗侧入口把未知项解析为空并清空（入口差异）；邮件随持有物不匹配自动失效。
217	
218	## 8. 边界与失败
219	
220	- 「回复 PP」按索引且索引越界（≥ 槽数）：运行错误（正常入口用「全部」或有效索引）；空槽（有槽位但招标识为空）由道具层守护（返回 0），字段层不守护。
221	- 提升计数极端负值：见 §5.4 边界（写入调用内的钳制失败：计数已改、PP 保留）。
222	- 状态设置：不可用个体静默；未知标识/非法类型报错（守卫先于校验）。
223	- 计数直接写入任意整数：原样保存。
224	- 持有物设置未知项（个体入口）：静默忽略（不是报错，也不清除）；战斗侧入口则解析为空并清空。
225	- 邮件耦合的隐式清除：更换持有物即可使邮件读取为空。
226	- HP 直写超过上限：钳制；负值 → 0（走清零分支；蛋的异常/计数保留）。
227	- 还原记录边界：见 §6.4（转送盒子路径与效果族更新点未穷尽）。
