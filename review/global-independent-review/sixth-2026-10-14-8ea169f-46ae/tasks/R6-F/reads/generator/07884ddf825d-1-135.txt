33: ## 2. 概念与术语（实现中立）
34: 
35: - **挑战 ID（challenge id）**：设施挑战的字符串标识（如 `pokecupsingle`）；生成产物（检查点、新列表条目、新 PBS 文件）均以其为名。
36: - **列表（trainer list）**：`Data/trainer_lists.dat` 中的兼容记录，包含训练家表、宝可梦表、挑战 ID 数组、训练家文件名、宝可梦文件名、默认标志；**默认列表**（默认标志为真）是无 ID 命中时的回退。
37: - **候选个体（candidate）**：拒绝采样产出的单个宝可梦；**池（party）**：候选的暂存集合——**不足 20 才补充**，是补充目标而非始终成立的容量上限（种子与退休成员回池可令其超过 20，§6.2/§6.4）。
38: - **可评级队伍**：从池中按建议数量取出的可评级小队，携带评分（rating＝胜率百分数）、当前待结算场次（games＝当前历史长度 h）、已结算累计 C 与可见累计场次（totalGames＝C＋h）。80／250 场更替门读取可见累计；当前历史清空后，已结算场数仍保留在 C 中（§7.4）。
39: - **真实分支**：1% 概率触发的真实无视觉战斗；**估算分支**：99% 概率的类型效果打分近似。
40: - **检查点文件**：生成中间产物 `<id>.rxdata`（池）与 `<id>_teams.rxdata`（队伍库），位于游戏根目录（非 `Data/`）——崩溃/中断后可从最近检查点继续的既有设计，如实登记。
41: - **审计名**：仅作追溯标识的方法/类名；行为描述不依赖其内部实现结构。

44: 
45: ### 3.1 设施设置调用点

50: ### 3.2 生成/复用询问（A-2）
51: 
52: - 先读 `Data/trainer_lists.dat`（缺失/异常 → 空表），把各列表显示名（文件名去 `.txt`，默认列表名前加 `*`）组为选项。消息的**取消返回位置与初始光标是两个独立行为**，分别按下述选项顺序解释，不规定调用参数序号。
53: - **无任何列表**：两选项消息「Generate Pokémon teams for this challenge?」（YES／NO）——**初始光标在 YES**；按确认（YES）→ 进入「新生成」支；按取消 → 映射到 NO 返回。
54: - **已有列表**：三选项消息同题（NO／YES, USE EXISTING／YES, USE NEW）——**初始光标在 NO**；按取消 → 映射到 NO 返回。
55: - **新生成支**：再经确认消息「This may take a long time. Are you sure?」（Yes／No——**初始光标在 Yes，按取消映射到 No**）——**取消或选 No 即返回**（不产生任何生成）；确认后创建消息窗口、进入长任务（§4–§8）：进度回调**只在被调用到时**检查距上次刷新是否满 5 秒，满则刷帧；**有文本消息时立即显示并刷新**——不承诺每 5 秒必有文本、也不承诺长计算段内持续刷新。完成后窗口销毁并提示「Team generation complete.」。
56: - **取消语义**：询问/确认阶段的取消只阻止生成启动；**已启动生成无中途取消路径**（进度回调只刷帧/显示，不查取消），如实登记。

58: ## 4. 复用已有列表（B）
59: 
60: - 选择列表（默认取消值 −1；**取消选择＝不改任何数据**直接返回）。
61: - 选中后提示该挑战将使用所选列表的宝可梦；随后**把本挑战 ID 从所有非默认列表的挑战数组中移除**（while 循环删除全部出现），再**仅当所选列表非默认**才把 ID 追加进其挑战数组——**选默认列表时 ID 被整体迁出后不再追加**（默认列表经回退支自然覆盖，§8.1 查询顺序）。
62: - 写回 `Data/trainer_lists.dat`、刷帧、调用训练家列表反写（§8.4）——复用分支也触发全量列表反写。
63: - 列表为空时选择步不会出现（§3.2 两选项形态）；**选择默认列表与选择非默认列表的迁移结果不同**，不互相替代。

65: ## 5. 候选个体生成（C；拒绝采样）
66: 
67: ### 5.1 总体结构
68: 
69: 外层为**无迭代上限**的拒绝采样循环：逐段构造物种 → EV → 性格 → 道具 → 招式，任一约束不满足即重掷对应段或整体重采；最终以规则集单成员合法判断为**唯一出口门**（WP54 合同）。**无可满足输入时本循环不终止**（如实登记，§10）。
70: 
71: ### 5.2 物种与等级（C-1）
72: 
73: - 等级恒为规则集建议等级（WP54）；物种从全部物种键等概抽样，**只收形态 0**。
74: - 每轮抽 0–19 均匀整数 r，按外层迭代**奇偶交替**两套偏好门：
75:   - 偶数轮：拒绝 `r<16 且 BST<400`；拒绝 `r<13 且 BST<500`——偏好中高 BST。
76:   - 奇数轮：拒绝 `BST>400`；拒绝 `r<10 且非宝宝形态`——偏好低 BST/宝宝。
77:   - 两轮共通：拒绝 `等级 < 该种最低等级`；拒绝 `r<10 且为宝宝形态`；拒绝 `r<7 且仍有进化形`。
78: - 各项族事实（BST/宝宝种/最低等级/进化形）经**全局缓存**按种 memoize（§9.1）。
79: 
80: ### 5.3 EV 与性格（C-2；强调条目可重复）
81: 
82: - EV 初始集合：每个主能力值独立以 50% 概率入选——**此阶段无重复**（先选集合、后续按道具/招式再调整）。
83: - 性格抽样：中性（无能力修正）或 LAX/GENTLE → 仅 5% 接受；有修正性格：若其**提升项不在 EV 集合** → 60% 拒（无提升强调）；若其**降低项在 EV 集合** → 90% 拒（有降低强调）——性格与 EV 强调一致性是概率门，不是硬约束。
84: - **后续调整的重复语义分两类**：**三种树果门**（§5.4）只在对应强调**不在列表**时才按其 50% 抽样补入一条——**已存在时不追加、也不消费该次抽样，树果不会产生重复条目**；**可能产生重复的是纯物理/纯特殊接受后调整**（§5.6）的 80% 追加——**追加、不去重**，同一能力可出现多条；删除操作则**清除该能力的全部条目**。构造阶段按**含重复条目的总数为分母**均分（§5.7）。

88: - 候选表为独立输入数据，共 **41 项**（按源表序）：ORANBERRY、SITRUSBERRY、ADAMANTORB、BABIRIBERRY、BLACKSLUDGE、BRIGHTPOWDER、CHESTOBERRY、CHOICEBAND、CHOICESCARF、CHOICESPECS、CHOPLEBERRY、DAMPROCK、DEEPSEATOOTH、EXPERTBELT、FLAMEORB、FOCUSSASH、FOCUSBAND、HEATROCK、LEFTOVERS、LIFEORB、LIGHTBALL、LIGHTCLAY、LUMBERRY、OCCABERRY、PETAYABERRY、SALACBERRY、SCOPELENS、SHEDSHELL、SHELLBELL、SHUCABERRY、LIECHIBERRY、SILKSCARF、THICKCLUB、TOXICORB、WIDELENS、YACHEBERRY、HABANBERRY、SOULDEW、PASSHOBERRY、QUICKCLAW、WHITEHERB。**先以 1/40 直取 LEFTOVERS**，否则表内等概抽。
89: - **物种限定门共 13 个**：LIGHTBALL→皮卡丘、SHEDSHELL→佛烈托斯/盔甲鸟、SOULDEW→拉帝欧斯/拉帝亚斯、ADAMANTORB→帝牙卢卡、PASSHOBERRY→大钢蛇、BABIRIBERRY→班基拉斯、HABANBERRY→烈咬陆鲨、OCCABERRY→巨金怪、CHOPLEBERRY→月伊布、YACHEBERRY→土台龟/天蝎王/哈克龙、SHUCABERRY→席多蓝恩、DEEPSEATOOTH→珍珠贝、THICKCLUB→卡拉卡拉/嘎啦嘎啦；另有 **FOCUSSASH 为非物种条件门**（BST>450 时 80% 重抽），与 13 门分列。

91: - 等级段替换：**等级 <10**（且 ORANBERRY 已注册）→ 1/40 或当前为 SITRUSBERRY 时换 ORANBERRY；**等级 >20**（且 SITRUSBERRY 已注册）→ 对称替换。
92: - **无效道具不在抽样阶段统一剔除**：中间表示构造时经存在性尝试查询，无效/不存在的道具转为**空**。

94: ### 5.5 招式合法集（C-4；首次入集与剪枝自删除）
95: 
96: - 来源三路**按序处理**：**升级招式**（学习等级 ≤ 当前等级，权重 2）→ **机器招式**（教学招式 ∩ 全部机器道具招式，权重 0——机器表全局缓存一次构建）→ **宝宝种蛋招式**（权重 2）。**同一招式已有副本时后续来源不再加权**（去重检查在入集前）；**某来源首次加入恰好产生零副本时**（如机器来源权重 0），该招式未实际入集，**后续来源仍可加入**。
97: - 入集权重（同一招式可多次入集实现偏置）：默认 base＋1；无效果码且威力 ≤40 → base；威力 ≤30 或 GROWL/TAILWHIP/LEER → base；威力 ≥60 或 REFLECT/LIGHTSCREEN/SAFEGUARD/SUBSTITUTE/FAKEOUT → base＋2；威力 ≥80 且普通系 → base＋3；指定高价值件（PROTECT/DETECT/TOXIC/AERIALACE/WILLOWISP/SPORE/THUNDERWAVE/HYPNOSIS/CONFUSERAY/ENDURE/SWORDSDANCE）→ base＋3。**BUBBLE 与 BUBBLEBEAM 永不加入**。
98: - 剪枝（按集合内两两比较；**比较资料是剪枝前构建的初始快照，删除作用于正在遍历的活集合**——有顺序影响，不是顺序无关的理想优势筛选）：**必中**（命中 0）招式删除同系无效果码且威力不高于它的招式——**无身份排除，满足条件的招式连同自身全部副本一并删除**（固定数据中 AERIALACE、SWIFT 正具备此条件——必中、无效果码、威力 60）；同效果码双变化招删低命中者；**剧毒**（BadPoisonTarget）删除**中毒**（PoisonTarget）；同效果码同系攻击招的剪枝需**同时**满足：**发起方有伤害**（威力非零）＋**PP 门**（发起方 PP 为 15/10 或与对方相同）＋**强度条件**（威力更高，或同威力而命中更高）→ 删除另一方——**PP 门属于发起方**：满足 PP 但强度不足不剪（负例见 GN07-c）；PP 门不满足同样不剪（成对方向相反对照如实登记）。
99: - 合法集按**等级全局缓存**（等级变化即整体重建，同种缓存命中不重算——Sketch 改写见 §5.6）。

101: ### 5.6 招式选取与一致性（C-5；共享缓存与 Sketch 豁免）
102: 
103: - **Sketch 特例（改写共享缓存）**：合法集首项为 SKETCH 时置 sketch 标志，并把**缓存列表本身**的前四个位置逐个改写为随机招式（等概随机，排除 Struggle 与 ReplaceMoveWithTargetLastMoveUsed 两效果码）——**列表不足四项会被扩展，超过四项的尾部保留**。**相同等级同种的后续采样看到的是改后的缓存**（首项通常不再是 SKETCH，sketch 标志也不再置位）；**切换等级才清空合法集缓存**。
104: - 合法集为空 → **整体重采**（外循环继续）；唯一招式数 <4 → 直接采用（不补齐，**不经过本段组合门与 SILKSCARF 门**）；≥4 → 选取循环：
105:   - 从加权集随机取至满 4 个不同招式；候选有同系更大威力招时 50% 跳过。
106:   - 组合约束：**蓄力**（STOCKPILE）与**喷出/吞下**（SPITUP/SWALLOW）必须成对——**sketch 标志豁免此配对要求**；**梦话/鼾声**（SLEEPTALK/SNORE）各需**睡觉**（REST）同在，否则仅在（sketch 或合法集本无 REST）时按 20% 放行——**梦话与鼾声各有独立的睡觉例外门**：两者同时出现而无 REST 时，满足例外前提也**需两道门分别通过**。
107:   - 物理/特殊一致：全队无物理招而 EV 含攻击 → 80% 重掷；无特殊招而 EV 含特攻 → 80% 重掷（物理/特殊/普通系标志**只统计威力非零招式**）。
108:   - 总威力门（**两门共用同一次十面抽**，不是两个独立随机事件）：该次抽 >6 且总威力 >180 → 拒；同次抽 >8 且总威力 >140 → 拒；总威力 0 → 95% 拒。
109:   - 接受后调整：纯物理队 → 80% **追加**攻击 EV（可重复，§5.3）、80% 清除特攻 EV 全部条目；纯特殊队对称；**SILKSCARF 在无普通系攻击招时换 LEFTOVERS**（普通系变化招不足以保留）。
110: - **道具-招式终校**：LIGHTCLAY 无光墙/反射壁 → LEFTOVERS；BLACKSLUDGE 非毒系 → LEFTOVERS；HEATROCK 无大晴天 → LEFTOVERS；DAMPROCK 无求雨 → LEFTOVERS；含 REST → 33% 换 LUMBERRY、再 25% 换 CHESTOBERRY（两段独立可叠加覆盖）。

112: ### 5.7 个体构造（C-6；均分分母含重复条目）
113: 
114: - 中间表示（物种/道具/性格/四招式/EV 条目）→ 实例化：个体值全主能力 31、随机 32 位 personalID、亲密度 0、RETURN 转 FRUSTRATION（存在时）、**EV 均分**——**分母为含重复条目的条目总数**，逐条目对该能力写同一整数值（重复写**不累加**）、重算数值。确定性向量（EV 上限 510）：空条目 → 各能力 0；单条目 → 该能力 510；两条不同 → 各 255；**[HP、攻击、攻击] → 分母 3 → HP 与攻击各 170、合计 340**（不是两能力各 255）。**单条目 510 超过单项上限 252**——生成路径**不自动夹回 252**（该写入与最终规则是否另行拒绝分开，WP54 消费合同）。
115: - 反向转换（写表用）：招式位按序取 id（空位 nil）、**EV 收录阈值为 >60**（每主能力独立判定）。

117: ## 6. 队伍组建与迭代（D）
118: 
119: ### 6.1 重复判定（D-1）
120: 
121: - 物种不同 → 必不重复。同种时两判据：
122:   - **招式判据**：四个招式位**按槽位原序**（含空位占位）逐项相等即重复，不去空位或排序；比较是**槽位序敏感**的。
123:   - **属性判据**：道具、性格、全部主能力 EV 值逐项相等即重复。
124: - 判据间为「或」：任一成立即视为重复。
125: 
126: ### 6.2 补充与同种上限（D-2；补充目标 ≠ 容量上限）
127: 
128: - **补充**：**池不足 20 才反复生成候选**、仅当不与池中任何成员重复才入池——**20 是补充目标而非容量上限**：已有大池不截断，种子填充与退休成员回池均可令其超过 20（§6.4）。候选无限重试，无进度上限登记。
129: - **去重**：顺序扫描，重复者丢弃；**同种成员超过 10 时删除该种最早成员**（先进先出顶出）——同种上限 10 **仅在显式去重阶段生效**（按重复判据之外的纯物种计数），其它阶段不受此限。
130: 
131: ### 6.3 队伍取样（D-3）
132: 
133: - 从池中按建议数量（生成阶段使用**设为 2 的规则副本**——每次取出 2 只，§6.4）**逐个随机抽取并即从池中删除**（池被消耗）；组成后过**该规则副本**的团队合法校验，不过则**重新抽取**（无迭代上限；池随每次尝试净消耗——耗尽早于满足时的行为无保护，如实登记）。
134: - 新队伍：评级以活动变体初值 1500/350/0.9开始（§7.4），历史空、累计已结算场次 0。
