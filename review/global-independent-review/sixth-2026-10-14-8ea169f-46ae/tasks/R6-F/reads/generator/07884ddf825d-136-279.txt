143: - 每轮迭代：
144:   1. **写池检查点**；进度消息「Generating teams (i of 11)」。

146:   3. **写队伍库检查点**；队伍库补至 600（每队建前补充池）。
147:   4. **写池检查点**；按评分降序排；进度消息「Simulating battles (i of 11)」。

178: 
179: 活动评级为 Glicko-2 **变体**，初值 R₀＝1500、D₀＝350、σ₀＝0.9。以下数学按独立变量给出，不调用或移植参考实现：
180: 
181: - **尺度**：归一化 rating₂＝(R−1500)÷173.7178、deviation₂＝D÷173.7178；**波动率 σ 以其原值（0.9）直接参与归一化域运算**（不做尺度换算，如实直述——空历史例：σ＝0.9 与归一化偏差平方相加后开方，换回时乘 173.7178）。
182: - **对局记录**：每条记录保存**记录当时**的对手评级 Rⱼ 与偏差 Dⱼ（快照）；之后逐队结算不回改这些值。结果 sⱼ∈{胜 1、负 0、平 −1}。
183: - **g/e 因子**：gⱼ＝1÷√(1＋3·(Dⱼ÷173.7178)²÷π²)；eⱼ＝1÷(1＋exp(−gⱼ·(rating₂−(Rⱼ−1500)÷173.7178)))。
184: - **方差**：v＝1÷Σⱼ(gⱼ²·eⱼ·(1−eⱼ))——**全部记录（含平局）参与**。
185: - **改进和**：Δ＝Σⱼ(sⱼ≠−1) gⱼ·(sⱼ−eⱼ)——**平局记录不进入改进和**（不等同按 0.5 计分）。
186: - **波动率更新**：改进量 **i₀＝Δ·v**（改进和先乘方差，与 Δ 本身分开）；a＝ln σ²（σ 为**本次更新前**的波动率）；τ＝1.2。**每次非空历史更新的迭代初始值 x₀＝a**（即本次更新前波动率平方的自然对数——**0.9 只属于固定示例，不是每次固定输入**）。以 x 为当前近似做牛顿迭代，每步：d＝(φ²＋v)＋eˣ（φ＝更新前 deviation₂）；i＝i₀÷d；**两项迭代量** h₁＝−(x−a)÷τ² − ½·eˣ·i²、h₂＝−1÷τ² − ½·eˣ·(φ²＋v)÷d² ＋ v·eˣ·(φ²＋v−eˣ)÷d³；**下一近似 x ← x − h₁÷h₂**；**至多 100 次**、步长绝对值 <10⁻⁶ 即停；σ′＝e^(x÷2)。**固定算术核对**：双方 R1500/D350、σ＝0.9——g≈0.6690694126、e＝0.5、v≈8.9354749036、初始近似 x₀＝a≈−0.2107210313。**一场平局**：Δ＝0 → i₀＝0 → 初始近似处 h₁＝0、h₂≈−0.6885384548 → **步进为 0、立即保持 σ′＝0.9**。**一场胜局**：Δ≈0.3345347063、i₀≈2.9892264725、i≈0.2165362337 → h₁≈−0.0189896159、h₂≈−0.6885384548 → **步进≈0.0275796011**、下一近似 x₁≈−0.2383006324（一步固定算术，非全程收敛值）。
187: - **偏差与评级更新（消费新值）**：t＝φ²＋**σ′²**（新波动率）；deviation₂′＝1÷√(1÷t＋1÷v)；rating₂′＝rating₂＋(deviation₂′)²·Δ（新偏差）；换回 R′＝1500＋173.7178·rating₂′、D′＝173.7178·deviation₂′。
188: - **空历史**：不更新评级/波动率，仅膨胀偏差 deviation₂′＝√(φ²＋σ²)——固定向量：D＝350、σ＝0.9 → D′≈**383.332855**。
189: - **展示分数（胜率百分数）按偏差分轨**：D >100 → Smogon 式（对手基准 1500/350：s＝√(100000＋D²＋350²)、g＝10^((1500−R)×0.79÷s)、胜率＝1÷(1＋g)×100）；D ≤100 → GLIXARE 式（sqr＝√(15.905694331435×(D²＋221781.21786254))、指数 inner＝(1500−R)×π÷sqr、胜率＝(10000÷(1＋10^inner)＋0.5)÷100）——**展示缓存随评级/偏差变更失效**。
190: - **场次结算与守恒**：前提为合法队伍、有效的已结算累计 C、评级数据及有限历史，本次评级更新正常完成并清空历史，期间没有队伍替换、外部修改或新对局。设结算前当前历史为 n 场；评级更新成功、历史清空后，把这 n 场并入已结算累计，得 **C′＝C＋n、h′＝0**。因此同一队伍的可见累计结算前为 C＋n，结算后仍为 C′＋h′＝C＋n，不减少、不重复累计；空历史的场次增量为 0（偏差膨胀仍按上条）。不是把清空后的 0 场作为本次已结算数量。
191: - **失败阶段**：在上述有效累计已存在的前提下，若评级更新在清空历史之前抛错，则历史清空及本次场次累计均未完成；原待结算历史和已结算累计仍在。评级更新可能已经修改部分评级字段，不承诺评级全字段事务回滚、外层正常收束或下一检查点写出必达；无效数据、外部修改及真实宿主异常表现不由正常结算不变量覆盖。

218: ### 8.3 宝可梦分配（F-2；编号与成员列表不对称）
219: 
220: - 先把宝可梦表全员**等级归一**为**原规则**建议等级（就地赋值——直接修改输入对象；**等级赋值只改等级与经验下限、不显式重算数值**——建议等级变化时数值与等级可不一致，如实登记），逐只缓存类型与**按原规则的**合法性。
221: - 每名训练家：既有宝可梦号 → 统计可用物种集合与**类型计数**（计数 ≥5 才保留：除 4、封顶 10；全 0 → 普通系置 1；无宝可梦号 → 全类型置 1）。
222: - 抽取（仅当传入宝可梦表）：对每只合法候选算**位次差** `|(候选位次×8÷表长) − (训练家位次×8÷训练家数)|`（截断至 7），查权重表 **[32,12,5,2,1,0,0,0]**；物种可用 → 四十面抽小于权重即入选；不可用 → 权重 × 该候选各类型计数后再判（**每类型独立一次机会——双属性候选同一轮可被加入两次**）。
223: - **集合不对称**：首轮结束只对**编号**去重，**成员列表仍可重复**；同种顺序补足**不检查编号已收**（同种支可把已选编号再次加入；仅同型支查重）；最终**仅排序、不再去重**——输出编号可含重复。
224: - **补足三对象与数量门**：分清**输入候选总表**、**已选编号列表**（可含重复）、**已选成员列表**（重复规则不同）。**顺序补足入口**：「已选编号数 < 容量（`MAX_PARTY_SIZE`＝6）**或**清个体规则的规则副本对**当前已选成员列表**判定失败」——满足才进入顺序补足；**顺序退出**需「编号数**达到容量**，**且**原规则对当前已选成员列表判定成功」（例：候选总表 10 项、已选 3 项已能组成原规则的 3 成员队但容量为 6——**仍需补足**，不能因存在合格子队伍即停；合格队在候选总表中但当前已选成员尚不构成时，检查的是当前成员列表）。不足时先按同种/同型顺序补足；仍不足 → **随机补位**：**不再按预先缓存的单体合法性筛选**（可加入不合法候选）。**随机阶段持续条件同时含两个**：「编号数仍小于候选总表长度」**且**「编号数不足容量**或**原规则判定失败」——**达到候选总表长度可在队伍仍不合格时停止**；**不是全候选表存在合法子队伍就能停**。**编号长度限制不是抽样次数上限**——重复抽到已收编号可持续无进展，已有重复编号又可能提前达到长度停止——**不能保证输出六个不同合法候选、也不能保证全部候选均已尝试**。
225: - 分配结果升序写回各训练家宝可梦号。

227: ### 8.4 写出与反写（F-3）
228: 
229: - 宝可梦表经反向转换（EV 阈值 >60）。
230: - 更新 `Data/trainer_lists.dat`：**先记录扫描开始时是否存在任意默认列表**（一次性事实），再**更新所有含本挑战 ID 的条目**——**各条目的默认标志都取该先前事实的反值**，遍历途中不重算：**已有默认且该默认也命中 ID → 该默认被清除**（可能最终没有默认）；**原无默认且多个条目命中 → 多个条目都成默认**；**原有不匹配的多个默认不被清理**。所有匹配条目就地换训练家表/宝可梦表、**保留原文件名**；**仅零匹配才新建条目**（文件名 `<id>_trainers.txt`/`<id>_pkmn.txt`、标志同取先前事实的反值）。**复用路径（§4）不做同样的标志操作**。查询回退顺序（§8.1）在多默认/无默认结果下按首个命中生效。
231: - **写出顺序与失败残留**：**先保存 `.dat`，再打开并截断总 PBS**，逐列表交错写总表、训练家表与宝可梦表——**后续失败不自动撤销先前数据或已写文件**；末尾成功消息/窗口销毁也不保证到达。**反写空值不对称**：道具可空（无效/空 → 空字段）；**性格为空或无效时不走同样的空值保护——必需查找直接失败**。**编译侧边界**：缺总表 → 新建默认引用（battle_tower 两文件）；节内**缺必需文件名键 → 报错**；文件名存在但**所指文件缺失 → 该子表为空**；**宝可梦行缺必要分隔字段 → 解析失败**（不同于未知标识变空）——各阶段失败的可见残留与重跑输入如实登记，引用 WP04/WP75 不代替这些具体消费边界。**旧检查点继续保留，重跑不是事务回滚**。
232: - **编译往返**：训练家列表编译（WP75 管线）把 PBS 编回 `.dat`（训练家台词经消息类型四组哈希收集；宝可梦行逐行经检查解析——物种/道具/性格不存在 → nil，招式名无效跳过、全空时取任意一招）——往返中「nil 道具 → 空字段（**性格不在此列**）」「EV 阈值 60」「无效招式丢弃」为如实登记的不互逆点。

253: ## 10. 边界、失败与未知汇总
254: 
255: 1. **调试门**：写杯入口非调试直接返回——正式配置下无任何生成/复用路径。
256: 2. **无终止保护**：候选采样（§5.1）、池补充（§6.2）、队伍取样（§6.3）均无迭代上限；严格规则下可能无进展——不补兜底、不承诺必然生成成功。
257: 3. **取消语义**：仅生成启动前的询问/确认可取消；长任务无中途取消；**保护检查与取消不撤销此前已发生的变化**（检查点已写部分不回滚）。
258: 4. **重复判定的槽位序敏感**（§6.1）为静态合同，不证明已运行的对局结果。
259: 5. **池消耗**：队伍取样从池中删除成员；耗尽早于满足时行为无保护。
260: 6. **真实分支副作用**：等级归一不恢复；正常返回后完整治疗（含 PP）＋持物还原——是治疗到目标状态而非战前快照；异常出口不承诺恢复段已执行（§7.2）。
261: 7. **评级数值边界**：估算分支平分 → 比较取整后的缩放评分、再同 → 平局；0–31 每方独立抖动；波动率迭代上限 100 次；胜率两式以偏差 100 分轨；波动率以原尺度参与归一化偏差计算（变体尺度混用，§7.4）。
262: 8. **数据缺口（demo）**：当前快照 `Data/` 仅 `Scripts/`、`Scripts.rxdata`、`messages_core.dat`——**`Data/trainer_lists.dat` 不存在**：**仅能断言未经准备的该快照在直接执行这些读取且仍缺文件时回退空表**；编译管线把列表数据列为常规产物（训练家列表编译在 PBS 全量编译序列内），**能从当前已存在的 PBS 生成它**，生成/复用也能写回——**后续读取不一定为空，不能据原始快照断言正常启动必走空表分支**；`PBS/battle_facility_lists.txt` 存在（默认＋4 杯赛节）；**`cup_fancy_trainers.txt` 与 `cup_fancy_pkmn.txt`（非 _single 变体）无任何列表/脚本引用**（未引用文件如实登记）；fancy 杯单双打均引用 `_single` 变体文件。
263: 9. **宿主/环境未知**：长任务实际耗时、真实对局胜负分布、评级收敛表现、生成结果的对局质量均未验证；训练家台词的翻译提取/反写（消息类型四组哈希）属 WP08 边界。
264: 10. **回退一致性**：选默认列表时 ID 迁出后不追加（§4）；生成写出时默认标志按**先前事实取反**——可多默认、可无默认，**不是唯一化**（§8.4，）——两条路径的默认语义不互相推导。
265: 11. **训练家生成**：普通抽样循环无成功退出——一般随机生成不保证完成、也非必然卡住（YOUNGSTER 连续快捷命中为可继续特殊路径）；既有非空表绕过（§8.2）。
