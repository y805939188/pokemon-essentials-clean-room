## 1. 目的、可见流程与状态边界（A）

本包回答“一场设施战斗如何被记录、记录了什么、何时成为可保存的‘上次战斗’、回放按什么规则重演，以及哪些内容不在记录内”。它不定义战斗规则本体（WP39–52）、设施会话（WP55／56）或存档系统（WP09）；不承诺跨版本／跨实现重放等价（同种子或同记录数组都不构成保证）。

可见流程（设施单场）：按挑战规则创建**可记录**战斗对象（战斗类型号决定记录的类型字段：0塔式／1Palace／2Arena）→ 战斗开始写入初始条件 → 每命令阶段追加一轮槽位，行动登记／随机／换人询问按发生时点追加 → 战斗结束时导出字节串；单场包装只在**胜／负／平**时把它放入临时字段，否则清空 → 由事件入口把临时记录提升为全局“上次战斗”（随存档保存）→ 回放入口反序列化并按类型分派重演；调试可用数字选择一个 `Battles/Battle###.dat` 文件回放。

入口现状：记录提升与回放入口在脚本内**没有调用者**（由地图事件驱动；事件缺失即U01）；调试回放入口独立于正常流程。回放不写回任何记录。

## 2. 记录生命周期与持久化（B）

两个记录存放处：

| 存放处 | 属性 | 写入／清空时机 |
| --- | --- | --- |
| 临时记录 | 游戏临时状态字段（不随存档） | 单场包装结束时：**先清空**；仅当决定∈{1胜、2负、5平}时写入导出字节串。调试按住Ctrl跳过战斗同样先清空后返回“胜利” |
| 全局“上次战斗” | 全局元数据字段（随存档保存；默认空） | 仅由提升入口写入：把临时记录移入全局并把临时置空。不提升则临时记录不持久 |

生命周期状态：`未开始 → 记录中（战斗对象内，不对外可见）→ 已导出（临时字段，通常仅存活到下一次战斗或被提升）→ 已提升（全局字段，跨存档保存）`。回放不改变任何记录；回放结束即退出。

各终局对临时记录的处理（单场包装，2026-09-29静态）：

| 决定 | 含义（WP42） | 临时记录 | 备注 |
| --- | --- | --- | --- |
| 1／2／5 | 胜／负／平 | 写入导出字节串 | 平局同样保留 |
| 3 | 逃离／弃权 | 清空 | 包装随即使玩家可弃权（设施训练家战） |
| 4 | 捕获终结 | 清空 | 本接入为训练家战，不可达 |
| 0 | 未决／中止 | 清空 | 含调试跳过（先给“SKIPPING BATTLE…”等提示） |

导出字节串是运行时序列化的不透明数据（**无显式格式版本号**）；其内部分量按§3以语义列出。记录的对象图包含队伍成员快照与物品对象等运行时对象，兼容性依赖实现内部结构（未决保留）。

## 3. 初始条件字段与记录结构（C）

记录五元组：`[战斗类型号, 初始条件属性包, 轮次表, 随机序列, 换人序列]`。

初始条件属性包（于战斗开始、在正常开始流程之前写入；值一律按当时的副本／序列化快照读取，训练家与队伍被**去引用**）：

| 键 | 记录内容 | 备注 |
| --- | --- | --- |
| internalBattle | 内部战斗标志 | 本接入恒假：设施战物品菜单被拒、对训练家可由确认弃权 |
| player | 玩家侧训练家快照数组，每项＝[类型, 名字, 编号, 徽章表副本] | 空则记空 |
| opponent | 对手侧训练家快照数组，每项＝[类型, 名字, 编号, 败台词, 胜台词] | 缺失台词以“...”占位 |
| party1／party2 | 双方队伍成员快照（含个体数据） | 去引用副本，回放只动副本 |
| party1starts／party2starts | 双方起始索引表 | 本接入未另行设置，保持初始化默认[0]（普通遭遇路径才由战斗触发流程写入，对照见来源） |
| weather／weatherDuration | 场地天气与剩余时长 | 取自战斗场地现值 |
| canRun | 可逃走许可 | 布尔 |
| switchStyle | 换人风格（系统设置现值） | 布尔 |
| showAnims | 招式动画开关现值 | 布尔 |
| items | 对手侧训练家物品表快照 | 本接入未另行设置，通常记空（普通遭遇路径才写入，对照见来源）；玩家伙伴物品表（ally）**未记录** |
| backdrop／backdropBase | 背景标识与基值 | 初始默认空／空值 |
| time／environment | 战斗时段数值与环境类别 | 初始默认0／无 |
| rules | 战斗规则标志快照 | 条款等（WP54前向） |

轮次表：每个命令阶段一项；每项固定**4席**（按战斗者索引；单打只用前两席）。槽位形式见§4。

随机序列与换人序列：顺序数组，只追加（见§5）。两者无长度上限、无逐项类型校验。

**不记录项（具名）**：Mega进化登记（记录与回放都不会产生登记，回放中Mega不会发生）；换位与呼叫命令（无登记入口，槽位保持空）；玩家伙伴物品表；AI内部状态与评分（回放时不重建AI决策，改由命令槽直接驱动）；背包与货币的真实扣减；随机种子；场景缓冲与演出状态；记录提升入口之外的一切持久化。另：记录战斗把“收服存储”覆盖为**空操作**（收服在设施不可达；完整接收链归WP38／WP62）。

## 4. 命令登记内容与时点（D）

登记以“命令阶段”为节拍：每命令阶段开始时**追加新一轮**（4个空席），进行中的每次成功登记**覆盖**该席当前内容（无追加式历史）。

| 命令 | 写入槽位 | 触发时点与失败／取消 |
| --- | --- | --- |
| 使用招式（正常） | [0, 招式索引] | 资格校验通过才写；校验失败不写。若随后选定目标，目标写入第3位 |
| 使用招式（自动） | [0, -1] | 安可／无可选招等自动入口；该入口**在自动逻辑返回后整体赋值**，先前经自动逻辑内部写入的目标位会被丢弃（具名边界） |
| 使用招式（Palace自动） | [0, 招式索引] 或 [0, -2] | Palace按性格概率与类别自动选招：有该类招式→索引；无该类招式→**-2**（回放按-2映射为挣扎）。该登记语义不做招式资格复检 |
| 物品 | [1, 物品对象, 目标索引, 招式索引] | 登记入口同时从背包扣减（若最终未使用由既有路径回还）；设施接入物品菜单被拒，本槽通常不可达 |
| 换人 | [2, 队伍索引] | 资格校验通过才写；失败不写 |
| 逃跑 | [3, 当时的决定值] | 逃跑尝试入口返回后写入：失败记0；成功记3（该记录随后因决定3被清，不保留）；调试改判时记入所设值。失败逃跑同样终止本轮的其余选招（语义照旧，不属记录） |
| 目标补充 | 既有席位的第3位 | 选靶取消不写；**若无先行走招登记**，写入会产生不完整槽（形如[空,空,目标]），回放不对此分派（具名边界） |

槽位只有上表所列命令族形态（招／物品／换人／逃跑，含自动-1与Palace-2两个哨兵）；未选择、强制动作（多回合招等）、换位、呼叫均为空席。**取消与返回不触发记录清空**——回退重选只会被后续登记覆盖；未被覆盖的旧内容在该轮保留。

时点对照：登记动作发生在命令菜单流程中（玩家侧与AI侧共用同一组登记入口；AI的选招／换人／物品最终也走登记入口）。记录模块不覆盖“撤销／返回”类入口。

## 5. 随机与换人序列、调用域（E）

### 5.1 记录随机入口

普通战斗中，战斗对象的随机入口本身就是全局随机；可记录战斗把它包装为“先取真实随机、再把结果追加入序列”。回放端按序列**依序取用、不重新随机**（WP06§5.3）。

经该入口、**进入记录序列**的域（有界清点：`011_Battle/`内共74处调用行，其中3处在Safari战斗类——该类自定义随机入口、不在本记录机制内；其余**71处分布于20个文件**）：

| 域（代表） | 处数（非定义行） | 说明 |
| --- | --- | --- |
| 攻击合并时的平手顺序 | 1 | 同优先级行动排序的洗牌随机（对回放结果关键） |
| 招式执行（命中、追加效果、状态时长、多段命中、使用计算、招式候选取一） | 43 | UseMoveSuccessChecks 9、MoveEffects_BattlerOther 9、ChangeMoveEffect 5、MoveAttributes 5、MultiHit 3、UsageCalculations 3、Move_Usage 2、Battler_Statuses 2、Battler_UseMove 2、BaseEffects 1、BattlerStats 1、SwitchingActing 1 |
| 随机目标与随机补位 | 3 | 随机选靶2处、随机补位索引1处 |
| 能力／道具触发与选择、回合末 | 21 | AbilityEffects 16、ItemEffects 2、EndOfRoundPhase 2、AbilityAndItem 1 |
| 收服摇晃与接收（机制涵盖） | 3 | 收服在设施不可达；完整捕获归WP38 |
（合计71处。）

**不进入记录序列**的随机：AI随机入口＝全局随机（AI评分噪声、AI选招权重、AI换人与物品倾向、Palace自动选招与Pinch换人概率、逃跑成功率的随机判定）；命令阶段内的“类别判定”分支走全局随机（同一判定的执行期分支才走记录入口）；场景动画与调试场景的随机仅呈现；战斗结束后世界侧检查（如队伍接触传播判定，且其门槛为“内部战斗”标志，本接入为假）不入记录。

### 5.2 换人序列

入口＝换人询问（返回队伍索引或取消-1），写入点由左右双方共用。**接受即入序列（按顺序）**，取消记-1。设施记录实际可达的调用点两类：回合末对手侧补位选择（AI经其补位决策取索引）；回合末玩家侧补位选择（设施为训练家战，走“由属主选择”路径）。另有第三处调用点——单打中“对手补位时询问玩家是否换人”的确认后选择——其门槛含**内部战斗标志**，本接入恒假，故在设施记录中不可达（具名列出以防误当可达来源）。若干具名换出效果以“随机补位”方式选择成员，其索引直接来自随机序列（5.1）。回放时玩家侧补位直接使用记录值，不再打开选择界面。

### 5.3 模式差异

| 方面 | 塔式／普通可记录 | Palace | Arena |
| --- | --- | --- | --- |
| 命令登记 | 通用登记入口（校验≠记录；失败不写） | Palace登记语义：自动选招结果入槽，含-2挣扎哨兵；不做资格复检 | 通用登记入口 |
| 随机使用 | 执行期机制随机入序列；AI与评估期随机不入 | 自动选招与Pinch换人用全局随机（**不入序列**）；结果以槽位快照 | 该类战斗文件内无随机调用（评判与提交为确定性状态机，WP56已述） |
| 回放登记 | 通用 | 按-2映射挣扎，其余同通用 | 通用；评判按状态机照常运行 |

### 5.4 消费、不足与保证边界

回放按序取用随机与换人条目；**数组越界无保护**——取到空值后索引继续递增，偏差从越界点起扩散（不夸大具体下游表现）。随机数量、次序或调用域在不同实现／版本间变化都会改变结果；记录内无格式版本号；因此**不承诺跨版本、跨实现或“同种子”等价**（U05保留；WP06边界不扩大）。

## 6. 回放：恢复、分派、重放、中止与清理（F）

### 6.1 入口与分派

回放入口：给定字节串→为空直接返回（无操作）→建立战斗场景（**标记可中止**）→反序列化五元组→按类型号分派三类回放战斗（0／1／2）→按重建的对手信息取训练家战背景音乐→在战斗动画包裹内运行战斗主体。**未知类型号**会使分派结果为空，随后启动调用将报错（静态具名缺陷；未运行验证）。调试回放：数字选择0–500（取消不播放），读取 `Battles/Battle%03d.dat` 数据文件（二进制读取）后走同一入口；该目录不随仓库提供（U01）。

### 6.2 恢复的内容与方式

重建：双方队伍为记录副本；训练家对象按快照重建（玩家侧含徽章、对手含胜负台词；均为新对象，不引用实时对象）；随后逐项回填初始条件（§3全部键）。**原玩家对象、实时队伍、背包与设置不被回放引用或改写**（回放只重建战斗；不过战斗规则本身允许的实时接触已按§5.1门槛排除）。

### 6.3 重放循环

命令阶段仅由记录驱动：每阶段递增轮次索引；对4席逐一——空席跳过；其余先清空该席选择再按槽分派：使用招式（-1→自动入口；其余含-2→招式登记）；有目标位则补目标；物品／换人按槽再登记；逃跑槽直接把记录的决定值写入。**AI侧命令循环不执行**（双方命令都已含在槽内；无现场AI决策）。记录数组不足或格式不符按5.4处理。

### 6.4 呈现与中止

回放场景为非交互：消息等待自动前进、暂停式显示降为普通显示；半途按取消键触发中止（战斗中止异常→外层捕获→决定置0并结束场景，**不执行正常战斗终局**；注意正常结束时另有普通终局路径——场景结束、退未用物品、离场能力、形态回调与持有物还原记录——回放正常结束会经过它，但设施包装的还原／统计／记录产出不在此路径）。中止或结束都不产出记录、不改实时队伍。

### 6.5 回放不做的设施善后

等级调整还原、双方治疗、Mega／原始回归清除、物品恢复、胜负统计与临时记录产出均为单场包装职责（WP55已述），回放入口**不调用**它们。
