## 4. WP04 修订项

### WP04-R01 [P1] 编译触发与异常清理遗漏执行前提

**位置**：WP04:48–57、86、114–121、163。

**证据**：`S/021_Compiler/001_Compiler.rb:1093–1114` 在异常分支首先重抛 Reset（含按类名识别）与 SystemExit，跳过后续诊断、再次删除及通用异常转换。删除阶段逐文件忽略 SystemCallError，所以“全部文件已被删除”不是保证。另在 PBS 缺失分支中，创建目录、load_all、write_all 位于 `data_files` 建立之前（1044–1051）；这里失败后，清理分支可能面对尚未建立的列表，不能沿用普通编译中失败的完整清理预期。

启动提示也不是独立的无条件编译触发：`S/999_Main/999_Main.rb:28–33` 要求调试、无 Game.rgssad、配置开启，并且用户选择肯定项才设置全量标志。拒绝提示并不否决随后新鲜度等自动条件。

**影响**：错误推断重启/退出或早期失败后的磁盘状态，会掩盖已经重写的文件或清理自身的失败。

**最小修订**：按异常类别及发生阶段写清“原样传播／打印并尝试清理／转 Reset／转通用错误”，删除结果表述为尝试；给早期列表未建立与诊断/清理失败保留边界。无需模拟所有操作系统故障。

**静态验收**：提示开启但用户拒绝，分别有/无 PBS 较新条件；普通编译中异常且列表已建立；编译中 Reset/SystemExit；某文件删除报 SystemCallError；PBS 缺失且 load_all/write_all 在列表建立前失败。逐例说明哪些步骤仍会执行、哪些状态不能保证恢复。

### WP05-R02 [P2] 元数据校验与版本比较采用了注释意图，存在三个反例

**位置**：WP05:73–83、119。

**证据与修正方向**（均在 `005_PluginManager.rb`）：

1. **“1.10 > 1.9”错误**。343–365 行按字符位置转换比较，第三个字符 1 小于 9，因此当前比较结果为 **1.10 < 1.9**。它不是通常的分段数值版本比较。先导点、末尾点及字母的行为也应按实现限定，不能套 SemVer。
2. **缺失键和显式空值不同**。register 的 111–147、254–284 行只遍历提供的键；getPluginOrder 的 538–544 行有其自身检查。不能把文件头的五个“Required lines”直接当成全部强制校验。至少缺 Essentials 会在执行阶段警告，缺 Link/Credits 不等于显式空 Link 报错；区分发现期、解析期、注册期。
3. **“meta.txt 无法表达 optional_exact”错误**。readMeta 的 423–432 行允许 Requires 的第三个分量成为依赖类型；register 的 188–241 行处理 optional_exact。注释 98–100 行不能推翻这条实际入口。

**影响**：错误拒绝可接受元数据、漏记可表达的依赖形式，并使依赖最低版本判断反向。

**最小修订及验收**：补按入口的校验表，并用静态向量核对 1.10/1.9、缺 Link/Credits、缺 Essentials、显式空 Link，以及 Requires 三分量的 optional_exact；区分缺依赖、已装但不满足版本。仅描述固定实现，不改参考比较器。

### WP05-R03 [P2] 回调参数和处理器类型限制不准确，重名规则未闭合

**位置**：WP05:49–57、64–65。

**证据**：`S/003_Game processing/005_Event_Handlers.rb:40–48` 只有回调参数个数大于 2 且与触发参数个数相等时才展开参数；两参数回调仍收到“发送者 + 其余参数数组”，不能只写“个数匹配即完整传参”。`HandlerHashSymbol:154–174,192–195` 没有“仅符号 ID”的注册校验；仅对响应 id 的非符号对象取 id，其他值保留。NamedEvent 的同键赋值（72–74）以及 HandlerHash 的同键赋值（107–112）会替换；菜单也使用后者（`006_Event_HandlerCollections.rb:83–85`）。

## 7. WP07 修订项

### WP07-R01 [P1] GET/POST 和底层/便利包装的协议及异常边界被合并

**位置**：WP07:78–83、105、115、139–140、153。

**证据**：`S/001_Technical/002_Files/003_HTTP_Utilities.rb` 中，仅 POST 第 5 行检查 http 前缀；GET 第 38–50 行直接把 URL 交 HTTPLite.get，不能据 POST 限制断言 GET 不覆盖 https。宿主实际协议支持仍未验证。

**影响**：错误承诺协议拒绝和“无错误传播”，掩盖文件已创建/截断但写入失败的状态。

**最小修订**：按 GET/POST × 基础/ToString/ToFile 分层列出前置过滤、宿主调用、响应形态、非 200、成功写入及写入异常；宿主协议能力保持待证。保留当前包装没有重试循环的静态结论，勿外推宿主内部策略。

**静态验收**：https URL 对 GET 被传给宿主、对当前 POST 被前缀检查挡下；非 Hash 响应原样返回；200 后写文件报错时基础入口传播而 ToFile 捕获；非 200 不写文件；不能把成功空正文当成可区分的失败诊断。无需真实网络或写盘实验。

### WP07-R02 [P2] 文件包装的捕获集合、返回形态及归档分支并不统一

**位置**：WP07:51–57、63、104、115。

**证据**：`S/001_Technical/002_Files/001_FileTests.rb:315–332` 的 pbGetFileChar 捕获 EISDIR；pbGetFileString 的 344–360 行没有捕获该异常，不能填“同上”。若它发生，后者不会由本函数归一成 nil。非归档 Char 读一个字节，归档分支则直接返回宿主原始读取结果；该差异无需有实际归档包才能静态辨认。

pbRgssOpen 的非归档分支（292–300）直接打开原输入，只有归档分支先 canonicalize（302）；RTP.eachPath（238–242）始终产出本地根路径，没有按 Game.rgssad 切换的分支。归档行为在其他入口中，不能嫁接到 eachPath。

**影响**：按现表会错误期待 nil 或统一路径处理，错误归属资源查找与宿主归档读取的责任。

**最小修订及验收**：逐入口列准确的捕获集合、普通/归档分支与返回形态；区分“源码看得到的分支”与“宿主运行未验证”。以同一个 EISDIR 异常到达两个读取入口为反例，再检查普通文件和归档路径，不执行参考读取函数。

### WP07-R03 [P2] 将诊断函数能力扩大为所有模式下的全局异常保证

**位置**：WP07:89–92、98、108、115、142；与 WP04 异常清理交界相关。

**证据**：`S/999_Main/999_Main.rb:16–21` 仅在调试模式将主流程包进 pbCriticalCode；非调试主流程直接调用，43–46 行专门处理 Hangup 并紧急保存。不能从 `pbPrintException` 的存在推出“任意未捕获异常都会追加日志并打印”的全模式保证。

**最小修订及验收**：分开格式化函数、显式调用它的业务入口、调试主流程包装、非调试 Hangup 分支和宿主未知行为；区分 EventScriptError 格式及日志写入失败。静态场景覆盖调试普通异常、非调试普通异常、Hangup、Reset/SystemExit 和日志写入失败；不猜测源码外宿主会怎样显示。
