## 1. 目的、范围与非目标

**目的**：描述作者输入（PBS 文本）到运行数据（.dat）的可见生命周期——什么时候触发编译、哪些输入被发现、按什么顺序编译、产物如何生效、哪些材料会被写回/删除/覆盖、失败时可能已经发生了什么。后续包据此判断"某数据何时生效、失败可能留下什么状态"，而不是各自重新追踪编译器。

**范围**（WP04 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP04-A：编译触发（触发条件、调试前提、新鲜度检查）。
2. WP04-B：输入发现与编译顺序（普通发现、专用入口、调度顺序）。
3. WP04-C：编译产物与写回行为（.dat、PBS 写回、MapInfos、地图事件、动画、全量反写）。
4. WP04-D：失败与部分状态（非原子性、删除行为、异常路径、错误定位、恢复条件）。
5. WP04-E：边界与交界（WP08 文本、WP73 编辑、WP75 转换、WP15 资源）。
6. F02-02、F02-03 中属于 WP04 部分的状态更新。

**非目标**：

- 不展开 schema 类型模式全集与字段语义（WP03 已登记锚点，字段归领域包）。
- 不提取文本提取/翻译流程（WP08）、编辑器行为（WP73）、事件简写转换规则全集（WP75）。
- 不验证任何编译运行的真实结果；不运行编译器、游戏或参考脚本，不修改 `reference/`。
- 不把候选 PBS 材料当作已支持变体（延续 WP01-R03/WP02 限定）。

## 2. 概念与术语

- **编译**：把作者文本内容转换成运行用序列化数据（.dat）的过程；本包特指参考实现的调试模式编译检查流程。
- **写回**：编译过程中对输入或工程材料的修改（PBS 文本改写、地图事件转换、MapInfos 登记、动画映射保存）。
- **新鲜度检查**：比较数据文件与 PBS 文件的修改时间以决定是否编译。
- **必选/可选数据文件**：缺失时是否触发调试模式的重编译判定（可选仅 ShadowPokemon，见 WP03）。
- **普通发现 / 专用入口**：顶层自动匹配的输入与按字段显式指定的输入（如设施名单引用）。
- **全量反写（write_all）**：PBS 目录缺失时，从当前数据覆盖式重建全部 PBS 文件的过程。
- 影响域编号 Dxx 见 module-map；证据状态五档定义见总览第 7 节。

## 3. WP04-A：编译触发

### 3.1 触发条件与调试前提（本轮逐行核实 `001_Compiler.rb:1039–1116`）

编译检查**仅在调试模式执行**（非调试直接返回，不存在普通运行的自动修复）。启动顺序：核心消息 → 插件 → 编译检查 → 游戏初始化（WP03 已登记）。满足任一条件即判定编译（mustCompile）：

| 触发条件 | 行为 | 证据 |
| --- | --- | --- |
| PBS 目录缺失 | 先创建目录、从当前数据**全量反写**全部 PBS，再判定编译 | 1044–1049 行 |
| 新地图导入 | 扫描 `Data/Map*.rxdata`，未在 MapInfos 登记的地图（**ID 999 地牢图除外**）自动登记并保存 MapInfos；有导入即判定编译 | 1061 行；`004_Compiler_MapsAndEvents.rb:45–83` |
| 必选数据文件缺失或不可读 | 判定编译（可选文件缺失不触发） | 1063–1075 行；必选清单见 WP03 第 4.2 节 |
| PBS 较新 | 任一被发现的 PBS 修改时间 ≥ 全部数据文件最新修改时间即判定编译 | 1077–1088 行 |
| 全量编译标志或按住 Ctrl | 直接判定编译 | 1090–1091 行 |
| 启动提示（配置） | `PROMPT_TO_COMPILE = true` 时启动先询问是否编译（默认 false 不问） | `999_Main/999_Main.rb:28–33`；WP02 词典 |

判定后进入编译（compile_all），见第 4 节。

## 4. WP04-B：输入发现与编译顺序

### 4.1 输入发现（引用主规格）

- **普通发现**：顶层 `*.txt` 按"完全基名或基名+下划线"匹配到数据类，最长基名优先，不递归子目录（WP02 第 6.1 节主规格，本文引用）。
- **专用显式入口**：设施名单 `battle_facility_lists.txt` 的 Trainers/Pokemon 字段显式指定输入文件（当前样本 10 个路径，WP02 第 6.1 节主规格）；不能据普通发现不递归就断言专用路径不访问子路径。
- **候选材料**：备份子目录不被普通发现扫描，也无自动切换机制（WP02 第 6.2 节主规格）；本包不新增切换办法。

### 4.2 编译调度顺序（`001_Compiler.rb:1020–1037`）

compile_all 的可见阶段：

1. `compile_pbs_files`：先执行**编译前 PBS 改写**（见 5.2），再按 22 项内容编译调用（TownMap、Connection、Type、Ability、Move、Item、BerryPlant、Species、Forms、Metrics、Shadow、RegionalDex、Ribbon、Encounter、TrainerType、Trainer、TrainerLists、Metadata、MapMetadata、DungeonTileset、DungeonParameters、PhoneMessage）逐类编译并保存对应 .dat。调用先后是调度顺序，不等于内容依赖关系（WP02 第 6.1 节）。
2. `compile_animations`：建立招式名到动画的映射（见 5.4）。
3. `compile_trainer_events`：地图/公共事件转换（见 5.3）。
4. 文本收集与消息保存（`Translator.gather_script_and_event_texts`、`MessageTypes.save_default_messages`、再载入核心消息）——文本生命周期交界归 WP08。

每类编译的行为（逐节解析、字段求值、条目级校验、全量终检、重复处理）按 WP03 第 5 节主规格引用，本文不重复定义。

## 5. WP04-C：编译产物与写回行为

**编译会修改材料，不是只读转换。** 当前快照可见的写回面：

### 5.1 数据文件（.dat）

- 判定编译后、编译开始前：**删除**全部列出数据文件（删除错误忽略）（1093–1100 行）。
- 编译中逐类保存新 .dat（各编译函数末尾的 save）。
- 动画映射有变化时保存 `move2anim.dat` 与 `PkmnAnimations.rxdata`。

### 5.2 PBS 文本改写（编译前）

`modify_pbs_file_contents_before_compiling`（940–947 行）对两处旧属性名自动改名：`PBS/trainer_types.txt` 的 `VictoryME` → `VictoryBGM`，`PBS/moves.txt` 的 `BaseDamage` → `Power`。机制（924–938 行）：整文件读入，有变化才整体重写并提示"Changes made to file X"。

### 5.3 地图与事件转换（`compile_trainer_events`，1683–1750 行）

- 对**全部地图**的每个事件尝试：训练家注释转换（`Battle:`/`Type:`/`Name:` 等注释编译为正式训练家事件，473–512 行）、道具事件转换（`item:X`/`hiddenitem:X` 命名转为道具球事件，771–800 行；**道具不存在则跳过不转换，也不报错**）、事件名与脚本修正、计数检查；任一变化即保存该地图与 tilesets，并逐条警告"Map X was modified and saved"。
- 公共事件做 `fix_event_use` 修正，有变化才保存。
- 有任何修改时警告"RMXP data was altered. Close RMXP now to ensure changes are applied."。
- 转换规则全集归 WP75；本包只登记"编译会写回地图/公共事件"的事实与边界。

### 5.4 动画映射（`compile_animations`，1274–1319 行）

- 读取 `PkmnAnimations.rxdata`（**读取失败则新建空动画集**）。
- 扫描名为 `Move:X` / `OppMove:X` 的动画，仅当招式 X 已定义时建立映射；有变化才保存 `move2anim.dat` 与 `PkmnAnimations.rxdata`。

### 5.5 全量反写（write_all，仅 PBS 目录缺失时）

从当前数据覆盖式重建全部 PBS 文件（21 个 write_* 调用，`003_Compiler_WritePBS.rb:794–820`）：按 `pbs_file_suffix` 分文件，写 BOM 头与 `[节名]` + `键 = 值`（值经 `pbWriteCsvRecord` 转换，枚举只查已有名称，WP03 第 5.2 节）。随后正常进入触发与编译流程（相当于 .dat → PBS → 删除 .dat → 从 PBS 重新编译的往返）。

## 6. WP04-D：失败与部分状态

**不能默认原子性或自动恢复。**

| 阶段 | 可能已发生的变化 |
| --- | --- |
| 编译前 | 全部列出数据文件已被删除（1093–1100 行） |
| 编译中 | 部分 .dat 已重写；PBS 可能已被改名改写（5.2）；MapInfos 可能已登记新地图（3.1）；地图/公共事件可能已转换保存（5.3）；动画映射可能已保存（5.4） |
| 异常时 | 打印异常后**再次删除**全部列出数据文件；Hangup 转为 Reset，其他异常转为"Unknown exception when compiling."（1103–1114 行） |
| 失败后 | 可能存在：缺失的数据文件、部分编译的 .dat、已改写的 PBS/地图/MapInfos/动画。下次调试启动时，缺失的必选文件再次触发重编译（3.1），但**不保证**上次失败留下的部分状态被识别或修复 |

错误定位：编译错误附 `FileLineData` 位置报告（文件/节/键/行号），由 `FileLineData.clear` 在 compile_all 开始时重置（`001_Compiler.rb:12–40, 1027`）。

## 8. 默认行为与配置变体

- **基线默认**：调试模式自动检查编译；`PROMPT_TO_COMPILE = false`（启动不询问）；Ctrl 可强制；PBS 缺失自动从数据全量反写再编译。
- **支持但未默认启用**：`PROMPT_TO_COMPILE = true` 启动询问；`$full_compile` 外部强制标志。
- **配置/数据关联**：`MECHANICS_GENERATION` 与数据集的组合边界（U03）、可选 Shadow 数据的启用（U06）保持开放，归 WP02/WP23/WP79。
- **未验证组合**：完整失败分支、全部转换规则组合、无 PBS 往返的真实结果、插件对编译的影响（U09）。
- 参考快照行为、官方版本预期、未来目标分开标记；本包只记录第一类。
