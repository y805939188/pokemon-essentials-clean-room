# 可移植规则 · 一次性奖励包

本页描述一种独立实现的领取方式。作者把一组成员、背包道具和金钱登记在同一个奖励标识下。领取记录属于当前存档；两份分别开始的新游戏可以各领一次。以下顺序及案例来自独立实现的静态检查，本次未运行。参考版本的普通赠送、静默赠送、脚本交换及捕获另见[获得、赠送与脚本交换](acquisition-gifts-and-script-trade.md)和[捕获与接收](capture-and-receiving.md)。

## 作者输入

奖励表可省略，省略时可领取的作者奖励为空，旧内容的输入身份保持原值。每条记录包含唯一标识、成员列表、道具数量、金额及已登记的来源。此格式中的标识长 1–12 个字符，以小写英文字母开头，随后可用小写字母、数字或连字符。若同一标识出现两次，第二条记录的标识字段报错。未知字段和空奖励也在内容检查阶段拒绝。

- 成员列表最多六个，按声明顺序给出已登记物种及 1–100 的整数等级。显式形态必须有对应的确切内容形态或该基础物种支持的创建形态。可选持物须合法、已登记且可持有，带持物的来源还需相应许可。
- 背包道具以已登记的道具标识和正整数数量给出，数量上限为 9,007,199,254,740,991。金额为 0–999,999 的整数，实际取得的金额还取决于当前余额及其上限。
- 普通、静默、仅入队和外来赠送是独立的运行时请求，可以接收一个新建或已有的成员；作者输入表未定义一份单独的赠送事件文件。一个奖励定义也不说明 NPC、地图或脚本会在何时发起领取。

## 存档身份与入口顺序

同一奖励正在等待接收时，再次领取返回同一操作标记；有其他互斥操作时拒绝开始新的领取。入口可用后先读取存档。读取失败返回存档不可用。已有同名领取记录时立即返回已领取，无须再访问内容或随机源。其余请求先要求随机源，再查奖励定义；因此仅给钱或道具的奖励也要求随机源可用，但不为创建成员取数。缺少定义返回未知奖励。若成员带持物，入口在生成成员之前检查来源许可、当前道具可持有且不属于邮件。

奖励标识和成员标识分开。领取表只认存档中实际登记的键，冷读后仍然如此。进入此规则前，使用旧格式的存档须先迁移；引入领取表的旧档迁移建立空表。成员使用存档中的下一个正序号，写作 `M` 加该数的三十六进制小写表示，跳过队伍或盒内已占的标识。序号分配不消耗创建随机数。超过 18 字符的成员标识空间停止分配。复制同一时点的存档会复制当时的领取记录；其他时间线不会因此获得一条记录。

## 生成模板与容量预检

在一份临时状态中按声明顺序为每个成员分配标识，先查队伍空位，再查盒容量。有位置才生成这个成员，设当前玩家为拥有者，写入种类及形态、明确的持物和首招列表，暂时安放并计算图鉴登记。无位置或创建失败时整包不进入已安装状态。一个已创建成员的随机抽取仍然发生，即使后面的成员无空位或背包放不下道具。

创建从两次范围 0–65,535 的取数得到个人识别值，再分别在 0–31 内取 HP、攻击、防御、特攻、特防和速度个体值。依物种及上下文可能另有创建形态取数；每次返回均需为范围内整数。临时状态随后试放全部道具，检查余额加金额是否仍是安全整数，按货币上限钳制，并形成临时领取记录。这些试算尚未授予玩家任何东西；进入等待状态的成员模板则保留个人识别值、个体值、形态、招式及持物。

模板预检结束后才建立本次接收操作。已有 32 条尚未确认的接收通知时，新的接收会被拒绝。若通知数量允许，接着检查接收配置：放置模式须为 0、1 或 2，命名模式须为非负安全整数。这两种拒绝均未安装奖励，但此前已为模板取用的随机数仍然消耗。接收通知可由界面中断或重建失败后的恢复操作留下，确认相应通知会释放其名额。

实际接收批次从临时结果中筛去领取前已在存档内的成员后，先按队伍顺序、再按盒号和槽位顺序枚举新成员。预检放盒时先找当前盒，再找其余盒的首个空位。跨盒时，后续接收的成员顺序可能与创建顺序不同。

## 收集决定并安装奖励

在模板已准备好、完整安装结果尚未形成时，继续操作要重新读取当前存档和内容。若当前存档已经登记该奖，返回已领取。否则按接收批次的顺序处理命名与放置。等待命名、满队时的位置或替换对象时，返回操作标记和待选成员；先前收集的决定与模板可继续使用。只决定一部分成员不会把他们写进存档。满队自动寄存、要求选择、强制入队替换及盒容量各按接收模式判定。合法替换先把移出的成员寄存、压紧队伍，再把新成员追加至队尾。

在当前状态上形成完整安装结果时，依次计算成员放置、背包道具、金额、图鉴、领取记录和下一个成员序号。图鉴按最终成员的持久种类、实际外观和登记条件更新已见与持有，入盒成员同样登记，赠送不会记为一次捕获。返回的金额为钳制后的实际差额。安装前验证完整结果，保留决定和图鉴呈现请求。所有持久变化随同一次安装，确认后才启动适用的图鉴呈现，并在恢复过接收界面时留下放置通知。若图鉴后续仍占用入口，应先完成它，再次领取同奖才会读到已领取记录。先前的模板预检不直接写队伍、盒子、道具、金钱、图鉴或领取表。

## 重试、读回与冷读

写入前绑定原状态、完整目标状态及对应的内容定义。完整目标一旦形成，更改已收集的决定会被拒绝。等待接收期间常规保存被阻止。处理存储异常时，按实际读回的结果分支。

| 存储观察 | 领取结果 |
| --- | --- |
| 写前失败，或写入返回后仍为原状态 | 保持等待。可用同一标记和相同决定重试既定目标，不重抽、不再添加一次道具。确认未安装时也可终止。 |
| 已经是完整目标，即使写入曾抛错 | 确认成功，不重复写入。若上次写后的读回失败，恢复读取后可先确认目标，哪怕内容此时暂不可用。 |
| 已尝试写入，但暂时无法读回或读到既非原状态也非完整目标的第三种状态 | 保持待确认。终止时仍无法读回或证实是第三种状态，要求重新载入；不会覆盖或自动退还。 |
| 第一次尝试写入之前已出现第三种状态 | 安装停止，保留现场。此操作尚未写入，技术终止可释放它，保留其他操作已写的状态。 |
| 仍为原状态，但比较时发现整组内容的语义值发生变化，即使奖励定义本身未改 | 旧计划失效。定义随后改回也不会使这次计划重新有效；可在证明未安装后结束旧操作。 |

重新启动后，从已保存的队伍、盒子、背包、金额、图鉴及领取表恢复结果。已持久登记的标识再次领取会返回已领取，既无写入也无创建取数。未安装的模板、交互标记及其决定属于当前会话。宿主把已保存的状态重新载入时，上一代接收和回执被清除。在开始新的接收前继续旧标记会被拒绝。若奖励尚未领取，重新发起会使用当时的状态和随机源。
