# 按作者配置选择训练家策略

**可选独立实现规则。** 本页适用于支持策略配置的单打训练家战斗。参考版本的选招与技能等级见[原版 AI 行动选择](ai-action-selection-and-skill.md)。基础策略的多属性计算见[独立实现的属性倍率](portable-ai-type-effectiveness.md)。

## 建立战斗时选用哪一份配置

训练家记录和训练家类型可以分别给出一份策略引用，包含策略标识、可选的策略版本和完整的参数对象。引用只携带纯数据。此配置中，整份引用深度最多为 8（根为 0），紧凑 JSON 编码最多为 8,192 个 UTF-8 字节。可执行值、非有限数、循环、稀疏数组和访问器均被拒绝。读取引用不会求值访问器。

1. 优先选训练家记录的完整引用。记录缺省时选训练家类型的完整引用。两者均缺省时选内置基础策略 `basic-gen8` 的版本 `1`，参数为空对象。各层参数不合并。例如记录明确选基础策略时，类型的选槽参数不会传给它。
2. 策略须事先登记。显式版本精确匹配；省略版本时选该标识当时的活动版本。训练家记录自身的版本与策略版本分别解释。未知标识、没有匹配版本或参数不符合所选策略时，建立战斗失败，策略调用数为零。
3. 建立战斗时固定实际策略、参数和适用内容目录。切换活动版本只影响随后建立的战斗。

## 一次选择的输入和结果

策略可以读取本次决策的请求身份、己方队伍与可用资源、对手前台公开的显示身份、血条和已揭示招式/特性/持物、场地和合法候选。对手未公开的选择和隐藏信息不会随请求提供。策略看到只读快照及参数，不能经这些输入改写战斗。提供给策略的随机输入只消费 AI 随机序列；本次决策结束后不能再通过它抽取。等待或结束的请求跳过策略。

选招请求允许其列出的招式或道具，强制替换请求允许其列出的替补。返回的选择必须关联当前请求。重试序列非空，所有候选均合法且不重复，首项等于首选。提交前还须核对当前请求及候选资格。

正常调度先按策略给出的顺序尝试候选，再按请求原顺序补试其余合法招式或强制替换成员。两组重叠时每项最多试一次，未列入策略的道具不会自动补上。每次尝试前记录完整战斗引擎快照。只有提交明确返回拒绝，且能证明尝试前后的完整快照完全相同，才可继续。接受一个候选即完成请求；所有候选都满足上述无副作用的拒绝条件才报告耗尽。即使没有动作被接受，若快照已变、无法核实快照相同或提交抛错，也要停止，不再尝试其余候选。已经产生行动后才返回拒绝或抛错，同样停止。存在自动动作的请求只尝试其自动候选。已提交请求再次送入调度会被拒绝。

| 情况 | 可观察结果 |
| --- | --- |
| 建立战斗时作者配置无效 | 拒绝建立，不转用基础策略。 |
| 决策前收集的公开状态无效 | 在调用策略、抽取 AI 随机数或提交行动前拒绝。 |
| 策略返回非法意图 | 严格检查返回错误，零行动。通常调度若仍拥有同一有效请求，可放弃失败策略的随机进度，尝试第一个合法招式或强制替换的第一个合法成员。缺少这样的候选则拒绝。 |
| 提交前请求或资源修订变化 | 若仍是同一请求，可以重新采集一次；再次变化时拒绝。先前的候选不会因此取得新请求的资格。 |
