# 运行能力与诊断分级

**独立实现规则 · V1-11**　WP05／WP07／WP72／WP77

原版的[诊断能力与调用前提](diagnostics-files-http.md)及[调试入口](../authoring/debug-contexts-and-controls.md)不变。独立实现按以下边界验收：

- 普通及发布运行不共享测试能力。仅传调试标志、设置测试数据参数或触发遗留事件，不能授予能力。入口与实际执行端均应拒绝；拒绝发生在加载测试数据、清状态、替换或推进会话、写结果变量、保存等副作用之前。用正常生产流程和明确获授权的隔离测试做正控，不把「删掉测试文件后报错」当通过。
- 面向玩家的错误使用稳定类别和固定提示，不拼入本机路径、堆栈、原始输入或玩家资料，不因正式内容不可用回落到合成数据。标志本身不授予详细诊断；明确获授权且隔离条件实际成立时，可给固定字段名、提示和可信的位置；不能确定的定位留空。适用范围应列出具体入口，不把局部检查宣称为全局日志保证。
- 验收对比拒绝前后相关状态及保存目的，包括自动、手动与测试专用位置等实际适用的目的。隔离授权的正控只证明其具备能力，不替代发布产物的拒绝验证。

静态验收用例见[可移植向量](../../vectors/portable.json)。对应编号为 V1-11-A, V1-11-B, V1-11-C, V1-11-D。
