# 操作归属与战斗结算来源

本页记录公开独立框架可复用的两组行为。下列用例是有前提的静态预期。参考游戏的[存档与新游戏](save-startup-continue.md)、[队伍与仓库](../creatures/party-and-storage.md)、[捕获接收](../creatures/capture-and-receiving.md)及[战斗终局](../battle/growth-end-of-round-and-battle-outcomes.md)各有独立规则。

## 操作归属、保存与时间线替换

一次操作属于发起它的应用和当前游戏时间线。应用先为相互冲突的操作保留位置，再读取会回调的状态或内容、创建战斗或开始学习。重入或迟到的结果不能借用另一操作的位置。同名战斗、相同队伍内容、公开的操作编号或选择编号均不足以创建归属。只读查询不赋予提交、取消或释放操作的资格。

| 当前操作或阶段 | 新遭遇 | 保存条件及可继续的操作 |
| --- | --- | --- |
| 无其他阻挡的队伍管理、单纯浏览背包或商店 | 拒绝准备新遭遇 | 可以保存。管理会话可把一项操作交给一个子操作。 |
| 管理中拿起成员待放置，或已有道具、学习、摘要图鉴子操作 | 拒绝 | 阻止保存。子操作存在时，父操作不能结束或修改成员以绕过它。道具子操作需当前管理资格和此时仍在队伍中的成员身份。 |
| 库存入口正在建立、正在处理道具子操作、待确认使用或丢弃、已有学习子操作 | 拒绝 | 阻止保存。商店只接受商店操作。结束子操作仅归还其所占用的父操作位置。 |
| 战斗准备、战斗、接收决定、战后进化或图鉴后续阶段 | 拒绝 | 阻止保存。合法后续仍属原战斗或接收操作。主体已安装后，显示失败或重复完成不会再安装一次。 |
| 学习、道具或事件进化、交换、领取、独立图鉴及其活动后续阶段 | 拒绝 | 在有关阶段阻止保存。普通学习可独立开始或由管理发起；机器教学须来自当前库存操作的教学请求。道具进化核对库存父操作和成员，事件进化从空闲开始。交换中的进化或学习属于交换草案。摘要图鉴要求当前管理操作和成员。 |
| 亲密度迁移正在异步准备或确认，或写入结果尚无法确认 | 拒绝 | 活动期间阻止保存和状态替换。应用准备成功并返回预览后释放本次异步占用。若宿主仍显示迁移的确认或取消选项，该宿主会继续阻止普通保存、载入替换及第二次预览，直至用户回应。不确定的持久化或提交后的状态安装仍未验证时，保留屏障。 |

两种门分别判断。战斗相关活动、受控接收、其他独占业务、活动中的世界操作或相关写入也可能阻止保存及新遭遇。遭遇阻挡在检查遭遇表、抽取随机数之前生效。普通治疗、领取、管理或直接提交结果不能绕过已有根操作。一次替换成功前发生的已提交写入，依该入口本身的规则处理。

在同一库存会话中，同一请求身份和相同语义只执行一次，字段排列不构成新请求。重用身份并改变内容会被拒绝。已证明没有安装的失败可以用原请求重试；安装后呈现失败保留已提交结果。仅改变游标不会使资源选择过期；移除物品再加回相同数量会使旧槽选择失效。该实例每次库存会话保留至多 256 条请求结果；满额后仍能识别已有请求、结束会话。它们不写进游戏存档。

新游戏是显式替换时间线的入口。没有亲密度迁移占用时，即使管理中的学习尚未完成，也可用合法的新游戏输入替换。此实例需要随机来源生成训练家身份及已验证的区域图鉴布局，按设置建立含空队伍的新状态；先安装，成功后才递增代次、清除原操作和待接收通知、退休旧会话。缺少所需输入时不进入该安装。宿主读档替换先检查是否允许，再安装并通知应用。先前战斗完成、取消或清理若晚到，在读取旧结果、呈现或改状态之前拒绝，不能代替后来会话释放其子操作。普通保存屏障与显式时间线替换的准入条件分别验证。有关战后安装、回程和保存的独立规则见 [V1-03](../world/portable-defeat-return-and-saving.md)。

## 正式战斗结算的生产者资格

基础战斗能力可创建会话、执行选择并给出战斗结果。首次把战斗结果安装到持久状态时，应用还须在创建会话前选定可接受的生产者，记录本应用、战斗操作、代次及返回会话的对应关系。外部结果文本、公开支持标志、接口形状、转调同一引擎的包装器，均不能自行改成正式结算来源。训练家决策和可选换人的资格也须各自建立。

| 结算模式 | 首次安装的前提 | 失败、恢复与重试 |
| --- | --- | --- |
| 完整持物及金钱结算 | 来源经过授权；结算事实属于同一战斗、代次、已验证内容和原始结果，成员与起始阵容相符。即使双方开局均无持物，仍需完整事实。新捕获者持物来自该对象的当前状态。 | 来源未知、已退休、内容改变、缺事实或配对不符时拒绝。缺失的事实不能按空物品处理，也不自动转入旧模式。只有原会话的恢复点及同源结算轨迹可恢复已封存事实。 |
| 显式选择的无持物兼容结算 | 预先选择无持物生产者。启用持物来源或实验持物、入场时任一方携物，或写回时当前队伍或新捕获者有持物，均拒绝。同步旧结果入口还须和预先选择的生产者给出的同场结果相等。 | 合法无持物战斗可安装一次，不产生完整结算的配对记录。普通未知来源不能因双方空手而获准写入。 |
| 查询已安装的结果 | 战斗身份及原始结果与已有记录一致。合法冷读后，应用空闲且无败北回程阻挡时，可通过无会话的直接结果入口查询精确重复；此时不用取得当前内容、捕获模板或新结算来源。若由新的正式会话查询已有完整配对，则需核实自己的配对事实；已认证的原会话可使用原配对。 | 精确重复返回已安装，不再次发奖或安装；同一身份却给出不同结果、或两个已核定配对冲突时拒绝。若之前安装未获确认，须核对完整目标状态；仍不一致时保留未决状态。旧记录不能凭空补出正式来源。 |

这些规则约束可观察的操作归属、当前性、配对和安装效果。实现可自行选择表示方式。新旧持物来源的分配与重复消费另见 [V1-02](../battle/portable-capture-held-items.md)。恢复点的行为限于同一会话下的受控恢复；游戏存档不承载这种资格。对应输入与预期见[独立框架静态用例](../../vectors/portable-framework-cases.json)，编号前缀为 OWNER 和 SETTLEMENT。
