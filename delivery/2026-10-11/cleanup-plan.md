# 重复材料和分支整理候选

本次整理解决入口与阶段导航，**未删除任何文件或分支**。正式规格、原稿、公共关闭账、原始交接、两次 FINAL、229 原／批准控制及 341 scoped 来源必须保留；旧会话私有封存包不进入仓库，也不要求上传。

[cleanup-inventory.json](cleanup-inventory.json) 以本次固定 Git 树统计相同 blob 的路径复用、历史快照占用、远端 213 个分支的精确 tip。它只作存储／导航整理依据，不声称全文读过各历史快照；相同 blob 本身不能证明某个审批路径可以删除。Git 对象库已经按 blob 共享，估算可减少的是工作树重复展开，不能称为同额远端存储节省。

可在后续可恢复整理中处理的候选包括：

- `review/**/input-snapshot/**`、`review/**/snapshot/**` 中同一 blob 的反复或嵌套复制。先把必要身份引用改为固定原 commit/path/blob 的历史导航，再从新的整理提交中移除当前重复副本；保留原提交和可达历史，禁止删原始唯一载荷。
- 同一冻结差异在多个旧复审包中重复保存的副本。仅在证明全文身份相同、消费者已改为唯一固定差异身份后减少当前树副本；当前 FINAL-2 的完整 C→最终差异单份保留。
- 仅作为旧阶段入口、其 tip 已在交付历史可达的工作分支，可在 main 合入且远端回执保留后归档或退休。清单提供已确认祖先的候选和相同 tip 组，不提前删除；main、交付分支、原交接，以及仍承载唯一作者／独立报告／授权证据的分支保留。

不立即处理：独立审查的唯一报告、未确认可达的分支、未消费／未读的参考样本、备份与资源文件、历史异常证据、原控制字段。未知价值不等于垃圾。不会为清理启动全历史语义复审；存在具体引用风险时定点检查对应消费者即可。

后续删除当前重复路径应以普通新提交保留历史，并附精确删除清单、替代固定入口和保全检查；不重写 Git 历史、不 GC／prune、不 force，不做不可恢复删除。本轮交付不依赖完成这些候选清理。
