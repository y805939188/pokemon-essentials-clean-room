状态：**Reviewed（限定静态范围，2026-09-28独立首审PASS_SCOPED；管理性回填）**。范围A～F：成员/输入队伍/可选子集/最终参赛队伍判断，默认杯赛组合、临时等级和还原接点、战斗条款。2026-09-28；F13-03，Combat Requirements／Creature-RPG／Pokémon Rules／User Interface。基线 `8c5911e4a4b07b07e832e4bb0d5d8859e88b4a9b`，只读文本；没有运行报名、战斗、生成器、事件或解释器。通过仅限该静态范围，设施完整会话、租借、回放与运行不随之通过。

## 1. 目的、可见流程与状态边界（A）

本包回答哪些成员/组合可以进入比赛、玩家如何选定参赛顺序、资格与等级调整在哪一步发生、战斗条款在哪个阶段生效。它不设计规则对象/API或未来继承层级。源码名只用于审计定位，不能从“杯赛”“子集”名称推断官方赛事规则。

输入是有序个体集合、候选身份/蛋/HP/等级经验/物品/招式/种族形态数据、作者选择的成员与组合条件、人数范围、调整策略、布局与条款，以及配置当前最大队伍6、最大等级100。输出是布尔资格、首个拒绝原因、按选择顺序的成员引用列表或取消空结果、建议数量/等级、临时等级/经验/能力值变化与旧经验记录、战斗规则布尔值与具名结果写入。资格查询通常不改个体，但婴儿/可进化与名字查询有缓存，不能称所有判断完全无状态。

可见报名入口先检查有没有可选合法队伍，成员逐个显示可报名/不可报名；选入后显示次序，可取消选入、看摘要、确认或退出。确认再检所选列表整体，不因每个成员标可选就承诺组合合法。战斗包装在开战前另恢复玩家队伍、按调整策略改等级；资格和调整不是同一步。完整设施轮次/报名收费/保存中断/胜场和租借/录像归WP55/57/58，本包只闭合真实直接字段和调用顺序；缺Demo事件不补造费用奖品。

## 2. 四类资格与数量、组合语义（A/B）

### 2.1 数量与规则组合

原始新规则集默认最少1、原始最大数0；原始最大数<0时公开最大长度用MAX_PARTY_SIZE（当前6），否则用该数。设单一人数n会把最少和最大都设max(1,n)；设范围分别对两端至少1，**不保证最少≤最大、不自动夹6**。完整输入队伍范围是最少max(1,最少参赛数)到max(6,最大参赛数)，最终参赛则按参赛最少/最大。建议人数取最大参赛数。仅用带number参数的初始化只设最大、**最少仍1**，不同于后来显式设人数。

成员条件/整队条件按加入顺序全部要求真；重复加入不去重，集合清除只清对应列表；重新设置整套规则、战斗种类、调整策略为覆盖。布局设置会附加单/双战规则并将人数设3/4；后来再设人数只改人数、不撤双战，故双战3名参赛可由工厂默认形成。战斗建立时顺序应用所有附加规则，布局后写覆盖先写，条款重复赋真不叠数值。

**名为“加入子集规则”的入口实际追加到整队条件列表。** 因此通过这个普通入口添加总等级/限制物种上限，会对完整待报名输入队伍全部求值；清“子集规则”不会删除它，清整队规则会删除它。保留独立子集列表的消费代码，但本快照公开添加入口没有向其中写入，不能把注释中的意图当当前运行效果。

规则复制只复制原始最大数和三类列表中的规则引用，**最少人数重置1**，不是完整值复制；参数对象引用共享，战斗种类/等级调整也保留原引用，未建立深层独立快照。复制后建议人数仍原最大，但最终可选最少数可能放宽。

建议等级不是合法性证明：先从1..最大等级开始，按成员条件遍历取最后一个最小等级、最后一个最大等级；独立子集列表中的最后总等级可覆盖“最大×建议人数”。总额足够时返两端较大值，否则总额整除建议人数再与最小取较大。由于普通“子集添加”实际放整队，默认杯赛的总等级未进入此建议算法，建议值可能使随后队伍不合法；真正判断仍是所有限制合取，不只最后条件。异常/非法类型、0建议人数和矛盾上下限未统一验证。

### 2.2 实际判断入口

表中方法名仅审计定位，按用户问题分层，不按名字许诺等价。

| 判断 | 实际检查和返回 |
| --- | --- |
| 单成员 isPokemonValid | 空成员假；按顺序成员规则，任一不真即假；没有规则时非空者真，**不会自动排蛋/倒下** |
| 完整输入队伍 canRegisterTeam | 空列表对象或长度小于输入最少/大于输入最大则假；所有成员合法；所有整队规则对整队合法；若独立子集列表非空，枚举“最少参赛数”大小的组合，存在一个满足全部子集规则才真；没有该列表则直接真 |
| 存在完整可报名组 hasRegistrableTeam | 输入空或不足最少假；枚举**输入最大长度**大小的组合，任一个完整输入判断真才真。组合长度不足时零次枚举→假，不自动用较短列表，所以3人队伍可能canRegister真但hasRegistrable假（默认输入最大6） |
| 是否能选出合法参赛组 hasValidTeam | 空或不足最少假；先统计单成员合法数，少于最少假；有整队规则时在**原输入（不是过滤后列表）**枚举最少大小组合，逐组调用最终判断，首真即真；没有整队规则时只凭合法数足够返真，不单独消费独立子集列表 |
| 最终已选队伍 isValid | 对长度先下限、后上限；逐成员；逐整队条件；逐独立子集条件。每一步失败即返假，并向可选错误集合追加首条人数/成员/规则错误；不是枚举另一个替代组合 |

枚举只产生指定正数k的无重复索引组合：k≤0或输入长度<k不产生；长度=k产整列；k1每个成员；其它按原索引递增顺序，存在性首个成功就停止。不重排个体、不把相同物种去重成同一条目。空最终数组受人数下限拒；最终判断直接访问列表长度，没有nil列表统一守卫。若规则失败却没有错误文案入口、并传入错误集合，可能访问缺失文案而异常（例如通用限制物种数量条件）；布尔查询不自动造文案。

### 2.3 实际选择界面与接收

UI_Party的多选入口先hasValidTeam，不成立直接返回空，不开选择界面；逐成员只按单成员判断标资格。选择加入最多公开number，按加入顺序编号，移除后顺序压紧；选满且刚加入时焦点移到确认，但不自动提交。确认构造所选引用列表，调用isValid并显示首个错误；失败继续选。退出/取消返回空，未调用设施setParty；看摘要不提交新队伍。

事件便利查询pbHasEligible忽略可变实参，读当前挑战规则对玩家现有队伍hasValidTeam。pbEntryScreen仅取消空值nil不提交；列表对象含空列表均传给挑战setParty，随后按是否含成员返回布尔。旧报名P遇空列表被覆盖且返回false；进行中活动队伍立即为空列表。nil取消保留P及活动队伍。空列表正例仅工具／替换UI边界，正常多选确认仍受人数下限限制。setParty保存引用列表；若挑战已进行还立即替换玩家活动队伍，否则留待挑战开始，开始处先保存原队伍引用再替换。这里只定位这次提交，完整恢复原队伍/存档异常窗口交WP55，不把“选队取消”与“开战中断”统一为回滚。

全Scripts文本只发现hasRegistrableTeam/canRegisterTeam在规则实现内部，实际报名UI使用hasValidTeam/isValid；不能声称所有四入口都已由默认Demo接待调用。生成对手入口使用建议等级/人数；候选数≤建议人数时直接全部构造并返回，不再次最终校验；更多时反复取样直到isValid，无尝试上限。这是规则消费者边界，不在本包运行或提取完整生成器。

## 4. 临时等级、经验和还原（D）

### 4.1 策略与范围

无调整策略不写等级、返回空记录；有策略先按**两侧当前列表顺序保存双方每个成员完整经验**，再计算指定侧目标等级，逐成员仅当当前等级不同才赋目标等级并重算能力。等级相同者保留级内经验，不统一归到该级起点。请求等级非法会由个体setter拒绝，已经写过的前面成员没有本层事务还原。

| 调整策略 | 目标及参数 |
| --- | --- |
| 固定级 | 两侧所有成员为L，L在创建策略时夹1..最大等级 |
| 上限级 | 两侧各取min(当前级,L)，L夹合法域；低于L者不提升 |
| 对手固定级 | 仅第二侧固定L，L夹合法域 |
| 开放级 | 仅第二侧固定为max(第一侧所有当前等级,最小参数,1)；最小参数没有预夹，第一侧空时起1，非法最终值可触发setter异常 |
| 总等级 | 仅第二侧；min/max分别夹合法域，先全置min，不检查最小总和是否已超总额；余预算按队伍次序每轮每成员加1，到总額或各到max。同数成员尽量均匀，余数偏前；min>max时停在min，不交换上下限 |
| 双侧不同策略 | 第一侧/第二侧各用各自策略的等级计算；空子策略保持该侧当前等级；子策略原“只敌/双侧”标志不决定此组合内的适用侧 |
| 单玩家上限 | 上项组合：第一侧上限L，第二侧固定L |
| 等级平衡（未见默认使用） | 两侧每成员R(113−0.072×按物种身份查到的种族总和)，保存的minLevel参数没有参与计算、无本地上下界夹限，最终setter仍查合法域 |

只有“双侧同策略”类型才被adjustLevelsBilateral便利入口执行；双侧不同策略类型虽也影响两边，不通过这个便利门。直接主调整入口支持四种适用范围。裸基础调整的默认计算调用了只有类级定义的空调整入口，若直接实例化基础类型存在缺方法路径；列出的具体策略有自己的实现，不因此一概不可用。

等级setter把经验设该成长曲线此级最低值并更新等级缓存；重算六能力值读取现有IV/EV/Nature/形态等，不自动重学招式、进化或改变友好。HP按新总HP减旧总HP的差加到当前值、至少1（仅原HP>0或总HP增加时赋），再夹0..新总HP；不保证保留百分比，倒下成员遇总HP增加可变正。没有在调整器中保存旧HP/状态/PP/招式/物品作为统一快照。

还原按两侧**当前位置索引**的旧经验：记录有值且当前经验不同，才写旧经验（使等级缓存失效）并重算能力；没有额外旧等级输入，曲线解级沿WP30。即使策略原只改敌方，两侧经验记录都可用于还原。队伍若重排/替换，不能凭此索引记录保证身份正确还原；调用者负责维持对应。若经验恰相同，不因HP或别的字段变了就强制重算。

### 4.2 真实开战顺序与正常返回

普通设施战斗包装先有Debug＋Ctrl跳过路径，直接返回胜利、清临时录像，跳过治疗/调整/战斗/还原；这是明确测试入口，不在本项目执行。

通常路径：先玩家全队完整治疗→保存双方经验并调整等级→保存双方当前物品身份→创建战斗并顺序施加布局/条款→internalBattle设假→通用prepare_battle再应用当前临时战斗规则/环境（其中size可覆盖刚设置布局）→战斗→正常返回后还原两侧经验/能力→两队逐个完整治疗、解除Mega/原始回归、恢复保存的物品身份。最后只决定1返回真，其它决定假；胜/败统计、录像完整逻辑留WP55/58。

该包装没有用统一确保块覆盖所有异常出口；不能将正常返回还原承诺扩大到抛错/强制中断。玩家治疗发生在保存经验之前，结束又治疗，所以它不保留战前受伤/PP/异常；调整器自身的经验还原也不是“恢复所有战斗字段”。完整挑战的原队伍保存/暂停/结束/地图返回留WP55，本包已给实际选队及单场调整边界。

## 5. 杯赛/模式的默认组合（E）
