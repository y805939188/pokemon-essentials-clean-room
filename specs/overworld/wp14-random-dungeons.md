## 1. 目的、范围与非目标

**目的**：描述随机地牢的行为规则——什么输入决定一次生成、布局/房间/通道如何被约束、种子如何被消费、事件与玩家如何被摆放、空间不足或绘制失败时发生什么。后续包据此判断"生成的地图必须提供什么行为"，而不是各自重新追踪生成器。

**范围**（WP14 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP14-A：生成触发与输入域（触发条件、参数/图块集/种子/屏幕尺寸输入）。
2. WP14-B：布局生成规则（节点图样、迷宫连接、房间、通道、连通性检查）。
3. WP14-C：图块化与装饰（墙体推断、错误修复/重绘、装饰、图块选择）。
4. WP14-D：事件与玩家摆放（摆放约束、重试、失败结果）。
5. F04-06 中属于 WP14 部分的状态更新。

**非目标**：

- 不验证真实地图可达性与实际生成结果（U01）；不把"相同 seed 跨实现一致"写成保证（U05，WP06 引用）。
- 不提取地图元数据全部字段语义（WP15 主规格；本文只登记 random_dungeon 标记的门控作用）。
- 不提取迷宫/地牢的玩法流程、奖励与 Demo 可达性（WP77 范围）。
- 不运行生成器或任何参考脚本；不修改 `reference/`；不设计未来生成算法架构。

## 2. 概念与术语

- **节点（node）**：地牢网格的逻辑单元；一张地图被划分为 节点列数 × 节点行数 的网格，每个节点占 单元宽 × 单元高 个图块。
- **可访问节点**：被节点图样（node_layout）选中的节点，参与迷宫连接。
- **房间（room）**：节点内一块矩形地面；**通道（corridor）**：连接相邻节点的固定宽度地面带。
- **墙体推断**：按地面 8 邻域位掩码查表得出墙图块类型；无法直接确定的组合进入错误修复。
- **重绘（redraw）**：布局/墙体阶段发现不可接受结果时，放弃本轮并重新生成（不重新播种）。
- **图块集映射（dungeon tileset）**：把布局符号（地面/墙/装饰）映射为实际图块 ID 的数据定义，含大网格对齐、双层墙等选项。
- **地牢参数（dungeon parameters）**：按（区域, 版本）索引的生成参数集。
- 影响域编号 Dxx 见 module-map；证据状态五档定义见总览第 7 节。

## 3. WP14-A：生成触发与输入域

### 3.1 触发条件与时机（本轮逐行阅读 `008_Overworld_RandomDungeons.rb:1063–1107`）

- 生成由**地图建立通知**（`on_game_map_setup`，WP05/WP11 引用）驱动：当地图元数据的 `random_dungeon` 标记为真时，在地图建立阶段生成并**就地改写**该图的宽度、高度与图块数据。
- 因此生成发生在 WP11 所述的地图 setup 链内（显式传送 setup、读档恢复 setup、新游戏 setup 等均经此通知）；边缘切图不重载当前图，不触发重新生成（WP11 引用 setup 与 setMapChanged 的区别）。
- 改写后该图以生成尺寸与内容参与后续加载/显示/通行（WP11/WP12 引用）；元数据其余字段语义归 WP15。

### 3.5 种子来源与消费点（WP06 交叉）

- **三级来源**：参数集 RNGSeed → 全局待播种子 `$PokemonGlobal.dungeon_rng_seed` → 系统新种子（`Random.new_seed`），取第一个非空。
- **消费规则**：按三级来源取到种子后，先**无条件清空**待播种子字段（无论种子来自哪级），再以 `Random.srand(seed)` **重播全局随机序列**（对后续所有 rand 消费者是可观察副作用，WP06 引用）；不得把清空写到播种之后。
- **消费点**（按生成顺序）：迷宫起点抽取、方向重洗、额外连接抽取、房间抽取、房间尺寸/中心、通道偏移、装饰密度判定与坐标、图块随机选取（含变体）、事件/玩家摆放的房间与坐标抽取、失败重试时的再次抽取。
- **重绘不重新播种**：同一轮生成内，布局/墙体失败后的重绘继续消费当前随机序列（4.4）。
- **不保证**：相同 seed 在不同实现/版本/参数组合下产生相同地图（U05）；本包只记录输入来源与消费顺序，不写跨实现一致不变量。

## 4. WP14-B：布局生成规则

### 4.1 尺寸推导（本轮逐行阅读 `Dungeon.initialize`，347–382 行）

- 横/纵缓冲 Bx=⌈屏幕宽/64⌉、By=⌈屏幕高/64⌉。大网格先在 Bx 奇数时 Bx+1，再判断**已调整的 Bx**是否奇数以决定 By+1，因此后者不执行，By 保持；576×448 得 (10,7)。这是顺序缺陷的静态合同，不改参考。
- **大网格奇数参数调整：意图与首次失败分层（GR-006）**：缓冲区之后、地图尺寸换算之前，构造对大网格对齐（SnapToLargeGrid 为真）**意图**写回参数——奇数单元宽 −1、奇数单元高 −1、奇数通道宽度调整（为 1 则 +1 成 2，其余奇数 −1）。但**标准参数对象只声明这三个字段的读取入口，没有任何写入入口**（无插件覆写/扩展的前提；参数类全文与其引入模块均无写回机制）：首个命中的奇数字段在**首次写回即报错**（Ruby 无对应方法的错误），构造中断——既得不到已调整尺寸，也进入不了 generate。失败时点：**待播种子的清空与播种在 generate 内、地图宽高/图块数据的重写在 generate 之后的回调中，二者此时尚未发生**（3.5 消费点、3.1 回调顺序不变）。PBS 正整数模式与参数专用校验均不拒绝奇数输入（编译只查重复区域/版本）。参考缺陷保留：不得替标准参数对象补写入入口使它"正常"，也不以"自动调整后正常生成"描述该路径。
- 地图尺寸逐轴分流：输入**≥20 直接作为地图图块尺寸并返回，不再调偶**；<20 才按 `节点数 × 单元尺寸 + 2 × 缓冲区` 换算，并在大网格且结果奇数时 +1。故大网格输入 21 的地图尺寸仍为 21。
- 可用尺寸 = 地图尺寸（大网格对齐时奇数则 −1，21→20）；可绘制区 = 可用尺寸 − 两侧缓冲，不得将可用尺寸回写为原地图尺寸。
- 可绘制区宽或高为负：**生成直接返回**（布局保持清空状态，全为虚空），后续图块化与摆放仍执行（4.4/4.5 的失败路径）。

### 4.2 迷宫与房间（`Maze` 全文、`generate_layout`）

1. **可绘制区小于一个单元**（宽或高 < 单元尺寸）：整个可绘制区绘为房间地面，结束布局，**不登记房间矩形候选**；初次生成仍不能摆放，绘图成功不等于有候选。
2. **节点网格**：可绘制区按整除划分为 节点列 × 节点行；按节点图样标记可访问节点（未识别图样按 full 处理）。
3. **迷宫连接**：从可访问集合随机取起点，深度优先连接可达部分；不无条件保证每种图样都连通。**空可访问集合在空抽样后读起点坐标即失败**，先于房间派生/零房间退化；种子已消费而原地图尚未重写。2×2 节点配 antiring 即为空集合。
4. **额外连接**：尚未连通的有效相邻节点分别登记 A→B/B→A 两记录，不放回抽取 ExtraConnections 个，数量不足则取全部；两方向都打通同一无向边，不先去重。请求 2 不保证增加两条不同边；2×2 生成树只余一条闭边时，抽完其两方向也只新增一条边。
5. **房间派生**：可房间节点为可访问集合与 RoomLayout 图样的交集，数量 N；请求 max(⌊N×RoomChance/100⌋,1)，实际 min(N,请求)。N=25、70% 得 17；N=1、超过 100% 仍仅 1。**实际数 0 才整区绘房间地面，不登记候选**；此路径救不了前一步的空起点失败。
6. **逐节点绘制**：按连接图样画通道（固定宽度、居中；ShiftCorridors 时在约束内随机偏移；大网格对齐调整奇偶）；房间节点画随机尺寸/位置的房间矩形（尺寸在 Min/Max 域内随机，中心在单元中心 ±2 内随机，整体被夹在缓冲与可用区边界内）。

九种图样分别作用于可访问集合与可房间筛选，坐标域为 0≤x<Nx、0≤y<Ny；使用同一谓词：

| 图样 | 保留节点的充要条件 |
| --- | --- |
| full / 未识别 | 全部有效节点 |
| no_corners | 不同时满足 x 为最左/最右且 y 为最上/最下 |
| ring | x=0 或 Nx−1，或 y=0 或 Ny−1 |
| antiring | 0<x<Nx−1 且 0<y<Ny−1 |
| plus | x=⌊Nx/2⌋ 或 y=⌊Ny/2⌋，4/5 列的竖线均为 x=2 |
| diagonal_up | abs(x+y−Ny+1)<2 |
| diagonal_down | abs(x−y)<2 |
| cross | 上述两条斜线任一为真 |
| quadrants | 排除「左右边缘且 2≤y<Ny−2」及「上下边缘且 2≤x<Nx−2」，其余保留 |

房间每轴从最小…最大闭区间均匀取整数（最大≤最小时取最小）；大网格奇数尺寸≤半单元时 +1，否则 −1，单元 10 中 5→6、9→8。中心为 ⌊单元尺寸/2⌋ 加 −2…2，左上为单元原点+中心−⌊房间尺寸/2⌋；先使奇数位置 +1 再夹入内界，不在夹取后再调偶。通道居中初值 ⌊(单元尺寸−宽度)/2⌋，启用偏移时 v=宽度（大网格先取 ⌊v/2⌋），仅 v>1 才抽 r∈[0,v−1] 并加 r−⌊v/2⌋，大网格偏移再乘 2、奇数位置再 +1。各方向矩形带与独立数值边界见 [净化 WP14 §4.2](../../deliverables/final-specification-set/engine-overworld/wp14-random-dungeons.md)，不以源方法名代替规则。

### 4.3 连通性检查（`check_for_isolated_rooms`）

- 布局完成后做泛洪检查：以第一个地面图块为起点泛洪；**没有任何地面 → 重绘**；存在未被泛洪覆盖的地面 → 重绘。即保证（每次通过的布局）地面全连通。

### 4.4 墙体推断、错误修复与重绘（`generate_walls`、`resolve_wall_error`）

- 对每个地面图块，其 8 邻域中的虚空格按"地面邻接位掩码"查 256 项映射表得到墙类型（下墙 12 种：wall_1/2/3/4/6/7/8/9 + 内墙 4 种；上层对应 upper_*）；双层墙选项时再对下层墙做一轮上层推断。
- **错误修复**：仅两种邻接组合（掩码 34 与 136，即对角两地面夹一格）进入修复分支——按具体邻接状态改写内墙/外墙/通道；分支均不命中时**置重绘**（布局整轮重来）。
- 映射表无对应项的其他组合：置重绘并抛出"can't resolve error"（静态路径；正常生成中仅 34/136 被标记为错误，该分支为防御性）。
- **重绘循环无次数上限**：布局/墙体阶段可因连通性或墙错误反复重来，直到通过为止（仅受随机序列终将产生可用布局约束；不运行验证其终止性）。

下墙 12 型已包含 4 内墙；下层邻接按最上非空布局是否 room/corridor，上层按第一墙层是否墙。独立的 256 输入墙型压缩决策表见 [净化 WP14 §4.4](../../deliverables/final-specification-set/engine-overworld/wp14-random-dungeons.md)，位权 N/NE/E/SE/S/SW/W/NW=1/2/4/8/16/32/64/128；0 在掩码 0/上层为虚空、非零掩码下层为通道，−1 仅为 34/136 的修复入口。此表为本款兼容合同，不规定未来查表实现。

**候选重绘生命周期**：清布局三层时**不清已登记房间矩形**，旧矩形仍可能被摆放抽中；§6.1 又不查当前地形。仅在给定旧矩形、当前非地面位置及尺寸/间距通过的条件向量下可接受，不能声称找到实际种子或已运行摆到墙上。

### 4.5 装饰（`paint_decorations`、`paint_wall_top_tiles`）

- 均以图块集是否登记对应装饰为前提（未登记则跳过该装饰）：
  - 地面斑块：按单元遍历，按概率在随机中心点半径内播种，再做平滑（孤立斑块按平滑率回填通道、密集地面按平滑率成斑）。
  - 1×1 地面装饰：按密度随机散布于地面。
  - 2×2 地面装饰（坑）：按密度选取四格全为房间地面的位置。
  - 1×1 / 2×2 虚空装饰（岩/缝）：按密度散布于虚空。
  - 墙顶（wall_top）：正南第一墙层为外墙 2/内墙 1/内墙 3 时，在本格第三图块层绘制（层索引 2）。

四种装饰密度是非负整数除法分母；PBS 接受 0。设原地图 W/H、可用 Uw/Uh、可绘制 Dw/Dh、密度 d>0，次数只为尝试上限，失败不补数量：

| 处理先后 | 尝试次数 | 坐标与许可 |
| --- | --- | --- |
| 2×2 地面 | ⌊Dw×Dh/d⌋ | x∈[0,Dw−1]、y∈[0,Dh−1] 后加缓冲；四格最上非空均为房间地面 |
| 1×1 地面 | ⌊Uw×Uh/d⌋ | x∈[0,Uw−1]、y∈[0,Uh−1] 再加缓冲；底层 room/corridor 且第一墙层无下墙；无独立有效范围门，不改成可绘制区抽样或补裁剪 |
| 2×2 虚空 | ⌊W×H/d⌋ | x∈[0,W−2]、y∈[0,H−2]，四格最终布局均为虚空 |
| 1×1 虚空 | ⌊W×H/d⌋ | x∈[0,W−1]、y∈[0,H−1]，最终布局为虚空 |

d=0 且对应非空映射存在、前阶段通过时，计算该项次数即除零失败，已清种子并播种、原地图宽高/图块尚未重写、尚未摆放；不是「密度 0 跳过」。映射未登记才跳过该项，其他阶段不自动通过。

斑块中心按完整单元均匀抽取，中心±半径为正方形闭域；符合地面门的中心±1 的 3×3 必落斑，其余另按概率。平滑顺序读四正邻：斑块 0 邻回填 corridor、1 邻按 2×率回填；非斑地面 ≥2 邻按邻数×率变斑，途中布局可改变，不作同步整图平滑。墙下选项决定读底层还是最上非空；wall_top 只在正南第一墙层为外墙 2/内墙 1/3 时写第三层。

## 5. WP14-C：图块化（`generateMapInPlace`、`get_random_tile_of_type`）

- 布局符号 → 实际图块：room/corridor 归为 floor；none → 图块 0；ignore → 跳过（2×2 装饰的占位）；2×2 装饰按四格写偏移图块。
- 每类符号从图块集登记的 ID 列表中**随机选取**；自动图块（ID < 384）按邻接关系取变体；大网格/大墙/大地面选项按坐标奇偶加偏移；北墙正北有墙时加 ThinNorthWallOffset。
- 地图的宽度、高度与三层图块数据被改写为生成结果（3.1）。

本款使用 [净化 WP14 §5.1–5.2 独立编号/邻接合同](../../deliverables/final-specification-set/engine-overworld/wp14-random-dungeons.md)：普通索引 t 为 384+t，自动索引 a 为 48a；`walls` 组合登记即使来自自动条目也用 384+t+墙排布偏移。四组双层/大墙编号表及 256 等符号邻接压缩表为精确兼容值，不从方法名推定。自动邻接比较该层**原布局符号**（room/corridor 不先合并），边界邻坐标夹到图内：掩码 0/255/85/7 的变体为 46/0/15/40。普通大虚空/地面按 x 奇数+1、y 奇数+8；大墙只对外 2/8/墙顶的 x、外 4/6 的 y 加对应偏移，不扩大到所有上墙/内墙。北墙变薄仅外 7/8/9 且正北第一墙层仍为墙；2×2 装饰四格**分别随机取基本编号**，普通编号再加 0/1/8/9，自动编号不加，不能假定四格同基值。

## 6. WP14-D：事件与玩家摆放

### 6.1 摆放约束（`get_random_room_tile`，1011–1039 行）

- 候选房间：房间矩形宽/高须**严格大于** 事件宽/高 + 1（即四周至少留 1 格，不贴墙——防止堵通道）。
- 单次尝试：随机候选矩形，宽 rw/高 rh、事件 w/h 时左上偏移在 [1,rw−w−1] / [1,rh−h−1] 均匀取整数；对每个新占格 p 和已占格 q 须 **max(abs(px−qx),abs(py−qy))≥2**，不是两轴都须 ≥2。(5,5)/(7,5) 允许，(5,5)/(6,6) 拒绝。
- 只核候选尺寸与占格间距，**不复查当前最终地面、通行位或墙**。小图/零房间退化的可见地面不等于候选，重绘旧矩形则仍参与抽样。
- 单事件最多 1000 次尝试；成功则登记占格，返回房间内的位置（多格事件取其底行左格）。
- 无合格房间或尝试耗尽 → 返回失败（nil）。

### 6.2 整体摆放与失败结果（生成回调，1078–1105 行）

- 顺序：每轮先逐个摆放地图全部事件（支持 `size(w,h)` 多格，WP13 引用），再摆放玩家（1×1）。
- **事件摆放失败**：任一事件摆放返回失败 → 置整体失败标记，整轮（事件+玩家）重来，**最多 100 轮**；100 轮后失败标记仍为真 → **抛出"无法把所有事件和玩家放进房间"异常**（在地图建立通知内抛出，沿 setup 调用链传播；WP11/WP07 引用异常分层）。
- **玩家摆放失败（参考快照行为，如实登记不修参考）**：玩家摆放返回失败时**不置整体失败标记**，直接进入下一轮。若每轮事件都成功而玩家连续 100 轮无法摆放，循环结束时失败标记仍为假——**不进入最终异常分支**，回调正常结束：事件位置保留最后一次成功摆放的结果，玩家传送暂存坐标**保留旧值**（本轮未写入新位置）。
- 玩家摆放成功时：位置写入传送暂存（`$game_temp.player_new_x/y`，生效路径归 WP11 传送链）。
- 即：最终异常保证仅适用于**事件失败**路径；玩家失败路径的可观察结果为"静默结束 + 事件已摆放 + 玩家坐标未更新"。**每轮开始重置失败标记，最终是否抛异常由最后一轮的标记决定**——先前某轮失败不保证最终异常。

## 8. 边界、失败与未知

- 可绘制区为负 → 生成提前返回（全虚空布局），图块化照做；摆放阶段**按事件集合分流**：事件集合为空时仅尝试玩家，无房间每次返回失败但**不置失败标记**，重试耗尽后**不抛异常**（玩家暂存坐标保留旧值）；至少有一个普通事件时该事件摆放失败置标记，重试耗尽后按 6.2 抛异常。
- 可绘制区小于单元 → 整区房间地面，无迷宫/通道且不登记候选；初次生成摆放仍失败。
- 非空可访问集合、实际房间数 0 → 整区房间地面、不登记候选；空可访问集合已在起点坐标读取失败，不能进入此退化。
- 布局不连通或无地面 → 重绘（无次数上限，4.4）。
- 墙错误不可修复 → 重绘；映射表外组合 → 重绘并抛错（防御性静态路径）。
- 事件摆放 100 轮失败 → 抛异常（沿 setup 链传播）。
- 玩家摆放 100 轮失败（事件均成功）→ **不抛异常**：回调静默结束，事件位置保留、玩家暂存坐标保留旧值（6.2，参考快照行为）。
- 图块集/参数身份未命中 → 回退（首个图块集 / 默认参数实例，WP03 引用），不报错。
- 大网格对齐 + 奇数单元宽/高或奇数通道（标准参数对象，无插件覆写/扩展）→ 构造生成上下文时首次写回因无写入入口即报错；待播种子清空/播种与地图宽高/图块重写均未到达（4.1，参考缺陷保留，GR-006）。
- 装饰未登记 → 跳过；装饰图块列表为空 → 写图块 0。
- 任一对应非空装饰映射存在且前阶段通过，密度 0 在计算尝试次数时除零失败；原图尚未重写，不能代入后续摆放的静默失败/100 轮异常。
