## 1. 目的、范围与非目标

**目的**：描述 overworld 画面必须满足的可观察规则——地图如何被绘制（图块层/自动图块/显示偏移/邻图拼接）、角色与物品如何呈现（精灵/灌木深度/反射/阴影）、天气与屏幕效果如何叠加、场景切换时哪些可见状态保持或重建。后续包据此判断"某一帧画面由什么决定、何时刷新"，而不是各自重新追踪渲染器。

**范围**（WP16 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP16-A：地图绘制（图块层、自动图块动画、显示偏移与滚动、邻图拼接、优先级/桥/反射分层）。
2. WP16-B：角色与附属精灵（角色图/图块图、图案帧、灌木深度、反射、冲浪基点、动态阴影、日夜着色）。
3. WP16-C：天气与屏幕效果（天气类型/淡入、色调/闪烁/震动、雾/全景、计时器与图片）。
4. WP16-D：场景刷新与视觉过渡（精灵集生命周期、地图切换的可见状态、转场）。
5. F05-03、F05-04 中属于 WP16 部分的状态更新。

**非目标**：

- 不验证任何实际视觉结果、动画时序或像素输出（未运行；E11 待验证项）。
- 不保留 Tilemap/Sprite 类层级或渲染管线结构；不设计未来渲染 API。
- 不重复 WP11（拓扑/偏移/传送顺序）、WP12（地形标签语义）、WP15（资源选择与缓存）的主规则——本文只引用并登记其可见结果。
- 不提取消息/窗口/输入（WP17）、战斗内画面（战斗包）。

## 2. 概念与术语

- **图块层**：地图数据的三层（0/1/2）；每个屏幕格每层一个图块精灵。
- **自动图块**：按邻接关系选型的图块（8 个标准位 + 额外自动图块），可按帧动画。
- **显示偏移**：地图显示坐标（子像素单位，WP11 引用）决定屏幕滚动；图块网格按整格滚动 + 亚格像素偏移。
- **优先级与分层**：图块按优先级决定 Z 序；桥、反射、雾、天气、画面效果各有固定分层。
- **可见状态保持**：跨图时画面连续性依赖显示偏移与邻图拼接（WP11 引用），精灵集则销毁重建（WP11 引用）。
- 影响域编号 Dxx 见 module-map；证据状态五档定义见总览第 7 节。

## 3. WP16-A：地图绘制

### 3.1 图块精灵网格与屏幕滚动（`001_TilemapRenderer.rb` 全文，本轮逐行阅读）

- 画面维护一个**屏幕图块精灵网格**（宽 = 画面宽格数 +1、高 = 画面高格数 +1，每格 3 层），多余的行/列挂在左/上边缘外；滚动时**整格列/行循环移位**（移出的一列/行重置到另一侧并标重绘），亚格部分按像素偏移摆放。
- 滚动量来自当前图显示偏移（子像素 ÷ 4 得像素，WP11 单位引用）；亚格偏移按取模计算。
- **邻图拼接**：遍历地图工厂的全部已加载图，各图按自身显示偏移投影到网格并填充图块；未被任何图覆盖的格置空（WP11 邻图摆放/修剪引用）。地图切换时若能取得相对偏移则平移网格保持连续，否则全量重绘（WP11 连接引用）。
- **图块来源**：tile_id < 8（自动图块数）×48 为自动图块（含空白 0）；其后依次为额外大自动图块、额外单图块自动图块（EXTRA_AUTOTILES 常量表，默认空），再其后为图块集普通图块（8 列）。巨型图块集（mega texture）按列重排。
- **图块属性**：地形标签决定**反射**（shows_reflections → Z = −100）与**桥**（bridge 且玩家在桥上 → Z = 0；WP12 桥状态引用）；优先级 0 → Z = 0，其余按 `行×32 + 优先级×32 + 33` 抬升。
- **桥状态变化**：玩家桥状态改变时触发全列 Z 值更新。

### 3.2 自动图块动画

- **源格式分开**：高 32 的单图块条带每帧宽 32，帧数至少 1；高 128 的标准大布局和高 192 的扩展大布局每帧宽 96，帧数为 max(整除图宽/96,1)。192×128 的源图为 2 帧，不能用宽/32再减半推成3。中间展开图可能按纹理容量分两列，不改变源帧数。
- **相位与间隔**：默认每帧 5/20 秒；文件名末尾 `[N]`（允许标记内空白）改为 N/20 秒。按共享起点的运行时长推进同名动画；有至少两帧而末尾 `[0]` 时，首次计算帧号遇到零间隔/非有限取整错误，不承诺安全静止。它与文件名前缀 `[0]` 的条带帧数校验不同。
- 每种大布局帧提供 48 个兼容图样，每个32×32 图样由四个16×16源格组成；以下顺序为左上、右上、左下、右下。源格以6列行优先从1编号，源点为((编号−1)模6×16, 向下整除(编号−1)/6×16)，动画帧横移96×帧号。数据身份保留，未来实现不必采用展开缓存。

### 4.2 角色精灵（`003_Sprite_Character.rb` 全文，本轮逐行阅读）

- **图块图角色**（tile_id ≥ 384）：从图块集切取（多格角色按宽高）；锚点底中。
- **图形角色**：`Graphics/Characters/名称`（WP15 资源引用），4×4 帧布局——横向 4 帧图案、纵向 4 朝向；名称含 `offset` 时锚点上移；玩家图形被缓存保留（retain，WP15 引用）。
- **灌木深度**：正常4×4字符图的单格高H、灌木深度d：H−d−2像素不透明段，随后两像素alpha170、两像素alpha85，底部d−2像素留空。图块图32×32、d=12的分支却将目标Y放到32/50/52等画布外；只登记这些越界目标和宿主裁剪未证，不把正常三段渐隐套给图块图。
- **可见性**：透明标记直接控制；名称含 `regulartone` 的事件免疫日夜着色，其余户外角色按时段着色（4.4）。
- **位置**：屏幕坐标按角色实时坐标（含移动/跳跃插值）与显示偏移计算（WP11/WP12 引用）；Z 按屏幕高度与角色高度排序。
- **动画**：角色 animation_id 非 0 时播放对应动画数据并清标记（资源缺失时行为未验证）。
- **更新机会**：事件角色仅在 `should_update?` 时更新（WP13 引用），玩家每帧更新。

### 4.3 反射、冲浪基点与动态阴影（`004_Sprite_Reflection.rb`、`005_Sprite_SurfBase.rb`、`009_Sprite_DynamicShadows.rb`）

- **反射**：玩家及名称含 reflection 的角色可有倒影；用水平镜像与180°旋转形成净垂直翻转，保持上移2像素的锚点偏移。排序 −50（玩家再+1）。非玩家 `reflection(非负整数)` 固定高度，其余跟随桥高度。高度>0 时叠色(48,96,160,255)、不透明度沿父值，TIME_SHADING 开启则隐藏；高度0 时叠色(224,224,224,96)、不透明度为父值×3/4，不另乘3/4亮度。父不透明度128时两分支分别128/96。父不可见时不呈现倒影。
- **默认摆动**：ANIMATE_REFLECTIONS 默认 true；地图未标 still_reflections 时，横向缩放围绕父值按运行时钟1秒正弦周期作±5%变化。still_reflections 或关闭开关才取消摆动；真实像素未证。
- **冲浪/潜水基点**：任一状态成立即持续呈现，二者均真时冲浪优先；兼容图为 `Graphics/Characters/base_surf`、`base_dive` 的4×4布局，按水上图案与朝向取格。过渡坐标存在时按该地图坐标定位，清除后仍存在并跟随父坐标；两状态均假才撤去。沿父色调、叠色、缩放和不透明度，不沿父 visible 标志，所以不能由父透明标记单独推导基点隐藏。
- **动态阴影创建**：普通地图初始化按事件编号收集注释 `begin Shadow Source`，再对带 `begin Shadow` 的目标事件和玩家建立关联。仅命令108注释参与；标记大小写不敏感但起始文本须完整相等，不接受任意空白修饰。后续连续108行按空白分词，只取第二词：非零整数转换值或字面0作为整数，其余保留文本；遇非108、单词行或新 begin 结束，最多读四参数行。无标记为无输入，有标记无参数为空输入。默认角度两端0、最大距离350、不透明度100；非零角度范围限制及距离门保持。
- **真实失败分叉**：至少一个合法光源记录及一个带 Shadow 的事件目标时，事件分支把整份光源列表当单光源输入；初始化首次距离检查向列表元素形状求屏幕坐标失败（缺 screen_x），早于目标阴影图加载。玩家分支逐光源接收单记录，不受这个列表形状错误；不能据此保证所有玩家阴影成功。传送清理玩家阴影的既有边界保留。真实地图/demo可达、宿主像素和插件仍未证，不能把事件路径修写成正常创建。

### 4.4 日夜着色（`003_Overworld_Time.rb:100–126`，本轮阅读）

- `TIME_SHADING` 开启且当前图为户外（outdoor_map）时，角色与地图元素按**逐小时色调表**（24 项，小时间按分钟线性插值）着色；否则色调归零。时间来源归 WP06（引用）。
- 画面级天气色调与日夜色调分别作用于不同层（天气在天气视口，角色在地图视口）。

默认24整点四通道色调以无损分段交付（每个范围内所有整点相同）：

| 整点 | R,G,B,Gray |
| --- | --- |
| 00–03、22–23 | −70,−90,15,55 |
| 04 | −60,−70,−5,50 |
| 05–08 | −40,−50,−35,50 |
| 09 | −20,−25,−15,20 |
| 10–17 | 0,0,0,0 |
| 18 | −5,−30,−20,0 |
| 19–20 | −15,−60,−10,20 |
| 21 | −40,−75,5,40 |

四通道均按分钟/60在当前与下一整点间线性插值，23点下一小时回绕0。缓存需要重算时读取当前宿主时钟；缓存有效期由运行时钟计30秒，不能在缓存未过期时承诺新时刻值立即出现。明暗度另取当天分钟m，午后换为1440−m，结果为整数向下取整(255×m/720)。无天气叠加、户外、TIME_SHADING开启且缓存需刷新时：00:00色调(−70,−90,15,55)，06:30为(−40,−50,−35,50)、明暗138；12:00色调0、明暗255；18:30为(−10,−45,−15,10)。06:30两端相同，不能单独证明插值边界。


### 4.5 世界角色动画

事件207将非空目标的动画标记设为给定ID（不存在目标则正常返回）；角色消费后清标记。草丛迈步消费者另在有效地图场景、占据格地形允许时请求临时动画，随格坐标/地图滚动，允许日夜着色、层高1；正常动画可同时存在，新的播放请求不统一取消旧动画。此合同与战斗动画编辑/播放器分开。

| 输入/阶段 | 行为 |
| --- | --- |
| 帧率/结束 | 默认20帧/秒，动画名称末尾 `[N]` 改帧率；相位以本次普通播放起点的运行时长计算。达到帧数结束释放呈现；临时格动画在没有活动效果时结束。 |
| 单元 | 每帧最多16单元；图样空或−1隐藏，其他按五列192×192图集取方格。单元给相对x/y、百分比缩放、角度、镜像、透明度和混合。透明度=单元值×父值/255；父色调随附。 |
| 定位 | 位置0/1/2为目标顶/中/底：x是目标图中心，y为目标图顶、半高或全高（有效高度>1）。屏幕位置3在有视口时为其宽/2、高−160，无视口为320/240；只保留兼容锚点，不要求固定视口组织。 |
| 顺序/定时 | 层高0为顺序1，层高1/2为屏幕y+48/+96再+1，其他2000（标准32格）。同帧重复更新只跟随位置，不重复定时；仅当前新帧触发相同帧号的SE/闪光。条件0总生效、1限命中、2限未命中；闪光分目标、视口或目标隐藏，持续参数乘2宿主单位。 |
| 跳帧 | 起点0，20fps，更新直接到.1秒即帧2：只触发帧2定时，不补帧1。 |
| 循环异常 | 新循环上下文的初始化读普通动画状态，而该状态为空；在读取帧数时局部失败，早于正常循环播放。不能将这个入口补写成无条件可用循环，也不能外推普通动画失败。 |

有效动画记录、足够帧数与合法媒体为静态前提；名称帧率为0、损坏单元与真实像素/宿主输出不由正常路径证明。

## 5. WP16-C：天气与屏幕效果

### 5.1 天气（`001_Overworld_Weather.rb`、`012_Weather.rb`、`001_Game_Screen.rb:13–69`，本轮阅读）

- **天气类型**：注册 9 种——None、Rain、Storm、Snow、Blizzard、Sandstorm、HeavyRain、Sun、Fog；类别归并为 Rain（含 Storm/HeavyRain）/Hail（Snow/Blizzard）/Sandstorm/Sun/Fog/None；各类型登记粒子/叠层图形与色调过程；Rain 类自动浇水树果（玩法消费者，WP46 交界登记不展开）。
- **设置语义**（屏幕 `weather(type, power, duration)`）：类型经数据注册校验（WP03 引用）；强度 power → 粒子上限 = (power+1) × 6（MAX_SPRITES 60 的十分比）；duration 保存为天气淡入标记——**正 duration 启用固定阶段淡入，duration 为 0 时立即切换**（不是实际时长数值）。
- **淡入/切换**：天气对象的 fade_in 入口只在**类型变化**时被全局精灵集调用（WP16-R02，见下条）；入口内**先判"正在淡入则返回"**，再判"类型与上限均无变化则返回"，之后才看 duration——**不是任何 duration=0 请求都能立即切换**：已有过渡在途时新请求被守卫拒绝，旧目标与当前过渡继续（屏幕保留新请求，后续全局更新按类型比较重新判断，不能写成已立刻生效，也不能写成一定永久丢弃）。通过守卫后：duration > 0 按**固定阶段时序**推进（阶段按 Graphics.delta 累积，并受旧天气 time_shift 影响——旧类型为 None +2、旧类型无叠层 +1；结束另须旧粒子不再可见）：旧粒子基础阶段 **1–3**、旧色调 0–2、旧叠层 0–1、新粒子 2–4、新色调 3–5、新叠层 4–5（相对阶段，非传入 duration 的比例）；duration 非正走立即切换分支。None 类型上限归零。
- **同类型强度变化（参考快照行为，WP16-R02）**：屏幕记录的类型与上限都会更新，但全局精灵集**仅在当前天气对象的类型与屏幕类型不同**时才调用 fade_in——同类型仅改强度时，天气对象不会再次收到新上限，可见粒子上限不能据源码保证刷新（天气对象内部的"同类型同上限则返回"分支只有被调用时才有效，不是全局消费者保证）。
- **滚动跟随**：天气视口偏移跟随地图显示偏移；跨图时按相对偏移平移天气粒子保持连续（无连接偏移则归零重置，WP11 引用）。
- **地图天气**：地图元数据的天气字段驱动的设置入口（WP15/WP59 交界，登记字段存在，消费者另见 4.x 与 WP59）。

### 5.3.1 零时长赋值与旧任务

画面色调、图片色调、雾色调、雾不透明度四入口均以20单位/游戏秒插值。正时长新请求以当前值重建起点/目标/时钟；零时长只立即赋新值，不取消或重置原在途任务。四入口分别以一个通道/不透明度验证：t0从0向100作40单位请求；t0.5零时长设200，立即200；t1下一更新仍按原任务得50，t2得100后旧任务结束。无旧任务时200保持；若t0.5改为正40单位向200，则起点沿当时当前值另起任务，不能沿原0→100。图片须有非空名称且处于当前业务更新区间；雾须地图更新到达。

力度0的震动请求不在入口拒绝，也不按「无震动」安全处理；首次更新以0最大位移计算相位，出现零除/非有限值取整失败。时长0的完成检查在相位计算之后，不能避免失败。力度>0且速度0是不同对照：位移0；力度>0、速度>0、时长0仍先算相位后判完成。异常出口不补造原子回滚。

### 5.4 图片与计时器

- **图片业务与显示分开**：编号1–100均可被呈现，普通世界业务只更新1–50，战斗业务只更新51–100。事件侧战斗编号偏移50，不等于世界将所有100条都推进。
- 显示（同名也一样）写入名称、原点、位置、缩放、不透明度和混合；重置移动目标/时长、色调与其时钟、角度0及旋转速度0。擦除只清名称：后续不呈现、业务更新早退，坐标/缩放/不透明度/角度等数值不因此清零。
- 移动的时长单位为1/20游戏秒：1单位=.05秒，0→100在.025秒为50；20单位=1秒。位置、缩放与不透明度从当时当前值线性到目标；原点/混合立即变更。原点0为左上，其他为中心；20×10图的中心为10/5。缩放200/50分别2/.5。图片间按编号排序。
- 旋转按运行时长，速度1每秒20度，−1一秒回绕340度；速度0停转并保留角度。图片色调及零时长旧任务见§5.3.1。
- **计时器**：业务剩余=初始秒数−当前游戏秒数+起点。起点存在才显示（数值0起点也是存在），负剩余显示夹0，显示格式为两位分钟:秒；达到0不清运行标志。停止清起点、隐藏，业务读数0；不要求清旧初始秒数。起点100、初始61、当前101得到60、显示01:00；开始0秒仍显示00:00。


### 5.5 地点条、灯光与黑暗

地点条只在有效场景/显示集、map_changed为真且新图 announce_location 为真时考虑。存在上一次地图记录时，NO_SIGNPOSTS按相邻两元素组成无向禁配对（奇数尾元素忽略）；或前图解析名称与新图名相同时抑制。无上次记录时跳过这两项抑制。采用运行时钟：滑入.4秒、完整停留1.6秒、滑出.4秒。飞行目的地存在时更新先早退；创建时曾延迟者在目的地清空后重设起点一次。正常非飞行更新遇消息显示或当前图不同即处置，不是暂停后续恢复；飞行守卫优先于这些处置门。

灯光按整段事件名识别 `light`、`outdoorlight` 及 `light(词字符+)`、`outdoorlight(词字符+)`，忽略大小写；括号参数允许字母/数字/下划线，不接受连字符、空格、前后附文。自定义 `Graphics/Pictures/参数` 可解析时使用，否则回退 `Graphics/Pictures/LE`。基础灯不透明度100、顺序1000，跟随事件屏坐标并按事件高度向上半格高、附随画面色调。户外灯从日夜明暗d得到：d≤64完全255，d≥144为0，中间为整数(255×(144−d)/80)，d=104时127；名称门独立于地图 outdoor_map 与 TIME_SHADING，不能额外加这些创建条件。

地图/显示集变更通知到达有效场景时，dark_map创建黑暗罩（不要求map_changed真）；初始半径64，flashUsed真则176。非暗图清flashUsed、处置当前罩并清引用。512×384默认中心为256/192，固定在屏中心，非跟随玩家；半径赋值四舍五入，不夹在64–176。罩的五次内圆处理每次半径取前者×.9向下取整。

仅直接FLASH效果入口：无有效未处置罩时返回false，无标志/统计写入；有罩且前置演出/文本正常完成时先写flashUsed和次数+1，再请求名义.7秒半径64→176并最终显式176。确认/徽章/地形等资格归WP59；不得以效果入口的成功前提省掉前段门。
