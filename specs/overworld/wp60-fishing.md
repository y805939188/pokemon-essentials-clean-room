## 1. 目的、范围与非目标

**目的**：定义钓鱼的完整交互链——鱼竿三档的入口资格、等待循环与提示节奏、咬钩与收竿的输入/超时条件、成功/失败/提前取消的返回、抛竿前后的临时状态（移动类型/锁定/朝向）恢复、随机输入与特性加速、以及最终以何种遭遇请求交接给遭遇系统；供遭遇（WP36）、战斗侧消费（WP38/WP39）与事件/调试引用。

**范围**（WP60 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP60-F1：入口——三支鱼竿的物品使用入口、面向地形/冲浪/悬崖资格、无表行为。
2. WP60-F2：等待循环——提示点节奏、提前取消、咬钩检定与收竿输入/超时、自动收竿配置。
3. WP60-F3：结果与返回——"没咬钩/跑掉了/钓到了"三分支及返回值；统计写入。
4. WP60-F4：临时状态与恢复——钓鱼标志、移动类型（步行/冲浪栖息）、模式锁定与整理、开始/结束公共事件。
5. WP60-F5：遭遇交接——`has_encounter_type?` 预取、成功后的类型请求与战斗侧消费（环境/捕球/演出位置）。
6. F14-04 中属于本产物部分的状态更新。

**非目标**：

- 不定义遭遇表内容/权重/等级（WP36）；不定义开战阵容、捕获与结算（WP39/WP38/WP42）。
- 不定义地形标签全集与冲浪运动（WP12）；不定义物品使用入口主规则（WP28）。
- 不定义真实反应时间、媒体与输入体验（运行范围）；不运行参考脚本。

## 2. 概念与术语

- **鱼竿档位（rodType）**：OldRod=1、GoodRod=2、SuperRod=3；决定咬钩概率基础。
- **咬钩（bite）**：等待中出现"！"与"有咬钩！"提示后，进入**收竿输入窗口**；窗口内按确认/取消键即收竿成功（受收竿判定）。
- **收竿判定（hook）**：收竿窗口通过后，按自动收竿配置或收竿概率决定是否真正"钓到"；当前收竿概率恒 100（除自动配置外必成）。
- **等待循环**：一次 `pbFishing` 调用至多执行**一轮**等待-提示-判定（重试逻辑在参考实现中被注释禁用——按现状登记）。
- **临时状态**：`$PokemonGlobal.fishing` 标志、玩家的移动类型（`fishing`/`surf_fishing` 专用类型）、模式锁定与朝向整理；在结束时恢复到 `walking_stopped`/`surfing_stopped`。

## 3. WP60-F1：入口与资格（物品侧）

### 3.1 三支鱼竿入口（UseInField）

1. 通行判据读取玩家当前坐标，向当前朝向作出边通行检查（包含当前格有效性、非自身且未穿透的有效图块事件阻挡与当前格通行规则）；不是面向目标格入边检查。资格 = 面向地形可钓鱼 且（surfing 标志为真或当前格出边通行）。目标格可钓地形独立读取；目标格全方向阻挡不自动否决鱼竿。拒绝时消息、false、无钓鱼计数。surfing=true（含静止）豁免通行门，diving=true 本身不豁免。
2. 预取遭遇：`本地图是否存在该竿的遭遇类型`（OldRod/GoodRod/SuperRod 三者独立）；结果作为"是否允许咬钩"的输入，**不阻止流程开始**。
3. 调用等待循环；**返回真时**：统计 fishing_battles +1 → 以该竿类型发起遭遇请求（WP36 §7）；**返回假时**：不请求遭遇。
4. 条目整体返回真（持有即"使用过"，即使未钓到）。
- 入口与快捷（已登记物品）路径共用同一处理器（**物品主动使用主规则引用 WP28；容器/登记引用 WP27**）。
- **直接调用 `pbFishing` 不重查**上述资格门，也不检查鱼竿库存（静态边界）。

### 3.2 无表/空表行为

- 本地图无该竿类型表或表为空：等待循环照常演出，但**咬钩分支不可能进入**（每轮必落在"没咬钩"分支）；因此不会产生候选与开战。**不允许**以"无表仍得到相同结果"承诺。
- 表中存在但运行期被过滤为空（理论上）：遭遇请求返回假、静默结束（WP36 §5）。

## 4. WP60-F2：等待与输入循环（`pbFishing`）

1. 统计 fishing_count +1。
2. **加速特性**：**首非蛋成员**（允许濒死；队首为蛋时取其后第一只非蛋）特性 ∈｛黏着、吸盘｝→ 加速为真。
3. **咬钩阈值** = `20 + 25 × 档位` → 45 / 70 / 95；加速时 ×1.5 → **67.5 / 105 / 142.5**（**不设上限**；>100 的阈值对 0–99 抽样恒真）。*参考注释标注 "67.5, 100, 100"，与算术不符——按代码行为登记，不采用注释值。*
4. 进入循环（单轮）：
   1. **等待段数** = `rand(5..10)`（加速时为两次掷的**较小值**）；**实际执行"段数+1"段**：**首段空文本**，其后逐段加点；每段显示后等待 **0.4 秒**（每段等待期间均可取消）。名义时长 = **(段数+1)×0.4 秒**（另有消息/动画开销，未作真实计时）。
   2. **等待中共按 确认/取消**（含首段空文本期间）→ 提前取消：结束语"连咬钩都没有……"，返回假。
   3. **咬钩检定**：**仅当预取"允许咬钩"且 `rand(100) < 咬钩阈值`** → 进入咬钩流程；否则"连咬钩都没有……"，返回假。**阈值与有效概率分列**：对整数 0–99 的抽样，**67.5 接受 0–67 共 68 个结果 → 有效 68%**；70 接受 0–69 → 70%；105/142.5 → 有效 100%。
   4. **咬钩流程**：播放"！"动画；收竿窗口时长 = `rand(5..10) ÷ 10` 秒（0.5–1.0）；显示"哦！有咬钩！"并进入**抖动循环**：每 0.2 秒一槽、**固定八槽序列 1,0,1,0,0,0,0,0**（玩家图形帧 1/0），**完整周期 1.6 秒**：
      - 每次更新图形/输入/地图并更新抖动帧后，先检查确认/取消输入：有输入立即收竿成功并复位图形帧；再在无输入时检查超时。
      - 仅非自动收竿且经过时间严格 > 窗口时长时超时 → "宝可梦跑掉了……"、false；等于时长且无输入继续。前轮未退出时，本轮即使抽样已过截止仍优先接受输入（如0.500无输入继续、下一轮0.510有输入true，反向同0.510无输入false）。
      - 启用自动收竿时**不设超时**（等待直到输入）。
   5. **收竿判定**：启用自动收竿 → **跳过收竿随机抽取**、直接成功；否则 `rand(100) < 收竿概率(=100)` → 恒成功（失败分支保留但当前不可达——静态记录）。成功时给"钓上来了！"消息（自动收竿时**不显示**该消息）。
5. 结束并释放消息窗口；返回"是否钓到"。
- **随机输入目录**（静态）：等待段数 5–10（加速取小；执行段数 +1）；每段 0.4 秒；咬钩检定 1 次（每调用）；抖动 8 槽×0.2 秒；收竿判定 1 次（自动收竿时跳过；当前恒定通过）。
- **与时钟/帧的关系**：等待与窗口以**经过的单调秒数**计时（`pbWait`/`System.uptime` 差值）；**帧循环只是更新/轮询机制**——不是"经过固定帧数即结束"的时间单位；不受游戏时钟流速影响（WP06/WP59 交界：不等同于步数/时段推进）。

## 5. WP60-F3：三分支结果与统计

| 分支 | 触发 | 消息 | 返回 | 后续 |
| --- | --- | --- | --- | --- |
| 提前取消 | 任一段等待（含首段空文本）中按确认/取消 | "连咬钩都没有……" | 假 | 无遭遇、无 fishing_battles |
| 没咬钩 | 未命中咬钩检定（阈值语义见 §4.3） | 同上 | 假 | 同上 |
| 跑掉 | 收竿窗口超时（非自动） | "宝可梦跑掉了……" | 假 | 同上 |
| 钓到 | 收竿成功（自动收竿跳过随机抽取） | "钓上来了！"（自动收竿时省略） | **真** | 统计 fishing_battles+1 + 遭遇请求 |

- 任何分支都计入 fishing_count；只有"钓到"计入 fishing_battles。
- **阈值与有效概率分开表述**：表中"命中"指对整数 0–99 抽样落在阈值内（有效概率见 §4.3）。

## 6. WP60-F4：临时状态与恢复

### 6.1 开始（`pbFishingBegin`）

- 置 `$PokemonGlobal.fishing = true`。
- **"公共事件替代"取决于公共事件确实可执行**：仅当该设置 ID 为**非负且事件存在**（公共事件执行返回真）→ 由**事件负责**本阶段表现——**被绕过的是内置的"移动类型设置 + 图形模式锁定 + 动画序列"整体**；**负数 ID 或事件不存在** → 执行内置回退：设移动类型 = 冲浪中 ? `surf_fishing` : `fishing`；锁定模式；按 4 帧序列切换图形帧（3→2→1→0，每帧 0.05 秒）。**不能统称"配置非负就只替换四帧动画"。**

### 6.2 结束（`pbFishingEnd`）

- 同规则：**有效结束公共事件**负责表现段（内置图形帧恢复被绕过）；**无效/缺失** → 内置恢复（0→1→2→3）。
- 执行随附块（最终消息——在表现之后、状态清理之前显示）。
- **清理（无论走事件还是内置，均执行）**：移动类型 = 冲浪中 ? `surfing_stopped` : `walking_stopped`；解锁模式；**整理朝向**；`fishing = false`。
- **恢复保证**：所有分支（成功/失败/取消/跑掉）都经过结束流程；"正常结束仍执行公共清理"结论保留。
- 移动类型 `fishing/surf_fishing/surfing_stopped/walking_stopped` 的语义引用 WP12；冲浪起点/停车语义不在本包。

## 7. WP60-F5：遭遇请求与战斗侧消费

1. **请求**：成功后以该竿的遭遇类型调用"请求一次遭遇"（单打默认；WP36 §7）；请求内部：候选选择 → 无候选返回假（此后**不提示**）；开战调用由 WP39 前向。
2. **战斗侧对"钓鱼类型"的具名消费**（静态目录；完整语义归各自包）：
   - 战斗环境判定：钓鱼类型时取**面向地形标签**（而非脚下），影响环境/形态派生（WP45/WP21 交界）。
   - 捕球倍率：诱惑球（LUREBALL）在钓鱼类型下倍率 ×5（旧球率时为 ×3）（WP38 前向）。
   - 战斗开场位置：钓鱼类型 → 水面位置演出（WP16/WP45 前向）。
3. `$game_temp.encounter_type` 的生命周期与清理**按 WP36 §7 的入口分列**：正常开战调用返回后清空；**第一/第二候选为空时早退、返回假并保留已写类型**（不把"请求结束"一律说成清空）。
4. **区分三级**：提示咬钩（本包）≠ 产生候选（WP36 选择）≠ 启动战斗（WP39）；任一后续环节失败不得回溯为"钓鱼失败"。

## 8. 规则与不变量

1. 入口资格 = 面向可钓地形 +（surfing标志或当前坐标向朝向的出边通行）；目标格通行不是此门；不受时段/天气/背包（除持有）影响。直接调用 pbFishing 不重查此门、也不查鱼竿库存。
2. 每调用至多一轮；**等待段数为区间随机（执行段数=段数+1）**、窗口时长区间随机；**加速特性 = 首非蛋成员（允许濒死）**，同时缩短提示（取小）与提升咬钩阈值（×1.5，不设上限）。
3. 收竿当前恒定通过（**自动收竿时跳过收竿随机抽取**）；失败分支为不可达保留（静态记录）。
4. 所有分支经统一结束流程恢复移动类型/锁定/朝向与钓鱼标志；模式锁定期间玩家不可自由行走。
5. 统计：fishing_count 每次调用 +1；fishing_battles 仅成功 +1。
6. 遭遇交接仅在成功时发生一次；无表/空表不产生开战。
7. 等待/窗口以**经过的单调秒数**计时（帧循环仅为更新/轮询机制），与游戏时钟/步数无耦合。

## 9. 边界与失败

- 面向不可钓鱼地形 → 入口拒绝（"不能在这里用。"），不进入等待，不计钓鱼次数；**仅 diving=true（surfing=false）不豁免**；冲浪中静止仍可用（标志判据）。
- 未冲浪且当前坐标出边通行失败 → 拒绝；不要用目标格阻挡替代此判据。可钓目标全阻挡而当前出边允许时可用；当前出边阻挡而目标通行允许时拒绝（其它门固定）。
- 无该竿类型表：整段演出但必为"没咬钩"（§3.2）。
- 等待任一段按键提前取消；咬钩轮询先收输入，只有无输入且非自动并严格超过时长才超时；等号继续、同轮晚采样输入仍优先。
- 自动收竿开启：窗口不超时、**跳过收竿随机抽取**、成功后不显示"钓上来了！"；仍需要一次输入完成收竿。
- 公共事件配置：**仅有效事件**替代对应内置表现段（开始=移动类型/锁定/动画；结束=表现段）；**无效 ID 回退内置**；状态清理与统计不受影响。
- 冲浪中钓鱼：使用 `surf_fishing` 类型与冲浪栖息恢复；水面上结束仍保持冲浪态（`surfing_stopped`）。
- 遭遇请求返回假（候选为空）：钓鱼已"成功"，但无战斗发生（静默）——静态调用 ≠ 战斗成功（WP36 引用）。
- 真实反应时间/触感/媒体：运行未决。
