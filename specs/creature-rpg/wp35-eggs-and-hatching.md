## 1. 目的、范围与非目标

**目的**：定义蛋的持久状态与"蛋到非蛋"的完整提交——蛋的判据与孵化计数、每步的计数与加速特性、多蛋排序、临界处理、孵化提交的字段写入与演出、命名出口、与图鉴/统计/队伍/寄养/赠蛋的调用关系及持久化边界；供事件赠蛋（WP26/WP64）、寄养（WP33）、图鉴（WP62）与界面审查（WP67-B）引用。

**范围**（WP35 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP35-A：蛋状态——判据、计数字段、数据来源（生成/脚本/调试）与展示消费者。
2. WP35-B：每步处理——计数、加速特性扫描、临界与多蛋排序、与步数/移动语义的引用边界。
3. WP35-C：孵化提交——`pbHatch` 的写入序列（统计、命名、拥有者、来源方式、地点/时间、最初招式）与演出次序。
4. WP35-D：演出与命名——场景输出、图鉴记录、条件条目、命名三出口与不可达分支登记。
5. WP35-E：持久化与跨包调用关系（保存恢复、赠蛋/领取/容量/图鉴）。
6. F09-07 中属于 WP35 部分的状态更新。

**非目标**：

- 不定义后代生成/遗传（WP34）；不定义寄养周期与兼容性（WP33）；不定义脚本赠蛋的创建字段（WP26 引用）。
- 不定义图鉴对象完整语义（WP62）、文字输入控件细节（WP17）、资源回退细节（WP15）。
- 不定义宿主/媒体/音频的实际效果与真实存档载入（运行范围）。
- 不运行游戏或参考脚本；不设计未来框架的孵化 API。

## 2. 概念与术语

- **蛋**：`steps_to_hatch > 0` 的个体（纯字段判据；无独立"蛋"标志）。
- **孵化计数**：`steps_to_hatch` 剩余步数；创建时为 0（非蛋），以"蛋"形态生成时初始化为该物种的孵化步数值。
- **加速特性**：队伍中非蛋成员持有的"加快孵化"标记特性（数据样本：熔岩铠甲、火焰之躯、蒸汽机）——每个计步事件至多生效一次。
- **孵化提交（`pbHatch`）**：把蛋转为普通个体的写入序列；**先写入、后演出**（无回滚）；**工具自身不检查蛋态/是否已孵化，也不写计数字段**（归零与防重由迈步调用者负责——§4/§5）。
- **演出**：裂纹逐帧、变色、破壳与名称/图鉴/命名交互的场景过程。

## 3. WP35-A：蛋状态与数据来源

### 3.1 判据与字段

| 项 | 行为 |
| --- | --- |
| 判据 | `蛋 = steps_to_hatch > 0`；`steps_to_hatch = 0` 即非蛋（正常迈步链在提交前先置 0；pbHatch 自身不写该字段——§5/§9） |
| 字段持久性 | 随个体保存（WP09 引用）；字段为**直接读写**（无读取期补 0/无负值防护——§9） |
| 数据默认 | 物种数据"孵化步数"字段分三个层次：构造**缺省 1**（未提供时）；PBS 文本按**正整数格式**校验（无上限钳制）；**编辑器属性上限 99,999 仅编辑器层**——不是所有数据输入的全域上限（文本字面值 100000 不被该上限在文本/构造路径钳制） |
| 创建默认 | 个体创建的字段初始值为 0（普通创建/调试置 0） |

### 3.2 写入来源（静态目录）

- **寄养生成**：蛋创建时把计数设为该物种孵化步数（WP33/WP34 引用）。
- **脚本赠蛋**（`pbGenerateEgg` 家族入口）：同样按物种孵化步数初始化（WP26 引用）。
- **调试**：把队伍中蛋的计数直接改为 1（一步孵化）；把某个体计数改为物种值（重新变蛋）或 0（取消蛋状态）——WP73 交界登记。

### 3.3 展示消费者（登记）

- 摘要界面按计数阈值显示**四段不相交区间**（一个默认文本＋三次覆盖）：**≥10,200**"还要很久"系；**2,550–10,199**"还不接近孵化"系；**1,275–2,549**"偶尔会动"系；**1–1,274**"能听到声音/即将孵化"系。边界对照：10200/10199、2550/2549、1275/1274（阈值静态核对；实际文本归 WP08）。
- 调试菜单显示"孵化还需 N 步"。

## 4. WP35-B：每步处理与加速

### 4.1 处理入口与次序

挂接"玩家迈步"事件的独立处理器（**本批重点比较的两个处理器为寄养更新与孵化**——该事件另有其它处理器（驱虫剂、雷达、友好度等），不穷尽登记；**寄存器顺序＝脚本装载顺序**，寄养处理器先于孵化处理器，静态记录）。每次迈步按下述顺序处理（对**队伍数组**逐成员，索引序）：

1. 跳过计数 ≤0 的成员。
2. 计数 −1。
3. **加速扫描**：**首次减值后动态读取**"非蛋队伍成员"集合（按字段判据即席过滤蛋，非静态名单；WP25 引用成员分类），取**首个**能力特性带"加快孵化"标记者 -> 计数再 −1（**首个即停，不叠加**；**仍为蛋的成员不参与扫描，但临界个体在首次减值到 0 后已成为非蛋，可进入该集合并被读特性（甚至临时再 −1，随后由置零分支归位）**——按扫描时点表述，见 §4.2）。
4. 若计数 ≤0 -> 计数**置 0**，随即执行孵化提交（§5）——包括演出；本轮内其后的成员继续按各自轮次处理。

### 4.2 边界语义（静态）

- **多蛋**：同一步中多个蛋各自减值；达到 0 的蛋按队伍顺序**逐个**提交（演出串联）；先孵化的个体变为非蛋后，若其带加速特性，**同一轮后续蛋的加速扫描可命中它**（顺序敏感边界）。
- **临界**：计数 1 -> 减值/加速后 ≤0 -> 置 0 -> 提交（**正常迈步链**的归零保证）；该保证**不推广到任意直接写入/直接调用**——直接写入的负数会因"计数≤0 则跳过"而不会被自动归零（§5/§9）。
- **加速不叠加**：多名加速特性成员只算一次；参与扫描的成员为**扫描时点的动态非蛋集合**（已濒死不另查——分类归 WP25；仍为蛋者不在集合内，刚归零的临界个体已在集合内，§4.1）。
- **计步来源**：什么样的移动产生"迈步"事件（骑行/奔跑/滑行/传送等是否计步）属 WP06/WP12 的已审计步规则；本包不把名称相似的计数器当同一来源。
- **演出期间**：提交的演出同步阻塞；期间不处理步骤（演出为场景循环，无输入推进计数）。
- **加速特性数据**：以特性标志查询（数据侧），本包不列举全部特性；现有样本三枚见 §4.1 追溯。

## 5. WP35-C：孵化提交（`pbHatch`，先写入后演出）

### 5.1 演出前写入（按序）

本节序列由 pbHatch 执行；**工具自身不检查蛋态/是否已孵化、不写计数字段**（归零与防重属迈步调用者——§4；直接调用按本节序列执行，重复直接调用会重复执行本序列）。

| 步 | 写入 |
| --- | --- |
| 1 | 统计"孵化合计" +1（**最先**，任何演出/命名之前） |
| 2 | 名称清空（未命名 -> 显示物种名，WP18 §6.5 引用） |
| 3 | 拥有者 <- 由玩家构造（**孵化即归属玩家**；即使蛋来自交换/外来来源，孵化时也重写拥有者）。**该赋值不清异色等已有缓存**；未求值的普通异色在首次读取时按**重写后**的拥有者与个体号计算——§9/§12.2 |
| 4 | 友好度 <- 120（固定） |
| 5 | 孵化时间 <- 当前时间 |
| 6 | 获得方式 <- "孵化"值（枚举值 1；来源字段语义引用 WP18 §6.3） |
| 7 | 孵化地图 <- 当前地图编号 |
| 8 | 记录最初招式：把**当前招式集**复制为最初招式记录（WP20 §5.2 引用；孵化时的配招成为"最初招式"） |

### 5.2 演出（同步；内部再写入）

1. 先显示"Huh?"等待与淡出（由包装入口完成）。
2. 场景：背景、蛋精灵、裂纹帧（1.5 秒 -> 四段摇晃与裂纹 0–4 -> 白闪换为个体精灵）、叫声、"Evolution"相关音乐、成功音效。场景/资源读取动态形态按WP21可提交形态、重算并登记该形态已见，早于通常的拥有/见过蛋写入。
3. **名称再次清空**后显示"**{名} 从蛋中孵化了！**"（{名} 按未命名显示物种名）。
4. 图鉴：登记个体 + 标记"已拥有" + 标记"见过蛋"（蛋已见的清理/语义归 WP62 引用）。
5. 条件条目：首次拥有 且 拥有图鉴 且 物种在解锁图鉴内 且 配置"更频繁提示新物种"开启 -> 额外消息 + "最近见过" + 图鉴信息页（与 WP26 §3.2 条件展示同构，引用）。
6. 命名询问（§6）。

### 5.3 演出替代分支（静态不可达登记）

包装入口在演出函数返回假值时存在一段纯文本替代流程（"Huh?/……/孵化了！"+图鉴+命名）；但演出函数**恒返回真**——该替代分支在参考实现中**不可达**（静态记录，不视为行为路径）。

## 6. WP35-D：命名出口与界面收尾

- **入口条件**：系统选项"给昵称"为 0（询问）时才询问；否则跳过（名字保持空 -> 显示物种名）。
- **三出口**：
  1. 拒绝询问 -> 不做输入、名字保持空（显示物种名）。
  2. 同意 -> 名称输入（长度下限 0、上限 10、初值空）：
     - 输入确认**空文本** -> 名字为空（显示物种名）；
     - 非空 -> 写入名称。
  3. 输入被取消等价于空文本出口（WP17 的输入两场景语义引用；WP26 §3.3 同构）。
- **收尾**：若发生过命名，结束场景时**不执行淡出**（演出内已处理）；否则正常淡出并释放场景资源（资源缺失边界引用 WP15）。
- **无跳过/无强制命名**：参考实现没有"跳过动画"或"必须命名"分支；不添加。

## 7. WP35-E：持久化与跨包调用关系

- **持久**：蛋计数随个体保存；恢复后未孵化的蛋继续从当前计数递减（计数 ≤0 的个体被迈步处理跳过）；**不重复提交**是**正常迈步链**的性质（归零后同轮/后续轮被跳过），**pbHatch 自身没有**蛋态检查或"已孵化"拒绝——直接重复调用会再次执行提交序列（§5.1/§9）。
- **与赠蛋（WP26）**：脚本赠蛋入口负责创建字段，其蛋进入队伍后按本包计步/孵化；"入口成功"不等于已孵化。
- **与寄养（WP33）**：寄养生成/领取只产出蛋并复位会话计数；持有蛋的计步与孵化归本包。
- **与队伍（WP25）**：蛋作为队伍成员参与容量/移动；计步扫描遍历队伍数组；盒中蛋不参与计步（只遍历队伍；盒内流转语义引用 WP25）。
- **与图鉴（WP62）**：孵化登记/已拥有/见过蛋/条件条目为调用序列（完整语义归 WP62）。
- **与统计（WP06）**：孵化合计；寄养统计归 WP33。

## 8. 规则与不变量

1. 蛋判据只有 `steps_to_hatch > 0`；没有独立布尔字段。
2. 每步对每个蛋**恰好**减 1，外加"至多 1 次"加速减免；加速不叠加；"蛋自身不参与扫描"按**扫描时点**成立（临界归零后的个体已是非蛋，可被读特性——§4.2）。
3. **正常迈步链**临界"置 0 并提交"；**不保证**任意来源无负值持久状态（直接写入的负值会因"计数≤0 跳过"而不被归零）——按调用者分层（§4.2/§9）。
4. 提交顺序固定：统计 -> 名称清空 -> 拥有者=玩家 -> 友好 120 -> 孵化时间 -> 获得方式 -> 孵化地图 -> 最初招式记录 -> 演出（含图鉴/命名）。
5. 提交**先于**演出完成；演出/命名不改变已提交字段的"回滚"语义——没有回滚。
6. 孵化重写拥有者（来源与方式字段也重写为孵化口径）；此前来源文本等字段保留与否按字段目录（引用 WP18 §6.0 字段表：来源文本未被清空，静态核对见 §9.2）。**拥有者重写不清异色等已有缓存**；未求值的普通异色首次读取按重写后拥有者计算（§5.1/§12.2 向量）。
7. 命名只有"空/非空"两态写入；拒绝与取消都落到空（显示物种名）。
8. 多蛋按队伍顺序逐个提交；同一步内先孵化的个体可能参与后续蛋的加速扫描（顺序敏感）。

## 9. 边界与失败

- 计数为 0 的蛋形态个体（人为制造）：不参与计步、不孵化（**正常迈步链**口径；直接调用 pbHatch 不等价——§5.1）。
- 队伍中的非蛋成员带加速特性：加速每步只减 1；多名只减 1；**濒死非蛋成员仍可提供加速**（扫描没有 HP 守卫，§4.2）。
- 同一步多蛋同时到 0：按队伍顺序逐个演出与提交（第一个的演出阻塞第二个的提交）。
- 盒中蛋：不计步（一直保持蛋态直至取回队伍）；调试可直接改计数（WP73）。
- 演出资源缺失（裂纹图/背景/音频）：资源回退与缺失边界引用 WP15；本包不定义替代表现。
- 命名：拒绝对话 -> 空名；输入空/取消 -> 空名；非空 -> 写入；无"改名失败"分支（输入控件边界引用 WP17）。
- **直接调用边界**：pbHatch 不把计数改 0、不检查蛋态；计数 0 的个体再次直接调用仍先增统计并重复提交；计数 5 的个体直接调用后计数仍为 5。
- 持久化：计数字段为**直接读写**——**无读取期补 0、无负值防护**；缺失/nil 在比较处按原始字段语义失败（不能从判据推出补 0）；负值可由直接写入持久存在且不会被步进跳过分支归零。旧档的具名迁移按证据处理、未登记者保留未决；不加载/转换真实存档。
- 孵化提交核心不显式改写球种、性别、个体号、形态、EV/IV、招式集（只登记「最初招式」快照）。此处不保证演出中的动态形态读取无副作用：普通非 Shadow DEERLING 蛋、存储形态 0、无强制形态、剩余 1 步、月份 2，非战斗/非储存且媒体和消息正常返回、跳过命名、无其它改写时，本步计数先归 0，§5.1 核心写入后演出查询得到 (2−1) mod 4 = 1，提交存储形态 1、重算并登记该形态已见，之后才完成通常的拥有/见过蛋写入。月份 1 的相同输入查询仍为 0，不发生这次变形提交；有效强制形态则优先返回，不以季节查询提交。异色：不显式改写，但未求值的普通异色首次判定取决于重写后的拥有者与个体号（已有缓存保持不变）——§5.1。
