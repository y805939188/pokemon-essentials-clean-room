## 1. 目的、范围与非目标

**目的**：定义玩家与 NPC 训练家的身份、外观、资源与许可，以及伙伴的注册/参与语义——供个体拥有者/外来判定（WP18）、战斗参与（WP39 引用）、集合与获得流程（WP25/WP26）与 UI（图鉴/训练家卡等）引用。

**范围**（WP24 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP24-A：身份、外观与标识——训练家基础字段、玩家扩展、玩家内容（编号/套装/字符集/回家点）、初始命名，及其与 WP18 拥有者的关系。
2. WP24-B：资源与许可——金钱/游戏币/对战点/火山灰的域与写入者；徽章与功能标记的读取消费者。
3. WP24-C：NPC 训练家数据与装载——训练家类型目录、训练家记录（版本）、装载流程、缺失数据反馈与调试新增路径、队伍生成覆盖次序。
4. WP24-D：伙伴——注册/注销、参与资格、战斗内拼接与战后处理、与野外流程的交界。
5. F07-02、F07-03 中属于 WP24 部分的状态更新。

**非目标**：

- 不定义战斗准备/布局的完整规则（WP39）、AI 行为技能（WP51）、服从性判定（WP40 引用本包徽章/等级输入）。
- 不定义收藏集合（WP25）、赠送/交换完整流程（WP26）、图鉴规则（WP62）、神秘礼物完整流程（WP64）。
- 不定义编辑器/调试菜单的完整 UI（WP73）；调试路径仅作对照登记。
- 不重复 WP18（个体/拥有者字段）与 WP02（配置值清单）。
- 不运行游戏或任何参考脚本；不设计未来框架的账号/存档 API。

## 2. 概念与术语

- **训练家（Trainer）**：`{类型, 名字, 标识, 语言, 队伍}` 的基础实体；玩家与 NPC 都是其特化。
- **训练家类型（trainer type）**：内容数据——显示名、性别、基础资金、技能档、标记、三类战斗 BGM（F07-02）。
- **训练家记录（trainer data）**：`{类型, 名字, 版本, 队伍数据…}` 的可装载数据；**版本**用作同一训练家的多套变体（事件传参选择）。
- **玩家内容（player metadata）**：按玩家编号提供训练家类型、各运动状态字符集与"回家点"（失败后去处）。
- **资源**：金钱、游戏币、对战点（BP）、火山灰——各有限值与写入入口。
- **许可标记**：徽章数组与一组功能布尔（图鉴/导航器/跑鞋/盒子连接等）——读取侧决定菜单与移动/道具备选资格；写入侧多为事件（材料缺口）。
- **伙伴（partner）**：注册为"随行训练家"的 NPC 记录 `{类型, 名字, 标识, 队伍}`；参与战斗时作为玩家侧第二训练家。

## 3. WP24-A：身份、外观与标识

### 3.1 训练家基础字段（`001_Trainer.rb` 全文，本轮逐行阅读）

- 字段：类型（规范标识）、名字（可写）、标识（32 位整数，可写）、语言（可写；初始化来源为**宿主语言映射**，见下条——与 WP08 的界面语言选择索引是两种独立身份）、队伍（数组，可写）。
- **标识双半**：公开号 = 低 16 位；秘密号 = 高 16 位；均可对给定值计算。生成：初始化时 32 位随机。
- **外来标识**：生成"任意其它"32 位随机且不等于自身的标识（供外来拥有者构造，WP18 §6.1 引用）。
- 显示名：类型名 + 名字；类型带"NoName"标记时只显示名字（WP03 数据）。
- 语言（GR-009）：初始化（构造）时经 `pbGetLanguage` 读取**宿主 `System.user_language` 前两字符**的映射——ja→1、en→2、fr→3、it→4、de→5、es→7、ko→8、其余（如 zh）→2；**此处不读取 LANGUAGES 或 `$PokemonSystem.language`**。界面消息文件选择索引（WP08：玩家选项 → `$PokemonSystem.language` → 消息文件）与个体来源语言编号是两种独立身份与读取时刻；**后续 UI 语言切换不回改**已构造训练家的语言字段（WP08 的切换只写系统选项与消息/存档，不触碰训练家/Owner 字段）。不读取真实主机语言补证。
- 派生查询（不穷尽，队伍相关见 §6/§7）：可战斗成员计数、首/末可用成员、是否拥有物种/招式/属性、全队治疗封装等——多数为集合/战斗读取，集合约束主规格在 WP25。

### 3.2 玩家扩展（`004_Player.rb` 全文，本轮逐行阅读）

| --- | --- | --- |

### 3.3 玩家内容与初始命名（`017_PlayerMetadata.rb`；`001_Utilities.rb:239–287`）

- **玩家元数据**：编号 → 训练家类型 + **7 个字符集键**（行走/奔跑/骑行/冲浪/潜水/钓鱼/冲浪钓鱼；未定义项按链式回退：奔跑缺省用行走、骑行用奔跑、冲浪用骑行、潜水用冲浪、钓鱼用行走、冲浪钓鱼用钓鱼）+ "回家点"（地图与坐标朝向；失败回程消费者归 WP11/WP13 交界）。编号为**数字键**（与其它内容数据的符号键不同）；**按编号取记录时，未登记的编号回退到记录 1**（记录 1 也缺失才取不到）。
- **切换玩家（包装入口）**：`pbChangePlayer(id)`——id < 1 拒绝（false、无改动）；否则按元数据取记录（**未登记编号回退记录 1**）；仍取不到才拒绝；成功则写 `character_ID`（负担字符集刷新）。**注意**：编号 99 未登记但记录 1 存在时切换会"成功"——存储 99、内容（训练家类型/字符集）按回退记录 1 读取——不能笼统写成"未登记即拒绝"。
- **初始命名流程**（`pbTrainerName`，静态核对）：
  1. 若当前玩家编号 <1 → 先切换到编号 1；
  2. 未提供名字时弹出名字输入（长度上限 = 配置值 10）；**取消/空输入** → 生成建议名：先取系统用户名第一个词，仅在非空且长度**严格小于**上限时接受并将首字母大写；否则去掉该首词尾部连续数字，再以同一条件判断。两次判断中，长度等于上限也继续下一阶段。仍不接受时，将**完整系统用户名**按首字母大写、其余字母小写处理后截取前上限个字符（注：源码留有"随机名字"的不可达分支——按行为记录，不作为设计依据）；
  3. 写入玩家名字与套装编号（outfit 参数）。
- **角色字符集选择**（消费者）：按"潜水/冲浪/骑行 > 行走"的优先级从元数据取字符集；玩家编号/套装变更时刷新（`refresh_charset`，WP12 运动状态处引用）。

### 3.4 与 WP18 拥有者的关系

- 拥有者构造读取训练家的 `标识/名字/性别/语言`：**性别来自训练家类型**（不是训练家字段）；语言来自训练家字段（`Owner.new_from_trainer` 逐项复制**现有**字段值，WP18 §6.1 引用）——默认初始化时该值为宿主语言映射编号，字段被改写后复制的是改写值（不重新读取宿主）；**UI 语言切换不回改**已有训练家/Owner 的语言字段（§3.1，GR-009）。
- 外来判定只比较标识与名字（WP18 §6.4 引用）；伙伴注册会把其队伍成员的拥有者重设为该训练家本人（§6.1）。
- 玩家标识的用途（异色判定输入、外来判定）见 WP18/WP19 引用；本包只保证"玩家标识在初始化时生成且可写"。

### 4.4 战斗内金钱结算（调用玩家 setter 的两个入口）

- **入口守卫**：两个结算入口都要求"内部战斗"且"启用金钱结算"；失败结算另要求"不损失金钱"开关关闭。任一不满足 → 整体跳过。
- **胜利所得（两个先后执行的阶段）**：① 训练家战奖励 = Σ（各对手队伍最高等级 × 其训练家类型的基础资金）——"护身金币/快乐时光"各 ×2；② "聚宝功"累积额——同样受两倍加成。**每阶段各自**：读取旧额 → 写入（受上限钳位）→ 计算实际变化 → **仅当实际变化 > 0** 才累计统计并显示提示；某阶段实际变化为 0 时该阶段**不显示提示、也不增加统计**（不是"显示 +0"）。
- **失败所失**：取玩家队伍最高等级（**不含伙伴队伍**）；倍率按徽章计数档位（8/16/24/36/48/64/80/100/120，计数超出取最后一档）；损失额不超过当前金钱；写入并记录实际损失统计（实际损失 >0 时提示）。
- 边界：上限由写入钳位；**已达上限时正奖励不产生变化 → 不提示、不统计**；两阶段共享同一上限时的先后差见 §11.2。

## 5. WP24-C：NPC 训练家数据与装载

### 5.1 数据责任

- **训练家类型**（PBS schema）：显示名、性别（男/女/未知或混合——未知映射 2）、基础资金（显示"金额×最高等级"）、技能档（AI 消费，WP51 引用）、标记（"NoName"等）、三类 BGM（战斗前/中/胜利）。
- **训练家记录**：类型 + 名字 + 版本 + 队伍条目；队伍条目字段（从装载消费面核对）：物种、等级、形态、持有物、招式列表、特性索引/显式特性、性别、异色/超级异色、性格、IV/EV、友好度、昵称、球、Shadow 标记——**个体生成细节与覆盖次序归 WP18 §4.3**（引用）；本包负责数据责任与装载流程。

### 5.2 装载流程（`002_Trainer_LoadAndNew.rb:4–10`）

1. 解析训练家类型：未知 → **报错**。
2. 按（类型, 名字, 版本）查训练家记录：不存在 → 返回空（由调用者处理缺失，§5.3）。
3. 存在 → 转换为可战斗训练家：显示名**可被对战变量替换**（"对手名数组"配置：类型匹配且变量为非 0 字符串 → 用变量值）；标识 = 外来标识；物品列表克隆；胜负台词；队伍逐条按 WP18 的生成覆盖次序构建；收尾重算。

### 5.3 缺失数据反馈与调试新增路径（与正常路径分开）

| 入口 | 非调试行为 | 调试行为 |
| --- | --- | --- |
| 训练家检查（事件调用） | 直接放行（不检查） | 类型缺失 → 提示可新建类型（调试编辑入口）；训练家（版本）缺失 → 提示"新增变体？"并可生成 |
| 缺失训练家（装载失败兜底） | **报错**（含类型/名字/版本信息） | 提示"新增训练家？"；选择"是"→ 交互式新建 |
| 交互式新建 | —（不可达） | 循环录入队伍成员（首个必须录入；物种选择 + 等级范围 1..等级上限、默认 10）；可选**写回**：注册到记录并写回 PBS（训练家类型/训练家两个文件；写回机制归 WP04）、提示已写入 |
| 空闲版本查找 | — | 0..255 内首个未占用的版本号；全部占用 → -1 |

- 调试新增的产物与作者数据同构（写回 PBS 即成为正常数据）；本包只登记行为，不设计未来编辑工具。

## 6. WP24-D：伙伴

### 6.1 注册与注销（`001_Overworld.rb:637–651`）

- **注册**（`pbRegisterPartner(类型, 名字, 版本)`）按实现顺序：
  1. **先解析训练家类型**：未知 → 报错——此时**载具未取消、伙伴槽未动**；
  2. 取消载具（载具清理归 WP12）；
  3. 装载训练家（§5.2；记录缺失 → 空）：**扩展点按正常返回**时，随后访问其队伍会因空对象失败——此时**载具已取消、旧伙伴槽尚未替换**（不假定原子回滚）；
  4. 触发"训练家装载"事件扩展点（WP05 引用；处理器可改动训练家）；
  5. 把其队伍成员的**拥有者设为该训练家本人**（"非外来"**仅相对该伙伴训练家**而言，不默认等于相对玩家）并逐个重算；
  6. 记录伙伴：`[类型, 名字, **训练家身份标识**（不是声明时的"版本"）, 队伍]`——**传入的版本号不保存**。
- **伙伴数据的再次读取（快照行为）**：战斗侧再次读取伙伴道具数据时，把所存的**身份标识**当作第三个"版本"参数查询训练家记录——**该键未命中才得到空道具列表**；仅"标识不同于原注册版本"不能保证没有另一变体命中——若恰好存在该标识值对应的另一版本，会读取到它（不保证来自原注册记录；只记录行为、不修参考）。
- **重复注册** = 替换（再次注册覆盖伙伴槽；旧记录不另行清理——静态语义）。
- **注销**：伙伴槽置空（无其它清理副作用）。

### 6.2 参与资格（战斗侧读取）

- **可行性查询**（战斗前的编成判断，与下一项是不同的入口）：双打 = 玩家可战斗成员 ≥2，**或**（有伙伴且可战斗成员 ≥1）；三打 = ≥3，**或**（有伙伴且 ≥2）。
- **本次伙伴参与谓词**（按实现的实际分支顺序）：① 无伙伴或规则禁用（"noPartner"）→ 假；② **敌方队伍成员数 > 1 → 真**；③ 否则若显式指定规模：单打（或"1v…"）→ 假，其它 → 真；④ 其余 → 假。（不把"单打/多目标野生"等称呼当作条件本身；完整布局归 WP39。）
- 参与时：伙伴作为玩家侧**第二训练家**，其队伍追加在玩家队伍之后并入战斗队伍（起止索引记录）；伙伴道具从其训练家数据读取（克隆；见 §6.1 的再次读取行为）。

### 6.3 战斗内与战后

- 伙伴队伍成员在战斗中按普通成员处理（含形态进入/离开触发，WP21 引用）。
- 战后清理分**两个独立分支**：① **伙伴在场** → 玩家全队治疗 + 伙伴队伍逐成员完整治疗并解除 Mega/Primal（每次战斗结束；含未参战情形——按调用位置静态登记）；② **败北/平局** → 另行对玩家队伍全队治疗——该分支**另有"可失败（can_lose）"前提**，不满足时不执行。两分支不可合并描述。

### 6.4 与野外流程的交界（已定位调用点）

- 漫游宝可梦流程在"伙伴在场"时跳过（具体条件归 WP37 引用）。
- 野生遭遇入口在"伙伴在场"时返回特定结果（细节归 WP36 引用）。
- 宝可雷达使用条件包含"未骑车且无伙伴"（细节归 WP37 引用）。

## 7. 规则与不变量

1. 训练家标识为 32 位；公开/秘密两半；外来标识 != 自身标识。
2. 拥有者构造的性别取自**训练家类型**；语言取自训练家字段；外来判定只用标识+名字（WP18 引用）。
3. 玩家编号/套装的**包装切换入口**：id <1 拒绝；**未登记编号按记录 1 回退继续**（存储原编号、内容读回退记录）；**原始字段赋值无校验**，写入与刷新有先后、失败不保证回滚；字符集按运动状态优先级与链式回退选择。
4. 四类资源 setter：非法类型报错、负值钳到 0、超上限钳到上限；本包不承诺"上限来自何处"以外的规则。
5. 徽章计数 = 布尔真值个数；场地招式许可的口径由配置二选一（默认数量≥需求）；服从性换算引用（WP40）。
6. 训练家装载：类型未知报错、记录缺失返回空、版本由调用者选择；显示名可被对战变量覆盖。
7. 调试新增路径与正常路径分离：写回 PBS 属调试能力；非调试缺失一律报错。
8. 伙伴槽为单槽：注册=替换、注销=置空；注册按"类型解析→取消载具→装载→扩展点→拥有者重设→记录"分阶段，失败留下的部分副作用（如载具已取消）**按实际阶段记录，不假定原子回滚**；注册时会重设其队伍成员拥有者并重算（"非外来"仅相对该伙伴训练家）。
9. 伙伴参与：**可行性查询**（双打/三打编成）与**本次参与谓词**是不同入口；谓词按 无伙伴/禁用 → 敌方队伍 >1 → 显式规模 → 其余为假 的顺序。

## 8. 边界与失败

- `money=`/`coins=` 等：非整数报错（不静默）；负值 → 0；超上限 → 上限。
- `pbChangePlayer(<1)` → false；**编号回退到记录 1 后仍取不到记录 → false**（不改状态；即"元数据缺失"=记录 1 也缺失/不可用）。
- 初始命名：名字输入取消/空 → 建议名流程；系统用户名不可用时的最终回退为"截断的系统用户名"（源码另含不可达的随机名分支——按行为登记）。
- 训练家类型未知：装载与伙伴注册入口**报错**；**类型检查和训练家检查入口**是 §7「非调试缺失」概述的例外，非调试直接返回 true，不查询类型或记录。调试模式下，未知类型提示新增；拒绝新增、类型仍未登记，且查询与解释器收尾正常（解释器也可不存在）时，类型检查返回 false，外层训练家检查随后也返回 false。装载的训练家记录缺失则返回空，其非调试缺失兜底报错（含参数信息），调试可新建；各检查分支仍按 §5.3 的对照表。
- 版本号超出已有变体：视同缺失（走 §5.3）；空闲版本查找满 256 → -1。
- 伙伴在场时野外/雷达差异见 §6.4（细节引用后续包）。
- 徽章/功能标记写入者缺失（U 类）：不得把"读取消费者存在"当成"许可流程完整"。
