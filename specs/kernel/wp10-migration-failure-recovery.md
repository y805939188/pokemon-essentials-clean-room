## 1. 目的、范围与非目标

**目的**：说明旧数据转换、保存/载入失败、备份、紧急保存与地图恢复的适用条件和结果——哪些旧存档被转换、按什么顺序、何时写回；失败在哪些分支发生、可能留下什么状态。后续包据此判断"某旧档如何被处理、失败可能损失什么"，而不是各自重新追踪转换与恢复路径。

**范围**（WP10 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP10-A：转换机制（注册、触发条件、排序、备份与写回时机）。
2. WP10-B：已登记转换目录（当前全部转换及其前提、输入、输出、副作用）。
3. WP10-C：失败与恢复（损坏/备份/紧急保存/地图恢复）。
4. WP10-D：各阶段副作用与调试/非调试分层。
5. F03-02、F03-04 中属于 WP10 部分的状态更新。

**非目标**：

- 不宣称未经验证的旧格式全兼容；缺旧档样本与宿主行为保持具名待证。
- 不修改或转换真实存档；不为复现失败破坏 reference；不运行游戏或任何参考脚本。
- 不提取各转换涉及对象的领域语义（如树果/寄养/电话的对象结构，归相应领域包）。
- 不重复定义 WP07 的诊断限制（引用）。

## 2. 概念与术语

- **转换（Conversion）**：对存档内容的一次定向修改，含触发条件（低于某版本）、逐值修改与整体修改。
- **触发版本**：转换声明的引擎（essentials）或游戏（game）版本阈值；存档版本**低于**该阈值才执行。
- **转换备份（.bak）**：执行转换前把**内存中的存档 Hash** 序列化到固定路径的快照（不是原文件逐字节复制）。
- **紧急保存备份**：紧急保存时把原存档文件**逐块复制**到 `.bak`（与转换备份是不同操作）。
- **读取时写回**：读取存档后，若发生转换则把结果重新写回存档文件（写回目标是**读取时使用的路径**）。
- 影响域编号 Dxx 见 module-map；证据状态五档定义见总览第 7 节。

## 3. WP10-A：转换机制

### 3.1 注册与触发（`S/002_Save data/003_SaveData_Conversion.rb`，本轮逐行阅读）

每个转换按以下配置登记（`SaveData.register_conversion(id) { … }`）：

| 配置 | 行为 |
| --- | --- |
| `essentials_version(v)` 或 `game_version(v)` | 触发条件：存档对应版本**低于** v 才执行（`should_run?`）；只能二选一，重复声明报错 |
| `display_title` | 执行时显示的标题（转换在语言选择之前执行，标题**不可本地化**） |
| `to_value(value_id) { … }` | 对指定持久值的修改；要求存档**含有**该值，缺失则抛错 |
| `to_all { … }` | 对整体存档的修改 |

### 3.2 触发判定与执行顺序（WP10-R01 修订）

- 触发判断使用**插件版本比较器**（WP05 主规格：逐字符位置比较）。以输入 "19" 与阈值 "20" 为例：**第一位 1 与 2 比较，结果为 -1，判定低于阈值，应触发**（不是"19 > 20 不触发"）。其他可复核输入输出：20/20 → 0（不低于，不触发）；1.10/1.9 → -1（1.10 < 1.9，触发较低阈值一侧按实现判定）；存档缺省版本按 essentials "18.1"、game "0.0.0" 处理（低于当前 20/21 阈值，触发对应转换）。
- **执行顺序**：**essentials 族先于 game 族**；各族内按比较器把阈值**从低到高**排序执行；**同阈值按登记顺序**。筛选出"应运行的列表"不等于所有转换都成功（执行可能中断，见 3.4）。
- **版本判断、转换族先后、同阈值登记顺序、候选列表与成功执行是不同层次**，不能混为同一关系。

### 3.3 旧格式入口与边界（WP10-R01 修订）

| 存档形态 | 处理路径 |
| --- | --- |
| 旧序列（pre-v19，Array 形式） | `to_hash_format` 按各 Value 的 `from_old_format` 回调组装 Hash。**当前 17 个默认登记均无 from_old_format 配置**（`002_SaveData_Value.rb:97–99` 返回 nil）——在固定默认登记、无动态插件补充且旧对象可成功读取的前提下，该 Array→Hash 路径得到**空 Hash**，之后跳过转换执行。**不能统一为"凡无版本信息的极旧档都会执行全部 14 项"**。登记接口存在不等于已有实际适配 |
| 空 Hash | 无键可读；按后续校验/加载规则处理 |
| 非空但缺版本标记的 Hash | 按缺省版本（18.1 / 0.0.0）处理（3.2），触发对应转换 |
| 显式版本 Hash | 按存档版本与阈值比较（3.2） |

### 3.4 备份与写回时机（WP10-R02 修订）

`run_conversions(save_data)`（`003_SaveData_Conversion.rb:195–210`）：

1. 收集应执行的转换；无则返回 false（不写转换备份、不写回）。
2. **先把内存中的存档 Hash 序列化到固定路径 `SaveData::FILE_PATH + ".bak"`**（转换前快照；**不是原文件逐字节复制**；覆盖同名旧备份，无追加/轮换证据）。
3. 逐个执行转换（控制台输出标题与完成状态；`to_value` 缺值即抛错中断）。
4. 把存档的 essentials_version/game_version 更新为当前版本，返回 true。
5. 随后（WP09 登记的读取路径）：`read_from_file` 在转换返回真时**把转换后的存档重新写回读取时使用的路径**（`001_SaveData.rb:43–48`）——**读取旧档会改写它**。

**备份与写回目标按读取路径区分**：

| 读取路径 | 转换备份位置 | 写回位置 |
| --- | --- | --- |
| 默认保存路径 | 默认路径旁 `.bak` | 默认路径 |
| 默认 `.bak` | 默认路径旁 `.bak`（**与读取来源同一文件**） | 默认 `.bak`（**同一文件**） |
| 自定义路径 | 默认路径旁 `.bak`（**不随自定义路径变化**） | 自定义路径 |

紧急保存的备份是另一操作：把原存档文件**逐块复制**到 `.bak`（`014_UI_Save.rb:7–16`），与转换备份（内存 Hash 快照）不同，不能混为"原档总能逐字节保留在旁边"。

### 3.5 副作用分层（WP10-D 的静态事实）

| 阶段 | 可能发生的变化 |
| --- | --- |
| 转换前 | 内存 Hash 快照写入 `.bak`（覆盖同名旧备份） |
| 转换中 | 某转换的 `to_value` 缺值 → 抛错中断，后续转换不执行；已执行的修改保留在内存数据中 |
| 写回后 | 转换后的存档重写读取路径对应文件（原旧档不再以原样存在，除非 `.bak` 保留）；控制台记录转换标题 |
| 异常处理 | 备份写入/转换执行/写回任一失败的行为未逐分支验证（不默认原子性或日志一定成功） |

## 5. WP10-C：失败与恢复

### 5.1 启动值读取到 UI 校验/递归备份的完整链（WP10-R03 修订）

| 分支 | 行为 |
| --- | --- |
| 早期启动值错误 | `Game.set_up_system:22–26` 在载入 UI 之前直接读取并加载启动值（含转换）；**错误可能在此就中断，不能保证所有坏档都到达备份界面** |
| 读取/转换抛错 | `read_from_file` 或转换本身抛异常——**与"返回无效 Hash"是不同分支**，不进入备份/删除逻辑 |
| 返回无效 Hash | `valid?` 为假时才进入：有 `.bak` 时提示"存档损坏，将载入备份"并读备份；**备份是递归调用 `file_path + '.bak'`（可能继续 `.bak.bak`）**；无备份时询问是否删除并重新开始 |
| 备份仍无效 | 递归到 `.bak.bak`（同上），继续同样判断 |
| 拒绝删除 | **调用 exit，产生 SystemExit 并退出当前游戏执行**（`013_UI_Load.rb:246–248`；外层 pbCriticalCode 对 SystemExit 原样传播，`003_Errors.rb:81–84`）——不删除、也不返回菜单继续 |
| 删除失败 | 删除动作本身捕获 SystemCallError 并提示失败（`013_UI_Load.rb:272–278`） |

### 5.2 紧急保存（Hangup 路径，`016_UI/014_UI_Save.rb:1–24`，WP10-R04 修订）

- 触发：脚本超时（Hangup）到达主流程分支时（两种模式均可能调用；调试与非调试差异见 5.3）。
- 行为序列：保存旧 scene 并把 scene 置 nil、提示超时将重启；**无 player 时直接返回（不恢复旧 scene）**；有 player 时：**无旧存档也可尝试新建保存**（不需要"已有存档"作为保存前提）；有旧存档时先逐块复制到 `.bak`（**备份复制失败可以阻止后面的保存**）；随后执行正常保存（WP09 路径）；成功提示"已保存"（**"旧档已备份"仅在实际存在旧档时成立**），失败提示"保存失败"。
- **scene 的恢复只在正常走到底时执行**（不是 ensure）——提前返回（无 player）或异常时 scene 不恢复。

### 5.3 调试与非调试分层（引用 WP07 主规格）

- 两种模式的主流程 Hangup 分支**均调用紧急保存**（5.2）；**仅非调试先打印异常**；**调试时该分支重抛后才由外层 pbCriticalCode 转成 Reset**（`999_Main/999_Main.rb:43–46`、`003_Errors.rb:81–89`）。
- 前提是 Hangup **到达此处**——编译/插件内部另行处理的超时不覆盖（WP04/WP05 引用）。
- Reset/SystemExit 的传播仅限具体分支（pbCriticalCode、Compiler.main；插件脚本执行入口经插件诊断/退出路径，WP05/WP07 已登记，引用）。
- 只描述异常信号传播，不声称宿主已经完成重启。

### 5.4 地图恢复失败（WP09 登记，WP10-R03 细化）

- 重新 setup 缺地图（Errno::ENOENT）：**调试给选图入口**（`pbWarpToMap`，取消则退出，选择后设图与坐标），**非调试抛"地图未找到，游戏无法继续"**（`001_StartGame.rb:83–92`）——静态分支可读，不能仅归为"待 WP77 材料"；场景实际显示/地图可达可待证。
- 地图损坏（`$game_map.events` 为 nil）：抛"地图损坏，游戏无法继续"（同文件 98–100）——**与缺图是不同错误**，分开记录。

## 6. 默认行为与配置变体

- **基线默认**：旧档按版本阈值转换（先备份再写回）；无效档走备份/删除路径；Hangup 走紧急保存。
- **支持但未默认启用**：`run_single_conversions`（对单个对象执行适用转换的入口）；`SKIP_CONTINUE_SCREEN`（调试跳过载入画面，WP02 词典）。
- **配置/数据关联**：`GAME_VERSION`/`Essentials::VERSION` 是转换的触发输入（WP02 词典）；`FLUTES_CHANGE_WILD_ENCOUNTER_LEVELS` 影响笛子转换的方向（WP02 词典）；`MECHANICS_GENERATION` 与数据集组合对转换结果的影响（U02/U03）。
- **未验证组合**：旧档样本的真实转换结果、备份恢复的真实路径、地图损坏分支、完整 Demo 启动（缺失地图/事件材料）。

## 7. 边界、失败与未知

- 备份覆盖：同名 `.bak` 被覆盖写入（无轮换）；从 `.bak` 读档并发生转换时，转换前备份与后续写回可能指向**同一个 `.bak`**（3.4）。
- 转换中断：`to_value` 缺值抛错，后续转换不执行；内存中已改数据是否写回取决于写回步骤是否到达（未验证）。
- 写回失败：备份已写入但写回失败时的状态未验证。
- 紧急保存：备份复制失败可以阻止后面的保存；scene 恢复只在正常走到底时执行（5.2）。
- 寄养转换的参考缺陷：旧 A 填入两个新槽、旧 B 找不到空槽（不是一对一保留，4 节）——登记为参考快照观察，不修 reference。
- 电话转换的前提：调用访问运行全局的方法，但调用者时机早于全局载入（4 节）——不能写成无条件成功。
- 旧档样本与宿主行为（U01/U02 相关）：缺旧档样本，不宣称任意旧档全兼容。
