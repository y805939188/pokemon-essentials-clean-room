## 1. 目的、范围与非目标

**目的**：描述作者输入（PBS 文本）到运行数据（.dat）的可见生命周期——什么时候触发编译、哪些输入被发现与如何解析校验、按什么顺序编译、产物如何生效、哪些材料会被写回/删除/覆盖、失败时可能已经发生了什么。后续包据此判断"某数据何时生效、失败可能留下什么状态"，而不是各自重新追踪编译器。

**范围**（WP04 自身声明范围，extraction-plan 第 2.1 节 (a) 类）：

1. WP04-A：编译触发（触发条件、调试前提、新鲜度检查、异常类别与阶段）。
2. WP04-B：输入发现、解析校验与内容依赖（普通发现、专用入口、活跃解析路径、跨内容引用）。
3. WP04-C：编译产物与写回行为（.dat、PBS 写回、MapInfos、地图事件、动画、反写调用者）。
4. WP04-D：失败与部分状态（非原子性、删除行为、异常路径、错误定位、恢复条件）。
5. WP04-E：边界与交界（WP08 文本、WP73 编辑、WP75 转换、WP15 资源）。
6. F02-02、F02-03 中属于 WP04 部分的状态更新。

**非目标**：

- 不提取字段的 Pokémon 语义（归领域包）；不提取文本提取/翻译流程（WP08）、编辑器行为（WP73）、事件简写转换规则全集（WP75）。
- 不验证任何编译运行的真实结果；不运行编译器、游戏或参考脚本，不修改 `reference/`。
- 不把候选 PBS 材料当作已支持变体（延续 WP01-R03/WP02 限定）。

## 2. 概念与术语

- **编译**：把作者文本内容转换成运行用序列化数据（.dat）的过程；本包特指参考实现的调试模式编译检查流程。
- **写回**：编译过程中对输入或工程材料的修改（PBS 文本改写、地图事件转换、MapInfos 登记、动画映射保存）。
- **新鲜度检查**：比较数据文件与 PBS 文件的修改时间以决定是否编译。
- **普通发现 / 专用入口**：顶层自动匹配的输入与按字段显式指定的输入（如设施名单引用）。
- **活跃解析路径**：当前实际使用的文本解析/求值函数族（`split_csv_line` / `get_csv_record` / `cast_csv_value` / `checkEnumField` 及通用/专用编译函数）；相邻标注 Unused 的旧辅助函数不是现行证据。
- 影响域编号 Dxx 见 module-map；证据状态五档定义见总览第 7 节。

## 3. WP04-A：编译触发

### 3.1 触发条件与调试前提（本轮逐行核实 `001_Compiler.rb:1039–1116`）

编译检查**仅在调试模式执行**（非调试直接返回，不存在普通运行的自动修复）。启动顺序：核心消息 → 插件 → 编译检查 → 游戏初始化（WP03 已登记）。满足任一条件即判定编译（mustCompile）：

| 触发条件 | 行为 | 证据 |
| --- | --- | --- |
| PBS 目录缺失 | 先创建目录、从当前数据**全量反写**全部 PBS，再判定编译（注意：这些步骤发生在数据文件清单建立**之前**，见 6.2 早期边界） | 1044–1049 行 |
| 新地图导入 | 扫描 `Data/Map*.rxdata`，未在 MapInfos 登记的地图（**ID 999 地牢图除外**）自动登记并保存 MapInfos；有导入即判定编译 | 1061 行；`004_Compiler_MapsAndEvents.rb:45–83` |
| 必选数据文件缺失或不可读 | 判定编译（可选文件缺失不触发） | 1063–1075 行；必选清单见 WP03 第 4.2 节 |
| PBS 较新 | 每个数据文件与被发现 PBS 的修改时间先截为整数秒，各集合分别取最大值（初始最大值为 0）；PBS 的整秒最大值 ≥ 数据的整秒最大值即判定编译，不按数据类逐一配对 | 1077–1088 行 |
| 全量编译标志或按住 Ctrl | 直接判定编译 | 1090–1091 行 |
| 启动提示（配置） | 调试 + 无 Game.rgssad + `PROMPT_TO_COMPILE = true` 且**用户选择肯定项**时置全量编译标志；**拒绝提示不否决随后新鲜度等自动条件** | `999_Main/999_Main.rb:28–33`；WP02 词典 |

隔离新鲜度条件时，前提为调试模式、PBS 目录存在且有合法被发现并可读的文本、全部必选数据存在可读，无新地图导入、全量编译标志或 Ctrl 等其他触发。对非负时间戳，PBS 1000.1 秒与数据 1000.9 秒均先截为 1000，因此仍触发；不能按亚秒高精度比较判否。相等也触发，其他触发条件独立保留。

### 3.2 异常类别与阶段（WP04-R01 修订）

判定后进入编译（compile_all）。编译主流程的异常按类别与发生阶段分别处理：

| 异常类别/阶段 | 行为 | 证据 |
| --- | --- | --- |
| Reset / SystemExit（任意阶段） | **原样重抛**：跳过诊断、清理与通用错误转换（含按类名识别的 Reset） | 1103–1105 行 |
| 其他异常（清单已建立后） | 打印异常（WP07 诊断面）→ **尝试**逐文件删除数据文件（每个文件的删除错误被忽略，不保证全部删除成功）→ Hangup 转 Reset，其余转 "Unknown exception when compiling." | 1106–1114 行 |
| 早期失败（PBS 缺失分支，数据文件清单建立之前） | load_all/write_all 失败时，清理分支面对的是**尚未建立的清单**，不能沿用普通编译中失败的完整清理预期 | 1044–1051 行 |
| 编译前删除 | 判定编译后、编译开始前**尝试**逐文件删除全部列出数据文件（删除错误忽略）——**不保证全部删除** | 1093–1100 行 |

## 4. WP04-B：输入发现、解析校验与内容依赖

### 4.1 输入发现（引用主规格）

- **普通发现**：顶层 `*.txt` 按"完全基名或基名+下划线"匹配到数据类，最长基名优先，不递归子目录（WP02 第 6.1 节主规格，本文引用）。
- **专用显式入口**：设施名单 `battle_facility_lists.txt` 的 Trainers/Pokemon 字段显式指定输入文件（当前样本 10 个路径，WP02 第 6.1 节主规格）；不能据普通发现不递归就断言专用路径不访问子路径。
- **被发现不等于可成功编译**：普通发现只决定输入归属；编译前改写等固定路径操作仍直接打开固定文件（如 `modify_pbs_file_contents_before_compiling` 打开固定 `PBS/moves.txt`——只有 `moves_extra.txt` 而缺 `moves.txt` 时，前者可被发现，后者按固定路径打开则失败，见 5.2）。
- **候选材料**：备份子目录不被普通发现扫描，也无自动切换机制（WP02 第 6.2 节主规格）；本包不新增切换办法。

### 4.2 活跃解析路径（WP04-R02 修订：本包自立的解析/校验目录）

以下为本轮逐行核实的**当前活跃**文本解析/求值路径；相邻多个标注 Unused 的旧 csv 辅助函数（`001_Compiler.rb:184, 216, 298, 335, 343, 352, 361, 367` 行）**不是现行证据**。

**分词（`split_csv_line`，255–293 行）**：按逗号拆分；含奇数个双引号的分段可能与后续分段合并。去除包围标记有位置条件：只有仍有后续分段供内部检查时，才检查已形成的完整值并可能去标记；末字段不进入该检查。这里每端的标记为一个反斜线 U+005C 加一个双引号 U+0022，共两个真实输入字符（记为 `\"`），不是显示转义。

- 非末字段 `\"PokeBall\",Other` 去除首值包围标记，得到 PokeBall、Other；单值 `\"PokeBall\"` 或末值 `Other,\"PokeBall\"` 保留标记，球标志精确匹配失败。普通 PokeBall 无引号，匹配成功。
- **合并耗尽也不等于去标记**：`Flags` 的完整输入为 `\"Alpha,Beta\"`（没有空白或第三段）时，两个初始分段合成一个值，但已耗尽后续分段，补查也未去掉标记，最终唯一标志仍是完整的 `\"Alpha,Beta\"`。只增加独立尾值 Other，输入 `\"Alpha,Beta\",Other`，首值才在下一次检查去掉标记，最终为 Alpha,Beta 与 Other 两个标志。不得把“合并后两端完整”概括为必然去除。

逐值去除首尾空白；丢弃合并产生的空值。以上位置条件与通用值转换分开。

**记录求值（`get_csv_record`，690–737 行）**：按 schema 逐值求值：

- 首字符 `*`：重复求值直至值耗尽（重复段长度 > 1 时产出子数组数组）。
- 首字符 `^`：可重复属性（多行累加；schema 长度减一）。
- **大写类型字母 = 可选**：值为空/nil 时该位为 nil（如 `vevV` 的第四位）。
- `q`：非格式化文本，整条原始记录原样取用（如图鉴描述），并终止该行求值。
- 其余按类型字母经 `cast_csv_value` 求值（WP03 第 5.1 节模式表：i/u/v/x/f/b/n/s/q/m/e/y）。
- 单值 schema 返回单值，否则返回值数组。

**枚举求值（`checkEnumField`，438–463 行）**：模块枚举按常量名解析；GameData 类枚举按 `exists?` 校验，未定义报 "Undefined value {1} in {2}." 并附位置（WP03 第 5.2 节）。

**属性级规则（WP04-R02 补：分节 → schema 消费 → 校验 → 登记全路径）**：

- **普通重复属性后值覆盖**：同一节内非 `^` 的同名属性出现多次时，**后值覆盖前值**（`001_Compiler.rb:123–128` 的分节写入）。
- **`^` 属性累加**：标记 `^` 的属性多行出现时**累加为列表**，不覆盖（同文件 123–125 行）。
- **通用未知属性不被消费**：通用编译循环只按 schema 列出的键求值（`002_Compiler_CompilePBS.rb:30–60`）；语法合法但不在 schema 中的属性**不会被消费，也不触发通用未知字段错误**（不因此报错）。
- **新身份定义、重复身份、未知引用分开**：
  - **新身份定义**：一个合法、此前不存在的身份可正常登记为新记录（存在性检查只拒绝**已登记**的重复身份，`002_Compiler_CompilePBS.rb:54–60`）。
  - **重复身份**：同一身份的第二个通用节被拒绝（"used twice"，见上条）；专用入口按其各自规则（WP03 第 5.2 节，如训练家同身份后项覆盖）。
  - **未知引用**：引用不存在的枚举值被通用枚举路径拒绝并提供位置（`checkEnumField`，WP03 第 5.2 节）；不能把"新身份未存在"误当成"未知引用"。

**条目级校验**：每个数据类编译时对转换后的条目做类特定校验（如进化方法必需参数、能力值/IV/等级范围、重复处理），随后全量终检（`compile_PBS_file_generic` 第 4–67 行；WP03 第 5.2 节重复/校验锚点，本文引用）。

## 5. WP04-C：编译产物与写回行为

**编译会修改材料，不是只读转换。** 当前快照可见的写回面：

### 5.1 数据文件（.dat）

- 判定编译后、编译开始前：**尝试**逐文件删除全部列出数据文件（删除错误忽略，不保证全部删除）。
- 编译中逐类保存新 .dat（各编译函数末尾的 save）。
- 动画映射有变化时保存 `move2anim.dat` 与 `PkmnAnimations.rxdata`。

### 5.2 PBS 文本改写（编译前）

`modify_pbs_file_contents_before_compiling`（940–947 行）对两处旧属性名自动改名：`PBS/trainer_types.txt` 的 `VictoryME` → `VictoryBGM`，`PBS/moves.txt` 的 `BaseDamage` → `Power`。机制（924–938 行）：整文件读入，有变化才整体重写并提示"Changes made to file X"。**这是固定路径操作**（见 4.3 的交界）。

### 5.3 地图与事件转换（`compile_trainer_events`，1683–1750 行）

- 对**全部地图**的每个事件尝试：训练家注释转换（`Battle:`/`Type:`/`Name:` 等注释编译为正式训练家事件，473–512 行）、道具事件转换（`item:X`/`hiddenitem:X` 命名转为道具球事件，771–800 行；**道具不存在则跳过不转换，也不报错**）、事件名与脚本修正、计数检查；任一变化即保存该地图与 tilesets，并逐条警告"Map X was modified and saved"。
- 公共事件做 `fix_event_use` 修正，有变化才保存。
- 有任何修改时警告"RMXP data was altered. Close RMXP now to ensure changes are applied."。
- 转换规则全集归 WP75；本包只登记"编译会写回地图/公共事件"的事实与边界。

### 5.4 动画映射（`compile_animations`，1274–1319 行）

- 读取 `PkmnAnimations.rxdata`（**读取失败则新建空动画集**）。
- 扫描名为 `Move:X` / `OppMove:X` 的动画，仅当招式 X 已定义时建立映射；有变化才保存 `move2anim.dat` 与 `PkmnAnimations.rxdata`。

### 5.5 反写（write_all 与通用/专用写出）

**调用者（WP04-R03 修订：启动触发与主动导出分开）**：

- 启动触发：PBS 目录缺失时，编译检查先 `GameData.load_all` 再 `write_all`（3.1）。
- 主动导出：调试菜单可直接调用 `Compiler.write_all` 或单个 write_*（`S/020_Debug/003_Debug menus/002_Debug_MenuCommands.rb:1378–1385`）——菜单 UX 归后续包，此处只登记它是真实写入调用者。

**通用写出（`write_PBS_file_generic`，`003_Compiler_WritePBS.rb:4–65`）**：按实际条目的 `pbs_file_suffix` 分组生成输出路径（无对应条目就没有该路径），写 BOM 头与 `[节名]` + `键 = 值`（值经 `pbWriteCsvRecord` 转换，枚举只查已有名称）。**不承诺重建或清理全部旧输入，也不承诺逐字节往返**。

**专用写出（格式不统一为"节名 + 键值"）**：`write_connections`（105–131 行）写行式连接数据，并跳过地图已不存在的连接；`write_encounters`（403–436 行）写遭遇节/方法/槽的专用格式。write_all 共 **22 项内容写出调用**（796–817 行，不含进度输出辅助）。

## 6. WP04-D：失败与部分状态

**不能默认原子性或自动恢复。**

| 阶段 | 可能已发生的变化 |
| --- | --- |
| 编译前 | 尝试逐文件删除全部列出数据文件（不保证全部删除，3.2） |
| 编译中 | 部分 .dat 已重写；PBS 可能已被改名改写（5.2）；MapInfos 可能已登记新地图（3.1）；地图/公共事件可能已转换保存（5.3）；动画映射可能已保存（5.4） |
| 异常时 | Reset/SystemExit 原样重抛（无清理）；其他异常打印后**尝试**再次删除数据文件（不保证全部删除）；Hangup 转 Reset，其余转 "Unknown exception when compiling."（3.2） |
| 早期失败（PBS 缺失分支） | 清理分支面对尚未建立的清单，完整清理预期不成立（3.2） |
| 失败后 | 可能存在：缺失的数据文件、部分编译的 .dat、已改写的 PBS/地图/MapInfos/动画。下次调试启动时，缺失的必选文件再次触发重编译（3.1），但**不保证**上次失败留下的部分状态被识别或修复 |

错误定位：编译错误附 `FileLineData` 位置报告（文件/节/键/行号），由 `FileLineData.clear` 在 compile_all 开始时重置（`001_Compiler.rb:12–40, 1027`）。

| 场景 | 输入 | 推导预期 |
| --- | --- | --- |
| 新鲜度（同一整秒内 PBS 较早） | 调试；PBS 目录存在，有合法被发现且可读 PBS；所有必选数据可读，其他触发关闭；最新 PBS 1000.1 秒、最新数据 1000.9 秒 | 两者先截为 1000，再取各集合最大值；1000 ≥ 1000，新鲜度触发编译 |
| 新鲜度（时间相等） | 同上一新鲜度场景前提；最新 PBS 与数据实际时间均 1000.9 秒 | 整秒最大值相等，仍触发；条件是 ≥，不是 > |
| 新鲜度（集合最大值反向对照） | 同上一新鲜度场景前提；最新 PBS 999.9 秒，两个数据文件分别 900.1 / 1000.1 秒 | PBS 最大值 999，数据最大值 1000，新鲜度不触发；不与其同类较旧数据 900 单独比较 |
| 提示开启但用户拒绝 | PROMPT_TO_COMPILE=true，用户选否 | 不置全量标志；新鲜度等自动条件仍可判定编译 |
| 普通编译中异常 | 清单已建立后异常 | 打印异常；尝试逐文件删除（不保证全部删除）；Hangup 转 Reset，其余转通用错误 |
| 编译中 Reset/SystemExit | 任意阶段 | 原样重抛；不诊断、不清理、不转换 |
| 删除报 SystemCallError | 某文件删除失败 | 该错误被忽略，继续其余文件；不保证全部删除 |
| PBS 缺失且早期失败 | load_all/write_all 在清单建立前失败 | 清理分支面对未建立清单；完整清理预期不成立 |
| 空值与可选模式 | `vevV` 第四位为空 | 该位为 nil；其余照常求值 |
| 引号文本（非末字段） | `Flags` 为 `\"PokeBall\",Other` | 首值在检查区内：恰两个引号且两端为 `\"` → 去除包围标记 → `PokeBall`；球标志匹配成功（is_poke_ball? 为真） |
| 引号文本（单值／末字段） | `Flags` 仅 `\"PokeBall\"` 或 `Other,\"PokeBall\"` | 末字段不进入检查区、初始双引号数恰为 2 时补查也跳过：包围标记与反斜线（真实字符 U+005C／U+0022）**原样保留**；存入带标记文本，球标志精确匹配失败（is_poke_ball? 为假）——GR-001 反例，不得把分词内部有位置条件的去除概括成无条件去除 |
| 引号文本（普通未包围） | `Flags` 为 `PokeBall` | 无引号分支：原样存入；球标志匹配成功 |
| 引号文本（合并耗尽／有独立尾值） | 有效道具的 Flags 完整值分别为 `\"Alpha,Beta\"` / `\"Alpha,Beta\",Other`；每端仅一个 U+005C 和一个 U+0022，无空白 | 前者合并耗尽，唯一标志仍为完整 `\"Alpha,Beta\"`（两个端点标记均保留）；后者首值在后续检查去标记，得到 Alpha,Beta 与 Other。合并本身不保证去标记；本表既有非末值、单值／末值与普通值预期保持 |
| 普通重复属性后值覆盖 | 同一节内 `Name` 两次（非 `^`） | 后值生效 |
| `^` 属性累加 | `^` 标记属性多行 | 多行累加为该属性的值列表 |
| 通用未知属性 | 语法合法但不在该 schema 的属性 | 通用流程不消费、不报错 |
| 新身份定义 | 合法且尚未登记的新道具 ID | 可登记为新记录 |
| 重复身份 | 同 ID 的第二个通用节 | 拒绝"used twice"并提供位置 |
| 未知引用 | 道具 Move 引用未定义招式 | 通用枚举路径拒绝并提供位置（与新身份定义不同） |
| 被发现≠可编译 | 只有 `moves_extra.txt` 缺 `moves.txt` | 前者可被发现；编译前改写按固定路径打开后者失败 |
| 主动导出 | 调试菜单调用 write_all；某作者类无条目 | 按实际条目后缀生成路径；无条目则无该路径 |
