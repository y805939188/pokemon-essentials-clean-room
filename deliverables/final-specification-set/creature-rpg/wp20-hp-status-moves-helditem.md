# HP、异常状态、已知招式与持有状态行为规格（净化正文；批次 9a）

分类：creature-rpg（生命/异常/招式状态的持久层）＋ Pokémon Rules（数值与容量规则）；性质：实现独立行为合同。

本规格为净化正文：按统一交接将批准输入 WP20《HP、异常状态、已知招式与持有状态》转写为独立行为文字，不含源文件路径、类名、行号与证据 URL（参考与已读集中登记于 `../../audit/source-traceability.md` 批次 9a 条目）。文中保留的字段名、入口身份名与配置键均为数据标识，不构成未来实现的数据结构或接口模板。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的、范围与非目标

### 1.1 目的

定义个体持久状态中「生命/异常/招式/PP/最初招式记录/持有物」的可观察规则，及其与战斗内临时状态的边界——哪些写入是持久的、哪些只属于一场战斗、战斗结束时哪些被还原。

### 1.2 范围

1. HP 赋值/濒死/恢复（完整治疗与单项恢复的逐入口核对）。
2. 异常状态与关联计数（值域、设置/拒绝、写入者与归零路径）。
3. 已知招式槽、PP 与上限、最初招式记录、可重学与兼容判定接口。
4. 持有物状态的读取/变更/清除及本规格可证约束。
5. 持久个体值与战斗临时值的边界登记（写穿、可更新的还原记录、重置）。

### 1.3 非目标

- 不定义战斗中异常施加/解除/回合计数、能力阶级、临时标记等机制（WP42/WP44）；不定义呼唤/服从等战斗动作（WP40）。
- 不定义道具的触发/消耗/恢复效果族（WP50）、主动/培养道具流程（WP28）、邮件完整流程（WP64）、球与捕获接收策略（WP38）。
- 不定义学习/替换/放弃的交互主规则（WP30）；本规格只定义招式状态（容量/顺序/PP/记录）与接口事实。
- 不定义进化、寄养、孵化的流程（WP31/WP33/WP35），只登记与治疗/濒死/招式的交界。

## 2. 概念与术语

| 术语 | 定义 |
| --- | --- |
| 持久个体值 | 存入个体、跨战斗保留的字段：hp/totalhp、status/statusCount、moves/first_moves 与每个招式的 PP/PP 提升计数、持有物等。 |
| 战斗临时值 | 只存在于一场战斗的运行时对象中的值（战斗内能力阶级、临时标记、替换用的招式副本等）；本规格只登记边界。 |
| 写穿 | 战斗内对临时对象的某些写入会同时镜像到持久个体（HP/异常/计数/持有物；招式 PP 仅经专门同步入口写回，见 §5.5）。 |
| 可更新的还原记录 | 战斗开始时以各成员当前持有物初始化一份还原记录；战斗中「永久消耗/移出」类效果会更新或清除该记录；战斗结束时把届时的记录值写回成员——不是不可变快照。 |

| 蛋守卫 | 多个治疗/重学/进化相关入口对蛋「直接无效果」（不报错）；本规格逐入口标明。 |

## 3. HP 与濒死

### 3.1 HP 赋值

唯一写入口的规则：

1. 写入值钳到 [0, 当前上限]（上限 = 最近一次能力重算的结果，WP19）。
2. 结果 HP = 0 时：请求清除异常状态与关联计数（该清理入口对蛋直接返回——蛋的既有异常/计数保留）；清除进化准备标记（不分蛋与否，恒执行）。
3. Shadow 扩展（叠加在同一入口上）：结果 HP ≤ 0 时同时清除 Hyper 模式标志（字段语义归 WP23，本规格只登记该叠加）。
4. 上限可能因重算变化；重算的写回规则见 WP19（含濒死个体在上限增加时被复活为增量值的推论）。

派生读取：上限（totalhp）与其余五项能力只由重算写入（WP19）；「能否战斗」与「是否濒死」按 §2 定义（蛋永不进入这两种判定）。

### 3.2 治疗入口

| 入口身份 | 输入 | 前置/守卫 | 结果 | 不改变 |
| --- | --- | --- | --- | --- |
| heal_HP | 无 | 蛋 → 无效果 | 当前 HP = 上限（直接写入，不经 §3.1 的 0 值路径） | 异常/计数、PP、进化准备标记、友好度 |
| heal_status | 无 | 蛋 → 无效果；**无「可用」守卫**（濒死也可调用） | 状态 = 无、计数 = 0 | HP、PP、进化准备标记 |
| heal_PP | 招式索引或「全部」 | 蛋 → 无效果 | 指定/全部招式 PP = 各自总 PP | HP、异常、进化准备标记 |
| heal | 无 | 蛋 → 无效果 | 上三项依序执行 + 清除进化准备标记 | 友好度、来源、拥有者 |
| heal_party（训练家侧全队治疗） | 队伍 | 逐成员按上行 | 同上（逐成员调用完整治疗的封装，WP24） | — |

单项恢复（道具层，归 WP28，此处登记接口事实）：部分回复 HP 的入口按「当前 HP + 回复量 → 超过上限即止于上限」计算后经 §3.1 写入；当「不可用或已满」时，入口拒绝并提示无效果；复活入口仅对已濒死个体生效（否则拒绝），恢复量按道具不同：普通复活（REVIVE）→ ⌊上限 / 2⌋ 且至少 1、随后清除异常；完全复活（MAXREVIVE 及复用其入口的同类道具、REVIVALHERB 等）→ 回满并清除异常（复活草另有友好度代价，归 WP28）。

已定位消费者目录（不穷尽）：战斗失败/平局后的全队治疗（野外收尾层）；特定比赛内失败/黑屏重开时全队治疗（比赛层）；战斗胜利后设施内全队治疗（设施层）；仓库收取时可配置的「存入即治疗」（见 §8；该路径会先保存并恢复进化准备标记）；寄养寄存时治疗（存入时执行；取回不另行治疗——WP33）；解释器「全体治疗」命令（参数 = 0 时：开「存入即治疗」设置则仅队伍，否则队伍+盒子；WP13 引用）；捕获成功且球带治疗效果（WP38）；各状态治疗道具（WP28）。

### 3.3 边界与失败（HP 相关）

- 蛋：上表入口全部无效果（不报错）；蛋的 HP/上限仍存在并可被能力重算写回。
- heal_HP 单独调用不清除异常（若个体有异常且非蛋）；完整治疗才清除——「治疗全部恢复」不可用于描述单项入口。
- 完整治疗不清除友好度/来源/昵称/招式（含每招式的 PP 提升计数）；只把 PP 回满到「含提升计数的总 PP」。
- 非蛋的 HP 为 0 个体，其异常早已在 §3.1 第 2 步被清除；heal_status 对 HP 为 0 的个体（含蛋）可安全调用（蛋为无效果）。
- 直接写入超出上限的 HP：被钳制；负值 → 0 并走清零分支。

## 4. 异常状态与关联计数

### 4.1 状态值域

登记状态（顺序即注册顺序）：NONE（无）、SLEEP（睡眠）、POISON（中毒）、BURN（灼伤）、PARALYSIS（麻痹）、FROZEN（冰冻）。各异常带展示动画名与图标位（图标号按注册顺序；「濒死」与病毒图标在展示资源末尾另行处理——资源规则归 WP15）。个体状态字段初始为「无」、计数 0（创建时经「回复异常」路径写入，WP18）。

### 4.2 状态设置

1. 守卫：个体不可用（蛋或濒死）→ 无效果（不报错）。
2. 解析输入（符号/字符串/记录；未知 → 解析为空）；解析为空 → 报错（提示含输入类型）；输入类型不合法同样报错。
3. 通过 → 写入规范标识；不改变关联计数（计数由战斗层按状态另行设置）。

### 4.3 关联计数语义

- 睡眠：剩余回合数（战斗回合解释归 WP44）。
- 中毒：0 = 普通中毒；1 = 剧毒标志（与战斗层的剧毒计数标记配合，机制归 WP44）。
- 其余状态：无独立语义（战斗层不对其写入有意义的计数）。
- 演变：战斗收尾时「中毒且计数 > 0 → 计数归 0」（坏毒转为普通毒，见 §4.4）；创建/完整治疗时计数 0。

### 4.4 已定位写入者目录（不穷尽；机制归相应规格）

| 写入者 | 结果 |
| --- | --- |
| 战斗内状态/计数设置与睡眠递减（WP44） | 写穿到持久个体（§5.5） |
| 野外收尾（战斗结束后清点） | 中毒且计数 > 0 → 计数 0 |
| 完整治疗/回复异常（本规格 §3.2） | 状态 = 无、计数 = 0 |
| 状态治疗道具（WP28） | 调用「回复异常」 |
| 捕获存储流程（弹出队员到盒子） | 对该成员执行同样的「坏毒转普通」清理 |
| 调试（对照） | 直接读写状态/计数 |

### 4.5 边界与失败（异常相关）

- 不可用个体上设置状态：静默无效果（包括用非法值——守卫先于校验）。
- 计数存储无域校验（写入者自行约束）；负数/过大值按原样保存（正常入口不产生）。
- HP 归零时状态被清除（非蛋；蛋保留既有异常/计数）——「濒死者仍带异常」的中间状态不持久。

## 5. 已知招式、PP 与最初招式记录

### 5.1 招式槽状态

- 常规初始化与学习界面使用 4 槽；**存储列表没有统一四项硬限制，也允许零项**。列表有序，元素为「招式对象」，持有招标识、当前 PP、PP 提升计数（每 1 次 +20% 总 PP，见 §5.4 公式）。
- 计数/查询：数量 = 列表长度；「是否知道招式 X」= 任一元素招标识等于 X 的规范标识（未知 X → 否，不报错）。
- 静默学习（入口身份 learn_move，供训练家装载/战斗中升级等直接调用）：
  1. 未知招式 → 无效果；
  2. 已知道 → 把该元素移到列表末尾（顺序变化、PP/计数保留、不新增）；
  3. 不知道 → 追加新招式对象（PP = 总 PP、提升计数 0）；若长度 > 4 → **仅移除首项一次**。起始长度 ≤4 时结果 ≤4；起始长度 5 时结果仍为 5，不循环截断。
- 删除：按招式标识删除（未知/不存在 → 无效果）；按索引删除时，长度 n 的有效整数索引为 `−n ≤ i < n`，负索引对应 `n+i`（−1 为末项、−n 为首项）；其它整数索引无变化。空列表没有有效索引；清空全部后数量为 0。调用方的取消哨兵须另作判断，例如调试选择先要求索引非负，不能据此把直接删除的 −1 写成无操作。
- 初始化（入口身份 reset_moves，创建/形态复检/训练家装载/等级缩放等调用）：按当前等级的物种「等级→招式」学习表，取等级 ≤ 当前等级的全部条目；按出现顺序去重且保留每种招式的最新一次；取末尾至多 4 项（即当前等级下最近学会的 ≤4 招）；每项新建招式对象（PP 满）。
- 直接替换整表：字段本身可整体写入，五个合法招式对象也保存全部五项，不自动截断；数量、整表首招记录与复制均保留该长度和顺序（重复标识的记录规则见 §5.2；复制语义见 WP18）。四项初始化保证不能反推所有列表入口；战斗中替换招式副本属战斗层，§5.5。
- 零招式跨界：关闭默认招式的创建、清空或 ROTOM 同值裸提交均可形成合法空列表。非蛋摘要 MOVES 页显示四个空占位；按 USE 进入详情时读取首招的伤害展示值失败，尚未进入可处理 BACK 的选择循环。直接进入遗忘画面（含事件选招、给定待学招的直接遗忘调用）也先访问空的首招而失败。相反，普通非蛋非 Shadow 个体从空列表学习合法招式走空槽成功分支，不调用满槽遗忘画面。这里登记模型与调用边界；完整界面责任仍归 WP66A。

### 5.2 最初招式记录（GR-008 更正后表述）

- 整表记录（入口身份 record_first_moves）：先清空，再把当前全部招标识依序复制入记录——**不做去重**：当前列表中的重复标识与顺序原样进入记录（当前列表可经 §5.4 招标识赋值等合法入口形成同标识两槽，PP 钳制规则不变）。
- 逐项入口：加入（未知 → 无效果；记录已含同标识 → 不再追加——但只阻止追加本身，不清除记录中已有的重复）／删除（未知 → 无效果；按标识删除全部同标识项）／清空。
- 已定位记录调用点（获得/转化时刻）：存入盒子/队伍前（赠送工具路径）；静默送出/送出到队伍（另一组赠送工具）；孵化完成；交换接收；捕获成功；神秘礼物；净化补记；调试（对照）。含义：记录「获得时刻的招式集」，供可重学功能使用。
- 逐项追加调用差异：**背包直接使用 TR** 经教学选择成功后，把所学招式追加到首招记录（已有则不重复），随后按道具属性消费；**队伍 Item → Use** 直接对已选成员教学成功并消费，但没有该记录追加。通用学习本身不自动补记；确认取消、拒绝或未学会均不追加。TM/HM/TR 按实际数据字段区分，例如具名 TM57 的字段为 TR、教学招为 CHARGEBEAM，不能仅凭名称把它当作非消耗 TM。教学统计与外层资源顺序归 WP28/WP30/WP66A。
- 消费方：招式重学界面——把记录作为候选来源之一（受配置开关控制「是否可教更多招式」）；以及可重学判定（§5.3）。
- 边界：记录与当前招式相互独立（之后学习/遗忘不自动同步记录；记录为空 ≠ 无候选）。

### 5.3 重学与兼容接口

- 可重学判定（入口身份 can_relearn_move?）：蛋或 Shadow → 否；否则：存在「等级 ≤ 当前等级、且当前未掌握」的等级学习表条目 → 是；或存在「记录中而当前未掌握」的招标识 → 是；否则否。
- 重学界面候选：先取等级 ≤ 当前等级且未掌握的等级招；「可教更多招式」开启时，再把记录中未掌握、未在等级候选中的招放在等级候选之前，最后去重。**不会直接追加物种整个蛋招表**；孵化时曾记录的蛋招或背包 TR 追加项只是通过首招记录进入。界面开关关闭时不追加记录，而个体的可重学判定仍按上条检查记录，两入口不能合并。
- 兼容判定（入口身份 compatible_with_move?）：未知招式为否；否则命中以下之一即为是——教学表（TM/教学）、等级学习表、蛋招式表（本物种蛋招式表为空时回退到前进化物种的蛋招式表）。
- 学习/替换的交互主规则（何时问、放弃、满槽处理）归 WP30；本规格只定义上述判定函数的行为。

### 5.4 招式对象与 PP 规则

- 总 PP（派生）：总PP = 基础PP + ⌊（基础PP × 提升计数）/ 5⌋（每 1 次提升 +20%，整除下取整）。向量与极端值见 WP19。
- 当前 PP 赋值：钳到 [0, 总PP]。
- 招标识赋值：改为新招式后，当前 PP 钳到「新招式的总 PP」（提升计数保留）。
- 提升计数赋值：写入任意整数（不钳位）；该调用随后即把当前 PP 按新总 PP 钳制。
  - 边界（静态）：提升计数过负（如 −6、基础 PP 20）→ 总 PP 变为 −4，写入提升计数的调用本身在钳制当前 PP 时失败（钳位区间反转：下界 0 > 上界 −4）；失败时提升计数已写入（−6）、当前 PP 保留原值；此后再做任何 PP 赋值仍会失败。正常入口不产生负计数。
- PP 恢复入口：完整治疗/回复 PP（§3.2）；道具层单项恢复（校验「槽位存在且招标识有效」与「总 PP > 0」，否则返回 0 不生效；回复量按总 PP 截断）；战斗内恢复道具在满足「同招标识且未变身」时同步战斗侧副本（WP42）。
- PP 消耗（战斗层）：战斗内经专门同步入口消耗——读包装对象、写其 PP，并在「原招式关联存在 + 标识相同 + 未处于变身」时写回持久对象的当前 PP（§5.5）；直接给包装对象写 PP 字段不触发该写回；多回合招式进行中不重复扣减、负 PP 的特殊调用不扣减、总 PP ≤ 0 视为无限（机制归 WP42，本规格登记边界事实）。

### 5.5 持久/战斗临时边界（招式与 PP，登记）

- 战斗开始时以持久招式列表逐项包装为战斗招式对象（各自持有独立 PP 数值与对原对象的关联；包装对象的 PP 只是一个独立字段）。
- 战斗中 PP 的三层区分：① 直接给包装对象写 PP 字段 → 只改战斗侧数值；② 经专门同步入口的设置/扣减 → 写包装对象，并在「原招式关联存在 + 标识相同 + 非变身」时写回持久对象的 PP；③ 变身/模仿等替换或复制出来的招式（无关联或标识不同）→ 永不写持久侧，战斗结束不保留。
- 战斗中升级学到新招式：持久列表更新后同步到战斗侧对应槽（战斗层流程，WP42）。
- 战斗结束：持久侧无需整体回写（同步入口已在过程中写回所需数值）；捕获的个体会被补记最初招式（§5.2）。
- 蛋的招式内容主要由孵化流程驱动（WP35）；学习/遗忘接口本身不含蛋守卫（守卫在各消费者/流程层）。

## 6. 持有物状态

### 6.1 读取

- 持有物记录读取：按标识解析（未知 → 空）；另有原始标识读取（未经解析）。
- 「是否持有」：无参 → 当前是否持有任意物；带参 → 当前持有物与给定项是否同一（比较语义接受符号/字符串/记录，WP03）；未持有时返回否。
- 物种「野生持有物池」读取：常见/少见/稀有三级池（各为列表）；生成侧按概率选取（WP36）。

### 6.2 变更与清除

- 设置规则：值非空且不是已登记道具 → 静默无效果（无提示）；空值 → 清除持有物；其余 → 写入规范标识。
- 入口差异（按行为登记）：个体字段入口（本节的设置规则）对未登记标识**静默忽略**；战斗侧对象的持有物入口对同一未知标识会解析为空并经由写穿**清空**个体持有物（§6.4 路径）——两个入口的失败结果不同，不能合并描述。
- 本规格不提供「取出/交给」的交互流程（队伍界面、道具使用、战斗效果均归各自规格）；本规格定义的是字段层行为与约束。

### 6.3 约束（本规格可证）

- 邮件耦合：邮件记录读取时若「邮件缺失或邮件对应道具与当前持有物不一致」→ 自动清除邮件；邮件写入只接受邮件对象或空值（其它报错）；邮件建立时若已有邮件 → 报错（邮件流程归 WP64）。含义：更换/清除持有物可隐式使邮件失效。
- 持有物与「所在球」是两个独立字段（球标识由捕获写入，WP18/WP38）。
- 进化消耗（特定进化条件持有物的清除，WP31）、战斗内效果（偷取/打落/消费等，WP42/WP50）与战斗还原记录（§6.4）分别经各自入口；不要概括为「所有入口遵守同一校验」——战斗侧入口对未知标识的行为与个体字段入口不同（§6.2 入口差异）。

### 6.4 战斗内变更与可更新的还原记录（登记）

- 战斗内持有物的战斗侧写入写穿到持久个体（战斗层对象写入时同时写个体；未知道具在其中解析为空并清空，见 §6.2 入口差异）。
- 战斗开始时以各成员当时的持有物初始化一份还原记录；该记录可在战斗中更新：当道具被永久移除（正常消耗/失去，且当前值与记录相同）时记录同步清除；副作用明确的「永久取得」（如对野生目标的夺取）可把记录更新为取得项；暂时移除（如打落）保留原记录。
- 战斗结束时：对仍在队伍中的成员执行「持有物 = 届时的记录值」。由「记录 vs 当前值」可推出：
  - 正常消耗且未再获得 → 记录与当前均空，战后仍为空（不返还）；
  - 暂时打落且记录未改 → 当前空、战后还原原持有物；
  - 记录被更新过的合法路径（永久取/失）→ 战后按更新后的记录值。
- 捕获个体：若加入队伍，则在加入时把当前持有物登记进记录（战后按登记值，保留捕获时持有物）；若直接送箱，则不在队伍还原循环内（保持当前值）。
- 特殊路径（静态登记，未穷尽）：把队伍成员转送盒子（捕获时满队选择）的成员从队伍移除、不在结束还原循环内，记录与相关数组按移位维护；两条路径（转送盒子 vs 留在队伍）在「届时持有物与记录值相同」时结果可能一致，不预断差异——完整语义归 WP38/WP50 前向。
- 各效果族对还原记录的更新点由 WP50 完整定义；本规格只定义「记录可更新 + 结束读取记录」的交界，不展开效果族。

## 7. 规则与不变量

1. HP ∈ [0, 上限]；HP = 0 ⇒（非蛋个体）状态 = 无、计数 = 0（蛋保留既有异常/计数——清理入口带蛋守卫）；进化准备 = 假（不分蛋与否，恒执行）；Shadow 扩展清 Hyper 标志（叠加恒执行）。
2. 蛋对治疗/异常设置/重学/进化相关入口一律「无效果」；蛋的 HP 仍受重算写回。
3. 异常状态设置只对可用个体生效；未知值报错、非法类型报错；设置不改计数。
4. 关联计数只对睡眠/中毒有语义；中毒计数在战斗收尾归 0。
5. 四槽是初始化与常规学习界面的限制；整表存储可为零项或超过四项。静默新增超出时只移除首项一次；初始化重取最近 ≤4 招；列表顺序是状态的一部分（静默学习已会招式移到末尾）。
6. 每招式的「总 PP」由基础 PP 与提升计数派生（§5.4 公式）；正常合法状态下当前 PP ∈ [0, 总 PP]（成功赋值的结果）；极端负计数的失败路径下旧 PP 可留在区间外（§5.4 边界）；提升计数自身无域校验。
7. 最初招式记录与当前招式相互独立；记录 = 某时刻招标识的副本。「不重复」只限定到逐项添加入口：整表记录清空后逐项复制当时全部标识，保留重复与顺序；逐项添加只阻止对已含标识的再追加，不清除已有重复（GR-008）。
8. 持久/临时边界：HP/异常/计数/持有物写穿；招式 PP 仅经专门同步入口写穿（直接字段赋值与替换/复制招式只在战斗侧）；战斗结束对队伍成员按届时的还原记录写回持有物。
9. 持有物字段设置只接受已登记项或空值（未知项静默忽略）；战斗侧入口把未知项解析为空并清空（入口差异）；邮件随持有物不匹配自动失效。

## 8. 边界与失败

- 「回复 PP」按索引且索引越界（≥ 槽数）：运行错误（正常入口用「全部」或有效索引）；空槽（有槽位但招标识为空）由道具层守护（返回 0），字段层不守护。
- 提升计数极端负值：见 §5.4 边界（写入调用内的钳制失败：计数已改、PP 保留）。
- 状态设置：不可用个体静默；未知标识/非法类型报错（守卫先于校验）。
- 计数直接写入任意整数：原样保存。
- 持有物设置未知项（个体入口）：静默忽略（不是报错，也不清除）；战斗侧入口则解析为空并清空。
- 邮件耦合的隐式清除：更换持有物即可使邮件读取为空。
- HP 直写超过上限：钳制；负值 → 0（走清零分支；蛋的异常/计数保留）。
- 还原记录边界：见 §6.4（转送盒子路径与效果族更新点未穷尽）。
