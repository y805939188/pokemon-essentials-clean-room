# 玩家、NPC 训练家与伙伴行为规格（净化正文；批次 9a）

分类：creature-rpg（身份/资源/许可；伙伴语义）＋ Pokémon Rules（服从/徽章等具体判定引用）；性质：实现独立行为合同。

本规格为净化正文：按统一交接将批准输入 WP24《玩家、NPC 训练家与伙伴》转写为独立行为文字，不含源文件路径、类名、行号与证据 URL（参考与已读集中登记于 `../../audit/source-traceability.md` 批次 9a 条目）。文中保留的字段名、入口身份名与配置键均为数据标识，不构成未来实现的数据结构或接口模板。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的、范围与非目标

### 1.1 目的

定义玩家与 NPC 训练家的身份、外观、资源与许可，以及伙伴的注册/参与语义——供个体拥有者/外来判定（WP18）、战斗参与（WP39 引用）、集合与获得流程（WP25/WP26）与 UI（图鉴/训练家卡等）引用。

### 1.2 范围

1. 身份、外观与标识：训练家基础字段、玩家扩展、玩家内容（编号/套装/字符集/回家点）、初始命名，及其与 WP18 拥有者的关系。
2. 资源与许可：金钱/游戏币/对战点/火山灰的域与写入者；徽章与功能标记的读取消费者。
3. NPC 训练家数据与装载：训练家类型目录、训练家记录（版本）、装载流程、缺失数据反馈与调试新增路径、队伍生成覆盖次序。
4. 伙伴：注册/注销、参与资格、战斗内拼接与战后处理、与野外流程的交界。

### 1.3 非目标

- 不定义战斗准备/布局的完整规则（WP39）、AI 行为技能（WP51）、服从性判定（WP40 引用本规格徽章/等级输入）。
- 不定义收藏集合（WP25）、赠送/交换完整流程（WP26）、图鉴规则（WP62）、神秘礼物完整流程（WP64）。
- 不定义编辑器/调试菜单的完整 UI（WP73）；调试路径仅作对照登记。
- 不重复 WP18（个体/拥有者字段）与 WP02（配置值清单）；不设计未来框架的账号/存档 API。

## 3. 身份、外观与标识

### 3.1 训练家基础字段

- 字段：类型（规范标识）、名字（可写）、标识（32 位整数，可写）、语言（可写；初始化来源为宿主语言映射，见下条）、队伍（数组，可写）。
- 标识双半：公开号 = 低 16 位；秘密号 = 高 16 位；均可对给定值计算。生成：初始化时 32 位随机。
- 外来标识：生成「任意其它」32 位随机且不等于自身的标识（供外来拥有者构造，WP18 引用）。
- 显示名：类型名 + 名字；类型带 NoName 标记时只显示名字（WP03 数据）。
- 语言（GR-009 更正后表述）：初始化（构造）时读取宿主系统用户语言前两字符的映射——ja→1、en→2、fr→3、it→4、de→5、es→7、ko→8、其余（如 zh）→2；此处不读取语言目录或系统语言选项。界面消息文件选择索引（WP08：玩家选项 → 系统语言选项 → 消息文件）与个体来源语言编号是两种独立身份与读取时刻；后续 UI 语言切换不回改已构造训练家的语言字段（WP08 的切换只写系统选项与消息/存档，不触碰训练家/Owner 字段）。未读取真实主机语言补证。
- 派生查询（不穷尽）：可战斗成员计数、首/末可用成员、是否拥有物种/招式/属性、全队治疗封装等——集合约束主规格在 WP25。

### 3.2 玩家扩展

| 字段 | 域与规则 | 说明 |
| --- | --- | --- |
| character_ID | 整数玩家编号（初始化 0）：原始字段赋值不做范围/存在性校验（仅同值早退；写入后在地图角色对象存在时刷新字符集——写入与刷新有先后、失败不保证回滚）；包装切换入口见 §3.3 | 触发字符集刷新（WP12/WP16 渲染交界） |
| outfit | 套装编号（整数）；写入同样触发字符集刷新 | 与玩家编号共同决定外观（§3.3） |
| badges | 布尔数组（默认 8 位）；训练家卡读取可跨「地区 × 8」扩展索引 | §4.2 |
| money / coins / battle_points / soot | 整数，写入入口钳到各自上限；非法类型报错（校验） | §4.1 |
| pokedex | 图鉴对象（创建即有；是否「获得」由图鉴标记区分） | 规则归 WP62 |
| 功能标记 | 见 §4.3 表 | 读取侧消费者明确；写入侧多为事件（缺口） |
| mystery_gifts | 已下载礼物数据数组 | 流程归 WP64 |
| trainer_type | 覆盖：由玩家元数据的当前编号解析（不是 Trainer 的基础字段） | §3.3 |

图鉴便捷查询：seen / owned 直接转发图鉴对象（WP62 引用）。

### 3.3 玩家内容与初始命名

- 玩家元数据：编号 → 训练家类型 + 7 个字符集键（行走/奔跑/骑行/冲浪/潜水/钓鱼/冲浪钓鱼；未定义项按链式回退：奔跑缺省用行走、骑行用奔跑、冲浪用骑行、潜水用冲浪、钓鱼用行走、冲浪钓鱼用钓鱼）+ 回家点（地图与坐标朝向；失败回程消费者归 WP11/WP13 交界）。编号为数字键（与其它内容数据的符号键不同）；按编号取记录时，未登记的编号回退到记录 1（记录 1 也缺失才取不到）。
- 切换玩家（包装入口）：编号 < 1 拒绝（false、无改动）；否则按元数据取记录（未登记编号回退记录 1）；仍取不到才拒绝；成功则写 character_ID（负担字符集刷新）。注意：编号 99 未登记但记录 1 存在时切换会「成功」——存储 99、内容（训练家类型/字符集）按回退记录 1 读取——不能笼统写成「未登记即拒绝」。
- 初始命名流程（静态核对）：
  1. 若当前玩家编号 < 1 → 先切换到编号 1；
  2. 未提供名字时弹出名字输入（长度上限 = 配置值 10）；取消/空输入 → 生成建议名：先取系统用户名第一个词，仅在非空且长度**严格小于**上限时接受并将首字母大写；否则去掉该首词尾部连续数字，再以同一条件判断。两次判断中，长度等于上限也继续下一阶段。仍不接受时，将**完整系统用户名**按首字母大写、其余字母小写处理后截取前上限个字符（「随机名字」分支不可达，按行为记录，不作为设计依据）；
  3. 写入玩家名字与套装编号（outfit 参数）。
- 角色字符集选择（消费者）：按「潜水/冲浪/骑行 > 行走」的优先级从元数据取字符集；玩家编号/套装变更时刷新（WP12 运动状态处引用）。

### 3.4 与 WP18 拥有者的关系

- 拥有者构造读取训练家的标识/名字/性别/语言：**性别来自训练家类型**（不是训练家字段）；语言来自训练家字段（Owner 由训练家构造时逐项复制现有字段值）——默认初始化时该值为宿主语言映射编号，字段被改写后复制的是改写值（不重新读取宿主）；UI 语言切换不回改已有训练家/Owner 的语言字段（§3.1，GR-009）。
- 外来判定只比较标识与名字（WP18 引用）；伙伴注册会把其队伍成员的拥有者重设为该训练家本人（§6.1）。
- 玩家标识的用途（异色判定输入、外来判定）见 WP18/WP19 引用；本规格只保证「玩家标识在初始化时生成且可写」。

## 4. 资源与许可

### 4.1 资源域与写入者目录

| 资源 | 域 | 写入入口行为 | 已定位写入者 |
| --- | --- | --- | --- |
| 金钱 | 0 .. 999,999（配置） | 非法类型报错；钳位 | 事件命令（增减）；商店交易写回（WP29）；战斗胜利/失败结算（§4.4）；迷你游戏（WP68 系列）；调试 |
| 游戏币 | 0 .. 99,999 | 同上 | 迷你游戏（WP68）；调试 |
| 对战点 | 0 .. 9,999 | 同上 | 对战点商店（消费写回并累计「已花费」统计；BP 兑换属 WP29）；调试；「已赢得」统计的写入来源仍未定位（归 WP55/WP77） |
| 火山灰 | 0 .. 9,999 | 同上 | 通用迈步中的条件采集（玩家且持煤灰袋；钳位后实际增量，见下文）；调试 |

煤灰处理分三个合同层次，前提为通用迈步通知已到达、当前实格及地形记录有效、资源/统计访问正常，无外部改写：

- 找到目标层：按层 2 → 1 → 0 查找首个煤灰草，只处理首层。通知资格与全局计步由已接受 WP12/WP13 及步进交界承接；不能把普通移动许可或全局步数增加当成采集资格。
- 条件采集与统计：仅通知携带的事件是玩家且玩家持有煤灰袋时，先请求资源 +1，再按钳位后的实际增量增加累计采集统计。默认上限 9,999；达到上限时资源和统计增量都是 0。
- 图块擦除：正常处理随后清空目标层并停止扫描。NPC、无袋玩家或持袋但已达上限的玩家仍清空首层；其它层保持。一次通知只擦一层，多层需要另一次通知才能继续处理。采集写入、统计和擦除有先后，失败不保证撤销已提交的状态；真实事件链可达性未证。

读入口（不穷尽）：消息格式化（金额/BP 文本）、商店界面、训练家卡、调试。

### 4.2 徽章与许可

- 存储：布尔数组（默认 8 位）；计数 = 真值个数。
- 消费者（已定位）：
  - 场地招式许可：配置开关选择口径——默认按「数量 ≥ 需要数」；变体为「按具体位」（即第 N 个徽章是否存在）；具体招式需求数值归内容数据（WP12/WP13 交界引用）。
  - 服从性：徽章计数换算可服从的等级上限（战斗规格引用；完整判定 WP40）。
  - 训练家卡显示：按「地区 × 8」扩展索引读取。
  - 失败罚金：见 §4.4 的倍数档。
- 写入者：核心脚本中未定位（仅调试工具可整批置真；可能由道馆事件写入，保留未决）。徽章获得时间统计字段的写入声明在事件侧（WP06 统计目录引用）。

| --- | --- | --- |
| 已获得图鉴 | 图鉴相关菜单显示（WP62/WP66 交界） | 未定位（事件驱动） |

### 4.4 战斗内金钱结算（调用玩家写入入口的两个入口）

- 入口守卫：两个结算入口都要求「内部战斗」且「启用金钱结算」；失败结算另要求「不损失金钱」开关关闭。任一不满足 → 整体跳过。
- 胜利所得（两个先后执行的阶段）：① 训练家战奖励 = Σ（各对手队伍最高等级 × 其训练家类型的基础资金）——「护身金币/快乐时光」各 ×2；② 「聚宝功」累积额——同样受两倍加成。每阶段各自：读取旧额 → 写入（受上限钳位）→ 计算实际变化 → 仅当实际变化 > 0 才累计统计并显示提示；某阶段实际变化为 0 时该阶段不显示提示、也不增加统计（不是「显示 +0」）。
- 失败所失：取玩家队伍最高等级（不含伙伴队伍）；倍率按徽章计数档位（8/16/24/36/48/64/80/100/120，计数超出取最后一档）；损失额不超过当前金钱；写入并记录实际损失统计（实际损失 > 0 时提示）。
- 边界：上限由写入钳位；已达上限时正奖励不产生变化 → 不提示、不统计；两阶段共享同一上限时的先后差见测试目录。

## 5. NPC 训练家数据与装载

### 5.1 数据责任

- 训练家类型：显示名、性别（男/女/未知或混合——未知映射 2）、基础资金（显示「金额 × 最高等级」）、技能档（AI 消费，WP51 引用）、标记（NoName 等）、三类 BGM（战斗前/中/胜利）。
- 训练家记录：类型 + 名字 + 版本 + 队伍条目；队伍条目字段（从装载消费面核对）：物种、等级、形态、持有物、招式列表、特性索引/显式特性、性别、异色/超级异色、性格、IV/EV、友好度、昵称、球、Shadow 标记——个体生成细节与覆盖次序归 WP18（引用）；本规格负责数据责任与装载流程。

### 5.2 装载流程

1. 解析训练家类型：未知 → 报错。
2. 按（类型， 名字， 版本）查训练家记录：不存在 → 返回空（由调用者处理缺失，§5.3）。
3. 存在 → 转换为可战斗训练家：显示名可被对战变量替换（「对手名数组」配置：类型匹配且变量为非 0 字符串 → 用变量值）；标识 = 外来标识；物品列表克隆；胜负台词；队伍逐条按 WP18 的生成覆盖次序构建；收尾重算。

### 5.3 缺失数据反馈与调试新增路径（与正常路径分开）

| 入口 | 非调试行为 | 调试行为 |
| --- | --- | --- |
| 训练家检查（事件调用） | 直接放行（不检查） | 类型缺失 → 提示可新建类型（调试编辑入口）；训练家（版本）缺失 → 提示「新增变体？」并可生成 |
| 缺失训练家（装载失败兜底） | 报错（含类型/名字/版本信息） | 提示「新增训练家？」；选择「是」→ 交互式新建 |
| 交互式新建 | —（不可达） | 循环录入队伍成员（首个必须录入；物种选择 + 等级范围 1..等级上限、默认 10）；可选写回：注册到记录并写回数据文件（训练家类型/训练家两个文件；写回机制归 WP04）、提示已写入 |
| 空闲版本查找 | — | 0..255 内首个未占用的版本号；全部占用 → −1 |

调试新增的产物与作者数据同构（写回数据文件即成为正常数据）；本规格只登记行为，不设计未来编辑工具。

### 5.4 逻辑音频选择与引子记忆边界

本节输出曲目请求及引子请求交付播放入口前的记忆状态。前提是类型/元数据及选曲所需对象有效，曲目转换正常，无插件或并发回调改写；请求不等于实际发声。曲目 A/B/M/G/X 均为具名有效内容夹具；空文本对照只限作者确实储存该值的有效类型记录，不推定默认内容文件会产生空文本。

| 入口 | 优先选择 | 无有效候选时的回退 | 固定默认曲目 |
| --- | --- | --- | --- |
| 野生开战 | 下一战战斗曲预置 | 本图野生战斗曲 → 全局野生战斗曲 | `Battle wild` |
| 野生胜利 | 下一战胜利曲预置 | 本图野生胜利曲 → 全局野生胜利曲 | `Battle victory` |
| 野生捕获成功 | 下一战捕获成功曲预置 | 本图野生捕获成功曲 → 全局野生捕获成功曲 | `Battle capture success` |
| 普通训练家开战（单个或有序数组） | 下一战战斗曲预置；否则取数组最后一个非 nil 的类型战斗曲字段 | 最后所得为 nil 或空文本时：本图训练家战斗曲 → 全局训练家战斗曲 | `Battle trainer` |
| 普通训练家胜利（单个或有序数组） | 下一战胜利曲预置；否则取数组最后一个非 nil 的类型胜利曲字段 | 最后所得为 nil 或空文本时：本图训练家胜利曲 → 全局训练家胜利曲 | `Battle victory` |
| 直接按训练家类型取战斗曲的辅助入口（FromType） | 下一战战斗曲预置；否则直接取该类型的非 nil 字段，含确实储存的空文本 | 类型字段为 nil 才查本图训练家战斗曲 → 全局训练家战斗曲 | `Battle trainer` |

地图元数据缺失或对应地图字段为 nil/空文本时跳到全局；全局字段为 nil/空文本时取对应默认。三个下一战预置独立，存在有效预置时先返回对应请求，不用其它种类的预置替代；选择本身不清预置。普通训练家数组按给定顺序检查：后项 nil 不覆盖前项，后项非空 B 覆盖 A，后项确实储存的空文本也覆盖 A，但随后因为空而落地图回退。直接类型辅助则保留空文本返回值，不落同一回退，也不承诺与普通入口相同的请求表示。在固定脚本静态检索中仅定位其定义，未定位普通消费者；这个限制不排除动态调用或插件。

训练家类型引子为 nil/空文本时，本入口不发引子请求，也不改下表的记忆/待播计时。引子为有效非空 I 时，先完成以下状态选择，再交付 I 请求：

| 引子请求前状态 | 记忆与待播计时结果 |
| --- | --- |
| 已有回程曲备忘 R/位置 r | 保留 R/r；本记忆选择阶段不改已有待播计时 |
| 无备忘；待播计时标记存在且有效待播曲为 Q | 取消待播计时，记忆 Q、位置 0；当前曲不覆盖 Q |
| 无备忘；无待播计时标记 | 记忆当前曲及当前位置；仅位置查询失败时位置取 0 |

这些是请求交付前的状态，未将之后播放、帧通知、媒体或宿主结果并入后置条件。记忆写入/待播计时取消可先于后段失败，不默认回滚。播放、音量、默认 BGM 覆盖与暂停/恢复继续引用 WP15；战前包装读取/恢复记忆及清下一战预置引用 WP16；捕获成功等待引用 WP67-A；地图/载具音频请求与移动完成引用已接受 WP11/WP12，不能由移动 BGM 推导本表选曲。真实发声、恢复位置和素材/宿主/插件组合未验证。源追踪：固定 `Data/Scripts/019_Utilities/003_Utilities_BattleAudio.rb` 1–149 及具名开战/胜利/捕获/事件引子消费者，范围身份见本轮作者后继证据。

## 6. 伙伴

### 6.1 注册与注销

注册（伙伴注册入口（类型， 名字， 版本））按实现顺序：

1. 先解析训练家类型：未知 → 报错——此时载具未取消、伙伴槽未动；
2. 取消载具（载具清理归 WP12）；
3. 装载训练家（§5.2；记录缺失 → 空）：扩展点按正常返回时，随后访问其队伍会因空对象失败——此时载具已取消、旧伙伴槽尚未替换（不假定原子回滚）；
4. 触发「训练家装载」事件扩展点（WP05 引用；处理器可改动训练家）；
5. 把其队伍成员的拥有者设为该训练家本人（「非外来」仅相对该伙伴训练家而言，不默认等于相对玩家）并逐个重算；
6. 记录伙伴：[类型， 名字， 训练家身份标识（不是声明时的「版本」）, 队伍]——传入的版本号不保存。

伙伴数据的再次读取（快照行为）：战斗侧再次读取伙伴道具数据时，把所存的身份标识当作第三个「版本」参数查询训练家记录——该键未命中才得到空道具列表；仅「标识不同于原注册版本」不能保证没有另一变体命中——若恰好存在该标识值对应的另一版本，会读取到它（不保证来自原注册记录；只记录行为、不修参考）。

重复注册 = 替换（再次注册覆盖伙伴槽；旧记录不另行清理——静态语义）。

注销：伙伴槽置空（无其它清理副作用）。

### 6.2 参与资格（战斗侧读取）

- 可行性查询（战斗前的编成判断，与下一项是不同的入口）：双打 = 玩家可战斗成员 ≥ 2，或（有伙伴且可战斗成员 ≥ 1）；三打 = ≥ 3，或（有伙伴且 ≥ 2）。
- 本次伙伴参与谓词（按实现的实际分支顺序）：① 无伙伴或规则禁用（noPartner）→ 假；② 敌方队伍成员数 > 1 → 真；③ 否则若显式指定规模：单打（或「1v…」）→ 假，其它 → 真；④ 其余 → 假。（不把「单打/多目标野生」等称呼当作条件本身；完整布局归 WP39。）
- 参与时：伙伴作为玩家侧第二训练家，其队伍追加在玩家队伍之后并入战斗队伍（起止索引记录）；伙伴道具从其训练家数据读取（克隆；见 §6.1 的再次读取行为）。

### 6.3 战斗内与战后

- 伙伴队伍成员在战斗中按普通成员处理（含形态进入/离开触发，WP21 引用）。
- 战后清理分两个独立分支：① 伙伴在场 → 玩家全队治疗 + 伙伴队伍逐成员完整治疗并解除 Mega/Primal（每次战斗结束；含未参战情形——按调用位置静态登记）；② 败北/平局 → 另行对玩家队伍全队治疗——该分支另有「可失败（can_lose）」前提，不满足时不执行。两分支不可合并描述。

### 6.4 与野外流程的交界（已定位调用点）

- 漫游个体流程在「伙伴在场」时跳过（具体条件归 WP37 引用）。
- 野生遭遇入口在「伙伴在场」时返回特定结果（细节归 WP36 引用）。
- 雷达启动要求未骑车；伙伴不是启动拒绝门。许可仍依次检查可摇且有陆地遭遇的地形、普通陆地遭遇表、骑车，再到调试直通与电量门（WP37 §6.1）。相同正常启动前提下，有伙伴/无伙伴均可返回成功，先累计使用数 +1、初始化或复用临时链、电量写 50，再摇草。
- 伙伴门在随后独立到达的雷达遭遇候选钩子：伙伴存在时清临时连锁，不回滚已发生的使用数/电量写入；无伙伴则继续 WP37 §7 的其它规则，不能保证任何候选都保持连锁。取消范围见 WP37 §8.1。
- 上车另属已接受 WP12 §5.1：成功新上车在骑行状态/计数、外观及音频请求之后取消临时链；已骑行再调用上车入口直接返回，不再次计数或取消。后段取消和启动骑车拒绝是不同阶段；正常素材/场景/回调是成功后置前提，早写状态不因后续失败自动回滚。

## 7. 规则与不变量

1. 训练家标识为 32 位；公开/秘密两半；外来标识 ≠ 自身标识。
2. 拥有者构造的性别取自训练家类型；语言取自训练家字段；外来判定只用标识+名字（WP18 引用）。
3. 玩家编号/套装的包装切换入口：id < 1 拒绝；未登记编号按记录 1 回退继续（存储原编号、内容读回退记录）；原始字段赋值无校验，写入与刷新有先后、失败不保证回滚；字符集按运动状态优先级与链式回退选择。
4. 四类资源写入入口：非法类型报错、负值钳到 0、超上限钳到上限；本规格不承诺「上限来自何处」以外的规则。
5. 徽章计数 = 布尔真值个数；场地招式许可的口径由配置二选一（默认数量 ≥ 需求）；服从性换算引用（WP40）。
6. 训练家装载：类型未知报错、记录缺失返回空、版本由调用者选择；显示名可被对战变量覆盖。
7. 调试新增路径与正常路径分离：写回数据文件属调试能力；装载的非调试缺失兜底报错，检查入口则在非调试直接返回 true。检查时的调试未知类型拒绝新增分支返回 false（§5.3、§8）。
8. 伙伴槽为单槽：注册 = 替换、注销 = 置空；注册按「类型解析 → 取消载具 → 装载 → 扩展点 → 拥有者重设 → 记录」分阶段，失败留下的部分副作用（如载具已取消）按实际阶段记录，不假定原子回滚；注册时会重设其队伍成员拥有者并重算（「非外来」仅相对该伙伴训练家）。
9. 伙伴参与：可行性查询（双打/三打编成）与本次参与谓词是不同入口；谓词按「无伙伴/禁用 → 敌方队伍 > 1 → 显式规模 → 其余为假」的顺序。

## 8. 边界与失败

- money / coins 等：非整数报错（不静默）；负值 → 0；超上限 → 上限。
- 切换玩家包装入口（编号 < 1）→ false；编号回退到记录 1 后仍取不到记录 → false（不改状态；即「元数据缺失」= 记录 1 也缺失/不可用）。
- 初始命名：名字输入取消/空 → 建议名流程；系统用户名不可用时的最终回退为「截断的系统用户名」（参考实现另含不可达的随机名分支——按行为登记）。
- 训练家类型未知：装载与伙伴注册入口报错；**类型检查和训练家检查入口**在非调试模式直接返回 true，不查询类型或记录。调试模式下，未知类型提示新增；拒绝新增、类型仍未登记，且查询与解释器收尾正常（解释器也可不存在）时，类型检查返回 false，外层训练家检查随后也返回 false。装载的训练家记录缺失则返回空，其非调试缺失兜底报错（含参数信息），调试可新建；各检查分支按 §5.3 的对照表，不把装载错误推广给检查。
- 版本号超出已有变体：视同缺失（走 §5.3）；空闲版本查找满 256 → −1。
- 伙伴在场时野外/追踪道具差异见 §6.4（细节引用后续规格）。
- 徽章/功能标记写入者缺失（未决类）：不得把「读取消费者存在」当成「许可流程完整」。
