# 队伍、盒子与成员移动行为规格（净化正文；批次 9a）

分类：creature-rpg（集合容器与成员移动）；性质：实现独立行为合同。

本规格为净化正文：按统一交接将批准输入 WP25《队伍、盒子与成员移动》转写为独立行为文字，不含源文件路径、类名、行号与证据 URL（参考与已读集中登记于 `../../audit/source-traceability.md` 批次 9a 条目）。文中保留的字段名、入口身份名与配置键均为数据标识，不构成未来实现的数据结构或接口模板。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的、范围与非目标

### 1.1 目的

定义队伍与盒子的容量、占位、成员移动与限制——哪些操作移动同一对象、哪些路径生成副本；容量/空位/守卫的实际行为；存入/取出与持久状态的保留规则。

### 1.2 范围

1. 容量与占位：队伍/盒子/每盒容量、计数、伪位置（队伍作为盒 −1）、空位查找、地区化储存。
2. 领域操作与界面流转：复制/移动/删除、捕获与赠送的容器结果、队伍顺序变更、界面「拿起/放下/交换/存入/取出/释放」。
3. 限制与守卫：不可存放/不可释放/邮件/蛋/最后可用成员/满队满盒，区分领域入口与 UI 守卫。
4. 持久状态界面的集合侧：存入治疗（配置）、进化准备标记、身份/来源不变。

### 1.3 非目标

- 不定义赠送/脚本交换完整接收流程（WP26）、捕获特有强制入队/转送选择（WP38）、寄养会话与繁殖（WP33）、专门 UI 全流程（图鉴/组队界面完整交互 WP66）。
- 不定义个体字段本身（WP18）与治疗语义细节（WP20，引用）；不定义存档布局（WP09/WP10，标记转换引用）。
- 不设计未来框架的容器 API；「盒数 40 / 每盒 30」是该内容配置的当前值，不提升为所有生物 RPG 的通用常量。

## 2. 概念与术语

| 术语 | 定义 |
| --- | --- |
| 队伍 | 玩家的有序成员数组（容量 6，配置值）；成员可为蛋/个体。 |
| 盒子 | 储存容器——多盒、每盒默认初始 6×5 = 30 格（有序网格，允许中间空位；容量 = 当前长度，见 §3.1）；盒有名字与背景（墙纸）编号。 |
| 伪位置（盒 −1） | 把「队伍」当作一个可寻址容器（与真实盒子同接口），取值/赋值/容量（6）/空位查找统一——但队伍侧删除会压缩数组（索引会移动），盒子侧删除留空位。 |
| 持有流转（界面） | 「拿起」= 把成员从容器取出并置于界面持有位（源立即删除）；「放下/交换」= 放入目标（可治疗）或与目标交换。 |
| 存入治疗 | 一项配置——把成员放入盒子时是否先「完整治疗」（并保留进化准备标记）。当前快照默认世代 8 → 该配置为关闭。 |
| 可用 | 非蛋且 HP > 0（界面守卫口径）。 |

## 3. 容量与占位

### 3.1 容量与计数

| 量 | 值/规则 | 备注 |
| --- | --- | --- |
| 队伍容量 | 6（配置） | 满队 = 队伍长度达到上限 |
| 盒数 | 40（配置，NUM_STORAGE_BOXES） | 盒数查询返回盒数组长度 |
| 每盒容量 | 默认初始 30（6 宽 × 5 高）；容量查询 = 当前成员数组长度（构造允许其它长度） | 不是硬性常数 |
| 盒计数 | 非空数；满 = 非空数等于长度；空 = 非空数为 0 | 清空后长度变 0 → 「空」与「满」可同时为真 |
| 全储存满 | 所有盒均为满 | 另有常用组合「队伍满且储存满」（赠送路径使用，WP26 引用） |
| 装置规模有效性 | 盒号 ≥ 盒数 → 0；盒 −1 → 6；否则该盒当前长度 | 供遍历与容量判断 |

- 清空（clear）语义：盒清空 = 成员数组清空（长度变 0，不是留下 30 个空位）；此后「空」与「满」同时为真，直到再次写入。
- 领域直写：容器的最小写入接口（按索引赋值）不做「目标必须为空 / 索引上界」校验——显式非负索引可覆盖已有成员、较大索引可扩展长度；只有「自动找空位」（目标索引 < 0 的复制路径）才使用空位扫描。界面层的空位/上界守卫不等于容器不变量。

### 3.2 伪位置与寻址

- 取值/赋值：[盒 −1] 与 [盒， 索引] 都支持；队伍作为盒 −1。
- 空位查找（输入：盒号）：盒 −1 → 队伍长度（≥ 6 → −1）；盒子 → 按当前长度从 0 起首个空位，否则 −1。
- 网格遍历（供界面绘制/统计）：按容量上限逐格读取。

### 3.3 地区化储存

- 多地区各自一套储存：按当前地图 → 地区编号解析并缓存；重解析条件 = 地图变化；无地图或无地区元数据时报错（提示设置地图元数据）；地区储存对象按需创建。
- 消费者事实：核心脚本中未定位地区化储存的消费者（全局储存句柄的默认赋值是基础储存类；「地区类可被外部/插件使用」属未决）。
- 代理并非完整透传（按行为分列）：
  - 移动代理转调底层复制——不删源：在同一地区储存内「移动」后，源与目标同时持有同一个体引用（与基础储存「复制成功后删源」不同）。
  - 删除代理实现引用未定义标识——调用失败（静态反例，不修参考）。
  - 墙纸：解锁代理转调底层不存在的同名方法——调用失败；地区对象没有已解锁墙纸的读取代理——依赖该读取的全局解锁/锁定工具不能经地区对象使用。
  - 其它同名代理（复制、捕获存储、空位查找等）与基础对象同义。

### 3.4 墙纸（背景）

- 总目录 = 16 种基础 + 24 种特殊（当前快照计数）；每盒有背景编号。
- 可用性：基础墙纸恒可用；特殊墙纸需解锁标记（数组按目录序号）；提供解锁/锁定工具（未定位正常游戏内解锁写入者——未决类）。
- 盒显示读取当前可用墙纸清单与当前背景；创建盒显示，以及刷新中因背景尚未读取或已变化而重读时，读取可改写背景记录。正常显示初始化与所需素材可用是以下显示结果的前提；不执行墙纸选择命令、直接退出也不撤销已发生的记录写入。

| 读取前的背景记录 | 显示值 | 读取后的背景记录 |
| --- | --- | --- |
| 空值或空文本 | 盒号模 16 的基础墙纸 | 保持原空值或空文本，不因默认显示写回 |
| 旧格式背景文本（格式见本节兼容附表） | 先转为整数编号，再按可用性选择 | 先写回整数；若该编号不可用，再写回盒号模 16 的基础编号 |
| 可用整数编号 | 该编号 | 保持该编号 |
| 不可用整数编号（包括未解锁或已锁回的特殊墙纸） | 盒号模 16 的基础墙纸 | 写回该基础编号 |

例如盒号 5 的背景 16 未解锁时，仅打开盒并退出就会显示并保留编号 5；旧格式的编号 2 文本转为整数 2 并保留；空文本只显示 5，记录仍为空文本。此兼容处理不保证任意字符串均可归一；特殊墙纸的正常解锁写入者仍未定位。

兼容附表（背景数据标识，不规定未来实现接口）：

| 旧格式／样本 | 解释 |
| --- | --- |
| 文本中首个完整匹配行：从行首到行尾仅含小写 `box` 紧接一串 ASCII 十进制数字 | 取该行的数字转为背景整数编号；行首为文本开头或 LF（U+000A）之后，行尾为文本末尾或 LF 之前。文本可有其它行，匹配行后的 LF 不阻止识别；随后仍需按可用性判断，不承诺任意字符串转换 |
| `box2` | 兼容样本：整数编号 2（基础墙纸可用） |
| `box2` 后接一个 LF（U+000A） | 同样识别完整行，背景记录写为整数 2；不是只允许没有换行的文本 |
| `prefix`、LF、`box2` 依次组成的文本 | 首行不匹配，第二行匹配，背景记录写为整数 2；同一行的 `box2x` 则不构成完整匹配行 |

## 4. 领域操作与界面流转

### 4.1 领域操作（容器方法层）

| 操作（入口身份） | 输入 | 结果（后置状态） | 失败/边界 |
| --- | --- | --- | --- |
| 复制（目标盒， 目标索引， 源盒， 源索引） | 位置 | 不生成新个体，源保持同一对象引用。**队伍目标**：未满时忽略显式目标索引，追加到队尾后压缩空项；[A] 复制 B 时，目标索引 0 或 5 都得到 [A,B]。**盒目标**：显式非负索引按该格写入；负索引自动找首个空位（找不到 → false）；若「存入治疗」开 → 治疗 + 保留进化准备 | 队伍满 → false；复制到盒且源为空 → 报错；仅盒目标的显式非负索引不做空位/上界校验，可覆盖占用格、扩展长度；盒号本身越界 → 写值失败 |
| 移动（同上） | 同上 | = 复制成功且删除源（源删除在队伍侧会压缩） | 复制失败 → 不删除源 |
| 删除（盒， 索引） | 位置 | 该处置空；队伍侧立即压缩（其后索引前移） | 空位置：无效果 |
| 捕获入队（个体） | 个体 | 追加到队伍末尾 | 满队 → false；返回值怪癖：成功时返回该个体对象（真值），调用者按真值使用（勿依赖布尔） |
| 捕获入盒（个体， 盒） | 个体+盒号 | 写入该盒首个空位；若「存入治疗」开且盒号 ≥ 0 → 治疗 + 保留进化准备 | 该盒无空位 → false |
| 捕获存储（个体） | 个体 | 当前盒优先首个空位；否则从 0 号盒起扫描所有盒，写入并把当前盒切换到该盒；返回盒号 | 全部满 → 返回 −1；注意：若「存入治疗」开，治疗发生在前，即使随后找不到空位（全满）也已发生（静态事实） |
| 队伍交换（旧索引， 新索引） | 两个队伍索引 | 两个位置的成员互换（同一对象换位；顺序变化） | 相同索引：无效果 |
| 队伍移除 remove_pokemon_at_index（索引）（训练家层） | 索引 | 移除该成员 | 前置：移除后仍须有其它可用成员，否则 false（成员守卫在训练家层；见 §5） |
| 清空盒 clear | 盒 | 网格清空（存档/新游戏路径引用 WP09） | — |

移动即同一对象：以上操作不创建个体副本（不复制身份/来源/持久状态）；副本语义只出现在明确「复制」语境（WP18 的个体克隆与进化复制路径）。

### 4.2 界面流转（队伍界面 + 仓库界面，静态核对）

队伍界面：菜单为摘要 / 开关（调试）/ 切换（选择另一成员 → 两成员换位；仅当队伍长度 > 1 时可用）/ 邮件（读信/取下）/ 道具（使用/给予/取下/移动子菜单）。切换 = 队伍交换语义（同一对象换位）。

仓库界面与 PC 菜单：界面分两层——逻辑与守卫在屏幕层，动画/呈现镜像在场景层；本节只登记逻辑层守卫。

- PC 菜单：整理盒子 / 取出 / 存入 / 离开——存入前置（PC 层，整队口径）：非蛋且 HP > 0 的成员 ≤ 1 → 拒绝进入并提示「不能存入最后一只」；取出前置（PC 层）：队伍满 → 拒绝。（整队前置与「整理模式」内的逐目标守卫不同，见 §5。）
- 界面操作（仓库屏）：
  - 取出（盒 → 队伍）：从盒取出必须给盒号（对队伍面板调用会报错）；队伍满 → 拒绝；持有位有成员 → 该成员入队，否则把所选成员移入队伍。
  - 存入（队伍 → 盒）：只能从队伍面板发起（对盒发起会报错）；守卫（按实际条件，只针对实际选中的成员/目标）：① 未持有且目标成员可用且队伍可用数 ≤ 1 → 拒绝（「最后一只」）；② 持有成员带邮件、或未持有且目标带邮件 → 要求移除；③ 持有成员不可存放、或未持有且目标不可存放 → 拒绝；④ 逐目标选盒循环：盒满 → 提示重试/换盒；⑤ 「存入治疗」开时对待存成员（持有或所选）先治疗（保留进化准备）；⑥ 移动。→ 把蛋/濒死成员存入不会被 ① 拒绝（目标不可用）；PC 菜单层的整队前置另算。
  - 拿起：目标为队伍最后可用成员（可用数 ≤ 1）→ 拒绝；否则删除源、置入持有位（源立即为空）。
  - 放下：目标格必须为空（否则报错）；仅当目标是盒子时：索引 ≥ 当前长度 → 拒绝、持有成员带邮件 → 要求移除、持有成员不可存放 → 拒绝——放回队伍空格不套用邮件/不可存放守卫；「存入治疗」开且目标为盒 → 治疗；写入；队伍侧压缩。
  - 交换：目标格必须非空（否则报错）；目标为盒时：持有成员不可存放 → 拒绝、持有成员带邮件 → 要求移除；目标为队伍一格时：该格成员可用且队伍可用数 ≤ 1 且持有成员不可用 → 拒绝（「最后一只」）；「存入治疗」开且目标为盒 → 对持有成员治疗；交换后持有位 = 原目标成员。
  - 释放：蛋 → 拒绝；带邮件 → 拒绝；「不可释放」→ 拒绝（三条对任何来源成员都检查）；直接释放队伍一格、该成员可用且队伍可用数 ≤ 1 → 蜂鸣拒绝（不弹确认；经持有位释放不套用该检查——条件含「未持有」）；确认对话框（默认「否」）选「是」→ 删除并提示；取消 → 无变化。
- 整理（PC 菜单第 0 项）即打开仓库界面进行人工移动/交换/排序——未见自动排序命令（检索未命中；搜索未命中 ≠ 不存在）。

## 5. 限制与守卫（按「入口 × 目标 × 是否持有」条件分层）

| 限制 | 领域层（容器/训练家方法） | 界面层守卫条件（入口 × 目标 × 是否持有） |
| --- | --- | --- |
| 满队 | 复制到队伍 / 捕获入队返回 false | 取出（PC 前置/仓库屏）；存入后队伍压缩是正常行为 |
| 盒满 / 全满 | 空位查找返回 −1 | 存入：目标盒满 → 重试/换盒；全满 → 捕获路径返回 −1（球使用限制归 WP38） |
| 最后可用成员 | 训练家层 remove_pokemon_at_index（移除后须仍有可用） | 存入：未持有 + 目标成员可用 + 整队可用数 ≤ 1；拿起：未持有 + 所选可用 + 可用数 ≤ 1；交换：目标为队伍格 + 该格可用 + 可用数 ≤ 1 + 持有成员不可用；释放：未持有 + 队伍格可用 + 可用数 ≤ 1；PC「存入」菜单：整队可用数 ≤ 1（进入前整队口径） |
| 蛋 | （容器不限制） | 释放拒绝；取出/存入/交换允许（蛋可存盒）——「最后一只」链按目标成员可用性判定，存蛋不受该链限制 |
| 不可存放 | 容器不检查 | 仅目标为盒：存入（持有成员或目标成员）、放下、交换 |
| 不可释放 | 容器不检查 | 释放（任何来源成员） |
| 邮件 | 容器不检查 | 仅目标为盒：存入（持有成员或目标成员）、放下、交换；释放（任何来源成员）。放回队伍空格不检查邮件（见 §4.2 放下） |

重要边界：除容量/空位（领域层确有检查）外，上表守卫大多在界面/调用者层，且带「目标/持有」条件——不能概括为「所有集合入口共同的不变量」；「PC 菜单整队前置」与「整理模式逐个目标前置」是两个不同检查；界面守卫不保证其它入口（脚本、事件、赠送、寄养）也检查。

地区储存：其「移动」只复制不删源、删除与墙纸代理失败（§3.3）——基础储存的移动不变量不推广到地区对象。

## 6. 持久状态交界（集合侧）

- 存入治疗（配置）：开启时在多处实现同一模式——复制入盒、捕获入盒、捕获存储、「放下/存入/交换到盒」（界面）——「先保存进化准备标记 → 完整治疗（HP/异常/PP 及清除该标记）→ 恢复进化准备标记」（完整治疗语义引用 WP20）。
  - 默认值：世代 ≤ 7 开、世代 8（当前默认）关；关闭时存入不做任何治疗。
- 身份/来源：移动/存入不改变身份、拥有者与来源记录（同一对象）；取出同样。
- 持有物：集合操作本身不动持有物；捕获流程的持有物登记在战斗侧（WP20、WP38 引用）。
- 蛋：可存入盒（蛋的展示/孵化流程 WP35）；存入治疗对蛋为无效果（WP20 蛋守卫）。
- 图鉴/统计：集合操作不触图鉴；捕获路径的登记归 WP38。
- 迁移交界：旧存档标记位掩码在迁移中转换（三处：队伍/寄养槽/盒子，WP21 引用；迁移机制 WP10）。

## 7. 规则与不变量

1. 队伍与盒子共享同一对象寻址（盒 −1 = 队伍）；队伍侧删除压缩、盒侧删除留空。
2. 基础储存的「移动」= 复制（同引用）成功后删除源；地区储存的移动代理只复制不删源（§3.3）；任何集合操作不复制个体身份或状态。
3. 容量：队伍上限 6、盒数 40 为配置；每盒默认初始 30、实际容量 = 当前长度；越界读取按容量函数语义（盒号 ≥ 盒数 → 0；盒 −1 → 6）；clear 后长度 0 且「空」/「满」同时为真；领域直写可覆盖/扩展。
4. 捕获存储的盒选择顺序：当前盒 → 0 号起扫描；成功时当前盒更新；全满 −1。
5. 存入治疗默认关闭（世代 8）；开启时「治疗 + 保留进化准备」（多处同模式）。
6. 最后可用成员保护存在于训练家移除方法与界面守卫链；各入口条件不同（含「未持有」「所选/目标成员」「持有成员是否可用」，§5）；活动口径 = 非蛋且 HP > 0。
7. 交换 = 两个位置的成员互换（同对象）；放置要求目标为空；放入盒才适用邮件/不可存放守卫，放回队伍空格不适用。
8. 释放不可逆：确认默认「否」；成功即删除（无回收）。
9. 邮件与「不可存放/不可释放」限制在界面层消费个体标记（且带目标条件）；领域容器不检查这些标记。

## 8. 边界与失败

- 报错路径（静态）：从盒取出却传队伍位置；存入却传非队伍位置；放下到非空格；复制空成员到盒；地区储存无地图/无地区。
- 返回值怪癖：捕获入队成功返回个体对象而非 true（调用者应只判真值）；捕获入盒成功返回 true/失败 false；捕获存储返回盒号（含 −1）。
- 索引变化：队伍删除压缩会让既有索引前移（调用者须按压缩后语义处理；界面的持有/放置流程即按此顺序执行）。
- 领域直写与界面守卫的差别：显式索引可覆盖占用格或扩展长度（§3.1）——界面层的「目标必须为空/不得越界」不是容器保证。
- 存量怪癖：捕获存储的治疗先于空位查找（全满时也已治疗）；地区储存的删除/墙纸解锁代理调用失败、移动代理只复制不删源（§3.3；静态反例，未修参考）。
- 墙纸解锁：正常游戏内解锁写入者未定位（未决类）。
- 守卫边界：非界面入口（脚本/事件/赠送/寄养）不继承界面的最后成员/邮件/标记守卫（且界面内各入口条件不同，§5）；本规格不声称所有入口一致（未穷尽脚本消费者）。
