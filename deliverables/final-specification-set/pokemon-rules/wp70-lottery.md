分类：Pokémon Rules（公开号和五位比较）；集合读取归 Creature-RPG，日期/随机输入归 Generic Kernel，游戏变量接点归 Engine/Overworld Integration。产生日期相关的五位号码，并在玩家队伍/储存个体中寻找拥有者公开号尾数匹配最多者。全部内容为静态提取；**无运行确认**（见 `../scope-statement.md`；不调用真实时钟、随机数或事件系统）。

## 1. 目的、分类与边界

此入口没有可操作的小游戏界面，不设翻牌/投注/中奖演出状态机。范围为生成/变量写入、号码转换/匹配、集合顺序/并列、输出/失败、静态场景。NPC 接待、何时每日刷新、兑奖奖品/次数、日期锁和领奖标记都没有事件证据；检索成功不等于已经发奖。

## 2. 号码生成、输入与状态变化

生成入口接收目标变量号，默认 1。读取宿主当前日/月/年，用数学量 d+32m+512y 作为临时全局随机种子，从 0～65535 均匀整数域取一次，随后无参重新播种，再把号码格式化为至少五位十进制字符串（合法生成域恰五位）写入目标变量。例：抽得 7 保存为 `00007`；不是只返回数字。

同日期、同随机实现条件下生成相同号码；不同日期不保证不同。不是日期一变就自动更新：仅调用入口时写一次；旧变量保留至再次写入，保存生命周期引用既有持久化边界，不另建彩票独立状态。结束的无参重播种**不恢复调用前随机序列**，其它普通随机消费者可能受影响（《时间、随机、计步与统计》/U05）。无本地异常保证重播种：抽号前后异常须按阶段判断。

变量写入包装拒绝空号/负号；变量容器只写 ≤5000 的编号，0 可用；大于 5000 不存值，但包装在地图存在时仍请求刷新。即使目标号不合法而不写，播种与取号已经发生；无变量容器时跳过写入，也可请求地图刷新。生成入口没有稳定的「返回开奖号码」合同，调用者应读取指定变量。

## 3. 匹配规则与领域概念

检索输入是外部中奖号码、名字变量号、位置变量号、匹配数变量号；后三者默认 2/3/4。号码先转整数：数字字符串接受前导零，带数字前缀的字符串按其可解析前缀，非数字字符串按 0；没有 0～65535 或五字符校验。比较只消费最低五个十进制位；负输入和无法转换的对象不属于正常号码域，可能有宿主转换/算术差异或直接失败，不补造输入拒绝界面。

每个个体用**其拥有者标识的低 16 位公开号**，不是个体随机身份、玩家当前公开号，也不比较拥有者名字/语言。公开号 0～65535，以五位看待。自个位向高位连续比较，遇首个不相等立即停止；结果 0～5。高位缺位等同 0，所以公开号 7 与号码 `00007` 匹配 5 位。

正式数学规则：把公开号和输入整数的第 j 位记作 dⱼ（j=0 为个位），匹配数为从 j=0 起相等的最长前缀长度，上限 5。中间不等后更高位的相等不再计入；外部号码 112345 与公开号 12345 可匹配 5 位。

## 4. 检索顺序、过滤与状态机

| 阶段 | 范围与顺序 | 最佳记录更新 |
| --- | --- | --- |
| 初始化 | 名字空、位置 0、匹配数 0 | 尚无胜者 |
| 第一遍 | 玩家队伍实际数组，从首至尾 | 仅严格多于现最佳时更新；位置记 1 |
| 第二遍 | 集合遍历从伪盒 −1（队伍）开始，再盒 0 至末盒；每容器按索引升序/实际容量 | 跳空位；严格更优才更新；这里不使用所给盒号，位置一律记 2 |
| 全部完成 | 写三结果变量 | 名字 → 位置 → 匹配数，随后返回末项匹配数 |

**没有过滤蛋、濒死、外来个体、不可存放标记或重复拥有者**。第一遍没有跳过空元素的保护，队伍含空洞时读取拥有者失败；第二遍跳过空位。第二遍使用的是含蛋的集合遍历，不是非蛋版本。

正常队伍 ≤ 容量且扫描期间稳定时，第二遍再次扫描队伍不会更优，因此已经胜出的队伍记录仍是位置 1；不要把第二遍叫成「只扫描盒子」。若外部改变集合/读取有副作用，此稳定性前提不成立，第二遍更新即可能把队伍成员标成位置 2。并列始终保留最先严格改进者：队伍先于盒子、队伍首项先于后项、低盒号/低格号先于后项；没有全匹配即早停。

按队伍/存储规格，默认 40 盒、每盒初始 30 格；这里循环实际盒数和各盒实际长度，清空后 0 长盒不扫描。当前盒不享有优先权。若全局储存换为地区代理，遍历当前地区的那一套，并不扫描所有地区；地区解析可能懒建或失败。寄养/伙伴队伍不在默认遍历范围。

## 5. 输出、变量边界与失败

正常结果是所选个体的显示名字（昵称存在用昵称，否则物种名，不返回拥有者名字）、位置 1 或 2、匹配数 1～5。全部 0 匹配或所有集合空时：名字空值、位置 0、匹配 0。变量容器读空值会返回 0，因此「名字变量读到 0」不等于存了字符串 `0`。

三项使用直接变量赋值，**没有生成号码入口的地图刷新请求**。三个变量号可以相同，按名字 → 位置 → 匹配数覆盖，最后留下匹配数；没有防冲突校验。大于 5000 的赋值被容器忽略，0 不拒绝；负号直接服从底层索引、可能从末端寻址或越界失败，未走生成包装的负号守卫。错误类型可在写入某项时失败，此前已写项保留。三个赋值不是原子提交。

普通正常返回值是最后匹配数（0～5），不是奖品、成员对象或「已领奖」标记。扫描阶段遇空队员/缺拥有者/储存失败会在三项写入前中止，旧结果变量仍可能残留，不能据其旧值兑奖。没有调用背包添加、金钱写入或彩票领奖统计递增。`lottery_prize_count` 仅有声明/初始化和事件侧注释；实际发奖继续 U01。
