# 动态形态与展示属性（净化正文；批次 5）

分类：Pokémon Rules（形态触发与展示数据）。本文件完整登记「同一物种为何、何时、以何种条件改变形态」，描述形态提交的直接副作用链，并登记展示属性（标记、缎带、华丽大赛属性）的读取/变更/边界。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的与范围

**目的**：供进化、战斗、界面、图鉴等规格统一引用形态规则，不再各自追踪处理器注册表。

**范围**：① 形态登记机制与**触发性目录**——注册/复制/条件注册语义，按触发族登记当前全部已注册物种及其条件、取值与回退；② 形态**提交**的副作用链（缓存/能力/招式/登记/创建与战斗内提交），以及锁定形态与时间标记；③ 展示属性——标记、缎带、华丽大赛属性的读取/变更/边界。

**非目标**：不定义 Mega/Primal 的触发资格与生命周期（归《Mega、Primal 与显式还原》；本文件只登记其注册接口与调用点归属）、Shadow 的形态相关字段；不定义战斗内形态变化的资格/次数/时机契约与战斗效果（归战斗规格）；不定义具体处理器物种的专有界面；不把「华丽大赛属性字段存在」扩成完整华丽大赛流程（U04 保留）；不定义资源文件组织；不重复个体规格的字段清单与复制清单。

## 2. 概念与术语

- **形态处理器注册表**：按物种登记的「触发时机名 → 处理器」映射。**处理器行为按物种单独定义**——同名时机不保证行为相同（本文件逐族核对）。
- **触发族**：注册表按调用时机划分的族——创建时、蛋创建时、读取时、提交时、战斗开始/入场/离场（形态取值与个体改写各一）、图像修饰、Primal 专用。
- **提交与只读**：只读路径调用处理器**不写入**个体（或把结果与当前值比较后才写）；提交路径经形态设置入口写入并触发副作用链（§4）。处理器返回**空表示「不改变」**；返回数值表示候选形态（是否写入由调用入口决定）。
- **锁定形态（forced_form）**：显式覆盖存储形态；优先于动态处理器结果；由外部写入、由特定流程解除（§3.4）。
- **时间标记（time_form_set）**：为「限时形态」记录设置时刻的整数时间戳；读取时按经过时长决定回退（§3.4）。
- **展示属性**：标记（6 个整数格）、缎带（标识列表）、华丽大赛属性（5 项数值＋光泽度）——只描述记录与展示，不构成玩法完成度。

## 3. 登记机制与触发族目录

### 3.1 注册与查找语义

- **注册表**以**物种标识**为键、值为「时机名 → 处理器」的**整份映射**；注册对该键**整体替换**——同一物种先后注册两个不同映射时，先前映射中的时机不再可用；处理器可为过程或哈希（一次注册多个时机）。
- **查找**：查询值若「非符号且可换算身份」（如内容记录对象）先取其身份再查；**字符串不做符号归一**（用字符串查询不会命中按符号登记的条目）；未命中时按序评估**条件注册**条目（条件过程接收查找键），取首个通过者；仍未中返回空。
- **复制**：在**复制时刻**解析源物种当前映射，并把**同一个处理器对象**绑定到各目标物种；两种后续影响要分开：
  - 给**源物种重新注册**（换新映射）**不会**自动重绑已复制目标——目标保留复制时取得的映射；
  - 对**共享处理器对象的原地修改**在源与各目标处同样可见。
  - 源未注册时复制静默无操作。当前 9 条复制语句、27 个目标物种。
- **条件注册**：机制存在（按键存放「条件过程＋处理器」，查找未命中时按序评估）；**当前注册条件条目为 0**（机制登记为可用但无用例）。
- **查询接口**：时机查询返回该时机的**处理器对象或空**——可作真值判断，但**不保证返回布尔真**；调用无注册时返回空，否则调用处理器（个体＋附加参数）。
- **注册表规模**（静态计数）：49 条具名注册＋9 条复制语句（27 目标物种）＝76 个物种带有处理器；各时机出现次数见审计（读取时 ×15、创建时 ×11、离场时 ×19、战斗开始 ×3、入场 ×2、提交时 ×6、战斗开始个体改写 ×2、离场个体改写 ×2、Primal ×2、蛋创建 ×1、图像修饰 ×1）。

### 3.4 锁定形态与限时形态

- **锁定形态（forced_form）**：读取优先于处理器结果（形态与简化形态读取都先取锁定值）；**已定位写入者仅调试工具**；**捕获成功时若物种带读取时处理器会解除锁定**（置空）——正常运行不设置锁定（U 类保留：搜索未命中 ≠ 不存在，插件/事件可能写入）。
- **时间标记（time_form_set）**：由两个物种的提交处理器维护（FURFROU 5 天、HOOPA 3 天）；读取处理器在「时间戳缺失或超过窗口」时返回回退形态（0），否则不改变。时间戳在形态 >0 时记录「当前时间」、在形态 0 时清空。窗口以**秒**计（5×86400 / 3×86400），时间来源归《时间、随机、计步与统计》。
- 边界：时间戳读取在处理器里做空值保护；系统时间回拨未验证（静态推导不覆盖）。

## 4. 形态提交的副作用链

### 4.1 提交入口与顺序

| 入口 | 顺序与副作用 |
| --- | --- |
| 形态写入（提交型） | 写入形态 → 清特性缓存 → 调用提交时处理器（若有）→ 重算能力（《属性派生、特性选择与六项能力》§5.5）→ 玩家/图鉴存在时登记图鉴（**登记读取性别与普通异色**） |
| 形态写入（提示型） | 同上，但「写入形态」与「处理器＋重算＋登记」之间**让出一次**（供提示消息后再执行处理器） |
| 简化形态写入 | 仅写入形态＋重算；**不调用处理器、不清特性缓存、不登记图鉴** |
| 创建复检 | 创建末段（形态为 0 且启用复检）调用创建时处理器；有返回值则走提交型写入（含图鉴登记）并（带招式初始化时）重做招式初始化 |

显式的提交型／提示型写入**没有旧形态等于新形态的短路**，同值也清缓存、调用处理器、重算并条件登记。动态读取只在处理器返回值与当前值不同时提交；ROTOMCATALOG 的外层选择也先拒绝同形态。这些调用方守卫不能补到裸提交中。

### 4.2 处理器内的招式改写（与招式状态规则的衔接）

- 四条提交处理器（ROTOM/KYUREM/NECROZMA/CALYREX）会改写招式列表，**路径分三类**：
  1. **直接改招标识**（ROTOM 已有旧形态招时、KYUREM 各形态互改、以及「目标招未被自己掌握」时的替换分支）：同一招式对象换标识——**保留槽位与 PP 提升计数；当前 PP 按新招式总 PP 钳制**（招标识赋值的钳制规则归《HP、状态、招式与持物》，不复制；**不自动回满**——旧当前 PP 超出新总 PP 才被压下，未超出则保留原值）。
  2. **经学习入口的交互学招**（ROTOM 无旧形态招的新增分支、NECROZMA/CALYREX 的新增分支、以及「招式清空后的保底补招」）：调用带交互的学习入口——已有该招时按调用参数跳过；有空格时直接学会；**满槽时询问「替换或放弃」**：选择替换会以**新招式对象**替换所选槽（PP/提升计数为新招初始值，**不继承**旧槽，机器教学的另一保留变体不适用此处）；**放弃则招式不变**。该入口对蛋/Shadow 有拒绝分支（拒绝＝未学会）。
  3. **逐项删除**：置空后压缩列表（压缩时机按物种不同，见下）。
- **拒绝不回滚形态**：交互学习被放弃、或被蛋/Shadow 拒绝时，该次学习不新增／替换招式；形态已写入，**此前已发生的删除也不回滚**。例如 NECROZMA／CALYREX 归 0 先删招、随后空列表补学被拒绝，可留下零招式；后续重算／登记按实际到达顺序处理，不能概括为形态与招式原子提交。

## 5. 展示属性

### 5.1 标记（markings）

- **存储**：6 个整数格（每格记录一个「变体号」；缺省视为 0/未选）。图形变体数**由界面资源决定**（资源高度/单格高度），不在数据层固定。
- **编辑（两个界面的入口能力不同，静态核对）**：
  - 共同：8 个位置（6 格＋确定/取消）；**确定键循环递增**（对缺值格按 0 起算）；**确定提交、取消/BACK 放弃**；绘制把格值钳到「变体数−1」（缺值按 0）。
  - **摘要界面另有「动作键清零」分支**：仅当该格当前值 > 0 时清零；该分支直接把当前值与 0 比较——**对尚未赋值的格（缺值）会在此比较处失败（静态异常路径）**；同一缺值格用确定键则正常（按 0 循环）。
  - **仓库界面的标记编辑没有清零分支**（仅方向/确定/取消处理）——不能把两个界面当作同一操作能力。
- **兼容转换**：旧存档的位掩码（整数）在存档迁移中转为 6 个 0/1 格（仅当旧值为整数时；三个位置都转换：队伍、寄养槽、仓库；转换条目归《迁移、失败与恢复》交界）。
- **复制/进化交界**：直接复制保留标记数组引用；进化的**复制接收路径**（特定物种「进化分裂」式效果）生成副本并**加入玩家队伍、登记图鉴（见过/拥有）**，副本清空标记、持有物与全部缎带、**球重置为普通球（POKEBALL，不是置空）**、治疗并重算；该路径有「队伍满」与「所需球不足」的前置失败（失败不产生副本，球在成功后才消耗）——属真实接收流程的交界，完整规则归进化规格（本文件只登记展示数据的重置与接收事实）。

### 5.2 缎带（ribbons）

- **存储**：标识列表（有序；**给予入口去重**，但列表并非全局去重保证——见升级路径）。
- **变更接口**：
  - 给予：未知/未登记标识忽略；已拥有不重复添加（**去重**）。
  - 升级：按参数顺序找「已拥有的第一个匹配项」，把该格**直接替换为下一个参数的标识**——**不检查该标识是否已在列表**（例：已拥有 `[A,B]` 且 A/B 均已登记，升级 (A,B) → `[B,B]`）；下一个参数未登记/缺失时跳过该匹配、继续扫描；全部匹配都不适用时：**首参和末参都有效且末参未拥有**才给予首参并返回之；否则无操作（返回空）。
  - 移除：**未登记标识 → 无操作**；**已登记但未拥有 → 位置查找失败后仍把空位置交给删除操作，调用失败（静态异常路径）**；清空全部。
- **展示**：摘要界面按**持有列表顺序**取缎带（每页 12 个、可滚动偏移）；缎带数据的「图标位置」只用于从图集**裁切**对应图像，**不是排序依据**（缎带目录为内容数据：标识/名称/图标位置/描述/标记；资源归资源规格）。
- **数据侧**：缎带目录为内容数据（编译往返，《PBS 生命周期》引用）；净化流程会给予固定缎带（Shadow 规格引用）；调试可增减。

### 5.3 华丽大赛属性（contest stats）

- **存储**：5 项数值（帅气/美丽/可爱/聪明/强壮）＋光泽度；创建为 0；复制按值保留。
- **已定位的领域消费者**：进化条件中的「美丽」判定读取美丽值（阈值型条件：美丽 ≥ 参数；内容样本中某物种登记有「美丽 170」的进化条件）——这是**进化资格输入**（与进化规格交界）；静态例：美丽 169 → 不满足、170 → 满足该条件（其它资格另给前提）。
- **仍未证**：核心脚本中**未定位**非调试的**写入者**与制作/比赛流程（U04 保留；「无用例」不等于「不存在」）；字段存在不构成完整华丽大赛证据。
- 与标记/缎带的关系：三者相互独立；进化复制路径不清除华丽大赛属性（与标记/缎带不同）——按该路径实际行为登记（§5.1）。

## 6. 规则与不变量

1. 只有注册表内**有对应用时机注册**的物种才会获得该行为；无注册时触发器返回「不改变」（空），不报错。
2. 读取时处理器**只在入口决定写回时提交**（形态读取：结果与当前不同才经提交型写入写回；战斗中/仓库中直接返回存储值，不触发处理器）。
3. 处理器返回空＝不改变；返回数值＝候选形态（数值本身不做域校验，消费者按各自逻辑使用）。
4. 提交顺序固定：写入 →（特性缓存清理）→ 处理器 → 重算 → 图鉴登记（比较入口差异表）；简化形态写入是唯一不触发处理器/登记/特性清理的写入。
5. 提交时处理器的招式改写只发生在已登记物种；三条路径的行为不同：直接换招标识**保留槽位与 PP 提升计数、当前 PP 按新招式总 PP 钳制**；**经学习入口的满槽交互由「替换/放弃」决定——放弃不回滚形态、替换生成新招式状态（不继承旧槽 PP/提升计数）**；删除的压缩时机按物种不同（遍历中可能跳项 / 遍历后统一）。
6. 战斗触发由调用者给出（是否野生/参战/终战）标志；同一处理器依赖这些标志决定回退。
7. 锁定形态优先于处理器；捕获会解除读取型物种的锁定。限时形态按「时间戳＋窗口」回退；时间戳在提交时维护。
8. 标记为 6 个整数格（资源决定变体数；两个编辑入口能力不同）；缎带**给予去重、升级不去重、移除按持有状态分失败路径**；华丽大赛属性独立存储且已有进化条件读取者；三者不因一般形态提交改变（例外：进化复制接收路径清空标记与缎带——按该路径登记）。
9. 条件注册机制存在但当前无注册；复制在复制时刻绑定共享处理器对象——**源物种之后重新注册不会重绑已复制目标**，原地修改则两处可见。

## 7. 边界与失败

- 处理器抛错：ROTOM 的无替换招边界（§4.2；形态已写入、替换未完成）。
- 复制时源未注册：静默无操作（不报错、目标无处理器）；字符串键查询不命中按符号登记的条目。
- 形态值不受域校验：处理器返回任意整数都会作为候选写回（不存在的形态号记录照常存储；资源/图鉴显示的后续行为归各自规格，「记录存在 ≠ 资源存在」）。
- 标记格值超范围：绘制钳位；编辑循环对超范围旧值按模运算循环（继续递增路径）。
- 标记编辑差异：摘要界面动作键在**缺值格**上失败（静态异常路径）；仓库界面**没有**清零分支。
- 缎带：升级不去重（可重复项）；「已登记但未拥有」的移除路径失败、未登记标识无操作；回退赠予要求首末参均有效且末参未拥有。
- 形态提交不接受交互学招的「放弃」作为回滚条件：放弃时形态已提交。
- 时间窗口以系统时间为准；时钟未设置/回拨的边界未验证。
- 华丽大赛属性：写入者未定位（U04）；**已有进化条件读取者**；标记/缎带的完整历史流程依赖事件/Demo（U01）。

## 8. 默认行为与配置变体

- 无处理器物种：形态保持创建/存储值；创建期不调用形态查询。
- 资源变体（标记变体数、缎带图标位置）随图形资源与内容数据而定。
- 季节/昼夜/环境判断依赖配置与时间系统（《规则配置档案与数据变体》《时间、随机、计步与统计》引用）；测试环境的时间差异会改变 DEERLING/ROCKRUFF/LYCANROC/SHAYMIN 的结果。
