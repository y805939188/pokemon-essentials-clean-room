# Shadow、Hyper、成长暂存与净化生命周期（净化正文；批次 5）

分类：Pokémon Rules（主）、Creature-RPG、Combat Requirements、User Interface 与 Engine/Overworld Integration（事件接点）。本文件定义 Shadow 状态、心量表、Hyper、成长暂存/恢复与净化各入口的行为。全部内容为静态读取、数据样本或独立固定算术；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的、边界与可见流程

Shadow 不是异常状态枚举中的一项。它有独立标志、心量表、Hyper 有效状态、暂存经验/EV 和招式记录。量表从满向 0 推进；0 仍是 Shadow，表示可进入某些净化入口，不是已解除。净化成功后恢复招式与部分暂存经验、恢复受额度约束的 EV、获得缎带，并可触发升级/学习/进化及命名。

玩家可见入口包含训练家暗影出场提示、捕获后的暗影个体、摘要心量表与阶段消息、呼唤、香类道具、遗迹石选择和净化室。抢夺许可/所有者改写/捕获接收**只引用捕获规格**；图鉴暗影拥有**只引用图鉴规格**。本文件不新增捕获公式，也不把 Shadow 招式的全部效果重新提取一遍；相关战斗效果由战斗效果规格负责。

默认与可选内容必须分开：核心脚本始终含 Shadow 扩展，顶层训练家数据有两个物种的 Shadow 标志样本；顶层内容数据没有 Shadow 专用类型/招式/四件道具/Shadow 个体表。备份目录含 131 个 Shadow 配置节、18 招、4 物品、1 类型，是**可选原始样本**，不是当前默认已编译/启用数据。实际运行数据缺失，不声称当前游戏已可达。完整数据与阶段/性格表见[附表](wp23-shadow-data-and-vectors.md)。

## 2. 状态、输入输出与建立/解除

| 概念 | 缺省/查询 | 变更 |
| --- | --- | --- |
| Shadow 标志与心量表 G | 判 Shadow 要求标志真、原始 G 存在且 G≥0；无量表的普通查询返回 0 | 建立写真与最大值 M；净化只清标志，不删除 G |
| 最大量表 M | 当前基础物种/简化形态查询 Shadow 内容，形态缺项回基础物种；没有记录用 4000 | 配置 GaugeSize 为正整数；直接坏数据 M=0 不是正常内容输入 |
| 心阶段 H | 非 Shadow 为 0；Shadow 为按五等分向上归档（§3） | 调整 G 后查询变化；不是单独持久状态 |
| Hyper 存储标志 | G=0 或 HP=0 时查询恒假，否则返回存储标志 | 建立/净化/呼唤/香/随机平静清或写标志；HP 赋值到 0 清标志 |
| 暂存经验 S、暂存 EV 向量 V | 正常建立 S=0、六项 V=0；未建立可缺失 | 经验赋值覆盖或战斗 EV 分配暂存；净化恢复后各置空 |
| Shadow 招式及原招式记录 | 记录招标识，不保存被删除原招的 PP 与提升计数 | 建立/阶段刷新/净化更新；§4 |
| 每个体行走计数 | 建立 0；有量表时懒初始化 0 | 可战斗队伍成员累计 256 步后降低量表并清计数 |
| 净化室 | 全局持久元数据懒建立 9 组；每组一中心、至多 4 外圈及朝向；当前组 0 | 引用移入/移出/交换、步进量表、领取 |

**S01 建立**：没有「已是 Shadow 则不重做」的守卫。重新建立会把 Hyper 清除、S/V 重置、G 改为 M、步数归 0、重新收集 Shadow 招式；若能收集到 Shadow 招式，保存**此刻已知招式**作为原招式，再按当前阶段换招。重复建立会丢弃旧暂存和旧恢复目标，不能当无副作用的幂等操作。原持物/所有者/异常/物种不由该入口统一改写。训练家装载在指定性格、IV/EV 等之后调用建立，再清普通异色并重算（训练家/能力规格）；与直接建立本身分开。

**S02 裸标志与成功净化不同**：直接清 Shadow 标志只使查询不再认作 Shadow，不自动返还成长或恢复招式。调用招式刷新时若已经非 Shadow，才恢复记录并清招式记录；暂存经验/EV 仍需净化提交处理。净化不统一改物种/形态、治疗 HP/异常/PP、改所有者或清暗影拥有图鉴记录。

**S03 复制的有限隔离**：普通个体复制规则引用《个体身份、物种与归属》。此扩展另复制招式标识记录的列表，但没有新建暂存 EV 容器，复制个体与原个体可共享同一暂存 EV 表；改副本该表的一项会影响原表。净化将副本的暂存 EV 引用置空不等于清空原表。此为参考快照观察，不把「所有 Shadow 字段深复制」写成保证。

## 3. 心量表、阶段与下降入口

合规 M>0 时：`H = ⌈5 × min（G, M） / M⌉`；非 Shadow 为 0。默认 M=4000：G=0 为阶段 0，1–800 为 1，801–1600 为 2，1601–2400 为 3，2401–3200 为 4，3201–4000 为 5。高于 M 的直接写值计算阶段时钳到 M；正式调整入口将结果钳到 0..M，且非 Shadow 不调整。原始量表写入口没有上述钳制，负值还会使 Shadow 查询为假，不能以正式调整保证所有坏输入。

下降量按**储存的性格身份**查 25 行数据，不用性格训练覆盖值；没有表项时战斗/行走/香基础 100、呼唤 300。香乘数分别 1/2/3；其它入口的乘数参数不放大下降量。未知方法对 Shadow 报错，对非 Shadow 在前置门直接返回。数据见附表。

| 入口 | 实际接收者/门 | 写入与后续 |
| --- | --- | --- |
| 建立/重新建立 | 给定个体，无非 Shadow 守卫 | G=M，H 通常 5，招式立即刷新 |
| 派入战斗 | 初始化后的新个体是 Shadow；只对**玩家本人所属席位**减量表 | 按「战斗」下降；若 SHADOW 类型存在，战斗副本先设为该单类型；不在此刷新 Shadow 招式 |
| 呼唤 | 当前场上 Shadow 且有效 Hyper（战斗命令规格的 Call 执行） | 先清 Hyper，再按「呼唤」下降；非 Hyper Shadow 无效果；不在该点刷新招式/净化 |
| 行走 256 步 | 玩家可战斗队伍成员，G 非 0；不等于所有队伍/盒子成员 | 步数到 256 → 按「行走」下降；变到 0 则准备提示＋换招，跨非 0 阶段则换招；再计数归 0。普通个体 G0 跳过；濒死/蛋不累计 |
| 香 | §7 分入口许可后 | 先友好度（维生素通道），再按「香」下降；量表改变则准备检查/换招。友好度变化发生在下降前的阶段门下 |
| 净化室每步 | 中心存在且 G>0，无 HP/蛋/256 步门 | 下降本组流量，达到净化室资格则通知；**不调用阶段换招**，G 已 0 的后续步跳过，不重复提示 |
| 战后通知 | 按战前量表快照的索引查看当前玩家队伍 | 战前值非空且非 0、当前 G0 才调用准备检查；它先换招再提示，不完成净化 |

「准备检查」只要求仍是 Shadow，会刷新招式；G0 时每次调用都可显示已可净化，不使用一般「可净化」查询的 LUGIA 排除门。战后心量表数组只在开始时按队伍索引保存；捕获换出成员时捕获规格会移动等级/要害/直接伤害数组，**未移动这份心量表数组**。因此满队替换后通知判断可能配到另一成员的战前 G。本文件单列该观察，不能沿用其他数组的移动保证；真实接收与成员移动主规则不改。

## 4. 招式保存、切换与恢复

**S04 建立招式记录**：从可选 Shadow 内容中按给定顺序只取存在的招式，至多 4 项；没有有效项时，仅在 SHADOWRUSH 实际存在才使用它作为后备。最终仍为空则不保存原招、不改变当前招式。默认顶层无该招与 Shadow 内容的条件下，建立仍可把个体设为 Shadow，但其原招式原样保留。

记录前 4 槽是 Shadow 招，后 4 槽保存建立时的原招标识。Shadow 状态下候选＝所有已记录 Shadow 招＋原招的一个后缀片段：若有 k 个 Shadow 招，先跳过原招前 k 槽，再按 H 允许恢复最多 `[H0:3, H1:3, H2:2, H3:1, H4:1, H5:0]` 项。不把原招前 k 槽在阶段 0 自动全恢复；解除 Shadow 并刷新才恢复全部原招。

**S05 实际替换**：保留当前列表中仍在候选集合内的招式对象及相对顺序（PP/提升计数保留）；删除其余；再按候选次序补入还未掌握的有效招式，满 4 槽停止。补入的是新招式对象，PP 初始满、提升计数 0。不是每次按候选重排，也不统一回满现有 PP。直接补招不走「Shadow 不能教学」的通用交互门。

非 Shadow 刷新时，记录长度超过 4 才从原招区域构成候选并恢复，之后把记录置空；非空但没有原招区域的异常/空原招建立情况不会强制删除现存 Shadow 招。空列表在入口直接返回，甚至不改为空引用。捕获成功会刷新 Shadow 招并记录首招；战斗中香改变持久招式不会由该香处理器自动重建场上招式副本（《HP、状态、招式与持物》各写入层不能混同）。

## 5. Hyper 与战斗状态

**H01 进入**：常规招式流程后段，在成长与设施记账之后、结束行动的持续能力检查之前尝试；若选择已被清空（如被替换）则不尝试。执行器要求未濒死、Shadow、当前非有效 Hyper、玩家本人所属。对正整数 G，从 0..G−1 取战斗随机 r；当 `r ≤ ⌊M/4⌋` 时写 Hyper 真并提示。概率为 `min（G, ⌊M/4⌋+1）/G`，不是严格小于门。默认 G=M=4000 为 1001/4000＝25.025%；G≤1001 时必命中。G0 没有进入前置排除。**普通默认战斗、M4000、G0 且其余门均通过**时，数值 0 随机入口返回 [0,1) 浮点（已审数值转交合同）；任一结果都 ≤1000，因此本次**写 Hyper 存储标志为真并请求进入 Hyper 提示**。有效查询仍因 G0 为假；同前提再次调用仍能重新写入/提示，不能把「有效假」写成「未发生写入」。G0 不套上述正整数概率；自定义小 M、改写随机服务/插件或回放记录不套本默认结论。未执行随机接口。

普通 Call 菜单还要求 SHADOW 类型已注册且为训练家战；默认顶层缺该类型时不能仅因个体 Shadow 就宣称菜单有呼唤。

**H02 服从与反伤**：非有效 Hyper/没有招式/招式数据类型为 SHADOW 则服从此门；其它招式用普通全局随机 0–99 取值 <20 才服从。它嵌在战斗命令规格的服从链中，非内部战斗或非玩家本人会在外层提前返回；不是独立的所有战斗 20% 规则。回合末阶段（战斗回合规格阶段 8）：有效 Hyper 且登记招式行动者受到总 HP 除 24 的整数商伤害，普通扣血入口对存活者至少扣 1、最多当前 HP，然后处理濒死；不另查魔法防守。阶段 18 才对仍存活有效 Hyper 用战斗随机 10% 清标志，否则提示仍处 Hyper；平静本身不减量表。

**H03 退出/保留**：HP 赋值到 0 先走《HP、状态、招式与持物》清理并清 Hyper；呼唤、香、成功净化明确清标志。普通完整治疗只恢复 HP/状态/PP 及进化准备，不专门清 Hyper、Shadow 或量表；因此存活 Hyper 全治疗后仍可 Hyper。G 降到 0 只令查询假，不必改存储标志，随后人工回升 G 可再次暴露旧标志。

初始化战斗席位前还有**旧对象**清 Hyper 步骤：旧队伍下标 >0 且旧对象此刻有效 Hyper 才清，随后载入新个体；不是对新入场者统一清除，也不是对下标 0 无条件清。普通换下先把旧战斗副本 HP 置 0，之后初始化读有效 Hyper 为假，所以不能据此承诺正常换下清 Hyper。索引 0、濒死副本和直接初始化分别有不同门；不补造「离场一定平静」。

**H04 与形态/能力**：暗影入场将副本类型设 SHADOW 只在该类型存在时执行，持久个体类型不改；之后 Mega/Primal 完整刷新会回读个体类型，不再次自动加暗影覆盖。本文件与《Mega、Primal 与显式还原》仅说明真实调用先后，没有新增互斥条件。Shadow 招式的效果克制按战斗效果规格实际检查目标 Shadow 标志，不以此副本类型替代；能力阶段链引用战斗能力规格。

## 6. 成长限制、暂存与成功净化

### 6.1 Shadow 期间

经验主规则（成长规格）与战斗时机（战斗结果规格）保持：实际收益先按**当前经验**到上限的余量钳制；心阶段 ≤3 且实际收益 >0 时增加暂存 S 与统计，当前经验不变，不走战斗升级/学习。阶段 4/5 不入经验与统计。S 不会计入这次最大经验余量；多次收益可使暂存总量超过最终可恢复余量。

经验裸赋值对 Shadow 把「请求值−当前经验」加入 S，既不直接写当前经验，也无阶段/上下限保护；负差额能减少 S，未正确建立 S 时可能在加法失败。不能把战斗阶段门当作所有赋值入口的规则。

EV 主规则：Shadow 且阶段 ≤3 且暂存表存在才入 V，单项与总量额度都同时计入当前 EV 与 V；**阶段 4/5 或 V 缺失落入普通 EV 写入分支**，不是完全禁止 EV。普通分支不额外计入残留暂存；净化恢复时再按当前额度限制。EV 分配本身不统一重算能力。

友好度的通用变化入口在 Shadow 且阶段 ≥4 时完全返回（正负变化均拦），≤3 走成长规格原规则；直接写友好度不共享此门。经验糖果、通用教学/重学、普通进化等具体拒绝门引用成长/进化规格；Shadow 不等于「所有低层成长入口都禁用」。摘要心量表替代普通成长展示，性格文字及能力色彩在阶段 ≤3 才显示；数据仍存在并可参与计算。

### 6.2 净化提交、调用者失败与副作用顺序

统一净化提交自身只要求 Shadow 且 G**恰为 0**；无 LUGIA、非蛋、HP、场景可达或资源检查，外围入口各自设门（§7）。下表是提交顺序，**能否越过等级工具的窗口取决于实际调用者**，不能合并为一条必然成功流程：

| 阶段 | 已写状态/调用 | 取消/失败边界 |
| --- | --- | --- |
| 1 | 净化统计 +1；Shadow=false、Hyper=false；授予 NATIONAL 缎带 | 之后消息/界面失败不回滚。重复再调用因已非 Shadow 早退；缎带去重引用《动态形态与展示属性》 |
| 2 | 显示心灵打开；保存当时招式标识对照；刷新原招；按新旧同位置差异提示恢复招式；重记首招 | 提示按位置差异，不等于每条都是新掌握；S05 不重新教学所有原招 |
| 3 | V 存在则按当前 EV 逐项额度加入、总额逐项增长；V 置空 | 原有 EV 或其他成长挤占额度时可丢弃部分 V；不先重算能力 |
| 4 | S 存在（包括数值 0）则取 `⌊4S/5⌋`，与当前经验作成长规格受限加法，S 置空；比较新旧等级并提示实际返还差额 | 恢复不是 100%；最大经验余量 0 可得到 0 返还。S 缺失则整个经验/重算段跳过 |
| 5a | 等级相同：赋最终经验并重算能力 | S=0 仍走此处，故可刷新恢复 EV 的能力；S 缺失不自动补一次重算 |
| 5b | 等级不同：先调用成长规格等级设置辅助，**只有正常返回后**才写精确最终经验 | 该辅助先设等级/能力与升级分支友好度，再显示能力变化窗口，随后才学招/进化；净化室在首个窗口的更新回调先失败（下表），不能承诺后续。遗迹石有该回调，不共享这个缺方法点；不是战斗逐级循环 |
| 6 | 前序正常返回且命名设置允许才询问，确认后输入并写昵称 | 拒绝命名不取消净化或恢复；空名由《个体身份、物种与归属》名字语义处理。学习放弃/进化取消也不回滚步骤 1–4 |

**分入口失败表**（均以前序资源/消息操作正常、个体与暂存数据有效为前提）：

| 调用者/经验分支 | 首次可确定的结果 | 已提交与未到达 |
| --- | --- | --- |
| 净化室，同等级恢复（含 S0） | 不调用等级变化窗口；写精确经验并重算，可继续后续命名/存放 | S0 与 S 缺失的区别仍按步骤 4/5a；是否最终存放成功另看容量 |
| 净化室，恢复后等级不同 | 净化室画面作为窗口更新接收者却无更新回调（审计名）；**首个能力变化窗口更新时缺方法失败，先于确认键检查**。场景上有同名方法不自动转发给画面 | 净化统计、Shadow/Hyper 清除、缎带、招式刷新/首招、V 恢复并清 V、清 S、等级赋值/能力重算及升级分支友好变化已提交；精确最终经验写回、后续学招/进化/昵称、存放/清中心均未到达；失败不回滚，中心仍引用已部分修改的对象 |
| 遗迹石，恢复后等级不同 | 遗迹石画面明确提供空更新回调，**不在同一缺方法点失败**；其他资源/消息正常时可继续等级工具及精确经验写回 | 学招放弃/进化取消/昵称拒绝仍按各自规则；不据此保证任意宿主操作成功 |

固定向量：默认 Medium 曲线的 RATTATA，L10/经验 1000、G0、S416、V 有效，净化室资格成立且前序呈现正常；恢复请求 ⌊416×4/5⌋=332，目标经验 1332 属 L11。等级工具先把经验设为 L11 下限 **1331**，再重算/升级友好变化；首个窗口更新缺方法失败，**没有写入 1332、没有存放或清中心**。此与已经到达存放之后的容量失败不是同一分支。

G、步数、所有者、HP 异常等没有统一清空步骤。非零 G/非 Shadow 直接净化早退无写入。异常状态被人为构造为 S 缺失而 V 存在时，EV 能已恢复但能力未重算，须如实保留；正常建立会同时建立两者。

Hyper 普通个体用物前门以 **Scent 旗标**判断，战斗 Shadow 扩展还要求身份在三种具名香中；两个条件叠加。当前可选四件道具样本均无 Flags 字段，三种香因此**没有 Scent 旗标**：即使条件化地把该样本用作有效物品数据，有效 Hyper 时仍被普通入口拦在处理器之前。只在非 Hyper 使用、直接调用处理器，或作者另外提供合格旗标的变体中进入清 Hyper 逻辑；这些层不能合并。默认顶层更无四件道具，不安装样本补证。

起始阶段的两个 Nature 对照：存储性格 HARDY、M4000/G2500/H4/h80，JOYSCENT 倍率 1、无友好修正，先拦友好变化再下降 90，得 **G2410/H4/h80**；只把存储性格改为 LONELY 则下降 130，得 **G2370/H3/h80**，本次不因跨到 H3 而追补友好。计算用性格覆盖不替代这里的存储性格。两例假定工具及后续消息正常，未运行。

## 8. 净化室：编成、数学、推进与领取

### 8.1 持久编成与可达入口

9 组，各 1 个中心 Shadow 与至多 4 个非 Shadow 外圈，带朝向索引；组表查询只复制列表容器，成员仍是原个体引用，不创造新拥有者或副本。入口会先将「见过净化室」设真，再打开界面；PC 选项仅在该标志真时显示。脚本内另有调试入口，正常首次事件调用 U01 未证。全局净化室读取会懒建立，行走调用也可触发建立；不是必须看过 PC 才开始持有状态。

| 操作 | 校验与顺序 | 状态结果 |
| --- | --- | --- |
| 空位置从储存选择 | 选择器以取出模式启动、**不展开队伍面板**：盒内网格选中有成员的位置并选 Select 才返回 `[盒号, 格号]`；BACK 在「Continue Box operations?」中选 Yes 继续选人、选 No/取消确认退出；Close Box 在「Exit from the Box?」中选 Yes 退出、选 No/取消确认继续选人；退出才返回空（不给位置）。「队伍」按钮**不产生队伍选择**：内部位置先经外层成员门，映射盒格为空则继续选人循环（选择链三层见下）。放置本身的门：拒蛋、中心只 Shadow、外圈只非 Shadow | 放置成功后才从源位置删成员（队伍删除会压紧、盒侧不压紧）。此选择/删除链没有「保留最后可战斗队员」门，但该事实与「正常 UI 能取得队伍位置」是两件事 |
| 移动 | 从当前位置移除 → 暂持引用；可切换组后再放置 | 持有时不能退出编辑；没有取消即恢复原位置的事务 |
| 放置/交换暂持成员 | 同放置的蛋/Shadow 位置门；有旧成员则旧成员改为暂持，空位则释放暂持 | 无复制、无属主改写；不治愈、不给经验、不自动净化 |
| 替换（与储存） | 直接比较新旧 Shadow 查询的**原始返回值相等**，不先归一为布尔，也不走放置的蛋检查 | 原始结果匹配才交换当前位置与源储存位置引用；**非 Shadow 蛋在原始结果也匹配时可替换普通外圈成员**，即使普通放置拒蛋；可战斗/最后成员也无同等门 |
| 取出（WITHDRAW） | 双满检查＝队伍满且所有盒满；通过后直接调用入盒工具，再清当前位置或暂持引用 | 与最终领取的入队优先不同；当前盒→其他盒，返回值未验。**盒全满但队伍有空位**通过双满门，入盒返回 −1 后仍清源，不能保证该个体仍在队伍/盒/室中 |
| 旋转 | 中心存在、没有暂持且有外圈时可选 | 朝向循环加 1；不消耗资源，改变中心亲和与流量 |
| 组交换 | 整个组状态交换；取消选择回原组 | 中心/外圈/朝向一起移动，当前组指向目标组 |
| 返回 | 暂持者被阻止；无暂持时询问是否继续编辑/观看 | 已有编成改动即时保留；退出编辑后可能立即开始净化 |

**选择链三层合同（N01 已闭合修订）**：

1. **正常 UI 实际能返回什么**：选择器以取出模式启动（储存界面规格引用），队伍面板不作为正常入口打开。公开返回只在外层选人循环的出口产生：盒内网格选中有成员的位置并选择菜单中的 **Select** 才返回 `[盒号, 格号]`；BACK 先进入「Continue Box operations?」确认——选 Yes 继续选人，选 No（或确认中再取消）才退出并返回空；Close Box 进入「Exit from the Box?」确认——确认退出后返回空。**空返回只表示本次净化室不按新选中位置提交放置/替换**：选择期间已完成的存入/取出、持物/标记与当前盒变化**不回滚**（如先切换当前盒再退出，当前盒仍保持新值；先完成取出再取消，已完成的队伍/盒子移动保留）。
2. **特殊负位置的来源与传播**：「队伍」按钮在内部选择器产生特殊负位置，但**该位置先经外层成员门**：读到映射盒格为空时，外层**直接继续储存选人循环**——没有成员菜单、不向净化室返回位置、也不进入放置调用；读到成员 X 时先显示成员菜单（Select/Summary/Withdraw/Item/Mark/Cancel），**只有选 Select 才向净化室返回该原始位置**，菜单其它操作或取消不是位置提交。位置到达净化室后：经蛋/Shadow 门可实际放置并**删除该盒格**（盒侧不压紧）；替换分支在 X 与室内当前成员的 Shadow 原始查询结果相等时，**把室内当前成员写入该盒格**、X 进入室内。「选择并暂持」分支属于当前正常输入未发出的**备用命令分支**（既有可达性限定），只作直接触发分析、不混入正常按钮流程。「空源位置交给放置消费者 → 假」的合同仅在**绕过选择器的直接调用**（或其它明确前提）下成立，不能写成上述正常空格点击的结果。读取成功**不推断后续操作安全**：泄漏成员进入暂持/移动等后续流程的行为未穷尽，具名保留、不称安全；也不给参考补「队伍面板可打开」的界面功能。
3. **直接调用的下游合同**：调用方不经选择器、直接提供**有效队伍位置**时（脚本/调试等入口），放置读取该队伍成员、成功后从队伍删除并压紧——**此链没有「保留最后可战斗队员」门**：该守卫只存在于队伍/储存规格的特定界面入口（PC 存入前置、仓库屏存入/拿起/释放守卫等），不在净化室放置、也不在容器删除本身。此合同成立，但**不得作为正常选择 UI 的可达示例**；也不能用它证明正常 UI 能取得队伍位置。

替换门的正常状态对照：未曾设置 Shadow 标志的新普通个体可返回空；成功净化明确写标志 false，查询返回 false。二者在放置的真假分支都走非 Shadow，但替换的相等门不同：

| 储存新成员/当前外圈成员 | 原始查询结果 | 替换门 |
| --- | --- | --- |
| 两只新普通个体（均未设 Shadow 标志） | 空/空 | 通过此门 |
| 新普通个体/已净化个体 | 空/false | 拒绝，不交换引用 |
| 两只已净化个体 | false/false | 通过此门 |

以上只是该门，不代替其他前提。普通放置对空与 false 均按非 Shadow 处理，但仍拒蛋。

外圈插入最多 4 项；空值删除后压紧。插到某位置之后时，朝向位于插入点之后则随之右移；直接替换/删除只把朝向钳到有效范围，**不会确保继续朝向原来那一只**。例如 [A,B,C] 朝向 B（索引 1），删除 A 后变 [B,C] 但仍索引 1，转而朝向 C。越界直接入口多为无效/空返回，带数组下标的直接查询不一律保护；UI 只产生有界位置。详情控制器另有「选择并暂持」分支，但当前输入层仅返回位置、组切换、返回三族，没有发出该命令的正常分支；不把其潜在共享引用路径算作已可达 UI。

### 8.2 亲和、节奏与每步流量

对有序外圈 n 只（0..4），按环顺序考察每只对下一只（含最后到第一）。若任一攻击属性对任一防御属性是超有效，即此有向边有利；**NORMAL→NORMAL 额外视为有利**。不使用复合属性倍率乘积，所以「一对有利、另一对抵抗/免疫」仍可算有利；使用持久个体类型，不用暗影战斗副本的 SHADOW 强制类型。

令 E 为有利外圈边数，C 为中心对当前朝向成员有利时 1、否则 0（无可朝向成员为 0）：

- 节奏 `T = n(n+1)/2 + E`，不要求中心存在；n=0 为 0，最大 T=14。
- 中心存在时每步流量 `F = E + C + ⌊n/2⌋`；中心不存在为 0。普通显示亲和是有利 2、不利 1、无对象 0；该显示值不能直接当流量。
- 没有跨组「更多最佳圆圈」的额外流量奖励；源注释提到但实际流量未消费别组。其它 8 组只参与 LUGIA 净化门。
- 1 只外圈也形成自身到自身的环；纯 NORMAL 单只该边有利，而常见单纯同类型未必有利。4 只纯 NORMAL 外圈 T=14；中心也含 NORMAL 时 F=7，中心不占优势时 F=6。

每次世界迈步通知在队伍 256 步处理后更新 9 组；中心 G>0 才扣 F 并钳到 0。无外圈 F=0，不推进；正 G 到 0 且资格通过才提示准备好。已 0 不因后续步重复提示；编成改变使原本 G0 合格，需进入/结束编辑的检查来发现，不把步进提示视为唯一入口。室内推进不更新招式、不恢复成长、不改变 HP/Hyper 存储标志，也不重置队伍用 256 步计数。

### 8.3 资格、净化与接收

普通组：中心存在、G0 且至少 1 外圈；忽略外圈的查询仅用于「需要至少一只普通成员」的消息。LUGIA 另要求**全部 9 组节奏恰为 14**，不要求别组有中心；也不把 LUGIA 的 G 自动清 0。完成所有圆圈而 G 仍正时，只能继续流量推进。

领取先快照合格组列表，按组号逐一：选定并打开该组 → 净化演出接点（实际只刷新）→ 统一净化调用（§6）。**跨级恢复在该调用内的首个能力变化窗口先失败**，不进入存放/清中心或后续组询问，中心仍保留已部分修改的对象。只有该调用正常返回的路径（如有效 S0 同等级恢复）才继续：通用存放 → 无条件清中心 → 若还有下一组合格，询问是否切换；拒绝则关闭并停止，后面组仍保留。开始时存在任一合格组会直接进入该流程，不先询问第一只；可到达的命名等取消按 §6 处理。

**确实到达通用存放后**，队伍有位则入队，否则存盒；成功路径再次记录届时招式为首招。默认净化室跨级路径未到该段，不承诺其已学招或已被存放。双满时通用存放只提示并返回，随后调用者仍清中心；此前已完成的 Shadow 清除/缎带/成长及可到达的命名不回滚。这是到达前提，与 §6.2 更早的跨级失败、以及 §8.1 取出时「盒满而队伍有位」分开。
