# 野外被动变化与失败回程（净化正文；批次 8）

分类：Pokémon Rules（主）；Generic Kernel（步数/时间/持久）、Engine/Overworld Integration（地图/步进/帧钩子/转移）、User Interface（消息/菜单/调试）、Demo/Developer Experience（编译模板与事件编排证据）。本文件固定野外被动效果与失败回程的规则合同——哪些入口计步、计什么、按什么次序产生什么效果、病毒如何随日期推进、失能后按什么顺序回到哪里。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的与范围

**范围**：① 触发、计数与效果次序；② 行走友好度；③ 野外中毒与全队失能；④ Pokérus 状态与日期推进；⑤ 治疗点、治疗与失败回程；⑥ 集成、持久、开发者入口与证据边界。

**非目标**：不定义普通遭遇算法、友好度数值全集、战斗终局/钱款/资源结算、场地招式与道具合同全集、寄养/育种/孵化合同、Shadow/净化合同、漫游/雷达合同、Safari/捕虫合同（各归主规格）；不展开地图事件编排/治疗点解释/费用话术——只能按实际可读证据登记（U01/demo 规格）；脚本提供入口不等于默认事件确实调用。

**已通过边界（继承，不重开）**：GR-011／GR-013；WP37（漫游/雷达）；WP53（Safari/捕虫——捕虫分流按当前合同引用，不重新推断其计数/治疗/判奖）；战斗终局、败/平、钱款与资源合同；普通遭遇与 Repel 门；友好度数值；时间/场地与回程工具；Shadow/净化（各归其规格）。

## 2. 概念与术语

- **步进入口四分**：**普通玩家迈步**（玩家完成一步）；**强制路线/事件解释器移动**（玩家处于强制路线或地图解释器运行中完成移动——**步后入口发一般迈步通知并返回，不计全局步数/玩家周期/遭遇；实际完成移动先已通知，完整前提下合计两次（§3.1）**）；**原地转向**（可判定遭遇但不计步）；**地图帧更新**（每帧一次，含微更新路径，WP53 已证暂停命令循环链）。**GR-011（已关闭）**的入口差别保持：步进、转向、主动请求是不同入口，主动请求包装本身不写遭遇触发标记。
- **全局步数（持久于全局元数据）**：仅在普通玩家迈步时 +1（31 位回绕）；**计数初始化**：首次迈步前惰性为 0。各消费者读自己关心的周期（友好周期 128、毒伤周期 4）；**不因消费者重置全局步数**（友好度用的是独立计数 `happinessSteps`，§4）。
- **共享转移处理状态（handled）**：当步消费者顺序共享是否已处理转移的状态；任一消费者置真后，后续按该门跳过且不再判定当步遭遇。不规定单槽数组或其它容器实现；毒伤当前成员循环的有界继续规则仍见§5.2。
- **三类目的地状态（互相独立、不是同一份状态）**：**最近中心记录**（`pokecenterMapId/X/Y/Direction`——由接待/中心事件写入；证据为**公开入口存在＋编译侧对既有中心事件的识别谓词**——**识别 ≠ 构造**：不为事件插入中心记录调用、也不是生成模板（§7.1），demo 编排 U01）；**场地回程目的地**（`healingSpot`——进入带回程目的地元数据的地图时**覆盖写入**，由 Teleport 消费、**使用后不清空**）；**洞穴逃脱点**（`escapePoint`——洞穴入口写入、洞穴出口/逃脱类入口**使用后清空**；失败回程**仅到达普通末尾的路径清空**——家图缺失提前返回与捕虫分流不经此步（§7.1/§7.2））；**角色/全局家地点**（角色元数据 `home` 与全局元数据 `home`——静态数据，Teleport 与失败回程的回退）。
- **Pokérus 编码（个体字段，独立数学）**：单整数字段——**菌株 S＝高 4 位（⌊字段/16⌋），剩余期限 T＝低 4 位（字段 mod 16）**；**阶段**：字段＝0 → 未感染；T>0 → 感染期（1）；T＝0 且 S>0 → 已治愈（2）。**期限由菌株决定：T＝1＋(S mod 4)**（1–4 天）。
- **持久 ≠ 已落盘**：全局元数据随存档保存（《保存、启动、新游戏与继续》）；`stepcount`、`happinessSteps`、`pokerusTime`、三类地点、统计、开关的持久归属见 §8；运行时刻值（帧计时器、倒计时）与落盘分开。

## 3. 触发、计数与效果次序

### 3.1 步进入口与全局计数

- **普通玩家迈步（正常分支，按序）**：①全局步数初始化（首次为 0）并 +1（31 位回绕）；②读 Repel 激活态（计数 >0——遭遇规格门输入）；③触发玩家步进通知；④触发可转移步进通知（共享handled状态）；⑤**handled 为真 → 本步结束（不再判定遭遇）**；⑥事件未触发且不在菜单 → 判定遭遇（无可战成员/无遭遇可能/无类型/触发判定未过即返回；通过后选择遭遇、触发遭遇选择通知、允许门、双打门、公开开战（可覆盖）；最后写遭遇类型清空、遭遇触发标记、强制单打复位——遭遇规格主责）。
- **强制路线/事件解释器移动（早退分支）**：玩家处于强制路线或地图解释器运行中完成移动——**只触发迈步通知（携带玩家）并返回**——**不计全局步数、不发玩家步进/可转移通知、不判定遭遇**。地形效果钩子（煤烟拾取/草丛摇动/瀑布冰面自动移动）在此分支照常收到通知。
- **原地转向**：可判定遭遇（同一遭遇判定入口——遭遇规格），**不计步**；转向清理与步进清理不同（GR-011 已关闭合同，继承）。
- **任意事件完成一步**：触发迈步通知（携带该事件）——煤烟（任何移动者擦除第一煤烟层；只有玩家持袋且未达上限时增加资源/统计）、草丛摇动动画（地图场景内的占用格）、瀑布/冰面自动移动（仅玩家）。
- **帧更新**：每帧一次（含暂停微更新链——WP53 已证部分，不重开）。

**完成移动的组合调用（不把入口孤立计一次）**：一般角色移动完成先发一般步进通知，随后玩家步后检测才进入上述分支。正常地图场景、无冰面/瀑布自动移动、实际平移完成、未中断或转移、强制路线仍有效且后续等待使它保持有效（或解释器仍运行）时：先一般通知，再步后入口第二次一般通知并返回；全局步数、玩家周期均不推进。两煤烟层、玩家持袋且煤烟≤9997时可擦两层、资源/统计+2。普通完成步为一次一般通知后玩家链/全局+1；NPC完成步只有一次一般通知；直接调用步后入口只有其一次，不能冒充实际移动的两次。自动地形、中断、路线已结束或其它字段改写须另给前提。

### 3.2 各通知的消费者次序（事件分发合同）

- **帧更新**：Pokérus 日期检查 → 低电量警告 → 延迟 BGM → **电话计时（门：玩家持有 Pokégear、不在菜单/战斗/消息窗、非强制路线/解释器；刷新可战联系人、下次来电倒计时（≤0 重置为 **20–39 整分钟（40 不含）**随机、按帧递减）、到 0 生成来电——注册 ≠ 必然产生效果；电话合同未归本文件，仅登记次序与门）** → 捕虫倒计时（WP53 主责）。
- **迈步通知（任意事件）**：煤烟拾取 → 草丛摇动 → 瀑布/冰面自动移动 → **冲浪跳跃收尾（门：地图场景＋事件是玩家＋有冲浪临时底座坐标：清底座；正在结束冲浪时取消载具、重置遭遇步数、播地图 BGM、清结束标记——世界时间场地规格主责引用）**。
- **玩家步进通知**：行走友好度 → 寄养步进处理（寄养规格主责）→ Repel 计数（§3.3）→ 雷达电量（WP37 主责）→ **Shadow 心灵量表与净化室（两个层级分列）：①**队伍成员计数门**——对可战成员逐个处理，**心量表非零才进入计数**（为零跳过；人工负值同样进入计数，与「大于 0」门不同，不能据此臆造量表下降）；计数 +1、到 256 执行步行心量变化（量表变化仍引用 Shadow 规格）、阶段归零做净化就绪检查、阶段变化更新 Shadow 招式、计数归零；②**净化室更新是对象存在门**——位于成员循环结束之后、按净化室对象是否存在调用其更新（自身组级效果门仍引用 Shadow 规格），**不要求队伍里有正心量表成员、也不等待 256 步**——队伍全为普通可战个体（无 Shadow）但净化室已存在且室内组满足 Shadow 规格推进条件时，普通玩家步进仍调用净化室更新（FP24 对照）** → 孵化步数（孵化规格主责）。
- **可转移步进通知（handled 串联）**：野外中毒（§5）→ Safari 计步（WP53 主责）。
- **换图**：新图设置（回程目的地覆盖写入、地图容器清空、遭遇表重建、已访问记录）→ 天气（世界时间场地规格主责）→ 足迹 → 强制骑行 → 漫游推进（WP37）→ 雷达取消（WP37）→ Safari 清空（WP53）→ 捕虫清理（WP53）。
- **地图/精灵集变更**：暗度精灵、位置窗 → 捕虫定时器（WP53）。
- **每个消费者仍由原规格主责**——本文件只登记次序与门，**不在本文件再算一遍同一步**。

**煤烟状态与收集门分开**：每次一般步进通知读取该移动者所在真实格，按图层2→1→0找首个煤烟层，擦除该层后停止。NPC、玩家无袋也擦除，无资源/统计；玩家持SOOTSACK时资源夹在0…9999，统计只加实际正增量。9999时仍擦除但资源/统计+0；低于上限一次+1。此规则按通知次数应用，不按孤立“玩家一步”假定只一次（§3.1）。

**低电量警告门与临时会话**：必须放电中，且满足（剩余秒数非空并≤600）或（电量百分比非空并≤15）之一；当前临时状态尚未警告，且不在菜单/战斗/消息窗、非强制路线、解释器未运行才继续。先置已警告状态，再请求消息；门阻止时不置状态。同一临时状态中充电后再放电也不重复，新的临时状态可能再次提示；仅脚本文本检索未见其它重置，不能扩张为插件/宿主保证。10%放电时菜单阻止而仍未警告，退出菜单首个合格帧置状态并请求一次；次帧不再请求。

### 3.3 Repel 计数的步进侧事实

- **写入**：Repel 道具（道具规格主责）——已激活时拒绝（效果仍在）、否则播放音效、统计 +1、按档位写入步数（100/200/250）。
- **步进递减（玩家步进通知）**：计数 ≤0 或玩家在冰面 → 不计；否则 −1；**减到 0**：背包无 Repel 旗标道具 →「效果消失」消息并结束；**有** → 确认「再用一个？」——确认则打开按 Repel 旗标过滤的背包选择屏，选定即使用该道具（消耗链回道具规格）。
- **遭遇门输入**：`repel > 0` 只是遭遇规格遭遇门（允许门：野生等级低于队首（可战）成员等级则拒绝并清累积——遭遇规格主规格，本文件不重算）。

## 4. 行走友好度

### 4.1 步数累计与周期门

- **独立计数（`happinessSteps`，持久于全局元数据）**：普通迈步时初始化（首次为 0）并 +1；**未达 128 即返回**；**到 128** → 对**全体可战成员**（非空、非蛋、未濒死——可战队伍集合）**逐个以 1/2 概率**（0..1 均匀整数为 0 才生效）**执行一次步行类别的友好变化**（**数值、获得地/豪华球/安抚铃修正与封顶只引用成长规格**，本文件不复制一套数学）；随后**计数重置为 0**。
- **空/全不合资格队伍**：队伍无可战成员（全蛋/全濒死/空）→ 循环无对象，**计数仍重置为 0**（周期正常消耗）；有事件触发不等于自动进行进化检查（进化检查归战斗/升级入口，战斗结果/《基础进化》引用；实际调用未证的部分不补成保证）。
- **资格与限制（逐项）**：**蛋**（非可战成员——不参与）；**濒死**（同上——不参与）；**Shadow**（友好变化覆写：**Shadow 个体且心灵阶段 ≥4 时不产生友好变化**——Shadow 规格主责，本文件引用）；**正值修正与封顶消费**（获得地一致 +1、豪华球 +1、安抚铃 ×1.5 取整、软顶配置开启时封顶到 179 以下——**默认软顶关闭**（配置值），成长规格/《规则配置档案与数据变体》引用）。

### 4.2 与步行相关的其它友好写入口（边界引用）

- **濒死（「faint」）**：野外中毒濒死时写入（§5）；**负值修正不受正值加成**——数值引用成长规格。
- **未知方法**：未登记的方法名在变化入口报错（防御性边界，成长规格引用）。

## 5. 野外中毒与全队失能

### 5.1 默认设置与配置变体

- **默认（机制世代 8）**：`POISON_IN_FIELD` 为**假**（世代 ≤4 才为真）——**默认不发生野外毒伤**（钩子第二门直接跳过）；`POISON_FAINT_IN_FIELD` 为**假**（世代 ≤3 才为真）——即使开启野外毒伤，**默认 HP 到 1 即清毒、不在野外濒死**。
- **配置变体（两个独立开关组合）**：野外毒伤开关（≤4 世代语义）× 野外濒死开关（≤3 世代语义）——四种组合按两个配置分别登记（不把「更代」当作单一开关）。

### 5.2 步进毒伤处理（逐项真实顺序）

**门（按序）**：①handled 已为真 → 不动；②**野外毒伤开关为假 → 不动**；③**全局步数不是 4 的倍数 → 不动**（每 4 步一次）。

**逐成员处理（对循环起点求值一次的可战成员快照，按队伍顺序；每个入列对象轮到时仍查当前毒状态与免疫）**：

1. **资格**：成员**未中毒 → 跳过**（**未中毒者在可战集合内、被状态门跳过**——不损 HP、不清毒、不反馈；蛋/已濒死者**不入可战集合**）；**免疫特性 → 跳过**（不损 HP、不清毒、不反馈）。
2. **音效/闪烁**：本批次**只在第一次实际处理时各发生一次**（毒步音效＋红色闪烁——**不是每个中毒成员各一次**）。
3. **HP 损失**：`HP > 1` 或野外濒死开关为真 → HP −1（开关为假且 HP=1 时不扣）。
4. **临界 HP**：**HP=1 且野外濒死开关为假 → 清状态为无异常＋「扛住了毒」消息**——本次不再继续处理该成员（**不发生濒死、不写友好**）；**HP=0（仅开关为真可达）→ 「faint」友好变化＋清状态为无异常＋濒死消息**。
5. **全队检查（每个成员处理完后立即做）**：**可战成员数归零 → handled 置真并调用全队失能交接（§5.3）**。**handled 没有显式中止当前循环**（控制流事实）——**但不能据此推导交接后剩余成员仍被继续毒伤**：无外部改队/改状态时，若快照中后面仍有可战成员，可战数就不会先归零（**最后可战者倒下时不存在未处理的可战尾部**；原已濒死的尾部不在快照内）；普通回程会**立即治疗全队并清除毒状态**——其后快照中剩余成员轮到时，会因毒状态已清而被各自的状态门**跳过**（不扣 HP、不濒死）。保留人为回调改状态夹具时，必须明确注入点、快照成员与治疗后的逐项门（FP08）。

### 5.3 全队失能交接（区分单个成员濒死与全队失能）

- **直接检查入口**：**可战成员数归零才执行**——两条消息（「没有能战斗的宝可梦！」＋「眼前一黑！」）、BGM/BGS 淡出、**淡出块中调用失败回程**（§7.2）。**单个成员濒死 ≠ 全队失能**——只剩一个可战成员倒下时才进入本交接。
- **有界前提**：本入口是公开函数——**直接检查入口的调用者**（中毒循环、以及任何脚本入口）按同一门执行；**异常/空队伍**（无可战成员）直接调用时同样进入消息＋淡出＋回程（有界前提：可战成员数为零即成立，不附加队伍非空校验）。

## 6. Pokérus 状态与日期推进

### 6.1 领域状态与编码（独立数学）

- **编码**：单整数字段——**菌株 S＝⌊字段/16⌋（高位），剩余期限 T＝字段 mod 16（低 4 位）**；**阶段判定**：字段为 0 → **未感染**；T > 0 → **感染期（阶段 1）**；T＝0 且 S > 0 → **已治愈（阶段 2）**。**期限由菌株决定：T＝1＋(S mod 4)**（1–4 天）。
- **赋予**：**已治愈（阶段 2）→ 拒绝（不能再感染、统计不加）**；**感染期（阶段 1）重复赋予不拒绝**——**显式合法菌株（1–15）被尊重（不随机）**；**未指定或越界（≤0 或 ≥16）才 1..15 均匀随机**；**统计仍 +1**（重复赋予的许可与统计分列）；期限按菌株计算（1–4 天）后写入。
- **重设期限**：字段为 0 → 不动；否则**按当前菌株重算期限并写回（保留菌株）**——**对已治愈个体同样生效**：T 被重设为 1＋(S mod 4) ≥ 1，**阶段随之回到感染期**（「重设期限」不是「保持已治愈」）。
- **降低期限**：**仅感染期生效**——字段 −1；**T 减到 0 → 阶段变为已治愈（2）**。
- **治愈**：**只清期限部分（T 置 0）、保留菌株**（**不是无条件变成已治愈**）：感染期输入 → 阶段变为已治愈（2）；**未感染输入（字段为 0）→ 保持字段 0、阶段仍为 0**（不凭空成为阶段 2）；已治愈输入 → 期限本为 0、无变化。**个体治疗不触碰病毒字段**——HP/状态/PP 恢复与 Pokérus 无关联（§7.3）。

### 6.2 每帧日期比较（时间戳首次写入来源单列）

- **门（按序）**：①玩家不存在或**原队伍中没有感染期成员 → 不动**（**首门看原队伍——带感染状态的蛋也能满足首门**）；②**上次时间（`pokerusTime`）为空 → 不动**（**默认值存在不等于有正常初始化调用**——仅脚本检索未见初始化写入者，首次推进依赖外部写入，demo 事件未知归 U01；不臆造每日必然推进）；③**上次时间的年/月/日与当前墙钟任一不同 → 推进**。
- **推进（一次）**：对**非蛋集合**逐个检查状态，仅感染期（阶段1）降低期限，阶段0/2不变（**扣期限才使用非蛋集合**：**濒死成员在集合内**（非蛋即入列）；**蛋自身不减期限**；**箱内/寄养成员不在集合内**——其期限不随本入口推进）；随后**上次时间＝当前墙钟**（**更新时点＝推进之后立即写入——扣期限集合为空时时间戳仍更新**，见 FP14-a）。
- **日期边界**：**日期相同 → 不推进**；**跨一天 → 推进一次**；**跨多天 → 仍只推进一次**（推进后立即把上次时间写为当前——**不补跳过的天数**）；**时钟回拨**（上次日期在未来）同样满足「不同」——**也推进一次并写回当前**（比较只看年/月/日是否不同，不区分方向）。

### 7.2 失败回程主流程（按真实顺序）

**分流（入口）**：野外全队失能（§5.3 淡出块）、普通战斗败/平且**不可败**（战斗结束通知——败/平且 `canLose` 为假 → 恢复音乐后调用，战斗结果规格引用）、**可败剧情战斗**（`canLose` 为真 → **不进入本流程**，战斗结果规格主责）、**事件 Game Over**（解释器命令——BGM/BGS 淡出＋淡出块中以 gameover 实参为真调用——**消息措辞与正常回程不同**）、**捕虫大会**（**最先检查**——捕虫会话为真 → 捕虫特殊回程并返回，**不执行本流程任何后续步骤**；按当前 WP53 合同引用，不重新推断其计数/治疗/判奖）。

**捕虫分流之后的真实顺序**：

1. **统计**：`blacked_out_count` +1（**捕虫分流不执行本步**；家路径同样计数）。
2. **治疗**：**立即对全队执行全体治疗**（HP/状态/PP 全恢复；**先于目的地解析**）。
3. **中心存在（ID 存在且 ≥0）→ 中心路径**：消息（gameover 与正常两种措辞）→ **取消载具** → **跟随者清理**（移除全部跟随者并注销伙伴，失败兜底不阻断）→ **`STARTING_OVER_SWITCH` 置真** → 转移参数取中心记录 → 下车 → **仅当地图场景时转移** → **请求地图刷新**。
4. **无中心 → 家回退（四种结果分开）**：取角色家，缺失取全局家——
   - **家存在但家图资源缺失（提前返回）**：（仅调试模式给出消息提示）**再次全体治疗并立即返回**——**无回家措辞、开关不写入、转移参数不设置、不转移，且不到达末尾的逃脱点清理（旧逃脱点保留）**；
   - **家存在且图资源存在 → 家路径**：消息（gameover 与正常两种措辞）→ 取消载具 → 跟随者清理 → 开关置真 → 转移参数取家 → 下车 → **仅当地图场景时转移** → 刷新；
   - **无有效家**：**仍显示回家措辞（普通/Game Over 两种）**→ 再次全体治疗——**无提前返回**（随后到末尾清逃脱点；开关不写入、不转移）；
5. **末尾**：**清空逃脱点**——**仅到达普通末尾的路径**（中心路径、有效家路径、**无家路径**）；**家图缺失的提前返回与捕虫分流不经过本步**。

**非目标与不承诺**：战斗结果规格已处理的钱款与战后资源合同继续引用——**回程入口不另加默认扣款或整档重置**；**禁止概括为每次必定换图或事务回滚**——转移未发生的分支（非地图场景、家图缺失、无家）按 §4–§5 逐项列出，不虚构异常兜底。

### 7.3 恢复入口的实际覆盖

- **个体完整治疗**：**蛋 → 不动**；否则 HP 全恢复、异常清除（状态与计数）、**全部招式 PP 全恢复**、待进化标记清除——**不触碰 Pokérus 字段、不写持有物/友好/形态**（Shadow/形态覆写归 Shadow/《动态形态与展示属性》引用）。**「可指定单一招式」不成立**：单招式 PP 恢复属于专门入口 `heal_PP`（可选单招式下标；缺省为全部招式）——**完整治疗没有选择单招式的输入**，两者分开。
- **队伍治疗**：对**队伍全体成员**（含蛋——蛋在个体治疗处自然不动）逐个个体完整治疗。
- **事件「全部恢复」（解释器命令，实参为 0 时）**：**存储治疗配置为真（`HEAL_STORED_POKEMON`，默认世代 ≤7 → 默认世代 8 为假）→ 仅队伍治疗**；**为假（默认）→ 遍历队伍与箱内全体**逐个个体完整治疗。**「全部恢复」的名字不承诺超过个体完整治疗的字段覆盖**。
- **存入治疗（配置不只影响全部恢复命令——引用队伍/存储规格已批准合同，不重开）**：同一配置还控制**存入侧治疗**——**复制入盒、捕获入盒、捕获存储、战斗侧捕获存储、界面放下/存入/交换到盒**：开启时**先保存待进化标记 → 完整治疗 → 恢复待进化标记**（**存入路径保留待进化标记；直接完整治疗则清除**）；**配置为假（默认）→ 存入不自动治疗**（队伍/存储规格合同引用）。

战斗后持物结果引用已接受捕获/战斗结果合同：实际参与伙伴时，当前玩家队伍与原有序参与成员可分离且共享个体身份；满队换出可能使盒中旧成员被还原为后继物品、留队成员被写空。只有一次正常终局还原，先于外层治疗/世界拾取；治疗本身不还原持物，后续按实际当前持物消费。不要求源数组布局，也不把伙伴登记等同参与，或把每个成员自身初始物品当无条件最终值。

- **逐成员处理的剩余循环**：全队失能交接（handled 置真＋回程启动）**没有显式中止当前循环**（控制流事实，§5.2 ⑤）——**但不能据此推导交接后剩余成员仍被继续毒伤**：无外部改队/改状态时，最后可战者倒下即不存在未处理的可战尾部；普通回程立即治疗全队并清除毒状态，其后快照中剩余成员轮到时被各自状态门跳过（不扣 HP、不濒死——有界合同见 §5.2）。
- **日期边界**：`pokerusTime` 为空 → 不推进（初始化写入者未定位，U01）；跨多天与时钟回拨都只推进一次并写回当前（§6.2）；**不臆造每日必然推进**。
- **回程分支**：非地图场景 → 不转移（统计/治疗/开关前的步骤已执行；开关写入与转移参数已设置但转移不发生——**刷新闻仍请求**）；家图缺失 →（仅调试消息）再次治疗后**提前返回**（无回家措辞、开关不写入、转移参数不设置、不转移、**不到达末尾逃脱点清理，旧逃脱点保留**）；无家 → 仍显示回家措辞（普通/Game Over 两种）＋再次治疗——**无家不是提前返回**（随后到末尾）；**逃脱点仅在到达普通末尾的路径清空（中心/有效家/无家）——家图缺失提前返回与捕虫分流不经此步**；捕虫分流最先返回（统计/治疗均不执行）。
- **恢复边界**：蛋在个体/队伍治疗中自然不动；「全部恢复」的覆盖不超过个体治疗边界（不触碰 Pokérus、持有物、形态——Shadow/形态归 Shadow/《动态形态与展示属性》）。
- **未知/未证**：中心记录与解释事件的实际编排（U01/demo 规格）；离线时间语义；素材存在与播放（U01/素材保留）；宿主随机源序列；地图事件运行可达性（模板 ≠ 默认运行）。
