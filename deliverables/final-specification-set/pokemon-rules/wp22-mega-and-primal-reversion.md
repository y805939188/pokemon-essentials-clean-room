# Mega、Primal 与显式还原（净化正文；批次 5）

分类：Pokémon Rules（主）、Combat Requirements、Creature-RPG 与 User Interface（接点）。本文件定义两种可逆特殊形态各自的资格、提交与还原。全部内容为静态证据与独立固定算术；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的、范围与用户流程

Mega 的常见玩家流程为进入选招菜单 → 切换 Mega 待执行选择 → 选择招式/目标 → 到执行时点变形并使用招式；取消待执行选择不会消费本场次数。Primal 在合格个体入场时自动尝试，不要求玩家在选招菜单登记。二者的「变形成功」「本场 Mega 已用」「个体当前特殊形态」是不同事实。

战斗动作阶段、次数与排序主规则引用战斗规格，所属训练家映射引用战斗上下文规格，普通换下引用换人规格。本文件补齐个体数据与这些阶段的连接，不另立一套战斗时序。一般进化、其他动态形态、能力效果族、捕获算法不属于本文件。Primal Reversion 在入场处指**进入原始形态**；本文件用「解除 Primal」表示恢复普通形态。

## 2. 输入、输出与状态域

| 状态／输入 | 读取者与时点 | 输出／写入范围 |
| --- | --- | --- |
| 基础物种、当前简化形态、形态数据中的 Mega 石／招式／还原形态 | 个体资格查询及实际 Mega 提交重新读取 | 找到目标形态号；没有匹配则无可用目标 |
| 个体持物、已知招式 | 资格查询；读持久个体，不是战斗招式临时复制列表 | 只判断身份匹配，不消耗石、环、宝珠或招式 PP |
| 战斗席位、侧、所属训练家、是否野生、Transform、Sky Drop | 战斗许可与调用者门 | 允许显示 Mega 选择或拒绝；非持久拥有者号码比较 |
| 全局禁止 Mega 开关 34、环标志物品目录、背包／所属训练家物品表 | 战斗创建收集环目录；许可时读实际资源 | 玩家本人读实时背包，伙伴／对方读其业主物品表 |
| 每侧每训练家 Mega 状态 | 新战斗初始化、菜单登记、执行、撤销 | 未用／某席待执行／本场已用；不属于个体持久属性 |
| Primal 物种处理器与当前持物、存储形态 | 每次 Primal 资格／查询／执行／解除 | 当前是否合格与是否已 Primal 随持物变化；无共享 Mega 次数 |
| 形态提交、能力值、HP、类型、特性 | 提交个体→战斗回读 | 持久个体形态与能力缓存变化；战斗数值／属性／特性更新；场景刷新；可能登记全局玩家图鉴 |

## 3. Mega 个体规则与内容

**M01 目标选择**：在物种数据遍历顺序中，找同基础物种且「解除 Mega 后形态」等于个体当前简化形态的条目；其要求的石与当前持物相同，**或**其要求的招式已掌握，即是候选。首个匹配条目决定目标。两个字段同时有值时是替代条件，不是必须同时满足。没有目标用 0 表示；可 Mega 要求目标大于 0 且不同于当前简化形态。默认数据 48 个目标、46 个基础物种，全部解除至 0；47 石＋1 招式型，详[默认资格附表](wp22-transformation-data.md)。SLOWBRO 的 Mega 目标为 2，普通形态 0 可用，地区形态 1 即使带相同石也不满足默认还原形态条件。

**M02 当前 Mega 身份**：读取当前形态的数据，只要它有 Mega 石或 Mega 招式字段，就算 Mega；不要求当前仍持有该石／仍知道该招。解除读取该当前形态的还原形态，非 Mega 无解除目标。直接执行个体 Mega 只在目标 >0 时提交，直接解除只在目标 ≥0 时提交；不负责战斗许可、环、次数、统计、演出或战斗副本同步。

**M03 查询不等于提交**：查找目标与可用性本身不写形态。简化形态优先使用强制形态；当前数据不存在特定形态时可回退基础物种数据（《个体身份、物种与归属》）。形态锁定并不因本文件的变形／解除自动清除，故人工锁定可能掩盖存储形态写入；不承诺它与正常路径等价。未知物种导致后续数据解引用失败的通用规则引用《内容身份、注册与 schema》与个体规格，不能用「无目标」概括全部坏输入。

**M04 默认与可选配置**：机制世代 8；Mega 后重算该席位行动顺序默认开启（派生于世代 ≥7），禁止 Mega 开关号 34 的当前游戏值来自存档／事件，不能把脚本声明当实际开关观察。Mega 资格本身无「世代必须 ≥6」门。环目录按物品 MegaRing 旗标，默认仅 MEGARING；MegaStone 旗标不是个体目标选择的必要门，目标由物种数据字段绑定。默认数据集与备份集不混合。训练家顶层数据对本次检索的环／代表性石／宝珠未命中，只能说明没有这批具名数据样本，不能断言 Demo 中不可获得或无此功能。

## 4. 战斗许可、登记、取消与实际执行

### 4.1 分层资格

| 层 | 实际门与结果 |
| --- | --- |
| 战斗个体可 Mega | Transform 效果为真则否；否则用持久个体 M01。没有额外 Shadow 门 |
| 正常战斗许可 | 禁止开关开 → 否；个体不可 Mega → 否；野生席位 → 否；然后调试 Ctrl 可直通；否则 Sky Drop 中 → 否，无环 → 否，该所属训练家不是「未用」→ 否 |
| 正常玩家菜单可达 | 须可显示命令、可进入普通选招菜单；安可／无可用招式走自动选招，特殊模式自动菜单也可截获，故个体可 Mega 不保证该入口出现按钮 |
| 裸登记／切换 | 只按侧与所属训练家记录席位，不重做许可；登记可覆盖该业主旧席位，切换相同席位则撤销。不是防重复／非法输入校验器 |
| 正常攻击调用者 | 非野生、未濒死、已选择招式且等于所属训练家的登记席位才调用执行；追击打断可在换人阶段提前调用（战斗动作规格） |
| 执行器自身 | 对象与个体存在、当时仍有可用 Mega 且尚非 Mega 才继续；不再次核对开关、环、Sky Drop、野生、所属训练家次数或登记。直接调用不具备正常调用者全部门 |

环按**当前战斗业主**归属：玩家侧业主 0 使用玩家背包；同侧伙伴有自己的物品表与次数，对方每位训练家也分别计次。个体的原拥有者／外来身份不决定环来源。普通一位训练家带多只可 Mega 个体，共用一次额度；一侧两位训练家不是合计一次。

### 4.2 待执行状态与取消

状态机：`未用 → 席位待执行 → 已用`；待执行 → 未用可由再次按按钮、取消整份选择、改选 Shift 或下一命令阶段清理残留实现。已用状态不会被新回合的残留清理复位。撤销只清「正好是该席位」的待执行记录；不能使已用恢复。选招不合法或多目标选择取消，返回选招继续时可保留 Mega 待执行选择；退出整个战斗菜单触发外层撤销才清除。执行前资格丢失而直接返回，不消费 Mega 次数，残留登记下一命令阶段再清。正常变形完成后，同一个体换下再换入仍是 Mega，但原业主额度仍已用。

### 4.3 提交与能力反馈

执行时先对玩家本人所属者累计 Mega 统计，再记原战斗特性；若幻觉能力当前有效则触发解除幻觉接点；显示通用「石与环反应」消息或消息号 1 的特殊意愿消息，随后变形。缺环名时消息有默认名称回退，这不是授予资格。目标形态名称非空优先，缺省为 Mega 加物种名；消息号 1 以数据决定，不由物种硬编码。

变形提交到持久个体，再同步战斗形态并完整回读数值／属性／特性，刷新画面，最后标记业主本场已用。GENGAR 已经 Mega 时清意念移物计数。之后执行失去旧特性、获得当前特性的接点并按设置重算该席位行动顺序；具体能力与天气连锁引用战斗能力规格，统计不是独立回滚事务。执行期返回失败的早退不走上述写入；中途异常没有补偿保证。

继承《动态形态与展示属性》§4：形态提交会清特性缓存、调用形态提交处理器、重算能力、登记全局玩家图鉴。这里先提交个体，再以战斗形态写穿个体，**同值也再提交一次**，最后刷新还会重算；不能承诺只调用一次形态处理器或只登记一次。默认 Mega／Primal 物种没有本文件特有的招式重置步骤；不重建战斗招式、不回满 PP、不清全部阶级／其他战斗效果。图鉴写入不受三个战斗包装的内部战斗门统一限制（图鉴规格）。

HP 变化遵循《属性派生、特性选择与六项能力》重算合同：保持已损失 HP 的差值，并受最低存活 HP 规则约束，不保证百分比不变或最大 HP 不变。默认数据有具名例外：METAGROSS,1 的 HP 基础值 95，基础形态 80；50 级、IV／EV 均 0 时最大 HP 140→155，当前 70→85；解除回 140／70。该数据与官方系列预期不作等同，见附表。濒死路径解除只写个体，没有完整刷新战斗副本，二者可在退出时短暂不同。

## 5. Primal 独立合同

**P01 条件**：物种处理器返回一个非空形态值，即有 Primal 形态；默认 GROUDON 持 REDORB、KYOGRE 持 BLUEORB 均返回 1，其余无返回。当前 Primal 身份＝处理器仍有返回且与**存储形态**相等。由此，持物被外部直接移除后，即便存储形态仍为 1，也不再被该查询视为 Primal。这不同于 Mega 按当前形态数据判身份。

**P02 执行与时机**：正常开场／换入的入场处理按速度序，在位置治疗、入场伤害及其濒死／经验／裁判之后，检查一般形态，随后尝试 Primal。执行器拒绝空对象／无个体／濒死／Transform／无目标／已 Primal；不查环、禁止 Mega 开关、野生身份、所属训练家额度，也不写 Mega 登记／统计。合格野生个体亦可进入 Primal；同侧多个个体可分别变形。

**P03 传播与能力**：持久形态→战斗形态→完整数值／类型／能力回读与场景刷新，同 §4.3 的重复提交边界。KYOGRE／GROUDON 各有前后动画调用，再给 Primal 消息。该执行器本身不调用 Mega 的失去／获得能力链，也不主动调用 Mega 后的排序重算；实际入场消费者紧接持续能力检查与入场能力，故新的能力可以在该处参与天气等效果。不能从「执行器无能力钩子」推导入场没有能力效果，也不能对裸 Primal 调用补造同一效果。

**P04 解除**：若存在专门解除处理器并有返回，直接提交该返回；否则仅当前 Primal 身份为真时提交 0。当前快照无专门解除处理器登记，只有上述两个进入处理器。缺宝珠→当前身份假→裸解除不回 0，是人工改物／坏状态边界；普通物品移动的不可丢失门约束两种宝珠与各自物种（战斗招式规格），不能把正常门与直接状态编辑混同。返回 0 的自定义进入处理器在接口层也算「非空」，与 Mega 必须目标 >0 不同；此处是静态变体合同，非默认数据或插件运行保证。

## 6. 换下、濒死、捕获、终局与设施对照

| 入口 | 状态与写入次序 | 结果／限制 |
| --- | --- | --- |
| 普通换下 | 换下能力→一般离场形态处理器／HP 钳制→战斗副本视为濒死以收尾能力 | **没有统一解除 Mega／Primal**；持久 HP 不因副本视为濒死归 0。再次上场保留特殊形态，Primal 查询已是目标则跳过 |
| 真正濒死 | 濒死流程清效果／状态→一般离场处理→若 Mega 则解除→若 Primal 则解除→清选择／成就记录等 | 改持久个体；该路径不完整回读战斗形态。默认 Mega 数据 HP 降低或不变，不靠解除复活；不能用此概括所有自定义 HP 形态 |
| 捕获成功 | 移出对方队伍／经验／战斗者复位→必要属主改写／球效果／球种→解除 Mega／Primal→Shadow 招式更新／首招记录→一般离场处理→待接收队列 | 捕获规格为主；解除在图鉴正式接收与入队／送盒之前，不恢复 Mega 额度 |
| 捕获满队换出既有成员 | 一般离场处理→剧毒计数清零→解除两种形态→送盒／移出队伍／记录左移 | 已送盒对象不会再依靠世界全队善后；本入口自行解除。取消成员选择未走这些写入 |
| 正常战斗对象终局 | 处理捕获队列→场景结束→撤销选择及离场能力→玩家侧参与个体一般离场处理／持物还原 | 此层**无统一解除两种特殊形态**；裸战斗／回放不能假设还调用世界或设施包装 |
| 世界战斗返回 | 玩家当前全队清剧毒计数并解除两种；有伙伴时治疗玩家及伙伴、解除伙伴；可输负／平再治疗；随后结束通知 | 对方原队伍不在该全队循环；结果 0 若正常返回世界包装，也可走此善后；异常未返回不能保证执行（战斗结果规格） |
| 设施单场包装返回 | 双方等级恢复→各成员治疗→解除 Mega／Primal→恢复各自原物品→记录／统计 | 双方都处理，解除在恢复旧物品前；回放入口不调用这套包装（设施/回放规格） |
| 捕虫大会失败回程接点 | 玩家队伍治疗→解除两种→转评判 | 只登记已读接点，完整会话留专门模式规格；不扩本文件范围 |

普通换下解除与世界终局解除不是同一事件；「离场处理器被调用」也不意味着它一定返回普通形态。完整捕获／队伍重排由捕获规格定义。显式解除不消费物品、不逆转已产生的图鉴／统计／Mega 次数。

## 7. 失败、不变量与扩展边界

- 无可用数据、石或招式不匹配、来源形态不匹配均使正常 Mega 不可登记；执行前再次无法取得目标则不变形。不会选择列表中的第二条来绕过首个匹配条目的返回语义。
- Transform 阻止战斗层获得 Mega／Primal 资格；个体裸接口不检查该战斗效果。Shadow 没有额外统一禁止门；两域实际组合由各入口与招式／持物状态决定，不按本文件阅读顺序新增优先级。
- 同一玩家业主一次额度在成功执行后不可由换下、濒死、取消或解除返还；裸登记、调试直通并不承诺守住正常次数限制。
- 资格读取与提交不是原子事务，数据处理器／消息异常不自动回滚已记统计或形态；默认数据与自定义处理器坏输入分列。
- AI 先尝试换人、道具与特殊自动菜单；没有截获才在许可真时登记 Mega，随后选招。差招转换人成功会撤销该登记（AI 规格）；评分／预测及记录回放 Mega 标记缺口（回放规格）不改变本文件真实变形规则。
