# Safari 与捕虫大会（净化正文；批次 8）

分类：Pokémon Rules（主）；Creature-RPG（会话/参赛队伍/捕获保留）、Combat Requirements（特殊战斗交界）、Engine/Overworld Integration（地图/步进/帧/转移钩子）、User Interface（暂停菜单/调试/专用窗口）。本文件固定两种捕获活动的规则合同——会话有哪些状态、何时开始/结束/清空、遭遇如何被接管、每个动作消耗什么、结果如何写回、保留与判奖如何结算、哪些入口取消哪些状态。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的与范围

**范围**：① Safari 会话与世界交接；② Safari 单次遭遇、动作与结果；③ 捕虫大会会话、参赛队伍、时间与越界；④ 捕虫大会战斗、Sport Ball 与保留结果；⑤ 判分、对手结果、名次与结算；⑥ 公共交界、界面、保存与 demo 配置。

**非目标**：不定义普通捕获/接收算法全集（《捕获判定与接收策略》）、常规战斗算法、普通遭遇算法、钓鱼、华丽大赛（各归主规格）；不展开接待/判奖/奖励事件的实际编排——费用、参赛日期、奖励、接待话术须有 demo 证据（U01/demo 规格）；脚本提供入口不等于默认事件确实调用。

**已通过边界（继承，不重开）**：GR-011（步进、转向、主动请求是不同入口）；GR-013（参战标记及正常终局合同）；WP37（漫游覆盖/结果返回、雷达连锁取消与通知、直接入口异常不自动等同正常公开链，按当前已批准字节继承）。本文件不为 Safari/捕虫补「所有覆盖结果统一布尔」的规则。

## 2. 概念与术语

- **Safari 会话（持久于全局元数据）**：起点四元组（图 ID、x、y、方向——开始入口写入，结束清空）、剩余球数、本次捕获数、剩余步数、会话决定（0＝进行中、1＝已决定待结束）、会话存在标记。**持久 ≠ 已落盘**——落盘只经保存流程，且模式中保存入口不可用（§8.3）。
- **Safari 区域**：接待图（会话起点所在图）∪ 带 `SafariMap` 元数据旗标的图；接待图单独处理——它可以在室外、有自己的草丛。
- **捕虫会话（持久于全局元数据）**：Sport Ball 预算、会话决定、保留捕获个体、单调时钟起点、结束标记、存在标记、暂存原队伍成员、参赛 NPC 下标集、名次表（每条＝[参赛者下标或 −1＝玩家, 物种, 分数]）、判奖点四元组、比赛图集、接待图集、参赛成员下标、上次比赛墙钟秒。
- **两种时间基准分开**：单调时钟（倒计时与到期判定）与墙钟（24 小时检查与上次比赛时间）是不同来源；保存/载入对单调时钟基准的影响未证。
- **比赛区域**：比赛图集 ∪ 接待图集（两集之外即越界）；比赛图/接待图按显式图 ID 或元数据旗标字符串配置。
- **覆盖钩子链（handled）**：已被其它钩子处理（handled 非空）→ 后续覆盖钩子不动；注册序：漫游 → Safari → 捕虫。
- **四状态词汇（捕虫）**：进行中且未判（inProgress 且决定为 0）、已判（inProgress 且决定非 0，或 ended）、已结束（结束后 inProgress 为否）、结束后待清理（离开判奖图才清理）。

## 3. Safari 会话与世界交接

### 3.1 会话状态机

- **状态五分**：**未开始/已清空**（存在标记为否——惰性创建的对象初始态，或结束后）、**首次创建**（首次访问时惰性创建：起点空、球数 0、捕获 0、步数 0、决定 0、存在标记为否）、**进行中**（开始后：存在标记为真、决定为 0）、**结果待处理**（存在标记仍为真但决定为 1——步尽/球尽/主动退出后；人已被送回起点或仍在区域内）、**真正结束/清空**（全部字段复位并请求地图刷新）。
- **开始入口（实参为球数）写入**：起点写为当前图＋玩家坐标＋朝向、球数写为入口实参、存在标记置真、步数写为配置步数——**不重置捕获数、不重置会话决定**（**重复开始不自动等同彻底重置**：未经结束再次开始，旧捕获数与旧决定保留；旧决定非 0 时计步门（§3.3）不再计数）。正常接待流程先结束/新档才开始（demo 事件编排 U01）。
- **结束入口写入**：起点清空、球数/捕获数/步数/会话决定全部归零、存在标记置否，并请求地图刷新。**清空入口本身没有「会话进行中」前置**——§3.2 的换图钩子就是脚本调用者：只要区域查询为否即执行清空（**未开始会话的普通换图也会先惰性创建会话对象、再清空并请求刷新**）；不写「无正常脚本调用者」。demo 接待/重启事件的实际编排仍归 U01。
- **接待地图/起点不回清**：回起点只做转移（§3.4），**不调结束入口**——回到起点后会话仍是「结果待处理」，接待图本身属于 Safari 区域，不会触发清空。

### 3.2 区域判定与换图钩子

- **区域判定**：会话进行中 **且**（当前图是接待图 **或** 当前图元数据带 `SafariMap` 旗标）；会话不在进行中恒为否。
- **换图钩子**：**只按区域查询结果决定清空——没有「会话进行中」前置**：区域查询为否 → 立即结束（清空并请求刷新）；在区域内 → 不动。三种对照：**①未开始**：正常无活动会话进入普通地图——仍会惰性创建会话对象、执行清空并请求刷新（不能以「并未从 Safari 离开」跳过）；**②区域内**：活动会话在接待图/旗标图间移动——不动；**③活动后离区**：会话进行（含结果待处理）中离开允许范围——清空。**正常用尽步数、用尽球、主动退出都先把会话决定置 1 并回起点（§3.3/§4.6/§8.3），活动会话的字段清空发生在离开允许范围之后**。

### 3.3 计步钩子

- **触发点**：玩家完成一步/结束冲浪时（可转移步进通知；先于当步遭遇判定——handled 为真时当步不再做遭遇判定）。
- **门（按序）**：①handled 已为真 → 不动（不与其它转移效果叠加）；②**配置步数为 0 → 整个钩子不执行**（无限步模式）；③不在 Safari 区域内 → 不动；④**会话决定非 0**（结果待处理）→ 不动。
- **通过门后**：步数 −1；**步数仍 >0 → 本步结束**；减到 0 → 两条消息（铃声＋会话结束）→ 会话决定置 1 → 回起点 → handled 置真（**当步不再做遭遇判定**）。
- **配置值分支（按来源真实分支，不按注释概括）**：`SAFARI_STEPS` 默认 600；**＝0 → 不计步**（钩子门②）；**负数 → 不属于门②，步数初始为负，第一步即减、判定不 >0 → 立即结束**（有界异常值按真实分支登记，不把「非正」统一写成无限）。

### 3.4 回起点

- **回起点入口**：**仅当当前场景是地图场景才执行**——淡出、设置转移（起点图/坐标、**朝向固定向下**）、下车、转移玩家；**非地图场景 → 跳过转移**（会话决定已写、会话仍在）。**回起点 ≠ 清会话**（§3.1）。
- **缺起点前置**：起点为空时进入本入口会在读取起点字段处失败（人工/异常前置——正常流程开始入口必先写起点；**缺场景/缺起点时是否跳过转移或在已写状态后失败，按此分列**）。

## 4. Safari 单次遭遇、动作与结果

### 4.1 覆盖门与直接入口

- **公开覆盖门**：公开野生开战包装在**单一敌方且允许覆盖**时触发；**handled 已被处理 → 不动**；**不在 Safari 区域内 → 不动**；否则把处理结果设为 Safari 战斗的返回。**注册序竞争**：漫游覆盖先于 Safari 先于捕虫——Safari 区域内若漫游钩子先处理（其自身门全过），本钩子不再执行（§8.1）。
- **直接入口（实参＝个体，或物种标识＋等级）**：实参为个体 → 直接使用；实参为物种标识（＋等级）→ 经生成入口生成（遭遇规格引用：**触发个体创建通知生成修饰**，含 Safari/捕虫 IV 重摇钩子，§8.1）。**不检查跳战条件、不触发开始战斗通知**（与正常核心开战不同，§4.2）。
- **战斗准备交接**：创建战斗场景 → 构造 Safari 战斗对象（场景、玩家、对方＝[个体]）→ **以会话当前球数初始化战斗球数**（方向：会话 → 战斗；返回后才把战斗剩余值回写会话，§4.6）→ 战斗准备（遭遇规格引用：地图天气/环境/背景/时间照常赋值——Safari 战斗接受天气写入并在开战与每轮末播天气动画，素材 U01）→ 战斗动画包装中执行开战。**不走的常规步骤**：开始战斗通知（队伍战前记录）、跳战判定、世界善后、通用结果统计/变量写入（Safari 走自己的字段与变量写入，§4.6）；battle_rules 不经核心开战清理（覆盖路径——暂态规则字段残留按生命周期处理，不虚构清理保证）。

### 4.2 战斗体

- **对方是伪对象**：唯一野生个体；**永不濒死**（濒死查询恒否）、无影子/无 Mega/无原始、未捕获标记读写为空操作；拥有者查询实时查玩家图鉴。
- **玩家队伍不参战**：无招式/道具/换人/经验/金钱/装备结算；经验获取为空操作；野生战为真、训练家战为否。
- **图鉴登记边界**：Safari 战斗**没有内部战斗标记**（初始化不写——与普通战斗的默认真不同）→ 见过/捕获两处登记入口**直接返回、不登记**；捕获后的图鉴拥有登记经由捕获 Mixin 的独立写入完成（§4.5，《捕获判定与接收策略》/图鉴规格引用）。

### 4.3 因子数学（独立变量，不复制参考表达式）

设物种捕获率 c_r（数据属性，0–255 常规域）：

- **初始捕获因子**：**F_c = clamp（⌊c_r × 100 / 1275⌋, 3, 20）**（整数算术——先乘后整除，再按下限 3、上限 20 钳制）。
- **逃跑基准率分段**：c_r ≤ 45 → 125；45 < c_r ≤ 60 → 100；60 < c_r ≤ 120 → 75；120 < c_r ≤ 250 → 50；c_r > 250 → 25。
- **初始逃跑因子**：**F_e = clamp（⌊E(c_r) × 100 / 1275⌋, 2, 20）**（下限 2、上限 20）。
- **每回合动作后重新钳制**：F_c 回到 [3, 20]、F_e 回到 [2, 20]（Bait/Rock 的修正可能越界，钳制在动作之后、回合末判定之前执行，§4.4）。
- **投球捕获率回算**：**R = ⌊F_c × 1275 / 100⌋**——作为投球捕获计算的捕获率输入（F_c ∈ [3,20] → R ∈ [38, 255]；与直接物种捕获率不同——钳制后的因子回算，截断方向见测试目录 SF11/SF12）。

### 4.4 四命令

每回合经专用命令菜单（Ball/Bait/Rock/Run）选择：

| 命令 | 许可与前置 | 反馈 | 消耗与状态更新 | 后续判定次序 |
| --- | --- | --- | --- | --- |
| **Ball** | **先查容量**（队伍满且存储满——队伍/存储与捕获规格引用）；**满 → 消息「箱子已满」，本命令作废重新选择——不耗球、不耗回合、不抽样** | 投球消息/动画（战斗界面引用）；按摇动结果的成功/失败消息（捕获规格引用） | **先球数 −1**、刷新数据盒；以 R 作为捕获率输入调投球（本路径**固定投 Safari 球**——**公共捕获计算按《捕获判定与接收策略》完整合同**：先看**本次实际投掷的球种与目标**——**目标是究极异兽且本次投的不是兽球 → 率折减、跳过普通球修饰（本固定路径即此分支；背包是否持有兽球不影响）**；普通目标 → 普通球修饰（SAFARIBALL ×1.5）→ HP/状态倍率与 x/y 计算 → 确定捕获（x ≥ 255 或无条件球）→ **默认启用的暴击捕获分支（一次暴击入口抽样＋一次摇动检查）**或普通摇动（**最多四次、首次失败即停**）；调试 Ctrl 必捕；兽球自身对究极异兽的效果归捕获规格合同、不并入本路径） | 捕获成功 → 记录与存储（§4.5）→ 核心编号置 4；未捕获 → 回合末判定（下方） |
| **Bait** | 无额外前置 | 投饵消息与动画（素材 U01） | **90% 概率 F_c 减半**（整数除法、0..99 均匀整数 < 90）；**F_e 必减半** | 回合末判定 |
| **Rock** | 无额外前置 | 投石消息与动画（素材 U01） | **F_c 必翻倍**；**90% 概率 F_e 翻倍** | 回合末判定 |
| **Run** | 无额外前置 | 逃离音效＋安全离开消息 | 核心编号置 3 | 回合结束 |
| **无效/取消** | — | — | **本轮重新选择——不耗球、不耗回合、不抽样、不更新因子** | — |

- **回合末（仅当核心编号仍为 0，按序）**：先重新钳制两因子（§4.3）→ ①**球数 ≤ 0 → 音效＋球尽消息，核心编号置 2**；②否则**逃跑判定：以 0..99 均匀整数 < 5×F_e 判定**——通过 → 逃离音效＋野生逃跑消息，核心编号置 3；③否则按本回合动作显示观察消息（Bait→进食、Rock→发怒、其它→警戒）；④天气动画（有天气时）。
- **显式中止**：战斗内中止异常 → 捕获 → 核心编号置 0、结束战斗场景（**显式中止与球尽/逃跑/捕获分列；核心编号 0 的语义是「未定或中止」**）。**中止不回滚任何已发生的消耗**：Ball 分支先扣球后投球，扣球后触发的中止只归零核心结果——已扣的球不退回，剩余球数按 §4.6 回写会话并参与球尽判定。

### 4.5 捕获记录与存储

- **捕获成功后的次序**：捕获记录与存储入口——①见过/捕获登记（**Safari 战斗无内部战斗标记 → 这两个登记入口直接返回**，§4.2）；②**图鉴拥有登记**（Mixin 自身写入：未拥有 → 写拥有、有图鉴且该物种在已解锁图鉴 →「已加入图鉴」消息＋图鉴页展示，图鉴规格引用）；③存储（Mixin 版：**昵称询问**（系统选项开启时）→ 队伍有空位则入队、满则送箱子并显示箱名；**「送盒询问」菜单在 Safari 战斗不生效**（该字段未被设置——队伍满时直接送箱，不出现「加入队伍/送箱」选择））。**「执行捕获」不等于一定登记/入队之外还承诺更多上下文**：经验/金钱/图鉴见过标记在 Safari 战斗不成立（无经验结算、§4.2 的登记边界）。

### 4.6 结果写回（四种输出分列）

战斗返回核心编号后，按序：

1. **会话球数回写**：会话球数 ← 战斗内剩余球数（战斗内消耗才是真实消耗——未消耗时回写值与原值相同；**扣球后中止回写的是剩余值、不回滚已扣球**）。
2. **球尽分支（会话球数 ≤ 0）**：**核心编号不为 2 时**播会话球尽消息（**最后一球抓到的情况走这里**——战斗内未播球尽消息）；会话决定置 1 → 回起点（§3.4）。**核心编号为 2（战斗内已判球尽）→ 不重复播消息**，仍置 1 并回起点。
3. **统计（仅核心编号为 4 时）**：`safari_pokemon_caught` +1、会话捕获数 +1、`most_captures_per_safari_game` 取大（《时间、随机、计步与统计》引用）。
4. **变量 1 写入**——**写的是战斗核心编号**（0＝未定/中止、2＝球尽、3＝玩家或野生逃跑、4＝捕获；注释语义按来源登记）。
5. **野生结束通知**：触发野生战斗结束通知（物种/等级/核心编号——**雷达连锁钩子在此消费；发生在球尽回起点之后，触发时会话/地图状态可能已变化**，WP37 引用）。
6. **外层返回**：**返回核心编号整数**（不是布尔——覆盖路径把该整数作为 handled 结果直接返回；**不能把所有覆盖结果都强行当普通布尔**，与 WP37 漫游的布尔返回、捕虫的布尔返回分列，§6.5）。

## 5. 捕虫大会会话、参赛队伍、时间与越界

### 5.1 会话状态机与配置入口

- **状态四分**：**未开始/已清空**（清理后——**清理不是回到全新对象**：它清预算/活动/决定/暂留个体/备用队伍/对手/名次/判奖点/地图集合，**但保留上次大会墙钟时间、所选成员下标与倒计时起点**；只有首次构造会把上次比赛时间设为空）、**进行中未判**（inProgress 且决定为 0）、**已判**（inProgress 且决定非 0，或 ended 为真）、**已结束**（结束入口后 inProgress 为否——名次表/参赛 NPC/判奖点/参赛成员下标**保留**，供判奖点事件查询；离开判奖图所在图才清理，§5.5）。
- **配置入口（接待事件调用，脚本 API）**：参赛成员设置（实参＝参赛成员下标——**只写字段、不校验**）；比赛图/接待图设置（实参为一个或多个图 ID 或旗标字符串——**累加式**写入，实参为字符串时按元数据旗标收集所有带该旗标的图 ID，否则按显式图 ID）；判奖点设置（实参＝图、x、y、方向（默认 8））；参赛者查询（实参＝对手下标——demo 事件用，U01）。
- **开始入口（实参为球数）逐项**：写预算（入口实参）、inProgress 置真、暂存队伍清空、保留个体清空、上次比赛时间清空、计时起点写为**单调时钟当前值**、名次表清空；**参赛成员＝玩家队伍参赛下标处成员**；**其余成员按原顺序逐个存入暂存队伍**；**玩家队伍缩为 [选中成员]**（**保留成员对象本身——不治疗、不重置任何字段**，不套其它设施的恢复合同）；**参赛 NPC＝从 8 名名单中抽 min（5, 8） 个不重复下标**（拒绝采样去重循环）；会话决定归零、结束标记置否；`bug_contest_count` +1（《时间、随机、计步与统计》引用）。
- **未选择/越界前置（三种下标分开，失败位置不同）**：①**未设置（空）**：预算/inProgress/计时器/名次表清空等已写入后，**在按下标读取队伍成员处失败**——缩队尚未发生（原队伍未被替换、对手未抽取）；②**正数越界**（如 4 员队伍下标 4）：**读取得到空值（不失败）**——其余 4 员全部存入暂存队伍、当前队伍被替换为**含一个空成员的集合**、决定/结束标记复位、参赛次数 +1——**开始入口照常完成**（不预设原参考没有的校验或回滚；后续空成员消费者的错误不预先移到选员处）；③**合法非负下标**：正常缩队。**负下标（如 −1，人工配置）**：选到末员——但排除其余成员用非负位置比较，**末员不被排除**：暂存队伍含全部成员（含末员），拼队后**同一对象在队伍中出现两次**（重复对象边界）。

### 5.2 结束与拼队

- **结束入口（实参＝是否中断）逐项（按序）**：①会话不在进行中 → 直接返回（**重复结束无效果**）；②**拼回队伍**：暂存队伍成员逐个加回玩家队伍——**原队序不保留**（选中成员已在队首，其余按存入顺序追加；**是否治疗：不治疗**——结束入口不恢复 HP/状态）；③**中断（实参为真）→ 结束标记置否、不存储保留个体**；**非中断 → 对保留个体执行昵称与存储**（**联合容量门——队伍满且存储满才失败**：此时两条消息并早退（本次最终接收**没有**新增图鉴/昵称/存储写入；**不回滚战斗阶段已完成的图鉴/统计记录**）；**仅箱满而队伍有位 → 入队**；仅队伍满而箱有位 → 入箱；门通过后才做见过＋拥有登记、昵称询问与存储，队伍/存储与捕获规格引用）→ 结束标记置真；④**获胜统计**：玩家名次为榜首（place 为 0）→ `bug_contest_wins` +1（**名次表为空时在名次查询处失败**——拼队已完成后、清字段之前的「先写状态再失败」位置，§10）；⑤清预算/inProgress/会话决定/保留个体/暂存队伍/比赛图集/接待图集；⑥上次比赛时间＝当前墙钟秒；⑦请求地图刷新。**参赛成员下标/判奖点/参赛 NPC/名次表不重置**（判奖后查询用）。
- **正常结束/中断结束/接收失败不一概承诺事务回滚**：拼队、存储、统计、清字段是顺序副作用；任一环节失败后，已写字段保持已写（§10 逐点列出）。

### 5.3 时间：单调倒计时与墙钟 24 小时

- **倒计时基准**：限时配置 `BUG_CONTEST_TIME`（默认 1200 秒）；计时起点在开始入口时取**单调时钟**。
- **到期查询（三门）**：**未决定才判**；限时 ≤ 0 → **永不到期**（0 与负数同分支——配置 0＝无限；负数没有独立分支，静态登记）；单调时钟差 ≥ 限时 → 到期。
- **到期通知（帧更新，再三门）**：到期后**玩家移动路线强制中、地图解释器运行中、消息窗口显示中 → 当帧推迟**（三门任一成立即跳过）；通过 → 两条消息（蜂鸣＋时间到）→ 开始判奖（§5.4）。**暂停菜单不推迟到期**：非淡出的暂停命令循环每迭代调用地图更新辅助入口，该入口在场景为地图且未淡出时进入微更新，微更新更新精灵集并派发帧事件——**到期回调只检查上述三项，没有暂停菜单活动门**：菜单保持打开、三项推迟条件均否且判奖配置有效时，**下一次微更新即可显示到期消息并开始判奖，无须先关闭菜单**（对照：淡出中不进入微更新、或任一推迟条件成立 → 当帧推迟）。**范围限定**：本链只对暂停命令循环证实，不据此推断所有其它菜单或战斗循环；判奖转移后的窗口外观仍归宿主未证（U01）。计时是否继续流逝按单调时钟定义（自然流逝）。
- **定时器显示**：**进行中且未决定且限时非 0 才创建**（限时为 0 不显示；**限时小于 0 不属于该门 → 显示**，剩余时间下界钳到 0 → 显示 00:00 且永不到期）；显示分:秒倒计时（剩余＝限时 − 单调时钟差，下界 0）。
- **墙钟 24 小时**：上次比赛时间未设置 → 否；否则 当前墙钟 − 上次比赛时间 < 24×3600。**该查询是接待事件的限频依据（demo/U01）——脚本开始入口本身不检查它，不把「检查 24 小时」说成所有开始调用都强制限频**。
- **保存/载入后的时间基准**：计时起点是运行时刻值——恢复保存后倒计时基准的实际语义未证（静态保留）。

### 5.4 判奖开始

- **开始判奖（按序）**：会话决定置 1 → 判分（§7）→ **仅当地图场景时**淡出转移到判奖点（下车、朝向取判奖点配置、**即使同图也请求刷新**）；非地图场景 → 跳过转移（判定与名次已写）。
- **捕虫黑屏/战败回退入口**：玩家队伍逐个**治疗＋去 Mega＋去原始**，然后开始判奖。**捕虫会话中全灭不走宝可梦中心流程**（《野外被动变化与失败回程》的失败回程先查捕虫会话）。
- **判奖点未设置**：判奖点为空时——判分与名次先完成，随后**在读取判奖点字段处失败**（地图场景时；「先写状态再失败」位置，§10）。

### 5.5 越界与清理

- **越界判定**：目标图在比赛图集或接待图集内 → 否；否则是。
- **离开地图钩子**：**进行中且目标图越界 → 结束（中断实参）**（中断——飞天/瞬移/传送出比赛区域即中断；不存储保留个体；**未判奖时名次表为空 → 在 §5.2 ④的名次查询处失败**，拼队已完成、会话字段未清——§10）。
- **进入地图钩子**：**条件只是「当前未进行」（inProgress 为否）**（**不额外要求曾成功结束**）**且（无判奖点或当前图不是判奖点所在图）→ 清理**；停留在判奖图 → 保留（名次表可供事件查询）。**清理保留上次比赛时间／参赛成员下标／计时起点**（§5.1——**离图清理后不足 24 小时的 24 小时查询仍为是**；人工复用对象时先前选员下标与计时起点仍存在，不能宣称回到全新对象）。

## 7. 判分、对手结果、名次与结算

### 7.1 玩家评分（独立算术）

设个体等级 L、六项 IV 值 iv_s、当前 HP 与 HP 上限、物种捕获率 c_r：

- **等级分**：**4 × L**。
- **IV 分**：**⌊100 × Σ_s (iv_s / 31)⌋**（六项分别除以 IV 上限 31 后求和、乘 100、向下取整——先浮点求和后一次取整；全 31 → 600 的浮点和按实现取整）。
- **HP 分**：**⌊100 × HP / HP_max⌋**（一次浮点除法后向下取整）。
- **稀有分**：**R = 60 + 20 ×（c_r ≤ 120 则加）+ 20 ×（c_r ≤ 60 则加）** ∈ {60, 80, 100}（**两道阈值、c_r 为数据属性**——c_r ≤ 60 → 100；60 < c_r ≤ 120 → 80；c_r > 120 → 60；**按当前实现登记，不以原作公式或「应该如此」替代**）。
- **总分 S = 等级分 + IV 分 + HP 分 + R**（玩家保留个体与对手个体同式）。

### 7.2 对手选择与生成

- **遭遇图集构建**：逐比赛图——**无 BugContest 遭遇类型 → 回退 Land**；该图拥有（回退后）类型 → 入列 [图, 类型]；**全图为空 → 异常**（判奖在转移前中断，会话决定已置 1，§10）。
- **每名对手**：**随机选一 [图, 类型]**（均匀抽取、各对手独立）→ 遭遇选择查询按该图该类型遭遇表（含遭遇版本）抽取 [物种, 等级]——**空候选 → 异常**；→ **按普通个体构造入口直接构造**——**不走生成入口，无个体创建通知修饰**（无 Safari/捕虫 IV 重摇、无闪光开关、无等级缩放——与普通野外生成入口的修饰区别按实际调用确认）；→ **HP 取 1 到 HP 上限−1 的离散均匀随机**；→ 按 §7.1 评分。
- **候选数量**：对手人数＝开始入口抽取的 min（5, 8）＝5 名（名单 8 人）；**判奖数组条数＝5 名对手＋（有玩家保留个体时再加 1）≥ 5**——**<3 的异常在正常流程不可达，属人工/变体前置防御**（参赛 NPC 被人工清空时）。
- **排序**：按分数降序（**同分次序按排序算法的实际行为——不臆造稳定同分规则**，§10/§13）。

### 7.3 名次与查询

- **名次表写入**：排序后**追加**前三名到名次表（**追加不是覆盖**——重复判奖时累加，每次 3 条；每条＝[参赛者下标（玩家为 −1）, 物种, 分数]）。
- **玩家名次**：**只扫描名次表前三条**——首条玩家（下标 −1）的位置（0/1/2），否则 3（未上榜）。
- **名次信息查询（实参＝名次位）**：**按调用者传入位置直接取条目，不局限于前三条**（重复判奖产生第二批记录后，位置 3 可读出第二批首名的名字/物种名/分数；**位置越界（如总数之外）在读取处失败**）——变量 1＝玩家名（下标 −1 时）或对手名、变量 2＝物种名、变量 3＝分数；**名次表为空时同样在读取处失败**（事件前置；先写状态再失败位置，§10）。**玩家名次与信息查询是两个范围不同的查询**（玩家名次永远只看前三条；不推断 demo 实际会查询第二批）。
- **结算次序回顾**（§5.2）：拼队 → 存储保留个体 → 获胜统计（玩家名次为榜首）→ 清字段 → 上次比赛时间——**真实奖励事件未知就保留**（demo/U01/demo 规格）。

## 8. 公共交界、UI、保存与 demo 配置

### 8.1 事件注册/调用次序（按目录加载序）

- **公开开战覆盖（覆盖竞争）**：漫游 → **Safari** → **捕虫**——三者都以 handled 空为门；**Safari 区域内漫游条目满足其全部门时，漫游覆盖先生效（产生漫游战斗而非 Safari 战斗）**；漫游门不成立才落到 Safari/捕虫覆盖。
- **遭遇选择钩子（物种层）**：漫游替换（先）→ 雷达连锁（后）——两个钩子都**不设 Safari/捕虫模式门**：Safari/捕虫区域内漫游可替换物种（25% 门等全过时）、雷达钩子对非摇动草遭遇一律取消连锁（WP37 引用）。
- **个体创建通知（生成层）**：按文件内注册序——闪光开关 → **Safari/捕虫 IV 重摇**（Safari 或捕虫区域内时：**若无任一 IV 达到上限，全部主属性 IV 重随机，至多 4 次，提前命中上限即停；发生重摇才重算能力值**）→ 传说/幻之/究极异兽保底 3 满 IV → 地图旗标等级缩放。两个模式入口的生成入口都会触发该链；**判奖的对手个体不走此链**（§7.2）。
- **换图**：漫游推进 → 雷达取消 → **Safari 区域外清空** → **捕虫结束后清理**。
- **离图**：**捕虫越界中断**（§5.5）。
- **可转移步进**：毒伤 → **Safari 计步**——handled 门串联；Safari 计步触发转移时当步不再做遭遇判定（§3.3）。
- **帧更新**：病毒/低电量/BGM → **捕虫倒计时**。
- **地图/精灵集变更**：暗度/位置窗 → **捕虫定时器显示**。
- **开始战斗通知**：**捕虫入口显式触发**（§6.1）；**Safari 入口不触发**（§4.1）。
- **野生战斗结束通知**：**两个模式入口都在结果写回后显式触发一次**（雷达连锁钩子消费；**触发点在球尽回起点/判奖转移之后**——回调发生时 Safari 会话可能已将会话决定置 1 且玩家已回起点、捕虫可能已完成判奖与转移，不套 WP37 每条正常路径结论）。

### 8.2 雷达与两种模式的静态关系

- 雷达许可门只看地形/遭遇表/骑车/调试/电量（WP37 引用）——**无 Safari/捕虫模式门**；连锁数据是暂态字段。
- 连锁存在时：漫游替换跳过（其自身门）；雷达钩子对非摇动草遭遇取消连锁；Safari/捕虫覆盖在开战覆盖层照常发生（handled 空时）——**连锁中的遭遇在两种模式区域内被模式战斗接管，随后模式入口的野生结束通知更新或取消连锁**（**结果可达性按模式分列**：Safari 普通四命令只产生 0/2/3/4——可达的增链输入是捕获结果 4；捕虫经普通战斗流程可产生击败 1 与捕获 4；人工直接注入结果 1 属人工夹具、并非 Safari 核心产出；非击败/捕获结果 → 取消；重摇/消息按 WP37 合同——且先回起点换图可能已取消连锁，§8.1）。

### 8.3 UI 与用户流程

- **暂停菜单信息行**：**Safari**——配置步数 >0 时显示「步数：剩余/上限＋球数」，**配置步数 ≤0 时只显示球数**；**捕虫**——有保留个体时显示「已捕获：物种＋等级＋预算」，否则「未捕获＋预算」。
- **主动退出**：暂停菜单「退出」（Safari，仅区域内出现）→ 确认 → 结束菜单场景、会话决定置 1、回起点（**确认才执行；取消返回菜单**）；「退出比赛」（捕虫）→ 确认 → 结束菜单场景、开始判奖（**主动退出捕虫＝进入判奖，不是中断**）。
- **背包**：捕虫进行中**不可用**（菜单出现条件：不在捕虫会话中）；Safari 中可用（但战斗内无背包——§4.2）。
- **保存**：**两种模式进行中均不可用**（菜单出现条件：系统允许保存、且不在 Safari 会话中、且不在捕虫会话中——三个行为条件分列）。
- **调试入口**（调试不混进默认用户流程）：「Safari 与捕虫大会」——**Safari**：步数编辑（0–99999，**仅配置步数 >0 时可编**）、Safari 球数编辑（0–99999）；**捕虫**：剩余时间编辑（按分钟 0–99999，**仅限时严格为正时可编——限时为 0 或负数都不可编：非正时该项显示「无限」、选择不进入编辑**；可编时改写计时起点并同步已存在的定时器显示）、Sport 球数编辑。**调试显示「无限」（非正限时）与地图定时器的 00:00（负限时）是两个入口的不同行为**（§5.3），不把显示门、到期门和编辑门合并。调试把球数/步数改为 0 后的后续判定走各自正常门。

### 8.4 保存与持久边界

- **持久（全局元数据，随存档保存）**：两个会话对象整体（「特殊战斗模式」字段组）。**但模式进行中保存入口不可用（§8.3）——正常流程能落盘的只有未开始/已结束态**；上次比赛时间、统计字段（`safari_pokemon_caught`、`most_captures_per_safari_game`、`bug_contest_count`、`bug_contest_wins`）随存档。
- **运行时刻值与落盘分开**：计时起点（单调时钟）、定时器显示、战斗内预算/因子是运行态——保存/载入对这些基准的实际语义未逐项验证（静态保留）。
- **版本转换**：当前转换集中**无 Safari/捕虫相关转换**——普通载入不涉及两会话对象的格式迁移（《迁移、失败与恢复》不重开）。
- **demo 可达性保留**：接待/判奖/奖励/费用/参赛日期事件的实际地图接点与调用链归 U01/demo 规格；脚本提供入口不等于默认事件确实调用。

## 10. 边界、失败与未知

- **Safari 边界**：回起点非地图场景 → 不转移（会话决定已写）；起点为空（人工/异常前置）→ 读取起点字段处失败；球数人工 0/负 → 战斗回合末/战斗后球尽分支照常判定；覆盖钩子 handled 已处理 → Safari 不接管（保留原处理结果）。
- **捕虫「先写状态再失败」位置（人工/事件/变体前置，逐个列出）**：①参赛下标**未设置（空）→ 开始入口在按下标读取队伍成员处失败**（预算/inProgress/计时器/名次表清空已写，缩队未发生）；**正数越界 → 读取得空值、开始入口照常完成**（当前队伍含一个空成员；后续空成员消费者的错误不预先移到选员处，不设原参考没有的校验/回滚）；②**未判奖就结束（含越界中断）→ 拼队完成后在名次查询处失败**——会话字段未清、上次比赛时间未写；③判奖点未设置（为空）→ 开始判奖在判分写名次后、读取判奖点处失败（地图场景时）；④判奖时比赛图集全无有效遭遇类型 → 异常（会话决定已置 1）；⑤对手抽中遭遇表空候选 → 异常；⑥名次表为空时信息查询/玩家名次 → 读取处失败；⑦最终接收的联合容量门：**队伍满且存储满 → 两条消息并早退**（本次接收无新增图鉴/昵称/存储写入、不回滚战斗阶段记录、不失败返回）；**仅箱满而队伍有位 → 入队**。
- **重复判奖**：败/平黑屏回退判一次、随后预算为 0 分支再判一次（名次表追加）；同一判奖入口被重复调用也追加——**名次表只追加不覆盖**；**玩家名次只扫描前三条；信息查询按传入位置取条目、可读追加后的后续条目（位置越界才失败）**（不推断 demo 实际查询第二批）。
- **共同边界**：覆盖路径不经核心开战——battle_rules 等暂态字段的清理按各自生命周期处理（不虚构清理保证）；战斗中异常中断（脚本错误）时字段清理未逐项验证；demo 可达性具名保留（U01/demo 规格）。
- **未知/未证**：定时器在菜单/战斗内流逝与恢复显示的全部宿主行为；保存/载入后计时起点与 24 小时墙钟的实际语义；素材存在与播放（U01/素材保留）；奖励/费用/接待话术事件（U01/demo 规格）。
