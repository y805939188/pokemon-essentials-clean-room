# 战斗成长交界、回合末与终局行为规格（净化正文；批次 10）

分类：combat-requirements；creature-rpg 成长/队伍交界；pokemon-rules 的阶段要求；性质：实现独立行为合同。

本规格为净化正文：按统一交接将批准输入 WP42《战斗成长交界、回合末与终局》转写为独立行为文字，不含源文件路径、类名、行号与证据 URL（参考与已读集中登记于 `../../audit/source-traceability.md` 批次 10 条目）。文中保留的字段名、配置键与数据身份名均为数据标识，不构成未来实现的数据结构或接口模板。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的与范围

### 1.1 目的

定义战斗中个体成长何时提交并反馈到场上，回合末按何种次序读取/修改状态，以及结果怎样经过战斗内终局、外层善后和世界交接。可见行为包括经验条、逐级能力变化、学招/放弃、残余效果、倒下/替补、胜负消息、金钱、捕获结果接收、战后进化与返回世界。

### 1.2 范围

A = 结果产生、主循环与检查点；B = 成长调用、等待、持久/场上同步；C = 普通回合末全序与早退；D = 正常终局及资源/队伍清理；E = 外层善后、包装返回及异常出口。具体经验、EV、能力和友好数学引用 WP30/WP19；状态/局部期限引用 WP44/WP45，不另造公式。特性具体处理器归 WP48/49；持有物完整族归 WP50；特殊招式归 WP46/47；捕获计算/接收策略归 WP38；进化条件归 WP31/32；失败回程完整域归 WP61——仍具名前向。本规格自身的提交顺序、返回消费者和跳出点不以这些前向留白。

### 1.3 非目标

不重定义上述前向域；不定义界面演出（WP67-A）；不运行参考代码。

## 2. 输入、输出与状态层

- 战斗决定：0 未决或中止、1 胜、2 负、3 逃离/弃权、4 捕获终结、5 平局。决定是可被具体后续裁判改写的记录，不是任何首次写入后不可变的锁。
- 资格以两侧参与队伍中可战斗成员计数为准（非空、非蛋、HP 等规则引用 WP20/WP25），不只看在场席位。伙伴计入玩家侧能否继续，但普通经验接收仍只玩家本人的队伍段。
- 成长输入包含对方被击败/捕获成员、其登记参与者、当前接收者资格、经验全体装置/共享道具、当前或可更新的还原持有物、成长开关；输出包含 EV、经验/暂存经验、等级、能力/HP、招式与统计。
- 当前战斗副本、持久个体、选择/临时标记、两侧/全场/位置效果、捕获待接收队列、世界临时记录分别追踪。调用完成不表示所有层已同一时刻更新，消息显示也不代替写入证据。
- 默认内部战斗、经验/金钱收益开启，相关世代 8 设置见 §10。直接战斗对象、野生/训练家核心、包装、跳过、覆写和显式中止是不同入口。

## 3. 主阶段与裁判（A）

### 3.1 正常阶段

开战资格、参与者、派出及入场初始化引用 WP39/WP41。主循环从回合号 0 开始：命令 → 检查决定是否正值 → 攻击 → 同样检查 → 回合末 → 同样检查；只有三阶段都未结束战斗，才回合号加 1。离开该循环后进入正常终局。命令阶段玩家即时逃跑等可让整轮攻击/回合末完全不执行。

攻击阶段的 Call、换人、物品、Mega 与招式顺序由 WP40 定义；换人之后、物品之后及招式执行循环的具名检查点会检测决定。一个处理器内部的写入或 HP 归 0，不自动产生全局中断或回滚。正常单席位招式调用返回后还会做一次普通裁判；指令/舞者等嵌套使用有自己的裁判及早退，详 WP49。

### 3.2 结果赋值入口

| 入口 | 行为合同 |
| --- | --- |
| 普通裁判 | 两侧都无可战斗成员 → 平局判定；仅玩家侧无 → 2；仅对侧无 → 1；两侧都有则不改现有决定。这里没有「决定已经正值就不重判」的通用门 |
| 普通平局判定 | 默认 5。自我 KO 条款开时：最后使用者未知仍 5；最后使用者在对侧 → 2，在本侧 → 1。按固定快照记录，不按条款名称重写方向 |
| 招式/灭亡歌检查点 | 基础检查点为空；已加载条款消费者在双方全灭时可改结果：drawclause 优先，但所列半伤吸取族排除；否则 modifiedselfdestructclause 只对爆炸自灭族。此处按本次检查点接收的来源侧：对侧 → 1、本侧 → 2；灭亡歌传保存的歌声来源，不能以最后出招方替代（R11）。后面普通裁判仍可能另行赋值，不能把检查点中间值当最终结果 |
| 回合末骤死条款 | 普通回合末返回后，若仍决定 0，按两侧可战斗数量比较：本侧多 → 1、少 → 2、相同保留 0；不额外比 HP。设施其他判定 WP54–58 前向 |
| 逃跑/招式终止 | 依 WP41 写 3；此写入由实际调用者的检查点消费，不统一假定立即跳出所有嵌套回调 |
| 成功捕获 | 对手先从参与队伍移出；允许捕获经验时临时设捕获标记并调用成长，之后撤标记、清其场上引用。若该侧已无可战斗成员，训练家场景写 1、野生写 4；随后球/来源修改与待接收队列写入由捕获路径继续完成 |
| 调试按时判定 | 满 100 回合先计算双方可战斗数，再比这些成员总剩余 HP，平手 5；但随后显式中止异常在开战外层被捕获，最终决定改 0。按时判定值是这个路径的中间值，非最后返回值 |

自身和双方全灭以当前参与队伍为准，捕获已移出可使无可战斗计数成立。捕获计算、球效果和具体接收策略不在本规格重新定义。

## 4. 成长调用与持续战斗反馈（B）

### 4.1 触发与接收集合

成长调用的实际位置包括：正常使用招式在结束模式破坏者标志后、动作结束/指令/舞者之前；使用前置失败可能自伤倒下的分支；火药自伤失败分支；捕获成功且开捕获经验时；入场危害倒下时；回合末具名两个成长点；特性/道具触发的替补中也可能嵌套这些路径。成长不等于战斗已经结束。

成长入口先检查野生胜利音乐条件（对方全无可战斗、本方仍有），之后才因非内部战斗或经验开关关而退出。此时不分配 EV/经验，也不清待处理参与者。

正常分配逐场上对方对象扫描：必须有非空参与者记录，且当前濒死或临时捕获标记真。接收者必须当前可战斗且属于玩家本人队伍段；统计有效参战者时还核对所有权。经验全体来源是玩家标志或背包装置；没有经验全体时才收集当前或还原记录持有经验分享道具的合格成员。参与者记录为空仍会在更早处跳过，不能由 Exp All 推导总能分配。有记录但有效参战者为 0，与记录空不是同一情况。

先按玩家队伍段顺序处理参战/分享者：每人先 EV、再经验。然后若经验全体生效，再按段顺序给其余可战斗成员，整体提示只对这一轮的首名，个别经验消息参数另控。该对手本次处理后清参与者记录，避免再次就同一登记分配；无当前合格接收者也可清记录。伙伴只影响战斗参与与胜负，不加入这份玩家本人分配循环。

### 4.2 经验、EV 与场上副本

具体收益和钳制引用 WP30 §4.2/WP19：人数份额分别向下取整后相加，基础份额≤0早退先于训练家倍率/缩放/+1；缩放先整除5，再乘实数等级因子并取整，后续各整数倍率逐项取整。CATERPIE L2基础经验39对L3接收者的限定例给13而非14（G11）；基础份额0仍保留已分配EV，不靠+1产生收益（G12）。当前持有物修正无结果时可回退到当前还原记录的物品，不能当作两个修正必然叠加（完整物品处理器 WP50）。EV 先写持久个体/所述暗影暂存，不在 EV 子步骤统一刷新能力。

| 路径 | 提交/同步时点 |
| --- | --- |
| 已到最大经验 | EV 已处理；重算持久个体能力后直接返回，没有这一入口的场上副本刷新。不承诺 EV 总会立刻改变当前场上攻防/速度 |
| 算出的经验 ≤ 0 或钳后增量 ≤ 0 | 直接返回；前面的 EV 写入不回滚，未保证调用能力重算或场上刷新 |
| 非暗影且有实际经验 | 先写实际获得经验统计；按下一个等级阈值分段写入持久经验，才调用经验条演出并等待其完成；逐个新等级做能力/HP 重算与场上回读，再显示升级消息/两页能力变化并处理该级所有学习项 |
| 非升级的末段 | 持久个体重算，然后在场者回读并刷新展示，即使本次没升一级；多级路径最后也有该收尾，不省略为只处理最高级 |
| 在场升级 | 友好度「升级」调用仅对当前在场引用；HP/等级/总 HP 回读。非变身时回读五项普通能力；变身中仍读等级/HP，但不覆盖变身五项数值。这里不是完整属性/特性刷新 |
| 后备升级 | 持久经验与能力按路径提交；没有场上对象则无战斗数据框经验条，也无在场升级友好度；仍有升级/学招消息消费 |
| 暗影分支 | 按 WP30 已审写入覆盖：心阶段 ≤ 3 且允许增加时实际增量进暂存经验、统计增加，当前经验不因此升级；心阶段更高不提交该经验；均不走普通逐级/学习循环。完整生命周期 WP23 |

升级的 HP 变化由 WP19 的重算规则给出，本规格不复制公式。数据矛盾导致新等级低于旧等级时明确报错；在此之前已写 EV，但通常尚未提交新的经验总量；不虚构事务回滚。

### 4.3 学招、取消与等待

按每个实际到达的新等级，遍历匹配该等级的全部学习表项。已有招直接跳过；有空槽时先写持久招式，再提示，随后在场列表追加战斗招式并检查招式变化形态。满槽先询问是否遗忘；接受才打开该单个体摘要遗忘选择，呈现4个旧招＋1个新招，返回招式槽或−1；没有先选择队伍成员这一层。取消返回负值后，确认放弃则结束本招学习，拒绝放弃则重新选择；起初拒绝遗忘也只结束本招。

选中槽后先替换持久招式及在场对应槽（生成新招式，PP/总 PP 按新招初始化），再显示忘记/学会消息，最后检查招式变化形态。战斗版不套通用机器教学保留旧 PP 分支，也不从其它学习接口搬来蛋/暗影拒绝或布尔返回语义。此调用者逐项继续处理学习表，不把取消一个招式当终止全部成长。

摘要消费者正常模式拒绝遗忘秘传招式并重新选择，调试可绕过；退回或选到新增招式的取消位置给 −1。实际 UI 等待期间，前面的经验/等级/能力写入已经发生；取消仅不替换该槽，不回滚成长、EV 或统计。无头像/素材的真实等待体验仍属未运行范围。

## 5. 普通回合末完整阶段合同（C）

### 5.1 顺序、集合与重新读取

回合末进入时记「正在回合末」真并通知场景，增量重算当前速度/相关排序输入，取得一次仅按速度从快到慢、以既有平局序打破同速的成员序列。该变体不按戏法空间反转，也不在构造序列时排除所有濒死对象；各步骤自己的存活/有效性门分别适用。成员状态在每次检查时重新读取，但不能声称整个缓存序列随每次速度/替换自动重排。替换通常重新初始化同一席位对象，后续读取可看到新成员；调用者内部若另取新速度序，按该调用点处理。

下表是本快照普通阶段的先后合同。局部数学/状态要求引用 WP44/WP45；这里补组合时点、参与集合和跳出。

| 序 | 阶段 | 读取/写入与边界 |
| --- | --- | --- |
| 1 | 天气结束/持续 | 先减正期限，到期清除/恢复默认；随后按缓存成员序，逐人天气特性反应、濒死处理，再该人的天气伤害。局部结束可只返回该子步骤 |
| 2 | 延迟攻击 | 按位置下标扫描、递减计时；到0且目标存在存活时，先在当前存活同侧成员中按来源队伍身份查找。来源在场则复用，不发生离场来源的额外交叉清理；来源离场但后备可战斗时，先清当前存活成员指向保存来源席位的着迷、锁定、黑色目光、下颚锁、章鱼桶锁、天空摔投及束缚等初始化交叉关系，再读来源个体计算数据并实际攻击。此清理不是正式换入，仍可解除现占位者的关系；来源数据不带入其特性、道具与招式组。可嵌套招式、成长、裁判；计时到0后早退的辅助残留依WP45，不统一全清 |
| 3 | 祈愿 | 按位置顺序递减/到期恢复，受益者是当前占位者 |
| 4 | 火海伤害 | 侧 0 再侧 1；先减计数，仍正才按缓存成员序伤害；后面侧期限阶段还会再减一次 |
| 5 | 持续恢复与治疗 | 对每名缓存成员，依次青草恢复 → 有效特性回合末治疗 → 有效持有物回合末治疗；没有把全员青草做完才做全员特性的通用顺序 |
| 6 | 亲密异常自愈 | 开关与内部战斗门通过时，按缓存成员序处理合格玩家成员；会影响后面的毒/灼伤资格 |
| 7 | 成员持续恢复 | 全员水流环一遍 → 全员扎根一遍 → 全员寄生种子一遍；吸取按实际 HP 损失移交，恢复/液体污泥及反应可连锁 |
| 8 | 暗影超频反伤 | 按缓存成员序，实际超频且登记招式行动者受总 HP/24 整数商伤害并处理濒死；完整暗影规则 WP23 |
| 9 | 异常残余 | 全员中毒（只有剧毒先增累计，毒疗/伤害分流）→ 全员灼伤；本地 HP 恢复与受伤能力可改变随后状态 |
| 10 | 成员效果伤害 | 先噩梦全员（已不视为睡眠先清噩梦）→ 诅咒全员；可受间接伤害者名义总 HP/4；具体建立族 WP46/47 |
| 11 | 束缚伤害 | 各存活正计时者先 −1；到 0 解除不扣本次，否则间接伤害资格及绑定带修正后伤害。来源离场清理依 WP41；不保证所有外部非法来源索引可恢复 |
| 12 | 章鱼桶锁降阶 | 各合格成员分别查询防御 −1、特防 −1，无来源的中央路径，随后检查降阶道具；不是通用多项镜甲预检入口（WP44） |
| 13 | 个人计时结束 | 依次挑衅、安可、定身、磁浮、意念移物、回复封锁、查封、瞌睡、灭亡歌；每种扫描缓存序列。安可另查招式是否仍存在/PP；查封结束重查场地道具；瞌睡到期查询；灭亡歌到 0 先 HP 归 0 并濒死反馈 |
| 14 | 第一个显式全阶段退出点 | 若决定 > 0，先调用成长，随后直接返回；侧/全场期限、后续能力、替补、尾清理全跳过；「正在回合末」仍可能保持真 |
| 15 | 侧效果期限 | 侧 0 整组，再侧 1 整组：反射壁、光墙、神秘守护、白雾、顺风、幸运咒语、彩虹、火海、湿地、极光幕。正值 −1，到 0 相应提示 |
| 16 | 全场期限 | 戏法空间 → 重力 → 玩水 → 玩泥巴 → 奇妙空间 → 魔法空间；魔法空间到 0 另按当时取出的速度序检查场地道具 |
| 17 | 场地结束/持续 | 递减、到期清除/默认恢复及重复通知依 WP45；青草恢复阶段已经在前面发生 |
| 18 | 成员后置阶段反应 | 对每名缓存成员：自身超频平静/吵闹/慢启动计时 → 有效特性回合末效果 → 有效持有物回合末效果 → 有效特性取得物品。能力/道具资格在各调用前再读，不假定四者共用入口时快照 |
| 19 | 成长与第二退出点 | 调用成长后，决定 > 0 则返回；未到形态/替补/尾清理 |
| 20 | 形态检查 | 缓存成员依次回合末形态检查，处理器按自身存活等前提决定效果 |
| 21 | 替补循环 | 按 WP41 入口先检查决定、再普通裁判；逐席补位、每轮统一入场通知，可因危害反复倒下再补。野生拒绝下一只可尝试专用逃跑 |
| 22 | 第三退出点 | 替补返回后决定 > 0 直接返回；不再做移动/持续能力/尾清理 |
| 23 | 远位自动调整 | 非1v1布局中，先根据调整前存活分布按侧0/1收集所有交换候选，再依同一计划执行；两席侧在全计划多于1项时跳过其候选，三席侧不套此门。详 §5.4；使用 WP41 位置交换合同，无完整再入场通知 |
| 24 | 持续能力再检查 | 按缓存成员序尝试复制等、检查原始天气终止；WP49 定义具体处理器/重入 |

### 5.4 远位自动调整的计划与执行

只在阶段23实际到达且布局非1v1时处理。先以调整前的当前存活集合按侧0、侧1收集候选；本侧尺寸1跳过。对尺寸2／3的一侧，只要其任一存活成员与任一存活对侧成员邻近，就终止整个候选收集；此前候选不撤销。没有邻近对时，本侧每名存活成员的目标位置为：双席0↔2、1↔3；三席移到本侧中央2／3。仅来源与目标归同一业主才纳入计划，不另加目标必须有存活个体的门。

候选全部收集后按计划顺序执行；候选总数大于1时，来源侧尺寸2的候选不执行，尺寸3的候选继续。实际交换仍要求两端席位已建立且同侧同业主；端点不存在则这一项失败且无移动消息，其余项继续。成功后显示横移／移到中央；不重新判邻近来取消后续已计划交换，不产生手动Shift的行动代价或完整入场通知，目标指向按WP41交换合同处理。

3v3六席均已建立、每侧单业主、仅0／1存活、2／3中央已濒死无后备时，计划0↔2及1↔3并依序都成功，最终存活位置2／3；不能在先移一侧后停止。3v2五席已建立、同样仅0／1存活且各侧单业主时，计划仍含0↔2与1↔3，但双席侧那一项因总数2跳过，最终2／1。业主对照使用合法3v3的后续状态：玩家侧三名业主分别占0／2／4，对方侧单业主，只有0／1存活且无后备；0与2不同业主、1与3同业主，故只有1↔3进入计划，最终0／3。原分布已经有近邻对时计划为空。所有例均为静态设计，不作实况证明。

捕获队列逐只做图鉴捕获/已见、首次拥有与允许时展示、暗影已捕标记、实际接收，正常遍历后清队列。接收可能将成员放入／替换队伍并左移相关记录，但不保证与伙伴合并参与集合保持身份对应。伙伴实际参战时，玩家当前队伍与原合并参与集合的成员顺序可分离：满队接收移除玩家成员并左移玩家六格还原记录，合并参与集合仍保留旧成员身份。正常终局仍遍历该合并集合并按同一索引读已移位记录，因此送盒旧成员仍可被写入后继成员的物品，留队成员也可被写错。无伙伴路径的参与集合随玩家队伍同步，才有送盒成员退出这次循环的结论；仅有伙伴登记而未实际参战不构成此反例。还原先于外层伙伴治疗和世界拾取／采蜜，后续按当时实际当前持物消费；不把它等同每个成员自身原物品。其余实际 UI 取消许可与容量策略归 WP38/WP25，不能把「调用了接收」写成一律入队。本规格不重算捕获概率。

正常终局末尾只按玩家侧参与数组还原持有物；不概括为双方所有原持有物统一恢复。还原记录在消耗/永久获得/接收等路径可更新，WP20 已审语义保留。离场特性获得的物品是否保留也须看其是否同步这份记录，WP49/50 按处理器核对。

### 7.1 正常核心返回

- 成长、裁判、残余、补位、终局、世界善后是不同阶段；不能以一个布尔返回值代替整个战斗状态。
- 所有临时清除以实际达到的消费者为条件；有界清单外的持久/辅助字段不自动清。

- 保存的还原持有物是可更新记录；同一个名字的能力在世界/战斗内入口不同，不能替代其有效性门。
- 没有参考运行、概率抽样、真实存档/地图/输入验证；静态异常边界不等于宿主容错承诺。
