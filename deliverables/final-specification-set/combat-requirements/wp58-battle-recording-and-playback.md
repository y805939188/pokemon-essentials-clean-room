# 战斗记录与回放行为规格（净化正文；批次 13）

分类：combat-requirements（主）／generic-kernel（序列化与持久边界）／user-interface（回放呈现接点）；性质：实现独立行为规格。

本稿为净化正文的一部分：按统一交接将批准输入 WP58《战斗记录与回放》转写为独立行为文字，不含源文件路径与行号（源定位集中登记于 `../../audit/source-traceability.md` 批次 13 条目）。范围 A～F：记录生命周期与「上次战斗」持久化、初始条件 18 属性与五元组、实际行动／记录／回放分层、随机与换人序列、布局／数组限度、模式差异、已述全局依赖与中止／终局边界；不扩大为任意战斗、跨版本等价、运行或安全隔离保证。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）——未加载或反序列化真实录像／存档、未写仿制模拟器；未把 WP06 的有限随机边界扩大为全复现保证。

## 1. 目的、可见流程与状态边界（A）

本稿回答「一场设施战斗如何被记录、记录了什么、何时成为可保存的『上次战斗』、回放按什么规则重演，以及哪些内容不在记录内」。它不定义战斗规则本体（WP39–52）、设施会话（WP55／56）或存档系统（WP09）；不承诺跨版本／跨实现重放等价（同种子或同记录数组都不构成保证）。

可见流程（设施单场）：按挑战规则创建**可记录**战斗对象（战斗类型号决定记录的类型字段：0 塔式／1 Palace／2 Arena）→ 战斗开始写入初始条件 → 每命令阶段追加一轮槽位，行动登记／随机／换人询问按发生时点追加 → 战斗结束时导出字节串；单场包装只在**胜／负／平**时把它放入临时字段，否则清空 → 由事件入口把临时记录提升为全局「上次战斗」（随存档保存）→ 回放入口反序列化并按类型分派重演；调试可用数字选择一个 `Battles/Battle###.dat` 文件回放。

入口现状：记录提升与回放入口在脚本内**没有调用者**（由地图事件驱动；事件缺失即 U01）；调试回放入口独立于正常流程。回放不写回任何记录。

## 2. 记录生命周期与持久化（B）

两个记录存放处：

| 存放处 | 属性 | 写入／清空时机 |
| --- | --- | --- |
| 临时记录 | 游戏临时状态字段（不随存档） | 单场包装结束时：**先清空**；仅当决定 ∈{1 胜、2 负、5 平} 时写入导出字节串。调试按住取消修饰键跳过战斗同样先清空后返回「胜利」 |
| 全局「上次战斗」 | 全局元数据字段（随存档保存；默认空） | 仅由提升入口写入：把临时记录移入全局并把临时置空。不提升则临时记录不持久 |

生命周期状态：`未开始 → 记录中（战斗对象内，不对外可见）→ 已导出（临时字段，通常仅存活到下一次战斗或被提升）→ 已提升（全局字段，跨存档保存）`。回放不改变任何记录；回放结束即退出。

各终局对临时记录的处理（单场包装）：

| 决定 | 含义（WP42） | 临时记录 | 备注 |
| --- | --- | --- | --- |
| 1／2／5 | 胜／负／平 | 写入导出字节串 | 平局同样保留 |
| 3 | 逃离／弃权 | 清空 | 包装随即使玩家可弃权（设施训练家战） |
| 4 | 捕获终结 | 清空 | 本接入为训练家战，不可达 |
| 0 | 未决／中止 | 清空 | 含调试跳过（先给跳过提示） |

导出字节串是运行时序列化的不透明数据（**无显式格式版本号**）；其内部分量按 §3 以语义列出。记录的对象图包含队伍成员快照与物品对象等运行时对象，兼容性依赖实现内部结构（未决保留）。

## 3. 初始条件字段与记录结构（C）

记录五元组：`[战斗类型号, 初始条件属性包, 轮次表, 随机序列, 换人序列]`。

初始条件属性包（于战斗开始、在正常开始流程之前写入；复制语义**按字段分列**：名字与徽章表作克隆、双方队伍／起始索引表／物品表／规则标志作序列化字节快照、NPC 台词及天气等其余字段直接赋值——不统一承诺深复制；训练家与队伍因此被**去引用**）：

| 键 | 记录内容 | 备注 |
| --- | --- | --- |
| internalBattle | 内部战斗标志 | 本接入恒假：设施战物品菜单被拒、对训练家可由确认弃权 |
| player | 玩家侧训练家快照数组，每项＝[类型, 名字, 编号, 徽章表副本] | 空则记空 |
| opponent | 对手侧训练家快照数组，每项＝[类型, 名字, 编号, 败台词, 胜台词] | 缺失台词以「...」占位 |
| party1／party2 | 双方队伍成员快照（含个体数据） | 去引用副本，回放只动副本 |
| party1starts／party2starts | 双方起始索引表 | 本接入未另行设置，保持初始化默认 [0]（普通遭遇路径才由战斗触发流程写入，对照见追溯条目） |
| weather／weatherDuration | 场地天气与剩余时长 | 取自战斗场地现值 |
| canRun | 可逃走许可 | 布尔 |
| switchStyle | 换人风格（系统设置现值） | 布尔 |
| showAnims | 招式动画开关现值 | 布尔 |
| items | 对手侧训练家物品表快照 | 本接入未另行设置，通常记空（普通遭遇路径才写入）；玩家伙伴物品表（ally）**未记录** |
| backdrop／backdropBase | 背景标识与基值 | 初始默认空／空值 |
| time／environment | 战斗时段数值与环境类别 | 初始默认 0／无 |
| rules | 战斗规则标志快照 | 条款等（WP54 前向） |

**布局与未保存的运行选项（具名）**：18 键中**没有双方场上人数**。普通战斗初始化默认 1v1；布局设置入口只改场上人数；设施的双打规则直接调用该入口，**不把布局写入所录 rules 字典**，回放入口也不再施加该规则工厂。因此**同一实现内也会丢布局**：双打记录回放为默认 1v1，后续非空 2 号／3 号席指令将访问不存在的战斗者（失败形态见 §5.4／§6.3）。其它不由记录恢复、保持回放初始化默认的具名运行选项：双方队伍顺序表（按队伍长度重新初始化）、可换人／可认输／控制玩家／经验与金钱开关、禁用球开关、捕获送盒方向、Mega 登记状态等——18 键不等于完整战斗状态。

轮次表：每个命令阶段一项；每项**先建 4 个空席**（按战斗者索引；单打只用前两席）；更大布局下按索引赋值可把该项扩展到 4 席以上，但回放一律按 4 席循环消费（§6.3），超出席位的记录不会被回放读取。槽位形式见 §4。

随机序列与换人序列：顺序数组，只追加（见 §5）。两者无长度上限、无逐项类型校验。

**不记录项（具名）**：Mega 进化登记——**原录制战斗的 Mega 能力未被取消**：命令菜单的 Mega 开关、Mega 登记与攻击阶段的 Mega 执行照常运行，但记录不保存该标记；回放不重建 Mega 登记，已登记的 Mega 不能据记录重现（不能写成「录制时也不会登记」）；换位与呼叫命令——**实际行动照常登记**（选择被写入实际行动数组），只是没有记录钩子：该席此前为空时仍为空席，但同轮已有成功登记（如出招）后撤销、再改选换位／呼叫时，旧记录不被清除、残留在该轮（见 §4 取消语义）；玩家伙伴物品表；AI 内部状态与评分（回放时不重建 AI 决策，改由命令槽直接驱动）；背包与货币的真实扣减；随机种子；场景缓冲与演出状态；记录提升入口之外的一切持久化。另：记录战斗把「收服存储」覆盖为**空操作**（收服在设施不可达；完整接收链归 WP38／WP62）。

## 4. 命令登记内容与时点（D）

登记以「命令阶段」为节拍：每命令阶段开始时**追加新一轮**（4 个空席），进行中的每次成功登记**覆盖**该席当前内容（无追加式历史）。

| 命令 | 写入槽位 | 触发时点与失败／取消 |
| --- | --- | --- |
| 使用招式（正常） | [0, 招式索引] | 资格校验通过才写；校验失败不写。若随后选定目标，目标写入第 3 位 |
| 使用招式（自动） | [0, -1] | 安可／无可选招等自动入口；该入口**在自动逻辑返回后整体赋值**，先前经自动逻辑内部写入的目标位会被丢弃（具名边界） |
| 使用招式（Palace 自动） | [0, 招式索引] 或 [0, -2] | Palace 按性格概率与类别自动选招：有该类招式 → 索引；无该类招式 → **-2**——以挣扎对象为载体的「无力」哨兵：登记时挣扎对象被放入选择，但执行成功检查按 -2 **提前失败**（提示「无力使用力量」），不等同实际使用普通挣扎攻击；回放经普通招式登记把 -2 原样传回，同样提前失败（§5.3／§6.3）。该登记语义不做招式资格复检 |
| 物品 | [1, 物品对象, 目标索引, 招式索引] | 登记入口同时从背包扣减（若最终未使用由既有路径回还）；设施接入物品菜单被拒，本槽通常不可达 |
| 换人 | [2, 队伍索引] | 资格校验通过才写；失败不写 |
| 逃跑 | [3, 当时的决定值] | 逃跑尝试入口返回后写入：失败记 0；成功记 3（该记录随后因决定 3 被清，不保留）；调试改判时记入所设值。失败逃跑同样终止本轮的其余选招（语义照旧，不属记录） |
| 目标补充 | 既有席位的第 3 位 | 选靶取消不写；**若无先行走招登记**，写入会产生不完整槽（形如 [空,空,目标]），回放不对此分派（具名边界） |

槽位只有上表所列命令族形态（招／物品／换人／逃跑，含自动 -1 与 Palace -2 两个哨兵）；未选择、强制动作（多回合招等）的席位保持空。换位、呼叫有实际行动登记但无记录钩子：席位此前为空时选它们仍为空席；同轮已有成功登记后撤销改选时，旧记录残留（不保证「均为空席」）。**取消与返回不触发记录清空**——回退重选只会被后续登记覆盖；未被覆盖的旧内容在该轮保留。

时点对照：登记动作发生在命令菜单流程中（玩家侧与 AI 侧共用同一组登记入口；AI 的选招／换人／物品最终也走登记入口）。记录模块不覆盖「撤销／返回」类入口。

## 5. 随机与换人序列、调用域（E）

### 5.1 记录随机入口

普通战斗中，战斗对象的随机入口本身就是全局随机；可记录战斗把它包装为「先取真实随机、再把结果追加入序列」。回放端按序列**依序取用、不重新随机**（WP06 对应节）。

经该入口进入记录序列的行为域：

| 域 | 记录边界 |
| --- | --- |
| 攻击合并时的平手顺序 | 同优先级行动排序的洗牌随机 |
| 招式执行 | 命中、追加效果、状态时长、多段命中、使用计算与候选取一 |
| 随机目标与随机强制补位 | 与属主选择式替补分开，结果从随机序列重取 |
| 能力／道具触发与选择、回合末 | 只含实际经过本记录随机机制的取值 |
| 收服摇晃与接收 | 机制涵盖，但收服在设施接入不可达（WP38） |

Safari 自有随机机制不在本记录域。

**不进入记录序列**的随机：AI 随机入口＝全局随机（AI 评分噪声、AI 选招权重、AI 换人与物品倾向、Palace 自动选招与压半换人概率、逃跑成功率的随机判定）；命令阶段内的「类别判定」分支走全局随机（同一判定的执行期分支才走记录入口）；场景动画与调试场景的随机仅呈现；战斗结束后世界侧检查（如队伍接触传播判定，且其门槛为「内部战斗」标志，本接入为假）不入记录。

### 5.2 换人序列

换人询问返回队伍索引或取消 −1；两侧共用顺序序列，**每次返回即追加**，取消也记 −1。完整来源按行为和时点分开：

| 来源 | 时点、属主及资格 | 记录／回放 |
| --- | --- | --- |
| 回合末对手／伙伴补位 | 非玩家侧存活训练家成员的替补由该属主策略选择；野生成员不补位 | 询问返回追加队伍索引；回放到同一时点消费该值 |
| 回合末玩家补位 | 设施训练家战中健康、非蛋、未在场且属于同一属主的合法后备 | 属主选择返回追加索引；回放直接消费，不打开实时选择界面 |
| 攻击阶段属主选择式替补 | 训练家战 TELEPORT；U-turn／Flip Turn／Volt Switch；PARTINGSHOT（含反射后实际换出者）；BATONPASS；EJECTBUTTON，以及在攻击过程中触发的 EJECTPACK／EMERGENCYEXIT／WIMPOUT。各自失败、已换出、存活、追打与候选门仍须满足，不要求内部战斗真 | 经同一询问机制追加索引；回放在对应攻击消费者时点直接消费。对于这条攻击后替补路径，命令槽仍记录原行动、被清选择的替补当轮不再行动；该行动限定不套到开场首命令前；不把该索引记成随机取值 |
| 开场／普通换入的最终退出扫描 | 入场效果处理后，全场按速度序逐成员先检查真实降阶且有效物品的 EJECTPACK，再检查跨过严格整数半 HP 且有效能力的 EMERGENCYEXIT／WIMPOUT，首个返回真即停止本次退出扫描。训练家战仍须各自天空摔投、对侧存活、能离场及同属主健康非蛋后备等门通过；不是任意降阶／扣 HP 都立即选人（WP41／WP49／WP50） | 非回合末时在这个入场消费者选后备并追加索引，回放到同一入场时点消费。开场先保存初始属性，再入场扫描，故录制时可在首命令槽建立前追加，回放在首命令消费前重取；清旧选择不表示替补不能参加随后首命令。普通换入同样按实际入场扫描时点处理 |
| 回合末退出物品／能力的延后补位 | EJECTPACK 或 EMERGENCYEXIT／WIMPOUT 在回合末通过各自门后只召回、离场，后备选择留给后段补位消费者 | 此退出处理器不立即询问／追加；到实际补位询问时才追加、回放同点消费，不把它记作攻击阶段选择 |
| 随机强制替补 | Roar／Whirlwind／Dragon Tail／Circle Throw 及 REDCARD；候选门通过才抽合法替补 | 不经询问，不追加换人条目；只消费记录随机序列 |
| 对手补位后的换人风格确认 | 单打、内部战斗、换人风格等门同时成立才询问玩家；设施内部战斗恒假 | 设施不可达，保持 RC-W16；不据此排除上述攻击阶段路径 |
| Arena 顺序补位／攻击阶段自换 | Arena 按队伍顺序补位，不询问；普通候选换入资格恒假 | 顺序补位不追加询问条目；BATONPASS 等不能到达询问入口 |

EJECTPACK 通过前置门后先消费物品再选后备；询问若返回取消负值，该负值仍追加，退出处理返回假但已消费，不恢复物品，也不提交替补。退出能力的负选择同样不提交替补；它没有该物品消费。不能把取消的返回、物品消费与换入成功合并成一个结果。

RC-W24 的合法 Tower BATONPASS 例在攻击后追加1，回放在同一攻击后时点消费1；RC-W25 给出随机强制换人与 Arena 邻近反向；RC-W26 给出首命令前的入场 EJECTPACK 对照。每条分支仍受普通战斗资格和终局门约束，不保证具名效果任意状态下都成功。

### 5.3 模式差异

| 方面 | 塔式／普通可记录 | Palace | Arena |
| --- | --- | --- | --- |
| 命令登记 | 通用登记入口（校验 ≠ 记录；失败不写） | Palace 登记语义：自动选招结果入槽，含 -2 挣扎哨兵；不做资格复检 | 通用登记入口 |
| 随机使用 | 执行期机制随机入序列；AI 与评估期随机不入 | 自动选招与压半换人用全局随机（**不入序列**）；结果以槽位快照 | 裁判评判与顺序补位不额外抽随机；通用招式执行随机仍受同一记录边界约束 |
| 回放登记 | 通用 | -2 经普通招式登记原样传回、执行检查按「无力」提前失败（不映射为可用的普通挣扎），其余同通用 | 通用；开场初始化，正常补位保留心／技累计、首发HP基线、计数与开始提示标记，计数至少3后可在第3/4/5轮连续裁判（WP56 §3、PA-P28） |

### 5.4 消费、不足与保证边界

回放按序取用随机与换人条目；**数组越界无保护**，且失败阶段按数组分列：轮次表缺轮次或缺席对象时，先在下标读取或长度调用处失败（空值没有这些方法）；随机／换人序列越界才表现为取到空值后索引继续递增、偏差从越界点起扩散（空值在下游使用处另行失败；不夸大具体下游表现）。随机数量、次序或调用域在不同实现／版本间变化都会改变结果；记录内无格式版本号；因此**不承诺跨版本、跨实现或「同种子」等价**（U05 保留；WP06 边界不扩大）。

## 6. 回放：恢复、分派、重放、中止与清理（F）

### 6.1 入口与分派

回放入口：给定字节串 → 为空直接返回（无操作）→ 建立战斗场景（**标记可中止**）→ 反序列化五元组 → 按类型号分派三类回放战斗（0／1／2）→ 按重建的对手信息取训练家战背景音乐 → 在战斗动画包裹内运行战斗主体。**未知类型号**会使分派结果为空，随后启动调用将报错（静态具名缺陷；未运行验证）。调试回放：数字选择 0–500（取消不播放），读取 `Battles/Battle%03d.dat` 数据文件（二进制读取）后走同一入口；该目录不随仓库提供（U01）。

### 6.2 恢复的内容与方式

重建：双方队伍由记录字节串反序列化为副本；训练家对象按快照重建（玩家侧含徽章、对手含胜负台词；均为新对象，不引用实时对象）；随后逐项回填初始条件（§3 全部键——**不含布局**，布局后果见 §3）。**副本不构成全局隔离**，分三层：

- **副本字段**：队伍成员与训练家属性在副本上改动，不写回原队伍／原训练家对象（但不据此宣称所有副本字段都与全局无关，见下）。
- **仍读取的实时依赖**：回放命令循环按槽再登记；物品登记入口对使用后消耗的物品按侧归属扣减（空物品／非消耗品先被跳过）——属玩家侧时扣**实时背包**，背包无该物即在扣减处报错（§6.3）；是否属玩家侧按侧／属主索引判断，不比较是否为原玩家对象。
- **可写入的全局状态**：回放正常结束走普通终局（§6.4），离场处理可对副本个体调用形态提交；形态提交入口**直接登记全局玩家图鉴，没有内部战斗门槛**（接收者与门详见 WP62 对应条目）。具名反例：BURMY——**传入参战标志实际为真**（按写入/读取口径：BURMY 位于队伍下标 0 且首发席位 0；**仅「实际参战过」不足以代替该标志**——下标 1 仅换入席位 0 时记录位 0 虽真、按其队伍下标读取却为假，形态保持 0，WP41／WP42 对应节）、战斗结束、旧形态 0、环境为 Cave 时离场形态变为 1，回放中的副本变形仍写实时玩家图鉴。该例不扩大为「所有实际参战过的后备都会在回放变形」。

设施正常菜单禁止用物只是输入来源限制，不构成回放入口的隔离保护或记录校验。

### 6.3 重放循环

命令阶段仅由记录驱动：每阶段递增轮次索引；**固定对 4 席**逐一（记录中超出 4 席的内容不被读取）——空席跳过；其余先清空该席选择再按槽分派：使用招式（-1 → 自动入口；其余含 -2 → 普通招式登记，-2 随后在执行成功检查按「无力」提前失败）；有目标位则补目标；物品按槽直调物品登记——该入口对**使用后消耗的物品（如 POTION）**同时扣背包（空物品／非消耗品先被跳过）：属玩家侧时扣**实时背包**，背包无该物即报错（给定记录含合法玩家侧消耗品背包槽时此分支实际可达）；换人按槽再登记；逃跑槽直接把记录的决定值写入。回放按 1v1 重建时，**需要读取战斗者的指令分支**（如出招的招式登记）在非空 2 号／3 号席访问不存在的战斗者对象；逃跑槽只写决定值、不读取战斗者（首次失败点随指令族而异，不概括每种非空指令都在登记时失败；未运行验证）。**AI 侧命令循环不执行**（双方命令都已含在槽内；无现场 AI 决策）。记录数组不足或格式不符按 §5.4 处理。

### 6.4 呈现与中止

回放场景的消息等待自动前进、暂停式显示降为普通显示，命令循环由记录驱动、通常无命令交互；但不作「任何回放都无交互」的普遍保证：-1 自动入口在**非单打、安可且属玩家侧**时仍调用选靶流程（消息开关只控制提示，不取消选靶调用）；标准回放因布局丢失回到 1v1（§3）使该分支通常不可达——那是布局缺陷的后果，不是交互保证。半途按取消键触发中止（战斗中止异常 → 外层捕获 → 决定置 0 并结束场景，**不执行正常战斗终局**；注意正常结束时另有普通终局路径——场景结束、退未用物品、离场能力、形态回调与持有物还原记录——回放正常结束会经过它，但设施包装的还原／统计／记录产出不在此路径）。中止或结束都不产出记录、不改实时队伍。

### 6.5 回放不做的设施善后

等级调整还原、双方治疗、Mega／原始回归清除、物品恢复、胜负统计与临时记录产出均为单场包装职责（WP55 已述），回放入口**不调用**它们。
