## 1. 目的、范围与非目标

### 1.1 目的

定义「一次战斗怎样被创建」——野生、训练家（含对视合并）与伙伴参与的入口接受什么输入、做什么校验、写哪些临时状态、以什么编组进入战斗；支持的单/双/三打与不对称布局、参与者（参战者）/所有者/队伍段/场上席位的对应关系；临时战斗规则与地图/地形/天气/时段的输入与默认值；创建期钩子的阶段与善后边界。

### 1.2 范围

1. 战斗入口（野生/训练家包装与核心、输入解析与校验、跳过、返回值与写入）。
2. 战斗初始化与布局（侧尺寸、对决编组、参与者缩减规则、位置/邻近关系）。
3. 所有者、队伍段与席位（业主索引、队伍起止、伙伴参与与能力计数）。
4. 参战者初始化职责（字段复制、效果清零、离场/濒死/捕获的写入点；供 WP40/41/42 引用）。
5. 临时规则、环境输入与钩子时间线。

### 1.3 非目标

- 不定义招式结算、行动顺序与命令（WP40）、换人/位置/逃跑（WP41）、回合末与终局结算（WP42）、成长/学习（WP30/WP42）、捕获判定与接收（WP38）、完整战斗天气生命周期（WP45）、AI（WP51）、效果族（WP43–WP50）。
- 不定义界面演出与资源（WP16/WP67-A 前向）；不定义设施规则对象的完整语义（WP54–WP58 前向）；不设计未来实现的类/接口。

## 3. 战斗入口与创建

### 3.1 野生战斗

包装（输入：分隔式「物种+等级」、单参数 [物种， 等级] 数组、或已有个体对象；可覆盖标记缺省假）：

1. 先生成对手个体数组（输入为分隔式或单参数数组时，唯一一次构造与生成修正钩子在此发生；已有个体对象参数直接复用，见 §3.3）。若恰 1 个对手且可覆盖：触发「呼唤野生战斗」覆写钩子——若钩子把截断标记设为非空值，立即返回该值（漫游个体/狩猎区/捕虫大会等改道入口；WP37/WP53 前向），不进入核心。
2. 否则进入核心执行（把生成好的个体对象逐一传入）；核心返回后，若恰 1 个对手且可覆盖：触发「野生战斗结束」钩子（物种， 等级， 结果）（雷达连锁消费，WP37 前向）。
3. 返回值归一：结果为 2（负）或 5（平）→ 假；其余结果（含 1 胜、3 逃/弃权、4 捕获）→ 真。返回值 ≠ 胜利判定，各模式分别归一。

核心步骤：

1. 读取结果变量号（缺省 1）、可败标记（缺省假）。
2. 准入跳过：跳过条件为真 → 走跳过路径（§3.4）并返回其结果。
3. 触发「开始战斗」钩子（记录全队战前等级与计数清零，§3.5 钩子）。
4. 再次调用输入解析器，但复用对象身份：核心对每个参数重跑解析——参数已是个体对象时直接加入原引用（包装传入的正是这些对象），因此「物种+等级」的构造与生成修正钩子只发生一次，覆写钩子看到并修改的个体就是核心使用的个体；只有直接调用核心（无包装）并传入「物种+等级」时，才在此处首次构造。
5. 确定玩家侧参与集合（§3.5）及呈现交接，记录所有者队伍段与伙伴道具；若未显式设尺寸规则 → 默认 NvN（N = 对手个数）。
6. 创建期规则应用（§7.1）→ 清空创建期规则字典 → 开场动画包裹战斗开始 → 善后（§7.4）→ 输入刷新 → 结果写入基准变量（含统计增减）。
7. 返回原始结果码（包装再归一）。

时间线（按入口分列，不用混合箭头）：

- 野生包装：生成对手（构造与生成修正一次）→ 覆写钩子（若可）→ 核心内 skip 检查（调试跳过时个体已生成）→「开始战斗」→ 以同一批个体对象开战。
- 直接核心（无包装）：skip 检查 →「开始战斗」→ 解析/生成（跳过时尚未生成）。
- 训练家包装·合并探测成立：满足 §3.2 探测条件时，数据参数先装载第一位训练家 A 并触发「训练家装载」钩子；保存的待战内容是已装载的 A 对象，本事件返回假。第二事件以另一训练家数据参数 B 正常进入核心时，先 skip 检查、再「开始战斗」，随后装载 B 并触发 B 的装载钩子，同时原样复用 A 对象；A 不再装载、不再触发装载钩子，第一次装载时对 A 的修改保留。
- 训练家包装·已探测装载但未存为待战：若装载后不满足「单一训练家且队伍不超上限」，包装以原输入进入自身核心；核心未 skip 时，原数据参数可再次装载并触发装载钩子。这与成功保存并复用待战对象的路径分开，不统一承诺所有包装的装载次数。
- 训练家核心（普通）：skip →「开始战斗」→ 解析训练家输入（数据参数装载并触发「训练家装载」；已有对象直接复用）→ 开战。
- 训练家对象输入：直接加入，不装载数据、不触发「训练家装载」（与数据装载路径分开）。

### 3.2 训练家战斗（含对视合并）

包装：

1. 对视合并探测（仅当无待战训练家、地图解释器运行中、且可双打）：取当前事件的解释器自身；列出事件接触触发类型 2 的训练家事件（不是显示层或渲染优先级；还须满足训练家标记、距离／可达、非跳跃、非覆盖触发等候选门），排除自身与 A 开关已开的；恰有 1 个其它触发事件时，先按输入生成训练家——若为单一训练家且其队伍 ≤ 队伍上限，把它记入待战登记 = [训练家， 事件 id] 并立即返回假（本次事件不发起战斗；由第二个事件触发时合并）。
2. 若已有待战训练家：将已保存的训练家对象追加至本次输入，执行核心；本次数据参数按需装载，待战对象直接复用且不再次触发装载钩子。若结果为 1（胜）→ 把待战训练家事件的 A 开关置真；清空待战登记。否则直接执行核心。
3. 返回值为真仅当结果 = 1（胜），负/逃/平均为假。

核心：与野生同骨架；差异：对方为训练家数组（道具数组、队伍起始）；战斗对象携带对方训练家数组；默认尺寸 NvN（N = 训练家数）；开场动画类型 3（非单打）或 1（单打）；结果写入带训练家战斗标记的统计分支。

### 3.3 输入解析与错误

野生输入逐项扫描：

- 个体对象 → 直接加入原引用；若遇到该参数时前面仍有物种在等待配对等级，则报错「物种 {species} 已给出但未给等级」。
- [物种， 等级] 数组 → 以物种校验后经野生生成入口生成（WP36 生成修正钩子链）。
- 物种 id → 暂存，等待下一个「等级」整数（1..最大等级，含两端校验）；非整数或越界 → 报错「期望等级 (1..N) 但 X 不是数字或不是有效等级」。
- 未知物种 id → 报错「物种 {X} 不存在」。
- 以「物种 id」结尾未配等级 → 报错。
- 数组形式与分隔参数形式的校验位置不同：单参数 [物种， 等级] 先查询物种，再把等级传给创建入口，仍生成新个体；该分支不执行分隔式的整数/1..最大等级前置检查。等级在后续个体创建的等级写入处处理（范围非法可报错；不保证与分隔式具有相同的类型检查或错误文本）。分隔式在「等待等级」阶段先做整数与范围校验。遇到数组时若仍有待配等级的物种也报悬挂配对错误；不把后续创建错误冒充统一入口错误。
- 空对手数组会由战斗初始化拒绝（§4.1）。

训练家输入逐项解析（任一形式）：

- 训练家对象 → 直接加入（道具、队伍、队伍起始）。
- [类型， 名称， 版本号， 收场台词（可选）] → 从数据装载（失败先走「缺失训练家」兜底再重试装载；仍失败 → 报错「数据 '{…}' 的训练家未定义」）；装载成功 → 触发「训练家装载」；有台词则覆盖收场台词。
- 类型/名称/版本号分隔式：类型须存在；名称须为非空字符串；版本号须 ≥ 0 整数；名称后紧邻整数视为版本号，否则按无版本装载。悬挂（类型后无名称等）→ 报错「训练家类型 {X} 已给出但未给训练家名」。
- 空队伍同样由战斗初始化拒绝。

### 3.4 准入跳过（skip）

条件（两者任一）：玩家可战斗成员数 = 0；或调试模式且按住 Ctrl。

跳过路径的写入（按训练家战斗分叉仅有消息差异）：

- 消息：非训练家战斗且队伍非空 →「SKIPPING BATTLE...」；训练家战斗在调试下同消息；训练家战斗且仍有可战斗成员 →「AFTER WINNING...」。
- 清空创建期规则字典；恢复被暂停的 BGM（备忘 BGM＋播放位置）；清除备忘 BGM/位置与四个「下一战」备忘（BGM/胜利曲/捕获 ME/背景）；重置遭遇步计数（WP36 交界）。
- 结果：常规 = 1（胜）；训练家战斗且可战斗成员为 0 → 0（未决）；写入基准备份变量并返回结果。
- 不触发开场动画、不创建战斗对象、不触发「开始战斗」。

### 3.5 玩家侧编组（伙伴）

- 可双打/三打查询：玩家可战斗数 ≥ 2/≥ 3 即可；或有伙伴时可战斗数 ≥ 1/≥ 2。
- 伙伴参与资格：无伙伴或 noPartner 规则 → 否；对手侧多于 1 个个体 → 是；否则仅在显式尺寸规则不是 single/1v 开头时为是；无尺寸规则 → 否。
- 参与时：读取伙伴类型、名称、身份与队伍（身份作为训练家版本的读取边界沿 WP24）；取得独立的伙伴可用道具列表，缺失则为空。按玩家段、伙伴段建立有序参与集合，保留成员共享身份，伙伴段从玩家段长度处开始；当前玩家队伍后来可与该集合分离，详 WP38/WP42。不规定训练家对象构造或数组组织；未显式设尺寸 → 自动加 double 规则。
- 队伍细分（所有者）在战斗内由队伍起始 + 业主索引映射（§5）。

## 4. 战斗初始化与布局

### 4.1 初始化

- 拒绝：参与数组 1 为空 →「Party 1 has no Pokémon.」；参与数组 2 为空 →「Party 2 has no Pokémon.」（异常抛出，创建失败）。
- 初始值：侧尺寸 [1,1]；决定 0；回合计 0；可逃/可换 = 真、可败 = 假；开关动画 = 真；经验/金钱收益 = 真；禁用球 = 假；发送盒子默认 1；Mega 登记每训练家 −1；初始持有物记录双方创建时道具；参战标记全假；记录带环标志的物品身份，建立 AI 选择所需的战斗上下文。
- 阵营判定：对方训练家为空 → 野生战斗；否则训练家战斗。单个训练家按一名所有者处理；未提供身份仍保留野生边界，不要求包装为单元素数组。
- 队伍顺序数组初始为自然顺序；战斗内换人只重排顺序数组而不重排参与数组（WP41）。

### 4.2 布局尺寸目录（支持集合）

尺寸字符串 → [玩家侧， 对方侧]：triple/3v3 → [3,3]；3v2 → [3,2]；3v1 → [3,1]；2v3 → [2,3]；double/2v2 → [2,2]；2v1 → [2,1]；1v3 → [1,3]；1v2 → [1,2]；其它/缺省 → [1,1]。

- 上限 = 每侧 3 席；不存在 4 席及以上的已支持布局（源注释明示需要改代码；见未决）。
- 单打判定 = 双侧各 1；单打/双打/三打日志与开场动画类型由尺寸推导。
- 位置编号：席位索引 i 的侧 = i % 2（0 玩家侧、1 对方侧）；同侧席位对为 i 与 i+2……；最大席位索引由较大侧尺寸推导。
- 对面取序（给定全局席位索引，返回对侧席位「最直接对面 → 次之」的完整序；用于目标光标与「最直接对面」）：

| 布局（我方×对方） | 我方席位视角 | 对方席位视角 |
| --- | --- | --- |
| 1v1 | 0 → [1] | 1 → [0] |
| 1v2 | 0 → [3,1] | 1/3 → [0] |
| 1v3 | 0 → [3,5,1] | 1/3/5 → [0] |
| 2v1 | 0/2 → [1] | 1 → [0,2] |
| 2v2 | 0 → [3,1]；2 → [1,3] | 1 → [2,0]；3 → [0,2] |
| 2v3 | 0 → [5,3,1]；2 → [3,1,5] | 1 → [2,0]；3/5 → [0,2] |
| 3v1 | 0/2/4 → [1] | 1 → [2,0,4] |
| 3v2 | 0 → [3,1]；2 → [3,1]；4 → [1,3] | 1 → [2,4,0]；3 → [2,0,4] |
| 3v3 | 0 → [5,3,1]；2 → [3,5,1]；4 → [1,3,5] | 1 → [4,2,0]；3 → [2,0,4]；5 → [0,2,4] |

（3v2 全局席位 1 → [2,4,0] 为具名核对点；全部九种布局均已列出，不再以示例代替全表。）

- 邻近关系（用于邻近限定效果，WP44/45 引用）：双侧均 ≤ 2 → 除自身外任意两席位均邻近；更大布局按「不相邻对」表判定——基础对 {0,4}、{1,5}（覆盖 3v1/1v3）；3v3 追加 {0,1}、{4,5}；3v2 追加 {0,1}、{3,4}；2v3 追加 {0,1}、{2,5}。两名席位命中任一不相邻对 → 非邻近；否则邻近（同一席位除外）。

### 4.3 参与者保真与缩减

1. 硬性拒绝：训练家战斗且任一侧尺寸 > 2，同时双方都多于 1 名训练家 → 报错「Can't have battles larger than 2v2 where both sides have multiple trainers」（理由：多训练家时远位参战者无法互相接近）。
2. 野生侧自动同步：参与者校验按队统计可战斗野生计数；若它与野生侧尺寸不一致，双侧原相等则双侧同改为该计数，否则只改野生侧。此处区别于 §3.1 核心起初按输入对手个数设置默认尺寸的时点。
3. 每训练家必需席位与首个失败：先比较需占位的业主范围与实际建立的可战斗计数范围，再逐业主比较席位需求。计数只在遇到可战斗成员时建立；缺失计数不自动规范化为 0。已有 NPC 对象的非空全濒死队伍可通过构造的非空门，但默认 1v1 中需求范围为 1、计数范围为空，先报 invalid-owner 错误，不到“has no able Pokémon”分支。若某个较早队伍段没有可战斗成员、较后段有，范围中间可为空值；范围长度门通过后，对空计数的数量比较可先失败，不能统一宣称消息分支可达。实际存在的计数项若无席位则有该侧具名错误；可比较的计数不足而必需席位为 1 时，才到“has no able Pokémon”分支。普通生成数据、已有对象与人为不完整段分别看待；不声称默认 PBS 一定提供异常队伍。训练家核心此前已触发开战记录并清创建期规则，失败不承诺回滚。
4. 缩减循环：某训练家可战斗数不足以填其必需席位 → 训练家战斗将两侧中较大者 −1（相等时两侧一起 −1）后重试；野生战斗只改玩家侧（野生侧固定）。缩到 0 → 报错「Couldn't lower either side's size any further, battle isn't possible」。具名场景：① 两侧各一名训练家、原 2v2、玩家仅 1 只可战斗而对方至少 2 只 → 降到 1v1；② 两只可战斗野生、玩家仅 1 只且无伙伴（原 2v2）→ 1v2（野生侧固定、仅玩家侧降）。
5. 该算法只删减席位、不新增；不会把不足成员补位成额外个体。

### 4.4 派出与开场

- 开场消息与派出顺序：对方先、玩家后；对方多名训练家/伙伴按序拼接消息；玩家消息最后。
- 野生开场按对手个数 1/2/3 具名消息；训练家按对方人数具名「挑战」消息。
- 派出对每个席位调用入场形态钩子（§7.2）；野生席位在建立时另外以「wild = true」调用一次入场钩子并登记已见（图鉴「见过」，WP62 前向）。
- 开场后按顺序播放：天气播报（当前战斗天气，WP45 前向）→ 场地播报 → 全员入场特性检查（WP49 前向）→ 进入主循环（命令 → 攻击 → 回合末，WP40/41/42）。

## 5. 所有者、队伍段与席位

- 业主索引映射（全局交错席位索引 → 该侧训练家数组下标）：单训练家恒 0；否则全局索引 ÷ 2 得本侧序号再查——双训练家且本侧 3 席 → [0,0,1][全局索引 ÷ 2]（我方全局 0/2/4 分别 → 业主 0/0/1；对方全局 1/3/5 同理）；本侧 2 席或三训练家 → 全局索引 ÷ 2。术语必须区分：全局交错席位索引（一切映射/排序用）与单侧第几个位置（= 全局 ÷ 2）。对手侧查询用对方数组，我方用玩家数组（玩家+伙伴）。该函数是席位—训练家的唯一映射点。
- 队伍段：队伍起始数组（每训练家的队伍起始，含末段边界）；业主 → 队伍段由起始序列切分；同名接口：段范围、段长度、段内迭代。由队伍起始反查业主（换人错误消息用）。
- 席位—队伍一致性：席位与队伍下标的归属查询、按（侧， 训练家）的位置数查询；玩家拥有 = 我方且业主索引 0——伙伴的席位居于我方但不是玩家拥有；玩家在场席位数只数玩家拥有的在场席位。
- 可战斗计数口径（供布局与资格）：全队可战斗／非在场可战斗（排除在场席位对应个体）／按队可战斗（每位训练家一段，含缺位空洞）。命名区分：首非蛋/首可战斗/数组首项/按所有者可选成员分属不同函数（成员资格细节引用 WP24/WP25 主规则）。
- 能力查询与目标辅助：全局/对方特性查询、对面取序、最直接对面（可要求未濒死）、近邻判定——供 WP40+ 引用。
- 席位交换接口：仅同侧且同一训练家的席位可互换；交换席位与选择数组并重映射一批「目标指向」效果（具名清单）；吸血种子等明确不换（HP 归属位）。变更理由与执行归 WP41，本规格只登记接口存在与限制。
- 参与者记录（供成长）：受击侧席位的参与者列表在被攻击/被换出等更新点登记「曾参与的对侧个体下标」；捕获后清空（§6.2）。成长结算引用 WP42，实战消费引用 WP30。

## 6. 参战者初始化职责（供 WP40/41/42 引用）

### 6.1 建立与复制

- 场上席位建立时绑定个体身份及队伍下标，清行动选择、成功状态与参与者记录；位置效果保留其独立归属。
- 初始化按非继承/接力两种路径处理效果，并取得以下战斗数据：
  - 名称/物种/形态/等级/HP/总 HP/属性/特性身份/持有物身份/六项能力/状态与计数，及该个体可用于战斗的招式。战斗数据与持久个体的同步边界见下面写入方向，不要求包装招式对象或复制容器。
  - 蛋拒绝：以蛋建立参战者 → 报错「An egg can't be an active Pokémon.」。
  - 延迟攻击离场来源：只读取该来源的显示/计算数据，不带入其特性、道具与招式，仍拒绝蛋。来源仍在场则使用其当前战斗数据。来源离场但后备仍可战斗时，先清当前存活成员指向保存来源席位的交叉关系，再读取来源数据；没有正式换入也可解除现占位者的拘束。WP42 阶段2及 R10 给出黑色目光对照；不要求创建临时参战对象。
- 效果清零（非继承路径，摘要级——完整效果族归 WP43–WP50）：全能力阶级归 0；一批跨回合类效果重置（束缚/混乱/诅咒/查封/集气/胃酸/回复封锁/扎根/锁定/寄生种子/磁力/灭亡歌/替身…）；被绑定/被锁定/被双锁/被击落/被陷阱等「以他人为指向」的交叉效果在自身上场时主动清除指向自己的对位记录（具名若干族）；幻觉按队伍末位合格个体建立。继承路径（接力棒）只保留明示子集并做条件再应用。
- 刷新（全量变更标记）：重算能力、回读等级/HP；非变身时覆盖六项数值（全量时含属性/特性）。
- 写入方向（按字段/入口分层，不设「同名访问器统一写回」总括）：
  - 只改战斗副本：特性入口（战斗中合法改特性 → 战斗查询用新值，持久个体特性不变）；特性 id 直接字段赋值（本地访问器）；变身后复制的数值/速度等不自动覆盖持久个体。
  - 写持久个体（各自独立入口）：持有物入口（同步个体持有物）；等级/形态/HP/状态/计数入口分别按各自逻辑写回。
  - 直接字段与入口不同：持有物 id 直接赋值只改战斗副本局部值，不写持久个体（与持有物入口路径对照）。
  - 回读刷新：从个体重算/回读（能力、等级、HP；全量时含属性/特性）。
  - HP/持有物等主规则引用已审 WP20/WP19，不由本规格重定义。

### 6.2 逐出与清除写入点

- 濒死：中止重复、播放消息、对方存活侧登记图鉴击败、效果清零、状态清零、按战内等级差改亲密（faintbad/faint，WP30 交界）、离场钩子（含形态还原与 Mega/Primal 还原）、清选择、记录「本回合有倒地」、清直接伤害计数（玩家拥有时才清）、触发他人「倒地时」特性、检查原始天气终结。不删除席位；替补与后续由 WP41/42 处理。
- 捕获/移除：清个体引用与队伍下标、HP 归零、效果清零、状态清零、清选择——席位保留为空（捕获后的接收与展示归 WP38/WP42）。
- 换出的清理/保留：离场钩子 + 未用选择撤销 + 道具回包等具体写入点归 WP41。

### 6.3 变更职责（摘要，供后续包引用）

- HP 变更（受伤/回复/吸收/效果伤害）：数值钳制、过界报错、半血记录、本回合受伤记录；效果伤害串联道具回复检查与受伤时特性，濒死则触发濒死流程。
- 濒死（见上）、PP（多回合招不扣、无限 PP、0 PP 不可用；同步真实招式）、类型变更/复位（含 BurnUp/Roost 标记）、形态变更（守护 HP 差值、大小变化、登记已见）、若干形态检查（状态/招式/天气/回合末）与变身（复制类型/特性/数值/阶级/招式与 PP 固定为 5）。

## 7. 临时规则、环境输入与钩子

### 7.1 创建期规则字典

- 写入接口：字符串逐个添加；取值规则（terrain/weather/environment/environ/backdrop/battleback/base/outcome/outcomevar）与其值成对；逐参扫描配对；悬挂取值规则 → 报错「参数 {X} 期望其后有变量但没有」；未知规则名 → 报错「战斗规则 "{X}" 不存在」。
- 键目录（全表）：size（接受 single/1v1/1v2/2v1/1v3/3v1/double/2v2/2v3/3v2/triple/3v3）；canLose（canlose/cannotlose）；canRun（canrun/cannotrun）；roamerFlees；canSwitch（canswitch/cannotswitch）；noexp（→ 经验收益 = false）；nomoney（→ 金钱收益 = false）；disablepokeballs；forcecatchintoparty；switchstyle/setstyle；anims/noanims；terrain（值经地形数据校验，未知 → nil）；weather（天气数据校验）；environment/environ（环境数据校验）；backdrop/battleback；base；outcome/outcomevar；nopartner。
- 创建时应用：size → 设尺寸；canLose/canRun/canSwitch；roamerFlees → 战斗内「总是逃跑」；经验/金钱收益；禁用球；forceCatchIntoParty → 发送盒子 = 2（总是入队），否则按配置读系统设置；switchStyle → 规则优先，否则读系统「对战风格」；动画显示同理；terrain/weather/environment/backdrop/base 见 §7.3；随后清空创建期字典（核心中一次，跳过路径中一次）。
- 战斗内规则字典：「总是逃跑」由创建期写入；条款类键为 selfkoclause、drawclause、modifiedselfdestructclause、suddendeath、sleepclause、modifiedsleepclause、freezeclause、evasionclause、skillswapclause、sonicboomclause、ohkoclause、selfdestructclause、perishsongclause、souldewclause（WP54 完整行为表）。drawclause、modifiedselfdestructclause、suddendeath 有已定位消费者，但固定设施设置文件没有对应设置包装；其余所列键有设施设置包装直接写战斗内规则。创建期添加接口不接受这些名字。sleep=true 不启用 sleepclause；skillswapclause 真时技能交换仍受共同目标门限制，WP47-B 局部表不取消该门。必要兼容字面不缩写、不去 clause 后缀。

### 7.2 钩子时间线（创建期）

生成、覆写、skip、开战记录与训练家装载的先后，按 §3.1 具名入口时间线：正常野生包装先构造并触发「野生个体已创建」，再在可覆盖且单对手时触发覆写钩子，未截断才到核心 skip／「开始战斗」；直接核心收到物种/等级时，先 skip／「开始战斗」，后生成。训练家数据装载才触发「训练家装载」；待战对象复用不再次触发。

正常进入战斗后的共同阶段：场景开始（对双方全队个体的「战斗开始处理」）→ 派出（每席位「进入战斗」钩子）→ 战斗内阶段（WP40/41/42）→「战斗结束」（结果， 可败）（善后；演变检查与全灭处理在该处理器内，§7.4）。正常野生包装返回后，仅单对手且允许覆写时另触发「野生战斗结束」；覆写截断和直接核心不套用这一包装回调。

### 7.3 环境/背景/时段输入

- 地形：规则优先；否则仅当「世界天气设定战斗场地」开启时，世界天气 Storm → Electric、Fog → Misty（只此两种）；其余不设。写入同时是「默认地形」。
- 天气：规则优先；否则按世界天气类别映射：Rain/Storm → Rain；Hail → Hail；Sandstorm → Sandstorm；Sun → Sun（None/Fog 等 → 不设）。写入同时是「默认天气」（完整战斗天气生命周期与管理归 WP45）。
- 环境：规则优先；否则按「地图元数据 battle_environment → 站位地形战场环境」：钓鱼型遭遇用面向地形标签，否则用脚下标签（遭遇类型字节来自 WP36 预取）；地图为 Forest 且标签为草类 → ForestGrass。
- 背景：规则 → 下一战备忘 → 冲浪「water」→ 地图元数据 battle_background（非空）→ 缺省「indoor1」。
- 基座名：规则 → 环境数据的 battle_base（有则写）。
- 时段：地图环境为洞穴 → 2（夜）；否则配置开启时段明暗时按实时：夜 → 2、暮 → 1、其它 → 0（引用 WP59 谓词）。

### 7.4 善后与结果写入

- 善后（结果， 可败）：全队中毒个体的状态计数清零（剧毒计数变常规）；Mega/Primal 显式还原（此善后与濒死路径才有，普通换下不解除——引用 WP41 分层）；有伙伴时治疗玩家全队并治疗/还原伙伴全队；负/平且可败时全队治疗并等待 0.25 秒；触发「战斗结束」；玩家转向正前。
- 结果写入：胜/捕获 → 野生/训练家胜场统计 +1；负/逃/平 → 对应的败场统计 +1；结果写入备份变量（缺省 1）。
- 全灭处理器（挂在「战斗结束」）：检查进化（可配置「所有战斗后检查」或非负非平；按队伍下标比较战前等级、允许濒死者按配置；运行进化画面）；清除战前记录；胜/捕获 → 逐个体尝试拾取/采蜜；负/平且不可败 → 恢复 BGM/BGS 并走全灭回退（存档/回退流程归 WP09 交界）。
- 结算其余部分（金钱、捕获登记、病毒传播、离场善后、结果界面收尾）已在源文件读出，但完整胜负/回合末/终局语义归 WP42；本规格只闭合「入口生成的调用合同」：调用已正常返回 ≠ 胜利（包装返回值、覆写钩子与结果码分别登记）。

## 8. 规则与不变量

1. 任一一次创建至多开一场战斗；包装返回值与决定码分别定义，不得互相替代。
2. 野生默认尺寸起初按输入对手个数设置，参与者校验再按可战斗野生计数同步；后续玩家侧缺员缩减时野生侧固定（§4.3）。训练家默认尺寸由训练家数驱动；两侧独立（不对称合法）。
3. 多训练家与 > 2 席不可组合（双方多训练家时）；不支持 4 席以上（静态上限）。
4. 席位 → 业主映射是单一事实源；队伍段由起始索引切分；伙伴席位非「玩家拥有」。
5. 准入跳过无战斗对象、无开场演出、无「开始战斗」；会清规则、恢复 BGM、清「下一战」备忘、重置遭遇步计数、写结果。
6. 野生「物种+等级」输入只构造一次；核心复用包装传入的个体引用（覆写钩子修改即进入核心）；仅直接核心才能出现「核心内首次构造」。训练家对象输入不触发装载钩子。
7. 创建期规则在战斗对象落实后清空；战斗内条款规则不经创建期添加接口。
8. 参战者建立时取得所需战斗数据与招式能力；蛋拒绝；濒死/捕获不删除席位。
9. 对战前记录（等级/会心数/直伤计数）只在「开始战斗」建立、在善后清除。
10. 对视合并只发生：无待战、解释器运行中、可双打、恰 1 个其它触发事件、单一训练家且队伍不超上限；合并时第一个事件返回假、由第二个事件完成。

## 9. 边界与失败

- 空参与数组 → 战斗初始化报错（Party 1/2 has no Pokémon）。
- 训练家数据缺失：装载失败先进入「补齐」回调再重试，仍失败才报错；类型/名称/版本号非法各有具名错误。
- 野生等级越界/未知物种/悬挂配对 → 报错（§3.3）；训练家悬挂配对 → 报错。
- 跳过：无成员或调试+Ctrl；训练家且无成员 → 结果 0（未决），否则 1。
- 尺寸不可能：逐级缩减；到 0 → 报错；多训练家 > 2 席组合 → 立即报错；某训练家无席位/无成员 → 报错。
- 中止：战斗内中止异常由上层捕获 → 决定置 0 并结束战斗；调试模式回合数 ≥ 100 → 以「按时判定」（可战斗数 → 总 HP）生成结果后中止。
- 对视合并：待战登记后若第二个事件未出现（例如玩家离开），登记保留到下一次任一训练家事件触发（静态记录，不承诺清理）。
- 结果解码按包装分列：野生包装只对 2（负）/5（平）返回假，对 3（逃/弃权）/4（捕获）返回真；训练家包装只对 1（胜）返回真，3/4/5 均为假。野生覆写截断时直接返回钩子值，不经过普通结果归一。
- 未运行确认：开场动画、消息顺序帧、伙伴实际编队、调试跳过均未运行验证。
