# Duel 行为规格（净化正文；批次 14）

分类：user-interface／engine-overworld（附「可选通用玩法」）；性质：实现独立行为规格。

本稿为净化正文的一部分：按统一交接将批准输入 WP68《Duel》（独立并行批次 B，待统一合入登记）转写为独立行为文字，不含源文件路径、行号与脚本入口名（源定位集中登记于 `../../audit/source-traceability.md` 批次 14 条目）。提供玩家角色与地图事件对手之间的独立动作对决。动作相克、临时生命与胜负属于本活动规则，不属于 Pokémon 常规战斗或 Generic Kernel。训练家显示身份引用 Creature-RPG；未读取队伍战斗数值。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的、分类与范围

范围 D-A～D-E：入口与身份、四动作、对手决策、回合／终局、地图副作用和失败。NPC 可达性、台词实参、外部奖励、真实移动／音画留给 WP77 和宿主验证；未扩展到常规战斗。

## 2. 概念、输入、输出与前置（D-A）

输入为对手训练家类型、对手名字、地图事件对象、12 条台词；台词按防御／精准／猛烈／特殊四组，每组三条。包装入口解析类型、建立一名空队伍 NPC 并进行名字及地图台词本地化，然后开始对决；此处不装载预设训练家队伍。

输出是布尔胜负：玩家获胜为真，玩家失败为假。没有平局或主动取消返回码，也不自行发钱、改玩家持久 HP、改变物品或队伍。生命是本次活动独立的两项临时数值，初始双方各 10；特殊动作的已用标记双方各自为假。展示玩家／对手名字、肖像和生命，消息说明交锋结果。

进入没有代币、道具、队伍数量或费用守卫。正常前提是合法类型、可用玩家／地图角色／事件、可处理的台词和呈现资源。类型不存在在开场前严格查找失败；12 条是调用契约，没有长度验证，不能把不足台词解释成正常取消。额外台词不消费。地图和消息翻译系统仍是实际前置。

## 3. 动作与损伤矩阵（D-B）

玩家每回合选择防御、精准攻击、猛烈攻击；特殊攻击在使用一次后移出玩家菜单。对手同样最多使用一次特殊攻击。特殊资格在动作选定时消耗，不因对手也使用特殊或即将终局而保留。

下表每格是「玩家损失／对手损失」；所有数值都是固定量，与生物能力、等级、命中或随机伤害无关。

| 玩家动作＼对手动作 | 防御 | 精准 | 猛烈 | 特殊 |
| --- | ---: | ---: | ---: | ---: |
| 防御 | 0／0 | 1／0 | 0／0 | 3／0 |
| 精准 | 0／1 | 0／0 | 2／1 | 3／0 |
| 猛烈 | 0／0 | 1／2 | 2／2 | 3／0 |
| 特殊 | 0／3 | 0／3 | 0／3 | 4／4 |

防御相遇是观察；精准互击无伤；猛烈被防御闪避；其余按矩阵。两人的损失在该回合均提交后才进入下一次终局检查，没有「先击倒就免去另一方伤害」。生命可在回合内暂时低于 0；下一轮先分别下限归零并更新显示。

## 4. 对手决策与随机输入（D-C）

每回合先选择对手动作，随后从对应台词组三条均匀选一条并显示，最后才询问玩家动作。因此台词是动作相关提示，玩家不是先交付动作再等待对手抽取。

| 对手状态 | 防御 | 精准 | 猛烈 | 特殊 |
| --- | ---: | ---: | ---: | ---: |
| 尚未用特殊 | 3/13 | 4/13 | 4/13 | 2/13 |
| 已用特殊 | 3/11 | 4/11 | 4/11 | 0 |

每次正常回合消费一次动作加权整数选择，再消费一次三选一台词选择；固定权重和资格使「总权重不正」的后备分支不可由本入口正常状态到达。包装构造 NPC 时此前还消费两次 16 位身份随机值（仅身份，不参与胜负）。这里的条件分布不等于整局胜率；玩家行动和特殊已用状态使后续条件不同。

## 5. 状态机与输入（D-D）

| 当前状态 | 事件／条件 | 下一状态与写入 |
| --- | --- | --- |
| 入口 | 类型与台词准备完成 | 开场；显示肖像／生命窗 |
| 开场 | 读取双方原速度后安排动作 | 双方请求速度 2、固定朝向；初始生命 10／10 |
| 回合检查 | 生命先归零、刷新；玩家为 0 | 失败收尾（即使对手也是 0） |
| 回合检查 | 玩家正生命，对手为 0 | 胜利收尾 |
| 回合检查 | 双方仍正生命 | 抽对手动作 → 消耗其特殊资格 → 显示台词 |
| 玩家选择 | 确认可选动作 | 消耗玩家特殊资格（若适用）→ 动作表现 → 提交矩阵损失 |
| 玩家选择 | BACK | 仍等待选择；取消编码为 0，按 WP17 不可取消 |
| 回合表现 | 正常结束 | 回到回合检查 |
| 正常收尾 | 等待与退出表现结束 | 请求双方取消固定朝向并恢复各自原速度，关闭窗口，返回胜负 |

普通台词确认遵从 [WP17 消息输入](wp17-messages-windows-input.md)；「关闭消息」不会退出活动。玩家可反复选择无伤组合，使活动没有固定回合上限。没有投降键或超时判负。

## 6. 世界写入、失败与恢复（D-E）

活动直接请求移动玩家地图角色与指定事件：前进、后退、跳跃、横向试探及速度变化；不校验双方间距、朝向或相邻关系。读入旧速度后正常结束恢复速度；朝向固定在结束时一律关闭，未保存旧朝向固定状态。移动路线工具会在每条路线前后请求穿透开／关，也不保存此前穿透状态。

这些是路线请求及静态等待的证据，不是实际坐标归位保证。没有坐标快照与回滚；地形、事件更新、强制路线替换和宿主执行时序都可能影响呈现，不能写成「退出恢复所有地图状态」。等待使用运行时长并给地图更新机会。正常收尾位于主流程后，没有针对中途异常的本地保证执行机制；发生资源／事件错误时可留下已发生移动、速度／朝向更改或已建显示对象。尚未开始速度写入的入口错误则没有这些后续副作用。

## 7. 示例场景与测试目录

示例场景 12 条见 `../test-catalog/user-interface-wp17-63-65-66-67-68-69-70-71.md` 的 DU 系列（D01–D12），覆盖：双方初始 10 命与独立特殊资格、精准对防御 −1、猛烈对防御闪避、精准对猛烈 −2/−1、双特殊各 4 归零判负、玩家特殊后菜单无特殊、对手已用特殊权重 3:4:4、BACK 不退出、连续防御无回合上限、对手 1 命精准对防御获胜、原速度与固定朝向恢复差异、无合法类型入口失败/缺事件部分副作用无回滚。矩阵 16 种动作组合另由静态检查核对覆盖，不用对局模拟器。

## 8. 依赖、配置与未决

已审固定快照版本（净化交付件）：[WP17 消息输入](wp17-messages-windows-input.md) 的选择／消息，[WP24 玩家训练家](../creature-rpg/wp24-player-trainers-partners.md) 的玩家与训练家身份；按包计划完整读入的 [WP19 属性与能力](../pokemon-rules/wp19-attributes-ability-and-stats.md) 与 [WP27 背包储存](../creature-rpg/wp27-bag-and-item-storage.md) 用于排除把生物数值／库存结算套入本活动。完整身份绑定见追溯条目，不追随主线版本变化。

固定内容为生命 10、特殊一次、动作矩阵、权重及每组 3 条台词；作者提供类型／名字／事件／台词。未发现独立世代开关。U01 台词和地图实参、WP77 实际可达与外部奖励，U05 随机宿主，U07 中断后的世界状态，媒体／插件／宿主交互保持未决。U01–U10 与 WP78→WP79→WP80 出口不在此关闭。
