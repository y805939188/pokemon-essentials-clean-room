# WP17 附表：绘制文本标记目录（净化正文；批次 14）

分类：user-interface 数据附表；性质：实现独立行为数据。

本附表为净化正文的一部分：按统一交接将批准输入 WP17 附表《绘制文本标记目录》转写为独立行为数据，不含源文件路径与行号（源定位集中登记于 `../../audit/source-traceability.md` 批次 14 条目）。范围为绘制层的格式化文本标记：识别集合与处理分支。标记只作行为定位，不是未来框架的格式 API；不复制处理函数。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

**识别与处理是两个集合**：识别集合 21 个名字（`c c2 c3 o fn br fs i b r pg pog u s icon img ac ar al outln outln2`，均可带 `/` 结束标记）；其中 **pg、pog 被识别但在绘制层无对应动作**（不能与消息层的反斜杠性别色 `\b`/`\r` 等同）；其余 19 个有显式处理分支。

## 1. 颜色与不透明度

| 标记 | 参数 | 可见效果 | 开闭/恢复 | 边界 |
| --- | --- | --- | --- | --- |
| `<c=X>` | 颜色值 | 后续文本正文色变为 X，**同时清除当前阴影色**（新正文色与空阴影一起压栈） | 颜色栈；`</c>` 弹栈后恢复外层的正文/阴影组合 | 参数按颜色解析入口解析：8 位＝32 位 RGBA、6 位＝24 位 RGB、4 位＝15 位 RGB（每分量 5 位左移 3）、1–2 位＝色板号。**不要把 c3 的空分量继承规则套给 c** |
| `<c2=XXXXXXXX>` | 8 位输入 | **前 4 位为正文色、后 4 位为阴影色**（各 15 位 RGB） | 颜色栈；`</c2>` 弹栈 | 不是单个 RRGGBBAA 值；消息层 `\[8hex]` 即转写为本标记（正文/阴影各半） |
| `<c3=A,B>` | 两个颜色值，逗号分隔 | 正文/阴影分别设为 A/B | 颜色栈；`</c3>` 弹栈 | **空分量保留上一颜色**（只改给定的分量） |
| `<o=N>` | 整数 | 后续文本不透明度改为 N | 不透明度栈；`</o>` 弹栈 | 非数字按 0 |


### 1.1 颜色兼容输入表

| 字符长度 | 解释 | 对照 |
| --- | --- | --- |
| 8 | RRGGBBAA四通道 | FF000080→红、alpha128 |
| 6 | RRGGBB，默认alpha255 | FF0000→红 |
| 4 | 15位打包RGB：最低5位为R、中5位G、高5位B，各乘8 | 001F→(248,0,0)；03E0→(0,248,0)；7C00→(0,0,248) |
| 1/2 | 十六进制色板号：0白、1蓝、2红、3绿、4青、5粉、6黄、7灰；其它取调用字体默认色 | 02与2同为红；08取默认色 |
| nil/其它长度 | 调用字体默认色 | 3位输入不是自动扩展短RGB |

普通色板的精确默认值（R,G,B；alpha255）：

| 号 | 默认RGB |
| --- | --- |
| 0 | 255,255,255 |
| 1 | 128,128,255 |
| 2 | 255,128,128 |
| 3 | 128,255,128 |
| 4 | 128,255,255 |
| 5 | 255,128,255 |
| 6 | 255,255,128 |
| 7 | 192,192,192 |

色板2是浅红(255,128,128)，不等于六位FF0000的(255,0,0)。

此表是普通颜色入口；c2的8字符仍拆两组4字符，不能套整组RGBA解释。实际字体默认色由宿主给出，像素未证。

### 4.1 图像标记的文尾消费边界

图像分支只有在格式化的主循环**真正到达标记位置**时才产生绘制项；标记识别本身不会向剩余文本插入字符。因此——

- **单独的图像标记**（如输入只有 `<img=a.png|0|0|16|16>`）：去掉标记后没有文字，主循环不进入，返回**空绘制项目列表**，不产生图像。
- **位于文尾的图像标记**（如 `A<img=a.png|0|0|16|16>`）：只处理到 A 的位置，文尾图像项**不会生成**。icon 同理。
- **标记后还有普通字符**（如 `<img=a.png|0|0|16|16>A`）：循环到达标记位置，图像项生成。
- 本边界是**直接格式化入口**的结果；调用者若在文尾另加控制字符（如消息层的换行/暂停控制），应据其实际输入判断，不能扩大为「所有消息中的文尾图像都无效」。

## 6. 口径与静态场景

- 本表按固定源码逐项核对识别正则与处理分支，非 AST 分析；各标记的完整排版结果（换行算法、对齐测量）以绘制函数整体为准，不在本表展开。
- 栈式标记（颜色/不透明度/字号/字体名/对齐）在文本结束时未闭合不会自动弹栈（按绘制调用为单位，下一次调用重新初始化；未逐调用验证残留，列主文档未决）。

### 静态推导场景索引

既有DT01–08及B04-D静态推导场景见 `../test-catalog/user-interface-wp17-63-65-66-67-68-69-70-71.md` 的 DT 系列：c2 两半颜色、嵌套颜色恢复（`<c3=FFFFFF,000000>A<c=FF0000>B</c>C</c3>D`——B 红色且无阴影、C 恢复外层组合、D 恢复调用默认）、字体回退 "Arial"、行中 `<ar>` 先换行再右对齐、`<icon=item>X` 循环到达生成、img 源矩形（含后续字符）按 16×16 截取、图像标记（单独/文尾）空列表与不生成、pg 无可见效果。


### 6.1 实体替换的入口差异

直接格式化输入没有任何已识别标记时走普通文本路径，保留实体字面量：`A&lt;B`仍按字面文本呈现，不解码成`A<B`。加入已识别但无动作的pg也选一般路径：`<pg>A&lt;B`得A<B。一般路径按 `&lt;`→<、`&gt;`→>、`&apos;`→单引号、`&quot;`→双引号、`&amp;`→&、`&m;`→♂、`&f;`→♀的固定顺序替换；例如 `&amp;lt;` 得 `&lt;`，不再回到首步重复解码。去格式标记入口无论有无标记都做这些替换；消息逐字格式化因前加颜色标记也走一般路径，不能由直接无标记反例推消息不解码。
