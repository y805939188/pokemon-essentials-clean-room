## 1. 目的、范围与非目标

**目的**：固定生命周期演出的用户流程合同——进化/孵化/交换/净化/名人堂/片尾各环节**玩家看见什么、何时可输入或取消、等待什么、取消与成功分别去哪一层、状态在何时提交**。后续包据此判断「某演出何时出现、某取消会回到哪里、某字段在何时写入」，而不是各自重新追踪六份演出文件。

**范围**：1) A 进化演出、取消与提交——普通进化场景；成长工具、道具使用、战后扫描、事件触发与交换收尾的调用者；入口参数/上下文、可取消权限、取消生效阶段、消息与音效/动画等待、成功与取消的返回、资源清理、后续图鉴/学招交接。2) B 孵化演出与命名——迈步触发与直接孵化入口的区别、单个与多蛋串行、裂纹/揭示/成功消息、图鉴与命名顺序、文字输入返回、命名拒绝或空结果、进入/退出的显示和音乐交接。3) C 交换演出与收到个体的收尾——实际交换包装、前置队伍选择、送出/收到展示、图鉴条件页、交换进化、场景释放和最后队伍槽替换。4) D 净化室与遗迹石的界面流程——组总览/详细组、中心/外圈显示、游标、组切换、拿起/放置/替换/旋转/取出、摘要与储存选择、合格组进入净化的时机、结果/成长/命名/存放、下一组询问和退出；遗迹石入口、消息承接与统一净化调用。5) E 名人堂登记与浏览——新增一届记录的演出入口与 PC 只浏览入口；记录采集、蛋的配置、容量与裁剪、届数编号、重复登记、导航、信息显示、播放等待、取消和返回。6) F 片尾流程——片尾入口、文本/名单与插件署名的实际来源、背景/滚动/音乐、播放结束和跳过、首次/重复进入差异、完成标记写入、返回地图或无地图上下文、资源释放和保存关联。

**非目标**：不定义进化资格、条件优先级、物种/形态变化、持物消费、额外个体与成功后置动作（WP31/WP32/WP22 主规格；本稿只登记演出交界与调用点）。不定义蛋计数、动态加速扫描、拥有者/名称/来源/首招的提交（WP35 主规格）；不定义交换资格、所有权与统计（WP26 主规格）。不定义心量/流量计算、暂存恢复、容器状态与净化资格（WP23 主规格）；不重新提取 Shadow 招式的全部效果（WP43–49）。不定义图鉴登记语义（WP62）、储存/容量规则（WP25）、消息/输入共同层（WP17）。不运行游戏/UI、不操作真实存档、不播放音频、不调整宿主界面、不编译/转换、不设计未来 UI 架构或把参考类组织当作未来模块。

## 2. 概念与术语

- **演出（presentation）**：一段阻塞流程的显示序列（背景、精灵、消息、音效/音乐）；**演出播放完毕与领域提交是两件事**——进化场景的成功消息先于物种写入；调用者返回「成功」也可能仅代表找到目标并调用了演出，不推成完成进化。
- **入口与消息承接**：演出推进、输入、消息显示和调用者编排分别有自己的合同；同一领域净化从净化室或遗迹石进入时，消息承接、成长刷新能力及收尾返回可以不同，不规定参考侧画面/流程对象的组织。
- **可取消权限（cancancel）**：进化场景以参数传入——普通入口默认可取消（BACK 在动画播放中有效）；**交换收尾与进化石入口传入不可取消**。**不能把进化场景概括成统一取消协议**。
- **取消生效阶段**：进化取消只在动画播放窗口内判定（BACK）；进入成功/收尾段后不再可取消。孵化、交换演出（除进化收尾外）与名人堂登记段**没有取消输入**；片尾跳过有自己的资格（见 §8）。
- **完成标记 vs 持久化**：演出中的字段写入（图鉴、统计、个体属性）发生在内存对象；**持久落盘只经保存流程（WP09）**——不能因「通关」主题推断自动保存、自动进入片尾或完整 demo 剧情链。
- **人工/直接入口**：直接调用包装函数（如直接孵化、直接调用放置）是**入口级静态对照**，与正常用户流程分开登记；不能给直接入口补上原本不存在的门。
- **已通过边界（必须继承，不重开）**：**WP23-N01 选择链三层**（正常 UI／特殊负位置经外层 Select 返回门／绕过选择器的直接调用；取消选择不回滚此前已完成的储存操作）；**WP23 跨级净化失败与同等级对照**（净化室默认跨级恢复在首个能力窗口更新处失败，后续学招/进化/命名/存放/清中心未必到达；遗迹石包装与同等级路径另有合同）；**WP32-N02**（新图鉴页条件路径的两处收尾调用与重复释放前置风险已静态确认，宿主结果未证——不宣称必定二次进化/必定安全/统一幂等）。

## 3. A：进化演出、取消与提交

### 3.1 调用入口与可取消权限

| 入口 | 调用者 | 取消权限 |
| --- | --- | --- |
| 升级检查（成长工具/经验糖路径） | 等级变化后检查进化 → 淡出淡入开场景（WP30/WP28 交界） | **可取消**（默认） |
| 满级稀有糖（独立入口，不经等级变化辅助） | 已满级且配置开启（**默认开启**，世代 ≥8——R01 修订）且升级进化有目标 → 直接淡出淡入开场景；配置关闭或无目标 → 无效提示、不进演出、不消费 | **可取消**（默认）；**取消后处理器仍报用物成功、糖果正常消费**——不能以「没有进化」推断退回（WP28 引用） |
| 进化石等使用道具 | Shadow 直接无效；检查到目标 → 淡出淡入开场景（WP28 交界） | **不可取消**（传 false） |
| 战后扫描（每场战斗结束清理） | 升级进化检查，否则战后条件检查；昏厥成员仅在配置允许时检查（WP42 交界） | **可取消**（默认） |
| 事件触发 | 事件编号进化扫描可战斗队伍（数据驱动；默认 Kubfu/Galarian Yamask 两例） | **可取消**（默认） |
| 交换收尾（交换进化） | §5 | **不可取消**（传 false） |

- **资格守卫在进入演出之前**（WP31/WP32 引用：蛋、Shadow、不变之石、Battle Bond 等）；**调用者检查到目标物种才打开场景**——打开场景本身不代表进化已完成。
- **物品/成长的既有写入不随取消回滚**：取消进化（可取消入口）只阻止物种变化与后续链；已经发生的升级/经验/糖果消耗按各调用者规则保留（WP28/WP30 引用；满级稀有糖取消后处理器仍报成功、正常消费——§3.1，R01 修订）。

### 3.2 演出序列与取消生效阶段

- **开场**：停 BGM →「What?」消息（决定音）→ 播当前个体叫声 →「{1} is evolving!」＋1 秒等待 → ME「Evolution start」＋BGM「Evolution」。
- **动画段与末轮输入**：旧种/新种缩放交替约9秒，节奏逐轮加快。每轮先推进两条动画，再采输入；可取消且BACK触发时先停BGM、播取消音并跳出，**之后才检查两条动画是否结束**。故最后一次更新恰完成且同轮BACK触发，仍取消；不可取消入口同帧继续成功。进入后续白闪/成功收尾后不再消费该取消键。
- **目标轮廓与颜色的三个阶段**：准备时目标隐藏；首次动画更新把目标设可见并施满白覆盖，但缩放为0，尚无非零尺寸影像；约2秒开始放大，约2.6秒出现首次放大的白色轮廓，早于约9秒动画结束。成功白闪阶段才恢复目标正常颜色；后来取消回旧种，不能抹去此前出现过的轮廓。前提是有效且有非透明像素的旧/目标资源、正常时间推进、无外部遮挡；这些静态属性/时点不证明实际像素或Demo播放。
- **闪白换形**：白出后按取消与否切回旧种或切到新种，白入还原。
- **取消返回**：统计 evolutions_cancelled 递增 →「Huh? {1} stopped evolving!」消息 → 结束（无物种变化、无后续链、无消耗后置动作）。**取消不误报领域成功**；重复入口不假定幂等（同一目标可再次从各入口触发）。
- **成功序列（提交次序固定）**：统计 evolution_count 递增 → 播新种叫声（等待叫声时长）→ 停 BGM → ME「Evolution success」→「Congratulations! Your {1} evolved into {2}!」（\wt[80] 停留）→ **后置动作**（持物消费/额外个体复制——进化后置动作，WP31/WP32 引用；Shedinja 型复制：克隆体清标记/缎带、重算并加入队伍、登记图鉴）→ **物种写入**（物种变更；原昏厥则 HP 置 0；重算能力；进化准备标记清除）→ 图鉴登记（见过＋拥有）→ **进化学招列表**（等级 0＝「进化时学习」与当前等级条目）→ **新种图鉴条件页**（见 §3.3）→ 逐个学招（共享学招流程，WP30/WP66-A 引用）。
- **关键时点**：成功消息与叫声在**物种写入之前**播放；图鉴/学招在物种写入之后。领域提交点是物种写入，演出完成点是学招/图鉴链结束。

### 3.3 新种图鉴条件页与 WP32-N02

- **条件**：配置 `SHOW_NEW_SPECIES_POKEDEX_ENTRY_MORE_OFTEN`（世代 ≥7，默认真）＋此前未拥有该物种＋持有图鉴＋该物种在已解锁图鉴内——「{1}'s data was added to the Pokédex.」消息＋登记最后见过＋淡出淡入打开图鉴条目（WP66-B 引用）。
- **WP32-N02（已通过边界，原样继承）**：**交换**的条件页路径在图鉴页内调用一次不淡出的收尾、外层包装随后仍调用通常收尾——**两处收尾调用存在**；收尾含交换进化检查，无「已结束则跳过」业务标志；脚本精灵释放工具会清空精灵表、第二次消息窗口因此跳过，但第二次仍直接释放同一视口——**宿主重复释放行为未验证**。**不能宣称必定二次进化/必定安全/统一幂等**；自定义连续交换进化存在重复检查风险（WP32-N02 保留，不改 reference 修复）。**三类条件页的后续按入口分别限定**（R02 修订）：**进化**——以按等级条目收集的**待学列表**（候选列表，不是最终实际学到的数量）为门：列表**非空**时页内只清消息窗、随后进入逐个学招、再由外层包装正常收尾（不在页内提前收尾）；列表**为空**时在页内提前不淡出收尾＋外层通常收尾（两处调用，同类宿主重复释放未证）。**孵化**——图鉴页内**没有**提前结束原场景的调用：返回后继续命名环节并正常结束（§4.2）。宿主重复释放保持未证，不称安全、必定重复进化或统一幂等。

## 4. B：孵化演出与命名

### 4.1 触发入口：迈步触发 vs 直接调用

- **迈步触发（正常用户流程）**：每走一步，队伍每只蛋孵化计数 −1；队伍中有「加速孵化」特性成员时再 −1（只算一次）；计数归零 → 孵化提交（WP35 引用：统计孵化数、清名、写入拥有者/初始亲密度/孵化时间/获得方式＝孵化/孵化地图、记录首招——**这些领域提交在演出之前**）。多只蛋同时归零时**逐只串行**（各自完整演出＋命名后再下一只）。
- **两个直接入口分列（R04 修订；均为入口级对照，不补蛋态/防重门）**：**直接孵化**——先做与迈步触发相同的前序领域写入（统计/拥有者/亲密度/时间/获得方式/地图/首招），再调用演出包装；**计数归零归属迈步触发侧**——目标尚有正计数时，直接调用本身不负责归零。**仅播放演出**——**不执行上述前序领域写入**（不增孵化统计、不改拥有者/亲密度/来源等）；但演出内部仍会做自身写入：先清昵称（重置为物种名）、登记图鉴（见过＋拥有＋见过蛋）、按选项与确认进入命名（§4.2）。**演出包装正常返回时明确返回 true**——其失败回退分支（纯消息版孵化）**在当前基线不可达**（包装恒真）；直接孵化侧不检查目标是否蛋、是否有计数（门在迈步触发侧与 WP35）。
- **演出包装**：「Huh?」消息 → 带音乐淡出淡入 → 场景。

### 4.2 演出序列与命名

- **裂纹段**：BGM「Evolution」；蛋摇摆 4 轮（裂纹帧 0→4，各配「Battle ball shake」音效，摇摆逐轮加快）。
- **揭示段**：白出（0.4 秒）→ 切换为宝可梦图（按指标定位）→ 白入 → 播叫声（按物种叫声时长等待）→ 停 BGM → ME「Evolution success」。
- **成功消息**：先**清除昵称**（重置为物种名显示，R15 修订：以行为表述，不引用参考赋值表达）→「{1} hatched from the Egg!」（\wt[80] 停留）。
- **图鉴**：登记见过＋拥有＋见过蛋（**无条件**）；**新种条件页**（同 §3.3 三条件＋配置）→「added to the Pokédex.」消息＋登记最后见过＋图鉴条目画面；**页内没有提前结束原场景的调用**——返回后继续命名环节并正常结束（R02 修订）。
- **命名（按输入模式分列，R03 修订）**：选项 Give Nicknames＝Give 且确认「Would you like to nickname the newly hatched {1}?」选 **Yes** 才进入文字输入画面（带个体预览、无淡出参数；**确认选 No → 不进入输入、无命名**）。**光标模式（默认）**：BACK 是**删除字符**（不退出输入）；需选 OK 提交——最小长度 0 时**可提交空文本**。**键盘模式**：Esc 才返回空文本。**返回值用途**：输入返回的字符串写入个体名——**空文本会清除昵称**（名称为空即视为未命名、按物种名显示，WP18 引用；不是「保留空串昵称、仅显示时回退」）。命名完成分支按「进入输入且返回」描述，不等同于最终确有昵称。**已完成的图鉴登记、个体属性（拥有者/亲密度/时间/地图/首招）不回滚**。
- **退出**：若已命名，文字输入画面已处理淡出——场景不再重复淡出（已命名分支）；否则正常淡出。BGM/音乐交接：演出内放「Evolution」BGM，结束后由外层画面恢复（WP16 引用）。
- **资源边界**：裂纹图（通用或物种专用）缺失时的实际行为未验证（资源存在性 U01 保留）；动画资源异常不虚构备用流程。

## 5. C：交换演出与收到个体的收尾

### 5.1 交换包装与前置选择

- **领域包装（WP26 引用）**：统计交换数 → 取队伍送出成员 → 创建或使用收到个体（外来拥有者、昵称、获得方式＝交换、按需重置招式、记录首招——**演出前完成**）→ 带音乐淡出淡入开场景 → 演出（§5.2）→ **演出全部结束后才把收到者写回原队伍槽**。**前置队伍选择/交换要约的取消属于调用者（事件/队伍画面）合同**（WP26/WP66-A 引用），不在本场景内；本场景自身**没有取消输入**。
- **收到者的图鉴**：演出开始前先登记见过＋拥有（无条件）。

### 5.2 演出序列

- 停 BGM、播送出个体叫声 → 显示送出者信息卡（名字/ID/OT）——**首卡等待是 2.5 秒自然推进**（共享等待以 50 个逻辑时间单位、20 单位/秒换算；**USE 或 BACK 可提前结束本次等待**——R05 修订；**此处的 BACK 是推进信息卡，不是取消交换**）→ 决定音、BGM「Evolution」 → **送出段**（变色、收回进球、球飞出屏幕上方）→「For {1}'s {2},\n{3} sends {4}.」＋「{1} bids farewell to {2}.」消息（**随后各消息仍有各自的等待规则**）→ **接收段**（球落下弹跳、开球、收到个体出现并放大、播其叫声）→ 停 BGM、ME「Battle capture success」 → 显示收到者信息 →「Take good care of {1}.」。
- **新种图鉴条件页**（同 §3.3 三条件＋配置）→「added to the Pokédex.」消息＋登记最后见过＋图鉴条目画面＋页内不淡出收尾（WP32-N02 边界同样适用，§3.3）。

### 5.3 交换进化与最终替换

- **收尾检查**：场景收尾时检查收到者的交换进化条件（WP32 引用：实现比较收到者自己的基础物种与参数，再查送出旧成员的不变之石；收到者自身的不变之石由 WP31 统一守卫）——有目标则**以不可取消权限打开进化场景**（§3；默认 KARRABLAST/SHELMET 两条默认交换因自身物种不匹配不进化，接收照常）。
- **最终替换**：**进化场景调用结束后**才把收到者写回原队伍槽——进化发生时收到者尚未进入玩家队伍（WP32 已审合同，本稿引用）。
- **三类「取消」分开**：选择器取消（前置、归调用者）／已启动的交换演出（无取消输入）／不可取消的交换进化（BACK 无效）——**不定义统一取消协议**。

## 6. D：净化室与遗迹石的界面流程

### 6.1 净化室模型与显示（本稿只登记界面交界；规则引用 WP23）

- **模型**：9 个组，每组中心 1 个 Shadow 位＋外圈至多 4 个普通位；tempo/flow 由属性优势环计算（WP23 引用；Normal/Normal 在本模型内计为优势）。**迈步减量的提示是有入口前提的状态转移（R09 修订）**：迈步处理**先跳过心量已为 0 的中心**——只有**本步开始心量为正、经本步减量后满足合格条件**的组才在迈步处提示「ready for purification!」；心量已 0 的组后续每步不重复提示；**经编成变化（加普通成员）让原本心量 0 的组新变合格，不会靠下一步补提示**——合格发现归打开时与编辑结束后的检查点（§6.2/§6.3）。Lugia 特例：全部 9 组 tempo 满才可净化（WP23 引用）。
- **总览（组列表）**：9 组编号＋各组 tempo 量条（蓝）与心量条（紫）；JUMPUP/JUMPDOWN 或列表选择切组。
- **详细组（圆形视图）**：中心 Shadow 图标＋外圈位置按组内成员数均布；flow 环按各相邻亲和度显示（0/1/2 强度），直面成员的指向 flow；信息区显示名字/等级/属性、心量条、flow 量条、tempo 量条；游标沿外圈分段移动、中心为 0 号位。
- **打开流程**：净化室入口先把玩家见过净化室标记写 true（PC 菜单可见门的已知写入点，WP65/WP23 引用）→ 打开场景——**存在任一合格组时直接进入净化链（§6.3），不先询问**；否则进入总览/编辑循环。

### 6.2 编辑操作与取消去向

- **取消去向五层（R06 修订）**：

  | 层 | BACK／CANCEL 行为 |
  | --- | --- |
  | 总览选组 | BACK → 确认「Continue viewing holograms?」——**Yes 继续选组；No（或确认中再 BACK）退出** |
  | 选组后命令（EDIT／SWITCH／CANCEL 菜单） | 选 CANCEL 或 BACK → **只回总览选组循环**（不弹退出确认） |
  | 换组目标选择（SWITCH 后） | BACK → **返回原组**（与自身互换、组内容不变；不弹退出确认） |
  | 详细组位置选择 | BACK → **持握成员时「You're holding a Pokémon!」（不退出）；否则确认「Continue editing sets?」——No 退出详细组** |
  | 详细组操作菜单（MOVE／SUMMARY／…／CANCEL） | 选 CANCEL 或 BACK → **只回位置选择**（不做持握门/退出确认） |

  确认的 Yes/No/BACK 结果继承共享 UI（WP66-A/WP17 引用）。
- **详细组操作**（位置选中后）：有当前成员或持握成员时给命令——**MOVE**（拿起当前成员为持握，原位置清空；该命令确实可从详细位置菜单到达，非备用分支）／**EXCHANGE 或 PLACE**（持握时：放到该位置——原位置有成员则换持（shift），无则放下并给放置提示）／**SUMMARY**（见下条边界）／**WITHDRAW**（见下条三分支）／**ROTATE**（仅中心 Shadow 且组非空：直面下标轮转）／**REPLACE**（见下条原始值门）／**CANCEL**。
- **SUMMARY 边界（R13 修订）**：**无持握成员时**——摘要候选按外圈成员数扫描（中心 Shadow 计入候选，但**中心独存（外圈 0）时候选为空、直接返回**：菜单虽显示 SUMMARY，**不会打开摘要**）；非空时打开组内摘要，**返回后游标跟随摘要最终停留成员**。**持握成员时是独立的单成员摘要分支**（只摘要持握成员）——两个分支不互相覆盖。
- **WITHDRAW 三分支（R08 修订；WP23 已审合同，与 §6.3 净化后通用存放分开）**：**双满（队伍满且全部盒满）→「All boxes are full.」拒绝、源成员保留**；**盒有位 → 存盒成功**（不优先入队）；**盒满但队伍有位 → 仍只尝试入盒、失败不检查返回值、源位置/持握引用仍被清除**——不保证成员仍被任一容器持有（不能写成「保留源成员的拒绝」）。
- **REPLACE 原始值门（R07 修订；WP23 已审合同，不重开）**：替换比较的是**原始 Shadow 查询结果是否相等**，不归一成「都非 Shadow」——**新普通个体（空值）与已净化个体（假值）不相等 → 拒绝**；两只已净化个体（假值与假值）可通过；**REPLACE 不调用普通放置的拒蛋门**——双方原始结果相等时，普通蛋可替换外圈成员（蛋例外）。
- **放置门（普通 PLACE）**：蛋 →「Can't place an egg there.」；中心位只收 Shadow（「Only a Shadow Pokémon can go there.」）；外圈只收非 Shadow（「Can't place a Shadow Pokémon there.」）；放置成功才从源位置删除（队伍删除压紧、盒侧不压紧，WP25/WP66-B 引用）。
- **放置提示**：中心 Shadow 已可净化但组内无普通成员时提示「there must be at least one regular Pokémon in the set to perform a purification ceremony.」。
- **选择链（WP23-N01 已通过边界，原样继承）**：储存选择以取出模式启动——**正常 UI** 只在外层选人循环出口产生位置（盒内选中成员并选 Select 才返回 [盒号, 格号]；BACK 经「Continue Box operations?」、Close Box 经「Exit from the Box?」，退出返回 nil）；**特殊负位置**（「队伍」按钮内部产生）先经外层成员门——映射盒格为空则继续选人循环（不返回位置、不进放置），有成员 X 时先显示成员菜单、**只有选 Select 才返回该原始位置**（随后可放置 X 并删该盒格）；**绕过选择器的直接调用**（如直接给放置消费者传队伍位置）放置成功、队伍删除压紧、**无「保留最后可战斗成员」守卫**——该事实与「正常 UI 能取得队伍位置」是两件事。**取消选择（返回 nil）只表示本次不按新选中位置提交放置/替换；选择期间已完成的存入/取出、持物/标记与当前盒变化不回滚**。
- **退出详细组**：持握成员时按取消 →「You're holding a Pokémon!」（不退出）；否则确认「Continue editing sets?」——No 退出。**编辑循环结束后再次检查合格组**——有则提示「There is a Pokémon that is ready to open its heart!」并进入净化链。

### 6.3 净化链与已通过跨级失败边界

- **统一净化调用（WP23 主责；本稿登记演出/消息顺序）**：资格（Shadow 且心量 0）→ 统计净化数 → 清 Shadow 与 Hyper、授缎带 →「{1} opened the door to its heart!」→ 恢复招式（逐个「{1} regained the move {2}!」）→ 记录首招 → 返还暂存 EV → **返还暂存经验（80%）**：有变化则「{1} regained {2} Exp. Points!」——**同等级**：写精确经验并重算能力；**跨等级**：走等级设置辅助（设等级/重算、场景刷新、升级消息与两个能力数值窗、学招、进化检查——WP30/WP42 引用）→ **命名**（选项 Give 且确认 → 文字输入；拒绝跳过）。
- **净化室链（每组）**：选定合格组 → 打开该组视图 → 演出接点（场景侧仅刷新，**无独立仪式动画**）→ 统一净化调用 → **通用存放**（队伍有位入队、否则入盒，WP25 引用）→ 无条件清中心 → 还有下一组合格时「There is another Pokémon that is ready to open its heart!」＋确认「Would you like to switch sets?」——**拒绝则关闭并停止**（后续组保留待净化）。
- **已通过边界（WP23 跨级失败，原样继承）**：净化室默认跨级恢复在首个能力窗口更新处因本入口缺少所需刷新操作而失败；后续学招/进化/命名/存放/清中心未必到达，中心仍保留部分修改（Shadow已清、缎带/EV/经验按已执行部分保留，不回滚）。同等级恢复（含S0）不进入等级变化窗口，精确经验写回和重算后可继续。遗迹石入口具有所需的空刷新能力，不在这一失败点停止。入口间此能力差异是行为边界，不要求采用参考侧方法/类组织，也不承诺所有输入必达最终演出。
- **双满存放失败**：确实到达通用存放而队伍与盒都满时，存放只提示并返回、**随后调用者仍清中心**；此前已完成的 Shadow 清除/缎带/成长及可到达的命名**不回滚**（WP23 已审合同，本稿引用）。

### 6.4 遗迹石入口

- **外层三层分开（R10 修订）**：**外层开放**——队伍经**一般可净化查询**（Shadow 且心量 0、**非 Lugia**；**没有 HP/可战斗门**）无合格成员时「You have no Pokémon that can be purified.」返回；否则先显示「There's a Pokémon that may open the door to its heart!」。**队伍显示与选中许可**——打开**整只队伍**的选择画面，成员按合格谓词**标注可选/不可选**（**不是「只列」合格成员**；可选谓词：可战斗（非昏厥）、非蛋、Shadow 且心量 0——WP66-A 引用；**选择器没有 Lugia 排除**：只有 Lugia 可净化时外层不开放，但另有合格非 Lugia 使入口开放时，存活心量 0 的 Lugia 可被选中并净化——WP23 已审合同）。**反例**：队伍只有一只濒死、非蛋、非 Lugia、心量 0 的 Shadow——外层仍显示可开放消息并进入队伍画面，该成员被标**不可选**。**最终统一净化**只对选中的合格成员发生。**取消选择不写净化状态**（外围消息已显示）；但选人包装仍会按 WP66-A 写选择结果变量（选中下标与名字变量）——不泛称完全无状态写入（R10 修订）。
- **遗迹石演出与返回**：背景＋消息窗；独立仪式演出为空操作（不证明素材可用）→统一净化（§6.3）→收尾。此入口的成长刷新为空操作，前序资源/消息正常时跨级恢复可继续等级工具与精确经验写回；学招放弃、进化取消、昵称拒绝仍各按其规则，不保证任意宿主操作成功。**包装返回透传场景收尾结果，不能当作净化成功标志**；不存在完成净化后固定报告成功的保证，与孵化包装明确true分开。底层释放具体返回未取证，不猜恒假/空值/固定值。
- **香类道具（JOYSCENT/EXCITESCENT/VIVIDSCENT，WP28/WP23 引用）**：非 Shadow 或（亲密度满且心量 0）→「It won't have any effect.」；Hyper 个体先按处理器先行步骤恢复理智（「came to its senses」消息）。**随后的消息按两种数值的实际变化分支（R12 修订）**：**心量本次未变** → 只显示「{1} turned friendly.」（不进入「心门稍开」与准备检查——正常反例：有效 Shadow 已零心量但亲密度未满）；**心量改变而亲密度未变** →「{1} adores you!\nThe door to its heart opened a little.」＋可净化检查；**两者都改变** →「{1} turned friendly.\nThe door to its heart opened a little.」＋可净化检查。
- **TIMEFLUTE（R12 修订；WP23 已审事实）**：自身使用门拒绝非 Shadow／心量 0／Lugia（「It won't have any effect.」、不消费）；**通过自身门时心量必非 0**——而统一净化只接受心量 0 的对象，**调用立即早退：不清 Shadow、不出现 §6.3 所列净化消息**；**道具处理器仍报成功、按外层规则消费**（普通使用门通过的前提：非蛋、非 Hyper 等——WP28 引用）。**TIMEFLUTE 不构成净化提交**。

## 7. E：名人堂登记与浏览

### 7.1 登记入口

- **记录写入（先于演出）**：当前队伍逐只**克隆**存入新一届记录数组（**蛋在默认配置（`ALLOW_EGGS`＝true）下也收录**）；追加到全局名人堂数组、届数编号递增 1；**容量裁剪按上限值分列（R14 修订）**：**正上限**（默认 50 届）——每次超限只删除最早一届（**编号不回退**——浏览显示的届号由编号与数组位置推算）；**负上限**——不裁剪；**上限 0**——见下条。
- **上限 0 的完整行为（R14 修订；历史数组、累计编号与 PC 门分开）**：从空记录/编号 0 开始登记——**先追加克隆记录并把编号增为 1，随后按「超出 0」只删最早一届**：**内存历史数组仍为空、编号已为 1**。PC 可见门只看编号（§7.2）→ **PC 项变为可见**；进入浏览时取最新一届得到空值，**成员创建对空值请求记录长度处失败**（不能正常浏览、也不静默隐藏——静态失败点；宿主错误呈现未证，不改 reference 修复）。**不能把「无记录」统一视为 PC 不可见**。
- **演出序列（不可跳过）**：BGM（默认「Hall of Fame」；配置为空则不播）→ 逐只成员：滑入（0.4 秒）、播叫声、显示数据（图鉴号、名字/物种与性别、等级、ID；蛋显示「Egg/Egg」、ID「?????"」）、各停留 3 秒、其余成员变暗 →「Welcome to the Hall of Fame!」（4 秒）→ 训练家滑入（移除横条）→ 训练家数据卡（名字/ID/时间/图鉴拥有与见过数——**首届时间为「进入名人堂用时」统计（由名人堂事件记录一次），之后各届为总游戏时间**）＋「League champion! Congratulations!」消息 → 停留 → BGM 1 秒淡出＋画面慢淡出。
- **无取消输入**：登记演出全程没有 BACK/USE 分支（自然播完）。
- **记录与保存的关系**：记录写入全局对象（内存，WP09 引用：随存档持久）；**登记本身不触发保存**——不能把内存更新写成已落盘，也不能推断自动进入片尾或自动保存（demo 剧情链归 U01/WP77）。
- **重复登记**：每次调用都新增一届（克隆当前队伍），编号递增；无去重。

### 7.2 PC 浏览入口（PC 注册项排序值 40）

- **可见门**：名人堂届数编号 > 0（WP65 引用）；进入前「Accessed the Hall of Fame.」消息。
- **导航**：从最新一届开始、无滑入动画直接展示；**LEFT/RIGHT** 在届内成员间移动（播叫声、其余变暗、显示数据与「Hall of Fame No.」届号）；**USE** 向更早一届跳转（成员下标＋10 越界触发）；越过届边界时换届（更早/更新），**到最早/最新一届之外则退出**；**BACK** 退出。返回 PC 主菜单（效果返回 false，WP65 引用）。
- **届号显示**：由届数编号与当前数组位置推算（裁剪后最旧一届的届号＝编号 − 数组长度＋1）。

## 8. F：片尾流程

- **入口**：事件把场景设为片尾场景（进入片尾显示，R15 修订：以行为表述，不引用参考赋值/创建语句；demo 事件 U01/WP77 引用）；无菜单/确认包装。
- **文本来源**：游戏致谢（配置 game_credits，可翻译、`<s>` 分双栏）＋**插件署名自动追加**（每个注册插件的名称/版本/作者列表，WP05 引用）＋引擎/宿主/版权固定段。名单较长时相邻两名并栏显示。
- **呈现**：背景按 11 秒/张轮换（默认 5 张）；文本以 40 像素/秒匀速上滚（速度不随帧率）；停 ME/BGS/SE、BGM 2 秒淡出后播片尾曲（默认「Credits」）。
- **结束路径**：**自然结束**（滚动越过全部文本高度）；**跳过**——**仅当已播放标记为真时**，USE 立即结束（**首次播放不可跳过**）。
- **收尾**：快照背景、BGM 2 秒淡出、8 帧黑屏过渡、释放精灵与视口、**标记已播放**（完成标记在循环结束后写入——首次自然播完才置位；跳过路径本来就已置位，R15 修订：以行为表述）、恢复之前 BGM、**返回地图场景（有地图上下文时）或场景置 nil（无地图上下文）**。
- **完成标记与保存**：标记写入全局元数据（内存，WP09 引用）；**不写存档**；调试菜单另有手动开关该标记的入口（对照，不作正常流程）。

- **名人堂**：`HALL_ENTRIES_LIMIT`＝50（默认；**上限 0 是配置变体而非「不保存」**——**原历史为空时**：登记仍追加记录并增编号、随后裁空（数组空/编号 >0），PC 可见后进入在成员创建处失败（LC 系列，R14）；**已有记录时每次只删最早一届、不清空、不触发该失败**；负值不裁剪）；`ALLOW_EGGS`＝true（蛋收录）；`SINGLE_ROW_OF_POKEMON`＝false（两行布局）；`ANIMATION`＝true（滑入动画；false 时直接到位）；`ENTRY_WAIT_TIME`＝3.0／`WELCOME_WAIT_TIME`＝4.0／`FINAL_FADE_DURATION`＝1.0；BGM「Hall of Fame」（空串不播）；`REMOVE_BARS_WHEN_SHOWING_TRAINER`＝true；PC 注册排序值 40、条件编号 >0。**配置名不等于行为保证**（如 ANIMATION＝false 仅跳过滑入）。

## 10. 边界、失败与未知

- **进化取消边界**：取消只在动画段判定；成功后置动作/物种写入不发生；evolutions_cancelled 递增；重复入口不幂等（§3.2）。
- **进化石对 Shadow 无效**（「It won't have any effect.」）；满级糖进化需配置开启（§9）。
- **孵化回退分支不可达**：演出包装恒真，纯消息版孵化在当前基线不可达（§4.1）；直接调用孵化无蛋态门（入口级对照）。
- **交换收到者进化**：不可取消；最终队伍槽替换在进化场景调用结束之后（§5.3）；WP32-N02 两处收尾调用与重复释放未证（§3.3）。
- **净化室跨级失败**：首个能力窗口更新处失败、后续未必到达、中心保留部分修改（WP23 已通过边界，§6.3）；同等级路径继续；遗迹石包装另有合同。
- **净化室双满**：存放失败只提示、调用者仍清中心、已完成修改不回滚（§6.3）。
- **净化室编辑退出**：持握成员时取消被「You're holding a Pokémon!」拦下；合格组在打开与编辑结束后两次检查（§6.2）。
- **名人堂**：编号 0 且从未登记时 PC 项不可见；**上限 0 变体且原历史为空时**：登记后编号 >0、PC 可见但进入在成员创建处失败（§7.1，R14）；**已有记录时每次只删一届、不清空、不触发该失败**；正上限每次超限只删一届、编号不回退（§7）；登记不自动保存（§7.1）。
- **片尾**：首次不可跳过；完成标记在循环结束后写入；无地图上下文时场景置 nil（§8）。
- **未证的异常清理**：演出中异常（脚本错误/事件中断）时的资源/状态清理未逐项验证；真实事件可达性（各入口的地图事件调用者）具名保留（U01/WP77）。
