## 1. 目的、范围与非目标

**目的**：从作者（游戏制作者）视角规定**工程与事件内容的自动转换、整理与外围制作**能力：

- 编译期地图/事件转换（训练家事件编译驱动及其全部子转换）：训练家注释事件、道具球命名事件、门动画改写、事件名规范化、旧脚本用法替换、文本命令规范化、柜台合并。
- 新地图导入：Data 目录新地图文件登记进地图信息树。
- 文件名更新器：旧图形文件更名与事件引用同步。
- 脚本散文件与归档往返（提取脚本／合并脚本）：Scripts.rxdata ↔ Data/Scripts 目录树。
- 区域地图文本制作（townmapgen.html）：town_map.txt 节内容的可视化编辑与文本生成（纯静态阅读结论）。
- 外围宿主工具文档边界（extendtext；animmaker 已归 WP74，不重提取）。

**范围**：A 入口与触发（编译生命周期内的调用点与门（WP04 引用）、debug 菜单两项、命令行两个 Ruby 脚本、浏览器页面、RMXP 外挂程序）；B 新地图导入（文件扫描、排除规则、编号与命名、写出与缓存、消息）；C 事件简写转换（训练家注释族（13 前缀）、道具球命名族、事件名三映射、门启发式改写、通道页补设、柜台合并）；D 旧用法与文本规范化（35 对标识替换＋2 条正则规则、六族旧战斗起式转换、金钱比较、道具球谓词改写、空战斗分支补退出、治疗循环事件化、Show Text 规范化）；E 往返与外围（脚本提取/合并两向守卫与写入、文件名更新两阶段、区域地图文本编辑与生成、extendtext 文档边界）；F 写出、失败与兼容（每个转换家族的触发条件、转换前后行为、真实写入对象、顺序、无变化、取消、重跑/已转换、冲突与部分失败；demo 素材缺口与未验证范围）。

## 2. 概念与术语（实现中立）

- **转换家族**：共享触发与写出方式的一组自动改写。本稿六族：新地图导入、训练家注释事件、道具球命名事件、事件改造（门/事件名/通道页/柜台）、旧用法替换、文本规范化。
- **识别谓词**：只判断「长得像什么」的检查（门启发式、通道启发式、柜台启发式、mart/nurse 识别）——命中才改写；识别边界继承 WP61：识别 ≠ 构造模板、不保证不误判。
- **事件简写**：作者在事件名或注释里写的紧凑约定（`item：X`/`hiddenitem：X` 名字、`Battle：`/`Type：` 等注释前缀、注释行内的 `SellItem（道具名,价格）` 括号形式），编译期展开为完整事件命令。
- **地图信息树（mapinfos）**：`Data/MapInfos.rxdata` 中的地图登记集合（编号、名字、顺序）；新地图导入的写入对象。
- **散文件树**：`Data/Scripts/` 目录下的 rb 脚本文件与子目录；与 `Data/Scripts.rxdata`（归档）互为往返。**提取产物按两层编号约定布局**（计数器两级，§12.1）；**作为合并输入的目录层级不设上限**（合并递归无层数上限，§12.2）——两层约定只约束提取侧产物，不是对散文件树本身的全局限制。
- **装载器（loader）**：提取完成后写入 `Data/Scripts.rxdata` 的单节归档（只有一条 Main 记录，内容为一段预置压缩数据）——本稿只登记写入形状，不执行、不解包。
- **town_map.txt 节**：区域地图 PBS 数据：`[编号]` 节＋`Name`／`Filename`＋若干 `Point`（字段：X、Y、地点名、地标、飞行图/飞行 X/飞行 Y、开关——Point 模式以 GameData 模式为准，WP04 引用）。
- **已发生写入**：转换/往返对工程文件的实际落盘（地图、地图信息、tileset、系统、公共事件、图形文件、Scripts.rxdata、ScriptsBackup.rxdata）——本稿逐族登记，不补原子回滚承诺。

## 3. 入口与触发（A）

### 3.1 编译期转换的调用点（WP04 引用，不重提取）

- 全量编译入口：不重编译（入参为假）→ 消息并直接返回；否则顺序＝编译 PBS 文件 → 编译动画（WP74 交界）→ **训练家事件编译驱动**（本稿主驱动；其入参未被使用，如实登记）→ 翻译收集（WP08 边界）→ 消息保存/载入。主入口仅调试模式：缺 PBS 目录则先建目录全量写出并强制重编译；**重编译标志会吸收新地图导入的返回值**（有新地图导入即触发重编译）；其后按数据/PBS 文件修改时间判定。
- debug 菜单文件选项下「Rename outdated files」：**先确认**才执行文件名更新，完成后提示 Done。

### 3.2 命令行脚本与浏览器/外挂入口

- 提取脚本：文件末行调用合并入口（提取入口行被注释）；合并脚本：末行调用提取入口（合并入口行被注释）——两文件除入口行外内容相同（各 183 行，同字节数）。运行需要本机 Ruby（README 声明）；本稿不执行。
- `townmapgen.html`：浏览器打开的作者工具页；本稿只静态阅读 HTML/脚本，不在浏览器运行。
- `extendtext.exe`：RMXP 显示文本/脚本对话框的放大外挂（仅文档陈述，§14）。

## 4. 新地图导入（B）

- **触发**：仅调试模式（非调试返回假）；在 WP04 重编译判定中被调用，返回值并入重编译决定（§3.1）。
- **识别**：扫描 `Data/` 下 `Map*.rxdata` 的数字编号文件；排除已登记在 mapinfos 的编号；**跳过编号 999**（随机地牢图）。
- **转换**：对每个未登记编号新建地图信息——名字 `MAP%03d`（编号三位补零），**顺序从现有最大顺序＋1 起逐个递增**。
- **写出与缓存**：有导入才写 `Data/MapInfos.rxdata` 并清空地图信息运行缓存；消息报告导入数量；无导入不写文件、无消息、返回假。
- **重跑/部分失败**：已登记的不重复导入（幂等）；地图文件本身不被修改（只登记信息）。

## 5. 训练家注释事件转换（C-1）

### 5.1 触发与识别（R01 修订——收集门与解析支分开）

- 事件有页且首图层命令表 ≥2 条，否则返回 nil（不改事件）。
- **收集门（白名单 13 个前缀）**：逐个注释首行（连续注释行拼为一块）检查——命中 `Battle:`、`Type:`、`Name:`、`BattleID:`、`DoubleBattle:`、`Backdrop:`、`EndSpeech:`、`Outcome:`、`Continue:`、`EndBattle:`、`EndIfSwitch:`、`VanishIfSwitch:`、`RegSpeech:` 之一才收集该注释块（匹配按行首锚定，块内后续行首命中同样入选）；任一入选即进入转换。**`CommonEvent:` 不在白名单内——独立写 `CommonEvent:` 的注释块不被收集、其值被忽略**。
- **解析支（13 条，与白名单不同集）**：`Battle`／`Type`／`Name`／`BattleID`／`DoubleBattle`／`Continue`／`EndIfSwitch`／`VanishIfSwitch`／`Backdrop`／`Outcome`／`EndBattle`／`RegSpeech`／`CommonEvent`——**`EndSpeech` 有收集无解析支**（入选的 `EndSpeech:` 块不产生任何战后台词赋值；战后文本只来自 `EndBattle:`）；**`CommonEvent` 有解析支无收集门**——只在某个已入选注释块的块内行首出现时才被消费，且**每块只取第一个命中支**：块以 `Battle:` 开头时，**Battle 支先命中并把其后整段（含续行）作为战斗文本**——续行行首的 `CommonEvent: 数字` 被吞入战斗文本、公共事件参数仍为默认 0（组合失败）；**真正可达的组合是块以 `EndSpeech:` 开头、末个续行行首为 `CommonEvent: 数字`**——该块靠 EndSpeech 入选、前面无更早命中支，于是进入 CommonEvent 支、该值进入电话登记的公共事件参数（整体转换仍需另有有效 `Battle:` 块）。
- 每个注释块按解析支顺序取**第一个命中支**（一支一块）；未命中任何支的入选块不改变任何字段（保持默认）。
- **必须有至少一条 `Battle:`**，否则返回 nil（此前已收集的其它前缀不产生任何改动）。
- 注释起始于事件第 0 条时，若事件名不含 trainer 字样则改名为 Trainer（3）；若事件名已是 Trainer（N） 形式则保留其 N。
- 转换产生**全新事件对象**替换原事件（同坐标、同 ID；首页图形属性经克隆保留）；**原注释不保留**（保留开关为常量假，如实登记）。

### 5.2 解析（各前缀语义）

- `Battle:` 追加一条战斗文本（可多条＝含再战）；`Type:`/`Name:` 去首尾空白作训练家类型/名字；`BattleID:` 数字（再战系列的起始版本号，默认 0）；`DoubleBattle:`/`Continue:` 值 TRUE/YES（大小写不敏感）为真；`EndIfSwitch:`/`VanishIfSwitch:` 收集开关编号（可多条）；`Backdrop:` 背景名；`Outcome:` 结果变量编号（默认 0）；`EndBattle:` 战后文本（可多条；**一条都没有时默认补一条「...」**）；`RegSpeech:` 登记电话台词；`CommonEvent:`（仅入选块内行首）公共事件编号（电话登记用，默认 0＝不带）。

### 5.3 训练家检查器（R02 修订）

- **检查集合按 Battle: 条数分开**（均在本编译驱动内执行，编辑器内不执行）：1 条 → 只查主战斗（起始版本号）；2 条 →**只查主战斗**（第二条文本直接写进再战页、**不查第二个版本**）；≥3 条 → 查主战斗＋逐个再战（版本号递增）。（运行时首页的系列检查脚本另有运行时合同（调试下确认「新建训练家变体？」，属 WP73-A/WP04 交界），与本编译期检查器是两个入口。）
- **门与「不再问」**：检查器整体先判**调试模式与「不再问」标志——非调试或已置「不再问」时本调用链直接返回**（不产生任何询问或异常）；底层公开缺失入口的非调试异常是该入口自身合同（WP73-A/WP04 已通过），**不是本编译调用链的结果**。
- 调试且未「不再问」时：**类型不存在** → 确认「新建训练家类型？」，是则调训练家类型新建编辑器（WP73-A 交界）；**类型存在但训练家不存在** → 经底层缺失入口三回答——是＝调新建入口创建、否＝不创建、**取消＝本次编译不再询问**（检查器置「不再问」标志，后续同类缺失静默跳过）。
- **字符图补设三支（R03 修订）**：事件已有字符图 → 不经此路径；无字符图且类型存在 → 查询类型的字符文件名——**解析到名称** → 经图像存在性检查，存在才补设；**查询返回空值**（资源路径均无该类型图）→**先与目录拼接即失败**（字符串拼接空值，未保护）——失败发生在存在性检查**之前**，转换无法产出正常新事件（传播边界按编译调用层，WP04 继承；运行形态未验证）。不会「平稳跳过不补图」。

### 5.4 产物页面结构（行为描述；R04 修订）

- **单战斗（1 条 Battle:）→ 2 页**：第 1 页（事件触碰触发）：类型开场、提醒玩家、战斗文本、（双打/背景/结果变量/允许败北按需设置战斗规则）、正常训练家战斗起式条件分支，分支内置自开关 A；页尾训练家收尾。第 2 页（动作触发、条件自开关 A）：战后文本。
- **多战斗（≥2 条 Battle:）→ 3 页**：第 1 页在单战斗结构基础上**追加一条独立的系列检查脚本命令**（带战数与版本号——运行时合同见 §5.3）——它是**额外的检查命令，不是战斗起式**；实际战斗仍是随后的正常训练家战斗起式条件分支（先检查、后战斗）。分支内再加「电话可登记？」子分支（登记台词＋Yes/No 选择＋电话登记——带公共事件或版本号的参数变体，公共事件值来自 §5.1 组合路径），自开关 A、B 双置；第 2 页（再战页，条件自开关 B）：开场后按电话变体号分支各战斗文本（首条「不超过」、末条「至少」、中间「等于」），电话再战起式＋胜后重置，自开关 A；第 3 页（结束页，条件自开关 A）：按变体号分支各战后文本（缺省回退到最后一条），并再放一次电话登记子分支（结构同第 1 页）。
- **首页与再战页的背景参数差异（R04 修订）**：首页的背景规则生成**字面字符串参数**（名称经转义处理后包在引号内）；再战页生成**不带引号的同名文本**——按事件脚本的求值语义它是**待求值内容**：普通背景名（如 forest）在求值环境无同名定义时会失败（经脚本执行的错误展示路径，WP17/WP04 交界；运行形态未验证），默认无背景（未配置 `Backdrop:`）则两页都不生成背景规则。**不能统一预测两页背景配置等效**，也不替参考产物补引号。
- **`EndIfSwitch: N` 页**：每条复制结束页骨架，改条件为开关 N（已有条件 1 则放到条件 2）、清自开关条件、内容为第一条战后文本（无则「...」）。
- **`VanishIfSwitch: N` 页**：同骨架但**无字符图**、无命令（事件在该开关下消失）。

## 6. 道具球命名事件转换（C-2）

- **识别**：事件名完整匹配 `item:名字` 或 `hiddenitem:名字`（大小写不敏感；名字为词字符）；**道具必须已注册**，否则返回 nil（不转换）。
- **产物**：2 页新事件（同坐标同 ID；改名为 `Item`／`HiddenItem`）：第 1 页（可见时带「Object ball」字符图）——道具球给予的条件分支＋自开关 A＋否则分支；第 2 页条件自开关 A（空白，表示已拾取）。
- **重跑**：转换后事件名不再匹配前缀（幂等）；不匹配前缀或道具未注册都不改事件。

## 7. 事件改造与修复（C-3）

### 7.1 事件名规范化

事件名（大小写不敏感、整名匹配）：`tree`→`CutTree`、`rock`→`SmashRock`、`boulder`→`StrengthBoulder`；其它名不改。

### 7.2 门启发式改写

- **外层识别（全部满足才进入后续）**：事件 ≥2 页；末页有开关 1 条件、有字符图、命令 >5 条且首条为条件分支。**外层完全未命中（页数不足、末页无开关条件、无字符图、命令数不足、首条非条件分支）→ 整个事件保持原样**。
- **开关 22 特例（先于结构门执行，R05 修订）**：外层满足后，若末页条件开关恰为 22 但其名字已被改作他用（非 `s：tsOff?("A")` 形式）→ **立即**重新注册该名字到新开关并改用（记为变更；系统开关表可能同时变化）——**此副作用发生在倒数第二页结构检查之前**。
- **改写条件**：末页条件开关的名字为 `s：tsOff?("A")` 形式，且**倒数第二页**恰有 1 条玩家转移命令且不含透明标志命令。
- **三条路径（R05 修订）**：(a) 外层未命中 → 原样；(b) 外层命中＋开关 22 被改名＋**结构门不通过**（如倒数第二页有 2 条转移）→**两页不重写，但开关重注册及系统开关表变化已发生并随驱动保存**——无「无操作式保证」；(c) 外层命中＋（如有需要已重注册）＋结构门通过 → 两页重写。
- **改写（两页都重写，仅路径 c）**：倒数第二页＝门开动画（门 SE＋转向序列）、玩家穿门移动、透明开、跟随者入门脚本、门关动画、全黑淡入、转移命令（沿用原参数）、淡出恢复；末页＝「玩家在事件上？」条件分支＋透明开＋跟随者隐藏＋门开到位＋透明关＋玩家出＋跟随者归位＋门关序列＋分支尾＋临时自开关 A 置位。
- **开关注册**：在系统开关表 1–5000 中找第一个空名或同名槽；找不到返回 1（如实登记）；注册写系统数据，随 tileset 保存落盘（§10）。

### 7.3 通道页补设

- **识别**：事件恰 1 页、无字符图、命令 ≤12 条、含玩家转移命令；事件所在格可通行，但**左、右、左上、右上四格均不可通行**（向下格的检查在源中被注释停用，如实登记）。

### 7.4 柜台合并

- **NPC 侧识别（商店/护士谓词）**：单页、移动类型固定、无任何开关/变量/自开关条件；且满足三者之一：命令 ≤1 条（空事件）；或简单商店（≤12 条命令、有字符图、首条为商店脚本起头）；或中心护士（>8 条命令、有字符图、首条为中心设置脚本起头）。
- **候选排除门（R12 修订）**：邻接候选先过空事件谓词——空/纯装饰候选（单页、固定移动、无条件、命令 ≤1 条）**直接跳过**（不检查柜台、不删除）。
- **柜台侧识别（柜台谓词）**：下列二选一——(a) 位于柜台标志格（**此支先于一切空间检查**，见下方边界条款）；(b) 在「有图事件与玩家可站位置之间」：NPC 事件有字符图、候选事件无字符图且为动作触发、NPC 格可通行、候选格不可通行、候选格另一侧（远离 NPC 方向）可通行。
- **邻接查询的真实边界（R13 修订）**：位置查询只拒绝负坐标、**不拒绝横坐标达到地图宽度**——其位置键（y×宽＋x）与下一行首格重合：宽 4 的地图上查询 (4,0) 可能取到 (0,1) 的事件。命中走 (a) 支（已在柜台格）时**不做空间核对**——所谓「四邻」扫描在最右列可能处理**几何上并不相邻**的事件（如实登记该检索缺口，不推荐为未来存储设计）。
- **多命中与共享（R12 修订）**：邻接按**上、下、左、右**固定顺序处理；每个命中都是**替换**（NPC 的页面被换成该候选的页面数组）而非累加——多候选命中时**最后处理的候选决定页面**，全部命中候选都列入删除（删除在本图全部事件处理完之后统一进行，因此同一候选可被多个 NPC 先后接收）；接收方保存的是**同一页数组对象**——后接收者套用视觉属性（图形/动画）会**改变先接收者已得页面的显示**（共享效果，如实登记）。
- **写出**：有合并才随 §10 落盘；tileset 通行表修改随 tileset/系统一同保存。

## 9. 文本命令规范化（D-2；Show Text 处理；R11 修订）

按源内实际先后次序执行四个子规则（互不嵌套保证不成立，组合效果见各条）：

1. **格式码规范化**：仅当**行首为反斜杠且码后随空白**才处理——`\B `→`\b`（**空白一并被删除**），`\R `→`\r`，`\PG `→`\pg`，`\POG `→`\pog`，`\G `→`\G`，`\CN `→`\CN`（大小写不敏感匹配、归一为小写或大写形式按源登记）。**裸码无后随空白不改**（`\B` 后无空格 → 不动）；**已小写但码后有空白也会变化**（`\pg x` → `\pgx`，空白被吃掉）。
2. **4 行窗口**：从第 2 行起数，每数到第 4 的续行改为新文本命令首行——9 行文本在**第 5、9 行（一基）**拆分（窗口 4/4/1）。
3. **短首行合并**：首行长度 1–20、**不含 `\n`**、且有续行 → 把第 2 行以 `\n` 并入首行、删除第 2 行、重审本条——**并入后首行已含 `\n`，同一短行规则不再满足**——**只并一次**（第三条行保持为续行，不连锁）。
4. **跨命令断句**：本命令 ≥3 行且下一条也是文本命令，且本命令末行**不含** `.,!?;-"` 结尾字符且**不含反斜杠或 `<`（任何位置）→ 在合并全文中找最后的句读点（优先 `. `/`.\n`/`!`/`?`，找不到退 `, `/`,\n`）；找到则在该点切分：**前半保留为本命令**（多行），**尾段作为新的文本命令（首行＋续行）放到原下一条文本之前**，**原下一条文本被降为续行、内容保留**（不丢弃）；无句读点则不动。
- 每条规则只在实际变化时记变更；命令数/缩进按源行为保持。

## 12. 脚本散文件与归档往返（E-2）

### 12.1 提取（归档 → 散文件）

- **守卫（R15 修订——数量启发式，不是状态判定）**：读取归档；**节数 <10** 打印「已是散文件状态」提示并返回（不写任何文件）；**节数 ≥10 照常执行**——本方向边界：**9 拒绝、10 放行、11 放行**（与合并方向不同，见 §12.2）。
- **破坏性前置**：创建目标目录后**先清空整个散文件树**（递归删除既有 rb 脚本文件与全部子目录内容）——README 亦声明「既有散文件会被删除」；无逐项确认。
- **转换**：逐节处理——节名转义为文件名安全形式（9 个实体：`&bs;`＝`\`、`&fs;`＝`/`、`&cn;`＝`:`、`&as;`＝`*`、`&qm;`＝`?`、`&dq;`＝`"`、`&lt;`＝`<`、`&gt;`＝`>`、`&po;`＝`|`）；正文解压并**删除全部 CR**；节名与正文皆空则跳过。
- **目录结构**：`[[ 名 ]]` 节 → 建目录（**两层编号约定**——编号计数器只有两级、按层重置、3 位补零、倒数第二节用 999；**两层约定是提取一侧的布局约定**，见 §12.3 与合并侧的关系）；**等号五连前缀**的节 → 回到主目录；其余节 → `NNN_节名` 加 rb 脚本后缀写入当前目录（文件编号每目录重置、3 位补零、末节用 999；空名/空节名归一为 `unnamed`）。
- **收尾（写入顺序固定）**：先把原归档**备份**到 `Data/ScriptsBackup.rxdata`，再把 `Data/Scripts.rxdata` **替换为装载器**（单节 Main 记录，内容为预置压缩数据块——本稿不执行、不解包，§1）。

### 12.2 合并（散文件 → 归档）

- **守卫（R15 修订——同一数量启发式、方向相反）**：读取归档；**节数 >10** 打印「已是归档状态」提示并返回；**节数 ≤10 照常执行**——本方向边界：**9 放行、10 放行、11 拒绝**（与提取方向 9 拒绝、10/11 放行相反；两方向的 9/10/11 矩阵分列）。**旧归档只参与进入门**：通过门后**丢弃旧归档列表**、从目录**重新聚合**——合并结果**不包含旧装载器或其它旧节**（如根目录恰一个脚本、无子目录——无论旧档是一节装载器还是其它 ≤10 节输入，**结果只有 1 节**）。**合并产物若仍 ≤10 节**（如上述单脚本产物——1 节），**第二次合并仍通过守卫**——重新聚合并覆盖归档、节 ID 重新随机（**同方向重跑并不必然安全**，如实登记）。
- **聚合**：按目录树**深度优先、字母序**——目录内先收全部 rb 脚本文件（排序后逐个生成节：节名＝文件名去编号前缀与 rb 脚本后缀、按 9 实体反转义、空名归一为 `unnamed`；正文原样压缩；节 ID 为随机数）；再按排序逐个处理子目录：第 0 层每个子目录前先插入一个**等号十八连**的空节，第 1 层先插入空节，再插入 `[[ 子目录名 ]]` 节，然后递归（**递归无层数上限**——三层及更深的散文件树同样被聚合；两层编号约定只约束提取侧布局，§12.1）。
- **写出**：聚合结果**直接覆盖** `Data/Scripts.rxdata`——**不备份**（与提取方向的不对称如实登记）；散文件保留在原地但不再生效（README 声明）。
- **空目录/无 rb 脚本文件**：守卫通过而目录无可聚合内容时，产物为仅含目录结构节的归档（如实登记）。

### 12.3 往返一致性（R16 修订——保留/规范化/丢失矩阵，不再宣称等价）

| 对象 | 提取方向 | 合并方向 | 往返结果 |
| --- | --- | --- | --- |
| 节 ID | 读档使用原 ID | **重新随机** | **不保留**（已知差异） |
| 节标题 | 修剪首尾空白、9 字符 → 实体转义 | 剥 `NNN_` 前缀与 rb 脚本后缀（**大小写敏感**）、实体反转义 | 修剪归一；**字面实体碰撞**：原标题含字面 `&bs;`（无反斜杠可转义时按字面写入文件名）→ 合并反转义为 `\`（**标题被改变**） |
| 空正文普通节 | **不生成文件**（正文为空的普通节不产生对应脚本文件） | 无从聚合 | **丢失**（结构节 `[[ ]]`/等号节由目录名重建，普通空节不还原） |
| 空标题/空白标题 | 归一 `unnamed` | 同 | 归一为 `unnamed`（原名不还原） |
| 正文 CR | **全部删除** | 原样写入 | **CR 不还原** |

- 守卫是数量启发式（§12.1/§12.2）——**不能仅按「已提取/已归档」标签推断同方向重跑安全**。

## 13. 区域地图文本制作（E-3；`townmapgen.html` 静态阅读）

### 13.1 页面与输入（R18 修订——显示属性 ≠ 真实校验）

- 区域行：图文件名（默认 `mapRegion0.png`，位于 `Graphics/UI/Town Map/`）、区域名（默认 Sample Region）、点宽/点高（**文本字段**，HTML 上标着 1–16 与默认 16——**这只是标记属性**：Refresh 与点击处理**直接取字段值使用，没有 1–16 的范围校验或钳制**）。
- **格尺寸真实处理（R18 修订）**：输入 32 → 点 (100,36) 按 32 向下取整得格 **(3,1)**（不会被钳回 16 对应的 (6,2)）；零、空白、非数字输入**没有本工具自己的拒绝/恢复分支**——进入数值转换或异常值传播（如实登记，不虚构浏览器对文本字段的校验）。飞行目的地、开关等文本字段同样按文本直接使用（**PBS 模式约束不是本页面的自动保障**）。
- 地图区 480×320：悬停预览坐标（无选择时）；**点击选中点**（按格宽/格高向下取整），选中后可编辑字段：地点名、地标、飞行目的地（图 ID,X,Y 逗号串）、开关编号；Save（点选才启用）写入或新建该点并重新生成文本；Cancel 还原字段并取消选择。

### 13.2 载入与生成（文本 ↔ 编辑器状态；R19 修订）

- **载入（R19 修订——开始清空、逐行修改、提示后失败、无回滚）**：开始解析即**先清空点数组**；逐行处理——跳过行首为 `#` 的注释（**行首有空白的注释不匹配此跳过门**——仅空行才按空白跳过）与 `[数字]` 节行；不匹配 `键 = 值` 的行弹出「Bad line syntax in line N」**但不停下或跳过**——紧接着访问失败的匹配结果并**未保护地中断**（弹错后仍失败）。**已发生的部分不会回滚**：坏行之前成功载入的点/名称/图片更新保留在数组中，坏行之后的行与后续生成/取消选择/重绘步骤**到不了**（页面不重绘，数组＝清空后已载入的前缀）。对照：首行即坏 → 数组空＋失败；中途坏 → 保留前缀＋失败；全合法 → 正常完成并重绘。
- **CSV 切分的不对称修剪（R19 修订）**：切分器只在**每次取完一段后修剪剩余输入**——**已取出的值本身不保证两侧修剪**（段内尾部空白保留）；引号处理代码已注释停用（保持）。
- **文本生成**：`Filename = …`＋`Name = …`＋逐点 `Point = X,Y,地点,地标,图,X,Y,开关`——生成函数内的引号包装逻辑已注释停用，**输出为原始未加引号的值**（如实登记）；换行风格为 CRLF。
- **输出方式**：生成文本只进文本框，**由用户自行复制到 town_map.txt**（页面明示需自行加节行 `[编号]`）——**本工具不写任何文件**（浏览器脚本无文件写入路径）；区域图文件与 knownpoint/selpoint 标记图是页面引用的素材（demo 缺失见 §16-8）。
- **编辑副作用**：所有状态在页面脚本内（点数组）；改图/改格/载入都会重绘标记；Save 后才入点数组，Cancel 前不保存。

## 16. 边界、失败与未知汇总

1. 调试门：新地图导入仅调试模式；主入口/编译驱动仅调试路径；菜单更名需确认。
2. 无变化路径：导入 0 张、转换 0 命中、更名 0 文件——都不写文件、各有既定消息或静默返回；往返守卫是**数量启发式**（提取 <10 拒绝、合并 >10 拒绝、**恰 10 两边放行**、合并产物 ≤10 节可再次合并覆盖，§12.1/§12.2）。
3. 识别不误判不保证：门/通道/柜台/mart/护士均为启发式（WP61 识别边界继承）；`SellItem` 只认**注释首行内大小写敏感的括号形式**（`SellItem（名,非负数字价）`，非锚定、冒号形/小写/负价不命中）且道具已注册才改写；道具球名需道具已注册。
4. 文本级替换的边界：**35 对**＋2 正则非语法分析（旧式变量读取**后随**赋值/比较运算符不动——运算符跟在读取之后才受保护（读取位于比较符左侧），读取为右操作数仍替换）；可逃/可败判定是文本包含；逗号切分器不处理转义引号。
5. 破坏性写入如实登记：提取前清空整个散文件树（原归档有备份）；合并直接覆盖归档不备份；更名＝**本地复制后删除**（目标先删再写——目标可能先丢或部分、源删除失败留两份、阶段 1 异常阻断阶段 2）；地图写回容错吞异常（保存失败不报告）；编译驱动无整体兜底（异常中止、已写不回滚）；**一次编译不保证达不变状态**（旧起式空分支二轮才补、治疗残留与单命令持续插入、门路径 b 副作用，§8.2/§8.4/§7.2）。
6. 停用/不可达：玩家转移处理的大停用块、通道补设的唯一调用点、事件 ID 工具的无效实现、装载器二进制块（不执行不解包）、townmapgen 的引号处理停用代码。
7. 训练家检查副作用：类型不存在可触发编辑器新建（编译期、调试下）；缺训练家三回答（建/不建/不再问）——「不再问」只影响本次编译进程；**2 条 Battle: 时第二个版本不被检查**（≥3 才逐个查再战）；**非调试或已「不再问」时本调用链直接返回**（底层缺失入口的非调试异常是该入口自身合同，不经本路径产生）。
8. **demo 素材缺口（未验证）**：`Data/` 仅含 `Scripts/`、`Scripts.rxdata`、`messages_core.dat`——无 `Map*.rxdata`/`MapInfos.rxdata`/`System.rxdata`/`Tilesets.rxdata`/`CommonEvents.rxdata`（地图数据访问层无法构造，全部地图类转换在 demo 不可运行）；`Graphics/` 整体缺失（berrytree、Town Map 目录、knownpoint/selpoint 均无）；demo 地图/事件内容可达性归 WP77。全部运行表现保持未知。
9. 宿主/环境相关未知：两个 Ruby 脚本的实际运行环境（README 要求本机 Ruby）；extendtext 的实际效果；townmapgen 在不同浏览器的行为；开关注册槽满返回 1 的后续影响。
