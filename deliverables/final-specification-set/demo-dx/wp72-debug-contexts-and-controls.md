## 1. 目的、范围与非目标

**目的**：固定调试情境与控制的规则合同——**调试能力从哪些入口可达、各自可见性门是什么、每个命令读什么输入、写什么状态、给什么反馈、失败与取消走哪条路、即时效果与持久归属如何分层**。后续包据此判断「某个调试动作实际改变了什么」，而不是各自重新追踪调试菜单文件。

**范围**：1) A 调试入口、菜单可见性与交互——地图热键、暂停菜单命令、载入界面受限菜单、队伍/存储个体调试、构造测试战斗时的个体调试、战斗命令热键、战斗内成员/队伍入口；菜单框架的层级/返回/根取消/默认选中与刷新/命令返回值关闭语义；`always_show` 三态、上下文用途过滤与可用处理器筛选。2) B 世界情境与会话状态控制——地图传送、开关/变量编辑、地图刷新、场地效果、寄养调试、漫游编辑、Safari/捕虫计数、遭遇版本、训练家重置、Exp All、战斗日志开关、片尾跳过、Shadow/净化室访问各入口。3) C 玩家、队伍、存储与背包操控——货币/徽章/图鉴与地区图鉴/跑步鞋/Pokégear/电话联系人/Box Link/角色/外观/名字/ID；治疗、添加个体、填/清盒子、示例队伍、蛋快速孵化、打开存储；加道具、填充/清空背包。4) D 个体诊断与编辑（非战斗）——HP/异常/治疗/濒死/Pokérus、等级/经验/EV/IV/个人 ID、友好/华丽六维、招式/PP/初始招式、物品/特性/性格/性别/物种/形态、闪光/球/缎带/昵称/所有权、丢弃许可、蛋、Shadow 与心量表、Mystery Gift、复制与删除。5) E 测试战斗及战斗内观察/编辑——普通/高级野生与训练家测试的构造与校验；战斗内双方在场者、速度顺序、队伍、训练家资源、Mega 配额、天气/场地/环境/时间/背景；场/阵营/席位/成员四层效果观察与编辑；成员 HP/状态/能力值/类型/招式/物品/特性/性格/性别/形态/物种/Shadow 的双层（原个体 vs 战斗当前）编辑。6) F 日志、持久性与后续工具边界——观察与修改分列；运行标志与调试标志共同门；临时战斗态/运行中持久对象/显式文件写出/编译输出分层；通往 WP73-A/B、WP74、WP75、WP76、WP64、WP77 的工具入口登记与归属。

**非目标**：不提取编辑器主体（WP73-A/B 主责）、动画编辑/组织/导入/导出（WP74）、文件更名/编译/文本抽取/工程与事件转换（WP75）、设施生成/模拟（WP76）、demo 事件编排（WP77/U01）。本稿只完整登记通往这些工具的**入口、条件、即时副作用和归属**，不宣布工具内部已完成。不重提取已通过规则：正常遭遇/捕获/结算（WP36/WP42/WP38）、战斗上下文（WP39/WP40）、AI 评分（WP51）、个体底层规则（WP18～WP23/WP25～WP35）、净化室合同（WP23）、漫游（WP37）、Safari/捕虫（WP53）、时间/场地（WP59）、野外被动与回程（WP61）、Mystery Gift 领域（WP64）。不运行参考实现/游戏/UI/测试战斗/随机模型/编译器/导入导出/保存转换，不操作真实存档，不访问网络，不设计未来 API。

## 2. 概念与术语

- **调试标志与运行内标志分层**：调试标志由宿主环境给定（测试运行语义；WP01/WP07 引用），是全部调试入口的总门；运行内标志是**运行中可切换的内部标志**——当前基线唯一的写入者是调试菜单的战斗日志开关（§8.1），读取者是日志模块（与调试标志共同门）与异常打印长度选择。**两者独立**：入口可见性只看调试标志；日志输出要求两者同真。
- **菜单注册与可用筛选**：命令以菜单名＋选项 ID 注册为哈希（名称/父级/描述/条件/效果等键）；**可用筛选**按排序键（缺省按注册序号）排序、逐个执行条件（无条件的调试主菜单注册项不设条件——调试门在**入口调用侧**，不在注册项上）；名称可为取值过程或静态文本。**`always_show` 三态**：未设置（nil）／显式真／显式假——**受限模式只排除显式假**（未设置与显式真都保留），§3.2。
- **命令菜单列表框架**：层级菜单——每个命令记录父级；列表给出当前层命令名；可下钻判定；取父级返回父层 ID 及当前层在父层中的下标（用于返回时恢复光标）；描述缺省回落「<No description available>」。**返回父级**（BACK 且存在父级：取消音效＋切回父层＋光标恢复到该层在父级中的位置）与**根取消**（BACK 且无父级：整体退出）分开；**效果返回值关闭语义**——个体调试菜单中效果返回真即退出整个调试菜单（复制/删除用此关闭）；地图调试菜单中地图传送项特殊——效果返回真才关菜单（先清理自身窗口/视口再转移，§4.1）。
- **原个体与战斗当前两层（R07 修订）**：战斗内编辑同时面对**原个体对象**（队伍/盒子中的持久数据）与**战斗当前状态**（在场派生层）。**写入器写穿**：在场对象的 **HP、状态、状态计数、道具、等级、形态**的写入器会**同步写回原个体**（状态写入器还重置相关计数并刷新场景——WP40 引用）；**战斗特性、能力阶段、能力值、类型、效果、Mega 配额等是战斗层**（不写回原个体）。各命令**按名选择写哪一层**（§7.4 逐项）；不存在「改了原个体就自动同步战斗层」或反向的通用保证；退出战斗调试后由战斗命令阶段执行一串**刷新回调**（§7.6），仅这些具名回调，不虚构全面重同步。**持久性推论**：写穿层的改动落在持久对象上（战后保留——WP39 生命周期引用）；战斗层改动随战斗结束消散。
- **用途过滤**：战斗个体调试菜单的命令带 `：pokemon`／`：battler`／`：both` 用途——有在场对象时排除 `：pokemon`，无在场对象时排除 `：battler`（在场成员与不在场队伍个体看到的命令集不同，§7.4）。
- **构造测试 ≠ 沙盒**：测试战斗走正常生成/战斗/捕获/结算入口（WP36/WP39/WP42 引用）——其真实副作用（图鉴登记、经验、拾取、传播、统计等）按正常规则成立；调试侧只负责候选构造与规则实参（可败、遭遇类型清空、人数布局）。
- **观察与修改分列**：仅展示（速度顺序、成员/队伍信息、效果当前值、寄养/漫游状态行）与写入（数值/开关/对象编辑）分开登记；观察行的「当前值」是读取时刻快照，不承诺实时刷新（各界面按自身刷新时机）。
- **持久归属分层**：**临时战斗态**（在场层与战斗设置——**按字段分层（R07 v3）：写穿层字段（HP/状态/状态计数/道具/等级/形态）落在持久个体上、按其后续正常生命周期演化（WP39/WP42 引用）；仅战斗层字段（战斗特性/能力阶段/能力值/类型/效果/Mega 配额等）随战斗结束消散——不声称所有在场编辑都消散**）；**运行中持久对象**（全局元数据/玩家/背包/存储/开关/变量/地图运行态上的改动——随存档保存的部分按 WP09 归属，其中临时字段为运行临时）；**显式文件写出**（动画导入导出、修复图块写地图文件、PBS 生成、编译、日志追加——各自的立即落盘语义按条登记）。**调试改变值 ≠ 正常事件调用 ≠ 会话重新初始化**；菜单效果完成后**不自动落盘存档**（保存由正常保存入口负责，WP09/WP10）。
- **已通过边界（必须继承，不重开）**：WP61（野外被动与回程——含 Pokérus 调试三动作合同与净化室惰性取用）、WP53（Safari/捕虫）、WP37（漫游）、WP23（Shadow/净化）、WP36/WP39/WP42/WP38（遭遇/战斗上下文/终局/捕获副作用）、WP24～WP28（玩家/存储/背包）、WP30（友好数值）、WP33/WP34/WP35（寄养/育种/孵化）、WP59（时间/场地）、WP64（Mystery Gift）、WP65（载入/暂停 UI 框架）、WP67-A/B、GR-001～016、WP23-N01。

- **层级原则**：菜单调用存在、入口要求调试标志、命令条件、父级可达、受限模式可见性是**不同层级**——不能因为效果处理器内部没有调试检查就宣称普通玩家可达（入口侧门已挡），也不能给所有直接调用统一补调试门（脚本直接调用各公开函数走各自前提，§10 有界前提）。
- **调试标志为假时**：地图 F9 不置标记；暂停/队伍命令不出现；载入界面与存储界面命令不加入；战斗 F9 分流不触发。**基线内没有非调试标志的调试菜单入口**（全脚本调用者检索）。

### 3.2 可见性三态与菜单交互

- **完整 vs 受限**：调试菜单的显示全部形参——为假时**只排除 `always_show` 显式假**的条目；未设置（基线中 PBS 编辑器、其它编辑器、文件选项等菜单节点）与显式真（基线中无）都保留。**基线显式假的条目**：Field options…、Battle options…、Pokémon options…、Item options…、Player options… 五个顶层分组节点（其子项随父级不可达而整体不可见——可见性沿父级链，不是逐条打标）。
- **个体调试菜单的构造测试模式**：构造测试标志为真时同样**只排除 `always_show` 显式假**——基线显式假的个体条目：**Set egg、Mystery Gift、Duplicate、Delete**（构造测试时这四项不出现；§6）。
- **交互合同（按菜单家族区分，R02 修订）**：USE——有子菜单则下钻（决定音效、光标归零）；无子菜单则调用效果；BACK——有父级返回父级（取消音效、光标恢复到当前层在父级中的下标）；无父级退出。**描述求值时机**：命令清单（含描述过程的求值）在**进入菜单时收集一次**——**下钻/返回父层只切换当前层与窗口命令名，不重新运行描述过程**（R02 v3 对照：进入一次菜单后往返层级，动态描述依赖值变化不触发重新求值）；光标移动只用已存文本刷新描述行，**不随光标移动重新求值**。**退出清理按家族分开**：地图调试菜单根退出带关菜单音效＋**淡出**＋释放窗口/视口；战斗调试菜单根退出为关菜单音效＋释放（**不走相同淡出链**）；特殊传送的整体关闭属于地图菜单（§4.1）。开关/变量页是**独立子屏幕**（§4.2——BACK 关闭子屏幕回到菜单，不算菜单内层级）。
- **命令返回值何时关闭菜单（R02 v3）**：**地图调试菜单**——普通效果返回值被忽略（菜单继续）；**仅地图传送项**（**仅存在于地图菜单**）的效果返回真时整体返回（其效果内部先完成自身窗口/视口清理与转移准备，§4.1）；**战斗调试菜单——普通效果返回值均被忽略，无特殊传送分支**。**个体调试菜单**——效果返回真即退出（基线中 Duplicate/Delete 返回真：编辑完成后整单关闭并回到底层界面）；取消在顶层且无父级时退出。
- **根取消不留副作用**：菜单框架本身不写游戏状态；所有状态写入都在各效果内（§4～§8 逐项）。

## 4. WP72-B：世界情境与会话状态控制

### 4.1 地图传送

- **目标选择**：地图选择列表默认定位在**默认图**（当前图 ID；无当前图时取系统编辑图 ID；再缺省 0）；取消 → 返回假（菜单继续、无写入）。
- **落点查找**：对目标图**最多 100 次随机尝试**——取随机坐标，要求严格可通行（含朝向 0 的通行判定与玩家占用语义，WP12 引用）且该格无非穿透且有图形的事件阻挡；**100 次失败则回退为一组纯随机坐标**（**不保证可通行**——不补安全落点保证）。
- **转移分支**：**当前是地图场景**——写转移参数（新图/落点/朝下）并调用玩家转移（正常转移链，WP11 引用）；**非地图场景**——取消载具、用地图工厂装配目标图、玩家落位朝下、地图更新与自动播放（音乐/BGS）。两分支最后都**请求地图刷新**；效果返回真——**调试菜单整体关闭**（先淡出、释放消息窗/精灵组/视口再执行转移）。
- **有界边界**：不补「异常回滚」或「必定成功换图」承诺；传送与正常事件传送共用底层，会话状态（跟随者/载具/临时标志）按正常规则演化，调试侧不额外复位。

### 4.2 开关与变量（独立子屏幕，模式 0/1）

- **开关页（模式 0）**：列出系统开关名表的全部条目（数量＝名表长度 −1）；USE **翻转当前原始开关值**并请求地图刷新。**表达式开关（名以 s：前缀）**：**显示**按前缀后的代码**求值**——以类/常量名开头（大写且常量存在）或以非解释器/游戏事件方法名开头或以非字母（如 $）开头才求值，求值异常回落 nil；**nil 显示「[-]」、真「[ON]」（绿）、假「[OFF]」（红）**。**USE 仍翻转底层原始开关**——表达式开关的显示由求值决定，**翻转原始值不改变求值结果**（显示不随之变，也不是把表达式改写为可编辑变量）。
- **变量页（模式 1）**：列出系统变量名表全部条目；当前值显示（空值显示「__」）。**LEFT/RIGHT（repeat）**：数值变量 ±1（**先 nil 归 0**；**钳到 ±99,999,999**）并请求地图刷新；**ACTION**：在 `0` 与空字符串之间互换（数值 → 0、字符串 → 空串的归零/置空切换）；**USE**：数值 → 数值输入框（**最多 8 位、允许负号**，写入同样钳 ±99,999,999）；字符串 → 自由文本输入（**最长 250**）；其它类型无编辑动作。写入后请求地图刷新。
- **开关/变量上限**：包装类读写均限 **ID ≤ 5000**（读越界得 false/0，写越界忽略）。

### 4.3 场地效果与杂项

- **场地效果页**（循环列表、即时翻转）：**Repel 步数**（0–99,999 数值写入，WP61 引用）；**怪力使用**（地图怪力标记翻转）；**闪光使用**——**仅当前图元数据为暗图且在地图场景**：翻转全局闪光标记并**重建黑暗精灵**（释放旧的、新建并加入场景精灵组；开启时半径置最大），否则消息「不在暗图」；**遭遇率降低/升高、野生等级降低/升高**四个地图标志（**先 nil 归假再翻转**——WP36 门输入引用）。
- **刷新地图**：置地图刷新标记并消息提示「地图将刷新」（实际刷新由地图更新链执行，WP11/WP13 引用）。
- **片尾跳过**：翻转片尾已播标记并按新值给出可/不可跳过消息（片尾流程归 WP67-B 引用）。

### 4.4 寄养调试

### 4.5 漫游编辑

- **观察行**：按 `ROAMING_SPECIES` 配置逐个显示——**开关门**（开关 ID ≤0 或对应开关为真）：`roamPokemon[i]` 为真 → 已捕获「[CAUGHT]」／已击败「[DEFEATED]」（红）；否则「[ROAMING][当前图 ID: 图名]」（绿，位置未设时「[map not set]」）；开关为假 →「[NOT ROAMING][Switch N is off]」。尾部两条命令：全员漫游、清空全部位置。
- **USE（状态分支，R04 修订）**：按序判定——①开关 ID 为正且开关原关闭 → **只把开关置真**（**不清已有终止状态**：已捕获/已击败保持）；②否则未击败（`roamPokemon` 非真）→ 已击败（置真、`Caught` 置假）；③已击败未捕获 → 已捕获；④已捕获且**开关 ID 为正** → 不漫游（开关置假、状态置 nil、`Caught` 置假）——**无正开关 ID 的已捕获项四分支都不命中：USE 不变**。**ACTION（单体漫游，开关门通过且未击败）**：**按住 CTRL**：位置在当前默认图与 nil 之间切换——**不清 `roamedAlready`**；**否则**：正常单体漫游推进（WP37 引用），位置未变则先置 nil 再推进一次——**仅此分支 `roamedAlready` 置假**。

- **输出合同（R13 修订——三种门分开）**：**普通日志输出**（日志/头/消息/AI/分数变化各通道）**共同门＝调试标志且运行内标志**——满足时回显控制台并把消息追加到内存缓冲；**各日志方法接受消息后立即调用刷新**（逐次刷新时机，不是批量缓冲）。**刷新**：**写文件**受两标志同真且缓冲非空门控（**以追加二进制模式写 `Data/debuglog.txt`**）；**清空缓冲在门之外**——两标志关闭时刷新不写文件但**缓冲仍被清空**。转储通道直接追加写 `Data/dumplog.txt`（同两标志门）。**异常包装**：记录异常与回溯后刷新——**异常报告（打印＋写 `errorlog.txt`）总是执行，与两标志无关**；运行内标志只影响报告细节（回溯长度 25 或 10 行）。**I/O 异常边界保留**（文件操作自身的宿主异常不另补条件）；不承诺文件轮转。
- **AI 日志**：AI/分数变化通道是**观察输出**——不是真实决策保证；WP51 评分不重提取。
- **调用者**：战斗各处与无视觉战斗场景（**设施/挑战模拟用无视觉场景**，消息经日志消息标志进日志模块——**WP76 边界**，本稿只登记其日志通道）。

### 8.2 持久分层（§2 概念展开）

- **临时战斗态（R07 v3——按字段分层）**：**写穿层字段**（HP/状态/状态计数/道具/等级/形态——§7.4 的在场编辑落在持久个体上、按其后续正常生命周期演化（WP39/WP42 生命周期引用）；**仅战斗层字段**（战斗特性/能力阶段/能力值/类型/效果/Mega 配额等）随战斗结束消散——**不声称所有在场编辑都消散**。
- **运行中持久对象**：§4～§6 的写入落在全局元数据/玩家/背包/存储/开关/变量/地图运行态——**随存档保存的归属按 WP09**；临时字段为运行临时（不写盘）。
- **显式文件写出**：**动画导出**（逐个动画建目录、Base64 写 `.anm`、复制图形/音频资源——完成/无动画消息；**整体异常捕获**（导出过程异常 →「The export failed.」消息））与**动画导入**（扫描 `Animations/` 子目录、复制资源、转换格式、**保存动画数据文件并清运行缓存**——**只有逐项动画解码的局部回落（解码失败跳过该项），没有导出式整体异常兜底**（R14：目录/资源复制/保存等局部保护之外的异常不保证变成统一失败消息）；WP74 主责）；**修复无效图块**（扫描全部地图的图块与事件页图形有效性、无效写 0、**改写地图文件并保存**、控制台与消息报告、「关闭 RMXP 以应用更改」警告——WP73-B/WP75 边界）；**PBS 生成/编译/文本抽取/文本编译**（§8.3——WP75）；**日志**（§8.1）。

## 9. 默认行为与配置变体

- **默认**：调试标志由宿主环境决定（测试运行语义——WP01/WP07 引用）。**加密包检查只参与「跳过继续界面」的提前分流**（调试且非加密包且配置允许才跳过）；**进入命令表构造后，Debug 项只由调试标志决定**（R01 修订：调试标志为真且加密包存在时，跳过分流不成立、进入菜单构造，Debug 仍加入——加密包不是隐藏 Debug 的独立条件）；运行内标志初值未在脚本基线中显式初始化（**全局缺省 nil 即假**——日志默认不输出；§8.1）。
- **配置值（WP02 引用）**：`SAFARI_STEPS`、`BUG_CONTEST_TIME`、`NUM_STORAGE_BOXES`、`BAG_MAX_PER_SLOT`、`BAG_MAX_POCKET_SIZE`、`MAX_MONEY/MAX_COINS/MAX_BATTLE_POINTS`、`MAX_PLAYER_NAME_SIZE`、`EGG_LEVEL`、`ROAMING_SPECIES`、`LANGUAGES`、`SKIP_CONTINUE_SCREEN`、`PROMPT_TO_COMPILE`——按各自语义影响对应编辑项的范围/可用性（如 SAFARI_STEPS＝0 时步数项显示 infinite 不可编辑）。

- **未验证组合**：宿主调试标志实际注入时机、无视觉场景模拟的内部行为（WP76）、各编辑器内部（WP73-A/B/WP74/WP75）、随机源实际序列。

## 10. 边界、失败与未知

- **取消约定（R03 修订）**：数值输入的取消返回值分两类——**显式设置取消值的入口**（BACK 返回该值：0/−1/当前值，调用方按约定处理）；**未设置取消值的入口**（**BACK 返回钳制后的默认值——与按 USE 接受默认值不可区分，调用方随后若无条件写入，状态仍可能改变**）。三个可达对照：①非战斗睡眠计数（默认 3、无独立取消值——**选 0 才取消；按 BACK 返回默认 3，仍赋予睡眠 3 回合**，§6.1）；②寄养「其它值」（以原计数为默认值、无独立取消值——**BACK 返回原计数后仍按 256−输入换算写入：计数 5 时 BACK 使计数变 251**，§4.4）；③所有权「设外来 ID」（以公开 ID 为默认值——**BACK 返回公开 ID 后仍执行完整 ID 合成：低半区 12、高半区 99 时 BACK 使两半区均 12**，§6.5）。选择列表取消 → 无写入；传送取消 → 返回假菜单继续；测试战斗 BACK → 放弃集合（**已发生的生成/加载副作用不回退**，§7.1）。**不承诺任何确认对话框的默认选择**（除文中具名）；**不作全局「取消不写」保证**——以各入口逐项注明为准。
- **容量与拒绝**：队伍/存储全满（添加个体/复制/领取蛋/取出）；盒子满（复制入盒）；口袋容量 0/满（填充背包跳过）；物种数 > 存储容量（填盒部分完成＋附注）；满四招（Teach 提示）；最大等级（Set Exp 提示）；单形态（设形态提示＋重置确认）；单性别（设性别提示）；非 Shadow（心量表提示）；战斗层最大 HP 1（Set HP 拒绝）。**均按实际消息登记，不补事务撤销**。
- **直接调用的有界前提**：各公开函数可被脚本直接调用——**此时不走入口侧调试门**；其行为合同不变（菜单框架与效果逻辑相同），但**可达性结论只对 §3.1 入口成立**。
- **不写盘承诺**：除 §8.2 具名文件写出外，调试编辑**不触发自动保存**；临时字段改动不持久。
- **异常路径**：动画**导出**整体异常捕获 →「The export failed.」式消息；动画**导入**只有逐项解码局部回落（无整体兜底，R14）；效果编辑器遇未知值类型 → 抛异常（防御）；求值型开关显示异常 → 回落 nil（「[-]」）。**不虚构其它异常兜底**。
- **未知/未证**：宿主两标志的实际环境与注入时机（WP01/WP07）；无视觉场景模拟内部（WP76）；各编辑器/工具内部（WP73-A/B、WP74、WP75）；demo 事件链与真实调试使用编排（WP77/U01）；随机源实际序列；批量填盒/填包的实际运行耗时。
