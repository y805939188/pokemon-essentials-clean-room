# PBS 生命周期（净化正文；批次 2）

分类：Demo/Developer Experience（作者工作流）；Generic Kernel（编译机制）。本文件描述作者输入（PBS 文本）到运行数据（.dat）的可见生命周期——什么时候触发编译、哪些输入被发现与如何解析校验、按什么顺序编译、产物如何生效、哪些材料会被写回/删除/覆盖、失败时可能已经发生了什么。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的与范围

**目的**：回答「某数据何时生效、失败可能留下什么状态」，供后续规格引用，而不追踪任何特定编译器结构。

**范围**：① 编译触发（触发条件、调试前提、新鲜度检查、异常类别与阶段）；② 输入发现、解析校验与内容依赖（普通发现、专用入口、活跃解析路径、跨内容引用）；③ 编译产物与写回行为（.dat、PBS 写回、MapInfos、地图事件、动画、反写调用者）；④ 失败与部分状态（非原子性、删除行为、异常路径、错误定位、恢复条件）；⑤ 边界与交界。

**非目标**：不提取字段的 Pokémon 语义（归领域规格）；不提取文本提取/翻译流程、编辑器行为、事件简写转换规则全集（各归相应规格）；不验证任何编译运行的真实结果；不把候选材料当作已支持变体。

## 2. 概念与术语

- **编译**：把作者文本内容转换成运行用序列化数据（.dat）的过程；本文件区分调试启动编译检查与运行中调试菜单的直接全量编译：二者共享内容阶段，触发、删除、异常处理与新地图导入前缀不同（§3.3）。
- **写回**：编译过程中对输入或工程材料的修改（PBS 文本改写、地图事件转换、MapInfos 登记、动画映射保存）。
- **新鲜度检查**：比较数据文件与 PBS 文件的修改时间以决定是否编译。
- **普通发现 / 专用入口**：顶层自动匹配的输入与按字段显式指定的输入（如设施名单引用）。
- **活跃解析路径**：当前实际使用的文本解析/求值函数族（分词、记录求值、值转换、枚举检查及通用/专用编译函数）；相邻标注 Unused 的旧辅助函数不是现行证据。

## 3. 编译触发

### 3.1 触发条件与调试前提

编译检查**仅在调试模式执行**（非调试直接返回，不存在普通运行的自动修复）。启动顺序：核心消息 → 插件 → 编译检查 → 游戏初始化。满足任一条件即判定编译：

| 触发条件 | 行为 |
| --- | --- |
| PBS 目录缺失 | 先创建目录、从当前数据**全量反写**全部 PBS，再判定编译（注意：这些步骤发生在数据文件清单建立**之前**，见 §6 早期边界） |
| 新地图导入 | 扫描地图数据文件，未在 MapInfos 登记的地图（**ID 999 地牢图除外**）自动登记并保存 MapInfos；有导入即判定编译 |
| 必选数据文件缺失或不可读 | 判定编译（可选文件缺失不触发；必选清单见《内容身份、注册与 schema》§4.2） |
| PBS 新鲜度 | 各成功读取的修改时间先截为整秒；分别取 PBS 集合与列出数据文件集合的整秒最大值，前者 ≥ 后者即判定编译（相等也触发，不逐类配对比较） |
| 全量编译标志或按住 Ctrl | 直接判定编译 |
| 启动提示（配置） | 调试＋无打包标记＋`PROMPT_TO_COMPILE = true` 且**用户选择肯定项**时置全量编译标志；**拒绝提示不否决随后新鲜度等自动条件** |

两个时间最大值的初值均为 0；数据文件读取错误触发编译，PBS 读取错误在时间收集处被忽略。隔离新鲜度条件时，须有合法被发现的 PBS，所有必选数据文件存在且可读，PBS 目录存在，且无新地图、全量标志、Ctrl 等其他触发。对非负时间戳，PBS 1000.1 秒、最新数据 1000.9 秒均截为 1000，故触发；PBS 999.9 秒、最新数据 1000.1 秒分别为 999、1000，不由新鲜度触发。不能按更高精度时间推断不同结果。

### 3.2 异常类别与阶段

启动检查判定后进入编译主流程。下表的删除与异常转换属于启动检查；运行中直接入口按 §3.3。诊断须正常返回才继续其后的清理与转换，打印诊断本身失败时不保证后续到达。异常按类别与发生阶段分别处理：

| 异常类别/阶段 | 行为 |
| --- | --- |
| 重置/退出类异常（任意阶段） | **原样重抛**：跳过诊断、清理与通用错误转换（含按兼容类别识别的重置类异常） |
| 其他异常（清单已建立后） | 打印异常（诊断面）→ **尝试**逐文件删除数据文件（每个文件的删除错误被忽略，不保证全部删除成功）→ Hangup 转 Reset，其余转 "Unknown exception when compiling." |
| 早期失败（PBS 缺失分支，数据文件清单建立之前） | 载入/反写失败时，清理分支面对的是**尚未建立的清单**，不能沿用普通编译中失败的完整清理预期 |
| 编译前删除 | 判定编译后、编译开始前**尝试**逐文件删除全部列出数据文件（删除错误忽略）——**不保证全部删除** |

### 3.3 运行中直接全量编译

调试菜单的 Compile data 创建消息窗后直接进入全量内容阶段：发现 PBS 输入并作固定路径兼容改写 → 按序编译 PBS → 编译动画 → 转换已登记地图及公共事件 → 收集文本 → 保存并按文件存在性载入消息。它不经过启动检查的 PBS 缺失建目录/全量反写、新地图导入、新鲜度与强制键判断、列出数据文件预删除，亦不具备启动检查的局部诊断/清单删除/通用异常转换。默认菜单可达仍受调试入口门控制；内容阶段自身不再检查调试标志。

在兼容完整工程、PBS 目录存在、旧产物有效、此前阶段正常且无扩展覆写时，合法词法的新招式 Status/Power40 在招式条目校验被拒绝：更早的类型/特性等档案可已保存新内容，招式表已清并可能有新登记前缀，当前坏招式未登记、整表保存未到，旧 moves.dat 仍在。直接入口不自动撤回这些状态，也不执行启动清单清理；完成消息、消息窗释放及后继阶段只在正常到达时成立。相同失败经启动检查且诊断正常返回时，预删除与异常后删除均按 §3.2 尝试，不保证 I/O 成功。

新复制的 Map007 文件若未登记在地图信息中，直接内容阶段不会为它补登记，事件转换仍只遍历已登记地图；启动检查才调用新地图导入并据返回值决定编译。全合法直接流程可到完成消息；缺目录、异常和未完成前缀不能解释为已完成全量编译。完整宿主及 Demo 均未执行。

## 4. 输入发现、解析校验与内容依赖

### 4.1 输入发现

- **普通发现**：顶层文本文件按「完全基名或基名＋下划线」匹配到数据类，最长基名优先，不递归子目录（《规则配置档案》§6.1 主规格，本文件引用）。
- **专用显式入口**：设施名单的训练家/个体字段显式指定输入文件（当前样本 10 个路径，同前）；不能据普通发现不递归就断言专用路径不访问子路径。
- **被发现不等于可成功编译**：普通发现只决定输入归属；编译前改写等固定路径操作仍直接打开固定文件（如编译前改写打开固定的 moves.txt——只有 moves_extra.txt 而缺 moves.txt 时，前者可被发现，后者按固定路径打开则失败，见 §5.2）。
- **候选材料**：备份子目录不被普通发现扫描，也无自动切换机制（《规则配置档案》§6.2 主规格）；本文件不新增切换办法。

### 4.2 活跃解析路径

以下为逐行核实的**当前活跃**文本解析/求值路径；相邻多个标注 Unused 的旧 csv 辅助函数**不是现行证据**。

**独立注释与物理空行的输入边界**：普通分节读取（如类型、特性、道具）先略过物理首列为井号的行及纯空白行；专用预处理逐行读取（如训练家）则在删除井号后缀、修剪空白后略过空结果。

| 合法材料中的单行 | 普通分节读取 | 专用预处理逐行读取 |
| --- | --- | --- |
| 首列 `# note`；或纯空白 | 略过 | 略过 |
| 一个 ASCII 空格后接 `# note`（缩进的独立注释） | 不作为物理注释略过；删后变空，节内按非法属性语法拒绝 | 删后为空，略过 |
| `Name = Alpha #Beta` | 按行内删后缀得到 Alpha，再按原 schema 消费 | 同样先删后缀，其余按该专用字段规则 |

普通输入先有完整合法唯一节 A，再有合法唯一节 B，坏缩进注释放在 B 内且此前无错时：B 节头已使 A 完成校验与内存登记，B 尚未交给条目校验/登记，最终整表校验与保存未到。当前表不自动回滚；磁盘删除与异常转换另取决于 §3.2/§3.3 的入口。把同一坏行放在第一个节之前，则先报缺少初始节，不能套用节内非法属性错误。首列井号、纯空白与合法训练家材料中的同一缩进注释是正常对照；不据此声称全部 PBS 读取家族都拒绝，或随附语料实际包含该输入。

**行与属性预处理（先于分词/schema 转换）**：普通分节路径对未被物理行门略过的行作预处理：删除第一个井号 U+0023 及其后缀，再修剪首尾空白，随后识别节头或分离属性名与值。此删注释规则不识别引号边界；普通文本和 `q` 文本都先经过它。合法基础物种节的 `Pokedex = Alpha#Beta` 因而得到图鉴文本 Alpha，无井号的 AlphaBeta 保持 AlphaBeta；普通 `Name = Alpha#Beta` 同样先得到 Alpha。引号包围不能保护井号后缀。翻译文本分节读取使用另一套规则（《本地化》§6.3），不得把这里的行内删注释套到翻译导入。

**分词**：按逗号拆分；含奇数个双引号的分段可能与后续分段合并。去除包围标记有位置条件：只有仍有后续分段供内部检查时，才检查已形成的完整值并可能去标记；末字段不进入该检查。这里每端的标记为一个反斜线 U+005C 加一个双引号 U+0022，共两个真实输入字符（记为 `\"`），不是显示转义。

- 非末字段 `\"PokeBall\",Other` 去除首值包围标记，得到 PokeBall、Other；单值 `\"PokeBall\"` 或末值 `Other,\"PokeBall\"` 保留标记，球标志精确匹配失败。普通 PokeBall 无引号，匹配成功。
- **合并耗尽也不等于去标记**：`Flags` 的完整输入为 `\"Alpha,Beta\"`（没有空白或第三段）时，两个初始分段合成一个值，但已耗尽后续分段，补查也未去掉标记，最终唯一标志仍是完整的 `\"Alpha,Beta\"`。只增加独立尾值 Other，输入 `\"Alpha,Beta\",Other`，首值才在下一次检查去掉标记，最终为 Alpha,Beta 与 Other 两个标志。不得把“合并后两端完整”概括为必然去除。

逐值去除首尾空白；丢弃合并产生的空值。以上位置条件与通用值转换分开。

**记录求值**：按 schema 逐值求值：

- 首字符 `*`：出现该属性时先尝试求值第一组，再判值是否耗尽；重复段长度 >1 时产出分组列表。显式空属性不能统一解释成零元素列表，具体结果由组内必需/可选原子决定。
- 首字符 `^`：可重复属性（多行累加；schema 长度减一）。
- **大写类型字母＝可选**：值为空/nil 时该位为 nil（如 `vevV` 的第四位）。
- `q`：非格式化文本，取用**行预处理、属性分离之后的整条值记录**（如图鉴描述），免除逐 CSV 值的类型转换，并终止该行求值；不能恢复预处理已删除的井号后缀或端部空白。
- 其余按类型字母经值转换求值（《内容身份、注册与 schema》§5.1 模式表：i/u/v/x/f/b/n/s/q/m/e/y）。
- 单值 schema 返回单值，否则返回值数组。

**特性 Flags 的显式空相邻例**：合法且未登记的新特性、schema／查询无覆写，缺值对象未被额外赋予字符串比较能力，其余转换、终检依赖正常时，省略 Flags 得空列表，普通标志查询为否；Flags 给普通文本 Other 得一个正常文本元素，查询 FasterEggHatching 为否。出现 Flags 属性但等号后没有 CSV 值时，重复字符串位置仍求首组，产出含一个缺值元素的列表；该列表不是零元素列表，登记保留它。随后普通标志查询在首个缺值元素的字符串比较处失败，不是跳过该元素或正常返回否。此例不推广到所有字段、所有 Flags 或所有显式空列表。

登记已完成不证明整表保存；终检和保存各自成功才谈档案加载，后续查询失败不自动撤回登记。普通文件读取没有本例的 UI 取消动作，外层编译清理仍按 §3.2／§6。条件孵化投影另要求一个正常蛋原剩2步、除该蛋外仅一个正常非蛋队员带该特性且此前正常：先减至1，随后标志查询失败，尚未额外减步、夹0或孵化；省略 Flags 对照仍为1且正常经过检查。外层事件恢复、最终错误画面和资源释放未知。上述均为静态推导、NOT_EXECUTED；未来保留、拒绝或清理此异常输入属于独立兼容政策。

**枚举求值**分两类来源：固定规则枚举按名称解析；内容类枚举按存在性检查校验，未定义报 "Undefined value {1} in {2}." 并附位置（具体语言模块、常量反射与类名检测的实现方式见审计）。

**属性级规则（分节 → schema 消费 → 校验 → 登记全路径）**：

- **普通重复属性后值覆盖**：同一节内非 `^` 的同名属性出现多次时，**后值覆盖前值**。
- **`^` 属性累加**：标记 `^` 的属性多行出现时**累加为列表**，不覆盖。
- **通用未知属性不被消费**：通用编译循环只按 schema 列出的键求值；语法合法但不在 schema 中的属性**不会被消费，也不触发通用未知字段错误**（不因此报错）。
- **新身份定义、重复身份、未知引用分开**：
  - **新身份定义**：一个合法、此前不存在的身份可正常登记为新记录（存在性检查只拒绝**已登记**的重复身份）。
  - **重复身份**：转换后的身份经该类存在性探测命中时，第二个通用节在登记前被拒绝（"used twice"）；普通同 ID 道具及同三元电话联系人如此。**电话 Default 例外**：以字符串默认键登记而以类型符号探测，两个合法默认节不会因重复而拒绝，后节整条覆盖前节；两节分别只有 Intro A/B 时最终只有 B。终检文本收集与缺联系人消息时的默认消费都以 B 为候选，实际显示仍经当前语言查找。联系人重复失败不自动撤回第一条内存登记。专用入口另按各自规则（如训练家后项覆盖——《内容身份、注册与 schema》§5.2）。
  - **未知引用**：引用不存在的枚举值被通用枚举路径拒绝并提供位置；不能把「新身份未存在」误当成「未知引用」。

**三类复合节头的转换与拒绝**：DungeonParameters、SpeciesMetrics、ShadowPokemon 的首分量、可选正整数次位、省略/空位语义0与外部身份等价关系由《内容身份、注册与 schema》§5.1.2 规定，显式0和未知 Species 先在值/枚举求值阶段拒绝。合法 `[cave_1]` 后接 `[cave,1]` 时，地牢参数专用条目校验先报当前区域cave/版本1重复及位置，反序报区域cave_1/版本0；尚未到通用重复门。Metrics/Shadow 各自合法的 `[RATTATA_1]` 与 `[RATTATA,1]` 别名则在转换后的通用身份探测门拒绝第二节。失败条目未登记，首条内存与其元数据保留，终检和本表保存未到；直接注册覆盖不是这个入口。

这些失败经直接内容编译时，旧本表档案可能仍在，更早内容表的档案可已保存；经已判定编译的启动检查时，预删除及诊断正常返回后的删除只是尝试，Reset/SystemExit 仍原样重抛（§3.2–§3.3）。不承诺回滚内存、全磁盘删除或成功保存。PBS 编译本身没有交互取消；独立指标编辑器正常 No 重载档案，确认改动后 Yes 先存档案再写 PBS，后一步失败不撤回先存档案（WP73-B §7.5），不能把它当 PBS 取消门。

**条目级校验**：每个数据类编译时对转换后的条目做类特定校验（如进化方法必需参数、能力值/IV/等级范围、重复处理），随后全量终检。

#### 4.2.1 单行浮点接受与记录消费边界

单行 `f` 值由十进制数字及最多一个 ASCII 小数点构成，小数点前后都允许无数字；带符号或指数不在此接受域。实际 PBS 属性空文本在分词后缺少首值，不能借低层空字符串转换推成合法属性。

合法基础物种的 Height/Weight 经行预处理→分词→浮点接受→数值转换→尺寸整数化→登记。尺寸存储为十分之一单位，结果 **max(1, round(10x))**，round 为最近整数取整。单点 `.` 转成0并存1；`1.0` 存10；独立的 `-1.0`、`+1.0`、`1e2` 在接受阶段拒绝。基础字段省略采用记录默认1；形态省略继承基础高度/体重 H/W，不能一概取1。普通数据0.7/6.9、编辑器整数尺寸、展示单位与行前井号处理各自保持。

整条属性值先经 CSV 分词，定长记录再只转换规定位置，完成后忽略解析结果中多余尾项；这些尾项不再作字段类型求值，也不因长度过多拒绝。这不保证任意尾部引号/井号无影响，它们仍可影响先行预处理和分词。合格元数据的 Home=3,7,5,8 与 Home=3,7,5,8,junk 都采用前四值，junk 无引号/井号，不进入第五项校验。

有效 NPC 成员已定义后，出现空 Moves 属性仍尝试首个必需招式枚举，因无值拒绝当前训练家；没有完成登记，也未到本训练家表最终保存。省略 Moves 则可通过这一项，正常生成采用等级招式；显式合法招式采用指定列表。`q` 整条值、大写可选位、位置相关引号规则以及作者六列能力映射（WP03 §5.3）不由定长尾项规则改变。

### 4.3 内容依赖（知识依赖，非源码加载顺序）

从 22 项编译调用与 schema 枚举引用可见的内容知识依赖。每条边按**编译解析/校验依赖**（schema 枚举引用，编译时必须有定义）、**调度先后**（仅调用顺序，不构成校验依赖）或**运行期关联**（非编译期关系）分别标注：

| 边 | 性质 |
| --- | --- |
| Type → Move | 编译解析/校验依赖（Move 的 Type 枚举） |
| Move → Item | 编译解析/校验依赖（Item 的 Move 枚举） |
| Type/Move/Item/Ability → Species → Forms | 编译解析/校验依赖（Species 的 Types/Abilities/Moves/Items 枚举，基础与形态属性集不同） |
| Species → Forms → Metrics、ShadowPokemon、RegionalDex、Encounter | 编译解析/校验依赖（形态归属、Shadow 的 Species 引用、图鉴/遭遇的物种引用） |
| TrainerType → Trainer | 编译解析/校验依赖（训练家节的类型引用） |
| TrainerType → PlayerMetadata | 编译解析/校验依赖（TrainerType 枚举） |
| Item → Metadata.StartItemStorage | 编译解析/校验依赖（StartItemStorage 的 Item 枚举列表） |
| 固定规则类 ← 多处 | 编译解析/校验依赖（GenderRatio/GrowthRate/Stat/Nature/Evolution/Weather/Environment/Target/TerrainTag 等被作者内容枚举引用） |
| Item ↔ BerryPlant | **仅运行期关联/调度先后，不是编译枚举依赖**——BerryPlant 的 schema 无 Item 枚举（节名为普通符号、其余数值），其条目/全量校验为空；运行期关联与调度注释不能写成编译校验依赖 |

**被发现输入与后续固定路径读写的交界**：普通发现决定「哪些文本被当作哪类输入」；编译前改写（§5.2）、设施名单显式读取等固定路径操作不受发现结果影响，二者分别取证，不能以前者覆盖后者。

### 4.4 遭遇专用输入的例外

遭遇文本不按通用非负数 schema 统一处理。下列差异属于输入兼容合同；完整遭遇选择与运行触发规则归遭遇规格。

| 层次 | 当前专用行为 |
| --- | --- |
| 地图/版本节头 | 文本按整数前缀转换；无整数前缀得到 0，负值可保留，版本省略取 0。不是严格非负整数格式校验 |
| 遭遇方式的显式概率 | 非空文本也按整数前缀转换；无前缀得到 0，负值可保留。该概率入口不采用槽的严格正整数约束 |
| 同一节首次出现某方式、概率省略/为空 | 使用该方式的默认概率 |
| 同一节再次出现同一方式 | 清空该方式此前的槽；显式非空概率替换旧概率，省略/空概率保留该方式已有概率，不重新恢复默认值 |
| 槽的权重和等级 | 槽行先要求以数字及逗号起始，再按严格正整数格式求值；权重和等级的 0 拒绝，等级上限与最小/最大关系另行校验。负权重行不进入槽行分支，不能把其错误阶段描述为槽内正数检查 |
| 地图×版本节重复 | 仍拒绝；与一个节内重复方式的“换槽、保留概率”不是同一层次 |

例如同一地图版本先写 Land,70 与合法 PIDGEY 槽，再写 Land（省略概率）与合法 RATTATA 槽，最终 Land 概率为 70，槽只有后一条 RATTATA。Land,junk 的概率为 0；这不能推出权重或等级 0 也可接受。

### 4.5 专用条目校验与接受前提

**招式类别×威力**：先完成字段词法转换，再做下表校验，随后登记。前提是唯一新身份、Type 等引用已登记，其余字段合法且警告正常返回；Category 的数字文本拒绝仍发生在本矩阵之前。

| 类别（含省略） | 威力 0 或省略 | 正威力 |
| --- | --- | --- |
| Status 或省略类别 | 正常得到 Status/0 | 拒绝当前条目 |
| Physical / Special | 警告后改为 Status/0，继续登记 | 保持类别/威力 |

Physical+40、Special+40、Status+0 和两字段均省略是正常对照。Status+40 或省略类别而 Power40 都拒绝；当前招式未登记，先前已登记条目不自动回滚，本调用未到招式整表保存。编译类别不保证最终招式效果，战斗时有效类别与公式仍按战斗合同。

**元数据**：编译入口先清全局与玩家两表。全局0的 Home 必须存在并有合法四元格式（首项正整数，后三项非负整数），在该条登记前检查。全部实际传入文件读完后先检查全局0存在，再检查玩家1存在；玩家2不能替代1，也不自动创建缺席记录。0与1可分散在不同文件；玩家自身 Home 可省略。终检及文本处理正常后，先保存全局，再保存玩家，两个文件不构成原子事务。只有0/Home与玩家2时，已登记0/2仍可保留但两类保存尚未调用；仅玩家1时，玩家1可先登记，随后全局0缺席拒绝；0无Home在该条登记前拒绝。此检查不另验证地图几何、朝向枚举、字符资源或媒体。

**地牢图块集文本**：完全缺席 Autotile 整组或 Tile 整组时，在创建该记录时失败，当前条目不完成登记；仅给一个合法 Tile 映射而无 Autotile，或反向仅给 Autotile，均如此。两类各提供合法条目时可通过这一前提；成功建记录后的某布局用途未映射才返回图块0。直接内部输入显式空列表是另一输入，不用它替代 PBS 缺整组的反例。此前条目及外层清理仍按各自失败前缀。

**进化属性合并**：同一有效物种节同时含旧复数 Evolutions 与重复单数 Evolution 时，先采用复数表（同一复数属性重复仍取后值），再追加单数条目，单数组内按自身出现顺序累加；跨拼写文本交错次序不改变这个分组顺序。A先单数到C/Level16，后复数到B/Level16，结果为B、C，条件同时满足时先选B；交换两个拼写的文本先后仍为B、C。只有两个单数B、C时仍按B、C。前向选择与旧复数编辑/单数写出副作用分层见WP31 §3.8、§4.3。

**连接文本**：六分量分别为地图A、端描述A、坐标A、地图B、端描述B、坐标B；端描述可为整数或精确方向 N/North、E/East、S/South、W/West。配对校验由第一端分支决定：N须对S、S须对N、E须对W、W须对E；第一端整数时不执行方向配对校验。故1,0,0,2,W,0可进入待保存记录；1,E,0,2,W,0也通过；1,W,0,2,0,0要求第二端E而拒绝。缺地图警告正常返回时不自动拒绝；编译接受不保证混合记录的运行换算或反写可用。

**训练家文本**：专用读取跳过不成属性/节头形状的普通杂行；合法训练家节内的未知属性不消费。节前任何等号属性先因缺节拒绝，即使键未知；已识别的成员属性（如IV）在本节第一个 Pokemon 定义前拒绝。有效节/成员间插入无等号的 garbage，与删除该行得到相同登记；合法节内未知键可跳过；首成员前IV与节前Unknown=Value不能跳过。无成员、等级、IV/EV终检、重复训练家后覆盖仍各自成立，不扩成全部非法内容都可保存。

## 5. 编译产物与写回行为

**编译会修改材料，不是只读转换。** 当前快照可见的写回面：

### 5.1 数据文件（.dat）

- 启动检查判定编译后、编译开始前：**尝试**逐文件删除全部列出数据文件（删除错误忽略，不保证全部删除）；运行中直接入口没有这次清单预删除。
- 编译中逐类保存新 .dat（各编译函数末尾保存）。
- 动画阶段本次构建存在有效映射条目时保存 move2anim.dat 与战斗动画集（§5.4）；不以磁盘新旧比较为写入门。

### 5.2 PBS 文本改写（编译前）

编译前改写对两处旧属性名自动改名：trainer_types.txt 的 `VictoryME` → `VictoryBGM`，moves.txt 的 `BaseDamage` → `Power`。机制：整文件读入，有变化才整体重写。**这是固定路径操作**（见 §4.3 的交界）。

### 5.3 地图与事件转换

- 对**地图信息中已登记的全部地图**的每个事件尝试：训练家注释转换（`Battle:`/`Type:`/`Name:` 等注释编译为正式训练家事件）、道具事件转换（`item:X`/`hiddenitem:X` 命名转为道具球事件；**道具不存在则跳过不转换，也不报错**）、事件名与脚本修正、计数检查；任一变化即保存该地图与 tilesets，并逐条警告「Map X was modified and saved」。
- 公共事件做修正，有变化才保存。
- 有任何修改时警告「RMXP data was altered. Close RMXP now to ensure changes are applied.」。
- 转换规则全集归事件转换规格；本文件只登记「编译会写回地图/公共事件」的事实与边界。

### 5.4 动画映射

- 读取战斗动画集（**读取失败则新建空动画集**）。
- 扫描名为 `Move:X` / `OppMove:X` 的动画，仅当招式 X 已定义时建立映射；本次存在任一有效条目就保存 move2anim.dat 与战斗动画集，即使关联与旧磁盘相同；零有效条目不保存，旧磁盘映射保留（WP74 §15）。磁盘写入不保证已预载集合/关联失效（§5.6）。

### 5.5 反写（全量写出与通用/专用写出）

**调用者（启动触发与主动导出分开）**：

- 启动触发：PBS 目录缺失时，编译检查先载入全部数据再全量反写（§3.1）。
- 主动导出：调试菜单可直接调用全量写出或单个分步写出——菜单 UX 归调试规格，此处只登记它是真实写入调用者。

**通用写出**：按实际条目的来源后缀分组生成输出路径（无对应条目就没有该路径），写 BOM 头与 `[节名]`＋`键 = 值`（值经记录写出转换，枚举只查已有名称）。**不承诺重建或清理全部旧输入，也不承诺逐字节往返**。

**专用写出（格式不统一为「节名＋键值」）**：连接写出写行式连接数据，并跳过地图已不存在的连接；遭遇写出写遭遇节/方式/槽的专用格式。全量写出共 **22 项内容写出调用**（不含进度输出辅助）。

**区域图鉴反写输入**：单项 regional_dexes 导出及全量反写都通过区域表读取入口取得内容；已有区域缓存时采用该缓存，不强制读取新档案。成功直接编译本身不清此缓存。已预载区域0仅 BULBASAUR、作者合法 PBS 改为仅 IVYSAUR（两物种有效），且全阶段成功、没有独立失效/会话重建/覆写时：编译后的 regional_dexes.dat 为 IVYSAUR，当前区域编号/成员查询仍读 BULBASAUR（前者编号1，IVYSAUR编号0）；随后正常导出把 PBS 写成 BULBASAUR 内容，磁盘档案仍为 IVYSAUR，直到另一次编译改变它。反写不承诺旧 PBS 的原字节复原；目标被打开覆盖后若写入失败可留下部分文本，不回滚已编译档案。

**遭遇概率往返**：只写出有非空槽的方式；概率大于 0 时写方式名及概率，否则只写方式名。合法地图版本的 Land 有合法槽、编辑后概率为 0，且保存与写出均成功时，运行登记和遭遇档案均先保存 0，PBS 却只写 Land。随后成功再编译该 PBS，Land 概率恢复默认 21，运行登记和档案均为 21。OldRod 默认概率为 0，同样省略后再编译仍为 0；正概率 70 则写出并保留 70。此处四阶段不含当前地图的遭遇缓存，缓存刷新另归遭遇/编辑器规格。

**文本反写再读的井号边界**：写出已有含井号文本时，`q` 值直接输出，普通文本的 CSV 包围只按逗号/引号需要生成，不为井号提供保护。若登记中的图鉴文本原为 Alpha#Beta，反写成功后输出仍含该井号，随后成功编译只登记 Alpha；即使有 CSV 包围，后续行预处理仍删除井号及后缀。此例允许登记来自其他有效入口，不假定含井号文本能由 PBS 初次无损建立。所有随附文本的受影响数量及宿主往返仍未验证。

**物种指标写出路径**：档案保存与 PBS 写出是两个步骤。PBS 输出路径只由**写出时全部已登记的非零形态指标记录**的来源后缀决定，基本形态记录自身不会建立路径；已选路径中再写同后缀的记录。非零形态的背面位置、正面位置、正面高度、阴影横移、阴影大小五组均等于写出时基本形态值时，省略该形态节，但已选择的输出路径仍会写出。

| 写出时状态 | PBS 结果（读写成功前提） |
| --- | --- |
| 只有基本形态记录，基本指标由 A 改为 B | 不产生指标 PBS 路径；档案已保存 B，旧 PBS 仍为 A。重载档案取 B，从旧 PBS 成功再编译则恢复 A |
| 有与基本记录同后缀的非零形态记录，五组值相等 | 选择该后缀路径，基本指标写为当前值，非零形态节省略；不是“不写整个文件” |
| 只有不同后缀的非零形态记录 | 只选择该非零形态后缀路径，基本记录所在的其他旧路径不因此改写 |
| 保存前曾查询/预览缺失的非零形态 | 查询可能已登记继承基本指标的形态记录；新记录后缀为空，因而会把默认指标路径加入选择集合。须按保存时登记集合判断，不能按启动时集合判断 |

**物种进化属性写出与编辑读取的区别**：PBS 正式写出使用单数 Evolution，过滤前驱条目，并把需要参数的真实前向进化参数转成文本；该转换可改变运行登记中的参数类型，不回溯修改此前已保存的档案。编辑器属性读取使用复数 Evolutions，该读取给空值并由编辑默认值补空列表；打开父编辑器后选择 No 不触发上述单数写出，也不会仅因读取就把原数值参数变文本。父编辑器 Yes 保存空列表则会清空所选物种的进化条目（含其前驱）；其他物种已有的反向关系未在这一步全局重建，运行登记和先保存的档案可能仍含旧关系，随后从写出的 PBS 全量成功再编译才重建。具体编辑操作与失败边界归内容编辑器规格，不能把这些入口混作一个无损往返。

#### 5.5.1 具名输出条件与再编译状态

各例假定依赖、其余字段、来源后缀、输入读取和输出写入正常；再次编译为独立后续步骤，按要求先重新编译基础物种或清相应表。写出、当前内存、随后再编译后的记录分别观察。

| 入口与已登记状态 | 写出与写出后内存 | 成功再编译或首次拒绝 |
| --- | --- | --- |
| 正式形态导出/全量写出：合法基A Generation1、正形态显式0 | 该形态节仍写，Generation属性省略；当前内存仍0 | 基础先重编译且仍1，形态继承为1 |
| 同基Generation1，形态2 | 写出2；内存仍2 | 仍2 |
| 基A Habitat Grassland，形态None | Habitat省略；内存仍None | 重编译继承Grassland |
| 基/形态同为Grassland，或两者Generation均0 | 属性可省略 | 同基值继承，结果不变 |
| 地图1唯一版本−1；Land概率70及合法非空槽 | 遭遇输出[001]，当前内存版本仍−1 | 无版本节再读为0，原−1身份不存在 |
| 同表版本1 | 输出[001,1] | 仍版本1 |
| 同地图1版本−1及0，同后缀，各有合法槽 | 输出两个[001]，不自动合并 | 第二节头前第一表已以0登记，随后重复地图×版本拒绝；不回滚第一表，未到遭遇档案最终保存 |
| 非重要道具Consumable=false | 显式写出false，覆写通用false省略 | 再读仍不消耗 |
| 同非重要道具Consumable=true | 可省略 | 缺省true，仍消耗 |
| 重要道具，原消费位真/假各例 | 该属性可不写 | 有效消费恒假，不为保存未生效原位要求不同文本 |

形态导出的实际入口是调试分步 pokemon_forms 导出或全量写出；普通物种编辑器保存只直接写基础物种，不能用它证明形态输出。上述Generation/Habitat写出本身不改这两个内存字段。既有指标路径、概率非正值省略、进化参数写出及井号损失是不同条件，仍分别成立。

**电话联系人节头**采用类型、原名及仅正版本的逗号连接文本，整条节头按 `q` 写出，不保护姓名里的逗号。作者可用“类型CAMPER、两端各为U+005C后接U+0022的姓名A,2、独立版本0”建立合法三元联系人；这两个端部标记各有两个真实字符，姓名处于非末字段，不能以普通引号必被剥离替代这个前提。正式写出后节头为[CAMPER,A,2]，原内存仍是姓名A,2/版本0；成功再编译则为姓名A/版本2。姓名A无逗号/版本0时省略版本仍同身份。姓名A,B/版本0以相同标记建立后，写出[CAMPER,A,B]，再编译在版本非负整数求值处拒绝，不自动补引号或复原原名。电话运行当前版本→初始版本→默认集仍按原合同，只是消费新编译得到的身份。

### 5.6 磁盘产物与同会话缓存

全量内容阶段的文件保存不自动使既有缓存失效；必须分别观察磁盘、当前读取对象和后续反写。以下限定无外部失效/扩展覆写、相关生产步骤成功：

| 已预载内容 | 直接全量编译后的当前读取 | 另一个有明确前提的入口 |
| --- | --- | --- |
| 区域图鉴表 | 保留旧缓存；编号、成员及区域 PBS 反写继续消费旧表（§5.5） | 编译前缓存尚未建立时，编译后首次读取载入新档案；地区图鉴编辑器总保存 Yes 先写档案、明确清该缓存再反写 |
| 战斗动画集合与招式关联 | 各自保留旧缓存；编译可从磁盘读动画并更新磁盘关联/集合，播放读取仍可取得预载旧对象 | 游戏初始化重新建立临时会话数据，后续读取按各自文件门取得内容；集合清空与关联清空是不同状态，编辑器只清集合的入口不扩大为两者全清 |
| 地图连接 | 连接档案可已更新，预载的连接/尺寸缓存仍保留；连接查询继续采用旧缓存 | 明确连接缓存清理或新进程才具备重载前提；同进程仅重建临时会话数据不清这一独立缓存 |

全局数据清理的定义另有区域、动画集合、关联、地图信息与连接的具名清理及遭遇重装动作，但全量编译和普通菜单分派没有接上该清理。新地图导入只明确清地图信息缓存。Reload system cache 只请求宿主文件缓存重载，不能据此补区域/动画/连接对象失效保证；隐藏宿主副作用未执行核验。既有遭遇快照装配与指标显示布局合同保持各自消费者前提，不从编译成功推导统一刷新。

## 6. 失败与部分状态

**不能默认原子性或自动恢复。**

| 阶段 | 可能已发生的变化 |
| --- | --- |
| 启动检查·编译前 | 尝试逐文件删除全部列出数据文件（不保证全部删除，§3.2）；直接入口无此清单删除（§3.3） |
| 编译中 | 部分 .dat 已重写；PBS 可能已被改名改写（§5.2）；MapInfos 可能已登记新地图（§3.1）；地图/公共事件可能已转换保存（§5.3）；动画映射可能已保存（§5.4） |
| 启动检查·异常时 | Reset/SystemExit 原样重抛（无清理）；其他异常打印后**尝试**再次删除数据文件（不保证全部删除）；Hangup 转 Reset，其余转通用错误（§3.2） |
| 启动检查·早期失败（PBS 缺失分支） | 清理分支面对尚未建立的清单，完整清理预期不成立（§3.2） |
| 直接入口·异常时 | 已保存的新产物、当前表登记前缀与未保存表的旧磁盘产物可以并存；不执行启动局部清理/转换，完成消息与后续清理未必到达（§3.3） |
| 失败后 | 可能存在：缺失的数据文件、部分编译的 .dat、已改写的 PBS/地图/MapInfos/动画。下次调试启动时，缺失的必选文件再次触发重编译（§3.1），但**不保证**上次失败留下的部分状态被识别或修复 |

错误定位：编译错误附位置报告（文件/节/键/行号），位置数据在编译主流程开始时重置。

## 8. 默认行为与配置变体

- **基线默认**：调试模式自动检查编译；`PROMPT_TO_COMPILE = false`（启动不询问）；Ctrl 可强制；PBS 缺失自动从数据全量反写再编译。
- **支持但未默认启用**：`PROMPT_TO_COMPILE = true` 启动询问（拒绝不否决自动条件）；外部全量编译标志；调试菜单主动导出全量/分步写出。
- **配置/数据关联**：`MECHANICS_GENERATION` 与数据集的组合边界（U03）、可选 Shadow 数据的启用（U06）保持开放。
- **未验证组合**：完整失败分支、全部转换规则组合、无 PBS 往返的真实结果、插件对编译的影响（U09）。
- 参考快照行为、官方版本预期、未来目标分开标记；本文件只记录第一类。
