# 通知、扩展与插件（净化正文；批次 4）

分类：Generic Kernel（扩展机制）。本文件描述扩展行为约束——通知（事件订阅）、可扩展菜单和插件载入各自支持什么、按什么顺序、在什么条件下生效、失败时发生什么。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的与范围

**目的**：回答「某行为能否被扩展/覆盖/拦截」，供后续规格引用，而不追踪任何特定扩展机制的实现结构。

**范围**：① 通知机制（事件订阅原语、命名事件注册表、内容处理器表）；② 菜单扩展（选项注册、排序、可用条件、调用）；③ 插件元数据与依赖（格式、注册校验、依赖/冲突/循环处理、版本比较）；④ 插件载入（源码发现、编译、预编译产物消费、版本兼容）；⑤ 失败与边界（错误致命性、发布模式、无插件样本）。

**非目标**：不设计任何未来事件总线、菜单系统或插件 API；不提取各事件/菜单项的具体业务行为（归相应领域规格）；不验证真实插件组合（当前快照无插件样本，U09）；不重复定义错误/诊断机制（归《诊断、文件与 HTTP》，本文件引用）。

## 2. 概念与术语

- **通知（事件订阅）**：命名的游戏事件（如进入地图、玩家迈步、战斗开始/结束）允许注册回调，在事件发生时被依次调用。
- **内容处理器表**：按内容身份（物种/特性/道具/招式）登记处理逻辑的表，支持精确匹配与条件回退。
- **可扩展菜单**：菜单选项以数据注册（名称、排序、可用条件、效果），菜单本身按注册数据生成。
- **插件**：插件目录下带 `meta.txt` 的脚本包；经依赖排序、编译、按序执行。
- **依赖/冲突/循环**：插件声明的 Requires/Exact/Optional/Conflicts 关系及其校验。
- **三阶段**：插件的源码发现、编译（生成预编译产物 `Data/PluginScripts.rxdata`）与预编译产物消费（读取/注册/执行）——三者的前提条件不同。

## 3. 通知机制

### 3.1 事件订阅原语

| 原语 | 行为 |
| --- | --- |
| 回调列表（无序名） | 支持替换全部回调、添加（**已存在则不重复添加**）、移除、清空；触发时依次调用全部回调：**仅当回调声明的参数个数大于 2 且与触发参数个数相等时传完整参数**；否则恒传（发送者, 其余参数数组）——两参数回调收到的是后者，不是「个数匹配即完整传参」；另有恒传完整参数的触发入口 |
| 命名回调表 | 按键登记/移除回调；**同键再登记则替换**；触发时依次调用全部回调（完整参数） |
| 身份处理器表 | 登记时**先**校验处理器形态（非过程/哈希/块则抛出参数错误），**再**按身份登记（空身份被忽略）；**同键再登记则替换**；查找未中返回空；支持把处理器复制到其他身份；触发时返回处理器的返回值（无处理器为空） |
| 符号处理器表（内容用） | 注册侧**没有「仅符号身份」的校验**：接受任意真值键；查找时非符号且可换算身份的对象取其身份，其余值按原样匹配；条件回退登记（精确未中时按登记顺序尝试条件处理器）；触发时把**按上述规则归一化后的键**作为首参传入（**类型不保证为符号**——字符串键登记并触发时首参仍为该字符串） |
| 内容专用表 | 物种/特性/道具/招式四类内容的效果各有独立处理器表（空特化，行为同上；效果族归战斗领域规格） |

### 3.2 命名事件注册表

- 按「事件名＋回调键」注册（同键替换）；可按键移除/清空；按事件名触发时调用该事件全部回调（事件未定义时不报错、无效果）。
- 文档化事件集（当前快照）：地图设置/进入/离开、每帧更新、玩家转向/迈步/可转移迈步/互动、训练家载入、野生物种选择/个体创建/战斗呼叫/战斗开始/战斗结束/野生战斗结束。
- 静态统计：注册点与触发点的全部文本命中均在文档化事件集内，未发现临时新事件名（统计口径见审计）。注意形似属性（如进化数据的「交换时回调」字段）不是本注册表的事件。
- 典型约定：迈步效果按命名键订阅（如亲密增长）；「可转移迈步」事件的消费者通过共享数组约定「已发生转移则跳过」。

## 4. 菜单扩展

- 为指定菜单注册选项（**同键替换**，选项表即身份处理器表）。选项数据（经样本核实）：`"name"`（显示名，可翻译或过程动态生成）、`"order"`（排序值）、`"condition"`（可用条件过程，返回假则不显示）、`"effect"`（选择效果过程）；其他函数键可经统一调用入口按名调用。
- 可用选项枚举：按 `order` 排序（缺省按注册序号），过滤条件不满足的选项，依次产出（选项, 数据, 显示名）。
- 静态统计：注册调用覆盖暂停菜单、队伍菜单、Pokégear、选项、PC、调试菜单族（调试族占多数）；菜单内容由注册数据驱动，插件可增删选项。
- 与地图事件解释器的关系：菜单扩展是独立机制，不等于事件命令扩展（归《地图事件、NPC 与跟随》）。

## 5. 插件元数据与依赖

### 5.1 meta.txt 与注册

- 每个插件目录须含 `meta.txt`（无则目录被忽略）。注释列出的推荐/必需字段（Name、Version、Essentials、Link、Credits）与**实际强制条件**分开记录：

| 阶段 | 强制校验 | 非强制/警告 |
| --- | --- | --- |
| 发现（读取全部目录的插件顺序） | 缺 Name 报错、重名报错；解析后的脚本列表缺失/空值 nil/假值 false 时防御报错，空列表合法 | — |
| 解析（读取单个 meta.txt） | 行语法错误报错 | 无 meta.txt 目录被忽略；Exact/Optional 依赖缺版本被忽略（不报错） |
| 注册 | 空 Name/Version/Link 报错（仅当**提供了**对应键）；依赖不满足报错；冲突报错；重名报错 | **未提供的键不校验**——缺 Essentials 仅执行阶段警告、缺 Link/Credits 不报错（缺键 ≠ 显式空值） |

- **Scripts 的归一化**：解析先为缺失/假值的脚本列表提供默认空列表，再追加自动候选；发现阶段防御检查的是**解析后列表值缺失、nil 或 false**，不是列表长度。故省略 Scripts 行且无自动候选时得到空列表，仍是合法插件；与整个预编译产物无插件条目分开。
- **自动候选的路径条件**：递归收集到的完整文件路径**包含区分大小写的子串 .rb** 就入选，不要求扩展名恰为 .rb。因此 old.rb.bak 入选；普通路径的 readme.txt 与只有 .RB 的路径不入选；目录名含 .rb 时，该目录下 readme.txt 也入选。显式 Scripts 路径不以此自动条件筛除。
- **同一插件内的顺序与去重**：显式 Scripts 路径按声明顺序排在前面，自动候选按递归收集顺序追加（每层路径排序，本层文件先于子目录递归文件），合并列表按相同路径文本保留首次出现。显式 b.rb,a.rb 保持 b.rb 在前；自动再次发现 a.rb、b.rb 不使它们重复或重新排序。路径字符串不同的别名不据此承诺去重。
- **依赖形式**：Requires（任意/最低版本）、Exact（精确版本）、Optional（存在则最低版本）、**OptionalExact（精确＋存在性）——meta.txt 的 Requires 第三分量可表达**（解析把第三分量识别为依赖类型，注册按「可选精确」处理）；源码注释所称「meta.txt 无法表达」与这条实际入口不一致，以实际入口为准。
- **版本比较器**：逐字符位置比较（按 16 进制字符值，前导点补 0、末尾点去掉）：**不是分段数值比较**——`"1.10"` 与 `"1.9"` 的第三位 1 < 9，结果为 **1.10 < 1.9**（不是通常版本习惯的 1.10 > 1.9）。依赖最低版本判断以此为据，不能套用通常版本习惯。
- **错误处理**：注册期错误输出「Plugin Error」到控制台与标准输出后**直接终止进程**——注册期错误一律终止，不进入后续加载。

### 5.2 依赖排序与循环

- 依赖校验：递归检测依赖环，成环报错（终止）。
- 最低版本不足时，错误报告已装版本并终止；只有该已装依赖登记了有效 Link，才追加其更新链接。缺 Link 是允许的，不补造链接。
- 载入排序：按依赖关系交换排序（依赖先于使用方）；缺失非 Optional 依赖报错；Optional 依赖缺失可跳过。
- 插件顺序确定：读取全部插件目录的 meta，校验必需字段与重名，再验证依赖、排序。

## 6. 插件载入（三阶段）

### 6.1 阶段一：源码发现

- 仅调试模式、非发布包（无打包归档）、插件目录存在时返回插件目录列表。
- 无插件目录或目录中无 meta.txt：发现阶段为空，**不等于**没有插件（可能已有预编译产物，见阶段三）。

### 6.2 阶段二：编译

- 以调试模式＋非发布包为前提；满足任一即编译：全量编译标志、预编译产物缺失、按住 SHIFT/CTRL、任一脚本或 meta.txt 新于产物。
- 编译：先按依赖排序处理插件，再按各插件上述脚本列表顺序写入预编译产物 `Data/PluginScripts.rxdata`；不另按脚本名重排。

### 6.3 阶段三：预编译产物消费

- 启动顺序：核心消息 → **插件** → 编译检查 → 初始化。产物消费**没有**调试/发布包的提前返回——**发布模式仍会读取预编译产物，对其中条目注册并执行**。
  1. 需要则先编译（阶段二前提不满足时不编译，直接读产物）。
  2. 读取产物（**空产物与读取失败分别对待**：产物为空走「未发现插件」；读取失败按宿主读取行为，未验证）。
  3. 插件的 Essentials 兼容列表不含当前版本时**警告但照常加载**。
  4. 逐插件注册（依赖/冲突校验在此生效）。
  5. 按产物内脚本顺序逐脚本以插件标记的文件名求值执行；**任一脚本异常 → 格式化错误后终止进程**。因此成功消费显式 b.rb,a.rb 的候选时先执行 b.rb，再执行 a.rb（前脚本异常会阻止后续）。
- 插件运行**早于**编译检查：插件可能先修改数据/规则，随后编译检查再处理（《PBS 生命周期》引用）。
- 发布边界：注释建议发布时删除插件源目录；但**删除源目录不等于禁用产物**——预编译产物在发布模式仍被消费。

## 7. 失败与边界

| 失败/边界 | 行为 |
| --- | --- |
| 注册期错误（字段、依赖、冲突、循环、重名） | 输出错误并直接终止进程 |
| 载入期脚本异常 | 格式化异常、追加写入错误日志、打印（可按 Ctrl 复制），随后终止进程 |
| Essentials 版本不匹配 | 仅警告，照常加载 |
| 无插件目录/无 meta.txt | 跳过对应插件（源发现为空，不证明无插件） |
| 预编译产物为空 | 走「未发现插件」，正常继续 |
| 预编译产物读取失败 | 按宿主读取行为，**未验证** |
| 真实插件组合 | **当前快照无插件样本（U09 保持开放）**；静态检查器行为不证明真实组合有效 |

错误与诊断的共用面（错误日志写入、控制台输出）归《诊断、文件与 HTTP》，本文件引用，不重复定义两套错误机制。

## 8. 默认行为与配置变体

- **基线默认**：调试模式下自动发现、按需编译、按序加载插件；版本不匹配仅警告；无插件时正常启动。
- **支持但未默认启用**：全量编译标志强制编译；SHIFT/CTRL 手动触发编译；调试菜单主动导出（《PBS 生命周期》登记）。
- **未验证组合**：真实插件组合、插件对编译/数据的影响（U09）、发布包行为（无打包归档材料）、预编译产物读取失败的行为。
- 参考快照行为、官方版本预期、未来目标分开标记；本文件只记录第一类。
