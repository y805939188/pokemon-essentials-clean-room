# 规则配置档案与数据变体（净化正文；批次 2）

分类：Generic Kernel（配置机制；部分内容跨 Pokémon 规则、宿主集成、UI 与作者配置）。本文件描述参考快照提供哪些影响行为的配置项、各自的默认值、哪些派生于机制世代、哪些需要作者手动选择，以及哪些配置/数据组合尚未验证。设置键名属于**配置/数据标识**（作者可修改的输入）；键名与默认值不是任何未来框架的公开 API。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的与范围

**目的**：建立可审计的规则配置档案——配置项集合、声明的默认值、派生关系、候选数据材料与手动选择边界。后续各领域规格据此定位其规则受哪些配置影响。

**范围**：① 配置体系总览（定义点、世代基准、直接世代引用）；② 配置词典（全部定义的默认值、派生方式、行为语义、影响域）；③ 派生关系分析；④ 候选数据与手动选择；⑤ 未验证组合表。

**非目标**：不提取各开关在具体规则中的完整语义（归相应领域规格）；不描述字段 schema 或完整编译生命周期（见同批《内容身份、注册与 schema》《PBS 生命周期》）；不验证任何配置组合的实际运行结果；不把备份目录的存在当作变体已受支持的证明；不比对官方版本的设置差异（U02 保持开放）。

## 2. 概念与统计单位

- **独立常量**：配置命名空间内单个常量定义。
- **方法型配置**：以方法形式定义的配置项（调用形式与常量不同；本档案只保留已证的配置内容与提供行为，不凭「方法」一词补造动态求值合同——源方法组织见审计）。
- **元信息**：引擎命名空间常量（版本标记等），不混入配置统计。
- **独立设置 / 世代派生设置 / 设置间派生**：默认值表达式是否引用机制世代或另一设置。派生只发生在**默认值计算**层面；作者把某条派生设置改写字面量后，该条即脱离联动（配置注释明确允许逐条修改）。
- **直接世代引用**：消费者不经派生设置、直接引用世代值的位置（其存在与作用为行为规则；命中统计与检索方法属审计证据，见追溯索引，不进入正文）。
- **候选变体材料**：快照中存在、但未被默认发现路径纳入的备选内容（本快照为数据备份目录）。

## 3. 配置体系总览

| 事实 | 内容 |
| --- | --- |
| 设置定义点 | 配置项的显式定义集中于**主设置与战斗设置**两个数据文件（定义点限定：覆盖固定快照与已搜索的声明形式，不排除插件、动态定义或其他配置体系——当前快照无插件内容，U09） |
| 配置规模 | **118 个常量**（主设置 88＋战斗设置 30）＋**3 个方法型配置**（片尾名单、背包口袋名、图鉴名）＋引擎元信息 3 条单列（枚举计数为档案自身清单口径；检索类统计见审计） |
| 世代基准 | **机制世代＝8**；配置注释声明各世代非精确复刻、仅第五世代及以后「较合理支持」 |
| 派生规模 | **世代派生 47 条**（主设置 25＋战斗设置 22；含数值型 6 条）、**设置间派生 1 条**（亲密度软上限跟随亲密效果开关），其余 70 条常量独立 |
| 直接世代引用 | 存在不经派生设置、直接引用世代值的消费位置（规模与逐文件/行定位属审计，见追溯索引）。限定：含直接引用的路径可能同时受其他设置影响；同一文件可含多个判断，**文件/行计数不等于独立分支数** |
| 行为决定因素 | 设置文件确定**声明的默认值**；当前全部行为还取决于消费者、数据、运行状态、游戏开关与玩家选项（如语言、捕获替换选项），不能只从设置文本推断 |

## 4. 配置词典

说明：

- 词典行可合并多个常量（如徽章加成 5 常量合并 1 行）；逐定义对照（含行号与复算口径）见追溯索引。
- 「默认值」指**当前快照在机制世代＝8 下的取值**；派生条目的取值随世代改变，标注阈值。
- 语义为行为层面简述；完整规则归相应领域规格。内容定义类（名单、文本、图形名）只登记存在与用途，不展开、不复制内容。

## 5. 派生关系分析

1. **世代派生 47 条**，阈值分组（复算自逐定义清单）：≥4：7 条；≥5：1 条；≥6：11 条；≥7：9 条；≥8：10 条；≤3：1 条；≤4：1 条；≤5：2 条；≤6：2 条；≤7：1 条；＝＝5：1 条；＝＝5 或 ≥7：1 条。其中数值型 6 条（SHINY_POKEMON_CHANCE、NUM_BADGES_BOOST 五项），其余 41 条为布尔型（分组计数为档案清单口径，复算方式见审计）。
2. **设置间派生 1 条**：APPLY_HAPPINESS_SOFT_CAP 默认跟随 AFFECTION_EFFECTS。注释说明关联理由（亲密效果在 179 以上生效）；作者可分离设置。
3. **模式选择 1 组**：FIELD_MOVES_COUNT_BADGES 决定 BADGE_FOR_* 八个设置的语义（徽章数量 vs 特定徽章），两组设置必须配套解读（场景例见测试目录 KC03）。
4. **派生仅是默认值**：派生设置在作者改写为字面量后脱离世代联动；世代基准本身独立。因此**声明的默认配置**由设置文件最终文本确定，不由世代数字单独决定；但具体行为仍需消费者、数据、状态和其他选项共同决定。
5. **直接世代引用不受派生覆盖**：存在不经派生设置的直接世代引用（规模与定位见审计）。即使作者把全部 47 条派生设置改为同一取值，这些直接引用仍按世代值变化。且含直接引用的行为路径可能同时受其他设置影响——「世代派生」不是该路径的唯一输入。
6. **组合状态**：本档案只登记表达式与默认值；任何「世代 X 下行为如何」的组合结论待相应领域规格与一致性核对，不宣称跨世代兼容（U03）。

## 6. 候选数据与手动选择

### 6.1 普通输入发现机制及其边界（作者输入/编译发现层面）

- 各数据类声明基名；发现函数在数据目录内枚举**顶层**文本文件（**不递归子目录**）。
- 匹配规则：文件名基名与数据类基名**完全相等**，或以「基名＋下划线」开头（如 `items_shadow_pkmn.txt` 按基名 `items` 匹配）。候选基名按**最长基名优先**排序后逐一匹配，先匹配成功即归属（影响多基名数据类的归属结果）。
- 内容编译调用共 **22 项**（调度顺序，不等于内容依赖关系，也不等于完整编译生命周期——见同批《PBS 生命周期》）。

**边界与例外**：

- 普通发现函数**不是**编译输入的唯一来源。设施名单编译流程读取名单文件各节的训练家/个体字段，并**显式读取字段指定的其他输入文件**：当前名单共 1 个默认训练家名单与 4 个训练家名单节，去重后引用 10 个输入路径（battle_tower 系列 2 个、cup 系列 8 个，均存在于数据目录顶层）；逐一核对它们不满足普通发现的匹配规则，不经普通发现进入编译。另有 2 个候选文件存在于数据目录顶层但未被当前名单引用（cup_fancy 非 _single 两文件，用途未调查）。引用集合与目录存在集合的区分及逐节清单见追溯索引；完整专用读取路径归《PBS 生命周期》。
- 不能据普通函数不递归子目录，就证明所有专用读取路径绝不访问子路径；也不能把它当成备份切换的完整性证明。
- 不匹配普通发现的文件**仍可能**经显式引用进入编译（如上例）；「不匹配即不进入」的概括不成立。

### 6.3 语言数据：作者配置与玩家选择

- **作者配置**：LANGUAGES 定义语言候选列表（每条＝显示名＋数据文件名片段，对应消息数据文件）；默认为空（不提供候选）。
- **玩家选择**（已核实的消费入口）：启动流程在候选 ≥ 2 且无存档时提供语言选择；载入界面在候选 ≥ 2 时显示语言菜单；选择保存在玩家系统选项中，文本资源按所选片段加载。
- **翻译提取的目标语言**：调试菜单的语言选择只决定提取目标目录及译文目标，随后另选游戏文本或核心文本；该选择不改当前玩家语言，也不重新加载当前消息资源。例如当前语言为 A，选择提取到 B 后在文本类别选择处取消，当前语言和消息资源仍为 A。
- **边界**：完整本地化与 UI 流程归相应领域规格；选项界面中的 LANGUAGES 命中为注释性引用，不计为使用点。
- **内容定义类设置**（RIVAL_NAMES、ROAMING_AREAS/SPECIES、REGION_MAP_EXTRAS、pokedex_names、bag_pocket_names、窗口皮肤清单、NO_SIGNPOSTS、DEXES_WITH_OFFSETS）：介于配置与内容之间，属于作者内容而非机制变体；语义归相应领域规格。
