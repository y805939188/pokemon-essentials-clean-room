# 保存、启动、新游戏与继续（净化正文；批次 4）

分类：Generic Kernel（持久化机制）＋ Engine/Overworld（启动与地图恢复）。本文件建立持久状态目录和启动阶段/新游戏/继续的状态规则——在何时读取、保留、初始化、重置、写入哪些状态。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的与范围

**目的**：回答「某状态是否持久、何时生效、新游戏后保留什么」，供后续规格引用，而不追踪任何特定保存系统的实现。

**范围**：① 持久值登记目录（登记项、形态、校验、默认/初始化、读取时机）；② 启动阶段与新游戏/继续（状态阶段、上游顺序、无存档与调试入口、地图恢复）；③ 保存路径与写入边界（成功路径、前置、内存与磁盘边界、失败形式）；④ 设置与进度的区分。

**非目标**：不提取保存文件的二进制格式与旧格式迁移细则（《迁移、失败与恢复》，本文件只登记交界）；不提取各保存值字段的领域语义（如玩家/背包/储存的字段，归相应领域规格）；不提取备份/紧急保存/恢复的全部失败分支（《迁移、失败与恢复》）；不宣称完整 Demo 启动成功（缺失地图/事件材料）。

## 2. 概念与术语

- **持久值**：一个被登记为保存内容的状态单元，具有保存/读取/新游戏值/类型校验/启动读取/新游戏重置等配置。
- **启动读取**：启动时即读取的值（在标题/选择之前就需要）。
- **新游戏值**：无存档或新游戏时用于初始化的值。
- **新游戏重置**：即使已加载，新游戏时也强制重置为初始值。
- **设置（选项）**：玩家的偏好（如语言、文本速度），与游戏进度状态分开。

## 3. 持久值登记目录

### 3.1 登记机制

每个持久值按以下配置登记：

| 配置 | 行为 |
| --- | --- |
| 保存取值（必需） | 保存时取什么值（缺则登记报错） |
| 读取恢复（必需） | 读取时如何恢复（缺则登记报错） |
| 新游戏值（可选） | 无存档或新游戏时的初始化值（无存档键时用它） |
| 类型约束 | 保存/读取时校验值的类型，不符抛**持久值类型错误** |
| 启动读取 | 启动早期即读取（标题/选择之前） |
| 新游戏重置 | 已加载值在新游戏时也强制重置 |
| 旧格式转换入口 | 从旧格式存档取值的转换入口（迁移归《迁移、失败与恢复》；**当前 17 项均未配置**） |

读取规则：

- **有效性校验**：逐值校验类型，**不因为有新游戏值就容忍缺键**——缺键即无效（与「键存在但值类型错」是不同情况）。**限定范围**：该结论适用于当前默认 17 项均配置类型约束的情形（缺失项以空值参与类型检查）；未配置类型约束的登记项没有独立必需键保证，不能外推到未绑定类型的扩展登记。
- **加载遍历**：存档有键则读取；**无键且有新游戏值则用新游戏值**；**键存在但类型错误**抛持久值类型错误（与缺键默认分支不同）。
- 已加载标记：只跳过已加载值；「标记为未加载」把「非启动读取或需重置」的值标记为未加载。
- **新游戏初始化**只作用于「有新游戏值且（未加载或要求重置）」的登记项，不是所有登记项。

## 4. 启动阶段与新游戏/继续

### 4.1 启动阶段表

| 阶段 | 行为 |
| --- | --- |
| 上游准备 | 核心消息加载 → 插件 → 编译检查 → 游戏初始化 → **系统设置**（读取并加载启动值，错误可能在此中断，不到达备份界面，《迁移、失败与恢复》引用） → 标题场景 |
| 启动读取 | 存档存在时先读取启动读取值（game_system、pokemon_system、essentials_version、game_version、stats）；无存档时以新游戏值初始化这些启动值 |
| 标题/载入界面 | **普通无存档路径仍构建菜单**（已读数据非空时首项「继续」，另有新游戏、选项、语言（候选 ≥2）、调试（调试模式）、退出）；**仅当调试模式＋无打包归档＋`SKIP_CONTINUE_SCREEN` 三者同时成立时**，才跳过菜单：已读存档数据为空 → 新游戏；已读数据有效且非空 → 继续载入。三门只决定是否跳菜单，不决定清空进度；不能永久等同文件存在性与已读数据是否非空（旧序列转空表边界见《迁移、失败与恢复》§3.3） |
| 新游戏 | 加载新游戏值（有新游戏值且未加载或要求重置的值取新游戏值）→ 设游戏时间锚点 → 会话数加 1 → 建地图容器与玩家位置 → 进入地图场景 |
| 继续（读档） | 加载全部未加载值 → 设游戏时间锚点 → 会话数加 1 → 恢复地图 → 进入地图场景 |
| 地图恢复 | **magic_number 不一致或 safesave 为真时重新设置地图**（缺地图时：调试给选图入口（取消则退出，选择后设图与坐标），非调试抛「地图未找到，无法继续」）；**两者都不成立才按地图变更恢复**；此后当前地图的事件集合缺失（空值）时抛「地图损坏，游戏无法继续」。集合存在但零条目不触发该损坏守卫；通过该守卫不等于后续恢复/完整启动成功（与缺图是不同错误） |

### 4.2 设置与进度的区分

- **设置（pokemon_system）**：玩家选项（语言、文本速度、选项配置）——启动读取，**新游戏时也读取保留**（不属于进度，不随新游戏重置）。
- **进度（其余各值）**：玩家、背包、储存、开关/变量、地图、统计等——按上表的新游戏值/重置规则处理；**game_system 是启动已加载、非强制重置的值，与 pokemon_system 一样可能保留**（不能把所有非选项对象统一为「新游戏重置的进度」）；stats 启动读取但**新游戏强制重置**（重建后会话数又加 1，完成时为 1，《时间、随机、计步与统计》对齐）。
- **版本（essentials_version、game_version）**：随存档保存的引擎/游戏版本，启动读取，供版本兼容判断（迁移归《迁移、失败与恢复》）；启动加载的状态与保存时读取当前常量是两种形态，分别记录。
- 语言属于设置（《本地化》引用）：新游戏不重置语言选择；具体选项集合的语义归选项界面规格。

## 5. 保存路径与写入边界

### 5.1 保存成功路径与前后状态

| 阶段 | 内存状态变化 | 磁盘状态 |
| --- | --- | --- |
| 保存前 | 设 safesave 标志；save_count 加 1；magic_number 设为系统数据的 magic_number；写入最近保存时刻（当前游戏时间，可能经游戏时间锚点刷新，《时间、随机、计步与统计》对齐） | 未触及 |
| 取值/校验 | 汇编保存数据：全部持久值的保存取值并校验（类型约束不符抛**持久值类型错误**——**不在 IO/系统调用错误捕获集合内，save_count 不回退**） | 未触及（此阶段尚未打开文件） |
| 打开/序列化 | 以覆盖模式打开后序列化写入 | 打开即截断旧文件（覆盖模式） |
| 成功后 | 帧计时重置 | 新存档文件 |
| IO/系统调用错误分支 | **仅回退 save_count（减 1）** 并返回失败——safesave、magic_number、最近保存时刻、锚点等**均不回退** | 文件状态未验证（可能部分写入/截断） |

路径选择：默认保存路径为宿主数据目录下的 `Game.rxdata`（该目录存在时），否则当前目录 `Game.rxdata`；也可传入自定义路径（调用方决定，与默认路径是两种写入目标）。

### 5.2 其他写档路径（各自责任，不暗示都经过正常保存）

- **语言菜单直写**：已有存档时切换语言把选项写入存档数据并直接写回（《本地化》引用）。
- **转换读取写回**：读取存档后若发生转换则把结果重新写回（《迁移、失败与恢复》引用）。
- **删除存档**：删除存档与 `.bak` 备份。

### 5.3 无存档/损坏/备份（启动侧事实）

- 无存档：存档数据为空表；普通路径仍显示菜单（§4.1）。
- 存档无效（有效性校验为假）：有 `.bak` 备份时提示「存档损坏，将载入备份」并读备份；无备份时询问是否删除存档并重新开始。完整失败/恢复规则归《迁移、失败与恢复》。

## 6. 默认行为与配置变体

- **基线默认**：启动读取五类启动值；有存档显示继续选项；保存按 §5.1 路径；设置与进度分开。
- **支持但未默认启用**：`SKIP_CONTINUE_SCREEN`（调试＋非归档＋配置三者同时成立时跳过菜单，直接新游戏/继续）；`.bak` 备份恢复路径。
- **配置/数据关联**：`GAME_VERSION`/引擎版本随存档保存（版本兼容输入，《迁移、失败与恢复》）；`MECHANICS_GENERATION` 与数据集组合对存档兼容的影响（U02/U03）。
- **未验证组合**：部分写入后的文件状态、备份恢复的真实路径、地图损坏分支、完整 Demo 启动（缺失地图/事件材料）。
- 参考快照行为、官方版本预期、未来目标分开标记；本文件只记录第一类。

## 7. 边界、失败与未知

- 保存写入失败（IO/系统调用错误）：仅 save_count 回退并返回失败；其余内存变更不回退（§5.1）；文件状态未验证（可能部分写入）。
- 保存校验失败（持久值类型错误）：不在 IO/系统调用错误捕获集合内，save_count 不回退；此阶段尚未打开文件（§5.1）。
- 存档无效：备份恢复或删除重开（§5.3）；无备份时的删除确认流程（删除动作本身捕获系统调用错误并提示失败，《迁移、失败与恢复》引用）。
- 地图损坏（事件集合缺失/空值）：抛错无法继续；存在且零条目的集合不命中该守卫（与缺图不同，§4.1）。
- 读取时写回：转换后存档被重写（§5.2，《迁移、失败与恢复》）。
- 完整 Demo 启动流程未验证（缺失地图/事件材料，U01）。
