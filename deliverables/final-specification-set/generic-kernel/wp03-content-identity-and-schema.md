# 内容身份、注册与 schema（净化正文；批次 2）

分类：Generic Kernel（身份/注册/schema 机制；内容本身多为 Pokémon 数据）。本文件建立跨域统一的内容引用概念——各类内容（物种、招式、道具、地图等）以什么身份被注册、查找、枚举和引用；未知或重复身份如何处理；固定规则与作者数据如何区分；每类内容的字段组由哪个后续领域规格负责。全部内容为静态证据；**无运行确认**（见 `../scope-statement.md`）。

## 1. 目的与范围

**目的**：统一「内容如何标识」的解释，供后续各领域规格引用，不再各自发明。

**范围**：① 内容身份模型（默认规则与按类的例外、查找语义、完整类清单）；② 注册、查找与缺失值处理（加载、默认值、缺失文件、查询副作用）；③ schema 与作者内容校验（字段约束结构、编译期错误）；④ 固定规则与作者数据的区分；⑤ 字段责任目录。

**非目标**：不提取各类内容的字段语义全集（归字段责任目录指派的领域规格）；不展开完整编译生命周期、写回与失败分支（同批《PBS 生命周期》）；不描述编辑器行为；不设计未来的 ID 类型、注册 API 或类层级；不提取资源文件命名与回退规则（归资源规格）。

## 2. 概念与术语

- **内容身份**：一个内容条目在注册表中的唯一键。默认形式有三类：符号身份、整数身份、符号＋整数双身份；按类覆写时存在复合身份（§3.2）。
- **复合身份**：由多个要素合成的身份，如（训练家类型, 姓名, 版本）三元组、（地图, 版本）、（物种, 形态）。
- **注册表**：每类内容的已登记条目集合及其状态，启动时从编译产物载入；可查询（存在性检查、查找、枚举）。本条不规定数据存放方式或每类一个容器对象。
- **schema**：作者数据类声明的字段约束——PBS 属性名到字段、类型模式与枚举引用的映射（部分类走专用解析，无自身 schema，见 §5.1）。
- **固定规则数据（hardcoded）**：在脚本中直接注册、不经 PBS 编译的内容（成长曲线、进化方式、能力值、地形等），可作作者内容的枚举引用源。
- **作者数据（PBS data）**：由作者在文本中定义、经编译产物载入的内容；其中 Type、Move、Item 等**也是**常用的枚举引用源——「是引用源」与「是固定规则」是两个不同维度。
- **必选/可选数据文件**：缺失时是否触发调试模式下的重编译判定（可选仅一例）。
- **查询操作概念**：**严格查询**（未知身份抛错）、**宽容查询**（未知身份返回空值）、**存在性检查**（未知身份返回假）——三者的默认契约与按类例外见 §3。

## 3. 内容身份模型

### 3.1 默认规则：三类身份与查找语义（有明确适用范围）

多数内容类的已登记内容共用同一查询模式，按身份形式分三类。**以下只是未被覆写时的默认契约，不能据此推出每个数据类都如此**（例外见 §3.2）：

| 身份类 | 键形式 | 接受的查找输入 | 未知身份行为 | 枚举顺序 |
| --- | --- | --- | --- | --- |
| 符号身份 | 符号 | 符号 / 条目实例 / 字符串（转符号后匹配） | 严格查询抛出「未知 ID」错误；宽容查询返回空值；存在性检查返回假（空输入亦为假） | 定义顺序；另有按原始名称字段（非翻译后显示名）字母序的枚举 |
| 整数身份 | 整数 | 条目实例 / 整数 | 同上（字符串/符号不可用于查找） | 数值顺序 |
| 双身份（符号＋整数） | 同一条目同时以符号和整数为键 | 符号 / 条目实例 / 字符串 / 整数 | 同上 | 按整数序号顺序 |

默认契约的补充限定：

- 容错仅覆盖**空输入与类型合法的未知身份**；错误输入类型（如对道具宽容查询传入整数）触发**参数验证错误**，不是返回空值/假。
- 两类查询对同类实例直接返回该实例，**不能据此推出该实例已登记**。
- 双身份「两键一条目」以注册时无键冲突为前提；冲突边界未逐类验证。
- 相等判定：与符号/字符串按符号身份比较，与整数按整数序号比较，与同类实例按身份比较。
- 反向读取（按 schema 取字段值用于写出）时，false 与空数组归一化为 nil。

### 3.2 按类例外（默认规则被覆写的实际契约）

| 类/操作 | 实际契约 |
| --- | --- |
| Trainer | 身份为（训练家类型, 姓名, 版本）三元组，版本默认 0；存在性检查与两类查询均接受该三元参数；严格查询对未知组合抛出「未知训练家」。队伍成员另有子字段约束（sub_schema） |
| PhoneMessage | 联系人按三元组登记。默认消息集经通用编译以字符串 `"default"` 为节身份注册，消费者按字符串键直取；存在性检查在姓名空时键退化为类型符号——编译登记、存在性探测与消费取值是**三个不同入口**，不能互相代证。联系人消费依次尝试（类型, 姓名, 版本）→（类型, 姓名, 初始版本）→默认集 |
| Encounter | 按（地图, 版本）复合身份登记。存在性检查只检查指定组合；严格查询在指定版本缺失时**回退版本 0**（两者全缺返回空值）；枚举按地图再版本排序。**按版本枚举的可观察结果**：在正常编译的键表中，目标版本 v＞0 时**枚举所有已存在的版本 v 条目，同时枚举所有已存在的版本 0 条目**（不论同地图是否已有版本 v；不会生成缺失版本的记录；v＝0 时仅枚举已存在的版本 0 条目）——该结果如实保留（内部键表示与形成原因见审计，不按合理化改写）；与严格查询的正确回退是两回事 |
| Metadata | 无参严格查询直接返回全局 0 号记录 |
| PlayerMetadata | 严格查询先按编号查找，**未知编号回退 1 号记录**（默认编号也为 1） |
| TerrainTag | 宽容查询对空输入与未知键均**回退 None 地形** |
| DungeonTileset | 宽容查询对未知键**回退首条图块配置** |
| DungeonParameters | 宽容查询先按（区域, 版本）合成符号、回退基础区域；仍缺时**新建默认参数实例返回（不登记）** |
| SpeciesMetrics | 形态指标查询对缺失指标可能**创建并登记**记录：基础指标缺失先登记基础默认，形态指标缺失再以基础值克隆登记。**查询有副作用**；物种本身未定义则抛错 |
| Species（形态） | 形态查询以「物种_形态号」合成符号查找，形态缺失回退基础物种符号，仍缺返回空值；空输入直接返回空值 |

### 3.3 完整内容类清单

**作者数据类（PBS 编译载入，共 19 个唯一逻辑内容种类）**：符号身份 14 类——Type、Ability、Move、Item、BerryPlant、Species、SpeciesMetrics、ShadowPokemon、Ribbon、Encounter、TrainerType、Trainer、DungeonParameters、PhoneMessage；整数身份 5 类——TownMap、Metadata、PlayerMetadata、MapMetadata、DungeonTileset。另有非类产物加载与 Species 资源解析扩展，不新增数据类。

**固定规则数据类（脚本内直接注册、不经编译产物载入，共 17 类）**：符号身份 15 类——GrowthRate、GenderRatio、EggGroup、BodyShape、BodyColor、Habitat、Evolution、Stat、Nature、Status、EncounterType、Environment、BattleWeather、BattleTerrain、Target；双身份 2 类——TerrainTag、Weather。

**合计 36 个唯一内容类。** PBS 基名：18 个声明类（PlayerMetadata 无基名，由 metadata 玩家节编译），经 Species 双基名（pokemon＋pokemon_forms）展开为 19 项，再合并 3 个非类基名（battle_facility_lists、map_connections、regional_dexes），共 **22 个基名**。

**非注册表编译产物与资源**：regional_dexes、map_connections、trainer_lists 三个 .dat、战斗动画集（存在性检查后加载）、move2anim.dat（宿主读取返回空值/假时回退空表；文件缺失或宿主读取失败的行为未验证）、MapInfos。它们的来源与加载方式各不相同，**不能统称为 PBS 作者数据编译产物**。

**来源标记**：PBS 来源条目携带 `pbs_file_suffix`（其来源文件相对基名的后缀）；该标记只适用于 PBS 编译条目，固定规则条目与查询时新建的默认记录不追溯到输入文件。

## 4. 注册、查找与缺失值处理

### 4.1 注册与加载

- 注册：条目按身份键写入本类数据表（双身份同时写两个键）。固定规则类在脚本加载时逐条注册。
- 加载：启动时统一从编译产物 .dat 载入全部作者数据（仅处理声明数据文件名的类）；加载本身是宿主提供的序列化读取，失败行为未验证。
- 启动顺序：核心消息 → 插件 → **编译检查** → 游戏初始化 → 标题场景。编译检查仅在调试模式执行（见 §4.2）。

### 4.2 缺失数据文件

| 情形 | 行为 |
| --- | --- |
| 必选数据文件缺失 | **仅在调试模式**的编译检查中判定必须重编译；非调试模式该检查直接返回，不存在普通运行自动修复。必选清单含各内容类与 map_connections、regional_dexes、trainer_lists 三个非类文件（仅此三个） |
| 可选数据文件缺失（仅 ShadowPokemon，唯一可选类） | 该条件本身不触发重编译判定；加载时先检查文件存在，不存在则**本次不读取** |
| 可选类的 PBS 输入全部缺失 | 通用编译在清空数据表**之前**直接返回 |

重要限定：可选缺席**不等于**「数据为空」——缺失加载分支只跳过读取，**不会清空已有表**；「数据为空」只在「初始为空表且无其他登记」的前提下成立。可选数据缺席后 Shadow 消费者的行为未逐点核实（U06）。

### 4.3 字段缺失值（默认值）

条目构造时对缺失字段赋类级默认值，例如：物种未命名显示名 → "Unnamed"、类型 → [:NORMAL]、捕获率 → 255、亲密度 → 70；道具卖价 → 买价的一半、BP 价 → 1；招式类型 → :NONE、命中 → 100、PP → 5；地图元数据标志 → 空表。默认值是**当前快照的类级声明**，不是 Pokémon 通用规则；完整字段语义归领域规格。

### 4.4 查询副作用

SpeciesMetrics 的指标查询可能创建并登记新记录（§3.2），因此「查询后注册表内容」与「查询前」可能不同；DungeonParameters 的缺失查询返回未登记的默认实例，不改变注册表。设计测试时不能把查询都当作只读。

## 5. schema 与作者内容校验

### 5.1 schema 结构

作者数据类的字段约束为 **PBS 属性名 → [目标字段, 类型模式, 枚举引用]**（逻辑约束结构，不规定声明形式）。多数类的约束以固定表形式给出；Species 的约束按**基础物种与形态两个属性集**分别给出；**并非每个作者类都有自身 schema**：Encounter 走专用逐行解析，Trainer 除主 schema 外还有队伍成员子约束（sub_schema）。

观察到的类型模式（行为层含义）：

| 模式 | 含义 |
| --- | --- |
| `m` | 符号值，名称字符约束（字母/数字/下划线、不以数字开头）；用于节名，也用于 Type 的相克引用（Weaknesses/Resistances/Immunities 为列表形式） |
| `s` / `q` | 文本 / 非格式化文本（如图鉴描述） |
| `i` | 有符号整数 |
| `u` | 非负整数（允许 0） |
| `v` | **严格大于 0** 的整数（显式拒绝 0） |
| `x` / `f` / `b` / `n` | 十六进制 / 浮点 / 布尔 / 名称（同 m 的字符约束） |
| `e` | 单个枚举值：引用固定规则类或作者数据类（如 Type、Move、Item、Weather），或内联枚举表（如道具 FieldUse 名值映射、招式 Category 字符串数组） |
| `y` | 枚举或整数 |
| `*` 前缀 | 列表（如 `*e`、`*s`、`*m`） |
| `^` | 可重复属性（同一属性多行累加，如 Evolution） |
| 复合 | 固定长度元组（如六项能力 `vvvvvv`、坐标 `vuu`） |

### 5.2 编译期身份与引用校验（按入口分别表述）

**重复处理按入口分开，不能统一成一种失败规则**：

| 入口 | 重复身份行为 |
| --- | --- |
| 直接注册（含固定规则注册与专用编译的注册调用） | **不检查已存在身份**：同键后项替换前项 |
| 通用 PBS 编译 | 注册前检查：**重复节名拒绝**（"Section name 'X' is used twice."）并报告位置 |
| 训练家专用编译 | 每节完成即直接注册，校验与终检无同身份拒绝：**两个合法同身份训练家节由后项覆盖** |
| 训练家队伍成员招式 | 重复招式**静默去重**（非错误检查） |
| 地区图鉴物种 | 重复物种**拒绝**（"Dex list number {1} has species {2} listed twice."） |
| 遭遇条目（槽） | 同一遭遇方式中**物种与等级范围相同**的槽**合并并累加权重**（权重求和），随后按权重降序排列；不是简单去重 |
| 遭遇节身份 | 同（地图, 版本）节重复定义**拒绝**（"Encounters for map 'X' are defined twice."）——与槽合并不是同一层级 |

**引用校验**：

| 校验 | 行为 |
| --- | --- |
| 未定义枚举值（如道具 Move 引用未定义招式） | 通用枚举求值路径拒绝："Undefined value {1} in {2}." 并报告位置。错误入口是记录求值→值转换→枚举检查的通用链，**不是**特定类型的专用报错函数 |
| 必需参数缺失 | 编译错误（如进化方式需要参数而未给） |
| 校验时机 | 条目级校验（编译该节时）＋全量终检（全部读入后） |

**已撤回的说法**：「枚举在写出时可自动补写新常量」缺乏证据——写出路径是值到文本的转换，对枚举只查找已有名称或返回值/错误，不创建新常量。

## 6. 固定规则与作者数据的区分

| 维度 | 固定规则数据 | 作者数据 |
| --- | --- | --- |
| 定义位置 | 脚本内注册（17 类） | PBS 文本编译（19 类）＋非类产物与独立资源（§3.3） |
| 加载 | 无 .dat；不经编译产物载入 | 从编译产物 .dat 载入 |
| 角色 | 作者内容的枚举引用源与规则参数（成长曲线、进化方式、能力值、地形、天气、目标、环境等） | 游戏实际内容（物种、招式、道具、地图、训练家等） |
| 可否含行为 | **可以**（如成长曲线的经验公式、进化方式的判定），不只是枚举 | 字段语义按类归领域规格 |
| 修改方式 | 改脚本（开发者） | 改 PBS（作者/编辑器） |

维度澄清：Type、Move、Item 是**作者数据**（经 PBS 编译），同时也充当其他内容的枚举引用源；「是枚举引用源」不等于「是固定规则」。判断「某行为由什么决定」时，含行为的固定规则（成长公式、进化判定）与纯枚举目录必须分别对待。

**Nature 的固定身份前提**：参考快照的性格目录有 25 个身份，派生性格按个人标识对 25 取余后选取目录顺序中的身份；该顺序与每个身份的能力修正属于固定规则，不能由作者 PBS 自由重排或只保留显示名。例如顺序 1 的 LONELY 为攻击 +10、防御 −10；顺序 2 的 BRAVE 为攻击 +10、速度 −10（顺序从 0 开始）。完整 25 身份顺序、20 项双能力修正与 5 项中性映射，以及能力取整、薄荷等消费者合同由 WP19 负责；本档案登记该必需依赖，不以通用 schema 的身份校验替代这些领域规则。

## 7. 字段责任目录（字段组粒度）

每类内容的字段语义由以下后续领域规格负责。**字段组 → 主要负责规格 → 必要引用/前向依赖**；单一责任的类按类整体归组。本表只指派责任，不展开语义。

| 类（身份类） | 字段组 | 主要负责规格 | 必要引用/前向依赖 |
| --- | --- | --- | --- |
| Species（符号，双基名） | 身份/物种与形态归属、来源 | WP18、WP21 | 本档案；地点输入（WP11） |
| 〃 | 基础能力/IV·EV 相关、数值字段 | WP19 | WP18、WP06 |
| 〃 | 升级/教学/蛋招式学习表 | WP30 | 招式槽状态（WP20）、战斗中生效（WP42） |
| 〃 | 进化数据（方法/参数/前后关系） | WP31、WP32 | 战后检查时机（WP42） |
| 〃 | 蛋群/薰香/后代 | WP33、WP34 | WP19、WP21；孵化计步交界（WP35） |
| 〃 | 野生持有物 | WP36 | 遭遇修正引用（WP18） |
| 〃 | Mega 石/Mega 招式/还原形态 | WP22 | 战斗资格/时机（WP40）、数值与特性联动（WP43/WP48） |
| 〃 | 图鉴文本/分类/形态展示 | WP62、WP08 | 资源（WP15）、WP21 |
| 〃 | 特性/隐藏特性 | WP48、WP49 | 计算阶段（WP43） |
| 〃 | 性别比例/成长曲线引用 | WP19、WP30 | WP18 |
| SpeciesMetrics（符号） | 图像尺寸/阴影/位置指标（资源选择） | WP15 | 本档案；地图绘制引用边界（WP16） |
| 〃 | 前后精灵位置/离地高度（**战斗放置**） | WP67-A | WP15、指标编辑（WP73-B） |

## 8. 默认行为与配置变体

- **基线默认**：全部作者数据按 §3.3 清单编译载入；ShadowPokemon 为唯一可选类（当前无顶层 shadow_pokemon 数据文件，其数据缺席，见《规则配置档案》§6.2）。
- **候选材料**：Shadow 备选数据（启用条件与完整生命周期待证，U06；只登记为候选，不作支持结论）。
- **未验证组合**：可选数据缺席时各消费者的行为（§4.2）；多文件后缀内容的归属组合（§3.3 来源标记）。
- 参考快照行为、官方版本预期、未来目标分开标记；本档案只记录第一类。

## 9. 边界、失败与未知

- 未被覆写的默认严格查询遇到未知身份抛出错误；按类覆写则按 §3.2 例外处理（回退、返回空值或新建实例）。**错误的最终用户呈现**未运行验证。
- 默认容错仅覆盖空输入与类型合法的未知身份；错误输入类型触发参数验证错误（§3.1）。
- 查询可能有副作用（SpeciesMetrics 登记新记录，§4.4）；缺失查询也可能返回未登记实例（DungeonParameters）。
- 调试模式的缺失文件重编译判定不适用于非调试运行（§4.2）。
- 可选数据缺席时 Shadow 消费者的容错（U06）未逐点核实。
- schema 类型模式的完整解析规则（非法输入的拒绝行为全集）归《PBS 生命周期》；本档案只登记结构与校验锚点。
- 固定规则类的行为内容（成长公式、进化判定）只登记存在与责任归属，不提取规则。
