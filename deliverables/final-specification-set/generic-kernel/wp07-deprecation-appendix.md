# 弃用告警机制（净化附表；批次 4）

分类：Generic Kernel（诊断）、Demo / Developer Experience（作者工具与兼容工作流）。本附表是 [wp07-diagnostics-files-http](wp07-diagnostics-files-http.md) 的附件，补弃用告警机制本体：被标记弃用的方法仍可被调用（**兼容不阻断**），但每次使用都会向**调试控制台**发出一条弃用警告（含替代方法指引）。全部内容为静态证据；**无运行确认**（调试控制台的宿主呈现未验证）。

## 1. 目的与可见行为

弃用机制让游戏与插件作者平滑迁移。两类入口：**直接告警**（按名发一条警告）与**弃用别名**（创建「调用时先告警、再按原方法执行」的别名）。

**非目标**：不复刻任何元编程/类结构（别名的实现机制只作行为描述）；不定义调试控制台的宿主呈现（诊断面已述控制台输出集合，本附页只说明告警文本进入该集合）；不提取全部弃用方法清单（别名登记点枚举归 `../../../audit/source-traceability.md`）。

## 2. 领域概念

- **弃用警告**：一条发往调试控制台的文本，含被弃用方法名、可选的移除版本、可选的替代方法（§3）。
- **弃用别名**：与被弃用方法同名异名的入口——调用时先发出弃用警告，再以相同参数调用原方法并返回其结果（**不阻断调用、不改变返回值**）（§4）。
- **校验**：别名创建的参数类型与目标方法存在性检查（参数验证机制归《内容身份、注册与 schema》引用）。

## 3. 直接告警

| 输入 | 行为 |
| --- | --- |
| 方法名（必需，被弃用方法名） | 组成首行文本「使用了已弃用的方法“{方法名}”或其别名」 |
| 移除版本（可选） | 提供时追加一行「该方法计划在 Essentials {版本} 中移除」 |
| 替代方法（可选） | 提供时追加一行「请改用“{方法名}”」 |

- 组成文本经本地化（《本地化》引用）后调用控制台警告输出，发往调试控制台（《诊断、文件与 HTTP》诊断面引用）。
- **首行（方法名）必有**；**移除版本与替代建议两个部分分别可选**——不给时对应行不存在（不推断为必给）。

## 4. 弃用别名

- **参数校验**：别名名与被别名方法名必须为符号；移除版本为空或字符串；类方法标记为真/假——**类型不符时触发参数验证错误（非返回空值/假）**。
- **目标方法存在性**：目标（类方法标记为真时取类的类、否则取模块/类自身）未定义被别名方法时，**抛出参数错误（「`类名` 未定义方法 `方法名`」）**——不是静默忽略。
- **别名行为**：定义别名方法——被调用时：(1) 组装别名显示名（类名＋分隔符＋方法名；分隔符：类方法标记为真用 `.`、否则用 `#`）；(2) 以别名显示名发出直接告警（传移除版本与被别名方法显示名）；(3) **按位置参数与关键字参数调用原方法并返回其结果**——**仅显式转发位置/关键字参数，未显式转发块回调**；**目标自身失败等边界按原方法合同，不被「透明兼容」抹掉**。
- **效果**：旧名调用继续工作（兼容），但每次使用产生一条弃用警告——**兼容不阻断调用、不改变返回值（限实际参数通道与正常返回）**；不产生静默失败。

## 5. 依赖与配置

- 消费《诊断、文件与 HTTP》（调试控制台输出集合——告警文本的去向）、《本地化》（本地化文本）、《内容身份、注册与 schema》（参数验证）。
- **消费者（与别名构造器分开）**：**直接调用者**——若干方法体**直接发告警并继续检查**（不经别名构造器登记；登记点枚举见追溯索引）。**别名构造器**：**当前核心脚本未找到其登记调用**（全脚本检索无命中——**不推成扩展永不调用**）。

## 6. 边界与不变量

- **兼容边界**：弃用告警**不阻断调用**（别名照常执行原方法——限实际参数通道与正常返回；未显式转发块回调，目标自身失败等边界不被抹掉）；告警只进调试控制台（宿主呈现未验证）。
- **失败边界**：别名创建时的类型校验失败（参数验证错误）与目标方法缺失（参数错误）是两个不同阶段；使用阶段的告警不影响返回。
- **不变量**：直接告警**首行（方法名）必有、移除版本与替代建议两部分分别可选**；别名先告警后执行原方法；分隔符按类方法标记真假二选一。
