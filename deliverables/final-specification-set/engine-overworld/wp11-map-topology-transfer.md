# 地图拓扑与转移（净化正文；批次 3）

分类：Engine/Overworld Integration。本文件描述地图身份、连接关系、局部坐标/相邻地图偏移、有效边界及相邻地图选择的行为规则——玩家如何在相邻地图间移动、地图如何被加载/卸载/恢复。全部内容为静态证据；**无运行确认**（真实地图数据缺失，U01——见 `../scope-statement.md`）。

## 1. 目的与范围

**目的**：回答「某位置属于哪张地图、跨图时坐标如何换算、何时触发进入/离开」，供后续实现构建地图加载与转移，而不追踪任何特定工厂结构。

**范围**：① 地图身份与连接关系（身份、连接配置、坐标/偏移规则）；② 跨图转移（边缘跨图、显式传送、重新建立/恢复）；③ 地图生命周期（加载/卸载、邻图、进入/离开通知、更新顺序）；④ 地图恢复与存档交界。

**非目标**：不编造真实地图宽高、可达路线或事件存在（U01）；不提取地形通行/运动/载具规则、事件/NPC/跟随规则、地图绘制细节或地图元数据字段语义（各归相应规格）。

## 2. 概念与坐标单位

- **地图身份**：整数 ID（地图数据文件名与元数据键共用）。
- **连接（connection）**：两张地图之间的一条邻接关系，含两侧的端点描述。
- **端点/锚点（anchor）**：连接端点加载后换算出的、该图坐标系内的二维点。方向字母（N/S/E/W）与显式坐标是两种端点描述。
- **邻图**：被加载到内存、按显示偏移摆放的相邻地图；仅保留显示范围内的邻图。
- **跨图转移**：玩家走出当前地图有效范围时，按连接换算到相邻地图的对应位置并切换当前地图。
- **重新建立（setup）**：整张地图重新加载（含事件/公共事件实例重建）；恢复用标记变更路径（保留已加载地图状态）。两者区别归存档恢复规格。
- **坐标单位**：位置以格计；1 格＝32 像素；1 像素＝4 子像素；每格 128 子像素。显示坐标以子像素为单位，不能与格坐标或像素坐标直接相加。

## 3. 地图身份与连接关系

### 3.1 地图身份与加载

- 地图以整数 ID 标识；建立时读取对应数据文件，装入图块集、雾/背景配置，触发地图建立通知，并创建该图的事件与公共事件实例。
- 地图容器持有已加载地图与当前图索引；按索引取当前图：**索引 nil/负数归 0**；索引不命中但首图存在时**回退首图**并输出提示；全部为空才抛错。
- 地图有效范围：0 ≤ x < 宽、0 ≤ y < 高；宽松范围各向外扩 10 格（用于互动判断）。

#### 3.1.1 驻留复用与临时查询建立（GR3-M03-002）

按图ID查询先查已加载集合：命中则复用同一实例，不发新的建立通知；未命中则先实际建立地图。普通加载在建立成功后才加入集合；地形、目标通行及部分连接坐标查询采用“不加入集合”方式，**不加入只限制驻留，不省略读取、建立或通知**。建立通知在地图数据/图块集等前置初始化之后、运行时事件实例创建之前发出。

当前图A查询未驻留图B，不必先排队正式传送，也不因这次查询切换当前图或移动玩家。若B的地牢标记为真，建立通知可生成B、消费待播种子、重播全局随机，玩家摆放成功还写玩家传送暂存坐标（WP14 §3.1.1）；不据此置传送请求标记。不在集合的临时B不因查询成功而自动驻留；两次之间仍不驻留时，重复查询可再次实际建立及生成，不能假设纯读、一次性缓存或相同布局。合法连接跨缘预检查也可沿此链；一次预检查可能有多次按ID临时取图，不规定每次预检查恰好只生成一次。

已驻留B、没有另行重建时的查询/边缘切换复用实例，才适用“不重生成”。非地牢B仍经建立通知，但该地牢消费者不生成、不消费种子也不写摆放暂存；其他订阅者的作用须分别判断。失败前缀与原单次生成限制见WP14；通知按已接受WP05的顺序与首次异常停止合同传播，无原子回滚保证。实际默认地图标记、连接/查询链和Demo可达性 `MISSING_MATERIAL`，案例 `NOT_EXECUTED`。

### 3.2 连接配置与坐标/偏移规则

- 连接来自编译产物（作者文本经编译生命周期）；原始配置每条为 [A图ID, A端描述, A坐标, B图ID, B端描述, B坐标]；加载时两端各自换算为一个二维锚点：
  - 端描述为 N 或 S：锚点 x＝配置坐标值，锚点 y＝边值（N→0，S→图高）。
  - 端描述为 E 或 W：锚点 x＝边值（E→图宽，W→0），锚点 y＝配置坐标值。
  - 端描述为显式坐标（非方向字母）：两个数值直接作为锚点 (x, y)。
  - 边值规则：N/W→0，E→图宽，S→图高。两端图尺寸为 0 的连接被忽略。
- 连接按两端分别索引（双向可查）。
- **跨图坐标换算**：A→B 方向时，目标坐标＝(B锚点 − A锚点)＋当前坐标，即 xB＝B锚点x − A锚点x＋xA、yB＝B锚点y − A锚点y＋yA。逐条连接检查，**第一个使目标落在 B 图有效范围内的连接生效**；都不满足则不转移。B→A 方向使用同一锚点对反向相减。
- **相对位置换算**：同图直接差值；有连接则按锚点偏移差值；无连接为 [0, 0]。
- **邻图显示偏移**：邻图显示坐标＝(锚点差 × 128 子像素)＋当前图显示坐标；仅保留显示范围（约 6 格缓冲区）内的邻图。

#### 3.2.1 连接文本的编译接受与运行消费

作者端点配对按第一端分支校验（WP04 §4.5）：方向N/S/E/W要求第二端对应S/N/W/E；整数第一端不执行该方向配对。因此1,0,0,2,W,0可编译保留，1,E,0,2,W,0正常通过，反向混合1,W,0,2,0,0拒绝。实际运行仍逐端按上节换算；编译接受不保证混合记录的跨图、资源读取或写出成功，缺地图警告不等于统一拒绝。

## 4. 跨图转移

四类入口的守卫、顺序与失败行为不同，不能互相套用：

| 入口 | 守卫/前提 | 关键顺序 | 失败/例外 |
| --- | --- | --- | --- |
| 边缘跨图 | 玩家**不在移动中**（移动中时直接返回）；玩家已不在当前图有效范围 | 离开通知 → 切换当前图与索引 → 落位 → 图更新 → 过渡音乐/刷新 → **进入通知（在落位之后触发，此时玩家已是新坐标）** → 天气持续输入写为 **20** | 无有效目标：不转移（坐标保持图外状态） |
| 同图显式传送 | 目标图 ID 与当前图相同 | 清传送标记 → 取消载具 → 音乐差异处理 → 清桥/阴影；不重建、不发本次地图进入通知；落位（取模）/转身/整姿 → 跟随者转移 → 图更新 → 显示层重建/转场/自动音乐/帧重置/输入更新 | 游泳是否取消由实际调用参数决定，见下文；共有前置副作用仍存在 |
| 跨图显式传送 | 目标图 ID 与当前图不同 | 清传送标记 → 取消载具（可选保留游泳）→ **音乐差异淡出（有正在播放的 BGM 或 BGS 时先读取目标地图文件；两者皆无则跳过该读取）** → 清桥/阴影 → 重建：清地图集合 → 离开通知（旧图非 0 且不同）→ 重载目标图（事件/公共事件实例重建）→ 邻图摆放 → **进入通知（在玩家落位之前触发，此时读到的仍是旧坐标）** → 落位/转身/整姿 → 跟随者转移 → 图更新 → 显示层重建 → 转场 → BGM → 帧重置 → 输入更新 | **无**缺图调试选图恢复（该分支仅属读档恢复入口）；缺图失败点按音频状态分两阶段（§8），不能统一写成「失败时集合已清空」 |
| 读档恢复 | 标记不一致或安全存档为真 → 重建；否则仅标记地图变更 | 两个正常分支均发进入通知并清局部记录 → 自动音乐 → 地图更新 → 记录恢复辅助（§6）；实际同ID重建在旧ID非零时仍发离开，非重建分支不发离开 | 缺图时调试选图/取消退出、非调试报错（仅此入口）；存档门见批准WP09，阶段边界见§6 |

补充规则：

- **普通移动不会「走出无连接的地图」**：玩家前移先经通行判定与边缘跨图通行判定；目标超出当前图时按连接换算，无相邻有效目标则通行失败（归地形运动规格）。「已在图外时边缘跨图找不到目标而返回」不等于普通移动可以越界出图。
- **跨界通行入口**：先找到连接所映射的目标图和图内坐标；无有效目标时拒绝，移动者 through 或调试 Ctrl 均不能越过此门。有效目标上先检查移动者 through、玩家调试 Ctrl；否则只对**目标坐标、方向 0**作目标地图层判定，再检查目标处的阻挡角色。方向 0 不检查单个方向位，但仍拒绝全向禁行及该入口的其他地形/碰撞守卫。此入口不查原图源格的前向位，也不追加目标格的反向位；同图普通移动的双端规则见 WP12 §3.2。没有 through/调试、其他守卫均通过时，原图向右位与邻图向左位各被禁仍可能许可跨右缘；邻图全向禁行则拒绝。
- **传送请求与执行分层**：事件命令 201 只排队并推进到下一命令，正常地图场景主循环和迷你更新都以「不取消游泳」消费此请求。因此正常 201 的同图/跨图传送保留冲浪与潜水；直接调用场景传送入口而省略该参数才采用「取消游泳」默认值。跨图进入通知仍可调整骑行，同图无此通知。边缘切图没有调用该显式载具取消入口。
- **冲浪临时残留（GR4-M03-002）**：载具取消对冲浪/潜水标记的处理不包括临时基点 `surf_base_coords` 或结束标记 `ending_surf`；传送、落位与显示层重建没有这两个字段的独立清理。无完成步/额外合格通知及其它写入时，失败上水后的正常同图 201 保游泳转移返回可仍带旧基点，显示选择仍取该基点（只断言状态/显示输入）。直接默认转移虽清游泳，临时字段也未因此清；后继玩家步后通知按地图场景＋玩家＋有基点的门清基点，结束标记为真才额外收尾并清标记，见 [WP12 §5.2](wp12-terrain-movement-vehicles.md)。人工结束标记真时，主解释器等待门会阻止正常 201 到达；仅可用于直接转移的条件对照，不推默认软锁。完整前提与未执行向量 GR4-SF01–GR4-SF07 见测试目录。固定R追溯：`Data/Scripts/003_Game processing/002_Scene_Map.rb` 72–101、121–133、165–175，`003_Interpreter.rb` 116–123，`004_Game classes/008_Game_Player.rb` 262–266、575–592，`012_Overworld/004_Overworld_FieldMoves.rb` 705–751，`005_Sprites/005_Sprite_SurfBase.rb` 44–79。
- **天气观察点**：边缘切图在进入通知后把天气持续输入覆写为 20，即使通知已写入 Rain/强度 60/持续 0，最终存储也为 Rain/60/**20**；显式重建没有这次边缘后写。20 是显示调用的正持续输入，不能解释为 20 秒。显示层只有天气类型差异时调用；已有渐变优先拒绝新调用，获准的正持续值走固定阶段时线（WP59/WP16 交界），不能凭最终输入推定当帧画面已变。
- **落位坐标取模**：传送/落位目标坐标对图宽/高取模后落地，并同步子像素坐标、触发离开旧格通知；传送输入坐标不保证原样生效。
- **通知时机与玩家位置**：跨图重建的进入通知在落位之前（订阅者读到旧坐标）；边缘跨图的进入通知在落位之后（订阅者读到新坐标）。离开通知均在切换前触发。

## 5. 地图生命周期

### 5.1 进入/离开与更新顺序

| 时机 | 顺序 |
| --- | --- |
| 场景主循环 | 建显示层 → 转场 → 循环：画面更新 → 输入更新 → 解释器更新 → 玩家更新 → 各图更新 → 地图生命周期更新 → 系统/画面更新 →（传送中则）传送 → 显示层更新 → 逐帧通知 →（回标题则）标记未加载并回标题 → 输入分发（互动/菜单/快捷/调试） |
| 跨图 | 玩家移出边界（且不在移动中）→ 连接换算 → 离开通知 → 切图 → 落位 → 图更新 → 过渡 → 进入通知 → 天气重置 |
| 显式传送 | 取消载具 → 音乐处理 →（图不同则）重建（含进入通知，在落位前）→ 落位/转身 → 跟随者转移 → 图更新 → 显示层重建 → 转场 → BGM → 帧重置 → 输入更新 |
| 生命周期修剪 | **玩家移动中不修剪**；先删与当前图无连接的图，再删超出显示范围的图，并重置索引 |
| 地图损坏 | 当前图事件集合为 nil → 抛错无法继续 |

进入/离开/建立通知按上表时机触发（事件订阅机制归通知规格）。骑行调整见 WP12；地点提示的进入门与生命周期如下。

### 5.2 邻图加载与卸载

- 加载：进入当前图范围或邻图范围内时按连接与显示偏移加载。
- 卸载：与当前图无连接或超出显示范围时被删除（玩家移动中不执行）。
- **实例复用与重建**：加载复用已存在实例；重建清空集合并重新构造——卸载后再加载会**重新构造事件实例**。事件实例的临时状态（消去标记、启动标记、临时自开关表）在实例初始化时重置；页条件读取的（持久）自开关存于全局表（键为 [图ID, 事件ID, 字母]），**不随实例重建丢失**。即：临时自开关随实例重建丢失，持久自开关保留。
- 邻图的事件/更新按各自地图实例进行（事件规则归事件规格）。

### 5.3 地点提示的进入门与生命周期

地图/显示集合变化通知须有场景与显示集合、地图确已改变且目标元数据 `announce_location` 为真才创建地点提示。已有前一地图历史时，`NO_SIGNPOSTS` 按相邻两个元素组成地图对、双向抑制；尾部孤立元素不组成地图对。前图解析名称与当前名称相同也抑制。没有前图历史时跳过这两项历史抑制。只刷新同一地图的显示集合不创建。

提示按单调时间依次进入 0.4 秒、停留 1.6 秒、退出 0.4 秒。创建时存在 `fly_destination` 则延迟；只要飞行目的地仍存在，更新直接返回，连消息显示/地图改变导致的销毁检查也尚未执行。目的地清空后的首次更新重置计时，再检查消息显示或当前地图身份不同并销毁；没有这些门才开始完整时线。常规消息/换图直接销毁，不在原提示上换文字。实际字体、像素与素材属于世界显示规格，未运行确认。

### 5.3.1 地图名称的材料、展开与生命周期

有效地图名先用元数据原名作为本地化哈希键，按当前语言game→core查找；缺命中返回原名。空译是命中，不再转core；地图消费者看到空值/空串才回退基本地图名，无元数据也走基本名。空原名、缺元数据、空译文是不同进入条件。大写`\PN`在所选可变文本中以全局玩家名直接展开；没有玩家时该查询不展开。普通名字Alice/Bob且无替换元字符/再次引入占位、查找替换正常是以下成功合同前提。

| 实际选中材料 | 展开后的保留与重复读取 | 恢复含占位材料的必要操作 |
| --- | --- | --- |
| 非空当前game译文，或game未中后的非空core译文 | 所选译文值保留已展开名字；独立原名不改 | 成功重载含模板的相应语言材料；语言重载不恢复独立原名/基本名 |
| 两语言层缺命中的非空元数据原名 | 登记原名保留已展开值，后续查找键也随原名变化 | 重新载入/登记含模板的元数据；仅语言重载不足 |
| 名称结果空/空串或缺元数据后的有效基本名缓存 | 基本名称缓存保留已展开值 | 清该缓存并成功读回未改材料；仅语言或元数据重载不保证恢复 |

重复读取同一材料且无重载、编辑、新键命中或其它写入时，已消耗占位不会随玩家改名自动重建。两层MAP_NAMES域均为空可确定原名主例两次缺命中；若只排除原模板键，原名展开后形成的新键可能命中新译文，结果须按新命中重新判定。上述各独立材料例排除已有别名；已有共享文本引用会使一次变化被多个持有者看到，编译缺名回填可能与基本名共享，不能保证原名变化绝不影响另一入口。

无大写占位内容不变；无玩家且不走继续预览时保留占位。通用消息显示先复制输入再处理控制字符，不因此改共享原文，不能把所有PN显示/本地化查询都归此写入。继续面板先查名，再以存档训练家名展开剩余占位且早于选择（WP65§3.2）；全局Alice、存档Bob时先行Alice占优。

查询和预览只改变内存，普通玩家存档不自动保存内容登记。后续显式确认该地图元数据保存，原名已变、没有另改、文件步骤正常时，内容档案和PBS可携带已展开原名（[世界编辑器§4](../demo-dx/wp73-b-world-editors.md)的保存次序与共享嵌套取消规则保持）。已展开后的UI失败不自动撤回；前置查找类型/结构失败、不可变文本或任意替换元字符名字不套成功主例。地点提示同名抑制、电话/漫游/地点展示消费当前命名服务值，并不重新构造模板；不据静态合同保证Demo事故或未来必须复用共享文本结构。

## 6. 地图恢复与存档交界

- 地图容器是持久值（存档目录），随存档保存/恢复；新游戏按起始图 ID 与坐标建立。
- 存档中地图的持久状态（已加载地图与玩家位置）按存档目录登记；跨图后地图状态保留/重建按 §4 规则。

### 6.1 正常读档的实例与记录（GR3-M03-004）

读档门沿已批准WP09（blob `d9a256cbc1054cc3ad190f83231bfdfa564ac4a2`）：系统标记不一致或安全保存为真才重建，两者都不成立才复用已加载实例并发送地图变更/进入通知。两正常分支的必要前提为有效存档/地图、各通知及更新返回、无插件或额外写入。

| 分支 | 离开 / 进入 | 局部记录与事件实例 |
| --- | --- | --- |
| 一致且非安全保存，未重建 | 只发送进入；无本次离开 | 进入首个消费者在可选记录新治疗点之后清局部消去/移动记录及地图局部效果；已加载地图事件实例可仍保留消去、位置、朝向或through状态，不能据清记录宣称实例也重置 |
| 实际重建（包含目标ID等于旧ID） | 旧ID非零时先离开，再建立/摆放邻图、进入；旧ID0不发离开 | 新建地图初始身份为0，离开门比较旧图与这个初始身份，故同ID实际重建也会离开；事件实例按新页数据初始化，进入仍清局部记录，不保证旧移动记录再次恢复 |

通过进入通知及地图事件集合的空值损坏守卫后，恢复遭遇/载具，随后自动音乐 → 地图更新 → **局部记录恢复辅助** → 新地图场景。集合存在但空数组/空集合不等于空值损坏（WP09）。无进入后追加记录时，两分支到辅助处的消去与移动记录均为空，辅助不会凭已清旧条目再次消去/移动。记录曾作为持久单元保存，不等于读档消费它时仍存在。

同图显式传送的不重建/不发进入条款只属§4那个入口；不得套到读档同ID实际重建或“只标记地图变更”恢复。同ID进入仍执行清记录消费者，天气消费者的“同图不处理”也不能抑制该清记录行为。

### 6.2 记录内容、条件恢复及失败前缀

局部消去记录以(记录图ID,事件ID)为键、值为真；移动记录以同样身份记录位置(x,y)、方向及through快照。有效整数ID且当前事件存在才追加移动记录；同键后写覆盖此前快照，记录与实例状态分别观察。清空还将力量已使用、黑/白笛遭遇率与等级效果四个局部标志归假。普通实例消去不登记；记录式脚本辅助有当前事件存在门；主事件命令116则以正事件ID为门，缺实例仍可登记(当前图ID,事件ID)→真，局部记录对象缺失时跳过登记。116推进一项并停止本次解释器更新，见 [WP13 §3.3 三入口表](wp13-map-events-npc-followers.md)及命令矩阵116行（GR4-M03-003）；本节的进入清表与条件恢复合同保持。

以下是“记录仍存在”的直接辅助输入，或进入清空之后有明确新写入的条件合同，**不是默认读档保留旧记录的承诺**：

| 字段 / 条件 | 辅助规则 |
| --- | --- |
| 消去 | 仅记录图等于当前图且标记真时消去同ID事件；缺事件安全跳过，异图不消去 |
| 位置与方向 | 仅同图且移动记录存在时处理；同图缺事件跳过整条。先落位，再按2/4/6/8转向下/左/右/上；其他方向不请求转向，落位仍发生 |
| through | 真值写入在上述地图匹配门之外；异图记录也会尝试给当前图同事件ID写through真。假值不写，**不会清当前已有真值** |
| 异图＋through真＋当前缺事件 | 未经过同图缺事件跳过门，through写入尝试失败；后续记录不再到达。已处理条目的消去/位置/转向/through前缀不自动回滚 |

具体反例：A≠B，A记录事件7为(8,8,下,true)，B事件7初始(2,2,右,false)：恢复后B仍(2,2,右)，through为真；把记录through改假，B原假保持假、原真也保持真。B缺事件7且记录真时失败；改为同图记录且缺事件则整条跳过。正常同图有效事件可落位并转向，through假仍不清旧真。记录坐标经过角色落位的取模/通知门，不保证任意越界输入原样落地。

进入通知失败时沿批准WP05“已执行前缀保留、后续未到”的合同：例如清空完成后后继消费者抛错，记录仍已清，地图更新/恢复辅助未到；若在清空前失败，则不能断言记录已清。地图更新失败则恢复辅助未到。辅助中后项缺事件失败不回滚已处理前项；没有统一异常恢复或重新尝试保证。具体宿主报错呈现未证。

异图through门差异是固定参考异常事实；未来是否保留是 `USER_DECISION`，不要求修改参考或预定新架构。实际存档样本、地图、页切换与额外动态消费者 `MISSING_MATERIAL`；正常/异常案例均 `NOT_EXECUTED`。

## 7. 默认行为与配置变体

- **基线默认**：地图按 ID 加载；连接按配置建立邻接与偏移；边缘跨图自动转移（不在移动中且目标有效时）；显式传送重新建立；生命周期按连接与显示范围修剪（移动中暂停）。
- **支持但未默认启用**：调试选图入口（缺图时调试模式下的选图恢复，仅读档恢复路径）；`NO_SIGNPOSTS`（跨指定地图对不显示地点路牌，配置词典）。
- **配置/数据关联**：地图连接配置（作者内容，编译生命周期）；地图元数据（户外/天气/音乐等，归资源/天气/战斗呈现规格引用边界）。
- **未验证组合**：真实地图宽高与可达路线（U01）、连接偏移组合的可达性、事件在邻图的行为、完整 Demo 转移流程。

## 8. 边界、失败与未知

- 无连接或目标无效：不转移（玩家停在边界外状态，通行判定归地形运动规格）。
- 两端图尺寸为 0 的连接：被忽略（§3.2）。
- 显式传送目标图缺失：该路径**没有**缺图恢复分支，且失败点按音频状态分两阶段——**(a) 有正在播放的 BGM 或 BGS**：差异淡出阶段读取目标地图文件，此时失败则传送标记已清、载具已处理，但旧地图集合仍在、尚无本次重建的离开/进入通知；**(b) BGM/BGS 均为空**：跳过该读取，经清桥/阴影后到达重建，若失败发生在目标图读取则旧集合已被替换且有相应前置副作用。既不是「失败一定无变化」，也不是「失败一定已清地图」。缺图调试选图/非调试报错分支仅属读档恢复入口。
- 地图索引 nil/负数归 0；索引不命中回退首图（带提示）；全空抛错（§3.1）。
- 落位坐标取模：超出 [0, 宽/高) 的传送坐标按取模落地（§4）；真实地图效果待验证。
- 邻图事件在跨图后的状态：重建时临时状态（含临时自开关）重置、持久自开关保留（§5.2）；标记变更路径保留已加载实例（存档恢复规格引用）。
