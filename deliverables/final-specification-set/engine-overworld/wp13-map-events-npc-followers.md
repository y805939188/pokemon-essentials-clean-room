# 地图事件、NPC 与跟随（净化正文；批次 3）

分类：Engine/Overworld Integration。本文件描述地图事件（事件页选择、条件、触发方式、启动/等待/结束、公共事件、并行/自动运行）和 NPC/跟随（NPC 移动/互动、训练家感知、跟随者生命周期与转移限制）的行为规则，以及解释器命令的兼容范围。全部内容为静态证据；**无运行确认**（Demo 事件材料缺失，U01/U08——见 `../scope-statement.md`）。

## 1. 目的与范围

**目的**：回答「某事件何时启动、命令会产生什么效果、跟随者如何行动」，供后续实现构建事件系统，而不追踪任何特定解释器结构。

**范围**：① 事件页与触发（页选择、条件、触发方式、启动/结束）；② 解释器运行（更新循环、等待/恢复、公共事件、并行/自动运行、深度限制）；③ 解释器命令兼容矩阵与移动路线命令矩阵（见同批附表正文《解释器命令兼容矩阵》《移动路线命令矩阵》）；④ NPC、训练家感知与跟随。

**非目标**：不复制具体 Demo 事件的收费、奖励、剧情结果（U01/U08）；不把方法存在当实现、把返回值当业务成功、把搜索未中当不存在；不承诺标准 RMXP 命令全兼容（以矩阵的实际分派/实现为准）；不提取战斗内事件/命令的行为。

## 2. 概念与术语

- **事件页（page）**：事件的一组条件与内容；按从后向前顺序选择第一个条件全部满足的页。
- **触发方式（trigger）**：事件启动条件（0＝动作键、1＝玩家接触、2＝事件接触、3＝自动运行、4＝并行处理）。
- **启动（starting）**：事件被标记为待运行；由触发检查或自动运行触发。
- **公共事件（common event）**：全局事件，trigger 1＝自动运行（主解释器执行）、trigger 2＝并行处理（自有解释器）。
- **解释器（interpreter）**：逐条执行事件命令的循环；支持等待（消息/移动/计时）、子解释器（公共事件调用）与深度限制（100）。
- **命令兼容**：命令在分派中的状态（有实现/空操作/标记/未分派回退）。
- **可越格触发判定**：**不是 through 的别名**——具名图形且非 through → 假；名称含 hiddenitem → 假；否则按占格是否可通行判定（无图形、非 through 的事件也可能为真）。
- **跟随者（follower）**：由跟随数据描述、以跟随实例随行的事件角色；部分场地/道具入口禁止带跟随者（§6.2）。

## 3. 事件页与触发

### 3.1 事件页选择

- 页按**从后向前**遍历：第一个条件全部满足的页成为当前页——开关 1/2 为 ON、变量 ≥ 指定值、自开关为 ON（开关名为 `s:` 前缀的脚本条件也支持）。
- 无满足页：事件不可见、可穿透、无触发与命令列表。
- 页内容决定图形/移动类型/速度/频率/路线/方向/穿透/触发/命令列表；触发为 4（并行处理）时创建自有解释器。
- 自开关与临时自开关影响页与冷却判定（过期且临时自开关 A 为 OFF 时通过，否则标记刷新）。临时自开关随事件实例重建丢失；页条件自开关在全局表（地图拓扑规格引用）。

### 3.2 触发与启动（按调用者分入口）

| 入口 | 调用者与守卫 | 行为 |
| --- | --- | --- |
| 动作键（trigger 0） | 玩家按互动键；主解释器未运行 | 同位检查（事件在同位、非跳跃、**可越格触发为真**才启动）与面前检查（事件在面前格、非跳跃、**可越格触发为假**才启动；面前格为柜台时再延伸一格） |
| 玩家接触（trigger 1） | 两条玩家路径：(a) **玩家移动失败**时玩家侧接触检查：候选 trigger [1,2]、事件在移动目标格、非跳跃、可越格触发为假；感知类事件另做可达检查、柜台类另做面向范围检查；(b) **玩家步完成**时同位检查（移动/跳跃/强制移动中不检查）：事件须同位、非跳跃、**可越格触发为真** | 满足则启动 |
| 事件接触（trigger 2） | 两条路径：(a) **NPC 自身移动失败**时事件侧接触检查：**trigger ＝＝ 2**、主解释器未运行、按方向的坐标对齐、非跳跃、可越格触发为假；(b) 事件自身更新时自动检查：与玩家同位、非跳跃、**可越格触发为真** | 满足则启动 |
| 感知（名称模式，trigger 2 前提） | NPC **转向后**与**移动完成后**两入口 | 共同守卫：主解释器未运行、非启动中、**trigger ＝＝ 2**、非跳跃、可越格触发为假。名含 ASCII `sight(N)`/`trainer(N)`（N 为十进制数字、大小写不敏感、括号内不含空格）→ **可达检查**（面向范围内且沿途每格可移动，两入口都有）；ASCII `counter(N)` → **面向范围检查**（只看朝向与距离），**仅存在于移动完成后的入口**。全角括号不是兼容字面 |
| 自动运行（trigger 3） | 自动检查 | 每更新机会即启动 |
| 并行处理（trigger 4） | 页选择时创建自有解释器，更新驱动 | 每更新机会由自有解释器执行 |

**更新机会前提（持续许可）**：「每帧执行」以实际更新调用为前提——更新资格的重算查询**最先检查「上一次成功更新」标记**：该标记在每次实际更新获准执行时置真；每次更新调用先重算资格（此时上一次标记仍可读，为真即直接许可、不再落到屏幕范围门），随后清除该标记，获准更新时再重新置真。因此**同一事件实例持续获得更新调用时，一旦成功更新过便持续放行**；标记之后才对**自动/并行、强制路线、落位发生、名称含 update** 的事件提前许可，以上均不成立才按屏幕范围（约 2 格缓冲）判定。菜单打开时地图更新**不更新地图事件但仍更新公共事件**——菜单是从地图调用层抑制调用本身，不改写标记；显示侧只读保存的资格结果，不重新进行屏幕判定。持续许可的边界：**事件实例重建**（地图重建重新创建实例，标记随实例生命周期重置）与**外部状态改写**不在本规则覆盖内。因此「屏幕外事件不更新」不成立（持续许可与并行/自动等例外），「菜单中一切暂停」也不成立（公共事件仍更新）。

启动后：非自动/非并行事件被锁定并清除启动标记；自动运行公共事件（trigger 1＋开关 ON）由主解释器启动。

### 3.3 实例消去与局部记录（GR3-M03-004）

消去当前事件实例与持久单元中的局部消去记录是两种状态。三个入口按各自的门分列（GR4-M03-003；辅助与恢复的既有 GR3-M03-004 范围保持）：

| 入口 | 实例状态 | 局部消去记录及门 |
| --- | --- | --- |
| 普通实例消去 | 消去并刷新指定的已有实例 | 不登记 |
| 记录式脚本辅助（兼容字面 `pbEraseThisEvent`） | 先检查当前事件存在，存在才消去/刷新 | 同一存在门内，记录对象存在才登记(当前图ID,事件ID)→真；缺事件既不消去也不登记 |
| 主事件命令116 | 事件ID > 0 时对当前图同ID实例安全消去/刷新；缺实例跳过 | 正ID且记录对象存在即登记(当前图ID,事件ID)→真，**不要求实例存在**；ID0不消去/登记；记录对象缺失安全跳过登记 |

以上以相关动作正常返回为前提，登记键取当前图而非另猜的事件地图。116无论ID是否正、实例/记录对象是否存在，正常返回前均把索引推进一项并给出 false 控制结果，外层依§4.1停止本次解释器更新，不再加一次索引；下一次解释器更新机会才尝试后条，仍须通过等待门。该 false 表示让出，不表示消去失败，也不保证下一渲染帧已执行后条。记录式脚本辅助的调用推进沿既有入口规则，不把116的让出套给它。移动记录保存同身份事件的(x,y,方向,through)快照，后写同键替换；有效整数ID且事件存在才记录。

普通读档两地图恢复分支先发进入通知，清这两种局部记录，再地图更新和调用条件恢复辅助（WP11 §6.1–6.2）。复用实例可仍保留已消去/移动状态；重建实例按页数据初始化；不能凭记录持久化声称旧条目会在读档时再放回。辅助异图同IDthrough真写入、假值不清与缺事件失败均沿WP11，不是统一按图过滤全部字段。

## 4. 解释器运行

### 4.1 更新循环与等待/恢复

| 阶段 | 行为 |
| --- | --- |
| 冻结防护 | 每 100 次循环刷新画面一次 |
| 地图失联 | 当前图与解释器地图不同且无连接 → **仅把事件 ID 置 0**（不清命令列表、索引或子解释器；执行循环按等待/执行继续推进）。失联只失去「本事件」上下文，不等于结束执行 |
| 子解释器 | 先更新子解释器（公共事件调用），结束才回到父解释器 |
| 消息等待 | 消息显示中不执行命令 |
| 移动等待 | **仅当该解释器已置路线等待标记（由等待移动完成命令设置）时**，才检查玩家、当前地图事件及跟随者的强制路线：任一处于强制移动路线则不执行命令；全部结束后清除等待。设定移动路线命令只设强制路线、**不设置该等待标记**——未执行等待命令时，进行中的路线不阻塞本解释器 |
| 上岸等待 | 玩家上岸流程中不执行命令 |
| 计时等待 | 106 输入每单位 1/20 秒，按单调时钟未到则不执行；路线 15 同单位但独立帧边界见路线表 |
| 菜单调用 | 暂停菜单将打开时不执行命令 |
| 无命令时 | 主解释器尝试启动下一个待启动事件（公共事件 → 地图事件 → 自动运行公共事件） |
| 深度限制 | 公共事件调用深度 > 100 时提示并退出 |
| 指令推进 | 命令返回 false → 本轮停止；返回 true → 索引＋1。注意按钮输入命令在命令体内已索引＋1 且返回 true（一次推进两条）；命令的启动效果与等待不能混谈（矩阵控制结果列） |

### 4.2 结束与恢复（三种终止状态分列）

- **命令结束**：命令列表执行完（索引到末尾）→ 结束处理：**清除命令列表**、结束跟随者覆盖；主解释器且事件 ID 有效时解锁该事件。
- **显式退出**：退出事件处理命令 → 同样进入结束处理。
- **地图失联**：仅事件 ID 归 0（§4.1），**已有命令列表继续有效**——失联后合法的全局命令（如开关赋值）仍可执行；事件的解锁/锁定上下文已失去。
- 脚本命令异常：按类别处理（SystemExit/Reset 原样抛出，其他进入事件错误处理路径）。
- 公共事件并行处理按开关状态刷新。

### 4.3 具名过场跳过、结束与重新启动（GR3-M03-003）

`SPECIAL` 本次触发在**系统更新**中独立检查，正常地图更新与迷你更新都会到达；正常系统更新早于地图末端快捷登记，迷你更新没有该末端分发。跳过门要求主地图解释器正在运行、可按解释器事件ID从当前地图取得事件，以及该事件当前命令列表含代码108或408的注释项，其完整文本**严格等于 `Cut Scene`**。大小写不同、尾空格、前后附文、拼接多个注释才得到该词或把同文本放入非注释命令均不匹配。

注释入口返回“匹配后的最多一项参数”的数组；跳过消费者只检测结果存在，**空数组也通过**，与未匹配/无列表/列表不是数组/解释器未运行/事件不存在返回的空值分开。不要求下一项是特定代码或含非空参数；合法注释在列表末端时仍可能匹配。主解释器运行判定是命令列表非空值，不以数组内容多寡替代；启动动作另有列表长度门。

在事件仍有效、正文列表至少两项、各动作正常返回且无额外写入前提下，顺序为：

1. 以**解释器所绑定的地图ID与当前取得事件ID**将持久自开关A置真。原值假→真且该解释器地图已加载时请求该地图刷新；原值已真不发新的值变化刷新请求。自开关真不是临时自开关A。
2. 结束当前解释器命令列表、结束跟随覆盖；主解释器有效事件按§4.2解锁。不是从旧索引继续，也不是把全部解释器字段初始化。
3. 再向刚才取得的同一事件请求启动；当前列表长度>1才标记待启动。只含一项匹配注释的列表可通过空数组门并写A/结束，但不设新的启动标记。刷新并不在写A调用时同步选择新页。

以后获得地图/解释器更新机会时，刷新按页条件选择（§3.1），解释器无命令时才按§4.1挑选待启动项。页变化会清启动标记并可能触发新页自己的自动运行；因此这里交付“请求重新启动”的顺序，**不保证任何配置都马上执行A页**或原列表重新开跑。需结合A页是否存在/满足、页触发与后续更新判断。自开关原已真也仍执行结束与启动请求，不能把不新请求刷新误读为不跳过。

失联事件ID归0或当前事件缺失时，注释上下文门不成立，无该跳过链的写A/结束/重启；原解释器列表继续性仍沿§4.1，不能把上下文不匹配改成通用终止。若在上述写A之后、结束/启动之前出现异常，则只保留实际已提交前缀，不保证回滚/完成后续步骤。

本门**要求解释器运行**，不能套地图末端新快捷登记的“解释器未运行”门，也不受那个末端消息窗口门替代。系统更新不清除本次SPECIAL触发事实；跳过结束解释器后，本轮后面若消息不显示、无冰滑/上下瀑、玩家静止且USE/ACTION较早检测未命中，则末端仍可登记快捷并按消费优先级处理；已有菜单/调试调用优先、消息显示/移动等门则可阻止。不得宣称SPECIAL独占、必开快捷或一律不开快捷（WP12 §4.3）。

## 5. 解释器命令兼容矩阵（要点）

命令支持矩阵见同批《解释器命令兼容矩阵》（正文）；移动路线命令为独立分派，见同批《移动路线命令矩阵》。要点：

- **直接结构分类（本快照）**：96 个主分派命令代码＝**28 空操作＋2 标记＋66 其他实现入口**。该数字不代表所有参数分支均有效，也不作为未来版本硬编码真值。
- **空操作 28 个**：126（增减物品）、127、128、129、133（战斗结束 ME）、301（战斗处理）、302（商店）、311、312、313、315、316、317、318、319、320、321、322、331–340。事件作者调用这些命令**无可见效果**（含 126 不改变背包、301 不启动战斗、311 不改变 HP）。
- **标记 2 个**：112（循环开始）、118（标签）。
- **续行不是无效数据**：401 由 101 消费、655 及相邻 355 由 355 合并；「未单独分派」仅限直接到达默认分支的代码。
- **启动效果 ≠ 等待完成**：设定移动路线后立即继续（等待移动完成才等待）；卷动地图仅已有滚动时等待；多数画面/音频效果启动后立即继续；旋转图片设旋转速度；按钮输入一次推进两条；脚本命令总是返回 true。
- **文本/分支组合边界**：101 先预读再显示，循环末端四项布局可在置消息等待前发生名称解析失败（命令矩阵 §3.1）；脚本条件 nil 跳过 Then 与 Else，严格 false 才 Else（111/411）；选项同缩进合并与一次性隐藏/改名保留原分支身份；确认及取消的原始返回值都先查可见→原映射，无条目才保留原值。首组 A/取消0 加后组 B/C/D/取消1，隐藏 A 后 BACK 进入 C；无隐藏或隐藏后确认首个可见 B 则进入 B，101 合入亦同（矩阵 §3.2；IM36–41）。
- **未分派回退**：不在分派表中的任意命令代码 → 返回 true（跳过并继续，无效果）；不承诺标准 RMXP 命令全兼容（以矩阵为准）。

## 6. NPC、训练家感知与跟随

### 6.1 NPC 移动与互动

- NPC（事件角色）按页的移动类型/速度/频率/路线移动；更新机会按 §3.2 的资格规则（非「屏幕外一律不更新」）。
- 对角固定两段、多格底行左锚点、中心主轴/备用轴和自主随机/接近概率见 WP12 §4.3；这些是移动选择，不是寻路保证。
- 训练家感知：按 §3.2 感知入口（trigger 2 前提、可达/面向两种检查、跳跃与可越格触发守卫）；不是「进入视野即启动」。
- 训练家事件由战斗入口调用（战斗上下文规格交界）；战斗后 NPC 的状态（再启动/再战）归电话/训练家规格。

### 6.2 跟随者生命周期与转移限制

- **加入**：跟随工厂加入——**去重守卫**：同一原始图＋事件 ID 已存在则直接返回；否则登记跟随数据（原始地图/事件/名称、当前地图/坐标/朝向、外观克隆；名称与可选公共事件覆盖）。
- **移除**：按事件移除（当前图匹配＋原始图/事件匹配）、按名称移除、全部移除。
- **实例化**：跟随实例按跟随数据创建；可穿透跟随（临时穿透）。
- **移动/更新**：玩家移动后跟随者依次移动：**领队链为玩家 → 前一跟随者**；每个跟随者跟随领队——**强制路线中跳过跟随**；相连地图时目标为领队身后格（岩架时取跳上来的一格）；不相连地图时目标为领队位置；跨图时按相对坐标向量换图定位；即时或不相连时即时落位，否则按**条件位移**：
  - **同轴相差一格** → 走一步（目标为玩家位置、或目标按进入方向许可、或当前位置不可通行时穿透走）。
  - **同轴相差两格** → 按中间/落点/起点许可决策：中间格许可 → 走两步（不启动跳跃）；中间格不许、落点许可、起点许可 → 尝试两格跳跃；中间格不许、落点许可、起点不许 → 穿透走两步；中间与落点均不许 → 不前进。中间格许可而第二步受阻时，不能保证两次行走尝试到达目标。
  - **其他非重合目标** → 直接定位：未命中同轴一格/两格分支时，只要目标与当前位置不同即直接定位——**既包括非同轴目标（即使只相差 (1,1)），也包括同轴相距三格及以上**；同轴超过两格不是逐格追赶或停留。
  - 位置判定按地形运动规格层 5 的跟随者实际入口（方向位/地形/具名图形事件；引用，不另写第二套通行规则）。
  移动后把坐标/地图/朝向写回跟随数据持久层。转向、逐帧更新（同步领队速度、按可见性设透明、冰滑时整姿停动画；玩家移动中且跟随者未动时设置/清除启动标记驱动其更新）。
- **显式传送**：跟随者放到玩家位置、朝向一致、不透明 255、写回持久层并设转移后隐藏标记；玩家开始移动时清该标记并转向玩家；可见性＝可见标记且非转移后隐藏。
- **互动**：USE 键且非菜单/战斗/强制路线/消息/解释器时，面前格上的跟随者（非跳跃）触发互动（需事件有命令列表且登记了公共事件 ID → 刷新、锁定并以该事件列表启动主解释器）。
- **转移限制**：带跟随者转移/骑乘许可仅在跟随者数为 0 时为真——**但守卫只在调用它们的场地/道具入口生效**；普通显式传送**没有此守卫**，反而会携带跟随者转移。不能由函数名推出「有跟随者就无法地图传送」。
- **持久化**：跟随者数据在玩家全局持久值中保存（存档目录）；旧格式为弃用转换（迁移规格）。
- 跟随机制是事件级跟随（事件角色随行），**不自动等同于完整「跟随宝可梦」系统**（其完整规则归后续适用规格；不得无证扩张，但本节机制是当前可读源码的直接提取）。

### 6.3 门入口的跟随操作族

这组入口的实际消费者包括门事件编译路径，不能仅凭没有 Demo 链而忽略；这里只记录静态调用，不宣称运行可达。

- 入门跟随：设置任何路线前先快照玩家与全部跟随者位置。按快照中玩家→前一跟随者计算相对向量，每次只取一个轴的一步（横轴非零优先），向路线前端累计；各跟随者收到累计路线后再置不透明度 0。例如玩家 (5,3)、F1 (5,4)、F2 (5,5)，F1 收到向上一步后隐藏，F2 收到向上两步后隐藏，不能使用已开始移动的 F1 实时坐标代替快照。
- 隐藏：仅将各实例不透明度置 0，不改坐标或持久可见标记。
- 出门放到玩家：各实例落到玩家位置、不透明度 255，写回持久 x/y，并置转移后隐藏标记；玩家开始移动后按 §6.2 清该标记。255 不等于该帧最终可见。
- 这些门路线使用非重复、可跳过的系统路线包装：穿透 ON → 请求命令 → 穿透 OFF → 终止；未保存/恢复此前 through 值，完成后 OFF。异步脚本后插入时长 0 的等待项，仍结束该次路线分派。包装的 `waitComplete` 参数未被消费，调用本身不等待；门编译另加事件 210 才形成等待链。

## 8. 边界、失败与未知

- 无满足页：事件不可见/可穿透/无触发（§3.1）。
- 解释器失联：地图不同且无连接 → 事件 ID 归 0，**命令列表继续**（§4.1/§4.2）。
- 深度超限：公共事件调用 > 100 层 → 提示并退出（§4.1）。
- 脚本异常：SystemExit/Reset 原样抛出；其他异常按事件错误处理（§4.2）。
- 空操作命令：28 个空操作命令被跳过且无效果（§5）；调用方（事件作者）若依赖这些命令将无可见效果——兼容性限制如实登记。
- 缺失地图/事件材料：具体 NPC 对话、事件页、任务流程、商店库存、奖励和可达性无法确认（U01/U08）。
