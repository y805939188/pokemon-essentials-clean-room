# 适用版本与兼容模式

实现一个功能时，先选定要复现的参考版本，再记录机制世代、作者数据、设置覆盖和输入模式。如果采用独立规则，另记 V1 编号；同一案例可分别保留原版预期和独立预期。[术语](terms.md) · [范围与证据](scope-and-evidence.md)

## 选择行为目标

| 目标 | 适用条件 | 验收依据 |
| --- | --- | --- |
| 固定参考快照 R | 正文描述 R 的静态行为时，保留入口、默认值、写入顺序、失败点及已产生的副作用。 | [原版行为与分域入口](../README.md) |
| 发行 v21.1 | 有版本对照时，按标为发行版的列判断。某处已确认相同不意味着整个发行版与 R 等价。 | [进化参数版本对照](../spec/creatures/basic-evolution.md) · [作者数据读取与终检](../spec/core/pbs-lifecycle.md) |
| 可移植独立规则 V1 | 采用者选取具体编号。V1-01 至 V1-07 及 V1-09 至 V1-11 定义独立实现合同；V1-08 提供原有选曲行为的验证补充。 | [11 组规则与静态向量](../vectors/portable-expectations.md) |
| 独立框架的功能规则 | 按功能选用公开框架中有实现与测试定义的行为。作者策略属于可选配置。 | [规则与用例索引](../vectors/portable-expectations.md) · [功能用例](../vectors/portable-framework-cases.json) |

例如，两个参考来源都可接受旧复数进化属性中的有效非负十进制参数。发行版对显式形态缺参的处理与 R 有差异，单数属性的支持也有差异。要覆盖这个入口，请分别设置来源、基础物种或形态、属性名和缺失位置。[基础进化](../spec/creatures/basic-evolution.md)

名人堂上限为零时，首次登记后可出现累计一届、保留零届。固定参考的 PC 入口可见，取最新记录时失败；独立规则 V1-09 则要求展示空历史并允许退出。登记与存档分别验证。[原版名人堂](../spec/ui/lifecycle-presentations-and-history.md) · [独立名人堂](../spec/ui/portable-hall-of-fame.md)

## 机制世代与作者配置

参考快照的机制世代默认为 8。改变世代会改变依赖世代的默认值；作者单独覆盖的设置会脱离默认联动，直接读取世代的规则仍按世代判断。读取配置词典时连同数据、运行状态、游戏开关和玩家选项核对。[规则配置与变体](../spec/core/rule-configuration-and-data-variants.md)

场地招式许可有两种解释。按徽章数量时比较已取得枚数；按特定徽章时读取指定徽章。备选数据集能否被正常发现、编译并使用要分别确认。目录存在、机制世代相同和允许设置某个开关，都不足以验证任意组合。[配置词典与未验证组合](../spec/core/rule-configuration-and-data-variants.md)

## 证据与宿主边界

静态观察仅覆盖正文指明的来源、入口与条件；目录和 JSON 中的预期供独立套件执行。原版、指定宿主、玩家安装包、其他平台各自需要相应的运行记录。可移植规则的 38 条 JSON 预期状态均为 `NOT_RUN`，其中没有原版运行断言。[可移植静态预期](../vectors/portable.json)

V1 系列以外的独立框架用例也标为 `NOT_RUN`。各例记录输入、动作和预期结果。[独立框架功能用例](../vectors/portable-framework-cases.json)

语言、对象布局、文件格式、场景接口和具体引擎由实现选择。复现已有行为时，对照可观察的输入、状态、顺序和输出。正文中具名宿主的异常、入口差别或资源前提仅在相应条件下适用。保留未验证边界直到获得对应证据。[范围与证据](scope-and-evidence.md)

本库保留了参考版本的双打、战斗设施等规则。仅收录这些规则不表示独立框架首版已实现它们。独立用例的范围限于各自列明的功能、入口和条件；完整 Demo、完整原版或跨语言实现等价性、签名 macOS 包的外部分发均未由这些用例验证。
